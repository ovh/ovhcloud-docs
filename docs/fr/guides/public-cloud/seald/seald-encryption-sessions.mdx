## Objectif

Ce guide explique comment utiliser les sessions de chiffrement du SDK Seald. Une session de chiffrement utilise une clé symétrique partagée pour tous les messages de la session, ce qui simplifie le code d'intégration et réduit le nombre d'appels réseau. En contrepartie, la gestion des droits (ajout ou révocation d'un destinataire) s'applique à l'ensemble de la session.

## Prérequis

- Un compte Seald actif avec un `appId` et `apiURL`.
- Le package `@seald-io/sdk` installé et initialisé. Consultez le guide [Installer le SDK Seald](/guides/public-cloud/seald/seald-install-sdk).
- Les `sealdId` des utilisateurs destinataires.

## En pratique

Cette section couvre la création d'une session, le chiffrement et déchiffrement de messages et fichiers, la gestion des destinataires, et la configuration de la mise en cache.

### Étape 1 — Créer une session de chiffrement

Appelez `seald.createEncryptionSession` en fournissant la liste des `sealdIds` des destinataires autorisés à déchiffrer :

```javascript
const session = await seald.createEncryptionSession(
  { sealdIds: [monSealdId, sealdIdUtilisateur2] },
  { metadata: 'Ma session de démo' }  // métadonnée non chiffrée, visible dans le tableau de bord
)
// session.sessionId — conservez-le pour récupérer la session ultérieurement
```

> [!INFO]
> Si vous créez une session pour un groupe dont vous faites partie, passez `encryptForSelf: false` pour éviter le chiffrement direct vers vos propres identités. Vous pourrez toujours déchiffrer grâce à votre appartenance au groupe.

### Étape 2 — Chiffrer et déchiffrer des messages

Utilisez l'objet `EncryptionSession` pour chiffrer des messages lisibles par tous les destinataires :

```javascript
// Chiffrer
const messageCiffré = await session.encryptMessage('Message super secret')
// Résultat : '{"sessionId":"...","data":"..."}'

// Récupérer la session depuis un message chiffré, puis déchiffrer
const sessionRecupérée = await seald.retrieveEncryptionSession({ encryptedMessage: messageCiffré })
const messageDéchiffré = await sessionRecupérée.decryptMessage(messageCiffré)
```

> [!INFO]
> Vous pouvez aussi récupérer la session par son identifiant : `seald.retrieveEncryptionSession({ sessionId })`.

### Étape 3 — Chiffrer et déchiffrer des fichiers

L'objet `EncryptionSession` expose aussi `encryptFile` et `decryptFile`. La clé de session est réutilisée pour tous les fichiers chiffrés dans la même session :

```javascript
// Chiffrer un fichier
const encryptedBuffer = await session.encryptFile(
  Buffer.from('Contenu secret', 'utf8'),
  { filename: 'secret.txt' }
)

// Déchiffrer
const { data, filename } = await session.decryptFile(encryptedBuffer)
console.log(data.toString('utf8')) // 'Contenu secret'
```

### Étape 4 — Gérer les destinataires

Tout destinataire ayant le droit `forward` (accordé par défaut) peut ajouter d'autres destinataires. Seul le créateur de la session a le droit `revoke` par défaut :

```javascript
// Ajouter un destinataire (nécessite le droit 'forward')
await session.addRecipients({ sealdIds: [sealdIdUtilisateur3] })

// Révoquer un destinataire (nécessite le droit 'revoke')
await session.revokeRecipients({ sealdIds: [sealdIdUtilisateur3] })

// Révoquer entièrement la session (nécessite le droit 'revoke')
await session.revoke()
```

### Étape 5 — Configurer la mise en cache des sessions (optionnel)

Pour réduire les appels réseau, activez le cache en définissant `encryptionSessionCacheTTL` à l'initialisation du SDK :

```javascript
const seald = SealdSDK({
  appId,
  apiURL,
  encryptionSessionCacheTTL: 30 * 60 * 1000  // 30 minutes
})
```

Le cache est rempli automatiquement à la création ou à la récupération d'une session. Passez `useCache: false` pour forcer un appel réseau :

```javascript
const sessionSansCache = await seald.retrieveEncryptionSession({ sessionId, useCache: false })
```

**Cache persistant dans le `localStorage` (navigateur uniquement) :**

Pour un cache persistant entre les rechargements de page, utilisez `createLocalStorageEncryptionSessionCache`. Cela nécessite une [base de données locale persistante](/guides/public-cloud/seald/seald-local-database) :

```javascript
import SealdSDK, { createLocalStorageEncryptionSessionCache } from '@seald-io/sdk'

const seald = SealdSDK({
  appId,
  apiURL,
  databasePath,
  databaseKey,
  encryptionSessionCacheTTL: 30 * 60 * 1000,
  createEncryptionSessionCache: createLocalStorageEncryptionSessionCache
})
```

> [!INFO]
> Le nettoyage du cache s'effectue automatiquement avec un intervalle égal au `encryptionSessionCacheTTL` (minimum 10 secondes). Pour personnaliser l'intervalle, utilisez `encryptionSessionCacheCleanupInterval`. Pour déclencher un nettoyage manuel : `await sdk.utils.cleanCache()`.
