## Objectif

Ce guide explique comment protéger une identité cryptographique du SDK Seald avec un mot de passe en utilisant le plugin `@seald-io/sdk-plugin-ssks-password`. L'identité est chiffrée avec une clé dérivée du mot de passe de l'utilisateur et stockée sur le serveur SSKS (Seald SDK Key Storage). Seul un utilisateur connaissant le mot de passe peut récupérer son identité.

:::warning
Une réinitialisation de mot de passe oublié n'est pas possible avec cette méthode sans perte de données. Si votre application nécessite une récupération de compte, utilisez plutôt la [protection des identités SSKS 2MR](/guides/public-cloud/seald/seald-ssks-2mr).
:::

## Prérequis

- Un compte Seald actif avec un `appId`, `apiURL` et `keyStorageURL`.
- Les packages `@seald-io/sdk` et `@seald-io/sdk-plugin-ssks-password` installés. Consultez le guide [Installer le SDK Seald](/guides/public-cloud/seald/seald-install-sdk).
- Une instance du SDK Seald initialisée avec une identité existante.

## En pratique

Cette section vous guide dans la sauvegarde d'une identité avec SSKS Password, sa récupération lors d'une nouvelle session, et le changement de mot de passe.

### Étape 1 — Instancier le SDK avec le plugin SSKS Password

Passez le plugin `SealdSDKPluginSSKSPassword` lors de la construction du SDK :

```javascript
import SealdSDK from '@seald-io/sdk'
import SealdSDKPluginSSKSPassword from '@seald-io/sdk-plugin-ssks-password'

const seald = SealdSDK({
  appId,
  apiURL,
  plugins: [SealdSDKPluginSSKSPassword(keyStorageURL)]
})
await seald.initialize()
```

### Étape 2 — Créer une identité et la sauvegarder avec un mot de passe

Après avoir appelé `initiateIdentity`, sauvegardez l'identité sur SSKS chiffrée avec le mot de passe de l'utilisateur :

```javascript
await seald.initiateIdentity({ signupJWT: 'votre-signup-jwt' })

await seald.ssksPassword.saveIdentity({
  userId: 'identifiant-utilisateur-unique', // une chaîne stable et unique pour cet utilisateur
  password: 'mot-de-passe-secret-utilisateur'
})
```

> [!INFO]
> Si vous souhaitez sauvegarder une sous-identité plutôt que l'identité de l'instance courante, passez l'argument `identity` :
> ```javascript
> const { identity: subIdentity } = await seald.createSubIdentity()
> await seald.ssksPassword.saveIdentity({
>   userId: 'identifiant-utilisateur-unique',
>   password: 'mot-de-passe-secret-utilisateur',
>   identity: subIdentity
> })
> ```

### Étape 3 — Récupérer une identité lors d'une nouvelle session

Lors des connexions suivantes, récupérez l'identité depuis SSKS en utilisant les mêmes `userId` et `password` :

```javascript
const seald = SealdSDK({
  appId,
  apiURL,
  plugins: [SealdSDKPluginSSKSPassword(keyStorageURL)]
})
await seald.initialize()

await seald.ssksPassword.retrieveIdentity({
  userId: 'identifiant-utilisateur-unique',
  password: 'mot-de-passe-secret-utilisateur'
})
// Le SDK est maintenant prêt à chiffrer et déchiffrer
```

> [!INFO]
> Si le mot de passe est saisi incorrectement plusieurs fois de suite, le serveur SSKS applique une limitation de débit. Dans ce cas, vous recevez le message d'erreur : `Request throttled, retry after {N}s`.

:::warning
Évitez d'appeler `ssksPassword.retrieveIdentity` pour le même utilisateur sur plusieurs appareils simultanément (par exemple dans des tests automatisés). Attendez qu'une récupération soit terminée avant d'en démarrer une autre.
:::

### Étape 4 — Changer le mot de passe

Lorsqu'un utilisateur change son mot de passe, appelez `changeIdentityPassword` pour rechiffrer l'identité avec le nouveau mot de passe et supprimer l'ancien :

```javascript
await seald.ssksPassword.retrieveIdentity({
  userId: 'identifiant-utilisateur-unique',
  password: 'ancien-mot-de-passe'
})

await seald.ssksPassword.changeIdentityPassword({
  userId: 'identifiant-utilisateur-unique',
  currentPassword: 'ancien-mot-de-passe',
  newPassword: 'nouveau-mot-de-passe'
})
```

> [!INFO]
> **Avancé — dérivation de clé personnalisée :** Si votre application dérive ses propres clés de chiffrement (par exemple avec PBKDF2), vous pouvez contourner la dérivation scrypt par défaut en passant `rawEncryptionKey` (un buffer aléatoire de 64 octets encodé en Base64) et `rawStorageKey` (une chaîne unique, jusqu'à 256 caractères) à la place de `password` :
> ```javascript
> await seald.ssksPassword.saveIdentity({
>   userId,
>   rawEncryptionKey: cleDerivee,     // 64 octets, encodés en Base64 — doit rester côté client uniquement
>   rawStorageKey: cleStockageServeur // non-secret, identifiant unique
> })
> ```

:::warning
Si vous utilisez le même mot de passe pour la protection SSKS et l'authentification de l'application, **n'envoyez jamais le mot de passe brut à votre serveur**. Dérivez-le côté client (avec scrypt ou PBKDF2) avant tout appel serveur, afin que votre serveur ne voie qu'une valeur dérivée et ne puisse jamais reconstruire la clé de chiffrement SSKS.
:::
