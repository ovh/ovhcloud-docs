## Objectif

Ce guide explique comment créer et gérer des identités cryptographiques avec le SDK Seald. Chaque utilisateur est représenté par une ou plusieurs identités — des clés privées générées localement sur l'appareil de l'utilisateur. Les sous-identités permettent au même utilisateur d'opérer sur plusieurs appareils tout en partageant l'accès à toutes leurs données chiffrées.

## Prérequis

- Un compte Seald actif avec un `appId`, `apiURL` et `keyStorageURL`. Contactez le [support Seald](mailto:support@seald.io) pour les obtenir.
- Le package `@seald-io/sdk` installé et initialisé. Consultez le guide [Installer le SDK Seald](/guides/public-cloud/seald/seald-install-sdk).
- Un JWT de signup valide émis par votre backend. Consultez le guide [Secrets JWT](/guides/public-cloud/seald/seald-jwt).

## En pratique

Cette section vous guide dans la création d'une première identité, l'ajout de sous-identités pour des appareils supplémentaires, la pré-génération de clés pour accélérer la création d'identité, et l'export ou l'import manuel de données d'identité.

### Étape 1 — Créer une première identité

Pour créer une identité pour un nouvel utilisateur, appelez `sdk.initiateIdentity` avec un JWT de signup généré par votre backend :

```javascript
import SealdSDK from '@seald-io/sdk'

const seald = SealdSDK({ appId, apiURL })
await seald.initialize()

// Créer la première identité Seald de l'utilisateur
await seald.initiateIdentity({ signupJWT: 'votre-signup-jwt' })
```

Le JWT de signup doit avoir le scope `PERMISSION_JOIN_TEAM` (valeur `3`). Chaque JWT doit inclure un `jti` (nonce unique) afin qu'il ne puisse être utilisé qu'une seule fois.

> [!INFO]
> Pour associer un identifiant personnalisé (connecteur) à l'identité — par exemple, un ID utilisateur interne — incluez la revendication `connector_add` dans le JWT. Le format du connecteur doit être `${IDENTIFIER}@${APP_ID}` avec le type `AP`. Vous pouvez également ajouter un connecteur ultérieurement en appelant `sdk.pushJwt()`.

### Étape 2 — Créer une sous-identité pour un nouvel appareil

Une fois qu'un utilisateur dispose d'une première identité, vous pouvez créer des sous-identités pour des appareils supplémentaires. Une sous-identité partage les mêmes droits d'accès que l'identité principale : tout ce qui est chiffré pour cet utilisateur peut être déchiffré par n'importe laquelle de ses sous-identités.

```javascript
// Une instance du SDK déjà initialisée avec une identité existante
const { subIdentity } = await seald.createSubIdentity()
// subIdentity est un Buffer — stockez-le ou protégez-le avec SSKS
```

Le `Buffer` retourné est au même format que `sdk.exportIdentity()`. Vous pouvez l'importer dans une autre instance du SDK, ou le sauvegarder sur SSKS en utilisant `ssksPassword.saveIdentity()` ou `ssks2MR.saveIdentity()`.

:::warning
Avoir un très grand nombre de sous-identités pour le même utilisateur (plusieurs dizaines) peut ralentir les opérations. Pour les utilisateurs qui se reconnectent fréquemment ou utilisent de nombreux appareils, préférez réutiliser une identité stockée sur SSKS plutôt que de créer une nouvelle sous-identité à chaque connexion.
:::

### Étape 3 — Pré-générer des clés d'identité (optionnel)

La génération de clés cryptographiques peut prendre plusieurs centaines de millisecondes. Vous pouvez les pré-générer en arrière-plan pour accélérer le prochain appel à `createSubIdentity` :

```javascript
// Pré-générer une clé en arrière-plan
seald.preGenerateIdentityKeys(1)

// … effectuer d'autres tâches …

// Le prochain appel à createSubIdentity sera plus rapide
const { subIdentity } = await seald.createSubIdentity()
```

### Étape 4 — Exporter et importer une identité manuellement

Si vous avez besoin de gérer le stockage d'identité en dehors de SSKS, utilisez `exportIdentity` et `importIdentity` :

```javascript
// Exporter l'identité actuelle sous forme de Buffer
const identityBuffer = await seald.exportIdentity()

// Importer un Buffer dans une nouvelle instance du SDK
const seald2 = SealdSDK({ appId, apiURL })
await seald2.initialize()
await seald2.importIdentity(identityBuffer)
```

:::danger
Vous êtes responsable de la sécurisation des buffers d'identité exportés. Si une identité exportée est compromise, toutes les données chiffrées pour cet utilisateur sont exposées. Stockez les identités exportées chiffrées dans un stockage à accès contrôlé.
:::
