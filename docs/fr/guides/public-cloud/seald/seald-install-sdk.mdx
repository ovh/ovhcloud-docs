## Objectif

Ce guide vous explique comment installer le SDK Seald (`@seald-io/sdk`) via npm, l'importer correctement selon votre plateforme cible (navigateur, Node.js/Electron ou React Native), et l'instancier dans votre application.

Il ne couvre pas la création d'identité ni le chiffrement — ces sujets sont traités dans les guides de démarrage rapide spécifiques à chaque plateforme.

## Prérequis

- Un compte Seald — utilisez le [tableau de bord staging](https://dashboard.staging-0.seald.io/) pour le développement, ou contactez Seald pour créer un compte de production.
- Node.js et npm installés sur votre poste de travail.
- Les identifiants suivants depuis le tableau de bord d'administration Seald :
    - `appId` : l'UUID unique de votre application.
    - `apiURL` : l'URL du serveur API (staging uniquement ; à omettre en production).
    - `keyStorageURL` : l'URL du serveur SSKS (staging uniquement ; à omettre en production — requis uniquement si vous utilisez un plugin de stockage d'identité).
    - `JWTSecretId` et `JWTSecret` : identifiants JWT pour générer les jetons d'identité utilisateur.

## En pratique

Le SDK Seald est distribué sous forme de packages npm. Installez le package principal, ajoutez optionnellement un ou deux plugins de stockage d'identité, puis suivez les instructions d'import et de configuration pour votre plateforme cible.

### Étape 1 — Installer les packages npm

**Installer le package principal :**

```bash
npm i -S @seald-io/sdk
```

**Installer les plugins de stockage d'identité nécessaires :**

```bash
# Stockage d'identité basé sur un mot de passe
npm i -S @seald-io/sdk-plugin-ssks-password

# Stockage d'identité par règle des deux hommes
npm i -S @seald-io/sdk-plugin-ssks-2mr
```

:::warning
Si vous ne configurez ni plugin de stockage d'identité ni base de données locale persistante, l'identité cryptographique de l'utilisateur ne sera sauvegardée nulle part. Toutes les données chiffrées avec cette identité deviennent irrécupérables dès la fermeture de l'onglet du navigateur ou de l'application.
:::

### Étape 2 — Importer le SDK

<Tabs>
<Tab label="Navigateur">

Le SDK fournit trois variantes de build pour le navigateur. Choisissez celle qui correspond à votre configuration de bundler.

**Polyfillée (recommandée pour les configurations webpack/bundler standard)**

Utilisez cette variante si votre bundler ne fournit pas déjà les polyfills Node.js :

```javascript
import SealdSDK from '@seald-io/sdk' // si votre bundler résout le champ "browser" (Webpack 5)
// ou de façon équivalente :
import SealdSDK from '@seald-io/sdk/browser'
// ou explicitement :
import SealdSDK from '@seald-io/sdk/browser/seald-sdk.polyfilled.js'
```

**Bibliothèque (recommandée lorsque vous gérez vous-même les polyfills webpack)**

Cette variante produit un bundle plus petit mais nécessite de configurer les polyfills manuellement dans webpack :

```javascript
import SealdSDK from '@seald-io/sdk/browser-library'
// ou explicitement :
import SealdSDK from '@seald-io/sdk/browser/seald-sdk.js'
```

Ajoutez la configuration suivante à votre `webpack.config.js` (installez d'abord les packages listés en `devDependencies` : `assert path-browserify events constants-browserify os-browserify util stream-browserify process buffer timers-browserify`) :

```javascript
module.exports = {
  node: { global: true },
  resolve: {
    fallback: {
      assert: require.resolve('assert/'),
      fs: false,
      path: require.resolve('path-browserify'),
      events: require.resolve('events/'),
      constants: require.resolve('constants-browserify'),
      os: require.resolve('os-browserify/browser'),
      util: require.resolve('util/'),
      stream: require.resolve('readable-stream'),
      crypto: false
    }
  },
  plugins: [
    new webpack.ProvidePlugin({
      process: 'process/browser',
      Buffer: ['buffer', 'Buffer'],
      setImmediate: ['timers-browserify', 'setImmediate'],
      clearImmediate: ['timers-browserify', 'clearImmediate']
    })
  ]
}
```

**Bundle (sans bundler — balise `<script>` directe)**

Copiez `@seald-io/sdk/browser/seald-sdk.browser.js` dans votre projet et incluez-le via une balise `<script>`. Le SDK est alors accessible via `window.SealdSDK`.

:::warning
Le rechargement à chaud (hot-reload) et le redémarrage à chaud (hot-restart) doivent être désactivés lors de l'utilisation du SDK Seald avec une base de données locale persistante. Les garder actifs peut corrompre la base de données locale.
:::

<Tab label="React Native">

**1. Installer les dépendances pair (versions exactes requises)**

```bash
npm i -S \
  @react-native-async-storage/async-storage@2.1.0 \
  @seald-io/react-native-scrypt@1.2.3 \
  react-native-quick-crypto@0.7.11 \
  @craftzdog/react-native-buffer@6.0.5 \
  react-native-quick-base64@2.1.2 \
  readable-stream@4.7.0
```

:::warning
Le SDK Seald ne fonctionne **pas** avec Expo Go car il repose sur des dépendances natives. Utilisez plutôt un [Development Build](https://docs.expo.dev/get-started/set-up-your-environment/?mode=development-build&buildEnv=local).
:::

**2. Ajouter le polyfill Buffer global**

Ajoutez l'import suivant le plus tôt possible dans le point d'entrée de votre application (par exemple `index.js`) :

```javascript
import { Buffer } from '@craftzdog/react-native-buffer'
global.Buffer = Buffer
```

**3. Configurer la résolution de modules**

Choisissez l'une des deux approches suivantes.

*Option A — Configuration Metro (`metro.config.js`) :*

```javascript
config.resolver.resolveRequest = (context, moduleName, platform) => {
  if (moduleName === 'crypto') {
    return context.resolveRequest(context, 'react-native-quick-crypto', platform)
  }
  if (moduleName === 'buffer') {
    return context.resolveRequest(context, '@craftzdog/react-native-buffer', platform)
  }
  if (moduleName === 'stream') {
    return context.resolveRequest(context, 'readable-stream', platform)
  }
  return context.resolveRequest(context, moduleName, platform)
}
```

*Option B — Plugin Babel (`babel.config.js`) :*

Installez d'abord `babel-plugin-module-resolver`, puis ajoutez :

```javascript
module.exports = {
  presets: ['module:metro-react-native-babel-preset'],
  plugins: [
    ['module-resolver', {
      alias: {
        crypto: 'react-native-quick-crypto',
        stream: 'readable-stream',
        buffer: '@craftzdog/react-native-buffer'
      }
    }]
  ]
}
```

**4. Importer le SDK**

Metro résout automatiquement le champ `react-native` du manifest du package :

```javascript
import SealdSDK from '@seald-io/sdk'
```

### Étape 3 — Instancier le SDK

Appelez la factory `SealdSDK` avec les identifiants de votre application, puis appelez `initialize()` avant d'effectuer toute opération du SDK.

**Sans plugins :**

```javascript
const seald = SealdSDK({ appId, apiURL })
await seald.initialize()
```

**Avec les plugins de stockage d'identité :**

```javascript
const seald = SealdSDK({
  appId,
  apiURL,
  plugins: [
    SealdSDKPluginSSKSPassword(keyStorageURL),
    SealdSDKPluginSSKS2MR(keyStorageURL)
  ]
})
await seald.initialize()
```

> [!INFO]
> En production, omettez les paramètres `apiURL` et `keyStorageURL`. Ils sont uniquement requis pour se connecter à l'environnement de staging.
