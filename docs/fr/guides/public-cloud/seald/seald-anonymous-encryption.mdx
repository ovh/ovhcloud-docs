## Objectif

Ce guide explique comment utiliser le SDK de chiffrement anonyme de Seald. Ce SDK permet à une entité sans identité Seald (un serveur backend, un utilisateur non connecté) de chiffrer des données pour des utilisateurs qui, eux, ont une identité Seald. Chaque opération de chiffrement anonyme doit être autorisée par votre backend via des JSON Web Tokens.

## Prérequis

- Un compte Seald actif avec un `appId` et `apiURL`.
- Le package `@seald-io/sdk` installé. Consultez le guide [Installer le SDK Seald](/guides/public-cloud/seald/seald-install-sdk).
- Les `sealdId` des utilisateurs destinataires.
- Un backend capable de générer les JWT de chiffrement anonyme. Consultez le guide [Secrets JWT](/guides/public-cloud/seald/seald-jwt).

## En pratique

Cette section couvre l'import et l'instanciation du SDK anonyme, la génération des JWT requis, et les deux méthodes de chiffrement.

### Étape 2 — Obtenir les JWT depuis votre backend

Le chiffrement anonyme nécessite deux JWT distincts, tous deux générés par votre backend :

- **JWT de récupération des clés** (`scopes: [1]` — `PERMISSION_ANONYMOUS_FIND_KEYS`) : pas de `jti`, car la requête peut être paginée.
- **JWT de création de session** (`scopes: [0]` — `PERMISSION_ANONYMOUS_CREATE_SESSION`) : avec `jti` pour le rendre à usage unique.

Consultez le guide [Secrets JWT](/guides/public-cloud/seald/seald-jwt) pour les exemples de code backend complets.

> [!INFO]
> Même si un seul JWT peut techniquement couvrir les deux opérations, il est recommandé de créer deux JWT séparés afin de pouvoir définir un `jti` sur le JWT de création de session.

### Étape 3 — Chiffrer un fichier directement

Utilisez `anonymousSDK.encrypt` pour chiffrer en une seule opération :

```javascript
const { id, encryptedFile } = await anonymousSDK.encrypt({
  getKeysToken,
  encryptionToken,
  recipients: { sealdIds: [sealdIdUser1, sealdIdUser2] },
  clearFile: clearFileBuffer,
  filename: 'document.txt'
})
// id — sessionId de la session créée
// encryptedFile — fichier chiffré au même format que clearFile
```

### Étape 4 — Créer une session de chiffrement anonyme (optionnel)

Pour chiffrer plusieurs fichiers ou messages avec la même clé, créez une `AnonymousEncryptionSession` :

```javascript
const session = await anonymousSDK.createEncryptionSession({
  getKeysToken,
  encryptionToken,
  recipients: { sealdIds: [sealdIdUser1, sealdIdUser2] }
})

// Chiffrer un fichier
const encryptedFile = await session.encryptFile(clearFileBuffer, { filename: 'document.txt' })

// Chiffrer un message
const encryptedMessage = await session.encryptMessage('Message secret')
```

Les destinataires déchiffrent ensuite normalement avec leur instance de SDK complète.
