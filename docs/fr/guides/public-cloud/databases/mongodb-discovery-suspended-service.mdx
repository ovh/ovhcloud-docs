## Objectif

Le plan Discovery de Public Cloud Databases pour MongoDB (type de nœud `db2-free`) arrive en fin de vie. Les services Discovery sont suspendus le 31 octobre 2026, puis supprimés le 30 novembre 2026 avec toutes leurs données.

**Ce guide explique ce qui se passe quand votre service Discovery est suspendu, et comment le réactiver pour récupérer vos données ou le passer au plan Production avant sa suppression.**

## Prérequis

- Disposer d'un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Disposer d'un service MongoDB au plan Discovery
- Avoir accès à l'<ManagerLink to="/">espace client OVHcloud</ManagerLink> ou à l'<ApiLink>API OVHcloud</ApiLink>. Si vous n'avez jamais utilisé l'API OVHcloud, consultez le guide « [Premiers pas avec les API OVHcloud](/guides/manage-and-operate/api/first-steps) ».

[[cpnav:publiccloud-databases]]

## En pratique

### Calendrier

| Date | Ce qui se passe |
|---|---|
| 31 août 2026 | Fin de commercialisation : aucun nouveau service Discovery ne peut être créé. |
| 31 octobre 2026 | Suspension : les services Discovery sont arrêtés. Ils peuvent être réactivés sans frais supplémentaires, pour récupérer leurs données ou pour passer à un autre plan. |
| 30 novembre 2026 | Fin de vie : les services Discovery sont supprimés, avec toutes leurs données. |

### Comprendre l'état d'un service suspendu

Dans l'espace client, un service suspendu a le statut `Suspendu`. Tant qu'il est suspendu :

- vos applications ne peuvent plus s'y connecter ;
- ses données sont conservées, telles qu'elles étaient au moment de la suspension, jusqu'au 30 novembre 2026 ;
- vous ne pouvez pas modifier ses paramètres, ses utilisateurs ni ses adresses IP autorisées.

Vous avez alors 3 options :

- [réactiver le service](#réactiver-votre-service-pour-récupérer-vos-données) pour récupérer vos données, sans frais ;
- [passer le service au plan Production](#passer-votre-service-au-plan-production) pour le conserver avec ses données ;
- ne rien faire : le service et ses données sont [supprimés le 30 novembre 2026](#suppression-du-service).

### Réactiver votre service pour récupérer vos données

La réactivation est gratuite et redémarre votre service pour que vous puissiez exporter vos données.

<Tabs>
<Tab label="Espace client OVHcloud">

1. Sélectionnez votre service MongoDB, puis ouvrez l'onglet <code className="action">Configuration</code>.
2. Dans la section `Service`, cliquez sur <code className="action">Réactiver le service</code>.
3. Confirmez en cliquant sur <code className="action">Réactiver</code>.

Le statut du service passe à `Mise à jour`, puis à `Disponible` une fois la réactivation terminée. Cela prend quelques minutes.

</Tab>
<Tab label="API OVHcloud">

Récupérez l'identifiant de votre projet Public Cloud, aussi appelé `serviceName` :

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project"} />

Récupérez l'identifiant de votre service MongoDB, aussi appelé `clusterId` :

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/mongodb"} />

Réactivez le service avec l'appel API suivant :

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/mongodb/\{clusterId\}/unshelve"} />

L'appel ne prend pas de corps de requête. La réponse contient le service, au statut `UPDATING`. L'appel est refusé avec une erreur `409 Conflict` si le service n'est pas suspendu, par exemple pendant une réactivation déjà en cours.

Suivez le statut du service avec l'appel API suivant, jusqu'à ce qu'il soit `READY` :

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/mongodb/\{clusterId\}"} />

</Tab>
</Tabs>

### Récupérer vos données

Une fois réactivé, votre service retrouve :

- ses données, telles qu'elles étaient au moment de la suspension ;
- ses utilisateurs, avec leurs rôles et leurs mots de passe ;
- ses adresses IP autorisées ;
- les mêmes informations de connexion qu'avant la suspension.

Exportez vos données avec `mongodump` en suivant le guide « [Sauvegarder et restaurer un service avec la CLI pour Public Cloud Databases for MongoDB](/guides/public-cloud/databases/mongodb-howto-backup-restore) ».

Si un utilisateur ne parvient pas à s'authentifier, réinitialisez son mot de passe : ouvrez l'onglet <code className="action">Utilisateurs</code>, cliquez sur le bouton <code className="action">...</code> à droite de l'utilisateur, puis sur <code className="action">Regénérer le mot de passe</code>, et confirmez. Le nouveau mot de passe ne s'affiche qu'une fois : notez-le.

:::warning
Un service réactivé qui reste au plan Discovery peut être suspendu à nouveau chaque nuit à partir du 15 novembre 2026.

Récupérez vos données, ou passez le service au plan Production, dès la fin de la réactivation.

:::

### Passer votre service au plan Production

Vous pouvez passer un service suspendu au plan Production sans le réactiver d'abord. Le service est réactivé, puis migré vers le plan Production avec ses données, et il ne sera plus suspendu.

La facturation du plan Production démarre dès le changement de plan. Les prix sont disponibles sur la [page des prix Public Cloud](/links/public-cloud/prices).

<Tabs>
<Tab label="Espace client OVHcloud">

1. Sélectionnez votre service MongoDB, puis ouvrez l'onglet <code className="action">Configuration</code>.
2. Sur la ligne `Plan`, cliquez sur <code className="action">Modifier</code>.
3. Dans la fenêtre `Modifier le plan`, sélectionnez le plan <code className="action">Production</code>, puis cliquez sur <code className="action">Modifier</code>.

Le statut du service passe à `Mise à jour`, puis à `Disponible` une fois la migration terminée.

</Tab>
<Tab label="API OVHcloud">

Utilisez l'appel API suivant :

<Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\{serviceName\}/database/mongodb/\{clusterId\}"} />

Renseignez le corps de requête suivant :

```json
{
  "plan": "production",
  "flavor": "db2-2"
}
```

Pour plus d'informations sur les changements de plan, consultez le guide « [Mettre à jour le plan d'une base de données Public Cloud](/guides/public-cloud/databases/update-cluster-plan) ».

</Tab>
</Tabs>

Le changement de plan prend plus de temps qu'une réactivation : comptez environ 30 minutes. Votre service est alors un service Production avec des nœuds `db2-2`. Ses données, ses informations de connexion, ses utilisateurs, leurs mots de passe et ses adresses IP autorisées sont conservés.

### Suppression du service

Le 30 novembre 2026, les services Discovery sont supprimés, avec toutes leurs données. Une fois supprimées, les données ne peuvent pas être récupérées.

Si vous n'avez plus besoin de votre service ni de ses données, vous n'avez rien à faire. Pour supprimer le service avant le 30 novembre 2026, utilisez l'appel API suivant :

<Api version="v1" section="/cloud" method="DELETE" route={"/cloud/project/\{serviceName\}/database/mongodb/\{clusterId\}"} />

Si la réactivation ou le passage au plan Production échoue, [contactez le support OVHcloud](/links/support-contact).
