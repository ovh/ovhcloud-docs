## Objectif

Les bases de données as-a-service (DBaaS) d'OVHcloud vous permettent de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure de base de données et sa maintenance. 

**Ce guide explique comment restaurer la sauvegarde d'une solution de base de données dans la console OVHcloud.**

Nous améliorons continuellement nos offres. Vous pouvez suivre et proposer des idées à ajouter à notre roadmap sur [https://github.com/orgs/ovh/projects/16/views/5](https://github.com/orgs/ovh/projects/16/views/5).

## Prérequis

- Un [service de base de données Public Cloud](/links/public-cloud/databases) opérationnel

[[cpnav:publiccloud-databases]]

## En pratique

### Étape 1 : Sélectionnez le service de base de données à partir duquel vous voulez restaurer des données

Dans le menu de gauche de votre projet Public Cloud, cliquez sur votre moteur sous **Bases de données**, puis sur le nom du service à partir duquel vous souhaitez restaurer la sauvegarde.

### Étape 2 : Accédez à l'onglet des sauvegardes

Dans la liste des onglets, cliquez sur <code className="action">Sauvegardes</code>.

### Étape 3 : Sélectionnez la sauvegarde à partir de laquelle restaurer

Sélectionnez la sauvegarde à partir de laquelle vous voulez restaurer. Pour vous aider à choisir, observez les dates auxquelles les sauvegardes ont été effectuées.

Cliquez sur le bouton <code className="action">...</code> correspondant à la sauvegarde choisie, puis sur <code className="action">Dupliquer</code> pour ouvrir le panneau **Dupliquer un cluster**. Vous pouvez aussi cliquer sur le bouton <code className="action">Dupliquer</code> au-dessus de la liste.

:::warning
Certains moteurs, comme MongoDB, permettent aussi de restaurer une sauvegarde sur place, c'est-à-dire sur le même service (<code className="action">Restaurer une sauvegarde</code>). Cette option restaure TOUTES les données dans l'état où elles se trouvaient au moment de la sauvegarde. Cela peut entraîner une perte de données.
:::

### Étape 4 : Configurez le service cible

Comme vu précédemment, lorsque vous restaurez une sauvegarde, vous créez un nouveau service de base de données distinct sur lequel les données de la sauvegarde seront importées. Vous pouvez configurer ce nouveau service comme vous le souhaitez dans le panneau **Dupliquer un cluster**.

#### Nom

Renseignez le **Nom du nouveau cluster**.

#### Point de restauration

Dans **Source de la copie**, choisissez le point de restauration à partir duquel le service sera dupliqué :

- **À partir d’une sauvegarde** : l'option la plus courante, restaurer à partir d'une des sauvegardes listées (champ **Sauvegarde**).
- **Point dans le temps** : si votre service prend en charge la restauration à un instant donné (consultez le guide [Sauvegardes automatiques](/guides/public-cloud/databases/backups) pour plus de détails), restaurer à partir d'une date et d'une heure précises.
- **État le plus récent** : restaurer à partir des données les plus récentes.

#### Configuration du nouveau cluster

Vous ne pouvez pas changer de moteur. Dans la section **Configuration du nouveau cluster**, vous pouvez choisir la **Version**, une autre **Région**, une autre **Offre**, un **Type de nœud** plus grand, le **Nombre de nœuds** et du **Stockage** additionnel pour votre nouveau service.

:::info
Le type de nœud et le stockage ciblés doivent être suffisamment grands pour restaurer la sauvegarde.
:::

Le prix estimé du nouveau service est affiché en bas du panneau. Cliquez maintenant sur <code className="action">Créer la copie</code> et le nouveau service sera créé. Notez qu'en fonction de la taille de la sauvegarde, la mise à disposition du service peut prendre un certain temps.

### Étape 5 : Attendez la création du service

Il ne vous reste plus qu'à attendre que votre service soit prêt.
Ce nouveau service est désormais totalement indépendant de celui à partir duquel vous avez forké la sauvegarde. Vous pouvez supprimer en toute sécurité l'ancien service sans impacter le nouveau.

:::warning
Le service nouvellement créé ne duplique ni les restrictions IP ni les utilisateurs qui avaient été créés sur l'ancien service. Vous devrez les recréer avant d'utiliser votre nouveau service.

:::
