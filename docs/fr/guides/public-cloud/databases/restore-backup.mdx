## Objectif

Les bases de données as-a-service (DBaaS) d'OVHcloud vous permettent de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure de base de données et sa maintenance. 

**Ce guide explique comment restaurer la sauvegarde d'une solution de base de données dans l'espace client OVHcloud.**

Nous améliorons continuellement nos offres. Vous pouvez suivre et proposer des idées à ajouter à notre roadmap sur [https://github.com/orgs/ovh/projects/16/views/5](https://github.com/orgs/ovh/projects/16/views/5).

## Prérequis

- Un [service de base de données Public Cloud](/links/public-cloud/databases) opérationnel

## En pratique

### Étape 1 : Sélectionnez le service de base de données à partir duquel vous voulez restaurer des données

Tout d'abord, accédez à la page d'aperçu du service à partir duquel vous voulez restaurer la sauvegarde.

<img className="thumbnail" alt="Sélectionner le service" src="/images/public-cloud/databases/databases-06-restore-backup/service-selection-20230331.png" loading="lazy" />

### Étape 2 : Accédez à l'onglet des sauvegardes

Dans la liste des onglets, cliquez sur <code className="action">Backups</code>.

<img className="thumbnail" alt="Aperçu du service" src="/images/public-cloud/databases/databases-06-restore-backup/service-overview-20230331.png" loading="lazy" />

### Étape 3 : Sélectionnez la sauvegarde à partir de laquelle restaurer

Sélectionnez la sauvegarde à partir de laquelle vous voulez restaurer. Pour vous aider à choisir, observez les dates auxquelles les sauvegardes ont été effectuées dans la colonne « Date de création ».

Cliquez sur le bouton <code className="action">...</code> correspondant à la sauvegarde choisie. Cliquez ensuite sur <code className="action">Dupliquer (Fork)</code> pour accéder à la page de configuration du nouveau service.

:::warning
Le service MongoDB offre la possibilité de restaurer une sauvegarde sur place, c'est-à-dire de restaurer la sauvegarde sur le même service. Cette option restaure TOUTES les données dans l'état où elles se trouvaient au moment de la sauvegarde. Cela peut entraîner une perte de données.

:::


<img className="thumbnail" alt="Onglet des sauvegardes" src="/images/public-cloud/databases/databases-06-restore-backup/backup-tab-20230511.png" loading="lazy" />

### Étape 4 : Configurez le service cible

Comme vu précédemment, lors de la restauration d'une sauvegarde, vous créez un nouveau service de base de données distinct sur lequel les données de la sauvegarde seront importées. Vous pouvez configurer ce nouveau service comme vous le souhaitez.

#### Options immuables

Pour des raisons évidentes, vous ne pouvez pas modifier le moteur, cette option n'est pas proposée. Il en va de même pour la version du moteur, que vous pourrez mettre à jour une fois le nouveau service en cours d'exécution.

Vous trouverez un rappel de toutes ces options dans le résumé de la commande.

<img className="thumbnail" alt="Options immuables" src="/images/public-cloud/databases/databases-06-restore-backup/immutable-options.png" loading="lazy" />

#### Région

Vous pouvez choisir une région différente pour votre nouveau service.

<img className="thumbnail" alt="sélectionner tRégion" src="/images/public-cloud/databases/databases-06-restore-backup/selectRegion.png" loading="lazy" />

#### Point de restauration

Vous devez choisir un point de restauration à partir duquel le service sera dupliqué.

##### **Backup**

L'option la plus courante consiste à restaurer à partir d'une sauvegarde.

<img className="thumbnail" alt="Point de restauration depuis une sauvegarde" src="/images/public-cloud/databases/databases-06-restore-backup/restore-point-selection-backup.png" loading="lazy" />

##### **Date spécifique et dernière sauvegarde**

Si votre service prend en charge la restauration à un point dans le temps (Point In Time Recovery, voir le guide [Sauvegarde automatisée](/guides/public-cloud/databases/backups) pour plus de détails), vous aurez également la possibilité de restaurer à partir d'une date et d'une heure spécifiques.

<img className="thumbnail" alt="Point de restauration depuis une date spécifique" src="/images/public-cloud/databases/databases-06-restore-backup/restore-point-selection-date.png" loading="lazy" />

Vous aurez également la possibilité de choisir directement la date la plus récente.

<img className="thumbnail" alt="Point de restauration depuis la plus récente" src="/images/public-cloud/databases/databases-06-restore-backup/restore-point-selection-latest.png" loading="lazy" />

#### Plan

Lors de la restauration d'une sauvegarde, vous pouvez sélectionner un autre plan de service.

<img className="thumbnail" alt="Sélection du plan" src="/images/public-cloud/databases/databases-06-restore-backup/plan-selection-20230331.png" loading="lazy" />

#### Nœuds

Vous pouvez choisir de mettre à niveau le nœud vers un flavor plus important.

<img className="thumbnail" alt="Sélection du nœud" src="/images/public-cloud/databases/databases-06-restore-backup/node-selection-20230331.png" loading="lazy" />

:::info
La rétrogradation de flavor sera bientôt proposée. La limitation est que le flavor ciblé doit disposer d'un espace de stockage suffisant pour restaurer la sauvegarde.

:::


#### Dimensionnement

Du stockage supplémentaire peut être commandé lors du fork du service.

<img className="thumbnail" alt="Sélection du dimensionnement" src="/images/public-cloud/databases/databases-06-restore-backup/sizing-selection.png" loading="lazy" />

:::info
La réduction du stockage sera bientôt proposée. La limitation est que le stockage total ciblé doit être suffisamment important pour restaurer la sauvegarde.

:::


#### Options

Vous pouvez mettre à jour les options réseau.

<img className="thumbnail" alt="Sélection des options" src="/images/public-cloud/databases/databases-06-restore-backup/option-selection-20230331.png" loading="lazy" />

Cliquez maintenant sur <code className="action">Créer un fork</code> et le nouveau service sera créé. Notez que selon la taille de la sauvegarde, cela peut prendre un certain temps avant que le service soit disponible.

### Étape 5 : Attendez la création du service

Il ne vous reste plus qu'à attendre que votre service soit prêt.
Ce nouveau service est désormais totalement indépendant de celui à partir duquel vous avez forké la sauvegarde. Vous pouvez supprimer en toute sécurité l'ancien service sans impacter le nouveau.

:::warning
Le service nouvellement créé ne duplique ni les restrictions IP ni les utilisateurs qui avaient été créés sur l'ancien service. Vous devrez les recréer avant d'utiliser votre nouveau service.

:::


<img className="thumbnail" alt="Service forké" src="/images/public-cloud/databases/databases-06-restore-backup/forked-service-20230331.png" loading="lazy" />
