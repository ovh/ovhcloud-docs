## Objectif

Les bases de données managées Public Cloud vous permettent d'envoyer les logs de votre service vers votre propre flux de données Logs Data Platform (LDP).

**Ce guide explique comment transférer les logs de service vers votre propre flux LDP avec l'API OVHcloud.**

## Prérequis

- Un [service de base de données Public Cloud](/links/public-cloud/databases) opérationnel
- Un accès à l'<ApiLink>API OVHcloud</ApiLink>
- Un compte Logs Data Platform au sein de ce compte OVHcloud avec au moins un flux de destination configuré
    - Si vous n'êtes pas familier avec toutes les possibilités de configuration des *Stream* LDP, créez simplement un nouveau flux avec les options par défaut (indexation et websocket activés, stockage à long terme désactivé) pour les besoins de ce guide.
- Un service de base de données opérationnel

## En pratique

### Créez votre abonnement

<Tabs>
  <Tab label="Depuis l'espace client OVHcloud">
    Sur la page de l'instance de base de données, accédez à la section <code className="action">Logs</code> et cliquez sur le bouton <code className="action">S'abonner</code>.
    
    <img className="thumbnail" alt="Abonnement LDP de la base de données" src="/images/public-cloud/databases/databases-16-logs-to-customer/ldp_database_subscription.png" loading="lazy" />

Sélectionnez le compte LDP concerné en cliquant sur le bouton <code className="action">S'abonner</code>.
    
    <img className="thumbnail" alt="Abonnement LDP de la base de données 2" src="/images/public-cloud/databases/databases-16-logs-to-customer/ldp_database_subscription2.png" loading="lazy" />

Les logs commenceront alors à être transférés vers votre flux LDP.
  </Tab>
  <Tab label="Depuis l'API OVHcloud">
    1\. Récupérez les informations nécessaires
    
    **Récupérez le `streamId` de votre destination LDP :**
    
    Connectez-vous à l'<ManagerLink to="/">espace client OVHcloud</ManagerLink>, accédez à la section <code className="action">Identité, Sécurité & Opérations</code>. Dans le menu de gauche, sélectionnez <code className="action">Logs Data Platform</code> puis cliquez sur l'instance LDP concernée.
    
    <img className="thumbnail" alt="Page de liste LDP" src="/images/public-cloud/databases/databases-16-logs-to-customer/ldp_page.png" loading="lazy" />

Accédez à l'onglet <code className="action">Flux de données</code>.
    
    <img className="thumbnail" alt="Page de détails LDP" src="/images/public-cloud/databases/databases-16-logs-to-customer/ldp_page_details.png" loading="lazy" />

Choisissez votre flux cible et cliquez sur <code className="action">Copier l'identifiant du flux</code>.
    
    **Récupérez le `serviceName` de votre destination LDP :**
    
    - Il s'agit de l'ID de votre projet Public Cloud. Vous pouvez le récupérer dans la section Public Cloud de votre projet.
    
    <img className="thumbnail" alt="ID de projet LDP" src="/images/public-cloud/databases/databases-16-logs-to-customer/ldp_project_id.png" loading="lazy" />

**Récupérez votre `clusterId` :**
    
    Dans le menu de gauche, cliquez sur <code className="action">Databases</code>, puis choisissez l'instance de base de données que vous souhaitez gérer.
    
    Dans les détails du cluster, vous trouverez le champ `Service ID`, qui correspond à l'ID du cluster.
    
    <img className="thumbnail" alt="Détails LDP de la base de données" src="/images/public-cloud/databases/databases-16-logs-to-customer/ldp_database_details.png" loading="lazy" />
    
    2\. Commencez par récupérer les types de logs disponibles pour votre cluster de base de données avec l'appel API suivant :
    
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/database/mysql/\\{clusterId\\}/log/kind"} />

Remplacez `mysql` dans la route par le moteur de votre service (par exemple `postgresql` ou `mongodb`).

Cela renverra la liste des valeurs kind valides que vous pouvez utiliser lors de l'abonnement aux logs.
    
    3\. Une fois le kind valide connu, utilisez-le pour vous abonner à un flux de logs avec cet appel API :
    
    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/database/mysql/\\{clusterId\\}/log/subscription"} />

```console
    body : {
        kind: <log_type_from_previous_call>
        streamId: <your_stream_id>
    }
    ```
    
    Les logs commenceront alors à être transférés vers votre flux LDP.
  </Tab>
</Tabs>


### Retrouver les logs dans Graylog

Sur la page LDP, cliquez sur le bouton <code className="action">sample-data-stream</code> (le dernier flux de données modifié lors de votre précédent abonnement), ou cliquez sur le bouton <code className="action">Graylog</code>.

<img className="thumbnail" alt="Base de données LDP - accès à Graylog" src="/images/public-cloud/databases/databases-16-logs-to-customer/ldp_database_go_to_graylogs.png" loading="lazy" />

Vous devez vous connecter à l'aide de vos identifiants Graylog. Vous pouvez les récupérer depuis la page de détails LDP, dans la section `Configuration`. L'identifiant de connexion correspond à la valeur affichée sur la ligne `Logs Data Platform service`, et le mot de passe est affiché sous `Password`.

<img className="thumbnail" alt="Base de données LDP - détails LDP" src="/images/public-cloud/databases/databases-16-logs-to-customer/ldp_database_ldp_details.png" loading="lazy" />

Une fois connecté, vous pouvez consulter les logs de votre service dans votre flux Graylog.

<img className="thumbnail" alt="Base de données LDP - résultat Graylog" src="/images/public-cloud/databases/databases-16-logs-to-customer/ldp_database_graylogs_result.png" loading="lazy" />

Vous pouvez également utiliser les requêtes Graylog suivantes pour un filtrage plus précis :

#### MongoDB

Requête : `cluster: "<HostID>"`

Vous pouvez trouver ce `HostID` dans votre espace client OVHcloud :

- Dans `Login information`, changez `Service` en `mongodb`
- Vous pouvez maintenant voir le champ `Host` au format `<HostID>.database.cloud.ovh.net`

#### Autres moteurs

Requête : `clusterID: "<Engine>-<HostID>"`

Vous pouvez trouver ce `HostID` dans votre espace client OVHcloud :

- Trouvez l'ID du cluster au format UUID (AAAAAAAA-BBBB-CCCC-DDDDDDDDDDDD)
- `HostID` correspond à la première partie de l'UUID (AAAAAAAA)

### Supprimer un abonnement

Vous disposez de 2 méthodes pour supprimer un abonnement :

<Tabs>
  <Tab label="Depuis l'espace client OVHcloud">
    Sur la page d'abonnement de l'instance de base de données, cliquez sur le bouton <code className="action">Se désabonner</code>.
    
    <img className="thumbnail" alt="Désabonnement LDP de la base de données" src="/images/public-cloud/databases/databases-16-logs-to-customer/ldp_database_unsubscribe.png" loading="lazy" />
  </Tab>
  <Tab label="Depuis l'API OVHcloud">
    - Vous pouvez supprimer des abonnements à l'aide du `subscriptionId` concerné dans cet appel API :
    
    <Api version="v1" section="/cloud" method="DELETE" route={"/cloud/project/\\{serviceName\\}/database/mysql/\\{clusterId\\}/log/subscription/\\{subscriptionId\\}"} />
  </Tab>
</Tabs>


- Si vous supprimez votre service de base de données, tous les abonnements de ce service sont automatiquement supprimés.
