## Objectif

Ce guide liste tous les paramètres avancés pris en charge qui vous permettent de configurer votre service Public Cloud Databases pour MySQL selon vos cas d'usage.

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud.
- Une base de données fonctionnant sur votre service Public Cloud Databases OVHcloud ([ce guide](/guides/public-cloud/databases/getting-started) peut vous aider à répondre à ce prérequis).
- Un accès à votre <ManagerLink to="/">espace client OVHcloud</ManagerLink> ou à l'<ApiLink>API OVHcloud</ApiLink>.

## En pratique

:::warning
La gestion des paramètres avancés n'est pas prise en charge via Terraform.

:::


### Depuis l'espace client OVHcloud

Veuillez consulter ce [guide](/guides/public-cloud/databases/advanced-configuration#depuis-lespace-client-ovhcloud) pour savoir comment modifier vos paramètres avancés depuis l'espace client OVHcloud.

### Depuis l'API

Veuillez consulter ce [guide](/guides/public-cloud/databases/advanced-configuration#depuis-lapi) pour savoir comment modifier vos paramètres avancés depuis l'API OVHcloud.

### Paramètres avancés pour MySQL

Vous trouverez ci-dessous les paramètres avancés disponibles pour un service MySQL :

:::info
Le tableau ci-dessous liste les paramètres avancés disponibles pour un service MySQL. Votre service affiche la liste exacte, avec les valeurs autorisées, dans l'onglet <code className="action">Configuration</code> de l'espace client et via l'API.

`mysql.lower_case_table_names` ne peut être défini qu'à la création du service.
:::


| Parameters |
|------------|
|**binlog_retention_period** `long`<br/>min: `600` max: `9007199254740991`<br/>Attention : réduire cette valeur peut rendre un grand nombre de journaux binaires éligibles à la purge en une seule fois. Selon le volume, cela peut parfois bloquer le processus de commit de MySQL et empêcher les écritures jusqu'à la fin de la purge. Par précaution, privilégiez une diminution progressive de la valeur, par petits paliers et pendant une période de faible trafic, plutôt qu'une baisse brutale en une seule étape.<br/>|
|**mysql.automatic_sp_privileges** `boolean`<br/>Lorsque cette option est activée, le serveur accorde automatiquement les privilèges EXECUTE et ALTER ROUTINE au créateur d'une routine stockée, et les révoque lorsque la routine est supprimée.<br/>|
|**mysql.connect_timeout** `long`<br/>min: `2` max: `3600`<br/>Le nombre de secondes pendant lesquelles le serveur mysqld attend un paquet de connexion avant de répondre par Bad handshake.<br/>|
|**mysql.default_time_zone** `string`<br/>Fuseau horaire par défaut du serveur, exprimé sous forme de décalage par rapport à UTC (de -12:00 à +12:00), d'un nom de fuseau horaire, ou de 'SYSTEM' pour utiliser le fuseau horaire par défaut du serveur MySQL.<br/>|
|**mysql.div_precision_increment** `long`<br/>min: `0` max: `30`<br/>Nombre de chiffres dont l'échelle du résultat des divisions effectuées avec l'opérateur / est augmentée. La valeur par défaut est 4.<br/>|
|**mysql.end_markers_in_json** `boolean`<br/>Indique si la sortie JSON de l'optimiseur, comme EXPLAIN FORMAT=JSON, ajoute des marqueurs de fin qui répètent la clé d'une structure près de son accolade fermante, ce qui facilite la lecture des structures JSON volumineuses.<br/>|
|**mysql.eq_range_index_dive_limit** `long`<br/>min: `0` max: `4294967295`<br/>Le nombre de plages d'égalité dans une requête à partir duquel l'optimiseur passe des index dives aux statistiques d'index pour estimer le nombre de lignes concernées. 0 signifie que les index dives sont toujours utilisés. La valeur par défaut est 200.<br/>|
|**mysql.group_concat_max_len** `long`<br/>min: `4` max: `18446744073709552000`<br/>La longueur maximale autorisée, en octets, pour le résultat de la fonction GROUP_CONCAT().<br/>|
|**mysql.information_schema_stats_expiry** `long`<br/>min: `900` max: `31536000`<br/>Le délai, en secondes, avant l'expiration des statistiques mises en cache.<br/>|
|**mysql.innodb_adaptive_hash_index** `boolean`<br/>Indique si l'indexation par hachage adaptatif d'InnoDB est activée. Le réglage optimal dépend de la charge de travail : elle accélère les recherches pour certaines charges, mais son verrou interne peut devenir un point de contention en cas de forte concurrence ; la désactiver peut alors améliorer le débit.<br/>|
|**mysql.innodb_change_buffer_max_size** `long`<br/>min: `0` max: `50`<br/>Taille maximale du buffer de modification InnoDB, exprimée en pourcentage de la taille totale du pool de buffers. La valeur par défaut est 25.<br/>|
|**mysql.innodb_flush_neighbors** `long`<br/>min: `0` max: `2`<br/>Indique si le vidage d'une page du pool de buffers InnoDB entraîne également le vidage d'autres pages modifiées dans le même extent (la valeur par défaut est 1) : 0 - les pages modifiées du même extent ne sont pas vidées, 1 - vide les pages modifiées contiguës du même extent, 2 - vide les pages modifiées du même extent.<br/>|
|**mysql.innodb_ft_enable_stopword** `boolean`<br/>Indique si le traitement des mots vides (stopwords) est appliqué lors de la création ou de la reconstruction d'un index FULLTEXT InnoDB. Activé par défaut.<br/>|
|**mysql.innodb_ft_max_token_size** `long`<br/>min: `10` max: `84`<br/>Longueur maximale des mots stockés dans un index FULLTEXT InnoDB.<br/>|
|**mysql.innodb_ft_min_token_size** `long`<br/>min: `0` max: `16`<br/>Longueur minimale des mots stockés dans un index FULLTEXT InnoDB. La modification de ce paramètre entraînera un redémarrage du service MySQL.<br/>|
|**mysql.innodb_ft_num_word_optimize** `long`<br/>min: `1000` max: `10000`<br/>Nombre de mots traités lors de chaque opération OPTIMIZE TABLE sur un index FULLTEXT InnoDB. La valeur par défaut est 2000.<br/>|
|**mysql.innodb_ft_result_cache_limit** `long`<br/>min: `1000000` max: `4294967295`<br/>Mémoire maximale, en octets, utilisée par requête pour le cache de résultats des recherches FULLTEXT InnoDB. Cette valeur est dimensionnée automatiquement en fonction de la mémoire de votre offre ; définir une valeur remplace la valeur par défaut calculée.<br/>|
|**mysql.innodb_ft_server_stopword_table** `string`<br/>Cette option permet de spécifier votre propre liste de mots vides (stopwords) pour l'index FULLTEXT InnoDB, pour toutes les tables InnoDB.<br/>|
|**mysql.innodb_ft_user_stopword_table** `string`<br/>Cette option permet de spécifier votre propre liste de mots vides (stopwords) pour l'index FULLTEXT InnoDB, pour des tables InnoDB spécifiques.<br/>|
|**mysql.innodb_io_capacity** `long`<br/>min: `100` max: `4294967295`<br/>Le nombre d'opérations d'E/S par seconde (IOPS) disponibles pour les tâches d'arrière-plan d'InnoDB, comme le vidage des pages du pool de buffers et la fusion des données du buffer de modification. Définissez une valeur adaptée au stockage sous-jacent ; elle ne doit pas dépasser innodb_io_capacity_max.<br/>|
|**mysql.innodb_io_capacity_max** `long`<br/>min: `100` max: `4294967295`<br/>Le nombre maximal d'opérations d'E/S par seconde (IOPS) que les tâches d'arrière-plan d'InnoDB peuvent effectuer lorsque le vidage prend du retard. La valeur par défaut est le double de innodb_io_capacity (2000 au minimum). Cette valeur doit être supérieure ou égale à innodb_io_capacity.<br/>|
|**mysql.innodb_lock_wait_timeout** `long`<br/>min: `1` max: `3600`<br/>La durée, en secondes, pendant laquelle une transaction InnoDB attend un verrou de ligne avant d'abandonner. La valeur par défaut est 120.<br/>|
|**mysql.innodb_log_buffer_size** `long`<br/>min: `1048576` max: `4294967296`<br/>La taille en octets du buffer qu'InnoDB utilise pour écrire dans les fichiers de log sur le disque. Les valeurs supérieures à 15 % de la RAM fournie par votre offre sont refusées, car un buffer plus grand laisse moins de mémoire pour le pool de buffers et les connexions clientes.<br/>|
|**mysql.innodb_max_dirty_pages_pct** `double`<br/>min: `5` max: `99`<br/>Pourcentage de pages modifiées dans le pool de buffers InnoDB à partir duquel InnoDB commence un vidage intensif. Réduire cette valeur répartit plus uniformément les E/S d'écriture et raccourcit la reprise après incident, au prix du vidage de pages qui auraient pu être modifiées à nouveau. Doit rester supérieur ou égal à innodb_max_dirty_pages_pct_lwm. La valeur par défaut est 90.<br/>|
|**mysql.innodb_max_dirty_pages_pct_lwm** `double`<br/>min: `0` max: `99`<br/>Pourcentage de pages modifiées dans le pool de buffers InnoDB à partir duquel InnoDB commence un pré-vidage, afin d'éviter que le taux de pages modifiées n'atteigne innodb_max_dirty_pages_pct. 0 désactive le pré-vidage. Ne peut pas être supérieur à innodb_max_dirty_pages_pct. La valeur par défaut est 10.<br/>|
|**mysql.innodb_max_purge_lag** `long`<br/>min: `0` max: `4294967295`<br/>Nombre de transactions en attente dont l'opération de purge InnoDB peut prendre du retard avant que les INSERT, UPDATE et DELETE ne soient ralentis pour lui permettre de rattraper ce retard. Le délai s'applique par ligne et augmente avec le retard ; il est plafonné par innodb_max_purge_lag_delay, qui doit également être défini pour que cette option ait un effet. La valeur par défaut est 0, ce qui n'entraîne jamais aucun délai.<br/>|
|**mysql.innodb_max_purge_lag_delay** `long`<br/>min: `0` max: `10000000`<br/>Plafond, en microsecondes, du délai par ligne que innodb_max_purge_lag applique aux INSERT, UPDATE et DELETE. MySQL limite systématiquement le délai à cette valeur : tant qu'elle vaut 0, aucun délai n'est appliqué et innodb_max_purge_lag seul n'a aucun effet. Les deux options doivent être différentes de zéro pour que l'une ou l'autre prenne effet. La valeur par défaut est 0.<br/>|
|**mysql.innodb_online_alter_log_max_size** `long`<br/>min: `65536` max: `1099511627776`<br/>La limite supérieure, en octets, de la taille des fichiers de log temporaires utilisés lors des opérations DDL en ligne sur les tables InnoDB.<br/>|
|**mysql.innodb_optimize_fulltext_only** `boolean`<br/>Lorsque cette option est activée, OPTIMIZE TABLE sur les tables InnoDB met uniquement à jour l'index FULLTEXT au lieu de reconstruire la table. Elle est destinée à être activée temporairement pendant la maintenance des index FULLTEXT, puis désactivée ; tant qu'elle est activée, OPTIMIZE TABLE ne récupère pas l'espace de la table.<br/>|
|**mysql.innodb_print_all_deadlocks** `boolean`<br/>Lorsque cette option est activée, les informations relatives à tous les interblocages (deadlocks) dans les transactions utilisateur InnoDB sont enregistrées dans le journal d'erreurs. Désactivé par défaut.<br/>|
|**mysql.innodb_read_io_threads** `long`<br/>min: `1` max: `64`<br/>Le nombre de threads d'E/S pour les opérations de lecture dans InnoDB. La valeur par défaut est 4. La modification de ce paramètre entraînera un redémarrage du service MySQL.<br/>|
|**mysql.innodb_rollback_on_timeout** `boolean`<br/>Lorsque cette option est activée, un dépassement de délai de transaction entraîne l'abandon et l'annulation complète de la transaction par InnoDB. La modification de ce paramètre entraînera un redémarrage du service MySQL.<br/>|
|**mysql.innodb_thread_concurrency** `long`<br/>min: `0` max: `1000`<br/>Définit le nombre maximal de threads autorisés dans InnoDB. La valeur par défaut est 0 (concurrence infinie - aucune limite).<br/>|
|**mysql.innodb_write_io_threads** `long`<br/>min: `1` max: `64`<br/>Le nombre de threads d'E/S pour les opérations d'écriture dans InnoDB. La valeur par défaut est 4. La modification de ce paramètre entraînera un redémarrage du service MySQL.<br/>|
|**mysql.interactive_timeout** `long`<br/>min: `30` max: `604800`<br/>Le nombre de secondes pendant lesquelles le serveur attend une activité sur une connexion interactive avant de la fermer.<br/>|
|**mysql.internal_tmp_mem_storage_engine** `string`<br/>values: `MEMORY`, `TempTable`<br/>Le moteur de stockage pour les tables temporaires internes en mémoire.<br/>|
|**mysql.log_output** `string`<br/>values: `NONE`, `TABLE`<br/>La destination de sortie du journal des requêtes lentes lorsque slow_query_log est activé (ON). Pour stocker les requêtes lentes dans la table mysql.slow_log, choisissez TABLE. Pour désactiver les journaux de requêtes lentes, choisissez NONE.<br/>|
|**mysql.long_query_time** `double`<br/>min: `0` max: `3600`<br/>Les slow_query_logs fonctionnent pour les instructions SQL dont l'exécution prend plus de long_query_time secondes.<br/>|
|**mysql.lower_case_table_names** `long`<br/>values: `0`, `1`<br/>Définit la manière dont les noms de tables et de bases de données sont stockés et comparés. 0 = sensible à la casse (par défaut), 1 = noms stockés en minuscules, comparaisons insensibles à la casse. Cette option ne peut être définie qu'à la création du service et ne peut pas être modifiée par la suite. Consultez https://dev.mysql.com/doc/refman/8.4/en/identifier-case-sensitivity.html pour plus de détails.<br/>|
|**mysql.max_allowed_packet** `long`<br/>min: `102400` max: `1073741824`<br/>Taille, en octets, du plus grand message pouvant être reçu par le serveur. La valeur par défaut est 67108864 (64M). Les instructions et les lignes dépassant cette taille sont rejetées avec une erreur de paquet trop volumineux (packet too large).<br/>|
|**mysql.max_connections** `long`<br/>min: `30` max: `100000`<br/>Le nombre maximal de connexions clientes simultanées autorisées. Réduisez cette valeur pour réserver de la mémoire à d'autres usages. La valeur ne peut pas dépasser la limite fournie par votre offre. Passer à une offre supérieure n'augmente pas une valeur que vous avez définie explicitement : augmentez-la vous-même après le changement d'offre.<br/>|
|**mysql.max_execution_time** `long`<br/>min: `0` max: `4294967295`<br/>Délai d'exécution maximal, en millisecondes, pour les instructions SELECT de premier niveau en lecture seule. 0 (la valeur par défaut) signifie aucun délai.<br/>|
|**mysql.max_heap_table_size** `long`<br/>min: `1048576` max: `1073741824`<br/>Limite la taille des tables internes en mémoire. Définit également tmp_table_size. La valeur par défaut est 16777216 (16M).<br/>|
|**mysql.max_seeks_for_key** `long`<br/>min: `1` max: `18446744073709552000`<br/>Limite du nombre maximal supposé de recherches d'index lors de la recherche de lignes à partir d'une clé. Réduire cette valeur amène l'optimiseur à privilégier les recherches par index plutôt que les parcours de table complets.<br/>|
|**mysql.max_user_connections** `long`<br/>min: `0` max: `99990`<br/>Le nombre maximal de connexions simultanées autorisées pour un même compte utilisateur. 0, la valeur par défaut, signifie aucune limite par compte. Toute autre valeur doit être inférieure d'au moins 10 à max_connections, afin que la supervision et vos propres sessions d'administration puissent toujours se connecter lorsqu'une application atteint sa propre limite. Les connexions de réplication et de gestion du service ne sont pas concernées, quelle que soit la valeur définie.<br/>|
|**mysql.net_buffer_length** `long`<br/>min: `1024` max: `1048576`<br/>Tailles initiales du buffer de connexion et du buffer de résultat. La valeur par défaut est 16384 (16K). La modification de ce paramètre entraînera un redémarrage du service MySQL.<br/>|
|**mysql.net_read_timeout** `long`<br/>min: `1` max: `3600`<br/>Le nombre de secondes à attendre pour recevoir davantage de données d'une connexion avant d'interrompre la lecture.<br/>|
|**mysql.net_write_timeout** `long`<br/>min: `1` max: `3600`<br/>Le nombre de secondes à attendre pour qu'un bloc soit écrit sur une connexion avant d'interrompre l'écriture.<br/>|
|**mysql.optimizer_prune_level** `long`<br/>min: `0` max: `1`<br/>Contrôle les heuristiques appliquées lors de l'optimisation des requêtes pour écarter de l'espace de recherche de l'optimiseur les plans partiels les moins prometteurs. 0 désactive les heuristiques (recherche exhaustive) ; 1 écarte les plans en fonction du nombre de lignes récupérées.<br/>|
|**mysql.optimizer_search_depth** `long`<br/>min: `0` max: `62`<br/>Profondeur maximale de la recherche effectuée par l'optimiseur de requêtes lors du choix de l'ordre des jointures. Des valeurs élevées produisent de meilleurs plans pour les jointures portant sur de nombreuses tables, mais allongent la compilation ; 0 laisse l'optimiseur choisir la profondeur automatiquement.<br/>|
|**mysql.optimizer_switch** `string`<br/>Liste, séparée par des virgules, d'affectations d'indicateurs de l'optimiseur sous la forme flag=on|off|default, ou la valeur unique 'default' pour réinitialiser tous les indicateurs. Les indicateurs non listés conservent leur valeur actuelle. Contrôle des comportements de l'optimiseur de requêtes comme l'index merge, le hash join et les stratégies de semi-jointure.<br/>|
|**mysql.performance_schema_events_statements_history_size** `long`<br/>min: `0` max: `1024`<br/>Le nombre de lignes par thread dans la table events_statements_history.<br/>|
|**mysql.relay_log_space_limit** `long`<br/>min: `134217728` max: `18446744073709552000`<br/>L'espace maximal, en octets, utilisé par l'ensemble des relay logs lors de la réplication depuis une source de migration externe. Lorsque cette limite est atteinte, le thread d'E/S de réplication cesse de récupérer les événements du relay log jusqu'à ce que le thread SQL ait rattrapé son retard. Augmentez cette valeur pour accorder davantage d'espace de relay log à une migration volumineuse, en vous assurant que le disque du service est dimensionné en conséquence. Ce paramètre s'applique uniquement au nœud qui réplique depuis la source externe ; les nœuds de secours utilisent toujours la valeur par défaut (la plus petite valeur entre 5 Gio et 30 % du disque du service), qui est également utilisée lorsque cette option n'est pas définie.<br/>|
|**mysql.slow_query_log** `boolean`<br/>Le journal des requêtes lentes permet de capturer les requêtes lentes. Définir slow_query_log sur false vide également la table mysql.slow_log.<br/>|
|**mysql.sort_buffer_size** `long`<br/>min: `32768` max: `1073741824`<br/>Taille du buffer de tri en octets pour l'optimisation ORDER BY. La valeur par défaut est 262144 (256K). Les valeurs supérieures à 2 % de la RAM fournie par votre offre sont refusées, car le buffer est alloué par session et son coût est multiplié par le nombre de connexions.<br/>|
|**mysql.sql_mode** `string`<br/>Mode SQL global. Laisser vide pour utiliser les valeurs par défaut du serveur MySQL. Lors de la création d'un nouveau service sans définir ce champ, un mode SQL par défaut (strict, conforme au standard SQL) est attribué.<br/>|
|**mysql.sql_require_primary_key** `boolean`<br/>Exige la définition d'une clé primaire pour les nouvelles tables ou pour les anciennes tables modifiées avec ALTER TABLE, et échoue si elle est absente. Il est recommandé de toujours définir des clés primaires, car diverses fonctionnalités peuvent être compromises si une table volumineuse en est dépourvue.<br/>|
|**mysql.tmp_table_size** `long`<br/>min: `1048576` max: `1073741824`<br/>Limite la taille des tables internes en mémoire. Définit également max_heap_table_size. La valeur par défaut est 16777216 (16M).<br/>|
|**mysql.wait_timeout** `long`<br/>min: `1` max: `2147483`<br/>Le nombre de secondes pendant lesquelles le serveur attend une activité sur une connexion non interactive avant de la fermer. Les valeurs inférieures à 30 sont refusées, car un délai plus court fermerait vos propres connexions inactives entre deux instructions.<br/>|
|**mysql.windowing_use_high_precision** `boolean`<br/>Indique si les fonctions de fenêtrage sont calculées avec une haute précision. Désactiver cette option privilégie la vitesse au détriment de l'exactitude lors de l'évaluation des fonctions de fenêtrage.<br/>|
