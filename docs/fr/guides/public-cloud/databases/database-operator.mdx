## Objectif

L'opérateur de base de données Kubernetes vous permet d'autoriser automatiquement l'IP de votre cluster Kubernetes sur votre service de bases de données Public Cloud OVHcloud.

**Ce guide explique comment installer et utiliser l'opérateur de base de données afin d'autoriser l'IP Kubernetes sur votre service**

## Prérequis

- Un accès à l'<ApiLink>API OVHcloud</ApiLink>. Créez vos identifiants à l'aide de notre guide [Premiers pas avec l'API OVHcloud](/guides/manage-and-operate/api/first-steps).
- Un [projet Public Cloud](/guides/public-cloud/cross-functional/create-a-public-cloud-project) dans votre compte OVHcloud

### Récupérer les informations de vos tokens API OVHcloud

Afin de générer votre API OVHcloud, veuillez suivre notre tutoriel [Premiers pas avec les API OVHcloud](/guides/manage-and-operate/api/first-steps).

Plus précisément, vous devez générer ces identifiants via la <CreateToken rights="GET=/cloud/project/*/database/*&POST=/cloud/project/*/database/*&PUT=/cloud/project/*/database/*&DELETE=/cloud/project/*/database/*">page de génération de tokens OVHcloud</CreateToken> avec les droits suivants :

- `GET /cloud/project/*/database/*`
- `POST /cloud/project/*/database/*`
- `PUT /cloud/project/*/database/*`
- `DELETE /cloud/project/*/database/*`

## En pratique

L'opérateur de base de données Kubernetes est stocké sous forme de chart Helm sur [Docker Hub](https://hub.docker.com/r/ovhcom/public-cloud-databases-operator/tags), un registre OCI.

### Valeurs Helm

La première étape consiste à créer un fichier `values.yaml`. 

Veuillez remplacer les `XXXX` par les identifiants récupérés précédemment.

Notez que la valeur de région est soit `ovh-eu`, soit `ovh-ca`, soit `ovh-us`.

```yaml
ovhCredentials:
  applicationKey: XXXX
  applicationSecret: XXXX
  consumerKey: XXXX
  region: ovh-eu # ovh-eu, ovh-ca or ovh-us

namespace: ovhcloud # Your Kubernetes namespace
```

### Installation

Utilisez le gestionnaire de paquets Kubernetes [helm](https://helm.sh) et le fichier de valeurs que vous avez créé pour installer l'opérateur.

```bash
helm install -f values.yaml public-cloud-databases-operator oci://registry-1.docker.io/ovhcom/public-cloud-databases-operator --version 0.1.1
```

Cette commande créera l'opérateur, les CRD et les objets secrets.

Vous trouverez la dernière version du chart Helm sur [DockerHub](https://hub.docker.com/r/ovhcom/public-cloud-databases-operator/tags).

Vous pouvez vérifier que l'opérateur est correctement installé en vérifiant les Pods dans le nouveau namespace Kubernetes :

```bash
kubectl get deploy -n ovhcloud
NAME                              READY   UP-TO-DATE   AVAILABLE   AGE
public-cloud-databases-operator   1/1     1            1           60m
```

Et que le secret contenant vos identifiants OVHcloud est correctement créé :

```bash
kubectl get secret ovh-credentials -n ovhcloud
NAME              TYPE     DATA   AGE
ovh-credentials   Opaque   4      60m
```

### Création de ressources personnalisées

Créez un objet de ressource personnalisée :

```yaml
apiVersion: cloud.ovh.net/v1alpha1
kind: Database
metadata:
  name: mydatabase
  namespace: ovhcloud
spec:
  projectId: XXXX # ID of your Public Cloud project ID
  serviceId: XXX # ID of your Public Cloud Databases service
```

Ou avec un sélecteur de labels pour choisir précisément vos nœuds en fonction d'un label :

```yaml
apiVersion: cloud.ovh.net/v1alpha1
kind: Database
metadata:
  name: mydatabase
  namespace: ovhcloud
spec:
  projectId: XXXX # ID of your Public Cloud project ID
  serviceId: XXX # ID of your Public Cloud Databases service
  labelSelector:
    matchLabels:
      LABELNAME: LABELVALUE
```

Le champ `serviceId` est facultatif. S'il n'est pas défini, l'opérateur s'exécutera sur tous les services de votre projet.

Appliquez-le au cluster :

```bash
kubectl apply -f cr.yaml
```

Vous pouvez vérifier qu'il a été correctement créé à l'aide de cette commande :
```bash
kubectl kubectl -n ovhcloud get database
NAME                              AGE
public-cloud-databases-operator   59m
```

### Labels des nœuds

Vous pouvez utiliser le labeling Kubernetes afin de sélectionner des nœuds spécifiques sur lesquels vous souhaitez que l'opérateur s'exécute.

La ressource personnalisée créée et le nœud doivent avoir le même label et la même valeur.

```bash
kubectl label nodes NODENAME1 NODENAME2 ... LABELNAME=LABELVALUE
```
