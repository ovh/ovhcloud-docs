## Objectif

Cette documentation vise à fournir une approche complète de la migration de base de données MongoDB, garantissant l'intégrité des données, un temps d'indisponibilité minimal et des performances optimales. Que vous migriez :

- d'une instance MongoDB vers une nouvelle instance MongoDB OVHcloud.
- de n'importe quelle base de données de type Document DB vers une instance MongoDB OVHcloud.

Ce guide couvre les outils et processus essentiels nécessaires à la réussite d'une migration.

## Outils de migration

### Outils avec temps d'indisponibilité prévu

Ces outils sont utilisés lors de processus de migration impliquant un certain temps d'indisponibilité prévu.

#### 1. mongodump

[mongodump](https://www.mongodb.com/docs/database-tools/mongodump/) est un utilitaire permettant de créer un export binaire du contenu d'une base de données MongoDB. Il est particulièrement utile pour sauvegarder des bases de données et migrer des données entre instances MongoDB.

Utilisez l'option [--dumpDbUsersAndRoles](https://www.mongodb.com/docs/database-tools/mongodump/#std-option-mongodump.--dumpDbUsersAndRoles) pour inclure les définitions d'utilisateurs et de rôles dans le répertoire de dump de la base de données lors de l'exécution de mongodump sur une base de données spécifique. Cette option ne s'applique que lorsque vous spécifiez une base de données via l'option --db.

#### 2. mongorestore

[mongorestore](https://www.mongodb.com/docs/database-tools/mongorestore/) complète mongodump en vous permettant de restaurer un dump binaire créé par mongodump. Cet outil est essentiel pour restaurer des données sur une instance MongoDB.

Utilisez l'option [restoreDbUsersAndRole](https://www.mongodb.com/docs/database-tools/mongorestore/#std-option-mongorestore.--restoreDbUsersAndRoles) pour restaurer les définitions d'utilisateurs et de rôles de la base de données concernée. Restaurer la base de données admin en spécifiant `--db admin` à mongorestore restaure déjà tous les utilisateurs et rôles.

### Outils avec temps d'indisponibilité minimal

Ces outils sont conçus pour minimiser le temps d'indisponibilité pendant le processus de migration.

#### 1. mongosync

Le binaire [mongosync](https://www.mongodb.com/docs/cluster-to-cluster-sync/current/reference/mongosync/) est le processus principal utilisé pour la synchronisation cluster à cluster. Il fournit une synchronisation de données continue et unidirectionnelle entre des clusters MongoDB situés dans le même environnement ou dans des environnements différents. Consultez les [limitations](https://www.mongodb.com/docs/cluster-to-cluster-sync/current/reference/limitations/) de mongosync avant de démarrer la migration.

#### 2. MongoDB Kafka Connector

[MongoDB Kafka Connector](https://www.mongodb.com/docs/kafka-connector/current/) vous permet d'intégrer MongoDB avec Apache Kafka, permettant une synchronisation des données en temps réel et minimisant le temps d'indisponibilité pendant les migrations en diffusant directement les modifications de données vers MongoDB.

## 1. Préparation

### Évaluer l'environnement actuel

- **Collecte de métriques** : collectez les métriques actuelles telles que l'utilisation du CPU, la RAM, les IOPS, l'espace disque et l'utilisation du réseau. Cela vous aidera à choisir la taille de cluster OVHcloud appropriée.
- **Sauvegarde** : créez une sauvegarde complète de votre instance MongoDB actuelle.

### Sélectionner un plan OVHcloud

- En fonction des métriques collectées (CPU, RAM, IOPS disque, espace disque, etc.), choisissez un plan OVHcloud qui répond ou est supérieur aux spécifications actuelles de votre instance MongoDB.
- Tenez compte des besoins futurs en matière de croissance et d'évolutivité. Vous pouvez consulter notre guide sur [comment dimensionner un cluster MongoDB](/guides/public-cloud/databases/mongodb-cluster-sizing).

## 2. Configurer le cluster OVHcloud

- **Créer le cluster** : [configurez le nouveau cluster MongoDB managé OVHcloud](/guides/public-cloud/databases/mongodb-getting-started).
- **Configuration** : configurez les paramètres du cluster OVHcloud pour qu'ils correspondent le plus fidèlement possible à la configuration de votre cluster MongoDB actuel.

## 3. Outils de migration de données

Utilisez l'un des outils mentionnés dans la section précédente.

## 4. Exécution de la migration

### Planifier la migration

- Planifiez la migration pendant une fenêtre de maintenance afin de minimiser l'impact.
- Informez les parties prenantes d'un éventuel temps d'indisponibilité.

### Migrer les données

- Exécutez la méthode de migration choisie.
- Surveillez le processus pour vous assurer que les données sont transférées correctement.

### Processus de bascule

- **Synchronisation continue** : si vous utilisez `mongosync` mentionné dans la section précédente, qui offre une synchronisation continue, surveillez les journaux de synchronisation.
- **Identifier le retard de synchronisation** : attendez que les journaux indiquent que le cluster cible n'a que quelques secondes de retard (par exemple, 2 secondes) sur le cluster source.
- **Arrêter les écritures sur le cluster source** : à ce stade, arrêtez toutes les opérations d'écriture sur le cluster source afin d'éviter toute perte de données.
- **Mettre à jour la configuration de l'application** : modifiez la configuration de l'application pour qu'elle pointe vers le nouveau cluster OVHcloud.
- **Déployer les modifications** : déployez la configuration mise à jour sur votre application.
- **Redémarrer l'application** : redémarrez l'application pour commencer à utiliser le nouveau cluster cible OVHcloud.

## 5. Tâches post-migration

### Vérifier les données

- Vérifiez que toutes les données ont été transférées et sont accessibles.
- Recherchez d'éventuelles incohérences ou données manquantes.

### Surveiller les performances

- Surveillez en continu le nouveau cluster OVHcloud pour vous assurer qu'il répond aux attentes de performance.
- Ajustez les configurations si nécessaire en fonction des métriques de performance.
