## Objectif

OpenSearch est une suite open source de recherche et d'analyse utilisée pour de nombreux cas d'usage liés à l'analyse de logs et de données, à la surveillance en temps réel et à la recherche applicative. Dérivée d'Elasticsearch et de Kibana, OpenSearch offre aux utilisateurs un système hautement évolutif avec un accès facile à de grands volumes de données et des métriques intégrées.

Ce guide explique comment configurer avec succès un service Public Cloud Databases pour OpenSearch dans l'espace client OVHcloud.

## Prérequis

- un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud

## En pratique

### Souscrire au service

Cliquez sur le bouton <code className="action">Créer un service</code>.

Le formulaire de création s'affiche sur une seule page, organisée en plusieurs sections :

- <code className="action">Service</code> : sélectionnez OpenSearch et la version à installer. Un nom est généré automatiquement pour votre service ; vous pourrez le modifier par la suite.
- <code className="action">Datacentre</code> : choisissez la région géographique du datacenter dans lequel votre service sera hébergé.
- <code className="action">Offre</code> : choisissez le plan de service approprié. Si nécessaire, vous pourrez faire évoluer le plan après la création.
- <code className="action">Instance</code> : choisissez le modèle de nœud. Le nombre de nœuds dépend du plan de service.
- <code className="action">Stockage</code> : vérifiez le stockage de votre service (le stockage est inclus dans le prix).
- <code className="action">Options</code> : décidez de rattacher un réseau public ou privé et, si vous le souhaitez, ajoutez les IPs autorisées.

Consultez la [page des caractéristiques d'OpenSearch](/guides/public-cloud/databases/opensearch-capabilities) pour connaître les versions disponibles et obtenir des informations détaillées sur les propriétés et les ressources matérielles de chaque plan.

Notez les informations tarifaires dans le récapitulatif de la commande. Le bouton <code className="action">Équivalent API et Terraform</code> affiche l'équivalent de la création de ce service avec l'[API OVHcloud](/guides/manage-and-operate/api/first-steps) ou Terraform. Cliquez sur <code className="action">Commander</code> pour créer votre service.

En quelques minutes, votre nouveau service de base de données sera déployé. Des messages dans l'espace client OVHcloud vous informeront lorsque la base de données sera prête à l'emploi.

### Configurer le service OpenSearch

Une fois le service Public Cloud Databases pour OpenSearch opérationnel, vous devrez définir au moins un utilisateur et une IP autorisée afin de pouvoir vous connecter pleinement au service.

L'onglet <code className="action">Dashboard</code> présente une vue d'ensemble de votre service, notamment les <code className="action">Informations de connection</code> nécessaires pour vous y connecter.

#### Étape 1 (obligatoire) : configurer un utilisateur

Basculez sur l'onglet <code className="action">Utilisateurs</code>. Un utilisateur par défaut, `avnadmin`, est préconfiguré lors de l'installation du service avec le pattern d'ACL `*` et la permission `admin`. Vous pouvez ajouter d'autres utilisateurs en cliquant sur le bouton <code className="action">Ajouter un utilisateur</code>.

Saisissez un nom d'utilisateur (de 3 à 32 caractères) et, si besoin, ses ACLs (voir ci-dessous), puis cliquez sur <code className="action">Créer un utilisateur</code>.

Une fois l'utilisateur créé, le mot de passe est généré. Veuillez le conserver en lieu sûr, car il ne sera plus affiché par la suite.

Les mots de passe peuvent ensuite être régénérés pour tous les utilisateurs, y compris `avnadmin`, via le bouton <code className="action">...</code> de l'onglet <code className="action">Utilisateurs</code>, puis <code className="action">Regénérer le mot de passe</code>.

#### Étape 2 (obligatoire) : configurer les IPs autorisées

:::warning
Pour des raisons de sécurité, la configuration réseau par défaut n'autorise aucune connexion entrante. Il est donc essentiel d'autoriser les adresses IP appropriées afin de pouvoir accéder à votre base de données.

:::


Si vous n'avez ajouté aucune IP lors de la création du service, basculez sur l'onglet <code className="action">Configuration</code>. Au moins une adresse IP doit être autorisée dans la section <code className="action">IPs</code> avant de pouvoir vous connecter à votre base de données.
Il peut s'agir par exemple de l'IP de votre ordinateur portable.

Saisissez une adresse IP individuelle ou un bloc d'IP dans le champ <code className="action">Adresse IP ou IP/masque</code> et ajoutez-la à la liste. Vous pouvez également retirer des adresses IP de la liste. Cliquez sur <code className="action">Sauvegarder les modifications</code> pour appliquer vos modifications.

Si vous ne savez pas comment obtenir votre IP, veuillez consulter un site tel que [www.WhatismyIP.com](https://www.whatismyip.com/).
Copiez l'adresse IP affichée sur ce site et conservez-la pour plus tard.

Votre service OpenSearch est désormais pleinement accessible !

Vous pouvez également configurer des listes de contrôle d'accès (ACL) pour des permissions plus granulaires.

#### Optionnel : configurer les ACLs

La base de données OpenSearch prend en charge des listes de contrôle d'accès (ACL) au niveau des index pour gérer les permissions. Cette approche permet de limiter les opérations disponibles pour des connexions spécifiques et de restreindre l'accès à certains jeux de données, ce qui améliore la sécurité de vos données.

Les ACLs se gèrent dans l'onglet <code className="action">Utilisateurs</code>. Vérifiez que l'option <code className="action">Activer les ACLs</code> est activée, puis définissez les ACLs de chaque utilisateur lorsque vous l'ajoutez ou le modifiez.

Vous pouvez accorder les permissions suivantes :

- **deny** : aucun accès
- **admin** : accès complet aux API et aux documents
- **readwrite** : accès complet aux documents
- **read** : autorise uniquement la recherche et la récupération de documents
- **write** : autorise la mise à jour, l'ajout et la suppression de documents

*Remarque* : la permission write permet à l'utilisateur du service de créer de nouveaux index correspondant au pattern, mais elle n'autorise pas la suppression de ces index.

Les règles sont définies séparément pour chaque utilisateur sous forme de combinaisons **pattern / permission**. Le **pattern** définit les index auxquels la permission s'applique. Les patterns suivent une syntaxe de type glob, où **\*** correspond à un nombre quelconque de caractères et **?** correspond à un caractère unique.

Lorsque plusieurs règles correspondent, elles sont appliquées dans l'ordre indiqué ci-dessus. Si les ACLs sont activées et qu'aucune règle ne correspond, l'accès est refusé.

##### **Contrôler l'accès aux API de premier niveau**

OpenSearch propose plusieurs points de terminaison d'API de « premier niveau » (*_mget*, *_msearch*, etc.), pour lesquels vous devez accorder l'accès séparément. Pour ce faire, utilisez des patterns similaires aux patterns d'index, par exemple :

- le pattern `_*` avec la permission `admin` accorderait un accès illimité à toutes les API de premier niveau
- le pattern `_msearch` avec la permission `admin` accorde un accès illimité uniquement à l'API _msearch

##### **Contrôle d'accès et OpenSearch Dashboards**

L'activation des ACLs ne restreint pas l'accès à OpenSearch Dashboards en lui-même, mais toutes les requêtes effectuées par OpenSearch Dashboards sont vérifiées par rapport aux ACLs de l'utilisateur actuel.

En pratique, pour qu'OpenSearch Dashboards fonctionne correctement, vous devez accorder à l'utilisateur un accès de niveau admin à l'interface *_msearch* (permission : `admin`, pattern : `_msearch`).

### Configuration avancée

#### Index et index patterns

Un index contient un schéma de base de données. Chaque donnée repose sur une unité de base qui est un document JSON, indexé avec un identifiant unique. L'indexation est la méthode utilisée pour stocker les données et permettre au moteur de recherche de les récupérer rapidement.

Vous pouvez en apprendre davantage en consultant la [documentation officielle d'OpenSearch - Managing indexes](https://docs.opensearch.org/latest/im-plugin/)

Les index ne peuvent pas être créés depuis l'espace client OVHcloud : créez-les via l'API OpenSearch (voir l'exemple cURL ci-dessous), ou laissez OpenSearch les créer automatiquement lors de l'écriture du premier document.

L'onglet <code className="action">Index patterns</code> vous permet de limiter le nombre d'index conservés pour un pattern donné, ce qui est utile, par exemple, lorsqu'un index est créé chaque jour pour stocker des logs. Cliquez sur <code className="action">Ajouter un pattern</code>, saisissez un pattern (`*` correspond à un nombre quelconque de caractères et `?` à un caractère unique) et un <code className="action">Nombre maximal d'index</code>, puis validez. Lorsque le nombre d'index correspondant au pattern dépasse ce maximum, les plus anciens sont supprimés. La valeur `0` signifie que le pattern n'est pas évalué (aucune limite).

Ce même onglet liste les index de votre service. Vous pouvez supprimer un index depuis cette liste.

#### Sauvegardes automatiques

OVHcloud effectue des sauvegardes quotidiennes pour votre service Public Cloud Databases pour OpenSearch.
Pour les consulter, basculez sur l'onglet <code className="action">Backups</code>. Les sauvegardes sont créées automatiquement et la durée de rétention dépend du plan de service. Consultez la [page des caractéristiques de Public Cloud Databases pour OpenSearch](/guides/public-cloud/databases/opensearch-capabilities) pour obtenir des informations détaillées sur les propriétés de chaque plan.

Via le bouton <code className="action">...</code>, vous pouvez <code className="action">Restaurer</code> une sauvegarde ou la <code className="action">Dupliquer (Fork)</code> vers un nouveau service. Les sauvegardes ne peuvent pas être supprimées. Pour plus d'informations, consultez nos guides sur les [sauvegardes](/guides/public-cloud/data-analytics/analytics/backups) et sur la [restauration d'une sauvegarde](/guides/public-cloud/data-analytics/analytics/restore-backup).

### Interroger le service OpenSearch

#### Requêtes DB avec cURL

Une fois le service opérationnel et configuré, vous pouvez essayer de vous y connecter depuis une session distante. Vous avez besoin au minimum :

- de l'identifiant et du mot de passe de l'utilisateur, avec des ACLs appropriées si elles sont activées ;
- de l'hôte et du port du service OpenSearch. Ils se trouvent dans la section <code className="action">Informations de connection</code> de l'onglet <code className="action">Dashboard</code>. Le port est propre à chaque service.

:::warning
Vérifiez que l'adresse IP de votre système exécutant la commande cURL fait bien partie des IPs autorisées définies pour ce service de base de données OpenSearch.

:::


L'URI affichée dans l'espace client commence par `opensearch://`. Pour l'utiliser avec cURL, remplacez ce schéma par `https://`. Une fois prêt, essayez ceci en ligne de commande, avec votre identifiant et votre mot de passe personnels :

```bash
export OPENSEARCH_URL=https://<service-host>:<port>
export OPENSEARCH_AUTH=<username>:<password>
```

Essayez ensuite de vous connecter :

```bash
curl -u $OPENSEARCH_AUTH $OPENSEARCH_URL
```

La réponse de la base de données devrait ressembler à :

```json
{
  "name" : "opensearch-<service-id>-1",
  "cluster_name" : "<cluster-name>",
  "cluster_uuid" : "<cluster-uuid>",
  "version" : {
    "distribution" : "opensearch",
    "number" : "3.3.2",
    "build_type" : "unknown",
    "build_hash" : "unknown",
    "build_date" : "2026-08-19T00:00Z",
    "build_snapshot" : false,
    "lucene_version" : "10.3.1",
    "minimum_wire_compatibility_version" : "2.19.0",
    "minimum_index_compatibility_version" : "2.0.0"
  },
  "tagline" : "The OpenSearch Project: https://opensearch.org/"
}
```

Créez maintenant un index :

```bash
curl -u $OPENSEARCH_AUTH -X PUT $OPENSEARCH_URL/my-index
```

En cas d'ACL mal définie pour l'utilisateur, la réponse ressemblera à :

```bash
{"error":{"root_cause":[{"type":"security_exception","reason":"no permissions for [indices:admin/create] and User [name=<username>, backend_roles=[], requestedTenant=null]"}],"type":"security_exception","reason":"no permissions for [indices:admin/create] and User [name=<username>, backend_roles=[], requestedTenant=null]"},"status":403}
```

Essayez d'ajouter un document :

```bash
curl -u $OPENSEARCH_AUTH -X PUT $OPENSEARCH_URL/my-index/_doc/1 -H 'Content-Type: application/json' -d '{"Description": "To be or not to be, that is the question."}'
```

Récupérez les données :

```bash
curl -u $OPENSEARCH_AUTH -X GET $OPENSEARCH_URL/my-index/_doc/1
```

Supprimez les données :

```bash
curl -u $OPENSEARCH_AUTH -X DELETE $OPENSEARCH_URL/my-index/_doc/1
```

Supprimez l'index :

```bash
curl -u $OPENSEARCH_AUTH -X DELETE $OPENSEARCH_URL/my-index/
```

:::info
Avec la permission `readwrite`, un utilisateur peut créer un index correspondant à son pattern et ajouter, lire ou supprimer des documents, mais il ne peut pas supprimer l'index lui-même : la suppression d'un index nécessite la permission `admin` sur un pattern correspondant. Vous pouvez aussi supprimer un index depuis l'onglet <code className="action">Index patterns</code>.
:::
