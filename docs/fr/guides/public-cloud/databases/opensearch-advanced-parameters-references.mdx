## Objectif

Ce guide répertorie tous les paramètres avancés pris en charge qui vous permettent de configurer votre Public Cloud Databases pour OpenSearch selon vos cas d'usage.

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Une base de données fonctionnant sur votre Public Cloud Databases OVHcloud ([ce guide](/guides/public-cloud/databases/getting-started) peut vous aider à répondre à ce prérequis)
- Un accès à votre <ManagerLink to="/">espace client OVHcloud</ManagerLink> ou à l'<ApiLink>API OVHcloud</ApiLink>

## En pratique

:::warning
La gestion des paramètres avancés n'est pas prise en charge via Terraform.

:::


### Depuis l'espace client OVHcloud

Reportez-vous à ce [guide](/guides/public-cloud/databases/advanced-configuration#depuis-lespace-client-ovhcloud) pour découvrir comment modifier vos paramètres avancés depuis l'espace client OVHcloud.

### Depuis l'API

Reportez-vous à ce [guide](/guides/public-cloud/databases/advanced-configuration#depuis-lapi) pour découvrir comment modifier vos paramètres avancés depuis l'API OVHcloud.

### Paramètres avancés pour OpenSearch

Vous trouverez ci-dessous un récapitulatif de chaque option de configuration disponible pour le service OpenSearch :

| | |
|---|---|
| Parameter | `opensearch.action_auto_create_index_enabled` |
| Value type | boolean |
| Minimum | |
| Maximum | |
| Description | Autorise ou bloque explicitement la création automatique des index. La valeur par défaut est true |

| | |
|---|---|
| Parameter | `opensearch.cluster_max_shards_per_node` |
| Value type | long |
| Minimum | 10 |
| Maximum | 10000 |
| Description | Contrôle le nombre de shards autorisés dans le cluster par nœud de données |

| | |
|---|---|
| Parameter | `opensearch.cluster_routing_allocation_node_concurrent_recoveries` |
| Value type | long |
| Minimum | 2 |
| Maximum | 16 |
| Description | Détermine le nombre de récupérations de shards entrantes/sortantes simultanées (généralement des répliques) autorisées sur un nœud. La valeur par défaut est 2. |

| | |
|---|---|
| Parameter | `opensearch.http_max_content_length` |
| Value type | long |
| Minimum | 1 |
| Maximum | 2147483647 |
| Description | Longueur maximale du contenu pour les requêtes HTTP vers l'API HTTP d'OpenSearch, en octets. |

| | |
|---|---|
| Parameter | `opensearch.http_max_header_size` |
| Value type | long |
| Minimum | 1024 |
| Maximum | 262144 |
| Description | Taille maximale autorisée pour les en-têtes, en octets |

| | |
|---|---|
| Parameter | `opensearch.http_max_initial_line_length` |
| Value type | long |
| Minimum | 1024 |
| Maximum | 65536 |
| Description | Longueur maximale d'une URL HTTP, en octets |

| | |
|---|---|
| Parameter | `opensearch.indices_memory_index_buffer_size` |
| Value type | long |
| Minimum | 3 |
| Maximum | 40 |
| Description | Valeur en pourcentage. La valeur par défaut est 10 %. Quantité totale de mémoire heap utilisée pour le tampon d'indexation, avant l'écriture des segments sur le disque. Il s'agit d'un paramètre expert. Une valeur trop basse ralentira l'indexation ; une valeur trop élevée améliorera les performances d'indexation mais entraînera des problèmes de performances pour les requêtes. |

| | |
|---|---|
| Parameter | `opensearch.indices_queries_cache_size` |
| Value type | long |
| Minimum | 3 |
| Maximum | 40 |
| Description | Valeur en pourcentage. La valeur par défaut est 10 %. Quantité maximale de mémoire heap utilisée pour le cache de requêtes. Il s'agit d'un paramètre expert. Une valeur trop basse diminuera les performances des requêtes et améliorera les performances des autres opérations ; une valeur trop élevée provoquera des problèmes avec les autres fonctionnalités d'OpenSearch. |

| | |
|---|---|
| Parameter | `opensearch.indices_query_bool_max_clause_count` |
| Value type | long |
| Minimum | 64 |
| Maximum | 4096 |
| Description | Nombre maximal de clauses qu'une BooleanQuery Lucene peut comporter. La valeur par défaut (1024) est relativement élevée, et l'augmenter peut entraîner des problèmes de performances. Étudiez d'autres approches avant d'augmenter cette valeur. |

| | |
|---|---|
| Parameter | `opensearch.indices_recovery_max_bytes_per_sec` |
| Value type | long |
| Minimum | 40 |
| Maximum | 400 |
| Description | Limite le trafic total de récupération entrant et sortant pour chaque nœud. S'applique aussi bien aux récupérations entre pairs qu'aux récupérations de snapshots (c'est-à-dire les restaurations à partir d'un snapshot). La valeur par défaut est 40 Mo |

| | |
|---|---|
| Parameter | `opensearch.indices_recovery_max_concurrent_file_chunks` |
| Value type | long |
| Minimum | 2 |
| Maximum | 5 |
| Description | Nombre de segments de fichiers envoyés en parallèle pour chaque récupération. La valeur par défaut est 2. |

| | |
|---|---|
| Parameter | `opensearch.override_main_response_version` |
| Value type | boolean |
| Minimum | |
| Maximum | |
| Description | Le mode de compatibilité configure OpenSearch pour qu'il indique sa version comme étant 7.10 afin que les clients continuent de fonctionner. La valeur par défaut est false |

| | |
|---|---|
| Parameter | `opensearch.script_max_compilations_rate` |
| Value type | string |
| Minimum | |
| Maximum | |
| Description | Le disjoncteur de compilation de scripts limite le nombre de compilations de scripts en ligne sur une période donnée. La valeur par défaut est use-context |

| | |
|---|---|
| Parameter | `opensearch.thread_pool_analyze_queue_size` |
| Value type | long |
| Minimum | 10 |
| Maximum | 2000 |
| Description | Taille de la file d'attente du pool de threads. |

| | |
|---|---|

| Minimum | 1 |
| Maximum | 128 |
| Description | Taille du pool de threads. Notez que cette valeur peut avoir un maximum dépendant du nombre de CPU - la valeur est automatiquement abaissée si elle est définie au-delà de la valeur maximale. |
