## Objectif

Ce guide répertorie tous les paramètres avancés pris en charge qui vous permettent de configurer votre Public Cloud Databases pour OpenSearch selon vos cas d'usage.

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Un service OpenSearch fonctionnant dans votre projet Public Cloud OVHcloud ([ce guide](/guides/public-cloud/data-analytics/analytics/getting-started) peut vous aider à répondre à ce prérequis)
- Un accès à votre <ManagerLink to="/">espace client OVHcloud</ManagerLink> ou à l'<ApiLink>API OVHcloud</ApiLink>

## En pratique

:::warning
Les paramètres avancés peuvent également être gérés avec Terraform, via l'argument `advanced_configuration` (paires clé/valeur) de la ressource [`ovh_cloud_project_database`](https://registry.terraform.io/providers/ovh/ovh/latest/docs/resources/cloud_project_database).

:::

:::info
La modification de la configuration avancée peut entraîner un redémarrage du service.

:::

Reportez-vous à ce [guide](/guides/public-cloud/data-analytics/analytics/advanced-configuration#depuis-lespace-client-ovhcloud) pour découvrir comment modifier vos paramètres avancés depuis l'espace client OVHcloud.

### Paramètres avancés pour OpenSearch

Vous trouverez ci-dessous un récapitulatif de chaque option de configuration disponible pour un service OpenSearch. Cette liste a été obtenue avec l'appel API suivant, qui renvoie la liste exacte des paramètres, avec leurs valeurs autorisées, pour votre propre service :

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/{serviceName}/database/opensearch/{clusterId}/capabilities/advancedConfiguration"} />

| Parameters |
|------------|
|**keep_index_refresh_interval** `boolean`<br/>L'automatisation du service réinitialise index.refresh_interval à sa valeur par défaut pour chaque index, afin que les index soient toujours visibles par la recherche. Si cela ne convient pas à votre cas d'usage, vous pouvez désactiver ce comportement en passant ce paramètre à true.<br/>|
|**opensearch.action_auto_create_index_enabled** `boolean`<br/>Autorise ou bloque explicitement la création automatique des index. La valeur par défaut est true.<br/>|
|**opensearch.action_destructive_requires_name** `boolean`<br/>Exige des noms d'index explicites lors d'une suppression.<br/>|
|**opensearch.auth_failure_listeners.internal_authentication_backend_limiting.allowed_tries** `long`<br/>min: `1` max: `32767`<br/>Nombre de tentatives de connexion autorisées avant le blocage de la connexion.<br/>|
|**opensearch.auth_failure_listeners.internal_authentication_backend_limiting.authentication_backend** `string`<br/>values: `internal`<br/>Backend interne. Saisissez `internal`.<br/>|
|**opensearch.auth_failure_listeners.internal_authentication_backend_limiting.block_expiry_seconds** `long`<br/>min: `0` max: `2147483647`<br/>Durée pendant laquelle la connexion reste bloquée après un échec de connexion.<br/>|
|**opensearch.auth_failure_listeners.internal_authentication_backend_limiting.max_blocked_clients** `long`<br/>min: `0` max: `2147483647`<br/>Nombre maximal d'adresses IP bloquées.<br/>|
|**opensearch.auth_failure_listeners.internal_authentication_backend_limiting.max_tracked_clients** `long`<br/>min: `0` max: `2147483647`<br/>Nombre maximal d'adresses IP suivies ayant échoué à se connecter.<br/>|
|**opensearch.auth_failure_listeners.internal_authentication_backend_limiting.time_window_seconds** `long`<br/>min: `0` max: `2147483647`<br/>Fenêtre de temps sur laquelle la valeur de `allowed_tries` est appliquée.<br/>|
|**opensearch.auth_failure_listeners.internal_authentication_backend_limiting.type** `string`<br/>values: `username`<br/>Type de limitation de débit.<br/>|
|**opensearch.cluster.filecache.remote_data_ratio** `long`<br/>min: `0` max: `100`<br/>Définit la quantité totale de données distantes pouvant être référencées, sous forme de ratio de la taille du disque réservée au cache de fichiers. Il s'agit d'un garde-fou contre la sursouscription d'un cluster. La valeur par défaut est 0.<br/>|
|**opensearch.cluster.remote_store.state.global_metadata.upload_timeout** `string`<br/>Délai d'attente de la fin de l'envoi de l'état du cluster. La valeur par défaut est 20s.<br/>|
|**opensearch.cluster.remote_store.state.metadata_manifest.upload_timeout** `string`<br/>Délai d'attente de la fin de l'envoi du fichier manifeste. Le fichier manifeste contient le détail de chacun des fichiers envoyés pour un état de cluster donné, qu'il s'agisse des fichiers de métadonnées d'index ou des fichiers de métadonnées globales. La valeur par défaut est 20s.<br/>|
|**opensearch.cluster.remote_store.translog.buffer_interval** `string`<br/>Valeur par défaut de l'intervalle de mise en tampon du translog utilisé lors des mises à jour périodiques du translog. Ce paramètre ne s'applique que lorsque le paramètre d'index `index.remote_store.translog.buffer_interval` n'est pas défini. La valeur par défaut est 650ms.<br/>|
|**opensearch.cluster.remote_store.translog.max_readers** `long`<br/>min: `100` max: `2147483647`<br/>Nombre maximal de fichiers translog ouverts pour les index adossés à un stockage distant. Limite le nombre total de fichiers translog par shard. Une fois cette limite atteinte, le stockage distant vide (flush) les fichiers translog. La valeur par défaut est 1000. Le minimum requis est 100.<br/>|
|**opensearch.cluster.routing.allocation.balance.prefer_primary** `boolean`<br/>Lorsque ce paramètre vaut true, OpenSearch tente de répartir uniformément les shards primaires entre les nœuds du cluster. Son activation ne garantit pas toujours un nombre égal de shards primaires sur chaque nœud, notamment en cas de bascule (failover). Repasser ce paramètre à false après l'avoir mis à true ne déclenche pas de redistribution des shards primaires. La valeur par défaut est false.<br/>|
|**opensearch.cluster.search.request.slowlog.level** `string`<br/>values: `debug`, `info`, `trace`, `warn`<br/>default: `trace`<br/>Niveau de journalisation.<br/>|
|**opensearch.cluster.search.request.slowlog.threshold.debug** `string`<br/>Seuil de niveau debug du temps total d'exécution d'une requête. La valeur doit être de la forme nombre et unité, l'unité étant l'une des suivantes (s,m,h,d,nanos,ms,micros), ou -1. La valeur par défaut est -1.<br/>|
|**opensearch.cluster.search.request.slowlog.threshold.info** `string`<br/>Seuil de niveau info du temps total d'exécution d'une requête. La valeur doit être de la forme nombre et unité, l'unité étant l'une des suivantes (s,m,h,d,nanos,ms,micros), ou -1. La valeur par défaut est -1.<br/>|
|**opensearch.cluster.search.request.slowlog.threshold.trace** `string`<br/>Seuil de niveau trace du temps total d'exécution d'une requête. La valeur doit être de la forme nombre et unité, l'unité étant l'une des suivantes (s,m,h,d,nanos,ms,micros), ou -1. La valeur par défaut est -1.<br/>|
|**opensearch.cluster.search.request.slowlog.threshold.warn** `string`<br/>Seuil d'avertissement (warn) du temps total d'exécution d'une requête. La valeur doit être de la forme nombre et unité, l'unité étant l'une des suivantes (s,m,h,d,nanos,ms,micros), ou -1. La valeur par défaut est -1.<br/>|
|**opensearch.cluster_max_shards_per_node** `long`<br/>min: `10` max: `10000`<br/>Contrôle le nombre de shards autorisés dans le cluster par nœud de données.<br/>|
|**opensearch.cluster_routing_allocation_node_concurrent_recoveries** `long`<br/>min: `2` max: `16`<br/>Nombre de récupérations de shards (généralement des réplicas) entrantes/sortantes simultanées autorisées sur un nœud. La valeur par défaut est le nombre de CPU du nœud * 2.<br/>|
|**opensearch.disk_watermarks.flood_stage** `long`<br/>Seuil d'utilisation du disque de niveau « flood stage ».<br/>|
|**opensearch.disk_watermarks.high** `long`<br/>Seuil haut d'utilisation du disque.<br/>|
|**opensearch.disk_watermarks.low** `long`<br/>Seuil bas d'utilisation du disque.<br/>|
|**opensearch.email_sender_name** `string`<br/>Doit être identique au nom d'expéditeur (Sender name) défini dans OpenSearch Dashboards.<br/>|
|**opensearch.email_sender_password** `string`<br/>Mot de passe de l'expéditeur des alertes OpenSearch, pour s'authentifier auprès du serveur SMTP.<br/>|
|**opensearch.email_sender_username** `string`<br/>Nom d'utilisateur de l'expéditeur des alertes OpenSearch.<br/>|
|**opensearch.enable_remote_backed_storage** `boolean`<br/>Active le stockage adossé à un stockage distant (remote-backed storage).<br/>|
|**opensearch.enable_searchable_snapshots** `boolean`<br/>Active les snapshots interrogeables (searchable snapshots).<br/>|
|**opensearch.enable_security_audit** `boolean`<br/>Active ou désactive l'audit de sécurité.<br/>|
|**opensearch.enable_snapshot_api** `boolean`<br/>Active ou désactive l'API de snapshot pour les dépôts personnalisés. Nécessite l'activation de la gestion de la sécurité.<br/>|
|**opensearch.http_max_content_length** `long`<br/>min: `1048576` max: `2147483647`<br/>Taille maximale du contenu des requêtes HTTP vers l'API HTTP d'OpenSearch, en octets.<br/>|
|**opensearch.http_max_header_size** `long`<br/>min: `1024` max: `262144`<br/>Taille maximale autorisée des en-têtes, en octets.<br/>|
|**opensearch.http_max_initial_line_length** `long`<br/>min: `1024` max: `65536`<br/>Longueur maximale d'une URL HTTP, en octets.<br/>|
|**opensearch.indices_fielddata_cache_size** `long`<br/>min: `3` max: `100`<br/>Valeur relative. Quantité maximale de mémoire heap utilisée pour le cache de field data. Il s'agit d'un paramètre expert : une valeur trop basse augmente le coût de chargement des field data ; trop de mémoire allouée à ce cache réduit la mémoire heap disponible pour les autres opérations.<br/>|
|**opensearch.indices_memory_index_buffer_size** `long`<br/>min: `3` max: `40`<br/>Valeur en pourcentage. La valeur par défaut est 10%. Quantité totale de mémoire heap utilisée pour le tampon d'indexation, avant l'écriture des segments sur le disque. Il s'agit d'un paramètre expert. Une valeur trop basse ralentit l'indexation ; une valeur trop haute améliore les performances d'indexation mais dégrade celles des requêtes.<br/>|
|**opensearch.indices_memory_max_index_buffer_size** `long`<br/>min: `3` max: `2048`<br/>Valeur absolue. Non bornée par défaut. Ne fonctionne pas sans indices.memory.index_buffer_size. Quantité maximale de mémoire heap utilisée pour le cache de requêtes : limite haute absolue de indices.memory.index_buffer_size.<br/>|
|**opensearch.indices_memory_min_index_buffer_size** `long`<br/>min: `3` max: `2048`<br/>Valeur absolue. La valeur par défaut est 48mb. Ne fonctionne pas sans indices.memory.index_buffer_size. Quantité minimale de mémoire heap utilisée pour le cache de requêtes : limite basse absolue de indices.memory.index_buffer_size.<br/>|
|**opensearch.indices_queries_cache_size** `long`<br/>min: `3` max: `40`<br/>Valeur en pourcentage. La valeur par défaut est 10%. Quantité maximale de mémoire heap utilisée pour le cache de requêtes. Il s'agit d'un paramètre expert. Une valeur trop basse dégrade les performances des requêtes et améliore celles des autres opérations ; une valeur trop haute perturbe d'autres fonctionnalités d'OpenSearch.<br/>|
|**opensearch.indices_query_bool_max_clause_count** `long`<br/>min: `64` max: `4096`<br/>Nombre maximal de clauses d'une BooleanQuery Lucene. La valeur par défaut (1024) est relativement élevée, et l'augmenter peut entraîner des problèmes de performances. Étudiez d'autres approches avant d'augmenter cette valeur.<br/>|
|**opensearch.indices_recovery_max_bytes_per_sec** `long`<br/>min: `40` max: `400`<br/>Limite le trafic total de récupération entrant et sortant pour chaque nœud. S'applique aussi bien aux récupérations entre pairs qu'aux récupérations depuis un snapshot (c'est-à-dire les restaurations depuis un snapshot). La valeur par défaut est 40mb.<br/>|
|**opensearch.indices_recovery_max_concurrent_file_chunks** `long`<br/>min: `2` max: `5`<br/>Nombre de blocs de fichiers envoyés en parallèle pour chaque récupération. La valeur par défaut est 2.<br/>|
|**opensearch.ism_enabled** `boolean`<br/>Indique si ISM (Index State Management) est activé ou non.<br/>|
|**opensearch.ism_history_enabled** `boolean`<br/>Indique si l'historique d'audit est activé ou non. Les journaux d'ISM sont automatiquement indexés dans un document de journaux.<br/>|
|**opensearch.ism_history_max_age** `long`<br/>min: `1` max: `2147483647`<br/>Âge maximal, en heures, avant le basculement (rollover) de l'index d'historique d'audit.<br/>|
|**opensearch.ism_history_max_docs** `long`<br/>min: `1` max: `9223372036854776000`<br/>Nombre maximal de documents avant le basculement (rollover) de l'index d'historique d'audit.<br/>|
|**opensearch.ism_history_rollover_check_period** `long`<br/>min: `1` max: `2147483647`<br/>Intervalle, en heures, entre deux vérifications de basculement (rollover) de l'index d'historique d'audit.<br/>|
|**opensearch.ism_history_rollover_retention_period** `long`<br/>min: `1` max: `2147483647`<br/>Durée de conservation, en jours, des index d'historique d'audit.<br/>|
|**opensearch.knn_memory_circuit_breaker_enabled** `boolean`<br/>Active ou désactive le disjoncteur (circuit breaker) mémoire KNN. La valeur par défaut est true.<br/>|
|**opensearch.knn_memory_circuit_breaker_limit** `long`<br/>min: `0` max: `100`<br/>Quantité maximale de mémoire, en pourcentage, pouvant être utilisée pour l'index KNN. La valeur par défaut est 50% de la taille de la heap JVM. La valeur 0 la définit à null, ce qui peut servir à invalider les caches.<br/>|
|**opensearch.ml_commons_connector_access_control_enabled** `boolean`<br/>Lorsque ce paramètre vaut true, les administrateurs peuvent contrôler l'accès et les permissions sur l'API des connecteurs à l'aide des backend_roles. La valeur par défaut est false.<br/>|
|**opensearch.ml_commons_max_model_on_node** `long`<br/>min: `1`<br/>Nombre maximal de modèles ML pouvant être déployés sur un même nœud ML. La valeur par défaut est 10.<br/>|
|**opensearch.ml_commons_model_access_control_enabled** `boolean`<br/>Active ou désactive le contrôle d'accès aux modèles pour ML Commons. Lorsqu'il est activé, l'accès aux modèles ML est régi par les permissions de sécurité. La valeur par défaut est false.<br/>|

Il s'agit d'un garde-fou contre la sursouscription d'un cluster. La valeur par défaut est 5gb. Nécessite le redémarrage de tous les nœuds OpenSearch.<br/>|
|**opensearch.override_main_response_version** `boolean`<br/>Le mode de compatibilité fait en sorte qu'OpenSearch annonce la version 7.10, afin que les clients continuent de fonctionner. La valeur par défaut est false. Obsolète et ignoré à partir de la version 3.3 du service.<br/>|

|**opensearch.remote_store.segment.pressure.consecutive_failures.limit** `long`<br/>min: `1` max: `2147483647`<br/>Nombre minimal d'échecs consécutifs qui déclenche la contre-pression (backpressure) sur les segments distants. La valeur par défaut est 5.<br/>|

La valeur par défaut est 10.<br/>|

|**opensearch.search.insights.top_queries.latency.enabled** `boolean`<br/>default: `false`<br/>Active ou désactive la surveillance des N requêtes les plus coûteuses selon cette métrique.<br/>|
|**opensearch.search.insights.top_queries.latency.top_n_size** `long`<br/>min: `1`<br/>Valeur de N pour la surveillance des N requêtes les plus coûteuses selon cette métrique.<br/>|

|**opensearch.search.insights.top_queries.memory.enabled** `boolean`<br/>default: `false`<br/>Active ou désactive la surveillance des N requêtes les plus coûteuses selon cette métrique.<br/>|

|**opensearch.search.insights.top_queries.memory.window_size** `string`<br/>Taille de la fenêtre de surveillance des N requêtes les plus coûteuses. La valeur doit être une durée avec unité, par exemple 1m, 5s, 1h.<br/>|
