## Objectif

Ce guide répertorie tous les paramètres avancés pris en charge qui vous permettent de configurer votre service Public Cloud Databases pour Kafka Connect selon vos cas d'usage.

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud   
- Un service Analytics actif sur votre projet OVHcloud Public Cloud ([ce guide](/guides/public-cloud/data-analytics/analytics/getting-started) peut vous aider à répondre à ce prérequis) 
- Un accès à votre <ManagerLink to="/">espace client OVHcloud</ManagerLink> ou à l'<ApiLink>API OVHcloud</ApiLink>

## En pratique

:::warning
La gestion des paramètres avancés n'est pas prise en charge via Terraform.

:::


### Depuis l'espace client OVHcloud

Veuillez consulter ce [guide](/guides/public-cloud/data-analytics/analytics/advanced-configuration#using-the-ovhcloud-control-panel) pour savoir comment modifier vos paramètres avancés depuis l'espace client OVHcloud.

### Depuis l'API

Veuillez consulter ce [guide](/guides/public-cloud/data-analytics/analytics/advanced-configuration#using-api) pour savoir comment modifier vos paramètres avancés depuis l'API OVHcloud.

### Paramètres avancés pour Kafka Connect

Vous trouverez ci-dessous un récapitulatif de toutes les options de configuration disponibles pour le service Kafka Connect :

| Paramètres |
|------------|
|**kafka_connect.connector_client_config_override_policy** `string`<br/>valeurs : `All`, `None`<br/>Définit les configurations client pouvant être remplacées par le connecteur. La valeur par défaut est None<br/>|
|**kafka_connect.consumer_auto_offset_reset** `string`<br/>valeurs : `earliest`, `latest`<br/>Comportement à adopter lorsqu'il n'existe aucun offset initial dans Kafka ou que l'offset actuel n'existe plus sur le serveur. La valeur par défaut est earliest<br/>|
|**kafka_connect.consumer_fetch_max_bytes** `long`<br/>min : `1048576` max : `104857600`<br/>Les enregistrements sont récupérés par lots par le consommateur, et si le premier batch d'enregistrements de la première partition non vide du fetch est plus grand que cette valeur, il sera tout de même renvoyé afin que le consommateur puisse continuer à progresser. Ce n'est donc pas un maximum absolu.<br/>|
|**kafka_connect.consumer_isolation_level** `string`<br/>valeurs : `read_committed`, `read_uncommitted`<br/>Niveau d'isolation de lecture pour les transactions. read_uncommitted est la valeur par défaut, mais read_committed peut être utilisé si un comportement de consommation exactement une fois (exactly-once) est souhaité.<br/>|
|**kafka_connect.consumer_max_partition_fetch_bytes** `long`<br/>min : `1048576` max : `104857600`<br/>Les enregistrements sont récupérés par lots par le consommateur. Si le premier batch d'enregistrements de la première partition non vide du fetch dépasse cette limite, le batch sera tout de même renvoyé afin que le consommateur puisse continuer à progresser. <br/>|
|**kafka_connect.consumer_max_poll_interval_ms** `long`<br/>min : `1` max : `2147483647`<br/>Délai maximal, en millisecondes, entre deux appels à poll() lors de l'utilisation de la gestion de groupe de consommateurs (valeur par défaut : 300000).<br/>|
|**kafka_connect.consumer_max_poll_records** `long`<br/>min : `1` max : `10000`<br/>Nombre maximal d'enregistrements retournés lors d'un seul appel à poll() (valeur par défaut : 500).<br/>|
|**kafka_connect.offset_flush_interval_ms** `long`<br/>min : `1` max : `100000000`<br/>Intervalle auquel tenter de valider (commit) les offsets des tâches (valeur par défaut : 60000).<br/>|
|**kafka_connect.offset_flush_timeout_ms** `long`<br/>min : `1` max : `2147483647`<br/>Nombre maximal de millisecondes à attendre pour que les enregistrements soient écrits et que les données d'offset de partition soient validées (commit) dans le stockage des offsets, avant d'annuler le processus et de restaurer les données d'offset en vue d'une future tentative de validation (valeur par défaut : 5000).<br/>|
|**kafka_connect.producer_batch_size** `long`<br/>min : `0` max : `5242880`<br/>Ce paramètre définit la limite supérieure de la taille de lot à envoyer. Si le nombre d'octets accumulés pour cette partition est inférieur à cette valeur, le producteur va « patienter » (linger) pendant la durée linger.ms en attendant l'arrivée d'autres enregistrements. Une taille de lot de zéro désactive entièrement le regroupement en lots (valeur par défaut : 16384).<br/>|
|**kafka_connect.producer_buffer_memory** `long`<br/>min : `5242880` max : `134217728`<br/>Nombre total d'octets de mémoire que le producteur peut utiliser pour mettre en tampon les enregistrements en attente d'envoi vers le broker (valeur par défaut : 33554432).<br/>|
|**kafka_connect.producer_compression_type** `string`<br/>valeurs : `gzip`, `lz4`, `none`, `snappy`, `zstd`<br/>Spécifie le type de compression par défaut pour les producteurs. Cette configuration accepte les codecs de compression standards ('gzip', 'snappy', 'lz4', 'zstd'). Elle accepte également 'none', valeur par défaut équivalente à l'absence de compression.<br/>|
|**kafka_connect.producer_linger_ms** `long`<br/>min : `0` max : `5000`<br/>Ce paramètre définit la limite supérieure du délai de regroupement en lots : dès qu'une partition atteint la taille batch.size, elle est envoyée immédiatement quel que soit ce paramètre. Cependant, si le nombre d'octets accumulés pour cette partition est inférieur à cette valeur, le producteur va « patienter » (linger) pendant la durée spécifiée en attendant l'arrivée d'autres enregistrements. Valeur par défaut : 0.<br/>|
|**kafka_connect.producer_max_request_size** `long`<br/>min : `131072` max : `67108864`<br/>Ce paramètre limite le nombre de lots d'enregistrements que le producteur enverra en une seule requête afin d'éviter l'envoi de requêtes trop volumineuses.<br/>|
|**kafka_connect.scheduled_rebalance_max_delay_ms** `long`<br/>min : `0` max : `600000`<br/>Délai maximal programmé pour attendre le retour d'un ou plusieurs workers partis avant de rééquilibrer et de réattribuer leurs connecteurs et tâches au groupe. Pendant cette période, les connecteurs et tâches des workers partis restent non attribués. Valeur par défaut : 5 minutes.<br/>|
|**kafka_connect.session_timeout_ms** `long`<br/>min : `1` max : `2147483647`<br/>Délai d'expiration, en millisecondes, utilisé pour détecter les pannes lors de l'utilisation des fonctionnalités de gestion de groupe de Kafka (valeur par défaut : 10000).<br/>|
