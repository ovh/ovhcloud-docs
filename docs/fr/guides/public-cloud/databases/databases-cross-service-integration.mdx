## Objectif

Cross Service Integration vous permet d'exposer les logs et les métriques de vos Public Cloud Databases.

**Ce guide explique comment utiliser Cross Service Integration.**

:::warning
**Hors périmètre :**

- Exposer des métriques et des logs en dehors d'OVHcloud Public Cloud
- Le moteur MongoDB n'est pas pris en charge  

:::


## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) sur votre compte OVHcloud
- Une base de données exécutée sur votre service Public Cloud Databases OVHcloud ([ce guide](/guides/public-cloud/databases/getting-started) peut vous aider à remplir ce prérequis)
- Un accès à l'<ApiLink>API OVHcloud</ApiLink> (facultatif)

## Concept

Les intégrations inter-services pour les logs et les métriques vous permettent par exemple :

- D'envoyer des métriques Valkey ou MySQL vers PostgreSQL.
- D'envoyer des métriques PostgreSQL ou MySQL vers OpenSearch.
- D'afficher des métriques dans le service Dashboards.

Pour cela, vous avez besoin de :

- Un service source
- Un service de destination

<img className="thumbnail" alt="Best practices" src="/images/public-cloud/databases/databases-07-cross-service-integration/databases_07_cross_service_integration_best_practice.png" loading="lazy" />

:::warning
Bien qu'il soit possible de définir le même cluster comme service de destination et service source, il s'agit d'une mauvaise pratique pour plusieurs raisons (performance, sécurité, résilience, etc.)

:::


![Mauvaises pratiques](/images/public-cloud/databases/databases-07-cross-service-integration/databases_07_cross_service_integration_bad_practice.png)

### Matrice d'intégration

- Tous les services prennent en charge les logs vers opensearch et kafka_logs vers kafka.
- Tous les services prennent en charge les métriques vers pg.

Autres intégrations :

| source →<br/>↓ destination | service dashboards	| kafka |
|:--|---|---|
| pg | dashboard, datasource | |
| opensearch | datasource | |
| kmm | | kafka_mirrormaker |
| kc | | kafka_connect |

#### Récupérer les identifiants de votre service et de votre cluster

Vous devez d'abord identifier votre `serviceId` et votre `clusterId`.

##### **Récupérer l'identifiant du service souhaité**

Exécutez l'appel API suivant :

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project"} />


Exemple de réponse :

```json
[
  "702de32b692c4842b0bb751dc5085daf",
  "297c1776595544759d77eee921edd49b",
  "3d4f8b8811ba4962a78f971503915f0d"
]
```

Dans la liste obtenue, sélectionnez et copiez l'identifiant du service correspondant au service souhaité, également appelé `serviceName`.

##### **Récupérer l'identifiant du cluster souhaité**

Ouvrez l'appel API suivant, collez votre identifiant de service dans le champ `serviceName` et cliquez sur <code className="action">Execute</code> :

#### Stocker vos logs ou métriques

Dans un premier temps, vous devez envoyer vos métriques ou logs quelque part, afin de les stocker et de récupérer les métriques avec Dashboards.

Pour cela, vous devez créer une nouvelle intégration :

  <Tab label="Kafka">
    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}/integration"} />

Le `destionationServiceId` et le `sourceServiceId` correspondent à l'identifiant du cluster de destination et à l'identifiant du cluster source.

Pour cela, créez d'abord une Public Cloud Database pour Dashboards via notre espace client ou l'API.

Une fois cela fait, récupérez la capacité d'intégration `GrafanaDashboard` relative au service de destination :
