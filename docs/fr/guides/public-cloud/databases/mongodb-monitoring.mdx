## Objectif

La surveillance des bases de données MongoDB est essentielle pour détecter les incidents et les ralentissements, ce qui permet de s'assurer qu'un système fonctionne correctement, notamment en termes de disponibilité, de fiabilité et d'évolutivité.

Vous pouvez surveiller vos bases de données via l'espace client OVHcloud (et également consulter un résumé et un historique), à l'aide d'une interface en ligne de commande (CLI) ou d'une interface graphique (GUI).

**Dans ce guide, nous allons vous montrer trois façons d'obtenir et d'utiliser au quotidien des conseils de bonnes pratiques pour maintenir vos bases de données MongoDB en parfait état.**

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud.
- Un service MongoDB managé OVHcloud. Si vous n'en avez pas, veuillez consulter le guide suivant : [Bien démarrer avec Public Cloud Databases](/guides/public-cloud/databases/getting-started).
- Un compte vous permettant de vous connecter à MongoDB. Si vous n'en avez pas, veuillez consulter le guide suivant : [Configurer votre instance MongoDB pour accepter les connexions entrantes](/guides/public-cloud/databases/mongodb-manage-control-panel).
- Un accès à l'<ManagerLink to="/">espace client OVHcloud</ManagerLink>.

## En pratique

### Utiliser les métriques fournies par OVHcloud

Vous pouvez utiliser les principales métriques et statistiques de l'<ManagerLink to="/">espace client OVHcloud</ManagerLink> pour suivre et gérer votre instance de base de données.

Pour chaque service Public Cloud Databases, dans l'onglet <code className="action">Métriques</code>, vous pouvez trouver les graphiques suivants :

- CPU utilisé (%)
- Espace disque utilisé
- Nombre d'IOPS en lecture
- Nombre d'IOPS en écriture
- Mémoire utilisée (disponible uniquement pour les plans de service **Production** et **Advanced**)
- Réception réseau (Mbps)
- Transmission réseau (Mbps)

Ces métriques sont disponibles pour une durée déterminée — 1 heure, 1 jour, 1 semaine, 1 mois, 1 an. Vous pouvez également activer l'actualisation automatique si vous souhaitez laisser cet onglet ouvert.

### Utiliser la CLI (interface en ligne de commande) pour récupérer des informations

Selon la solution à laquelle vous avez souscrit (Discovery, Production ou Advanced), vous pouvez utiliser le même outil « mongo ». Ce binaire est disponible dans un fichier .zip, que vous pouvez trouver sur le site officiel de MongoDB via le lien suivant : [https://www.mongodb.com/try/download/community](https://www.mongodb.com/try/download/community). Vous pouvez ensuite télécharger la version qui correspond le mieux à votre plateforme.

Veuillez noter que pour accéder à ces données, vous avez besoin de privilèges MongoDB élevés, notamment du rôle « clusterMonitor » pour récupérer les statistiques du serveur.

Trois commandes peuvent être utilisées pour obtenir des informations en temps réel.

Vous pouvez découvrir le fonctionnement du serveur via la commande générale `serverStatus()`. Vous pouvez également l'utiliser pour recueillir des données sur les différents types de requêtes que vous effectuez.

```bash
> db.serverStatus()

{
	host: 'replicaset-0',
	version: '6.0.12',
	process: 'mongod',
	pid: Long("565"),
	uptime: 4430,
        …
        "ok" : 1
	…
  	opcounters: {
    		insert: Long("5"),
  		query: Long("2683"),
    		update: Long("1150"),
    		delete: Long("1324"),
    		getmore: Long("3099"),
   		command: Long("103420")
  	},
	…
}
```

D'autres commandes permettent de renvoyer des valeurs chiffrées, en particulier pour une base de données spécifique : **dbStats** (`db.stats()`)

```bash
> db.stats()

{
	 db: 'admin',
 	 collections: 3,
 	 views: 0,
 	 objects: 7,
 	 avgObjSize: 243,
 	 dataSize: 1701,
 	 storageSize: 94208,
 	 indexes: 4,
 	 indexSize: 131072,
 	 totalSize: 225280,
	  scaleFactor: 1,
	  fsUsedSize: 340033536,
	  fsTotalSize: 1020702720,
	  ok: 1,
	  …
}
```

Tout comme **dbStats** renvoie des informations sur une base de données spécifique, vous pouvez également utiliser la commande **collStats** (`db.coll.stats()`) pour accéder aux informations sur une collection de données spécifique.

### Utiliser une GUI (interface graphique) pour surveiller l'état des instances MongoDB

Selon la solution à laquelle vous avez souscrit (Discovery, Production ou Advanced), vous pouvez utiliser le même outil « MongoDB Compass ». Il s'agit d'un outil multiplateforme, conçu pour fonctionner sur tout appareil : Mac, Windows, Linux. Il est disponible sur le site officiel de MongoDB via le lien suivant : [https://www.mongodb.com/try/download/compass](https://www.mongodb.com/try/download/compass).

MongoDB Compass dispose d'un onglet <code className="action">Performance</code>.

<img className="thumbnail" alt="Surveillance - Compass" src="/images/public-cloud/databases/mongodb-15-monitoring/monitoring02.png" loading="lazy" />

Cet onglet affiche en temps réel les informations suivantes, particulièrement utiles pour le dépannage ou l'optimisation fine :

- Operations : nombre d'opérations effectuées (par exemple, INSERT, COMMAND, UPDATE, etc.)
- Read & write : le nombre de lectures/écritures effectuées
- Network : le nombre de connexions actuelles au serveur
- Memory : l'utilisation de la RAM du serveur
- Hottest Collections : les collections les plus fréquemment utilisées au moment de la collecte
- Slowest Operations : les opérations les plus lentes au moment de la lecture

Vous pouvez également arrêter une opération listée sous « Slowest Operations » si elle prend trop de temps.
Cliquer sur l'opération ciblée ouvrira le panneau « Operation Details » à droite. Cliquer sur le bouton <code className="action">KILL OP</code> mettra fin à cette requête.
