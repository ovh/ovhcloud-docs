## Objectif

Ce guide explique comment migrer une base de données MySQL externe vers un service Public Cloud Databases MySQL OVHcloud.

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud.
- Une base de données fonctionnant sur votre service Public Cloud Databases OVHcloud ([ce guide](/guides/public-cloud/databases/getting-started) peut vous aider à répondre à ce prérequis).
- Un accès à l'<ManagerLink to="/">espace client OVHcloud</ManagerLink> et à l'<ApiLink>API OVHcloud</ApiLink>.

## En pratique

### Prérequis techniques

- La base de données source doit être en version >= 5.7 et \<= 8.0.
- gtid_mode doit être activé (ON) à la fois sur la source et sur la cible (activé par défaut sur les bases de données Public Cloud MySQL).
- Un utilisateur disposant des permissions de lecture et de réplication des données peut être créé sur la base de données source.

### Configuration

- Créez une base de données MySQL managée dans votre projet Public Cloud.
- Créez un utilisateur sur la base de données source avec les permissions de réplication et de lecture des données.

### Depuis l'API OVHcloud

- Créez d'abord une tâche pour vérifier si la migration est possible.

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/database/mysql/\\{clusterId\\}/migration/check"} />

```console
body : {
   "sourceHost": <hostmane>,
   "sourcePassword": <replication user password>,
   "sourcePort": 3306,
   "sourceSsl": true,
   "sourceUsername": <replication user name>
}
```

- Récupérez ensuite le résultat de la tâche de vérification de migration avec l'appel API suivant :

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/database/mysql/\\{clusterId\\}/migration/check"} />

Si le champ Success indique `true`, vous pouvez continuer.
Dans le cas contraire, vous pouvez consulter la raison dans le champ result.

- Créez une tâche pour migrer la base de données externe vers la base de données managée :

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/database/mysql/\\{clusterId\\}/migration"} />

```console
body : {
   "sourceHost": <hostmane>,
   "sourcePassword": <replication user password>,
   "sourcePort": 3306,
   "sourceSsl": true,
   "sourceUsername": <replication user name>
}
```

- Récupérez le résultat de la migration :

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/database/mysql/\\{clusterId\\}/migration"} />

Une fois la migration terminée, la tâche continue de répliquer la base de données source.
Vous devez l'arrêter avec la requête suivante pour terminer complètement le processus.
Attention, si vous ne le faites pas et que vous supprimez des données dans la base de données source, ces mises à jour seront répliquées vers la base de données cible.

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/database/mysql/\\{clusterId\\}/migration/stop"} />


### Utilisateurs

Actuellement, les utilisateurs ne sont pas migrés lors de ce processus et doivent être recréés manuellement dans la base de données managée.
