## Objectif

Avez-vous un site web ou un blog de type CMS, peut-être propulsé par WordPress ? Découvrez comment accélérer les temps de chargement des pages et les requêtes SQL grâce à un service Valkey ! Dans ce tutoriel, nous allons mettre en place un service Valkey pour les données de votre CMS. Tous les utilisateurs, même les administrateurs et surtout les visiteurs, bénéficieront directement d'une meilleure performance du site web.

### Plateforme CMS

Pour ce tutoriel, nous proposons d'utiliser le CMS WordPress, fonctionnant sur Linux Ubuntu avec MySQL comme base de données principale. Pour obtenir le cache d'objets, nous utiliserons une base de données Public Cloud pour Valkey et le plugin WordPress Redis Object Cache, compatible avec Valkey.

:::warning
Ce tutoriel vous montrera comment utiliser une ou plusieurs solutions OVHcloud avec des outils externes, et décrira les actions à mener dans un contexte spécifique. Merci de penser à adapter ces actions à votre situation.

## Prérequis

Ce tutoriel nécessite :

- Un WordPress fonctionnel
- Un compte administrateur WordPress pour installer un plugin
- Un [client PHP](https://valkey.io/clients/) pris en charge par le plugin (dans ce tutoriel : PhpRedis)
- Une base de données OVHcloud Public Cloud pour Valkey

## En pratique

### Environnement technique du tutoriel

Ce tutoriel s'appuie sur les composants logiciels suivants :

- Linux Ubuntu 24.04 LTS / Apache 2.4 / PHP 8.3 / MySQL 8.0
- WordPress : 7.1
- PhpRedis : 5.3.7 (paquet `php-redis` d'Ubuntu 24.04)
- Redis Object Cache : 3.0
- Valkey : l'une des versions listées dans le guide [Fonctionnalités de Valkey](/guides/public-cloud/databases/valkey-capabilities)

Les captures d'écran ont été réalisées avec des versions antérieures de WordPress et du plugin : votre interface peut légèrement différer.

### Configuration de votre CMS : WordPress

Si vous devez installer WordPress, veuillez consulter le guide officiel : [WordPress How To Install](https://developer.wordpress.org/advanced-administration/before-install/howto-install/).

Une fois cela fait, nous allons configurer correctement le back-end de WordPress.
Pour les étapes suivantes, considérons que vous disposez d'un système WordPress fonctionnel sur une plateforme LAMP (Linux, Apache, MySQL, PHP).

### Client PHP : PhpRedis

Comme WordPress est basé sur PHP, nous aurons besoin d'un client PHP compatible avec Valkey. Nous proposons d'utiliser l'un des principaux [clients PHP](https://valkey.io/clients/) : PhpRedis.

Le protocole TLS étant requis pour sécuriser la connexion à la base de données OVHcloud Public Cloud pour Valkey, nous devons utiliser la version 5.3.x de PhpRedis ou une version supérieure.

Veuillez vérifier que PhpRedis est installé, avec une version compatible :

- Si vous avez un accès SSH à votre serveur WordPress, vous pouvez utiliser la commande suivante :

```bash
dpkg -l php-redis
```
Si ce n'est pas disponible sur votre système, veuillez l'installer :

```bash
sudo apt install php-redis
sudo systemctl restart apache2
```
- Si vous n'avez pas d'accès SSH au système, utilisez la fonction phpinfo() et effectuez une recherche sur le module `redis` (l'extension PhpRedis), comme dans l'exemple suivant :

<img className="thumbnail" alt="Module PhpRedis dans PHPInfo" src="/images/public-cloud/databases/redis-tuto-01-wordpress/Redis_phpinfo.png" loading="lazy" />

### Plugin WordPress : Redis Object Cache

Il existe plusieurs plugins de cache d'objets pouvant être utilisés pour intégrer un service Valkey. Vous pouvez les rechercher directement dans le menu Extensions. Pour ce tutoriel, nous avons décidé d'utiliser le plus populaire d'entre eux : Redis Object Cache. Cliquez sur le bouton Install Now :

### Configurer WordPress pour se connecter au service Valkey

#### Modifier wp-config.php

Avant d'activer le plugin Redis Object Cache, il est nécessaire de configurer les paramètres de connexion au service Valkey.
Par défaut, ce plugin recherche un service hébergé sur le même serveur que votre WordPress.
Ce n'est pas notre cas de figure ici, puisque le service Valkey est hébergé sur OVHcloud Public Cloud Databases.

Nous allons suivre la documentation officielle du plugin pour définir le serveur distant : [configuration de Redis Object Cache](https://github.com/rhubarbgroup/redis-cache/blob/develop/README.md).
Cela doit être fait dans le fichier de configuration de WordPress (**wp-config.php** situé dans /var/www/wordpress/ dans notre exemple) en ajoutant les lignes suivantes, en remplaçant `<host>`, `<port>`, `<username>` et `<password>` par les valeurs de votre service (l'hôte et le port sont affichés dans la section <code className="action">Informations de connection</code> de l'onglet <code className="action">Dashboard</code> de votre service dans l'espace client) :

```php
define( 'WP_REDIS_CLIENT', 'phpredis' );
define( 'WP_REDIS_SCHEME', 'tls' );
define( 'WP_REDIS_HOST', '<host>' );
define( 'WP_REDIS_PORT', <port> );
define( 'WP_REDIS_PASSWORD', [ '<username>', '<password>' ] );
define( 'WP_REDIS_SSL_CONTEXT', [
    'verify_peer' => true,
    'verify_peer_name' => true,
]);
define( 'WP_REDIS_PREFIX', 'myvps_' );
```

Le schéma `tls` est obligatoire : le service Valkey refuse les connexions non chiffrées. Le certificat du serveur est signé par une autorité de certification publique, aucun certificat n'est donc à télécharger : conservez la vérification du certificat activée (`verify_peer` et `verify_peer_name` à `true`) et ne la désactivez jamais.

L'utilisateur défini dans `WP_REDIS_PASSWORD` doit être autorisé par ses ACL à lire et écrire les clés utilisées par le plugin (par exemple le motif de clés `myvps_*` si vous utilisez le préfixe ci-dessus).

#### Préfixe des clés

Le préfixe des clés (`WP_REDIS_PREFIX`, qui remplace la constante obsolète `WP_CACHE_KEY_SALT`) n'est pas obligatoire, d'autant plus si vous n'avez qu'une seule application utilisant un service Valkey, mais si vous avez plusieurs sites WordPress, il sera utile pour déterminer **what-pushes-what**.

#### Définir une politique d'éviction adaptée au cache

Par défaut, le paramètre avancé `valkey_maxmemory_policy` de votre service vaut `noeviction` : lorsque la mémoire est pleine, Valkey refuse les nouvelles écritures et le plugin ne peut plus stocker d'objets dans le cache. Pour un usage de type cache comme celui-ci, nous vous recommandons de positionner ce paramètre sur `allkeys-lru`, afin que Valkey supprime les clés les moins récemment utilisées lorsque la mémoire est pleine.

Pour modifier ce paramètre, suivez le guide [Configurer les paramètres avancés pour Public Cloud Databases](/guides/public-cloud/databases/advanced-configuration). La modification de la configuration avancée peut entraîner un redémarrage du service.

#### Vérifier que les IPs autorisées sont à jour

N'oubliez pas d'ajouter l'adresse IP de votre serveur WordPress aux IPs autorisées du service Valkey. Pour cela, suivez le guide [Configurez les connexions entrantes d'un service Public Cloud Databases pour Valkey](/guides/public-cloud/databases/valkey-prepare-for-incoming-connections).

### Vérifier le gain de performance

#### Valider que le cache est alimenté

Si vous pouvez utiliser une CLI pour interroger le service Valkey (consultez le guide [Comment se connecter à un service Valkey avec la CLI](/guides/public-cloud/databases/valkey-connect-cli)), vous pouvez vérifier que les informations y ont été ajoutées après avoir parcouru quelques pages WordPress.

Dans notre cas :

```bash
valkey-cli --tls -u valkeys://<username>:<password>@<host>:<port>
```

#### Installer un plugin de suivi des requêtes

Si vous souhaitez obtenir plus d'informations sur l'impact du cache sur la performance, vous pouvez mesurer le gain de temps de réponse directement depuis votre navigateur. Vous pouvez également obtenir plus de détails en utilisant un plugin WordPress supplémentaire comme [Query Monitor](https://wordpress.org/plugins/query-monitor/).

#### Exemple de gain de performance avec un site WordPress basique

En utilisant un site WordPress simple, avec peu de contenu et un nombre très limité d'articles, examinons l'amélioration obtenue.

Nous allons observer le nombre de requêtes à la base de données dans les deux cas : avec et sans le cache activé.

Sans le cache, on observe un total de 15 requêtes à la base de données prenant 0,0235 s.

Avec le cache, on observe un total de 2 requêtes à la base de données prenant 0,0043 s.

#### Deux avantages principaux à utiliser un service Valkey

Comme nous l'avons vu, l'utilisation d'un service Valkey vous permet de gagner en performance pour votre CMS. Ce gain sera d'autant plus important que votre site stockera des données plus nombreuses et plus volumineuses. Vous bénéficierez également directement du fait que le serveur MySQL sera moins sollicité par la charge et les accès concurrents, ce qui permettra de gérer un nombre croissant d'utilisateurs.
