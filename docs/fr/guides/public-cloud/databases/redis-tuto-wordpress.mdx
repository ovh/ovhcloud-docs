## Objectif

Avez-vous un site web ou un blog de type CMS, peut-être propulsé par WordPress ? Découvrez comment accélérer les temps de chargement des pages et les requêtes SQL grâce à un service Valkey ! Dans ce tutoriel, nous allons mettre en place un service Valkey pour les données de votre CMS. Tous les utilisateurs, même les administrateurs et surtout les visiteurs, bénéficieront directement d'une meilleure performance du site web.

### Plateforme CMS

Pour ce tutoriel, nous proposons d'utiliser le CMS WordPress, fonctionnant sur Linux Ubuntu avec MySQL comme base de données principale. Pour obtenir le cache d'objets, nous utiliserons une base de données Public Cloud pour Valkey et un plugin WordPress pour Redis®.

:::warning
Ce tutoriel vous montrera comment utiliser une ou plusieurs solutions OVHcloud avec des outils externes, et décrira les actions à mener dans un contexte spécifique. Merci de penser à adapter ces actions à votre situation.

## Prérequis

Ce tutoriel nécessite :

- Un WordPress fonctionnel
- Un compte administrateur WordPress pour installer un plugin
- Un [client PHP Redis®](https://redis.io/clients#php) pris en charge par le plugin
- Une base de données OVHcloud Public Cloud pour Valkey

## En pratique

### Environnement technique du tutoriel

Les principales versions des composants logiciels utilisés pour les captures d'écran et l'exemple suivants sont les suivantes :

- Linux Ubuntu 21.10 / apache2 2.4.48 / PHP 8.0 / MySQL 8.0.27
- WordPress : 5.8.2
- phpredis : 5.3.2
- Redis Object Cache : 2.0.21
- Redis® open source : 6.2

### Configuration de votre CMS : WordPress

Si vous devez installer WordPress, veuillez consulter le guide officiel : [WordPress How To Install](https://wordpress.org/support/article/how-to-install-wordpress/).

Une fois cela fait, nous allons configurer correctement le back-end de WordPress.
Pour les étapes suivantes, considérons que vous disposez d'un système WordPress fonctionnel sur une plateforme LAMP (Linux, Apache, MySQL, PHP).

### Client PHP Redis® : PhpRedis

Comme WordPress est basé sur PHP, nous aurons besoin d'un client PHP Redis®. Nous proposons d'utiliser l'un des principaux [clients PHP Redis®](https://redis.io/clients#php) recommandés : PhpRedis.

Le protocole TLS étant requis pour sécuriser la connexion à la base de données OVHcloud Public Cloud pour Valkey, nous devons utiliser la version 5.3.x de PhpRedis ou une version supérieure.

Veuillez vérifier que PhpRedis est installé, avec une version compatible :

- Si vous avez un accès SSH à votre serveur WordPress, vous pouvez utiliser la commande suivante :

```bash
dpkg -l php-redis
```
Si ce n'est pas disponible sur votre système, veuillez l'installer :

```bash
sudo apt install php-redis
sudo systemctl restart apache2
```
- Si vous n'avez pas d'accès SSH au système, utilisez la fonction phpinfo() et effectuez une recherche sur le module Redis®, comme dans l'exemple suivant :

<img className="thumbnail" alt="Plugin Redis PHPInfo" src="/images/public-cloud/databases/redis-tuto-01-wordpress/Redis_phpinfo.png" loading="lazy" />

### Plugin WordPress Redis®

Il existe plusieurs plugins Redis® pouvant être utilisés pour intégrer un service Valkey. Vous pouvez les rechercher directement dans le menu Extensions. Pour ce tutoriel, nous avons décidé d'utiliser le plus populaire d'entre eux : Redis Object Cache. Cliquez sur le bouton Install Now :

<img className="thumbnail" alt="Recherche du plugin Redis" src="/images/public-cloud/databases/redis-tuto-01-wordpress/Redis_plugin_list.png" loading="lazy" />

Vous pouvez obtenir plus d'informations sur ce plugin WordPress dans la [documentation officielle du plugin WordPress - Redis Object Cache](https://wordpress.org/plugins/redis-cache/).

### Configurer WordPress pour se connecter au service Valkey

#### Modifier wp-config.php

Avant d'activer le plugin Redis Object Cache, il est nécessaire de configurer les paramètres de connexion au service Valkey.
Par défaut, ce plugin recherche un service Valkey hébergé sur le même serveur que votre WordPress.
Ce n'est pas notre cas de figure ici, puisque le service Valkey est hébergé sur OVHcloud Public Cloud Databases.

Nous allons suivre le wiki officiel du plugin pour définir le serveur distant : [https://github.com/rhubarbgroup/redis-cache/wiki/Configuration-Options](https://github.com/rhubarbgroup/redis-cache/wiki/Configuration-Options).
Cela doit être fait dans le fichier de configuration de WordPress (**wp-config.php** situé dans /var/www/wordpress/ dans notre exemple) en ajoutant les lignes suivantes :

```php
define('WP_REDIS_CLIENT', 'phpredis' );
define('WP_REDIS_SCHEME', 'tls');
define('WP_REDIS_HOST', 'my_redis-123456-123456.database.cloud.ovh.net');
define('WP_REDIS_PORT', '20185');
define('WP_REDIS_PASSWORD', ['my_redis_user', 'my_password_here']);
define('WP_CACHE_KEY_SALT', 'myOVHcloudRedis_' );
```
#### Modifier l'hôte

La clé de salage n'est pas obligatoire, d'autant plus si vous n'avez qu'une seule application utilisant un service Valkey, mais si vous avez plusieurs sites WordPress, il sera utile pour déterminer **what-pushes-what**.

#### Vérifier que les IPs autorisées sont à jour

N'oubliez pas d'ajouter l'adresse IP de WordPress à la liste des IPs autorisées du service Valkey.

### Vérifier le gain de performance

#### Valider que le cache est alimenté

Si vous pouvez utiliser une CLI pour interroger le service Valkey, vous pouvez vérifier que les informations y ont été ajoutées après avoir parcouru quelques pages WordPress.

Dans notre cas :
```bash
my_redis-123456-123456.database.cloud.ovh.net:20185> SCAN 0
1) "480"
2) 1) "myvps_wp:post_meta:782"
2) "myvps_wp:post_meta:418"
3) "myvps_wp:terms:13"
4) "myvps_wp:site-options:1-notoptions"
5) "myvps_wp:options:alloptions"
6) "myvps_wp:post_meta:905"
7) "myvps_wp:options:notoptions"
8) "mywpvps_wp:posts:get_page_by_path-83503918bbdb048f39fd1d3e462c8251-0.24924400 1637188954"
9) "myvps_wp:useremail:yo@chrisam.es"
10) "myvps_wp:terms:3"
```
#### Installer un plugin de suivi des requêtes

Si vous souhaitez obtenir plus d'informations sur l'impact du cache sur la performance, vous pouvez mesurer le gain de temps de réponse directement depuis votre navigateur. Vous pouvez également obtenir plus de détails en utilisant un plugin WordPress supplémentaire comme [Query Monitor](https://wordpress.org/plugins/query-monitor/).

#### Exemple de gain de performance avec un site WordPress basique

En utilisant un site WordPress simple, avec peu de contenu et un nombre très limité d'articles, examinons l'amélioration obtenue.

Nous allons observer le nombre de requêtes à la base de données dans les deux cas : avec et sans le cache activé.

Sans le cache, on observe un total de 15 requêtes à la base de données prenant 0,0235 s :

Avec le cache, on observe un total de 2 requêtes à la base de données prenant 0,0043 s :

#### Deux avantages principaux à utiliser un service Valkey

Comme nous l'avons vu, l'utilisation d'un service Valkey vous permet de gagner en performance pour votre CMS. Ce gain sera d'autant plus important que votre site stockera des données plus nombreuses et plus volumineuses. Vous bénéficierez également directement du fait que le serveur MySQL sera moins sollicité par la charge et les accès concurrents, ce qui permettra de gérer un nombre croissant d'utilisateurs.
