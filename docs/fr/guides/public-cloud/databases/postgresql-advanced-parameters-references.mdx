## Objectif

Ce guide liste tous les paramètres avancés pris en charge qui vous permettent de configurer votre Public Cloud Databases for PostgreSQL selon vos cas d'usage.

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud.
- Une base de données exécutée sur votre service OVHcloud Public Cloud Databases ([ce guide](/guides/public-cloud/databases/getting-started) peut vous aider à répondre à ce prérequis).
- Un accès à votre <ManagerLink to="/">espace client OVHcloud</ManagerLink> ou à l'<ApiLink>API OVHcloud</ApiLink>.

## En pratique

:::warning
La gestion des paramètres avancés n'est pas prise en charge via Terraform.

:::


### Depuis l'espace client OVHcloud

Veuillez consulter ce [guide](/guides/public-cloud/databases/advanced-configuration#depuis-lespace-client-ovhcloud) pour découvrir comment modifier vos paramètres avancés depuis l'espace client OVHcloud.

### Depuis l'API

Veuillez consulter ce [guide](/guides/public-cloud/databases/advanced-configuration#depuis-lapi) pour découvrir comment modifier vos paramètres avancés depuis l'API OVHcloud.

### Paramètres avancés pour PostgreSQL

Vous trouverez ci-dessous un récapitulatif de toutes les options de configuration disponibles pour un service PostgreSQL :

#### Paramètres généraux

| Parameters |
|------------|
|**pg.autovacuum_analyze_scale_factor** `double`<br/>min: `0` max: `1`<br/>Spécifie une fraction de la taille de la table à ajouter à autovacuum_analyze_threshold pour décider s'il faut déclencher un ANALYZE (par exemple `0.2` pour 20 % de la taille de la table). La valeur par défaut est `0.2`.<br/>|
|**pg.autovacuum_analyze_threshold** `long`<br/>min: `0` max: `2147483647`<br/>Spécifie le nombre minimum de tuples insérés, mis à jour ou supprimés nécessaire pour déclencher un ANALYZE sur une table donnée. La valeur par défaut est `50`.<br/>|
|**pg.autovacuum_freeze_max_age** `long`<br/>min: `200000000` max: `1500000000`<br/>Spécifie l'âge maximal (en transactions) que le champ pg_class.relfrozenxid d'une table peut atteindre avant qu'une opération VACUUM ne soit forcée pour éviter un bouclage (wraparound) des identifiants de transaction au sein de la table. Le système lance des processus autovacuum pour éviter ce bouclage même lorsque l'autovacuum est par ailleurs désactivé. La modification de ce paramètre entraîne un redémarrage du service.<br/>|
|**pg.autovacuum_max_workers** `long`<br/>min: `1` max: `20`<br/>Spécifie le nombre maximum de processus autovacuum (autres que le lanceur d'autovacuum) pouvant s'exécuter simultanément. La valeur par défaut est `3`. La modification de ce paramètre entraîne un redémarrage du service.<br/>|
|**pg.autovacuum_naptime** `long`<br/>min: `1` max: `86400`<br/>Spécifie le délai minimum entre deux exécutions de l'autovacuum sur une base de données donnée. Le délai est exprimé en secondes. La valeur par défaut est `60`.<br/>|
|**pg.autovacuum_vacuum_cost_delay** `long`<br/>min: `-1` max: `100`<br/>Spécifie la valeur de délai de coût utilisée lors des opérations VACUUM automatiques. Si `-1` est spécifié, la valeur classique de vacuum_cost_delay sera utilisée. La valeur par défaut est `2` (valeur par défaut du projet PostgreSQL).<br/>|
|**pg.autovacuum_vacuum_cost_limit** `long`<br/>min: `-1` max: `10000`<br/>Spécifie la valeur de limite de coût utilisée lors des opérations VACUUM automatiques. Si `-1` est spécifié, la valeur classique de vacuum_cost_limit sera utilisée. La valeur par défaut est `-1` (valeur par défaut du projet PostgreSQL).<br/>|
|**pg.autovacuum_vacuum_scale_factor** `double`<br/>min: `0` max: `1`<br/>Spécifie une fraction de la taille de la table à ajouter à autovacuum_vacuum_threshold pour décider s'il faut déclencher un VACUUM (par exemple `0.2` pour 20 % de la taille de la table). La valeur par défaut est `0.2`.<br/>|
|**pg.autovacuum_vacuum_threshold** `long`<br/>min: `0` max: `2147483647`<br/>Spécifie le nombre minimum de tuples mis à jour ou supprimés nécessaire pour déclencher un VACUUM sur une table donnée. La valeur par défaut est `50`.<br/>|
|**pg.bgwriter_delay** `long`<br/>min: `10` max: `10000`<br/>Spécifie le délai entre deux cycles d'activité du background writer, en millisecondes. La valeur par défaut est `200`.<br/>|
|**pg.bgwriter_flush_after** `long`<br/>min: `0` max: `2048`<br/>Chaque fois que plus de bgwriter_flush_after octets ont été écrits par le background writer, tente de forcer l'OS à transmettre ces écritures au stockage sous-jacent. Exprimé en kilooctets. Une valeur de 0 désactive la réécriture forcée. La valeur par défaut est `512`.<br/>|
|**pg.bgwriter_lru_maxpages** `long`<br/>min: `0` max: `1073741823`<br/>À chaque cycle, le background writer n'écrira pas plus de ce nombre de buffers. Une valeur de zéro désactive l'écriture en arrière-plan. La valeur par défaut est `100`.<br/>|
|**pg.bgwriter_lru_multiplier** `double`<br/>min: `0` max: `10`<br/>Le besoin moyen récent en nouveaux buffers est multiplié par bgwriter_lru_multiplier pour estimer le nombre de buffers qui sera nécessaire au cycle suivant (dans la limite de bgwriter_lru_maxpages). La valeur 1.0 représente une politique « juste à temps » consistant à écrire exactement le nombre de buffers prévu comme nécessaire. Des valeurs plus élevées apportent une marge face aux pics de demande, tandis que des valeurs plus faibles laissent volontairement des écritures à effectuer par les processus serveur. La valeur par défaut est `2.0`.<br/>|
|**pg.deadlock_timeout** `long`<br/>min: `500` max: `1800000`<br/>Il s'agit du délai, en millisecondes, à attendre sur un verrou avant de vérifier s'il existe une situation d'interblocage (deadlock). La valeur par défaut est `1000` (valeur par défaut du projet PostgreSQL).<br/>|
|**pg.default_toast_compression** `string`<br/>values: `lz4`, `pglz`<br/>Spécifie la méthode de compression TOAST par défaut pour les valeurs des colonnes compressibles. La valeur par défaut est `lz4`. Disponible uniquement à partir de PostgreSQL 14.<br/>|
|**pg.idle_in_transaction_session_timeout** `long`<br/>min: `0` max: `604800000`<br/>Met fin aux sessions ayant des transactions ouvertes après ce nombre de millisecondes<br/>|
|**pg.jit** `boolean`<br/>Contrôle l'utilisation, à l'échelle du système, de la compilation Just-in-Time (JIT).<br/>|
|**pg.log_autovacuum_min_duration** `long`<br/>min: `-1` max: `2147483647`<br/>Fait consigner chaque action exécutée par l'autovacuum si elle a duré au moins ce nombre de millisecondes. Une valeur de zéro consigne toutes les actions d'autovacuum. La valeur -1 désactive la consignation des actions d'autovacuum. La valeur par défaut est `1000`.<br/>|
|**pg.log_error_verbosity** `string`<br/>values: `DEFAULT`, `TERSE`, `VERBOSE`<br/>Contrôle le niveau de détail écrit dans le journal du serveur pour chaque message consigné.<br/>|
|**pg.log_line_prefix** `string`<br/>values: `'%m[%p]%q[user=%u,db=%d,app=%a]'`, `'%t[%p]:[%l-1]user=%u,db=%d,app=%a,client=%h'`, `'pid=%p,user=%u,db=%d,app=%a,client=%h'`, `'pid=%p,user=%u,db=%d,app=%a,client=%h,txid=%x,qid=%Q'`<br/>Choisissez l'un des formats de journal disponibles.<br/>|
|**pg.log_min_duration_statement** `long`<br/>min: `-1` max: `86400000`<br/>Consigne les instructions dont l'exécution dépasse ce nombre de millisecondes, -1 désactive cette option<br/>|
|**pg.log_temp_files** `long`<br/>min: `-1` max: `2147483647`<br/>Consigne les instructions pour chaque fichier temporaire créé dont la taille dépasse ce nombre de kilooctets, -1 désactive cette option<br/>|
|**pg.max_files_per_process** `long`<br/>min: `1000` max: `4096`<br/>Nombre maximum de fichiers pouvant être ouverts par processus dans PostgreSQL. La valeur par défaut est `1000` (valeur par défaut du projet PostgreSQL). La modification de ce paramètre entraîne un redémarrage du service.<br/>|
|**pg.max_locks_per_transaction** `long`<br/>min: `64` max: `6400`<br/>Nombre maximum de verrous par transaction dans PostgreSQL. La modification de ce paramètre entraîne un redémarrage du service.<br/>|
|**pg.max_logical_replication_workers** `long`<br/>min: `4` max: `64`<br/>Nombre maximum de workers de réplication logique dans PostgreSQL (issus du pool de max_parallel_workers). La valeur par défaut est `4` (valeur par défaut du projet PostgreSQL). La modification de ce paramètre entraîne un redémarrage du service.<br/>|
|**pg.max_parallel_workers** `long`<br/>min: `0` max: `96`<br/>Définit le nombre maximum de workers que le système peut prendre en charge pour les requêtes parallèles. La valeur par défaut est `8` (valeur par défaut du projet PostgreSQL).<br/>|
|**pg.max_parallel_workers_per_gather** `long`<br/>min: `0` max: `96`<br/>Définit le nombre maximum de workers pouvant être démarrés par un seul nœud Gather ou Gather Merge. La valeur par défaut est `2` (valeur par défaut du projet PostgreSQL).<br/>|
|**pg.max_pred_locks_per_transaction** `long`<br/>min: `64` max: `5120`<br/>Nombre maximum de verrous de prédicat par transaction dans PostgreSQL. La valeur par défaut est `64` (valeur par défaut du projet PostgreSQL). La modification de ce paramètre entraîne un redémarrage du service.<br/>|
|**pg.max_prepared_transactions** `long`<br/>min: `0` max: `10000`<br/>Nombre maximum de transactions préparées dans PostgreSQL. La valeur par défaut est `0`. La modification de ce paramètre entraîne un redémarrage du service.<br/>|
|**pg.max_replication_slots** `long`<br/>min: `8` max: `64`<br/>Nombre maximum de slots de réplication dans PostgreSQL. La valeur par défaut est `20`. La modification de ce paramètre entraîne un redémarrage du service.<br/>|
|**pg.max_slot_wal_keep_size** `long`<br/>min: `-1` max: `2147483647`<br/>Taille maximale de WAL (en Mo) réservée aux slots de réplication dans PostgreSQL. Si `-1` est spécifié, les slots de réplication peuvent conserver une quantité illimitée de fichiers WAL. La valeur par défaut est `-1` (valeur par défaut du projet PostgreSQL). Le paramètre de taille minimale wal_keep_size est prioritaire sur celui-ci.<br/>|
|**pg.max_stack_depth** `long`<br/>min: `2097152` max: `6291456`<br/>Profondeur maximale de la pile, en octets. La valeur par défaut est `2097152` (valeur par défaut du projet PostgreSQL).<br/>|
|**pg.max_standby_archive_delay** `long`<br/>min: `1` max: `43200000`<br/>Délai maximum du standby en mode archive, en millisecondes. La valeur par défaut est `30000` (valeur par défaut du projet PostgreSQL).<br/>|
|**pg.max_standby_streaming_delay** `long`<br/>min: `1` max: `43200000`<br/>Délai maximum du standby en mode streaming, en millisecondes. La valeur par défaut est `30000` (valeur par défaut du projet PostgreSQL).<br/>|
|**pg.max_wal_senders** `long`<br/>min: `20` max: `64`<br/>Nombre maximum d'émetteurs WAL dans PostgreSQL. La valeur par défaut est `20`. La modification de ce paramètre entraîne un redémarrage du service.<br/>|
|**pg.max_worker_processes** `long`<br/>min: `8` max: `96`<br/>Définit le nombre maximum de processus en arrière-plan que le système peut prendre en charge. La valeur par défaut est `8`. La modification de ce paramètre entraîne un redémarrage du service.<br/>|
|**pg.password_encryption** `string`<br/>values: `md5`, `scram-sha-256`<br/>Choisit l'algorithme de chiffrement des mots de passe.<br/>|
|**pg.pg_partman_bgw.interval** `long`<br/>min: `3600` max: `604800`<br/>Définit l'intervalle de temps, en secondes, entre deux exécutions des tâches planifiées de pg_partman. La valeur par défaut est `3600`.<br/>|
|**pg.pg_partman_bgw.role** `string`<br/>Contrôle quel rôle utiliser pour les tâches planifiées en arrière-plan de pg_partman.<br/>|
|**pg.pg_stat_monitor.pgsm_enable_query_plan** `boolean`<br/>Active ou désactive le suivi des plans de requête. La modification de ce paramètre entraîne un redémarrage du service. Disponible uniquement à partir de PostgreSQL 13.<br/>|
|**pg.pg_stat_monitor.pgsm_max_buckets** `long`<br/>min: `1` max: `10`<br/>Définit le nombre maximum de buckets. La modification de ce paramètre entraîne un redémarrage du service. Disponible uniquement à partir de PostgreSQL 13.<br/>|
|**pg.pg_stat_statements.track** `string`<br/>values: `all`, `none`, `top`<br/>Contrôle quelles instructions sont comptabilisées. Indiquez top pour suivre les instructions de premier niveau (celles émises directement par les clients), all pour suivre également les instructions imbriquées (comme celles invoquées au sein de fonctions), ou none pour désactiver la collecte des statistiques d'instructions. La valeur par défaut est `top`.<br/>|
|**pg.temp_file_limit** `long`<br/>min: `-1` max: `2147483647`<br/>Limite de fichiers temporaires PostgreSQL en KiB, -1 pour illimité<br/>|
|**pg.timezone** `string`<br/>Fuseau horaire du service PostgreSQL<br/>|
|**pg.track_activity_query_size** `long`<br/>min: `1024` max: `10240`<br/>Spécifie le nombre d'octets réservés pour suivre la commande en cours d'exécution pour chaque session active. La modification de ce paramètre entraîne un redémarrage du service.<br/>|
|**pg.track_commit_timestamp** `string`<br/>values: `off`, `on`<br/>Enregistre l'horodatage de commit des transactions. La modification de ce paramètre entraîne un redémarrage du service.<br/>|
|**pg.track_functions** `string`<br/>values: `all`, `none`, `pl`<br/>Active le suivi du nombre d'appels de fonction et du temps utilisé.<br/>|
|**pg.track_io_timing** `string`<br/>values: `off`, `on`<br/>Active la mesure du temps des appels d'E/S de la base de données. La valeur par défaut est `off`. Lorsqu'elle est activée, le système interroge de manière répétée l'heure actuelle auprès du système d'exploitation, ce qui peut entraîner une surcharge significative sur certaines plateformes.<br/>|
|**pg.wal_sender_timeout** `long`<br/>Met fin aux connexions de réplication inactives depuis plus longtemps que cette durée, en millisecondes. Une valeur de zéro désactive ce délai d'expiration.<br/>|
|**pg.wal_writer_delay** `long`<br/>min: `10` max: `200`<br/>Intervalle de vidage (flush) du WAL, en millisecondes. La valeur par défaut est `200`. Définir ce paramètre à une valeur plus basse peut avoir un impact négatif sur les performances.<br/>|
|**pgbouncer.autodb_idle_timeout** `long`<br/>min: `0` max: `86400`<br/>Si les pools de bases de données créés automatiquement sont restés inutilisés pendant ce nombre de secondes, ils sont libérés. Si la valeur est 0, ce délai d'expiration est désactivé. [secondes]<br/>|
|**pgbouncer.autodb_max_db_connections** `long`<br/>min: `0` max: `2147483647`<br/>N'autorise pas plus de ce nombre de connexions serveur par base de données (quel que soit l'utilisateur). Une valeur de 0 signifie illimité.<br/>|
|**pgbouncer.autodb_pool_mode** `string`<br/>values: `session`, `statement`, `transaction`<br/>Mode de pool PGBouncer<br/>|
|**pgbouncer.autodb_pool_size** `long`<br/>min: `0` max: `10000`<br/>Si la valeur est non nulle, crée automatiquement un pool de cette taille par utilisateur lorsqu'un pool n'existe pas déjà.<br/>|
|**pgbouncer.max_prepared_statements** `long`<br/>min: `0` max: `3000`<br/>PgBouncer suit les commandes liées aux instructions préparées nommées au niveau protocole envoyées par le client dans les modes de pooling par transaction et par instruction lorsque max_prepared_statements est défini à une valeur non nulle. Une valeur de 0 désactive les instructions préparées. max_prepared_statements vaut 100 par défaut, et son maximum est 3000.<br/>|
|**pgbouncer.min_pool_size** `long`<br/>min: `0` max: `10000`<br/>Ajoute davantage de connexions serveur au pool si celui-ci est en dessous de ce nombre. Améliore le comportement lorsque la charge habituelle revient soudainement après une période d'inactivité totale. La valeur est effectivement plafonnée à la taille du pool.<br/>|
|**pgbouncer.server_idle_timeout** `long`<br/>min: `0` max: `86400`<br/>Si une connexion serveur est restée inactive pendant plus de ce nombre de secondes, elle sera fermée. Si la valeur est 0, ce délai d'expiration est désactivé. [secondes]<br/>|
|**pgbouncer.server_lifetime** `long`<br/>min: `60` max: `86400`<br/>Le pooler fermera une connexion serveur inutilisée connectée depuis plus longtemps que cette durée. [secondes]<br/>|
|**pgbouncer.server_reset_query_always** `boolean`<br/>Exécute server_reset_query (DISCARD ALL) dans tous les modes de pooling<br/>|
|**pglookout.max_failover_replication_time_lag** `long`<br/>min: `10` max: `9223372036854776000`<br/>Nombre de secondes d'indisponibilité du master avant de déclencher un basculement (failover) de la base de données vers le standby<br/>|
|**shared_buffers_percentage** `double`<br/>min: `20` max: `60`<br/>Pourcentage de la RAM totale que le serveur de base de données utilise pour les buffers de mémoire partagée. La plage valide est 20-60 (flottant), ce qui correspond à 20 % - 60 %. Ce paramètre ajuste la valeur de configuration shared_buffers. La modification de ce paramètre entraîne un redémarrage du service.<br/>|
|**timescaledb.max_background_workers** `long`<br/>min: `1` max: `4096`<br/>Le nombre de workers en arrière-plan pour les opérations timescaledb. Vous devez configurer ce paramètre sur la somme de votre nombre de bases de données et du nombre total de workers en arrière-plan simultanés que vous souhaitez voir s'exécuter à un instant donné. La modification de ce paramètre entraîne un redémarrage du service.<br/>|
|**work_mem** `long`<br/>min: `1` max: `1024`<br/>Définit la quantité maximale de mémoire à utiliser par une opération de requête (comme un tri ou une table de hachage) avant d'écrire dans des fichiers disque temporaires, en Mo. La valeur par défaut est 1 Mo + 0,075 % de la RAM totale (jusqu'à 32 Mo).<br/>|
