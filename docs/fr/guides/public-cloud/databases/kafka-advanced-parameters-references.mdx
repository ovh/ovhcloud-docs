## Objectif

Ce guide répertorie tous les paramètres avancés pris en charge qui vous permettent de configurer votre service Public Cloud Databases pour Kafka selon vos cas d'usage.

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud   
- Un service Analytics actif sur votre projet OVHcloud Public Cloud ([ce guide](/guides/public-cloud/data-analytics/analytics/getting-started) peut vous aider à répondre à ce prérequis)
- Un accès à votre <ManagerLink to="/">espace client OVHcloud</ManagerLink> ou à l'<ApiLink>API OVHcloud</ApiLink>

## En pratique

:::warning
La gestion des paramètres avancés n'est pas prise en charge via Terraform.

:::


### Depuis l'espace client OVHcloud

Veuillez consulter ce [guide](/guides/public-cloud/data-analytics/analytics/advanced-configuration#using-the-ovhcloud-control-panel) pour savoir comment modifier vos paramètres avancés depuis l'espace client OVHcloud.

### Depuis l'API

Veuillez consulter ce [guide](/guides/public-cloud/data-analytics/analytics/advanced-configuration#using-api) pour savoir comment modifier vos paramètres avancés depuis l'API OVHcloud.

### Paramètres avancés pour Kafka

Vous trouverez ci-dessous un récapitulatif de toutes les options de configuration disponibles pour le service Kafka :

| Paramètres |
|------------|
|**kafka.auto_create_topics_enable** `boolean`<br/>Active la création automatique des topics. (Par défaut : true)<br/>|
|**kafka.compression_type** `string`<br/>valeurs : `gzip`, `lz4`, `producer`, `snappy`, `uncompressed`, `zstd`<br/>Spécifie le type de compression final pour un topic donné. Cette configuration accepte les codecs de compression standards ('gzip', 'snappy', 'lz4', 'zstd'). Elle accepte également 'uncompressed', équivalent à l'absence de compression, ainsi que 'producer', qui signifie que le codec de compression défini par le producteur est conservé.(Par défaut : producer)<br/>|
|**kafka.connections_max_idle_ms** `long`<br/>min : `1000` max : `3600000`<br/>Délai d'expiration des connexions inactives : les threads du processeur de sockets du serveur ferment les connexions inactives depuis plus longtemps que cette valeur. (Par défaut : 600000 ms (10 minutes))<br/>|
|**kafka.default_replication_factor** `long`<br/>min : `1` max : `10`<br/>Facteur de réplication pour les topics créés automatiquement (Par défaut : 3)<br/>|
|**kafka.group_initial_rebalance_delay_ms** `long`<br/>min : `0` max : `300000`<br/>Durée, en millisecondes, pendant laquelle le coordinateur de groupe attend l'arrivée d'autres consommateurs dans un nouveau groupe avant d'effectuer le premier rééquilibrage. Un délai plus long signifie potentiellement moins de rééquilibrages, mais augmente le temps avant le début du traitement. La valeur par défaut est de 3 secondes. Lors du développement et des tests, il peut être souhaitable de définir cette valeur à 0 afin de ne pas retarder le temps d'exécution des tests. (Par défaut : 3000 ms (3 secondes))<br/>|
|**kafka.group_max_session_timeout_ms** `long`<br/>min : `0` max : `1800000`<br/>Délai d'expiration de session maximal autorisé pour les consommateurs enregistrés. Des délais plus longs laissent plus de temps aux consommateurs pour traiter les messages entre les heartbeats, au prix d'un temps de détection des pannes plus long. Par défaut : 1800000 ms (30 minutes)<br/>|
|**kafka.group_min_session_timeout_ms** `long`<br/>min : `0` max : `60000`<br/>Délai d'expiration de session minimal autorisé pour les consommateurs enregistrés. Des délais plus longs laissent plus de temps aux consommateurs pour traiter les messages entre les heartbeats, au prix d'un temps de détection des pannes plus long. (Par défaut : 6000 ms (6 secondes))<br/>|
|**kafka.log_cleaner_delete_retention_ms** `long`<br/>min : `0` max : `315569260000`<br/>Durée de conservation des enregistrements de suppression ? (Par défaut : 86400000 (1 jour))<br/>|
|**kafka.log_cleaner_max_compaction_lag_ms** `long`<br/>min : `30000` max : `9223372036854776000`<br/>Durée maximale pendant laquelle un message restera non compacté. S'applique uniquement aux logs en cours de compaction. (Par défaut : 9223372036854775807 ms (Long.MAX_VALUE))<br/>|
|**kafka.log_cleaner_min_cleanable_ratio** `double`<br/>min : `0.2` max : `0.9`<br/>Contrôle la fréquence du compacteur de logs. Une valeur plus élevée signifie des compactions plus fréquentes, mais aussi plus d'espace gaspillé pour les logs. Envisagez de définir log.cleaner.max.compaction.lag.ms pour forcer des compactions plus rapides, plutôt que de définir une valeur très élevée pour cette option. (Par défaut : 0.5)<br/>|
|**kafka.log_cleaner_min_compaction_lag_ms** `long`<br/>min : `0` max : `9223372036854776000`<br/>Durée minimale pendant laquelle un message reste non compacté dans le log. S'applique uniquement aux logs en cours de compaction. (Par défaut : 0 ms)<br/>|
|**kafka.log_cleanup_policy** `string`<br/>valeurs : `compact`, `compact,delete`, `delete`<br/>Politique de nettoyage par défaut pour les segments dépassant la fenêtre de rétention (Par défaut : delete)<br/>|
|**kafka.log_flush_interval_messages** `long`<br/>min : `1` max : `9223372036854776000`<br/>Nombre de messages accumulés sur une partition de log avant que les messages ne soient écrits sur le disque (Par défaut : 9223372036854775807 (Long.MAX_VALUE))<br/>|
|**kafka.log_flush_interval_ms** `long`<br/>min : `0` max : `9223372036854776000`<br/>Durée maximale, en ms, pendant laquelle un message d'un topic quelconque est conservé en mémoire (page-cache) avant d'être écrit sur le disque. Si cette valeur n'est pas définie, celle de log.flush.scheduler.interval.ms est utilisée (Par défaut : null)<br/>|
|**kafka.log_index_interval_bytes** `long`<br/>min : `0` max : `104857600`<br/>Intervalle auquel Kafka ajoute une entrée à l'index des offsets (Par défaut : 4096 bytes (4 kibioctets))<br/>|
|**kafka.log_index_size_max_bytes** `long`<br/>min : `1048576` max : `104857600`<br/>Taille maximale, en octets, de l'index des offsets (Par défaut : 10485760 (10 mébioctets))<br/>|
|**kafka.log_local_retention_bytes** `long`<br/>min : `-2` max : `9223372036854776000`<br/>Taille maximale des segments de log locaux pouvant croître pour une partition avant qu'elle ne devienne éligible à la suppression. Si la valeur -2 est définie, la valeur de log.retention.bytes est utilisée. La valeur effective doit toujours être inférieure ou égale à la valeur de log.retention.bytes. (Par défaut : -2)<br/>|
|**kafka.log_local_retention_ms** `long`<br/>min : `-2` max : `9223372036854776000`<br/>Nombre de millisecondes de conservation des segments de log locaux avant qu'ils ne deviennent éligibles à la suppression. Si la valeur -2 est définie, la valeur de log.retention.ms est utilisée. La valeur effective doit toujours être inférieure ou égale à la valeur de log.retention.ms. (Par défaut : -2)<br/>|
|**kafka.log_message_downconversion_enable** `boolean`<br/>Cette configuration contrôle si la conversion descendante des formats de message est activée pour satisfaire les requêtes de consommation. (Par défaut : true)<br/>|
|**kafka.log_message_timestamp_difference_max_ms** `long`<br/>min : `0` max : `9223372036854776000`<br/>Différence maximale autorisée entre l'horodatage auquel un broker reçoit un message et l'horodatage spécifié dans le message (Par défaut : 9223372036854775807 (Long.MAX_VALUE))<br/>|
|**kafka.log_message_timestamp_type** `string`<br/>valeurs : `CreateTime`, `LogAppendTime`<br/>Définit si l'horodatage du message correspond à l'heure de création du message ou à l'heure d'ajout au log. (Par défaut : CreateTime)<br/>|
|**kafka.log_preallocate** `boolean`<br/>Faut-il préallouer le fichier lors de la création d'un nouveau segment ? (Par défaut : false)<br/>|
|**kafka.log_retention_bytes** `long`<br/>min : `-1` max : `9223372036854776000`<br/>Taille maximale du log avant suppression des messages (Par défaut : -1)<br/>|
|**kafka.log_retention_hours** `long`<br/>min : `-1` max : `2147483647`<br/>Nombre d'heures de conservation d'un fichier log avant suppression (Par défaut : 168 heures (1 semaine))<br/>|
|**kafka.log_retention_ms** `long`<br/>min : `-1` max : `9223372036854776000`<br/>Nombre de millisecondes de conservation d'un fichier log avant suppression (en millisecondes). Si cette valeur n'est pas définie, celle de log.retention.minutes est utilisée. Si la valeur -1 est définie, aucune limite de temps n'est appliquée. (Par défaut : null, log.retention.hours s'applique)<br/>|
|**kafka.log_roll_jitter_ms** `long`<br/>min : `0` max : `9223372036854776000`<br/>Écart maximal à soustraire de logRollTimeMillis (en millisecondes). Si cette valeur n'est pas définie, celle de log.roll.jitter.hours est utilisée (Par défaut : null)<br/>|
|**kafka.log_roll_ms** `long`<br/>min : `1` max : `9223372036854776000`<br/>Durée maximale avant qu'un nouveau segment de log ne soit créé (en millisecondes). (Par défaut : null, log.roll.hours s'applique (Par défaut : 168, 7 jours))<br/>|
|**kafka.log_segment_bytes** `long`<br/>min : `10485760` max : `1073741824`<br/>Taille maximale d'un seul fichier log (Par défaut : 1073741824 bytes (1 gibioctet))<br/>|
|**kafka.log_segment_delete_delay_ms** `long`<br/>min : `0` max : `3600000`<br/>Délai d'attente avant la suppression d'un fichier du système de fichiers (Par défaut : 60000 ms (1 minute))<br/>|
|**kafka.max_connections_per_ip** `long`<br/>min : `256` max : `2147483647`<br/>Nombre maximal de connexions autorisées depuis chaque adresse IP (Par défaut : 2147483647).<br/>|
|**kafka.max_incremental_fetch_session_cache_slots** `long`<br/>min : `1000` max : `10000`<br/>Nombre maximal de sessions de fetch incrémental que le broker maintiendra. (Par défaut : 1000)<br/>|
|**kafka.message_max_bytes** `long`<br/>min : `0` max : `100001200`<br/>Taille maximale de message que le serveur peut recevoir. (Par défaut : 1048588 bytes (1 mébioctet + 12 octets))<br/>|
|**kafka.min_insync_replicas** `long`<br/>min : `1` max : `7`<br/>Lorsqu'un producteur définit acks sur 'all' (ou '-1'), min.insync.replicas spécifie le nombre minimal de répliques devant confirmer une écriture pour que celle-ci soit considérée comme réussie. (Par défaut : 1)<br/>|
|**kafka.num_partitions** `long`<br/>min : `1` max : `1000`<br/>Nombre de partitions pour les topics créés automatiquement (Par défaut : 1)<br/>|
|**kafka.offsets_retention_minutes** `long`<br/>min : `1` max : `2147483647`<br/>Fenêtre de rétention des logs, en minutes, pour le topic des offsets (Par défaut : 10080 minutes (7 jours))<br/>|
|**kafka.producer_purgatory_purge_interval_requests** `long`<br/>min : `10` max : `10000`<br/>Intervalle de purge (en nombre de requêtes) du purgatoire des requêtes du producteur (Par défaut : 1000).<br/>|
|**kafka.replica_fetch_max_bytes** `long`<br/>min : `1048576` max : `104857600`<br/>Nombre d'octets de messages à tenter de récupérer pour chaque partition. Ce n'est pas un maximum absolu : si le premier batch d'enregistrements de la première partition non vide du fetch est plus grand que cette valeur, il sera tout de même renvoyé afin de garantir que la progression puisse continuer. (Par défaut : 1048576 bytes (1 mébioctet))<br/>|
|**kafka.replica_fetch_response_max_bytes** `long`<br/>min : `10485760` max : `1048576000`<br/>Nombre d'octets maximal attendu pour l'ensemble de la réponse de fetch. Les enregistrements sont récupérés par lots, et si le premier batch d'enregistrements de la première partition non vide du fetch est plus grand que cette valeur, il sera tout de même renvoyé afin de garantir que la progression puisse continuer. Ce n'est donc pas un maximum absolu. (Par défaut : 10485760 bytes (10 mébioctets))<br/>|
|**kafka.sasl_oauthbearer_expected_audience** `string`<br/>Paramètre (facultatif), sous forme de liste séparée par des virgules, permettant au broker de vérifier que le JWT a été émis pour l'une des audiences attendues. (Par défaut : null)<br/>|
|**kafka.sasl_oauthbearer_expected_issuer** `string`<br/>Paramètre facultatif permettant au broker de vérifier que le JWT a été créé par l'émetteur attendu.(Par défaut : null)<br/>|
|**kafka.sasl_oauthbearer_jwks_endpoint_url** `string`<br/>URL de l'endpoint JWKS OIDC. En définissant cette valeur, l'authentification SASL SSL OAuth2/OIDC est activée. Voir également les autres options pour SASL OAuth2/OIDC. (Par défaut : null)<br/>|
|**kafka.sasl_oauthbearer_sub_claim_name** `string`<br/>Nom du scope à partir duquel extraire la revendication (claim) du sujet du JWT.(Par défaut : sub)<br/>|
|**kafka.socket_request_max_bytes** `long`<br/>min : `10485760` max : `209715200`<br/>Nombre maximal d'octets dans une requête socket (Par défaut : 104857600 bytes).<br/>|
|**kafka.transaction_partition_verification_enable** `boolean`<br/>Active la vérification confirmant que la partition a bien été ajoutée à la transaction avant l'écriture d'enregistrements transactionnels dans la partition. (Par défaut : true)<br/>|
|**kafka.transaction_remove_expired_transaction_cleanup_interval_ms** `long`<br/>min : `600000` max : `3600000`<br/>Intervalle auquel supprimer les transactions ayant expiré suite au dépassement de transactional.id.expiration.ms (Par défaut : 3600000 ms (1 heure)).<br/>|
|**kafka.transaction_state_log_segment_bytes** `long`<br/>min : `1048576` max : `2147483647`<br/>Les octets de segment du topic de transaction doivent rester relativement réduits afin de faciliter une compaction des logs et des chargements de cache plus rapides (Par défaut : 104857600 bytes (100 mébioctets)).<br/>|
|**kafka_authentication_methods.certificate** `boolean`<br/>Active l'authentification par certificat/SSL<br/>|
|**kafka_authentication_methods.sasl** `boolean`<br/>Active l'authentification SASL<br/>|
