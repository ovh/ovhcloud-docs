## Objectif

Les moteurs de bases de données Public Cloud sont des services managés, ce qui signifie qu'ils ne sont pas entièrement configurables. Par exemple, il n'est pas possible de modifier *pg_hba.conf*.

:::info
La configuration avancée est disponible pour les moteurs Public Cloud Databases suivants :

- MySQL
- PostgreSQL
- Valkey

:::



## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Une base de données en cours d'exécution sur votre service Public Cloud Databases OVHcloud ([ce guide](/guides/public-cloud/databases/getting-started) peut vous aider à répondre à ce prérequis)
- Un accès à l'<ApiLink>API OVHcloud</ApiLink> (facultatif)

## En pratique

:::warning
Veuillez noter que les modifications apportées aux paramètres avancés s'appliquent au niveau du cluster et donc à toutes les bases de données du cluster.

:::


:::info
Selon le moteur, certains paramètres peuvent déjà être définis.

:::


:::info
Une fois la configuration avancée soumise, il n'est pas possible de la réinitialiser à ses valeurs initiales. Il est seulement possible de mettre à jour les valeurs, nous vous recommandons donc de noter les valeurs initiales avant de les modifier.

Consultez la section [Vérification](#vérification) ci-dessous

:::


### Depuis l'espace client OVHcloud

{/* CP-STEPS-START:using-the-ovhcloud-control-panel */}
Cliquez sur <code className="action">Databases</code> dans la barre de navigation de gauche, sélectionnez l'instance de votre moteur puis l'onglet <code className="action">Configuration avancée</code>.

Sélectionnez la clé du paramètre avancé que vous souhaitez définir, puis renseignez sa valeur.

Une fois prêt, cliquez sur <code className="action">Configuration avancée</code>.

:::info
En haut à droite de l'onglet de configuration avancée, vous pouvez voir les paramètres déjà définis.

:::
{/* CP-STEPS-END:using-the-ovhcloud-control-panel */}


### Depuis l'API

:::info
Si vous n'êtes pas familier avec l'utilisation de l'API OVHcloud, veuillez consulter notre guide [Premiers pas avec les API OVHcloud](/guides/manage-and-operate/api/first-steps).

:::


#### Récupérer les identifiants de votre service et de votre cluster

Vous devez d'abord identifier le service et le cluster auxquels vous souhaitez appliquer les modifications.

##### **Récupérer l'identifiant du service souhaité**

Exécutez l'appel API suivant :

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project"} />


Exemple de réponse :

```json
[
  "702de32b692c4842b0bb751dc5085daf",
  "297c1776595544759d77eee921edd49b",
  "3d4f8b8811ba4962a78f971503915f0d"
]
```

Dans la liste obtenue, sélectionnez et copiez l'identifiant du service souhaité, également appelé serviceName.

##### **Récupérer l'identifiant du cluster souhaité**

Ouvrez l'appel API suivant, collez votre identifiant de service dans le champ `serviceName` puis cliquez sur <code className="action">Execute</code> :

<Tabs>
  <Tab label="MySQL">
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/database/mysql"} />
  </Tab>
  <Tab label="PostgreSQL">
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/database/postgresql"} />
  </Tab>
  <Tab label="Valkey">
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/database/redis"} />
  </Tab>
</Tabs>


Exemple de réponse :

```json
[
  "b412100d-d298-4bee-84b7-4d5e552d3bf1"
]
```

Dans la liste obtenue, sélectionnez et copiez l'identifiant du cluster, également appelé clusterId.

#### Récupérer la configuration avancée existante

Ouvrez l'appel API suivant, renseignez les champs correspondants (serviceName, clusterId) et cliquez sur <code className="action">Execute</code> :

<Tabs>
  <Tab label="MySQL">
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/database/mysql/\\{clusterId\\}/advancedConfiguration"} />
  </Tab>
  <Tab label="PostgreSQL">
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/database/postgresql/\\{clusterId\\}/advancedConfiguration"} />
  </Tab>
  <Tab label="Valkey">
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/database/redis/\\{clusterId\\}/advancedConfiguration"} />
  </Tab>
</Tabs>


Exemple de réponse (vide si aucune configuration avancée n'est encore définie) :

```json
{}
```

#### Liste des paramètres de configuration avancée

Ouvrez l'appel API suivant, renseignez les champs correspondants (serviceName, clusterId) et cliquez sur <code className="action">Execute</code> :

<Tabs>
  <Tab label="MySQL">
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/database/mysql/\\{clusterId\\}/capabilities/advancedConfiguration"} />
  </Tab>
  <Tab label="PostgreSQL">
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/database/postgresql/\\{clusterId\\}/capabilities/advancedConfiguration"} />
  </Tab>
  <Tab label="Valkey">
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/database/redis/\\{clusterId\\}/capabilities/advancedConfiguration"} />
  </Tab>
</Tabs>


Exemple de réponse :

```json
[
  {
    "name": "pg.autovacuum_analyze_scale_factor",
    "type": "double",
    "description": "Specifies a fraction of the table size to add to autovacuum_analyze_threshold when deciding whether to trigger an ANALYZE. The default is 0.2 (20% of table size)",
    "minimum": 0,
    "maximum": 1
  }
]
```

#### Modifier la configuration avancée

Ouvrez l'appel API suivant et renseignez les champs correspondants (serviceName, clusterId)

<Tabs>
  <Tab label="MySQL">
    <Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\\{serviceName\\}/database/mysql/\\{clusterId\\}/advancedConfiguration"} />
  </Tab>
  <Tab label="PostgreSQL">
    <Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\\{serviceName\\}/database/postgresql/\\{clusterId\\}/advancedConfiguration"} />
  </Tab>
  <Tab label="Valkey">
    <Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\\{serviceName\\}/database/redis/\\{clusterId\\}/advancedConfiguration"} />
  </Tab>
</Tabs>


Ensuite, en fonction des paramètres choisis, définissez les valeurs sous forme de paires clé/valeur dans le *corps de la requête*, comme dans l'exemple ci-dessous :

```json
{
  "pg.log_error_verbosity": "VERBOSE",
  "pg.max_parallel_workers": "12",
  "pg.max_parallel_workers_per_gather": "4"
}
```

Une fois prêt, cliquez sur <code className="action">Execute</code> pour mettre à jour la configuration avancée.

### Vérification

Vous pouvez vérifier les modifications de différentes manières, par exemple :

**Depuis l'API**

Exécutez à nouveau l'appel de récupération de la configuration avancée ci-dessus. La réponse contient désormais vos valeurs mises à jour :

```json
{
  "pg.log_error_verbosity": "VERBOSE",
  "pg.max_parallel_workers": "12",
  "pg.max_parallel_workers_per_gather": "4"
}
```
