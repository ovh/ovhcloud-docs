## Objectif

Cette page présente les capacités techniques et les limitations de l'offre Public Cloud Analytics pour Kafka Connect.

Nous améliorons continuellement nos offres. Vous pouvez suivre et proposer des idées à ajouter à notre roadmap sur [https://github.com/orgs/ovh/projects/16/views/5](https://github.com/orgs/ovh/projects/16/views/5).

## Capacités et limitations

### Régions prises en charge et multi-AZ

L'offre Public Cloud Analytics est disponible dans les régions suivantes :

- `BHS` (Beauharnois, Canada)
- `DE` (Francfort, Allemagne)
- `GRA` (Gravelines, France)
- `SBG` (Strasbourg, France)
- `SGP` (Singapour, Singapour)
- `EU-WEST-PAR` (Paris, France)
- `EU-SOUTH-MIL` (Milan, Italie)
- `UK` (Londres, Royaume-Uni)
- `WAW` (Varsovie, Pologne)
- `RBX` (Roubaix, France)
- `AP-SOUTH-MUM` (Mumbai, Inde)

Les nœuds doivent se trouver dans la même région.

### Versions de Kafka Connect

Les versions suivantes de Kafka Connect sont prises en charge :

- Kafka Connect 3.8
- Kafka Connect 3.9

Consultez le [guide de politique de cycle de vie d'Analytics](/guides/public-cloud/data-analytics/analytics/lifecycle-policy) pour connaître les recommandations relatives aux mises à niveau de version et aux annonces de fin de vie des versions majeures.

### Plans

Trois plans sont disponibles :

- *Essential/Discovery*
- *Business/Production*
- *Enterprise/Advanced*

Voici un aperçu des capacités des différents plans :

| Plan                  | Nombre de nœuds | Nœuds supplémentaires |
| --------------------- | --------------- | ---------------------- |
| *Essential/Discovery* | 1               | Non                    |
| *Business/Production* | 3               | Non                    |
| *Enterprise/Advanced* | 6               | Non                    |

Le choix du plan affecte le nombre de nœuds exécutés par votre cluster ou le SLA.

#### Nœuds

- **Essential/Discovery** : le cluster est constitué d'un seul nœud.
- **Business/Production** : le cluster est livré avec 3 nœuds.
- **Enterprise/Advanced** : le cluster est livré avec 6 nœuds.

### Fonctionnalités

#### Réseau

Le réseau public ainsi que le réseau privé (vRack) peuvent être utilisés pour toutes les offres.

Le trafic entrant et sortant est inclus dans les plans de service et non facturé à l'usage.

L'adresse IP du service analytics est susceptible de changer périodiquement. Il est donc conseillé de ne pas se baser sur ces IPs pour une quelconque configuration, comme une politique de connexion ou de sortie. Utilisez plutôt l'enregistrement DNS fourni et mettez en place des politiques de sortie basées sur des CIDR pour une gestion réseau plus robuste et flexible.

##### Considérations relatives au réseau privé

Voici quelques éléments à prendre en compte lors de l'utilisation d'un réseau privé :

- Les ports réseau sont créés dans le réseau privé de votre choix. Par conséquent, certaines opérations ultérieures sur ce réseau pourraient être restreintes - par exemple, vous ne pourrez pas supprimer le réseau si vous n'avez pas au préalable arrêté les services analytics.
- Lors d'une connexion depuis un sous-réseau externe, la passerelle IP OpenStack doit être activée dans le sous-réseau utilisé pour le service analytics. Le client est responsable de toute autre configuration réseau personnalisée.
- Le dimensionnement du sous-réseau doit prendre en compte les nœuds de service, les autres services colocalisés dans le même sous-réseau, ainsi qu'une allocation d'adresses IP disponibles supplémentaires à des fins de maintenance. Un dimensionnement inadéquat des sous-réseaux pourrait entraîner des difficultés opérationnelles et des dysfonctionnements des services.
- Les annonces de routes des sous-réseaux OpenStack ne seront pas appliquées à vos services.
- Vous ne pouvez créer des services en réseau privé que si vous êtes le propriétaire d'origine du réseau. Vous ne pouvez pas créer de services en réseau privé sur un réseau partagé.

##### IPs autorisées

Une fois votre service opérationnel, vous pourrez spécifier des adresses IP (ou des blocs CIDR) pour autoriser le trafic entrant. Jusque-là, votre service restera inaccessible.

#### Paramètres avancés

Vous pouvez personnaliser davantage votre Kafka Connect en utilisant des paramètres avancés. Consultez la [documentation de référence des paramètres avancés](/guides/public-cloud/databases/kafkaconnect-advanced-parameters-references) pour plus d'informations sur les paramètres pris en charge.

#### Logs et métriques

Les logs et métriques sont disponibles via l'espace client et l'API. De plus, une intégration inter-services peut être configurée pour exploiter vos logs et métriques dans d'autres services Public Cloud Databases. Vous pourriez ainsi consulter vos logs Kafka Connect dans Opensearch et vos métriques dans le service Dashboards (les métriques doivent d'abord être exportées vers un moteur compatible avec les séries temporelles, tel que PostgreSQL). Consultez la [documentation sur l'intégration inter-services](/guides/public-cloud/databases/databases-cross-service-integration) pour plus d'informations.

- **Rétention des logs** : 1000 lignes de logs
- **Rétention des métriques** : 1 mois calendaire

Veuillez noter que si le cluster est supprimé, les logs et métriques sont également automatiquement supprimés.
