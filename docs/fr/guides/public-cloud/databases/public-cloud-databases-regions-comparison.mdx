## Objectif

OVHcloud propose deux modes de déploiement pour ses services [Public Cloud Databases](/links/public-cloud/databases), chacun adapté à des besoins spécifiques en matière de résilience, de disponibilité, de performance et de latence. Ce document présente en détail les caractéristiques de chaque mode de déploiement, puis propose un comparatif complet pour aider les utilisateurs à choisir l'option la plus adaptée à leurs besoins.

## Concepts

Les bases de données managées d'OVHcloud proposent deux principaux modes de déploiement, chacun optimisé pour des cas d'usage spécifiques et offrant différents niveaux de résilience et de bascule (failover) :

1. **Région 1-AZ** : pour les applications standards, offrant une résilience de base avec un coût optimisé.
2. **Région 3-AZ** : adaptée aux applications traitant des données hautement critiques ou nécessitant une haute disponibilité avec un RTO/RPO faible et une résilience aux pannes de zone de disponibilité.

## Modes de déploiement

:::info
Les informations suivantes concernent les différents modes de déploiement disponibles pour le service de base de données managée d'OVHcloud. Sélectionnez le mode le plus adapté à vos besoins en fonction de la résilience, de la disponibilité et de la performance.
:::


### Région 1-AZ

Une région 1-AZ correspond à une **zone de disponibilité unique couvrant plusieurs datacenters au sein d'une même région géographique**. Lorsqu'un service de base de données est déployé avec plusieurs nœuds, cette configuration à zone unique offre une résilience face aux pannes de nœud et de disque, mais peut être vulnérable à une panne complète de la région OpenStack. À noter que, dans une région 1-AZ, le service de base de données est situé dans une région OpenStack spécifique qui s'étend sur plusieurs datacenters. Les nœuds d'un service de base de données multi-nœuds sont répartis sur différents hôtes, qui **peuvent être** situés dans différents datacenters. Si une panne survient dans un datacenter spécifique hébergeant un ou plusieurs nœuds du service de base de données, l'accès aux données peut être affecté, même si les autres datacenters de la zone restent opérationnels.

#### Caractéristiques

- **Rentabilité :** déployer dans une région 1-AZ est généralement plus économique, ce qui la rend adaptée au développement, aux tests et aux charges de travail non critiques, pour lesquels le coût est un critère prioritaire.
- **Anti-affinité des hôtes :** les nœuds d'un service de base de données multi-nœuds sont déployés sur des hôtes physiques différents, offrant une résilience en cas de panne d'un hôte.

#### Limites

- **Point de défaillance unique :** dans une région 1-AZ, les nœuds des services de base de données **peuvent être** déployés au sein d'un seul datacenter. Si ce datacenter subit une panne, l'accès à vos services de base de données peut être affecté, même si les autres datacenters de la même zone de disponibilité restent opérationnels.

### Région 3-AZ

Les régions 3-AZ sont composées de **trois zones de disponibilité indépendantes**, chacune isolée en matière d'alimentation électrique, de refroidissement et de systèmes réseau, garantissant une véritable isolation des pannes. Cette architecture assure la **disponibilité du service** même si une zone de disponibilité entière subit une panne.

#### Caractéristiques

- **Haute disponibilité :** le service de base de données multi-nœuds est déployé sur trois zones de disponibilité indépendantes, garantissant la continuité de service même si une zone subit une panne.
- **Faible latence :** l'architecture offre une latence ultra-faible entre les zones de disponibilité, garantissant la performance des opérations de lecture/écriture de la base de données sur les nœuds primaires et secondaires.

#### Cas d'usage idéaux

Les régions 3-AZ sont particulièrement adaptées aux applications critiques et sensibles à la disponibilité, pour lesquelles la gouvernance des données exige une disponibilité continue. Cela inclut des secteurs tels que le e-commerce, les plateformes de santé, les services financiers ou les applications de diffusion en direct (live streaming).
