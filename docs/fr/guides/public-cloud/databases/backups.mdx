## Objectif

Cette page fournit les descriptions techniques des méthodes et des routines de sauvegarde automatique pour chaque moteur.

Nous améliorons continuellement nos offres. Vous pouvez suivre et proposer des idées à ajouter à notre roadmap sur [https://github.com/orgs/ovh/projects/16/views/5](https://github.com/orgs/ovh/projects/16/views/5).

## Méthodes de sauvegarde

* Sauvegarde quotidienne sur site distant :

Nous sauvegardons nos bases de données managées Public Cloud toutes les heures (snapshots incrémentiels), toutes les 12 ou toutes les 24 heures (sauvegardes) — selon le produit — avec la possibilité de restaurer à partir du dernier point dans le temps, selon la période de rétention du plan client choisi.

* PITR :

Que vous rencontriez un problème ou que vous souhaitiez simplement voir à quoi ressemblaient vos données à une date antérieure, vous pouvez restaurer vos données à n'importe quel point dans le temps compris dans la période de rétention du plan client choisi, pour PostgreSQL et MySQL. Pour MongoDB Enterprise, le point dans le temps doit se situer dans les dernières 24 heures.

## Sauvegarde hors site

### Mécanisme de réplication

Pour MongoDB, les données de sauvegarde sont transférées directement vers la région distante.

Pour les autres moteurs, les sauvegardes sont d'abord préparées sur site, puis répliquées vers une autre région. Les données de sauvegarde sur site persistent une fois répliquées vers l'autre région.

### Paramètres personnalisés

L'emplacement et l'heure de sauvegarde par défaut peuvent être remplacés en définissant l'attribut `backups` lors de la création ou de la mise à jour de votre service. Par exemple, les paramètres suivants définissent `GRA` (Gravelines, France) et `DE` (Francfort, Allemagne) comme emplacements de sauvegarde et `01:00:00` comme heure de sauvegarde quotidienne :

```json
"backups": {
  "regions": ["GRA", "DE"],
  "time": "01:00:00"
}
```

Pour rappel, voici l'endpoint API pour la création d'une base de données.

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/mysql"} />

Remplacez `mysql` dans la route par le moteur de votre service (par exemple `postgresql` ou `mongodb`).


Les paramètres de sauvegarde doivent respecter les règles suivantes :

- Pour MongoDB, le tableau `regions` n'accepte qu'un seul élément. Vous êtes libre de définir l'emplacement de sauvegarde dans la même région que le service, bien que cela puisse être considéré comme **peu recommandé**.
- Pour les autres moteurs, le tableau `regions` accepte un ou deux éléments. Si un seul élément est spécifié, il doit correspondre à la région dans laquelle le service s'exécute. Si deux éléments sont spécifiés, l'un d'eux doit correspondre à la région dans laquelle le service s'exécute, tandis que l'autre élément peut être défini sur n'importe quelle autre région. Il est **recommandé** d'utiliser 2 régions pour vos sauvegardes.

:::info
Notez que l'heure de sauvegarde ne peut être personnalisée que pour MongoDB, MySQL et PostgreSQL.

:::


## Lexique

RPO : Recovery Point Objective

Off-Site : dans une région différente

On-Site : dans la même région
