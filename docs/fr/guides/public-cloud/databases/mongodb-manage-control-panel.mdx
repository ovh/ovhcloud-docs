## Objectif

Public Cloud Databases vous permet de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure de base de données et son maintien en conditions opérationnelles.

**Ce guide explique comment configurer votre instance MongoDB pour accepter les connexions entrantes.**

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Une base de données MongoDB active sur votre service Public Cloud Databases OVHcloud (vous pouvez utiliser [ce guide](/guides/public-cloud/databases/getting-started) pour remplir ce prérequis)

[[cpnav:publiccloud-databases]]

## En pratique

### Configurer votre instance MongoDB pour accepter les connexions entrantes

Avant d'établir une connexion, nous devons vérifier que notre instance MongoDB est correctement configurée.

Dans le menu de gauche de votre projet Public Cloud, cliquez sur <code className="action">MongoDB</code> sous **Bases de données**, puis sur le nom de votre service MongoDB.

#### Étape 1 : Vérifiez vos rôles utilisateur et votre mot de passe

Sélectionnez l'onglet <code className="action">Utilisateurs</code>. Vérifiez que vous disposez d'un utilisateur avec des droits suffisants et un mot de passe configuré. Si vous ne vous souvenez plus du mot de passe de l'utilisateur, vous pouvez soit créer un nouvel utilisateur, soit régénérer le mot de passe d'un utilisateur existant. Attention ! En procédant ainsi, vous devrez mettre à jour tous les endroits où vous utilisez déjà cette paire utilisateur/mot de passe.

Nous fournissons les rôles natifs officiels de MongoDB. Veuillez consulter la [documentation officielle MongoDB](https://docs.mongodb.com/manual/reference/built-in-roles/) pour sélectionner les rôles adaptés à votre cas d'usage.

Dans notre exemple, nous allons créer un nouvel utilisateur nommé `foo` avec le rôle `userAdmin` sur la base de données `bar` et le rôle `readWriteAnyDatabase` sur toute base de données, comme son nom l'indique. Cliquez sur <code className="action">Ajouter un utilisateur</code>, saisissez le **Nom d'utilisateur**, ajoutez chaque rôle sous **Rôles** (<code className="action">Ajouter le rôle</code>), puis cliquez sur <code className="action">Créer</code>.

Après quelques secondes, l'utilisateur est prêt. Pour obtenir son mot de passe, cliquez sur le bouton <code className="action">...</code> de la ligne de l'utilisateur, puis sur <code className="action">Réinitialiser le mot de passe</code>, et notez le mot de passe : il n'est affiché qu'une seule fois.

#### Étape 2 : Autorisez les connexions entrantes depuis le client MongoDB

Dans cette étape, ouvrez l'onglet <code className="action">Configuration</code> et repérez la section **Restrictions d’IP** (liste de contrôle d'accès).
Par défaut, une base de données Public Cloud n'accepte aucune forme de connexion depuis l'extérieur.
Cela permet d'aider à prévenir les tentatives de connexion intrusives.

Cliquez sur <code className="action">Ajouter</code>, saisissez l'adresse IP ou le bloc CIDR dans le champ **Bloc d’IP (CIDR)**, puis cliquez sur <code className="action">Enregistrer</code>. Dans notre cas, nous allons saisir 109.190.200.59.

:::info
Si vous souhaitez autoriser toutes les connexions depuis l'extérieur, vous pouvez saisir l'IP 0.0.0.0/0. Veuillez l'utiliser avec précaution. Toutes les IP seront alors autorisées.

:::


### Récupérer vos informations de connexion (URI)

Ouvrez l'onglet <code className="action">Vue d'ensemble</code>. Dans la carte **Détails de connexion**, copiez l'**URI**.

Vous pouvez spécifier la chaîne de connexion MongoDB en sélectionnant, dans la liste **Protocole** de la carte, soit :

- *mongodb* pour le format Standard Connection String **(bientôt obsolète)**.
- *mongodbSrv* pour le format DNS Seed List Connection String.

:::info
MongoDB 3.6 a introduit le concept de seed list, spécifiée à l'aide d'enregistrements DNS, notamment les enregistrements SRV et TXT. Cela permet à un client de se connecter à un replica set même si l'un des nœuds spécifiés par le client est indisponible.

L'utilisation d'enregistrements SRV élimine la nécessité pour chaque client de transmettre un ensemble complet d'informations d'état pour le cluster. À la place, un unique enregistrement SRV identifie tous les nœuds associés au cluster (ainsi que leurs numéros de port), et un enregistrement TXT associé définit les options de l'URI.

*Pour en savoir plus, [cliquez ici](https://www.mongodb.com/docs/manual/reference/connection-string/)*.

:::


<Tabs>
  <Tab label="mongodb">
    Cela devrait ressembler à ceci lorsque vous avez un seul nœud :
    ```
    mongodb://`<username>`:`<password>`@`<hostname>`/admin?tls=true
    ```
    Et à ceci lorsque vous avez un cluster MongoDB avec plusieurs nœuds, appelé replica set :
    ```
    mongodb://`<username>`:`<password>`@<hostname node1>,<hostname node 2>,<hostname node 3>/admin?replicaSet=replicaset&tls=true
    ```
  </Tab>
  <Tab label="mongodbSrv">
    Cela devrait ressembler à ceci :
    ```
    mongodb+srv://`<username>`:`<password>`@`<hostname>`/admin?replicaSet=replicaset&tls=true
    ```
  </Tab>
</Tabs>
