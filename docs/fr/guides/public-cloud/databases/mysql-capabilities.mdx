## Objectif

Cette page présente les capacités techniques et les limitations de l'offre MySQL de Public Cloud Databases.

Nous améliorons continuellement nos offres. Vous pouvez suivre et proposer des idées à ajouter à notre roadmap sur [https://github.com/orgs/ovh/projects/16/views/5](https://github.com/orgs/ovh/projects/16/views/5).

## Capacités et limitations

### Régions prises en charge et multi-AZ

L'offre Public Cloud Databases est disponible dans les régions suivantes :

- `BHS` (Beauharnois, Canada)
- `DE` (Francfort, Allemagne)
- `GRA` (Gravelines, France)
- `SBG` (Strasbourg, France)
- `SGP` (Singapour, Singapour)
- `EU-WEST-PAR` (Paris, France)
- `EU-SOUTH-MIL` (Milan, Italie)
- `UK` (Londres, Royaume-Uni)
- `WAW` (Varsovie, Pologne)
- `RBX` (Roubaix, France)
- `AP-SOUTH-MUM` (Mumbai, Inde)

L'ensemble de l'instance de base de données doit se trouver dans la même région.

### Versions de MySQL

L'offre Public Cloud Databases prend en charge les versions de MySQL suivantes :

- MySQL 8.0
- MySQL 8.4

Veuillez consulter le [guide sur la politique de cycle de vie des SGBD](/guides/public-cloud/databases/lifecycle-policy) pour connaître les recommandations relatives aux montées de version et aux annonces de fin de vie des versions majeures. MySQL recommande de toujours installer et utiliser la dernière version stable.

### Connecteurs MySQL

Vous pouvez utiliser n'importe lequel des [connecteurs et API recommandés par MySQL](https://dev.mysql.com/doc/refman/8.0/en/connectors-apis.html) pour accéder à votre cluster.

### Plans

Trois plans sont disponibles :

- **Essential/Discovery** : 1 nœud
- **Business/Production** : 2 nœuds
- **Enterprise/Advanced** : 3 nœuds

Le choix du plan a un impact sur le nombre de nœuds que votre cluster peut exécuter, sur le SLA, ainsi que sur d'autres fonctionnalités comme la rétention des sauvegardes.

#### Type de licence

Chaque cluster est fourni avec la licence MySQL Community (GPL).

Le coût de la licence est inclus dans les plans de service. Vous ne pouvez pas apporter vos propres licences.

### Ressources matérielles

Pour plus d'informations sur les types de nœuds et les tarifs, veuillez consulter la [page des tarifs](/links/public-cloud/prices).

#### Stockage flexible

Vous pouvez augmenter le stockage de votre cluster jusqu'au maximum autorisé pour une référence donnée. Veuillez consulter le [guide pour redimensionner le stockage de votre cluster](/guides/public-cloud/databases/resize-cluster-storage) pour plus d'informations.

#### Montée en gamme du modèle de nœud

Vous pouvez faire évoluer le modèle de nœud de votre cluster pour augmenter vos ressources matérielles. Cette opération n'entraîne aucune interruption de service, mais sachez que vous ne pourrez pas revenir en arrière sur le modèle de nœud par la suite.

#### Type de disque

Le type de stockage disponible peut varier selon la région dans laquelle se trouve votre cluster : consultez [Disponibilité des produits Public Cloud](/links/public-cloud/regions-pci) pour plus d'informations sur la disponibilité des types de Block Storage selon la région. Ainsi, votre cluster peut reposer par exemple sur du Block Storage de type *High Speed* ou *High Speed Gen2*.

Par ailleurs, les caractéristiques de performance des différentes offres de stockage peuvent varier en fonction, par exemple, de la taille de stockage utilisée par votre cluster : *High Speed* peut offrir de meilleures performances IOPS que *High Speed Gen2* pour certaines tailles de disque. Consultez la [page Block Storage](/links/public-cloud/block-storage) pour plus d'informations sur ces caractéristiques de performance.

Public Cloud Databases sélectionnera le type de disque le plus efficace pour votre cluster en fonction des paramètres de celui-ci.

#### Stockage effectif

La taille de disque indiquée ci-dessus correspond à la taille totale du disque de la machine sous-jacente. Cependant, une petite partie de cet espace est réservée à l'installation du système d'exploitation.

Nous mettons tout en œuvre pour éviter les situations de « disque plein », qui pourraient nuire à la santé du cluster. Ainsi :

1. Lorsqu'un niveau d'utilisation du disque préoccupant est atteint, un e-mail d'avertissement est envoyé.
2. Lorsqu'un niveau d'utilisation du disque préoccupant est atteint, le service passe à l'état « DISK_FULL » et en mode « lecture seule », ce qui signifie qu'aucune écriture supplémentaire n'est possible.
3. Vous avez alors la possibilité de passer à un plan de service supérieur offrant davantage de stockage.

Consultez la [documentation sur la gestion des situations de « disque plein »](/guides/public-cloud/databases/handling-disk-full) pour plus d'informations.

### Fonctionnalités

#### Réseau
Les clusters MySQL sont accessibles via le port par défaut 3306.

Le réseau public ainsi que le réseau privé (vRack) peuvent être utilisés pour toutes les offres.

Le trafic entrant et sortant est inclus dans les plans de service et non facturé à l'usage.

L'adresse IP du service de base de données est susceptible de changer périodiquement. Il est donc conseillé de ne pas se fier à ces IPs pour une quelconque configuration, comme une politique de connexion ou de sortie. Utilisez plutôt l'enregistrement DNS fourni et mettez en œuvre des politiques de sortie basées sur des CIDR pour une gestion réseau plus robuste et plus flexible.

##### Considérations sur le réseau privé
Voici quelques éléments à prendre en compte lors de l'utilisation d'un réseau privé :

- Les ports réseau sont créés dans le réseau privé de votre choix. Par conséquent, certaines opérations sur ce réseau peuvent être restreintes - par exemple, vous ne pourrez pas supprimer le réseau si vous n'avez pas préalablement arrêté les services Public Cloud Databases.
- Lors d'une connexion depuis un sous-réseau externe, la passerelle IP OpenStack doit être activée sur le sous-réseau utilisé pour le service de base de données. Le client est responsable de toute autre configuration réseau personnalisée.
- Le dimensionnement du sous-réseau doit prendre en compte les nœuds de service, les autres services colocalisés dans le même sous-réseau, ainsi qu'une réserve d'adresses IP disponibles supplémentaires à des fins de maintenance. Un dimensionnement insuffisant des sous-réseaux peut entraîner des difficultés opérationnelles et des dysfonctionnements des services.
- L'annonce des routes des sous-réseaux OpenStack ne sera pas appliquée à vos services.
- Vous ne pouvez créer des services de réseau privé que si vous êtes le propriétaire d'origine du réseau. Vous ne pouvez pas créer de services de réseau privé sur un réseau partagé.

##### IPs autorisées

Une fois votre service opérationnel, vous pourrez spécifier des adresses IP (ou des blocs CIDR) pour autoriser le trafic entrant. Jusque-là, votre service restera inaccessible.

#### Nombre maximal de connexions simultanées

Le nombre de connexions simultanées dans Public Cloud Databases pour MySQL dépend de la mémoire totale disponible sur le nœud.
Nous autorisons 75 connexions par Go de mémoire utilisable. La mémoire utilisable correspond à la mémoire totale du nœud moins le système d'exploitation et les frais de gestion, actuellement estimés à 350 Mio. La mémoire utilisable est arrondie au gigaoctet le plus proche.

Ainsi, par exemple, sur un serveur disposant de 7 Go de mémoire, vous obtiendrez 7 * 75 = 525 connexions, et avec 15 Go de mémoire, vous obtiendrez 14 * 75 = 1050 connexions.
Notez que le paramètre max-connections de MySQL est toujours défini avec une unité supplémentaire (par exemple 526 / 1051 dans les cas ci-dessus), car il y a généralement un processus système qui consomme l'une des connexions disponibles.

#### Paramètres avancés

Vous pouvez personnaliser davantage votre MySQL en utilisant des paramètres avancés. Consultez la [documentation de référence des paramètres avancés](/guides/public-cloud/databases/mysql-advanced-parameters-references) pour plus d'informations sur les paramètres pris en charge.

#### Sauvegardes

Les clusters du plan *Essential* sont automatiquement sauvegardés quotidiennement. La rétention des sauvegardes est de 2 jours.

Les clusters du plan *Business/Production* sont automatiquement sauvegardés quotidiennement. La rétention des sauvegardes est de 14 jours.

Les clusters du plan *Enterprise/Advanced* sont automatiquement sauvegardés quotidiennement. La rétention des sauvegardes est de 30 jours.

Consultez le [guide sur les sauvegardes automatiques](/guides/public-cloud/databases/backups) pour plus d'informations.

#### Logs et métriques

Les Logs et les métriques sont disponibles depuis l'espace client, l'API, et peuvent être transférés vers Logs Data Platform. Pour les instructions de configuration, consultez le guide [Public Cloud Databases - Comment configurer le transfert des logs](/guides/public-cloud/databases/logs-to-customers).

- **Rétention des logs** : 1000 lignes de logs
- **Rétention des métriques** : 1 mois calendaire

Veuillez noter que si l'instance de base de données est supprimée, les logs et les métriques sont également automatiquement supprimés.

#### Utilisateurs et rôles

La création d'utilisateurs est possible depuis l'espace client et l'API, avec des rôles et privilèges d'administrateur par défaut.
