## Objectif

Les bases de données managées Public Cloud d'OVHcloud vous permettent de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure de base de données et sa maintenance.

**Ce guide explique comment commander un service de base de données managée Public Cloud via la console OVHcloud, l'API, le CLI ou Terraform.**

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Un accès à l'<ApiLink>API OVHcloud</ApiLink> *(méthodes API et Terraform — créez vos identifiants en consultant le guide [Premiers pas avec l'API OVHcloud](/guides/manage-and-operate/api/first-steps))*
- [Terraform](https://www.terraform.io/) installé *(méthode Terraform uniquement — testé avec la version v1.14.6)*

## En pratique

<Tabs>
  <Tab label="Depuis la console OVHcloud">
    {/* CP-STEPS-START:order-database-instance */}

    Dans le menu de gauche de votre projet Public Cloud, cliquez sur votre moteur de base de données sous **Bases de données** (`PostgreSQL`, `MySQL`, `MongoDB` ou `Valkey`). La section **Analytics** du menu donne accès à `Kafka`, `ClickHouse`, `OpenSearch`, `Managed Dashboards`, `Data Platform` et `Lakehouse`.

    Cliquez sur <code className="action">Créer un service</code>. Tous les paramètres se trouvent sur la page **Créer une base de données infogérée**, et le panneau **Récapitulatif** de droite se met à jour au fil de vos choix.

    **Nom et moteur**
    
    Renommez éventuellement votre service (un nom est généré par défaut, et vous pouvez en générer un autre), puis sélectionnez le **Moteur de base de données** et sa **Version**.

    **Région**
    
    Choisissez la région du datacentre dans lequel votre base de données sera hébergée (vous pouvez **Filtrer par mode de déploiement** : région 1-AZ ou 3-AZ).

    **Offre**
    
    Choisissez une offre de service. Vous pourrez la faire évoluer après la création. Consultez la [page des capacités](/links/public-cloud/databases) du type de base de données choisi pour le détail des propriétés de chaque offre.

    **Type de nœud et nœuds**
    
    Sélectionnez le **Type de nœud**. Selon l'offre, le **Nombre de nœuds** est fixe ou ajustable. Consultez la [page des capacités](/links/public-cloud/databases) du type de base de données choisi pour le détail du matériel et de la configuration, et prenez note des informations tarifaires.

    **Stockage**
    
    Vous pouvez sélectionner du stockage additionnel pour le cluster, en plus du stockage inclus dans le type de nœud.

    **Réseau**
    
    Par défaut, le service est accessible via le **Réseau public**. Si vous disposez déjà d'un sous-réseau privé, sélectionnez **Réseau privé (vRack)**, puis choisissez le **Réseau privé** et le **Sous-réseau**. Cette option peut ne pas être disponible pour l'offre sélectionnée. Vous pouvez aussi cliquer sur <code className="action">Créer un réseau privé</code>. Pour des instructions détaillées, consultez le guide [Configurer le vRack pour Public Cloud](/guides/public-cloud/network-services/vrack).

    **Restrictions IP**
    
    Cliquez sur <code className="action">Ajouter une IP</code> (ou <code className="action">Ajouter mon IP actuelle</code>) pour ajouter les adresses IP ou plages d'adresses (CIDR) autorisées à se connecter à votre service.

    :::info
    Par sécurité, la configuration réseau par défaut bloque toutes les connexions entrantes. Autorisez une adresse IP adaptée pour accéder à votre base de données.
    :::

    **Récapitulatif et confirmation**
    
    Vérifiez le panneau **Récapitulatif**, puis cliquez sur <code className="action">Créer la base de données</code> pour confirmer. Pour afficher l'appel API ou Terraform équivalent avant de commander, cliquez sur <code className="action">Équivalent API et Terraform</code>.

    Votre service de base de données se déploie en quelques minutes. Le statut du service dans la console OVHcloud indique quand la base de données est prête à être utilisée.

    Pour configurer votre service après l'installation, consultez le guide *Configurer votre instance pour accepter les connexions entrantes* correspondant à votre type de base de données, [disponible dans notre catalogue](/links/public-cloud/databases).

    Les options de configuration varient selon le type de base de données. Des exemples sont disponibles dans le dépôt [public-cloud-databases-examples](https://github.com/ovh/public-cloud-databases-examples).

    {/* CP-STEPS-END:order-database-instance */}
  </Tab>
  <Tab label="Depuis l'API OVHcloud">
    **Étape 1 : Rassemblez l'ensemble des paramètres requis**

    Pour créer un service de base de données, spécifiez au minimum :

    - un _moteur_ et sa _version_ (par exemple `MongoDB 8.0`)
    - le _plan_ (par exemple `production`)
    - les _nœuds_ du cluster (par exemple 3 nœuds avec 4 cœurs, 15 Gio de mémoire, 100 Gio de disque)

    *Lister les fonctionnalités*

    L'endpoint _capabilities_ liste les valeurs autorisées pour le moteur, le plan et le flavor.

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/{serviceName}/database/capabilities"} />

    L'appel renvoie un objet listant les moteurs autorisés (avec leurs versions), les plans et les flavors.

    *Obtenir la disponibilité*

    L'endpoint _availability_ liste les combinaisons de paramètres valides. Chaque entrée liste un _moteur_, une _version_, un _plan_, un _flavor_, une _région_, le support du réseau public/privé et le nombre minimum/maximum de nœuds. Choisissez la combinaison qui correspond le mieux à vos besoins.

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/{serviceName}/database/availability"} />

    **Étape 2 : Créez un service de base de données MongoDB**

    :::warning
    La création d'un cluster entraîne des frais.
    :::

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/{serviceName}/database/mongodb"} />

    - **description** : une description lisible par un humain pour le service.
    - **plan** : le plan souhaité.
    - **version** : la version de MongoDB.
    - **nodesPattern** : spécifiez le _flavor_, la _région_ et le nombre de nœuds.
    - **nodeslist** : laissez non défini — utilisez plutôt **nodesPattern** pour des clusters de même région et de même flavor.
    - **ipRestrictions** : les plages d'adresses IP autorisées à se connecter.

    :::info
    Pour des raisons de sécurité, la configuration réseau par défaut bloque toutes les connexions entrantes. Autorisez une adresse IP appropriée pour accéder à votre base de données.
    :::

    Pour le réseau privé, spécifiez également **networkId** (ID du vRack) et **subnetId** (ID du sous-réseau du vRack).

    L'appel renvoie l'objet du cluster. Son **status** est `CREATING`. Notez l'**id** pour l'étape suivante.

    **Étape 3 : Attendez que votre service de base de données soit prêt**

    Le cluster met quelques minutes à devenir utilisable. Vérifiez son statut à l'aide de :

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/{serviceName}/database/mongodb/{clusterId}"} />

    Son **status** passe à `READY` lorsque le cluster est disponible.

    **Étape 4 : Réinitialisez le mot de passe de l'utilisateur principal**

    Listez les utilisateurs de votre cluster pour obtenir l'ID de l'utilisateur admin :

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/{serviceName}/database/mongodb/{clusterId}/user"} />

    Réinitialisez le mot de passe de l'utilisateur admin :

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/{serviceName}/database/mongodb/{clusterId}/user/{userId}/credentials/reset"} />

    Notez le nouveau mot de passe pour vous connecter au cluster.

    :::warning
    Ce mot de passe ne sera plus disponible par la suite : OVHcloud ne stocke pas les mots de passe des utilisateurs.
    :::

    **Étape 5 : Commencez à utiliser le cluster**

    Les informations de connexion au cluster sont disponibles dans la console OVHcloud. Vous pouvez désormais utiliser le cluster.
  </Tab>
  <Tab label="Depuis le CLI OVHcloud">
    :::info
    Toutes les commandes nécessitent soit le flag `--cloud-project <projectId>`, soit la variable d'environnement `OVH_CLOUD_PROJECT_SERVICE`, définie avec l'ID de votre projet Public Cloud.
    :::

    **Étape 1 : Rassemblez l'ensemble des paramètres requis**

    Listez les moteurs, plans et flavors de nœuds disponibles :

    ```bash
    ovhcloud cloud reference managed-database list-engines --cloud-project <projectId>
    ovhcloud cloud reference managed-database list-plans --cloud-project <projectId>
    ovhcloud cloud reference managed-database list-node-flavors --cloud-project <projectId>
    ```

    **Étape 2 : Créez un service de base de données MongoDB**

    :::warning
    La création d'un cluster entraîne des frais.
    :::

    ```bash
    ovhcloud cloud managed-database create \
      --cloud-project <projectId> \
      --engine mongodb \
      --version 8.0 \
      --plan production \
      --nodes-pattern.flavor db1-4 \
      --nodes-pattern.region GRA \
      --nodes-pattern.number 3 \
      --description "My MongoDB cluster" \
      --ip-restrictions "203.0.113.0/24"
    ```

    :::info
    Pour des raisons de sécurité, la configuration réseau par défaut bloque toutes les connexions entrantes. Autorisez une adresse IP appropriée pour accéder à votre base de données.
    :::

    Pour le réseau privé, ajoutez `--network-id <networkId>` et `--subnet-id <subnetId>`.

    **Étape 3 : Attendez que votre service de base de données soit prêt**

    ```bash
    ovhcloud cloud managed-database get <clusterId> --cloud-project <projectId>
    ```

    Son **status** passe à `READY` lorsque le cluster est disponible.

    **Étape 4 : Réinitialisez le mot de passe de l'utilisateur principal**

    ```bash
    # Liste les utilisateurs et récupère l'ID de l'utilisateur admin
    ovhcloud cloud managed-database user list <clusterId> --cloud-project <projectId>

    # Réinitialise le mot de passe de l'utilisateur admin
    ovhcloud cloud managed-database user credentials-reset <clusterId> <userId> --cloud-project <projectId>
    ```

    :::warning
    Ce mot de passe ne sera plus disponible par la suite : OVHcloud ne stocke pas les mots de passe des utilisateurs.
    :::

    **Étape 5 : Commencez à utiliser le cluster**

    Les informations de connexion au cluster sont disponibles dans la console OVHcloud. Vous pouvez désormais utiliser le cluster.
  </Tab>
  <Tab label="Depuis Terraform">
    **Étape 1 : Rassemblez les paramètres requis par OVHcloud**

    Le fournisseur Terraform OVHcloud nécessite les identifiants suivants :

    - une `application_key`
    - un `application_secret`
    - une `consumer_key`

    Pour les récupérer, suivez le guide [Premiers pas avec les API OVHcloud](/guides/manage-and-operate/api/first-steps). Générez des identifiants avec les droits suivants :

    - **GET** `/cloud/project/*/database/*`
    - **POST** `/cloud/project/*/database/*`
    - **PUT** `/cloud/project/*/database/*`
    - **DELETE** `/cloud/project/*/database/*`

    - <CreateToken rights="GET=/cloud/project/*/database/*&POST=/cloud/project/*/database/*&PUT=/cloud/project/*/database/*&DELETE=/cloud/project/*/database/*">Générer des tokens API OVHcloud</CreateToken>

    Le `service_name` correspond à l'ID de votre projet Public Cloud. Récupérez-le via le bouton <code className="action">Copier dans le presse-papiers</code> dans la section Public Cloud.

    **Étape 2 : Rassemblez l'ensemble des paramètres requis**

    Pour créer un nouveau cluster MongoDB, spécifiez au minimum :

    - le _moteur_ (par exemple `mongodb`)
    - la _version_ (par exemple `8.2`)
    - la _région_ (par exemple `EU-WEST-PAR`)
    - le _plan_ (par exemple `production`)
    - le _flavor_ (par exemple `b3-8`)

    **Étape 3 : Créez les fichiers Terraform**

    Créez un fichier `main.tf` :

    ```terraform
    terraform {
      required_providers {
        ovh = {
          source  = "ovh/ovh"
          version = ">= 2.11.0"
        }
      }
    }

    provider "ovh" {
      endpoint           = var.ovh.endpoint
      application_key    = var.ovh.application_key
      application_secret = var.ovh.application_secret
      consumer_key       = var.ovh.consumer_key
    }

    resource "ovh_cloud_project_database" "service" {
      service_name = var.product.project_id
      description  = var.product.name
      engine       = var.product.engine
      version      = var.product.version
      plan         = var.product.plan
      nodes {
        region = var.product.region
      }
      nodes {
        region = var.product.region
      }
      nodes {
        region = var.product.region
      }
      flavor = var.product.flavor
      ip_restrictions {
        ip = var.product.ip
      }
    }

    resource "ovh_cloud_project_database_mongodb_user" "dbuser" {
      service_name = ovh_cloud_project_database.service.service_name
      cluster_id   = ovh_cloud_project_database.service.id
      name         = var.access.name
    }
    ```

    Créez un fichier `variables.tf` :

    ```terraform
    variable "ovh" {
      type = map(string)
      default = {
        endpoint           = "ovh-eu"
        application_key    = ""
        application_secret = ""
        consumer_key       = ""
      }
    }

    variable "product" {
      type = map(string)
      default = {
        project_id = ""
        name       = ""
        engine     = ""
        region     = "EU-WEST-PAR"
        plan       = "production"
        flavor     = "b3-8"
        version    = ""
        ip         = "0.0.0.0/32"
      }
    }

    variable "access" {
      type = map(string)
      default = {
        name = "johndoe"
      }
    }
    ```

    Utilisez `ovh-eu` pour l'API OVHcloud Europe, ou `ovh-ca` pour l'Amérique du Nord.

    Créez un fichier `secrets.tfvars` avec vos valeurs réelles :

    ```terraform
    ovh = {
      endpoint           = "ovh-eu"
      application_key    = "<application_key>"
      application_secret = "<application_secret>"
      consumer_key       = "<consumer_key>"
    }

    product = {
      project_id = "<service_name>"
      name       = "mongodb-terraform"
      engine     = "mongodb"
      region     = "EU-WEST-PAR"
      plan       = "production"
      flavor     = "b3-8"
      version    = "8.2"
      ip         = "<ip_range>"
    }

    access = {
      name = "johndoe"
    }
    ```

    :::info
    Remplacez `<service_name>`, `<application_key>`, `<application_secret>`, `<consumer_key>` et `<ip_range>` par vos valeurs réelles.
    :::

    Créez un fichier `outputs.tf` :

    ```terraform
    output "cluster_uri" {
      value = ovh_cloud_project_database.service.endpoints.0.uri
    }

    output "user_name" {
      value = ovh_cloud_project_database_mongodb_user.dbuser.name
    }

    output "user_password" {
      value     = ovh_cloud_project_database_mongodb_user.dbuser.password
      sensitive = true
    }
    ```

    **Étape 4 : Exécutez**

    ```bash
    terraform init
    terraform plan -var-file=secrets.tfvars
    terraform apply -var-file=secrets.tfvars -auto-approve
    ```

    Exportez les identifiants et l'URI :

    ```bash
    export PASSWORD=$(terraform output -raw user_password)
    export USER=$(terraform output -raw user_name)
    export URI=$(terraform output -raw cluster_uri)
    ```

    Votre cluster MongoDB est maintenant prêt.

    Des exemples pour d'autres moteurs (MySQL, PostgreSQL) sont disponibles dans le dépôt [public-cloud-databases-examples](https://github.com/ovh/public-cloud-databases-examples).
  </Tab>
