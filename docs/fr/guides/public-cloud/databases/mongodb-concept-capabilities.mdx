## Objectif

Cette page présente les capacités et les limitations techniques de l'offre Public Cloud Databases pour MongoDB.

## Capacités et limitations

### Versions de MongoDB

L'offre Public Cloud Databases prend en charge les versions suivantes de MongoDB :

- MongoDB 6.0
- MongoDB 7.0
- MongoDB 8.0

Consultez le [guide sur la politique de cycle de vie des SGBD](/guides/public-cloud/databases/lifecycle-policy) pour connaître les recommandations relatives aux mises à niveau de version et aux annonces de fin de vie des versions majeures. Par ailleurs, MongoDB recommande de toujours installer et d'utiliser la dernière version stable de MongoDB. Consultez [MongoDB Versioning](https://docs.mongodb.com/manual/reference/versioning/) pour plus d'informations.

### Drivers MongoDB

Les [drivers MongoDB](https://www.mongodb.com/docs/drivers/) fournissent l'interface permettant aux applications d'interagir avec les bases de données MongoDB. Ils offrent :

- **Prise en charge native des langages** : des drivers sont disponibles pour différents langages de programmation, notamment JavaScript (Node.js), Python, Java, C#, PHP, Ruby, Go, et bien d'autres.
- **Opérations asynchrones** : de nombreux drivers prennent en charge des opérations asynchrones et non bloquantes afin d'améliorer les performances.
- **Documentation complète** : des guides détaillés et des exemples pour aider les développeurs à mettre en œuvre les opérations sur la base de données.
- **Compatibilité** : les drivers sont conçus pour fonctionner de manière transparente avec les fonctionnalités de MongoDB, garantissant une manipulation des données fiable et efficace.

Ces drivers garantissent que les applications peuvent communiquer efficacement et en toute sécurité avec les bases de données MongoDB, quel que soit l'environnement de programmation utilisé.

### Plans

Trois plans sont disponibles :

- **Discovery** : 3 nœuds
- **Production** : 3 nœuds
- **Advanced** : 3 à 7 nœuds (incluant en option un nœud d'analyse)

Le choix du plan a une incidence sur le nombre de nœuds que votre cluster peut exécuter, ainsi que sur le type de licence MongoDB.

#### Type de licence

Les trois plans, **Discovery**, **Production** et **Advanced**, utilisent la licence MongoDB Community.

Le coût de la licence est inclus dans les plans de service. Vous ne pouvez pas apporter vos propres licences.

### Fonctionnalités

#### Réseau

Les clusters MongoDB sont joignables via le port par défaut 27017.

Les réseaux public et privé (vRack) peuvent être utilisés pour toutes les offres. Le réseau privé n'est pas disponible pour l'offre Discovery.

Le trafic entrant et sortant est inclus dans les plans de service et non facturé à l'usage.

L'adresse IP du service de base de données est susceptible de changer périodiquement. Il est donc déconseillé de s'appuyer sur ces adresses IP pour une quelconque configuration, telle que la connexion ou la politique de sortie. Utilisez plutôt l'enregistrement DNS fourni et mettez en œuvre des politiques de sortie basées sur des blocs CIDR pour une gestion du réseau plus robuste et plus flexible.

##### Considérations relatives au réseau privé

Voici quelques éléments à prendre en compte lors de l'utilisation d'un réseau privé :

- Les ports réseau sont créés dans le réseau privé de votre choix. Par conséquent, les opérations ultérieures sur ce réseau peuvent être restreintes. Par exemple, vous ne pourrez pas supprimer le réseau si vous n'avez pas préalablement arrêté les services Public Cloud Databases.
- Lors d'une connexion depuis un sous-réseau externe, la passerelle IP Openstack doit être activée dans le sous-réseau utilisé pour le service de base de données. Le client est responsable de toute autre configuration réseau personnalisée.
- Le dimensionnement du sous-réseau doit tenir compte des nœuds de service, des autres services colocalisés au sein du même sous-réseau, ainsi que d'une réserve d'adresses IP disponibles supplémentaires à des fins de maintenance. Un dimensionnement insuffisant du sous-réseau peut entraîner des difficultés opérationnelles et un dysfonctionnement des services.
- Vous ne pouvez créer des services de réseau privé que si vous êtes le propriétaire d'origine du réseau. Vous ne pouvez pas créer de services de réseau privé sur un réseau partagé.

##### IPs autorisées

Une fois votre service opérationnel, vous pourrez spécifier des adresses IP (ou des blocs CIDR) pour autoriser le trafic entrant. En attendant, votre service sera injoignable.

#### Sauvegardes

Les clusters du plan *Discovery* ne sont pas sauvegardés.

Les clusters du plan *Production* sont automatiquement sauvegardés tous les jours. La rétention des sauvegardes est de 7 jours.

Les clusters du plan *Advanced* sont automatiquement sauvegardés tous les jours, avec prise en charge du [PITR](https://en.wikipedia.org/wiki/Point-in-time_recovery). La rétention des sauvegardes est de 30 jours, avec une capacité PITR portant sur les 24 dernières heures.

Consultez le [guide sur les sauvegardes automatiques](/guides/public-cloud/databases/backups) pour plus d'informations.

#### Logs et métriques

Les logs et les métriques sont disponibles depuis l'espace client, l'API, et peuvent être transférés vers Logs Data Platform. Consultez le [guide Public Cloud Databases - Comment configurer le transfert des logs](/guides/public-cloud/databases/logs-to-customers) pour plus d'informations.

- **Rétention des logs :** 1000 lignes de logs ;
- **Rétention des métriques :** 1 année civile.

Veuillez noter que si l'instance de base de données est supprimée, les logs et les métriques sont également automatiquement supprimés.

#### Utilisateurs et rôles

La création d'utilisateurs est autorisée avec les rôles proposés suivants :

| Rôle                 | Base de données |
| -------------------- | --------------- |
| backup               | admin           |
| clusterManager       | admin           |
| clusterMonitor       | admin           |
| clusterAdmin         | admin           |
| dbAdmin              | Configuré par l'utilisateur |
| dbAdminAnyDatabase   | admin           |
| dbOwner              | Configuré par l'utilisateur |
| enableSharding       | Configuré par l'utilisateur |
| hostManager          | Configuré par l'utilisateur |
| read                 | Configuré par l'utilisateur |
| readWrite            | Configuré par l'utilisateur |
| readWriteAnyDatabase | admin           |
| readAnyDatabase      | admin           |
| restore              | admin           |
| root                 | admin           |
| userAdmin            | Configuré par l'utilisateur |
| userAdminAnyDatabase | admin           |

Afin de gérer correctement votre cluster MongoDB, certains utilisateurs MongoDB sont configurés dans vos clusters par OVHcloud :

- `admin@admin` est votre utilisateur initial
- `mms-automation@admin` est un utilisateur technique requis à des fins d'automatisation
- `backup-*@admin` sont utilisés pour effectuer les sauvegardes

Par ailleurs, la création d'utilisateurs depuis le Shell MongoDB n'est **pas** prise en charge : vous devez utiliser l'API OVHcloud ou l'espace client OVHcloud afin de gérer les utilisateurs de vos clusters. Tout utilisateur créé via le shell mongo sera supprimé par le mécanisme d'automatisation.
