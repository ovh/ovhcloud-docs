## Objectif

Public Cloud Databases vous permet de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure de base de données et son maintien en conditions opérationnelles.

**Ce guide explique comment configurer votre instance PostgreSQL pour accepter les connexions entrantes.**

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Une base de données PostgreSQL fonctionnant sur votre service Public Cloud Databases OVHcloud ([ce guide](/guides/public-cloud/databases/getting-started) peut vous aider à répondre à ce prérequis)

## En pratique

### Configurer votre instance PostgreSQL pour accepter les connexions entrantes

Avant d'établir une connexion, nous devons vérifier que notre instance PostgreSQL est correctement configurée.

Cliquez sur <code className="action">Databases</code> dans le menu de navigation de gauche et sélectionnez votre instance PostgreSQL.

#### Étape 1 : vérifier vos rôles utilisateur et votre mot de passe

Sélectionnez l'onglet <code className="action">Utilisateurs</code>. Vérifiez que vous disposez d'un utilisateur avec des droits suffisants et un mot de passe configuré. Si vous ne vous souvenez plus du mot de passe de l'utilisateur, vous pouvez soit créer un nouvel utilisateur, soit régénérer le mot de passe d'un utilisateur existant. Attention ! En procédant ainsi, vous devrez mettre à jour tous les endroits où vous utilisez déjà cette paire utilisateur/mot de passe.

Ce premier utilisateur **avnadmin** dispose des privilèges suivants :

```console
  LOGIN
  NOSUPERUSER
  INHERIT
  CREATEDB
  CREATEROLE
  REPLICATION
```

Nous nous appuyons sur les rôles et privilèges officiels de PostgreSQL. Vous pouvez les gérer vous-même via la CLI ou du code.
Pour l'instant, **la gestion des droits et privilèges des utilisateurs n'est pas prise en charge via l'espace client OVHcloud ou l'API OVHcloud**.

Consultez le guide « [Gérer les utilisateurs, rôles et privilèges](/guides/public-cloud/databases/postgresql-users-roles-grants) » pour connaître le périmètre du privilège `replication`, le comportement par défaut d'un nouvel utilisateur et les commandes `GRANT` usuelles. La [documentation officielle de PostgreSQL](https://www.postgresql.org/docs/current/database-roles.html) décrit l'ensemble des rôles disponibles.

Pour réinitialiser le mot de passe de **avnadmin**, cliquez sur <code className="action">...</code> à droite de l'utilisateur, puis sur <code className="action">Regénérer le mot de passe</code>.

<img className="thumbnail" alt="Menu d'actions de l'utilisateur" src="/images/public-cloud/databases/postgresql-07-prepare-for-incoming-connections/postgresql_07_prepare_for_incoming_connections-20261006-1.png" loading="lazy" />

Pour créer un nouvel utilisateur, cliquez sur <code className="action">Ajouter un utilisateur</code>, remplissez le formulaire, puis cliquez sur <code className="action">Créer un utilisateur</code>.

<img className="thumbnail" alt="Créer un utilisateur" src="/images/public-cloud/databases/postgresql-07-prepare-for-incoming-connections/postgresql_07_prepare_for_incoming_connections-20261006-2.png" loading="lazy" />

Une fois créé ou mis à jour, l'utilisateur doit avoir le statut `READY` dans l'espace client.

:::warning
Créer un utilisateur ne lui donne pas accès à vos données. Il peut se connecter à la base, mais ne dispose d'aucun privilège de lecture ou d'écriture sur vos tables tant que vous ne les lui avez pas accordés en SQL.

:::

#### Étape 2 : autoriser les connexions entrantes depuis le client PostgreSQL

Par défaut, un service Public Cloud Databases n'accepte aucune connexion venant de l'extérieur. Cela permet de prévenir les tentatives de connexion intrusives.

:::warning
Tant qu'aucune adresse IP n'est autorisée, votre service reste injoignable, même s'il apparaît comme disponible dans l'espace client : les tentatives de connexion échouent, généralement par un délai d'attente dépassé, sans message d'erreur explicite côté client.

:::

Sélectionnez l'onglet <code className="action">Configuration</code>, puis repérez la section `IPs`.

Saisissez une adresse IP ou un bloc CIDR dans le champ **Adresse IP ou IP/masque**, renseignez une description permettant d'identifier son origine, puis cliquez sur <code className="action">Ajouter</code>. Dans notre exemple, nous saisissons `203.0.113.10/32`.

Deux raccourcis sont proposés au-dessus du champ de saisie :

- <code className="action">IP actuelle</code> : ajoute l'adresse IP publique depuis laquelle vous consultez l'espace client. Pratique pour un poste de développement, à condition que votre adresse soit fixe.
- <code className="action">OVHcloud Dataplatform IP</code> : ajoute les adresses nécessaires pour que les services de la Data Platform d'OVHcloud puissent joindre votre base de données.

<img className="thumbnail" alt="Ajouter une IP" src="/images/public-cloud/databases/postgresql-07-prepare-for-incoming-connections/ip_authorize.png" loading="lazy" />

:::warning
Vous pouvez saisir `0.0.0.0/0` pour autoriser les connexions depuis n'importe quelle adresse. Votre service devient alors accessible depuis l'ensemble d'Internet, et seul le couple identifiant/mot de passe protège vos données. Réservez cet usage à des tests, et privilégiez des blocs CIDR restreints ou le réseau privé vRack pour vos environnements de production.

:::

:::info
Une adresse IP dynamique change périodiquement : si votre poste ou votre passerelle de sortie n'a pas d'adresse fixe, vos connexions cesseront de fonctionner sans modification de votre part. Autorisez dans ce cas le bloc CIDR de votre opérateur, ou passez par un point de sortie à adresse fixe.

:::

#### Collecter les informations requises

Sélectionnez l'onglet <code className="action">Dashboard</code> pour retrouver les informations de connexion dans la section `Informations de connection` : nom d'hôte, port, protocole, mode SSL, URI de connexion et certificat CA du service.

<img className="thumbnail" alt="Section des informations de connexion" src="/images/public-cloud/databases/postgresql-07-prepare-for-incoming-connections/postgresql_07_prepare_for_incoming_connections-20261006-3.png" loading="lazy" />

Sélectionnez l'onglet <code className="action">Bases de données</code> pour obtenir le nom de la base de données.

<img className="thumbnail" alt="Onglet Databases" src="/images/public-cloud/databases/postgresql-07-prepare-for-incoming-connections/postgresql_07_prepare_for_incoming_connections-20261006-4.png" loading="lazy" />

Sélectionnez l'onglet <code className="action">Utilisateurs</code> pour obtenir le nom d'utilisateur.

<img className="thumbnail" alt="Tableau des utilisateurs" src="/images/public-cloud/databases/postgresql-07-prepare-for-incoming-connections/postgresql_07_prepare_for_incoming_connections-20261006-5.png" loading="lazy" />
