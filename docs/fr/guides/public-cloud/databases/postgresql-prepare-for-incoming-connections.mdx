## Objectif

Public Cloud Databases vous permet de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure de base de données et son maintien en conditions opérationnelles.

**Ce guide explique comment configurer votre instance PostgreSQL pour accepter les connexions entrantes.**

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Une base de données PostgreSQL fonctionnant sur votre service Public Cloud Databases OVHcloud ([ce guide](/guides/public-cloud/databases/getting-started) peut vous aider à répondre à ce prérequis)

[[cpnav:publiccloud-databases]]

## En pratique

### Configurer votre instance PostgreSQL pour accepter les connexions entrantes

Avant d'établir une connexion, nous devons vérifier que notre instance PostgreSQL est correctement configurée.

Dans le menu de gauche de votre projet Public Cloud, cliquez sur <code className="action">PostgreSQL</code> sous **Bases de données**, puis sur le nom de votre service PostgreSQL.

#### Étape 1 : vérifier vos rôles utilisateur et votre mot de passe

Sélectionnez l'onglet <code className="action">Utilisateurs</code>. Vérifiez que vous disposez d'un utilisateur avec des droits suffisants et un mot de passe configuré. Si vous ne vous souvenez plus du mot de passe de l'utilisateur, vous pouvez soit créer un nouvel utilisateur, soit régénérer le mot de passe d'un utilisateur existant. Attention ! En procédant ainsi, vous devrez mettre à jour tous les endroits où vous utilisez déjà cette paire utilisateur/mot de passe.

Ce premier utilisateur **avnadmin** dispose des privilèges suivants :

```console
  LOGIN
  NOSUPERUSER
  INHERIT
  CREATEDB
  CREATEROLE
  REPLICATION
```

Nous nous appuyons sur les rôles et privilèges officiels de PostgreSQL. Vous pouvez les gérer vous-même via la CLI ou du code.
Pour l'instant, **la gestion des droits et privilèges des utilisateurs n'est pas prise en charge via la console OVHcloud ou l'API OVHcloud**.

Consultez le guide « [Gérer les utilisateurs, rôles et privilèges](/guides/public-cloud/databases/postgresql-users-roles-grants) » pour connaître le périmètre du privilège `replication`, le comportement par défaut d'un nouvel utilisateur et les commandes `GRANT` usuelles. La [documentation officielle de PostgreSQL](https://www.postgresql.org/docs/current/database-roles.html) décrit l'ensemble des rôles disponibles.

Pour réinitialiser le mot de passe de **avnadmin**, cliquez sur le bouton <code className="action">...</code> de la ligne de l'utilisateur, puis sur <code className="action">Réinitialiser le mot de passe</code>.

Pour créer un nouvel utilisateur, cliquez sur <code className="action">Ajouter un utilisateur</code>, remplissez le formulaire du panneau **Ajouter un utilisateur**, puis cliquez sur <code className="action">Créer</code>.

Une fois créé ou mis à jour, l'utilisateur doit avoir le statut `READY` dans la console OVHcloud.

:::warning
Créer un utilisateur ne lui donne pas accès à vos données. Il peut se connecter à la base, mais ne dispose d'aucun privilège de lecture ou d'écriture sur vos tables tant que vous ne les lui avez pas accordés en SQL.

:::

#### Étape 2 : autoriser les connexions entrantes depuis le client PostgreSQL

Par défaut, un service Public Cloud Databases n'accepte aucune connexion venant de l'extérieur. Cela permet de prévenir les tentatives de connexion intrusives.

:::warning
Tant qu'aucune adresse IP n'est autorisée, votre service reste injoignable, même s'il apparaît comme disponible dans la console OVHcloud : les tentatives de connexion échouent, généralement par un délai d'attente dépassé, sans message d'erreur explicite côté client.

:::

Sélectionnez l'onglet <code className="action">Configuration</code>, puis repérez la section **Restrictions d’IP**.

Cliquez sur <code className="action">Ajouter</code>, saisissez une adresse IP ou un bloc CIDR dans le champ **Bloc d’IP (CIDR)** et une description permettant d'identifier son origine, puis cliquez sur <code className="action">Enregistrer</code>. Dans notre exemple, nous saisissons `203.0.113.10/32`.

Deux raccourcis sont disponibles à côté du bouton d'ajout :

- <code className="action">Ajouter mon IP actuelle</code> : ajoute l'adresse IP publique depuis laquelle vous consultez la console OVHcloud. Pratique pour un poste de développement, à condition que votre adresse soit fixe.
- <code className="action">Ajouter OVHcloud Data Platform</code> : ajoute les adresses nécessaires pour que les services de la Data Platform d'OVHcloud puissent joindre votre base de données.

:::warning
Vous pouvez saisir `0.0.0.0/0` pour autoriser les connexions depuis n'importe quelle adresse. Votre service devient alors accessible depuis l'ensemble d'Internet, et seul le couple identifiant/mot de passe protège vos données. Réservez cet usage à des tests, et privilégiez des blocs CIDR restreints ou le réseau privé vRack pour vos environnements de production.

:::

:::info
Une adresse IP dynamique change périodiquement : si votre poste ou votre passerelle de sortie n'a pas d'adresse fixe, vos connexions cesseront de fonctionner sans modification de votre part. Autorisez dans ce cas le bloc CIDR de votre opérateur, ou passez par un point de sortie à adresse fixe.

:::

#### Collecter les informations requises

Sélectionnez l'onglet <code className="action">Vue d'ensemble</code> pour retrouver les informations de connexion dans la carte **Détails de connexion** : hôte, port, protocole, URI de connexion et certificat CA du service (<code className="action">Télécharger (.pem)</code>).

Sélectionnez l'onglet <code className="action">Bases de données</code> pour obtenir le nom de la base de données.

Sélectionnez l'onglet <code className="action">Utilisateurs</code> pour obtenir le nom d'utilisateur.
