## Objectif

Public Cloud Databases vous permet de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure de base de données et son maintien en conditions opérationnelles.

**Ce guide explique comment se connecter à une instance de service Valkey avec une Command Line Interface (CLI).**

## Prérequis

- Un accès à l'<ManagerLink to="/">espace client OVHcloud</ManagerLink> ;
- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud ;
- Un service Valkey exécuté sur votre OVHcloud Public Cloud Databases ([ce guide](/guides/public-cloud/databases/getting-started) peut vous aider à répondre à ce prérequis)
- [Configurer votre service Valkey](/guides/public-cloud/databases/valkey-prepare-for-incoming-connections) pour accepter les connexions entrantes

## Concept

Un service Valkey peut être géré de plusieurs façons.
L'une des plus simples, mais aussi des plus puissantes, consiste à utiliser une Command Line Interface (CLI), également appelée console ou terminal.
Pour interagir correctement avec l'instance, nous devons d'abord installer ce que l'on appelle un client, afin de nous connecter au service Valkey et de le contrôler à distance.
Il s'agit d'une interaction client-serveur.

## En pratique

### Installer valkey-cli sur votre client

:::info
`valkey-cli` est le client officiel de Valkey. Il est fourni avec les paquets Valkey.

:::


Vous devez d'abord installer un logiciel pour interagir avec votre instance à distance. Ce logiciel officiel peut être installé sur différents supports comme votre propre ordinateur, un VPS, une machine virtuelle... La seule règle est de pouvoir accéder au réseau public (Internet) et de disposer des privilèges suffisants pour l'installer.

Selon votre système d'exploitation :

- **macOS** (Homebrew) : `brew install valkey`
- **Debian / Ubuntu** : `sudo apt install valkey-tools`
- **Fedora / RHEL** : `sudo dnf install valkey`
- **Alpine Linux** : `apk add valkey-cli`
- **Docker** : l'image officielle `valkey/valkey` contient `valkey-cli`, par exemple `docker run -it --rm valkey/valkey valkey-cli --version`
- **Windows** : `valkey-cli` n'est pas disponible nativement. Utilisez-le depuis [WSL](https://learn.microsoft.com/windows/wsl/install) (avec l'une des commandes Linux ci-dessus) ou depuis Docker.

Pour les autres méthodes d'installation, consultez la [documentation officielle d'installation de Valkey](https://valkey.io/topics/installation/).

Vérifiez que le client est installé :

```console
$ valkey-cli --version
valkey-cli 9.1.2
```

Le numéro de version dépend de votre paquet. Votre client doit prendre en charge TLS, ce qui est le cas des paquets listés ci-dessus.

:::info
`redis-cli` et les autres clients compatibles Redis peuvent également se connecter à votre service Valkey, avec les mêmes options.

:::

Nous sommes maintenant prêts à découvrir comment nous connecter à notre instance.

### Connexion

Récupérez l'hôte, le port et l'URI de votre service dans l'onglet <code className="action">Dashboard</code>, section `Informations de connection`, comme expliqué dans le guide [Configurer les connexions entrantes](/guides/public-cloud/databases/valkey-prepare-for-incoming-connections).

:::warning
TLS est obligatoire : les connexions sans TLS sont refusées. Utilisez toujours le schéma `valkeys://` (ou l'option `--tls`). Le certificat du serveur est signé par une autorité de certification publique : vous n'avez pas besoin de télécharger de certificat CA ni d'ajouter d'option `--cacert`.

:::

Dans votre terminal, saisissez :

```console
valkey-cli --tls -u valkeys://<username>:<password>@<host>:<port> PING
```

N'oubliez pas de modifier le nom d'utilisateur, le mot de passe, l'hôte et le port.

Le résultat devrait ressembler à ceci :

```console
$ valkey-cli --tls -u valkeys://<username>:<password>@<host>:<port> PING
Warning: Using a password with '-a' or '-u' option on the command line interface may not be safe.
PONG
```

Cela signifie que l'instance est active et répond à votre commande.

Pour être en mode interactif, exécutez la même commande sans commande Valkey à la fin :

```console
valkey-cli --tls -u valkeys://<username>:<password>@<host>:<port>
```

Dans notre exemple, cela ressemblera à ceci :

```console
$ valkey-cli --tls -u valkeys://<username>:<password>@<host>:<port>
Warning: Using a password with '-a' or '-u' option on the command line interface may not be safe.
<host>:<port>> PING
PONG
<host>:<port>> HELLO

 3) "version"

```

Félicitations ! Vous êtes maintenant pleinement en mesure d'interagir avec votre instance !

:::tip
Utilisez `PING` ou `HELLO` pour tester une connexion. `INFO` est refusé aux utilisateurs dont les permissions ne l'incluent pas.

:::

#### Éviter le mot de passe dans la ligne de commande

Avec l'option `-u`, le mot de passe reste dans l'historique de votre shell et apparaît dans la liste des processus, d'où l'avertissement affiché par `valkey-cli`. Pour l'éviter, utilisez l'une de ces méthodes :

- Connectez-vous sans identifiants, puis authentifiez-vous dans la session interactive :

    ```console
    $ valkey-cli --tls -h <host> -p <port>
    <host>:<port>> AUTH <username> <password>
    OK
    ```

- Laissez `valkey-cli` vous demander le mot de passe, qui n'est pas affiché :

    ```console
    $ valkey-cli --tls -h <host> -p <port> --user <username> --askpass
    Please input password:
    ```

:::warning
Ne mettez pas uniquement le nom d'utilisateur dans l'URI (`valkeys://<username>@<host>:<port>`) : `valkey-cli` interprète la valeur placée avant `@` comme un mot de passe, et l'authentification échoue.

:::

### Utilisation de valkey-cli

Vous pouvez gérer votre instance à l'aide de la Command Line Interface en mode interactif ou en définissant des paramètres en tant qu'arguments de `valkey-cli`.

Veuillez consulter la [documentation officielle de valkey-cli](https://valkey.io/topics/cli/) et la [liste des commandes Valkey](https://valkey.io/commands/).

### En cas de problèmes de connexion ou d'exécution de commandes

Si vous ne vous authentifiez pas, toutes les commandes sont refusées avec une erreur `NOAUTH` :

```console
$ valkey-cli --tls -h <host> -p <port> PING
(error) NOAUTH Authentication required.
```

Si le nom d'utilisateur ou le mot de passe est erroné, l'authentification échoue avec une erreur `WRONGPASS` :

```console
WRONGPASS invalid username-password pair or user is disabled.
```

Vérifiez le nom d'utilisateur dans l'onglet <code className="action">Utilisateurs</code> de votre service. Le mot de passe n'est affiché qu'une seule fois, à la création : si vous l'avez perdu, régénérez-le depuis l'onglet <code className="action">Utilisateurs</code>.

Si l'utilisateur est authentifié mais que ses permissions (ACL) n'autorisent pas la clé, la commande ou le canal, vous obtiendrez une réponse `NOPERM` :

```console
<host>:<port>> GET foo
(error) NOPERM No permissions to access a key
```

Dans ce cas, vérifiez les clés, catégories, commandes et canaux autorisés pour votre utilisateur, dans l'onglet <code className="action">Utilisateurs</code> ou avec l'[API](/guides/public-cloud/databases/valkey-update-acls). Pour en savoir plus, consultez la [documentation officielle sur les ACL Valkey](https://valkey.io/topics/acl/).
