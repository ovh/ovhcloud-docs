## Objectif

Public Cloud Databases vous permet de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure de base de données et son maintien en conditions opérationnelles.

**Ce guide explique comment sauvegarder et restaurer manuellement votre base de données Public Cloud Databases for MongoDB.**

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Une base de données MongoDB exécutée sur votre service OVHcloud Public Cloud Databases ([ce guide](/guides/public-cloud/databases/getting-started) peut vous aider à répondre à ce prérequis)
- [Configurer votre instance MongoDB](/guides/public-cloud/databases/mongodb-manage-control-panel) pour accepter les connexions entrantes

## Concept

Public Cloud Databases effectue automatiquement des sauvegardes quotidiennes de vos bases de données. Cependant, vous pourriez avoir besoin d'effectuer des opérations manuelles de sauvegarde et de restauration afin de renforcer la sécurité de vos données, ou par exemple pour exporter et importer des données entre instances de bases de données.

## En pratique

### Vérifiez que vous pouvez vous connecter à votre base de données

Suivez le guide [MongoDB - Se connecter avec la CLI](/guides/public-cloud/databases/mongodb-connect-cli) afin de vérifier que vous pouvez vous connecter à votre base de données. Cette étape permet de vérifier que le filtrage IP est correctement configuré et que vous disposez d'une URI de service appropriée.

### Installer les MongoDB Database Tools

Suivez la [documentation MongoDB](https://docs.mongodb.com/database-tools/) pour installer les MongoDB Database Tools pour votre plateforme. Vous aurez besoin des binaires `mongodump` et `mongorestore` pour effectuer le reste de cette procédure.

## Effectuer une sauvegarde de vos données

Sauvegardez votre base de données dans un fichier à l'aide de la commande suivante :

```bash
$ mongodump --gzip --archive=path/to/backup.gz --readPreference=secondaryPreferred \
  --uri="mongodb+srv://`<username>`:<password>@mongodb-e49d02ee-o2626ab53.database.cloud.ovh.net/admin?replicaSet=replicaset"
```

L'utilisateur MongoDB doit disposer de privilèges suffisants pour effectuer l'opération de sauvegarde. Vous pouvez vous en assurer en attribuant à cet utilisateur le rôle `backup`.

Cette opération peut prendre un certain temps - de quelques secondes à quelques heures, selon la quantité de données que contient votre base de données et votre connexion réseau. Une fois terminée, le fichier `path/to/backup.gz` contiendra une sauvegarde de vos données.

## Restaurer vos données à partir d'une sauvegarde précédente

:::warning
Cette opération peut écraser les données existantes de votre base de données avec les données de la sauvegarde que vous restaurez. Assurez-vous que c'est bien ce que vous souhaitez faire !
:::


:::info
`mongorestore` fusionne les données

Après l'opération de restauration, toutes les données qui étaient stockées dans votre base de données et qui ne font pas partie du fichier de sauvegarde (par exemple d'autres collections ou d'autres clés) resteront intactes : autrement dit, `mongorestore` fusionne les données de votre fichier de sauvegarde avec les données préexistantes dans la base de données.
:::


Restaurez votre base de données à partir d'une sauvegarde à l'aide de la commande suivante :

```bash
$ mongorestore --gzip --archive=path/to/backup.gz \
  --uri="mongodb+srv://`<username>`:`<password>`@mongodb-e49d02ee-o2626ab53.database.cloud.ovh.net/admin?replicaSet=replicaset"
```

L'utilisateur MongoDB doit disposer de privilèges suffisants pour effectuer l'opération de restauration. Vous pouvez vous en assurer en attribuant à cet utilisateur le rôle `restore`.

Là encore, selon le volume de données et votre connexion réseau, cette opération peut prendre un certain temps. Une fois terminée, toutes les données contenues dans votre fichier de sauvegarde sont présentes dans votre base de données.
