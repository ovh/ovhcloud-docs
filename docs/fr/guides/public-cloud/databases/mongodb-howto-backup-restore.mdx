## Objectif

Public Cloud Databases pour MongoDB sauvegarde automatiquement votre service. Vous pouvez aussi vouloir votre propre copie de vos données, par exemple pour la conserver hors d'OVHcloud ou pour la transférer vers un autre service.

**Ce guide explique comment exporter vos données avec `mongodump`, les restaurer avec `mongorestore`, et que faire d'un service Discovery avant la fin de vie de ce plan.**

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Un service Public Cloud Databases pour MongoDB
- L'adresse IP de votre machine [autorisée sur le service](/guides/public-cloud/databases/mongodb-manage-control-panel)
- Un utilisateur MongoDB disposant du rôle `backup@admin` pour exporter, et des rôles `readWriteAnyDatabase@admin` et `restore@admin` pour restaurer

## En pratique

### Fin de vie du plan Discovery

Le plan gratuit Discovery (type de nœud `db2-free`) n'est plus commercialisé depuis le 31 août 2026 :

- **31 octobre 2026** : les services Discovery sont suspendus. Ils peuvent être réactivés sans frais supplémentaires, mais uniquement pour les passer à un autre plan ou pour récupérer leurs données.
- **30 novembre 2026** : les services Discovery sont supprimés, avec toutes leurs données.

Avant ces dates, choisissez l'une des options suivantes.

#### Passer votre service au plan Production

Votre service et ses données sont conservés. La facturation du plan Production démarre dès le changement de plan.

1. Dans l'espace client OVHcloud, ouvrez votre service MongoDB, puis l'onglet <code className="action">Configuration</code>.
2. Sur la ligne `Plan`, cliquez sur <code className="action">Modifier</code>.
3. Dans la fenêtre `Modifier le plan`, sélectionnez le plan **Production**, puis cliquez sur <code className="action">Modifier</code>.

Votre service passe en plan Production, avec des nœuds `db2-2`.

#### Exporter vos données

Exportez gratuitement vos données avec `mongodump`, en suivant la [section suivante](#exporter-vos-données-avec-mongodump). Vous pourrez ensuite les restaurer sur un autre service MongoDB avec `mongorestore`.

### Installer les MongoDB Database Tools

Installez les [MongoDB Database Tools](https://www.mongodb.com/docs/database-tools/installation/) sur votre machine. Ils contiennent les binaires `mongodump` et `mongorestore`.

### Construire la chaîne de connexion

Copiez l'URI `mongodb+srv://` depuis la section `Informations de connection` de l'onglet <code className="action">Dashboard</code>. Pour `mongodump` et `mongorestore`, remplacez le chemin `/admin` par un paramètre `authSource=admin` :

```bash
mongodb+srv://<username>:<password>@<srv-hostname>/?authSource=admin&replicaSet=replicaset
```

:::warning
Si vous conservez `/admin` dans le chemin, `mongodump` n'exporte que la base `admin`, et `mongorestore` ne restaure que dans celle-ci. Vos autres bases sont ignorées, sans aucune erreur.
:::

### Exporter vos données avec mongodump

Exportez toutes vos bases dans une archive compressée :

```bash
mongodump --gzip --archive=backup.gz --readPreference=secondaryPreferred \
  --uri="mongodb+srv://<username>:<password>@<srv-hostname>/?authSource=admin&replicaSet=replicaset"
```

La sortie liste chaque collection exportée, avec son nombre de documents. L'export lit sur un nœud secondaire, pour limiter la charge sur le nœud primaire.

Selon le volume de données et votre connexion réseau, cette opération peut prendre de quelques secondes à plusieurs heures. Une fois terminée, le fichier `backup.gz` contient vos données.

### Restaurer vos données avec mongorestore

:::warning
`mongorestore` fusionne l'archive avec les données déjà présentes dans le service : les collections absentes de l'archive ne sont pas modifiées, et les documents déjà présents ne sont pas écrasés.
:::

Restaurez l'archive en excluant la base `admin` :

```bash
mongorestore --gzip --archive=backup.gz --nsExclude 'admin.*' \
  --uri="mongodb+srv://<username>:<password>@<srv-hostname>/?authSource=admin&replicaSet=replicaset"
```

Les utilisateurs ne sont pas restaurés : sur Public Cloud Databases pour MongoDB, les utilisateurs se gèrent uniquement depuis l'espace client OVHcloud ou l'API OVHcloud.

La dernière ligne de la sortie indique le nombre de documents restaurés et le nombre de documents en échec. Les documents déjà présents dans le service sont comptés en échec. Pour remplacer plutôt les collections de l'archive, ajoutez l'option `--drop` :

```bash
mongorestore --gzip --archive=backup.gz --nsExclude 'admin.*' --drop \
  --uri="mongodb+srv://<username>:<password>@<srv-hostname>/?authSource=admin&replicaSet=replicaset"
```
