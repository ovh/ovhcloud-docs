## Objectif

Public Cloud Databases vous permet de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure de base de données et son maintien en conditions opérationnelles.

**Ce guide explique comment configurer votre instance MySQL pour accepter les connexions entrantes.**

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Une base de données MySQL fonctionnant sur votre Public Cloud Databases OVHcloud ([ce guide](/guides/public-cloud/databases/getting-started) peut vous aider à répondre à ce prérequis)

## En pratique

### Configurer votre instance MySQL pour accepter les connexions entrantes

Avant d'établir une connexion, nous devons vérifier que notre instance MySQL est correctement configurée.

Cliquez sur <code className="action">Databases</code> dans la barre de navigation de gauche et sélectionnez votre instance MySQL.

#### Étape 1 : Vérifiez vos utilisateurs et votre mot de passe

Sélectionnez l'onglet <code className="action">Utilisateurs</code>. Vérifiez que vous disposez d'un utilisateur avec les droits suffisants et un mot de passe configuré. Si vous ne vous souvenez plus du mot de passe de l'utilisateur, vous pouvez soit créer un nouvel utilisateur, soit régénérer le mot de passe d'un utilisateur existant.

:::warning
Attention ! Ce faisant, vous devrez mettre à jour tous les endroits où vous utilisez déjà cette paire utilisateur/mot de passe.

:::


Ce premier utilisateur **avnadmin** est préconfiguré lors de l'installation du service et dispose des droits suivants :

```sql
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, RELOAD, PROCESS, REFERENCES, INDEX, ALTER, SHOW DATABASES, CREATE TEMPORARY TABLES, LOCK TABLES, EXECUTE, REPLICATION SLAVE, REPLICATION CLIENT, CREATE VIEW, SHOW VIEW, CREATE ROUTINE, ALTER ROUTINE, CREATE USER, EVENT, TRIGGER ON *.* TO "avnadmin"@"%" WITH GRANT OPTION

GRANT REPLICATION_APPLIER,ROLE_ADMIN ON *.* TO "avnadmin"@"%" WITH GRANT OPTION
```

Vous pouvez afficher les droits actuels d'un utilisateur avec la commande SQL `SHOW GRANTS FOR 'avnadmin'@'%';`.

Vous pouvez ajouter d'autres utilisateurs en cliquant sur le bouton <code className="action">Ajouter un utilisateur</code>.

Saisissez un nom d'utilisateur puis cliquez sur <code className="action">Créer un utilisateur</code>. Les utilisateurs MySQL n'ont pas de rôles : seul un nom est demandé. Le mot de passe est généré et affiché une seule fois à la création. Notez-le, car il ne pourra pas être récupéré par la suite.

:::warning
Un utilisateur créé depuis l'espace client reçoit les mêmes privilèges qu'**avnadmin** : il peut lire et écrire dans toutes vos bases, créer des bases et des utilisateurs, et transmettre ses propres privilèges. Ne confiez pas un tel utilisateur à une application.

Pour une application, créez en SQL un utilisateur dédié, limité à ses besoins, par exemple en étant connecté avec **avnadmin** :

```sql
CREATE USER 'myuser'@'%' IDENTIFIED BY '<mot-de-passe-robuste>';
GRANT SELECT, INSERT, UPDATE, DELETE ON mydatabase.* TO 'myuser'@'%';
```

Les privilèges des utilisateurs ne peuvent pas être gérés depuis l'espace client OVHcloud ni depuis l'API OVHcloud. Consultez la [documentation officielle de MySQL](https://dev.mysql.com/doc/refman/8.4/en/grant.html) pour la syntaxe complète de `GRANT`.

:::

:::info
Vous pouvez supprimer un utilisateur ou régénérer son mot de passe via le bouton <code className="action">...</code> à droite de l'utilisateur dans le tableau des utilisateurs, puis <code className="action">Supprimer</code> ou <code className="action">Regénérer le mot de passe</code>. Un utilisateur ne peut pas être modifié après sa création.

Les utilisateurs créés directement en SQL (`CREATE USER`) n'apparaissent pas dans l'espace client OVHcloud ni dans l'API OVHcloud, et ne peuvent pas y être gérés.

:::


#### Étape 2 : Autorisez les connexions entrantes depuis le client MySQL

Par défaut, un service Public Cloud Databases n'accepte aucune connexion venant de l'extérieur. Cela permet de prévenir les tentatives de connexion intrusives.

:::warning
Tant qu'aucune adresse IP n'est autorisée, votre service reste injoignable, même s'il apparaît comme disponible dans l'espace client : les tentatives de connexion échouent, généralement par un délai d'attente dépassé, sans message d'erreur explicite côté client.

:::

Sélectionnez l'onglet <code className="action">Configuration</code>, puis repérez le bloc `IPs`.

Saisissez une adresse IP ou un bloc CIDR dans le champ `Adresse IP ou IP/masque`, renseignez une description permettant d'identifier son origine, puis cliquez sur <code className="action">Ajouter</code>. Dans notre exemple, nous saisissons `203.0.113.10/32`.

Deux raccourcis sont proposés au-dessus du champ de saisie :

- <code className="action">IP actuelle</code> : ajoute l'adresse IP publique depuis laquelle vous consultez l'espace client. Pratique pour un poste de développement, à condition que votre adresse soit fixe.
- <code className="action">OVHcloud Dataplatform IP</code> : ajoute les adresses nécessaires pour que les services de la Data Platform d'OVHcloud puissent joindre votre base de données.

Validez les modifications en cliquant sur le bouton <code className="action">Sauvegarder les modifications</code>.

:::warning
Vous pouvez saisir `0.0.0.0/0` pour autoriser les connexions depuis n'importe quelle adresse. Votre service devient alors accessible depuis l'ensemble d'Internet, et seul le couple identifiant/mot de passe protège vos données. Réservez cet usage à des tests, et privilégiez des blocs CIDR restreints ou le [réseau privé vRack](/guides/public-cloud/databases/configure-vrack) pour vos environnements de production.

:::

:::info
Une adresse IP dynamique change périodiquement : si votre poste ou votre passerelle de sortie n'a pas d'adresse fixe, vos connexions cesseront de fonctionner sans modification de votre part. Autorisez dans ce cas le bloc CIDR de votre opérateur, ou passez par un point de sortie à adresse fixe.

:::


#### Collecter les informations requises

Sélectionnez l'onglet <code className="action">Dashboard</code> pour retrouver les informations de connexion dans le bloc `Informations de connection` : hôte, port, protocole, mode SSL, URI de connexion et certificat CA (champ `Certificat`). Le port est propre à chaque service, et le mode SSL est obligatoire : votre client doit se connecter en TLS.

Sélectionnez l'onglet <code className="action">Databases</code> pour obtenir le nom de la base de données (`defaultdb` par défaut).

Sélectionnez l'onglet <code className="action">Utilisateurs</code> pour obtenir le nom d'utilisateur.
