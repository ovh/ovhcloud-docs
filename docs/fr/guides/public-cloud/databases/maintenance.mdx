## Objectif

Public Cloud Databases vous permet de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure de base de données et son maintien en conditions opérationnelles.

**Ce guide explique comment votre service de base de données planifie et exécute les opérations de maintenance.**

## Pourquoi des opérations de maintenance ?

Il peut arriver, au cours du cycle de vie d'un cluster, qu'une action soit nécessaire pour en assurer le bon fonctionnement. Par exemple, une nouvelle version corrective d'un paquet du système d'exploitation sous-jacent peut être publiée pour apporter des correctifs.

## Comment ces opérations sont-elles réalisées ?

- À un moment donné, le système détecte qu'une opération de maintenance devient nécessaire. Par exemple, une nouvelle version d'un paquet participant à l'installation du service peut devenir disponible.
- Il expose alors une nouvelle opération de maintenance pour votre service, avec une description indiquant ce qui doit être fait, un statut (`SCHEDULED`, `APPLYING`, `APPLIED`) et une date planifiée. Cette date est calculée à partir de la propriété « heure de maintenance » de votre service.
- L'opération est déclenchée lorsque la date planifiée est atteinte.

## Quel est l'impact attendu sur le service ?

La VM sous-jacente doit souvent être reconstruite, ou le service doit redémarrer.

Pour les services à nœud unique, cela signifie qu'il y a une courte période durant laquelle votre service devient indisponible.

Pour les services multi-nœuds, les mécanismes de résilience propres à chaque moteur garantissent que le service reste disponible lorsqu'un nœud fait l'objet d'une intervention. Si l'application gère correctement de tels cas (par exemple, en se reconnectant et en réessayant correctement en cas d'échec), l'impact devrait être minime, voire inexistant.

## Comment puis-je suivre les maintenances planifiées ?

Vous pouvez obtenir la liste des maintenances d'un service via le point de terminaison API dédié à chaque moteur :

## Comment puis-je contrôler la planification ?

Vous pouvez modifier l'heure de maintenance de votre service pour choisir un horaire qui vous convient mieux. Par exemple, si votre application est moins sollicitée la nuit, vous pouvez cibler cette plage horaire. Notez que cela n'affecte que la planification des futures opérations de maintenance ; cela ne replanifiera pas les opérations déjà existantes.

<img className="thumbnail" alt="Choisir la maintenance" src="/images/public-cloud/databases/databases-15-maintenances/maintenancesql2.png" loading="lazy" />

Vous pouvez également décider d'appliquer certaines opérations de manière préventive, en utilisant ce point de terminaison API :

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/postgresql/\{clusterId\}/maintenance/\{maintenanceId\}/apply"} />


Cela peut être une bonne idée si, par exemple, vous souhaitez vous préparer à une période de forte activité et ainsi éviter des perturbations pendant celle-ci.
