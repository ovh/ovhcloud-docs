## Objectif

Cette page présente les capacités techniques et les limitations de l'offre Public Cloud Databases pour PostgreSQL.

Nous améliorons continuellement nos offres. Vous pouvez suivre et proposer des idées à ajouter à notre roadmap sur [https://github.com/orgs/ovh/projects/16/views/5](https://github.com/orgs/ovh/projects/16/views/5).

## Capacités et limitations

### Régions prises en charge et multi-AZ

L'offre Public Cloud Databases est disponible dans les régions suivantes :

- `BHS` (Beauharnois, Canada)
- `DE` (Francfort, Allemagne)
- `GRA` (Gravelines, France)
- `SBG` (Strasbourg, France)
- `SGP` (Singapour, Singapour)
- `EU-WEST-PAR` (Paris, France)
- `EU-SOUTH-MIL` (Milan, Italie)
- `UK` (Londres, Royaume-Uni)
- `WAW` (Varsovie, Pologne)
- `RBX` (Roubaix, France)
- `AP-SOUTH-MUM` (Mumbai, Inde)

Les nœuds de la base de données doivent se trouver dans la même région.

### Versions de PostgreSQL

L'offre Public Cloud Databases prend en charge les versions de PostgreSQL suivantes :

- PostgreSQL 14
- PostgreSQL 15
- PostgreSQL 16
- PostgreSQL 17
- PostgreSQL 18

Reportez-vous au [guide sur la politique de cycle de vie des SGBD](/guides/public-cloud/databases/lifecycle-policy) pour connaître les recommandations relatives aux mises à niveau de version et aux annonces de fin de vie des versions majeures. Vous pouvez également suivre le cycle de vie (EOL) des versions de PostgreSQL sur leur page officielle : [https://www.postgresql.org/support/versioning/](https://www.postgresql.org/support/versioning/)

### Connecteurs PostgreSQL

Vous pouvez utiliser n'importe quel [driver ou extension recommandé par PostgreSQL](https://www.postgresql.org/download/product-categories/) pour accéder à votre instance.

### Offres

Différentes offres sont disponibles :

- **Essential/Discovery** : 1 nœud
- **Business/Production** : 2 nœuds
- **Enterprise/Advanced** : 3 nœuds

Votre choix d'offre détermine le nombre de nœuds que votre cluster peut exécuter, le SLA, et quelques autres fonctionnalités telles que la rétention des sauvegardes.

#### Type de licence

Le logiciel PostgreSQL est distribué sous licence PostgreSQL, une licence open source permissive, similaire aux licences BSD ou MIT.
Plus d'informations sur [https://www.postgresql.org/about/licence/](https://www.postgresql.org/about/licence/).

### Ressources matérielles

Pour plus d'informations sur les types de nœuds et les tarifs, reportez-vous à la [page des tarifs](/links/public-cloud/prices).

#### Stockage flexible

Vous pouvez augmenter le stockage de votre cluster jusqu'au maximum autorisé pour une référence donnée. Reportez-vous au [guide de redimensionnement du stockage de votre cluster](/guides/public-cloud/databases/resize-cluster-storage) pour plus d'informations.

#### Mise à niveau du modèle de nœud

Vous pouvez mettre à niveau le modèle de nœud de votre cluster afin d'augmenter vos ressources matérielles. Cette opération n'entraîne aucune interruption de service, mais sachez que vous ne pourrez pas revenir en arrière sur le modèle de nœud par la suite.

#### Type de disque

Le type de stockage disponible peut varier selon la région dans laquelle se trouve votre cluster : consultez [Disponibilité des produits Public Cloud](/links/public-cloud/regions-pci) pour plus d'informations sur la disponibilité des types de Block Storage selon la région. Ainsi, votre cluster peut reposer par exemple sur du Block Storage de type *High Speed* ou *High Speed Gen2*.

Par ailleurs, les caractéristiques de performance des différentes offres de stockage peuvent varier en fonction, par exemple, de la taille de stockage utilisée par votre cluster : *High Speed* peut offrir de meilleures performances IOPS que *High Speed Gen2* pour certaines tailles de disque. Consultez la [page Block Storage](/links/public-cloud/block-storage) pour plus d'informations sur ces caractéristiques de performance.

Public Cloud Databases sélectionne le type de disque le plus efficace pour votre cluster en fonction des paramètres de celui-ci.

#### Stockage effectif

La taille de disque indiquée ci-dessus correspond à la taille de disque totale de la machine sous-jacente. Cependant, une petite partie de cet espace est réservée à l'installation du système d'exploitation.

Nous mettons tout en œuvre pour éviter les situations de « disque plein » qui pourraient nuire à l'état de santé du cluster. Ainsi :

1. Lorsqu'un niveau d'utilisation du disque préoccupant est atteint, un e-mail d'avertissement est envoyé.
2. Lorsqu'un niveau d'utilisation du disque préoccupant est atteint, le service passe à l'état « DISK_FULL » et en mode « lecture seule », ce qui signifie qu'aucune nouvelle écriture n'est possible.
3. Vous avez alors la possibilité de passer à une offre de service supérieure disposant de plus de stockage.

Consultez la [documentation sur la gestion des situations de « disque plein »](/guides/public-cloud/databases/handling-disk-full) pour plus d'informations.

### Fonctionnalités

#### Réseau

Les clusters PostgreSQL sont accessibles via un port personnalisé disponible depuis l'espace client OVHcloud et l'API.

Le réseau public ainsi que le réseau privé (vRack) peuvent être utilisés pour toutes les offres.

Le trafic entrant et sortant est inclus dans les plans de service et non facturé à l'usage.

L'adresse IP du service de base de données est susceptible de changer périodiquement. Il est donc recommandé de ne pas se baser sur ces adresses IP pour vos configurations, telles que la connexion ou les politiques de trafic sortant. Utilisez plutôt l'enregistrement DNS fourni et mettez en place des politiques de trafic sortant basées sur des blocs CIDR pour une gestion réseau plus robuste et plus flexible.

##### Considérations relatives au réseau privé

Voici quelques points à prendre en compte lors de l'utilisation du réseau privé :

- Les ports réseau sont créés dans le réseau privé de votre choix. Par conséquent, certaines opérations ultérieures sur ce réseau peuvent être restreintes - par exemple, vous ne pourrez pas supprimer le réseau si vous n'avez pas préalablement arrêté les services Public Cloud Databases.
- Lors d'une connexion depuis un sous-réseau externe, la passerelle IP OpenStack doit être activée sur le sous-réseau utilisé pour le service de base de données. Le client est responsable de toute autre configuration réseau personnalisée.
- Le dimensionnement du sous-réseau doit prendre en compte les nœuds de service, les autres services colocalisés au sein du même sous-réseau, ainsi qu'une réserve d'adresses IP disponibles supplémentaires à des fins de maintenance. Un dimensionnement insuffisant du sous-réseau peut entraîner des difficultés opérationnelles et des dysfonctionnements des services.
- L'annonce des routes des sous-réseaux OpenStack ne sera pas appliquée à vos services.
- Vous ne pouvez créer des services de réseau privé que si vous êtes le propriétaire d'origine du réseau. Vous ne pouvez pas créer de services de réseau privé sur un réseau partagé.

##### IPs autorisées

Une fois votre service opérationnel, vous pourrez spécifier des blocs CIDR pour autoriser le trafic entrant. Jusque-là, votre service restera inaccessible.

#### Nombre maximal de connexions simultanées

Le nombre de connexions simultanées dans Public Cloud Databases pour PostgreSQL dépend de la mémoire totale disponible sur le nœud.
Nous autorisons environ 100 connexions par tranche de 4 Go de mémoire RAM, avec un plafond maximal de 1000 connexions actives.

Ainsi, par exemple, sur un serveur disposant de 7 Go de mémoire, vous obtiendrez environ 200 connexions, et avec 15 Go de mémoire, vous obtiendrez 400 connexions.

#### Paramètres avancés

Vous pouvez personnaliser davantage votre instance PostgreSQL à l'aide de paramètres avancés. Consultez la [documentation de référence des paramètres avancés](/guides/public-cloud/databases/postgresql-advanced-parameters-references) pour plus d'informations sur les paramètres pris en charge.

#### Sauvegardes

Les clusters de l'offre *Essential* sont automatiquement sauvegardés quotidiennement. La rétention des sauvegardes est de 2 jours.

Les clusters de l'offre *Business/Production* sont automatiquement sauvegardés quotidiennement. La rétention des sauvegardes est de 14 jours.

Les clusters de l'offre *Enterprise/Advanced* sont automatiquement sauvegardés quotidiennement. La rétention des sauvegardes est de 30 jours.

Consultez le [guide sur les sauvegardes automatisées](/guides/public-cloud/databases/backups) pour plus d'informations.

#### Logs et métriques

Les logs et métriques sont disponibles depuis l'espace client OVHcloud, l'API, et peuvent être transférés vers Logs Data Platform. Pour les instructions de configuration, consultez le [guide Public Cloud Databases - Comment configurer le transfert des logs](/guides/public-cloud/databases/logs-to-customers).

- **Rétention des logs** : 1000 lignes de logs
- **Rétention des métriques** : 1 mois calendaire

Veuillez noter que si l'instance de base de données est supprimée, les logs et métriques sont également automatiquement supprimés.

#### Utilisateurs et rôles

La création d'utilisateurs est possible depuis l'espace client OVHcloud et l'API, avec des rôles et privilèges d'administrateur par défaut.
Le seul privilège spécifique que vous pouvez définir est `replication`.
