## Objectif

[Wagtail](https://wagtail.org/) est un système de gestion de contenu (CMS) gratuit et open source écrit en Python. Il est populaire parmi les sites web utilisant le [framework Django](https://www.djangoproject.com/).

Dans ce tutoriel, nous allons vous montrer comment installer [Wagtail](https://wagtail.org/) et comment le connecter au [service de base de données](/links/public-cloud/databases) [PostgreSQL](https://www.postgresql.org/) managé par OVHcloud.

:::warning
OVHcloud fournit des services dont vous êtes responsable de la configuration et de la gestion. Vous êtes donc responsable de leur bon fonctionnement.

Ce tutoriel est conçu pour vous aider autant que possible dans les tâches courantes. Si vous rencontrez des difficultés pour effectuer ces actions, veuillez contacter un prestataire de services spécialisé et/ou en discuter avec notre [communauté d'utilisateurs](/links/community). OVHcloud ne peut pas vous fournir d'assistance technique à ce sujet.

:::


## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud.
- Un service Public Cloud Databases for PostgreSQL opérationnel.
- Un environnement Python dans une version stable et une connectivité réseau publique (Internet). Ce tutoriel a été réalisé avec Python 3.9.7.

## Configurer votre instance PostgreSQL pour accepter les connexions entrantes

Avant d'établir une connexion, nous devons vérifier que notre instance PostgreSQL est correctement configurée.

Cliquez sur <code className="action">Databases</code> dans le menu de navigation de gauche et sélectionnez votre instance PostgreSQL.

### Étape 1 : vérifiez vos rôles utilisateur et votre mot de passe

Sélectionnez l'onglet <code className="action">Utilisateurs</code>. Vérifiez que vous disposez d'un utilisateur avec des droits suffisants et d'un mot de passe configuré. Si vous ne vous souvenez plus du mot de passe de l'utilisateur, vous pouvez soit créer un nouvel utilisateur, soit régénérer le mot de passe d'un utilisateur existant. Attention ! En faisant cela, vous devrez mettre à jour tous les endroits où vous utilisez déjà cette paire utilisateur/mot de passe.

Ce premier utilisateur **avnadmin** dispose des privilèges suivants :

```console
  LOGIN
  NOSUPERUSER
  INHERIT
  CREATEDB
  CREATEROLE
  REPLICATION
```

Nous nous appuyons sur les rôles et privilèges officiels de PostgreSQL. Vous pouvez les gérer vous-même via la CLI ou par code.
À ce jour, **la gestion des droits et privilèges des utilisateurs n'est pas prise en charge via l'espace client OVHcloud ou l'API OVHcloud**.

Veuillez consulter la [documentation officielle de PostgreSQL](https://www.postgresql.org/docs/current/database-roles.html) pour sélectionner les rôles adaptés à votre cas d'usage.

Dans notre exemple, nous allons simplement réinitialiser le mot de passe de **avnadmin**.

Une fois créé ou mis à jour, l'utilisateur doit être prêt et avoir le statut "Enabled" dans l'espace client.

<img className="thumbnail" alt="Utilisateur prêt" src="/images/public-cloud/databases/postgresql-tuto-02-connect-wagtail-to-managed-postgresql/user_enabled.png" loading="lazy" />

### Étape 2 : autoriser les connexions entrantes depuis le client PostgreSQL

Dans cette étape, sélectionnez l'onglet <code className="action">IPs autorisées</code> (liste de contrôle d'accès).
Par défaut, une base de données Public Cloud n'accepte aucune forme de connexion venant de l'extérieur.
Cela permet de prévenir les tentatives de connexion intrusives.

Cliquez pour autoriser une nouvelle IP, et saisissez l'IP de votre environnement Python trouvée précédemment. Dans notre cas, nous saisirons 109.190.200.59.

<img className="thumbnail" alt="Ajouter une IP" src="/images/public-cloud/databases/postgresql-tuto-02-connect-wagtail-to-managed-postgresql/ip_authorize.png" loading="lazy" />

:::info
Si vous souhaitez autoriser toutes les connexions provenant de l'extérieur, vous pouvez saisir l'IP 0.0.0.0/0. Veuillez l'utiliser avec précaution. Toutes les IP seront autorisées.

:::


:::info
Avant d'installer Wagtail, il est nécessaire d'installer les bibliothèques libjpeg et zlib, qui apportent la prise en charge des images JPEG, PNG et GIF (via la bibliothèque Python Pillow).

:::


## En pratique

### Créer et activer un environnement virtuel

```bash
$ python3 -m venv mysite/env
$ source mysite/env/bin/activate
```

:::info
Si vous utilisez un système de contrôle de version (par exemple git), mysite sera le répertoire de votre projet. Le répertoire env qu'il contient doit être exclu de tout système de contrôle de version.

:::


### Installer Wagtail

Veuillez suivre la [documentation officielle](https://docs.wagtail.org/en/stable/getting_started/tutorial.html) pour installer Wagtail.

Vous trouverez ci-dessous un résumé du processus d'installation.

Utilisez pip, fourni avec Python, pour installer Wagtail et ses dépendances :

```bash
$ pip install wagtail
```

### Générer votre site

Wagtail fournit une commande de démarrage similaire à django-admin startproject. L'exécution de wagtail start mysite dans votre projet génèrera un nouveau dossier mysite avec quelques éléments spécifiques à Wagtail, notamment les paramètres de projet requis, une application "home" avec un modèle HomePage vide et des templates de base, ainsi qu'une application "search" d'exemple.

Comme le dossier mysite a déjà été créé par venv, exécutez wagtail start avec un argument supplémentaire pour spécifier le répertoire de destination :

```bash
$ wagtail start mysite mysite
```

### Installer les dépendances du projet

```bash
$ cd mysite
$ pip install -r requirements.txt
```

### Créer la base de données

Si vous conservez les paramètres par défaut de Wagtail, une base de données SQLite locale sera utilisée dans le répertoire du projet. Cela convient pour un PoC, mais n'est pas recommandé en production, pour plusieurs raisons (performance, sécurité, résilience, etc.). Ici, nous allons configurer Wagtail pour qu'il utilise une base de données Public Cloud Databases for PostgreSQL comme backend.

Avant de créer la base de données, modifions le fichier `mysite/mysite/settings/base.py` et adaptons les paramètres de connexion à la base de données.

Les paramètres utiles, disponibles dans l'<ManagerLink to="/">espace client OVHcloud</ManagerLink>, sont :

- L'hôte (Host) et le port (Port) de la base de données
    - Récupérez-les depuis l'onglet "General Information".
- Le nom (Name) de la base de données
    - Récupérez-le depuis l'onglet "Databases", généralement "defaultdb".
- L'utilisateur (User) de la base de données
    - Récupérez-le depuis l'onglet "Users", généralement "avnadmin".
- Le mot de passe (Password) de la base de données
    - Récupérez-le après l'avoir réinitialisé.

<img className="thumbnail" alt="Mot de passe réinitialisé" src="/images/public-cloud/databases/postgresql-tuto-02-connect-wagtail-to-managed-postgresql/postgresql_tuto_02_connect_wagtail_to_managed_postgresql-2022040814593090.png" loading="lazy" />

```python
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'NAME': <db_name>,
        'USER': `<username>`,
        'PASSWORD': <password>,
        'HOST': <host>,
        'PORT': <port>,
        'OPTIONS': {
          'sslmode': 'require'
        }
    }
}
```

Créez ensuite la base de données :

```bash
$ python manage.py migrate
```

Cette commande garantit que les tables de votre base de données correspondent aux modèles de votre projet. Chaque fois que vous modifiez un modèle (par exemple en ajoutant un champ à un modèle), vous devrez exécuter cette commande pour mettre à jour la base de données.

### Créer un utilisateur administrateur

Une fois connecté au site d'administration, un superutilisateur dispose de toutes les permissions et peut consulter/créer/gérer la base de données.

```bash
$ python manage.py createsuperuser
```

### Démarrer le serveur

```bash
$ python manage.py runserver
```

Si tout a fonctionné, `http://127.0.0.1:8000` affichera une page d'accueil :

<img className="thumbnail" alt="Page d'accueil de Wagtail" src="/images/public-cloud/databases/postgresql-tuto-02-connect-wagtail-to-managed-postgresql/postgresql_tuto_02_connect_wagtail_to_managed_postgresql-2022021414341293.png" loading="lazy" />

Vous pouvez désormais accéder à la zone d'administration à l'adresse `http://127.0.0.1:8000/admin` :

![Page d'administration de Wagtail](/images/public-cloud/databases/postgresql-tuto-02-connect-wagtail-to-managed-postgresql/postgresql_tuto_02_connect_wagtail_to_managed_postgresql-20220215093836579.png)

### Nettoyage

Pour nettoyer votre installation Wagtail, assurez-vous qu'elle est arrêtée en appuyant sur <code className="action">CTRL+C</code> dans le terminal que vous avez utilisé pour la lancer, puis supprimez votre dossier d'installation.

```sh
rm -rf /home/my/app/path/my-wagtail/
```

Pour nettoyer votre PostgreSQL, utilisez l'espace client OVHcloud pour supprimer votre service PostgreSQL managé :
