## Capacités et limitations

### Régions prises en charge et multi-AZ

L'offre Public Cloud Analytics est disponible dans les régions suivantes :

- `BHS` (Beauharnois, Canada)
- `DE` (Francfort, Allemagne)
- `GRA` (Gravelines, France)
- `SBG` (Strasbourg, France)
- `SGP` (Singapour, Singapour)
- `EU-WEST-PAR` (Paris, France)
- `EU-SOUTH-MIL` (Milan, Italie)
- `UK` (Londres, Royaume-Uni)
- `WAW` (Varsovie, Pologne)
- `RBX` (Roubaix, France)
- `AP-SOUTH-MUM` (Mumbai, Inde)

Les nœuds Kafka MirrorMaker doivent se trouver dans la même région.

### Versions de Kafka

L'offre Public Cloud Analytics prend en charge les versions Kafka suivantes :

- Kafka MirrorMaker 3.7
- Kafka MirrorMaker 3.8

Vous pouvez suivre le cycle de publication de Kafka sur leur page officielle : [https://kafka.apache.org/downloads](https://kafka.apache.org/downloads)

### Clients Kafka

Vous pouvez utiliser n'importe lequel des clients recommandés par Kafka pour accéder à votre cluster.

De plus, Kafka Connect est disponible chez OVHcloud.

### Plans

Trois plans sont disponibles :

- **Essential/Discovery** : 1 nœud
- **Business/Production** : 3 nœuds
- **Enterprise/Advanced** : 6 nœuds

Le plan choisi affecte le nombre de nœuds que votre cluster peut exécuter, ainsi que le SLA.

Plus d'informations sur [https://github.com/apache/kafka/blob/trunk/LICENSE](https://github.com/apache/kafka/blob/trunk/LICENSE).

### Fonctionnalités

#### Réseau
Les réseaux public et privé (vRack) peuvent être utilisés pour toutes les offres.

Le trafic entrant et sortant est inclus dans les plans de service et non facturé à l'usage.

L'adresse IP du service analytics est susceptible de changer périodiquement. Il est donc conseillé de ne pas s'appuyer sur ces adresses IP pour une quelconque configuration, telle que la connexion ou la politique de trafic sortant. Utilisez plutôt l'enregistrement DNS fourni et mettez en œuvre des politiques de trafic sortant basées sur des blocs CIDR pour une gestion réseau plus robuste et flexible.

##### Considérations relatives au réseau privé
Voici quelques éléments à prendre en compte lors de l'utilisation d'un réseau privé :

- Les ports réseau sont créés dans le réseau privé de votre choix. Par conséquent, les opérations ultérieures sur ce réseau peuvent être restreintes - par exemple, vous ne pourrez pas supprimer le réseau si vous n'avez pas au préalable arrêté les services Public Cloud Analytics.
- Lors d'une connexion depuis un sous-réseau externe, la passerelle IP OpenStack doit être activée dans le sous-réseau utilisé pour le service analytics. Le client est responsable de toute autre configuration réseau personnalisée.
- Le dimensionnement du sous-réseau doit tenir compte des nœuds de service, des autres services colocalisés dans le même sous-réseau, ainsi que d'une allocation d'adresses IP disponibles supplémentaires à des fins de maintenance. Un dimensionnement inadéquat des sous-réseaux pourrait entraîner des difficultés opérationnelles et un dysfonctionnement des services.
- Les annonces de routes des sous-réseaux OpenStack ne seront pas appliquées à vos services.
- Vous ne pouvez créer des services de réseau privé que si vous êtes le propriétaire d'origine du réseau. Vous ne pouvez pas créer de services de réseau privé sur un réseau partagé.

##### IPs autorisées

Une fois votre service opérationnel, vous pourrez spécifier des adresses IP (ou des blocs CIDR) pour autoriser le trafic entrant. En attendant, votre service sera inaccessible.

#### Réplication Kafka et rétention des données

Vous pouvez sélectionner un cluster Kafka source et un cluster Kafka de destination au sein du même projet Public Cloud.
Les clusters Kafka externes ne sont pas pris en charge pour le moment.

Vous avez besoin d'au moins 2 clusters Kafka pour créer des flux de réplication.

Les paramètres autorisés pour les flux de réplication sont :

- Source
- Target
- Topics
- Topics exclusion
- Sync group offset
- Sync interval en secondes (s)
- Heartbeats (true/false)

La rétention des données n'est limitée que par l'espace de stockage de votre cluster.

#### Paramètres avancés

Bien que les paramètres avancés soient pris en charge pour Kafka, ils ne le sont pas pour Kafka MirrorMaker.

#### Sauvegardes

Kafka est un outil de streaming. Nous n'effectuons pas de sauvegarde des données Kafka.

#### Logs et métriques

Les logs et métriques sont disponibles via l'espace client et l'API, et peuvent être transmis vers Logs Data Platform. Pour les instructions de configuration, consultez [Analytics - Comment configurer la transmission des logs](/guides/public-cloud/data-analytics/analytics/logs-to-customers).

- **Rétention des logs** : 1000 lignes de logs
- **Rétention des métriques** : 1 mois calendaire

Veuillez noter que si l'instance analytics est supprimée, les logs et métriques sont également automatiquement supprimés.

#### Utilisateurs et rôles

La création d'utilisateurs est possible via l'espace client et l'API.

Vous pouvez spécifier un nom d'utilisateur pour chaque utilisateur. Par défaut, le rôle est **admin**.
