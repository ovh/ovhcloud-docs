## Objectif

Public Cloud Databases vous permet de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure de base de données et son maintien en conditions opérationnelles.

**Ce guide explique comment configurer votre instance Valkey pour accepter les connexions entrantes.**

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Un service Valkey fonctionnant sur votre Public Cloud Databases OVHcloud ([ce guide](/guides/public-cloud/databases/getting-started) peut vous aider à répondre à ce prérequis)

## En pratique

### Configurer votre instance Valkey pour accepter les connexions entrantes

Avant d'établir une connexion, nous devons vérifier que notre instance Valkey est correctement configurée.

Cliquez sur <code className="action">Databases</code> dans la barre de navigation de gauche et sélectionnez votre instance Valkey.

#### Étape 1 : Vérifiez vos rôles utilisateur et votre mot de passe

Sélectionnez l'onglet <code className="action">Utilisateurs</code>. Vérifiez que vous disposez d'un utilisateur avec les droits suffisants et un mot de passe. Si vous ne vous souvenez plus du mot de passe de l'utilisateur, vous pouvez soit créer un nouvel utilisateur, soit régénérer le mot de passe d'un utilisateur existant. Attention ! Ce faisant, vous devrez mettre à jour tous les endroits où vous utilisez déjà cette paire utilisateur/mot de passe.

Dans notre exemple, nous allons créer un utilisateur nommé *redisUser* avec les droits suivants :

- Clés :
    - **\*** (pour *allkeys*)
- Commandes :
    - **+ping** (pour la commande *ping*)
    - **+info** (pour la commande *info*)
    - **+echo** (pour la commande *echo*)
    - **+get** (pour la commande *get*)
    - **+set** (pour la commande *set*)
    - **+client** (pour la commande *client*)
- Canaux :
    - **\*** (pour *allchannels*)

<img className="thumbnail" alt="Création d'un utilisateur" src="/images/public-cloud/databases/redis-08-prepare-for-incoming-connections/redis_08_prepare_for_incoming_connections-2022032912263856.png" loading="lazy" />

Une fois créé ou mis à jour, l'utilisateur doit être prêt et afficher le statut « Activé » dans le Control Panel.

<img className="thumbnail" alt="Utilisateur prêt" src="/images/public-cloud/databases/redis-08-prepare-for-incoming-connections/redis_08_prepare_for_incoming_connections-20220329122758377.png" loading="lazy" />

:::info
Suivez la [documentation officielle des commandes](https://redis.io/commands/) pour en savoir plus.

Suivez ce [guide](/guides/public-cloud/databases/redis-capabilities#utilisateurs-et-rôles) pour en savoir plus sur les capacités et limitations des utilisateurs et des rôles.

:::


#### Étape 2 : Autorisez les connexions entrantes du service

:::warning
Pour des raisons de sécurité, la configuration réseau par défaut n'autorise aucune connexion entrante. Il est donc essentiel d'autoriser les adresses IP appropriées afin de pouvoir accéder à votre base de données.

:::


Dans cette étape, sélectionnez l'onglet <code className="action">IPs autorisées</code>. Les adresses IP doivent être autorisées ici avant de pouvoir se connecter à votre base de données.

En cliquant sur <code className="action">Ajouter une adresse IP / masque</code>, une nouvelle fenêtre s'ouvre dans laquelle vous pouvez ajouter des adresses IP uniques ou des blocs pour autoriser l'accès à la base de données.

<img className="thumbnail" alt="Ajout d'une IP" src="/images/public-cloud/databases/redis-08-prepare-for-incoming-connections/ip_authorize.png" loading="lazy" />

Vous pouvez modifier et retirer l'accès à la base de données via le bouton <code className="action">...</code> dans le tableau des IPs.

:::info
Si vous souhaitez autoriser les connexions depuis l'extérieur, vous pouvez saisir l'IP 0.0.0.0/0. Veuillez l'utiliser avec précaution.

:::


#### Collecter les informations requises

Sélectionnez l'onglet <code className="action">Informations générales</code> pour trouver les identifiants de connexion requis dans la section `Login informations`.
