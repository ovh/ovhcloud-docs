## Objectif

Public Cloud Databases vous permet de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure de base de données et son maintien en conditions opérationnelles.

**Ce guide explique comment configurer votre instance Valkey pour accepter les connexions entrantes.**

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Un service Valkey fonctionnant sur votre Public Cloud Databases OVHcloud ([ce guide](/guides/public-cloud/databases/getting-started) peut vous aider à répondre à ce prérequis)

[[cpnav:publiccloud-databases]]

## En pratique

### Configurer votre instance Valkey pour accepter les connexions entrantes

Avant d'établir une connexion, nous devons vérifier que notre instance Valkey est correctement configurée.

Cliquez sur <code className="action">Databases</code> dans la barre de navigation de gauche et sélectionnez votre instance Valkey.

#### Étape 1 : Vérifiez vos rôles utilisateur et votre mot de passe

Sélectionnez l'onglet <code className="action">Utilisateurs</code>. Vérifiez que vous disposez d'un utilisateur avec les droits suffisants et un mot de passe. Un utilisateur `default` existe sur chaque nouveau service.

Le mot de passe d'un utilisateur n'est affiché qu'une seule fois, à la création de l'utilisateur, et ne peut pas être récupéré par la suite. Si vous ne vous souvenez plus du mot de passe de l'utilisateur, vous pouvez soit créer un nouvel utilisateur, soit régénérer le mot de passe d'un utilisateur existant : cliquez sur le bouton <code className="action">...</code> à droite de l'utilisateur, puis sur <code className="action">Regénérer le mot de passe</code>. Attention ! Ce faisant, vous devrez mettre à jour tous les endroits où vous utilisez déjà cette paire utilisateur/mot de passe.

Pour créer un nouvel utilisateur, cliquez sur <code className="action">Ajouter un utilisateur</code>, remplissez le formulaire, puis cliquez sur <code className="action">Créer un utilisateur</code>. Chaque champ accepte plusieurs valeurs :

- **Nom d'utilisateur** : le nom de l'utilisateur.
- **Clés** : les patterns de clés auxquelles l'utilisateur peut accéder, par exemple `cache:*`.
- **Catégories** : les catégories de commandes autorisées (`+`) ou interdites (`-`), par exemple `+@read`, `+@write`, `+@connection`.
- **Commandes** : des commandes individuelles autorisées (`+`) ou interdites (`-`), par exemple `-flushall`.
- **Channels** : les patterns de canaux pub/sub auxquels l'utilisateur peut accéder, par exemple `news:*`.

Dans notre exemple, nous créons un utilisateur nommé *app-user* avec les droits suivants :

- Clés :
    - **cache:\*** (uniquement les clés commençant par `cache:`)
- Catégories :
    - **+@read** (commandes de lecture)
    - **+@write** (commandes d'écriture)
    - **+@connection** (commandes de connexion comme `PING`, `HELLO` ou `AUTH`)
    - **+@pubsub** (commandes pub/sub, nécessaires en plus d'un pattern de canal pour publier ou s'abonner)
- Commandes :
    - **-flushall** (interdit la commande `FLUSHALL`)
- Channels :
    - **news:\*** (uniquement les canaux commençant par `news:`)

Avec ces droits, tout accès à une clé hors de `cache:*` est refusé avec l'erreur `NOPERM No permissions to access a key`.

Une fois créé ou mis à jour, l'utilisateur doit afficher le statut `READY` dans l'espace client OVHcloud.

Pour modifier les droits d'un utilisateur existant, cliquez sur le bouton <code className="action">...</code> à droite de l'utilisateur, puis sur <code className="action">Modifier</code>. Les nouveaux droits s'appliquent immédiatement, sans reconnexion. Vous pouvez également les gérer [avec l'API](/guides/public-cloud/databases/valkey-update-acls).

:::info
Consultez la [documentation des ACL Valkey](https://valkey.io/topics/acl/) et la [documentation des commandes Valkey](https://valkey.io/commands/) pour en savoir plus.

Suivez ce [guide](/guides/public-cloud/databases/valkey-capabilities#utilisateurs-et-rôles) pour en savoir plus sur les capacités et limitations des utilisateurs et des rôles.

:::


#### Étape 2 : Autorisez les connexions entrantes du service

:::warning
Pour des raisons de sécurité, la configuration réseau par défaut n'autorise aucune connexion entrante. Il est donc essentiel d'autoriser les adresses IP appropriées afin de pouvoir accéder à votre base de données.

:::


Sélectionnez l'onglet <code className="action">Configuration</code>, puis repérez la section `IPs`. Les adresses IP doivent être autorisées ici avant de pouvoir se connecter à votre base de données.

Saisissez une adresse IP ou un bloc CIDR dans le champ **Adresse IP ou IP/masque**, ajoutez une description pour identifier sa provenance, puis cliquez sur <code className="action">Ajouter</code>. Dans notre exemple, nous saisissons `203.0.113.10/32`. Le raccourci <code className="action">IP actuelle</code> ajoute l'adresse IP publique depuis laquelle vous naviguez dans l'espace client OVHcloud.

Cliquez sur <code className="action">Sauvegarder les modifications</code> pour appliquer vos changements. Vous pouvez retirer une IP autorisée depuis la même section, puis sauvegarder vos modifications.

:::warning
Vous pouvez saisir `0.0.0.0/0` pour autoriser les connexions depuis n'importe quelle adresse. Votre service devient alors accessible depuis l'ensemble d'Internet, et seule la paire nom d'utilisateur/mot de passe protège vos données. Veuillez l'utiliser avec précaution.

:::


#### Collecter les informations requises

Sélectionnez l'onglet <code className="action">Dashboard</code> pour trouver les informations de connexion dans la section `Informations de connection` : hôte, port et URI du service.

L'URI est de la forme `valkeys://<username>:<password>@<host>:<port>`. TLS est obligatoire : les connexions sans TLS sont refusées. Le certificat du serveur est signé par une autorité de certification publique : vous n'avez pas besoin de télécharger de certificat CA pour vous connecter.

Sélectionnez l'onglet <code className="action">Utilisateurs</code> pour obtenir le nom d'utilisateur.
