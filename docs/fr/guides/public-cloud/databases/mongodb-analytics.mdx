## Objectif

Ce guide explique comment configurer, dans votre cluster, un nœud dédié aux requêtes de type analytique dans un cluster Public Cloud Databases pour MongoDB de l'offre Advanced. Cela vous permet d'exécuter ce type de requêtes, ou des outils de [BI (Business Intelligence)](https://en.wikipedia.org/wiki/Business_intelligence) - notamment le [MongoDB BI Connector](https://www.mongodb.com/products/bi-connector) - sans dégrader les performances opérationnelles du cluster.

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) actif sur votre compte OVHcloud
- Un cluster de base de données MongoDB compatible multi-nœuds (donc de l'offre *Production* ou *Advanced*) fonctionnant sur votre Public Cloud Databases OVHcloud ([ce guide](/guides/public-cloud/databases/getting-started) peut vous aider à remplir cette condition)
- [Configurer votre instance MongoDB](/guides/public-cloud/databases/mongodb-manage-control-panel) pour accepter les connexions entrantes

## À quoi sert un nœud Analytics ?

Imaginons que vous exploitiez un site de recettes de cuisine très populaire. Vous pourriez utiliser une base de données MongoDB pour stocker les recettes, une couche API/backend pour donner accès à ces données, et une couche de présentation frontend - un site web ou une application - afin d'afficher ces recettes de manière attrayante à vos utilisateurs finaux.

Or, lorsqu'un utilisateur final souhaite rechercher et afficher une recette, la couche API/backend doit pouvoir trouver et récupérer le bon document assez rapidement, car votre utilisateur final a déjà faim, et l'on sait tous qu'une expérience utilisateur réactive est plus agréable. De plus, comme ce site de recettes est très populaire, vous devez pouvoir servir un grand nombre d'utilisateurs finaux simultanément, donc de nombreuses requêtes similaires en même temps. Autrement dit, les requêtes opérationnelles doivent souvent répondre à des exigences de faible latence, portent généralement sur un petit sous-ensemble de la base de données dans son ensemble, et vous pourriez avoir à exécuter un grand nombre de requêtes de plus petite taille.

D'un autre côté, en tant qu'exploitant de ce site populaire, vous souhaitez comprendre les tendances d'utilisation dans leur ensemble. Pour cela, vous pourriez avoir besoin d'interroger votre base de données afin d'obtenir des informations sur l'état de votre système, par exemple : qui sont vos meilleurs utilisateurs ? Où se trouvent-ils ? À quel moment de la journée votre site est-il le plus actif ? Ces requêtes analytiques répondent à des exigences différentes des précédentes : elles portent généralement sur une plus grande partie de la base de données, elles sont moins sensibles à la latence, et vous ne voulez pas qu'elles perturbent l'expérience de l'utilisateur final.

En résumé, un nœud Analytics dans votre cluster Public Cloud Databases pour MongoDB vous permet d'exécuter ces requêtes analytiques tout en garantissant que vos requêtes opérationnelles n'en pâtissent pas, en les redirigeant vers un nœud spécifique du cluster.

## En pratique

### Faire en sorte que votre cluster propose un nœud Analytics

#### Comment créer un cluster disposant d'un nœud Analytics ?

Depuis l'API, vous pouvez créer un nouveau cluster avec :

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/mongodb"} />


À l'aide du paramètre **nodeList**, vous pouvez définir les nœuds du cluster. L'attribut **role** peut prendre la valeur `STANDARD` ou `ANALYTICS` selon le rôle souhaité pour le nœud concerné.

#### Comment ajouter un nœud Analytics à un cluster existant ?

Si vous disposez déjà d'un cluster existant, vous pouvez ajouter un nouveau nœud à l'aide de l'endpoint API suivant :

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/mongodb/\{clusterId\}/node"} />


En spécifiant l'attribut **role**, `STANDARD` ou `ANALYTICS`, vous pouvez demander le rôle souhaité pour le nœud concerné.

#### Comment transformer un nœud non-Analytics en nœud Analytics ?

Vous pouvez modifier le rôle d'un nœud donné à l'aide de :

<Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\{serviceName\}/database/mongodb/\{clusterId\}/node/\{nodeId\}"} />


Là encore, l'attribut **role** (`STANDARD` / `ANALYTICS`) permet d'attribuer au nœud le rôle demandé.

### Diriger les requêtes analytiques vers le nœud Analytics

Le cluster peut désormais être joint via deux chaînes de connexion différentes :

- Utilisez `mongodb+srv://<username>:<password>@<cluster hostname>/admin?replicaSet=replicaset&tls=true` pour les connexions opérationnelles, par exemple dans la configuration de l'application.
- Utilisez `mongodb+srv://<username>:<password>@<cluster hostname>/admin?replicaSet=replicaset&tls=true&readPreference=secondary&readPreferenceTags=nodeType:ANALYTICS` pour la charge de travail analytique, par exemple dans vos outils de BI.

Remarquez les paramètres de requête supplémentaires `readPreference=secondary` et `readPreferenceTags=nodeType:ANALYTICS` : ils dirigent les requêtes vers le nœud Analytics que nous avons configuré.

## Contraintes et limitations

- Quoi qu'il en soit, votre cluster a besoin d'au moins 3 nœuds non-Analytics. Cela signifie que le plus petit cluster disposant d'un nœud Analytics est un cluster à 4 nœuds.
- Un cluster ne peut avoir qu'un seul nœud Analytics au maximum.
- Si l'un des trois premiers nœuds d'un cluster est un nœud Analytics, vous ne pourrez alors pas réduire le cluster de 4 à 3 nœuds à l'aide de l'appel API suivant, utilisant le paramètre `nodeNumber` :

<Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\{serviceName\}/database/mongodb/\{clusterId\}"} />


Vous pouvez soit utiliser l'endpoint de suppression de nœud pour retirer le nœud Analytics, soit transformer ce nœud Analytics en nœud standard avant de réduire la taille du cluster.
