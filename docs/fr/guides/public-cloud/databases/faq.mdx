## Objectif

Voici les questions les plus fréquemment posées sur Public Cloud Databases.

## Généralités

### Qu'est-ce que Public Cloud Databases d'OVHcloud ?

Public Cloud Databases est un service managé vous permettant de déployer et d'utiliser facilement des instances de bases de données.

Nous proposons des services économiques et prenons en charge l'infrastructure. Nous fournissons par défaut diverses fonctionnalités telles que des sauvegardes automatiques, des mises à jour logicielles, un réseau public ou privé, des outils d'observabilité tels que les logs et les métriques, ainsi que des mécanismes de sécurité de bout en bout.

Nos bases de données Public Cloud sont accessibles via le réseau public (Internet) ou le réseau privé (vRack), ce qui permet de nombreux cas d'usage : connexion à des instances Public Cloud OVHcloud ou à des clusters Kubernetes, à des serveurs dédiés (baremetal) OVHcloud, à Hosted Private Cloud, à des VPS OVHcloud... mais permet également le Cloud hybride, tant que vous pouvez utiliser le réseau public (Internet).

### Quelle est la différence entre cette offre et les bases de données de l'hébergement web ?

Les principales différences avec nos bases de données pour l'hébergement web résident dans la possibilité de se connecter aux réseaux public et privé, l'intégration native dans Public Cloud avec un modèle de facturation à l'usage, une gamme de calcul plus étendue, et une résilience améliorée grâce au clustering. Par ailleurs, Public Cloud Databases proposera davantage de possibilités en matière de SGBD.

### Quels sont les SGBD pris en charge ?

Nous ajoutons de plus en plus de systèmes de gestion de bases de données (SGBD) au fil du temps ; retrouvez la liste exacte et les versions proposées sur notre page [Capacités et limitations](/guides/public-cloud/databases/capabilities).

### Puis-je connecter Public Cloud Databases à d'autres produits OVHcloud ?

Oui. Les bases de données Public Cloud peuvent être connectées au réseau public (Internet) ou au réseau privé (vRack).

Vous pouvez ensuite les connecter à tout produit compatible avec ces topologies réseau :

- Réseau public : tout produit Cloud d'OVHcloud.
- Réseau privé (vRack) : Baremetal Cloud, Hosted Private Cloud, instances Public Cloud, clusters Kubernetes managés Public Cloud.

### Puis-je connecter Public Cloud Databases à des services tiers ?

Oui. Vous pouvez accéder à vos services Public Cloud Databases via le réseau public (Internet). Vous pouvez ensuite connecter un service tiers, par exemple un autre fournisseur Cloud ou une infrastructure sur site.

### Où puis-je trouver la roadmap du produit ?

Nous publions notre roadmap sur [Github](https://github.com/ovh/public-cloud-roadmap/projects). Vous pouvez filtrer par étiquette telle que « Databases ».

## Plans de service et instances

### Quelles sont les principales différences entre les plans Essential/Discovery, Business/Production et Enterprise/Advanced ?

Nous avons conçu nos plans de service en fonction des cas d'usage métier. Ils présentent des différenciateurs majeurs, propres à chaque SGBD.

Globalement, nous avons conçu 5 plans de service en pensant aux usages suivants :

- Essential/Discovery : idéal pour les tests, les preuves de concept et le développement. Non destiné à un usage en production, principalement en raison de l'absence de SLA, de haute résilience via le clustering ou de réseau privé.
- Business/Production : premier niveau pour une infrastructure de développement ou de production. La haute résilience est assurée, avec un SLA.
- Enterprise/Advanced : le plus haut niveau de service, avec toutes les fonctionnalités et un meilleur SLA. Pour certains SGBD comme MongoDB, vous bénéficiez également du plus haut niveau de licence.

### Qu'est-ce qui est exactement géré par OVHcloud en mon nom ?

OVHcloud gère diverses tâches en votre nom :

- Mise en place : nous vous fournissons une instance de base de données avec une installation de pointe, ce qui signifie que nous prenons en charge le provisionnement, ainsi que la configuration initiale du système d'exploitation et du logiciel SGBD.
- Une fois votre base de données en cours d'exécution : selon votre plan de service, nous effectuons des tâches administratives telles que les sauvegardes quotidiennes, la mise à jour du logiciel, et la mise à disposition d'outils de sécurité pour l'authentification.

Néanmoins, dans la mesure où nous fournissons l'accès à la base de données, vous restez responsable, en tant que client, de la gestion des services :

- Configuration des paramètres selon vos cas d'usage, y compris le réseau, la sécurité et les sauvegardes.
- Définition de vos schémas de données relationnels ou NoSQL adaptés à vos besoins.
- Optimisation des performances (performance tuning).

### Combien d'instances de base de données puis-je exécuter ?

Public Cloud d'OVHcloud vous permet de créer des projets, pour lesquels vous disposez ensuite de quotas et d'une facturation par projet. Les quotas sont visibles dans votre espace client OVHcloud et dépendent de votre historique. Le quota par défaut est limité à 20 instances par projet.

### Comment démarrer ?

Public Cloud Databases nécessite un projet Public Cloud. Une fois un projet créé, vous pouvez démarrer des instances de base de données via l'espace client OVHcloud en quelques minutes.

Veuillez consulter notre documentation [Bien démarrer avec Public Cloud Databases](/guides/public-cloud/databases/getting-started).

### Comment importer des données dans une instance de base de données ?

Nous utilisons des versions officielles et non modifiées (vanilla) des SGBD, ce qui vous permet de vous appuyer sur la documentation officielle de chaque SGBD pour importer des données dans Public Cloud Databases. Par exemple, pour PostgreSQL, vous pouvez utiliser pg_dump et pg_restore ; pour MySQL, vous pouvez utiliser mysqldump et mysqlimport.

Veuillez vous référer au site officiel de la documentation de chaque SGBD :

- [MongoDB](https://docs.mongodb.com/manual/)
- [MySQL](https://dev.mysql.com/doc/)
- [PostgreSQL](https://www.postgresql.org/docs/)
- [Valkey](https://valkey.io/docs/)

## Logiciels et versions des SGBD

### Quelles sont les versions de SGBD proposées ?

Nous ajoutons de plus en plus de systèmes de gestion de bases de données (SGBD) au fil du temps ; retrouvez la liste exacte et les versions proposées sur notre page [Capacités et limitations](/guides/public-cloud/databases/capabilities).

### Qu'est-ce qu'une version mineure et une version majeure ?

Chaque logiciel, y compris les logiciels de base de données, propose de nouvelles versions de son code, incluant généralement des corrections de bugs, des améliorations de sécurité et des évolutions.

En général, une mise à niveau de version mineure ne comporte que des changements rétrocompatibles avec les applications existantes. À l'inverse, une version majeure peut entraîner des incompatibilités.

Chaque SGBD se comporte différemment et sa documentation officielle fait foi.

### Comment puis-je sélectionner la version du SGBD lors de la création d'une instance de base de données ?

Vous pouvez créer une instance de base de données via l'API ou l'espace client OVHcloud. Dans les deux cas, vous pouvez sélectionner divers paramètres tels que le type de SGBD et sa version.

### Puis-je mettre à jour manuellement la version de mon SGBD ?

Oui, lorsque toutes les conditions requises sont réunies :

- Lorsque votre service est en cours d'exécution.
- Lorsqu'une autre version du SGBD est disponible.
- Lorsque le SGBD le permet.

Si toutes les conditions sont validées, vous pouvez effectuer la mise à jour directement via l'API ou l'espace client OVHcloud.

### Quels sont les risques et mes responsabilités concernant les mises à jour de SGBD ?

Une mise à jour de SGBD doit toujours être testée au préalable, et le client doit suivre les bonnes pratiques officielles du SGBD. En général, les nouvelles versions majeures introduisent de nouvelles fonctionnalités et en déprécient quelques-unes. Selon votre propre usage, cela peut entraîner une indisponibilité de votre application.

### Puis-je tester une nouvelle version avant de mettre à niveau ?

Oui. Une fois votre instance de base de données en cours d'exécution, vous pouvez restaurer une sauvegarde sous la forme d'une nouvelle instance de base de données (fork).

Au cours de ce processus, vous pouvez sélectionner diverses options, telles qu'une autre version de votre SGBD. Une fois que vous avez vérifié le bon fonctionnement de votre nouveau service, vous pouvez soit le conserver, soit le supprimer.

La facturation étant effectuée à la seconde, cette opération peut être répétée autant de fois que nécessaire (sans augmentation significative de votre facture).

### Que se passe-t-il si j'utilise une version dépréciée du SGBD sur mon instance de base de données ?

Vous serez averti afin de mettre à niveau votre version.

### Quelles sont les extensions prises en charge pour chaque SGBD ?

Chaque SGBD a ses propres spécificités en matière d'extensions. En règle générale, nous ne proposons que les extensions officiellement prises en charge.

Retrouvez la liste exacte et les versions proposées sur notre page [Capacités et limitations](/guides/public-cloud/databases/capabilities).

## Facturation

### Comment les services sont-ils facturés ?

Public Cloud Databases est facturé selon un modèle « à l'usage » (pay-as-you-go). L'ensemble de l'écosystème Public Cloud vous permet de créer des projets, d'y associer un moyen de paiement (carte bancaire, PayPal, etc.), puis de lancer différents produits et services au sein de ce projet.

Vous ne payez pas avant d'utiliser le service. À la fin du mois, nous récapitulons vos dépenses dans une facture par projet. Public Cloud Databases est facturé à la seconde, selon la gamme et le modèle sélectionnés lors de la création de l'instance de base de données, avec une durée minimale de facturation d'une minute.

### Où puis-je trouver mes factures ?

Dans la section Public Cloud de l'espace client OVHcloud, retrouvez la catégorie « Project Management » (Gestion de projet). La sous-section « Billing Control » (Contrôle de facturation) vous permet de consulter la consommation actuelle de chaque produit, tel que Public Cloud Databases, mais aussi de retrouver vos factures précédentes dans votre historique.

### Qu'est-ce qui est inclus dans les tarifs ?

La tarification de Public Cloud Databases inclut :

- La mise en place et la gestion des services.
- Le nombre de nœuds sélectionné et les caractéristiques internes telles que le vCPU, la RAM et le stockage.
- Le trafic réseau entrant/sortant, selon les limites de nos gammes régionales.
- Les sauvegardes (la rétention varie, voir nos capacités).
- Les logs et métriques (la rétention varie, voir nos capacités).
- Les licences logicielles, lorsque nécessaire.

### Qu'est-ce qui n'est pas inclus dans la tarification ?

Notre tarification n'inclut pas :

- Les coûts supplémentaires de rétention des sauvegardes.
- Les coûts supplémentaires de rétention des logs et métriques.
- Le trafic réseau supplémentaire pour les régions APAC (Sydney et Singapour).

### Quand la facturation commence-t-elle et se termine-t-elle ?

Pour chaque instance de base de données, la facturation :

- Débute lorsque le service est en cours d'exécution. Par exemple, si le service met 5 minutes à démarrer, vous ne payez pas pour ce temps de mise en place.
- S'arrête lorsque vous supprimez votre service.

Nous nous basons sur l'heure UTC.

## Gammes, résilience et déploiements

### Comment dois-je sélectionner la quantité requise de calcul, de RAM et de stockage ?

Pour sélectionner la quantité adéquate de calcul, de RAM et de stockage, vous devez évaluer vos besoins.

Si vous disposez déjà d'instances de base de données, vous pouvez vérifier ce qui est consommé actuellement. Pour un nouveau service, vous devrez anticiper vos besoins. Gardez à l'esprit que vous pouvez faire évoluer votre base de données à la hausse ou à la baisse.

### Une fois mon instance de base de données lancée, puis-je faire évoluer mon service à la hausse ou à la baisse ?

Pour chaque instance de base de données, vous pouvez :

- Sélectionner un plan de service supérieur si nécessaire (Essential/Discovery vers Business/Production ou Enterprise/Advanced, Business/Production vers Enterprise/Advanced).
- Sélectionner une gamme de calcul et de stockage supérieure ou inférieure, à condition que le nouveau stockage soit suffisant pour contenir vos données.

### Mon instance de base de données reste-t-elle disponible pendant la mise à l'échelle ?

Dans la plupart des cas, et si votre plan prend en charge la haute disponibilité, votre instance reste disponible pendant la mise à l'échelle. Cependant, le statut de votre service passera à « updating » (mise à jour), ce qui vous empêchera de modifier votre service (par exemple, ajouter un utilisateur).

### Quelles sont les performances de chaque gamme ?

Nous ne fournissons pas de résultats de benchmarks pour le moment pour Public Cloud Databases. Chaque cas d'usage métier est différent, et les benchmarks peuvent fortement différer par rapport à vos propres cas d'usage réels. Gardez simplement à l'esprit que nos écarts de performance sont linéaires.

### Où mes instances de base de données sont-elles déployées ?

Lors de la création de l'instance de base de données, vous pouvez sélectionner la région et le datacenter pour déployer votre service. Retrouvez la liste exacte sur notre page [Capacités et limitations](/guides/public-cloud/databases/capabilities).

### Proposons-nous des déploiements Multi-AZ ?

Public Cloud Databases prend en charge les modes de déploiement en zone de disponibilité unique (Single Availability Zone) et en zones de disponibilité multiples (Multi-Availability Zone).

### Comment la haute disponibilité est-elle assurée ?

Pour assurer la haute disponibilité, nous utilisons les principes du clustering. Votre service et vos données sont répliqués sur plusieurs nœuds, ce qui protège l'ensemble du système contre une panne de nœud. Votre service est résilient principalement parce que nous dupliquons les données et la configuration sur plusieurs nœuds.

L'implémentation exacte peut différer selon le SGBD. En effet, chaque SGBD possède ses propres mécanismes et bonnes pratiques.

Par exemple :

- La haute disponibilité de MongoDB commence à partir de 3 nœuds.
- Pour PostgreSQL ou MySQL, elle commence à partir de 2 nœuds.

### Que désigne-t-on par nœuds « primaire » (primary) et « répliques » (replicas) ?

Pour les SGBD relationnels tels que MySQL et PostgreSQL, chaque nœud a un rôle :

- Un nœud primaire peut accepter les opérations de LECTURE et d'ÉCRITURE. Il fait office de source de vérité et est répliqué vers les nœuds répliques.
- Un nœud réplique est une copie du nœud primaire du point de vue des données, et ne peut accepter que des opérations de LECTURE. Les nœuds répliques sont très utiles pour assurer la haute disponibilité, mais aussi pour améliorer les performances en LECTURE.

En cas de panne du nœud primaire, une réplique peut être élue comme nœud primaire.

### En cas de panne d'un nœud, la bascule (failover) est-elle automatique ?

Oui, en cas de panne d'un nœud, le mécanisme de bascule est automatique, quel que soit le SGBD. OVHcloud prend en charge le processus de bascule ; de nouveaux nœuds sont élus et promus si nécessaire.

### Quelles sont les conséquences d'une bascule (failover) pour mon cluster ?

Une bascule est automatique, mais l'ensemble du processus peut prendre de quelques secondes à une minute.

En cas de bascule, votre cluster sera en mode dégradé :

- Les opérations de LECTURE peuvent être effectuées normalement.
- Les opérations d'ÉCRITURE seront rejetées jusqu'à la fin du processus de bascule.

## Sauvegardes et maintenance

### Comment effectuez-vous les sauvegardes ?

Les sauvegardes sont effectuées différemment selon le SGBD. Consultez [Sauvegardes automatiques](/guides/public-cloud/databases/backups) pour plus de détails.

### Puis-je effectuer des sauvegardes manuelles ?

Oui, vous pouvez effectuer des sauvegardes manuelles.

Nous utilisons des versions officielles et non modifiées (vanilla) des SGBD, ce qui vous permet de vous appuyer sur la documentation officielle de chaque SGBD pour effectuer des sauvegardes de Public Cloud Databases. Par exemple, pour PostgreSQL, vous pouvez utiliser pg_dump et pg_restore. Pour MySQL, vous pouvez utiliser mysqldump et mysqlimport.

Veuillez vous référer au site officiel de la documentation de chaque SGBD :

- [MongoDB](https://docs.mongodb.com/manual/)
- [MySQL](https://dev.mysql.com/doc/)
- [PostgreSQL](https://www.postgresql.org/docs/)
- [Valkey](https://valkey.io/docs/)

### Puis-je télécharger directement les sauvegardes réalisées par OVHcloud ?

Non, vous ne pouvez pas télécharger directement les sauvegardes réalisées par OVHcloud. Mais vous pouvez les restaurer vers un autre service, puis utiliser les lignes de commande officielles pour exporter les données.

### Où mes sauvegardes sont-elles stockées, et pendant combien de temps ?

Lorsque cela est possible, nous stockons vos sauvegardes chiffrées en dehors de la région de votre service, pour des raisons de durabilité. L'emplacement de la sauvegarde est disponible avec les autres informations de la sauvegarde dans l'API.

La durée de conservation de la sauvegarde dépend du plan auquel vous avez souscrit. Vous pouvez la retrouver dans notre documentation [Sauvegardes automatiques](/guides/public-cloud/databases/backups).

### Quelles sont mes responsabilités concernant les sauvegardes ?

En tant que client, vous êtes seul responsable de la réalisation des sauvegardes appropriées pour vos services.

### Qu'est-ce qu'une fenêtre de sauvegarde ? Mon instance de base de données sera-t-elle disponible pendant les sauvegardes ?

La fenêtre de sauvegarde est la période de la journée pendant laquelle les opérations de sauvegarde sont exécutées. Votre instance reste disponible.

### Puis-je modifier la fenêtre de sauvegarde ?

Oui, vous le pouvez, via l'espace client OVHcloud, Terraform, ou l'API.

### Puis-je modifier l'emplacement de la sauvegarde ?

Oui, vous le pouvez. Veuillez consulter [Sauvegardes automatiques](/guides/public-cloud/databases/backups) pour plus de détails.

### Qu'est-ce qu'une fenêtre de maintenance ? Mon instance de base de données sera-t-elle disponible pendant les opérations de maintenance ?

La fenêtre de maintenance est la période de la journée pendant laquelle les opérations de maintenance, telles que les correctifs de sécurité, peuvent être exécutées. Selon l'opération de maintenance, votre instance de base de données peut être disponible ou non pendant cet événement, mais dans la plupart des cas, elle reste disponible.

### Puis-je modifier la fenêtre de maintenance ?

Oui, vous le pouvez, via l'espace client OVHcloud, Terraform, ou l'API.

## Sécurité

### Quels sont les mécanismes de sécurité mis en place pour mon instance de base de données ?

Chaque instance de base de données est fortement sécurisée grâce à plusieurs mesures :

- **Infrastructure** : nous nous appuyons sur la pile logicielle open source OpenStack pour l'ensemble de notre Public Cloud. Nous sommes audités par des organismes officiels et certifiés selon les normes ISO 27001, par exemple.
- **Réseau public ou privé** : selon vos besoins et vos politiques internes en matière de sécurité, vous pouvez opter pour un accès via le réseau public (Internet) ou le réseau privé (vRack).
- **ACL réseau** : nous proposons des listes de contrôle d'accès (Access Control List, ACL) vous permettant de préciser quelles IP ou plages d'IP sont autorisées à se connecter à votre instance de base de données. Par défaut, aucune ACL n'est déclarée sur le service, ce qui signifie que personne ne peut se connecter à votre service tant que vous n'en avez pas ajouté au moins une.
- **Chiffrement de bout en bout** : les connexions aux bases de données sont, par défaut, chiffrées avec le protocole TLS, assurant une protection par chiffrement de bout en bout. OVHcloud génère un certificat SSL/TLS pour chaque instance de base de données. Une fois qu'une connexion chiffrée est établie entre votre application et votre instance de base de données, vos flux de données seront chiffrés.
- **Chiffrement des données** : les données sont stockées sur des volumes dédiés qui sont chiffrés.
- **Souveraineté européenne des données** : Public Cloud Databases fait partie d'OVHcloud, une entreprise européenne. Cela garantit la souveraineté des données à nos clients. [En savoir plus](/links/about-us/data-sovereignty)

### Qui peut accéder à mon instance de base de données initialement ?

Lorsque vous démarrez une nouvelle instance de base de données, les valeurs par défaut sont les suivantes :

- Aucun accès pour les IP ou plages d'IP. Rien n'est autorisé (ACL).
- 1 utilisateur créé (admin) mais non configuré. Vous devez réinitialiser le mot de passe.

En résumé, votre base de données est initialement inaccessible. Cela est fait intentionnellement pour protéger vos données contre les connexions non sollicitées.

### Comment puis-je gérer les accès autorisés à mon instance de base de données ?

Une fois votre instance de base de données créée, vous pouvez gérer les IP ou plages d'IP autorisées, soit depuis l'espace client OVHcloud, soit via Terraform ou l'API. Vous avez besoin d'au moins 1 IP autorisée pour accéder à votre service.

Veuillez consulter notre [guide de démarrage](/guides/public-cloud/databases/getting-started) pour une documentation détaillée, étape par étape.

### Comment puis-je ajouter de nouveaux utilisateurs pour mon instance de base de données ?

Une fois votre instance de base de données créée, vous pouvez gérer les utilisateurs de la base de données, soit depuis l'espace client OVHcloud, soit via Terraform ou l'API. Vous avez besoin d'au moins 1 utilisateur créé et configuré. Veuillez consulter notre [guide de démarrage](/guides/public-cloud/databases/getting-started) pour une documentation détaillée, étape par étape.

### Mes données sont-elles chiffrées ?

Les volumes sur lesquels les données sont stockées sont chiffrés, et les sauvegardes sont également chiffrées avant d'être stockées.

### Quelles sont les certifications disponibles pour Public Cloud Databases ?

OVHcloud répond aux plus hauts standards de certification. Public Cloud Databases bénéficie de plusieurs certifications :

- ISO 27001
- Prévu : HIPAA / HDS 1-2-3

Pour la conformité dans le domaine de la santé, telle que HIPAA/HDS, veuillez consulter notre [page officielle](/links/hosted-private-cloud/certification-hds). Pour un aperçu des certifications, veuillez consulter notre [page officielle](/links/compliance).

## Réseau

### Puis-je me connecter à mon instance de base de données via le réseau public ?

Oui, toutes les instances de base de données peuvent se connecter au réseau public. Cela doit être spécifié et sélectionné lors de la création de l'instance de base de données. Si vous sélectionnez la connectivité via réseau public, vous ne pourrez pas être connecté via le réseau privé.

### Puis-je me connecter à mon instance de base de données via le réseau privé (vRack) ?

Oui, selon le plan de service, les instances de base de données peuvent se connecter au réseau privé (vRack). Cela doit être spécifié et sélectionné lors de la création de l'instance de base de données. Si vous sélectionnez la connectivité via réseau privé, vous ne pourrez pas être connecté via le réseau public.

### Puis-je déplacer mon instance du réseau public vers le réseau privé, ou inversement ?

Non, vous ne le pouvez pas. Une fois le type de réseau d'une instance défini, vous ne pouvez pas basculer vers l'autre type de réseau. Cependant, si votre instance contient déjà des données et que vous souhaitez passer à l'autre type de réseau, vous pouvez restaurer votre instance à partir d'une sauvegarde vers une nouvelle instance utilisant l'autre type de réseau (fork).

### Puis-je déplacer mon instance de base de données d'un vRack à un autre ?

Pour le moment, vous ne pouvez pas déplacer votre base de données d'un vRack à un autre. Vous pouvez suivre notre [roadmap officielle](https://github.com/ovh/public-cloud-roadmap/projects).

### Le trafic réseau entrant est-il inclus (données envoyées VERS votre instance de base de données) ?

Oui, le trafic réseau entrant est inclus dans nos tarifs et n'est pas facturé à l'usage.

### Le trafic réseau sortant est-il inclus (données extraites DEPUIS votre instance de base de données) ?

Oui, le trafic réseau sortant est inclus dans nos tarifs et n'est pas facturé à l'usage. Cela vous permet de bénéficier d'une tarification prévisible, sans aucun risque d'augmentation incontrôlée de votre facture.

Exceptions : pour les instances de base de données situées en région APAC (Sydney, Singapour), le trafic entrant/sortant est plafonné. Cette information est indiquée sur la page de tarification du site.

## Dépannage

### Je n'arrive pas à me connecter à mon instance de base de données

Chaque instance de base de données est sécurisée par défaut.

Pour vous connecter à une instance de base de données, veuillez vérifier les points suivants :

- Disposer d'une instance de base de données en cours d'exécution. Assurez-vous qu'elle n'est pas en mode « maintenance » ou « setting up » (configuration en cours).
- Disposer d'au moins 1 utilisateur configuré (identifiant et mot de passe).
- Disposer d'au moins 1 IP autorisée. Il doit s'agir de l'IP qui accédera à votre base de données (votre ordinateur, votre serveur dédié, etc.). À des fins de dépannage uniquement, vous pouvez également ajouter l'IP « 0.0.0.0 » afin d'autoriser « toute » connexion. Retirez-la une fois vos tests terminés.
- Connaître les paramètres de connexion de votre instance de base de données : adresse de l'hôte, port, mode de sécurité.

Une fois prêt, vous pouvez tester la connexion via l'interface en ligne de commande officielle du SGBD, ou avec du code applicatif classique tel que Python, PHP, Java... Vous trouverez des exemples de connexion dans différents langages dans notre [dépôt d'exemples](https://github.com/ovh/public-cloud-databases-examples).

Si vous rencontrez toujours des problèmes de connectivité, veuillez contacter notre support.

### J'ai besoin de réinitialiser les identifiants de mon utilisateur

Si vous avez oublié les identifiants de votre utilisateur, ou si vous avez des préoccupations en matière de sécurité, vous pouvez modifier le mot de passe de votre utilisateur directement depuis l'espace client OVHcloud, dans la section « Users & Roles » (Utilisateurs et rôles). Cela déconnectera les connexions existantes établies par cet utilisateur.

### Mon instance de base de données manque d'espace de stockage

Chaque instance de base de données dispose d'un espace de stockage limité. Nous vous recommandons de surveiller en permanence votre espace de stockage restant.

Pour gérer les problèmes de stockage, veuillez consulter le guide [Gérer des situations de « Full Disk »](/guides/public-cloud/databases/handling-disk-full).

### Mes requêtes sont lentes

Les requêtes sont des opérations effectuées sur vos instances de base de données, telles que des opérations de LECTURE, d'ÉCRITURE ou de SUPPRESSION.

Les performances de ces requêtes dépendent de nombreux facteurs externes :

- Votre schéma de données. L'organisation de vos données a un impact fort sur vos performances.
- Le volume de données interrogé. Une requête sur 1 table de 1 000 lignes est différente d'une requête sur 20 tables d'1 million de lignes.
- La qualité de votre code applicatif.
- La performance de la gamme : chaque gamme possède ses propres caractéristiques matérielles. Plus vous disposez de RAM et de vCPU, plus les requêtes seront efficaces.
- L'usage intensif du service (par exemple, un trafic légitime dû à des opérations commerciales).
- Un incident sur l'infrastructure matérielle ou le réseau.

Pour diagnostiquer vos performances, la première étape consiste généralement à vérifier que le service n'est pas affecté, par exemple par une [tâche de travaux](https://www.status-ovhcloud.com/). Pour tester une gamme supérieure, vous pouvez dupliquer votre instance de base de données vers un modèle de gamme supérieure et retester les performances.

De manière générale, si vous constatez une lenteur ponctuelle, des compétences en administration de base de données et système sont nécessaires.

### Mes données sont corrompues

Si vos données sont corrompues, vous disposez de 2 options :

- Si vos données sont importantes, vous pouvez restaurer une sauvegarde où vos données sont valides. Vous devrez mener cette investigation par vous-même.
- Si vos données peuvent être supprimées, vous pouvez supprimer le service de base de données et en créer un nouveau, ou simplement suivre la documentation officielle du SGBD pour supprimer l'ensemble des données.
