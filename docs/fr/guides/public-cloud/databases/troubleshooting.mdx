## Objectif

Public Cloud Databases vous permet de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure de base de données et son maintien en conditions opérationnelles.
Chaque service s'appuie sur des systèmes de gestion de bases de données (SGBD) tiers, maintenus par des sociétés ou communautés tierces telles que la communauté PostgreSQL, Oracle, MongoDB, RedisLab, Apache Foundation et bien d'autres.

**Ce guide explique comment résoudre les problèmes courants.**

### Je ne parviens pas à me connecter à Public Cloud Databases

Si vous ne parvenez pas à vous connecter à Public Cloud Databases, veuillez vérifier les points suivants :

- **Votre instance de base de données est active et fonctionnelle :** lorsque vous créez une nouvelle instance de base de données, vous devez attendre quelques minutes avant que votre service ne soit prêt à l'emploi. Vous pouvez vérifier le statut de votre service dans l'espace client. Il doit être à l'état « running ». Notez que lorsque vous modifiez des instances de base de données, par exemple en ajoutant des nœuds ou en modifiant la version du SGBD, votre service peut passer de l'état « running » à l'état « updating ». Vous pouvez rencontrer des problèmes de connexion pendant cette période.
- **Au moins 1 utilisateur est créé :** veuillez vérifier que vous disposez d'au moins un utilisateur créé pour votre service, avec des rôles suffisants. Si vous n'êtes pas sûr du mot de passe, créez un nouvel utilisateur avec un mot de passe nouvellement généré.
- **Au moins 1 adresse IP est autorisée :** par défaut, une instance de base de données n'est pas accessible depuis l'extérieur. Vous devez indiquer, dans l'espace client, au moins une adresse IP de confiance (autorisée). Vous devez autoriser l'adresse IP depuis laquelle la demande de connexion sera initiée. Astuce : pour une courte période, vous pouvez essayer d'autoriser un joker d'adresse IP **0.0.0.0/0**. Cette règle **autorisera toute connexion IP**. Veuillez l'utiliser avec précaution.
- **La syntaxe correcte de l'URI de service est utilisée :** veillez à copier l'URI de service exacte fournie dans votre espace client afin d'éviter tout problème de syntaxe. Connectez-vous au port par défaut de chaque SGBD.  
- **Client et/ou framework de développement à jour :** chaque client de SGBD fournit une matrice de compatibilité pour les versions logicielles. Veillez à respecter les prérequis officiels du SGBD, tels que les versions de paquets Linux, les versions PHP ou Python, etc.

Pour vous accompagner dans votre parcours de connexion, nous détaillons les procédures exactes dans notre [documentation Public Cloud Database](/guides/public-cloud/databases/overview). N'hésitez pas à parcourir les guides pour plus de détails.

### Public Cloud Databases - mot de passe perdu

OVHcloud ne stocke pas les mots de passe pour Public Cloud Databases. Vous ne pouvez pas récupérer un mot de passe.
Si vous oubliez votre mot de passe, vous disposez de deux solutions :

- **Régénérer le mot de passe :** dans l'espace client, sélectionnez l'onglet <code className="action">Utilisateurs</code> de votre service de base de données. Pour l'utilisateur souhaité, sur le côté droit de la ligne du tableau, vous trouverez un bouton d'action. Sélectionnez <code className="action">Régénérer le mot de passe</code>. Une fois régénéré, le nouveau mot de passe s'affichera dans votre navigateur web. Veuillez le copier et le stocker en lieu sûr. Astuce : en procédant ainsi, TOUTES les connexions existantes établies avec cet utilisateur seront interrompues. Vous devrez modifier le mot de passe dans tous les scripts utilisant cet utilisateur.
- **Créer un nouvel utilisateur :** dans l'espace client, sélectionnez l'onglet <code className="action">Utilisateurs</code> de votre service de base de données. Créez un nouvel utilisateur avec les rôles souhaités. Un mot de passe sera généré et s'affichera dans votre navigateur web. Veuillez le copier et le stocker en lieu sûr.

Pour vous accompagner dans la gestion des utilisateurs, n'hésitez pas à consulter nos guides pour plus de détails dans la [documentation Public Cloud Database](/guides/public-cloud/databases/overview).

### Public Cloud Databases - manque d'espace de stockage

Nous vous recommandons de surveiller autant que possible les métriques de votre service Public Cloud Databases, en particulier l'espace de stockage.
Si votre espace de stockage devient insuffisant, OVHcloud va :

1. Envoyer une alerte à votre contact e-mail principal (NIC-Admin) lorsque 80 % de la capacité de stockage est atteinte.
2. Placer votre ou vos instances de base de données à l'état « DISK_FULL » et en mode lecture seule + suppression lorsque 95 % de la capacité de stockage est atteinte.
3. Remettre votre instance de base de données en mode lecture-écriture une fois la capacité de stockage repassée sous les 80 %.

Si vous atteignez les limites de capacité de stockage, vous disposez de deux options :

- **Passer à une flavor supérieure :** Public Cloud Databases est fourni avec un espace de stockage inclus pour chaque modèle de nœud. Selon le SGBD, vous pourrez peut-être changer de modèle de flavor pour un modèle supérieur, avec une capacité de stockage plus importante.
- **Nettoyer les données :** supprimez les données inutiles dans votre instance de base de données, ce qui vous permettra d'atteindre un niveau de capacité de stockage acceptable.

### Public Cloud Databases - lenteurs constatées

Plusieurs raisons peuvent entraîner un ralentissement d'une instance de base de données. Pour commencer le dépannage :

- **Vérifier le tableau de bord des métriques :** la première étape consiste à comprendre si la lenteur est ponctuelle ou périodique. De nombreuses métriques peuvent vous aider à déterminer si ce phénomène se produit chaque heure, chaque jour, ou de manière non cyclique.
- **Comparer les métriques à vos besoins :** si la lenteur constatée correspond à un niveau élevé de métriques, comme l'utilisation du CPU ou de la RAM, cela signifie que votre instance de base de données atteint ses performances maximales. Si vous atteignez les performances maximales, cela peut être lié à des opérations légitimes de votre part, ou à des dysfonctionnements de code. OVHcloud n'est pas responsable des scripts utilisés.
- **Vérifier les requêtes lentes :** les principaux SGBD vous permettent d'examiner les requêtes lentes, c'est-à-dire d'examiner les requêtes effectuées sur les bases de données qui prennent trop de temps. Réduire le temps des requêtes est toujours bénéfique pour les performances.
- **Vérifier les statuts de santé OVHcloud :** OVHcloud peut rencontrer des problèmes de réseau ou de bases de données. Nous les répertorions sur [https://www.status-ovhcloud.com/](https://www.status-ovhcloud.com/).

Si la lenteur persiste, veuillez contacter notre équipe support.

### Public Cloud Databases - panne ou redémarrage

**Une panne d'instance de base de données** peut survenir lorsque des couches inférieures (logicielles ou matérielles) ne fonctionnent pas dans des conditions optimales.

Selon la panne, l'utilisation de votre service peut être affectée par :

- une lenteur générale
- un redémarrage
- l'impossibilité de se connecter aux bases de données
- l'impossibilité de lire ou d'écrire des données

Pour dépanner une panne :

1. **Vérifier le statut de l'instance de base de données :** connectez-vous à votre espace client Public Cloud et explorez vos services de base de données. Vérifiez le statut. Le statut nominal est **Running** ;
2. **Vérifier les statuts de santé OVHcloud :** lorsque des pannes majeures surviennent, elles sont répertoriées sur [https://www.status-ovhcloud.com/](https://www.status-ovhcloud.com/).

**Un redémarrage d'instance de base de données** peut survenir lorsque :

- Une opération de maintenance majeure est planifiée. Vérifiez votre fenêtre de maintenance directement sur l'espace client Public Cloud ;
- Une modification du cluster est demandée. Selon le SGBD choisi et le plan de service, le redémarrage peut être nécessaire même si nous essayons de l'éviter autant que possible. Lorsqu'une modification est nécessaire, nous en informons les clients via l'espace client.
