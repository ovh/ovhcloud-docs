## Introduction

MongoDB offre la possibilité de contrôler comment et où les données sont lues et écrites au sein d'un environnement de base de données distribué.

[ReadPreference](https://www.mongodb.com/docs/manual/core/read-preference/) vous permet de spécifier depuis quel membre du replica set (primaire ou secondaire) vos opérations de lecture doivent être servies, en optimisant les performances, la cohérence ou la disponibilité en fonction des besoins de votre application.

Par défaut, la préférence de lecture de MongoDB est configurée pour lire depuis le nœud primaire. Cela garantit la lecture des données les plus récentes. Cependant, en configurant la préférence de lecture sur secondaire, vous pouvez répartir les opérations de lecture entre tous les nœuds secondaires, améliorant ainsi l'évolutivité de la lecture et réduisant la charge sur le nœud primaire. Cela peut améliorer les performances et réduire la latence, en particulier dans les déploiements géographiquement répartis.

[WriteConcern](https://www.mongodb.com/docs/manual/reference/write-concern/) définit le niveau d'accusé de réception requis de la base de données lors d'une opération d'écriture, vous permettant d'équilibrer durabilité des données et performance d'écriture. Ensemble, ces paramètres offrent un contrôle flexible et précis sur la cohérence, la disponibilité et la performance des données dans votre déploiement MongoDB.

Le writeConcern de MongoDB vise à offrir une flexibilité dans l'équilibre entre durabilité des données et performance d'écriture. Le writeConcern **w=1** signifie que l'opération d'écriture est accusée réception uniquement par le nœud primaire, offrant une latence plus faible et un débit plus élevé, adapté aux cas d'usage où la performance est essentielle et où une perte de données occasionnelle est acceptable. À l'inverse, le writeConcern **majority**, qui est la valeur par défaut, garantit que l'écriture est accusée réception par la majorité des membres du replica set, offrant une durabilité et une cohérence des données plus élevées, idéal pour les applications où l'intégrité et la fiabilité des données sont primordiales, telles que les transactions financières ou les systèmes de données critiques.

## ReadPreference

[ReadPreference](https://www.mongodb.com/docs/manual/core/read-preference/) contrôle la façon dont les clients MongoDB dirigent les opérations de lecture vers les membres d'un replica set. Il détermine quel membre du replica set sera utilisé pour les opérations de lecture. Voici les différents types de ReadPreference :

1. **primary** : mode par défaut. Toutes les opérations de lecture sont dirigées vers le nœud primaire.
2. **primaryPreferred** : lit depuis le nœud primaire si disponible, sinon depuis les nœuds secondaires.
3. **secondary** : toutes les opérations de lecture sont dirigées vers les nœuds secondaires.
4. **secondaryPreferred** : lit depuis les nœuds secondaires si disponibles, sinon depuis le nœud primaire.
5. **nearest** : lit depuis le membre (primaire ou secondaire) présentant la latence réseau la plus faible.

### Configuration via la chaîne de connexion

Vous pouvez spécifier la préférence de lecture dans la chaîne de connexion à l'aide du paramètre `readPreference`.

Exemple :

```javascript
mongodb://username:password@host:port/dbname?readPreference=secondary
```

### Configuration pour une opération spécifique

Vous pouvez également définir la préférence de lecture de manière programmatique pour une opération spécifique.

Exemple en Python (PyMongo) :

```python
document = db.collection.find_one({"key": "value"}, read_preference=ReadPreference.NEAREST)
```

## WriteConcern

[WriteConcern](https://www.mongodb.com/docs/manual/reference/write-concern/) décrit le niveau d'accusé de réception demandé à MongoDB pour les opérations d'écriture. Il garantit la durabilité et la cohérence des données en spécifiant combien de membres du replica set doivent accuser réception de l'écriture.

Voici les principales options de WriteConcern :

1. **w** : spécifie le nombre de membres du replica set devant accuser réception de l'écriture.
      - `0` : aucun accusé de réception.
      - `1` : accusé de réception du nœud primaire uniquement.
      - `majority` : accusé de réception de la majorité des membres du replica set.
      - Un nombre supérieur à 1 : accusé de réception du nombre de membres spécifié.
2. **wtimeout** : spécifie une limite de temps (en millisecondes) pour l'accusé de réception du writeConcern.
3. **j** : si la valeur est true, attend que l'opération d'écriture soit validée dans le journal.

### Configuration via la chaîne de connexion

Vous pouvez spécifier le writeConcern dans la chaîne de connexion à l'aide des paramètres `w`, `wtimeout` et `journal`.

Exemple :

```javascript
mongodb://username:password@host:port/dbname?w=majority&wtimeoutMS=5000&journal=true
```

### Configuration pour une opération spécifique

Vous pouvez définir le writeConcern pour des opérations spécifiques plutôt que globalement.

```python
# Specific write operation with WriteConcern
result = db.collection.with_options(write_concern=WriteConcern("majority")).insert_one({"key": "value"})
```
