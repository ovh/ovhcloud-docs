## Objectif

Le RACI ci-dessous détaille le partage des responsabilités entre OVHcloud et le client pour le service Managed Rancher Service. Ce modèle peut aider le client à utiliser le service Managed Rancher Service au mieux.

| Rôles |
| --- |
|R : Est en charge de la Réalisation du processus|
|A : Est Approbateur de la réalisation du processus|
|C : Est Consulté pendant le processus|
|I : est Informé des résultats du processus|

### 1. Avant la souscription

#### 1.1. Spécifier le service en fonction des besoins

| **Activité** | **Client** | **OVHcloud** |
| --- | --- | --- |
| Se renseigner sur les fonctionnalités et les limites du service, telles que décrites dans la documentation OVHcloud | RA | CI |
| Apprendre à utiliser les conteneurs et Kubernetes | RA |  |
| Créer un projet Public Cloud | RA | I |
| Choisir la localisation du service | RA | I |
| Choisir la formule adaptée aux besoins métier (édition OVHcloud ou Standard) | RA | I |

### 2. Mise à disposition du service

#### 2.1. Installer le service

| **Activité** | **Client** | **OVHcloud** |
| --- | --- | --- |
| Produire, acheminer, livrer et maintenir les logiciels sous-jacents, les machines physiques et les bâtiments d’hébergement du control plane Rancher et de ses composants associés |  | RA |
| Acheter et détenir les droits d’utilisation des logiciels fournis par OVHcloud |  | RA |

#### 2.2. Modèle de réversibilité

| **Activité** | **Client** | **OVHcloud** |
| --- | --- | --- |
| Utiliser la documentation native de Rancher et Kubernetes pour exporter les données et la configuration réversibles | RA |  |

#### 2.3. Installation du SI client

| **Activité** | **Client** | **OVHcloud** |
| --- | --- | --- |
| Concevoir des applications modernes et/ou moderniser les workloads et l’architecture logicielle pour les rendre compatibles avec Kubernetes | RA |  |

### 3. Utilisation du service

#### 3.1. Opérations

##### **3.1.1. Opérations quotidiennes**

| **Activité** | **Client** | **OVHcloud** |
| --- | --- | --- |
| Mobiliser les ressources de calcul et de stockage adéquates pour délivrer le service (control plane Rancher) |  | RA |
| Décider de faire évoluer la formule du service existant en fonction des besoins métier | RA | I |
| Gérer l’accessibilité et le bon fonctionnement du Managed Rancher Service | RA | I |

##### **3.1.2. Gestion des accès**

| **Activité** | **Client** | **OVHcloud** |
| --- | --- | --- |
| Gérer les accès à l’espace client OVHcloud (Control Panel) | RA | I |
| Gérer les accès aux interfaces de gestion spécifiques au service (interface Rancher, API, etc.) | RA | I |
| Gérer les accès physiques des équipes OVHcloud aux infrastructures |  | RA |
| Gérer les accès logiques des équipes OVHcloud aux infrastructures |  | RA |

##### **3.1.3. Monitoring**

| **Activité** | **Client** | **OVHcloud** |
| --- | --- | --- |
| Surveiller le bon fonctionnement des dispositifs physiques (utilities) supportant le service Managed Rancher |  | RA |
| Surveiller le bon fonctionnement des dispositifs virtuels (utilities) supportant le service Managed Rancher | I | RA |
| Traiter et prendre en charge les alertes émises par les dispositifs managés de l’infrastructure du Managed Rancher Service | I | RA |
| Maintenir et surveiller les logs générés par le service Managed Rancher sur l’infrastructure de gestion |  | RA |
| Conserver les logs du service Managed Rancher mis à disposition dans l’interface Rancher ou via l’API | RA |  |
| Fournir et surveiller le bon fonctionnement des dispositifs physiques et virtuels (utilities) utilisés dans les clusters downstream managés par le Managed Rancher Service | RA |  |

##### **3.1.4. Stockage**

| **Activité** | **Client** | **OVHcloud** |
| --- | --- | --- |
| Gérer le contenu hébergé sur le Managed Rancher Service | RA | I |
| Assurer la continuité et la pérennité des données | RA |  |
| Assurer la maintenance du stockage et des dispositifs du control plane Rancher |  | RA |

##### **3.1.5. Connectivité**

| **Activité** | **Client** | **OVHcloud** |
| --- | --- | --- |
| Exploiter les systèmes de gestion réseau automatisés pour le control plane (architecture, mise en œuvre, maintenance logicielle et matérielle des réseaux publics et privés déployés) | I | RA |
| Fournir et maintenir un nom de domaine pour le service | I | RA |

##### **3.1.6. Gestion**

| **Activité** | **Client** | **OVHcloud** |
| --- | --- | --- |
| Fournir l’inventaire du service utilisé | I | RA |
| Gérer les risques sur les composants managés du service Managed Rancher |  | RA |
| Maintenir le service en conditions opérationnelles et de sécurité |  | RA |
| Gérer les clusters downstream (versions, dimensionnement, etc.) | RA | I |

##### **3.1.7. Continuité d’activité**

| **Activité** | **Client** | **OVHcloud** |
| --- | --- | --- |
| Gérer les systèmes de gestion automatisés et la disponibilité du control plane | I | RA |
| Maintenir un plan de continuité d’activité et de reprise après sinistre à la fois sur le control plane et sur les clusters downstream | RA | I |

#### 3.2. Gestion des évènements

##### **3.2.1. Incidents**

| **Activité** | **Client** | **OVHcloud** |
| --- | --- | --- |
| Notifier les incidents au sein de la configuration Rancher | RA | I |
| Intervenir sur les incidents affectant le Managed Rancher Control Plane | I | RA |

#### **3.2.2. Changements**

| **Activité** | **Client** | **OVHcloud** |
| --- | --- | --- |
| Se conformer à la politique de cycle de vie (Lifecycle Policy) du service | RA |  |
| Déployer les correctifs et mettre à jour les logiciels et systèmes d’information hébergeant le control plane Public Cloud Managed Rancher | I | RA |
| Déployer les correctifs, mettre à jour et configurer le système d’information géré par le service Public Cloud Managed Rancher | RA |  |
| Réaliser des interventions préventives sur les éléments du control plane Public Cloud Managed Rancher | I | RA |

### 4. Réversibilité

#### 4.1. Modèle de réversibilité
