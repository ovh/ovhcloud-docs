Ce tutoriel vous guide dans l'installation de [WordPress](https://wordpress.org/) sur votre OVHcloud Managed Kubernetes Service.

## Avant de commencer

Ce tutoriel suppose que vous disposez déjà d'un cluster OVHcloud Managed Kubernetes fonctionnel, ainsi que de connaissances de base sur son utilisation. Pour en savoir plus sur ces sujets, consultez le [guide de démarrage rapide OVHcloud Managed Kubernetes Service](/guides/public-cloud/containers-orchestration/managed-kubernetes/deploy-hello-world).

Vous devez également avoir [Helm](https://docs.helm.sh/) installé sur votre poste de travail et sur votre cluster ; reportez-vous au tutoriel [Comment installer Helm sur OVHcloud Managed Kubernetes Service](/guides/public-cloud/containers-orchestration/managed-kubernetes/install-helm).

## Prérequis

L'équipe OVHcloud Managed Kubernetes Service travaille sur un correctif qui sera publié début 2022. En attendant, veuillez supprimer la storage class par défaut et installer la nouvelle.

- Supprimez la `StorageClass` concernée que vous utilisez par défaut.

```bash
kubectl delete storageclasses.storage.k8s.io csi-cinder-high-speed
```

Cela supprimera la `StorageClass` existante :

```console
$ kubectl delete storageclasses.storage.k8s.io csi-cinder-high-speed
storageclass.storage.k8s.io "csi-cinder-high-speed" deleted
```

- Créez une nouvelle `StorageClass` intégrant le correctif requis.

```bash
kubectl apply -f https://raw.githubusercontent.com/ovh/docs/develop/pages/public_cloud/containers_orchestration/managed_kubernetes/fix-persistent-volumes-permissions/files/fixed-cinder-high-speed-storage-class.yaml
```

Cela applique le manifeste YAML `StorageClass` corrigé :

```console
$ kubectl apply -f https://raw.githubusercontent.com/ovh/docs/develop/pages/public_cloud/containers_orchestration/managed_kubernetes/fix-persistent-volumes-permissions/files/fixed-cinder-high-speed-storage-class.yaml
storageclass.storage.k8s.io/csi-cinder-high-speed created
```

Si vous avez déjà installé une version précédente du chart Helm WordPress de Bitnami, suivez le guide étape par étape ci-dessous.

- Supprimez le chart Helm concerné.

Par exemple, avec le chart Helm `bitnami/wordpress`, concerné par ce comportement :

```bash
helm uninstall my-first-k8s-wordpress
```

Et n'oubliez pas de vérifier que les `PersistentVolumeClaim` (PVC) et `PersistentVolume` (PV) concernés ont bien été supprimés avant de réinstaller le chart Helm :

```bash
kubectl get persistentvolumeclaims -A | grep wordpress
kubectl get persistentvolumes 
```

Si un `PersistentVolumeClaim` est listé, supprimez-le (le `PersistentVolume` sera supprimé automatiquement).

```bash
kubectl delete pvc data-my-first-k8s-wordpress-mariadb-0
```

La commande supprime le `PersistentVolumeClaim` restant :

```console
$ kubectl delete pvc data-my-first-k8s-wordpress-mariadb-0
persistentvolumeclaim "data-my-first-k8s-wordpress-mariadb-0" deleted
```

## Installer le chart Helm WordPress

Pour ce tutoriel, nous utilisons le [chart Helm WordPress](https://github.com/bitnami/charts/tree/master/bitnami/wordpress) disponible sur le [dépôt Bitnami](https://github.com/bitnami/charts/). Le chart est entièrement configurable, mais nous utilisons ici la configuration par défaut, avec seulement l'ensemble minimal de personnalisations nécessaires pour qu'il fonctionne correctement sur OVHcloud Managed Kubernetes Service.

:::info
### Personnaliser votre installation

Vous souhaitez peut-être utiliser un nom d'utilisateur différent, définir votre propre mot de passe, ou choisir une base de données externe plutôt que de déployer le conteneur MariaDB...

Pour personnaliser votre installation sans renoncer à la simplicité de Helm et du chart Helm WordPress, vous pouvez simplement définir certains des [paramètres configurables du chart WordPress](https://github.com/helm/charts/tree/master/stable/wordpress#configuration), puis les ajouter à votre commande `helm install` avec l'option `--set` (`--set param1=value1,param2=value2`).
:::


```
helm install my-first-k8s-wordpress bitnami/wordpress --set allowOverrideNone=true
```

Cela installera les éléments nécessaires :

- un `Pod` MariaDB pour la base de données ;
- un `Pod` WordPress pour le serveur web avec le code PHP de WordPress ;
- l'allocation des volumes persistants (`PersistentVolumeClaim` et `PersistentVolume`) ;
- et l'initialisation des `Services`.

À la fin, les paramètres de connexion de votre nouveau WordPress vous seront fournis :

```console
$ helm install my-first-k8s-wordpress bitnami/wordpress --set allowOverrideNone=true
NAME: my-first-k8s-wordpress
LAST DEPLOYED: Fri Dec 17 15:42:22 2021
NAMESPACE: default
STATUS: deployed
REVISION: 1
TEST SUITE: None
NOTES:
CHART NAME: wordpress
CHART VERSION: 12.2.5
APP VERSION: 5.8.2

** Please be patient while the chart is being deployed **

Your WordPress site can be accessed through the following DNS name from within your cluster:

    my-first-k8s-wordpress.default.svc.cluster.local (port 80)

To access your WordPress site from outside the cluster follow the steps below:

1. Get the WordPress URL by running these commands:

  NOTE: It may take a few minutes for the LoadBalancer IP to be available.
        Watch the status with: 'kubectl get svc --namespace default -w my-first-k8s-wordpress'

   export SERVICE_IP=$(kubectl get svc --namespace default my-first-k8s-wordpress --template "{{ range (index .status.loadBalancer.ingress 0) }}{{.}}{{ end }}")
   echo "WordPress URL: http://$SERVICE_IP/"
   echo "WordPress Admin URL: http://$SERVICE_IP/admin"

2. Open a browser and access WordPress using the obtained URL.

3. Login with the following credentials below to see your blog:

  echo Username: user
  echo Password: $(kubectl get secret --namespace default my-first-k8s-wordpress -o jsonpath="{.data.wordpress-password}" | base64 --decode)
```

Comme l'indiquent les instructions, vous devrez attendre quelques instants pour obtenir l'URL du `LoadBalancer`.
Vous pouvez vérifier si le `LoadBalancer` est prêt à l'aide de la commande suivante :

```
kubectl get svc --namespace default -w my-first-k8s-wordpress
```

Après quelques minutes, vous obtiendrez l'URL du `LoadBalancer` :

```console
$ kubectl get svc --namespace default -w my-first-k8s-wordpress
NAME                     TYPE           CLUSTER-IP    EXTERNAL-IP     PORT(S)                      AGE
my-first-k8s-wordpress   LoadBalancer   10.3.83.253   <pending>      80:32296/TCP,443:31838/TCP   2m13s
my-first-k8s-wordpress   LoadBalancer   10.3.83.253   51.178.69.190   80:32296/TCP,443:31838/TCP   2m13s
```

Vous pouvez ensuite suivre les instructions pour obtenir l'URL d'administration :

```console
$ export SERVICE_IP=$(kubectl get svc --namespace default my-first-k8s-wordpress --template "{{ range (index .status.loadBalancer.ingress 0) }}{{.}}{{ end }}")

$ echo "WordPress URL: http://$SERVICE_IP/"
WordPress URL: http://51.178.69.190/

$ echo "WordPress Admin URL: http://$SERVICE_IP/admin"
WordPress Admin URL: http://51.178.69.190/admin
```

Copiez-collez l'URL WordPress dans votre navigateur pour découvrir votre nouveau blog en fonctionnement :

## Suppression (nettoyage)

Pour nettoyer votre cluster, utilisez simplement Helm afin de supprimer votre blog WordPress.

```bash
helm uninstall my-first-k8s-wordpress
```

Cela supprimera votre WordPress et les ressources associées de votre cluster :

```console
$ helm uninstall my-first-k8s-wordpress
release "my-first-k8s-wordpress" uninstalled
```

Vous devez également supprimer manuellement le `PersistentVolumeClaim` restant, pour le moment :

```bash
kubectl delete pvc data-my-first-k8s-wordpress-mariadb-0
```

Cela supprimera le `PersistentVolumeClaim` installé par le chart Helm WordPress de Bitnami :

```console
$ kubectl delete pvc data-my-first-k8s-wordpress-mariadb-0
persistentvolumeclaim "data-my-first-k8s-wordpress-mariadb-0" deleted
```
