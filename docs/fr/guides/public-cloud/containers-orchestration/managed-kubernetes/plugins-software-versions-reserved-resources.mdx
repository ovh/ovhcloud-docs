Nous listons ici quelques détails sur l'espace client, les plugins (CNI, CRI, CSI...) et les versions logicielles que nous utilisons, ainsi que les ressources que nous réservons sur chaque nœud.

## Versions de Kubernetes

Actuellement, nous prenons en charge les versions Kubernetes suivantes :

* `1.31`
* `1.32`
* `1.33`
* `1.34`
* `1.35`

Si vous utilisez un Managed Kubernetes Service avec une version plus ancienne, nous vous encourageons fortement à utiliser la [fonctionnalité de mise à niveau de version](/guides/public-cloud/containers-orchestration/managed-kubernetes/upgrading-version) pour bénéficier du support officiel de votre cluster.

Vous trouverez plus de détails sur notre [politique de fin de commercialisation, de fin de service et de fin de vie dans la section dédiée](/guides/public-cloud/containers-orchestration/managed-kubernetes/eos-eol-policies).

Nous suivons de près les versions de Kubernetes, et de nouvelles versions seront régulièrement disponibles.

## Versions de l'OS, du kernel et de Docker

La version de l'OS, du kernel et du daemon Docker sur vos nœuds sera régulièrement mise à jour. Les versions actuelles sont :

* OS : Ubuntu 22.04 LTS

Les versions installées dépendent de la version de Kubernetes :

## Politiques activées

* [Network policies](https://kubernetes.io/docs/concepts/services-networking/network-policies/)
* [Resource quotas](https://kubernetes.io/docs/concepts/policy/resource-quotas/)
* [Limit range](https://kubernetes.io/docs/concepts/policy/limit-range/)

Modes d'autorisation :

* [Node](https://kubernetes.io/docs/reference/access-authn-authz/node/) : autorise les requêtes API effectuées par les Kubelets.
* [RBAC](https://kubernetes.io/docs/reference/access-authn-authz/rbac/) : le contrôle d'accès basé sur les rôles (Role-Based Access Control) est une méthode de régulation de l'accès aux ressources informatiques ou réseau en fonction des rôles des différents utilisateurs au sein d'une organisation.

Feature gates :

* `TTLAfterFinished` : permet à un contrôleur TTL de nettoyer les ressources après la fin de leur exécution (activé par défaut à partir de `v1.23`, paramètre supprimé dans `v1.25`).

### Kubelet

* `protect-kernel-defaults` : empêche les paramètres kernel ajustés de remplacer les valeurs par défaut des paramètres kernel du kubelet.

## Ressources réservées

Chaque worker node dispose d'une certaine quantité de CPU, de RAM et de stockage réservée aux composants Kubernetes.
Ces quotas réservés peuvent évoluer à l'avenir ; cette page sera mise à jour en conséquence.

Pour garantir la disponibilité du nœud d'un client, la quantité de ressources réservées dépend de la flavor de l'instance.

* La réservation de **CPU** est définie par la formule suivante :
    > 15 % d'1 CPU + 0,5 % de l'ensemble des cœurs CPU

* La réservation de **RAM** est une constante :
    > 1590 Mo

* La réservation de **stockage** est définie par la formule suivante :
    > log10(stockage total en Go) * 10 + 10 % du stockage total
