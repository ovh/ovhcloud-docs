## Objectif

Ce tutoriel explique comment installer [Traefik](https://github.com/traefik/traefik) en tant qu'Ingress Controller sur votre OVHcloud Managed Kubernetes Service.

## Prérequis

- Disposer d'un cluster OVHcloud Managed Kubernetes fonctionnel et de connaissances de base sur son utilisation (consultez le [guide de démarrage rapide OVHcloud Managed Kubernetes Service](/guides/public-cloud/containers-orchestration/managed-kubernetes/deploy-hello-world))
- Disposer de [Helm](https://helm.sh/fr/docs/intro/install/) installé sur votre poste de travail (consultez le tutoriel « [Installer et utiliser Helm sur OVHcloud Managed Kubernetes](/guides/public-cloud/containers-orchestration/managed-kubernetes/install-helm) »)

## Ressources Ingress et Traefik

Dans Kubernetes, une ressource Ingress permet d'accéder à vos Services depuis l'extérieur du cluster. L'objectif est d'utiliser un seul Load Balancer pour l'Ingress Controller au lieu de créer un Load Balancer par Service.

![Ingress Kubernetes](/images/public-cloud/containers-orchestration/managed-kubernetes/installing-nginx-ingress/ingress.png)

Une Ingress est mise en œuvre par un Ingress Controller tiers, qui surveille l'API Kubernetes pour détecter les ressources Ingress nouvelles ou mises à jour.

Dans ce tutoriel, vous allez installer Traefik Proxy. Traefik achemine les requêtes entrantes vers les Services backend selon les règles définies dans vos ressources Ingress.

Le déploiement de Traefik crée également un Load Balancer OVHcloud Public Cloud. Ce Load Balancer achemine le trafic externe vers Traefik, qui transmet ensuite chaque requête au Service backend approprié.

:::warning
La communauté Kubernetes a [mis fin au projet ingress-nginx en mars 2026](https://kubernetes.io/blog/2025/11/11/ingress-nginx-retirement/). Le projet ne reçoit plus de nouvelles versions, de correctifs ni de mises à jour de sécurité, et ne doit plus être déployé pour de nouvelles charges de travail.

Ce guide présentait auparavant ingress-nginx et utilise désormais Traefik. Si vous utilisez déjà ingress-nginx, suivez le [guide de migration vers Traefik](https://doc.traefik.io/traefik/migrate/nginx-to-traefik/), passez en revue les annotations propres à votre Ingress Controller et testez la migration avant de supprimer votre Ingress Controller actuel.
:::

## En pratique

### Installer le chart Helm Traefik

Pour ce tutoriel, nous utilisons le [chart Helm officiel de Traefik](https://github.com/traefik/traefik-helm-chart) avec sa configuration par défaut.

```bash
helm repo add traefik https://traefik.github.io/charts
helm repo update traefik
helm upgrade --install traefik traefik/traefik \
  --version 41.0.2 \
  --namespace traefik \
  --create-namespace \
  --wait --timeout 3m
```

Vérifiez que le Deployment Traefik est disponible :

```bash
kubectl rollout status deployment/traefik -n traefik
```

La création du `LoadBalancer` est asynchrone et peut prendre plusieurs minutes. Surveillez le Service jusqu'à ce qu'une adresse apparaisse dans la colonne `EXTERNAL-IP` :

```bash
kubectl get service traefik -n traefik --watch
```

Appuyez sur `Ctrl+C` pour arrêter la surveillance du Service, puis récupérez son adresse IP externe :

```bash
export INGRESS_URL=$(kubectl get service traefik -n traefik -o jsonpath='{.status.loadBalancer.ingress[0].ip}')
echo "Ingress URL: http://$INGRESS_URL/"
```

### Tester Traefik avec une Ingress

Pour tester Traefik, vous pouvez par exemple [installer WordPress](/guides/public-cloud/containers-orchestration/managed-kubernetes/install-wordpress) sur votre cluster. Créez ensuite un fichier `ingress.yml` avec le contenu suivant :

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: ingress
  namespace: default
spec:
  ingressClassName: traefik
  rules:
    - http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: [YOUR_WORDPRESS_SERVICE_NAME]
                port:
                  number: 80
```

:::info
Remplacez `[YOUR_WORDPRESS_SERVICE_NAME]` par le nom de votre Service WordPress.
:::

Appliquez le fichier :

```bash
kubectl apply -f ingress.yml
```

Vérifiez que l'Ingress dispose d'une adresse :

```bash
kubectl get ingress ingress
```

Ouvrez `http://$INGRESS_URL/` dans votre navigateur pour afficher votre site WordPress :
