## Objectif

Dans ce tutoriel, nous allons vous montrer comment déployer vos applications sur des `Nodes` et des `Nodes Pools` spécifiques, à l'aide des concepts Kubernetes `labels` et `NodeAffinity`, sur votre OVHcloud Managed Kubernetes Service.

L'exemple choisi ici tire parti d'une spécificité de facturation OVHcloud : utiliser la facturation mensuelle pour les nœuds que vous prévoyez également de conserver sur le long terme peut réduire vos coûts Kubernetes jusqu'à 50 %. Nous constatons que des clients ayant des workloads variés créent un premier pool de nœuds en facturation mensuelle pour couvrir leurs besoins de calcul de long terme, et ajoutent de l'élasticité au cluster avec un second pool de nœuds utilisant l'autoscaling et la facturation horaire.

Nous allons :

- créer un cluster Managed Kubernetes
- créer un pool de nœuds avec 3 nœuds et un mode de facturation « mensuel »
- créer un autre pool de nœuds avec l'autoscaling activé (0 nœud minimum et 10 maximum), en mode de facturation « horaire »
- déployer une application sur un pool de nœuds (et des nœuds) spécifique

## En pratique

### Création du cluster

Accédez à l'interface d'administration de vos clusters OVHcloud Managed Kubernetes en cliquant sur <code className="action">Managed Kubernetes Service</code> dans le menu de gauche, puis cliquez sur <code className="action">Create a cluster</code>.

<img className="thumbnail" alt="Créer un cluster" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/creating-a-cluster1.png" loading="lazy" />

Ou, si vous avez déjà un cluster, l'interface est légèrement différente : vous devez cliquer sur le bouton <code className="action">Create a Kubernetes cluster</code> :

<img className="thumbnail" alt="Créer un cluster" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/creating-a-cluster1-bis.png" loading="lazy" />

Sélectionnez un emplacement pour votre nouveau cluster.

<img className="thumbnail" alt="Sélectionner un emplacement" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/creating-a-cluster2.png" loading="lazy" />

Choisissez la version mineure de Kubernetes.

:::info
Nous recommandons d'utiliser systématiquement la dernière version stable.
Consultez notre page [Fin de vie / fin de support](/guides/public-cloud/containers-orchestration/managed-kubernetes/eos-eol-policies) pour comprendre notre politique de versions.

:::


<img className="thumbnail" alt="Choisir la version mineure de Kubernetes" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/creating-a-cluster3-bis.png" loading="lazy" />

Vous pouvez désormais choisir d'intégrer votre cluster Kubernetes à un réseau privé à l'aide du vRack OVHcloud. Pour plus d'informations sur cette option, consultez notre guide [Utiliser le vRack](/guides/public-cloud/containers-orchestration/managed-kubernetes/using-vrack).

<img className="thumbnail" alt="Choisir un réseau privé pour ce cluster" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/creating-a-cluster4-bis.png" loading="lazy" />

Pour ce tutoriel, nous allons configurer deux pools de nœuds différents.

Rappel : un pool de nœuds est un groupe de nœuds partageant la même configuration, ce qui vous offre une grande flexibilité dans la gestion de votre cluster.

<img className="thumbnail" alt="Pool de nœuds" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/nodepool.png" loading="lazy" />

Pour notre premier pool de nœuds, choisissez une flavor, « B2-7 » par exemple.

<img className="thumbnail" alt="Pool de nœuds" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/creating-a-cluster5.png" loading="lazy" />

À l'étape suivante, définissez la taille du pool de nœuds par défaut.

<img className="thumbnail" alt="Pool de nœuds par défaut" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/creating-a-cluster6-bis.png" loading="lazy" />

À l'étape suivante, choisissez le mode de facturation `Monthly`.

<img className="thumbnail" alt="Choisir le mode de facturation" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/creating-a-cluster8-bis.png" loading="lazy" />

Enfin, indiquez un nom pour votre cluster et cliquez sur le bouton <code className="action">Send</code>.

<img className="thumbnail" alt="Nommer le cluster" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/creating-a-cluster9.png" loading="lazy" />

### Création du second pool de nœuds

Votre cluster Kubernetes est maintenant opérationnel. Vous pouvez le voir dans votre espace client OVHcloud.

<img className="thumbnail" alt="Sélectionner votre cluster" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/create-a-nodepool-1.png" loading="lazy" />

Cliquez sur votre cluster, puis sur l'onglet <code className="action">Pools de nœuds</code>.

Nous allons créer notre second pool de nœuds.
Cliquez sur le bouton <code className="action">Ajouter un pool de nœuds</code>.

Indiquez ensuite un nom pour votre second pool de nœuds, `hourly` par exemple.

<img className="thumbnail" alt="Nommer votre second pool de nœuds" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/create-a-nodepool-2.png" loading="lazy" />

Sélectionnez une flavor pour votre nouveau pool de nœuds ; nous pouvons choisir « B2-7 » comme pour notre autre pool de nœuds.

<img className="thumbnail" alt="Sélectionner une flavor pour votre second pool de nœuds" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/create-a-nodepool-3.png" loading="lazy" />

À l'étape suivante, définissez la taille de notre second pool de nœuds.
Cette fois, nous pouvons activer la fonctionnalité <code className="action">Autoscaling</code>.
Définissez dans ce cas la taille minimale et maximale du pool, par exemple 0 en minimum et 10 en maximum.

:::info
En activant l'anti-affinité, les nœuds actuels et futurs seront lancés sur des hyperviseurs (serveurs physiques) différents, garantissant une meilleure tolérance aux pannes.

:::


<img className="thumbnail" alt="Définir une taille et l'autoscaling pour votre second pool de nœuds" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/create-a-nodepool-4.png" loading="lazy" />

Puis choisissez le mode de facturation `Hourly` pour ce second pool de nœuds.

<img className="thumbnail" alt="Mode de facturation" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/create-a-nodepool-5.png" loading="lazy" />

La création du pool de nœuds est désormais en cours. Il devrait être disponible en quelques minutes dans votre espace client OVHcloud.

Le second pool de nœuds sera d'abord au statut `Installing`.
Attendez que son statut passe à `OK`.

<img className="thumbnail" alt="Statut Installing" src="/images/public-cloud/containers-orchestration/managed-kubernetes/label-nodeaffinity-node-pools/create-a-nodepool-6.png" loading="lazy" />

### Déploiement de notre application

Le moment est venu de découvrir la puissance des concepts Kubernetes `labels` et `NodeAffinity`.

Nous avons un pool de nœuds en facturation « mensuelle » et un autre en facturation « horaire ». L'objectif de disposer de ces deux pools de nœuds est de pouvoir séparer nos besoins selon les types d'applications.

Afin de déployer notre application sur des nœuds spécifiques, nous devons connaître le label du pool de nœuds cible.

Il faut savoir que les nœuds créés par Kubernetes portent dans leur label le nom du pool de nœuds. Grâce à cela, vous pouvez demander à Kubernetes de déployer les applications dans le pool de nœuds souhaité.

Affichons les labels de nos nœuds en cours d'exécution :

```bash
$ kubectl get node --show-labels
```

Comme vous pouvez peut-être le constater, nos nœuds en cours d'exécution portent le label `nodepool=nodepool-cc40f90c-effb-4945-b7b9-05073725d62d`.
Le format du label est : `nodepool=<name of the nodepool>`.

Le moment est venu de déployer une application, uniquement sur notre pool de nœuds `hourly`, et d'observer le comportement de l'AutoScaling.

Créez un fichier `deployment.yaml` avec le contenu suivant :

```yaml
apiVersion: v1
kind: Service
metadata:
  name: hello-world
  labels:
    app: hello-world
spec:
  type: LoadBalancer
  ports:
  - port: 80
    targetPort: 80
    protocol: TCP
    name: http
  selector:
    app: hello-world
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hello-world-deployment
  labels:
    app: hello-world
spec:
  replicas: 1
  selector:
    matchLabels:
      app: hello-world
  template:
    metadata:
      labels:
        app: hello-world
    spec:
      containers:
      - name: hello-world
        image: ovhplatform/hello
        ports:
        - containerPort: 80
      affinity:
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
            - matchExpressions:
              - key: nodepool
                operator: In
                values:
                - hourly
```

```bash
$ kubectl apply -f deployment.yaml
service/hello-world created
deployment.apps/hello-world-deployment created
```

Lorsque vous appliquez ce manifeste YAML, un Pod sera d'abord à l'état `Pending`. Un nouveau nœud sera créé. Une fois ce nouveau nœud créé avec succès, le Pod sera démarré sur ce nœud.

```bash
$ kubectl get pod -w
NAME                                      READY   STATUS    RESTARTS   AGE
hello-world-deployment-585c6cfcd8-kntp9   0/1     Pending   0          12s
hello-world-deployment-585c6cfcd8-kntp9   0/1     Pending   0          3m3s
hello-world-deployment-585c6cfcd8-kntp9   0/1     ContainerCreating   0          3m29s
hello-world-deployment-585c6cfcd8-kntp9   0/1     ContainerCreating   0          3m41s
hello-world-deployment-585c6cfcd8-kntp9   1/1     Running             0          3m45s
```

Vous devez attendre plusieurs minutes afin d'obtenir un nouveau nœud correspondant à vos critères.

```bash
$ kubectl get node
NAME                                         STATUS   ROLES    AGE   VERSION
hourly-node-d4f9d7                           Ready    <none>   18s   v1.34.0
nodepool-cc40f90c-effb-4945-b7-node-23e81b   Ready    <none>   21h   v1.34.0
nodepool-cc40f90c-effb-4945-b7-node-4bd23f   Ready    <none>   21h   v1.34.0
nodepool-cc40f90c-effb-4945-b7-node-ef121e   Ready    <none>   21h   v1.34.0
```

Et vous pouvez vérifier sur quel nœud notre application est en cours d'exécution :

```bash
$ kubectl get pod -o wide
NAME                                      READY   STATUS    RESTARTS   AGE   IP         NODE                 NOMINATED NODE   READINESS GATES
hello-world-deployment-585c6cfcd8-kntp9   1/1     Running   0          13m   10.2.8.2   hourly-node-d4f9d7   <none>           <none>
```

Grâce à cette fonctionnalité, vous pouvez choisir et contrôler où vous souhaitez déployer vos applications.

Notez qu'un label donné peut être appliqué à plusieurs pools de nœuds et/ou à des nœuds spécifiques uniquement si cela a un sens pour vous.
