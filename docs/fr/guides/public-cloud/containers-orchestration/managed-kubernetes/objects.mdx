Nous listons ici les objets Kubernetes que vous pouvez retrouver en exécution dans un OVHcloud Managed Kubernetes.

Ces objets sont créés soit à la création du cluster, soit à la création du `node`, et ils permettent le fonctionnement et la gestion du cluster.

:::warning
Merci de vous abstenir de les supprimer ou de les modifier de quelque façon que ce soit !
:::


### Namespaces

Plusieurs `namespaces` existent et fonctionnent dans votre cluster :

- `default` : namespace par défaut
- `kube-node-lease` : pour l'objet lease de heartbeat des Nodes
- `kube-public` : réservé principalement à l'usage du cluster et, dans certains cas, à des ressources spécifiques devant être publiquement accessibles
- `kube-system` : pour les objets créés par Kubernetes

Les ressources listées ci-dessous fonctionnent dans ces `namespaces`.

### Services

Plusieurs `services` de gestion fonctionnent dans votre cluster :

- `kubernetes`
- `kube-dns`
- `metrics-server`
- `wormhole`

Sur notre exemple de cluster, nous obtenons :

```console
$ kubectl get services --all-namespaces
NAMESPACE     NAME                        TYPE           CLUSTER-IP     EXTERNAL-IP      PORT(S)                  AGE
default       kubernetes                  ClusterIP      10.3.0.1       <none>           443/TCP                  14d
kube-system   kube-dns                    ClusterIP      10.3.0.10      <none>           53/UDP,53/TCP,9153/TCP   14d
kube-system   metrics-server              ClusterIP      10.3.224.150   <none>           443/TCP                  14d
kube-system   wormhole                    ClusterIP      10.3.0.2       <none>           443/TCP                  14d
```

### Deployments

Pour implémenter ces services, vous trouverez plusieurs objets `deployment` :

- `coredns`
- `kube-dns-autoscaler`
- `metrics-server`

Sur notre exemple de cluster, nous obtenons :

```console
$ kubectl get deployments --all-namespaces
NAMESPACE     NAME                        READY   UP-TO-DATE   AVAILABLE   AGE
kube-system   coredns                     2/2     2            2           14d
kube-system   kube-dns-autoscaler         1/1     1            1           14d
kube-system   metrics-server              1/1     1            1           14d
```

### Daemon sets

Il existe également plusieurs `daemonsets` définissant les pods qui seront déployés sur chaque nœud :

- `canal`
- `kube-proxy`
- `wormhole`

Sur notre exemple de cluster, avec 5 nœuds, nous obtenons :

```console
$ kubectl get daemonsets --all-namespaces
NAMESPACE     NAME         DESIRED   CURRENT   READY   UP-TO-DATE   AVAILABLE   NODE SELECTOR                 AGE
kube-system   canal        3         3         3       3            3           beta.kubernetes.io/os=linux   14d
kube-system   kube-proxy   3         3         3       3            3           <none>                        14d
kube-system   wormhole     3         3         3       3            3           <none>                        14d
```

### Replica sets

Il existe également plusieurs `replicasets` définissant les pods qui s'exécuteront sur plusieurs instances :

- `coredns-*`
- `kube-dns-autoscaler-*`
- `metrics-server-*`

Sur notre exemple de cluster, nous obtenons :

```console
$ kubectl get replicaset --all-namespaces
NAMESPACE     NAME                                   DESIRED   CURRENT   READY   AGE
kube-system   coredns-77b9fbd56                      2         2         2       14d
kube-system   kube-dns-autoscaler-ddf4c7d5b          1         1         1       14d
kube-system   metrics-server-66bb5cd998              1         1         1       14d
```

### Pods

Vous trouverez une instance des pods suivants en exécution sur chaque nœud de votre cluster :

- `canal`
- `kube-proxy`
- `wormhole`

Vous trouverez également une instance globale de :

- `kube-dns-autoscaler`
- `metrics-server`

Et plusieurs instances de :

- `coredns`

Sur notre exemple de cluster, avec 3 nœuds, nous obtenons :

