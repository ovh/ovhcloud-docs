## Objectif

[Knative](https://knative.dev) est une plateforme permettant de déployer et de gérer des applications Serverless sur Kubernetes.

![Knative](/images/public-cloud/containers-orchestration/managed-kubernetes/installing-knative/knative.png)

Knative fournit un ensemble de composants middleware construits au-dessus de Kubernetes, qui masquent les détails complexes et permettent aux développeurs de se concentrer sur l'essentiel. Construit en codifiant les bonnes pratiques partagées par des implémentations réelles ayant fait leurs preuves, Knative résout les aspects « ennuyeux mais difficiles » du déploiement et de la gestion des services cloud native, afin que vous n'ayez pas à le faire vous-même.

Concrètement, vous allez déployer des composants Knative, et Knative créera lui-même les composants Kubernetes nécessaires. Vous n'avez pas à vous soucier des composants Kubernetes.

Knative prend en charge plusieurs couches de routage HTTP, notamment Istio, Gloo, Contour, Kourier et Ambassador.

Knative comporte deux composants :

- Serving
- Eventing

![Composants Knative](/images/public-cloud/containers-orchestration/managed-kubernetes/installing-knative/knative-inside.png)

Il permet notamment :

- le déploiement rapide de conteneurs Serverless ;
- le scale to zero (pas d'appel = pas de pod = pas de consommation de mémoire/CPU) ;
- le scale from zero (pic de trafic démarre x pods) ;
- la gestion de la configuration et des révisions ;
- la répartition du trafic entre les révisions, blue/green... ;
- un système d'eventing.

Pour en savoir plus sur les [fonctionnalités de Knative 1.0](https://knative.dev/blog/releases/announcing-knative-v1-0-release/).

Knative a atteint la version 1.0. Pour célébrer cette étape, ce tutoriel vous guide dans l'installation de Knative sur un cluster OVHcloud Managed Kubernetes Service nouvellement créé, puis dans le déploiement d'une application d'exemple utilisant le composant Knative Serving. Vous pouvez utiliser la fonction *Réinitialiser le cluster* dans la section Public Cloud de l'<ManagerLink to="/">OVHcloud Control Panel</ManagerLink> pour réinitialiser votre cluster avant de suivre ce tutoriel.

## Prérequis

Ce tutoriel suppose que vous disposez déjà d'un cluster OVHcloud Managed Kubernetes fonctionnel, ainsi que de connaissances de base sur son fonctionnement. Pour en savoir plus sur ces sujets, consultez la documentation [Déployer une application Hello World](/guides/public-cloud/containers-orchestration/managed-kubernetes/deploy-hello-world).

## En pratique

### Installer la CLI Knative « kn »

La CLI Knative (`kn`) offre une interface rapide et simple pour créer des ressources Knative, comme des Knative Services et des sources d'événements, sans avoir à créer ou modifier directement des fichiers YAML.

`kn` simplifie également la réalisation de procédures autrement complexes, comme l'autoscaling et la répartition du trafic.

Pour installer la CLI, [suivez les instructions](https://knative.dev/docs/getting-started/quickstart-install/#install-the-knative-cli) correspondant à votre système d'exploitation.

Vérifiez ensuite que la CLI est correctement installée sur votre machine :

```console
kn version
```

Voici un exemple de résultat :

```console
$ kn version
Version:      v1.17.0
Build Date:   2025-01-22 16:25:15
Git Revision: f7347245
Supported APIs:
* Serving
  - serving.knative.dev/v1 (knative-serving v1.17.0)
* Eventing
  - sources.knative.dev/v1 (knative-eventing v1.17.0)
  - eventing.knative.dev/v1 (knative-eventing v1.17.0)
```

#### Installer une couche réseau (Ingress Gateway)

Comme couche réseau, vous pouvez [installer celle de votre choix](https://knative.dev/docs/install/serving/install-serving-with-yaml/#install-a-networking-layer) : Istio, Contour, Gloo ou Ambassador. Dans ce tutoriel, nous allons installer [Kourier](https://github.com/3scale-archive/kourier) : un Ingress léger pour Knative Serving.

Installez le contrôleur Knative Kourier en exécutant la commande :

```console
kubectl apply -f https://github.com/knative/net-kourier/releases/latest/download/kourier.yaml

namespace/kourier-system created
configmap/kourier-bootstrap created
configmap/config-kourier created
serviceaccount/net-kourier created
clusterrole.rbac.authorization.k8s.io/net-kourier created
clusterrolebinding.rbac.authorization.k8s.io/net-kourier created
deployment.apps/net-kourier-controller created
service/net-kourier-controller created
deployment.apps/3scale-kourier-gateway created
service/kourier created
service/kourier-internal created
horizontalpodautoscaler.autoscaling/3scale-kourier-gateway created
poddisruptionbudget.policy/3scale-kourier-gateway-pdb created
```

Configurez Knative Serving pour utiliser Kourier par défaut en exécutant la commande :

```console
kubectl patch configmap/config-network \
  --namespace knative-serving \
  --type merge \
  --patch '{"data":{"ingress.class":"kourier.ingress.networking.knative.dev"}}'
```

Comme vous pouvez le constater, un nouveau namespace `kourier-system` est créé avec un déploiement :

```console
$ kubectl get deploy -n kourier-system
NAME                     READY   UP-TO-DATE   AVAILABLE   AGE
3scale-kourier-gateway   1/1     1            1           104m
```

Récupérez l'adresse IP externe ou le CNAME en exécutant la commande :

```console
kubectl get service kourier -n kourier-system
```

Voici un exemple de résultat :

```console
$ kubectl get service kourier -n kourier-system 
NAME      TYPE           CLUSTER-IP    EXTERNAL-IP      PORT(S)                      AGE
kourier   LoadBalancer   10.3.15.239   135.125.83.166   80:31357/TCP,443:31782/TCP   2m19s
```

    Avertissement : comme la création du `LoadBalancer` est asynchrone et que le provisionnement du load balancer peut prendre plusieurs minutes, vous obtiendrez certainement un état `<pending>` pour le champ `EXTERNAL-IP`. Réessayez dans quelques minutes pour obtenir l'adresse IP externe.

Conservez cette valeur pour l'utiliser dans la section suivante consacrée à la configuration du DNS.

#### Configurer le DNS

Pour ce tutoriel, même si cela n'est pas obligatoire, vous pouvez configurer le DNS afin d'éviter d'avoir à exécuter des commandes `curl` avec un en-tête d'hôte.

Pour configurer le DNS pour Knative, récupérez l'adresse IP externe obtenue lors de la configuration réseau (`135.125.83.166` dans cet exemple) et configurez-la chez votre fournisseur DNS comme suit :

Configurez un enregistrement A générique (wildcard) pour le domaine :

```console
# Here knative.example.com is the domain suffix for your cluster
*.knative.example.com == A 135.125.83.166
```

Chez OVHcloud, vous pouvez créer une nouvelle entrée dans une zone DNS existante, comme ceci :
![Nouvelle entrée OVHcloud dans la zone DNS pour Knative](/images/public-cloud/containers-orchestration/managed-kubernetes/installing-knative/ovhcloud-entry-dns.png)

Une fois votre fournisseur DNS configuré, indiquez à Knative d'utiliser ce domaine :

```console
# Replace example.com with your domain suffix
kubectl patch configmap/config-domain \
  --namespace knative-serving \
  --type merge \
  --patch '{"data":{"knative.example.com":""}}'
```

Pour en savoir plus sur le DNS chez OVHcloud, consultez notre guide sur [la configuration d'une zone DNS](/guides/web-cloud/domains/dns-zone-edit).

### Déployer une application

Pour vérifier que Knative fonctionne réellement dans le cluster, vous allez déployer une application hello-world.

La première chose à faire est de créer un namespace dans lequel nos applications s'exécuteront :

```
kubectl create namespace knative-apps
```

Voici un exemple de résultat :

```console
$ kubectl create namespace knative-apps
namespace/knative-apps created
```

Créez maintenant votre premier fichier Knative Service, nommé `service.yaml` :

```
apiVersion: serving.knative.dev/v1
kind: Service
metadata:
  name: hello-world
spec:
  template:
    spec:
      containers:
      - image: ovhplatform/hello
        ports:
            - containerPort: 80
```

Comme vous pouvez le constater, le fichier YAML du service Knative est simple et concis.

Il doit être appliqué à notre cluster avec la commande :

```
kubectl apply -f service.yaml -n knative-apps
```

Voici un exemple de résultat :

```console
$ kubectl apply -f service.yaml -n knative-apps
service.serving.knative.dev/hello-world created
```

En interne, Knative a créé plusieurs composants Knative et Kubernetes :

![Composants Knative Serving](/images/public-cloud/containers-orchestration/managed-kubernetes/installing-knative/knative-serving.png)

Un déploiement :

Un pod :

### Réduction à zéro (scale to zero)

Une des forces de Knative Serving est l'autoscaling intégré. Cela signifie que votre Knative Service ne démarre votre application pour effectuer son travail que si nécessaire ; sinon, il effectue un « scale to zero » en arrêtant les instances et en attendant qu'une nouvelle requête arrive.

Ainsi, si vous n'envoyez pas de requêtes à votre application, les pods seront automatiquement supprimés !

```console
$ kubectl get po -n knative-apps
No resources found in knative-apps namespace.
```

### Suppression (nettoyage)

Si vous le souhaitez, vous pouvez désinstaller les applications Knative, ainsi que les composants Serving et les composants principaux.

Tout d'abord, supprimez notre application Hello World :

```console
kubectl delete -f service.yaml -n knative-apps
```

Ensuite, supprimez les CRD Knative :

```console
kubectl api-resources -o name | grep knative | xargs kubectl delete crd
```

Ensuite, supprimez les ressources Knative :

```console
kubectl -n knative-serving delete po,svc,daemonsets,replicasets,deployments,rc,secrets --all
kubectl -n kourier-system delete po,svc,daemonsets,replicasets,deployments,rc,secrets --all
```

Enfin, supprimez les namespaces :

```console
kubectl delete namespace knative-serving
kubectl delete namespace kourier-system
kubectl delete namespace knative-apps
```
