## Objectif

Le service OVHcloud Managed Kubernetes vous fournit des clusters Kubernetes sans que vous ayez à vous soucier de leur installation ou de leur exploitation.

Depuis la console OVHcloud et via l'API, vous pouvez réinitialiser votre cluster OVHcloud Managed Kubernetes.

:::info
Lors d'une réinitialisation, toutes les données de l'ETCD seront supprimées (pods, déploiements, services, secrets, CRD, etc.). De la même manière, les load balancers ainsi que tous les PVC (Persistent Volume Claim) avec leurs volumes PCI cinder seront supprimés.
Les nœuds seront soit supprimés, soit réinstallés (selon l'option choisie lors de la réinitialisation).(selon l'option choisie lors de la réinitialisation).

:::


L'ensemble de la configuration du cluster est réinitialisé, mais certaines valeurs peuvent être définies (facultatif) :

- workerNodesPolicy : reinstall|delete
- minor_version : par ex. 1.25
- updatePolicy : "ALWAYS_UPDATE" par défaut
- customization : configuration de l'API Server et du kube proxy
- privateNetworkId : UUID OpenStack du réseau privé
- privateNetworkConfiguration : true|false
- defaultVrackGateway : IP de la gateway
- kubeProxyMode : ipvs|iptables

## Prérequis

- un cluster OVHcloud Managed Kubernetes

## En pratique

### Réinitialiser un cluster Kubernetes depuis la console OVHcloud

#### Étape 1 - Demander la réinitialisation du cluster depuis la console OVHcloud

Cliquez sur le nom de votre cluster Kubernetes pour accéder à sa page de détails. Dans la carte **Gérer le cluster** de l'onglet <code className="action">Vue d'ensemble</code>, cliquez sur <code className="action">Réinitialiser le cluster</code>.

#### Étape 2 - Choisir le type de réinitialisation souhaité

Dans la fenêtre **Réinitialiser la configuration du cluster**, la section **Vos nœuds de calcul** propose deux options :

- Choisir **Supprimer les nœuds** signifie que les nœuds actuels du cluster sont supprimés, et que le cluster est réinitialisé à un état vide.

- Choisir **Réinstaller les nœuds** signifie que le cluster est réinitialisé sans détruire les nœuds. Selon le plan de votre cluster, cette option peut ne pas être encore disponible (elle est alors signalée comme bientôt disponible).

Vous pouvez également choisir la version mineure du cluster et le réseau privé associé.

Cliquez sur le bouton <code className="action">Confirmer</code> pour continuer.

#### Étape 3 - Attendre la fin de la réinitialisation

Selon le type de réinitialisation choisi, le processus peut prendre plusieurs minutes. Pendant ce temps, le statut du cluster indique qu'il est en cours de réinitialisation.

### Réinitialiser un cluster Kubernetes via l'API

#### L'API Explorer

Pour simplifier les choses, nous utilisons l'[API Explorer](/guides/manage-and-operate/api/first-steps), qui permet d'explorer, d'apprendre et d'interagir avec l'API de manière interactive.

Si vous vous rendez dans la section Kubernetes de l'API Explorer, vous verrez les endpoints disponibles, tels que :

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/{serviceName}/kube"} />

#### Endpoints de l'API

- Réinitialiser un cluster Kubernetes :

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/kube/\{kubeId\}/reset"} />

**Entrée :**
```json
{
  "name": "my-test-cluster",
  "updatePolicy": "ALWAYS_UPDATE",
  "version": "1.34"
}
```

**Résultat :**
```json
null
```

Par défaut, si vous ne le spécifiez pas, l'option `workerNodesPolicy` sera équivalente à `delete`. Si vous ne souhaitez pas que vos nœuds soient supprimés mais réinstallés à la place, vous devez spécifier `"workerNodesPolicy": "reinstall"`.

:::info
Vous devriez recevoir une réponse avec un contenu `null`. Ce message sera amélioré à l'avenir avec les mêmes informations que celles obtenues après la création d'un cluster Kubernetes.

:::


- Vérifier que le cluster Kubernetes est en cours de réinitialisation :

**Résultat :**
