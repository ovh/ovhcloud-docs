## Objectif

OVHcloud Managed Kubernetes Service vous donne accès à des clusters Kubernetes sans que vous ayez à vous soucier de leur installation ou de leur exploitation.

Ce guide explique comment récupérer le fichier de configuration `kubectl` pour interagir avec un cluster OVHcloud Managed Kubernetes.

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud.
- Vous devez disposer d'un cluster OVHcloud Managed Kubernetes.
- Vous devez avoir installé l'outil de ligne de commande [`kubectl`](https://kubernetes.io/docs/reference/kubectl/overview/).

Vous trouverez les instructions d'installation détaillées de `kubectl` dans la [documentation officielle](https://kubernetes.io/docs/home/) de Kubernetes.

## En pratique

### Étape 1 - Configurer les paramètres par défaut de kubectl

Accédez à l'interface d'administration de vos clusters OVHcloud Managed Kubernetes en cliquant sur <code className="action">Managed Kubernetes Service</code> dans le menu de gauche.

Cliquez ensuite sur l'un de vos clusters Kubernetes dans l'onglet.

<img className="thumbnail" alt="Configuration des paramètres par défaut de kubectl" src="/images/public-cloud/containers-orchestration/managed-kubernetes/configuring-kubectl-on-an-ovh-managed-kubernetes-cluster/kubernetes-quickstart-01.png" loading="lazy" />

Cliquez ensuite sur <code className="action">kubeconfig</code> pour télécharger le fichier de configuration `kubectl` :

<img className="thumbnail" alt="Configuration des paramètres par défaut de kubectl" src="/images/public-cloud/containers-orchestration/managed-kubernetes/configuring-kubectl-on-an-ovh-managed-kubernetes-cluster/kubernetes-quickstart-02.png" loading="lazy" />

Comment les fichiers kubeconfig sont-ils chargés ?

- 1. depuis le flag <code className="action">--kubeconfig</code>, s'il est spécifié
- 2. depuis la variable d'environnement `KUBECONFIG`, si elle est définie
- 3. depuis le fichier `$HOME/.kube/config`, par défaut

Ainsi, après l'avoir téléchargé, si vous souhaitez utiliser ce fichier de configuration par défaut dans `kubectl`, vous pouvez l'enregistrer sous le nom `config` dans le répertoire `$HOME/.kube/`. Vous pouvez également le placer dans votre répertoire de travail, en utilisant la variable d'environnement `KUBECONFIG` ou le flag `--kubeconfig`.

Dans cet exemple, nous utilisons la méthode de la variable d'environnement `KUBECONFIG`.

#### Pour macOS ou Linux :

Saisissez la commande suivante dans votre terminal :

```
export KUBECONFIG=/Users/myuser/.kube/my-test-cluster.yml
```

#### Pour Windows 7, 10 et 11 :

1. Dans le menu Windows ou la barre de recherche Cortana, recherchez « Modifier les variables d'environnement système ».
2. Dans la fenêtre Propriétés système, cliquez sur l'onglet *Avancé*, puis sur le bouton *Variables d'environnement* en bas de la fenêtre.
3. Dans la fenêtre qui s'ouvre (illustrée ci-dessous), ajoutez une nouvelle variable, `KUBECONFIG`, avec le chemin du fichier `kube-config` comme valeur.

<img className="thumbnail" alt="Ajouter des variables d'environnement" src="/images/public-cloud/containers-orchestration/managed-kubernetes/configuring-kubectl-on-an-ovh-managed-kubernetes-cluster/configuring_default_settings_for_kubectl-02.png" loading="lazy" />

Vous pouvez également ajouter la variable pour le processus shell actuel avec cette commande :

```
set KUBECONFIG=my-test-cluster.yml
```

### Étape 2 - Vérifier que *kubectl* peut se connecter au cluster

Vous pouvez vérifier que `kubectl` est capable d'interagir avec le cluster en l'utilisant pour envoyer une commande `cluster-info` :

```
kubectl cluster-info
```

Le cluster doit renvoyer une réponse contenant quelques informations clés sur lui-même :

```console
$ kubectl cluster-info
Kubernetes control plane is running at https://xxxxxx.c2.gra.k8s.ovh.net
CoreDNS is running at https://xxxxxx.c2.gra.k8s.ovh.net/api/v1/namespaces/kube-system/services/kube-dns:dns/proxy
Metrics-server is running at https://xxxxxx.c2.gra.k8s.ovh.net/api/v1/namespaces/kube-system/services/https:metrics-server:/proxy

To further debug and diagnose cluster problems, use 'kubectl cluster-info dump'.
```

### Définir l'accès pour plusieurs clusters Kubernetes

Vous pouvez également spécifier plusieurs fichiers kubeconfig dans votre variable d'environnement `KUBECONFIG`, séparés par un signe deux-points (`:`).

```
export KUBECONFIG=/Users/myuser/.kube/my-test-cluster.yml:/Users/myuser/.kube/my-test-cluster2.yml
```

### Basculer vers un autre cluster

Vous pouvez basculer entre différents clusters à l'aide de la commande <code className="action">kubectl config</code>.

```console
$ kubectl config use-context kubernetes-admin@my-test-cluster
Switched to context "kubernetes-admin@my-test-cluster".

$ kubectl config use-context kubernetes-admin@my-test-cluster2
Switched to context "kubernetes-admin@my-test-cluster2".
```

Vous pouvez également installer et utiliser [kubectx](https://github.com/ahmetb/kubectx).
