## Fonctionnalités récentes

### Routeur client et exposition publique désactivée (disponible)

Les nouveaux clusters Standard en Kubernetes 1.35 peuvent utiliser votre propre routeur ou pare-feu comme passerelle par défaut des nœuds, sans passerelle managée OVHcloud, et peuvent être créés avec leur exposition publique désactivée (ni IP flottante, ni load balancer public). Sur tout nouveau cluster Standard, le trafic entre les nœuds et le control plane passe désormais par un chemin privé opéré par OVHcloud. Ces options se définissent à la création du cluster avec l'API OVHcloud.

Pour plus d'informations, consultez :

- [Utiliser une passerelle personnalisée sur un cluster OVHcloud Managed Kubernetes](/guides/public-cloud/containers-orchestration/managed-kubernetes/vrack-custom-gateway#utiliser-votre-propre-routeur-ou-pare-feu-plan-standard)
- [Limites connues - Routeur client et exposition publique désactivée](/guides/public-cloud/containers-orchestration/managed-kubernetes/known-limits#routeur-client-et-exposition-publique-désactivée)

### Volumes persistants chiffrés LUKS (disponible)

OVHcloud Managed Kubernetes prend désormais en charge les volumes de stockage bloc chiffrés avec LUKS, à l'aide des clés managées OVHcloud (OMK). Cette fonctionnalité est disponible dans certaines régions.

Pour plus d'informations, consultez :

- [Datacenters, nodes et storage flavors - Classes de stockage chiffrées LUKS](/guides/public-cloud/containers-orchestration/managed-kubernetes/datacenters-nodes-storage-flavors#classes-de-stockage-chiffrées-luks)
- [Documentation sur les volumes chiffrés LUKS](/guides/public-cloud/containers-orchestration/managed-kubernetes/known-limits#volumes-persistants-chiffrés-luks)
- [Tutoriel complet sur la création de volumes persistants chiffrés](https://blog.ovhcloud.com/create-encrypted-persistent-volumes-on-ovhcloud-managed-kubernetes-clusters-with-luks/)
