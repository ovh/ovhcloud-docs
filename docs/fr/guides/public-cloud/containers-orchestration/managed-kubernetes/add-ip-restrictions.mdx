## Objectif

Le service OVHcloud Managed Kubernetes vous fournit des clusters Kubernetes sans que vous ayez à vous soucier de leur installation ou de leur exploitation.

Ce guide couvre la fonctionnalité qui vous permet de gérer l'accès au serveur API de votre cluster OVHcloud Managed Kubernetes. Grâce à elle, vous pouvez ajouter des restrictions IP à un cluster.

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Un cluster OVHcloud Managed Kubernetes

## En pratique

### Ajouter des restrictions IP via l'espace client OVHcloud

Accédez à l'interface d'administration de vos clusters OVHcloud Managed Kubernetes en cliquant sur <code className="action">Managed Kubernetes Service</code> dans le menu de gauche.

<img className="thumbnail" alt="Clusters" src="/images/public-cloud/containers-orchestration/managed-kubernetes/add-ip-restrictions/clusters.png" loading="lazy" />

Cliquez sur votre cluster Kubernetes.

<img className="thumbnail" alt="Votre cluster Kubernetes" src="/images/public-cloud/containers-orchestration/managed-kubernetes/add-ip-restrictions/cluster.png" loading="lazy" />

Cliquez sur l'onglet <code className="action">Accès APIServer</code> ou sur le lien *Modifier les limitations*.

<img className="thumbnail" alt="Accès APIServer" src="/images/public-cloud/containers-orchestration/managed-kubernetes/add-ip-restrictions/apiserver_access.png" loading="lazy" />

Cliquez sur le bouton <code className="action">+ Ajouter une nouvelle limitation</code>.

Saisissez une plage IPv4 dans le champ *Clients autorisés*, puis cliquez sur le bouton <code className="action">✔️</code>.
Vous pouvez ajouter une ou plusieurs plages IP.

<img className="thumbnail" alt="Ajouter une restriction IP à un cluster Kubernetes" src="/images/public-cloud/containers-orchestration/managed-kubernetes/add-ip-restrictions/add-ip-restriction.png" loading="lazy" />

:::info
En l'absence d'IP dans les clients autorisés, cela signifie qu'aucune restriction n'est appliquée.

:::


### Ajouter des restrictions IP via Terraform

Depuis la version 0.19+ de notre [provider OVH Terraform](https://registry.terraform.io/providers/ovh/ovh/latest/docs), vous pouvez également ajouter des restrictions IP via Terraform.

#### Obtenir les informations de votre cluster/vos jetons API

Le « provider OVH » doit être configuré avec un ensemble d'identifiants :

* un `application_key`
* un `application_secret`
* un `consumer_key`

**Pourquoi ?**

Parce que, en arrière-plan, le « provider OVH Terraform » effectue des requêtes vers les API OVHcloud.

Afin de récupérer ces informations nécessaires, suivez notre tutoriel [Premiers pas avec les API OVHcloud](/guides/manage-and-operate/api/first-steps).

Plus précisément, vous devez générer ces identifiants via la <CreateToken rights="GET=/*&POST=/*&PUT=/*&DELETE=/*">page de génération de tokens OVHcloud</CreateToken> avec les droits suivants : **GET**, **POST**, **PUT** et **DELETE** sur `/*`.

Une fois vos jetons OVHcloud générés avec succès, veillez à les enregistrer, car vous en aurez besoin très prochainement.

La dernière information nécessaire est le `service_name` : il s'agit de l'ID de votre projet Public Cloud.

**Comment l'obtenir ?**

Dans la section Public Cloud, vous pouvez récupérer l'ID de votre nom de service grâce au bouton <code className="action">Copier dans le presse-papier</code>.

<img className="thumbnail" alt="Copier-coller le nom du service" src="/images/public-cloud/containers-orchestration/managed-kubernetes/add-ip-restrictions/get-service-name.png" loading="lazy" />

Vous utiliserez également cette information dans les fichiers de définition des ressources Terraform.

#### Instructions Terraform

Commencez par créer un fichier `provider.tf` avec la version minimale, l'endpoint européen (« ovh-eu ») et les clés récupérées précédemment dans ce guide.

Terraform 0.13 et versions ultérieures :

```bash
terraform {
  required_providers {
    ovh = {
      source  = "ovh/ovh"
    }
  }
}

provider "ovh" {
  endpoint           = "ovh-eu"
  application_key    = "<your_access_key>"
  application_secret = "<your_application_secret>"
  consumer_key       = "<your_consumer_key>"
}
```

Terraform 0.12 et versions antérieures :

```bash
# Configure the OVHcloud Provider
provider "ovh" {
  endpoint           = "ovh-eu"
  application_key    = "<your_access_key>"
  application_secret = "<your_application_secret>"
  consumer_key       = "<your_consumer_key>"
}
```

Les clés secrètes peuvent également être récupérées depuis votre environnement.

- `OVH_ENDPOINT`
- `OVH_APPLICATION_KEY`
- `OVH_APPLICATION_SECRET`
- `OVH_CONSUMER_KEY`

Cette dernière méthode (ou une alternative similaire) est recommandée pour éviter de stocker des données secrètes dans un dépôt source.

Ici, nous avons défini l'endpoint `ovh-eu` car nous souhaitons appeler l'API OVHcloud Europe, mais d'autres endpoints existent selon vos besoins :

* `ovh-eu` pour l'API OVHcloud Europe
* `ovh-us` pour l'API OVHcloud États-Unis
* `ovh-ca` pour l'API OVHcloud Canada

Ensuite, définissez les ressources que vous souhaitez créer dans un nouveau fichier nommé `ovh_kube_cluster_iprestrictions.tf` :

```bash
resource "ovh_cloud_project_kube_iprestrictions" "iprestrictions" {
	service_name  = `<service_name>`
	kube_id       = <cluster_id>
    ips           = ["<your_IP_range>"]
}
```

:::info
N'oubliez pas de remplacer `<service_name>`, `<cluster_id>` et `<your_IP_range>` par les données réelles.

:::
