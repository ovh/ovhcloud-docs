Ce tutoriel vous guide dans l'installation de [Jenkins](https://jenkins.io/) sur votre OVHcloud Managed Kubernetes Service.

Vous allez installer un cluster Jenkins master et slave à l'aide du [plugin Jenkins Kubernetes](https://plugins.jenkins.io/kubernetes/).

## Avant de commencer

Ce tutoriel suppose que vous disposez déjà d'un cluster OVHcloud Managed Kubernetes fonctionnel, ainsi que de connaissances de base sur son utilisation. Pour en savoir plus sur ces sujets, consultez le [guide de démarrage rapide OVHcloud Managed Kubernetes Service](/guides/public-cloud/containers-orchestration/managed-kubernetes/deploy-hello-world).

Vous devez également avoir [Helm](https://docs.helm.sh/) installé sur votre poste de travail et sur votre cluster ; reportez-vous au tutoriel [Comment installer Helm sur OVHcloud Managed Kubernetes Service](/guides/public-cloud/containers-orchestration/managed-kubernetes/install-helm).

## Prérequis

L'équipe OVHcloud Managed Kubernetes Service travaille sur un correctif qui sera publié début 2022. En attendant, veuillez supprimer la storage class par défaut et installer la nouvelle.

- Supprimez la `StorageClass` concernée que vous utilisez par défaut.

```bash
kubectl delete storageclasses.storage.k8s.io csi-cinder-high-speed
```

Cela supprimera la `StorageClass` existante :

```console
$ kubectl delete storageclasses.storage.k8s.io csi-cinder-high-speed
storageclass.storage.k8s.io "csi-cinder-high-speed" deleted
```

- Créez une nouvelle `StorageClass` intégrant le correctif requis.

```bash
kubectl apply -f https://raw.githubusercontent.com/ovh/docs/develop/pages/public_cloud/containers_orchestration/managed_kubernetes/fix-persistent-volumes-permissions/files/fixed-cinder-high-speed-storage-class.yaml
```

Cela applique le manifeste YAML `StorageClass` corrigé :

```console
$ kubectl apply -f https://raw.githubusercontent.com/ovh/docs/develop/pages/public_cloud/containers_orchestration/managed_kubernetes/fix-persistent-volumes-permissions/files/fixed-cinder-high-speed-storage-class.yaml
storageclass.storage.k8s.io/csi-cinder-high-speed created
```

## Installer le chart Helm Jenkins

:::warning
Comme pour Helm 2, le repository officiel Helm `stable` est aujourd'hui obsolète.
La communauté Helm est en train de passer à un modèle de hub, avec un [Helm Hub](https://hub.helm.sh/), où les charts peuvent être recherchés à l'aide de `helm search hub <keyword>`.
La plupart des charts du repository Helm _stable_ ayant été transférés vers le [repository Bitnami](https://github.com/bitnami/charts/), nous l'utilisons dans ce tutoriel.
:::


Pour ce tutoriel, nous utilisons le [chart Helm Jenkins](https://github.com/bitnami/charts/tree/master/bitnami/jenkins) disponible sur les repositories Helm de Bitnami.

Le chart est entièrement configurable, mais nous utilisons ici la configuration par défaut.

:::info
### Personnaliser votre installation

Vous souhaitez peut-être utiliser un autre nom d'utilisateur administrateur, définir votre propre mot de passe administrateur, ou modifier les ressources allouées...

Pour personnaliser votre installation sans renoncer à la simplicité de Helm et du chart Helm Jenkins, vous pouvez simplement définir certains des [paramètres configurables du chart Jenkins](https://github.com/bitnami/charts/tree/master/bitnami/jenkins#parameters), puis les ajouter à votre commande `helm install` avec l'option `--set` (`--set param1=value1,param2=value2`).
:::


```bash
helm install my-first-jenkins bitnami/jenkins
```

Cela installera votre Jenkins master :

```console
$ helm install my-first-jenkins bitnami/jenkins

NAME: my-first-jenkins
LAST DEPLOYED: Mon Dec 20 11:30:59 2021
NAMESPACE: default
STATUS: deployed
REVISION: 1
TEST SUITE: None
NOTES:
CHART NAME: jenkins
CHART VERSION: 8.0.22
APP VERSION: 2.319.1

** Please be patient while the chart is being deployed **

1. Get the Jenkins URL by running:

** Please ensure an external IP is associated to the my-first-jenkins service before proceeding **
** Watch the status using: kubectl get svc --namespace default -w my-first-jenkins **

  export SERVICE_IP=$(kubectl get svc --namespace default my-first-jenkins --template "{{ range (index .status.loadBalancer.ingress 0) }}{{.}}{{ end }}")
  echo "Jenkins URL: http://$SERVICE_IP/"

2. Login with the following credentials

  echo Username: user
  echo Password: $(kubectl get secret --namespace default my-first-jenkins -o jsonpath="{.data.jenkins-password}" | base64 --decode)
```

Comme l'indiquent les instructions, vous devrez attendre quelques instants pour obtenir l'URL du `LoadBalancer`.
Vous pouvez vérifier si le `LoadBalancer` est prêt à l'aide de la commande suivante :

```bash
kubectl get svc --namespace default -w my-first-jenkins
```

Après quelques minutes, vous obtiendrez l'URL du `LoadBalancer` :

```console
$ kubectl get svc --namespace default -w my-first-jenkins

NAME               TYPE           CLUSTER-IP   EXTERNAL-IP   PORT(S)                      AGE
my-first-jenkins   LoadBalancer   10.3.3.52    <pending>     80:32193/TCP,443:32260/TCP   49s
my-first-jenkins   LoadBalancer   10.3.3.52    152.228.169.118   80:32193/TCP,443:32260/TCP   54s
```

L'URL indiquée sous `EXTERNAL-IP` est votre URL Jenkins. Vous pouvez ensuite suivre les instructions du chart Helm pour obtenir les paramètres de connexion. Dans notre exemple :

```console
$ export SERVICE_IP=$(kubectl get svc --namespace default my-first-jenkins --template "{{ range (index .status.loadBalancer.ingress 0) }}{{.}}{{ end }}")

$ echo "Jenkins URL: http://$SERVICE_IP/"
Jenkins URL: http://152.228.169.118/

$ echo Username: user
Username: user

$ echo Password: $(kubectl get secret --namespace default my-first-jenkins -o jsonpath="{.data.jenkins-password}" | base64 --decode)
Password: KMhUs53TJT
```

En saisissant l'URL dans votre navigateur, vous accéderez au nouveau Jenkins :

Connectez-vous avec l'utilisateur `admin` et le mot de passe obtenu précédemment. Et voici votre Jenkins :

<img className="thumbnail" alt="Leeeeeeeroy Jenkins !" src="/images/public-cloud/containers-orchestration/managed-kubernetes/installing-jenkins/installing-jenkins-02.png" loading="lazy" />

Vous disposez désormais d'un Jenkins fonctionnel sur votre OVHcloud Managed Kubernetes Service.

## Suppression (nettoyage)

Pour nettoyer votre cluster, utilisez simplement Helm afin de supprimer votre release Jenkins.

```bash
helm delete my-first-jenkins
```

Cela supprimera votre Jenkins et les ressources associées de votre cluster :

```console
$ helm delete my-first-jenkins
release "my-first-jenkins" uninstalled
```
