## Objectif

Vous pouvez créer un snapshot unique d'une instance ou configurer un planning afin d'automatiser les snapshots de vos instances. Les snapshots peuvent être utilisés pour restaurer votre instance à un état antérieur ou pour créer une nouvelle instance identique.

**Ce guide explique comment créer des snapshots manuels et automatiques d'une instance Public Cloud.**

## Prérequis

- Avoir une instance [Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud.
- CLI OpenStack. Consultez notre guide « [Préparer l'environnement pour utiliser l'API OpenStack](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment) ». (optionnel)

[[cpnav:publiccloud-instances]]

## En pratique

### Créer un snapshot d'une instance

:::warning
Cette option est uniquement disponible via un **Cold Snapshot** pour les instances Metal. L'instance Metal passera en mode rescue et, une fois le snapshot effectué, l'instance sera redémarrée en mode normal.

:::


:::info
Deux types de snapshots sont disponibles :

- Local : Un snapshot local est stocké dans la même région que votre instance.
- Distant : Un snapshot distant crée automatiquement une copie du snapshot local dans une autre région de votre choix.

Chaque snapshot est facturé séparément. Le snapshot distant sera facturé selon la tarification du stockage dans la région distante sélectionnée.

**Note :** les Local Zones ne sont pas éligibles pour les snapshots distants

:::


{/* CP-STEPS-START:create-backup */}
<Tabs>
  <Tab label="Console OVHcloud">
    Dans le menu de gauche de votre projet Public Cloud, cliquez sur <code className="action">Instances</code> sous **Compute**.

    Cliquez sur le bouton <code className="action">...</code> à droite de l'instance et sélectionnez <code className="action">Créer un snapshot</code>. La page de création du snapshot s'ouvre, avec l'instance présélectionnée dans la section **Sélectionnez une instance**.

    <details>
    <summary>Snapshot local</summary>


    Dans la section **Donnez un nom à votre snapshot**, renseignez un nom pour le snapshot. Prenez connaissance des informations tarifaires et cliquez sur <code className="action">Créer</code>.


    </details>

    <details>
    <summary>Snapshot distant</summary>


    Dans la section **Donnez un nom à votre snapshot**, renseignez un nom pour le snapshot. Prenez connaissance des informations tarifaires. Activez <code className="action">Ajouter un snapshot distant (Option)</code>, renseignez un nom dans le champ **Nom du snapshot distant**, sélectionnez une région et cliquez sur <code className="action">Créer</code>.


    </details>

    L'instance est suspendue quelques secondes pendant la prise du snapshot. Il n'est pas possible de suivre la progression du snapshot en temps réel. Cependant, sur la page **Instance Snapshot** (<code className="action">Instance Snapshot</code> sous **Compute** dans le menu de gauche), le statut du snapshot est affiché pendant le processus.

    Une fois le snapshot terminé, celui-ci sera disponible sur la page **Instance Snapshot** et dans l'onglet <code className="action">Snapshots</code> de l'instance.
  </Tab>
  <Tab label="API OVHcloud">
    Authentifiez-vous sur <ApiLink>l'API OVHcloud</ApiLink>.
    
    Vous pouvez répertorier toutes les régions disponibles à l'aide de l'appel API suivant :
    
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/region"} />

Utilisez ensuite l'appel API suivant :
    
    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/instance/\\{instanceId\\}/snapshot"} />

Renseignez les variables :
    
    - **instanceId** : Identifiant unique de l’instance concernée.
    - **regionName** : Nom de la région où se situe l’instance source.
    - **serviceName** : Identifiant du projet OVHcloud.
    - **distantRegionName (optionnel)** : Nom de la région distante où le snapshot distant sera stocké.
    - **distantSnapshotName (optionnel)** : Nom du snapshot distant à créer dans la région distante.
    - **snapshotName** : Nom du snapshot local à créer.
    
    :::info
    Ne créez un snapshot distant que si les paramètres relatifs à la région distante (**distantRegionName** et **distantSnapshotName**) sont renseignés.

    :::

  </Tab>
  <Tab label="CLI OpenStack">

    ```bash
    +--------------------------------------+-----------+--------+--------------------------------------------------+--------------+
    ```
    
    Vous pouvez répertorier toutes les régions disponibles à l'aide de la commande suivante :
    
    ```bash
    $ openstack region list
    ```
    
    <details>
    <summary>Snapshot local</summary>

    
    Exécutez ensuite la commande suivante pour créer un snapshot de votre instance :
    
    ```bash
    $ openstack server image create --name snap_server1 aa7115b3-83df-4375-b2ee-19339041dcfa
    ```
    

    </details>
    
    <details>

    </details>

### Créer un snapshot automatique d'une instance

:::info
Si vous souhaitez automatiser cette fonctionnalité directement via OpenStack, vous pouvez créer un workflow Mistral associé à un cron trigger.

:::


{/* CP-STEPS-START:create-automated-backup */}
Dans le menu de gauche de votre projet Public Cloud, cliquez sur <code className="action">Instances</code> sous **Compute**. Cliquez sur le bouton <code className="action">...</code> à droite de l'instance et sélectionnez <code className="action">Créer un snapshot automatique</code>.

La page **Créer une planification** s'ouvre. Vous pourrez alors configurer les paramètres suivants :
{/* CP-STEPS-END:create-automated-backup */}

#### **Le workflow** 

{/* CP-STEPS-START:automated-backup-workflow */}
La planification crée un snapshot automatique de l'instance et de son volume principal. Aucun type de workflow n'est à choisir.
{/* CP-STEPS-END:automated-backup-workflow */}

#### **La ressource** 

{/* CP-STEPS-START:automated-backup-resource */}
Dans la section **Sélectionnez une ressource ciblée**, vous pouvez sélectionner l'instance dont vous souhaitez créer un snapshot.
{/* CP-STEPS-END:automated-backup-resource */}

#### **Le nom** 

{/* CP-STEPS-START:automated-backup-name */}
Dans la section **Donnez un nom à votre planification**, entrez un nom pour la planification de snapshot automatique. Consultez les informations de tarification dans le récapitulatif à droite, puis créez la planification en cliquant sur <code className="action">Créer</code>.
{/* CP-STEPS-END:automated-backup-name */}

#### **Le planning**

{/* CP-STEPS-START:automated-backup-schedule */}
Dans la section **Définir l'ordonnancement**, vous pouvez définir une planification personnalisée (**Personnalisé**, au format cron UNIX, en UTC) ou choisir l'une des fréquences par défaut :

- **Rotation 7** : snapshot quotidien avec rétention des 7 derniers snapshots
- **Rotation 14** : snapshot quotidien avec rétention des 14 derniers snapshots

<details>

<summary>**Ajout d'un snapshot distant**</summary>


Activez <code className="action">Ajouter un snapshot distant</code>, sélectionnez une localisation, prenez connaissance des informations de tarification et cliquez sur le bouton <code className="action">Créer</code>.

</details>
{/* CP-STEPS-END:automated-backup-schedule */}


### Gestion des snapshots et des plannings

{/* CP-STEPS-START:manage-backups-schedules */}
Les planifications sont listées et supprimées sur la page **Gestion du workflow** : cliquez sur <code className="action">Workflow</code> sous **Compute** dans le menu de gauche.

Les snapshots de vos instances sont gérés sur la page **Instance Snapshot** : cliquez sur <code className="action">Instance Snapshot</code> sous **Compute** dans le menu de gauche.
{/* CP-STEPS-END:manage-backups-schedules */}

:::warning
L'option de snapshot de l'instance doit être supprimée séparément si vous ne souhaitez plus qu'elle vous soit facturée. La suppression d'une instance ne supprime pas les options qui y sont attachées.

:::


:::warning
**Notez que vous ne pouvez pas supprimer un snapshot d'instance si une instance qui a été générée à partir de ce snapshot est en cours d'exécution au moment de l'action de suppression.**

:::
