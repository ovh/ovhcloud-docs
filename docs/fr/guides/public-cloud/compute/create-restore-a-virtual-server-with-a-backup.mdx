## Objectif

La console OVHcloud vous permet de créer des [snapshots de vos instances](/guides/public-cloud/compute/save-an-instance) en quelques clics et d'automatiser ce processus.
Vous pouvez être amenés à vouloir restaurer votre instance grâce à un snapshot, par exemple en cas de mauvaise manipulation effectuée sur la configuration de votre instance. Vous pouvez utiliser ces snapshots d'instances pour deux raisons principales :

- Créer une instance sur la base du snapshot, afin de dupliquer l'instance d'origine. Par exemple si vous configurez une infrastructure de répartition de charge (load balancing).
- Restaurer une instance à partir d'un snapshot. Par exemple si des modifications récentes ont cassé des configurations critiques sur l'instance.

**Découvrez comment utiliser vos snapshots pour dupliquer ou restaurer vos instances.**

## Prérequis

- Disposer d'[un snapshot d'une instance Public Cloud](/links/public-cloud/instance-backup). À cet effet, consultez [le guide dédié à la création d'un snapshot](/guides/public-cloud/compute/save-an-instance).

## En pratique

{/* CP-STEPS-START:backup-types-note */}
:::info
Deux types de snapshots sont disponibles :

- Locale : stockée dans la même région que votre instance.
- Distante : automatiquement répliquée dans une autre région de votre choix.

Les opérations de **création** et de **restauration** d'une instance depuis un snapshot distant sont entièrement prises en charge via l’API OVHcloud, offrant une plus grande flexibilité et une intégration facilitée dans vos processus d’automatisation.

**Note :** Dans la console OVHcloud, vous pouvez créer une instance à partir de n'importe quel snapshot listé sur la page **Instance Snapshot**, mais vous ne pouvez restaurer une instance existante qu'à partir d'un snapshot stocké dans sa propre région.

:::
{/* CP-STEPS-END:backup-types-note */}


### Créer une instance à partir d'un snapshot

{/* CP-STEPS-START:create-instance-from-backup */}
<Tabs>
  <Tab label="Console OVHcloud">
    Dans le menu de gauche de votre projet Public Cloud, cliquez sur <code className="action">Instance Snapshot</code> sous **Compute**. La page **Instance Snapshot** liste vos snapshots.

    Cliquez sur le bouton <code className="action">...</code> dans la ligne du snapshot choisi, puis sélectionnez <code className="action">Créer une instance</code>.

    La page **Créer une instance** s'ouvre avec certains éléments prédéfinis :

    - **Localisation** : Votre instance sera créée dans la même région que votre snapshot. La région est déterminée par le snapshot et ne peut pas être modifiée.
    - **Image** : Le snapshot est présélectionné dans l'onglet <code className="action">Snapshots</code> de la section **Sélectionnez une image**.
    - **Modèle** : Seuls les modèles pouvant accueillir votre image seront disponibles, en fonction de votre quota.

    Définissez le nom de la nouvelle instance, la clé SSH, les paramètres réseau et de facturation, puis cliquez sur le bouton <code className="action">Créer mon instance</code>.

    Pour plus d'informations sur la création d'une instance, consultez [ce guide](/guides/public-cloud/compute/getting-started).

    :::info
    Pour créer une instance dans un autre datacentre que celui du snapshot, il faudra transférer celui-ci vers la zone correspondante. Référez-vous alors au [guide sur la sauvegarde d'une instance d'un datacentre à l'autre](/guides/public-cloud/compute/transfer-instance-backup-from-one-datacentre-to-another).

    :::

  </Tab>
  <Tab label="API OVHcloud">
    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/instance"} />

Renseignez les variables :
    
    - **serviceName** : L’ID du projet OVHcloud.
    - **regionName** : Le nom de la région où l’instance sera créée.
    
    Exemple de corps de requête :
    
    ```json
    {
      "billingPeriod": "hourly",
      "bootFrom": {
        "imageId": "5cb8ea68-****-****-****-820be8346***"
      },
      "flavor": {
        "id": "e81b46f8-****-****-****-cad655e65***"
      },
      "name": "newInstance",
      "network": {
        "public": true
      },
      "sshKey": {
        "name": "MySSHKey"
      }
    }
    ```
  </Tab>
  <Tab label="CLI OpenStack">
    Pour créer une instance à partir de votre snapshot, utilisez l'ID du snapshot comme image avec cette commande :
    
    ```bash
    $ openstack server create --key-name SSHKEY --flavor 98c1e679-5f2c-4069-b4da-4a4f7179b758 --image 0a3f5901-2314-438a-a7af-ae984dcbce5c Server1_from_snap
    ```
  </Tab>
  <Tab label="Horizon">
    Dans l'interface Horizon, cliquez sur <code className="action">Compute</code> dans le menu de gauche, puis sur <code className="action">Images</code>. Cherchez l'image désirée et Cliquez sur le bouton <code className="action">Launch</code> se trouvant sur la droite de la ligne de votre image. 
    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon1.png" loading="lazy" />

Nommez votre instance dans le champs dédié et determinez le nombre d'instance à créer. Puis cliquez sur l'onglet <code className="action">Flavor</code>.
    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon-2" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon2.png" loading="lazy" />

Choisissez le modèle d'instance désiré, puis cliquez sur l'onglet <code className="action">Networks</code>.
    
    :::warning
    Si votre instance est un serveur Windows, vous devez sélectionner une flavor de type win-xx-xx (par exemple, win-b2-15) et disposer d’une interface publique sur le réseau Ext-Net. Sans ces conditions, l’authentification auprès du KMS OVHcloud ne sera pas possible, et votre serveur restera avec une [licence non activée](/guides/public-cloud/compute/activate-windows-license-private-mode). Cela pourrait entraîner des limitations, notamment l’absence de mises à jour. À noter qu’il est impossible de redimensionner une instance Linux (par exemple b2-15) en une instance Windows (comme win-b2-15). Pour effectuer cette transition, il est nécessaire de recréer une nouvelle instance.

    :::

    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon-3" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon3.png" loading="lazy" />

Choisissez le network que vous souhaitez lui assigner, puis cliquez sur le bouton <code className="action">Launch Instance</code>.
    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon-4" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon4.png" loading="lazy" />

Vous pouvez retrouver le status de votre nouvelle instance dans <code className="action">Compute</code> dans le menu de gauche, puis sur <code className="action">Instances</code>.
    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon-5" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon5.png" loading="lazy" />
  </Tab>
</Tabs>
{/* CP-STEPS-END:create-instance-from-backup */}


### Restaurer une instance à partir d'un snapshot

{/* CP-STEPS-START:restore-instance-from-backup */}
<Tabs>
  <Tab label="Console OVHcloud">
    Dans le menu de gauche de votre projet Public Cloud, cliquez sur <code className="action">Instances</code> sous **Compute**, puis cliquez sur le nom de l'instance concernée.

    Dans la carte **Informations générales** de l'onglet <code className="action">Vue d'ensemble</code>, cliquez sur <code className="action">Modifier l'image</code> sur la ligne **Image**. Le panneau **Modifier l'image** s'ouvre.

    Dans la section **Sélectionner une distribution**, sélectionnez les snapshots, puis sélectionnez le snapshot à restaurer dans la section **Sélectionner une image**. Seuls les snapshots stockés dans la région de l'instance sont proposés. Cliquez sur <code className="action">Modifier l'image</code> si vous êtes certain de vouloir remplacer l'image actuelle par le snapshot.

    L'instance sera réinstallée et redémarrée jusqu'à ce que le processus soit terminé.

    :::warning
    Comme indiqué dans le message d'avertissement, toutes les données de l'instance seront supprimées : aucune donnée ajoutée après la création du snapshot ne pourra être récupérée.

    :::

  </Tab>
  <Tab label="API OVHcloud">
    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/instance/\\{instanceId\\}/reinstall"} />

Renseignez les variables :
    
    - **serviceName** : L’ID du projet OVHcloud.
    - **regionName** : Le nom de la région où se trouve l’instance source.
    - **instanceId** : L’ID unique de l’instance.
    
    Exemple de corps de requête :
    
    ```json
    {
      "imageId": "5cb8ea68-****-****-****-820be8346***",
      "imageRegionName": "GRA11"
    }
    ```
  </Tab>
</Tabs>
{/* CP-STEPS-END:restore-instance-from-backup */}
