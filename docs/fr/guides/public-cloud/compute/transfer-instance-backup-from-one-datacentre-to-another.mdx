## Objectif

Vous pourriez être amené à déplacer votre [instance Public Cloud](https://www.ovhcloud.com/fr/public-cloud/compute/) d'une région OpenStack à une autre, soit parce que vous préférez migrer vers une nouvelle région OpenStack disponible, soit parce que vous souhaitez migrer d'OVHcloud Labs vers Public Cloud.

**Découvrez comment transférer une sauvegarde d'instance d'une région OpenStack à une autre tout en préservant la configuration et l'état de l'instance.**

## Prérequis

- Disposer de la CLI OpenStack. Consultez notre guide « [Comment préparer l'environnement pour utiliser l'API OpenStack](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment) ».
- Avoir une connectivité aux API OVHcloud OpenStack.
- Prévoir un espace de stockage suffisant correspondant à la taille du disque de l'instance (pour le stockage de sauvegarde temporaire).

Cet environnement sera utilisé comme « jump host » pour transférer la sauvegarde d'une région à une autre. Il peut s'agir d'une instance hébergée sur OVHcloud ou de votre machine locale.

Vous aurez également besoin d'une [instance Public Cloud](https://www.ovhcloud.com/fr/public-cloud/compute/) sur votre compte OVHcloud.

## En pratique

:::info
Si vous devez créer une sauvegarde avec OpenStack, consultez notre guide « [Sauvegarder une instance](/guides/public-cloud/compute/save-an-instance) ».
:::

### Étape 1 - Télécharger la sauvegarde

Listez vos images privées pour identifier la sauvegarde à transférer :

```bash
openstack image list --private
```

Téléchargez la sauvegarde vers votre stockage local :

```bash
openstack image save --file backup.qcow2 <image-id>
```

### Étape 2 - Basculer vers la région cible

Si vous transférez la sauvegarde vers une autre région au sein du même projet, mettez à jour `OS_REGION_NAME` :

```bash
export OS_REGION_NAME=<région-cible>
```

Si vous transférez la sauvegarde vers un autre projet ou compte, sourcez le fichier RC correspondant :

```bash
source openrc.sh
```

### Étape 3 - Importer la sauvegarde dans la région cible

La commande d'import diffère selon que la région cible est une région standard ou une Local Zone.

#### Région standard

```bash
openstack image create \
  --disk-format qcow2 \
  --container-format bare \
  --file backup.qcow2 \
  <nom-image>
```

#### Local Zone

Les noms de région Local Zone contiennent `-lz-` (par exemple `eu-central-lz-prg-a`). Ces régions requièrent `--disk-format raw`. L'extension du fichier de sauvegarde n'a pas d'incidence sur l'import — c'est le paramètre `--disk-format` qui indique à OpenStack comment interpréter le fichier.

```bash
openstack image create \
  --disk-format raw \
  --container-format bare \
  --file backup.qcow2 \
  <nom-image>
```

:::warning
**Images Windows uniquement** — vous devez ajouter les propriétés suivantes, sans quoi il ne sera pas possible d'associer un flavor de type `win-x-x` depuis l'espace client OVHcloud. Ce type de flavor est requis pour l'authentification via le [KMS OVHcloud](/guides/manage-and-operate/kms/quick-start).

Ajout des propriétés à la création (région standard) :

```bash
openstack image create \
  --disk-format qcow2 \
  --container-format bare \
  --file backup.qcow2 \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <nom-image>
```

Ajout des propriétés à la création (Local Zone) :

```bash
openstack image create \
  --disk-format raw \
  --container-format bare \
  --file backup.qcow2 \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <nom-image>
```

Ou sur une image déjà créée :

```bash
openstack image set \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <image-uuid>
```
:::

:::
