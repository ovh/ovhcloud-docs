## Objectif

Dans le cadre de la configuration d’une infrastructure hautement disponible, vous pouvez avoir besoin de couper les accès à vos instances pour effectuer différents tests. OpenStack vous permet de passer en Shelve, arrêter (Shutoff), suspendre ou mettre en pause votre instance. Dans chaque cas, votre IP est maintenue.

:::warning
Dans la console OVHcloud, seules les actions **Shelve** / **Unshelve** et **Hard stop** (action OpenStack *stop*, *Shut Off* dans Horizon) sont disponibles. **Suspend** / **Resume** et **Pause** / **Unpause** sont disponibles via l'API OVHcloud (v2), dans Horizon et via l'API OpenStack.

:::

**Ce tutoriel indique comment passer en Shelve, arrêter (Hard stop), suspendre ou mettre en pause votre instance.**

## Prérequis

- Avoir créé une [instance Public Cloud OVHcloud](/guides/public-cloud/compute/getting-started) au forfait **horaire**.
- Avoir accès à l’interface [Horizon](/guides/public-cloud/cross-functional/introducing-horizon).
- Avoir des connaissances de l’[API OpenStack](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment) et des [variables OpenStack](/guides/public-cloud/cross-functional/compute-set-openstack-environment-variables).

## En pratique

:::warning
**Applicabilité :** ce guide concerne toutes les instances Public Cloud, quel que soit leur mode de facturation (horaire ou mensuel).

**Facturation mensuelle :** pour les instances facturées au mois, le prix mensuel de l'instance continue d'être facturé quel que soit son état. Une instance mensuelle en Shelve est facturée à son prix mensuel, plus le snapshot.

**Attention :** tant que l’instance n’est pas supprimée, toute opération continuera d’entraîner la facturation de l’instance.

:::

{/* CP-STEPS-START:options-table */}
Le tableau ci-dessous vous permet de différencier les options disponibles sur vos instances. Cliquez sur l'option de votre choix pour poursuivre la lecture de ce guide. Nous mettons entre parenthèses l'action OpenStack correspondante.

|Option|État de la mémoire|Données du disque|Ressources de l'hôte (CPU/RAM)|Reprise|Facturation|
|---|---|---|---|---|---|
|[Hard stop (*stop*)](#hard-stop-instance)|Perdu|Conservées|Toujours allouées sur l'hôte|Démarrage à froid (l'OS redémarre)|Vous êtes facturé au même tarif.|
|[Shelve (*shelve*)](#shelve-instance)|Perdu|Sauvegardées dans une image snapshot|Libérées une fois l'instance déchargée (*offloaded*)|Démarrage à froid depuis le snapshot, éventuellement sur un autre hôte|Instances à l'heure : seul le snapshot est facturé. Instances au mois : le prix mensuel de l'instance, plus le snapshot.|
|[Pause (*pause*)](#pause-instance)|Conservé dans la RAM de l'hôte|Conservées|Toujours allouées et consommées|Instantanée, exactement là où elle s'était arrêtée|Vous êtes facturé au même tarif.|
|[Suspend (*suspend*)](#stop-suspend-instance)|Écrit sur le disque de l'hôte|Conservées|RAM/CPU libérés sur l'hyperviseur, allocation conservée|Restaure l'état sauvegardé, comme une mise en veille prolongée|Vous êtes facturé au même tarif.|

Dans chaque cas, l'adresse IP de l'instance est conservée.

{/* CP-STEPS-END:options-table */}

### Passer une instance en Shelve

:::danger
Attention, le passage en Shelve d'une instance de type IOPS ou T1/T2-180 entraînera la perte des données sur les disques NVMe en passthrough.
En effet, le passage en Shelve de ce type d'instance entraîne la décommission de son hôte et donc des disques en passthrough.

:::

Cette option libère les ressources dédiées à votre instance Public Cloud, mais l’adresse IP sera conservée. Les données sur votre disque local seront stockées dans un snapshot créé automatiquement une fois l’instance passée en Shelve. Les données stockées en mémoire et ailleurs ne seront pas sauvegardées.

{/* CP-STEPS-START:shelve-instance */}
<Tabs>
  <Tab label="Console OVHcloud">
    Dans le menu de gauche de votre projet Public Cloud, cliquez sur <code className="action">Instances</code> sous **Compute**.

    Cliquez sur le bouton <code className="action">...</code> à droite de l'instance à passer en Shelve, puis sur <code className="action">Shelve</code>.

    Dans la fenêtre **Passer votre instance en Shelve**, prenez connaissance du message et cliquez sur <code className="action">Confirmer</code>.

    Une fois l'opération terminée, le statut de votre instance apparaîtra comme **Shelve**.

    Pour visualiser le snapshot, cliquez sur <code className="action">Instance Snapshot</code> sous **Compute** dans le menu de gauche. Un snapshot nommé *xxxxx-shelved* est alors visible.
  </Tab>
  <Tab label="CLI OVHcloud">
    Avant de poursuivre, il est recommandé de consulter ces guides :

    - [Connaître les bases de la CLI OVHcloud](/guides/manage-and-operate/cli/getting-started)

    Saisissez la commande suivante :

    ```shell
    ovhcloud cloud instance shelve <instance_id>
    ```
  </Tab>
  <Tab label="API OVHcloud">
    Utilisez l'appel API suivant, où `projectId` est l'ID de votre projet Public Cloud et `instanceId` l'ID de l'instance :

    <Api version="v2" section="/publicCloud" method="POST" route={"/publicCloud/project/\{projectId\}/compute/instance/\{instanceId\}/action"} />

    Avec le corps de requête suivant :

    ```json

    }
    ```
  </Tab>
  <Tab label="API OpenStack/Nova">

    - [Préparer l’environnement pour utiliser l’API OpenStack](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment)
    - [Charger les variables d’environnement OpenStack](/guides/public-cloud/cross-functional/compute-set-openstack-environment-variables)

    Une fois votre environnement prêt, saisissez ce qui suit dans la ligne de commande :

    ```bash

    =====================================

    ~$ nova shelve <UUID server>
    ```
  </Tab>
  <Tab label="Horizon">

    - Pour vous connecter avec un utilisateur OpenStack spécifique : ouvrez la page de connexion à [Horizon](https://horizon.cloud.ovh.net/auth/login/) et renseignez les [identifiants OpenStack](/guides/public-cloud/cross-functional/create-and-delete-a-user) préalablement créés, puis cliquez sur <code className="action">Connect</code>.

    Si vous avez déployé des instances dans différentes régions, assurez-vous d’être dans la bonne région. Vous pouvez le vérifier en haut à gauche dans l’interface Horizon.

    <img className="thumbnail" alt="horizon interface" src="/images/public-cloud/compute/suspend-or-pause-an-instance/firstaccesshorizon.png" loading="lazy" />

    Cliquez sur le menu <code className="action">Compute</code> à gauche puis sur <code className="action">Instances</code>. Sélectionnez <code className="action">Shelve Instance</code> dans la liste déroulante correspondant à l’instance.

    <img className="thumbnail" alt="instance shelve" src="/images/public-cloud/compute/suspend-or-pause-an-instance/shelveinstancehorizon.png" loading="lazy" />

    Une fois la procédure terminée, votre instance aura le statut *Shelved Offloaded*.

    <img className="thumbnail" alt="instance réservée" src="/images/public-cloud/compute/suspend-or-pause-an-instance/newinstancestatushorizon.png" loading="lazy" />

    Pour visualiser le snapshot, dans le menu <code className="action">Compute</code>, cliquez sur <code className="action">Images</code>.

<a name="unshelve-instance"></a>

### Faire un Unshelve d'une instance

Cette option réactive votre instance pour continuer à l’utiliser. Veuillez noter qu’une fois cette opération effectuée, la facturation reprendra normalement.

:::danger
**Actions sur le snapshot**

Toute action sur le snapshot autre que la réactivation (*unshelve*) peut être très dangereuse pour votre infrastructure en cas de mauvaise utilisation. Lorsqu’une instance est « réactivée » (*unshelved*), le snapshot est automatiquement supprimé. Il est déconseillé de déployer une nouvelle instance à partir d’un snapshot créé suite au passage en Shelve d’une instance.

OVHcloud met à votre disposition des services dont la responsabilité vous incombe. En effet, n’ayant aucun accès à ces machines, nous n’en sommes pas les administrateurs et ne pourrons vous fournir d’assistance. Il vous appartient d’en assurer la gestion logicielle et la sécurisation au quotidien. En cas de difficultés ou de doutes concernant l’administration, l’utilisation ou la sécurisation d’un serveur, nous vous recommandons de faire appel à un [prestataire spécialisé](/links/partner).
:::

    Dans la fenêtre **Unshelve de votre instance**, cliquez sur <code className="action">Confirmer</code>.

<a name="hard-stop-instance"></a>

### Faire un Hard stop (*stop*) d'une instance

Cette option arrête votre instance (action OpenStack *stop*, *Shut Off* dans Horizon). Les données du disque sont conservées, mais l'état de la mémoire est perdu : l'instance redémarre lorsque vous la relancez. Les ressources dédiées à l'instance restent réservées, y compris l'adresse IP, et l'instance reste facturée au même prix.

{/* CP-STEPS-START:turn-off-instance */}
<Tabs>
  <Tab label="Console OVHcloud">
    Dans le menu de gauche de votre projet Public Cloud, cliquez sur <code className="action">Instances</code> sous **Compute**.

    Cliquez sur le bouton <code className="action">...</code> à droite de l'instance à arrêter, puis sur <code className="action">Hard stop</code>.

    Dans la fenêtre **Hard stop de votre instance**, prenez connaissance du message et cliquez sur <code className="action">Confirmer</code>.

    Une fois l'opération terminée, le statut de votre instance apparaîtra comme **Hard stop (Shutoff)**.

    Pour **relancer** l'instance, cliquez sur le bouton <code className="action">...</code> à droite de l'instance et sélectionnez <code className="action">Lancer</code>, puis cliquez sur <code className="action">Confirmer</code> dans la fenêtre **Lancer votre instance**. Dans certains cas, vous devrez peut-être effectuer un redémarrage à froid.

    Une fois l'opération terminée, le statut de votre instance apparaîtra comme **Actif**.
  </Tab>
  <Tab label="CLI OVHcloud">
    Saisissez la commande suivante :

    ```shell
    ovhcloud cloud instance stop <instance_id>
    ```

    Pour **relancer** l'instance, saisissez la commande suivante :

    ```shell
    ovhcloud cloud instance start <instance_id>
    ```
  </Tab>
  <Tab label="API OVHcloud">
    Utilisez l'appel API suivant, où `projectId` est l'ID de votre projet Public Cloud et `instanceId` l'ID de l'instance :

    <Api version="v2" section="/publicCloud" method="POST" route={"/publicCloud/project/\{projectId\}/compute/instance/\{instanceId\}/action"} />

    Avec le corps de requête suivant :

    ```json
    {
      "type": "STOP"
    }
    ```

    Pour **reprendre** l'instance, utilisez le même appel avec le type `START` :

    ```json
    {
      "type": "START"
    }
    ```
  </Tab>
  <Tab label="API OpenStack/Nova">
    Une fois votre environnement prêt, saisissez la commande ci-dessous dans la ligne de commande :

    ```bash
    ~$ openstack server stop <UUID server>

    =========================================

    ~$ nova stop <UUID server>
    ```

    Pour **relancer** l'instance, saisissez la commande ci-dessous dans la ligne de commande :

    ```bash
    ~$ openstack server start <UUID server>

    =========================================

    ~$ nova start <UUID server>
    ```
  </Tab>
  <Tab label="Horizon">
    Dans l’interface Horizon, cliquez sur le menu <code className="action">Compute</code> à gauche puis sélectionnez <code className="action">Instances</code>. Sélectionnez <code className="action">Shut Off Instance</code> dans la liste déroulante correspondant à l’instance.

    Pour **relancer** l’instance, sélectionnez <code className="action">Start Instance</code> dans la liste déroulante correspondant à l’instance.
  </Tab>
</Tabs>

{/* CP-STEPS-END:turn-off-instance */}

<a name="stop-suspend-instance"></a>

### Suspendre (*Suspend*) une instance

Cette option suspend votre instance : l'état de la mémoire est écrit sur le disque de l'hôte, et la RAM et le CPU sont libérés sur l'hyperviseur tandis que l'allocation est conservée. À la reprise, l'état sauvegardé est restauré, comme après une mise en veille prolongée. Vous êtes facturé au même tarif.

Cette action n'est pas disponible dans la console OVHcloud : utilisez l'API OVHcloud, l'interface Horizon ou les API OpenStack/Nova.

<Tabs>
  <Tab label="API OVHcloud">
    Utilisez l'appel API suivant, où `projectId` est l'ID de votre projet Public Cloud et `instanceId` l'ID de l'instance :

    <Api version="v2" section="/publicCloud" method="POST" route={"/publicCloud/project/\{projectId\}/compute/instance/\{instanceId\}/action"} />

    Avec le corps de requête suivant :

    ```json
    {
      "type": "SUSPEND"
    }
    ```

    Pour **reprendre** l'instance, utilisez le même appel avec le type `RESUME` :

    ```json
    {
      "type": "RESUME"
    }
    ```
  </Tab>
  <Tab label="API OpenStack/Nova">
    Une fois votre environnement prêt, saisissez la commande ci-dessous dans la ligne de commande :

    ```bash
    ~$ openstack server suspend <UUID server>

    =========================================

    ~$ nova suspend <UUID server>
    ```

    Pour **reprendre** l’instance, saisissez la commande ci-dessous dans la ligne de commande :

    ```bash
    ~$ openstack server resume <UUID server>

    =========================================

    ~$ nova resume <UUID server>
    ```
  </Tab>
  <Tab label="Horizon">
    Dans l’interface Horizon, cliquez sur le menu <code className="action">Compute</code> à gauche puis sélectionnez <code className="action">Instances</code>. Sélectionnez <code className="action">Suspend Instance</code> dans la liste déroulante correspondant à l’instance.

    <img className="thumbnail" alt="suspension instance Horizon" src="/images/public-cloud/compute/suspend-or-pause-an-instance/suspendinstancehorizon.png" loading="lazy" />

    Un message de confirmation s’affiche indiquant que l’instance est suspendue.

    Pour **reprendre** l’instance, effectuez les mêmes opérations que ci-dessus. Dans la liste déroulante correspondant à l’instance, sélectionnez <code className="action">Resume Instance</code>.
  </Tab>
</Tabs>


<a name="pause-instance"></a>

### Mettre en pause une instance

Cette action n'est pas disponible dans la console OVHcloud : utilisez l'API OVHcloud, l'interface Horizon ou les API OpenStack/Nova. Elle vous permet de mettre en veille ou « geler » votre instance. L'état de la mémoire est conservé dans la RAM de l'hôte, et l'instance reprend instantanément, exactement là où elle s'était arrêtée.

<Tabs>
  <Tab label="API OVHcloud">
    Utilisez l'appel API suivant, où `projectId` est l'ID de votre projet Public Cloud et `instanceId` l'ID de l'instance :

    <Api version="v2" section="/publicCloud" method="POST" route={"/publicCloud/project/\{projectId\}/compute/instance/\{instanceId\}/action"} />

    Avec le corps de requête suivant :

    ```json
    {
      "type": "PAUSE"
    }
    ```

    Pour **reprendre** l'instance, utilisez le même appel avec le type `UNPAUSE` :

    ```json
    {
      "type": "UNPAUSE"
    }
    ```
  </Tab>
  <Tab label="API OpenStack/Nova">
    Une fois votre environnement prêt, saisissez la commande ci-dessous dans la ligne de commande :

    ```bash
    ~$ openstack server pause <UUID server>

    =========================================

    ~$ nova pause <UUID server>
    ```

    Pour **réactiver** l’instance, saisissez la commande ci-dessous dans la ligne de commande :

    ```bash
    ~$ openstack server unpause <UUID server>

    =========================================

    ~$ nova unpause <UUID server>
    ```
  </Tab>
  <Tab label="Horizon">
    Dans l’interface Horizon, cliquez sur le menu <code className="action">Compute</code> à gauche puis sélectionnez <code className="action">Instances</code>. Sélectionnez <code className="action">Pause Instance</code> dans la liste déroulante correspondant à l’instance.

    <img className="thumbnail" alt="Suspendre instance" src="/images/public-cloud/compute/suspend-or-pause-an-instance/pauseinstancehorizon.png" loading="lazy" />

    Le message de confirmation apparait indiquant la mise en pause de l’instance.

    Pour **réactiver** l’instance, effectuez les mêmes démarches que celles indiquées précédemment. Dans la liste déroulante correspondant à l’instance, sélectionnez <code className="action">Resume Instance</code>.
  </Tab>
</Tabs>
