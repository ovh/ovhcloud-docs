## Objectif

Les services Analytics vous permettent de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure Analytics et son maintien en conditions opérationnelles.
Chaque service s'appuie sur des moteurs Analytics tiers, maintenus par des sociétés ou communautés tierces telles que l'Apache Foundation, Grafana Labs ou la communauté OpenSearch.

**Ce guide explique comment résoudre les problèmes courants.**

## En pratique

### Je n'arrive pas à me connecter à mon service Analytics

Si vous ne parvenez pas à vous connecter à votre service Analytics, veuillez vérifier les points suivants :

- **Votre instance de service Analytics est bien en cours d'exécution :** lorsque vous créez une nouvelle instance de service Analytics, vous devez patienter quelques minutes avant que votre service soit prêt à l'emploi. Vous pouvez vérifier le statut de votre service depuis l'<ManagerLink to="/">espace client OVHcloud</ManagerLink>. Il doit être à l'état « running ». Notez que lorsque vous modifiez une instance de service Analytics, par exemple en ajoutant des nœuds ou en mettant à niveau la version du moteur, votre service peut passer de l'état « running » à « updating ». Pendant cette période, vous pouvez rencontrer des interruptions de connexion temporaires.
- **Au moins un utilisateur est créé :** vérifiez que vous disposez d'au moins un utilisateur créé pour votre service, avec des rôles suffisants. Si vous n'êtes pas sûr du mot de passe, créez un nouvel utilisateur avec un mot de passe nouvellement généré.
- **Au moins une adresse IP est autorisée :** par défaut, une instance de service Analytics n'est pas accessible depuis l'extérieur. Vous devez spécifier, dans l'espace client OVHcloud, au moins une adresse IP de confiance (autorisée). Vous devez autoriser l'adresse IP depuis laquelle la demande de connexion sera initiée. Astuce : pendant une courte durée, vous pouvez essayer d'autoriser un joker d'adresse IP **0.0.0.0/0**. Cette règle **autorisera toute connexion IP**. Veuillez l'utiliser avec précaution.
- **La syntaxe correcte de l'URI de service est utilisée :** veillez à copier exactement l'URI de service fournie dans votre espace client OVHcloud pour éviter les erreurs de syntaxe. Connectez-vous sur le port par défaut de chaque SGBD.
- **Le client et/ou framework de développement sont à jour :** chaque client de moteur Analytics fournit une matrice de compatibilité des versions logicielles. Veillez à suivre les prérequis officiels de votre moteur Analytics, notamment les versions des paquets Linux, les versions prises en charge des langages de programmation comme Python ou PHP, etc.

Pour vous accompagner dans votre parcours de connexion, nous détaillons les procédures exactes dans notre documentation Analytics. N'hésitez pas à parcourir les guides pour plus de détails.

### Analytics - mot de passe perdu

OVHcloud ne stocke pas les mots de passe des services Analytics. Vous ne pouvez pas récupérer un mot de passe.
Si vous avez oublié votre mot de passe, deux solutions s'offrent à vous :

- **Régénérer le mot de passe :** depuis l'<ManagerLink to="/">espace client OVHcloud</ManagerLink>, sélectionnez l'onglet <code className="action">Utilisateurs</code> de votre service Analytics. Pour l'utilisateur souhaité, vous trouverez un bouton d'action à droite de la ligne du tableau. Sélectionnez <code className="action">Régénérer le mot de passe</code>. Une fois régénéré, le nouveau mot de passe s'affichera dans votre navigateur. Copiez-le et conservez-le en lieu sûr. Astuce : cette action mettra fin à TOUTES les connexions existantes établies avec cet utilisateur. Vous devrez modifier le mot de passe dans tous les scripts utilisant cet utilisateur.
- **Créer un nouvel utilisateur :** dans l'espace client, sélectionnez l'onglet <code className="action">Utilisateurs</code> de votre service Analytics. Créez un nouvel utilisateur avec les rôles souhaités. Un mot de passe sera généré et s'affichera dans votre navigateur. Copiez-le et conservez-le en lieu sûr.

Pour vous accompagner dans la gestion des utilisateurs, n'hésitez pas à consulter nos guides Analytics pour plus d'informations.

### Analytics - manque d'espace de stockage

Nous vous recommandons de surveiller autant que possible les métriques de votre service Analytics, en particulier l'espace de stockage.
Si vous manquez d'espace de stockage, OVHcloud :

1. Envoie une alerte à votre contact principal (contact administratif) lorsque 80 % de la capacité de stockage est atteinte.
2. Place votre ou vos instances de service Analytics à l'état « DISK_FULL » et en mode lecture seule + suppression lorsque 95 % de la capacité de stockage est atteinte.
3. Remet votre instance de service Analytics en mode lecture-écriture une fois que la capacité de stockage repasse sous 80 %.

Si vous atteignez les limites de capacité de stockage, deux options s'offrent à vous :

- **Passer à des flavors supérieurs :** les services Analytics incluent du stockage dans chaque flavor de nœud. Selon le moteur Analytics, vous pouvez avoir la possibilité de passer à un flavor de nœud supérieur, offrant une capacité de stockage accrue.
- **Nettoyer les données :** supprimez les données inutiles de votre instance de service Analytics, afin d'atteindre un niveau acceptable de capacité de stockage.

### Analytics - lenteurs constatées

Plusieurs raisons peuvent provoquer un ralentissement d'une instance Analytics. Pour commencer le dépannage :

- **Vérifier le tableau de bord des métriques :** la première étape consiste à comprendre si la lenteur est ponctuelle ou périodique. De nombreuses métriques peuvent vous aider à déterminer si ce phénomène se produit chaque heure, chaque jour, ou de manière non cyclique.
- **Confronter les métriques à vos besoins :** si la lenteur constatée correspond à un niveau élevé de métriques, comme l'utilisation du CPU ou de la RAM, cela signifie que votre instance de service Analytics atteint ses performances maximales. Si vous atteignez les performances maximales, cela peut être lié à des opérations légitimes de votre côté, ou à des dysfonctionnements de code. OVHcloud n'est pas responsable des scripts utilisés.
- **Vérifier les requêtes lentes :** les principaux moteurs Analytics vous permettent d'investiguer les requêtes lentes, c'est-à-dire d'analyser les requêtes exécutées sur vos données qui prennent un temps d'exécution excessif. L'optimisation de ces requêtes peut apporter des améliorations de performance significatives.
- **Vérifier les statuts de santé OVHcloud :** OVHcloud peut rencontrer des problèmes réseau ou de service Analytics. Nous les répertorions sur [https://www.status-ovhcloud.com/](https://www.status-ovhcloud.com/).

Si la lenteur persiste, veuillez contacter notre équipe support.

### Analytics - panne ou redémarrage

**Une panne d'instance de service Analytics** peut survenir lorsque les couches inférieures (logicielles ou matérielles) ne fonctionnent pas dans des conditions optimales.

Selon la panne, l'utilisation de votre service peut être affectée par :

- une lenteur générale
- un redémarrage
- une impossibilité de se connecter au service Analytics
- une impossibilité de lire ou d'écrire des données

Pour dépanner une panne :

1. **Vérifier le statut de l'instance de service Analytics :** connectez-vous à l'<ManagerLink to="/">espace client OVHcloud</ManagerLink> et explorez vos services Analytics. Vérifiez le statut. Le statut nominal est **Running** ;
2. **Vérifier les statuts de santé OVHcloud :** en cas de panne majeure, celle-ci est répertoriée sur [https://www.status-ovhcloud.com/](https://www.status-ovhcloud.com/).

**Un redémarrage d'instance de service Analytics** peut survenir lorsque :

- Une opération de maintenance majeure est planifiée. Vérifiez votre fenêtre de maintenance directement depuis l'espace client OVHcloud.
- Une modification du cluster a été demandée. Selon le moteur Analytics et l'offre de service choisis, un redémarrage peut être nécessaire, bien que nous nous efforcions de l'éviter autant que possible. Lorsqu'une modification nécessite un redémarrage, les clients en sont informés via l'espace client OVHcloud.
