## Objectif

Le service Analytics vous permet de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure Analytics et son maintien en conditions opérationnelles.

**Ce guide explique comment restaurer une sauvegarde d'une offre de service Analytics depuis la console OVHcloud.**

Nous améliorons continuellement nos offres. Vous pouvez suivre et proposer des idées à ajouter à notre roadmap sur [https://github.com/orgs/ovh/projects/16/views/5](https://github.com/orgs/ovh/projects/16/views/5).

## Prérequis

- Un [service Analytics](/links/public-cloud/analytics) en cours d'exécution

[[cpnav:publiccloud-analytics]]

## En pratique

### Étape 1 : Sélectionner le service Analytics à partir duquel restaurer les données

{/* CP-STEPS-START:step-1-select-the-analytics-service-you-want-to-restore-data-from */}
Dans le menu de gauche de votre projet Public Cloud, cliquez sur votre produit sous **Analytics**, puis sur le nom du service à partir duquel vous souhaitez restaurer la sauvegarde.
{/* CP-STEPS-END:step-1-select-the-analytics-service-you-want-to-restore-data-from */}

### Étape 2 : Accéder à l'onglet des sauvegardes

{/* CP-STEPS-START:step-2-go-to-the-backup-tab */}
Dans la liste des onglets, cliquez sur <code className="action">Sauvegardes</code>.
{/* CP-STEPS-END:step-2-go-to-the-backup-tab */}

### Étape 3 : Sélectionner la sauvegarde à restaurer

{/* CP-STEPS-START:step-3-select-the-backup-to-restore-from */}
Sélectionnez la sauvegarde à partir de laquelle vous voulez restaurer. Pour vous aider à choisir, observez les dates auxquelles les sauvegardes ont été effectuées.

Cliquez sur le bouton <code className="action">...</code> correspondant à la sauvegarde choisie, puis sur <code className="action">Dupliquer</code> pour ouvrir le panneau **Dupliquer un cluster**. Vous pouvez aussi cliquer sur le bouton <code className="action">Dupliquer</code> au-dessus de la liste.
{/* CP-STEPS-END:step-3-select-the-backup-to-restore-from */}

### Étape 4 : Configurer le service cible

{/* CP-STEPS-START:step-4-configure-the-target-service */}
Lorsque vous restaurez une sauvegarde, vous créez un nouveau service distinct sur lequel les données de la sauvegarde seront importées. Vous pouvez configurer ce nouveau service comme vous le souhaitez dans le panneau **Dupliquer un cluster**.

#### Nom

Renseignez le **Nom du nouveau cluster**.

#### Point de restauration

Dans **Source de la copie**, choisissez le point de restauration à partir duquel le service sera dupliqué :

- **À partir d’une sauvegarde** : l'option la plus courante, restaurer à partir d'une des sauvegardes listées (champ **Sauvegarde**).
- **Point dans le temps** : si votre service prend en charge la restauration à un instant donné (consultez le guide [Sauvegardes automatiques](/guides/public-cloud/data-analytics/analytics/backups) pour plus de détails), restaurer à partir d'une date et d'une heure précises.
- **État le plus récent** : restaurer à partir des données les plus récentes.

#### Configuration du nouveau cluster

Vous ne pouvez pas changer de moteur. Dans la section **Configuration du nouveau cluster**, vous pouvez choisir la **Version**, une autre **Région**, une autre **Offre**, un **Type de nœud** plus grand, le **Nombre de nœuds** et du **Stockage** additionnel pour votre nouveau service. Le réseau du nouveau service ne peut pas être modifié dans ce panneau.

:::info
Le type de nœud et le stockage ciblés doivent être suffisamment grands pour restaurer la sauvegarde.
:::

Le prix estimé du nouveau service est affiché en bas du panneau. Cliquez maintenant sur <code className="action">Créer la copie</code> et le nouveau service sera créé. Notez qu'en fonction de la taille de la sauvegarde, la mise à disposition du service peut prendre un certain temps.
{/* CP-STEPS-END:step-4-configure-the-target-service */}

### Étape 5 : Attendre la création du service

{/* CP-STEPS-START:step-5-wait-for-service-creation */}
Il ne vous reste plus qu'à attendre que votre service soit prêt.
Ce nouveau service est désormais totalement indépendant de celui à partir duquel vous avez forké la sauvegarde. Vous pouvez supprimer l'ancien service en toute sécurité sans impacter le nouveau.

:::warning
Les restrictions IP de l'ancien service sont appliquées au nouveau, mais les utilisateurs créés sur l'ancien service ne sont pas dupliqués : recréez-les avant d'utiliser votre nouveau service. Vérifiez les restrictions IP dans l'onglet <code className="action">Configuration</code> du nouveau service.

:::

{/* CP-STEPS-END:step-5-wait-for-service-creation */}
