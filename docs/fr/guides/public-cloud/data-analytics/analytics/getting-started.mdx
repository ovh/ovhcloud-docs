## Objectif

Les services OVHcloud Public Cloud Analytics vous permettent de vous concentrer sur la création et le déploiement de vos applications cloud, pendant qu'OVHcloud prend en charge l'infrastructure analytics et son maintien en conditions opérationnelles.

**Ce guide explique comment commander un service Public Cloud Analytics via l'espace client OVHcloud, l'API, la CLI ou Terraform.**

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Accès à l'<ApiLink>API OVHcloud</ApiLink> *(méthodes API et Terraform — créez vos identifiants en consultant le guide [Premiers pas avec l'API OVHcloud](/guides/manage-and-operate/api/first-steps))*
- [Terraform](https://www.terraform.io/) installé *(méthode Terraform uniquement — testé avec la version v1.14.6)*

## En pratique

<Tabs>
  <Tab label="Depuis l'espace client OVHcloud">
    {/* CP-STEPS-START:order-analytics-instance */}
    Connectez-vous à votre <ManagerLink to="/">espace client OVHcloud</ManagerLink>, ouvrez la section <code className="action">Public Cloud</code>, puis sélectionnez votre projet. Dans la barre de navigation de gauche, sous **Databases & Analytics**, cliquez sur <code className="action">Analytics</code> pour accéder à `Kafka`, `Kafka Connect`, `Kafka MirrorMaker`, `Dashboards` ou `OpenSearch`.

    Cliquez sur <code className="action">Créer votre service d'analytics managé</code> (ou <code className="action">Créer un service</code> si votre projet contient déjà des services Analytics).

    **Étape 1 : Sélectionner votre moteur et sa version**

    Vous pouvez renommer votre service (un nom est généré automatiquement par défaut), puis sélectionner le moteur et sa version.

    **Étape 2 : Sélectionner un datacentre**

    Choisissez la région géographique du datacentre qui hébergera votre service Analytics.

    **Étape 3 : Sélectionner une offre**

    Choisissez une offre. Vous pourrez la faire évoluer après la création.

    Consultez la [page des capacités](/links/public-cloud/analytics) du type de service Analytics sélectionné pour obtenir le détail des caractéristiques de chaque offre.

    **Étape 4 : Sélectionner votre instance**

    Sélectionnez l'instance. Le nombre de nœuds est déterminé par l'offre choisie précédemment et ne peut pas être modifié dans ce cas.

    Consultez la [page des capacités](/links/public-cloud/analytics) du type de service Analytics sélectionné pour obtenir le détail du matériel et de la configuration.

    Prenez note des informations tarifaires.

    **Étape 5 : Dimensionnement**

    Du stockage additionnel peut être commandé et, selon le moteur, le nombre de nœuds de votre cluster peut être ajusté.

    **Étape 6 : Configurer vos options**

    Configurez le réseau et les IPs autorisées.

    *Connecter un réseau privé (optionnel)*

    Si vous disposez déjà d'un sous-réseau privé, sélectionnez **Réseau privé (vRack)** et choisissez-le dans le menu déroulant. Cette option peut ne pas être disponible pour le type de service sélectionné.

    Vous pouvez être redirigé pour créer un réseau privé ou un sous-réseau via les liens correspondants. Dans ce cas, vous devrez recommencer la commande du service Analytics.

    Pour des instructions détaillées, consultez le guide [Configurer vRack pour Public Cloud](/guides/public-cloud/network-services/vrack).

    *IPs autorisées*

    Ajoutez les adresses IP ou plages d'adresses autorisées à se connecter à votre service.

    :::info
    Pour des raisons de sécurité, la configuration réseau par défaut bloque toutes les connexions entrantes. Autorisez une adresse IP adaptée pour accéder à votre service Analytics.
    :::

    **Étape 7 : Récapitulatif et confirmation**

    Le panneau de droite affiche un récapitulatif de votre commande, mis à jour au fur et à mesure de vos sélections. Vérifiez-le, puis cliquez sur <code className="action">Commander</code> pour confirmer.

    Pour visualiser l'appel API ou Terraform équivalent avant de commander, cliquez sur <code className="action">Équivalent API et Terraform</code>.

    Votre service Analytics se déploie en quelques minutes. Des messages dans l'espace client OVHcloud vous informeront lorsque le service Analytics sera prêt à l'emploi.

    Pour configurer votre service après l'installation, consultez le guide *Configurer votre instance pour accepter les connexions entrantes* correspondant à votre type de service Analytics, [disponible dans notre catalogue](/links/public-cloud/databases).

    Les options de configuration varient selon le type d'Analytics. Des exemples sont disponibles dans le dépôt [public-cloud-databases-examples](https://github.com/ovh/public-cloud-databases-examples).

    {/* CP-STEPS-END:order-analytics-instance */}

  <Tab label="Depuis l'API OVHcloud">
    **Étape 1 : Rassembler les paramètres requis**

    Pour créer un service Analytics, spécifiez au minimum :

    - un _moteur_ et sa _version_ (par exemple `opensearch 2.0`)
    - l'_offre_ (par exemple `business`)
    - les _nœuds_ du cluster (par exemple 3 nœuds avec 4 cœurs, 15 Gio de mémoire, 100 Gio de disque)

    *Lister les capacités*

    L'endpoint _capabilities_ liste les valeurs autorisées pour le moteur, l'offre et le flavor.

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/{serviceName}/database/capabilities"} />

    L'appel retourne un objet listant les moteurs autorisés (avec leurs versions), les offres et les flavors.

    *Obtenir la disponibilité*

    L'endpoint _availability_ liste les combinaisons de paramètres valides. Par exemple, une offre OpenSearch `Essential` autorise les clusters à nœud unique, alors qu'une offre `Business` autorise de 3 à 8 nœuds. Choisissez la combinaison qui correspond le mieux à vos besoins.

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/{serviceName}/database/availability"} />

    **Étape 2 : Créer un service Analytics OpenSearch**

    :::warning
    La création d'un cluster entraîne des frais.
    :::

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/{serviceName}/database/opensearch"} />

    - **description** : une description lisible du service.
    - **plan** : l'offre souhaitée.
    - **version** : la version d'OpenSearch.
    - **nodesPattern** : indiquez le _flavor_, la _région_ et le nombre de nœuds.
    - **nodeslist** : laissez ce champ vide — utilisez plutôt **nodesPattern** pour des clusters de même région et même flavor.
    - **ipRestrictions** : les plages d'adresses IP autorisées à se connecter.

    :::info
    Pour des raisons de sécurité, la configuration réseau par défaut bloque toutes les connexions entrantes. Autorisez une adresse IP adaptée pour accéder à votre service Analytics.
    :::

    Pour la mise en réseau privée, indiquez également **networkId** (identifiant vRack) et **subnetId** (identifiant du sous-réseau vRack).

    L'appel retourne l'objet du cluster. Son **status** est `CREATING`. Notez l'**id** pour l'étape suivante.

    **Étape 3 : Attendre que votre service Analytics soit prêt**

    Le cluster met quelques minutes à devenir utilisable. Vérifiez son statut à l'aide de :

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/{serviceName}/database/opensearch/{clusterId}"} />

    Son **status** passe à `READY` lorsque le cluster est disponible.

    **Étape 4 : Réinitialiser le mot de passe de l'utilisateur principal**

    Listez les utilisateurs de votre cluster pour obtenir l'ID de l'utilisateur admin :

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/{serviceName}/database/opensearch/{clusterId}/user"} />

    Réinitialisez le mot de passe de l'utilisateur admin :

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/{serviceName}/database/opensearch/{clusterId}/user/{userId}/credentials/reset"} />

    Notez le nouveau mot de passe pour vous connecter au cluster.

    :::warning
    Ce mot de passe ne sera plus disponible par la suite : OVHcloud ne stocke pas les mots de passe utilisateur.
    :::

    **Étape 5 : Commencer à utiliser le cluster**

    Les informations de connexion au cluster sont disponibles dans votre espace client OVHcloud. Vous pouvez maintenant utiliser le cluster.
  </Tab>
  <Tab label="Depuis la CLI OVHcloud">
    :::info
    Toutes les commandes nécessitent soit l'option `--cloud-project <projectId>`, soit la variable d'environnement `OVH_CLOUD_PROJECT_SERVICE`, définie avec l'ID de votre projet Public Cloud.
    :::

    **Étape 1 : Rassembler les paramètres requis**

    Listez les moteurs, offres et flavors de nœuds disponibles :

    ```bash
    ovhcloud cloud reference managed-analytics list-engines --cloud-project <projectId>
    ovhcloud cloud reference managed-analytics list-plans --cloud-project <projectId>
    ovhcloud cloud reference managed-analytics list-node-flavors --cloud-project <projectId>
    ```

    **Étape 2 : Créer un service Analytics OpenSearch**

    :::warning
    La création d'un cluster entraîne des frais.
    :::

    ```bash
    ovhcloud cloud managed-analytics create \
      --cloud-project <projectId> \
      --engine opensearch \
      --version 2.0 \
      --plan business \
      --nodes-pattern.flavor db1-7 \
      --nodes-pattern.region GRA \
      --nodes-pattern.number 3 \
      --description "My OpenSearch cluster" \
      --ip-restrictions "203.0.113.0/24"
    ```

    :::info
    Pour des raisons de sécurité, la configuration réseau par défaut bloque toutes les connexions entrantes. Autorisez une adresse IP adaptée pour accéder à votre service Analytics.
    :::

    Pour la mise en réseau privée, ajoutez `--network-id <networkId>` et `--subnet-id <subnetId>`.

    **Étape 3 : Attendre que votre service Analytics soit prêt**

    ```bash
    ovhcloud cloud managed-analytics get <clusterId> --cloud-project <projectId>
    ```

    Son **status** passe à `READY` lorsque le cluster est disponible.

    **Étape 4 : Réinitialiser le mot de passe de l'utilisateur principal**

    ```bash
    # Lister les utilisateurs et récupérer l'ID de l'utilisateur admin
    ovhcloud cloud managed-analytics user list <clusterId> --cloud-project <projectId>

    # Réinitialiser le mot de passe de l'utilisateur admin
    ovhcloud cloud managed-analytics user credentials-reset <clusterId> <userId> --cloud-project <projectId>
    ```

    :::warning
    Ce mot de passe ne sera plus disponible par la suite : OVHcloud ne stocke pas les mots de passe utilisateur.
    :::

    **Étape 5 : Commencer à utiliser le cluster**

    Les informations de connexion au cluster sont disponibles dans votre espace client OVHcloud. Vous pouvez maintenant utiliser le cluster.
  </Tab>
  <Tab label="Depuis Terraform">
    **Étape 1 : Rassembler les paramètres requis pour OVHcloud**

    Le provider Terraform OVHcloud nécessite les identifiants suivants :

    - une `application_key`
    - un `application_secret`
    - une `consumer_key`

    Pour les récupérer, suivez le guide [Premiers pas avec les API OVHcloud](/guides/manage-and-operate/api/first-steps). Générez des identifiants avec les droits suivants :

    - **GET** `/cloud/project/*/database/*`
    - **POST** `/cloud/project/*/database/*`
    - **PUT** `/cloud/project/*/database/*`
    - **DELETE** `/cloud/project/*/database/*`

    - <CreateToken rights="GET=/cloud/project/*/database/*&POST=/cloud/project/*/database/*&PUT=/cloud/project/*/database/*&DELETE=/cloud/project/*/database/*">Générer les jetons de l'API OVHcloud</CreateToken>

    Le `service_name` correspond à l'ID de votre projet Public Cloud. Récupérez-le via le bouton <code className="action">Copier dans le presse-papiers</code> dans la section Public Cloud.

    **Étape 2 : Rassembler les paramètres requis**

    Pour créer un nouveau cluster OpenSearch, spécifiez au minimum :

    - le _moteur_ (par exemple `opensearch`)
    - la _version_ (par exemple `3.3`)
    - la _région_ (par exemple `EU-WEST-PAR`)
    - l'_offre_ (par exemple `production`)
    - le _flavor_ (par exemple `b3-8`)

    **Étape 3 : Créer les fichiers Terraform**

    Créez un fichier `main.tf` :

    ```terraform
    terraform {
      required_providers {
        ovh = {
          source  = "ovh/ovh"
          version = ">= 2.11.0"
        }
      }
    }

    provider "ovh" {
      endpoint           = var.ovh.endpoint
      application_key    = var.ovh.application_key
      application_secret = var.ovh.application_secret
      consumer_key       = var.ovh.consumer_key
    }

    resource "ovh_cloud_project_database" "service" {
      service_name = var.product.project_id
      description  = var.product.name
      engine       = var.product.engine
      version      = var.product.version
      plan         = var.product.plan
      nodes {
        region = var.product.region
      }
      nodes {
        region = var.product.region
      }
      nodes {
        region = var.product.region
      }
      flavor = var.product.flavor
      ip_restrictions {
        ip = var.product.ip
      }
    }

    resource "ovh_cloud_project_database_opensearch_user" "analyticsuser" {
      service_name = ovh_cloud_project_database.service.service_name
      cluster_id   = ovh_cloud_project_database.service.id
      name         = var.access.name
    }
    ```

    Créez un fichier `variables.tf` :

    ```terraform
    variable "ovh" {
      type = map(string)
      default = {
        endpoint           = "ovh-eu"
        application_key    = ""
        application_secret = ""
        consumer_key       = ""
      }
    }

    variable "product" {
      type = map(string)
      default = {
        project_id = ""
        name       = ""
        engine     = ""
        region     = "EU-WEST-PAR"
        plan       = "production"
        flavor     = "b3-8"
        version    = ""
        ip         = "0.0.0.0/32"
      }
    }

    variable "access" {
      type = map(string)
      default = {
        name = "johndoe"
      }
    }
    ```

    Utilisez `ovh-eu` pour l'API OVHcloud Europe, ou `ovh-ca` pour l'Amérique du Nord.

    Créez un fichier `secrets.tfvars` avec vos valeurs réelles :

    ```terraform
    ovh = {
      endpoint           = "ovh-eu"
      application_key    = "<application_key>"
      application_secret = "<application_secret>"
      consumer_key       = "<consumer_key>"
    }

    product = {
      project_id = "<service_name>"
      name       = "opensearch-terraform"
      engine     = "opensearch"
      region     = "EU-WEST-PAR"
      plan       = "production"
      flavor     = "b3-8"
      version    = "3.3"
      ip         = "<ip_range>"
    }

    access = {
      name = "johndoe"
    }
    ```

    :::info
    Remplacez `<service_name>`, `<application_key>`, `<application_secret>`, `<consumer_key>` et `<ip_range>` par vos valeurs réelles.
    :::

    Créez un fichier `outputs.tf` :

    ```terraform
    output "cluster_uri" {
      value = ovh_cloud_project_database.service.endpoints.0.uri
    }

    output "user_name" {
      value = ovh_cloud_project_database_opensearch_user.analyticsuser.name
    }

    output "user_password" {
      value     = ovh_cloud_project_database_opensearch_user.analyticsuser.password
      sensitive = true
    }
    ```

    **Étape 4 : Exécuter**

    ```bash
    terraform init
    terraform plan -var-file=secrets.tfvars
    terraform apply -var-file=secrets.tfvars -auto-approve
    ```

    Exportez les identifiants et l'URI :

    ```bash
    export PASSWORD=$(terraform output -raw user_password)
    export USER=$(terraform output -raw user_name)
    export URI=$(terraform output -raw cluster_uri)
    ```

    Votre cluster OpenSearch est maintenant prêt.

    Un exemple pour Kafka est disponible dans le dépôt [public-cloud-databases-examples/kafka/terraform](https://github.com/ovh/public-cloud-databases-examples/tree/main/databases/kafka/terraform/hello-world).
  </Tab>
