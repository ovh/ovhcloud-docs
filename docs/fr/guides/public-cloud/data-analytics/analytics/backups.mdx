## Objectif

Cette page fournit les descriptions techniques des méthodes et routines de sauvegarde automatisée pour chaque moteur Analytics.

Nous améliorons continuellement nos offres. Vous pouvez suivre et proposer des idées à ajouter à notre roadmap sur [https://github.com/orgs/ovh/projects/16/views/5](https://github.com/orgs/ovh/projects/16/views/5).

## Méthodes de sauvegarde

- Sauvegarde quotidienne sur un site distant :

Nous sauvegardons nos services Analytics managés toutes les heures (snapshots incrémentaux), toutes les 12 heures ou toutes les 24 heures (sauvegardes complètes) — selon le produit — avec la possibilité de restaurer à partir du dernier point dans le temps, en fonction de la période de rétention de l'offre client choisie.

Que vous rencontriez un problème ou que vous souhaitiez simplement consulter vos données à une date antérieure, vous pouvez restaurer vos données à tout point dans le temps compris dans la période de rétention de l'offre client choisie.

## Sauvegarde hors site (Off-site)

### Mécanisme de réplication

Les sauvegardes sont d'abord préparées sur site, puis répliquées vers une autre région. Les données de sauvegarde sur site persistent même après la réplication vers la région distante.

### Emplacement par défaut

Les services Analytics proposent une configuration par défaut pour les sauvegardes distantes, basée sur la région où s'exécute le service :

| Emplacement du service | Emplacement de sauvegarde hors site par défaut |
|---|---|
| BHS (Beauharnois, Canada) | SBG (Strasbourg, France) |
| DE (Francfort, Allemagne) | GRA (Gravelines, France) |
| EU-WEST-PAR (Paris, France) | GRA (Gravelines, France) |
| EU-SOUTH-MIL (Milan, Italie) | GRA (Gravelines, France) |
| GRA (Gravelines, France) | SBG (Strasbourg, France) |
| SBG (Strasbourg, France) | GRA (Gravelines, France) |

### Paramètres personnalisés

L'emplacement et l'heure de sauvegarde par défaut peuvent être remplacés en configurant l'attribut backups, soit lors de la création, soit lors de la mise à jour de votre service Analytics. Par exemple, les paramètres suivants définissent GRA (Gravelines, France) et DE (Francfort, Allemagne) comme emplacements de sauvegarde et 01:00:00 comme heure de sauvegarde quotidienne :

```json
"backups": {
  "regions": ["GRA", "DE"],
  "time": "01:00:00"
}
```

Pour rappel, voici l'endpoint API pour la création d'un service Analytics :

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/kafka"} />

Remplacez `kafka` dans la route par le moteur de votre service (par exemple `opensearch` ou `grafana`).


Les paramètres de sauvegarde doivent respecter les règles suivantes :

- Le tableau `regions` accepte un ou deux éléments. Si un seul élément est spécifié, il doit correspondre à la région dans laquelle le service s'exécute. Si deux éléments sont spécifiés, l'un d'eux doit correspondre à la région dans laquelle le service s'exécute, tandis que l'autre peut être défini sur n'importe quelle autre région. Il est **recommandé** d'utiliser 2 régions pour vos sauvegardes.

## Lexique

- RPO : Recovery Point Objective
- Off-Site : dans une région différente
- On-Site : dans la même région
