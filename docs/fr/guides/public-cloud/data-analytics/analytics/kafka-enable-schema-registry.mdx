## Objectif

Apache Kafka est une plateforme open source distribuée de streaming d'événements, conçue pour le traitement de données en temps réel et à grande échelle, avec une scalabilité et une durabilité élevées ainsi qu'une faible latence.

Le Schema Registry stocke les schémas de vos messages et permet aux producteurs et aux consommateurs de s'accorder sur leur format.

Ce guide explique comment activer le Schema Registry de votre service Kafka depuis l'espace client OVHcloud ou l'API OVHcloud, et comment enregistrer un premier schéma.

## Prérequis

- Disposer d'un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Disposer d'un [service Kafka](/guides/public-cloud/data-analytics/analytics/kafka-create-cluster) [acceptant les connexions entrantes](/guides/public-cloud/data-analytics/analytics/kafka-incoming-connections) depuis votre adresse IP, avec au moins un utilisateur
- Disposer d'un accès à l'[API OVHcloud](/guides/manage-and-operate/api/first-steps) (pour les étapes via l'API)

### Récupérer le point d'accès du Schema Registry

Une fois le Schema Registry activé, un point d'accès `kafkaSchemaRegistry` est ajouté à votre service. Vous le trouvez dans la liste `endpoints` du détail du service :

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}"} />

```json
{
  "component": "kafkaSchemaRegistry",
  "domain": "kafka-xxxxxxxx-xxxxxxxxx.database.cloud.ovh.net",
  "port": 20189,
  "scheme": "https",
  "ssl": true,
  "uri": "https://<username>:<password>@kafka-xxxxxxxx-xxxxxxxxx.database.cloud.ovh.net:20189"
}
```

Le Schema Registry utilise HTTPS avec le certificat CA de votre service, ainsi que le nom et le mot de passe d'un utilisateur Kafka.

### Donner accès au Schema Registry

Un utilisateur a besoin d'une ACL Schema Registry pour lire ou enregistrer des schémas. Sans elle, chaque requête renvoie `401 Unauthorized`.

Par exemple, pour permettre à l'utilisateur `app-orders` d'enregistrer des schémas pour le subject `orders-value`, créez l'ACL suivante :

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}/schemaRegistryAcl"} />

```json
{
  "username": "app-orders",
  "resource": "Subject:orders-value",
  "permission": "schema_registry_write"
}
```

Consultez le [guide des ACL](/guides/public-cloud/data-analytics/analytics/kafka-configure-acl) pour connaître les permissions et ressources disponibles.

### Enregistrer et lister des schémas

Téléchargez le certificat CA de votre service sous le nom `ca.pem` (consultez le guide « [Se connecter à un cluster Kafka en CLI](/guides/public-cloud/data-analytics/analytics/kafka-connect-cluster-cli) »), puis enregistrez un schéma Avro pour le subject `orders-value` :

```bash
curl --cacert ca.pem -u 'app-orders:<password>' \
  -H 'Content-Type: application/vnd.schemaregistry.v1+json' \
  -X POST https://<host>:<port>/subjects/orders-value/versions \
  -d '{"schema":"{\"type\":\"record\",\"name\":\"Order\",\"fields\":[{\"name\":\"amount\",\"type\":\"int\"}]}"}'
```

Le Schema Registry renvoie l'identifiant du schéma :

```json
{"id":1}
```

Listez les subjects auxquels l'utilisateur a accès :

```bash
curl --cacert ca.pem -u 'app-orders:<password>' https://<host>:<port>/subjects
```

```json
["orders-value"]
```
