## Objectif

Apprenez à basculer votre service Analytics entre le réseau public (Internet) et un réseau privé (vRack), sans recréer le service.

## Prérequis

- Disposer d'un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud
- Disposer d'un accès à l'<ApiLink>API OVHcloud</ApiLink> (créez vos identifiants en consultant le guide « [Premiers pas avec les API OVHcloud](/guides/manage-and-operate/api/first-steps) »)
- Disposer d'un service Analytics existant, au statut `READY`
- Disposer d'un réseau privé vRack et d'un sous-réseau existants (consultez le guide « [Configuration du vRack Public Cloud](/guides/public-cloud/network-services/vrack) »)

## Points à prendre en compte

- La mise à jour du réseau déclenche une reconstruction du service, pendant laquelle celui-ci est temporairement indisponible.
- La bascule du réseau privé vers le réseau public efface les restrictions IP existantes. Reconfigurez-les dès que le service revient au statut `READY`.
- Vérifiez que votre service est au statut `READY` avant de changer de réseau. L'API rejette la requête si le service se trouve dans un autre statut (par exemple `UPDATING` ou `CREATING`).

## En pratique

### Basculer du réseau public vers un réseau privé

Pour déplacer vers un réseau privé un service Analytics actuellement sur le réseau public, envoyez une requête PUT avec les champs **networkId** (identifiant du réseau vRack) et **subnetId** (identifiant du sous-réseau vRack) :

<Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}"} />

:::info
Remplacez `kafka` dans chaque route de cette page par le moteur de votre service (par exemple `clickhouse`, `grafana`, etc.).
:::

Incluez les champs suivants dans le corps de la requête :

```json
{
  "networkId": "<private-network-uuid>",
  "subnetId": "<subnet-uuid>"
}
```

Le **status** du service passe à `UPDATING`. Surveillez-le à l'aide de l'appel API suivant :

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}"} />

Dès que le **status** revient à `READY`, votre service est accessible sur le réseau privé.

### Basculer du réseau privé vers le réseau public

Pour ramener votre service Analytics sur le réseau public, envoyez une requête PUT avec les champs **networkId** et **subnetId** définis à `null` :

<Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}"} />

Incluez les champs suivants dans le corps de la requête :

```json
{
  "networkId": null,
  "subnetId": null
}
```

:::warning
La bascule vers le réseau public efface toutes les restrictions IP existantes. Dès que le service revient au statut `READY`, reconfigurez vos IP autorisées.
:::

Le **status** du service passe à `UPDATING`. Surveillez-le comme indiqué ci-dessus, puis reconfigurez vos restrictions IP comme décrit ci-dessous.

### Reconfigurer les restrictions IP

Si la bascule a effacé vos restrictions IP, reconfigurez-les dès que le service revient au statut `READY` en envoyant une requête PUT avec le champ **ipRestrictions** :

<Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}"} />

Incluez les champs suivants dans le corps de la requête :

```json
{
  "ipRestrictions": [
    {
      "ip": "203.0.113.0/24",
      "description": "My allowed network"
    }
  ]
}
```

:::warning
Tant que les restrictions IP ne sont pas reconfigurées, aucun client ne peut se connecter à votre service. Par sécurité, la configuration réseau par défaut bloque toutes les connexions entrantes.
:::

### Vérifier la configuration réseau

Dès que le service revient au statut `READY`, vérifiez le type de réseau :

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}"} />

Le champ **networkType** de la réponse indique la configuration actuelle : `public` ou `private`.
