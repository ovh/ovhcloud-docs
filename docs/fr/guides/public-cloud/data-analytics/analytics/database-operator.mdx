## Objectif

L'opérateur de base de données Kubernetes vous permet d'autoriser automatiquement l'IP de votre cluster Kubernetes sur votre service OVHcloud Analytics.

**Ce guide explique comment installer et utiliser l'opérateur de base de données afin d'autoriser l'IP Kubernetes sur votre service.**

## Prérequis

- Accès à l'<ApiLink>API OVHcloud</ApiLink>. Créez vos identifiants à l'aide de notre guide [Premiers pas avec l'API OVHcloud](/guides/manage-and-operate/api/first-steps).
- Un [projet Public Cloud](/guides/public-cloud/cross-functional/create-a-public-cloud-project) dans votre compte OVHcloud

### Récupérer les informations de vos tokens API OVHcloud

Pour générer votre API OVHcloud, suivez notre tutoriel [Premiers pas avec les API OVHcloud](/guides/manage-and-operate/api/first-steps).

Plus précisément, vous devez générer ces identifiants via la <CreateToken rights="GET=/cloud/project/*/database/*&POST=/cloud/project/*/database/*&PUT=/cloud/project/*/database/*&DELETE=/cloud/project/*/database/*">page de génération de tokens OVHcloud</CreateToken> avec les droits suivants :

- `GET /cloud/project/*/database/*`
- `POST /cloud/project/*/database/*`
- `PUT /cloud/project/*/database/*`
- `DELETE /cloud/project/*/database/*`

## En pratique

L'opérateur de base de données Kubernetes est stocké sous la forme d'un chart Helm sur [Docker Hub](https://hub.docker.com/r/ovhcom/public-cloud-databases-operator/tags), un registre OCI.

### Valeurs Helm

La première étape consiste à créer un fichier `values.yaml`.

Remplacez les `XXXX` par les identifiants récupérés précédemment.

Notez que la valeur de la région est `ovh-eu`, `ovh-ca` ou `ovh-us`.

```yaml
ovhCredentials:
  applicationKey: XXXX
  applicationSecret: XXXX
  consumerKey: XXXX
  region: ovh-eu # ovh-eu, ovh-ca or ovh-us

namespace: ovhcloud # Your Kubernetes namespace
```

### Installation

Utilisez le gestionnaire de paquets Kubernetes [helm](https://helm.sh) ainsi que le fichier de valeurs que vous avez créé pour installer l'opérateur.

```bash
helm install -f values.yaml public-cloud-databases-operator oci://registry-1.docker.io/ovhcom/public-cloud-databases-operator --version 0.1.1
```

Cette commande crée l'opérateur, les CRD et les objets secret.

Vous pouvez trouver la dernière version du chart Helm sur [DockerHub](https://hub.docker.com/r/ovhcom/public-cloud-databases-operator/tags).

Vous pouvez vérifier que l'opérateur est correctement installé en contrôlant les Pods dans le nouveau namespace Kubernetes :

```bash
kubectl get deploy -n ovhcloud
NAME                              READY   UP-TO-DATE   AVAILABLE   AGE
public-cloud-databases-operator   1/1     1            1           60m
```

Ainsi que le secret contenant vos identifiants OVHcloud, qui doit être correctement créé :

```bash
kubectl get secret ovh-credentials -n ovhcloud
NAME              TYPE     DATA   AGE
ovh-credentials   Opaque   4      60m
```

### Créer des ressources personnalisées

Créez un objet de ressource personnalisée :

```yaml
apiVersion: cloud.ovh.net/v1alpha1
kind: Database
metadata:
  name: myanalyticsservice
  namespace: ovhcloud
spec:
  projectId: XXXX # ID of your Public Cloud project ID
  serviceId: XXX # ID of your Analytics service
```

Ou avec un sélecteur de label pour cibler vos nœuds en fonction d'un label :

```yaml
apiVersion: cloud.ovh.net/v1alpha1
kind: Database
metadata:
  name: myanalyticsservice
  namespace: ovhcloud
spec:
  projectId: XXXX # ID of your Public Cloud project ID
  serviceId: XXX #ID of your Analytics service
  labelSelector:
    matchLabels:
      LABELNAME: LABELVALUE
```

Le champ `serviceId` est facultatif. S'il n'est pas défini, l'opérateur sera exécuté sur l'ensemble des services de votre projet.

Appliquez-le au cluster :

```bash
kubectl apply -f cr.yaml
```

Vous pouvez vérifier qu'il a bien été créé à l'aide de cette commande :

```bash
kubectl kubectl -n ovhcloud get database
NAME                              AGE
public-cloud-databases-operator   59m
```

### Labels des nœuds

Vous pouvez utiliser l'étiquetage Kubernetes afin de sélectionner les nœuds spécifiques sur lesquels vous souhaitez que l'opérateur soit exécuté.

La CR créée et le nœud doivent porter le même label et la même valeur.

```bash
kubectl label nodes NODENAME1 NODENAME2 ... LABELNAME=LABELVALUE
```
