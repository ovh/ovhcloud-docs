## Objectif

Tout accès aux données d'un Lakehouse passe par un utilisateur, ses rôles et un identifiant.

**Ce guide explique comment organiser vos données en catalogues et schémas, en donner l'accès à des utilisateurs et gérer leurs identifiants.**

## Prérequis

- Un Lakehouse dans votre projet Public Cloud. Consultez le guide [Lakehouse - Premiers pas](/guides/public-cloud/data-analytics/lakehouse/lakehouse-getting-started).
- Un accès à l'<ManagerLink to="/">espace client OVHcloud</ManagerLink>.

## En pratique

Dans l'espace client OVHcloud, ouvrez votre projet Public Cloud, rendez-vous dans **Analytics** > **Lakehouse** et cliquez sur le nom de votre Lakehouse.

### Catalogues et schémas

Ouvrez l'onglet **Catalogues** pour lister les catalogues du Lakehouse.

![Onglet Catalogues avec deux catalogues](/images/guides/public-cloud/data-analytics/lakehouse/manage-access/catalogs.png)

- Pour ajouter un catalogue, cliquez sur **Ajouter un catalogue**, saisissez son nom et une description facultative, puis validez. Le nom ne pourra plus être modifié : les moteurs se connectent au catalogue par ce nom.
- Pour ajouter un schéma, cliquez sur le nom d'un catalogue, puis sur **Ajouter un schéma**.

Un catalogue ou un schéma est disponible au bout de quelques secondes.

### Utilisateurs et comptes de service

Ouvrez l'onglet **Utilisateurs** et cliquez sur **Ajouter un utilisateur**. Choisissez le type :

- **Utilisateur**, pour une personne ;
- **Compte de service**, pour une application ou un pipeline.

Un nouvel utilisateur n'a accès à aucune donnée tant que vous ne lui avez pas attribué de rôle.

### Groupes

Les groupes permettent d'attribuer des rôles une seule fois pour plusieurs utilisateurs. Ouvrez l'onglet **Groupes**, cliquez sur **Ajouter un groupe**, puis sur le nom du groupe et sur **Ajouter un membre**. Un membre reçoit tous les rôles attribués au groupe.

### Rôles

Ouvrez l'onglet **Rôles** pour voir les rôles du Lakehouse.

![Onglet Rôles avec les six rôles par défaut](/images/guides/public-cloud/data-analytics/lakehouse/manage-access/roles.png)

Les rôles par défaut sont les suivants :

| Rôle | Donne |
|---|---|
| **Lakehouse Admin** | Tous les privilèges sur les données de tous les catalogues, y compris ceux créés ensuite. |
| **Data Owner** | Lire et modifier les données de tous les catalogues, et créer, modifier et supprimer leurs tables et vues. |
| **Data Editor** | Lire et modifier les données de tous les catalogues, et créer et modifier leurs tables et vues, sans les supprimer. |
| **Data Viewer** | Lire les données et métadonnées de tous les catalogues. |
| **Metadata Viewer** | Voir les noms des schémas, tables et vues de tous les catalogues, sans lire les données. |
| **User Admin** | Aucun privilège sur les données. |

#### Attribuer un rôle

1. Dans l'onglet **Utilisateurs** ou **Groupes**, ouvrez le menu d'actions (`...`) de l'utilisateur ou du groupe et cliquez sur **Gérer les accès**.
2. Sous **Quel rôle voulez-vous donner ?**, choisissez le rôle.
3. Pour limiter un rôle par défaut à un catalogue, choisissez ce catalogue comme portée. Sinon, conservez le rôle tel qu'il est défini.
4. Cliquez sur **Attribuer le rôle**.

L'attribution est appliquée en quelques secondes. Un rôle limité à un catalogue ne donne accès qu'à ce catalogue : les identifiants émis ensuite ne couvrent que ce catalogue, et la lecture d'une table d'un autre catalogue est refusée.

#### Créer un rôle personnalisé

Quand les rôles par défaut ne conviennent pas, cliquez sur **Ajouter un rôle personnalisé** dans l'onglet **Rôles**.

![Formulaire de création d'un rôle personnalisé avec sa portée et ses actions](/images/guides/public-cloud/data-analytics/lakehouse/manage-access/role-custom.png)

Un rôle personnalisé est une liste de permissions. Pour chaque permission, choisissez :

- la **Portée** : **Tout le Lakehouse**, un **Catalogue** ou un **Schéma** ;
- les actions : **Lecture** (`BROWSE`, `SELECT`), **Écriture** (`INSERT`, `UPDATE`, `DELETE`) et **Structure** (`CREATE_TABLE`, `ALTER`, `DROP`), ou des privilèges individuels dans le détail en dessous.

Cliquez sur **Ajouter une permission** pour combiner plusieurs portées, puis sur **Créer le rôle**. L'enregistrement remplace toutes les permissions du rôle.

### Identifiants

Un identifiant connecte un outil au Lakehouse avec les droits des rôles d'un utilisateur.

Pour en créer un, ouvrez le menu d'actions (`...`) de l'utilisateur, cliquez sur **Gérer les identifiants**, puis sur **Créer un identifiant**. Choisissez :

- la **Durée de validité** : 7, 30, 60 ou 90 jours ;
- **Générer une clé d'accès S3**, uniquement pour un outil qui lit ou écrit directement les fichiers du bucket.

Le secret client et la clé secrète S3 ne sont affichés qu'une seule fois, dans la fenêtre qui suit la création. Un utilisateur peut détenir jusqu'à trois identifiants actifs.

Pour révoquer un identifiant, cliquez sur **Révoquer** sur sa ligne, ou sur **Tout révoquer** pour révoquer tous les identifiants de l'utilisateur. Un identifiant révoqué est refusé en moins d'une seconde par le point d'accès SQL et le catalogue Iceberg REST.

:::tip
Attribuez à chaque outil ou pipeline son propre compte de service et son propre identifiant. Vous pourrez ainsi révoquer un accès sans perturber les autres.
:::
