:::warning
Lakehouse est en alpha. Il n'est accessible qu'aux comptes invités au programme alpha, et ses fonctionnalités, son interface et son API peuvent évoluer.
:::

## Objectif

Lakehouse stocke vos données dans des tables Apache Iceberg sur OVHcloud Object Storage et les rend accessibles à plusieurs moteurs à la fois : le moteur SQL et la console de données fournis avec le Lakehouse, et vos propres outils (Trino, Python, DuckDB) via le catalogue Iceberg REST.

**Ce guide explique comment créer un Lakehouse, donner à un utilisateur l'accès à ses données et lancer votre première requête SQL.**

## Prérequis

- Un [projet Public Cloud](/links/public-cloud/public-cloud) dans votre compte OVHcloud.
- Un accès à l'<ManagerLink to="/">espace client OVHcloud</ManagerLink>, avec un compte invité au programme alpha de Lakehouse.

## En pratique

### Étape 1 - Créer un Lakehouse

Dans l'espace client OVHcloud, ouvrez votre projet Public Cloud, rendez-vous dans **Analytics** > **Lakehouse** et cliquez sur **Créer un Lakehouse**.

![Formulaire Créer un Lakehouse avec son nom, sa région et son premier catalogue](/images/guides/public-cloud/data-analytics/lakehouse/getting-started/lakehouse-create.png)

Remplissez le formulaire :

- **Nom** : de 3 à 63 lettres minuscules, chiffres et tirets bas, en commençant par une lettre. Le nom doit être unique dans le projet. Un nom aléatoire vous est proposé.
- **Région** : le Lakehouse et ses données sont hébergés dans cette région. Paris (EU-WEST-PAR) est une région 3-AZ.
- **Premier catalogue** : un catalogue regroupe vos tables, et les moteurs s'y connectent par son nom. Son nom suit les mêmes règles que celui du Lakehouse et ne pourra plus être modifié. Vous pourrez ajouter d'autres catalogues ensuite.

Cliquez sur **Créer le Lakehouse**. Le Lakehouse apparaît dans la liste et passe au statut **Disponible** au bout de quelques secondes.

![Liste des Lakehouses avec un Lakehouse au statut Disponible](/images/guides/public-cloud/data-analytics/lakehouse/getting-started/lakehouse-list.png)

### Étape 2 - Découvrir la page du Lakehouse

Cliquez sur le nom de votre Lakehouse. L'onglet **Vue d'ensemble** affiche son identifiant, son realm et le nom de l'en-tête du realm (`Polaris-Realm`), dont certains outils ont besoin. La section **Détails de connexion** liste les points d'accès Iceberg, S3 et SQL du Lakehouse et donne le lien vers la console de données.

![Onglet Vue d'ensemble d'un Lakehouse avec ses informations générales et ses détails de connexion](/images/guides/public-cloud/data-analytics/lakehouse/getting-started/lakehouse-overview.png)

Le panneau **Configurer votre Lakehouse**, à droite, liste les premières étapes et donne un lien vers chacune d'elles. Les étapes suivantes en reprennent le contenu.

### Étape 3 - Ajouter un schéma

Les tables sont regroupées en schémas à l'intérieur d'un catalogue. Ouvrez l'onglet **Catalogues**, cliquez sur le nom de votre catalogue puis sur **Ajouter un schéma**. Saisissez un nom, par exemple `raw`, et validez. Le schéma est disponible au bout de quelques secondes.

### Étape 4 - Créer un utilisateur et lui attribuer un rôle

Les données du Lakehouse sont accessibles via des **utilisateurs** : des personnes (type **Utilisateur**) ou des applications (type **Compte de service**). Un utilisateur n'accède qu'aux données que ses rôles autorisent.

1. Ouvrez l'onglet **Utilisateurs** et cliquez sur **Ajouter un utilisateur**. Saisissez un nom, choisissez le type et validez.
2. Sur la ligne de l'utilisateur, ouvrez le menu d'actions (`...`) et cliquez sur **Gérer les accès**.
3. Sous **Quel rôle voulez-vous donner ?**, choisissez un rôle et cliquez sur **Attribuer le rôle**. Pour créer des tables et écrire des données, choisissez **Data Owner** ; pour seulement lire les données, choisissez **Data Viewer**.

![Onglet Utilisateurs avec deux utilisateurs et un compte de service](/images/guides/public-cloud/data-analytics/lakehouse/getting-started/users.png)

Les rôles et leurs privilèges sont décrits dans le guide [Lakehouse - Gérer l'accès à vos données](/guides/public-cloud/data-analytics/lakehouse/lakehouse-manage-access).

### Étape 5 - Créer un identifiant

Un identifiant connecte vos outils au Lakehouse avec les droits des rôles de l'utilisateur, jusqu'à son expiration ou sa révocation.

1. Sur la ligne de l'utilisateur, ouvrez le menu d'actions (`...`) et cliquez sur **Gérer les identifiants**, puis sur **Créer un identifiant**.
2. Conservez le nom proposé ou saisissez le vôtre, et choisissez la **Durée de validité** : 7, 30, 60 ou 90 jours.
3. Cochez **Générer une clé d'accès S3** uniquement si un outil lit ou écrit directement les fichiers du bucket (par exemple DuckDB ou pyiceberg). Le catalogue Iceberg REST, le SQL et la console de données n'en ont pas besoin.
4. Cliquez sur **Créer**.

![Fenêtre Nouvel identifiant avec son nom, sa durée de validité et l'option de clé d'accès S3](/images/guides/public-cloud/data-analytics/lakehouse/getting-started/credential-new.png)

La fenêtre affiche ensuite l'**ID client** et le **secret client**, ainsi qu'un fichier d'environnement contenant toutes les valeurs dont vos outils ont besoin. Cliquez sur **Télécharger le .env** pour l'enregistrer.

![Identifiant créé, avec son ID client, son secret client masqué et son fichier d'environnement](/images/guides/public-cloud/data-analytics/lakehouse/getting-started/credential-created.png)

:::warning
Le secret client et la clé secrète S3 ne sont affichés qu'une seule fois. En cas de perte, créez un nouvel identifiant et révoquez l'ancien.
:::

### Étape 6 - Lancer une requête dans la console de données

Cliquez sur **Ouvrir la console de données** dans la fenêtre de l'identifiant, ou sur **Accéder à la console** dans l'onglet **Vue d'ensemble**, et connectez-vous avec l'ID client et le secret client de l'identifiant.

Dans la console de données, ouvrez **Data**, cliquez sur `+` pour commencer une nouvelle requête, choisissez le catalogue dans le sélecteur et lancez votre SQL avec **Exécuter**. Par exemple, avec un utilisateur qui a le rôle **Data Owner** :

```sql
CREATE TABLE raw.orders (
    order_id   BIGINT,
    region     VARCHAR,
    amount     DOUBLE,
    order_date DATE
);

INSERT INTO raw.orders VALUES
    (1, 'Bretagne', 120.50, DATE '2026-11-02'),
    (2, 'Occitanie', 89.90, DATE '2026-11-03');

SELECT region, count(*) FROM raw.orders GROUP BY 1;
```

![Console de données avec une requête SQL et son résultat](/images/guides/public-cloud/data-analytics/lakehouse/getting-started/data-console-sql.png)

Les tables que vous créez sont des tables Apache Iceberg standard : vous pouvez aussi les lire et les écrire depuis vos propres outils, comme décrit dans le guide [Lakehouse - Connecter vos propres outils](/guides/public-cloud/data-analytics/lakehouse/lakehouse-connect-tools).

### Supprimer un Lakehouse

Dans l'onglet **Vue d'ensemble**, cliquez sur **Supprimer** sous les informations générales. La suppression d'un Lakehouse supprime aussi ses catalogues, ses utilisateurs et ses groupes.

![Fenêtre de confirmation de la suppression d'un Lakehouse](/images/guides/public-cloud/data-analytics/lakehouse/getting-started/lakehouse-delete.png)

Un Lakehouse dont les catalogues contiennent encore des schémas ou des tables n'est supprimé qu'avec ses données : cochez **Supprimer aussi les données de tous les catalogues** pour confirmer. Cette action est irréversible.
