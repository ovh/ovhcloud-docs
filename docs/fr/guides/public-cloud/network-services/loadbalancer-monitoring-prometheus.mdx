## Objectif

Le Load Balancer Public Cloud peut être surveillé de 2 façons. Vous pouvez soit interroger une API pour obtenir des statistiques d'utilisation, soit configurer un listener Prometheus pouvant être scrapé par votre infrastructure Prometheus pour collecter des métriques.

Ce guide vous explique comment surveiller votre Load Balancer Octavia à l'aide de ces deux méthodes.

## Prérequis

- Un Load Balancer créé. Si ce n'est pas le cas, consultez le guide « [Premiers pas avec le service Load Balancer pour Public Cloud](/guides/public-cloud/network-services/getting-started-load-balancer) ».

## Instructions

### Surveillance via CLI

Le service Load Balancer agrège ces statistiques et les met à disposition via l'API OpenStack. Ces statistiques sont disponibles au niveau du Load Balancer ou du listener.

Les statistiques du Load Balancer peuvent être interrogées via le [Client OpenStack](https://docs.openstack.org/python-openstackclient/latest/). Elles incluent les métriques de tous les listeners configurés pour le Load Balancer interrogé.

```bash
$ openstack loadbalancer stats show <lb id>

+--------------------+-----------+
| Field              | Value     |
+--------------------+-----------+
| active_connections | 0         |
| bytes_in           | 2236722   |
| bytes_out          | 100973832 |
| request_errors     | 0         |
| total_connections  | 3606      |
+--------------------+-----------+
```

Les statistiques d'un listener individuel peuvent également être interrogées via le [Client OpenStack](https://docs.openstack.org/python-openstackclient/latest/).

```bash
$ openstack loadbalancer listener stats show <listener id>

+--------------------+-------+
| Field              | Value |
+--------------------+-------+
| active_connections | 0     |
| bytes_in           | 89    |
| bytes_out          | 237   |
| request_errors     | 0     |
| total_connections  | 1     |
+--------------------+-------+
```

### Surveillance avec Prometheus

Pour ajouter un endpoint Prometheus sur un Load Balancer Public Cloud, créez un listener avec le protocole `PROMETHEUS`. Cela activera l'endpoint `/metrics` qui, par défaut, écoute sur toutes les interfaces de votre Load Balancer. **Si votre Load Balancer utilise une Floating IP, l'endpoint `/metrics` sera par défaut ouvert sur Internet**. Pour éviter cela, nous recommandons de définir l'option `allowed_cidrs` afin de protéger vos métriques, par exemple avec le CIDR du sous-réseau où le Load Balancer est déployé.

Ce type de listener offre les mêmes fonctionnalités que les listeners « classiques » mais ne prend pas en charge l'association de pools ni de politiques L7. Toutes les métriques sont identifiées par l'ID d'objet Octavia (UUID) des ressources.

:::info
Actuellement, les métriques spécifiques à UDP et SCTP ne sont pas remontées via les endpoints Prometheus.

:::

#### Configurer Prometheus pour collecter vos métriques

Une fois le listener `PROMETHEUS` à l'état `ACTIVE`, vous pouvez configurer Prometheus pour collecter les métriques du Load Balancer en mettant à jour le fichier `prometheus.yml`.

```yaml
[scrape_configs]
- job_name: 'Octavia LB1'
  static_configs:
  - targets: ['192.0.2.10:9100']
```

Pour plus d'informations sur la configuration de Prometheus, consultez le [site du projet Prometheus](https://prometheus.io/).

Vous pouvez connecter [Grafana](https://grafana.com) à l'instance [Prometheus](https://prometheus.io) pour obtenir des capacités graphiques et de tableau de bord supplémentaires. Un tableau de bord Grafana pour les Load Balancers Octavia est disponible [ici](https://grafana.com/grafana/dashboards/15828-openstack-octavia-amphora-load-balancer/).

Les métriques ont le format de nommage suivant :

- Les métriques `octavia_loadbalancer_xxx` ou `octavia_memory_pool_xxx` sont globales au Load Balancer

- Les métriques `octavia_pool_xxx` sont instanciées par pool via le label &#123;pool=ID&#125;
- Les métriques `octavia_member_xxx` sont instanciées par membre via le label &#123;member=ID&#125;

|octavia_member_idle_connections_limit|Limite du nombre de connexions inactives disponibles.|
