## Objectif

Les ressources d'infrastructure peuvent être exposées à Internet via leurs propres adresses IP publiques. Dans l'univers Public Cloud, il s'agit des adresses **Basic IP**. Pour les services créés sur une telle infrastructure, il n'est cependant pas recommandé d'utiliser ces adresses IP pour exposer les services eux-mêmes.

Lorsqu’un service doit être optimisé pour son évolutivité ou son agilité, son adresse IP publique ne doit pas être liée à un serveur ou à une machine virtuelle en particulier. Dans ce cas, les adresses IP réservées séparées constituent le meilleur moyen de rendre les services accessibles au public.

Dans l'univers Public Cloud, il est possible d'utiliser soit une **Additional IP** (auparavant appelée Failover IP), soit une **Floating IP**.

Les deux services offrent une gestion flexible de l'accès public à vos services. Ils peuvent rester agnostiques en termes d'infrastructure et être mis à l'échelle ou migrés si nécessaire.

**Ce guide présente les différences entre ces trois types d'adresses IP publiques.**

## Concepts IP Public Cloud

### Basic IP

Une Basic IP est l'adresse IP publique qu'une ressource Public Cloud reçoit lorsqu'elle est attachée directement à **Ext-Net**, le réseau public géré par OVHcloud dans chaque région. C'est le moyen par défaut de donner un accès à Internet à une instance : une instance créée en **Mode Public** de mise en réseau reçoit automatiquement une Basic IP. Une passerelle (Gateway) utilise également une Basic IP pour son trafic sortant.

Une Basic IP est fournie sous la forme d'un couple d'adresses : une IPv4 et une IPv6. Chaque adresse peut être supprimée séparément ; la suppression de l'une n'entraîne pas la suppression de l'autre.

Une Basic IP est liée à la ressource pour laquelle elle a été créée. Elle ne peut pas être déplacée vers une autre instance ou un autre service réseau, et sa configuration ne peut pas être modifiée. Si vous détachez l'interface Ext-Net d'une instance, ou si vous supprimez la Basic IP, l'adresse est relâchée et ne peut pas vous être réattribuée. Pour une adresse qui doit survivre à une instance donnée, utilisez plutôt une Additional IP ou une Floating IP.

Les cas d'usage typiques sont les instances qui ont besoin d'un accès direct à Internet sans configuration supplémentaire : environnements de test et de développement, serveurs autonomes, ou instances qui utilisent également une Additional IP (qui nécessite le Mode Public).

Une Basic IP n'est pas facturée séparément : elle est incluse dans le prix de l'instance ou de la Gateway à laquelle elle appartient.

Pour plus d'informations :

- Les modes de mise en réseau Public et Privé sont décrits dans la page [Concepts - Réseau Public Cloud](/guides/public-cloud/network-services/concepts) et dans le guide [Comment créer une instance Public Cloud et s'y connecter](/guides/public-cloud/compute/getting-started#networking-modes).
- Le détachement de l'interface Ext-Net d'une instance connectée à un vRack est traité dans le guide [Configuration du vRack Public Cloud](/guides/public-cloud/network-services/vrack).
- L'IP publique de la Gateway est détaillée dans la [FAQ Public Cloud Network Services](/guides/public-cloud/network-services/faq).
- Ext-Net réserve une plage interne que vos sous-réseaux privés ne doivent pas utiliser ; consultez les [limites connues](/guides/public-cloud/network-services/known-limits#conflit-de-routage-entre-le-routeur-openstack-et-les-floating-ips).

### Additional IP (auparavant appelée Failover IP)

Ce type d’adresse IP publique est disponible pour les services de tous les univers OVHcloud concernés : le Bare Metal Cloud (pour les serveurs bare metal), le Public Cloud (avec OpenStack) ou le Hosted Private Cloud (avec VMware ou Nutanix par exemple).

Ils sont destinés à être utilisés dans des scénarios multiproduits, par exemple dans des opérations de failover ou des cas d'usage de cloud hybride. Ils sont facturés sur une base mensuelle.

Une fois qu'une adresse Additional IP est disponible dans votre espace client, elle peut être attachée/détachée ou déplacée entre les serveurs et les instances Public Cloud. Des modifications manuelles peuvent être nécessaires sur le backend pour appliquer de nouvelles configurations IP.

Veuillez noter que dans l'univers Public Cloud, les Additional IP ne peuvent être utilisées qu'avec des instances en **Mode Public** de mise en réseau (ayant des IP publiques dans le réseau externe).

Retrouvez plus d'informations sur la configuration d'adresses Additional IP dans [ce guide](/guides/public-cloud/network-services/configure-additional-ip).

### Floating IP

Ce type d’adresse IP publique est disponible uniquement pour les [services Public Cloud](https://www.ovhcloud.com/fr/public-cloud/) conçus pour les cas d’usages cloud native et notamment l’automatisation (ex : Terraform, Ansible). Ils servent à exposer une instance privée ou un service de réseau privé (un Load Balancer par exemple) sur le réseau public.

La configuration du système backend (instance/Load Balancer) lors de l'utilisation de l'adresse Floating IP est entièrement automatique (via le protocole DHCP), aucune configuration manuelle n'est nécessaire. Cependant, une passerelle est nécessaire pour mapper une adresse IP publique à une instance ou un service réseau.

Veuillez noter que les Floating IP ne peuvent être utilisées qu'avec des instances en **Mode Privé** de mise en réseau (au sein d'un réseau privé spécifique dans une région donnée).

Les Floating IP sont facturées à la seconde et à l'usage (pay-as-you-go).

Pour plus d'informations sur la configuration des Floating IP, consultez la page [Concepts - Réseau Public Cloud](/guides/public-cloud/network-services/concepts).

### Comment obtenir des adresses IP publiques dans votre espace client ?

Dans la rubrique **Network** du menu de gauche, sélectionnez <code className="action">IP Publiques</code>. Gérez ici les Additional IP et les Floating IP selon vos besoins. L'onglet <code className="action">Basic IP</code> liste les adresses Basic IP de votre projet, avec leur région, la ressource associée (instance ou Gateway) et leur statut.

Les adresses Basic IP ne se commandent pas depuis cette page : elles sont créées avec l'instance ou la Gateway à laquelle elles appartiennent.

<img className="thumbnail" alt="Concept IP" src="/images/public-cloud/network-services/concepts-02-additional-ip-vs-floating-ip/concip.png" loading="lazy" />

En fonction de votre choix, vous pouvez faire votre sélection parmi les différentes régions. D’autres options de configuration sont également disponibles.

:::warning
Les modes de tarification dépendent de l'utilisation de l'IP que vous choisissez. Une Basic IP est incluse dans le prix de son instance ou de sa Gateway, l'utilisation d'une adresse Additional IP est facturée au mois, tandis que l'utilisation d'une adresse Floating IP est facturée à la seconde.

:::
