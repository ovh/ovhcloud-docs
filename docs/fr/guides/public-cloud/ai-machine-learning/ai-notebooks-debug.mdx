## Objectif

Ce tutoriel vous donne quelques pistes pour dépanner vos notebooks en cas de problème.

## Prérequis

- un Notebook que vous souhaitez démarrer avec **AI Notebooks**
- un [conteneur Object Storage](/guides/storage-and-backup/object-storage/pcs-create-container) dans votre compte OVHcloud
- un utilisateur Public Cloud avec le rôle **Administrator** ou **AI Training Operator**

## En pratique

### Qu'est-ce qu'un AI Notebook et comment en lancer un ?

Toutes les étapes pour démarrer et travailler sur AI Notebooks sont décrites dans le guide [AI Notebooks - Getting Started](/guides/public-cloud/ai-machine-learning/ai-notebooks-definition).

### Je ne parviens pas à me connecter à mon notebook

Si vous ne parvenez pas à vous connecter à AI Notebooks, veuillez vérifier les points suivants :

- **Votre notebook est bien démarré :** pour vous connecter à votre notebook, il doit être au statut `RUNNING` ou `IN SERVICE` (couleur verte dans l'espace client OVHcloud). Si votre notebook est en cours de démarrage, patientez quelques instants le temps que vos données se synchronisent, puis vous pourrez vous connecter. Le temps de démarrage peut varier selon certains paramètres. Plus vous synchronisez de données, plus cela prendra de temps.

- **Vous disposez d'un utilisateur ou d'un token autorisé :** pour pouvoir vous connecter à votre notebook, vous devez avoir créé un utilisateur ou un token. Pour créer un nouvel utilisateur, connectez-vous à l'espace client OVHcloud et ouvrez votre projet Public Cloud. Dans le menu de gauche, cliquez sur `AI Dashboard`, dans la section `AI & Machine Learning`. Cela vous permettra de gérer et de créer des utilisateurs AI. Pour simplement accéder aux solutions AI, utilisez le rôle `AI Platform - Read Only`. Pour un usage plus avancé, incluant la gestion, sélectionnez le rôle `AI Platform - Operator`.
Pour suivre toutes les étapes en détail, veuillez vous référer à cette [documentation](/guides/public-cloud/ai-machine-learning/ai-users).

Autrement, vous pouvez générer un token autorisé directement via notre [CLI](/guides/public-cloud/ai-machine-learning/ai-cli-app-token).

### Je ne parviens pas à installer des paquets via une commande APT

AI Notebooks ne permet pas l'utilisation de `apt-get install` car vous n'êtes pas root. Vous pouvez installer vos différents paquets à l'aide de ces commandes :

1\. commande `pip` :

```console
pip install package-name
```

2\. commande `conda` :

```console
conda install package-name
```

- **Installer des paquets dans un terminal :** commencez par ouvrir un nouveau terminal.
Si vous avez choisi l'éditeur `Jupyterlab`, ouvrez un nouveau terminal : `File` > `New` > `Terminal`
Si vous avez choisi l'éditeur `VScode`, ouvrez un nouveau terminal en cliquant sur l'icône de menu > `Terminal` > `New Terminal`

Vous pouvez ensuite exécuter :

```console
pip install package-name
```

ou

```console
conda install package-name
```

directement dans votre terminal.

- **Installer des paquets directement dans une cellule de notebook :** si vous souhaitez installer un paquet directement dans une cellule de notebook, n'oubliez pas de mettre un point d'exclamation devant votre commande. Vous pourrez alors installer un paquet avec :

```console
!pip install package-name
```

ou

```console
!conda install package-name
```

Il est toujours recommandé d'installer ou de désinstaller des paquets dans un terminal, en particulier pour les autorisations. Vous pouvez autoriser (ou non) l'installation ou la désinstallation de paquets par oui ou non. Cela est impossible à faire dans une cellule de notebook.

### Je rencontre des problèmes de compatibilité entre mes paquets installés

Vérifiez la compatibilité entre le framework que vous avez choisi lors du lancement de votre notebook et le paquet que vous avez installé.

Si votre framework n'est pas compatible avec la version du paquet :

- Vous pouvez désinstaller le paquet avec une commande `pip uninstall <package_name>` ou `conda remove <package_name>`. Puis réinstallez le paquet avec une version compatible avec votre framework.

- Sinon, plusieurs versions existent pour certains frameworks. Choisissez celle qui convient le mieux à votre projet.

### Comment utiliser ma propre image Docker avec AI notebooks ?

AI Notebooks ne permet pas l'utilisation d'images Docker personnalisées. Si vous avez besoin d'un paquet ou d'un framework très spécifique, vous pouvez apporter vos propres images Docker avec OVHcloud AI Training.

### Je ne suis pas sûr(e) de la facturation des Notebooks

Vous ne payez que pour les ressources que vous utilisez et, le cas échéant, le stockage local. Consultez [cette documentation](/guides/public-cloud/ai-machine-learning/ai-notebooks-billing) pour des exemples détaillés.

### Je ne vois pas mes données synchronisées dans l'Object Storage

Lorsque vous créez un AI Notebook, nous copions vos données dans les conteneurs Object Storage attachés, à proximité de vos ressources de calcul (`CPU` et `GPU`), afin d'améliorer les performances et de réduire la latence.

:::info
Lorsque vous écrivez des données dans un volume attaché, nous attendons l'arrêt de l'AI Notebook pour resynchroniser vos données.
:::


Si vous ne parvenez pas à voir vos données synchronisées, veuillez vérifier que :

- **Votre notebook est arrêté :** pour voir vos données synchronisées dans l'Object Storage, votre notebook doit au préalable être arrêté. Le statut de votre notebook doit être arrêté (couleur rouge). Si votre notebook est en statut `STOPPING`, patientez un peu et vous pourrez voir vos données synchronisées.

- **Votre conteneur d'objets n'est pas vide :** si votre conteneur d'objets est vide, vous n'avez peut-être pas enregistré vos données au bon endroit lors de son utilisation dans votre notebook. Vérifiez comment le volume a été monté au démarrage de votre notebook.

### J'ai peut-être atteint les limites de ressources

Chaque service AI Notebooks est fourni avec un dashboard de supervision, vous permettant de surveiller de près vos consommations de calcul, de stockage et de réseau.

Pour vérifier vos métriques d'utilisation, rendez-vous dans l'espace client Public Cloud et sélectionnez AI Notebooks. Tous vos notebooks seront listés. Cliquez sur votre notebook pour consulter ses informations. Dans `Resources`, vous pouvez ensuite accéder à la supervision de vos ressources via le `Graph Dashboard`.

Veuillez noter que chaque AI Notebook est limité à une quantité maximale de CPU et de GPU. Vous pouvez vous référer au guide [Capacités et limites](/guides/public-cloud/ai-machine-learning/ai-notebooks-capabilities) d'AI Notebooks.

### Je rencontre des lenteurs

Des lenteurs peuvent survenir dans deux cas principaux : vous exécutez des tâches intensives mobilisant toutes vos ressources, ou il s'agit d'un problème du côté d'OVHcloud.

Pour le premier cas, vous pouvez vous référer à la question *« J'ai peut-être atteint les limites de ressources »*.

Pour le second cas, vous pouvez vérifier sur [OVHcloud status](https://public-cloud.status-ovhcloud.com/) si une tâche affecte notre infrastructure.

Si ce n'est pas le cas, contactez notre support.

### Puis-je installer un nouvel éditeur de notebook ?

Actuellement, vous pouvez choisir entre trois éditeurs de code en direct pour lancer et modifier votre notebook :

- VSCode
- JupyterLab
- JupyterLab Real Time (environnement collaboratif)

Vous pouvez obtenir la liste des éditeurs disponibles à l'aide de la CLI ovhai avec la commande suivante : `ovhai capabilities editor list`

Vous ne pouvez pas installer votre propre éditeur de code sur AI Notebooks.

### Je souhaite créer des notebooks personnalisés

OVHcloud AI Notebooks est fourni avec un environnement AI préinstallé, tel que TensorFlow, PyTorch ou HuggingFace, ainsi que des paquets utiles.

Mais il peut arriver que vous ayez besoin d'un paquet ou d'un notebook très spécifique.

Bien que cela ne soit pas possible avec AI Notebooks, vous pouvez apporter vos propres notebooks personnalisés avec **AI Training**.

AI Training vous permet de bénéficier de la même technologie et de la même tarification, mais vous pouvez créer des notebooks directement avec vos **propres images Docker**.

Si vous souhaitez créer et utiliser une image Docker personnalisée, vous pouvez le faire avec AI Training en suivant ce [tutoriel](/guides/public-cloud/ai-machine-learning/ai-training-build-use-custom-image).

### Quels sont les ports disponibles vers le réseau public ?

Chaque notebook expose une URL publique dont le port par défaut est `8080`. Ce port par défaut ne peut pas être modifié.

Cette URL publique commence par l'ID du notebook (rempli avec des 0 ici) et ressemble à ce qui suit :

-   https://00000000-0000-0000-0000-000000000000.notebook.gra.ai.cloud.ovh.net

Cependant, vous pouvez accéder à d'autres ports que le port `8080` par défaut en ajoutant son numéro à l'URL de votre notebook. Par exemple, si vous souhaitez accéder au port `8501` de votre notebook, vous devrez ajouter `-8501` à l'URL de votre notebook. L'URL de votre notebook pour accéder au port `8501` sera alors https://00000000-0000-0000-0000-000000000000-8501.job.gra.ai.cloud.ovh.net/

Seule la couche HTTP est accessible.

### CLI : mon notebook est au statut « failed »

- Vérifiez que vous disposez de l'autorisation de connexion à Public Cloud Object Storage (PCS) : si vous supprimez l'autorisation de connexion à PCS, la synchronisation des données échouera, tout comme le notebook.

- Vérifiez que vous avez accès aux données du volume que vous essayez de connecter à votre notebook : si vous essayez de connecter un volume (depuis PCS) sans disposer des droits d'accès, votre notebook aura le statut `failed`.

Pour le déboguer vous-même, exécutez la commande suivante dans la CLI :

```console
ovhai notebook get `<notebook_id>`
```

Vous saurez ainsi si le statut `failed` est lié à la synchronisation des données et quel volume n'a pas pu être synchronisé.

### Combien de temps puis-je utiliser mon AI Notebook ?

Un AI Notebook fonctionne en continu jusqu'à une interruption manuelle par l'utilisateur, sauf s'il dépasse **7 jours consécutifs passés à l'état RUNNING**. Il sera alors automatiquement arrêté. Vous pouvez choisir de le redémarrer automatiquement à l'aide de l'option `auto-restart` (en réglant ce paramètre sur `True`). Le notebook redémarrera alors à l'identique. Pour augmenter cette limite de 7 jours, vous devrez contacter le support afin de demander une augmentation de ce quota pour votre projet Public Cloud. Autrement, vous pouvez contacter [notre support](https://help.ovhcloud.com/csm?id=csm_get_help) pour prolonger la période de redémarrage automatique de **7** à **28 jours**, garantissant une perturbation minimale de votre travail.

### Mon notebook s'est arrêté de manière inattendue

Bien que nous fassions tout notre possible pour éviter cette situation, comme pour tout service, des interruptions peuvent survenir.

Veuillez ouvrir un ticket auprès de [notre support](https://help.ovhcloud.com/csm?id=csm_get_help).

Si votre notebook s'est arrêté de manière inattendue, cela peut être dû à un problème sur notre backend. En général, vos données distantes sont en sécurité et seront synchronisées dans Public Cloud Object Storage.

Votre stockage local éphémère sera perdu.
