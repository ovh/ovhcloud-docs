## Ce que vous pouvez faire en code

Tout ce qu'un projet Data Platform fait via son interface peut également se faire en code. Cette section s'adresse aux personnes qui développent sur la platform plutôt qu'à celles qui l'exploitent.

Les [APIs Data Platform](/guides/public-cloud/data-platform/landing-page-developers-apis) sont l'alternative programmatique à l'interface : des endpoints REST pour les buckets et pour l'Identity Access Manager, accessibles à tout utilisateur et authentifiés avec les identifiants du projet.

Trois SDKs couvrent trois usages :

| SDK | Langage | Principal contexte d'usage |
| :-- | :------: | :------------------ |
| [Custom Actions](/guides/public-cloud/data-platform/landing-page-developers-python-sdk) | Python | [Actions personnalisées](/guides/public-cloud/data-platform/dpe-actions-custom) et [notebooks Jupyter intégrés](/guides/public-cloud/data-platform/dpe-notebooks) |
| Front APP | ReactJS | Dashboards personnalisés à l'intérieur d'une application déployée |
| Front API | NodeJS | Personnalisation de l'API qu'appelle une application |

Le SDK Custom Actions est celui que la plupart des projets utilisent : il s'exécute dans les actions personnalisées, les actions PySpark personnalisées et les notebooks, et c'est ainsi qu'une tâche lit et écrit des datasets, des tables et des buckets.

:::warning
Les deux SDK Front sont en cours de remplacement. Leur documentation actuelle reste sur le site legacy jusqu'à la sortie des nouveaux. Voir [le signpost des SDK Front](/guides/public-cloud/data-platform/developers-front-sdks).
:::

L'infrastructure derrière tout cela : [Docker](https://docs.docker.com/) exécute chaque processus et composant déployé, [Python 3](https://www.python.org/downloads/) fait fonctionner les composants de traitement des données et de data science, et [NodeJS](https://nodejs.org/en/) fait fonctionner les composants API et application, ce qui importe si vous comptez développer localement contre eux.
