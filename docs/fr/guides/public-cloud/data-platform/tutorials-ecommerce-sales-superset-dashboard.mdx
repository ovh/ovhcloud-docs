## Objectif

Ce guide vous accompagne dans la transformation des lignes de commande nettoyées d'une boutique en ligne en dashboard Superset : chiffres clés, chiffre d'affaires dans le temps, produits les plus vendus, ventes par pays et fidélité des clients.

C'est la deuxième partie de [Préparer les commandes d'une boutique en ligne pour un dashboard des ventes](/guides/public-cloud/data-platform/tutorials-ecommerce-sales). Superset interroge le Lakehouse via [Trino](/guides/public-cloud/data-platform/connectors-consumers-trino) : tout le SQL de cette page est donc en **dialecte Trino**.

## Prérequis

Pour suivre ce guide, vous avez besoin de :

- La table `online_retail_ii_clean` dans le dataset `default_dataset` de votre projet, produite par l'action Custom de nettoyage de [la première partie](/guides/public-cloud/data-platform/tutorials-ecommerce-sales#étape-5--nettoyer-les-commandes).
- Une application Apache Superset connectée à votre projet. Si vous ne l'avez pas encore déployée, suivez [Déployer Apache Superset](/guides/public-cloud/data-platform/tutorials-install-apache-superset).
- Le dataset Superset `online_retail_ii_clean`, créé à l'[étape 6 de la première partie](/guides/public-cloud/data-platform/tutorials-ecommerce-sales#étape-6--connecter-superset).

## Instructions

### Étape 1 : créer les datasets clients dans SQL Lab

Les graphiques clients ont besoin d'une ligne par client ou par retour d'un client, ce qu'un graphique ne peut pas calculer à partir des lignes de commande. Vous préparez ces lignes une seule fois, avec deux requêtes enregistrées comme datasets virtuels.

#### Créer le dataset virtuel customer_summary

1. Ouvrez **SQL** > **SQL Lab**.
2. Sélectionnez votre base de données et le schéma `default_dataset`.
3. Collez la requête ci-dessous et cliquez sur **Run**.
4. Dans la barre d'outils de la requête, cliquez sur l'icône **Save or Overwrite Dataset** et enregistrez le dataset sous le nom `customer_summary`.

```sql
WITH purchase_days AS (
    SELECT DISTINCT customer_id, CAST(invoicedate AS DATE) AS purchase_day
    FROM default_dataset.online_retail_ii_clean
    WHERE customer_id IS NOT NULL
      AND invoice NOT LIKE 'C%'
),
customers AS (
    SELECT
        customer_id,
        COUNT(*)          AS purchase_days,
        MIN(purchase_day) AS first_purchase,
        MAX(purchase_day) AS last_purchase
    FROM purchase_days
    GROUP BY customer_id
)
SELECT
    customer_id,
    purchase_days,
    LEAST(purchase_days, 10)                                   AS purchase_days_capped,
    CASE WHEN purchase_days >= 2 THEN 1 ELSE 0 END             AS is_repeat,
    first_purchase,
    last_purchase,
    date_diff('day', last_purchase, DATE '2011-12-09')         AS days_since_last_purchase,
    CASE
        WHEN date_diff('day', last_purchase, DATE '2011-12-09') <= 90  THEN '1. Active (90 days)'
        WHEN date_diff('day', last_purchase, DATE '2011-12-09') <= 180 THEN '2. At risk (91 to 180 days)'
        WHEN date_diff('day', last_purchase, DATE '2011-12-09') <= 365 THEN '3. Lapsed (181 to 365 days)'
        ELSE '4. Lost (over a year)'
    END                                                        AS recency_segment
FROM customers
```

Le résultat compte une ligne par client identifié : **5 852 lignes**.

<img className="thumbnail" alt="SQL Lab avec la requête customer_summary, l'icône Save or Overwrite Dataset dans la barre d'outils de la requête et les premières des 5,85k lignes de résultat" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/superset-sql-lab-customer-summary.png" loading="lazy" />

#### Créer le dataset virtuel purchase_intervals

Recommencez les mêmes étapes avec la requête ci-dessous, et enregistrez-la sous le nom `purchase_intervals`.

```sql
WITH purchase_days AS (
    SELECT DISTINCT customer_id, CAST(invoicedate AS DATE) AS purchase_day
    FROM default_dataset.online_retail_ii_clean
    WHERE customer_id IS NOT NULL
      AND invoice NOT LIKE 'C%'
),
with_previous AS (
    SELECT
        customer_id,
        purchase_day,
        lag(purchase_day) OVER (PARTITION BY customer_id ORDER BY purchase_day) AS previous_purchase
    FROM purchase_days
)
SELECT
    customer_id,
    purchase_day,
    date_diff('day', previous_purchase, purchase_day) AS days_since_previous_purchase
FROM with_previous
WHERE previous_purchase IS NOT NULL
```

Le résultat compte une ligne par retour d'un client : **27 026 lignes**.

:::info
**Remarque :** dans SQL Lab, sélectionnez d'abord le schéma. Sans lui, Trino renvoie `Schema must be specified when session schema is not set`. Vous pouvez aussi préfixer la table, comme dans les requêtes ci-dessus : `default_dataset.online_retail_ii_clean`.
:::

Pour chaque colonne ci-dessous, cliquez sur **Add item**, puis renseignez son nom et son expression SQL. Commencez par `revenue`, la plus simple. Cliquez sur **Save** une fois les deux colonnes ajoutées.

#### Ajouter revenue

| Paramètre | Valeur |
|---|---|
| Column name | `revenue` |
| SQL expression | `quantity * price` |

`revenue` est le montant de chaque ligne de commande. Une annulation a une quantité négative, donc un montant négatif : une simple somme donne le chiffre d'affaires net. Tous les montants du dashboard reposent sur cette colonne.

### Étape 8 : créer et assembler le dashboard

1. Ouvrez **Dashboards** et cliquez sur **+ Dashboard**. Le nouveau dashboard s'ouvre en mode édition.
2. Cliquez sur son titre et renommez-le `Online store sales`.
3. Ajoutez un en-tête `Key figures`, faites glisser les quatre tuiles des chiffres clés depuis le panneau de droite et placez-les sur une même ligne.
4. Ajoutez un en-tête `Trends and breakdowns`, puis un composant d'onglets avec quatre onglets : `Customers`, `Time`, `Products` et `Geography`.
5. Faites glisser chacun des autres graphiques depuis le panneau de droite dans son onglet. Dans l'onglet *Customers*, placez les trois tuiles sur une même ligne, les deux graphiques en barres côte à côte et l'histogramme sur toute la largeur.
6. Cliquez sur **Save**.

## Ce que vous avez construit

Vous disposez d'un dashboard qui répond aux questions du responsable d'une boutique en ligne : combien la boutique vend et à combien de clients, comment les ventes évoluent au fil de l'année, quels produits et quels pays comptent, et à quelle fréquence les clients reviennent.

À partir de là, vous pouvez ajouter des filtres de dashboard sur `country` ou sur une période, ou appliquer le même pipeline à vos propres données de commandes. Pour un autre dashboard Superset construit sur la Data Platform, consultez le [cas d'usage FOCUS et Apache Superset](/guides/public-cloud/data-platform/tutorials-finops-focus-superset).
