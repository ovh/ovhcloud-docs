## Là où les données sortent du projet

Application Services est l'endroit où les données d'un projet sont exposées vers l'extérieur : sous forme d'[APIs](/guides/public-cloud/data-platform/landing-page-app-services-apis) que d'autres systèmes appellent, et sous forme d'[applications](/guides/public-cloud/data-platform/landing-page-app-services-apps) que les utilisateurs ouvrent dans un navigateur. Les deux partagent un même cycle de vie, un même modèle de ressources et une même couche d'identité, de sorte qu'ils se présentent comme un service unique.

Ce cycle de vie est build puis deploy. Modifier une API ou une application change sa source, et rien n'atteint la production tant qu'un **artifact** n'est pas construit, une image de conteneur préparée automatiquement pour ce composant, puis déployé, ce qui exécute un conteneur à partir de cette image.

<img className="thumbnail" alt="Conteneur" src="/images/public-cloud/data-platform/product/app-services/picts/container-artefact.png" loading="lazy" />

*Figure 1 : construction d'un artifact sur Data Platform*

Le déploiement est en **blue/green**. Deux environnements de production identiques existent, un seul est actif à la fois, et celui qui est actif sert tout le trafic. Basculer de l'un à l'autre maintient le temps d'indisponibilité et le risque de rollback à un niveau faible.

<img className="thumbnail" alt="Déploiement blue/green" src="/images/public-cloud/data-platform/product/app-services/picts/blue.png" loading="lazy" />

*Figure 2 : schéma d'un déploiement blue/green*

Une fois qu'un composant est déployé, des nœuds peuvent être ajoutés ou retirés, chaque nœud étant une instance de l'artifact. C'est ainsi qu'une API ou une application se scale horizontalement.

Chaque application est liée à une API déployée, et chaque API peut servir toute requête sauvegardée dans l'[Analytics Manager](/guides/public-cloud/data-platform/landing-page-analytics-manager) sous authentification IAM, de sorte que les données sortent de la platform par un unique chemin authentifié plutôt que par un accès direct à la base de données.
