## Objectif

Ce guide vous accompagne dans le chargement de deux ans de commandes d'une boutique en ligne, soit environ 1 million de lignes de commande, dans le Lakehouse, leur fusion dans une seule table et leur nettoyage avec une action Custom. Vous chargez les fichiers avec [Connectors](/guides/public-cloud/data-platform/connectors-sources-upload-files), créez les tables dans le [Lakehouse Manager](/guides/public-cloud/data-platform/lakehouse-manager-tables), puis fusionnez et nettoyez les commandes avec le [Data Processing Engine](/guides/public-cloud/data-platform/dpe-actions-load).

À la fin, vous disposerez de la table `online_retail_ii_clean`, prête à être interrogée depuis Apache Superset. La deuxième partie du guide, [Construire le dashboard des ventes dans Superset](/guides/public-cloud/data-platform/tutorials-ecommerce-sales-superset-dashboard), la transforme en dashboard des ventes.

## Prérequis

Pour suivre ce guide, vous avez besoin de :

- Un projet Data Platform. Ce guide utilise un projet nommé `ecommerce-sales`.
- Les fichiers ci-dessous : les commandes de la boutique, un fichier par année, et le script de nettoyage de l'action Custom.

| **Type** | **Nom** |
| --- | --- |
| Commandes, de décembre 2009 à décembre 2010 | <a className="rp-link" href="/images/public-cloud/data-platform/getting-further/ecommerce-sales/resources/online_retail_II_200910.xlsx" download>online_retail_II_200910.xlsx</a> |
| Commandes, de décembre 2010 à décembre 2011 | <a className="rp-link" href="/images/public-cloud/data-platform/getting-further/ecommerce-sales/resources/online_retail_II_201011.xlsx" download>online_retail_II_201011.xlsx</a> |
| Script Python de nettoyage | <a className="rp-link" href="/images/public-cloud/data-platform/getting-further/ecommerce-sales/resources/online_retail_cleaning.py" download>online_retail_cleaning.py</a> |

:::info
**À propos des données :** les commandes proviennent d'[Online Retail II](https://archive.ics.uci.edu/dataset/502/online+retail+ii), UCI Machine Learning Repository, sous licence CC BY 4.0 (DOI 10.24432/C5CG6D). L'UCI les publie dans un seul classeur, avec une feuille par année ; chaque feuille est enregistrée dans son propre fichier.
:::

Nous recommandons de d'abord terminer les [guides de démarrage](/guides/public-cloud/data-platform/landing-page-getting-started). Ce guide suppose que vous êtes à l'aise avec les principaux composants de la Data Platform.

## Instructions

### Étape 1 : charger les fichiers

1. Ouvrez **Connectors** > **Sources** et créez une nouvelle source de type *File Upload*.
2. Nommez-la `online_retail_ii`.
3. Déposez `online_retail_II_200910.xlsx` et `online_retail_II_201011.xlsx` dans la zone *Files*.
4. Cliquez sur **Create**.

<img className="thumbnail" alt="La source File Upload nommée online_retail_ii avec les deux fichiers Excel annuels ajoutés" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/connectors-file-upload.png" loading="lazy" />

### Étape 2 : analyser les fichiers

1. Ouvrez **Connectors** > **Analyzer**.
2. Sélectionnez la source `online_retail_ii`, puis le fichier `online_retail_II_200910.xlsx`.
3. Cliquez sur **Extract metadata**.
4. Faites de même pour `online_retail_II_201011.xlsx`.

L'[Analyzer](/guides/public-cloud/data-platform/connectors-analyzer-extract-metadata) détecte huit attributs : `invoice`, `stockcode`, `description`, `quantity`, `invoicedate`, `price`, `customer_id` et `country`. Vérifiez que `invoice` et `stockcode` sont détectés comme **String** : les numéros de facture comme `C489449` et les codes produit comme `85123A` ne sont pas des nombres.

<img className="thumbnail" alt="L'Analyzer qui affiche les huit attributs détectés dans online_retail_II_200910.xlsx" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/connectors-analyzer.png" loading="lazy" />

### Étape 3 : créer les tables

#### Créer une table par année

1. Ouvrez **Lakehouse Manager** > **Tables**.
2. Cliquez sur **New table** > **Create from a Connectors source**.

<img className="thumbnail" alt="Le menu New table du Lakehouse Manager avec l'option Create from a Connectors source" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/lakehouse-new-table.png" loading="lazy" />

3. Sélectionnez le fichier `online_retail_II_200910.xlsx` de la source `online_retail_ii`, puis cliquez sur **Next**.

<img className="thumbnail" alt="La sélection du fichier online_retail_II_200910.xlsx de la source online_retail_ii" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/lakehouse-create-table-from-connector.png" loading="lazy" />

4. Gardez les paramètres par défaut et cliquez sur **Create**. La table est nommée `online_retail_ii_200910`, dans le dataset `default_dataset`.

<img className="thumbnail" alt="Les paramètres par défaut de la table, avec le nom online_retail_ii_200910 et les trois options automatiques activées" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/lakehouse-create-table-settings.png" loading="lazy" />

5. Recommencez avec `online_retail_II_201011.xlsx`. La table est nommée `online_retail_ii_201011`.

Les deux tables apparaissent avec 8 attributs et environ 525k et 542k lignes.

<img className="thumbnail" alt="Les deux tables annuelles listées dans le Lakehouse Manager avec leur nombre de lignes" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/lakehouse-yearly-tables.png" loading="lazy" />

#### Créer la table de toutes les commandes

1. [Dupliquez](/guides/public-cloud/data-platform/lakehouse-manager-manage-tables#duplicate) la table `online_retail_ii_200910`. Survolez sa ligne et cliquez sur l'icône **Duplicate**.

<img className="thumbnail" alt="L'icône Duplicate sur la ligne de la table online_retail_ii_200910 dans le Lakehouse Manager" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/lakehouse-duplicate-table.png" loading="lazy" />

2. Nommez la nouvelle table `online_retail_ii`, dans le dataset `default_dataset`, et cliquez sur **Create**.
3. [Construisez](/guides/public-cloud/data-platform/lakehouse-manager-manage-tables#build-table) la table.

La table a les mêmes 8 attributs, et aucune ligne pour l'instant.

<img className="thumbnail" alt="La table vide online_retail_ii avec les mêmes 8 attributs que les tables annuelles" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/lakehouse-empty-table.png" loading="lazy" />

### Étape 4 : fusionner les deux années

#### Créer les actions Load

1. Ouvrez **Data Processing Engine** > **Actions** et cliquez sur **New action**.
2. Recherchez `load`, sélectionnez l'action *Load* et cliquez sur **Select**.

<img className="thumbnail" alt="L'action Load sélectionnée dans la liste des types d'action" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-load-action.png" loading="lazy" />

3. Renseignez l'action :

| Paramètre | Valeur |
|---|---|
| Source table | `online_retail_II_200910.xlsx` de `online_retail_ii` |
| Destination | `online_retail_ii` de `default_dataset` |
| Attributes | chaque attribut source mappé sur l'attribut de destination du même nom |

4. Cliquez sur **Create**.

<img className="thumbnail" alt="Les paramètres de l'action Load qui mappent online_retail_II_200910.xlsx sur la table online_retail_ii" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-load-action-settings.png" loading="lazy" />

5. Créez une deuxième action *Load*, avec `online_retail_II_201011.xlsx` comme source et la même destination.

La liste des actions affiche vos deux actions *Load*, à côté des deux actions générées automatiquement à la création des tables annuelles.

<img className="thumbnail" alt="La liste des actions avec les deux nouvelles actions Load et les deux actions générées" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-actions.png" loading="lazy" />

#### Exécuter les deux actions avec un workflow

1. Dans **Data Processing Engine** > **Workflows**, cliquez sur **New workflow**.
2. Nommez-le `Merge`.
3. Dans *Stage 1*, ajoutez vos deux actions *Load*.
4. Cliquez sur **Create**, puis exécutez le workflow.

<img className="thumbnail" alt="Le workflow Merge avec les deux actions Load dans Stage 1" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-workflow.png" loading="lazy" />

Le workflow prend quelques minutes. Quand son statut passe au vert, ouvrez **Lakehouse Manager** > **Tables** : `online_retail_ii` contient les lignes des deux tables annuelles, soit **1 067 371 lignes**.

<img className="thumbnail" alt="La liste des workflows avec l'exécution du workflow Merge terminée" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-workflow-list.png" loading="lazy" />

:::warning
N'exécutez le workflow `Merge` qu'une seule fois. Une nouvelle exécution peut ajouter une seconde fois les mêmes lignes de commande. Après chaque exécution, vérifiez que `online_retail_ii` contient 1 067 371 lignes.
:::

### Étape 5 : nettoyer les commandes

#### Créer la table propre

1. Dans **Lakehouse Manager** > **Tables**, dupliquez `online_retail_ii`.
2. Nommez la nouvelle table `online_retail_ii_clean` et construisez-la.

Vous avez maintenant quatre tables. `online_retail_ii_clean` a les mêmes 8 attributs et aucune ligne pour l'instant.

<img className="thumbnail" alt="Les quatre tables du guide listées dans le Lakehouse Manager" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/lakehouse-all-tables.png" loading="lazy" />

#### Créer l'action de nettoyage

1. Dans **Data Processing Engine** > **Actions**, cliquez sur **New action**.
2. Recherchez `custom`, sélectionnez l'action *Custom* et cliquez sur **Select**.

<img className="thumbnail" alt="L'action Custom sélectionnée dans la liste des types d'action" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-custom-action.png" loading="lazy" />

3. Renseignez l'action :

| Paramètre | Valeur |
|---|---|
| Action name | `online_retail_cleaning` |
| Function name | `online_retail_cleaning` |
| Development language | `Python 3.11` |
| Python requirements | `pandas` |
| File | chargez `online_retail_cleaning.py` |

4. Cliquez sur **Create**, puis exécutez l'action.

<img className="thumbnail" alt="L'action Custom online_retail_cleaning avec son nom de fonction, son langage, ses dépendances et le fichier chargé" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-cleaning-action.png" loading="lazy" />

:::info
**Remarque :** le nom de fonction est le point d'entrée du script et doit être `online_retail_cleaning`. Les autres fonctions du fichier sont des fonctions utilitaires : en choisir une comme nom de fonction renvoie `'Event' object is not subscriptable`.
:::

L'action lit `online_retail_ii`, applique les règles de nettoyage et écrit le résultat dans `online_retail_ii_clean`. Ouvrez ses logs : chaque règle indique le nombre de lignes concernées, et la dernière ligne donne le nombre de lignes écrites dans `online_retail_ii_clean` : **1 021 128 lignes**.

Les règles apparaissent dans les logs sous leur nom anglais :

| Règle | Une ligne est supprimée quand |
|---|---|
| 1. Exact duplicates | elle est identique à une autre ligne sur les 8 colonnes |
| 2. Invalid invoice number | la facture ne compte pas 6 chiffres, précédés ou non d'un `C` |
| 3. Invalid stock code | le code produit ne compte pas 5 chiffres, suivis ou non de lettres |
| 4. Missing description | la description est vide |
| 5. Inconsistent quantity | une vente n'est pas positive, ou une annulation n'est pas négative |
| 6. Zero or negative price | le prix n'est pas strictement positif |
| 7. Missing invoice date | la date est vide |

Une dernière étape, **8. Harmonized descriptions**, attribue à chaque code produit sa description la plus fréquente, pour qu'un produit n'apparaisse jamais sous deux noms.

#### Créer une action pour vider la table propre

L'action de nettoyage ajoute des lignes à `online_retail_ii_clean`. Avant de la relancer, videz la table avec une [action Delete](/guides/public-cloud/data-platform/dpe-actions-delete).

1. Cliquez sur **New action**, recherchez `delete` et sélectionnez l'action *Delete*.
2. Dans *Table list*, déplacez `online_retail_ii_clean` vers *Table to empty*.
3. Cliquez sur **Create**.

<img className="thumbnail" alt="L'action Delete avec online_retail_ii_clean dans la liste Table to empty" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-delete-action.png" loading="lazy" />

Pour nettoyer à nouveau les données, exécutez d'abord cette action *Delete*, puis `online_retail_cleaning`.

### Étape 6 : connecter Superset

Toutes les données sont maintenant prêtes dans le Lakehouse. Pour les analyser, créez une application Apache Superset :

1. Créez une connexion Trino en suivant le guide [Consumer Trino](/guides/public-cloud/data-platform/connectors-consumers-trino).
2. Créez l'application et connectez-la à Trino en suivant les étapes 1 à 3 de [Déployer Apache Superset](/guides/public-cloud/data-platform/tutorials-install-apache-superset).

#### Créer le dataset dans Superset

1. Dans Superset, ouvrez **Datasets** et cliquez sur **+ Dataset**.
2. Sélectionnez la connexion de base de données que vous avez créée, nommée `Trino DP` dans ce guide, puis le schéma `default_dataset` et la table `online_retail_ii_clean`.
3. Vérifiez les colonnes, puis cliquez sur **Create and explore dataset**.

<img className="thumbnail" alt="Le formulaire de dataset Superset avec la base de données, le schéma default_dataset et la table online_retail_ii_clean sélectionnés" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/superset-dataset-selection.png" loading="lazy" />

Chaque graphique du dashboard part ensuite de **Charts** > **+ Chart** : choisissez le dataset `online_retail_ii_clean`, puis le type de graphique.

<img className="thumbnail" alt="L'écran de création de graphique de Superset avec le dataset online_retail_ii_clean sélectionné" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/superset-charts.png" loading="lazy" />

Continuez avec [Construire le dashboard des ventes dans Superset](/guides/public-cloud/data-platform/tutorials-ecommerce-sales-superset-dashboard).

## Bon à savoir

- **Vous pouvez connecter une vraie boutique.** Ce guide utilise un jeu de données public, chargé sous forme de fichiers. Pour analyser les commandes de votre propre boutique, créez une source [Shopify](/guides/public-cloud/data-platform/connectors-sources-shopify) ou [Stripe](/guides/public-cloud/data-platform/connectors-sources-stripe) à la place de la source File Upload : dans **Connectors** > **Sources**, les deux apparaissent dans la fenêtre *New source*. Les tables et le script de nettoyage suivent alors les attributs de cette source.

<img className="thumbnail" alt="La fenêtre New source avec les connecteurs Stripe et Shopify" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/connectors-new-source-shopify-stripe.png" loading="lazy" />

## Ce que vous avez construit

Vous disposez d'une table brute qui contient chaque ligne de commande de la boutique, d'une table propre qui respecte la description du jeu de données, et d'un dataset Superset construit dessus.

La partie suivante, [Construire le dashboard des ventes dans Superset](/guides/public-cloud/data-platform/tutorials-ecommerce-sales-superset-dashboard), transforme la table propre en dashboard : chiffres clés, chiffre d'affaires dans le temps, produits les plus vendus, ventes par pays et fidélité des clients.
