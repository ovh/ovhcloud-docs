## Objectif

Lors de l'exécution d'un job de traitement de données, lorsque vous atteignez de gros volumes de données à traiter, il peut être nécessaire de filtrer l'exécution d'une action. Le *perimeter* vous permet de **définir un champ sur lequel filtrer le périmètre des données** à traiter par l'action.

<img className="thumbnail" alt="Périmètre des préférences du Data Processing Engine" src="/images/public-cloud/data-platform/product/dpe/actions/settings/picts/dpe-preferences-perimeter.png" loading="lazy" />

## 1. En fonction d'un attribut d'une table du Projet

Si vous souhaitez filtrer une action par rapport à une liste de données présentes dans la colonne [d'une table du Lakehouse Manager](/guides/public-cloud/data-platform/lakehouse-manager-tables), par exemple :

| Reference Table | Source Table | Destination Table |
|             ---          |          ---          |             ---            |
| <img className="thumbnail" alt="1. En fonction d'un attribut d'une table du Projet — Tmpdate" src="/images/public-cloud/data-platform/product/dpe/actions/settings/picts/03-tmpdate.png" loading="lazy" /> | <img className="thumbnail" alt="1. En fonction d'un attribut d'une table du Projet — Orders" src="/images/public-cloud/data-platform/product/dpe/actions/settings/picts/03-orders.png" loading="lazy" /> |  <img className="thumbnail" alt="1. En fonction d'un attribut d'une table du Projet — Aggr" src="/images/public-cloud/data-platform/product/dpe/actions/settings/picts/03-aggr.png" loading="lazy" /> |

Vous souhaitez agréger les données de l'attribut "income" contenues dans la table source "orders" dans la table de destination "aggr_date" groupées par "date_order". La table tmp_date contient une liste de dates à agréger allant du 2019-01-01 au 2019-01-03.

En activant ce mode de périmètre, un pré-stage sera créé automatiquement, dont l'objectif est de constituer la liste des valeurs de périmètre contenues dans la table tmp_date, attribut date, et filtrera l'action entre toutes les valeurs trouvées.

### Compatibilité

Cette option de périmètre est uniquement compatible avec les actions et sources suivantes :

| Types d'action | Types de source |
|          ---        |          ---          |
| Load; Aggregate; Diff; Delete_Diff; Delete; Custom | **Databases**: MySQL, PostgreSQL, SQLServer, Impala, Hive, BiqQuery, ElasticSearch, Cassandra, Redshift, Oracle |

### Configuration

Pour configurer cette option de périmètre, sélectionnez *Based on an attribute of a Project table* dans le menu déroulant "Perimeter Type".

<img className="thumbnail" alt="Configuration — P1" src="/images/public-cloud/data-platform/product/dpe/actions/settings/picts/p1.png" loading="lazy" />

Si vous utilisez l'interface en mode avancé, vous devrez ajouter les champs suivants à la configuration JSON de votre action :

```json
"perimeter": {
  "active": true,
  "type": "dwh_attributes",
  "values": "dwh/default_dataset/tmp_dates/date",
  "var_name": "date_order",
  "attribute": "date",
  "attribute_type": "map"
}
``` 

## 2. En fonction d'un ensemble de valeurs prédéfinies

Ce mode vous permet de saisir une liste de valeurs sur lesquelles filtrer un attribut de source/table.

### Compatibilité

Cette option de périmètre est uniquement compatible avec les actions et sources suivantes :

| Types d'action | Types de source |
|          ---        |          ---          |
| Load; Aggregate; Diff; Delete_Diff; Delete; Custom | **Databases**: MySQL, PostgreSQL, SQLServer, Impala, Hive, BiqQuery, ElasticSearch, Cassandra, Redshift, Oracle |

### Configuration

Pour configurer cette option de périmètre, sélectionnez *Based on predefined set* dans le menu déroulant "Perimeter Type".

<img className="thumbnail" alt="Configuration — P2" src="/images/public-cloud/data-platform/product/dpe/actions/settings/picts/p2.png" loading="lazy" />

Si vous utilisez l'interface en mode avancé, vous devrez ajouter les champs suivants à la configuration JSON de votre action :

```json
"perimeter": {
        "active": true,
        "type": "predefined_set",
        "var_name": "value_2",
        "values": [
          "10",
          "15"
        ]
      }
```

## 3. En fonction du périmètre de dates du workflow

Si vos données source possèdent un attribut de date, il est possible de filtrer le traitement de votre action par rapport aux dates définies dans votre workflow.

### Compatibilité

Cette option de périmètre est uniquement compatible avec les actions et sources suivantes :

| Types d'action | Types de source |
|          ---        |          ---          |
| Load; Aggregate; Diff; Delete_Diff; Delete; Custom | **Databases**: MySQL, PostgreSQL, SQLServer, Impala, Hive, BiqQuery, ElasticSearch, Cassandra, Redshift, Oracle; **API**: Facebook, Twitter, Google Analytics, YouTube Private, YouTube Public, LinkedIn |

### Configuration

Pour configurer cette option de périmètre, sélectionnez *Based on the date perimeter of the workflow* dans le menu déroulant "Perimeter Type".

<img className="thumbnail" alt="Configuration — P3" src="/images/public-cloud/data-platform/product/dpe/actions/settings/picts/p3.png" loading="lazy" />

Vous devez passer en mode avancé pour configurer cette option. Il vous suffit d'ajouter les champs suivants à la configuration JSON de votre action :

```json
"perimeter":{
	"active":true,
	"type":"workflow/dates",
	"var_name":"date"
}
```
Retrouvez plus de détails sur nos options *Segmentation* et *Perimeter* pour les actions DPE dans les articles **Additional Remarks** des paramètres des actions DPE.
