## Objectif

:::info
Bon à savoir : ce tutoriel fonctionne également pour vos API.
:::

## Prérequis

### Définition des droits d'accès

Dans ce tutoriel, nous allons expliquer comment donner les privilèges de lecture / écriture sur le dépôt Git pour votre application.

### Configuration du dépôt

Si vous connaissez déjà Git, et si vous avez un dépôt prêt à l'emploi, passez directement à l'étape suivante. 
Sinon, voici une liste de fournisseurs de dépôts :

- [Github](https://github.com)
- [Gitlab](https://gitlab.com)
- [Bitbucket](https://bitbucket.org)

Créer un premier dépôt est assez simple, veillez simplement à ne pas créer de dépôt public si vous souhaitez stocker une application confidentielle.

## Marche à suivre

Une fois votre dépôt configuré, rendez-vous sur l'interface de votre application afin de les lier.

Allez dans votre APP Manager et cliquez sur Edit sur l'application que vous souhaitez lier.

<img className="thumbnail" alt="Marche à suivre — Interface de l'application" src="/images/public-cloud/data-platform/product/app-manager/settings/picts/app-interface.png" loading="lazy" />

Dans le menu de gauche, allez dans vos Settings. Vous devez maintenant renseigner les champs suivants :

__Repository__ : c'est l'adresse de votre dépôt. Elle est fournie par votre fournisseur de dépôt, et vous pouvez souvent la trouver sur sa page d'accueil. Cette adresse peut être soit une URL HTTP, soit une adresse SSH (selon le mode de connexion choisi)

__SSH__ : si vous souhaitez utiliser une adresse SSH, vous devez copier la « Public Key » affichée à l'écran dans vos dépôts et comptes distants, en plus de l'adresse saisie ci-dessus. La clé SSH est générée automatiquement par votre APP Manager, vous n'avez pas besoin d'en générer une vous-même.

__HTTPS__ : c'est l'adresse HTTPS de votre dépôt. Les URL de clonage https:// sont disponibles sur tous les dépôts, publics ou privés. Dans le cas d'un dépôt privé, chaque interaction avec le dépôt nécessite de saisir un nom d'utilisateur et un mot de passe,

__Branch__ : une fois les configurations précédentes terminées, vous pouvez synchroniser les branches distantes via ce bouton, puis en sélectionner une avant de sauvegarder.

<img className="thumbnail" alt="Marche à suivre — Paramètres du dépôt Git" src="/images/public-cloud/data-platform/product/app-manager/settings/picts/git-repository-settings.png" loading="lazy" />

Une fois la configuration terminée, vous pouvez effectuer 2 nouvelles actions depuis l'écran Overview :

__Push that version__ : cela vous permet de créer une nouvelle branche sur votre dépôt Git, à partir de cette version. C'est la première étape pour initialiser votre dépôt.

__Synchronize__ : cela permet de télécharger le contenu de la branche précédemment sélectionnée, et de créer automatiquement une nouvelle version au sein de votre environnement Data Platform.

<img className="thumbnail" alt="Marche à suivre — Versions du dépôt git" src="/images/public-cloud/data-platform/product/app-manager/settings/picts/versions-git-repository.png" loading="lazy" />

### Configurer un dépôt avec une authentification SSH

Lors de la configuration de votre application, si vous sélectionnez SSH comme mode de connexion, la clé SSH requise est automatiquement fournie par votre Application Manager.
Cette clé doit être copiée / collée dans votre dépôt Git. Selon les fournisseurs, les écrans permettant d'effectuer cette action peuvent varier.

Prenons Github comme exemple, l'un des fournisseurs les plus courants.
Pour ajouter des clés SSH à un dépôt, vous devez aller dans ses « Settings ».  
<img className="thumbnail" alt="Configurer un dépôt avec une authentification SSH — Paramètres Github" src="/images/public-cloud/data-platform/product/app-manager/settings/picts/github_settings.png" loading="lazy" />

Sélectionnez « Deploy Keys », puis cliquez sur « Add deploy key ».  
Vous pouvez ici coller votre clé SSH (fournie par votre APP Manager), lui donner un nom, par exemple : Data Platform - MyFirstProject.  
Pensez à cocher « Allow write Access » afin de pouvoir utiliser la synchronisation dans les deux sens. Cette option est nécessaire pour la fonction « Push the version » évoquée au point précédent.

### Configurer un dépôt avec une authentification HTTPS

#### Authentification privée

Concernant la création d'une authentification HTTPS, il vous suffit de renseigner les champs « username » et password de votre compte (qui a accès au dépôt). À chaque synchronisation, le mot de passe sera redemandé, nous ne le stockons pas dans votre projet.

#### Authentification publique

Concernant l'authentification publique, il n'est pas nécessaire de renseigner d'informations.

Votre application est maintenant synchronisée avec le dépôt.
