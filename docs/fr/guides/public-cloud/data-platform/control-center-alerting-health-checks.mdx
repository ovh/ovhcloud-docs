## Objectif

Des alertes peuvent être définies pour surveiller les **métriques des instances déployées** sur la Platform, comme le statut des API ou l'utilisation du CPU d'un moteur de requêtes. Elles sont appelées *health check alerts* sur la Platform.

<img className="thumbnail" alt="alerts" src="/images/public-cloud/data-platform/product/cc/alerting/picts/cc-deployment-store.png" loading="lazy" />

Une alerte de health check est configurée en spécifiant une [cible](#configurer-la-cible-de-lalerte) ainsi que des [conditions de déclenchement](#configurer-les-conditions-de-déclenchement-de-lalerte) et des [options de déclenchement](#configurer-les-options-de-déclenchement-de-lalerte).

## Configurer la cible de l'alerte

Lors de la création d'une nouvelle alerte de health check, il est nécessaire de choisir le type de déploiement à surveiller. Les types suivants sont disponibles :

- [Déploiements always-up dans le Data Processing Engine](/guides/public-cloud/data-platform/dpe-jobs-preferences#always-up)
- [API](/guides/public-cloud/data-platform/landing-page-app-services-apis)
- [Applications](/guides/public-cloud/data-platform/landing-page-app-services-apps)

Si ce n'est pas déjà fait, vous devez également choisir le Projet dans lequel créer l'alerte.

<img className="thumbnail" alt="alerts" src="/images/public-cloud/data-platform/product/cc/alerting/picts/cc-deployment-new.png" loading="lazy" />

Si vous choisissez de surveiller un objet spécifique (application, API, etc.), l'alerte ne sera déclenchée que si cette instance spécifique remplit les conditions de déclenchement.  
Par exemple, dans la capture d'écran ci-dessous, l'alerte ne sera déclenchée que si l'API "public" utilise plus de 99 % de sa RAM pendant plus d'1 minute.

<img className="thumbnail" alt="alerts" src="/images/public-cloud/data-platform/product/cc/alerting/picts/cc-deployment-target-one.png" loading="lazy" />

## Configurer les conditions de déclenchement de l'alerte

Une condition de déclenchement sur une alerte est une expression logique composée d'une *metric*, d'un *operator* et d'une *value*. Plusieurs conditions peuvent être ajoutées à la même alerte : dans ce cas, elles seront combinées avec une condition *AND*. À chaque boucle d'évaluation - se produisant chaque minute - la Platform exécute l'expression définie dans chaque déclencheur d'alerte. Le statut de l'alerte passe donc à *active* si **toutes les conditions de déclenchement sont et restent vraies** pendant une durée supérieure à la [période d'attente de l'alerte](#spécifier-la-période-dattente-de-lalerte) (configurable plus loin dans le processus).

Pour ajouter une nouvelle condition de déclenchement, appuyez sur **Add** dans le panneau correspondant.

<img className="thumbnail" alt="alerts" src="/images/public-cloud/data-platform/product/cc/alerting/picts/cc-deployment-trigger-new.png" loading="lazy" />

Les déclencheurs peuvent être définis sur les métriques suivantes pour les instances déployées :

- **Status** : une alerte sera levée si la cible surveillée est indisponible (pour la valeur *DOWN*). 
  - Notez que le statut *DOWN* ne déclenchera pas d'alerte si la cible surveillée est arrêtée/redémarrée manuellement par un utilisateur
- **Utilisation du CPU** (en %) : une alerte sera levée si le CPU utilisé par la cible surveillée dépasse ou descend en dessous d'un certain seuil
- **Utilisation de la RAM** (en %) : une alerte sera levée si la mémoire utilisée par la cible surveillée dépasse ou descend en dessous d'un certain seuil
- **Détection de logs** (*bientôt disponible !*)

## Configurer les options de déclenchement de l'alerte

Les options de déclenchement permettent de préciser exactement la façon dont l'alerte est déclenchée, sur la base du déclencheur défini ci-dessus, et la façon dont les notifications sont envoyées aux abonnés.

### Spécifier la période d'attente de l'alerte

La *waiting period* est la **durée pendant laquelle les [déclencheurs](#configurer-les-conditions-de-déclenchement-de-lalerte) de l'alerte doivent rester vrais** pour que l'alerte soit effectivement déclenchée.

<img className="thumbnail" alt="alerts" src="/images/public-cloud/data-platform/product/cc/alerting/picts/cc-deployment-wait-for.png" loading="lazy" />

Ce paramètre optionnel amène la Platform à attendre une certaine durée entre le premier moment où la condition de déclenchement de l'alerte est remplie (comme une instance avec une utilisation élevée du CPU) et le moment où l'alerte est comptabilisée comme *active*.

Si cette durée est de 0 (valeur par défaut), l'alerte sera immédiatement déclenchée au statut *active* dès que toutes les conditions de déclenchement sont vraies.  
Si elle est supérieure à 0, l'alerte restera au statut *watching* jusqu'à ce qu'un nombre suffisant de boucles d'évaluation validant continuellement la condition de déclenchement soit effectué par la Platform pour atteindre cette durée d'attente, après quoi elle sera déclenchée au statut *active*

:::info
Prenons l'exemple d'une alerte sur l'utilisation du CPU > 99 % pour une API, où cette durée est fixée à 5 minutes. La première fois que le CPU dépasse le seuil de 99 %, un compte à rebours invisible de 5 minutes commence. Si le CPU reste au-dessus de 99 % pendant plus de 5 minutes, alors l'alerte passera à l'état **active**.
:::

:::info
Comme la Platform n'évalue les conditions de déclenchement que chaque minute, il peut s'écouler quelques secondes supplémentaires (jusqu'à une minute) de délai en plus de la durée d'attente avant que le système ne reconnaisse effectivement que l'alerte a été déclenchée.
:::

### Spécifier la fréquence de notification

Pour chaque alerte, il est possible :

- de notifier les abonnés **une seule fois au moment du déclenchement** (lorsque l'alerte passe à l'état *active*). Les abonnés ne seront pas notifiés à nouveau tant que l'alerte n'est pas résolue puis déclenchée à nouveau.
- de notifier les abonnés régulièrement **tant que l'alerte est active**. Vous pouvez définir la fréquence de notification par alerte.

Il est également possible d'activer les notifications de résolution. Cela enverra une notification à tous les abonnés lorsque l'alerte sera résolue - ce qui se produit automatiquement dès que la condition de déclenchement évaluée n'est plus vérifiée.
