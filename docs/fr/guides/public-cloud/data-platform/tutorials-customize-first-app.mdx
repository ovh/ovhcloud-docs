## Objectif

Ce tutoriel reprend l'application que vous avez construite dans le guide Premiers pas et lui ajoute deux éléments : un graphique qui classe vos 7 stations les plus fréquentées, et un **format de nombre** qui affiche le nombre de trajets en millions de passagers plutôt qu'en longues suites de chiffres.

Vous construisez les deux dans le **Visual Editor** du template **Mosaic**, comme dans [Exposer et visualiser vos données](/guides/public-cloud/data-platform/getting-started-expose-and-visualize), puis vous les déployez dans une nouvelle version de votre application.

## Prérequis

Pour suivre ce tutoriel, vous devez disposer de l'application `analytics` créée dans [Exposer et visualiser vos données](/guides/public-cloud/data-platform/getting-started-expose-and-visualize), avec sa version `v2` en cours d'exécution.

:::info
L'onglet *Visual Editor* n'apparaît que sur une version en cours d'exécution. Toutes les étapes ci-dessous se déroulent sur la version qui sert actuellement vos utilisateurs, et vous la copiez à la fin pour publier vos modifications.

:::

## Ce que vous allez construire

| Phase | Où | Résultat |
|---|---|---|
| 1. Déclarer un format de nombre | *Formats* dans le Visual Editor | Un format `Rides` qui affiche les valeurs en millions de passagers (`Mpax`) |
| 2. Ajouter un titre et un graphique de classement | La page *Home* de l'application | Un graphique en barres *Top 7 stations* qui utilise le format `Rides` |
| 3. Déployer une nouvelle version | **Applications & APIs** | La version `v3`, qui remplace `v2` sans interruption |

## En pratique

### Étape 1 : ouvrir le Visual Editor

Ouvrez **Applications & APIs**, puis votre application `analytics`, puis sa version `v2`, et accédez à l'onglet *Visual Editor*.

L'éditeur s'ouvre sur *Home*, la page que le template Mosaic crée dans chaque application. Elle contient deux conteneurs : *Filters* en haut, et un conteneur vide en dessous. Ce tutoriel remplit le conteneur vide. La page *Rides analytics* que vous avez construite dans le guide Premiers pas reste inchangée.

<img className="thumbnail" alt="La page Home dans le Visual Editor, avec deux conteneurs vides, Filters en haut" src="/images/public-cloud/data-platform/getting-further/customize-first-app/picts/01-home-dashboard.png" loading="lazy" />

### Étape 2 : déclarer un format de nombre

Le nombre de vos trajets se compte en millions, et un graphique qui affiche `25833640` est difficile à lire. Un format de nombre règle ce problème pour toute l'application, en une seule fois.

Cliquez sur **Formats** dans la barre d'outils. La boîte de dialogue *Number and date formats* liste les formats dont l'application dispose déjà, comme les pourcentages et les nombres abrégés.

Sous *Measures*, saisissez `Rides` dans le champ du nom et cliquez sur **Add**. Remplissez ensuite la nouvelle entrée :

| Champ | Valeur | Effet |
|---|---|---|
| Unit | `Mpax` | Ajouté après le nombre : millions de passagers |
| Multiplier | `0.000001` | Convertit un nombre de trajets en millions |
| Decimals | `2` | Arrondit à 2 décimales |

Laissez *Shorten above* et *Suffixes* vides. À côté du nom de l'entrée, un aperçu affiche une valeur d'exemple dans ce format, `1.23Mpax` : vérifiez-la avant d'enregistrer.

<img className="thumbnail" alt="L'entrée Rides dans la boîte de dialogue Number and date formats : Mpax, 0.000001, 2 décimales" src="/images/public-cloud/data-platform/getting-further/customize-first-app/picts/02-formatter-measure.png" loading="lazy" />

Cliquez sur **Save**, puis sur **Close**.

:::info
Les formats sont enregistrés dans les sources de la version, dans `config/formatter.json`, et sont partagés par tous les graphiques de l'application. Ils suivent la version lorsque vous la copiez à l'étape 5.

:::

### Étape 3 : ajouter un titre

Survolez le conteneur vide sous *Filters* et cliquez sur son bouton **+ Add**, puis sélectionnez **Basic** > **HTML**.

Le panneau *HTML options* s'ouvre à droite. Dans *HTML*, saisissez :

```html
<h1 class='text-xl'>Top 7 Stations</h1>
```

<img className="thumbnail" alt="Le titre Top 7 Stations dans le conteneur, avec le panneau HTML options ouvert" src="/images/public-cloud/data-platform/getting-further/customize-first-app/picts/03-title-block.png" loading="lazy" />

:::warning
Le contenu d'un bloc HTML est injecté tel quel. Toute personne qui peut modifier le dashboard peut exécuter un script dans la session de chaque lecteur : n'accordez donc les droits de modification qu'à des personnes de confiance.

:::

Le bouton **+ Add** du conteneur n'apparaît que lorsque votre pointeur survole le conteneur.

### Étape 4 : ajouter le graphique de classement

Cliquez à nouveau sur **+ Add** dans le même conteneur et sélectionnez **Charts** > **Bar horizontal**.

Dans l'onglet *General*, nommez le graphique `Top 7 stations`.

Ouvrez l'onglet *Data*. Laissez **Data source** sur *Query builder*, puis décrivez le classement :

- Sous *Measures*, cliquez sur **+ Add** et sélectionnez `rides` avec l'agrégation `sum`.
- Sous *Group by*, cliquez sur **+ Add** et sélectionnez `station_name`.
- Sous *Order by*, cliquez sur **+ a criterion** et sélectionnez `rides`, `descending`.
- Dans *Row limit*, saisissez `7` pour ne garder que les 7 stations les plus fréquentées.

<img className="thumbnail" alt="L'onglet Data du graphique : somme de rides par station_name, ordre décroissant, limitée à 7 lignes" src="/images/public-cloud/data-platform/getting-further/customize-first-app/picts/04-chart-data.png" loading="lazy" />

Ouvrez l'onglet *Format*. Il liste les champs du graphique. Sur la ligne `rides`, sélectionnez le format `Rides` que vous avez déclaré à l'étape 2 : l'aperçu affiche `1.23Mpax`. L'axe et les infobulles du graphique l'utilisent désormais.

<img className="thumbnail" alt="L'onglet Format du graphique, avec le format Rides sélectionné pour le champ rides" src="/images/public-cloud/data-platform/getting-further/customize-first-app/picts/05-chart-format.png" loading="lazy" />

Cliquez sur **Apply**. Le graphique interroge vos données via votre API et affiche les 7 stations les plus fréquentées, avec un axe en `Mpax`.

<img className="thumbnail" alt="Le graphique en barres Top 7 stations sous le titre, avec son axe en Mpax" src="/images/public-cloud/data-platform/getting-further/customize-first-app/picts/06-chart-added.png" loading="lazy" />

Cliquez sur **Save** dans la barre d'outils. Le compteur à côté revient à *no changes*.

<img className="thumbnail" alt="Le dashboard enregistré avec son titre et son graphique, le compteur de la barre d'outils indiquant no changes" src="/images/public-cloud/data-platform/getting-further/customize-first-app/picts/07-dashboard-saved.png" loading="lazy" />

### Étape 5 : déployer une nouvelle version

L'enregistrement écrit vos modifications dans les sources de `v2`, mais vos utilisateurs reçoivent toujours le build réalisé avant ces modifications. Pour les publier, copiez la version en cours d'exécution :

1. Revenez à la vue d'ensemble de votre application.
2. Dans la carte *Deployed version*, ouvrez le menu **…** et sélectionnez **Copy**.
3. Nommez la copie `v3`, cochez **Auto Build** et **Auto Deploy**, puis cliquez sur **CREATE**.

    <img className="thumbnail" alt="La liste Versions : v3.0.0 tout juste créée, v2.0.0 déployée et marquée Rebuild needed, v1.0.0 arrêtée" src="/images/public-cloud/data-platform/getting-further/customize-first-app/picts/08-version-copied.png" loading="lazy" />

`v2` continue de servir vos utilisateurs pendant que `v3` est construite et déployée. La Data Platform bascule sur `v3` dès que cette version est prête, puis arrête `v2`.

Le build prend quelques minutes. Pour le suivre, ouvrez l'onglet *Builds* de la version et cliquez sur l'icône des logs. La boîte de dialogue *Build Logs* affiche l'état du build, son temps d'attente dans la file et chaque étape au fur et à mesure de son exécution.

<img className="thumbnail" alt="La boîte de dialogue Build Logs de la version v3.0.0, en cours, qui affiche les premières étapes du build au fur et à mesure" src="/images/public-cloud/data-platform/getting-further/customize-first-app/picts/09-build-logs.png" loading="lazy" />

### Étape 6 : ouvrir votre application

Une fois `v3` en cours d'exécution, ouvrez votre application et connectez-vous avec **Data Platform**. La page *Home* affiche désormais le titre *Top 7 Stations* et le graphique de classement, avec ses chiffres en millions de passagers.

## Ce que vous avez construit

Votre application dispose d'un format de nombre partagé par tous ses graphiques et d'un graphique de classement sur sa page *Home*, déployés dans la version `v3` sans interruption pour vos utilisateurs. Vous pouvez réutiliser ce format dans chaque graphique qui affiche des trajets.

## Besoin de plus de flexibilité ?

Le Visual Editor est le moyen le plus rapide de construire une application. Si vous êtes développeur et recherchez un **contrôle total sur le code de votre application**, la Data Platform propose aussi des templates construits avec des frameworks front-end modernes.

Ces templates se connectent à la même API et vous permettent de construire des applications entièrement personnalisées avec votre propre workflow de développement.
