## Objectif

Pour des sources comme les réseaux sociaux qui sont spécifiques à un compte utilisateur, il est possible de configurer plusieurs comptes pour une même source dans le composant Lakehouse Manager. Vous pouvez ensuite exploiter ces comptes pour diviser une action DPE utilisant cette source en plusieurs tâches, chaque tâche récupérant les données d'un ou plusieurs comptes.

## Prérequis

Avant d'utiliser ce type de segmentation, certains points **doivent être vérifiés** :

- Vous avez déjà configuré une source dans les Connectors possédant des comptes tels que ci-dessous

### Compatibilité

Cette option de segmentation n'est compatible qu'avec les actions et sources suivantes :

| Types d'action | Types de source |
|          ---        |          ---          | 
| Load; Custom | **API**: Facebook, Twitter, Google Analytics, YouTube Private, YouTube Public, LinkedIn |

## Comment utiliser ce type de segmentation ?

Pour configurer cette option de segmentation, sélectionnez *Based on the source's accounts* dans la liste déroulante « Segmentation Type ».

<img className="thumbnail" alt="How to use this type of segmentation? — Accounts conf" src="/images/public-cloud/data-platform/getting-further/segmentation/picts/accounts-conf.png" loading="lazy" />

**Bucket size / chunksize :** définissez le nombre de comptes gérés pour chaque tâche. 
(par défaut = 1)

### Actions Load

L'[action Load source](/guides/public-cloud/data-platform/dpe-actions-load) constituera la base de la segmentation.

<img className="thumbnail" alt="source" src="/images/public-cloud/data-platform/getting-further/segmentation/picts/accounts-source.png" loading="lazy" />

### Actions Custom

Assurez-vous que la clé `params.load_from[0].source` indique l'adresse de la source : 
*dwh/SOURCE_NAME/ENDPOINT_NAME*

:::info
Reportez-vous à la capture d'écran précédente pour un exemple du mode JSON avancé.

### Autres astuces

#### Charger depuis un seul ensemble de comptes.

Vous pouvez coder en dur une liste de compte(s) à charger, en ajoutant une clé « values » comme indiqué ci-dessous.
Cela peut être utile si vous devez récupérer un historique d'un compte nouvellement créé sans récupérer toutes les données de l'ensemble des comptes.

La configuration ressemblerait à ceci :
 
```json
 "environment": {
    "params": {
      "segmentation": {
        "active": true,
        "type": "accounts",
        "values": ["account_jp","account_fr"]
        "chunksize": 1
      }
    }
  }
```

Les valeurs doivent correspondre aux **clés de compte** définies dans la source, comme vous pouvez le voir dans l'écran du premier cas d'usage (dans l'exemple : account_fr, account_jp, account_us).

si « values » n'est pas présent, le job récupérera les données de tous les comptes définis dans la source qui sont activés.

## En coulisses

Si votre action a une segmentation **basée sur les comptes de la source**,
lors de l'exécution de l'action, ou de l'action dans un workflow :

1. Le Job Controller découpe l'action en plusieurs tâches, chacune avec un compte différent (ou un ensemble de comptes, selon la configuration `chunksize`) parmi les comptes définis dans la source
1. Puis chaque **worker** exécute **chaque tâche l'une après l'autre**.  
Cela signifie qu'il n'y a aucun problème à avoir des centaines de tâches, votre action sera parallélisée en fonction du nombre de workers.
