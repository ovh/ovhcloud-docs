## Objectif

Une fois qu'une API a été créée, vous pourrez accéder à son interface de gestion. L'onglet *Overview* vous permet de gérer facilement l'ensemble du cycle de vie de votre API.

<img className="thumbnail" alt="apercu" src="/images/public-cloud/data-platform/product/api-manager/picts/api-interface-overview.png" loading="lazy" />

L'écran est divisé en 3 parties :

- Le bloc du haut (vert) affiche des **indicateurs relatifs aux ressources utilisées par l'API**. Ces indicateurs permettent par exemple de savoir s'il est nécessaire d'augmenter le nombre d'instances.

- Le bloc de gauche (jaune) indique **le statut de la version active** (en production). Certains raccourcis sont proposés sous forme de boutons selon l'état (New / Built / Deployed) de la version.

- Le bloc de droite (bleu) liste les **différentes versions de l'API**. La version active est affichée en bleu. Différentes actions sont possibles pour chaque version :
    - Synchroniser / télécharger - action dépendant du type de source du code (fichier ZIP ou dépôt GIT)
    - Dupliquer la version
    - Construire l'artefact de cette version
    - Déployer / arrêter la version
    - Ouvrir la console de construction
    - Supprimer la version - nécessite que la version n'ait pas été déployée

## Configuration des extensions

Lors de la création d'une API via le Marketplace, celle-ci est créée avec un ensemble d'extensions par défaut qui peuvent être visualisées dans l'onglet *Extensions*.

<img className="thumbnail" alt="extensions" src="/images/public-cloud/data-platform/product/api-manager/picts/extensions-overview.png" loading="lazy" />

[Voir la liste des extensions](/guides/public-cloud/data-platform/app-services-apis-extensions-list)
 
Cet écran permet de visualiser les différentes bibliothèques organisées par catégories avec la possibilité de :

- Supprimer les extensions déjà installées
- Ajouter de nouvelles extensions non encore installées sur l'API
- Configurer le package d'une extension
- Accéder à des informations complémentaires sur les bibliothèques
- Importer une extension open source ou propriétaire, spécifique à un projet ou à une organisation

:::warning
L'ajout d'une extension nécessite de recharger votre API (sur la page Overview) afin de pouvoir la construire.
:::

## Paramètres

Trois types de paramètres d'API sont configurables dans l'onglet *Settings*.

<img className="thumbnail" alt="API settings" src="/images/public-cloud/data-platform/product/api-manager/picts/settings-api.png" loading="lazy" />
 
- **Global** : fait référence aux informations globales de l'API telles que son nom, sa description et son image principale.

- **Environment Variables** : définit les variables dont l'API a besoin pour fonctionner. Celles nécessaires au bon fonctionnement de l'API et de ses différentes extensions sont renseignées automatiquement. Seules les variables spécifiques à un besoin métier sont présentées ici.

- **Domain Name System** : vous permet d'ajouter une ou plusieurs URL permettant d'accéder à l'API, en plus de celle générée par défaut. Ces URL ont pour domaine « eu.dataplatform.ovh.net » à moins que vous n'ayez ajouté un autre domaine au niveau de l'organisation.
