## Qu'est-ce que le Data Processing Engine ?

Le Data Processing Engine construit et exécute les pipelines de données d'un projet, des sources brutes jusqu'aux tables que les analystes interrogent. Il couvre l'extraction et le chargement depuis une source enregistrée, la transformation des données déjà détenues dans le projet, et la planification et le déclenchement autour des deux.

<img className="thumbnail" alt="Qu'est-ce que le Data Processing Engine ? — Homepage Data Processing Engine" src="/images/public-cloud/data-platform/product/dpe/picts/homepage-dpe.png" loading="lazy" />

Quatre objets composent le modèle :

- Une [action](/guides/public-cloud/data-platform/landing-page-dpe-actions) est une unité de travail : charger une table, l'agréger, exécuter du SQL, exécuter du Python ou du PySpark personnalisé.
- Un [workflow](/guides/public-cloud/data-platform/dpe-workflows) enchaîne des actions en étapes selon un ordre d'exécution donné.
- Un [environnement](/guides/public-cloud/data-platform/dpe-environments) est un ensemble réutilisable de paramètres d'exécution, couvrant les ressources, le périmètre, la segmentation et les variables, partagé entre actions et workflows.
- Un [job](/guides/public-cloud/data-platform/landing-page-dpe-jobs) est une exécution d'une action ou d'un workflow.

L'exécution est basée sur des jobs plutôt que continue. Lorsqu'une action ou un workflow est déclenché, la platform construit un worker avec les ressources demandées, exécute le job, puis arrête le worker, de sorte que le compute n'est facturé que pour l'exécution. Un mode d'exécution toujours actif est disponible pour les charges de travail qui ne peuvent pas attendre le provisionnement.

Chaque job s'exécute en tant que [compte de service](/guides/public-cloud/data-platform/iam-service-accounts), et les [rôles IAM](/guides/public-cloud/data-platform/iam-roles-conditions) de cette identité décident de ce que le job peut lire et écrire. Les [Notebooks](/guides/public-cloud/data-platform/dpe-notebooks) sont l'équivalent interactif : des instances Jupyter pour explorer les données avant que leur logique ne devienne une action. Pour les jobs PySpark, le [Spark History Server](/guides/public-cloud/data-platform/dpe-spark-history-server) conserve l'UI Spark des exécutions passées disponible, de sorte qu'un job terminé peut toujours être inspecté étape par étape.
