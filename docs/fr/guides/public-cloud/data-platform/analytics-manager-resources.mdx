## Objectif

L'onglet ressources vous permet de gérer le **moteur de requêtes** de votre Projet, c'est-à-dire la technologie qui alimente l'analytique SQL dans le Projet.

Il exécute les requêtes sur une ou plusieurs [tables](/guides/public-cloud/data-platform/lakehouse-manager-tables), et est capable de distribuer le traitement des requêtes sur plusieurs instances de travail.

<img className="thumbnail" alt="resources1" src="/images/public-cloud/data-platform/product/am/picts/resources-deactivated.png" loading="lazy" />

Vous pouvez activer un moteur de requêtes par Projet, afin d'utiliser les fonctionnalités avancées de l'Analytics Manager.

## Gérer le moteur de requêtes

### Aucun moteur de requêtes

Par défaut, les Projets nouvellement créés n'ont **aucun moteur de requêtes activé**. Vous pouvez l'activer manuellement sur la page des ressources.

Sans moteur de requêtes activé, vous pouvez tout de même faire ce qui suit :

- Créer et exécuter des requêtes à l'aide du [mode visuel](/guides/public-cloud/data-platform/analytics-manager-queries-visual-builder), sur un seul [dataset](/guides/public-cloud/data-platform/lakehouse-manager-datasets)
- Déployer et utiliser des [applications dans Application Services](/guides/public-cloud/data-platform/landing-page-app-services-apps)
- Vous [connecter](/guides/public-cloud/data-platform/developers-python-sdk-reference#la-fonction-connect) à vos données depuis une action du [Data Processing Engine](/guides/public-cloud/data-platform/landing-page-dpe).
- Vous connecter aux [datasets](/guides/public-cloud/data-platform/lakehouse-manager-datasets) directement depuis l'extérieur du Projet - *bientôt disponible !*

Cependant, il est impossible de faire ce qui suit sans moteur de requêtes :

- Créer et exécuter des requêtes à l'aide du [mode SQL](/guides/public-cloud/data-platform/analytics-manager-queries-sql-editor) 
- Interroger (et joindre) des données réparties sur plusieurs [datasets](/guides/public-cloud/data-platform/lakehouse-manager-datasets), ou même sur des [sources directement interrogeables](/guides/public-cloud/data-platform/connectors-sources-configure#rendre-votre-source-de-données-directement-interrogeable)
- Créer des [tableaux de bord](/guides/public-cloud/data-platform/analytics-manager-dashboards)
- Consulter l'[historique](/guides/public-cloud/data-platform/analytics-manager-history) des requêtes et les métriques détaillées d'exécution des requêtes
- Mettre en oeuvre des [permissions](/guides/public-cloud/data-platform/iam-roles-conditions) précises sur les tables et l'accès aux données qu'elles contiennent - *bientôt disponible !*

## Gérer les instances

Vous pouvez gérer le nombre d'instances de travail parallèles au sein d'un cluster Trino. Il y aura également toujours un coordinateur, qui distribue les requêtes dans le cluster.

<img className="thumbnail" alt="resources1" src="/images/public-cloud/data-platform/product/am/picts/resources-horizontal1.png" loading="lazy" />

Si vous n'avez qu'une seule instance dans votre cluster, le coordinateur sera également un worker.

<img className="thumbnail" alt="resources1" src="/images/public-cloud/data-platform/product/am/picts/resources-horizontal2.png" loading="lazy" />

Vous pouvez également mettre à l'échelle votre moteur de requêtes verticalement et lui allouer **plus de puissance de calcul** en augmentant le nombre de [Data Platform Units](/guides/public-cloud/data-platform/manage-pricing) (DPU) de chaque instance. Le DPU est une unité de capacité de traitement générale, représentant l'accès à environ *1 vCPU* et *4 Go de RAM*, selon la disponibilité du matériel.

<img className="thumbnail" alt="Gérer les instances — Ressources verticales" src="/images/public-cloud/data-platform/product/am/picts/resources-vertical.png" loading="lazy" />
