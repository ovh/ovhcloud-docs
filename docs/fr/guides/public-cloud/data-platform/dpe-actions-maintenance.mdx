## Objectif

Les utilisateurs veulent que les données se chargent presque instantanément dans leur point de consommation final, qu'il s'agisse d'une API ou d'une application de tableau de bord visuel. Pour cela, la Data Platform fonctionne avec des caches pour précalculer le résultat des requêtes ou précharger les informations générales sur le modèle de données.

Cependant, cela signifie également que le cache et les métadonnées doivent être gérés et mis à jour régulièrement au cours de vos procédures de traitement. Dans la marketplace d'actions du Data Platform Store, vous trouverez donc 3 types d'**actions de maintenance** :

- **Update Metadata** : qui met à jour les métadonnées du modèle de données.
- **Flush Cache: Analytics Manager** : qui met à jour le cache de l'[Analytics Manager](/guides/public-cloud/data-platform/landing-page-analytics-manager) pour afficher les dernières données du modèle de données.
- **Flush Cache: App Services** : qui met à jour le cache de l'[API déployée](/guides/public-cloud/data-platform/landing-page-app-services-apis) dans votre projet pour afficher le dernier résultat de chaque requête.

Ces trois actions sont idéalement exécutées à la fin d'un workflow qui affecte le modèle de données. Nous vous recommandons vivement de simplement les ajouter par défaut à la fin de chaque workflow.

## Maintenance automatisée

S'il peut être utile de choisir précisément quand ces actions sont exécutées au cours d'un workflow à des fins d'optimisation, nous comprenons que cela peut être fastidieux à gérer. Nous vous proposons donc 2 façons simples d'ajouter cette routine de maintenance à vos procédures de traitement.

### Workflow Auto Flush-all

Lorsque vous créez un nouveau Projet, nous vous conseillons de créer un workflow *_flushall* qui contient 4 actions exécutées séquentiellement en 4 étapes : Update metadata, Flush Cache: Analytics Manager, Flush Cache: App Services, puis Purge Buckets.

<img className="thumbnail" alt="Workflow Auto Flush-all — Flush all workflow" src="/images/public-cloud/data-platform/product/dpe/actions/flush-update-metas/picts/flush_all_workflow.png" loading="lazy" />

:::warning
L'action **Purge Buckets** doit être désactivée par défaut (ou ne pas être incluse si vous ne prévoyez aucune utilisation immédiate) car elle vide toutes les données actuellement stockées dans l'espace de stockage objet. Cette action doit être utilisée avec prudence, car elle supprimera **définitivement** toutes les informations archivées.
:::

### Options Auto Flush-all

Une autre façon d'exécuter cette routine de maintenance consiste simplement à activer l'option « Automatically flush all caches » pour vos workflows, située dans l'onglet préférences de votre workflow. Cela exécutera les 3 actions : Update metadata, Flush Cache: Analytics Manager, Flush Cache: App Services.

<img className="thumbnail" alt="Options Auto Flush-all — Auto flush all" src="/images/public-cloud/data-platform/product/dpe/actions/flush-update-metas/picts/auto-flush-all.png" loading="lazy" />

## Update Metadata

L'action Update Metadata est utilisée pour **mettre à jour les métadonnées du modèle de données** stockées soit dans l'entrepôt de données, soit dans le datastore. Il est fortement recommandé de l'exécuter à la fin de l'exécution d'un workflow qui affecte généralement le modèle de données. Les métadonnées du modèle de données sont utilisées par d'autres composants pour naviguer dans le modèle de données, tels que l'[Analytics Manager](/guides/public-cloud/data-platform/landing-page-analytics-manager), ou les [API](/guides/public-cloud/data-platform/landing-page-app-services-apis).

Lors de la création d'une nouvelle action Update Metadata, aucune configuration n'est requise.

:::info
Notez que **l'action peut être assez intensive et s'exécuter pendant une longue durée** si la taille de votre entrepôt de données est importante. Nous recommandons donc de les exécuter une fois par workflow, et non systématiquement après chaque action, afin d'optimiser votre temps d'exécution.
:::

## Flush Cache: Analytics Manager

Cette action est utilisée pour vider le [cache](https://developer.mozilla.org/en-US/docs/Web/API/Cache) de l'[Analytics Manager](/guides/public-cloud/data-platform/landing-page-analytics-manager). Il est fortement recommandé de la lancer à la fin d'un workflow. Cela garantit que l'Analytics Manager utilise les dernières métadonnées du [Lakehouse Manager](/guides/public-cloud/data-platform/landing-page-lakehouse-manager).

L'action accepte un paramètre optionnel `params.timeout`, voir [Configurer un timeout d'action](/guides/public-cloud/data-platform/dpe-actions-maintenance#configurer-un-timeout-daction). Sa configuration JSON se présente comme suit :

```json
{
	"display_name": "Flush Cache: Analytics Manager action",
	"action": "flush-cache-qb",
	"params": {
	  "timeout": "2h"
	}
}
```

## Flush Cache: App Services

Cette action est utilisée pour **appeler les [API du Projet](/guides/public-cloud/data-platform/landing-page-app-services-apis) afin de vider son [cache](https://developer.mozilla.org/en-US/docs/Web/API/Cache)**. Il est fortement recommandé de la lancer à la fin d'un workflow. Cela garantit que l'API affiche les dernières valeurs des requêtes ou attributs préconfigurés.

L'action accepte un paramètre optionnel `params.timeout`, voir [Configurer un timeout d'action](/guides/public-cloud/data-platform/dpe-actions-maintenance#configurer-un-timeout-daction). Sa configuration JSON se présente comme suit :

```json
{
	"display_name": "Flush Cache: App Services action",
	"action": "flush-cache-front",
	"params": {
	  "timeout": "2h"
	}
}
```

## Configurer un timeout d'action

Les deux actions de flush cache acceptent un timeout :

| Nom du paramètre | Description | Exemples | Requis |
| :--------------- | :--------------------- | :-----------------  | :----------------- |
| params.timeout | Durée maximale de l'action ; si l'action prend plus de temps à s'exécuter, elle sera interrompue avant la fin de son exécution. Cela peut entraîner des insertions partielles de données ou d'autres problèmes. À utiliser avec une grande prudence, uniquement pour des cas spécifiques. | Format utilisant Xd Xh Xm Xs | Non |

Afin d'ajouter un timeout d'action, allez dans les *préférences* et activez le paramètre timeout, en ajoutant la durée souhaitée, ou bien, modifiez la configuration JSON de l'action.
