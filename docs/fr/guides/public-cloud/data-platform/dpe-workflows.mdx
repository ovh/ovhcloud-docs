## Objectif

Les workflows sont vos pipelines ETL et de traitement de données orchestrés sur la Platform. Un workflow est une structure organisationnelle du Data Processing Engine qui représente **une séquence d'[actions](/guides/public-cloud/data-platform/landing-page-dpe-actions)** pouvant être :

- exécutées manuellement ou via un appel API ;
- planifiées pour s'exécuter à un moment donné (CRON).

Lors de la **création de workflows**, vous pouvez organiser les actions en stages afin de personnaliser le traitement de vos données : les stages s'exécutent séquentiellement et les actions en parallèle.

À chaque lancement d'un workflow, vous pouvez **suivre son exécution** en consultant les logs.

## Créer un workflow

La Platform propose une interface simple, en pointer-cliquer, pour orchestrer vos actions au sein de workflows planifiés. La création d'un workflow comporte 2 étapes principales :

- **Stages** : configurez les stages successifs du workflow. Les actions de chaque stage peuvent être ajoutées lors de la création du workflow ou ultérieurement.
- **Préférences** : vous pouvez définir différents paramètres et informations concernant le workflow.

<img className="thumbnail" alt="Créer un workflow — Nouveau workflow" src="/images/public-cloud/data-platform/product/dpe/workflows/picts/new-workflow.png" loading="lazy" />

### Stages

Au sein d'un workflow, les actions sont organisées en stages **séquentiels**. À l'intérieur d'un stage, les actions s'exécutent en **parallèle** (elles peuvent donc s'exécuter [en parallèle sur plusieurs instances](/guides/public-cloud/data-platform/dpe-jobs-resources#dimensionner-vos-tâches-horizontalement)).

<img className="thumbnail" alt="Stages — Organisation des traitements" src="/images/public-cloud/data-platform/product/dpe/workflows/picts/organisation-traitements.png" loading="lazy" />

Si un workflow contient des actions comportant plusieurs versions de langage, il s'exécute avec la **version de langage la plus récente** qu'il contient. Vous pouvez modifier ce comportement depuis les [préférences du workflow](/guides/public-cloud/data-platform/dpe-workflows#préférences).

:::warning
Pour le moment, un même workflow **ne peut pas** contenir à la fois des [actions PySpark](/guides/public-cloud/data-platform/dpe-actions-custom-pyspark) et des actions classiques.
:::

:::info
Un workflow doit contenir **au moins une action** pour pouvoir être démarré. Les workflows vides ne peuvent pas être exécutés.
:::

### Préférences

L'onglet des préférences permet de donner au workflow un nom, une description et des tags, ainsi que de définir plusieurs [paramètres d'exécution](/guides/public-cloud/data-platform/dpe-jobs-preferences).

<img className="thumbnail" alt="Préférences — Préférences du workflow" src="/images/public-cloud/data-platform/product/dpe/workflows/picts/workflow-preferences.png" loading="lazy" />

:::info
**À quoi sert l'« Auto Flushall » ?** La plateforme stocke le résultat des requêtes en cache (autrement dit, elles sont « pré-calculées ») afin d'améliorer les performances lors de l'utilisation d'une application. L'exécution du « Flush all » relance les requêtes et actualise les données de l'application. Cette option est donc activée par défaut et ajoute généralement 5 à 10 secondes de traitement à votre workflow. Pour des workflows de traitement de données successifs et complexes, vous pouvez la désactiver et l'exécuter une seule fois à la fin, dans un workflow distinct.
:::

### Mode avancé

Vous pouvez également aller plus loin en utilisant notre IDE intégré dans le mode avancé : l'onglet **Avancé** permet de personnaliser davantage votre workflow à l'aide des fichiers de configuration JSON.

[Découvrez comment configurer un workflow via le mode avancé](/guides/public-cloud/data-platform/dpe-workflows-advanced-mode)

## Gérer les workflows

Depuis l'écran des workflows, vous voyez rapidement quels workflows sont en cours d'exécution, se sont exécutés avec succès ou ont rencontré des erreurs lors de leur exécution.

En survolant l'icône *More* (les « ... ») sur la ligne d'un workflow, vous pouvez également :

- **Supprimer** un workflow ;
- **Éditer** un workflow existant ;
- **Exécuter** un workflow ;
- **Consulter les logs** d'un workflow.

<img className="thumbnail" alt="Gérer les workflows — Opérations CRUD sur un workflow" src="/images/public-cloud/data-platform/product/dpe/workflows/picts/crud_workflow.png" loading="lazy" />

Lorsque le nombre de workflows augmente, vous pouvez organiser l'affichage à l'aide des *Folders* ou rechercher un workflow précis grâce à la barre de recherche située en haut à droite de l'écran. Pour ranger des workflows dans des dossiers, glissez-déposez simplement un workflow dans le dossier voulu.

<img className="thumbnail" alt="Gérer les workflows — Actions de base sur un workflow" src="/images/public-cloud/data-platform/product/dpe/workflows/picts/workflow-basic-actions.png" loading="lazy" />

## Superviser un workflow

### Logs

Pour suivre la progression d'un workflow, vous pouvez ouvrir ses logs en cliquant sur l'**icône Console**. Le [Logs Explorer du Control Center](/guides/public-cloud/data-platform/control-center-logs-explorer) s'ouvre alors dans une nouvelle fenêtre.

Notez que dans les [préférences](/guides/public-cloud/data-platform/dpe-workflows#préférences) d'un workflow, vous pouvez définir le niveau d'information disponible dans les logs (debug, info, notice, warning, error, critical).

<img className="thumbnail" alt="Logs — Log ETL" src="/images/public-cloud/data-platform/product/dpe/workflows/picts/etl-log.png" loading="lazy" />

### Alertes

Comme pour les actions, vous pouvez superviser l'exécution d'un workflow en définissant des alertes sur certaines métriques d'exécution clés (réussite du job, durée d'exécution, mémoire utilisée, etc.). Cela crée une [alerte](/guides/public-cloud/data-platform/landing-page-control-center-alerting) dans le [Control Center](/guides/public-cloud/data-platform/landing-page-control-center).

<img className="thumbnail" alt="Alertes — Alerte ETL" src="/images/public-cloud/data-platform/product/dpe/workflows/picts/etl-alert.png" loading="lazy" />
