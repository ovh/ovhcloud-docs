## Objectif

Sur la Platform, un **Projet** est un environnement cloud avec des ressources dédiées qui contient tous les composants nécessaires pour gérer le cycle de vie de vos données, de l'ingestion à la restitution. Les données physiques, quant à elles, sont stockées dans un dataset lié au Projet.

## Que puis-je faire dans un Projet

Les Projets sont le hub à partir duquel vous accédez à tous les services de la platform ainsi qu'à vos données. Les tâches nécessaires pour mettre en production une application de données sont toutes automatisées, telles que :

- faire travailler une équipe entière sur le même environnement, avec différents droits d'accès aux données ou aux modules
- construire un schéma de base de données logique, sans être lié à une base de données spécifique
- automatiser la collecte de données, l'ETL et la visualisation
- surveiller l'infrastructure cloud et ses performances

:::info
En général, un Projet peut répondre à un ou plusieurs cas d'usage spécifiques. Vous pouvez utiliser plusieurs Projets afin de travailler sur différents environnements (staging, production...) pour le même cas d'usage.
:::

## Quels services sont inclus dans un Projet

Un Projet est un environnement flexible composé de plusieurs services, ce qui signifie que vous pouvez ajouter des services à votre Projet comme vous le souhaitez. Ces services sont répartis en catégories et seuls les services *Admin tools* sont obligatoires pour que votre projet fonctionne, tous les autres pouvant être ajoutés selon vos besoins.

<img className="thumbnail" alt="Quels services sont inclus dans un Projet — Page d'accueil du Projet" src="/images/public-cloud/data-platform/product/project/picts/project_home.png" loading="lazy" />

- **Data Analytics** : collecte, entreposage et traitement des données, et requêtage.
  - Les [Connectors](/guides/public-cloud/data-platform/landing-page-connectors)
  - Le [Lakehouse Manager](/guides/public-cloud/data-platform/landing-page-lakehouse-manager)
  - Le [Data Processing Engine](/guides/public-cloud/data-platform/landing-page-dpe)
  - L'[Analytics Manager](/guides/public-cloud/data-platform/landing-page-analytics-manager)
- **Application Services** : passerelles API et visualisation des données.
  - Les [APIs](/guides/public-cloud/data-platform/landing-page-app-services-apis)
  - Les [APPs](/guides/public-cloud/data-platform/landing-page-app-services-apps)
- **Admin Tools** : gestion des ressources et contrôle d'accès.
  - Le [Control Center](/guides/public-cloud/data-platform/landing-page-control-center)
  - L'[Identity Access Manager](/guides/public-cloud/data-platform/landing-page-iam)

## Comment allouer des ressources dans un Projet ?

Les Projets ont été conçus dès l'origine pour évoluer facilement à mesure que les besoins de votre Projet de données évoluent. Vous pouvez **scaler horizontalement et verticalement** de manière indépendante n'importe quel composant de votre choix en quelques clics, par exemple dans les [préférences](/guides/public-cloud/data-platform/dpe-jobs-resources) d'un [workflow du Data Processing Engine](/guides/public-cloud/data-platform/dpe-workflows). Les instances déployées, telles que les [APIs](/guides/public-cloud/data-platform/landing-page-app-services-apis) et les [applications](/guides/public-cloud/data-platform/landing-page-app-services-apps), peuvent également être scalées indépendamment.

Chaque composant de votre Projet consommera des [ressources](/guides/public-cloud/data-platform/manage-pricing) lorsqu'il est activement en cours d'exécution (via un job ou un déploiement).

:::info
Même à l'arrêt, votre Projet utilise par défaut une poignée de DPUs. Vous pouvez gérer cette quantité dans le [Control Center](/guides/public-cloud/data-platform/landing-page-control-center).
:::
