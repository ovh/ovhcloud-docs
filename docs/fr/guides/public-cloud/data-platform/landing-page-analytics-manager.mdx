## Qu'est-ce que l'Analytics Manager ?

L'Analytics Manager est l'endroit où les données du projet deviennent des réponses. Il interroge les [tables](/guides/public-cloud/data-platform/lakehouse-manager-tables) détenues dans le Lakehouse Manager, via un constructeur no-code ou un éditeur SQL, et transforme les résultats en graphiques et en dashboards.

<img className="thumbnail" alt="Index1" src="/images/public-cloud/data-platform/product/am/picts/homepage-am.png" loading="lazy" />

Une requête est à la fois l'unité de travail et l'unité de réutilisation. Les requêtes sont sauvegardées, nommées et versionnées, de sorte qu'une seule définition alimente un graphique, une tuile de dashboard et un endpoint API au lieu d'être réécrite à chaque fois. Les requêtes s'exécutent sur des moteurs cloud-native, et lisent soit les tables du lakehouse, soit, lorsqu'une [source est marquée comme directement interrogeable](/guides/public-cloud/data-platform/connectors-sources-configure#rendre-votre-source-de-données-directement-interrogeable), le système externe lui-même.

Les [Dashboards](/guides/public-cloud/data-platform/analytics-manager-dashboards) assemblent des requêtes sauvegardées sur une page pour les utilisateurs finaux, et peuvent être publiés au-delà des personnes qui les ont créés. L'[Historique](/guides/public-cloud/data-platform/analytics-manager-history) enregistre chaque exécution avec ses métriques de performance, c'est là qu'un dashboard lent se diagnostique. Les [Paramètres](/guides/public-cloud/data-platform/analytics-manager-settings) contiennent les dépôts et le cache de requêtes.

L'Analytics Manager est aussi la charnière entre les rôles. Les data engineers alimentent et modélisent les tables, les analystes écrivent les requêtes, et les développeurs d'applications les consomment via [Application Services](/guides/public-cloud/data-platform/landing-page-app-services), qui expose chaque requête sauvegardée comme un endpoint en direct sous authentification IAM.
