## Objectif

Toutes les actions et workflows, lorsqu'ils sont lancés, sont construits et exécutés dans des **conteneurs livrés avec des packages préchargés**. Ainsi, en particulier dans le cas des actions personnalisées, vous n'avez pas toujours besoin de spécifier manuellement les librairies dont vous avez besoin pour exécuter votre code.

Actuellement, les jobs de la Data Platform ne sont compatibles qu'avec Python 3+, il n'y a donc que 2 packages par défaut à gérer :

- **Python Libraries** : si vous êtes sur le point d'écrire votre propre action personnalisée, inutile de vous faire un cours sur les librairies Python... en arrière-plan, nous exécutons simplement une commande *pip install*.
- **Data Platform Modules** : afin de conserver une image légère des conteneurs, tous les connecteurs de la Data Platform ne sont pas chargés automatiquement. Pour utiliser un connecteur spécifique via le SDK, veuillez spécifier les modules requis depuis notre liste interne prise en charge.

:::warning
**Notez** que nous ne permettons pas aux utilisateurs de remplacer les librairies par défaut installées par des versions plus anciennes afin d'éviter les problèmes d'incompatibilité.
:::

Cependant, **vous pouvez tout à fait installer toute autre librairie en plus de la liste fournie** ci-dessus en les ajoutant dans le champ « Requirements » de la configuration de votre action personnalisée, que ce soit dans l'interface ou dans le fichier JSON. Utilisez simplement le même format que pour une commande *pip install* afin de spécifier la version de la librairie.

[Découvrir toutes les librairies Python sur le site officiel de Pypi](https://pypi.org/)

## Data Platform Modules

Lorsque vous créez une nouvelle action personnalisée à l'aide du Data Processing Engine de la Data Platform, vous serez certainement amené à vous connecter à des sources de données externes et à utiliser une variété de formats de fichiers. **La Data Platform dispose d'une liste préexistante de modules pour gérer à la fois les formats de données et les types de connecteurs au sein de votre code**.

La liste des modules préinstallés par défaut inclut principalement la prise en charge des formats de fichiers génériques et d'autres composants de la platform (data warehouse et datastore) : mySQL, S3<sup>1</sup>, CSV, XML, XLS, XLSX, JSON. Les formats de fichiers Parquet ne sont pas installés par défaut en raison de la taille du module (environ 400 Mo), ce qui ajouterait de la latence à la construction des workers.

Pour installer des modules de la Data Platform pour vos actions personnalisées, vous pouvez soit le faire via l'interface graphique de configuration de l'action personnalisée, dans la section *Requirements*. Par exemple, si vous utilisez les fonctions du SDK pour vous connecter à une source Dropbox externe mais que vous n'avez pas installé le module Dropbox, votre code lèvera une erreur à moins de configurer votre action personnalisée comme ci-dessous :

<img className="thumbnail" alt="Écran de création d'une action personnalisée" src="/images/public-cloud/data-platform/product/dpe/actions/custom/picts/fp-modules.png" loading="lazy" />

Ou vous pouvez directement saisir la liste des modules dans la configuration JSON de l'action sous la clé *modules* :

```json
{
  "modules": [
    {
      "type": "action",
      "id": "aggregate",
      "version": "latest"
    },
    { ... }
  ],
```

:::info
**Notez** que par défaut dans le menu déroulant de l'interface, tous les modules seront installés dans leur dernière version. Si vous essayez d'installer une version spécifique, veuillez la spécifier directement dans la configuration JSON de l'action (voir syntaxe ci-dessus) en mode Advanced.
:::
