## Objectif

Le **consommateur OpenLineage** vous permet de transmettre les événements de lineage de données générés par votre projet Data Platform vers une solution de lineage externe de votre choix. Une fois connectée, la platform diffuse en continu des événements conformes à [OpenLineage](https://openlineage.io/) vers votre backend de lineage afin que vous puissiez y visualiser et explorer votre graphe de lineage de données.

<img className="thumbnail" alt="Consommateur Open lineage" src="/images/public-cloud/data-platform/product/connectors/consumers/openlineage/picts/open-lineage-consumer.png" loading="lazy" />

:::info
La Data Platform inclut également un visualiseur de lineage intégré : consultez [Lineage](/guides/public-cloud/data-platform/lakehouse-manager-lineage) dans le Lakehouse Manager. Le consommateur OpenLineage est destiné aux équipes qui souhaitent retrouver ces mêmes événements dans leur propre solution de lineage, consultez les [outils compatibles](#solutions-de-lineage-compatibles) ci-dessous.
:::

:::warning
**Avis de compatibilité :** à l'heure actuelle, [Marquez](https://marquezproject.ai/) est la seule solution de lineage validée pour fonctionner de manière fiable avec les événements OpenLineage de la Data Platform. D'autres outils compatibles OpenLineage peuvent recevoir les événements mais pourraient offrir une expérience dégradée. Nous recommandons d'utiliser Marquez pour de meilleurs résultats.
:::

## Solutions de lineage compatibles

La solution de lineage suivante a été validée pour fonctionner avec la Data Platform :

| Outil | Description |
| :--- | :--- |
| [Marquez](https://marquezproject.ai/) | Service de métadonnées open source conçu nativement pour OpenLineage |

Tout outil exposant un endpoint d'API HTTP OpenLineage peut techniquement être utilisé, mais seul Marquez est officiellement pris en charge à l'heure actuelle.

## Configurer le consommateur OpenLineage

Si vous ne l'avez pas encore fait, [ajoutez un nouveau](/guides/public-cloud/data-platform/landing-page-connectors-consumers) consommateur **OpenLineage** dans les Connectors. Sinon, éditez-le simplement.

Vous devrez fournir les valeurs suivantes :

| Champ | Requis | Description |
| :--- | :--- | :--- |
| **Endpoint URL** | Oui | L'URL HTTP(S) de l'API OpenLineage de votre solution de lineage (par ex. `https://marquez.example.com/api/v1/lineage`) |
| **Auth token** | Non | Un bearer token utilisé pour authentifier les requêtes vers votre backend de lineage. Laissez vide si votre backend ne nécessite pas d'authentification |
| **Keep Events** | Non | Si vrai, les événements sont stockés dans le bucket après leur envoi, à des fins d'historique. Sinon, ils sont supprimés. (Par défaut : false) |
| **Disable Trino events** | Non | Si vrai, les événements de lineage générés par les requêtes Trino (Explorer, Analytics Manager) ne sont pas transmis à votre backend de lineage. Seuls les événements des actions DPE (Load, Aggregate, Custom) sont envoyés. Utilisez cette option pour réduire le bruit si seul le lineage par lot vous intéresse. (Par défaut : false) |

<img className="thumbnail" alt="Configurer le consommateur OpenLineage — configuration du consommateur Open lineage" src="/images/public-cloud/data-platform/product/connectors/consumers/openlineage/picts/open-lineage-consumer-configure.png" loading="lazy" />

Une fois qu'un consommateur de lineage est configuré, tous les événements de lineage seront stockés dans le [Bucket du Lakehouse Manager](/guides/public-cloud/data-platform/lakehouse-manager-buckets) **DWH** sous `openlineage/events/queued`. Les événements seront transmis à votre solution de lineage à chaque exécution de l'action DPE [Send OpenLineage Events](/guides/public-cloud/data-platform/dpe-actions-send-openlineage-events).

## Envoyer des événements de lineage depuis le DPE

Les événements de lineage sont transmis par l'action [**Send OpenLineage Events**](/guides/public-cloud/data-platform/dpe-actions-send-openlineage-events) dans le Data Processing Engine. Vous pouvez la configurer pour s'exécuter :

- **En tant que cron job** : selon un planning fixe (par ex. toutes les heures, toutes les nuits)
- **En tant qu'action always-up** : en continu, pour garder votre solution de lineage synchronisée quasiment en temps réel

Consultez la documentation [Send OpenLineage Events](/guides/public-cloud/data-platform/dpe-actions-send-openlineage-events) pour le détail de la configuration.

:::info
Pour les actions Custom, le suivi du lineage est optionnel (opt-in). Consultez [Suivre le lineage des données dans une action Custom](/guides/public-cloud/data-platform/developers-python-sdk-lineage) pour apprendre à émettre des événements de lineage depuis votre propre code Python.
:::
