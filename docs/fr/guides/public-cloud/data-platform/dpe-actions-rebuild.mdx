## Objectif

L'action *Rebuild* **reconstruit entièrement une table existante** en créant une nouvelle table physique avec le même schéma et en y insérant toutes ses données.

Elle est principalement utilisée pour modifier des propriétés de champ qui ne peuvent pas être modifiées une fois qu'une table est construite, notamment l'ajout d'une contrainte **Required** ou **Required + Identifier** à un attribut (voir [contraintes d'attribut](/guides/public-cloud/data-platform/lakehouse-manager-manage-tables#contraintes-dattribut)).

## Pourquoi reconstruire une table

Reconstruire une table présente plusieurs avantages :

- **Modifier des propriétés de champ** telles que *Required*, ce qui [ne peut pas être fait une fois qu'une table est construite](/guides/public-cloud/data-platform/lakehouse-manager-manage-tables#contraintes-dattribut).
- **Restructurer des données partitionnées.** Si la table utilise des partitions, toutes les données sont réécrites en utilisant ces partitions. Notez que lorsque des partitions sont ajoutées à une table existante, seules les nouvelles données sont stockées sous ces partitions. L'action Rebuild vous permet de restructurer correctement *toutes* les données.
- **Nettoyer les métadonnées et le stockage.** Toutes les métadonnées et l'historique sont supprimés afin de conserver une seule version propre de la table. Cela peut réduire le stockage et améliorer les performances, car Iceberg optimise la façon dont il stocke les données.

:::warning
L'action Rebuild supprime **tout l'historique de la table**. Une fois qu'elle est exécutée, vous ne pouvez plus utiliser la fonctionnalité [Time Travel](/guides/public-cloud/data-platform/lakehouse-manager-time-travel) pour revenir à une version précédente. Il s'agit d'un nouveau départ.
:::

## Configurer une action Rebuild

Pour créer une nouvelle action *Rebuild*, accédez à l'onglet *Actions* du Data Processing Engine (DPE), cliquez sur **Nouvelle action**, et sélectionnez l'action *Rebuild*. Sélectionnez ensuite la table à reconstruire et ajustez sa configuration de champ (indicateur requis, indicateur d'identifiant et valeur par défaut).

<img className="thumbnail" alt="Configurer une action Rebuild — Rebuild config" src="/images/public-cloud/data-platform/product/dpe/actions/rebuild/picts/rebuild-config.png" loading="lazy" />

### Valeurs par défaut

Lorsque vous modifiez la propriété d'un attribut en **Required** ou **Required + Identifier**, vous devez définir une **valeur par défaut**. Cette valeur remplace toute valeur NULL trouvée pour cet attribut pendant la reconstruction, garantissant que la nouvelle contrainte requise est respectée.

### Conserver une table de sauvegarde

L'option **Conserver une table de sauvegarde** conserve une sauvegarde de la table précédente, *avec son historique*. La table de sauvegarde est nommée avec le préfixe `_back_{hash}` (par exemple, `my_table_back_d26433d4`). Vous pouvez retrouver ce nom dans les logs d'exécution.
