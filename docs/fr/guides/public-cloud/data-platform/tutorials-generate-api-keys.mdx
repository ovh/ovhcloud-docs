## Objectif

Si vous souhaitez vous connecter à la Data Platform depuis l'extérieur de la platform, vous devrez générer une **clé API et une clé secrète** pour vous authentifier. La *clé API* est la clé publique associée à l'utilisateur qui se connecte à une API. La *clé secrète* est la clé privée connue uniquement de l'utilisateur. La combinaison des deux est utilisée pour s'authentifier, via la génération de [tokens d'authentification](#générer-un-token-dauthentification) temporaires.

Les clés API et secrètes peuvent être générées par [utilisateur](/guides/public-cloud/data-platform/iam-users) ou par [service account](/guides/public-cloud/data-platform/iam-service-accounts).

## Générer un nouveau jeu de clés API et secrètes

### Pour un utilisateur

Accédez à l'onglet **Users** de l'Identity Access Manager. Recherchez l'utilisateur pour lequel vous souhaitez générer des clés API et secrètes, à l'aide de la barre de recherche en haut à droite si nécessaire. Éditez l'utilisateur.

<img className="thumbnail" alt="For a user — Users search" src="/images/public-cloud/data-platform/getting-further/generate-api-key/picts/users-search.png" loading="lazy" />

Dans les paramètres de l'utilisateur, faites défiler jusqu'au panneau **API Access** et cliquez sur *Add access*.

<img className="thumbnail" alt="For a user — Users api key" src="/images/public-cloud/data-platform/getting-further/generate-api-key/picts/users-api-key.png" loading="lazy" />

Sélectionnez la durée de vie des clés (c'est-à-dire la date d'expiration à partir d'aujourd'hui) et indiquez si vous souhaitez envoyer un e-mail à l'utilisateur avec les informations de clé API et secrète. Cliquez ensuite sur **Create**.

:::info
La valeur *Default* peut être modifiée dans les paramètres de votre Identity Access Manager.
:::

<img className="thumbnail" alt="For a user — Users api key options" src="/images/public-cloud/data-platform/getting-further/generate-api-key/picts/users-api-key-options.png" loading="lazy" />

Une nouvelle fenêtre s'ouvrira avec les valeurs de la clé API et de la clé secrète.

:::warning
Après la fermeture de la fenêtre, il n'est plus possible de consulter à nouveau la clé secrète. Assurez-vous de conserver une trace des clés, soit en envoyant un e-mail à l'utilisateur, soit en les stockant dans votre code.
:::

<img className="thumbnail" alt="For a user — Users api key confirmation" src="/images/public-cloud/data-platform/getting-further/generate-api-key/picts/users-api-key-confirmation.png" loading="lazy" />

Pour supprimer une clé, survolez la clé que vous souhaitez supprimer et cliquez sur l'icône **trash** 🗑️. Une fois la clé supprimée, les identifiants associés deviendront inactifs et ne pourront plus être utilisés pour s'authentifier.

<img className="thumbnail" alt="For a user — Users api key deleting" src="/images/public-cloud/data-platform/getting-further/generate-api-key/picts/users-api-key-deleting.png" loading="lazy" />

### Pour un service account

Accédez à l'onglet **Service Accounts** de l'Identity Access Manager. Recherchez le service account pour lequel vous souhaitez générer des clés API et secrètes, à l'aide de la barre de recherche en haut à droite si nécessaire.

<img className="thumbnail" alt="For a service account — Sa search" src="/images/public-cloud/data-platform/getting-further/generate-api-key/picts/sa-search.png" loading="lazy" />

Dans les paramètres du service account, repérez le panneau **API Access** et cliquez sur *Add access*.

<img className="thumbnail" alt="For a service account — Sa api key" src="/images/public-cloud/data-platform/getting-further/generate-api-key/picts/sa-api-key.png" loading="lazy" />

Ensuite, [la procédure est la même que pour les utilisateurs](#pour-un-utilisateur). Notez que si vous souhaitez envoyer un e-mail contenant une trace des clés API et secrète, vous devez renseigner une adresse e-mail pour le service account.

<img className="thumbnail" alt="For a service account — Sa email" src="/images/public-cloud/data-platform/getting-further/generate-api-key/picts/sa-email.png" loading="lazy" />

## Générer un token d'authentification

### Scripts de génération

Une fois vos clés API et secrète créées, vous devez générer un token d'authentification dynamique afin de vous authentifier auprès de la Data Platform via un endpoint API. Les tokens d'authentification ne sont actifs que pendant une courte durée : cette durée peut être configurée dans vos paramètres IAM.

<img className="thumbnail" alt="Generation scripts — Token settings" src="/images/public-cloud/data-platform/getting-further/generate-api-key/picts/token-settings.png" loading="lazy" />

Pour générer un token, exécutez simplement les exemples de commandes ci-dessous.

<Tabs>
<Tab label="cURL">

```bash
curl --request POST \
  --url https://{project_subdomain}.eu.dataplatform.ovh.net/iam/login \
  --header 'Content-Type: application/json' \
  --data '{
    "auth_mode": "apikey",
    "apikey": "",
    "secretkey": ""
  }'
```

</Tab>
<Tab label="Python 3+">

```python
import requests

url = "https://{project_subdomain}.eu.dataplatform.ovh.net/iam/login"

payload = {
  "auth_mode": "apikey",
  "apikey": "",
  "secretkey": ""
}

response = requests.request("POST", url, data=payload)

print(response.text)
```

</Tab>
</Tabs>

:::warning
Pensez à mettre à jour le **\{project_subdomain\}**, sinon vos appels ne fonctionneront pas.
:::
