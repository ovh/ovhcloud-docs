## Objectif

Dans certains cas, vous voudrez utiliser votre propre code Python déjà existant.

Afin d'importer vos modules Python personnalisés et de les utiliser dans une [action Custom](/guides/public-cloud/data-platform/dpe-actions-custom), vous pouvez faire référence à un dépôt Git externe qui sera récupéré avant chaque build de votre job.

Voici les étapes pour utiliser un dépôt Git externe comme module Python :

1. Adaptez votre module pour qu'il soit compatible avec `pip install` 
  - voir la [documentation de setuptools](https://packaging.python.org/guides/distributing-packages-using-setuptools/)
2. Votre module Python doit être hébergé sur un hôte accessible ; si le dépôt est privé, vous devez obtenir un `access token`. 
Par exemple, sur [GitHub](https://github.com), vous devez générer un **personal access token** 
(D'autres fournisseurs peuvent avoir des procédures similaires)

  - [comment définir les tokens](https://docs.github.com/en/free-pro-team@latest/github/authenticating-to-github/creating-a-personal-access-token)
  - [définir votre token personnel dans GitHub](https://github.com/settings/tokens)
3. Vérifiez que le téléchargement du package fonctionne bien avec votre token 
  - Archive Zip : `https://<access_token>@github.com/<myorg>/<myProject>/archive/<ref>.zip`
  - Git : `git+https://<access_token>@github.com/<myorg>/<myProject>.git`
  - Git avec un nom de tag ou un hash de commit : `git+https://<access_token>@github.com/<myorg>/<myProject>.git@<tag>`
  - Git avec récupération automatique de la dernière version : `git+https://<access_token>@github.com/<myorg>/<myProject>.git@latest`
4. Vérifiez que `pip install` fonctionne avec votre URL sur votre ordinateur local
```bash
pip install <URL>
```
5. Dans votre projet, dans une action Custom, ajoutez les dépendances dans l'**Advanced Mode** dans `forepaas.json` : 
  - avec une archive Zip HTTPS
```json
      {
        "dependencies": {
          "python": {
            "https://<access_token>@github.com/<myorg>/<myProject>/archive/<ref>.zip": null
          }
        }
      }
```
  - avec un dépôt Git+HTTPS
```json
      {
        "dependencies": {
          "python": {
            "git+https://<access_token>@github.com/<myorg>/<myProject>.git": null
          }
        }
      }
```
  - avec un dépôt Git+HTTPS, incluant un nom de `tag` ou un `commit hash`
```json
      {
        "dependencies": {
          "python": {
            "git+https://<access_token>@github.com/<myorg>/<myProject>.git@<tag>": null
          }
        }
      }
```
  - avec un dépôt Git+HTTPS, utilisant automatiquement la dernière version
```json
      {
        "dependencies": {
          "python": {
            "git+https://<access_token>@github.com/<myorg>/<myProject>.git@latest": null
          }
        }
      }
```

:::info
**Résolution automatique de la dernière version :** utiliser `@latest` à la fin d'une URL de dépendance `git+` demande à la platform de récupérer et de substituer automatiquement le tag de version le plus récent avant l'installation. Cela évite d'avoir à mettre à jour manuellement la dépendance de chaque action lorsqu'une nouvelle version de votre module est publiée, cliquez sur **Force Build** pour récupérer la nouvelle version. Notez que la dernière version n'est pas détectée automatiquement à l'exécution, un **Force Build** manuel est toujours nécessaire.
:::

:::warning
Épingler un `tag` ou un `commit hash` spécifique vous donne un contrôle précis sur la version utilisée lors de l'exécution et est recommandé pour les charges de travail de production.
:::

6. Dans le code Python de votre action Custom, vous pouvez maintenant l'importer et l'utiliser !
```python
import mypackage
```
