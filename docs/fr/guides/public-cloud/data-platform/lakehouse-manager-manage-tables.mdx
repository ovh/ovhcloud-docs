## Objectif

Il existe six interactions de table au total. En vue Canvas, affichez les trois premières options en cliquant sur une table et affichez les trois autres en cliquant sur l'icône « **...** » après avoir cliqué sur la table. En vue Liste, survolez simplement la table pour afficher toutes les interactions disponibles.

## Ajouter un nouvel attribut

:::info
Représenté par le symbole ➕.
:::

Ajoute un nouvel attribut à la table cible en ouvrant la fenêtre de création d'attribut, illustrée ci-dessous.

<img className="thumbnail" alt="Create attribute" src="/images/public-cloud/data-platform/product/lakehouse-manager/tables/picts/tables-new-attribute.png" loading="lazy" />

### Contraintes d'attribut

Lors de la définition d'un attribut sur une table, vous pouvez ajouter les contraintes suivantes :

- **Required :** le champ ne peut jamais contenir NULL. Si une tâche tente d'y insérer une valeur nulle, le moteur de requête renvoie une erreur.
- **Required + Identifier :** le champ est requis *et* marqué comme **champ identifiant**, ce qui signifie qu'il est utilisé pour définir l'unicité d'une ligne pour les opérations **upsert**. Consultez la [stratégie d'écriture](/guides/public-cloud/data-platform/dpe-jobs-preferences#stratégie-décriture) des actions Load / Aggregate (Python et PySpark) pour plus d'informations.

<img className="thumbnail" alt="Attribute constraints" src="/images/public-cloud/data-platform/product/lakehouse-manager/tables/picts/tables-attribute-constraints.png" loading="lazy" />

:::warning
**Une fois qu'une table est construite, vous ne pouvez plus ajouter de champ Required.** Vous pouvez toujours *retirer* la propriété Required d'un champ requis existant, mais vous ne pouvez pas ajouter la contrainte NOT NULL à un champ après coup. La seule façon d'ajouter un champ requis (ou identifiant) à une table construite est de la reconstruire entièrement. Consultez l'[action Rebuild](/guides/public-cloud/data-platform/dpe-actions-rebuild).
:::

:::info
Un champ identifiant ne peut pas être un `double` ou un `decimal`.
:::

## Éditer la table

:::info
Représenté par le symbole ✏️.
:::

Permet l'édition du schéma et de la configuration de la table.

<img className="thumbnail" alt="Edit table" src="/images/public-cloud/data-platform/product/lakehouse-manager/tables/picts/tables-config.png" loading="lazy" />

### Actions de base

Vous pouvez modifier les configurations de base suivantes :

- Nom de la table
- Type de table
- Description de la table
- Tags de la table (utilisés pour la rechercher facilement)
- Queryable (si une table n'est pas définie comme queryable, elle ne sera pas détectée par les générateurs de requêtes visuels automatisés de l'Analytics Manager et de l'Explorer du Lakehouse Manager)

### Étiquetage et indexation

Lors de l'édition d'une table, vous pouvez en outre ajouter :

- Un **label** 
- Une ou plusieurs **clés/index de partition** (*dans les options avancées*)

<img className="thumbnail" alt="MTA3" src="/images/public-cloud/data-platform/product/lakehouse-manager/tables/picts/tables-indexes.png" loading="lazy" />

#### Labels

Vous pouvez choisir l'un des attributs de la table comme **label** optionnel pour la clé primaire de cette table.

Cela transforme la table en un *dictionnaire* qui va être stocké dans le cache des [APIs](/guides/public-cloud/data-platform/landing-page-app-services-apis) que vous déployez dans votre Projet. L'API appliquera la traduction dans les requêtes utilisant ce dictionnaire, et le label s'affichera automatiquement dans vos applications à la place de la clé primaire.

:::info
**Astuce :** en définissant des labels, vous n'avez pas besoin de stocker des données supplémentaires volumineuses dans les tables agrégées.
:::

#### Index

De plus, vous pouvez définir des **index** ou des **clés de partition** pour localiser rapidement des données sans avoir à parcourir chaque ligne d'une table.

:::info
**Astuce :** définir des index améliore la vitesse des opérations de récupération de données sur une table, au prix d'écritures et d'espace de stockage supplémentaires pour maintenir la structure de l'index.
:::

## Construire la table

:::info
Représenté par le symbole ▶️ pour lancer la construction, ou ⏹️ pour l'arrêter.
:::

Cliquez pour démarrer ou arrêter la tâche de construction pour la table cible. Cette tâche correspond à la construction physique de vos tables dans la base de données et est **requise pour charger et accéder à vos données** dans la platform.

Démarrer la tâche de construction ouvrira automatiquement les logs de la tâche vous permettant de surveiller son statut :

<img className="thumbnail" alt="Tables4" src="/images/public-cloud/data-platform/product/lakehouse-manager/tables/picts/canvas-view-4.png" loading="lazy" />

## Dupliquer

:::info
Représenté par le symbole 📑.
:::

Crée une copie de la table cible qui devra être construite séparément.

## Supprimer

:::info
Représenté par le symbole 🗑.
:::

Retire la table cible du schéma de données logique.
Retire également son équivalent physiquement construit si la table a déjà été construite.
