## Objectif

**Custom Sources** vous permet d'apporter votre propre connecteur pour une API que Data Platform ne couvre pas. Votre **agent de code** écrit et teste le connecteur sur votre poste, guidé par un skill que vous téléchargez depuis Data Platform. Vous importez le résultat sous forme de **package**, Data Platform le vérifie et le publie, et chaque utilisateur du projet peut ensuite créer des sources à partir de ce connecteur.

Une source construite sur un connecteur personnalisé fonctionne comme n'importe quelle autre source : elle apparaît dans la liste *Sources*, ses métadonnées sont extraites, et elle alimente les [actions *Load*](/guides/public-cloud/data-platform/dpe-actions-load), les tables et le lineage. Seul le nom de son connecteur la distingue des autres.

### Custom Sources ou HTTP REST

Le [connecteur HTTP REST](/guides/public-cloud/data-platform/connectors-sources-rest) couvre déjà les API que vous pouvez décrire dans un formulaire. Utilisez une source personnalisée lorsque cela ne suffit pas et que l'API demande du Python pour être lue :

- une pagination que HTTP REST ne sait pas suivre ;
- plusieurs appels pour construire un seul enregistrement ;
- des réponses à remettre en forme avant leur chargement ;
- un mode d'authentification que HTTP REST ne prend pas en charge.

Un connecteur personnalisé n'est jamais construit ni modifié dans Data Platform. Le package est le connecteur : son code, ses endpoints et ses champs d'identifiants viennent du package, et ne changent que lorsque vous en importez un nouveau.

## Prérequis

- Un agent de code IA sur votre poste, pour construire le connecteur.
- La documentation de l'API, ou un fichier OpenAPI ou des exemples cURL, et des identifiants valides si l'API en demande.
- La permission d'écrire des sources dans le projet, voir [Permissions](#permissions).

## Instructions

### Télécharger le skill

Dans le service Connectors, ouvrez *Custom Sources* et cliquez sur **Download skill**. Le skill est un dossier que vous confiez à votre agent de code. Il contient :

| Contenu | Rôle |
|---|---|
| `SKILL.md` | Les instructions que suit l'agent, de la documentation de l'API au package terminé |
| Un package d'exemple | Un connecteur complet comme point de départ |
| `reference/package-format.md`, `reference/connector-contract.md` | Le format d'un package et les fonctions qu'un connecteur doit fournir |
| `harness/` | Un exécuteur qui lance le connecteur comme le fait un job d'extraction, les vérifications que Data Platform effectue à l'import, et la commande qui construit le package |

Vous pouvez télécharger à nouveau le skill à tout moment depuis la même page.

### Construire et tester le connecteur avec votre agent

Confiez le dossier du skill à votre agent de code et demandez-lui de construire un connecteur pour votre API. En suivant le skill, l'agent :

1. Vérifie qu'une source personnalisée est le bon outil, plutôt que HTTP REST.
2. Vous demande la documentation de l'API, les données souhaitées et le fonctionnement de l'authentification.
3. Écrit le connecteur : un manifeste, `forepaas.json`, et un module Python.
4. Exécute le connecteur sur l'API réelle, avec les identifiants que vous exportez dans des variables d'environnement `CUSTOM_SOURCE_<KEY>`. Les valeurs des identifiants ne sont jamais écrites dans un fichier.
5. Lance les mêmes vérifications que Data Platform à l'import, puis construit le package, un fichier `.tgz`.
6. Vous indique ce que le connecteur extrait, les champs d'identifiants qu'il déclare, les avertissements restants et ce qu'il n'a pas pu exécuter.

Le test s'exécute sur votre poste, sur l'API réelle : Data Platform ne voit jamais vos identifiants pendant la construction du connecteur.

### Importer le connecteur

Sur la page *Custom Sources*, cliquez sur **Upload connector**, puis déposez le fichier `.tgz` dans la fenêtre ou cliquez pour le sélectionner. Data Platform lance ses vérifications et affiche les endpoints trouvés, avec :

- des **erreurs**, qui bloquent l'import : corrigez-les avec votre agent et importez le nouveau package ;
- des **avertissements**, qui ne le bloquent pas : lisez-les, et corrigez-les avec votre agent s'ils vous concernent.

<img className="thumbnail" alt="La fenêtre Upload connector listant les endpoints trouvés dans le package, avec le résultat des vérifications et le bouton Add" src="/images/public-cloud/data-platform/product/connectors/custom-sources/picts/custom-sources-upload.png" loading="lazy" />

Cliquez sur **Add**. Le connecteur est publié immédiatement et sa page s'ouvre. Vous pouvez créer une source à partir de ce connecteur tout de suite, ou plus tard depuis la même page.

Un package est refusé s'il déclare une dépendance autre qu'une dépendance Python, s'il contient un script, ou s'il contient un fichier autre que le manifeste, le module Python et l'icône. Son nom technique ne peut pas être celui d'un connecteur intégré à Data Platform.

### Consulter et modifier le connecteur

Ouvrez un connecteur depuis la liste *Custom Sources*. Sa page comporte deux onglets :

- **Definition** : le résultat des vérifications, avec les éventuels avertissements restants, puis l'identité du connecteur, sa connexion (URL de base, méthode d'authentification), ses champs d'identifiants et ses endpoints avec leurs paramètres.
- **Code** : le code Python exécuté dans les jobs d'extraction.

<img className="thumbnail" alt="La page d'un connecteur personnalisé, avec les boutons Export, Connect to the source et Upload new version et l'onglet Definition" src="/images/public-cloud/data-platform/product/connectors/custom-sources/picts/custom-sources-details.png" loading="lazy" />

Trois éléments se modifient dans Data Platform : le **nom d'affichage** (200 caractères au plus), la **description** (2 000 caractères au plus) et l'**icône**. Un bouton **Save** apparaît lorsque vous modifiez l'un d'eux. Tout le reste vient du package et reste en lecture seule : pour changer le code, les endpoints, les champs d'identifiants ou l'authentification, mettez à jour le connecteur avec votre agent et importez une nouvelle version.

Le **nom technique** ne peut pas changer. Il identifie le connecteur, et un import avec le même nom technique le remplace.

### Créer une source à partir du connecteur

Sur la page du connecteur, cliquez sur **Connect to the source**. Vous pouvez aussi cliquer sur **New Source** dans la liste *Sources* : les connecteurs personnalisés figurent dans la catégorie *Custom source* du store, à côté des connecteurs intégrés.

L'assistant de création de source standard s'ouvre. Nommez la source, renseignez les champs d'identifiants que déclare le connecteur, choisissez les endpoints et leurs paramètres, puis enregistrez. Consultez [Configurer votre connecteur](/guides/public-cloud/data-platform/connectors-sources-configure) pour les étapes suivantes, de l'extraction des métadonnées au chargement.

### Mettre à jour un connecteur

1. Sur la page du connecteur, cliquez sur **Export**. Le package se télécharge, sans aucune valeur d'identifiant. Conservez-le comme sauvegarde.
2. Confiez le package exporté à votre agent, avec le skill, et demandez la modification. L'agent conserve le nom technique, teste chaque endpoint, lance les vérifications et construit un nouveau package.
3. Cliquez sur **Upload new version** et importez le nouveau package. Il remplace le précédent.

Les sources qui utilisent le connecteur exécutent le nouveau code dès leur prochain job. En cas de problème, importez à nouveau le package exporté à l'étape 1.

Importer un package portant le même nom technique depuis **Upload connector** sur la page *Custom Sources* remplace aussi le connecteur : la fenêtre propose de le remplacer, jamais d'en créer un second. **Upload new version** refuse un package dont le nom technique est différent.

### Partager un connecteur avec un autre projet

Cliquez sur **Export** sur la page du connecteur, puis importez le package dans l'autre projet avec **Upload connector**. Le même connecteur y est publié. Les valeurs des identifiants ne font pas partie du package : chaque source de l'autre projet a besoin des siennes.

### Supprimer un connecteur

Pour supprimer un connecteur, cliquez sur **Delete** dans la liste *Custom Sources*. La page du connecteur n'a pas de bouton de suppression.

:::warning
**Les sources qui utilisent le connecteur cessent de fonctionner.** Lorsque des sources dépendent du connecteur, la confirmation les liste par leur nom. Une fois le connecteur supprimé, ces sources sont conservées comme orphelines, signalées dans la liste *Sources*, et leur prochain job échoue avec un message qui nomme le connecteur manquant. {/* verify: the orphan flag in the Sources list is listed as remaining frontend work in the handover; confirm it ships on 2026-11-02 */}
:::

### Permissions

Custom Sources utilise les permissions existantes sur les sources dans l'[Identity Access Manager](/guides/public-cloud/data-platform/iam-roles-conditions). Il n'existe pas de rôle dédié. {/* verify: the exact service, resource and action names of the source permissions in the IAM */}

| Pour | Il vous faut |
|---|---|
| Voir la page *Custom Sources*, les connecteurs et leur code | *Source* en lecture |
| Importer un connecteur ou une nouvelle version, changer son nom d'affichage, sa description ou son icône | *Source* en écriture |
| Supprimer un connecteur | *Source* en suppression |
| Créer une source à partir d'un connecteur personnalisé | Le même droit que pour toute autre source |

Sans droits sur les sources, la page *Custom Sources* et la catégorie *Custom source* du store n'apparaissent pas. Avec des droits en lecture seule, la page et les connecteurs sont visibles, et **Save**, **Upload connector**, **Upload new version** et **Delete** sont désactivés.

### Bon à savoir

- **Le code s'exécute uniquement dans les jobs d'extraction de votre projet**, comme un connecteur intégré. Il ne s'exécute jamais dans un service partagé de Data Platform.
- **Les identifiants sont déclarés comme champs secrets** dans le package et renseignés à la création d'une source. Leurs valeurs ne font jamais partie d'un package, y compris d'un package exporté.
- **Une nouvelle version s'applique à toutes les sources du connecteur** dès leur prochain job. Si le nouveau package supprime un endpoint utilisé par une source, l'import ne vous avertit pas : le prochain job de cette source échoue. {/* verify: the handover lists a warning at upload for a dropped endpoint as undecided; confirm the behaviour on 2026-11-02 */}
- **Data Platform ne conserve pas d'historique des versions.** Exportez le connecteur avant d'importer une nouvelle version, pour pouvoir le restaurer.

### Dépannage

| Symptôme | Où regarder |
|---|---|
| « L'import affiche des erreurs et **Add** est désactivé » | Chaque erreur nomme le fichier, le champ ou la valeur en cause. Transmettez les erreurs à votre agent, puis importez le nouveau package. Lancer les vérifications avec le harness avant l'import détecte les mêmes erreurs. |
| « L'import est refusé car le nom est déjà pris par un connecteur intégré » | Demandez à votre agent de changer le nom technique dans `forepaas.json`, puis de reconstruire le package et de l'importer à nouveau. |
| « **Upload new version** refuse le package » | Le nom technique diffère de celui du connecteur. Partez du package exporté, pour que l'agent conserve le nom technique. |
| « Une source échoue après l'import d'une nouvelle version » | Vérifiez que le nouveau package contient toujours les endpoints utilisés par la source. Importez à nouveau le package précédent pour restaurer le connecteur. |
| « Le job d'une source échoue en nommant un connecteur manquant » | Son connecteur a été supprimé. Importez à nouveau le connecteur avec le même nom technique, ou créez la source sur un autre connecteur. {/* verify: that re-uploading the same technical name reattaches orphaned sources */} |
