## Qu'est-ce qu'une API Data Platform ?

Une API dans un projet Data Platform est un service déployé qui expose les données du projet via HTTP, l'authentification étant gérée par l'[Identity Access Manager](/guides/public-cloud/data-platform/landing-page-iam) du projet. Les applications appellent l'API plutôt que d'accéder directement à une base de données, de sorte que les identifiants et la logique de requête restent à l'intérieur de la platform.

Les APIs sont construites de deux façons : à partir des modèles point-and-click fournis avec la platform, ou à partir de code écrit contre le Front API SDK en NodeJS. Dans les deux cas, le résultat est versionné, construit et déployé via le cycle de vie [Application Services](/guides/public-cloud/data-platform/landing-page-app-services), et servi par des nœuds qui peuvent être scalés horizontalement.

:::info
Toute requête sauvegardée dans l'[Analytics Manager](/guides/public-cloud/data-platform/analytics-manager-queries) peut être exposée en tant qu'endpoint, de sorte que la requête sauvegardée d'un analyste devienne la source de données d'une application sans aucun code intermédiaire. Comme la syntaxe des requêtes fait abstraction du stockage sous-jacent, les données analytiques sont servies sans exposer directement aucune base de données.
:::

Chaque [application](/guides/public-cloud/data-platform/landing-page-app-services-apps) du projet est liée à une API déployée : l'application sait quelle API appeler pour exécuter ses requêtes.

Les [extensions](/guides/public-cloud/data-platform/app-services-apis-extensions-list) sont des modules attachés à une API plutôt que du code écrit dans celle-ci : mise en cache en mémoire ou Redis, filtrage des utilisateurs IAM, passthrough des requêtes Analytics Manager, stockage web clé-valeur. Ajouter une extension nécessite de recharger et reconstruire l'API avant qu'elle ne prenne effet.
