## Objectif

L'action *Data quality (Spark)* évalue les [règles de qualité](/guides/public-cloud/data-platform/lakehouse-manager-data-quality) d'une table du Lakehouse Manager sur des exécuteurs Spark, et envoie le résultat au Lakehouse Manager sous forme de rapport, avec une entrée par règle. Le rapport met à jour le statut de qualité de la table. L'action exécute les mêmes règles, donne les mêmes résultats et fait échouer le job dans les mêmes conditions que l'action [Data quality](/guides/public-cloud/data-platform/dpe-actions-data-quality), pour les tables trop grandes pour un worker.

Utilisez-la lorsque le rapport d'une exécution Data quality contient `suggested_package: data-quality-pyspark`, ou lorsque vous savez déjà que la table est trop grande : l'action Data quality la suggère par défaut au-delà de 1 000 000 000 cellules (lignes multipliées par colonnes).

Comme toute autre action, elle peut être exécutée à la demande, planifiée avec un déclencheur cron, ou placée dans un [workflow](/guides/public-cloud/data-platform/dpe-workflows).

## Prérequis

- Une table du Lakehouse Manager avec au moins une règle de qualité active. Les règles sont lues dans le Lakehouse Manager à chaque exécution.
- L'image Spark 4.1.2, la seule qui embarque le moteur de règles (Python 3.13).

## Configurer l'action

### Paramètres

| Paramètre | Obligatoire | Description |
|---|---|---|
| **Table à vérifier** (`table`) | Oui | La table à vérifier, au format `dwh/<dataset>/<table>`, par exemple `dwh/events/clicks` |
| **Version de Spark** (`spark_version`) | Oui | L'image Spark sur laquelle le job s'exécute. Seule la version `4.1.2` embarque le moteur de règles |
| **Résultats critiques autorisés** (`max_criticals`) | Non | Dans **Quand le job échoue**. Le job échoue lorsque plus de règles que cette valeur finissent en critique. Non défini : seules les règles réglées sur [**Faire échouer le job**](/guides/public-cloud/data-platform/lakehouse-manager-data-quality#impact-sur-le-job) peuvent le faire échouer |
| **Avertissements autorisés** (`max_warnings`) | Non | Dans **Quand le job échoue**. Le job échoue lorsque plus de règles que cette valeur finissent en avertissement. Non défini : les avertissements ne font jamais échouer le job |

L'action n'offre pas de choix de moteur : chaque règle s'exécute sur Spark, y compris les règles `custom_sql`. Leur expression s'écrit dans le dialecte SQL de Trino, comme pour l'action Data quality, et est traduite en Spark SQL.

La table est lue une seule fois par exécution, dans son snapshot courant (`VERSION AS OF`) : toutes les règles voient les mêmes données, même si un chargement a lieu simultanément.

Dimensionnez les ressources Spark selon la table, voir [Dimensionner les ressources du Data Processing Engine](/guides/public-cloud/data-platform/dpe-jobs-resources).

### Exemple de corps de requête

Pour créer l'action par l'API, envoyez le corps de l'action à l'API du Data Processing Engine. Le module de connecteur `polar-data` est requis en plus de l'action :

```json
{
  "display_name": "Quality of events (Spark)",
  "repository": "<repository id>",
  "repository_version": "<repository version id>",
  "action": "data-quality-pyspark",
  "language": "pyspark",
  "modules": [
    {"type": "action", "id": "data-quality-pyspark", "version": "latest"},
    {"type": "connector", "id": "polar-data", "version": "latest"}
  ],
  "params": {"table": "dwh/events/clicks", "spark_version": "4.1.2"},
  "environment": {"fpu": {"size": 2, "instances": 1}}
}
```

## Quand le job échoue

Le rapport est toujours envoyé en premier : un job en échec a quand même son rapport dans le Lakehouse Manager, avec la raison de chaque résultat, et le [statut de qualité de la table](/guides/public-cloud/data-platform/lakehouse-manager-data-quality#statut-de-qualité-de-la-table) est mis à jour quel que soit le résultat du job. Le résultat du job et le statut de la table sont deux choses différentes : une règle **Signaler seulement** qui finit en critique rend la table critique sans faire échouer le job.

Le job échoue lorsque :

- le nombre de règles qui finissent en critique dépasse **Résultats critiques autorisés** ou, lorsque ce champ n'est pas défini, une règle réglée sur **Faire échouer le job** finit en critique ;
- le nombre de règles qui finissent en avertissement dépasse **Avertissements autorisés**, lorsque ce champ est défini ;
- aucune règle n'a pu être évaluée, par exemple lorsque la table ne peut pas être lue.

Le job réussit lorsque la table n'a aucune règle active, ou lorsque la table n'a jamais été chargée : chaque règle renvoie alors `no_data` avec la raison « This table has no data yet: it was never loaded ».

Résultats qui ne font jamais échouer le job :

- les résultats `not_evaluated` et `no_data`, tant qu'au moins une règle a pu être évaluée ;
- une règle portant sur une colonne que la table n'a plus. Elle est signalée en avertissement, avec la raison « Column `<name>` is no longer in the table », et n'est pas comptée dans **Avertissements autorisés**. Modifiez ou supprimez la règle.
