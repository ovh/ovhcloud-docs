## Ce que couvrent les API

Les API de la Data Platform sont l'alternative programmatique à l'interface, pour construire et gérer un [projet](/guides/public-cloud/data-platform/manage-projects) en code plutôt qu'à la main.

:::warning
**L'API complète de la Data Platform est en cours de développement.** Ce que cette section documente aujourd'hui est l'[authentification](/guides/public-cloud/data-platform/developers-api-authentication) : comment obtenir un token par mot de passe ou par identifiants de clé API, et comment l'invalider. Les références de endpoints pour le reste de la platform arriveront ici au fur et à mesure de leur sortie.
:::

En attendant, deux autres voies couvrent la majorité du travail programmatique. Le [Custom Actions SDK](/guides/public-cloud/data-platform/landing-page-developers-python-sdk) lit et écrit des datasets, des tables et des buckets depuis le compute propre d'un projet. Les buckets du projet parlent S3<sup>1</sup>, donc n'importe quel client compatible S3 fonctionne directement contre eux, comme le montre le [tutoriel d'accès aux buckets](/guides/public-cloud/data-platform/tutorials-bucket-s3-access).

Les conventions ci-dessous s'appliquent aux endpoints d'authentification et à l'API au fur et à mesure de sa croissance.

## Formats généraux

### Format de réponse

- Format des données : JSON, voir http://www.json.org
- Jeu de caractères : UTF-8
- Toutes les réponses non vides sont envoyées avec l'en-tête : `Content-Type: application/json; charset=utf-8`

### Codes de réponse HTTP

| Code | Message         | Signification                                              |
| :--- | :-------------: | :--------------------------------------------------------- |
| 200  | OK              | Réponse par défaut pour les requêtes GET ou POST réussies avec un contenu non vide                                       |
| 400  | Bad Request     | Valeur invalide pour les paramètres GET ou POST  |                 
| 401  | Unauthorized   | Identifiants ou droits invalides   |
| 403  | Forbidden       | Erreur d'authentification  |
| 404  | Not Found       | Action ou requête introuvable                  |
| 500  | Internal Server | Une erreur côté serveur est survenue                |

### Gestion des erreurs

En cas d'erreur côté client (code HTTP 4xx) ou côté serveur (code HTTP 5xx), le corps de la réponse peut contenir un objet JSON décrivant l'erreur :

```json
{
   "error": "Invalid parameter", // code 400, 403, 500
   "warning": "Action not found" // code 404
}
```

### Timestamp

Tous les endpoints de données renvoient le timestamp associé aux données fournies.
```json
{
    "timestamp": 1435929960
}
```

### Durée

Tous les endpoints de données renvoient l'attribut duration. Il représente le temps effectif pris par le système pour exécuter une requête, en secondes.
```json
{
    "duration": 0.056
}
```
