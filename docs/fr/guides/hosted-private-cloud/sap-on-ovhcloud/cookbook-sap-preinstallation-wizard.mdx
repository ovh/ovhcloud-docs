## Introduction

L'assistant de pré-installation SAP proposé par OVHcloud facilite le déploiement d'un système SAP sur votre service VMware on OVHcloud déjà configuré dans votre compte client. Il vous permet de mettre en place des environnements SAP NetWeaver 7.50 ou S/4HANA, que ce soit en configuration ABAP ou Java, et selon des schémas standard, distribué ou hautement disponible.

:::info
Il est important de noter que le terme « pré-installation » désigne ici l'installation de la couche technique uniquement. Cela inclut la base de données SAP HANA ainsi que la couche technique SAP NetWeaver 7.50 ou S/4HANA. Après cette phase de pré-installation, il vous faudra installer le module SAP spécifique à vos besoins et finaliser les configurations dans le cadre d'une post-installation.

:::

## Premiers pas

{/* CP-STEPS-START:cp-access */}
Dans l'onglet <code className="action">Fonctionnalités</code> du <code className="action">SAP Features Hub</code>, la carte **Assistant de pré-installation SAP** propose deux liens : <code className="action">Lancer une pré-installation</code> ouvre la page de configuration, et <code className="action">Liste des pré-installations</code> ouvre l'onglet <code className="action">Pré-installations</code>.

Sur la page de configuration, vous pouvez saisir manuellement toutes les informations, ou cliquer sur <code className="action">Importer un document de configuration</code> pour importer un fichier JSON préalablement créé. Ce fichier peut être généré à partir du schéma de notre API ou provenir d'une précédente installation, ce qui pré-remplit les informations et accélère le processus.

<Api version="v1" section="/dedicatedCloud" method="POST" route={"/dedicatedCloud/\{serviceName\}/sap"} />
{/* CP-STEPS-END:cp-access */}

**Prérequis**

- Vous devez disposer d'un service VMware on OVHcloud<sup>1</sup> déjà déployé dans votre compte client.
- Un projet Public Cloud doit être créé dans votre compte OVHcloud.
    - Dans ce projet Public Cloud, un conteneur Object Storage doit être créé pour y stocker vos sources SAP<sup>2</sup>.
- Un serveur DHCP doit être configuré dans le réseau où vous souhaitez déployer votre système SAP pour la machine virtuelle OVHcloud<sup>3</sup> qui sera déployée le temps du processus d'installation.

Il est important de noter que notre assistant de pré-installation SAP prend uniquement en charge les installations utilisant la base de données SAP HANA. Par conséquent, seules les sources SAPEXEDB pour SAP HANA sont prises en charge. Tous les autres fichiers SAPEXEDB doivent être supprimés de votre conteneur Object Storage s'ils ont été sélectionnés via le SAP Maintenance Planner.

En cas d'installation SAP S/4HANA Java, téléchargez et déposez également dans votre conteneur Object Storage les fichiers DATA_UNITS (accessibles via Software Center > INSTALLATIONS & UPGRADES > By Alphabetical Index (A-Z) > S > SAP S/4HANA > &#123;VERSION&#125; > INSTALLATION AND UPGRADE > 5XXXXX.ZIP).

<sup>1</sup> *Si vous souhaitez déployer un système SAP de production, nous recommandons fortement d'utiliser notre gamme SAP HANA on Private Cloud. Cette solution est spécifiquement conçue et certifiée pour héberger des systèmes SAP avec une base de données SAP HANA.*

<sup>2</sup> *OVHcloud n'est pas autorisé à fournir les sources SAP requises pour une installation. Par conséquent, nous vous demandons de stocker vos sources SAP dans un conteneur Object Storage OVHcloud. Pour cela, utilisez l'outil SAP Maintenance Planner afin de générer la liste et de télécharger l'ensemble des sources SAP nécessaires à votre installation souhaitée. N'oubliez pas de déposer l'exécutable SAPCAR dans votre conteneur Object Storage.*

<sup>3</sup> *Lors du déploiement de votre système SAP, une machine virtuelle dédiée nommée « ovhcloud-sap-wizard » sera déployée dans votre service VMware on OVHcloud. Cette machine virtuelle est essentielle pour orchestrer l'ensemble du processus d'installation. Elle est équipée de 2 vCPUs, 1 Go de RAM et 30 Go de stockage. À la fin du processus d'installation, qu'il ait réussi ou échoué, cette machine virtuelle sera automatiquement supprimée.*

## Étape par étape

La page **Configurer une pré-installation** comporte sept sections. Remplissez-les dans l'ordre : certaines listes restent vides tant que vous n'avez pas choisi une valeur dans une section précédente (le service VMware on OVHcloud, puis le datacentre). Le panneau **Récapitulatif** affiche **Complet** ou **Incomplet** pour chaque section.

### Infrastructure cible

{/* CP-STEPS-START:etape-1 */}
Sélectionnez le <code className="action">Service VMware on OVHcloud</code> que vous souhaitez utiliser pour votre installation SAP. Choisissez le <code className="action">Datacentre</code>, ainsi que le <code className="action">Cluster</code> qui hébergera vos machines virtuelles SAP.
{/* CP-STEPS-END:etape-1 */}

### Définition de l'installation

{/* CP-STEPS-START:etape-2 */}
Choisissez le type d'installation SAP que vous souhaitez réaliser : la <code className="action">Version d'application</code> (SAP NetWeaver 7.50 ou S/4HANA), le <code className="action">Type d'application</code> (ABAP ou Java) et le <code className="action">Type de déploiement</code> (standard, distribué ou hautement disponible). Les valeurs proposées dépendent de ce que le service VMware sélectionné déclare pouvoir installer. Le type de déploiement détermine le nombre de serveurs applicatifs et le rôle de chacun dans la section **Machines virtuelles**. Si vous le modifiez par la suite, les serveurs applicatifs déjà configurés sont abandonnés.
{/* CP-STEPS-END:etape-2 */}

### Détails du système

{/* CP-STEPS-START:etape-3 */}
Fournissez les identifiants système SAP (**SAP SID** et **SAP HANA SID**) ainsi que les quatre mots de passe qui seront utilisés lors de l'installation : **SAP MASTER** (utilisé pour tous les utilisateurs SAP demandés par l'installeur, comme DDIC ou sapadm), **SIDadm**, **SAP HANA MASTER** et **SAP HANA SYSTEM**.
{/* CP-STEPS-END:etape-3 */}

### Sources d'installation

{/* CP-STEPS-START:etape-4 */}
Renseignez les informations du conteneur Object Storage OVHcloud qui héberge les sources SAP nécessaires pour cette installation : **ID du conteneur**, **Endpoint** (un point d'accès S3<sup>4</sup> du stockage objet OVHcloud, par exemple `https://s3.gra.io.cloud.ovh.net`), **Clé d'accès** et **Clé secrète**. Assurez-vous que le conteneur ne contient que le contenu généré par le SAP Maintenance Planner correspondant à la version (NetWeaver 7.50 ou S/4HANA) et au type d'application (ABAP ou Java) sélectionnés. La clé d'accès et la clé secrète sont celles de l'utilisateur Object Storage qui a les droits de lecture sur ce conteneur.
{/* CP-STEPS-END:etape-4 */}

### Configurations OS

{/* CP-STEPS-START:etape-5 */}
Renseignez les paramètres du système d'exploitation pour vos machines virtuelles, à commencer par le **Nom de domaine**. Un domaine privé, comme `mydomain.local`, est valide.

La **Clé de licence SUSE** est optionnelle. Pour mettre à jour les paquets du système d'exploitation avant l'installation, renseignez d'abord cette clé : l'option <code className="action">Réaliser une mise à jour des paquets OS avant l'installation</code> ne devient disponible qu'une fois la clé saisie.

Sous **Firewall local**, vous pouvez activer le pare-feu au niveau du système d'exploitation de vos machines virtuelles, séparément pour les services centraux, les serveurs applicatifs et la base de données SAP HANA. En cas d'activation, une zone « SAP » est créée dans le service « firewalld » autorisant les communications réseau sélectionnées.
{/* CP-STEPS-END:etape-5 */}

### Machines virtuelles

{/* CP-STEPS-START:etape-6 */}
Renseignez les informations pour la configuration et le dimensionnement de vos machines virtuelles. La section comporte trois parties :

- les paramètres réseau : <code className="action">Groupe de ports VMware</code>, **Masque de sous-réseau** et **Passerelle par défaut** ;
- le **Serveur SAP HANA** : <code className="action">Modèle OVA</code>, <code className="action">Datastore</code>, <code className="action">Politique de stockage Thick</code>, puis le nom, le mot de passe root, l'adresse IPv4, le numéro d'instance, les vCPU et la RAM de la machine virtuelle ;
- les **Serveurs applicatifs** : leur modèle OVA et leur datastore, puis une carte par serveur. Cliquez sur <code className="action">Ajouter un serveur</code> pour en ajouter un, jusqu'à 12 serveurs applicatifs.

Nous recommandons vivement d'utiliser le datastore vSAN pour la machine virtuelle hébergeant la base de données SAP HANA, offrant des performances optimisées. Pour les serveurs d'application SAP, vous avez cependant la possibilité d'utiliser un datastore NFS (ssd-XXXXXX).

Il est également recommandé de créer et de sélectionner votre politique de stockage Thick pour votre machine virtuelle SAP HANA. Vous pouvez retrouver les informations relatives à cette politique de stockage dans notre [documentation](/guides/hosted-private-cloud/sap-on-ovhcloud/cookbook-sap-hana-template-vmware) au chapitre « Configuration des paramètres avancés », point 5.

:::warning
Il n'est pas possible d'appliquer une politique de stockage Thick sur les datastores NFS (ssd-XXXXXX). Par conséquent, si vous sélectionnez un datastore NFS pour votre machine SAP HANA, la politique de stockage Thin sera utilisée.

:::


Toutes les machines virtuelles doivent être déployées dans le même sous-réseau. Ce sous-réseau doit avoir un accès à Internet pour télécharger les sources SAP depuis votre conteneur Object Storage OVHcloud et mettre à jour les paquets du système d'exploitation si vous avez activé cette option. Le groupe de ports choisi doit également fournir le DHCP : sur un réseau sans DHCP, la pré-installation échoue dès sa première étape.

Vous pouvez choisir un modèle OVA/OVF de machine virtuelle différent pour votre base de données SAP HANA et pour vos serveurs applicatifs, ainsi qu'un datastore différent. Cependant, il n'est pas possible de déployer vos serveurs applicatifs sur différents modèles OVA/OVF de machine virtuelle et datastores. De plus, si le serveur SAP HANA et les serveurs applicatifs utilisent des modèles différents, la licence SUSE n'est pas activée sur les machines et le système d'exploitation n'est pas mis à jour.
{/* CP-STEPS-END:etape-6 */}

### Fonctionnalités SAP optionnelles

{/* CP-STEPS-START:etape-7 */}
Cette section vous permet d'activer deux fonctionnalités optionnelles : notre agent de sauvegarde pour SAP HANA et l'export des logs SAP vers Logs Data Platform. Chaque interrupteur affiche les champs à renseigner.

**Sauvegarder les bases de données SAP HANA avec l'agent OVHcloud Backint**

Nous vous invitons à prendre connaissance des prérequis dans notre [documentation](/guides/hosted-private-cloud/sap-on-ovhcloud/cookbook-install-ovhcloud-backint-agent).

**Envoyer les logs SAP vers OVHcloud Logs Data Platform**

Nous vous invitons à prendre connaissance des chapitres Logs Data Platform, Data stream et outils de collecte dans notre [documentation](/guides/hosted-private-cloud/sap-on-ovhcloud/cookbook-sap-logs-on-ovhcloud-logs-data-platform-solution-setup).
{/* CP-STEPS-END:etape-7 */}

### Récapitulatif et soumission

{/* CP-STEPS-START:etape-8 */}
Vérifiez l'exactitude des informations de chaque section pour éviter tout problème lors de la pré-installation.

Une fois toutes les sections complètes, vous pouvez exporter cette configuration au format JSON avec <code className="action">Exporter la configuration</code>. Vous pourrez ensuite la réimporter dans une nouvelle configuration avec <code className="action">Importer un document de configuration</code> pour pré-remplir les informations.

:::warning
Le fichier exporté contient toutes les valeurs que vous avez saisies en clair, y compris les mots de passe des comptes SAP, les mots de passe root des machines virtuelles, les clés secrètes Object Storage et le certificat de la plateforme de logs. Conservez-le en lieu sûr.

:::

Cliquez ensuite sur <code className="action">Soumettre la configuration</code>. La soumission provisionne les machines virtuelles et y installe SAP : à partir de là, la configuration ne peut plus être modifiée.

Vous suivez ensuite la pré-installation depuis sa propre page, qui affiche sa progression étape par étape, ce qui est installé et ses horodatages. Une pré-installation qui a échoué n'est jamais reprise ni redémarrée : pour recommencer, créez et soumettez une nouvelle configuration. Vous pouvez également retrouver la liste de l'ensemble de vos pré-installations et leurs détails dans l'onglet <code className="action">Pré-installations</code> du <code className="action">SAP Features Hub</code>.
{/* CP-STEPS-END:etape-8 */}

## Résolution des problèmes courants

<details>

<summary>Le message d'erreur indique que la configuration demandée dépasse les capacités de mon datacentre.</summary>


Si vous avez récemment supprimé des machines virtuelles pour libérer de la capacité au sein de votre datacentre, il se peut que les informations de capacité ne soient pas encore mises à jour. Veuillez patienter quelques minutes avant de réessayer. Si le problème persiste, n'hésitez pas à contacter le support OVHcloud pour obtenir de l'aide.

</details>


<details>

<summary>Le fichier JSON importé contient des erreurs de syntaxe.</summary>


Assurez-vous que le fichier JSON est correctement formaté. Vous pouvez utiliser un validateur JSON pour vérifier la validité du fichier avant de l'importer dans l'assistant.

</details>


<details>

<summary>Les sources SAP ne sont pas accessibles depuis le conteneur Object Storage.</summary>


Vérifiez que le conteneur Object Storage est correctement configuré et que les permissions d'accès sont appropriées. Un utilisateur Object Storage ayant les droits de lecture est nécessaire pour le téléchargement des sources sur vos machines virtuelles.

</details>


<details>

<summary>Les paramètres de mémoire alloués aux machines virtuelles sont insuffisants.</summary>


Augmentez la quantité de mémoire RAM allouée aux machines virtuelles en fonction des exigences de SAP pour votre configuration. Consultez la documentation SAP pour obtenir des recommandations sur la mémoire.

</details>


<details>

<summary>Un message d'erreur indique qu'une erreur interne s'est produite lors de l'installation et je ne peux pas démarrer une nouvelle installation car une tâche précédente est toujours en cours.</summary>


Si une erreur interne survient et que le statut de la tâche n'a pas correctement été mis à jour, veuillez supprimer la tâche en question via notre API.

<Api version="v1" section="/dedicatedCloud" method="DELETE" route={"/dedicatedCloud/\{serviceName\}/sap/\{taskId\}"} />

Cette action permettra de supprimer la tâche en erreur bloquant les nouvelles installations. Veuillez également supprimer les machines virtuelles qui ont été créées par la tâche d'installation en erreur.

</details>


<details>

<summary>L'installation SAP tombe en erreur car des paquets sont dans une version inférieure à celles exigées par SAP.</summary>


Vérifiez que le modèle OVA/OVF de machine virtuelle utilisé est conforme aux exigences de SAP pour la version que vous souhaitez installer. Si le modèle est supporté mais que certaines versions de paquets sont obsolètes, effectuez une mise à jour système en utilisant l'option disponible dans l'assistant. Vous devrez fournir une licence SUSE pour cette opération. Si le modèle OVA/OVF est trop ancien, envisagez de sélectionner un modèle plus récent.

</details>


## Questions fréquentes (FAQ)

<details>

<summary>Puis-je utiliser un service VMware on OVHcloud autre que celui de la gamme SAP HANA on Private Cloud ?</summary>


Bien que notre assistant de pré-installation SAP soit optimisé pour la gamme SAP HANA on Private Cloud, il est possible d'utiliser un service VMware on OVHcloud d'une autre gamme. Cependant, nous recommandons vivement la gamme SAP HANA on Private Cloud pour bénéficier d'une solution spécifiquement conçue et certifiée pour héberger des systèmes SAP avec une base de données SAP HANA.

</details>


<details>

<summary>Puis-je utiliser mes modèles OVA/OVF de machines virtuelles pour déployer le système SAP ?</summary>


Vous ne pouvez pour le moment pas utiliser vos modèles OVA/OVF de machines virtuelles pour déployer votre système SAP via notre assistant.

</details>


<details>

<summary>Puis-je reprendre mon installation si celle-ci a échoué ?</summary>


En cas d'échec de l'installation, vous ne pourrez pas reprendre l'installation. Il faudra supprimer le système SAP construit et lancer une nouvelle installation. Si nécessaire, vous pouvez également contacter le [support OVHcloud](https://help.ovhcloud.com/csm?id=csm_get_help) pour obtenir de l'aide.

</details>


<details>

<summary>Puis-je ajouter un serveur d'application SAP à un système SAP existant ?</summary>


L'assistant de pré-installation SAP d'OVHcloud ne prend pas en charge l'ajout de composants supplémentaires à un système SAP déjà existant.

</details>
