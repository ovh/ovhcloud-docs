## Objectif

**Ce guide vous présente comment interconnecter deux clusters Nutanix Fournis par OVHcloud au travers d'un même vRack sur deux sites OVHcloud distants. Dans ce guide l'interconnexion est effectuée entre les datacenters de Gravelines et de Roubaix.** 

:::warning
OVHcloud vous met à disposition des services dont la configuration, la gestion et la responsabilité vous incombent. Il vous appartient donc de ce fait d’en assurer le bon fonctionnement.

Ce guide a pour but de vous accompagner au mieux sur des tâches courantes. Néanmoins, nous vous recommandons de faire appel à un prestataire spécialisé si vous éprouvez des difficultés ou des doutes concernant l’administration, l’utilisation ou la mise en place d’un service sur un serveur.

:::

## Prérequis

- Être connecté sur vos clusters via Prism Central.

[[cpnav:privatecloud-nutanix-console+network-vrack-console+network-load-balancer-console]]

## En pratique

Nous allons interconnecter deux clusters Nutanix distants, l'un à Gravelines et l'autre à Roubaix au travers du même vRack.<br/>
Consultez notre [présentation du vRack](https://www.ovhcloud.com/fr/network/vrack/) pour en savoir plus sur la solution vRack OVHcloud.

### Préparation des deux clusters avant l'interconnexion

Avant d'interconnecter les deux clusters il faut s'assurer qu'ils utilisent des adresses IP différentes (sauf pour la passerelle) sur une même plage d'adresses IP.<br/>
Dans notre guide, nous allons utiliser la plage d'adresses `192.168.0.0/22`.

 Le cluster de Gravelines utilise ces adresses :

- Serveur 1 : adresse VM **CVM** `192.168.2.1`, adresse IP hyperviseur **AHV** `192.168.2.21`.
- Serveur 2 : adresse VM **CVM** `192.168.2.2`, adresse IP hyperviseur **AHV** `192.168.2.22`.
- Serveur 3 : adresse VM **CVM** `192.168.2.3`, adresse IP hyperviseur **AHV** `192.168.2.23`.
- Adresse virtuelle de **Prism Element** : `192.168.2.100`.
- Adresse IP **Prism Central** :`192.168.2.101`.
- Passerelle : `192.168.2.254`.
- Version du cluster : `6.1`.

Le cluster de Roubaix utilise ces adresses :

- Serveur 1 : adresse VM **CVM** `192.168.1.1`, adresse IP hyperviseur **AHV** `192.168.1.21`.
- Serveur 2 : adresse VM **CVM** `192.168.1.2`, adresse IP hyperviseur **AHV** `192.168.1.22`.
- Serveur 3 : adresse VM **CVM** `192.168.1.3`, adresse IP hyperviseur **AHV** `192.168.1.23`.
- Adresse virtuelle de **Prism Element** : `192.168.1.100`.
- Adresse IP **Prism Central** :`192.168.1.101`.
- Passerelle : `192.168.2.254`.
- Version du cluster : `6.1`.

Aidez-vous de notre guide dédié au [redéploiement personnalisé de votre Cluster](/guides/hosted-private-cloud/nutanix-on-ovhcloud/cluster-custom-redeployment).

:::info
Le guide mentionné ci-dessus vous propose de redéployer les deux clusters. Néanmoins, vous pouvez n'en redéployer qu'un, le plus important est de ne pas avoir les mêmes adresses IP identiques sur l'ensemble du réseau, sauf pour la passerelle OVHGateway.

:::


### Arrêt de la machine virtuelle OVHgateway.

La connexion Internet sortante est fournie par les machines virtuelles OVHgateway avec la même adresse IP privée sur les deux sites. Nous allons arrêter la machine virtuelle OVHGateway de Roubaix. Cette machine virtuelle ne sera plus nécessaire.

La connexion Internet sortante sera rétablie quand l'interconnexion au travers du **vRack** sera faite.

Connectez-vous à l'interface **Prism Central** du cluster situé à Roubaix. 

Rendez-vous dans la gestion des machines virtuelles, sélectionnez `OVHgateway` au travers du menu <code className="action">Actions</code> et cliquez sur <code className="action">Guest Shutdown</code>.

<img className="thumbnail" alt="01 OVHgateway Shutdown 01" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/45-vrack-interconnection/01-ovhgateway-shutdown01.png" loading="lazy" />

L'accès à Prism Central est maintenu à l'aide du Load Balancer.

#### Paramétrage des vRack

{/* CP-STEPS-START:parametrage-des-vrack */}

Cette opération consiste à supprimer l'affectation du vRack à Roubaix et ensuite à étendre le vRack de Gravelines avec Roubaix. Les modifications du vRack se font au travers de la console OVHcloud.

{/* CP-STEPS-END:parametrage-des-vrack */}
#### Suppression des éléments du vRack de Roubaix.

{/* CP-STEPS-START:suppression-elements-vrack-roubaix */}

Choisissez le cluster de Roubaix dans la catégorie `Nutanix`. Dans son onglet <code className="action">Vue d'ensemble</code>, notez le nom du vRack indiqué à la ligne **vRack** de la section **Réseau**.

Dans le menu latéral, ouvrez **Réseau**, cliquez sur <code className="action">vRack</code>, puis sur le vRack concerné, et ouvrez son onglet <code className="action">Services rattachés</code>. Le tableau liste tous les éléments qui se trouvent dans votre vRack :

 - Les serveurs dédiés ;
 - les IP ;
 - le Load Balancer.

 Notez-les. Les services se détachent un par un : sur la ligne de chaque service, cliquez sur <code className="action">Détacher</code>, puis confirmez dans la fenêtre qui s'ouvre. Répétez l'opération pour tous les services.

:::warning
Cette opération peut durer quelques minutes, veuillez patienter pendant cette période.

:::

{/* CP-STEPS-END:suppression-elements-vrack-roubaix */}
#### Ajout d'éléments supprimés du vRack de Roubaix dans le vRack de Gravelines

{/* CP-STEPS-START:ajout-elements-vrack-gravelines */}

Choisissez le cluster de Gravelines dans la catégorie `Nutanix` et, dans son onglet <code className="action">Vue d'ensemble</code>, notez le nom du vRack à la ligne **vRack** de la section **Réseau**.

Dans le menu latéral, ouvrez **Réseau**, cliquez sur <code className="action">vRack</code>, puis sélectionnez le vRack de Gravelines. Cliquez sur l'onglet <code className="action">Services rattachés</code>, puis sur <code className="action">Attacher un service</code>. La page **Services éligibles** s'ouvre.

Rattachez ces éléments du cluster de Roubaix :

- Les serveurs physiques ;
- l'IP publique.

Dans le menu déroulant **Type de service**, sélectionnez **Serveurs dédiés**, puis cliquez sur <code className="action">Rattacher</code> sur la ligne de chaque serveur physique. Sélectionnez ensuite **Blocs IPv4 additionnels** et cliquez sur <code className="action">Rattacher</code> sur la ligne du bloc d'IP publique.

:::warning
Cette opération peut durer quelques minutes, veuillez patienter pendant cette période.

:::


:::info
L'ajout de l'adresse publique n'est pas obligatoire mais elle pourra être disponible pour de futurs besoins.

:::

Le **vRack** qui était uniquement utilisé par les serveurs du cluster de Gravelines est maintenant utilisé sur les deux sites et contient :

- Les serveurs physiques des deux clusters.
- Les adresses IP publiques des deux clusters.
- Le Load Balancer de Gravelines qui sert pour Prism Central.

L'accès Internet sur le site de Roubaix en sortie est à nouveau disponible au travers du vRack et de la machine virtuelle OVHgateway de Gravelines. L'accès à Prism Central du cluster de Roubaix est pour l'instant inaccessible.

{/* CP-STEPS-END:ajout-elements-vrack-gravelines */}
### Modification du Load Balancer de Roubaix

Nous allons reconfigurer le Load Balancer de Roubaix pour qu'il fonctionne avec le vRack commun aux deux sites, afin de pouvoir accéder à Prism Central pour le cluster de Roubaix.

{/* CP-STEPS-START:modification-load-balancer-roubaix */}

Dans le menu latéral, ouvrez **Réseau**, cliquez sur <code className="action">Load Balancer</code>, puis sélectionnez le Load Balancer de Roubaix.

Positionnez-vous sur l'onglet <code className="action">Réseau</code>. Le Load Balancer de Roubaix ayant été détaché de son vRack dans la section précédente, son ancien réseau privé n'existe plus : le détachement du vRack supprime toutes les configurations de réseaux privés du Load Balancer.

Dans la section **vRack**, cliquez sur <code className="action">Associer un vRack</code>. Dans la fenêtre **Attacher un vRack**, sélectionnez le vRack commun aux deux sites et cliquez sur <code className="action">Attacher</code>.

Dans la section **Réseaux privés**, cliquez sur <code className="action">Ajouter un réseau privé</code>. La page **Ajouter un réseau privé** s'ouvre.

Choisissez ces valeurs :

- **Nom d'affichage** (facultatif) : Nom du réseau privé.
- **VLAN** : VLAN du réseau d'administration de Nutanix, normalement le 1.
- **Sous-réseau (CIDR)** : LAN du réseau privé 192.168.0.0/22.
- **NAT IP** : Plage d'adresses utilisée par le Load Balancer 192.168.2.128/27.

:::warning
La plage choisie pour **NAT IP** ne doit pas être utilisée par d'autres éléments du réseau privé, notamment la plage prise par le Load Balancer de Gravelines.

:::

Cliquez ensuite sur <code className="action">Ajouter le réseau privé</code>.

Reliez la ferme de serveurs à ce réseau privé : rendez-vous dans l'onglet <code className="action">Fermes de serveurs</code>, ouvrez le menu <code className="action">⋮</code> de la ferme `NutaCluster-all` et cliquez sur <code className="action">Modifier</code>. Sur la page **Modifier la ferme de serveurs**, sélectionnez le nouveau réseau dans le champ **Réseau privé**, puis cliquez sur <code className="action">Enregistrer les modifications</code>.

Vos modifications restent en attente tant que vous ne les appliquez pas. Rendez-vous dans l'onglet <code className="action">Vue d'ensemble</code> puis, dans la section **Informations générales**, sous **Déploiement**, cliquez sur <code className="action">Appliquer N changements</code>, N étant le nombre de modifications en attente. Un seul clic applique la configuration à toutes les zones de votre Load Balancer.

Le Load Balancer est relié au vRack commun aux deux sites et l'accès à Prism Central pour le cluster de Roubaix est à nouveau disponible.

{/* CP-STEPS-END:modification-load-balancer-roubaix */}
