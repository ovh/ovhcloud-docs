## Objectif

**Ce guide explique aux utilisateurs d'une organisation comment créer des instances (machines virtuelles), des volumes de stockage block et des réseaux privés avec le service Compute and Block Storage dans l'OPCP Cloud Console.**

## Prérequis

- Disposer d'un accès à l'OPCP Cloud Console, comme décrit dans notre guide « [OPCP Cloud Console](/guides/hosted-private-cloud/opcp/cloud-console-getting-started) ».
- Disposer du service **Compute and Block Storage**, activé pour votre organisation par votre IT Admin.
- Disposer d'une clé publique SSH : le formulaire de création d'instance en exige une.

## En pratique

### Ce que le service propose dans l'Alpha

| Ressource | Ce que vous pouvez faire |
|-----------|--------------------------|
| **Instances** | Créer, démarrer, arrêter, redémarrer et supprimer des machines virtuelles. Ouvrir leur console dans le navigateur. Changer leur gabarit. |
| **Block Storage** | Créer des volumes, les attacher à des instances et les détacher, augmenter leur taille. Chaque instance démarre sur un volume. |
| **Private Networks** | Créer des réseaux isolés des autres organisations, et y connecter des instances. |
| **SSH keys** | Enregistrer les clés publiques injectées dans les nouvelles instances. |

Vous gérez ces ressources dans l'OPCP Cloud Console, avec la CLI OpenStack, ou dans Horizon pour les cas que l'OPCP Cloud Console ne couvre pas encore.

### Ouvrir le service

Dans la barre latérale de l'OPCP Cloud Console, ouvrez **Compute and Block Storage**. Le service affiche son propre menu :

| Menu | Contenu |
|------|---------|
| <code className="action">Compute</code> > <code className="action">Instances</code> | Vos instances. |
| <code className="action">Storage</code> > <code className="action">Block Storage</code> | Vos volumes. |
| <code className="action">Network</code> > <code className="action">Private Networks</code> | Vos réseaux privés. |
| <code className="action">User settings</code> > <code className="action">SSH keys</code> | Vos clés publiques SSH. |
| <code className="action">Manage</code> > <code className="action">API access</code> | Les endpoints et identifiants pour utiliser l'API OpenStack. |

L'onglet **Overview** du service affiche ses Outputs, dont le fichier `openrc.sh` pour la CLI OpenStack. Pour utiliser la CLI, consultez notre guide « [Comment installer une instance depuis la CLI OpenStack](/guides/hosted-private-cloud/opcp/how-to-setup-instance-from-cli) ».

### Gabarits et images

Un **gabarit** (*flavor*) définit le nombre de vCPU et la quantité de RAM d'une instance. Dans l'Alpha, utilisez les gabarits `cb-`. Leur nom indique la famille, le nombre de vCPU et la RAM en Go.

| Famille | Gabarits (vCPU / RAM) |
|---------|-----------------------|
| Usage général (`cb-b-`) | `cb-b-2-8` (2 / 8 Go), `cb-b-4-16` (4 / 16 Go), `cb-b-8-32` (8 / 32 Go) |
| Optimisé calcul (`cb-c-`) | `cb-c-2-4` (2 / 4 Go), `cb-c-4-8` (4 / 8 Go), `cb-c-8-16` (8 / 16 Go) |
| Optimisé mémoire (`cb-r-`) | `cb-r-2-16` (2 / 16 Go), `cb-r-4-32` (4 / 32 Go), `cb-r-8-64` (8 / 64 Go) |

Les gabarits n'ont pas de disque local : le disque système d'une instance est un volume de stockage block, dont vous choisissez la taille.

:::warning
Seuls les gabarits `cb-` peuvent exécuter des instances Compute and Block Storage. Avec la CLI OpenStack ou Horizon, une instance créée avec un autre gabarit reste à l'état `scheduling`.

:::

L'Alpha propose les images suivantes :

| Image | Utilisateur par défaut |
|-------|------------------------|
| `Debian 12 BMPOD` | `debian` |
| `Debian 13 BMPOD` | `debian` |
| `CentOS 9 BMPOD` | `cloud-user` |

### Ajouter une clé SSH

1. Accédez à <code className="action">User settings</code> > <code className="action">SSH keys</code>.
2. Ajoutez une nouvelle clé, donnez-lui un nom et collez votre clé **publique**, par exemple le contenu de `~/.ssh/id_ed25519.pub`.

Vous pouvez aussi créer la clé directement dans le formulaire de création d'instance, avec <code className="action">New SSH key</code>.

### Créer un réseau privé

1. Accédez à <code className="action">Network</code> > <code className="action">Private Networks</code> et cliquez sur <code className="action">Create network</code>.
2. Saisissez un **nom** (*Name*) et l'**adresse du réseau** (*Network address*), par exemple `192.168.1.0/24`.
3. Laissez **DHCP** activé, afin que les instances obtiennent leur adresse IP automatiquement.
4. Si besoin, ouvrez <code className="action">Advanced settings</code> pour définir les plages d'allocation d'adresses IP, les serveurs DNS ou des routes d'hôte.
5. Cliquez sur <code className="action">Create</code>.

:::info
Dans l'Alpha, les réseaux privés ne peuvent pas être connectés à Internet. Laissez <code className="action">Connect to Public Internet</code> désactivé.

:::

### Créer une instance

1. Accédez à <code className="action">Compute</code> > <code className="action">Instances</code> et cliquez sur <code className="action">Create instance</code>.
2. Saisissez un **nom** (*Name*).
3. Choisissez un **gabarit** (*Flavor*) dans l'une des familles `cb-`.
4. Laissez l'**isolation** (*Isolation*) sur <code className="action">Shared</code>. Les hyperviseurs dédiés ne sont pas disponibles dans l'Alpha.
5. Sous **Storage**, choisissez l'**image** et la taille du volume système. Le volume est créé avec l'instance.
6. Sous **Network**, sélectionnez votre réseau privé.
7. Sous **Access & Security**, sélectionnez votre clé SSH. Une clé SSH est obligatoire.
8. Si besoin, sous <code className="action">Advanced settings</code>, ajoutez des données utilisateur (un script cloud-init exécuté au premier démarrage), par exemple pour définir un mot de passe pour la console VNC (consultez la section [Se connecter à une instance](#se-connecter-à-une-instance)).
9. Confirmez la création.

L'instance est `building`, puis `active`.

### Se connecter à une instance

Dans l'Alpha, les instances ne sont pas joignables depuis l'extérieur de la plateforme : il n'y a ni adresse IP publique ni IP flottante (*floating IP*), vous ne pouvez donc pas vous y connecter en SSH depuis votre poste.

- **Dans le navigateur** : dans la liste des instances, choisissez <code className="action">VNC</code> pour ouvrir la console de l'instance dans le navigateur.
- **Entre instances** : une instance peut joindre les autres instances du même réseau privé, par exemple `ssh debian@192.168.1.10` avec l'utilisateur par défaut de l'image.

Les images n'autorisent que la connexion par clé SSH. Pour vous connecter via la console VNC, définissez un mot de passe pour l'utilisateur par défaut lors de la création de l'instance, avec des données utilisateur telles que :

```yaml
#cloud-config
password: <votre-mot-de-passe>
chpasswd:
  expire: false
```

### Créer et attacher un volume

1. Accédez à <code className="action">Storage</code> > <code className="action">Block Storage</code> et cliquez sur <code className="action">Create</code>.
2. Saisissez un **nom** (*Name*) et une **taille** (*Size*).
3. Choisissez une **source** (*Source*) : <code className="action">No source</code> pour un volume vide, une image, ou un autre volume à copier.
4. Si besoin, activez <code className="action">Attach to instance after creation</code> et sélectionnez l'instance.
5. Cliquez sur <code className="action">Create</code>.

Pour attacher un volume existant, ouvrez l'instance et ajoutez-lui le volume, ou attachez-le depuis la page du volume. Le volume apparaît alors dans l'instance comme un nouveau disque (par exemple `/dev/vdb`) : formatez-le et montez-le depuis le système d'exploitation.

Pour détacher un volume, ouvrez-le et choisissez <code className="action">Detach volume</code>. Le volume système d'une instance ne peut pas être détaché.

### Connecter une instance à un réseau

Pour connecter une instance existante à un autre réseau privé :

- depuis le réseau : ouvrez-le dans <code className="action">Private Networks</code> et attachez l'instance ;
- ou depuis l'instance : ouvrez-la et ajoutez le réseau.

L'instance obtient une nouvelle interface réseau avec une adresse de ce réseau. Pour la déconnecter, choisissez <code className="action">Detach instance</code> sur le réseau.

### Ce qui n'est pas encore dans l'Alpha

Les fonctionnalités suivantes ne sont pas disponibles dans l'Alpha :

- L'accès public aux instances : pas de connexion Internet pour les réseaux privés, pas d'adresses IP flottantes, pas d'accès SSH depuis l'extérieur de la plateforme.
- Les snapshots de volume, et l'extension d'un volume chiffré et attaché.
- Les hyperviseurs dédiés à une organisation.
- Les instances bare metal et les instances GPU.
- Les sauvegardes vers Object Storage.
- La supervision et les alertes pour les instances.
