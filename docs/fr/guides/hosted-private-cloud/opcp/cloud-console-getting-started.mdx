## Objectif

**Ce guide explique aux Organization Admins et aux Organization Users comment se connecter à l'OPCP Cloud Console, utiliser les services activés pour leur organisation et créer les comptes utilisateurs de l'organisation.**

L'**OPCP Cloud Console** est l'interface Cloud Store destinée aux organisations. Pour une présentation de Cloud Store et de ses concepts, consultez notre guide « [Premiers pas avec le Cloud Store](/guides/hosted-private-cloud/opcp/cloudstore-getting-started) ».

## Prérequis

- Disposer d'une organisation créée par votre IT Admin, avec au moins un service activé.
- Disposer de l'**URL** de l'OPCP Cloud Console, de votre identifiant (votre adresse e-mail) et de votre mot de passe de première connexion : le premier mot de passe généré lors de la création de votre organisation, fourni par votre IT Admin, si vous êtes l'Organization Admin ; sinon, le mot de passe temporaire défini par votre Organization Admin.
- Disposer d'un accès HTTPS (TCP/443) à l'URL de l'OPCP Cloud Console depuis votre poste.

## En pratique

### Connexion à l'OPCP Cloud Console

1. Accédez à l'**URL** de l'OPCP Cloud Console. Si l'URL n'inclut pas déjà votre organisation, saisissez le **nom de l'organisation** et cliquez sur <code className="action">Submit</code>.

    <img className="thumbnail" alt="Saisie du nom de l'organisation sur la page de l'OPCP Cloud Console" src="/images/hosted-private-cloud/opcp/cloud-console-getting-started/cloud_console_organization.png" loading="lazy" />

2. Une page affiche l'organisation sélectionnée. Cliquez sur <code className="action">Log in</code>, puis, sur le formulaire de connexion de votre organisation, saisissez votre adresse e-mail et votre mot de passe et cliquez sur <code className="action">Sign In</code>.

    <img className="thumbnail" alt="Page affichant l'organisation sélectionnée avec les boutons Log in et Change organization" src="/images/hosted-private-cloud/opcp/cloud-console-getting-started/cloud_console_login.png" loading="lazy" />

3. Lors de votre première connexion, définissez un nouveau mot de passe.

:::warning
Votre premier mot de passe est temporaire : le formulaire de connexion vous demande de le remplacer par un mot de passe de votre choix lors de votre première connexion.

:::

#### Se déconnecter

Pour vous déconnecter, cliquez sur votre badge utilisateur en haut à droite, puis choisissez l'option de déconnexion dans le menu.

La session expire après 30 minutes d'inactivité, et au plus tard 10 heures après la connexion.

### Utiliser les services activés

La barre latérale liste les services activés de votre organisation, c'est-à-dire les services que votre IT Admin a activés pour elle.

<img className="thumbnail" alt="Page d'accueil de l'OPCP Cloud Console" src="/images/hosted-private-cloud/opcp/cloud-console-getting-started/cloud_console_home.png" loading="lazy" />

Ouvrez un service pour afficher sa version et ses onglets :

- **Overview** affiche les **Outputs** du service : les informations nécessaires pour vous y connecter avec vos propres outils, par exemple un fichier `openrc.sh` pour la CLI OpenStack et le nom de la région.
- **Onglets du service** : chaque service peut ajouter ses propres onglets pour gérer ses ressources cloud, par exemple `Compute` pour les machines virtuelles ou `Buckets` pour Object Storage.

Chaque service définit les adresses (FQDN) de ses propres interfaces. L'OPCP Cloud Console les affiche intégrées lorsque c'est possible, ou sous forme de lien direct sinon.

<img className="thumbnail" alt="Outputs d'un service Compute and Block Storage" src="/images/hosted-private-cloud/opcp/cloud-console-getting-started/cloud_console_compute_overview.png" loading="lazy" />

<img className="thumbnail" alt="Buckets d'un service Object Storage" src="/images/hosted-private-cloud/opcp/cloud-console-getting-started/cloud_console_object_storage.png" loading="lazy" />

### Créer un compte utilisateur

L'Organization Admin crée les comptes utilisateurs dans le **realm Keycloak** de l'organisation. Chaque organisation dispose de son propre realm, isolé des autres organisations : toute opération liée à l'identité (ajout d'utilisateurs, configuration de la fédération, définition de rôles) s'effectue dans le realm de l'organisation cible.

<img className="thumbnail" alt="Utilisateurs du realm d'une organisation" src="/images/hosted-private-cloud/opcp/cloud-console-getting-started/organization_realm_users.png" loading="lazy" />

1. Ouvrez la console d'administration Keycloak de votre organisation et connectez-vous en tant qu'Organization Admin. Votre IT Admin peut vous en communiquer l'URL : dans l'OPCP Admin Console, sous <code className="action">Management</code> > <code className="action">Organizations</code>, l'icône en forme de bouclier de votre organisation l'ouvre, de même que le lien <code className="action">IAM Admin Console</code> de la page de l'organisation. L'URL est de la forme `https://keycloak-layer-3.<domaine>/admin/account-<name>/console/`.
2. Accédez à <code className="action">Users</code> et cliquez sur <code className="action">Add user</code>.
3. Renseignez le nom d'utilisateur, l'e-mail, le prénom et le nom. L'e-mail est l'**identifiant de connexion** de l'utilisateur.
4. Cliquez sur <code className="action">Create</code>. Le nouvel utilisateur n'a pas encore de mot de passe.
5. Ouvrez l'onglet <code className="action">Credentials</code> de l'utilisateur et cliquez sur <code className="action">Set password</code>.
6. Saisissez un mot de passe et confirmez-le, laissez <code className="action">Temporary</code> activé et cliquez sur <code className="action">Save</code>. Avec <code className="action">Temporary</code> activé, l'utilisateur doit définir un nouveau mot de passe lors de sa première connexion.

    <img className="thumbnail" alt="Fenêtre Set password d'un utilisateur, avec l'interrupteur Temporary activé" src="/images/hosted-private-cloud/opcp/cloud-console-getting-started/organization_realm_set_password.png" loading="lazy" />

7. Aucun e-mail n'est envoyé : transmettez à l'utilisateur l'URL de l'OPCP Cloud Console, son e-mail et son mot de passe temporaire, par un canal sécurisé.

Pour retirer l'accès d'un utilisateur, désactivez son interrupteur <code className="action">Enabled</code>.

Depuis ce même realm, l'Organization Admin peut également configurer des groupes d'utilisateurs (<code className="action">Groups</code>), connecter le fournisseur d'identité de l'entreprise (<code className="action">Identity providers</code>) ou un annuaire LDAP / Active Directory (<code className="action">User federation</code>).

:::info
Les services déclarent leurs propres rôles et groupes, que la plateforme crée dans le realm lorsqu'ils sont activés pour l'organisation. Compute and Block Storage et Object Storage ne créent ni groupes ni droits par utilisateur : tous les utilisateurs de l'organisation peuvent les utiliser.

:::

### Correspondance des organisations dans Keycloak

:::info
L'OPCP Cloud Console repose sur sa **propre stack Keycloak dédiée**, indépendante du Keycloak OPCP Core et du Keycloak de l'OPCP Admin Console. Elle n'est pas fédérée avec ces instances : les identités, realms et identifiants gérés pour l'OPCP Cloud Console sont totalement isolés des administrateurs des autres couches d'identité OPCP.

:::

Chaque organisation dispose automatiquement d'un realm dédié, nommé `account-{name}`. Cette conception garantit :

- une configuration indépendante des flux d'authentification par organisation ;
- des bases d'utilisateurs et des mappings de rôles séparés par realm.
