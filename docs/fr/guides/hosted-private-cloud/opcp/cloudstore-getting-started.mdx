## Objectif

**Ce guide vous présente Cloud Store, ses deux consoles et les concepts à connaître avant de commencer à l'utiliser.**

**Cloud Store** est la plateforme de gestion d'[On-Premise Cloud Platform (**OPCP**)](/guides/hosted-private-cloud/opcp/getting-started). Il fonctionne au-dessus d'OPCP Core et du matériel OPCP, et vous permet de déployer des services cloud sur vos hôtes bare metal et de les mettre à disposition des entreprises, départements ou équipes qui les utilisent.

## Prérequis

- Une plateforme OPCP avec Cloud Store, livrée par OVHcloud.
- L'**URL** de l'OPCP Admin Console et vos identifiants de connexion, fournis lors de la livraison du service.

## En pratique

### Les deux consoles de Cloud Store

Cloud Store propose deux interfaces, une par public :

| Console | Pour | Rôle |
|---------|------|------|
| **OPCP Admin Console** | IT Admins | Créer des organisations, déployer des services depuis le catalogue de services et les activer pour des organisations. |
| **OPCP Cloud Console** | Organization Admins et Organization Users | Utiliser les services activés pour l'organisation et créer des ressources cloud, comme des machines virtuelles, des volumes ou des buckets. |

Chaque console dispose de son propre guide :

- [OPCP Admin Console](/guides/hosted-private-cloud/opcp/admin-console-getting-started)
- [OPCP Cloud Console](/guides/hosted-private-cloud/opcp/cloud-console-getting-started)

### Rôles

| Rôle | Console | Responsabilités |
|------|---------|-----------------|
| IT Admin | OPCP Admin Console | Crée les organisations, déploie les services et les active pour les organisations. |
| Service Packager | — | Conçoit, maintient et publie des services dans le catalogue de services, et définit leurs versions et leurs descriptions. |
| Organization Admin | OPCP Cloud Console | Créé avec l'organisation. Gère les utilisateurs de l'organisation. |
| Organization User | OPCP Cloud Console | Utilise les services activés pour l'organisation et crée des ressources cloud. |

### Concepts clés

#### Organisation

Une **organisation** est un environnement isolé dans lequel un groupe d'utilisateurs consomme les services activés pour lui. Elle représente généralement une entreprise, un département ou une équipe. Chaque organisation dispose de son propre realm Keycloak, qui isole ses identités de celles des autres organisations.

#### Catalogue de services et déploiements de services

Le **catalogue de services** (Service Catalog) liste les services disponibles sur votre plateforme, par exemple Compute and Block Storage ou Object Storage. Depuis le catalogue, l'IT Admin déploie une version donnée d'un service sur l'infrastructure : il obtient un **déploiement de service** (Service Deployment). Tous les déploiements de services sont regroupés dans la section <code className="action">Deployments</code> de l'OPCP Admin Console.

Un même service peut avoir plusieurs déploiements, par exemple un par région ou par datacenter.

#### Pools d'hôtes, plan de contrôle et plans de données

Lors du déploiement d'un service, l'IT Admin répartit des hôtes bare metal dans des **pools d'hôtes** (Host Pools). Un pool d'hôtes est un groupe d'hôtes qui assure un rôle du déploiement de service :

- le **plan de contrôle** (Control Plane), qui gère le service et son cycle de vie ;
- un ou plusieurs **plans de données** (Data Planes), qui exécutent les charges de travail et les ressources cloud des organisations ;
- ou les deux rôles à la fois, dans un pool convergé unique, comme pour les services de stockage de type Ceph.

Pour faire évoluer le plan de contrôle ou un plan de données, ajoutez des hôtes au pool d'hôtes correspondant.

#### Services activés

Un **service activé** (Enabled Service) est un déploiement de service activé pour une organisation. Il rend le service visible dans l'OPCP Cloud Console de cette organisation, et l'organisation est rattachée à un ou plusieurs plans de données du déploiement. Selon le service, un plan de données est partagé entre plusieurs organisations ou dédié à une seule : les services qui ne peuvent pas être partagés disposent d'un pool d'hôtes dédié pour chaque organisation.

### Parcours types

1. **Déploiement d'un service** : l'IT Admin se connecte à l'OPCP Admin Console, ouvre le catalogue de services, sélectionne un service et le déploie. Il choisit une version, répartit les pools d'hôtes et configure le service.
2. **Création d'une organisation** : l'IT Admin ouvre <code className="action">Organizations</code>, crée une organisation pour le client et définit son Organization Admin (e-mail, prénom, nom).
3. **Activation d'un service** : l'IT Admin active le déploiement de service pour l'organisation, depuis la page du déploiement ou depuis celle de l'organisation.
4. **Utilisation de la Cloud Console** : l'Organization Admin se connecte à l'OPCP Cloud Console et gère les utilisateurs de l'organisation. Les Organization Users ouvrent les services activés et créent des ressources cloud.

### Authentification et zones de sécurité

La plateforme répartit l'authentification en deux **zones de sécurité** (Security Zones), chacune reposant sur ses propres instances Keycloak :

| Zone de sécurité | Instance Keycloak | Utilisateurs | Rôle |
|------------------|-------------------|--------------|------|
| Admin Security Zone | Keycloak OPCP Core | DC operators, Super admins | Identité au niveau infrastructure |
| Admin Security Zone | Keycloak de l'OPCP Admin Console | IT Admins, Service Packagers | Gestion de la plateforme |
| Public Security Zone | Un realm Keycloak par organisation | Organization Admins, Organization Users | OPCP Cloud Console et services activés |

- Au sein de l'**Admin Security Zone**, le Keycloak de l'OPCP Admin Console est fédéré avec le Keycloak OPCP Core : les droits accordés sur les projets OpenStack dans OPCP Core sont propagés à l'OPCP Admin Console.
- La **Public Security Zone** repose sur une instance Keycloak indépendante gérée par l'API de l'OPCP Admin Console. Elle n'est pas fédérée avec l'Admin Security Zone, et le realm de chaque organisation est isolé des autres.
