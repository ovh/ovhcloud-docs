## Objectif

**Ce guide vous présente comment vous connecter à l'OPCP Admin Console, comprendre ses concepts clés et effectuer les premières opérations : créer des organisations, déployer des services et les activer pour des organisations.**

L'**OPCP Admin Console** est l'interface de gestion centrale des IT Admins dans **Cloud Store**, déployée sur [On-Premise Cloud Platform (**OPCP**)](/guides/hosted-private-cloud/opcp/getting-started). Elle permet de gérer les organisations, de déployer des services et de contrôler les accès sur l'ensemble de la plateforme, afin que les IT Admins puissent proposer des services Cloud Native à leurs clients depuis un catalogue de services. Avec l'**OPCP Cloud Console**, l'interface en libre-service des organisations, elle compose Cloud Store.

## Prérequis

- L'**URL** de votre OPCP Admin Console, fournie lors de la livraison du service.
- Les identifiants de connexion (nom d'utilisateur et mot de passe) fournis lors de la livraison du service. Ces identifiants sont gérés par **Keycloak**, la solution de gestion des identités et des accès utilisée par la plateforme.

## En pratique

### Connexion à l'OPCP Admin Console

Accédez à l'**URL** fournie pour votre OPCP Admin Console. Une page de connexion s'affiche.

<img className="thumbnail" alt="Page de connexion de l'OPCP Admin Console" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/admin_console_login.png" loading="lazy" />

Cliquez sur le bouton de connexion pour être redirigé vers la page d'authentification **Keycloak**. Deux options s'offrent à vous :

- Saisir vos identifiants directement dans le formulaire de connexion Keycloak.
- Utiliser le bouton <code className="action">OPCP-SSO</code> pour vous authentifier via le Keycloak OPCP Core fédéré. Cette option permet aux utilisateurs déjà enregistrés dans OPCP Core de se connecter sans gérer un jeu d'identifiants supplémentaire.

<img className="thumbnail" alt="Formulaire de connexion Keycloak de l'OPCP Admin Console" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/admin_console_keycloak_login.png" loading="lazy" />

Une fois authentifié, l'interface obtient un jeton d'accès OIDC utilisé pour toutes les opérations suivantes.

### Tableau de bord de l'OPCP Admin Console

Après connexion, vous êtes redirigé vers le tableau de bord de l'OPCP Admin Console.

<img className="thumbnail" alt="Tableau de bord de l'OPCP Admin Console" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/admin_console_dashboard.png" loading="lazy" />

Depuis le tableau de bord, vous pouvez accéder aux sections suivantes :

- **Catalogue** : Parcourir les services disponibles sur la plateforme (par exemple, VCF) et les déployer sur l'infrastructure.
- **Déploiements** : Suivre les déploiements de services en cours d'exécution sur l'infrastructure et les activer pour des organisations.
- **Organisations** : Créer et gérer les environnements isolés de vos clients ou équipes internes.
- **Gestion IAM** : Configurer les utilisateurs et les permissions dans Keycloak.

### Concepts clés

Avant d'utiliser l'OPCP Admin Console, il est important de comprendre ses principaux concepts.

#### Rôles

Cloud Store réunit deux interfaces, chacune destinée à son propre public :

- L'**OPCP Admin Console** est utilisée par les **IT Admins**, qui exploitent la plateforme : ils déploient les services sur l'infrastructure, les activent pour des organisations, et créent et gèrent les organisations.
- L'**OPCP Cloud Console** est l'interface en libre-service utilisée par les **Organization Admins** et les **Organization Users**, qui consomment les services activés pour leur organisation.

| Rôle | Responsabilités |
|------|-----------------|
| IT Admin | Créer des organisations, déployer des services, activer des services pour des organisations |
| Service Packager | Concevoir, maintenir et publier des services dans le catalogue, définir leurs versions et leurs descriptions |
| Organization Admin | Gérer une organisation : utilisateurs, groupes d'utilisateurs, fournisseur d'identité, projets et accès |
| Organization User | Créer et consommer des ressources cloud dans les projets auxquels il est affecté |

#### Déploiements de services et services activés

Chaque service publié dans le catalogue est utilisé en deux temps :

- Un **déploiement de service** est une instance du service déployée sur l'infrastructure, avec une version donnée et du matériel alloué. Il exécute le **plan de contrôle** (Control Plane) du service, qui gère son cycle de vie et orchestre les opérations entre organisations. Un même déploiement de service peut être activé pour plusieurs organisations.
- Un **service activé** est un déploiement de service activé pour une organisation spécifique. Il rend le service visible dans l'OPCP Cloud Console de cette organisation. L'activation d'un service donne uniquement accès au service : aucune ressource cloud n'est créée à ce stade, sauf pour les services qui ne peuvent pas être partagés entre organisations, qui disposent d'un **plan de données** (Data Plane) dédié pour chaque organisation.

Ce modèle permet aux IT Admins d'offrir le même service à plusieurs clients, chaque organisation conservant un accès isolé tout en partageant le même déploiement de service.

### Création d'une organisation

Une **organisation** est un environnement client isolé — par exemple une entreprise ou un département — disposant de sa propre OPCP Cloud Console, de ses utilisateurs, de ses projets et de ses services activés. Chaque organisation dispose de son propre realm Keycloak, garantissant une isolation IAM complète. Les organisations doivent être créées avant que des services puissent être activés pour elles.

Pour créer une organisation :

1. Depuis le tableau de bord de l'OPCP Admin Console, accédez à la section <code className="action">Organisations</code>.
2. Cliquez sur <code className="action">Créer une organisation</code>.
3. Remplissez les champs requis : nom de l'organisation, nom complet de l'Organization Admin et adresse e-mail de l'Organization Admin.

    <img className="thumbnail" alt="Formulaire de création d'organisation" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/organization_creation_form.png" loading="lazy" />

4. Validez le formulaire.

La plateforme effectue automatiquement les actions suivantes :

- Création d'un realm Keycloak dédié nommé `organization-{name}`.
- Création d'un utilisateur Organization Admin avec le rôle `organization-admin`.
- Configuration d'un mot de passe temporaire (l'Organization Admin sera invité à le modifier lors de sa première connexion).
- Configuration d'un client `cloud-console` pour l'accès à l'OPCP Cloud Console.

### Déploiement et activation d'un service

La mise à disposition d'un service pour une organisation se fait en 2 étapes : commencez par **déployer** le service sur l'infrastructure, puis **activez** le déploiement de service pour une ou plusieurs organisations.

#### Étape 1 — Déployer un service

1. Accédez au <code className="action">Catalogue</code> depuis le tableau de bord.

    <img className="thumbnail" alt="Catalogue" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/service_catalog.png" loading="lazy" />

2. Sélectionnez le service que vous souhaitez déployer.
3. Cliquez sur <code className="action">Déployer</code>.
4. Choisissez la version et configurez les propriétés requises.
5. Sélectionnez le pool d'hôtes (Hosts Pool) sur lequel le service sera déployé.
6. Validez le formulaire.

:::info
Le déploiement d'un service est **asynchrone**. L'interface confirmera que le déploiement a démarré, mais le provisionnement s'effectue en arrière-plan via Kubernetes et Terraform. Vous pouvez suivre l'état du déploiement depuis la section <code className="action">Déploiements</code>.
:::


#### Étape 2 — Activer le service pour une organisation

Une fois le déploiement de service actif et au moins une organisation créée :

1. Accédez à la vue détaillée du déploiement de service dans la section <code className="action">Déploiements</code>.
2. Cliquez sur <code className="action">Activer</code>.
3. Sélectionnez l'organisation cible.
4. Configurez les propriétés requises, le cas échéant.
5. Pour les services nécessitant un plan de données dédié, sélectionnez le pool d'hôtes réservé à l'organisation.
6. Validez le formulaire.

Lors de l'activation d'un service, la plateforme crée automatiquement les ressources Keycloak nécessaires (client-id, rôles et groupes) dans le realm de l'organisation cible, garantissant que seuls les utilisateurs autorisés de cette organisation puissent accéder au service.

:::info
Comme pour le déploiement, l'activation d'un service est **asynchrone**. L'éventuel provisionnement de l'infrastructure est géré par Kubernetes et Terraform en arrière-plan.
:::


### Mise à l'échelle de la capacité

Vous pouvez ajouter ou retirer des hôtes d'un déploiement de service ou d'un plan de données dédié pour ajuster la capacité.

1. Accédez à la page du déploiement de service ou du service activé.
2. Cliquez sur <code className="action">Étendre la capacité</code>.
3. Sélectionnez les hôtes à ajouter.
4. Validez le formulaire.

L'opération de mise à l'échelle est asynchrone. Kubernetes réconcilie la configuration et provisionne les ressources sur les hôtes mis à jour.

### Authentification et zones de sécurité

La plateforme répartit l'authentification en deux **zones de sécurité** (Security Zones), chacune reposant sur ses propres instances Keycloak :

| Zone de sécurité | Instance Keycloak | Utilisateurs | Rôle |
|------------------|-------------------|--------------|------|
| Admin Security Zone | OPCP Core Keycloak | DC operators, Super admins | Identité au niveau infrastructure |
| Admin Security Zone | Keycloak de l'OPCP Admin Console | IT Admins, Service Packagers | Gestion de la plateforme |
| Public Security Zone | Realms Keycloak par organisation | Organization Admins, Organization Users | Accès aux services |

- Au sein de l'**Admin Security Zone**, le Keycloak de l'OPCP Admin Console est fédéré avec le Keycloak OPCP Core. Les droits accordés sur les projets OpenStack dans OPCP Core sont ainsi propagés à l'OPCP Admin Console.
- La **Public Security Zone** repose sur une instance Keycloak indépendante gérée par l'API de l'OPCP Admin Console. Chaque organisation dispose de son propre realm isolé.

:::info
L'[OPCP Cloud Console](/guides/hosted-private-cloud/opcp/cloud-console-create-user-account) est exposée dans la **Public Security Zone**, tandis que l'OPCP Admin Console se trouve dans l'**Admin Security Zone**. La stack Keycloak de l'OPCP Cloud Console **n'est pas fédérée** avec les instances Keycloak de l'Admin Security Zone (OPCP Core et OPCP Admin Console).
:::

#### Gestion de l'IAM sur le Keycloak de l'OPCP Admin Console

Pour pouvoir gérer les utilisateurs, rôles et groupes sur le Keycloak de l'OPCP Admin Console, vous devez au préalable attribuer le rôle `cloud-store-admins` à votre utilisateur dans le **Keycloak OPCP Core**.

1. Connectez-vous à la console d'administration du Keycloak OPCP Core.
2. Accédez à l'utilisateur auquel vous souhaitez accorder les droits de gestion IAM.
3. Dans l'onglet <code className="action">Role mappings</code>, attribuez le rôle client `cloud-store-admins`.

<img className="thumbnail" alt="Attribution du rôle cloud-store-admins dans le Keycloak OPCP Core" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/opcp_keycloak_cloud_store_admins_role.png" loading="lazy" />

Une fois ce rôle attribué, l'utilisateur disposera des permissions nécessaires pour administrer le Keycloak de l'OPCP Admin Console, y compris la gestion des realms, clients, utilisateurs et rôles.

### L'OPCP Cloud Console

L'**OPCP Cloud Console** est l'interface en libre-service destinée aux Organization Admins et aux Organization Users. Elle présente les services activés pour leur organisation.

Les Organization Admins invitent et retirent des utilisateurs, configurent les groupes d'utilisateurs, connectent le fournisseur d'identité de l'entreprise (SSO), créent des projets et affectent des utilisateurs ou des groupes d'utilisateurs aux projets avec un rôle : **Project Writer** (accès complet) ou **Project Reader** (lecture seule). Les Organization Users ouvrent ensuite leurs projets et créent des ressources cloud, comme des machines virtuelles, des volumes ou des bases de données.

Les utilisateurs s'authentifient via le realm Keycloak spécifique à leur organisation (Public Security Zone) et ne peuvent accéder qu'aux services activés pour leur organisation. L'OPCP Cloud Console récupère la liste des services activés et les filtre en fonction des permissions de l'utilisateur.
