## Objectif

**Ce guide présente aux IT Admins comment utiliser l'OPCP Admin Console pour créer des organisations, déployer des services depuis le catalogue de services et les activer pour des organisations.**

L'**OPCP Admin Console** est l'interface Cloud Store destinée aux IT Admins. Pour une présentation de Cloud Store et de ses concepts, consultez notre guide « [Premiers pas avec le Cloud Store](/guides/hosted-private-cloud/opcp/cloudstore-getting-started) ».

## Prérequis

- L'**URL** de l'OPCP Admin Console et vos identifiants de connexion, fournis lors de la livraison du service. Ces identifiants sont gérés dans le Keycloak de l'OPCP Admin Console.
- Un accès HTTPS (TCP/443) à l'URL de l'OPCP Admin Console depuis votre poste.
- Des hôtes bare metal enregistrés dans OPCP Core et rattachés à des projets OpenStack, avec des hôtes disponibles pour les services que vous prévoyez de déployer.

## En pratique

### Connexion à l'OPCP Admin Console

Accédez à l'**URL** de l'OPCP Admin Console et cliquez sur <code className="action">Log in</code>.

<img className="thumbnail" alt="Page de connexion de l'OPCP Admin Console" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/admin_console_login.png" loading="lazy" />

Vous êtes redirigé vers la page d'authentification **Keycloak**. Deux options s'offrent à vous :

- Saisir vos identifiants directement dans le formulaire de connexion Keycloak.
- Utiliser le bouton <code className="action">OPCP-SSO</code> pour vous authentifier via le Keycloak OPCP Core fédéré. Cette option permet aux utilisateurs déjà enregistrés dans OPCP Core de se connecter sans gérer un jeu d'identifiants supplémentaire. Elle est nécessaire pour gérer les pools d'hôtes, car l'utilisateur est alors identifié auprès d'OpenStack.

<img className="thumbnail" alt="Formulaire de connexion Keycloak de l'OPCP Admin Console" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/admin_console_keycloak_login.png" loading="lazy" />

Une fois authentifié, vous arrivez sur la page d'accueil de l'OPCP Admin Console.

<img className="thumbnail" alt="Page d'accueil de l'OPCP Admin Console" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/admin_console_home.png" loading="lazy" />

La barre latérale donne accès aux sections suivantes :

| Section | Contenu |
|---------|---------|
| **Services** | Chaque service déployé, comme raccourci vers ses déploiements. |
| **Management** | <code className="action">Organizations</code>, <code className="action">Service Catalog</code> et <code className="action">Deployments</code>. |
| **External links** | <code className="action">OPCP Dashboard</code>, pour accéder aux outils d'OPCP Core. |

#### Se déconnecter

Pour vous déconnecter, cliquez sur votre badge utilisateur en haut à droite, puis choisissez l'option de déconnexion dans le menu.

La session expire après 30 minutes d'inactivité, et au plus tard 10 heures après la connexion.

### Créer une organisation

Une **organisation** est un environnement isolé, par exemple une entreprise, un département ou une équipe. Créez-la avant d'activer des services pour elle.

1. Accédez à <code className="action">Management</code> > <code className="action">Organizations</code>. La liste affiche chaque organisation avec son administrateur et son statut. Les icônes de la colonne `Actions` ouvrent l'OPCP Cloud Console de l'organisation et sa console d'administration Keycloak.

    <img className="thumbnail" alt="Liste des organisations" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/organizations.png" loading="lazy" />

2. Cliquez sur <code className="action">Create a new organization</code>.
3. Saisissez le **nom de l'organisation** (`Organization name`), par exemple `dpt-real-estate`.
4. Renseignez l'**Organization Admin** : e-mail, prénom et nom.

    <img className="thumbnail" alt="Formulaire de création d'organisation" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/organization_creation_form.png" loading="lazy" />

5. Cliquez sur <code className="action">Create</code>. L'organisation passe au statut `pending`, puis `active`.

La plateforme effectue automatiquement les actions suivantes :

- création d'un realm Keycloak dédié nommé `account-{name}` ;
- création de l'utilisateur Organization Admin. Son identifiant de connexion est son adresse e-mail ;
- configuration d'un mot de passe par défaut de première connexion, défini lors de l'installation de Cloud Store. L'Organization Admin doit le modifier lors de sa première connexion.

:::warning
Aucun e-mail n'est envoyé à l'Organization Admin. Une fois l'organisation `active`, transmettez-lui vous-même ses identifiants, comme décrit dans la section [Transmettre l'accès à l'organisation](#transmettre-laccès-à-lorganisation) ci-dessous.
:::

### Déployer un service

Un **déploiement de service** (Service Deployment) exécute un service sur des hôtes bare metal que vous affectez à des **pools d'hôtes** (Host Pools). Il est déployé une seule fois, puis vous pouvez l'activer pour autant d'organisations que nécessaire.

1. Accédez à <code className="action">Management</code> > <code className="action">Service Catalog</code>. Le catalogue affiche les services disponibles sur votre plateforme, leur dernière version et s'ils sont déployés. Pour mettre à jour le catalogue, contactez le support OVHcloud.

    <img className="thumbnail" alt="Catalogue de services" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/service_catalog.png" loading="lazy" />

2. Ouvrez un service. La page liste ses déploiements existants. Cliquez sur <code className="action">New deployment</code>.

    <img className="thumbnail" alt="Déploiements d'un service" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/service_deployments.png" loading="lazy" />

3. **Choisissez la version du service** (`Choose the version of your service`), puis cliquez sur <code className="action">Next</code>.

    <img className="thumbnail" alt="Choix de la version du service" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/deploy_version.png" loading="lazy" />

4. **Affectez des hôtes aux pools d'hôtes** (`Allocate the host pools`). Pour chaque pool d'hôtes requis par le service, par exemple `compute` et `block-storage` pour Compute and Block Storage, sélectionnez le projet OpenStack et les hôtes à utiliser. Les prérequis du service (nombre et type d'hôtes) sont affichés au-dessus de la liste.

    <img className="thumbnail" alt="Affectation des hôtes aux pools d'hôtes" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/deploy_host_pools.png" loading="lazy" />

5. **Configurez le service** (`Configure your service`) avec les propriétés définies par le service.
6. Cliquez sur <code className="action">Deploy</code>.

:::info
Seuls les hôtes disponibles dans OpenStack sont listés. Les hôtes sélectionnés sont effacés et réinstallés pendant le déploiement.
:::

Le déploiement d'un service est **asynchrone** : la console confirme que le déploiement a démarré, et le provisionnement s'effectue en arrière-plan via Kubernetes et OpenTofu. Sa durée dépend du service : de quelques minutes à plusieurs heures pour les services les plus complexes.

### Suivre un déploiement de service

Tous les déploiements de services sont regroupés dans <code className="action">Management</code> > <code className="action">Deployments</code>. Ils apparaissent également sous le nom du service dans la barre latérale.

Un déploiement de service, comme un service activé, a l'un des trois statuts suivants :

| Statut | Signification |
|--------|---------------|
| `deploying` | Le déploiement est en cours. |
| `deployed` | Le déploiement est terminé. |
| `deleting` | La suppression est en cours. |

La page d'un déploiement de service affiche sa version, son statut et les onglets suivants :

<img className="thumbnail" alt="Page d'un déploiement de service" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/deployment_detail.png" loading="lazy" />

| Onglet | Contenu |
|--------|---------|
| **Enabled services** | Les organisations pour lesquelles ce déploiement est activé. <code className="action">Enable a service</code> l'active pour une autre organisation. |
| **Host pools** | Les hôtes de chaque pool d'hôtes : nom, IP de management, fabricant, modèle, CPU, RAM et disque. |
| **Outputs** | Les endpoints et fichiers produits par le service. |
| **Settings** | La configuration choisie lors du déploiement. |

<img className="thumbnail" alt="Pools d'hôtes d'un déploiement de service" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/deployment_host_pools.png" loading="lazy" />

#### Mise à l'échelle de la capacité

Pour ajouter des hôtes à un déploiement de service, ouvrez son menu <code className="action">⋮</code> et choisissez <code className="action">Expand capacity</code>. Sélectionnez des hôtes disponibles dans son projet OpenStack, puis confirmez. La même action existe sur les services activés qui disposent d'un pool d'hôtes dédié.

<img className="thumbnail" alt="Menu des actions d'un déploiement de service" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/deployment_actions.png" loading="lazy" />

<img className="thumbnail" alt="Sélection des hôtes pour augmenter la capacité d'un déploiement de service" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/deployment_expand_capacity.png" loading="lazy" />

L'opération est asynchrone : Kubernetes réconcilie la configuration et provisionne les nouveaux hôtes.

### Activer un service pour une organisation

Activer un déploiement de service pour une organisation crée un **service activé** (Enabled Service). Il rend le service visible dans l'OPCP Cloud Console de l'organisation, et la plateforme crée les ressources Keycloak nécessaires (client, rôles et groupes) dans le realm de l'organisation, afin que seuls les utilisateurs de cette organisation puissent accéder au service.

Le déploiement de service doit être au statut `deployed` et l'organisation doit exister.

1. Ouvrez le déploiement de service, onglet <code className="action">Enabled services</code>, et cliquez sur <code className="action">Enable a service</code>. Vous pouvez également partir de la page d'une organisation.
2. **Nommez le service activé** (`Name your enabled service`) et sélectionnez l'**organisation**. Si vous ne saisissez pas de nom, l'identifiant technique est utilisé.

    <img className="thumbnail" alt="Activation d'un service pour une organisation" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/enable_service_form.png" loading="lazy" />

3. **Affectez des hôtes au pool d'hôtes** (`Allocate the host pool`) lorsque le service nécessite des hôtes dédiés à l'organisation. Pour les services dont les hôtes sont partagés entre organisations, cette étape est marquée `not applicable`.
4. **Configurez le service activé** (`Configure your enabled service`) avec les propriétés définies par le service.
5. Confirmez. Le service activé est en cours de déploiement, puis passe au statut `deployed`.

La page d'une organisation liste ses services activés, avec leur déploiement de service et leur type de service.

<img className="thumbnail" alt="Page d'une organisation" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/organization_detail.png" loading="lazy" />

### Désactiver un service ou supprimer un déploiement de service

Tous les services activés peuvent être désactivés. Ouvrez le service activé depuis la page de l'organisation, puis choisissez <code className="action">Delete</code> dans son menu <code className="action">⋮</code>.

<img className="thumbnail" alt="Menu des actions d'un service activé" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/enabled_service_actions.png" loading="lazy" />

Un déploiement de service ne peut être supprimé que lorsqu'il n'a plus aucun service activé. Désactivez d'abord ses services activés, puis choisissez <code className="action">Delete</code> dans le menu <code className="action">⋮</code> du déploiement de service. Tant qu'il reste des services activés, l'action est grisée.

Pendant la suppression, le service activé ou le déploiement de service est au statut `deleting`. Une fois la suppression terminée, ses hôtes redeviennent disponibles.

### Transmettre l'accès à l'organisation

Une fois le service activé déployé, les utilisateurs de l'organisation le retrouvent dans l'OPCP Cloud Console. Depuis la page de l'organisation, vous pouvez ouvrir le service activé : son onglet `Outputs` présente les données techniques de son déploiement. Les services peuvent ajouter leurs propres onglets, comme `Compute`.

<img className="thumbnail" alt="Outputs d'un service activé" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/enabled_service_outputs.png" loading="lazy" />

Transmettez ensuite à l'Organization Admin :

- l'**URL de l'OPCP Cloud Console** : dans <code className="action">Management</code> > <code className="action">Organizations</code>, l'icône en forme de maison l'ouvre avec l'organisation déjà sélectionnée ;
- son **identifiant** : l'adresse e-mail saisie lors de la création de l'organisation ;
- le **mot de passe par défaut de première connexion** défini lors de l'installation de Cloud Store.

:::warning
Le mot de passe par défaut de première connexion est commun et défini lors de l'installation. L'Organization Admin est obligé de le modifier lors de sa première connexion.
:::

L'Organization Admin peut ensuite suivre notre guide « [OPCP Cloud Console](/guides/hosted-private-cloud/opcp/cloud-console-getting-started) ».

### Gestion de l'IAM sur le Keycloak de l'OPCP Admin Console

Pour pouvoir gérer les utilisateurs, rôles et groupes sur le Keycloak de l'OPCP Admin Console, vous devez au préalable attribuer le rôle `cloudstore-admins` à votre utilisateur dans le **Keycloak OPCP Core**.

1. Connectez-vous à la console d'administration du Keycloak OPCP Core.
2. Accédez à l'utilisateur auquel vous souhaitez accorder les droits de gestion IAM.
3. Dans l'onglet <code className="action">Role mappings</code>, attribuez le rôle client `cloudstore-admins`.

<img className="thumbnail" alt="Attribution du rôle cloudstore-admins dans le Keycloak OPCP Core" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/opcp_keycloak_cloud_store_admins_role.png" loading="lazy" />

Une fois ce rôle attribué, l'utilisateur dispose des permissions nécessaires pour administrer le Keycloak de l'OPCP Admin Console, y compris la gestion des realms, clients, utilisateurs et rôles.
