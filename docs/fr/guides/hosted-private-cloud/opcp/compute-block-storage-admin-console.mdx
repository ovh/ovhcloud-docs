## Objectif

**Ce guide explique aux IT Admins comment déployer le service Compute and Block Storage depuis l'OPCP Admin Console, le configurer, le faire évoluer et l'activer pour des organisations.**

**Compute and Block Storage** fournit des machines virtuelles (instances), des volumes de stockage block persistants et des réseaux privés aux organisations de votre plateforme. Il repose sur OpenStack : Nova exécute les instances sur des hyperviseurs, et Cinder stocke les volumes dans un cluster Ceph. Les deux fonctionnent sur des hôtes bare metal de votre OPCP.

Ce guide couvre ce qui est propre à Compute and Block Storage. Les étapes générales (Service Catalog, déploiements de service, organisations) sont décrites dans notre guide « [OPCP Admin Console](/guides/hosted-private-cloud/opcp/admin-console-getting-started) ». L'utilisation du service par les utilisateurs d'une organisation est décrite dans notre guide « [Utiliser Compute and Block Storage](/guides/hosted-private-cloud/opcp/compute-block-storage-cloud-console) ».

## Prérequis

- Disposer d'un accès à l'OPCP Admin Console, comme décrit dans notre guide « [OPCP Admin Console](/guides/hosted-private-cloud/opcp/admin-console-getting-started) ».
- Disposer d'hôtes bare metal enrôlés dans OPCP Core, disponibles dans OpenStack et non utilisés par un autre service :
    - au moins **1 hôte pour le pool d'hôtes `compute`**, qui devient un hyperviseur. Ajoutez des hôtes pour augmenter la capacité, et pour que les instances continuent de fonctionner en cas de panne d'un hyperviseur. Chacun doit disposer d'un disque de données d'au moins 1 000 Gio. Les hôtes AMD EPYC doivent avoir leur mode NUMA réglé sur **NPS4** ;
    - au moins **3 hôtes pour le pool d'hôtes `storage`**, qui forment le cluster Ceph. Ceph conserve 3 copies de chaque volume, chacune sur un hôte différent.
- Disposer d'une organisation pour laquelle activer le service. Pour en créer une, consultez la section « [Créer une organisation](/guides/hosted-private-cloud/opcp/admin-console-getting-started#créer-une-organisation) ».

## En pratique

### Vue d'ensemble de l'architecture

| Composant | S'exécute sur | Rôle |
|-----------|---------------|------|
| **Control plane** | Le contrôleur OPCP | Déployé une fois par déploiement de service. Exécute les services OpenStack qui gèrent les instances et les volumes, ainsi qu'une interface web Horizon. |
| **Hyperviseurs** | Hôtes du pool d'hôtes `compute` | Exécutent les instances. Ils sont partagés par toutes les organisations pour lesquelles le service est activé. |
| **Cluster Ceph** | Hôtes du pool d'hôtes `storage` | Stocke les volumes de stockage block. |
| **Data plane** | Le contrôleur OPCP | Créé pour chaque organisation lorsque vous activez le service pour elle. Fournit à l'organisation son propre projet OpenStack, son accès via l'OPCP Cloud Console et sa propre interface web pour le service. |

Chaque organisation ne voit que ses propres instances, volumes et réseaux.

### Déployer le service

1. Accédez à <code className="action">Management</code> > <code className="action">Service Catalog</code> et ouvrez **Compute and Block Storage**. Cliquez sur <code className="action">New deployment</code>.
2. **Choisissez la version de votre service**, puis cliquez sur <code className="action">Next</code>.
3. **Affectez les pools d'hôtes** :
    - `compute` : sélectionnez les hôtes qui deviennent des hyperviseurs ;
    - `storage` : sélectionnez les hôtes qui forment le cluster Ceph.

    Un hôte ne peut appartenir qu'à un seul pool d'hôtes.

4. **Configurez votre service**. Le service a deux paramètres, chacun avec une valeur par défaut adaptée à la plupart des déploiements. Consultez la section [Paramètres](#paramètres) ci-dessous.
5. Cliquez sur <code className="action">Deploy</code>.

:::warning
Les hôtes sélectionnés sont effacés et réinstallés pendant le déploiement.

:::

Le déploiement installe les hyperviseurs et le cluster Ceph. Il dure de plusieurs dizaines de minutes à quelques heures, selon le nombre d'hôtes. Le déploiement de service est `deploying`, puis `deployed`.

:::warning
**Alpha : étape manuelle requise.** Le déploiement ne crée pas encore les gabarits d'instance (gabarits `cb-`) ni l'agrégat d'hôtes qui les place sur les hyperviseurs. Tant que cette étape n'est pas réalisée, les organisations ne peuvent pas créer d'instances. Une fois votre déploiement de service `deployed`, contactez OVHcloud pour faire réaliser cette étape.

:::

#### Paramètres

| Paramètre | Valeur par défaut | Description |
|-----------|-------------------|-------------|
| `horizon_enabled` | `true` | Déploie l'interface web Horizon. Les utilisateurs des organisations y accèdent via un lien dans l'OPCP Cloud Console, pour les cas que l'interface du service ne couvre pas encore. |
| `allow_uninstall_with_bound_nodes` | `false` | Autorise la suppression du déploiement de service alors que des hôtes sont encore utilisés. Les hôtes sont alors libérés et effacés. Laissez-le à `false`, sauf si le support OVHcloud vous demande de le modifier. |

### Outputs

Une fois le déploiement de service `deployed`, son onglet <code className="action">Outputs</code> affiche notamment les hôtes de chaque pool d'hôtes (`compute_nodes`, `storage_nodes`) et l'adresse d'Horizon (`horizon_url`).

Chaque service activé dispose de ses propres Outputs, utilisés par les utilisateurs de l'organisation. Ils sont affichés dans l'onglet <code className="action">Overview</code> du service dans l'OPCP Cloud Console :

| Output | Contenu |
|--------|---------|
| `Console` | Le lien vers l'interface web du service pour cette organisation. |
| `Horizon` | Le lien qui connecte les utilisateurs de l'organisation à Horizon, si `horizon_enabled` vaut `true`. |
| `OpenRC` | Un fichier `openrc.sh` pour la CLI OpenStack. Il ne contient aucun secret : les utilisateurs s'authentifient avec leur propre identifiant d'application (*application credential*). |

### Activer le service pour une organisation

Activez le déploiement de service pour chaque organisation qui a besoin d'instances, comme décrit dans la section « [Activer un service pour une organisation](/guides/hosted-private-cloud/opcp/admin-console-getting-started#activer-un-service-pour-une-organisation) ».

- Les hyperviseurs et le cluster Ceph sont partagés entre les organisations : l'étape du pool d'hôtes est marquée `not applicable`.
- Aucune propriété n'est à renseigner : le service récupère tout ce dont il a besoin dans les Outputs du déploiement de service.

Le service activé est `deploying`, puis `deployed`. Les utilisateurs de l'organisation trouvent alors **Compute and Block Storage** dans l'OPCP Cloud Console. Transmettez-leur notre guide « [Utiliser Compute and Block Storage](/guides/hosted-private-cloud/opcp/compute-block-storage-cloud-console) ».

### Faire évoluer le service

#### Ajouter des hôtes

Pour ajouter de la capacité, ouvrez le menu <code className="action">⋮</code> du déploiement de service et choisissez <code className="action">Expand capacity</code>, comme décrit dans la section « [Mise à l'échelle de la capacité](/guides/hosted-private-cloud/opcp/admin-console-getting-started#mise-à-léchelle-de-la-capacité) ».

- Un hôte ajouté au pool d'hôtes `compute` devient un nouvel hyperviseur.
- Un hôte ajouté au pool d'hôtes `storage` rejoint le cluster Ceph, et ses disques augmentent la capacité de stockage.

:::warning
**Alpha : étape manuelle requise.** Un nouvel hyperviseur n'exécute des instances qu'une fois ajouté à l'agrégat d'hôtes des gabarits `cb-`. Cet ajout n'est pas encore automatique : après avoir ajouté des hôtes au pool d'hôtes `compute`, contactez OVHcloud pour les faire ajouter.

:::

#### Retirer des hôtes

Le retrait d'hôtes d'un déploiement de service n'est pas pris en charge dans l'Alpha.

### Supprimer le service

1. Demandez aux organisations de supprimer toutes leurs instances et tous leurs volumes.
2. Désactivez le service pour chaque organisation.
3. Supprimez le déploiement de service, comme décrit dans la section « [Désactiver un service ou supprimer un déploiement de service](/guides/hosted-private-cloud/opcp/admin-console-getting-started#désactiver-un-service-ou-supprimer-un-déploiement-de-service) ».

:::warning
Supprimez toutes les instances et tous les volumes avant de supprimer le déploiement de service. Des instances restées sur un hyperviseur bloquent la suppression du déploiement de service.

:::
