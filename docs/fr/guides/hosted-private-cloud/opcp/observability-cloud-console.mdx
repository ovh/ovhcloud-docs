## Objectif

**Ce guide explique aux utilisateurs d'une organisation comment ouvrir le service Observability depuis l'OPCP Cloud Console, explorer leurs logs, métriques et traces, et configurer des tableaux de bord et des alertes.**

Le service **Observability** fournit à votre organisation son propre Grafana, avec ses propres logs, métriques, traces et alertes. Aucune autre organisation ne peut voir vos données. Vous vous connectez avec le compte de votre organisation.

Le déploiement du service par votre IT Admin est décrit dans notre guide « [Déployer le service Observability](/guides/hosted-private-cloud/opcp/observability-admin-console) ».

Ce guide documente la version `0.1.0-alpha.99`.

## Prérequis

- Disposer d'un compte dans votre organisation, comme décrit dans notre guide « [OPCP Cloud Console](/guides/hosted-private-cloud/opcp/cloud-console-getting-started) ».
- Le service Observability doit être activé pour votre organisation par votre IT Admin.

## En pratique

### Ce que le service propose dans l'Alpha

| Fonctionnalité | Dans l'Alpha |
|----------------|--------------|
| Grafana pour votre organisation, avec authentification unique | Oui |
| Logs, métriques et traces de votre organisation | Oui |
| **IAM audit log** : connexions et modifications IAM de votre organisation | Oui, sauf si votre IT Admin l'a désactivé |
| **Usage & Limits** : la consommation du service Observability par votre organisation, par rapport à ses limites | Oui |
| Vos propres tableaux de bord et règles d'alerte, notifications vers vos outils | Oui |
| Envoi des logs, métriques et traces de vos propres serveurs et applications | Oui, consultez la section [Envoyer vos propres données](#envoyer-vos-propres-données) |
| Données et accès par projet | Non : tout est par organisation, consultez la section [Limitations connues](#limitations-connues) |

### Ouvrir le service

1. Connectez-vous à l'OPCP Cloud Console et ouvrez **Observability** dans vos services activés.
2. Dans l'onglet <code className="action">Overview</code>, ouvrez le lien `grafana_url`.
3. Connectez-vous avec le compte de votre organisation.

Chaque utilisateur de l'organisation qui se connecte obtient le rôle **Editor** dans Grafana : il peut explorer les données, et créer et modifier des tableaux de bord et des règles d'alerte.

### Explorer vos données

Dans l'Alpha, les données de votre organisation proviennent de l'IAM audit log de votre realm Keycloak, et de ce qu'envoient vos propres serveurs et applications (consultez la section [Envoyer vos propres données](#envoyer-vos-propres-données)). Les autres services du Cloud Store ajoutent leurs données, par exemple les logs d'accès S3 de vos buckets, avec la Beta.

Quatre sources de données sont provisionnées dans votre Grafana :

| Source de données | Contenu | Langage de requête |
|-------------------|---------|--------------------|
| **Loki** (par défaut) | Logs | LogQL |
| **Mimir** | Métriques | PromQL |
| **Tempo** | Traces | TraceQL |
| **Alertmanager** | Vos alertes et paramètres de notification | — |

Pour explorer vos données :

1. Ouvrez <code className="action">Explore</code> dans le menu de Grafana et sélectionnez une source de données.
2. Construisez la requête avec le mode **Builder**, ou saisissez-la en mode **Code**. Par exemple :
    - Loki : `{job="keycloak-audit", type="LOGIN_ERROR"}` renvoie les connexions échouées de votre organisation ;
    - Mimir : ouvrez le **Metrics browser** pour lister les métriques de votre organisation, puis choisissez-en une.
3. Sélectionnez la période et cliquez sur <code className="action">Run query</code>.

| Tableau de bord | Ce qu'il montre |

| **Usage & Limits** | Vos séries de métriques actives, vos échantillons de métriques par seconde et votre ingestion de logs, par rapport aux limites Observability de votre organisation. |

Pour créer votre propre tableau de bord, accédez à <code className="action">Dashboards</code> > <code className="action">New</code>. Vous pouvez aussi importer un tableau de bord depuis un fichier JSON avec <code className="action">Dashboards</code> > <code className="action">New</code> > <code className="action">Import</code>.

### Envoyer vos propres données

Vos serveurs, applications et scripts peuvent envoyer leurs logs, métriques et traces à la **passerelle** de votre organisation, et les relire. Les données apparaissent dans votre Grafana, à côté du reste.

- **Adresse :** le lien `gateway_url` dans l'onglet <code className="action">Overview</code> du service.
- **Accès :** un jeton du realm de votre organisation dans chaque requête. Demandez à votre IT Admin un client ID, un client secret et l'URL du jeton (consultez la section « [Fournir des identifiants d'envoi à une organisation](/guides/hosted-private-cloud/opcp/observability-admin-console#fournir-des-identifiants-denvoi-à-une-organisation) »).
- **API :** les API standard de Loki, Mimir (Prometheus) et Tempo, et OTLP sur HTTP.

Notre guide « [Envoyer et lire des données avec la passerelle Observability](/guides/hosted-private-cloud/opcp/observability-gateway) » décrit l'API et donne des exemples de bout en bout avec curl, Grafana Alloy et le SDK OpenTelemetry.

### Conservation des données et limites

Votre IT Admin définit la durée de conservation de vos données. Par défaut :

| Données | Conservation par défaut |
|---------|-------------------------|
| Logs | 30 jours |
| Métriques | 365 jours |
| Traces | 30 jours |

Le service Observability fixe des limites pour chaque organisation. Elles s'appliquent uniquement aux données envoyées à ce service, pas à vos autres services du Cloud Store :

| Signal | Limite |
|--------|--------|
| Métriques | 150 000 séries actives, 15 000 échantillons par seconde |
| Logs | 1 Mio/s (pic de 4 Mio), 5 000 flux de logs actifs |
| Traces | 2 Mio/s (pic de 4 Mio) |

Les données au-delà d'une limite de débit sont refusées, puis renvoyées plus tard par leur expéditeur. Les séries de métriques au-delà de 150 000 sont ignorées. Suivez votre consommation sur le tableau de bord **Usage & Limits**.

### Configurer des alertes

Vous pouvez écrire des règles d'alerte sur vos logs et vos métriques, et envoyer les notifications vers vos propres outils.

1. Accédez à <code className="action">Alerting</code> > <code className="action">Contact points</code> et cliquez sur <code className="action">Add contact point</code>. Choisissez l'intégration (e-mail, webhook, Slack, Microsoft Teams, PagerDuty, etc.) et renseignez ses paramètres.
2. Accédez à <code className="action">Alerting</code> > <code className="action">Alert rules</code> et cliquez sur <code className="action">New alert rule</code>.
3. Choisissez la source de données **Mimir** ou **Loki**, écrivez la requête et la condition, puis choisissez votre point de contact.
4. Enregistrez la règle.

Les règles sont évaluées par le service lui-même : elles continuent de fonctionner lorsque personne n'a Grafana ouvert.

:::info
Lorsque vous écrivez une règle, l'aperçu peut afficher l'erreur `Jwt is missing`. Enregistrez quand même la règle : elle est évaluée correctement. Vérifiez le résultat dans <code className="action">Explore</code>.

:::

:::warning
Les notifications ne peuvent être envoyées qu'à des adresses publiques. Un point de contact qui cible une adresse privée (par exemple `10.x.x.x` ou `192.168.x.x`) échoue avec `blocked address`.

:::

### Limitations connues

L'Alpha présente les limitations connues suivantes :

| Limitation | Détail |
|------------|--------|
| Tout est par organisation | Tous les utilisateurs de l'organisation voient toutes ses données et sont **Editor**. Les données, rôles et tableaux de bord par projet arrivent avec la Beta. |
| Pas de transfert, pas d'export | L'envoi d'une copie de vos données vers une plateforme externe, et l'export complet, arrivent avec la Beta. |
| Peu de sources de données | Dans l'Alpha, en dehors des données que vous envoyez vous-même, seul l'IAM audit log envoie des données à votre organisation. Les services du Cloud Store, par exemple Object Storage, envoient les leurs avec la Beta. |
| Conservation | Seul votre IT Admin peut modifier la durée de conservation de vos données. |
| Erreurs de requête brèves | Pendant les mises à jour ou les redémarrages du service, les requêtes sur les dernières heures peuvent échouer brièvement. Aucune donnée n'est perdue : relancez la requête. |
