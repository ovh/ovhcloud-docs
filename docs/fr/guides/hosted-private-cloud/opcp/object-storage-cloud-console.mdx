## Objectif

**Ce guide explique aux utilisateurs d'une organisation comment obtenir des clés d'accès S3, créer des buckets et téléverser des objets avec le service Object Storage, dans son interface web et avec l'API S3.**

## Prérequis

- Disposer d'un accès à l'OPCP Cloud Console, comme décrit dans notre guide « [OPCP Cloud Console](/guides/hosted-private-cloud/opcp/cloud-console-getting-started) ».
- Disposer du service **Object Storage**, activé pour votre organisation par votre IT Admin comme décrit dans notre guide « [Déployer Object Storage](/guides/hosted-private-cloud/opcp/object-storage-admin-console) ».
- Pour utiliser l'API S3 : un client S3, par exemple l'[AWS CLI](https://aws.amazon.com/cli/), [S3cmd](https://s3tools.org/s3cmd) ou [Cyberduck](https://cyberduck.io/).

## En pratique

### Ce que le service propose dans l'Alpha

| Ressource | Ce que vous pouvez faire |
|-----------|--------------------------|
| **Clés d'accès** | Créer des clés d'accès S3 et les révoquer. Le secret d'une clé n'est affiché qu'une seule fois, à sa création. |
| **Buckets** | Créer et supprimer des buckets. Activer le versioning, définir des règles de cycle de vie qui suppriment les anciens objets, publier un bucket comme site web statique. |
| **Objets** | Téléverser des fichiers et des dossiers, créer des dossiers, télécharger, copier, déplacer, renommer et supprimer des objets. Définir leur type de contenu et leurs en-têtes de cache. Partager un objet avec une URL signée temporaire. Restaurer une version antérieure d'un objet. |

Vous gérez ces ressources dans l'interface web du service, ou avec n'importe quel client S3.

### Ouvrir le service

Dans la barre latérale de l'OPCP Cloud Console, ouvrez le service. Il apparaît sous le nom que votre IT Admin lui a donné en l'activant pour votre organisation.

Le lien <code className="action">Console</code> dans l'en-tête du service, également affiché dans son onglet <code className="action">Overview</code>, ouvre l'interface web d'Object Storage dans un nouvel onglet du navigateur. Ce guide décrit cette interface.

L'interface web comporte trois onglets :

| Onglet | Contenu |
|--------|---------|
| <code className="action">Buckets</code> | Vos buckets et leurs objets. |
| <code className="action">Connect</code> | L'endpoint S3, et la configuration des clients Cyberduck et S3cmd. |
| <code className="action">Access Keys</code> | Vos clés d'accès S3. |

### Obtenir des clés d'accès S3

Une clé d'accès est une paire composée d'une **access key** et d'une **secret key**. Les clients S3 l'utilisent pour s'authentifier.

1. Ouvrez l'onglet <code className="action">Access Keys</code> et cliquez sur <code className="action">Request new Access Key</code>.
2. Si vous le souhaitez, donnez à la clé un nom qui indique où vous l'utilisez.
3. Cliquez sur <code className="action">Request new Access Key</code>.
4. Copiez l'**Access Key** et la **Secret Key**, puis cliquez sur <code className="action">Copy Secret & Close</code>.

:::warning
La secret key n'est affichée qu'une seule fois et ne peut pas être récupérée ensuite. Conservez-la en lieu sûr. Si vous la perdez, révoquez la clé et créez-en une nouvelle.

:::

Pour révoquer une clé, ouvrez son menu dans la liste des clés d'accès et choisissez de la révoquer. Les applications qui l'utilisent ne peuvent plus accéder à vos buckets.

Chaque clé d'accès donne un accès complet à tous les buckets de votre organisation.

### Informations de connexion

Les clients S3 ont besoin de trois valeurs :

| Valeur | Où la trouver |
|--------|---------------|
| **Endpoint** | L'onglet <code className="action">Connect</code>, ou le haut de l'onglet <code className="action">Buckets</code>, par exemple `https://s3.object-storage-<id>.<votre domaine>`. |
| **Région** | `opcp-s3`. |
| **Access key et secret key** | Consultez la section [Obtenir des clés d'accès S3](#obtenir-des-clés-daccès-s3). |

Les deux styles d'URL fonctionnent : `https://<endpoint>/<bucket>` et `https://<bucket>.<endpoint>`.

### Créer un bucket et téléverser des objets dans l'interface web

1. Ouvrez l'onglet <code className="action">Buckets</code> et cliquez sur <code className="action">Create bucket</code>.
2. Saisissez un **Bucket name**. Utilisez uniquement des lettres minuscules, des chiffres, des points ou des tirets. Les noms de bucket sont uniques sur toute la plateforme : le nom choisi peut donc être déjà pris.
3. Cliquez sur <code className="action">Create bucket</code>.
4. Ouvrez le bucket. Glissez-déposez des fichiers, ou utilisez <code className="action">Upload files</code> ou <code className="action">Upload folders</code>. Utilisez <code className="action">Create folder</code> pour organiser vos objets.

Dans le bucket, le menu de chaque objet permet de le télécharger, le copier, le déplacer, le renommer ou le supprimer, de modifier ses paramètres, ou de créer une <code className="action">Signed URL</code> : un lien temporaire, valable de 5 minutes à 1 semaine, qui donne accès à l'objet sans identifiants.

### Créer un bucket et téléverser des objets avec l'API S3

Les exemples ci-dessous utilisent l'AWS CLI.

1\. **Configurez l'AWS CLI** avec votre clé d'accès :

```bash
aws configure --profile opcp
# AWS Access Key ID: <access key>
# AWS Secret Access Key: <secret key>
# Default region name: opcp-s3
# Default output format: json
```

2\. **Créez un bucket et téléversez un objet :**

```bash
ENDPOINT=https://s3.object-storage-<id>.<votre domaine>
aws --profile opcp --endpoint-url "$ENDPOINT" s3 mb s3://my-bucket
aws --profile opcp --endpoint-url "$ENDPOINT" s3 cp ./report.pdf s3://my-bucket/
aws --profile opcp --endpoint-url "$ENDPOINT" s3 ls s3://my-bucket/
```

Si votre plateforme utilise sa propre autorité de certification, ajoutez `--ca-bundle <fichier contenant le certificat de l'autorité>` à chaque commande. Votre IT Admin peut vous fournir ce certificat.

L'onglet <code className="action">Connect</code> décrit comment configurer Cyberduck et S3cmd avec les mêmes valeurs.

### Paramètres d'un bucket

Ouvrez un bucket et choisissez <code className="action">Settings</code> pour modifier ses paramètres :

| Paramètre | Effet |
|-----------|-------|
| **Bucket Versioning** | Conserve les versions antérieures de chaque objet lorsqu'il est modifié ou supprimé. Vous pouvez restaurer une version antérieure, ou la supprimer. |
| **Bucket Lifecycle configuration** | Des règles qui suppriment les objets après un nombre de jours, éventuellement seulement ceux dont le nom commence par un préfixe. Elles peuvent aussi supprimer les versions antérieures des objets et les téléversements incomplets. Avec le versioning activé, les objets supprimés passent d'abord par la <code className="action">Lifecycle Bin</code>, où vous pouvez les restaurer ou les supprimer définitivement. |
| **Static Website Hosting** | Publie le bucket comme site web, avec un document d'index et un document d'erreur. |

:::warning
**Static Website Hosting** rend tous les objets actuels et futurs du bucket accessibles publiquement, sans identifiants, à toute personne qui peut joindre la plateforme.

:::

### Fonctionnalités S3 disponibles dans l'Alpha

Le service repose sur Ceph RGW, qui prend en charge la plupart de l'API S3. L'interface web du service s'appuie sur les fonctionnalités suivantes :

- La création, la liste et la suppression de buckets et d'objets, les téléversements multipart.
- Le versioning des buckets et les règles de cycle de vie.
- L'hébergement de sites web statiques.
- Les URL présignées.

Pour les différences entre Object Storage sur OPCP et dans les régions OVHcloud, consultez notre guide « [Fonctionnalités et spécifications d'Object Storage sur OPCP](/guides/hosted-private-cloud/opcp/s3-opcp-limitations) ».

### Limitations connues

L'Alpha présente les limitations connues suivantes :

| Ce que vous constatez | Que faire |
|-----------------------|-----------|
| Chaque clé d'accès donne un accès complet à tous les buckets de l'organisation. Il n'y a pas de droits par utilisateur ou par bucket. | Considérez chaque clé d'accès comme une clé vers toutes vos données. Révoquez les clés que vous n'utilisez plus. |
| Un nom de bucket est refusé car déjà pris. | Les noms de bucket sont uniques sur la plateforme : choisissez un autre nom. |
| La capacité du service est limitée, et ses données peuvent être perdues lors d'une mise à jour du service. | Ne stockez pas dans l'Alpha de données que vous devez conserver. |

Les fonctionnalités suivantes ne sont pas disponibles dans l'Alpha :

- Le chiffrement des objets avec des clés gérées par la plateforme (SSE-S3, SSE-KMS).
- Les quotas et le suivi de la consommation par organisation.
- Les politiques d'accès par utilisateur.
