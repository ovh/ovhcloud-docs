## Objectif

Ce guide présente deux méthodes complémentaires pour sauvegarder une instance SNC Cloud Platform :

*   **Sauvegarde complète du système** : un snapshot du volume système est transformé en image, qui peut être conservée, téléchargée hors plateforme pour une sauvegarde externe, ou utilisée pour recréer une instance à l'identique (_clone_).
*   **Sauvegarde des données applicatives** : un outil comme [Restic](https://restic.readthedocs.io/en/stable/) automatise les sauvegardes des données de vos instances vers Object Storage. Les sauvegardes peuvent être utilisées pour restaurer vos données en cas de problème.

## Prérequis

- Avoir une instance
- Pour la méthode snapshot/clonage : un accès à la console OpenStack (_Horizon_) ou le CLI `openstack` configuré (voir [Comment créer une instance SNC Cloud Platform et s'y connecter](/guides/hosted-private-cloud/cloud-platform/create-instance) pour l'installation et la configuration du CLI)
- Pour la méthode Restic :
    - Avoir généré une Access Key pour Object Storage
    - Avoir installé **Restic**
    - Avoir installé **S3cmd** et configuré celui-ci avec l'Access Key

## Sauvegarde et clonage via un snapshot de volume

Pour rappel, un volume est attaché à chaque instance pour le disque système.
L'opération consiste donc globalement à sauvegarder ce volume, et ensuite à créer une nouvelle instance à partir de cette sauvegarde.
Dans le détail, il s'agit de :

*   créer un snapshot du volume
*   créer un volume à partir de ce snapshot
*   uploader ce volume comme image
*   nettoyer le volume et le snapshot créés précédemment (s'ils ne sont plus utilisés)

Ensuite, une instance peut être créée à partir de cette image.

Ces opérations ne peuvent pas se faire pour l'instant depuis le SNC Regional Panel. Il faut utiliser la console OpenStack (_Horizon_) ou bien le CLI _openstack_.

### En utilisant la console OpenStack (Horizon)

Se connecter sur la console OpenStack en cliquant sur le bouton "_Open horizon_" depuis la console OVHcloud.

![Bouton Open horizon de la console OVHcloud](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-17_16-0-1.png)

Aller dans le menu _Instances_, et cliquer sur l'instance à sauvegarder (instance _test_ dans cet exemple).

![Liste des instances avec l'instance test](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_10-32-36.png)

Aller tout en bas de la description de l'instance dans la section _Volumes Attached_, et cliquer sur le volume attaché.

![Section Volumes Attached avec le volume attaché à l'instance](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_10-33-34.png)

Le volume peut également être retrouvé dans le menu _Volumes_ en recherchant le volume attaché à l'instance.

![Menu Volumes avec le volume attaché à l'instance](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_10-35-25.png)

Créer ensuite un snapshot du volume :

![Action Create Snapshot sur le volume](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_15-16-34.png)

Le nommer et lancer la création du snapshot.
L'opération est presque immédiate.

:::warning
La création d'un snapshot d'un volume monté et en cours d'utilisation est certes _crash consistent_, mais pas _application consistent_.
Pour garantir à 100 % la cohérence des données sauvegardées, il est recommandé d'arrêter l'instance auparavant.
:::

![Formulaire de création du snapshot](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_15-18-40.png)

Aller dans le menu _Snapshots_ et créer un volume à partir du snapshot.

![Menu Snapshots avec l'action de création de volume](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_15-20-31.png)

Le nommer et laisser les autres valeurs. Lancer la création du volume.
L'opération est presque immédiate.

![Formulaire de création du volume depuis le snapshot](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_15-21-35.png)

Dans cet exemple, le volume va être sauvegardé dans les images. Ceci peut permettre par exemple de télécharger l'image localement pour une sauvegarde externe.

Choisir l'action "_Upload to Image_" dans la liste des actions du volume.

![Action Upload to Image dans la liste des actions du volume](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_15-24-24.png)

Nommer l'image, et garder "_Raw_" comme format de disque. Lancer l'upload.

![Formulaire d'upload avec le format Raw](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_15-25-37.png)

Le volume passe en status "_Uploading_". Selon la taille du volume, la création de l'image peut être plus ou moins longue.
Attendre que l'image soit complètement créée.

Le volume et le snapshot créés précédemment peuvent être supprimés (d'abord le volume, puis le snapshot) s'ils ne seront pas réutilisés.

Pour créer une nouvelle instance à partir de l'image, aller dans le menu _Images_, et cliquer sur l'action "_Launch_" pour l'image.

![Action Launch sur l'image dans le menu Images](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_15-28-49.png)

Les menus de création d'instance sont alors proposés, comme décrit dans [Comment créer une instance SNC Cloud Platform et s'y connecter](/guides/hosted-private-cloud/cloud-platform/create-instance).

En résumé :

*   dans le menu _Details_, nommer l'instance et choisir _nova-vm_ comme "Availability Zone"
*   dans le menu _Source_, cliquer sur _Yes_ pour "Create New Volume" et donner la taille adéquate
*   choisir la flavor dans le menu _Flavor_
*   choisir _Ext-Net_ comme réseau
*   ne pas choisir de keypair, la configuration ne sera pas prise en compte. Le fichier `authorized_keys` de l'instance ne sera pas modifié

et lancer la création de l'instance en cliquant sur "_Launch Instance_" et attendre que l'instance soit dans l'état "_Running_".

Au démarrage de l'instance, le _cloud-init_ détectera que l'instance a changé, et réinstallera la bonne configuration réseau.
Se connecter ensuite sur l'instance avec son IP publique.

### En utilisant le CLI (_openstack_)

Consulter [Comment créer une instance SNC Cloud Platform et s'y connecter](/guides/hosted-private-cloud/cloud-platform/create-instance) pour les détails concernant l'installation et la configuration du CLI _openstack_.

Récupérer le volume attaché à l'instance :

```bash
$ openstack volume list
+--------------------------------------+------------------+-----------+------+-------------------------------------+
| ID                                   | Name             | Status    | Size | Attached to                         |
+--------------------------------------+------------------+-----------+------+-------------------------------------+
...
| 7b643b08-7e98-4280-81fa-3f96569e8ef1 |                  | in-use    |   20 | Attached to test on /dev/sda        |
...
+--------------------------------------+------------------+-----------+------+-------------------------------------+
```

Créer le snapshot de ce volume.

:::warning
Il y a une limitation avec l'API cinder et l'option `--force` : il faut forcer la version de l'API pour que l'option soit bien prise en compte.
:::

```bash
$ OS_VOLUME_API_VERSION=3.71 openstack volume snapshot create --force --volume 7b643b08-7e98-4280-81fa-3f96569e8ef1 test-snapshot
+-------------+--------------------------------------+
| Field       | Value                                |
+-------------+--------------------------------------+
| created_at  | 2026-06-26T15:11:26.201472           |
| description | None                                 |
| id          | aaab4422-de3e-436d-897c-c7ddd0b1cadc |
| name        | test-snapshot                        |
| properties  |                                      |
| size        | 20                                   |
| status      | creating                             |
| volume_id   | 7b643b08-7e98-4280-81fa-3f96569e8ef1 |
+-------------+--------------------------------------+
```

Créer ensuite le volume pour ce snapshot :

```bash
$ openstack volume create --snapshot test-snapshot test-volume
...
```

Et créer une image à partir de ce volume :

```bash
$ openstack image create --volume test-volume test-image
+---------------------+--------------------------------------+
| Field               | Value                                |
+---------------------+--------------------------------------+
| container_format    | bare                                 |
| disk_format         | raw                                  |
| display_description | None                                 |
| id                  | 0092c933-283c-4890-9bca-a445bcaf40fd |
| image_id            | 026968e1-7930-4c3c-a63c-cc3bfac8ac6b |
| image_name          | test-image                           |
| protected           | False                                |
| size                | 20                                   |
| status              | uploading                            |
| updated_at          | 2026-06-26T15:13:01.457308           |
| visibility          | private                              |
| volume_type         | public_standard                      |
+---------------------+--------------------------------------+
```

Attendre que l'image soit prête (_active_).

```bash
$ openstack image show test-image -f value -c status
active
```

Le volume et le snapshot précédemment créés peuvent être supprimés s'ils ne seront plus utilisés.

```bash
$ openstack volume delete test-volume
$ openstack volume snapshot delete test-snapshot
```

Une instance peut maintenant être créée à partir de cette image. Récupérer ensuite son adresse IP, et une fois prête, se connecter dessus.

```bash
$ openstack server create --flavor b3-8 --image "test-image" --boot-from-volume 20 --network Ext-Net test-restore
...
$ openstack server show test-restore -f value -c status -c addresses
{'Ext-Net': ['xx.xx.xx.xx']}
ACTIVE
$ ssh debian@xx.xx.xx.xx hostname
test-restore
```

## Sauvegarde des données avec Restic (Object Storage)

:::info
L'outil de sauvegarde Restic est utilisé pour décrire une méthode possible pour faire des sauvegardes.
L'utilisateur est libre de choisir la solution qui lui convient.
:::


### Créer un bucket pour stocker les sauvegardes

Renseignez la commande suivante :

```bash
$ s3cmd mb s3://backup
```

### Initialiser le dépôt de sauvegarde

Commencez par choisir un mot de passe pour chiffrer vos sauvegardes. Dans ce guide, GPG est utilisé à cette fin :

```bash
$ gpg --gen-random --armor 1 20
```

Notez ce mot de passe dans un endroit sûr, avec vos informations d’identification S3<sup>1</sup>. Ensuite, la configuration de Restic sera placée dans des variables d'environnement. Cela inclut des informations sensibles, comme votre secret S3 et le mot de passe du dépôt. Par conséquent, assurez-vous que les commandes suivantes **n’apparaissent pas** dans le fichier d'historique de votre shell. Ajustez le contenu des variables d'environnement en fonction du nom de votre bucket, de la région et des informations d'identification API de votre utilisateur.

```bash
unset HISTFILE
export AWS_DEFAULT_REGION="eu-west-rbx-snc"
export AWS_ACCESS_KEY_ID="06bd244758d047eea26eb9cc1e572be7"
export AWS_SECRET_ACCESS_KEY="55db67712e594cd8a557abfd7a33a743"
export RESTIC_REPOSITORY="s3:https://s3-beta.eu-west-rbx-snc.cloud.snc.ovh.net/backup"
export RESTIC_PASSWORD="BYhISmzRvIPMwvbzgl8ROQ=="
```

Une fois l'environnement configuré, la commande Restic peut être appelée pour initialiser le dépôt :

```bash
$ restic init
created restic repository 821bcf92bf at s3:https://s3-beta.eu-west-rbx-snc.cloud.snc.ovh.net/backup

Please note that knowledge of your password is required to access
the repository. Losing your password means that your data is
irrecoverably lost.
```

Restic est maintenant prêt à être utilisé avec S3. Essayez de créer une sauvegarde :

```bash
$ restic backup /var/log/
repository 821bcf92 opened (repository version 2) successfully, password is correct
no parent snapshot found, will read all files
error: open /var/log/btmp: permission denied
error: Open: open /var/log/private: permission denied

Files:          30 new,     0 changed,     0 unmodified
Dirs:            7 new,     0 changed,     0 unmodified
Added to the repository: 745.784 MiB (173.112 MiB stored)

processed 30 files, 750.189 MiB in 0:04
snapshot 38e47b16 saved
```

```bash
$ restic snapshots
repository 821bcf92 opened (repository version 2) successfully, password is correct
ID        Time                 Host        Tags        Paths
---------------------------------------------------------------
38e47b16  2025-12-22 00:24:23  demo                  /var/log
---------------------------------------------------------------
1 snapshots
```

:::info
Un snapshot a été créé.
:::


Vérifiez le contenu du bucket :

```bash
$ s3cmd la
                          DIR  s3://backup/data/
                          DIR  s3://backup/index/
                          DIR  s3://backup/keys/
                          DIR  s3://backup/snapshots/
2025-12-22 00:22          155  s3://backup/config
```

:::info
Une sauvegarde a été créée et stockée dans le bucket S3.
:::
