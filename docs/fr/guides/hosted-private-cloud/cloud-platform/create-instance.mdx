Ce guide détaille les étapes pour créer une instance SNC Cloud Platform, selon les différentes méthodes proposées :

*   depuis le SNC Regional Panel
*   depuis la console OpenStack (_Horizon_)
*   avec le CLI OpenStack (_openstack_)
*   avec OpenTofu (_tofu_)

Pour le moment, les API OVHcloud et par conséquent le provider OVHcloud Terraform ne sont pas supportés.

## Création d'une instance depuis le SNC Regional Panel

Se connecter sur le SNC Regional Panel de votre région.

Dans le bandeau gauche cliquer sur "Compute" et ensuite sur le bouton "Create server"

![Bouton Create server dans la section Compute du SNC Regional Panel](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-17_14-55-1.png)

Ensuite définir les différents éléments de configuration :

*   Nommer l'instance
*   Choisir le gabarit. 3 classes de gabarits sont proposées :
    *   _General purpose_, pour une utilisation classique.
        Ce sont des instances avec 4 Gio de mémoire par vCPU.
    *   _Compute optimized_, pour des utilisations orientées 'compute intensive'.
        Elles ont deux fois plus de vCPU par Gio de mémoire.
    *   _Memory optimized_, pour des utilisations nécessitant beaucoup de mémoire.
        Elles ont deux fois plus de mémoire par vCPU que les _General purpose_.

Les instances de type '_dedicated_' garantissent que les instances tourneront sur des hypervisors dédiés au client.  
L'hypervisor ne sera pas partagé avec un autre client ; en contrepartie l'hypervisor dans son intégralité sera facturé, quel que soit le nombre d'instances qu'il héberge.

![Choix du gabarit : General purpose, Compute optimized, Memory optimized et dédié](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-17_15-2-34.png)

*   Cliquer sur '_Create block storage_'.
    *   Nommer le block storage.
    *   Sélectionner _Image_ et choisir l'image à déployer.
        Seules les images gérées par OVHcloud sont proposées. Pour déployer sa propre image, préalablement ajoutée à la librairie d'image, il faudra utiliser _Horizon_ ou le mode _CLI_.
    *   Choisir la taille du volume. La taille doit être au moins égale à la taille nécessaire pour l'image à déployer.
        Sélectionner la case à cocher "_Bootable"_ et cliquer sur le bouton "_Create"._

![Formulaire de création du block storage avec image et taille](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-17_15-14-20.png)

*   Choisir le réseau sur lequel sera attachée l'instance.
    Si l'instance doit être accédée depuis le réseau public, choisir le réseau "_Ext-Net_".
*   Choisir la clé ssh. La connexion sur l'instance ne pourra se faire qu'en ssh avec clé.
    Si aucune clé n'a été créée, cliquer sur "_New ssh key_".
*   Cliquer sur "_Create_" une fois que le volume est prêt (ce qui peut être plus ou moins long selon la taille de l'image).

![Choix du réseau Ext-Net et de la clé ssh](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-17_15-8-34.png)

Attendre que l'instance passe en status "_active_"

Son adresse IP publique est affichée dans la colonne "_IP adresses_"

![Instance active avec son adresse IP publique dans la colonne IP adresses](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-17_15-23-49.png)

## Création d'une instance depuis la console OpenStack (Horizon)

Se connecter sur la console OpenStack en cliquant sur le bouton "_Open horizon_" depuis la console OVHcloud.

![Bouton Open horizon](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-17_16-0-1.png)

Tout d'abord il faut créer une "_key pair"_ en important la clé publique ssh.

Dans le bandeau gauche, aller dans la section "_Compute_" → "_Key Pairs_" et cliquer sur le bouton "_Import Public Key_".

![Menu Key Pairs et bouton Import Public Key](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-17_16-24-30.png)

Importer sa clé.

![Formulaire d'import de la clé publique](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-17_16-26-0.png)

Dans le bandeau gauche, aller dans la section "_Compute_" → "_Instances_" et cliquer sur le bouton "_Launch Instance_".

![Bouton Launch Instance dans la section Instances](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-17_16-1-50.png)

Dans la première section (_Details_) :

*   nommer l'instance
*   choisir "_nova-vm_" pour l'_Availability Zone_
*   cliquer sur _Next_

![Section Details de l'assistant Launch Instance](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-17_16-29-13.png)

Dans la section suivante (_Source_) :

*   dans le champ _Select Boot Source_, choisir _Image_ et surtout cliquer sur _Yes_ pour _Create New Volume_
*   choisir la taille du volume, qui doit être au moins égale à celle nécessaire pour l'image et cliquer sur _Yes_ pour _Delete Volume on Instance Delete_
*   choisir l'image désirée et cliquer sur la flèche vers le haut à droite de l'image
*   cliquer sur _Next_

Les images gérées par OVHcloud ainsi que les images ajoutées par l'utilisateur sont listées.

![Section Source avec choix de l'image et Create New Volume](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-17_16-34-40.png)

Dans la section suivante, choisir le gabarit de l'instance en cliquant sur la flèche vers le haut à droite du gabarit désiré.
Se référer au paragraphe précédent pour la description des différents gabarits.

Cliquer sur _Next_.

Dans la section suivante, choisir le réseau sur lequel sera connectée l'instance.

Si l'instance doit être accédée depuis le réseau public, choisir le réseau "_Ext-Net_".

Et cliquer sur _Next_ jusqu'à la section _Key Pair_.

![Section Networks du formulaire de création d'instance](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-17_16-49-43.png)

Dans la section _Key Pair_, choisir la clé précédemment créée, et cliquer sur _Launch Instance_.

![Section Key Pair avec sélection de la clé puis Launch Instance](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-17_16-50-54.png)

L'instance est en cours de création.
Attendre qu'elle soit dans le status "_Active_" pour s'y connecter.

Son adresse IP publique apparaît dans la colonne "_IP Address_".

![Instance en status Active avec son adresse IP publique](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-17_16-56-40.png)

## Création d'une instance avec le CLI OpenStack

Tout d'abord, installer le CLI OpenStack.
Voici un exemple sous Debian 13 :

```bash
sudo apt update
...
sudo apt install -y python3 python3-pip python3-venv
...
python3 -m venv ~/.venvs/osc
. ~/.venvs/osc/bin/activate
(osc) $ pip install --upgrade pip
...
(osc) $ pip install python-openstackclient
...
(osc) $ echo "source ~/.venvs/osc/bin/activate" >> ~/.bashrc
```

Il faut ensuite créer une _application credentials_ qui fournira les _credentials_ nécessaires pour se connecter aux API.

Dans la console OVHcloud, cliquer sur l'image du profil en haut à droite, aller dans le menu "_API access_" puis cliquer sur le bouton "_Create application credentials_".

![Menu API access de la console OVHcloud](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-18_10-56-34.png)

![Bouton Create application credentials](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-18_10-57-18.png)

Nommer l'application et définir sa date d'expiration (ne rien renseigner pour éviter l'expiration de l'application). Cliquer sur "_Request credentials_".

![Formulaire de création de l'application credentials](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-18_10-59-5.png)

Le secret de l'application s'affiche. Le copier. Il ne pourra plus être récupéré une fois le popup fermé.

L'application apparaît dans la liste des applications.

![Liste des application credentials avec la nouvelle application](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-18_14-29-27.png)

Enfin, récupérer le fichier _clouds.yaml_ en cliquant sur "_Download clouds.yaml_" en haut à droite, renseigner les champs demandés et cliquer sur "_Download clouds.yaml_".

![Formulaire Download clouds.yaml](/images/hosted-private-cloud/cloud-platform/create-instance/image-2026-6-18_14-31-1.png)

Un fichier "_clouds.yaml_" va être téléchargé sur le poste de travail.
Il suffit ensuite de le copier dans le home directory. Il permettra l'accès aux API OpenStack.

:::warning
Il faut que l'IP depuis laquelle est effectuée la connexion aux API soit « whitelistée » chez OVHcloud.
:::

Pour vérifier l'accès aux API :

```bash
(osc) $ openstack server list
+--------------------------------------+------------+--------+----------------------------------------------+--------------------------+--------+
| ID                                   | Name       | Status | Networks                                     | Image                    | Flavor |
+--------------------------------------+------------+--------+----------------------------------------------+--------------------------+--------+
| 1d4bbfcc-48b5-4cb2-80ba-5aafd9f5a0eb | test       | ACTIVE | Ext-Net=xx.xx.xx.xx                          | N/A (booted from volume) | b3-8   |
+--------------------------------------+------------+--------+----------------------------------------------+--------------------------+--------+
```

Tout d'abord il faut créer une clé ssh à partir de sa clé publique :

```bash
(osc) $ openstack keypair create --type ssh --public-key my_key.pub test
+-------------+-------------------------------------------------+
| Field       | Value                                           |
+-------------+-------------------------------------------------+
| created_at  | None                                            |
| fingerprint | ae:e7:62:0a:cf:7f:18:55:d3:f6:5b:96:f5:53:a2:b0 |
| id          | test                                            |
| is_deleted  | None                                            |
| name        | test                                            |
| type        | ssh                                             |
| user_id     | 9036e7ea1c0e49409b9af4289bca4a25                |
+-------------+-------------------------------------------------+
```

L'instance peut maintenant être créée. Prenons le même exemple que précédemment : b3-8, disque de 20 Go, image Debian 13 :

```bash
(osc) $ openstack image list -f value -c Name | grep -i "debian 13"
Debian 13 OVH

(osc) $ openstack server create --flavor b3-8 --image "Debian 13 OVH" --boot-from-volume 20 --network Ext-Net --key-name test test
...
```

Attendre que l'instance soit en status "_ACTIVE_" et récupérer son IP publique :

```bash
(osc) $ openstack server show test -f value -c status -c addresses
{'Ext-Net': ['xx.xx.xx.xx']}
ACTIVE
```

Il reste à se connecter dessus en ssh, user _debian_ (voir [Connexion à l'instance](#connexion-à-linstance)).

## Création d'une instance avec OpenTofu

Tout d'abord, installer le CLI _tofu_.
Voici un exemple sous Debian 13 :

```bash
sudo apt update
...
sudo apt install -y apt-transport-https ca-certificates curl gnupg
...
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://get.opentofu.org/opentofu.gpg | sudo tee /etc/apt/keyrings/opentofu.gpg > /dev/null
curl -fsSL https://packages.opentofu.org/opentofu/tofu/gpgkey | sudo gpg --no-tty --batch --dearmor -o /etc/apt/keyrings/opentofu-repo.gpg > /dev/null
sudo chmod a+r /etc/apt/keyrings/opentofu.gpg /etc/apt/keyrings/opentofu-repo.gpg
echo "deb [signed-by=/etc/apt/keyrings/opentofu.gpg,/etc/apt/keyrings/opentofu-repo.gpg] https://packages.opentofu.org/opentofu/tofu/any/ any main" | sudo tee /etc/apt/sources.list.d/opentofu.list > /dev/null
sudo apt update
...
sudo apt install -y tofu
...
tofu version
OpenTofu v1.12.2
on linux_amd64
```

Ensuite, créer une _application credentials_ qui fournira les _credentials_ nécessaires pour se connecter aux API, comme détaillé dans la [section CLI](#création-dune-instance-avec-le-cli-openstack).

Voici un exemple simplifié de scripts terraform pour créer la keypair ssh et l'instance, avec en output l'adresse IP publique de l'instance :

```hcl
// provider.tf
#
# Providers definition
#

# Providers
terraform {
  required_providers {
    openstack = {
      source  = "terraform-provider-openstack/openstack"
    }
  }
}

# OpenStack provider
provider "openstack" {
  auth_url                      = "https://auth.cloud.ovh.net/v3/"
  domain_name                   = "default"
  application_credential_id     = var.openstack_creds.app_id
  application_credential_secret = var.openstack_creds.app_secret
  region                        = var.openstack_creds.region
}


// variables.tf
#
# Variables for the deployment
#

# OpenStack credentials
variable "openstack_creds" {
  description = "OpenStack credentials"
  default     = {

    # credentials
    app_id     = "xxxxxx"
    app_secret = "xxxxxx"

    # region
    region     = "pod4.rbx"

  }
}

# SSH Key
variable "ssh_key" {
  description = "ssh key"
  default     = {
    public_key = "ssh-ed25519 xxxxxx user@domain",
    name       = "test"
  }
}

# Instance
variable "instance" {
  description = "Instance parameters"
  default     = {
    image                 = "Debian 13 OVH"
    flavor                = "b3-8"
    volume_size           = 20
    delete_on_termination = true
  }
}


// instance.tf
#
# Instance deployment
#

# Get image id
data "openstack_images_image_v2" "debian" {
  name        = var.instance.image
  most_recent = true
}

# SSH Key creation
resource "openstack_compute_keypair_v2" "test" {
  name       = var.ssh_key.name
  public_key = var.ssh_key.public_key
}

# Instance creation
resource "openstack_compute_instance_v2" "test" {
  name        = "test"
  image_name  = data.openstack_images_image_v2.debian.id
  flavor_name = var.instance.flavor
  key_pair    = var.ssh_key.name
  block_device {
    uuid                  = data.openstack_images_image_v2.debian.id
    source_type           = "image"
    destination_type      = "volume"
    boot_index            = 0
    volume_size           = var.instance.volume_size
    delete_on_termination = var.instance.delete_on_termination
  }
  network {
    name = "Ext-Net"
  }
  depends_on = [
    openstack_compute_keypair_v2.test
  ]
  security_groups = ["default"]
}

// outputs.tf
output "ip_address" {
  description = "instance public IP address"
  value       = openstack_compute_instance_v2.test.network[0].fixed_ip_v4
}
```

:::warning
Il faut que l'IP depuis laquelle est effectuée la connexion aux API soit « whitelistée » chez OVHcloud.
:::

Initialiser et appliquer la configuration :

```bash
tofu init
...
tofu version
OpenTofu v1.12.2
on linux_amd64
+ provider registry.opentofu.org/terraform-provider-openstack/openstack v3.4.0

tofu apply
...
Plan: 1 to add, 0 to change, 0 to destroy.

Changes to Outputs:
  + ip_address = (known after apply)

Do you want to perform these actions?
  OpenTofu will perform the actions described above.
  Only 'yes' will be accepted to approve.

  Enter a value: yes

openstack_compute_instance_v2.test: Creating...
openstack_compute_instance_v2.test: Still creating... [10s elapsed]
...
openstack_compute_instance_v2.test: Creation complete after 2m21s [id=8e97df41-f2e2-43f7-a1d7-a7fa4121ab11]

Apply complete! Resources: 1 added, 0 changed, 0 destroyed.

Outputs:

ip_address = "xx.xx.xx.xx"
```

Ensuite se connecter en ssh avec le user associé à l'image, et la clé privée associée à la clé publique enregistrée.

:::info
Pour une utilisation plus avancée de Terraform/OpenTofu sur cette plateforme (networking, object storage S3, pièges connus), consulter [le guide Terraform de la plateforme](/guides/hosted-private-cloud/cloud-platform/terraform).
:::

:::warning
Par défaut, le _security group_ _default_ n'autorise rien. Il est donc nécessaire au préalable de configurer les _security groups_ pour autoriser la connexion ssh sur l'instance.
:::
