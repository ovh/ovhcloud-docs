## Objectif

OVHcloud propose une fonctionnalité de migration de machines virtuelles vers Public VCF as-a-Service, reposant sur **VMware Cloud Director Availability (VCDA)**. Cette fonctionnalité permet de migrer simplement vos VMs depuis un environnement vSphere ou VCD on-premises vers votre organisation Public VCF as-a-Service.

**Ce guide vous accompagne pour lancer une première migration : réplication des données, suivi puis bascule (migration) vers votre organisation Public VCF as-a-Service.**

## Prérequis

- Disposer d'une organisation [Public VCF as-a-Service](/links/hosted-private-cloud/vmware-vcd) active.
- Avoir activé l'option de migration sur votre organisation depuis votre <ManagerLink to="/">espace client OVHcloud</ManagerLink>. Si nécessaire, consultez le guide « [Activer l'option de migration VCDA sur votre organisation Public VCF as-a-Service](/guides/hosted-private-cloud/powered-by-vmware/vcda-enable-offer) ».
- Disposer d'une appliance **VCDA on-premises** déployée, configurée et appairée avec votre organisation Public VCF as-a-Service. Si ce n'est pas encore le cas, consultez le guide « [Migration Public VCF as-a-Service avec VCDA - Premiers pas](/guides/hosted-private-cloud/powered-by-vmware/vcda-getting-started) ».
- Disposer d'un compte utilisateur sur votre organisation Public VCF as-a-Service avec les droits suffisants pour gérer les réplications.

## En pratique

### Vue d'ensemble du workflow

Le workflow de migration se découpe en 3 étapes principales :

<img className="thumbnail" alt="Workflow de migration VCDA : lancer la réplication, attendre la fin de la synchronisation, puis lancer la migration finale (bascule)" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/workflow-fr.png" loading="lazy" />

Les opérations peuvent être pilotées depuis deux interfaces :

- **L'interface de votre appliance VCDA on-premises**, pour les opérations côté source (recommandé pour ce guide) ;
- **L'interface VMware Cloud Director** de votre organisation Public VCF as-a-Service, via le **plugin Availability**.

#### Accéder au plugin Availability dans VMware Cloud Director

Depuis votre organisation Public VCF as-a-Service, ouvrez le portail VCD et cliquez sur <code className="action">More</code> > <code className="action">Availability</code> pour accéder au plugin VCDA :

<img className="thumbnail" alt="Plugin Availability dans VMware Cloud Director" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/01-vcd-availability-plugin.png" loading="lazy" />

Le plugin affiche l'état des réplications entrantes et sortantes pour votre organisation.

### Étape 1 : Lancer la réplication

Dans cet exemple, la migration est lancée **depuis** l'appliance VCDA on-premises **vers** l'organisation Public VCF as-a-Service.

Connectez-vous à l'interface de votre appliance VCDA on-premises (`https://<IP-de-l-appliance>`) avec le compte `root`.

Dans le menu de gauche, cliquez sur <code className="action">Outgoing Replications</code> puis sur l'onglet <code className="action">vApp</code>.

Cliquez sur le bouton <code className="action">New migration</code> (icône cloud avec une flèche vers le haut) pour démarrer l'assistant.

<img className="thumbnail" alt="Bouton New migration" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/02-new-migration-button.png" loading="lazy" />

#### Authentification sur l'organisation cible

L'assistant vous demande de vous authentifier sur l'organisation Public VCF as-a-Service qui sera la cible de la migration.

Saisissez :

- **Username** : votre nom d'utilisateur sur l'organisation Public VCF as-a-Service (au format `utilisateur@organisation`) ;
- **Password** : le mot de passe associé.

Cliquez sur <code className="action">LOGIN</code>.

<img className="thumbnail" alt="Authentification dans l'assistant de migration" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/03-wizard-auth.png" loading="lazy" />

#### Étape 1.1 : Sélection des VMs sources

Sélectionnez le vCenter source dans la liste déroulante <code className="action">Select VMs to replicate from</code>, puis cochez la ou les machines virtuelles à migrer.

<img className="thumbnail" alt="Sélection des VMs sources" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/04-source-vm-selection.png" loading="lazy" />

Cliquez sur <code className="action">Next</code>.

#### Étape 1.2 : Choix du vDC et de la politique de stockage

Sélectionnez le **virtual datacenter (vDC)** cible dans votre organisation Public VCF as-a-Service ainsi que la **politique de stockage** à utiliser pour les VMs migrées.

<img className="thumbnail" alt="Sélection du vDC et de la politique de stockage" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/05-destination-vdc.png" loading="lazy" />

Cliquez sur <code className="action">Next</code>.

#### Étape 1.3 : Paramètres de la réplication

Cette étape vous permet d'ajuster les paramètres de la réplication :

- **Compress replication traffic** : à activer uniquement en cas de bande passante limitée (consommation CPU augmentée) ;
- **Delay start synchronization** : pour décaler le démarrage de la synchronisation initiale ;
- **VDC policy settings** : politiques de placement et de dimensionnement à appliquer côté cible (laissez <code className="action">None</code> pour conserver la configuration d'origine).

<img className="thumbnail" alt="Paramètres de réplication" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/06-settings.png" loading="lazy" />

Cliquez sur <code className="action">Next</code>.

#### Étape 1.4 : Récapitulatif

L'assistant affiche un récapitulatif de la migration à venir. Vérifiez :

- les VMs sélectionnées ;
- le site source et le site de destination ;
- le vDC et la politique de stockage ;
- les politiques de dimensionnement et de placement.

<img className="thumbnail" alt="Récapitulatif de la migration" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/07-ready-to-complete.png" loading="lazy" />

Cliquez sur <code className="action">Finish</code> pour démarrer la réplication.

### Étape 2 : Suivre l'avancement de la réplication

Une fois la réplication lancée, elle apparaît dans la liste <code className="action">Outgoing Replications</code> avec l'état **Synchronizing**.

<img className="thumbnail" alt="Réplication en cours" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/08-replication-in-progress.png" loading="lazy" />

Le détail de la réplication indique :

- la progression du checksum (vérification des blocs) ;
- les octets transférés ;
- l'état des composants côté source et cible.

:::warning
Attendez que la réplication atteigne l'état **Healthy** avant de lancer la migration finale. La durée de la réplication initiale dépend de la taille des disques et de la bande passante disponible.
:::

Lorsque la réplication est prête à être basculée, l'état devient **Healthy** et le **Recovery state** affiche **Not started** :

<img className="thumbnail" alt="Réplication prête" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/09-replication-ready.png" loading="lazy" />

### Étape 3 : Lancer la migration

Une fois la réplication en état **Healthy**, vous pouvez déclencher la bascule.

Sélectionnez la réplication dans la liste, puis cliquez sur <code className="action">ALL ACTIONS</code> > <code className="action">Migrate</code>.

<img className="thumbnail" alt="Menu Migrate" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/10-migrate-menu.png" loading="lazy" />

#### Étape 3.1 : Paramètres de la migration

Configurez les paramètres de bascule :

- **Power settings** : cochez <code className="action">Power on recovered vApps</code> pour démarrer automatiquement les VMs côté cible après la bascule ;
- **Network Settings** :
    - <code className="action">Apply preconfigured network settings on migrate</code> : applique les paramètres réseau définis dans le profil de récupération ;
    - <code className="action">Connect all VMs to network</code> : reconnecte simplement les VMs au réseau choisi ;
- **VDC policy settings** : politiques de placement, de dimensionnement et de stockage à utiliser côté cible.

<img className="thumbnail" alt="Paramètres de migration" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/11-migrate-settings.png" loading="lazy" />

Cliquez sur <code className="action">Next</code>.

#### Étape 3.2 : Confirmation

Vérifiez le récapitulatif :

- les vApps à migrer ;
- le site de récupération ;
- les paramètres réseau ;
- la politique de stockage.

<img className="thumbnail" alt="Confirmation de la migration" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/12-migrate-confirm.png" loading="lazy" />

:::info
Le workflow de migration exécute automatiquement les étapes suivantes :

1. Synchronisation finale (si la VM source est démarrée) ;
2. Arrêt de la VM source ;
3. Synchronisation finale (une fois la VM source arrêtée) ;
4. Import de la VM dans le site cible.

:::

Cliquez sur <code className="action">Finish</code> pour lancer la migration.

#### Suivi de la migration en cours

La bascule apparaît dans la liste des réplications avec l'état **Migrate** et un pourcentage d'avancement :

<img className="thumbnail" alt="Migration en cours" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/13-migration-in-progress.png" loading="lazy" />

#### Migration terminée

Une fois la migration finalisée, la VM apparaît dans votre organisation Public VCF as-a-Service et l'état de la réplication passe en **Failed-Over** dans la vue **Incoming Replications** du portail VCD :

<img className="thumbnail" alt="Migration terminée" src="/images/hosted-private-cloud/powered-by-vmware/vcda-trigger-migration/14-migration-completed.png" loading="lazy" />

Vous pouvez désormais retrouver vos VMs migrées directement dans votre vDC Public VCF as-a-Service, prêtes à être utilisées.
