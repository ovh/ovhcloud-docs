## Objectif

Ce guide explique à quoi sert la fonctionnalité **LTR (Long Term Retention)** dans Zerto et comment la configurer pour conserver vos points de restauration sur une durée étendue.

La fonctionnalité permet notamment de :

- Associer un bucket OVHcloud Object Storage à Zerto pour la conservation long terme.
- Définir la politique d'immutabilité des données.
- Sécuriser la configuration avec les bonnes informations de connexion.
- Reprendre facilement la configuration en cas d'échec.

## Prérequis

- Disposer d'un service Managed VMware vSphere avec Zerto activé.
- Disposer d'un bucket OVHcloud Object Storage.
- Disposer des identifiants S3<sup>1</sup> associés à ce bucket (access key et secret key).

:::info
Configurez la LTR depuis la section Zerto de votre datacenter dans Managed VMware vSphere.
:::

## En pratique

### Étape 1 : Comprendre les informations demandées

Lors de l'ajout ou de l'édition d'un bucket LTR, les champs suivants sont utilisés :

- `repositoryName` : nom du repository affiché dans Zerto.
- `bucketName` : nom du bucket OVHcloud Object Storage.
- `endPointUrl` : URL de l'endpoint S3 de la région cible.
- `objectStorageAccessKey` : clé d'accès S3.
- `objectStorageSecretKey` : clé secrète S3.
- `repositoryType` : type de repository (`highPerformance` ou `standard`).
- `defaultRepository` : définir ce repository comme repository par défaut.

Statut des champs :

| Champ | Statut | Détails |
|:--|:--|:--|
| repositoryName | Obligatoire | Nom du repository affiché dans Zerto. |
| bucketName | Obligatoire | Nom du bucket OVHcloud Object Storage. |
| endPointUrl | Obligatoire | Endpoint S3 de la région du bucket. |
| objectStorageAccessKey | Obligatoire | Clé d'accès S3 du bucket. |
| objectStorageSecretKey | Obligatoire | Clé secrète S3 du bucket. |
| repositoryType | Obligatoire | `highPerformance` ou `standard` (ce paramètre correspond à la classe du bucket Object Storage et peut aussi être administré depuis l'interface Object Storage). |
| enableImmutability | Optionnel | Active la protection d'immutabilité. |
| immutabilityPolicy | Conditionnel | Obligatoire si `enableImmutability` est activé. |
| numberOfDays | Conditionnel | Obligatoire si `immutabilityPolicy = Period` (30 à 90 jours). |
| defaultRepository | Optionnel | Définit ce repository comme valeur par défaut. |

### Étape 2 : Configurer l'immutabilité

Pour l'immutabilité, activez l'option `enableImmutability`, puis choisissez une politique :

- `Period` : vous définissez explicitement une durée en jours.
- `perVPGRetentionPolicy` : la durée est pilotée par la politique de rétention Zerto.

Si vous choisissez `Period`, renseignez `numberOfDays` entre **30 et 90 jours**.

### Étape 3 : Vérifier le prérequis Object Lock

L'**Object Lock** doit être activé sur le bucket OVHcloud Object Storage.

Sans cette configuration, la rétention long terme ne peut pas fonctionner correctement.

Message à afficher :

```text
Object Lock must be enabled on your OVHcloud Object Storage bucket.
Without this configuration, LTR will not work correctly.
```

:::warning
Si Object Lock n'est pas activé, la configuration LTR peut échouer ou ne pas garantir l'immutabilité attendue.
:::

### Étape 4 : Utiliser des endpoints région à jour

Vérifiez que l'endpoint renseigné correspond bien à la région OVHcloud de votre bucket.

Les endpoints région peuvent évoluer ; utilisez toujours les valeurs les plus récentes proposées dans l'interface.

### Étape 5 : Gérer les échecs de configuration

Si une tentative de configuration échoue :

- Un message d'erreur explicite doit indiquer que la configuration n'a pas abouti.
- Le formulaire d'ajout doit redevenir disponible pour permettre une nouvelle tentative.

### Étape 6 : Comprendre l'état sans bucket configuré

Quand aucun bucket n'est associé, la page affiche :

- Un message expliquant qu'un bucket OVHcloud Object Storage est nécessaire pour activer LTR.
- Un bouton **Commander un bucket OVHcloud** redirigeant vers la commande Object Storage OVHcloud.
  - Si vous disposez d'un projet Public Cloud, la redirection ouvre la section Object Storage du Manager.
  - Si vous ne disposez pas de projet Public Cloud, la redirection ouvre la page Object Storage du site OVHcloud.
- Un bouton secondaire **Ajouter un bucket existant** ouvrant la fenêtre d'ajout.

### Étape 7 : Gérer les buckets existants

Pour chaque bucket configuré, les actions disponibles sont :

- `Edit` : modifier la configuration du bucket.
- `Delete` : supprimer la configuration du bucket.
