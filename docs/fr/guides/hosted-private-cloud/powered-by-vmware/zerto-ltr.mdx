## Objectif

Ce guide explique à quoi sert la fonctionnalité **LTR (Long Term Retention)** dans Zerto et comment la configurer pour conserver vos points de restauration sur une durée étendue.

La fonctionnalité permet notamment de :

- Associer un bucket OVHcloud Object Storage à Zerto pour la conservation long terme.
- Définir la politique d'immutabilité des données.
- Sécuriser la configuration avec les bonnes informations de connexion.
- Reprendre facilement la configuration en cas d'échec.

## Prérequis

- Disposer d'un service Managed VMware vSphere avec Zerto activé.
- Disposer d'un bucket OVHcloud Object Storage.
- Disposer des identifiants S3<sup>1</sup> associés à ce bucket (access key et secret key).

{/* CP-STEPS-START:cp-access */}

:::info
Configurez la LTR depuis l'onglet **PRA** de votre datacenter dans Managed VMware vSphere, en cliquant sur <code className="action">LTR</code>.
:::

[[cpnav:privatecloud-vmware-vsphere-console]]

{/* CP-STEPS-END:cp-access */}

## En pratique

### Étape 1 : Comprendre les informations demandées

{/* CP-STEPS-START:comprendre-informations-demandees */}

Lors de l'ajout d'un bucket LTR (fenêtre **Ajouter un bucket LTR**) ou de son édition (fenêtre **Modifier le bucket LTR**), les champs suivants sont utilisés :

| Champ | Statut | Détails |
|:--|:--|:--|
| **Nom du bucket** | Obligatoire | Nom du bucket OVHcloud Object Storage. Il sert également de nom au repository dans Zerto. Un nom déjà utilisé est refusé. |
| **URL de l'endpoint** | Obligatoire | URL de l'endpoint S3 de la région du bucket. |
| **Clé d'accès** | Obligatoire | Clé d'accès S3 du bucket. |
| **Clé secrète** | Obligatoire | Clé secrète S3 du bucket. |
| **Activer l'immutabilité** | Optionnel | Protège les données contre la suppression ou la modification pendant la période définie. |
| **Type d'immutabilité** | Conditionnel | Affiché lorsque **Activer l'immutabilité** est activé : **Période** ou **Per VPG Retention Policy** (par défaut). |
| **Nombre de jours** | Conditionnel | Obligatoire si **Type d'immutabilité** est **Période** (30 à 90 jours). |

Le type de repository (`highPerformance` ou `standard`) n'est pas à renseigner : il est déduit de l'URL de l'endpoint. Il correspond à la classe du bucket Object Storage et peut être administré depuis l'interface Object Storage.

Lors de l'édition d'un bucket, laissez les champs de clés vides pour conserver les valeurs actuelles.

{/* CP-STEPS-END:comprendre-informations-demandees */}

### Étape 2 : Configurer l'immutabilité

{/* CP-STEPS-START:configurer-immutabilite */}

Pour l'immutabilité, activez l'option **Activer l'immutabilité**, puis choisissez un **Type d'immutabilité** :

- **Période** : vous définissez explicitement une durée en jours.
- **Per VPG Retention Policy** (par défaut) : la durée est pilotée par la politique de rétention Zerto.

Si vous choisissez **Période**, renseignez **Nombre de jours** entre **30 et 90 jours**.

{/* CP-STEPS-END:configurer-immutabilite */}

### Étape 3 : Vérifier le prérequis Object Lock

{/* CP-STEPS-START:verifier-object-lock */}

L'**Object Lock** doit être activé sur le bucket OVHcloud Object Storage.

Sans cette configuration, la rétention long terme ne peut pas fonctionner correctement.

La fenêtre **Ajouter un bucket LTR** rappelle cette exigence et précise que seuls les buckets OVHcloud Object Storage sont pris en charge.

:::warning
Si Object Lock n'est pas activé, la configuration LTR peut échouer ou ne pas garantir l'immutabilité attendue.
:::

{/* CP-STEPS-END:verifier-object-lock */}

### Étape 4 : Utiliser des endpoints région à jour

{/* CP-STEPS-START:utiliser-endpoints-region */}

Vérifiez que l'endpoint renseigné correspond bien à la région OVHcloud de votre bucket.

Le champ **URL de l'endpoint** est un champ libre : saisissez l'URL complète de l'endpoint S3 de la région, au format `https://s3.<region>.io.cloud.ovh.net` (par exemple `https://s3.gra.io.cloud.ovh.net`). Les endpoints région peuvent évoluer ; utilisez toujours les valeurs les plus récentes.

{/* CP-STEPS-END:utiliser-endpoints-region */}

### Étape 5 : Gérer les échecs de configuration

{/* CP-STEPS-START:gerer-echecs-configuration */}

Si une tentative de configuration échoue :

- Un message d'erreur indique que le bucket LTR n'a pas pu être ajouté.
- La fenêtre d'ajout se ferme : cliquez à nouveau sur <code className="action">Ajouter un bucket</code> (ou sur <code className="action">+ Ajouter un bucket existant</code> si aucun bucket n'est encore configuré) pour faire une nouvelle tentative.

La configuration d'un bucket peut prendre jusqu'à 15 minutes. Pendant ce délai, il n'est pas possible d'ajouter un nouveau bucket.

{/* CP-STEPS-END:gerer-echecs-configuration */}

### Étape 6 : Comprendre l'état sans bucket configuré

{/* CP-STEPS-START:etat-sans-bucket */}

Quand aucun bucket n'est associé, la vue **LTR** affiche :

- Le message **Aucun repository LTR configuré**, qui explique qu'un bucket OVHcloud Object Storage doit être associé à votre environnement Zerto pour activer la rétention long terme.
- Un lien <code className="action">Créer un bucket OVHcloud</code> redirigeant vers Object Storage OVHcloud :
  - Si vous disposez d'un seul projet Public Cloud, il ouvre la section Object Storage de ce projet dans la console OVHcloud ; si vous en avez plusieurs, il ouvre la liste de vos projets Public Cloud.
  - Si vous ne disposez pas de projet Public Cloud, il ouvre la page Object Storage du site OVHcloud.
- Un bouton <code className="action">+ Ajouter un bucket existant</code> ouvrant la fenêtre **Ajouter un bucket LTR**.

{/* CP-STEPS-END:etat-sans-bucket */}

### Étape 7 : Gérer les buckets existants

{/* CP-STEPS-START:gerer-buckets-existants */}

Les buckets configurés sont listés dans un tableau (colonnes **Nom du bucket**, **Nombre de jours**, **Endpoint** et **Actions**). Pour chaque bucket, le menu ⋮ (colonne **Actions**) propose les actions suivantes :

- <code className="action">Éditer</code> : modifier la configuration du bucket (fenêtre **Modifier le bucket LTR**).
- <code className="action">Supprimer</code> : supprimer la configuration du bucket.

{/* CP-STEPS-END:gerer-buckets-existants */}
