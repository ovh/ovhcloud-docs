## Objectif

**Ce guide présente les opérations de base sur les machines virtuelles (VM) dans le vCenter de votre Workload Domain Private VCF as-a-Service : créer une VM, la déployer depuis la bibliothèque de contenu, la cloner et en faire un modèle.**

## Prérequis

- Disposer d'un Workload Domain [Private VCF as-a-Service](/links/hosted-private-cloud/private-vcf-aas-3-az) livré.
- Disposer d'un accès au vCenter de votre Workload Domain avec un compte administrateur.

## En pratique

### Avant de commencer

Quelle que soit la façon dont vous créez une VM, trois choix comptent particulièrement sur Private VCF as-a-Service :

| Choix | Ce qu'il faut savoir |
|---|---|
| **Politique de stockage** | Elle décide de la protection de la VM. En 3-AZ, choisissez une politique qui réplique sur les deux sites si la VM doit survivre à la perte d'une AZ (consultez la section « [Les politiques de stockage](/guides/hosted-private-cloud/powered-by-vmware/private-vcf/vsan-storage#politiques-de-stockage) » du guide « Private VCF as-a-Service - Gérer le stockage vSAN du cluster »). |
| **Réseau** | Branchez la VM sur un groupe de ports de votre vRack ou sur un segment NSX. Les groupes de ports de la plateforme ne sont pas visibles (consultez le guide « [Private VCF as-a-Service - Configurer le réseau du cluster](/guides/hosted-private-cloud/powered-by-vmware/private-vcf/network-configuration) »). |
| **Placement** | En 3-AZ, rangez la VM dans le groupe de VM de l'AZ où elle doit tourner (consultez la section « [3-AZ : placer vos VM par AZ](/guides/hosted-private-cloud/powered-by-vmware/private-vcf/vsan-storage#placer-vos-vm-par-az) » du guide « Private VCF as-a-Service - Gérer le stockage vSAN du cluster »). Sinon, DRS la place librement dans l'une ou l'autre AZ. |

### Créer une VM

1. Dans le vCenter, ouvrez la vue <code className="action">Hôtes et clusters</code>.
2. Faites un clic droit sur votre cluster, puis cliquez sur <code className="action">Nouvelle machine virtuelle</code>.
3. Choisissez <code className="action">Créer une machine virtuelle</code>, puis cliquez sur <code className="action">Suivant</code>.
4. Donnez un nom à la VM et choisissez son dossier.
5. Sélectionnez votre cluster comme ressource de calcul.
6. Sélectionnez la politique de stockage de la VM, puis le datastore `<cluster>-ds-vsan01`.
7. Laissez la compatibilité proposée par défaut.
8. Choisissez la famille et la version du système d'exploitation invité.
9. Réglez le matériel : nombre de vCPU, mémoire, taille du disque, carte réseau et son réseau. Pour installer le système depuis une image ISO, rattachez-la au lecteur CD/DVD et cochez <code className="action">Connecter lors de la mise sous tension</code>.
10. Vérifiez le résumé, puis cliquez sur <code className="action">Terminer</code>.

Démarrez la VM, ouvrez sa console depuis l'onglet <code className="action">Résumé</code> et installez le système d'exploitation. Installez ensuite **VMware Tools**, qui permet au vCenter d'arrêter proprement la VM et de lire son adresse IP.

:::tip
Pour déposer une image ISO, parcourez le datastore et utilisez <code className="action">Télécharger des fichiers</code>, ou ajoutez-la à la bibliothèque de contenu.

:::

### Déployer une VM depuis la bibliothèque de contenu

Votre Workload Domain est livré avec une bibliothèque de contenu, synchronisée à la livraison des hôtes. Vous pouvez aussi y ajouter vos propres modèles et images.

1. Ouvrez <code className="action">Bibliothèques de contenu</code> depuis le menu principal du vCenter, puis la bibliothèque.
2. Dans l'onglet <code className="action">Modèles</code>, faites un clic droit sur un modèle, puis cliquez sur <code className="action">Nouvelle VM à partir de ce modèle</code>.
3. Suivez l'assistant : nom, dossier, cluster, politique de stockage et réseau, comme pour créer une VM.
4. Personnalisez si besoin le matériel avant de cliquer sur <code className="action">Terminer</code>.

### Cloner une VM

Le clonage crée une copie complète d'une VM existante, avec ses disques et sa configuration.

1. Faites un clic droit sur la VM, puis cliquez sur <code className="action">Cloner</code> > <code className="action">Cloner la machine virtuelle</code>.
2. Donnez un nom au clone et choisissez son dossier, puis le cluster.
3. Sélectionnez la politique de stockage du clone. Elle peut être différente de celle de la VM d'origine.
4. Choisissez les options de clonage :
    - **Personnaliser le système d'exploitation** : applique une spécification de personnalisation, pour changer le nom d'hôte, l'adresse IP ou l'identifiant du système ;
    - **Personnaliser le matériel de cette machine virtuelle** : modifie le matériel du clone ;
    - **Allumer la machine virtuelle après création** : démarre le clone à la fin de l'opération.
5. Vérifiez le résumé, puis cliquez sur <code className="action">Terminer</code>.

:::warning
Un clone non personnalisé garde le même nom d'hôte et la même adresse IP fixe que la VM d'origine. Ne démarrez pas les deux sur le même réseau sans avoir changé l'un des deux.

:::

### Créer un modèle

Un modèle est une copie de référence qui ne démarre pas : il sert à déployer des VM identiques.

- **Cloner vers un modèle** : faites un clic droit sur la VM, puis cliquez sur <code className="action">Cloner</code> > <code className="action">Cloner vers un modèle</code>. La VM d'origine est conservée.
- **Convertir en modèle** : faites un clic droit sur une VM éteinte, puis cliquez sur <code className="action">Modèle</code> > <code className="action">Convertir en modèle</code>. La VM devient un modèle et n'existe plus en tant que VM.
- **Cloner en tant que modèle dans la bibliothèque** : faites un clic droit sur la VM, puis cliquez sur <code className="action">Cloner</code> > <code className="action">Cloner en tant que modèle dans la bibliothèque</code>, pour ranger le modèle dans votre bibliothèque de contenu.

Pour déployer une VM depuis un modèle de l'inventaire, faites un clic droit sur le modèle, puis cliquez sur <code className="action">Nouvelle VM à partir de ce modèle</code>.

### Les VM Windows

Si vous installez Windows Server ou SQL Server sous licence OVHcloud (SPLA), OVHcloud relève leur utilisation chaque heure, à partir de la licence déclarée sur chaque VM. Après un clonage ou un déploiement depuis un modèle, vérifiez la licence déclarée sur la nouvelle VM.
