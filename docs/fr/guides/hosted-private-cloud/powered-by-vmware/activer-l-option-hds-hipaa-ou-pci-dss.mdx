## Objectif

Pour rendre votre infrastructure Private Cloud conforme à [l'hébergement des données de santé](https://www.ovhcloud.com/fr/enterprise/products/hosted-private-cloud/safety-compliance/hds/) en Europe (certification HDS pour la France et conformité règlementaire pour l’Italie, le Royaume-Uni, l’Allemagne et la Pologne) ou des [données bancaires](https://www.ovhcloud.com/fr/enterprise/products/hosted-private-cloud/safety-compliance/pci-dss/) (certification PCI DSS), vous devez réaliser les opérations décrites dans ce guide.

**Découvrez comment activer l'option pour l'hébergement des données de santé ou des données bancaires sur votre offre Hosted Private Cloud.**

## Prérequis

* Posséder une [infrastructure Private Cloud](/links/hosted-private-cloud/vmware) sur votre compte OVHcloud. Version 6.0 ou supérieure.

[[cpnav:privatecloud-vmware-vsphere-console]]

## En pratique

### Activation

{/* CP-STEPS-START:activation */}

Pour adapter votre Private Cloud à cette certification, l'une des options de sécurité correspondantes doit être activée. Pour le vérifier, rendez-vous dans **Private Cloud** › **Managed VMware vSphere** dans la console OVHcloud et sélectionnez le service concerné dans la liste.

Le service s'ouvre sur son onglet <code className="action">Tableau de bord</code>. Vérifiez l'état d'activation des options de sécurité dans la section **Conformité**, sur la ligne **Conformité sectorielle**.

Si l'option de sécurité souhaitée n'est pas activée, cliquez sur <code className="action">Activer la conformité sectorielle</code> sur cette ligne pour ouvrir l'assistant d'activation.

Plusieurs conditions sont essentielles :

- **Les options [NSX](https://www.ovhcloud.com/fr/enterprise/products/hosted-private-cloud/nsx-datacenter-vsphere/) et [vROps](https://www.ovhcloud.com/fr/enterprise/products/hosted-private-cloud/vrops/) doivent être installées** : dans l'onglet <code className="action">Tableau de bord</code>, section **Options**, vous pouvez vérifier l'état d'activation de ces options sur les lignes **Virtualisation du réseau et de la sécurité (NSX-T)** et **vRealize Operations (vROps)**. Si vROps n'est pas activée, cliquez sur <code className="action">Activer des options</code> sur sa ligne.

- **La politique d'accès à vCenter doit être restreinte** : depuis l'onglet <code className="action">Contrôle d'accès</code>, vous pouvez vérifier l'état de la politique d'accès dans la section **Paramètres de session**, sur la ligne **Politique d'accès vCenter**. La politique y est affichée mais ne peut pas être modifiée depuis la console OVHcloud : si elle n'est pas restreinte, contactez nos équipes support pour la faire modifier. N'hésitez pas à consulter notre guide [Gérer votre Hosted Private Cloud depuis la console OVHcloud](/guides/hosted-private-cloud/powered-by-vmware/manager-ovh-private-cloud).

- **Vous devez disposer d'au moins une adresse IP autorisée pour vous connecter à vCenter** : depuis l'onglet <code className="action">Contrôle d'accès</code>, assurez-vous d'avoir autorisé au moins une adresse IP dans la liste des IP et blocs autorisés à se connecter. Si nécessaire, cliquez sur <code className="action">Associer un bloc IP</code>. N'hésitez pas à consulter notre guide [Gérer votre Hosted Private Cloud depuis la console OVHcloud](/guides/hosted-private-cloud/powered-by-vmware/manager-ovh-private-cloud).

Pour vous assurer que vous pouvez toujours vous connecter, nous vous recommandons d'avoir au moins deux adresses IP autorisées. Pour des raisons d'accessibilité, ces dernières doivent être fixes et non dynamiques.

- **L'utilisateur « admin » doit avoir des informations à jour et disposer de l'autorisation nécessaire** : depuis l'onglet <code className="action">Utilisateurs</code>, assurez-vous pour l'utilisateur « admin » que le numéro de téléphone et l'adresse e-mail sont correctement renseignés. L'utilisateur « admin » doit aussi disposer de l'autorisation « **token validator** » (colonne **Token validator**). Si nécessaire, pour modifier l'utilisateur, ouvrez le menu ⋮ (colonne **Actions**) de l'utilisateur, puis cliquez sur <code className="action">Éditer</code> : la fenêtre **Modifier** affiche les champs **Mail** et **Numéro de téléphone** ainsi que l'autorisation **Token validator**. N'hésitez pas à consulter notre guide [Gérer votre Hosted Private Cloud depuis la console OVHcloud](/guides/hosted-private-cloud/powered-by-vmware/manager-ovh-private-cloud).

Pour vous assurer que vous pouvez toujours vous connecter à vCenter, nous vous recommandons d'avoir au moins deux utilisateurs disposant des informations et autorisations nécessaires (avec des adresses de messagerie et des numéros de téléphone différents).

L'assistant d'activation comporte quatre étapes :

1. La première étape vous permet de choisir la certification à activer sur votre service (par exemple **Certification Hébergement des données de santé (HDS)** ou **Certification Payment Card Industry Data Security Standard (PCI DSS)**). Sélectionnez-la, puis cliquez sur <code className="action">Suivant</code>.
2. La deuxième étape garantit que la politique d'accès à vCenter est restreinte et que vous disposez d'au moins une adresse IP pouvant se connecter à vCenter. Elle affiche la politique d'accès et le nombre d'adresses IP et blocs autorisés.
3. Vérifiez à l'étape suivante que les coordonnées de l'utilisateur « admin » (ou des autres utilisateurs) sont correctement renseignées : au moins l'un de vos utilisateurs administrateur doit posséder un numéro de mobile, une adresse e-mail et être enregistré comme « token validator ». Si nécessaire, l'étape renvoie vers l'onglet <code className="action">Utilisateurs</code> pour configurer vos utilisateurs.
4. La dernière étape récapitule votre commande. Cliquez sur <code className="action">Commander</code> pour la confirmer.

Une fois les étapes d'activation terminées, vous devez :

- valider le token envoyé par SMS aux utilisateurs avec l'autorisation **token validator**. Cela confirme que vous pourrez recevoir ces tokens, qui sont essentiels pour valider les opérations
- compléter les documents que vous recevrez par e-mail pour finaliser la partie contractuelle

{/* CP-STEPS-END:activation */}

Nous vous conseillons de débuter avec l'interface sécurisée en poursuivant la lecture de ce guide. 

:::info
 L'interface vSphere ne sera pas accessible lors de l'activation de l'option de sécurité.

:::


### Débuter avec l'interface sécurisée

Après l'activation de l'option de sécurité, vous recevrez un e-mail détaillant le procédé de validation des tokens et leur fonctionnement.

Comme spécifié, les mesures de sécurité suivantes seront mises en place après l’activation de l’option de sécurité :

- tous les utilisateurs existants de votre Private Cloud seront désactivés;

- vous devrez modifier les mots de passe de vos utilisateurs afin que ceux-ci soient réactivés;

- la modification des mots de passe de vos utilisateurs devra être réalisée uniquement à partir de l'interface sécurisée. Vous ne pourrez plus effectuer cette manipulation à partir de la console OVHcloud.

Pour rappel, l'accès à l'interface sécurisée ne sera possible qu'une fois l'option de sécurité activée.
 
Connectez-vous ensuite à l'interface sécurisée via le lien fourni dans l'e-mail que vous avez reçu. Celui-ci sera similaire à `https://pcc-xxx-xxx-xxx-xxx.ovh.com/secure/password-lost`. Une fois connecté, vous pourrez changer le mot de passe de l'utilisateur « admin » puis les mot de passe des éventuels utilisateurs supplémentaires.

Pour plus de détails, consultez [notre guide dédié au fonctionnement de l'interface sécurisée](/guides/hosted-private-cloud/powered-by-vmware/interface-secure)
