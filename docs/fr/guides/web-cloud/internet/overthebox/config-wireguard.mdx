## Objectif

OverTheBox propose un mode de fonctionnement **WireGuard**<sup>1</sup>, une alternative au tunnel OverTheBox historique (glorytun / MPTCP).

**Ce guide vous explique comment basculer votre service OverTheBox en mode WireGuard et le configurer via l'API OVHcloud.**

:::warning
Le mode **WireGuard** d'OverTheBox est actuellement en phase **bêta**. Son comportement et les appels API associés sont susceptibles d'évoluer.

:::

## Prérequis

- Disposer d'un service **OverTheBox Starter** ou **OverTheBox Business** fourni par OVHcloud. WireGuard n'est pas disponible sur les anciennes offres : vous pouvez changer d'offre en consultant le guide « [Comment changer l'offre de mon service OverTheBox](/guides/web-cloud/internet/overthebox/offer-migration) ».
- Consulter notre guide « [Premiers pas avec les API OVHcloud](/guides/manage-and-operate/api/first-steps) » afin de vous familiariser avec l'APIv6 OVHcloud.

:::warning
L'**IPv6 n'est pas disponible** en mode WireGuard. Si vous avez besoin de l'IPv6, utilisez le mode OverTheBox historique et consultez le guide « [Comment configurer IPv6 sur OverTheBox](/guides/web-cloud/internet/overthebox/config-ipv6) ».

:::


:::warning
Les modes de fonctionnement sont **exclusifs** : le tunnel OverTheBox historique (glorytun / MPTCP) et WireGuard ne peuvent pas fonctionner en même temps. Basculer vers un mode désactive automatiquement l'autre.

:::


## En pratique

Tous les appels API de ce guide sont disponibles dans la <ApiLink section="/overTheBox">section */overTheBox*</ApiLink> de la console API.

:::info
Lors de l'utilisation de l'API, tous les champs marqués d'un astérisque (\*) sont obligatoires.
:::


### Vérifier le mode de fonctionnement actuel

Récupérez les informations de votre service, notamment le champ `operationMode`, à l'aide de l'appel suivant :

<Api version="v1" section="/overTheBox" method="GET" route={"/overTheBox/\{serviceName\}"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |

Le champ `operationMode` renvoyé indique le mode actif :

- `overthebox-legacy` : le tunnel OverTheBox historique (glorytun / MPTCP).
- `wireguard` : le mode WireGuard.

### Lister les modes de fonctionnement disponibles

Les modes disponibles dépendent de votre offre. Utilisez l'appel suivant pour connaître ceux accessibles sur votre service :

<Api version="v1" section="/overTheBox" method="GET" route={"/overTheBox/\{serviceName\}/availableOperationModes"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |

Le mode `wireguard` n'apparaît dans la liste que si votre offre le permet (offres **Starter** ou **Business**).

### Basculer en mode WireGuard

Utilisez l'appel suivant pour changer le mode de fonctionnement de votre service :

<Api version="v1" section="/overTheBox" method="PUT" route={"/overTheBox/\{serviceName\}/operationMode"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |
| `operationMode` | Oui | Le mode de fonctionnement à appliquer : `wireguard` (ou `overthebox-legacy` pour revenir au tunnel historique) |

:::warning
Le basculement en mode WireGuard désactive le tunnel OverTheBox historique et rend l'IPv6 indisponible. L'opération peut entraîner une courte interruption de service, le temps que la nouvelle configuration soit appliquée.

:::


### Récupérer la configuration du serveur WireGuard

Une fois le service en mode WireGuard, récupérez la configuration du serveur (nécessaire pour configurer vos clients) à l'aide de l'appel suivant :

<Api version="v1" section="/overTheBox" method="GET" route={"/overTheBox/\{serviceName\}/wireguard"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |

La réponse contient les informations à reporter dans la configuration de vos clients WireGuard :

| Champ | Description |
|-------|-------------|
| `endpoint.ipv4` | Adresse IPv4 publique du serveur WireGuard |
| `endpoint.port` | Port de connexion du serveur WireGuard |
| `publicKey` | Clé publique du serveur WireGuard |
| `privateIpv4` | Plage d'adresses IPv4 privées du serveur WireGuard |
| `maxPeerActive` | Nombre maximum de pairs actifs simultanément |
| `maxPeerAllowed` | Nombre maximum de pairs configurables |

### Gérer les pairs WireGuard

Un *pair* (*peer* dans l'API) représente un client autorisé à se connecter au serveur WireGuard de votre OverTheBox.

#### Lister les pairs

<Api version="v1" section="/overTheBox" method="GET" route={"/overTheBox/\{serviceName\}/wireguard/peers"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |

#### Créer un pair

<Api version="v1" section="/overTheBox" method="POST" route={"/overTheBox/\{serviceName\}/wireguard/peers"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |
| `name` | Oui | Un nom pour identifier le pair |
| `description` | Oui | Une description du pair |
| `privateKey` | Non | La clé privée WireGuard du client |
| `publicKey` | Non | La clé publique WireGuard du client (ignorée si `privateKey` est fournie) |
| `privateIpv4` | Oui | L'adresse IPv4 privée à attribuer au pair (dans la plage `privateIpv4` du serveur) |

Les clés du pair sont gérées selon les paramètres transmis :

| Paramètres transmis | Clés stockées sur le service | `privateKey` dans la réponse | QR code disponible |
|---------------------|------------------------------|------------------------------|--------------------|
| Aucune clé | Paire de clés générée par l'API | Oui | Oui |
| `privateKey` (avec ou sans `publicKey`) | Clé privée fournie et clé publique dérivée de celle-ci (le paramètre `publicKey` est ignoré) | Oui | Oui |
| `publicKey` seule | Clé publique uniquement | Non | Non |

Dès qu'une clé privée est stockée pour le pair, qu'elle ait été générée par l'API ou transmise dans le paramètre `privateKey`, sa configuration complète peut être récupérée sous forme de QR code : consultez la section « [Récupérer le QR code d'un pair](#récupérer-le-qr-code-dun-pair) ».

:::warning
Lorsque la réponse contient la **clé privée** du pair (champ `privateKey`), celle-ci est renvoyée en clair. Ne la partagez pas : toute personne qui la détient peut se connecter à votre service.

:::

:::info
À sa création, un pair est **inactif** par défaut. Pour l'activer, définissez son paramètre `active` sur `true` à l'aide de l'appel `PUT` décrit dans la section « [Modifier un pair](#modifier-un-pair) ».

:::


#### Consulter un pair

<Api version="v1" section="/overTheBox" method="GET" route={"/overTheBox/\{serviceName\}/wireguard/peers/\{peerId\}"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |
| `peerId` | Oui | L'identifiant du pair |

Si le pair dispose d'une clé privée stockée, la réponse inclut le champ `privateKey`.

#### Récupérer le QR code d'un pair

Cette opération renvoie la configuration WireGuard complète d'un pair, encodée dans un QR code. Scannez ce QR code avec l'application WireGuard officielle pour importer la configuration du client en une seule étape.

<Api version="v1" section="/overTheBox" method="GET" route={"/overTheBox/\{serviceName\}/wireguard/peers/\{peerId\}/qrcode"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |
| `peerId` | Oui | L'identifiant du pair |

La réponse contient un champ `qrcode` : une image PNG encodée en base64. Collez sa valeur ci-dessous pour afficher le QR code. Le décodage est effectué localement dans votre navigateur : la valeur n'est transmise à aucun serveur.

<QRCodeViewer />

Le QR code contient la configuration complète du client :

- **Section `[Interface]`** : la clé privée du pair, son adresse IPv4 privée (au format CIDR) et, si un port est défini pour le pair, son port d'écoute (`ListenPort`).
- **Section `[Peer]`** : la clé publique du serveur WireGuard, `AllowedIPs = 0.0.0.0/0` (tout le trafic du client transite par le tunnel) et, si l'adresse IPv4 publique du service est disponible, le point de terminaison du serveur (`Endpoint`) accompagné de `PersistentKeepalive = 25`.

:::info
Le QR code ne peut être généré que si le pair est **actif** (`active: true`) et dispose d'une **clé privée stockée** sur votre service. Dans le cas contraire, l'appel renvoie une erreur `409`. C'est notamment le cas :

- tant que la tâche d'activation ou de [régénération des clés](#régénérer-les-clés-dun-pair) du pair n'est pas terminée ;
- pour un pair déclaré avec sa seule clé publique : [régénérez ses clés](#régénérer-les-clés-dun-pair) pour pouvoir obtenir son QR code.

:::

:::warning
Si l'adresse IPv4 publique du service n'est pas disponible, la configuration ne comporte pas de point de terminaison (`Endpoint`). Ajoutez-le manuellement dans le client après l'import, au format `endpoint.ipv4:endpoint.port` (voir la section « [Récupérer la configuration du serveur WireGuard](#récupérer-la-configuration-du-serveur-wireguard) »).

:::

Pour une procédure pas à pas côté client, consultez le guide « [Comment configurer un client WireGuard](/guides/web-cloud/internet/overthebox/config-wireguard-client) ».

#### Modifier un pair

<Api version="v1" section="/overTheBox" method="PUT" route={"/overTheBox/\{serviceName\}/wireguard/peers/\{peerId\}"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |
| `peerId` | Oui | L'identifiant du pair |
| `name` |  | Un nom pour identifier le pair |
| `description` |  | Une description du pair |
| `privateKey` |  | La clé privée WireGuard du client (la clé publique en est dérivée automatiquement et le paramètre `publicKey` est ignoré) |
| `publicKey` |  | La clé publique WireGuard du client |
| `privateIpv4` |  | L'adresse IPv4 privée attribuée au pair |
| `active` |  | Active (`true`) ou désactive (`false`) le pair |

Seuls les paramètres transmis sont modifiés. Les modifications sont appliquées sur votre OverTheBox par une tâche asynchrone.

:::warning
Si vous transmettez le paramètre `publicKey` **sans** `privateKey`, la clé privée stockée pour ce pair est **effacée** : son [QR code](#récupérer-le-qr-code-dun-pair) ne pourra plus être généré.

:::

#### Supprimer un pair

<Api version="v1" section="/overTheBox" method="DELETE" route={"/overTheBox/\{serviceName\}/wireguard/peers/\{peerId\}"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |
| `peerId` | Oui | L'identifiant du pair |

#### Régénérer les clés d'un pair

Cette opération génère une nouvelle paire de clés (privée / publique) pour un pair existant et la stocke sur votre service. Elle permet de renouveler les clés d'un client, ou d'obtenir le QR code d'un pair déclaré avec sa seule clé publique.

<Api version="v1" section="/overTheBox" method="POST" route={"/overTheBox/\{serviceName\}/wireguard/peers/\{peerId\}/regenerate"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |
| `peerId` | Oui | L'identifiant du pair |

:::warning
Les anciennes clés du pair cessent d'être valides : le client configuré avec celles-ci ne peut plus se connecter. Si le pair est actif, votre OverTheBox redémarre son service WireGuard pour appliquer les nouvelles clés, ce qui peut entraîner une courte interruption pour les clients connectés.

Tout QR code récupéré précédemment devient invalide. Une fois la tâche terminée, [récupérez le nouveau QR code](#récupérer-le-qr-code-dun-pair) et importez-le dans le client.

:::

### Régénérer la configuration WireGuard

Cette opération régénère les clés du serveur WireGuard :

<Api version="v1" section="/overTheBox" method="POST" route={"/overTheBox/\{serviceName\}/wireguard/regenerate"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |

:::warning
La régénération modifie la clé publique du serveur. Vous devrez mettre à jour la configuration de tous vos clients WireGuard pour rétablir la connexion, par exemple en important à nouveau leur [QR code](#récupérer-le-qr-code-dun-pair).

:::


### Réinitialiser la configuration WireGuard

Cette opération réinitialise la configuration WireGuard du service :

<Api version="v1" section="/overTheBox" method="POST" route={"/overTheBox/\{serviceName\}/wireguard/reset"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |

:::warning
La réinitialisation est une opération destructive : elle supprime les pairs configurés et restaure la configuration WireGuard par défaut.

:::
