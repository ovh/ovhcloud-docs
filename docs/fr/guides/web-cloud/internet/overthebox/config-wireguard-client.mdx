## Objectif

Lorsque votre service OverTheBox fonctionne en mode WireGuard<sup>1</sup>, chaque équipement à connecter doit être configuré comme un client WireGuard.

**Ce guide vous explique comment configurer un client WireGuard pour vous connecter à votre service OverTheBox.**

:::warning
Le mode **WireGuard** d'OverTheBox est actuellement en phase **bêta**. L'IPv6 n'est pas disponible et un service ne peut pas fonctionner en mode OverTheBox et WireGuard en même temps.

:::

## Prérequis

- Disposer d'un service OverTheBox basculé en mode **WireGuard** (consultez le guide « [Comment configurer WireGuard sur OverTheBox](/guides/web-cloud/internet/overthebox/config-wireguard) »).
- Consulter notre guide « [Premiers pas avec les API OVHcloud](/guides/manage-and-operate/api/first-steps) » afin de vous familiariser avec l'APIv6 OVHcloud.
- Avoir installé l'application **WireGuard** officielle sur votre équipement, disponible sur le [Google Play Store](https://play.google.com/store/apps/details?id=com.wireguard.android) (Android) et l'[App Store](https://apps.apple.com/fr/app/wireguard/id1441195209) (iOS).

## En pratique

La configuration d'un client repose sur un échange d'informations entre l'application WireGuard et votre service OverTheBox. Deux méthodes sont possibles :

- **[Import par QR code](#méthode-1--importer-la-configuration-par-qr-code)** (recommandé) : l'API génère la paire de clés du client et vous fournit sa configuration complète sous forme de QR code, à scanner avec l'application WireGuard.
- **[Configuration manuelle](#méthode-2--configurer-le-client-manuellement)** : l'application WireGuard génère la paire de clés, vous déclarez la clé publique du client sur votre service, puis vous saisissez vous-même la configuration du serveur dans l'application.

Tous les appels API de ce guide sont disponibles dans la <ApiLink section="/overTheBox">section */overTheBox*</ApiLink> de la console API.

### Méthode 1 : importer la configuration par QR code

#### Étape 1 : créer le pair

Déclarez le client comme pair sur votre service. Pour que le QR code puisse être généré, une clé privée doit être stockée pour ce pair :

- **sans transmettre de clé**, l'API génère automatiquement une paire de clés pour ce client ;
- **en transmettant la clé privée** du client (paramètre `privateKey`), celle-ci est stockée et la clé publique en est dérivée automatiquement.

<Api version="v1" section="/overTheBox" method="POST" route={"/overTheBox/\{serviceName\}/wireguard/peers"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |
| `name` | Oui | Un nom pour identifier le client |
| `description` | Oui | Une description du client |
| `privateKey` | Non | La **clé privée** du client. Si ce paramètre est absent, l'API génère une paire de clés |
| `privateIpv4` | Oui | L'adresse IPv4 privée attribuée au client, comprise dans la plage `privateIpv4` du serveur (voir l'[étape 1 de la méthode 2](#étape-1--récupérer-les-informations-du-serveur)) |

Notez l'identifiant du pair renvoyé dans la réponse : il vous servira aux étapes suivantes.

:::warning
La réponse contient la **clé privée** du client en clair (champ `privateKey`). Ne la partagez pas : toute personne qui la détient peut se connecter à votre service.

:::

#### Étape 2 : activer le pair

À sa création, un pair est **inactif**. Activez-le en définissant son paramètre `active` sur `true` :

<Api version="v1" section="/overTheBox" method="PUT" route={"/overTheBox/\{serviceName\}/wireguard/peers/\{peerId\}"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |
| `peerId` | Oui | L'identifiant du pair |
| `active` | Oui | `true` pour activer le pair |

L'activation est appliquée sur votre OverTheBox par une tâche asynchrone. Attendez la fin de cette tâche avant de passer à l'étape suivante.

#### Étape 3 : récupérer et scanner le QR code

Récupérez la configuration du pair sous forme de QR code :

<Api version="v1" section="/overTheBox" method="GET" route={"/overTheBox/\{serviceName\}/wireguard/peers/\{peerId\}/qrcode"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |
| `peerId` | Oui | L'identifiant du pair |

La réponse contient un champ `qrcode` : une image PNG encodée en base64. Collez sa valeur ci-dessous pour afficher le QR code. Le décodage est effectué localement dans votre navigateur : la valeur n'est transmise à aucun serveur.

<QRCodeViewer />

Dans l'application **WireGuard**, appuyez sur le bouton <code className="action">+</code>, choisissez l'option de création à partir d'un QR code, puis scannez le QR code affiché. Le tunnel est importé avec sa configuration complète : il ne vous reste qu'à l'activer.

:::info
Le QR code ne peut être généré que si le pair est **actif** et dispose d'une **clé privée stockée** sur votre service. Dans le cas contraire, l'appel renvoie une erreur `409`. Un pair déclaré avec sa seule clé publique (méthode manuelle) n'a pas de clé privée stockée : pour obtenir son QR code, [régénérez ses clés](/guides/web-cloud/internet/overthebox/config-wireguard#régénérer-les-clés-dun-pair).

:::

:::warning
Si l'adresse IPv4 publique de votre service n'est pas disponible, la configuration contenue dans le QR code ne comporte pas de point de terminaison (`Endpoint`). Après l'import, ajoutez-le manuellement dans la section **Pair** du tunnel, au format `ipv4:port` (voir l'[étape 1 de la méthode 2](#étape-1--récupérer-les-informations-du-serveur)).

:::

### Méthode 2 : configurer le client manuellement

La procédure détaillée ci-dessous porte sur l'application mobile, mais le principe (échange de clés et déclaration du pair via l'API) reste identique pour un client sur ordinateur ou routeur.

#### Étape 1 : récupérer les informations du serveur

Récupérez la configuration du serveur WireGuard de votre service :

<Api version="v1" section="/overTheBox" method="GET" route={"/overTheBox/\{serviceName\}/wireguard"} />


Les champs suivants sont nécessaires pour configurer votre client :

| Champ de l'API | Utilisation dans le client WireGuard |
|----------------|--------------------------------------|
| `publicKey` | Clé publique du **pair** (le serveur OverTheBox) |
| `endpoint.ipv4` et `endpoint.port` | Point de terminaison du pair, au format `ipv4:port` |
| `privateIpv4` | Plage d'adresses privées du serveur : choisissez-y une adresse libre à attribuer à votre client |

#### Étape 2 : configurer le tunnel dans l'application WireGuard

Créez le tunnel dans l'application, sans l'activer pour l'instant : le pair doit d'abord être déclaré et activé sur votre service.

    - **Adresses IP autorisées** : `0.0.0.0/0` pour faire transiter l'ensemble de votre trafic par le service.
    - **Maintien de connexion permanente** : `30` secondes (recommandé pour maintenir le tunnel actif).

4. Enregistrez le tunnel à l'aide du bouton en haut à droite.

#### Étape 3 : déclarer votre client comme pair

Déclarez le client sur votre service en transmettant la **clé publique** affichée dans l'application (ou la **clé privée**, voir l'astuce ci-dessous) :

<Api version="v1" section="/overTheBox" method="POST" route={"/overTheBox/\{serviceName\}/wireguard/peers"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |
| `name` | Oui | Un nom pour identifier le client |
| `description` | Oui | Une description du client |
| `publicKey` | Non | La **clé publique** générée par l'application WireGuard du client (ignorée si `privateKey` est fournie) |
| `privateKey` | Non | La **clé privée** générée par l'application WireGuard du client (la clé publique en est dérivée automatiquement) |
| `privateIpv4` | Oui | L'adresse IPv4 privée attribuée au client (comprise dans la plage `privateIpv4` du serveur) |

:::tip
Si vous transmettez la **clé privée** du client (paramètre `privateKey`), elle est stockée sur votre service : vous pourrez ainsi récupérer plus tard la configuration du client sous forme de [QR code](#étape-3--récupérer-et-scanner-le-qr-code), par exemple pour l'installer sur un autre équipement. Si vous ne transmettez que la clé publique, aucune clé privée n'est stockée et le QR code n'est pas disponible.

:::

#### Étape 4 : activer le pair

À sa création, un pair est **inactif**. Activez-le en définissant son paramètre `active` sur `true` :

<Api version="v1" section="/overTheBox" method="PUT" route={"/overTheBox/\{serviceName\}/wireguard/peers/\{peerId\}"} />


| Paramètre | Obligatoire | Description |
|-----------|----------|-------------|
| `serviceName` | Oui | Le nom interne de votre service OverTheBox |
| `peerId` | Oui | L'identifiant du pair, renvoyé à l'étape précédente |
| `active` | Oui | `true` pour activer le pair |

L'activation est appliquée sur votre OverTheBox par une tâche asynchrone. Attendez la fin de cette tâche avant de passer à l'étape suivante.

#### Étape 5 : activer le tunnel

Dans l'application **WireGuard**, activez le tunnel créé à l'[étape 2](#étape-2--configurer-le-tunnel-dans-lapplication-wireguard) pour établir la connexion.
