## Objectif

Le S/MIME apporte deux garanties à vos e-mails Exchange, grâce à un certificat personnel :

- **Le chiffrement** garantit que seul le destinataire autorisé peut lire le contenu du message. Si l'e-mail est intercepté pendant son acheminement, ou si une personne non autorisée y accède, son contenu reste illisible.
- **La signature numérique** garantit l'identité de l'expéditeur et l'intégrité du message. Elle assure que l'e-mail a bien été envoyé par l'expéditeur attendu et que son contenu n'a pas été modifié entre son envoi et sa réception.

Les deux sont indépendants : un e-mail peut être signé, chiffré, ou les deux.

Le S/MIME repose sur un **certificat propre à chaque utilisateur**, contenant une clé publique et une clé privée. OVHcloud n'émet pas de certificats S/MIME : vous commandez le vôtre auprès d'une autorité de certification (Sectigo, par exemple) pour l'adresse e-mail principale de votre compte Exchange.

**Ce guide explique comment publier votre certificat S/MIME, puis comment signer et chiffrer vos e-mails dans Outlook, dans le webmail OWA et sur mobile.**

## Prérequis

- Un service [Hosted Exchange](/links/web/emails-hosted-exchange), [Private Exchange](/links/web/emails-private-exchange) ou [Trusted Exchange](/links/web/emails-trusted-exchange)
- Un certificat S/MIME émis pour l'**adresse e-mail principale** de votre compte Exchange
- Outlook pour Windows installé et [configuré avec votre compte Exchange](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/how-to-configure-outlook-2016)
- Pour chiffrer un e-mail : le certificat de chaque destinataire (voir [Comment fonctionne le chiffrement](#how-encryption-works))

:::warning
**Commencez par Outlook, quel que soit le client que vous prévoyez d'utiliser.** La publication de votre certificat dans l'organisation Exchange ne peut se faire que depuis Outlook pour Windows. Tant qu'elle n'est pas faite, les autres utilisateurs de votre organisation ne peuvent ni chiffrer les e-mails qui vous sont adressés, ni vérifier vos signatures — et les autres clients (OWA, iOS, Android) ne peuvent pas être utilisés pour le S/MIME.

:::

## En pratique

### Étape 1 : publier son certificat depuis Outlook

La publication de votre certificat le rend accessible au sein de votre organisation Exchange. Les autres utilisateurs le récupèrent alors automatiquement pour chiffrer les e-mails qu'ils vous adressent et pour vérifier la signature numérique des messages que vous leur envoyez. Une fois cette étape faite, vous pouvez utiliser les autres clients de messagerie.

## Fonctionnement

### Comment fonctionne le chiffrement <a name="how-encryption-works"></a>

Chaque utilisateur possède un certificat contenant une clé publique et une clé privée. Lors de l'envoi d'un e-mail chiffré :

1. Le client de messagerie récupère le certificat du destinataire, et donc sa clé publique.
2. Le message est chiffré avec cette clé publique.
3. Une fois chiffré, le message devient illisible pour tout intermédiaire, y compris le serveur Exchange.
4. Seul le destinataire peut le déchiffrer, avec sa clé privée stockée sur son poste.

C'est pour cette raison que vous devez déjà disposer du certificat du destinataire pour chiffrer un e-mail qui lui est adressé.

### Comment fonctionne la signature

1. L'expéditeur utilise sa clé privée pour signer le message.
2. Le client de messagerie calcule une empreinte (hash) du contenu de l'e-mail.
3. Cette empreinte est chiffrée avec la clé privée : cela forme la signature.
4. Le client de messagerie du destinataire vérifie la signature avec la clé publique de l'expéditeur, récupérée via son certificat publié dans l'organisation Exchange.

Toute modification du message invalide la signature.

## Limitations

- Pour chiffrer un e-mail, vous devez déjà disposer du certificat du destinataire.
- La perte du poste ou des certificats entraîne la **perte d'accès aux e-mails chiffrés** en l'absence de sauvegarde. Conservez une copie de sauvegarde de votre certificat en lieu sûr.
- Le S/MIME est moins adapté aux usages multi-clients, web et mobiles sans configuration spécifique sur chaque client.
- Si une règle de transport modifie le corps de l'e-mail, l'e-mail signé est présenté comme une pièce jointe dans l'Outlook du destinataire.
