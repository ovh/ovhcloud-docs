## Objectif

Il peut arriver qu'Outlook affiche en boucle une fenêtre de connexion Microsoft 365 qui demande vos identifiants, parfois accompagnée du message « Indiquez le compte à utiliser pour ouvrir autodiscover.xml ». Cette fenêtre peut réapparaître même après le redémarrage d'Outlook ou la création d'un nouveau profil. Pourtant, la boîte mail concernée n'est pas hébergée dans le cloud Microsoft : elle se trouve sur une solution Exchange OVHcloud (Hosted Exchange ou Exchange dédié).

Ce comportement provient d'une fonctionnalité d'Outlook appelée « Direct Connect to Office 365 », qui force le client à interroger l'autodiscover d'Office 365 et court-circuite celui de votre serveur Exchange OVHcloud.

**Ce guide vous explique comment identifier l'origine de ces demandes de connexion répétées et empêcher Outlook de se connecter à Office 365.**

## Prérequis

- Disposer d'une [solution Exchange OVHcloud](/links/web/emails-hosted-exchange) déjà installée.
- Disposer de l'application [Outlook classique](https://support.microsoft.com/fr-FR/Outlook/install-or-reinstall-classic-outlook-on-a-windows-pc) (Outlook 2016, 2019, 2021 ou Microsoft 365) sur Windows.
- Disposer d'un accès administrateur au poste client pour modifier le registre Windows.
- L'enregistrement SRV OVHcloud doit être correctement configuré dans la zone DNS du nom de domaine. Consultez notre guide « [Ajouter un nom de domaine sur son service Exchange](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-adding-domain) ».

## En pratique

### Comprendre le problème

Microsoft a introduit dans Outlook une fonctionnalité appelée « Direct Connect to Office 365 ». Lorsqu'elle est active, Outlook se connecte directement à l'autodiscover d'Office 365 et ignore l'URL d'autodiscover de votre serveur Exchange.

Ce serveur peut être un Exchange installé dans les locaux de votre entreprise (on-premises) ou une solution Hosted Exchange OVHcloud. **Une solution Hosted Exchange n'est pas hébergée sur les serveurs Office 365 / Microsoft 365** : il s'agit d'un serveur Exchange hébergé sur les serveurs OVHcloud.

Outlook interroge alors Office 365 en pensant que la boîte mail se trouve dans le cloud Microsoft, au lieu de vérifier d'abord l'autodiscover du serveur Exchange OVHcloud. C'est ce qui déclenche les fenêtres de connexion Microsoft à répétition.

Lors de l'ajout du compte, cette recherche automatique des paramètres (autodiscover) est visible à l'étape « Recherche des paramètres de votre serveur de messagerie » :

<img className="thumbnail" alt="Assistant Outlook recherchant les paramètres du serveur de messagerie lors de l'ajout d'un compte" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/outlook-connecting-to-office-365/outlook-add-account-searching-settings.png" loading="lazy" />

### Identifier les symptômes

Vous êtes probablement concerné par ce problème si vous constatez les éléments suivants :

- Une fenêtre de connexion Microsoft 365 s'affiche en boucle dans Outlook et redemande sans cesse les identifiants.
- Le message « Indiquez le compte à utiliser pour ouvrir autodiscover.xml » apparaît.

    <img className="thumbnail" alt="Fenêtre de connexion Microsoft 365 dans Outlook demandant le compte pour ouvrir autodiscover.xml" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/outlook-connecting-to-office-365/outlook-office365-signin-prompt.png" loading="lazy" />

- La fenêtre persiste après le redémarrage d'Outlook ou la création d'un nouveau profil Outlook.
- La boîte mail est pourtant bien hébergée sur Exchange OVHcloud et l'autodiscover OVHcloud est correctement configuré.
- Un message d'erreur en rouge « Ce nom d'utilisateur est peut-être incorrect… » peut s'afficher lorsque le compte saisi n'est pas reconnu par le tenant Microsoft 365.

    <img className="thumbnail" alt="Message d'erreur rouge « Ce nom d'utilisateur est peut-être incorrect » dans la fenêtre de connexion Microsoft" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/outlook-connecting-to-office-365/outlook-office365-username-incorrect-error.png" loading="lazy" />

### Vérifier que la boîte mail est bien hébergée sur Exchange OVHcloud

Avant d'appliquer le correctif, vérifiez que la configuration côté OVHcloud est correcte :

- Vérifiez que l'enregistrement SRV `_autodiscover` du nom de domaine pointe vers les serveurs OVHcloud, comme indiqué dans le guide « [Ajouter un nom de domaine sur son service Exchange](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-adding-domain) ».

    <img className="thumbnail" alt="Zone DNS du nom de domaine dans l'espace client OVHcloud avec l'enregistrement SRV _autodiscover" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/outlook-connecting-to-office-365/ovhcloud-manager-dns-zone-srv-autodiscover.png" loading="lazy" />

- Lancez un diagnostic depuis votre espace client pour confirmer l'état du compte, en suivant le guide « [Utilisation du diagnostic d'erreurs Exchange](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/diagnostic-advanced) ».

Si la configuration OVHcloud est correcte mais que les fenêtres de connexion persistent, la cause se situe côté client : Outlook privilégie l'endpoint Office 365.

### Identifier la cause

Ce comportement se déclenche dans 2 situations principales :

- **Le nom de domaine a été déclaré sur un tenant Office 365.** Lorsque vous ajoutez un domaine à un tenant Microsoft 365, Microsoft considère que les boîtes mail de ce domaine se trouvent dans le cloud. Outlook se connecte alors à l'autodiscover Office 365 au lieu de celui d'OVHcloud.
- **Un compte identique a été créé dans Office 365.** Si une boîte mail ou un utilisateur portant la même adresse e-mail (ou le même UPN) existe dans un tenant Microsoft 365, Outlook peut être redirigé vers ce compte cloud plutôt que vers votre compte Exchange OVHcloud.

:::tip
Si vous n'utilisez pas (ou plus) Office 365 pour ce domaine, pensez également à supprimer le domaine ou le compte concerné du tenant Microsoft 365. Le correctif ci-dessous reste toutefois nécessaire tant qu'Outlook continue de privilégier l'endpoint Office 365.
:::

### Appliquer le correctif : la clé de registre `ExcludeExplicitO365Endpoint`

Pour empêcher Outlook d'utiliser l'endpoint explicite Office 365 lors de l'autodiscover, ajoutez une clé de registre sur le poste client.

:::warning
La modification du registre Windows est une opération sensible. Une erreur peut empêcher le système ou des applications de fonctionner correctement. Nous vous recommandons de sauvegarder le registre avant toute modification.
:::

#### Via l'Éditeur du Registre

1. Ouvrez l'**Éditeur du Registre** (`regedit`) dans la session de l'utilisateur concerné sur le poste client.

    <img className="thumbnail" alt="Recherche Windows affichant l'application Éditeur du Registre et l'option Exécuter en tant qu'administrateur" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/outlook-connecting-to-office-365/windows-search-registry-editor-run-as-admin.png" loading="lazy" />

2. Accédez à la clé suivante. Si la sous-clé `AutoDiscover` n'existe pas, créez-la :

```text
HKEY_CURRENT_USER\Software\Microsoft\Office\16.0\Outlook\AutoDiscover
```

Le numéro de version `16.0` correspond à Outlook 2016, 2019, 2021 et Microsoft 365.

3. Créez une nouvelle **valeur DWORD (32 bits)**, nommez-la `ExcludeExplicitO365Endpoint` et attribuez-lui la valeur `1`.
4. Fermez l'Éditeur du Registre.

<img className="thumbnail" alt="Éditeur du Registre Windows affichant la valeur ExcludeExplicitO365Endpoint définie à 1" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/outlook-connecting-to-office-365/registry-editor-exclude-explicit-o365-endpoint.png" loading="lazy" />

#### Via la ligne de commande

Vous pouvez également ajouter la clé en une seule commande dans une invite de commandes :

```bat
reg add HKEY_CURRENT_USER\Software\Microsoft\Office\16.0\Outlook\AutoDiscover /t REG_DWORD /v ExcludeExplicitO365Endpoint /d 1
```

:::warning
Sous Windows 11 avec Office 2024 LTSC (et, plus largement, les versions récentes), la clé `AutoDiscover` ne se trouve plus dans le contexte système mais dans le **contexte de l'utilisateur connecté**. Lancez donc l'Éditeur du Registre (ou l'invite de commandes) avec la session de l'utilisateur concerné, et non en tant qu'administrateur d'un autre compte.
:::

### Vérifier la connexion à Exchange OVHcloud

Démarrez Outlook et vérifiez que la fenêtre de connexion Microsoft 365 n'apparaît plus. Outlook se connecte désormais directement à votre serveur Exchange OVHcloud, et non à Office 365 / Microsoft 365.

Inutile de recréer le profil Outlook après l'ajout de la clé de registre.

Pour confirmer la connexion, ouvrez Outlook classique et observez la **barre d'état** en bas de la fenêtre : elle doit afficher **Connecté à : Microsoft Exchange**. Outlook communique alors avec votre serveur Exchange OVHcloud, et non plus avec Office 365 :

<img className="thumbnail" alt="Interface d'Outlook classique avec la barre d'état affichant « Connecté à : Microsoft Exchange » en bas de la fenêtre" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/outlook-connecting-to-office-365/outlook-classic-status-bar-connected-to-exchange.png" loading="lazy" />

<Region zones={['eu']}>

Pour vérifier le nom exact du serveur (<Tooltip content="Le `?` représente le numéro de votre serveur Exchange OVHcloud (par exemple `ex1`, `ex2`, `ex3`…), qui varie selon l'infrastructure qui héberge votre boîte mail.">`ex?.mail.ovh.net`</Tooltip>), maintenez la touche **Ctrl** enfoncée et faites un clic droit sur l'icône Outlook dans la zone de notification de Windows, puis sélectionnez **État de la connexion**.

</Region>

<Region zones={['ca']}>

Pour vérifier le nom exact du serveur (`ex.mail.ovh.ca`), maintenez la touche **Ctrl** enfoncée et faites un clic droit sur l'icône Outlook dans la zone de notification de Windows, puis sélectionnez **État de la connexion**.

</Region>

:::danger
Si vous prévoyez de migrer ultérieurement des boîtes mail vers Office 365 / Exchange Online, pensez à **supprimer la clé de registre `ExcludeExplicitO365Endpoint`**. Tant qu'elle est présente, elle empêche Outlook de se connecter à Exchange Online.
:::
