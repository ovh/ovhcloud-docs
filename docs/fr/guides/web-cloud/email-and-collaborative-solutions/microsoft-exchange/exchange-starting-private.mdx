## Objectif

Le service Private Exchange met à votre disposition un serveur Exchange dédié pour vos adresses e-mail professionnelles, avec des fonctionnalités collaboratives comme la synchronisation du calendrier et celle des contacts.

Une fois votre commande livrée, le serveur doit être configuré une première fois avant de pouvoir créer des comptes e-mail. Cette configuration s'effectue entièrement depuis l'espace client OVHcloud, en trois temps : le choix de l'adresse de votre serveur de messagerie ([étape 2](#étape-2-choisir-ladresse-de-votre-serveur-de-messagerie)), la validation du nom de domaine qui la porte ([étape 3](#étape-3-valider-lappartenance-de-votre-nom-de-domaine)), puis l'ajout du ou des noms de domaine de vos adresses e-mail ([étape 5](#étape-5-ajouter-votre-nom-de-domaine-et-créer-vos-comptes)).

**Découvrez les premières étapes à réaliser une fois votre serveur Private Exchange livré.**

## Prérequis

- Disposer d'une [solution Private Exchange OVHcloud](https://www.ovhcloud.com/fr/emails/private-exchange/).
- Avoir reçu l'e-mail confirmant la livraison de votre service Private Exchange.
- Disposer d'un nom de domaine dont vous pouvez modifier la zone DNS (géré chez OVHcloud ou hors OVHcloud).

## En pratique

### Étape 1 : réceptionner l'e-mail de livraison

Une fois votre commande traitée, un e-mail est envoyé à l'adresse de contact renseignée dans votre espace client OVHcloud. Il confirme que votre service Private Exchange est disponible et vous invite à le configurer depuis l'espace client OVHcloud.

Pour retrouver cet e-mail depuis l'<ManagerLink to="/">espace client OVHcloud</ManagerLink>, cliquez sur le nom de votre compte en haut à droite, puis sur <code className="action">E-mails de service</code>. Recherchez l'e-mail dont l'objet ressemble à :

> **\[ab12345-ovh] Votre service Private Exchange SE est prêt !**

:::info
Le nom d'un service Private Exchange dans votre espace client OVHcloud commence par **private-**, contient une partie de votre identifiant client (NIC handle) et se termine par un chiffre (1 pour le premier service Private Exchange installé, 2 pour le second, etc.).

:::

À ce stade, le serveur existe mais rien n'est encore utilisable : son adresse n'a pas été choisie et aucun nom de domaine ne lui est associé. Passez à l'[étape 2](#étape-2-choisir-ladresse-de-votre-serveur-de-messagerie).

### Étape 2 : choisir l'adresse de votre serveur de messagerie

Sélectionnez votre service Private Exchange dans l'espace client OVHcloud. Le service n'ayant jamais été configuré, un assistant de configuration s'affiche à la place de la page de gestion habituelle : **Bienvenue dans votre espace Private Exchange**.

Dans la section **Choisissez l'adresse de votre serveur de messagerie**, deux champs sont obligatoires :

- **Votre sous-domaine** : la partie hôte de l'adresse, par exemple `mail`.
- **Votre nom de domaine** : le nom de domaine qui portera l'adresse de votre serveur, par exemple `mydomain.ovh`.

Ensemble, ils forment l'**adresse de votre serveur de messagerie**, par exemple `mail.mydomain.ovh`. Cette adresse sert à :

- l'accès au webmail (Outlook Web App, OWA) ;
- le nom de serveur à renseigner lors de la configuration d'un client de messagerie comme Outlook ;
- le nom couvert par le certificat SSL délivré pour votre serveur.

Le message affiché sous les champs dépend de l'endroit où votre nom de domaine est géré.

<img className="thumbnail" alt="Assistant de configuration avec un nom de domaine géré hors OVHcloud" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-starting-private/private-exchange-welcome-external.png" loading="lazy" />

:::warning
**L'adresse du serveur de messagerie ne peut plus être modifiée une fois confirmée.** Vérifiez soigneusement le sous-domaine et le nom de domaine avant de continuer. Si vous avez besoin d'une autre adresse par la suite, la seule solution est de commander un nouveau service Private Exchange.

:::

Cliquez sur <code className="action">Suivant</code>. Une fenêtre de confirmation affiche l'adresse qui sera attribuée à votre serveur et vous rappelle que cette information ne pourra plus être modifiée par la suite. Cliquez sur <code className="action">Confirmer</code> pour continuer.

### Étape 3 : valider l'appartenance de votre nom de domaine

Cette étape ne concerne que les noms de domaine qui **ne sont pas gérés dans le même espace client OVHcloud** que votre service Private Exchange (nom de domaine géré hors OVHcloud, ou dans un autre espace client OVHcloud).

:::info
**Nom de domaine géré dans le même espace client OVHcloud** : la configuration est automatique et vous n'avez rien à valider. La page décrite ci-dessous peut néanmoins s'afficher quelques instants pendant que la configuration automatique est en cours. **N'ajoutez pas l'enregistrement vous-même : patientez.** La page disparaît d'elle-même une fois l'enregistrement créé et détecté. Vous pouvez alors passer à l'[étape 4](#étape-4-vérifier-que-votre-serveur-est-prêt).

:::

Pour un nom de domaine géré hors OVHcloud ou dans un autre espace client, l'assistant affiche la page **Configuration de votre produit Private Exchange**, avec la section **Validez l'appartenance de votre domaine**. Pour prouver que vous contrôlez le nom de domaine choisi à l'[étape 2](#étape-2-choisir-ladresse-de-votre-serveur-de-messagerie), un enregistrement **CNAME** doit être ajouté dans sa zone DNS. L'enregistrement à créer est affiché sur la page, avec un bouton permettant de le copier.

<img className="thumbnail" alt="Page de validation de l'appartenance du domaine avec l'enregistrement CNAME à ajouter" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-starting-private/private-exchange-cname.png" loading="lazy" />

Copiez l'enregistrement CNAME **avant de quitter la page**, puis créez-le dans la zone DNS de votre nom de domaine, depuis l'interface où vous gérez sa zone DNS.

- Une fois l'enregistrement ajouté, sa détection peut prendre jusqu'à 1 heure. Vous pouvez quitter la page : le processus se poursuit en arrière-plan.
- **Vous disposez de 48 heures pour ajouter l'enregistrement CNAME.** Passé ce délai, la configuration est annulée et vous devez la recommencer depuis le début.

Une fois l'enregistrement CNAME détecté, le serveur est finalisé automatiquement : le certificat SSL est généré pour l'adresse de votre serveur de messagerie et le webmail est activé. Aucun e-mail supplémentaire n'est envoyé à ce stade : vérifiez l'état de votre serveur directement dans l'espace client OVHcloud, comme décrit à l'[étape 4](#étape-4-vérifier-que-votre-serveur-est-prêt).

### Étape 4 : vérifier que votre serveur est prêt

Sélectionnez de nouveau votre service Private Exchange dans l'espace client OVHcloud. L'assistant ne s'affiche plus : vous arrivez sur l'onglet <code className="action">Informations générales</code> du service.

<img className="thumbnail" alt="Onglet Informations générales d'un service Private Exchange après sa première configuration" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-starting-private/private-exchange-general-information.png" loading="lazy" />

Vérifiez les éléments suivants :

- **Diagnostic serveur** (Résumé) : les pastilles `A`, `AAAA`, `PTR` et `PTR v6` indiquent si les enregistrements DNS de l'adresse de votre serveur de messagerie sont corrects. Lorsqu'une pastille n'est pas verte, cliquez dessus pour afficher le détail et les valeurs à configurer.
- **Certificat SSL** (Résumé) : doit être **Actif**, avec sa date d'expiration.
- **Webmail** (Connexion) : le lien vers votre Outlook Web App, de la forme `https://mail.mydomain.ovh`.
- **Domaines associés** (Statistiques) : affiche **0** à ce stade. C'est normal, le nom de domaine de vos adresses e-mail est ajouté à l'[étape 5](#étape-5-ajouter-votre-nom-de-domaine-et-créer-vos-comptes).

Si votre nom de domaine est géré hors OVHcloud ou dans un autre espace client, les pastilles `A` et `AAAA` restent orange tant que vous n'avez pas créé vous-même les enregistrements correspondants. Cliquez sur chaque pastille : le détail indique le type d'enregistrement, le sous-domaine et la valeur cible (l'adresse IPv4 ou IPv6 de votre serveur) à renseigner dans la zone DNS de votre nom de domaine, depuis l'interface où vous gérez sa zone DNS.

<img className="thumbnail" alt="Détail de l'enregistrement A affiché depuis le diagnostic serveur" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-starting-private/private-exchange-diagnostic-a-record.png" loading="lazy" />

:::info
Les enregistrements `PTR` et `PTR v6` (DNS inverse) sont gérés par OVHcloud. Si l'une de ces pastilles signale un problème, vous ne pouvez pas le corriger vous-même : contactez nos équipes support.

:::

### Étape 5 : ajouter votre nom de domaine et créer vos comptes

Votre serveur est prêt, mais vous ne pouvez pas créer de comptes e-mail tant qu'aucun nom de domaine ne lui est associé. Ce nom de domaine est celui qui apparaîtra dans vos adresses e-mail (par exemple `john.smith@mydomain.ovh`). Il peut être identique à celui utilisé pour l'adresse du serveur, ou différent.

Cliquez sur l'onglet <code className="action">Domaines associés</code>, puis sur le bouton <code className="action">Ajouter un domaine</code>, et suivez les étapes décrites dans notre guide « [Ajouter un nom de domaine sur son service Exchange](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-adding-domain) ».

:::warning
À la dernière étape de l'ajout d'un domaine, l'option **Configuration recommandée** achemine **tous les e-mails adressés à votre nom de domaine** vers votre service Private Exchange, **immédiatement**. Si ce nom de domaine reçoit déjà des e-mails sur un autre service (une autre solution e-mail OVHcloud, un service e-mail tiers ou un serveur interne), choisissez **Configuration personnalisée** : elle vous permet de conserver l'autre solution e-mail en parallèle de votre service Private Exchange et de décider du moment de la bascule.

:::

Une fois le nom de domaine ajouté, surveillez la colonne **Diagnostic** du tableau plutôt que la colonne **Statut** : le statut peut être **Ok** alors que les pastilles `MX`, `SRV`, `SPF` ou `DKIM` sont encore rouges. Une pastille rouge signifie qu'un enregistrement DNS est manquant ou incorrect. Cliquez dessus pour afficher la valeur à configurer. Tant que l'enregistrement `MX` n'est pas correct, votre nom de domaine ne reçoit aucun e-mail sur votre service Private Exchange.

- **Nom de domaine géré chez OVHcloud, avec la configuration recommandée** : les enregistrements sont créés pour vous dans la zone DNS. Les pastilles peuvent rester rouges un certain temps, jusqu'à la propagation des modifications (24 heures maximum) : vous n'avez rien à faire.
- **Nom de domaine non géré par votre espace client OVHcloud** : le nom de domaine apparaît d'abord avec le mode **Validation de domaine en cours** et le statut **Confirmation**, avec une pastille `CNAME` rouge dans la colonne **Diagnostic**. Vous devez prouver que vous en êtes propriétaire : cliquez sur la pastille `CNAME` pour afficher l'enregistrement à créer dans la zone DNS de votre nom de domaine (de la forme `xxxxx-check.mydomain.ovh` pointant vers `ovh.com`). **Vous disposez de 48 heures pour le faire.** Une fois le nom de domaine validé, créez vous-même les enregistrements de messagerie à partir des valeurs affichées dans la colonne **Diagnostic**. Consultez notre guide « [Créer un enregistrement CNAME pour valider son nom de domaine sur sa solution e-mail](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-dns-cname) ».

Vous pouvez ensuite créer vos premiers comptes e-mail depuis l'onglet <code className="action">Comptes e-mail</code>.

### Renouveler le certificat SSL

Le certificat SSL délivré pour l'adresse de votre serveur de messagerie a une durée de validité limitée. Sa date d'expiration est affichée sous **Certificat SSL**, dans le **Résumé** de l'onglet <code className="action">Informations générales</code>. À l'approche de la date d'expiration, ou une fois celle-ci dépassée, un message vous invite à renouveler le certificat. N'attendez pas son expiration : avec un certificat expiré, le webmail et les clients de messagerie affichent des avertissements de sécurité.

<img className="thumbnail" alt="Certificat SSL expiré avec l'option de renouvellement" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-starting-private/private-exchange-ssl-expired.png" loading="lazy" />

1. Cliquez sur le bouton <code className="action">...</code> à côté du message, puis sur <code className="action">Renouveler le certificat SSL</code>.
2. Dans la fenêtre **Renouvellement de certificat SSL**, sélectionnez l'adresse e-mail qui recevra la confirmation du renouvellement. Seules les adresses d'administration de vos noms de domaine sont proposées, comme `admin@`, `administrator@` ou `hostmaster@`, suivies de votre nom de domaine ou de l'adresse de votre serveur de messagerie. **L'adresse sélectionnée doit exister** : si aucune d'elles n'existe, créez le compte e-mail correspondant (ou un alias vers un compte existant) avant de continuer.
3. Cliquez sur <code className="action">Suivant</code>. Vérifiez les informations affichées (modèle de serveur, adresse du serveur et e-mail de confirmation), puis cliquez sur <code className="action">Confirmer</code>.

<img className="thumbnail" alt="Fenêtre de renouvellement du certificat SSL, choix de l'adresse e-mail de confirmation" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-starting-private/private-exchange-ssl-renewal.png" loading="lazy" />

:::warning
Vous devez pouvoir lire les e-mails reçus à l'adresse sélectionnée : une fois le renouvellement pris en compte, un e-mail décrivant les prochaines étapes y est envoyé. Sans cet e-mail, le renouvellement ne peut pas aboutir.

:::

Une fois la confirmation effectuée, un message en haut de la page confirme la prise en compte du renouvellement et vous rappelle l'adresse e-mail à laquelle les prochaines étapes ont été envoyées. Pendant ce temps, la section **Certificat SSL** indique que le certificat est en cours d'installation et ne peut pas être renouvelé de nouveau. Suivez les instructions de l'e-mail reçu : la nouvelle date d'expiration s'affiche une fois le certificat installé.
