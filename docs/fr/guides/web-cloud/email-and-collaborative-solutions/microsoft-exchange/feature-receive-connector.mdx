## Objectif

Un connecteur de réception indique à votre plateforme Exchange quels serveurs sont autorisés à lui remettre des e-mails, et à quelles conditions. Il sert à placer une solution antispam externe, aussi appelée passerelle de filtrage, devant votre plateforme Exchange : les <Tooltip term="mxRecord">enregistrements MX</Tooltip> de votre nom de domaine pointent vers cette passerelle, qui filtre les e-mails entrants puis les transmet à Exchange.

Le connecteur de réception est disponible pour [Private Exchange](/links/web/emails-private-exchange) et [Trusted Exchange](/links/web/emails-trusted-exchange). Il se crée et se gère uniquement avec l'API OVHcloud.

**Ce guide vous explique comment créer, modifier, désactiver et supprimer un connecteur de réception sur votre plateforme Exchange avec l'API OVHcloud.**

:::info
Pour faire passer les e-mails **sortants** de votre plateforme par un serveur externe, utilisez plutôt un connecteur d'envoi : consultez notre guide « [Exchange - Configurer un connecteur d'envoi](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/feature-send-connector) ».
:::

## Prérequis

- Disposer d'une plateforme [Private Exchange](/links/web/emails-private-exchange) ou [Trusted Exchange](/links/web/emails-trusted-exchange).
- Disposer d'identifiants API créés sur la <CreateToken rights="GET=/email/exchange&GET=/email/exchange/*&POST=/email/exchange/*&PUT=/email/exchange/*&PATCH=/email/exchange/*&DELETE=/email/exchange/*">page de génération de tokens OVHcloud</CreateToken>, avec au minimum le droit `GET` sur `/email/exchange` et les droits `GET`, `POST`, `PUT`, `PATCH` et `DELETE` sur `/email/exchange/*`. Consultez notre guide « [Premiers pas avec les API OVHcloud](/guides/manage-and-operate/api/first-steps) ».
- Connaître les adresses IP des serveurs de votre solution antispam externe qui remettront les e-mails à Exchange. Demandez-les au prestataire de cette solution.

## En pratique

### Comprendre le connecteur de réception par défaut

Chaque plateforme Exchange dispose d'un connecteur de réception par défaut. Il appartient à Exchange : vous ne pouvez ni le modifier ni le supprimer, seulement l'activer ou le désactiver. Dans l'API, sa propriété `default` vaut `true`.

:::warning
**Ne désactivez pas le connecteur de réception par défaut.** Si aucun autre connecteur ne s'applique, sa désactivation coupe la réception de tous les e-mails de la plateforme.
:::

### Trouver les paramètres de chemin

Les appels du connecteur de réception ont besoin du nom de l'organisation (`organizationName`) et du nom du service (`exchangeService`) de votre plateforme. Récupérez-les dans l'ordre : le premier appel ci-dessous fournit l'organisation, nécessaire au second.

**1. Organisation** (`organizationName`)

Listez les organisations Exchange de votre compte avec l'appel API ci-dessous :

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange"} />

**2. Service** (`exchangeService`)

Listez les services Exchange de l'organisation avec l'appel API ci-dessous :

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service"} />

### Créer un connecteur de réception

Créez le connecteur avec l'appel API ci-dessous :

<Api version="v1" section="/email/exchange" method="POST" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector"} regions={["eu"]} />

Renseignez les champs suivants dans le corps de la requête. Tous sont obligatoires.

| Champ | Type | Description |
|---|---|---|
| `name` | string | Nom du connecteur, 255 caractères au maximum |
| `remoteIpRanges` | string[] | Adresses IP des serveurs autorisés à remettre des e-mails par ce connecteur (voir ci-dessous) |
| `requireTls` | boolean | `true` pour exiger TLS pour tous les e-mails reçus par ce connecteur |
| `maxMessageSize` | long | Taille maximale d'un e-mail reçu par ce connecteur, en Mo |
| `enabled` | boolean | `true` pour activer le connecteur dès sa création |

Chaque entrée de `remoteIpRanges` peut être :

- une adresse IP seule, par exemple `203.0.113.10` ;
- un réseau en notation CIDR, par exemple `203.0.113.0/28` ;
- une plage d'adresses « début-fin », bornes incluses, par exemple `203.0.113.10-203.0.113.20`.

Les adresses IPv4 et IPv6 sont acceptées.

:::warning
**Limites de `remoteIpRanges`**

- Une même adresse IP ne peut pas figurer dans deux connecteurs de réception de la plateforme.
- La liste complète, une fois ses entrées jointes par des virgules, ne doit pas dépasser 255 caractères. Préférez un réseau CIDR à une longue liste d'adresses seules.

:::

L'appel renvoie une tâche : le connecteur est créé une fois cette tâche terminée.

### Lister et consulter les connecteurs de réception

Listez les connecteurs de réception de la plateforme, connecteur par défaut compris, avec l'appel API ci-dessous :

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector"} regions={["eu"]} />

L'appel renvoie la liste des identifiants (`id`) des connecteurs. Consultez le détail d'un connecteur avec l'appel API ci-dessous :

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

En plus des champs de création, la réponse contient `id`, l'identifiant du connecteur, et `default`, qui vaut `true` pour le connecteur de réception par défaut.

### Modifier un connecteur de réception

Pour modifier un ou plusieurs champs sans toucher aux autres, utilisez l'appel API ci-dessous :

<Api version="v1" section="/email/exchange" method="PATCH" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

Pour remplacer toute la configuration du connecteur, renseignez tous les champs dans l'appel API ci-dessous :

<Api version="v1" section="/email/exchange" method="PUT" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

:::info
Le champ `remoteIpRanges` remplace la liste enregistrée dans son ensemble. Pour ajouter une adresse IP, renvoyez la liste complète : les adresses existantes et la nouvelle.
:::

Pour activer ou désactiver un connecteur, modifiez son champ `enabled`. Sur le connecteur de réception par défaut, c'est le seul champ que vous pouvez modifier : consultez l'avertissement de la section « [Comprendre le connecteur de réception par défaut](#comprendre-le-connecteur-de-réception-par-défaut) ».

Chaque modification renvoie une tâche : elle s'applique une fois cette tâche terminée.

### Supprimer un connecteur de réception

Supprimez un connecteur avec l'appel API ci-dessous :

<Api version="v1" section="/email/exchange" method="DELETE" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

L'appel renvoie une tâche : le connecteur est supprimé une fois cette tâche terminée. Vous ne pouvez pas supprimer le connecteur de réception par défaut.
