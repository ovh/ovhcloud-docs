## Objectif

Le **Model Context Protocol** (MCP) est un standard ouvert qui permet à un assistant IA d’utiliser des outils externes. Le serveur MCP d’OVHcloud expose vos services OVHcloud sous forme d’outils, afin qu’un assistant puisse consulter et modifier votre configuration pour vous.

Concrètement, vous n’avez plus besoin de naviguer dans une interface ni d’écrire des appels API : vous demandez simplement :

```text
Liste mes noms de domaine et indique-moi lesquels expirent dans les 60 prochains jours.
```

**Ce guide vous explique comment connecter un agent IA au serveur MCP d’OVHcloud et l’utiliser pour gérer vos noms de domaine, vos enregistrements DNS et vos redirections.**

## Prérequis

- Être connecté à votre <ManagerLink to="/">espace client OVHcloud</ManagerLink>
- Avoir installé un client MCP compatible (voir [Connecter votre agent](#3--connecter-votre-agent-à-mcp))
- Disposer d’un navigateur, pour réaliser l’étape de connexion OAuth2

## En pratique

### 1 — Le fonctionnement de MCP

Trois éléments interviennent :

| Élément | Rôle |
|---------|------|
| **Votre agent IA** | L’assistant auquel vous parlez (agent en terminal, chat intégré à un IDE, votre propre application) |
| **Le serveur MCP d’OVHcloud** | Publie les *outils* disponibles et les exécute sur votre compte |
| **Votre compte OVHcloud** | Les droits, vérifiés à chaque appel, qui déterminent ce que l’agent peut faire |

Vous n’appelez jamais un outil par son nom. Vous décrivez votre besoin, l’agent sélectionne l’outil correspondant, et il vous demande confirmation avant toute modification.

:::warning
Un agent IA connecté à MCP agit avec **vos** droits. Lisez chaque demande de confirmation avant de l’accepter, en particulier pour les opérations qui suppriment des enregistrements ou modifient des serveurs DNS.
:::

### 2 — Le hub MCP d’OVHcloud

Le [hub MCP d’OVHcloud](https://mcp.eu.ovhcloud.com/index.html) recense les services exposés sous forme d’outils MCP. C’est la référence pour savoir ce qui est disponible.

Choisissez l’URL correspondant à la région de votre compte OVHcloud :

| Région | URL du serveur MCP |
|--------|--------------------|
| Europe | `https://mcp.eu.ovhcloud.com/mcp/{section}` |
| Canada | `https://mcp.ca.ovhcloud.com/mcp/{section}` |

`{section}` est à remplacer par le nom de la section à laquelle vous souhaitez vous connecter, tel qu’il apparaît sur les cartes du hub. Vous vous connectez toujours à une section précise : il n’existe pas d’URL globale exposant l’ensemble des outils.

#### Sections pour les noms de domaine

Deux sections couvrent les noms de domaine, une par version d’API :

| Section | Contenu exposé |
|---------|----------------|
| `v1_domain` | Les outils domaine de l’API v1 |
| `v2_domain` | Les outils domaine de l’API v2 |

L’URL à utiliser est donc `https://mcp.eu.ovhcloud.com/mcp/v1_domain` pour un compte européen sur l’API v1.

À ce jour, l’API v1 reste la plus complète en termes de fonctionnalités : `v1_domain` expose donc un jeu d’outils plus large que `v2_domain`. L’API v2 s’enrichit progressivement.

Pour comprendre ce qui distingue l’API v1 de l’API v2, consultez le guide « [API v2 OVHcloud - Principes de fonctionnement](/guides/manage-and-operate/api/apiv2#vision-as-code) ».

Vous pouvez ajouter l’une, l’autre, ou les deux simultanément. `v1_domain` seule suffit à réaliser toutes les opérations de ce guide.

### 3 — Connecter votre agent à MCP

L’authentification repose sur **OAuth2** : au premier contact de votre agent avec le serveur, une fenêtre de navigateur s’ouvre sur la page de connexion OVHcloud. Une fois que vous êtes connecté, l’agent réutilise cette session pour ses appels MCP.

:::info
Aucun en-tête HTTP personnalisé n’est nécessaire : le flux OAuth2 fournit les identifiants. Les instructions de configuration d’OVHcloud précisent de laisser **vide** la section des en-têtes de votre configuration client.
:::

<Tabs>
<Tab label="SHAI">

[SHAI](https://github.com/ovh/shai) est l’agent en terminal d’OVHcloud. La version **0.1.5 ou supérieure** est requise.

Créez le fichier de configuration suivant, à partir du [modèle `.ovh.config`](https://github.com/ovh/shai/blob/main/.ovh.config) disponible dans le dépôt SHAI :

```bash
$HOME/.config/shai/agents/ovh.config
```

Déclarez sous `tools.mcp` une entrée par section que vous souhaitez utiliser. Cet exemple active les deux versions de l’API :

```json
{
  "name": "ovh",
  "description": "OVH agent with OVH MCP server for cloud management and API calls",
  "tools": {
    "builtin": ["*"],
    "builtin_excluded": [],
    "mcp": {
      "v1_domain": {
        "config": {
          "type": "http",
          "url": "https://mcp.eu.ovhcloud.com/mcp/v1_domain"
        },
        "enabled_tools": ["*"]
      },
      "v2_domain": {
        "config": {
          "type": "http",
          "url": "https://mcp.eu.ovhcloud.com/mcp/v2_domain"
        },
        "enabled_tools": ["*"]
      }
    }
  },
  "system_prompt": "{{CODER_BASE_PROMPT}}",
  "max_tokens": 4096,
  "temperature": 0.3
}
```

Remplacez les points d’accès par ceux de votre région.

:::info
N’ajoutez aucun identifiant dans ce fichier à la main. Après votre connexion, SHAI y inscrit lui-même un `access_token` et un `expires_at` dans le bloc `config` de chaque serveur. Ces valeurs sont des secrets personnels : ne versionnez jamais ce fichier et ne le partagez pas en l’état.
:::

Démarrez ensuite l’agent. Votre navigateur s’ouvre sur la page de connexion OVHcloud : identifiez-vous pour finaliser la connexion.

</Tab>
<Tab label="Goose">

Le plus rapide est de passer par le [hub MCP d’OVHcloud](https://mcp.eu.ovhcloud.com/index.html) : repérez la carte **V1 Domain** (ou **V2 Domain**) et cliquez sur le bouton **Add in Goose**. Goose s’ouvre avec l’extension déjà pré-remplie, nom, point d’accès et transport. Il ne reste qu’à confirmer l’ajout.

Le bouton utilise le point d’accès du hub que vous consultez. Depuis le hub européen, il configure donc l’extension sur `https://mcp.eu.ovhcloud.com` : pour un compte au Canada, ouvrez le hub de votre région ou suivez la configuration manuelle ci-dessous.

**Configuration manuelle.** Dans Goose, ajoutez une nouvelle extension de type **HTTP**, puis renseignez :

- **URL** : l’URL de votre région avec la section souhaitée, `https://mcp.eu.ovhcloud.com/mcp/v1_domain` ou `https://mcp.eu.ovhcloud.com/mcp/v2_domain`
- **En-têtes** : laissez vide

Enregistrez l’extension. Goose ouvre votre navigateur pour la connexion OVHcloud.

Pour utiliser les deux versions d’API, créez une seconde extension avec l’autre section.

</Tab>
<Tab label="Claude Code">

Ajoutez un serveur par section, avec l’URL de votre région :

```bash
claude mcp add --transport http v1_domain https://mcp.eu.ovhcloud.com/mcp/v1_domain
claude mcp add --transport http v2_domain https://mcp.eu.ovhcloud.com/mcp/v2_domain
```

La première commande suffit pour toutes les opérations de ce guide. Ajoutez `--scope user` pour rendre un serveur disponible dans tous vos projets, et non uniquement dans le projet courant. Ne renseignez aucune option `--header`.

Puis, depuis Claude Code, lancez la connexion OAuth2 :

```text
/mcp
```

Identifiez-vous auprès d’OVHcloud dans la fenêtre de navigateur qui s’ouvre. `claude mcp list` affiche alors `✔ Connected` en face de chaque serveur ajouté.

</Tab>
</Tabs>

Pour vérifier que la connexion fonctionne, posez à votre agent une question en lecture seule :

```text
Liste mes noms de domaine OVHcloud.
```

### 4 — Afficher les informations d’un nom de domaine

Commencez par lister vos noms de domaine, puis demandez le détail de l’un d’eux.

Exemple de demande :

```text
Montre-moi les détails de mydomain.ovh : date d'expiration, serveurs DNS et état du verrou de transfert.
```

### 5 — Commander un nom de domaine

La commande d’un nom de domaine s’effectue avec l’outil `order-new-domain-name`, disponible dans la section `v1_domain`.

Exemple de demande :

```text
Commande mydomain.ovh pour un an.
```

Avant tout achat, demandez une **simulation**. L’outil accepte un paramètre `dryRun` : positionné à `true`, il vérifie la disponibilité du nom et calcule le tarif **sans rien engager ni facturer**.

```text
Simule la commande de mydomain.ovh pour un an.
```

Votre agent affiche alors le devis — le prix, la durée et la configuration qui seront appliqués au nom de domaine — puis attend votre accord avant d’aller plus loin.

Une fois le devis validé, l’agent relance l’appel avec `dryRun` à `false`. La commande devient ferme : l’API retourne l’**URL du bon de commande**. Votre agent vous transmet cette URL directement dans sa réponse : ouvrez-la dans votre navigateur pour régler la commande. Vous retrouverez également ce bon de commande dans votre espace client OVHcloud, dans la section <ManagerLink to="/#/billing/orders">Mes commandes</ManagerLink>.

:::info
Le bon de commande doit être **réglé** pour que l’enregistrement soit transmis au registre. Votre agent ne peut pas payer à votre place : suivez l’URL du bon de commande qu’il vous a retournée pour effectuer le paiement. Tant que celui-ci n’est pas encaissé, le nom de domaine reste disponible pour un tiers.
:::

:::warning
Valider la commande génère un bon de commande réel et facturable sur votre compte OVHcloud. Lisez la demande de confirmation de votre agent avant de l’accepter, et vérifiez le nom de domaine et la durée : un enregistrement ne s’annule pas comme une modification de configuration.
:::

### 6 — Modifier un enregistrement DNS

Outils associés : `create-domain-zone-record` pour ajouter un enregistrement, `delete-domain-zone-record` pour en supprimer un, et `get-domain-zone-details` pour inspecter la zone.

Exemples de demandes :

```text
Change l'enregistrement A de www.mydomain.ovh vers 203.0.113.42.
```

Vous n’avez pas besoin de savoir quel type d’enregistrement modifier. Décrivez le résultat que vous attendez : votre agent identifie l’enregistrement concerné, vous explique ce qu’il va changer et attend votre accord avant d’appliquer.

```text
Mon site est maintenant hébergé sur un serveur dont l'adresse IP est 203.0.113.42.
Fais en sorte que www.mydomain.ovh pointe dessus.
```

:::warning
Un enregistrement DNS modifié ne devient actif qu’après le rafraîchissement de la zone. Si vous omettez cette étape, votre modification est enregistrée mais jamais appliquée. Demandez explicitement à votre agent de rafraîchir la zone, ou vérifiez qu’il l’a fait.
:::

La propagation sur Internet peut ensuite prendre jusqu’à 24 heures, selon le TTL de l’enregistrement.

### 7 — Créer une redirection

Une redirection envoie les visiteurs de votre domaine vers une autre adresse.

Exemple de demande :

```text
Redirige blog.mydomain.ovh vers https://mydomain.ovh/actualites, en gardant l'adresse visible dans le navigateur.
```

### 8 — Les autres opérations couvertes

Les sections `v1_domain` et `v2_domain` exposent les routes correspondantes de l’API OVHcloud sous forme d’outils : **toute opération réalisable sur vos noms de domaine via l’API l’est également via MCP**. Au-delà des tâches ci-dessus, cela couvre par exemple :

- DNSSEC : activation, désactivation et gestion des enregistrements DS
- Protection de transfert : verrouillage et déverrouillage
- Gestion des contacts : propriétaire, administrateur, technique et facturation
- Serveurs DNS et enregistrements glue
- Identifiants et enregistrements DynHost (DNS dynamique)
- Sauvegarde, restauration, import et export de zone
- Gestion des tâches : accélération, annulation, relance
- Récupération du code AuthInfo et approbation des transferts sortants

Si vous n’êtes pas certain qu’une opération soit possible, demandez à votre agent de vous expliquer ce qu’il est capable de faire sur vos noms de domaine.
