## Objectif

Le SPF (Sender Policy Framework) permet au serveur qui reçoit un e-mail de s’assurer que ce dernier a bien été envoyé depuis un serveur de confiance.

<details>

<summary>Pourquoi mettre en place le SPF pour vos e-mails ?</summary>

- Il permet de prévenir les potentielles usurpations d’identité venant d’adresses e-mail utilisant votre nom de domaine (spoofing).
- Il permet également d’authentifier les e-mails que vous envoyez.
- Le SPF s’ajoute en tant qu’enregistrement dans la zone DNS du nom de domaine.

Cette vérification repose sur les informations renseignées dans l’enregistrement SPF, qui est en réalité un enregistrement TXT de la zone DNS. Il contient :

- **des adresses de serveurs et/ou plusieurs adresses IP** : elles sont ainsi identifiées comme sources d’envoi légitimes ;
- **un qualifieur** : il indique au serveur de réception comment traiter un message non légitime, c’est-à-dire envoyé depuis une source non listée.

Veillez donc à déclarer dans l’enregistrement SPF toutes les sources que vous utilisez pour envoyer des e-mails avec votre nom de domaine. Ces sources peuvent être votre propre serveur e-mail, celui de votre prestataire ou l’une des solutions e-mail d’OVHcloud.

**Exemple**

Vous envoyez un e-mail depuis votre adresse `john.smith@domain.tld`.

Seul le serveur sortant **A** (Outgoing Mail Server **A**) est déclaré dans l’enregistrement SPF du nom de domaine `domain.tld`.

Lorsque le serveur de réception (Inbound Mail Server) reçoit l’e-mail, celui-ci va lire la zone DNS de votre nom de domaine `domain.tld` pour inspecter l’enregistrement SPF.

- Le serveur sortant **A** (Outgoing Mail Server **A**) est listé dans l’enregistrement SPF : l’e-mail est donc transmis normalement dans la boîte de réception du destinataire.
- Le serveur sortant **B** (Outgoing Mail Server **B**) n’est pas listé dans l’enregistrement SPF : l’e-mail envoyé depuis ce serveur est donc marqué comme suspect à la réception. Cela peut se traduire par une mention `[SPAM]` dans l’objet de l’e-mail, le placement dans un dossier `Courrier indésirable`, ou une suppression directe, selon les règles du serveur de réception.

<img className="thumbnail" alt="Schéma du fonctionnement d’un enregistrement SPF entre serveurs d’envoi et de réception" src="/images/assets/schemas/emails/spf-records-diagram.png" loading="lazy" />

:::info
Le SPF n’est qu’une indication fournie aux serveurs recevant des e-mails, dont les vôtres. Il appartient à ces derniers d’appliquer ou non ce qui est spécifié dans l’enregistrement SPF des noms de domaine pour lesquels ils reçoivent des messages.

:::

</details>

## En pratique

### Vérifier votre configuration SPF actuelle

Si votre nom de domaine utilise les serveurs DNS d’OVHcloud, vous pouvez vérifier si un enregistrement SPF est déjà configuré pour celui-ci.

<details>

<summary>Comment vérifier une configuration SPF existante ?</summary>

{/* CP-STEPS-START:verif-acces */}

Accédez à la page <ManagerLink to="/beta/#/web-cloud/domains/listing">Domaines & DNS</ManagerLink>, choisissez le nom de domaine concerné, puis cliquez sur l’onglet <code className="action">Zone DNS</code>.

Le tableau affiche la <Tooltip term="dnsZone">zone DNS</Tooltip> de votre nom de domaine : chaque ligne correspond à un enregistrement DNS.

:::info
En cas de doute, vérifiez que votre nom de domaine utilise bien les serveurs DNS d’OVHcloud dans la section **Configuration DNS** de l’onglet <code className="action">Vue d’ensemble</code>.

:::

Pour retrouver la ligne de l’enregistrement SPF OVHcloud, appliquez un filtre d’affichage au tableau à l’aide du bouton <code className="action">Filtres</code>. Comme l’enregistrement peut apparaître à deux endroits différents et que le filtre n’affiche qu’un type à la fois, filtrez d’abord sur <code className="action">TXT</code>, puis sur <code className="action">SPF</code>.

<img className="thumbnail" alt="Bouton Filtres et liste Type d’enregistrement de la zone DNS" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/filter-type.png" loading="lazy" />

Vous obtenez l’un des résultats suivants.

{/* CP-STEPS-END:verif-acces */}

- **Un SPF correspondant aux informations OVHcloud de votre offre est affiché** : votre nom de domaine utilise déjà la configuration OVHcloud. Si vous ne souhaitez plus l’utiliser, vous devrez la modifier lors de l’étape suivante.

- **Un SPF ne correspondant pas aux informations OVHcloud est affiché** : votre nom de domaine utilise déjà un SPF personnalisé. Si votre configuration est erronée, modifiez-la ou remplacez-la par la configuration OVHcloud lors de l’étape suivante.

- **Aucun SPF ne s’affiche dans la colonne cible** : vérifiez d’abord, en modifiant le filtre, que l’enregistrement n’existe pas sous le type SPF ou TXT. Si aucun SPF ne s’affiche dans la zone, votre nom de domaine n’en utilise pas. Vous pourrez en ajouter un lors de l’étape suivante.

:::info
<Region zones={['eu']}>

Un SPF se compose toujours de la forme suivante : « v=spf1 `sources` `qualifieur` ». Par exemple, le SPF OVHcloud est : `v=spf1 include:mx.ovh.com ~all`.

</Region>
<Region zones={['ca', 'apac']}>

Un SPF se compose toujours de la forme suivante : « v=spf1 `sources` `qualifieur` ». Par exemple, le SPF OVHcloud est : `v=spf1 include:mx.ovh.ca ~all`.

</Region>

:::

</details>

### Configurer un nouvel enregistrement SPF <a name="spfrecord"></a>

{/* CP-STEPS-START:spf-formulaire */}

Au-dessus du tableau, cliquez sur <code className="action">Ajouter une entrée</code>, puis, dans la liste **Type**, sélectionnez <code className="action">SPF — Serveurs autorisés à envoyer des e-mails</code> (section **Champs mails**). Un formulaire s’ouvre pour construire votre enregistrement SPF champ par champ.

<img className="thumbnail" alt="Formulaire Ajouter une entrée de la zone DNS, enregistrement SPF" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/add-spf-record.png" loading="lazy" />

- **Sous-domaine** : ce champ est obligatoire. Indiquez `@` pour appliquer le SPF à l’ensemble du nom de domaine, ou saisissez un sous-domaine si vous n’envoyez des e-mails que depuis celui-ci.
- **Mécanismes d’autorisation** : cochez les sources autorisées à envoyer des e-mails pour votre nom de domaine.
    - **Inclure les serveurs e-mail OVH (include:mx.ovh.com)** : cochée par défaut, cette case autorise en une seule fois l’ensemble des serveurs e-mail sortants OVHcloud en insérant `include:mx.ovh.com`. Laissez-la cochée si vous utilisez une [solution e-mail OVHcloud](#ovhcloudspfvalue) et vérifiez dans cette section la valeur à utiliser selon votre zone.
    - **Autoriser les serveurs MX du domaine (mx)** : autorise les serveurs qui reçoivent vos e-mails à en envoyer également.
    - **Autoriser l’adresse IP du domaine (a)** : autorise le serveur qui héberge votre nom de domaine (utile lorsque votre site web et vos e-mails partagent la même adresse IP, par exemple sur un serveur dédié).
- **Serveurs supplémentaires à autoriser (include)** : ajoutez les domaines SPF d’autres prestataires qui envoient des e-mails en votre nom (plateforme marketing, CRM, etc.), afin que leurs serveurs soient considérés comme légitimes.
- **Adresses IPv4 autorisées (ip4)** et **Adresses IPv6 autorisées (ip6)** : ajoutez des adresses IP ou des plages d’adresses spécifiques autorisées à envoyer des e-mails.
- **Politique SPF** : choisissez la manière dont les serveurs de réception doivent traiter un e-mail envoyé depuis une source qui n’est **pas** listée (voir notre recommandation ci-dessous). La valeur `~all` (« Accepter mais marquer comme suspect ») est présélectionnée et marquée **Recommandé**.
- <Tooltip term="ttl">**TTL**</Tooltip> : laissez-le sur `Par défaut` ou définissez une valeur.

Le cadre **Aperçu de l’enregistrement** affiche l’enregistrement en cours de construction au fur et à mesure que vous remplissez les champs. Une fois terminé, cliquez sur <code className="action">Ajouter</code>.

{/* CP-STEPS-END:spf-formulaire */}

:::tip
Les valeurs `~all` et `-all` de la **Politique SPF** sont toutes les deux valides, mais pour une protection optimale nous vous recommandons vivement `-all`, qui demande aux serveurs qui reçoivent vos e-mails de **rejeter** tout message envoyé depuis une source non listée dans votre enregistrement SPF.

Ne choisissez `-all` qu’une fois certain que votre enregistrement liste **toutes** vos sources d’envoi légitimes : votre solution e-mail OVHcloud, mais aussi tout service tiers qui envoie des e-mails en votre nom (plateforme marketing, CRM, outil de ticketing, etc.). Si une source légitime manque, ses e-mails seront rejetés. Si vous n’êtes pas certain que la liste est exhaustive, utilisez `~all`, qui marque ces e-mails comme suspects au lieu de les rejeter.
:::

:::info
<Region zones={['eu']}>

Pour une solution e-mail OVHcloud, l’enregistrement SPF minimal consiste simplement à laisser cochée la case **Inclure les serveurs e-mail OVH (include:mx.ovh.com)**, cochée par défaut — cela produit `v=spf1 include:mx.ovh.com ~all` (voir [Configuration SPF OVHcloud pour les offres e-mail mutualisées](#ovhcloudspfvalue)).

</Region>
<Region zones={['ca', 'apac']}>

Pour une solution e-mail OVHcloud, l’enregistrement SPF minimal est `v=spf1 include:mx.ovh.ca ~all` : décochez la case **Inclure les serveurs e-mail OVH (include:mx.ovh.com)**, cochée par défaut, qui insère la valeur européenne `mx.ovh.com`, puis saisissez `mx.ovh.ca` dans le champ **Serveurs supplémentaires à autoriser (include)** (voir [Configuration SPF OVHcloud pour les offres e-mail mutualisées](#ovhcloudspfvalue)).

</Region>

:::

{/* CP-STEPS-START:spf-txt-avance */}

Si vous disposez déjà de la chaîne SPF complète (fournie par votre service e-mail) ou si vous avez besoin d’une balise absente du formulaire, saisissez-la directement : sélectionnez le type <Tooltip term="txtRecord">**TXT**</Tooltip> (<code className="action">TXT — Texte libre (vérification, SPF…)</code>) au lieu de SPF et collez la valeur complète `v=spf1 …` dans le champ **Valeur**, ou utilisez le <code className="action">Mode avancé</code>, en tête du formulaire.

{/* CP-STEPS-END:spf-txt-avance */}

:::info
La modification nécessite un temps de <Tooltip term="dnsPropagation">propagation</Tooltip> de 4 à 24 heures avant d’être pleinement effective.

:::

### Modifier un enregistrement SPF <a name="modifyspf"></a>

{/* CP-STEPS-START:modifier */}

Accédez à la page <ManagerLink to="/beta/#/web-cloud/domains/listing">Domaines & DNS</ManagerLink>, choisissez le nom de domaine concerné, puis cliquez sur l’onglet <code className="action">Zone DNS</code>.

Le tableau affiche la zone DNS de votre nom de domaine : chaque ligne correspond à un enregistrement DNS. Repérez votre enregistrement TXT ou SPF dans ce tableau, cliquez sur le bouton <code className="action">⋮</code> de la colonne **Actions**, puis sur <code className="action">Modifier</code>. La ligne se déploie en un formulaire de modification.

<img className="thumbnail" alt="Menu d’actions d’une ligne de la zone DNS" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/row-actions.png" loading="lazy" />

### Configuration SPF OVHcloud pour les offres e-mail mutualisées <a name="ovhcloudspfvalue"></a>

La configuration SPF OVHcloud générale s’applique aux solutions ci-dessous :

- <Tooltip term="mxPlan">MX Plan</Tooltip> seul ou inclus dans une offre d’[hébergement web OVHcloud](/links/web/hosting).
<Region zones={['eu']}>
- [Email Pro](/links/web/email-pro).
</Region>
<Region zones={['eu', 'ca']}>
- [Hosted Exchange](/links/web/emails-hosted-exchange).
</Region>

La configuration est la suivante :

<Region zones={['eu']}>

```bash
domain.tld IN TXT "v=spf1 include:mx.ovh.com ~all"
```

</Region>
<Region zones={['ca', 'apac']}>

```bash
domain.tld IN TXT "v=spf1 include:mx.ovh.ca ~all"
```

</Region>

<Region zones={['eu', 'ca']}>

### Configuration SPF OVHcloud pour Private Exchange

Pour l’offre Private Exchange, vous devez renseigner les adresses IP de votre serveur e-mail : utilisez l’argument `ip4` pour l’adresse IPv4 (**A**) et l’argument `ip6` pour l’adresse IPv6 (**AAAA**) de votre serveur Private Exchange.

```bash
domain.tld IN TXT "v=spf1 ip4:203.0.113.1 ip6:2001:db8::1 ~all"
```

<Region zones={['eu']}>

Si vous utilisez également [une offre e-mail mutualisée](#ovhcloudspfvalue), vous pouvez ajouter l’argument `include:mx.ovh.com` à l’enregistrement ci-dessus, ce qui donne la valeur suivante :

```bash
domain.tld IN TXT "v=spf1 ip4:203.0.113.1 ip6:2001:db8::1 include:mx.ovh.com ~all"
```

</Region>
<Region zones={['ca', 'apac']}>

Si vous utilisez également [une offre e-mail mutualisée](#ovhcloudspfvalue), vous pouvez ajouter l’argument `include:mx.ovh.ca` à l’enregistrement ci-dessus, ce qui donne la valeur suivante :

```bash
domain.tld IN TXT "v=spf1 ip4:203.0.113.1 ip6:2001:db8::1 include:mx.ovh.ca ~all"
```

</Region>

<summary>Comment récupérer les adresses IP d’un serveur Private Exchange ?</summary>

{/* CP-STEPS-START:exchange-ip */}

Accédez à la page <ManagerLink to="/beta/#/web-cloud/email/exchange">Exchange</ManagerLink>, puis cliquez sur le service dont le **Type d’offre** est **Private Exchange**.

Dans l’onglet <code className="action">Vue d’ensemble</code>, carte **Informations générales**, la partie **Diagnostics du serveur** affiche les pastilles `A` et `AAAA`. Cliquez sur <code className="action">Voir les diagnostics</code> puis, dans le volet qui s’ouvre, sur les onglets <code className="action">A</code> et <code className="action">AAAA</code> : relevez la valeur affichée sous **Cible**.

<img className="thumbnail" alt="Volet Diagnostics du serveur d’un service Private Exchange, onglet A et sa cible" src="/images/assets/screens/console/product-selection/web-cloud/email-and-collaborative-solutions/exchange/server-diagnostics.png" loading="lazy" />

Si les pastilles `A` et `AAAA` sont vertes, le volet indique « Configuration automatique effectuée » et n’affiche pas les adresses IP. Récupérez-les alors depuis la zone DNS du nom de domaine attaché à votre plateforme Private Exchange. Pour cela, relevez d’abord l’adresse du lien **Webmail** de la carte **Informations générales**.

<img className="thumbnail" alt="Carte Informations générales d’un service Private Exchange, lien Webmail et diagnostics du serveur" src="/images/assets/screens/console/product-selection/web-cloud/email-and-collaborative-solutions/exchange/general-information.png" loading="lazy" />

Accédez ensuite à la page <ManagerLink to="/beta/#/web-cloud/domains/listing">Domaines & DNS</ManagerLink>, choisissez le nom de domaine attaché à votre plateforme Private Exchange, puis cliquez sur l’onglet <code className="action">Zone DNS</code>. Récupérez les adresses IPv4 (enregistrement `A`) et IPv6 (enregistrement `AAAA`) correspondant à l’URL du webmail.
