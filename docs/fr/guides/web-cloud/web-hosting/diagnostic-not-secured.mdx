- Avoir la gestion des [serveurs DNS](/guides/web-cloud/domains/dns-server-general-information) et de la [zone DNS](/guides/web-cloud/domains/dns-zone-general-information) de votre nom de domaine

## En pratique

Afin de résoudre cette anomalie, vous devrez :

1. déterminer l’hébergement auquel est relié votre nom de domaine, afin d’intervenir sur le bon serveur ;
2. créer, activer ou renouveler un [certificat SSL](/guides/web-cloud/web-hosting/ssl-on-webhosting) pour votre nom de domaine sur l’hébergement concerné.

### 1 - Vérifier l’hébergement attaché à votre nom de domaine

#### Vérifier l’adresse IP de l’hébergement

Les messages d’erreur mentionnés [plus haut](#objectif) ne signifient pas forcément que votre site est hébergé sur l’une de nos [offres Web Cloud](/links/web/hosting). Vous devez donc vérifier l’adresse IP du serveur auquel est relié votre [nom de domaine](/links/web/domains).

{/* CP-STEPS-START:ip-hebergement */}

Pour retrouver l’adresse IP de votre [hébergement OVHcloud](/links/web/hosting), cliquez sur les onglets ci-dessous pour afficher successivement chacune des **2** étapes.

<Tabs>
  <Tab label="Étape 1">
    Accédez à la page <ManagerLink to="/beta/#/web-cloud/hosting">Hébergements web</ManagerLink>, puis choisissez l’hébergement web concerné.

    <img className="thumbnail" alt="Page Hébergements web et liste des hébergements du compte" src="/images/assets/screens/console/product-selection/web-cloud/hosting-plans.png" loading="lazy" />
  </Tab>
  <Tab label="Étape 2">
    L’hébergement s’ouvre sur l’onglet <code className="action">Vue d’ensemble</code>. Dans la section **Informations générales**, vous trouverez les mentions **IPv4** et **IPv6**.

    <img className="thumbnail" alt="Section Informations générales, adresses IPv4 et IPv6" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/general-information/ipv4-ipv6.png" loading="lazy" />

    Notez l’adresse IPv4 et/ou IPv6, à l’aide du bouton de copie situé à droite de chaque adresse, puis poursuivez la lecture du guide.
  </Tab>
</Tabs>

{/* CP-STEPS-END:ip-hebergement */}

#### Vérifier l’adresse IP dans la zone DNS

Il vous faut maintenant vérifier que l’adresse IP indiquée dans la [Zone DNS](/guides/web-cloud/domains/dns-zone-edit) correspond bien à celle de votre [hébergement Web Cloud](/links/web/hosting).

{/* CP-STEPS-START:ip-zone-dns */}

Cliquez sur les onglets ci-dessous pour afficher successivement chacune des **2** étapes.

<Tabs>
  <Tab label="Étape 1">
    Accédez à la page <ManagerLink to="/beta/#/web-cloud/domains/listing">Domaines & DNS</ManagerLink>, sélectionnez le nom de domaine concerné, puis ouvrez l’onglet <code className="action">Zone DNS</code>.

    <img className="thumbnail" alt="Page Domaines & DNS et liste des noms de domaine du compte" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/listing.png" loading="lazy" />
  </Tab>
  <Tab label="Étape 2">
    Le tableau affiche un enregistrement DNS par ligne, avec les colonnes **Sous-domaine**, **Type**, **Cible** et **TTL (en secondes)**. Pour n’afficher que les entrées de type `A`, déroulez le menu <code className="action">Tous les types</code> et sélectionnez <code className="action">A</code>.

    <img className="thumbnail" alt="Menu Tous les types déroulé sur les types d’enregistrement" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/filter-type.png" loading="lazy" />

    Notez la **Cible** de l’entrée de type `A` pour votre nom de domaine.
  </Tab>
</Tabs>

{/* CP-STEPS-END:ip-zone-dns */}

#### Effectuer les actions nécessaires

**Cliquez sur le scénario correspondant à votre situation pour afficher le contenu.**

<details>
<summary>L’adresse IP correspond à celle de votre hébergement mutualisé</summary>

L’adresse IP indiquée dans la [Zone DNS](/guides/web-cloud/domains/dns-zone-edit) correspond à celle de votre hébergement mutualisé. Passez à la [partie 2](#etape2).

</details>

<details>
<summary>L’adresse IP ne concerne aucun hébergement de votre compte mais apparaît dans la liste des serveurs Web Cloud</summary>

L’adresse IP indiquée dans la zone ne concerne aucun hébergement de votre <ManagerLink to="/">compte OVHcloud</ManagerLink>, mais elle apparaît dans la [liste des serveurs Web Cloud](/guides/web-cloud/web-hosting/clusters-and-shared-hosting-ip).

Vérifiez que vous ne possédez pas un hébergement possédant cette adresse IP dans l’un de vos autres <ManagerLink to="/">comptes OVHcloud</ManagerLink> si vous en avez créé plusieurs. Si besoin, contactez votre webmaster ou les [partenaires OVHcloud](/links/partner) à ce sujet.

</details>

<details>
<summary>L’adresse IP n’est pas celle de votre hébergement et n’apparaît pas dans la liste des serveurs Web Cloud</summary>

L’adresse IP indiquée dans la zone n’est pas celle de votre hébergement et elle n’apparaît pas non plus dans la [liste des serveurs Web Cloud](/guides/web-cloud/web-hosting/clusters-and-shared-hosting-ip).

Contactez votre webmaster ou les [partenaires OVHcloud](/links/partner) à ce sujet.

</details>

{/* CP-STEPS-START:serveurs-dns */}

<details>
<summary>Votre domaine utilise d’autres serveurs DNS OVHcloud (ns?.ovh.net / dns?.ovh.net)</summary>

Au-dessus de la zone DNS présente dans votre console OVHcloud, un avertissement indique « **Cette zone DNS n’est pas autoritaire pour votre nom de domaine.** » : votre domaine utilise d’autres serveurs [DNS](/guides/web-cloud/domains/dns-zone-edit), et les modifications effectuées dans cette zone ne sont pas prises en compte.

Pour savoir quels serveurs DNS votre domaine utilise, ouvrez l’onglet <code className="action">Vue d’ensemble</code> du nom de domaine et consultez la section **Serveurs DNS** : la liste **Serveurs DNS hébergeant la zone** les affiche. S’ils apparaissent sous la forme « ns **?** .ovh.net » ou « dns **?** .ovh.net » (le « **?** » correspondant au numéro de serveur DNS concerné), il s’agit d’autres serveurs DNS OVHcloud.

<img className="thumbnail" alt="Section Serveurs DNS avec la configuration et la liste des serveurs DNS hébergeant la zone" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/general-information/dns-servers-ovhcloud.png" loading="lazy" />

Modifiez les serveurs DNS de votre domaine, afin qu’ils correspondent à ceux inscrits dans les entrées de type `NS` de la zone. Pour effectuer cette opération, suivez les instructions de [ce guide](/guides/web-cloud/domains/dns-server-edit).

{/* v8-review: TO DOCUMENT — the « This DNS zone is not authoritative for your domain name. » banner was not seen live (no domain on the test account uses servers other than its zone's); its wording comes from ZoneBanners.tsx and zone.json. Unlike v6, it does not list the DNS servers in use, hence the pointer to the Overview « DNS servers » section. */}

</details>

<details>
<summary>Votre domaine utilise des serveurs DNS externes (non OVHcloud)</summary>

Au-dessus de la zone DNS présente dans votre console OVHcloud, le même avertissement « **Cette zone DNS n’est pas autoritaire pour votre nom de domaine.** » s’affiche. Dans la section **Serveurs DNS** de l’onglet <code className="action">Vue d’ensemble</code> du nom de domaine, la ligne **Configuration** indique **Personnalisée** et les serveurs DNS listés n’apparaissent pas sous la forme « ns **?** .ovh.net » ou « dns **?** .ovh.net ».

Contactez votre webmaster ou les [partenaires OVHcloud](/links/partner) à ce sujet.

</details>

{/* CP-STEPS-END:serveurs-dns */}

{/* CP-STEPS-START:domaine-absent */}

<details>
<summary>Votre nom de domaine n’apparaît pas dans votre console OVHcloud</summary>

Votre nom de domaine n’apparaît pas sur la page <ManagerLink to="/beta/#/web-cloud/domains/listing">Domaines & DNS</ManagerLink> de votre console OVHcloud.

Cela signifie que votre nom de domaine n’est pas géré depuis votre console OVHcloud.

Vérifiez qu’il n’est pas géré depuis l’un de vos autres <ManagerLink to="/">comptes OVHcloud</ManagerLink>, si vous en avez créé plusieurs.

Vous pouvez également déterminer son bureau d’enregistrement et les serveurs DNS auxquels il est lié via notre outil [WHOIS](/links/web/domains-whois).

Si besoin, contactez votre webmaster ou les [partenaires OVHcloud](/links/partner) à ce sujet.

</details>

{/* CP-STEPS-END:domaine-absent */}

### 2 - Vérifier le certificat SSL de votre hébergement <a name="etape2"></a>

{/* CP-STEPS-START:certificat-ssl */}

Cliquez sur les onglets ci-dessous pour afficher successivement chacune des **2** étapes.

<Tabs>
  <Tab label="Étape 1">
    Accédez à la page <ManagerLink to="/beta/#/web-cloud/hosting">Hébergements web</ManagerLink>, puis choisissez l’hébergement web concerné.

    <img className="thumbnail" alt="Page Hébergements web et liste des hébergements du compte" src="/images/assets/screens/console/product-selection/web-cloud/hosting-plans.png" loading="lazy" />
  </Tab>
  <Tab label="Étape 2">
    Cliquez sur l’onglet <code className="action">SSL</code>.

    <img className="thumbnail" alt="Onglet SSL d’un hébergement web" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/ssl-certificates.png" loading="lazy" />

    Repérez votre nom de domaine dans la colonne **Domaine principal**, puis vérifiez sa colonne **Statut**. Si votre nom de domaine n’apparaît pas dans le tableau, votre hébergement ne contient pas de certificat SSL pour ce domaine.

    <img className="thumbnail" alt="Tableau des certificats SSL et sa colonne Statut" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/ssl-certificates/tab.png" loading="lazy" />
  </Tab>
</Tabs>

{/* CP-STEPS-END:certificat-ssl */}

#### Scénario 1 : votre hébergement ne contient pas de certificat SSL

Activez un [certificat SSL](/links/web/hosting-options-ssl) sur votre hébergement en suivant les instructions de [ce guide](/guides/web-cloud/web-hosting/ssl-on-webhosting).

#### Scénario 2 : le certificat SSL de votre hébergement ne fonctionne pas

Si vous avez généré un **certificat SSL « Let's Encrypt »**, activez l’option SSL de votre hébergement en suivant les instructions de [ce guide](/guides/web-cloud/web-hosting/ssl-on-webhosting).

Si vous disposez d’un **certificat SSL importé** et que celui-ci ne fonctionne pas, contactez son fournisseur.

Si vous avez commandé l’un des **certificats SSL payants** de notre partenaire [SECTIGO](https://sectigo.com/), vérifiez si vous avez reçu un e-mail vous proposant de le renouveler.
<br/>Si besoin, contactez le [support de SECTIGO](https://sectigo.com/support) à ce sujet.
