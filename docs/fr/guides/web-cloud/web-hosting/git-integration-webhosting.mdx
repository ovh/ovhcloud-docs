## Objectif

Dans le paysage numérique actuel, les sociétés sont de plus en plus dynamiques et innovantes. La capacité à gérer et à déployer efficacement le code de son site web est essentielle pour maintenir la compétitivité et la pérennité de votre marque. Git, système de gestion de versions le plus utilisé au monde, permet de stocker le code de votre site web sur des plateformes comme GitHub, permettant une meilleure traçabilité des modifications, ainsi qu’une automatisation et des déploiements plus rapides. En tant que client OVHcloud, vous bénéficiez d’une infrastructure robuste pour héberger votre site web, tout en exploitant les nombreux avantages de Git et de GitHub pour le développement et l’évolution de votre site web.

{/* CP-STEPS-START:objectif-intro */}

- Disposer d’une offre d'[hébergement web OVHcloud](/links/web/hosting).

#### Définir le dépôt GitHub

Renseignez l’adresse de votre dépôt GitHub. Si vous n’avez pas encore de dépôt GitHub pour votre projet, créez-en un.

Pour créer un nouveau dépôt :

- Connectez-vous à votre compte GitHub.
- Cliquez sur votre image de profil en haut à droite, puis sur <code className="action">Your repositories</code>.
- Sur la droite de l’écran qui s’affiche, cliquez sur <code className="action">New</code>.

Définissez un nom pour votre dépôt et remplissez les informations demandées.

:::warning
Cochez l’option `Add a README file` pour que GitHub initialise correctement votre dépôt.

:::

Enfin, cliquez sur <code className="action">Create Repository</code>.

Copiez l’adresse de votre dépôt GitHub. Celle-ci doit être de la forme :

- `https://github.com/<username>/<repository_name>.git` pour un dépôt public.
- `git@github.com:<username>/<repository_name>.git` pour un dépôt privé.

{/* CP-STEPS-START:definir-depot */}

Retournez dans le panneau **Configuration git** et collez l’adresse de votre dépôt GitHub dans le champ **Dépôt**. Elle doit être de la forme `https://github.com/<username>/<repository_name>.git` pour un dépôt public, ou `git@github.com:<username>/<repository_name>.git` pour un dépôt privé. Tant que l’adresse n’a pas l’un de ces formats et que le champ **Branche** est vide, le bouton <code className="action">Appliquer la configuration</code> reste inactif.

Définissez maintenant la branche de votre dépôt GitHub. La branche par défaut est `main`, mais si vous voulez utiliser une autre branche, créez-en une sur GitHub en suivant les étapes ci-dessous :

- Connectez-vous à votre compte GitHub.
- Cliquez sur votre image de profil en haut à droite, puis sur <code className="action">Your repositories</code>.
- Dirigez-vous dans le dépôt GitHub concerné.
- Cliquez sur <code className="action">Main</code>, puis sur <code className="action">View all branches</code>, ou cliquez directement sur l’onglet <code className="action">x Branch</code>.
- À droite de l’écran qui s’affiche, cliquez sur <code className="action">New branch</code>. 
- Indiquez le nom de la nouvelle branche et confirmez en cliquant sur <code className="action">Create new branch</code>.

Retournez dans le panneau **Configuration git** de la console OVHcloud et indiquez le nom de la nouvelle branche que vous venez de créer dans le champ **Branche**.

Si vous renseignez l’adresse d’un dépôt GitHub privé (de type `git@github.com:<username>/<repository_name>.git`), un encadré **Clé SSH (dépôt privé)** s’affiche sous le champ **Dépôt**.

<img className="thumbnail" alt="Encadré Clé SSH (dépôt privé) affiché pour une adresse de dépôt privé" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/configure-ssh-key.png" loading="lazy" />

Pour configurer votre clé SSH, consultez l’étape « Associer une clé SSH à GitHub (uniquement pour les dépôts GitHub privés) » ci-dessous.

{/* CP-STEPS-END:definir-depot */}

#### Associer une clé SSH à GitHub (uniquement pour les dépôts GitHub privés) <a name="linkSSHKey"></a>

:::info
**Pourquoi la clé SSH est-elle nécessaire uniquement pour un dépôt privé ?**

Lorsque votre dépôt GitHub est public, les fichiers peuvent être récupérés sans authentification, ce qui signifie que Git peut cloner et mettre à jour le code sans avoir besoin d’une clé SSH. En revanche, si votre dépôt est privé, GitHub exige une authentification pour y accéder. La clé SSH permet alors d’établir cette connexion sécurisée et de garantir que seuls les utilisateurs autorisés puissent interagir avec le dépôt.

:::

:::info
La génération d’une clé SSH est une étape cruciale, car elle établit une connexion sécurisée et chiffrée entre le répertoire de votre site web et le dépôt GitHub. Cette clé assure que les transferts de données et les modifications de code se font de manière sûre et authentifiée, prévenant les accès non autorisés et garantissant l’intégrité du code.

:::

{/* CP-STEPS-START:cle-ssh */}

Copiez la clé SSH affichée dans l’encadré **Clé SSH (dépôt privé)** en cliquant sur le bouton de copie situé à droite.

<img className="thumbnail" alt="Encadré Clé SSH (dépôt privé) et bouton de copie" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/configure-ssh-key.png" loading="lazy" />

Comme l’indique la console, ajoutez cette clé publique comme clé de déploiement (« deploy key ») dans les réglages de votre dépôt GitHub :

- Connectez-vous à votre compte GitHub et accédez au dépôt concerné.
- Cliquez sur l’onglet <code className="action">Settings</code> du dépôt, puis sur <code className="action">Deploy keys</code> dans la colonne de gauche.
- Cliquez sur <code className="action">Add deploy key</code>.

Le formulaire d’ajout d’une clé de déploiement s’affiche :

- **Title** : ajoutez une description pour votre clé SSH. Par exemple, vous pouvez nommer cette clé « OVHcloud ».
- **Key** : collez votre clé SSH.
- **Allow write access** : laissez cette case décochée, le déploiement ne nécessite qu’un accès en lecture à votre dépôt.

Pour valider les informations, cliquez sur <code className="action">Add key</code>. Si vous y êtes invité, confirmez l’accès à votre compte dans GitHub.

{/* CP-STEPS-END:cle-ssh */}

#### Configurer le déploiement automatique

{/* CP-STEPS-START:deploiement-automatique */}

En bas du panneau **Configuration git**, la section **Configurer votre déploiement automatique** affiche l’URL de webhook, accompagnée d’un bouton de copie. Configurer un webhook permet à votre dépôt GitHub de notifier automatiquement votre hébergement web OVHcloud des événements qui se produisent sur le dépôt GitHub (nouveau déploiement, changement dans le code, etc.). Cette fonctionnalité est particulièrement utile si vous travaillez en groupe sur le même projet et que vous souhaitez rester à jour de toutes les modifications du dépôt GitHub. Pour en savoir plus, découvrez comment [configurer un webhook sur GitHub](#configureWebhook).

{/* CP-STEPS-END:deploiement-automatique */}

#### Valider l’association de Git

{/* CP-STEPS-START:valider-association */}

Avant de valider le panneau **Configuration git**, assurez-vous que :

- Votre clé SSH a bien été ajoutée comme clé de déploiement de votre dépôt GitHub (dépôt privé uniquement).
- L’adresse de votre dépôt GitHub est correcte. Elle doit être de la forme `https://github.com/<username>/<repository_name>.git` (dépôt public) ou `git@github.com:<username>/<repository_name>.git` (dépôt privé).
- Le nom de la branche du dépôt GitHub est correct.
- Le dossier racine de votre site web est vide : dans le cas contraire, le déploiement échouera.

Pour valider les informations, cliquez sur <code className="action">Appliquer la configuration</code>.

{/* CP-STEPS-END:valider-association */}

### Activation de l’association de Git

#### Succès de l’association de Git

{/* CP-STEPS-START:succes-association */}

Dans la colonne **Git** du tableau de l’onglet <code className="action">Mes sites</code>, la mention **Configuration en cours…** apparaît sur la ligne du site web concerné : Git est en cours d’activation. Le processus peut prendre plusieurs minutes, et le tableau se met à jour automatiquement.

Lorsque l’association de Git est effectuée, le statut **Actif** apparaît dans la colonne **Git** pour le site web concerné.

<img className="thumbnail" alt="Colonne Git avec le statut Actif" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/sites-git-column.png" loading="lazy" />

{/* CP-STEPS-END:succes-association */}

#### Erreurs de l’association de Git

{/* CP-STEPS-START:erreurs-association */}

Dans la colonne **Git** du tableau de l’onglet <code className="action">Mes sites</code>, si la mention **Erreur** apparaît sur la ligne du site web que vous voulez associer à Git, cela signifie qu’au moins une des erreurs suivantes est survenue :

- La clé SSH n’a pas été ajoutée comme clé de déploiement de votre dépôt GitHub (dépôt privé).
- Le dossier racine du site web n’était pas vide au moment de l’association.
- L’adresse du dépôt GitHub n’existe pas ou est erronée.
- La branche du dépôt GitHub n’existe pas ou son nom est erroné.

Pour connaître la cause de l’erreur, cliquez sur la mention **Erreur**. Le panneau **Erreur de déploiement Git** s’ouvre : il rappelle le dépôt et la branche configurés, les causes fréquentes, ainsi que les informations du dernier déploiement.

<img className="thumbnail" alt="Panneau Erreur de déploiement Git" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/error-drawer.png" loading="lazy" />

Une fois la cause corrigée, choisissez l’une des actions de la partie **Ce que vous pouvez faire** : <code className="action">Relancer</code> pour relancer le déploiement (ou l’association), <code className="action">Modifier</code> pour corriger la configuration, ou <code className="action">Supprimer</code> pour supprimer l’association avant d’associer Git à nouveau.

{/* CP-STEPS-END:erreurs-association */}

#### Configurer le webhook <a name="configureWebhook"></a>

Connectez-vous à votre compte GitHub et accédez au dépôt sur lequel vous souhaitez configurer le webhook. Dirigez-vous sur l’onglet <code className="action">Settings</code> puis, dans le menu latéral des paramètres, cliquez sur <code className="action">Webhooks</code>. Cliquez sur le bouton <code className="action">Add webhook</code> pour accéder au formulaire :

- **Payload URL** : entrez l’URL fournie dans le formulaire d’association de Git (<code className="action">URL de webhook</code>).
- **Content type** : choisissez <code className="action">application/json</code> comme type de contenu pour les données envoyées.
- **Secret** : le secret est facultatif. GitHub l’utilisera pour signer les messages envoyés par le webhook, renforçant ainsi la sécurité.
- **SSL verification** : si votre site web supporte le HTTPS, laissez cette option activée pour une sécurité accrue.
- **Which events would you like to trigger this webhook ?** : sélectionnez les événements qui déclencheront l’envoi du webhook. Pour un déploiement automatique, <code className="action">Just the push event</code> (Juste l’événement push) est souvent suffisant, mais vous pouvez choisir <code className="action">Send me everything</code> pour recevoir des notifications pour tous les événements.
- **Active** : assurez-vous que la case est cochée pour activer le webhook.

Cliquez sur <code className="action">Add webhook</code> pour enregistrer et activer votre nouveau webhook.

#### Tester votre webhook

Après avoir créé votre webhook dans GitHub, dirigez-vous dans la liste de vos webhooks et sélectionnez celui que vous venez de créer, ou cliquez sur <code className="action">Edit</code>.

Sur l’écran qui s’affiche, cliquez sur l’onglet <code className="action">Recent Deliveries</code>. Pour envoyer un événement test spécifiquement, GitHub envoie généralement un événement `ping` lors de la création du webhook, et vous pouvez utiliser le bouton <code className="action">Redeliver</code> à côté de cet événement pour le tester.

Si le test a fonctionné, l’onglet <code className="action">Response</code> renvoie un code 200. Si un code d’erreur est retourné (généralement 500 ou 400), cela signifie que votre webhook a été mal configuré. Retournez dans le formulaire d’ajout d’un webhook et vérifiez les informations, spécifiquement l’URL du webhook fournie par OVHcloud.

#### Utiliser le webhook

Une fois votre webhook configuré, le code de votre site web sera mis à jour automatiquement à chaque fois que des changements surviennent sur le dépôt GitHub. Par exemple, si des modifications sont apportées par un de vos collègues sur le dépôt GitHub, alors le code de votre site web sera mis à jour en local (sur votre hébergement OVHcloud).
