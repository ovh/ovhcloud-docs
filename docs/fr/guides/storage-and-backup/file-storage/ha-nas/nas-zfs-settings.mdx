## Objectif

Chaque partition d'un service NAS-HA est un dataset ZFS. Trois de ses propriétés ZFS peuvent être ajustées selon les données qu'elle héberge : la mise à jour des temps d'accès (*atime*), la taille de bloc maximale (*recordsize*) et la synchronisation des écritures (*sync*).

Pour simplifier ce réglage, OVHcloud propose des templates d'usage qui appliquent en une seule fois une combinaison prédéfinie de ces paramètres.

**Ce guide explique le rôle de chaque paramètre ZFS, les valeurs appliquées par chaque template et comment modifier les paramètres d'une partition depuis l'espace client OVHcloud ou via l'API OVHcloud.**

## Prérequis

- Un [service NAS-HA](https://www.ovhcloud.com/fr/storage-solutions/nas-ha/) OVHcloud disposant d'au moins une [partition](/guides/storage-and-backup/file-storage/ha-nas/nas-get-started)
- Un accès à l'espace client OVHcloud ou à l'API OVHcloud (consultez le guide [Premiers pas avec les API OVHcloud](/guides/manage-and-operate/api/first-steps))

## En pratique

:::warning
Les paramètres ZFS par défaut conviennent à la plupart des usages. Ne les modifiez que si vous connaissez les données hébergées sur la partition et l'impact de chaque paramètre décrit ci-dessous.
:::

### Comprendre les paramètres ZFS

#### Mise à jour des temps d'accès (atime)

Lorsque *atime* est activé, ZFS met à jour la date de dernier accès d'un fichier à chaque lecture. Chaque opération de lecture génère alors également une opération d'écriture.

Lorsque *atime* est désactivé (`off`), ces écritures supplémentaires sont évitées, ce qui améliore les performances des usages intensifs en lecture. Désactivez-le, sauf si une application hébergée sur la partition s'appuie sur les dates d'accès aux fichiers. Tous les templates d'usage règlent *atime* sur `off`.

#### ZFS recordsize

Le *recordsize* est la taille maximale des blocs dans lesquels ZFS stocke les données d'un fichier. Les fichiers plus petits que le *recordsize* utilisent un bloc plus petit : un fichier de 16 Ko occupe un bloc de 16 Ko (plus les métadonnées), et non un bloc complet de 128 Kio.

En règle générale, alignez le *recordsize* sur la taille des lectures et écritures de l'application :

- **Lectures et écritures petites et aléatoires** (bases de données, disques de machines virtuelles) : un *recordsize* réduit évite de lire et de réécrire un bloc volumineux pour modifier quelques kilo-octets.
- **Lectures et écritures volumineuses et séquentielles** (fichiers vidéo, images, sauvegardes, archives) : un *recordsize* élevé réduit le nombre de blocs et de métadonnées à gérer, ce qui améliore le débit.

Les valeurs disponibles sont listées ci-dessous. L'espace client les affiche en unités décimales (1 ko = 1 000 octets).

| Valeur (octets) | Taille binaire | Affichage dans l'espace client |
|-----------------|----------------|--------------------------------|
| `4096` | 4 Kio | 4.1 ko |
| `8192` | 8 Kio | 8.2 ko |
| `16384` | 16 Kio | 16.4 ko |
| `32768` | 32 Kio | 32.8 ko |
| `65536` | 64 Kio | 65.5 ko |
| `131072` (par défaut) | 128 Kio | 131.1 ko (Défaut) |
| `1048576` | 1 Mio | 1 Mo |

:::info
Un nouveau *recordsize* ne s'applique qu'aux fichiers écrits après la modification. Les fichiers existants conservent la taille de bloc avec laquelle ils ont été écrits, jusqu'à leur réécriture.
:::

#### Sync

Le paramètre *sync* détermine la manière dont ZFS traite les demandes d'écriture synchrones, c'est-à-dire les demandes pour lesquelles l'application attend la confirmation que les données sont stockées sur disque.

| Valeur | Comportement | Usage |
|--------|--------------|-------|
| `standard` (par défaut) | ZFS respecte les demandes d'écriture synchrones : l'écriture est confirmée une fois les données sécurisées sur disque. Les écritures asynchrones sont mises en mémoire tampon. | Recommandé pour tous les usages. Allie sécurité des données et performances. |
| `always` | Toutes les écritures sont traitées comme synchrones, même lorsque l'application ne le demande pas. | Sécurité des données maximale, au prix de performances d'écriture réduites. |
| `disabled` | ZFS ignore les demandes d'écriture synchrones et les confirme avant que les données ne soient écrites sur disque. | Performances très élevées, mais des données confirmées comme écrites peuvent être perdues en cas d'incident. Inadapté aux bases de données et aux clients NFS qui s'appuient sur les écritures synchrones. |

:::danger
Avec *sync* réglé sur `disabled`, une application peut considérer des données comme enregistrées alors qu'elles ne sont pas encore sur disque. N'utilisez cette valeur que si vous maîtrisez parfaitement le risque de perte de données.
:::

### Templates d'usage

Un template d'usage applique en une seule fois une combinaison prédéfinie des trois paramètres à la partition. Tous les templates règlent *atime* sur `off` et *sync* sur `standard`. Ils ne diffèrent que par le *recordsize* :

| Template | Usage prévu | atime | sync | recordsize |
|----------|-------------|-------|------|------------|
| `Default` | Partage de fichiers généraliste | `off` | `standard` | `131072` (128 Kio) |
| `Virtual machines` | Images de machines virtuelles | `off` | `standard` | `65536` (64 Kio) |
| `Databases` | Stockage de bases de données | `off` | `standard` | `16384` (16 Kio) |
| `File Systems (big files)` | Partage de fichiers volumineux (images, vidéos, streaming) | `off` | `standard` | `1048576` (1 Mio) |

Si aucune de ces combinaisons ne correspond à votre usage, définissez chaque valeur vous-même avec l'option `Custom` (espace client) ou les paramètres personnalisés (API).

### Modifier les paramètres ZFS d'une partition

La modification est appliquée à l'ensemble de la partition par une tâche asynchrone.

<Tabs>
<Tab label="Espace client OVHcloud">

Une fois votre service NAS-HA sélectionné, ouvrez l'onglet <code className="action">Partitions</code>.

Dans le tableau des partitions, cliquez sur le bouton <code className="action">...</code> sur la ligne de la partition concernée, puis sur <code className="action">Paramétrer l'usage (ZFS)</code>. La fenêtre <code className="action">Modifier les paramètres</code> s'ouvre.

**Pour appliquer un template d'usage :**

1. Dans la liste déroulante <code className="action">Sélectionner le template</code>, sélectionnez l'un des templates : <code className="action">Default</code>, <code className="action">Virtual machines</code>, <code className="action">Databases</code> ou <code className="action">File Systems (big files)</code>.
2. Cliquez sur <code className="action">Modifier les paramètres</code> pour valider.

**Pour définir des valeurs personnalisées :**

1. Dans la liste déroulante <code className="action">Sélectionner le template</code>, sélectionnez <code className="action">Custom</code>. Les champs <code className="action">Mise à jour des temps d'accès (atime)</code>, <code className="action">ZFS recordsize</code> et <code className="action">Sync</code> s'affichent, renseignés avec les valeurs actuelles de la partition.
2. Ajustez les valeurs nécessaires : la case <code className="action">Désactiver</code> pour *atime*, une valeur de la liste déroulante <code className="action">ZFS recordsize</code> et l'une des options <code className="action">Always</code>, <code className="action">Disabled</code> ou <code className="action">Standard</code> pour *sync*. Les valeurs par défaut sont signalées par la mention **(Défaut)**.
3. Cliquez sur <code className="action">Modifier les paramètres</code> pour valider.

Une notification vous informe une fois les paramètres ZFS de la partition mis à jour.

</Tab>
<Tab label="API OVHcloud">

Toutes les routes ci-dessous se trouvent dans la <ApiLink section="/dedicated/nasha">section */dedicated/nasha*</ApiLink> de la console API.

Pour récupérer le nom de votre service et de vos partitions, utilisez les routes suivantes :

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha"} />

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha/\{serviceName\}/partition"} />

Pour modifier les paramètres ZFS d'une partition, utilisez la route suivante :

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/options"} />

| Paramètre | Requis | Description |
|-----------|--------|-------------|
| `serviceName` | Oui | Le nom interne de votre service NAS-HA |
| `partitionName` | Oui | Nom de la partition |
| `templateName` |  | Template d'usage à appliquer : `Default`, `Virtual machines`, `Databases` ou `File Systems (big files)` |
| `atime` |  | Mise à jour des temps d'accès : `off` (par défaut) ou `on` |
| `recordsize` |  | Taille de bloc maximale, en octets : `4096`, `8192`, `16384`, `32768`, `65536`, `131072` (par défaut) ou `1048576` |
| `sync` |  | Synchronisation des écritures : `standard` (par défaut), `always` ou `disabled` |

Pour appliquer un template, envoyez uniquement le paramètre `templateName`. Par exemple, pour une partition hébergeant une base de données :

```json
{
  "templateName": "Databases"
}
```

Pour définir des valeurs personnalisées, envoyez plutôt les paramètres `atime`, `recordsize` et `sync`, sans `templateName` :

```json
{
  "atime": "off",
  "recordsize": "65536",
  "sync": "standard"
}
```

L'appel renvoie une tâche. Vous pouvez suivre sa progression avec la route suivante :

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha/\{serviceName\}/task/\{taskId\}"} />

</Tab>

### Vérifier les paramètres ZFS d'une partition

Pour vérifier les paramètres appliqués à une partition, utilisez la route API suivante :

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/options"} />

La réponse contient les valeurs actuelles de `atime`, `recordsize` et `sync`, ainsi que le champ `templateName`, qui indique le nom du template appliqué à la partition, le cas échéant.
