## Objectif

Monter un volume NAS-HA depuis une instance Public Cloud via le réseau privé vRack.

Cela garantit que tout le trafic de données reste sur le réseau privé, sans exposition à Internet.

:::info
Le volume NAS-HA et l'instance Public Cloud doivent se trouver dans la même région (par exemple RBX, GRA ou SBG), car les réseaux privés OpenStack sont régionaux.

:::


## Prérequis

- Disposer d'un [service NAS-HA](/links/storage/nas-ha) dans votre compte OVHcloud.
- Disposer d'une [instance OVHcloud Public Cloud](/guides/public-cloud/compute/getting-started) dans la même région.
- Disposer d'un [réseau privé vRack](/guides/public-cloud/network-services/vrack) actif dans la même région.

## Vue d'ensemble

Le diagramme ci-dessous illustre comment un volume NAS-HA se connecte à une instance Public Cloud via le réseau privé vRack.

<img className="thumbnail" alt="Schéma d'un volume NAS-HA connecté à des instances Public Cloud via vRack Services" src="/images/storage-and-backup/file-storage/ha-nas/nas-pci-connection-via-vrack/architecture.png" loading="lazy" />

1. Correspondance critique — VLAN ID

    L'identifiant VLAN (par exemple : `1900`) doit être strictement identique à la fois dans le réseau privé du Public Cloud et dans la configuration du vRack Services.

2. Correspondance critique — Sous-réseau (CIDR)

    Le CIDR du sous-réseau (par exemple : `10.235.0.0/24`) doit également correspondre entre les deux services pour qu'ils fonctionnent au sein du même réseau logique dans le vRack.

3. Information — Plage d'adresses de service

    La plage d'adresses de service (par exemple : `10.235.0.240/28`) est un sous-ensemble réservé du sous-réseau principal. Ces adresses IP sont exclusivement utilisées par les points de terminaison du service NAS-HA (par exemple : `10.235.0.241`) et ne doivent pas être attribuées à des instances.

4. Sécurité — Règle ACL

    La liste de contrôle d'accès (ACL) du volume NAS-HA doit autoriser explicitement l'adresse IP privée de toute instance nécessitant un accès (par exemple : `10.235.0.15`).

5. Concept — vRack Services

    vRack Services agit comme un pont réseau sécurisé, permettant à des services managés tels que le NAS-HA situés en dehors de votre projet Public Cloud de se connecter de manière transparente à votre réseau privé vRack.

## En pratique

### Étape 1 - Associer le projet Public Cloud au vRack

Avant de déployer votre volume NAS-HA via un réseau privé vRack, associez d'abord votre projet Public Cloud à un vRack.

Cette association permet la mise en réseau privé entre vos instances Public Cloud et les services managés par OVHcloud tels que le NAS-HA.

Suivez l'**étape 1 : activer et gérer un vRack** de notre guide « [Configuration du vRack Public Cloud](/guides/public-cloud/network-services/vrack) ».

### Étape 2 - Créer un réseau privé dans votre projet Public Cloud <a name="step2"></a>

Pour connecter votre instance Public Cloud à un volume NAS-HA via vRack, provisionnez d'abord un réseau privé dédié dans votre projet.

Ce réseau isolé permet une communication sécurisée entre vos instances et les ressources de stockage OVHcloud via l'architecture vRack.

Suivez l'**étape 2 : créer un réseau privé dans le vRack** de notre guide « [Configuration du vRack Public Cloud](/guides/public-cloud/network-services/vrack) ».

### Étape 3 — Démarrer l'instance sur le réseau privé

Déployez votre instance Public Cloud dans le réseau privé que vous avez créé. Assurez-vous qu'elle est connectée au bon sous-réseau pour permettre une communication sécurisée via le vRack.

Suivez l'**étape 3 : intégrer une instance dans le vRack** de notre guide « [Configuration du vRack Public Cloud](/guides/public-cloud/network-services/vrack) ».

Assurez-vous qu'une adresse IP est attribuée à l'instance dans le sous-réseau sélectionné (par exemple : `10.235.0.15`).

### Étape 4 - Créer une ressource vRack Service pour NAS-HA

Il existe deux méthodes pour créer une ressource vRack Service pour votre volume NAS-HA.

Ces deux méthodes atteignent le même objectif : connecter en toute sécurité votre service NAS-HA à votre vRack et à vos instances Public Cloud.

<details>

<summary>Première méthode : création via vRack Services</summary>


Une ressource vRack Service agit comme un adaptateur réseau, reliant des services managés comme le NAS-HA à votre vRack et à son sous-réseau privé.

Pour des instructions détaillées, consultez notre guide : [vRack Services - Exposer un service managé sur votre vRack](/guides/network/vrack-services/global).

1. Dans la console OVHcloud, ouvrez <code className="action">Bare Metal Cloud</code>, puis cliquez sur <code className="action">vRack Services</code> sous **Réseau** dans le menu de gauche.

2. Cliquez sur <code className="action">Commander un vRack Service</code>.

3. Sélectionnez la même **Région** que celle de votre vRack, de votre instance Public Cloud et de votre service NAS-HA. Cliquez ensuite sur <code className="action">Commander un vRack Service</code>. <a name="step4-a-region-selection"></a>

4. Cliquez sur <code className="action">Non merci, j'ai déjà un vRack</code>, cochez la case pour accepter les conditions générales, puis cliquez sur <code className="action">Confirmer</code>.

5. Localisez votre nouveau vRack Services dans la liste et cliquez sur son nom.

6. Configurez le vRack Services comme suit :

    - vRack : dans la tuile **Informations générales** de l'onglet <code className="action">Vue d'ensemble</code>, cliquez sur <code className="action">Associer un vRack</code>, sélectionnez le même vRack que celui utilisé pour votre projet Public Cloud, puis cliquez sur <code className="action">Associer</code>.

    - Créez un sous-réseau : dans l'onglet <code className="action">Subnets</code>, cliquez sur <code className="action">Ajouter un subnet</code> et remplissez le formulaire.

        :::info
        Assurez-vous que le CIDR correspond à votre réseau privé Public Cloud.

        :::


        - **CIDR** : par exemple, `10.235.0.0/24`.
        - **Plage de service** : par exemple, `10.235.0.240/28`.
            - Sous-ensemble réservé du sous-réseau privé pour attribuer des adresses IP aux services NAS-HA managés dans le vRack.
        - **VLAN** : sélectionnez <code className="action">Utiliser un VLAN</code> et renseignez le même **Numéro de VLAN** que celui de votre réseau privé Public Cloud (voir [Étape 2](#step2)).
        - Cliquez sur <code className="action">Ajouter un subnet</code>.

    - Créez un Service Endpoint : dans l'onglet <code className="action">Endpoints</code>, cliquez sur <code className="action">Créer un endpoint</code>. Sélectionnez <code className="action">NAS-HA</code> comme **Type de service**, sélectionnez votre service NAS-HA dans **Service managé** ainsi que votre **Sous-réseau**, puis cliquez sur <code className="action">Créer un endpoint</code>.

</details>


<details>

<summary>Seconde méthode : création via la section NAS-HA</summary>


1. Cliquez sur le nom de votre service NAS-HA dans la liste.

2. Dans la tuile **Configuration du réseau** de l'onglet <code className="action">Vue d'ensemble</code>, cliquez sur <code className="action">Configurer le réseau</code>.

3. Sélectionnez votre vRack dans le champ **vRack**.

4. Si aucun vRack Services n'a été créé, cliquez sur <code className="action">Activer vRack Services</code> et suivez la [première méthode : création via vRack Services](#step4-a-region-selection) à partir du point 3.

5. Si vous avez déjà créé un vRack Services, sélectionnez-le dans le champ **vRack Services**, sélectionnez votre **Sous-réseau**, puis cliquez sur <code className="action">Configurer le réseau</code>.

</details>


### Étape 5 — Connecter le volume NAS-HA au vRack

Une fois les étapes précédentes accomplies avec succès, tous les volumes créés dans votre service NAS-HA résident automatiquement dans votre vRack et son sous-réseau dédié, les rendant immédiatement accessibles à vos instances Public Cloud.

### Étape 6 — Configurer le contrôle d'accès (ACL)

Dans l'onglet <code className="action">ACL</code> de votre volume NAS-HA, cliquez sur <code className="action">Ajouter une règle</code> :

- Dans **Adresse IP**, ajoutez l'adresse IP ou la plage CIDR autorisée à monter le volume :

    - Pour autoriser une instance unique, renseignez l'adresse IP de l'instance, par exemple : `10.235.0.15`.
    - Pour autoriser toutes les instances du sous-réseau, renseignez l'adresse du sous-réseau, par exemple : `10.235.0.0/24`.

- Définissez le **Niveau d'accès** souhaité : <code className="action">Lecture/Écriture</code> ou <code className="action">Lecture seule</code>, puis cliquez sur <code className="action">Ajouter une règle</code>.

:::info
**Recommandation :** Utilisez des adresses IP individuelles autant que possible pour renforcer la sécurité.

:::


Après avoir appliqué les ACL, vérifiez la connectivité réseau depuis votre instance Public Cloud :

```bash
ping <IP-DE-VOTRE-SERVICE-NAS-HA>
```

### Étape 7 — Monter le volume

Vous pouvez monter votre volume NAS-HA via NFS ou via CIFS. Vous avez besoin des valeurs suivantes :

| Argument | Description |
|---|---|
| `<IP-DE-VOTRE-SERVICE-NAS-HA>` | L'adresse IP de votre Service Endpoint, affichée dans la tuile **Configuration du réseau** de votre service NAS-HA (par exemple : `10.235.0.241`) |
| `<NFS_PATH>` | Le chemin d'accès au volume, composé du nom du service et du nom de la partition (par exemple : `zpool-123456/partition01`) |
| `<CIFS_PATH>` | Le chemin d'accès au volume, composé du nom du service et du nom de la partition séparés par `_` (par exemple : `zpool-123456_partition01`) |

:::warning
L'utilisateur NFS est `root` et l'utilisateur SMB/CIFS est `nobody`. Toute modification de droits effectuée par l'un de ces utilisateurs peut générer des conflits avec les droits définis par l'autre protocole.

:::


#### Montage via NFS

1. Installez le client NFS sur votre instance Public Cloud :

    ```bash
    sudo apt install -y nfs-common
    ```

2. Montez le volume NAS-HA :

    ```bash
    sudo mkdir -p /mnt/nas-ha
    sudo mount -t nfs <IP-DE-VOTRE-SERVICE-NAS-HA>:/<NFS_PATH> /mnt/nas-ha
    df -h /mnt/nas-ha
    ```

    **Exemple :**

    ```bash
    sudo mount -t nfs 10.235.0.241:/zpool-123456/partition01 /mnt/nas-ha
    ```

Le NAS-HA prend en charge NFSv3 et NFSv4. Si aucune version n'est précisée, votre client NFS utilise la version la plus récente qu'il prend en charge. Pour forcer une version, ajoutez l'option `-o vers=3` (ou `vers=4`, `vers=4.1`, `vers=4.2`). Pour plus d'informations, et pour les instructions concernant les autres systèmes d'exploitation, consultez notre guide « [Montage d'un NAS-HA via partage NFS](/guides/storage-and-backup/file-storage/ha-nas/nas-nfs) ».

#### Montage via CIFS

**Depuis une instance Linux**

1. Installez les utilitaires CIFS sur votre instance Public Cloud :

    ```bash
    sudo apt install -y cifs-utils
    ```

2. Montez le volume NAS-HA :

    ```bash
    sudo mkdir -p /mnt/nas-ha
    sudo mount -t cifs -o uid=root,gid=100,dir_mode=0700,username=root,password= //<IP-DE-VOTRE-SERVICE-NAS-HA>/<CIFS_PATH> /mnt/nas-ha
    ```

**Depuis une instance Windows**

Ouvrez **Windows PowerShell** et exécutez la commande suivante :

```bash
net use z: \\<IP-DE-VOTRE-SERVICE-NAS-HA>\<CIFS_PATH>
```

**Exemple :**

```bash
net use z: \\10.235.0.241\zpool-123456_partition01
```

Pour plus d'informations, notamment pour corriger les erreurs Windows `System error 1272` et `System error 3227320323`, consultez notre guide « [Monter un NAS-HA via un partage CIFS](/guides/storage-and-backup/file-storage/ha-nas/nas-cifs) ».

### Étape 8 — Activer le montage NFS automatique au démarrage (facultatif)

Pour monter automatiquement votre volume NAS-HA via NFS au démarrage, ajoutez l'entrée suivante dans le fichier `/etc/fstab` :

```bash
<IP-DE-VOTRE-SERVICE-NAS-HA>:/<NFS_PATH> /mnt/nas-ha nfs rw 0 0
```

Testez ensuite la configuration :

```bash
sudo umount /mnt/nas-ha
sudo mount -a
```

Si aucune erreur ne se produit, le volume NAS-HA sera désormais monté automatiquement au démarrage.

## Résultat attendu

- L'instance peut accéder au volume NAS-HA via l'`<IP-DE-VOTRE-SERVICE-NAS-HA>`.
- Toute la communication se déroule en privé au sein du vRack.
- Le montage NFS ou CIFS est entièrement fonctionnel, et le montage NFS est persistant après les redémarrages.

## Dépannage

| Symptôme                           | Cause probable                                                | Résolution                                                                                                                                                |
| ---------------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mount.nfs: No route to host`        | Instance et NAS-HA pas dans la même région, ou VLAN ID incorrect. | Vérifiez que l'instance, le NAS-HA et le vRack Services sont dans la même région. Recréez le vRack Service en utilisant le même VLAN ID que le réseau privé. |
| `mount.nfs: access denied by server` | ACL NAS-HA manquantes ou incorrectes.                             | Ajoutez l'IP de l'instance (par exemple : `10.235.0.x`) ou le sous-réseau (par exemple : `10.235.0.0/24`) avec l'accès en Lecture/Écriture.                |
| La commande `mount` reste bloquée indéfiniment   | Version NFS incorrecte ou point de terminaison non réactif.    | Utilisez : `-o vers=3,timeo=600,retrans=2` pour forcer NFSv3 et définir des délais d'attente.                                                             |
| Le montage réussit, mais sans lecture ni écriture   | ACL ou permissions POSIX trop restrictives.                    | Ajustez les ACL ou mettez à jour les permissions au niveau du volume.                                                                                     |
| Le montage fonctionne, mais pas après un redémarrage  | Aucune entrée dans `/etc/fstab`.                               | Ajoutez : `<IP-DE-VOTRE-SERVICE-NAS-HA>:/<NFS_PATH> /mnt/nas-ha nfs rw 0 0`.                                                             | 
| vRack Services affiche « Inactive »    | Service non encore provisionné.                                | Attendez la fin du provisionnement, ou reconfigurez-le depuis la tuile **Configuration du réseau** de votre service NAS-HA.                                                           |
