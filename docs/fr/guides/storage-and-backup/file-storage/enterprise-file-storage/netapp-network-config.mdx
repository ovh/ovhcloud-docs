## Objectif

Les services Enterprise File Storage peuvent être gérés via [les API OVHcloud](/guides/storage-and-backup/file-storage/enterprise-file-storage/netapp-quick-start) ou depuis la console OVHcloud.

Découvrez dans ce guide comment rattacher votre service Enterprise File Storage à un [réseau privé vRack](https://www.ovhcloud.com/fr/network/vrack/), via la technologie vRack Services et la fonctionnalité Service Endpoint.

:::info
Pour plus d’informations concernant vRack Services, consultez [cette page](/guides/network/vrack-services/global).

:::


## Prérequis

- Avoir un service [Enterprise File Storage](https://www.ovhcloud.com/fr/storage-solutions/enterprise-file-storage/) dans votre compte OVHcloud.

## Overview

<img className="thumbnail" alt="Schéma global" src="/images/storage-and-backup/file-storage/enterprise-file-storage/netapp-network-config/global_schema_20240410.png" loading="lazy" />

Enterprise File Storage est un service exposé via une adresse IP sur le vRack. L’attribution de l’IP de votre service se fait en trois étapes :

1. Sélection ou création d’un vRack
2. Sélection ou création d'un vRack Services
3. Sélection ou création d’un sous-réseau

[[cpnav:storage-enterprise-file-storage]]

## En pratique <a name="instructions"></a>

Cliquez sur le nom de votre service dans la liste.

Par défaut, le service n’est pas rattaché à un réseau privé : dans la tuile **Configuration du réseau** de l'onglet <code className="action">Vue d'ensemble</code>, son **Statut** est **Configuration utilisateur requise**.

Cette étape est nécessaire avant même de pouvoir créer vos volumes et/ou de paramétrer vos ACLs.

Cliquez sur <code className="action">Configurer le réseau</code> dans cette tuile pour configurer votre Service Endpoint et ainsi permettre à vos volumes d’être consommés depuis votre réseau privé. La page **Configurer le réseau** s'ouvre.

### Etape 1 - Sélection ou création d’un vRack

Pour activer votre vRack Services, vous devez avoir un vRack. Le vRack est un service gratuit. Sélectionnez votre vRack dans le champ **vRack**. Si vous n'en avez pas à cette étape, il est possible d'en commander un via le lien <code className="action">Commander un vRack</code> situé sous ce champ.

:::info
Veuillez noter que la création de vRack Services, de Sous-réseaux ou de Service Endpoints sur un vRack en production **n'entraîne aucune interruption de service**.
Par conséquent, vous pouvez suivre les étapes 2 et 3 de ce guide en toute sécurité dans un environnement de production.

:::


### Etape 2 - Sélection ou création d'un vRack Services

Sélectionnez un vRack Services dans le champ **vRack Services**. Seuls les vRack Services éligibles pour votre service sont proposés. Si vous n'avez pas de vRack Services, cliquez sur le lien <code className="action">Activer vRack Services</code>, vous serez alors redirigé vers les pages de vRack Services. Pour plus d'informations sur la création d'un vRack Services, vous pouvez consulter [cette page](/guides/network/vrack-services/global).

Une fois votre vRack Services activé, revenez sur la page **Configurer le réseau** de votre service pour terminer la configuration.

### Etape 3 - Sélection ou création d’un sous-réseau

Sélectionnez dans le champ **Sous-réseau** le sous-réseau sur lequel vous voulez exposer votre service Enterprise File Storage. Si votre sous-réseau n’existe pas encore, il est nécessaire de le créer : cliquez sur le lien <code className="action">Créer un sous-réseau</code>, ou rendez-vous dans l'onglet <code className="action">Subnets</code> de votre vRack Services. Pour plus d'informations sur la création d'un sous-réseau, vous pouvez consulter [cette page](/guides/network/vrack-services/global).

Une fois ces trois étapes terminées, cliquez sur le bouton <code className="action">Configurer le réseau</code>. Vous allez être redirigé vers l'onglet <code className="action">Vue d'ensemble</code> de votre service Enterprise File Storage et pourrez suivre le déploiement de votre Service Endpoint dans la tuile **Configuration du réseau**.

Après quelques instants, le **Statut** passe de **En cours de déploiement…** à **Déployé** : votre nouveau Service Endpoint est configuré et disponible. La tuile affiche son **vRack**, son **vRack Services**, son **Sous-réseau**, sa **Plage de service** et son **IP du point de terminaison**.

Vous pouvez à présent suivre les guides ci-dessous pour créer et gérer vos volumes, créer et gérer vos snapshots ainsi que vos ACLs.

### Tests de connectivité réseau à votre Service Endpoint depuis un client NFS

:::info
**Prérequis :**

- Votre client NFS doit avoir une interface réseau configurée dans le même sous-réseau que votre vRack Services et doit être dans le même VLAN que celui-ci. Le sous-réseau du vRack Services n'est pas routable et nécessite un sous-réseau de type CIDR 24  (x.x.x.x/24 ou x.x.x.x/255.255.255.0).
- Si ce n'est pas possible, vous pouvez utiliser une passerelle qui fera une translation d'adresse et de port vers celui-ci mais il vous faudra contacter le [support OVHcloud](https://help.ovhcloud.com/csm?id=csm_get_help). Sans cela vous ne pourrez pas monter vos partages NFS.
- L'adresse IP de votre Service Endpoint est dans un sous-ensemble en CIDR 27, 28 ou 29 de votre sous-réseau vRack Services.
- L'adresse IP de votre Service Endpoint doit être unique dans votre sous-réseau et doit être exclue de votre serveur DHCP si vous en utilisez un.
- Exemple : sous-réseau vRack Services 10.0.0.0/24 - Service Endpoint 10.0.0.16/29  - Votre service sera donc accessible à l'adresse IP 10.0.0.16 dans le sous-réseau 10.0.0.0/24.

:::


- La commande **arping IP_Endpoint** ne doit retourner qu'une seule adresse MAC.
- La commande **traceroute -T IP_Endpoint -p 2049** ne doit pas retourner d'erreur.
- La commande  **nmap -sV -T4 -p111,635,2049,4045,4046 IP_Endpoint** doit retourner des ports dans l'état OPEN (indispensable pour le bon fonctionnement de NFSv3).
