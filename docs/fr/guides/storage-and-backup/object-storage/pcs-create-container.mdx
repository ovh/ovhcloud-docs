## Objectif

L'offre Object Storage Swift pour Public Cloud propose une solution de stockage illimité avec une facturation simple et adaptée à vos besoins. Les conteneurs peuvent être configurés pour différents cas d'usage :

- Hébergement statique (site web statique)
- Hébergement privé (par exemple, stockage de données personnelles)
- Hébergement public (contenu accessible publiquement)
- Stockage à froid (archivage)

**Ce guide explique comment créer et gérer vos conteneurs Object Storage Swift.**

## Prérequis

- Posséder un [projet Public Cloud](/guides/public-cloud/cross-functional/create-a-public-cloud-project) dans votre compte OVHcloud

Selon l'outil que vous souhaitez utiliser :

- **API Swift S3<sup>1</sup>** : disposer d'un environnement [préparé pour l'API OpenStack](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment) avec `python-openstackclient` et `awscli` installés
- **Client Swift** : disposer d'un environnement [préparé pour l'API OpenStack](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment) avec `python-swiftclient` installé
- **OVHcloud CLI** : disposer de l'[OVHcloud CLI](/guides/manage-and-operate/cli/getting-started) installé et configuré

## En pratique

### Préparation

<Tabs>
  <Tab label="Via l'espace client OVHcloud">
    Connectez-vous à votre espace client OVHcloud et ouvrez <code className="action">Object Storage</code> dans le menu de gauche sous **Storage & backup**.
  </Tab>
  <Tab label="Via l'API Swift S3">
    **Définir les variables d'environnement OpenStack**

    ```bash
    source <user_name>-openrc.sh
    Please enter your OpenStack Password for project <project_name> as user <user_name>:
    ```

    **Installer le client OpenStack si nécessaire**

    ```bash
    pip install python-openstackclient
    ```

    Référence des commandes du client OpenStack : [docs.openstack.org](https://docs.openstack.org/python-openstackclient/latest/)

    **Créer des identifiants EC2**

    Les tokens S3 nécessitent deux paramètres — **access** et **secret** — générés depuis Keystone :

    ```bash
    openstack ec2 credentials create
    +------------+----------------------------------------------------------------------------------------------------------------------------+
    | Field      | Value                                                                                                                      |
    +------------+----------------------------------------------------------------------------------------------------------------------------+
    | access     | 5a4d8b8d88104123a862c527ede5a3d3                                                                                           |
    | links      | {u'self': u'https://auth.cloud.ovh.net/v3/users/d74d05ff121b44bea9216495e7f0df61/credentials/OS-EC2/5a4d8b8d88104123a862c527ede5a3d3'} |
    | project_id | 20e124b71be141299e111ec26b1892fa                                                                                           |
    | secret     | 925d5fcfcd9f436d8ffcb20548cc53a2                                                                                           |
    | trust_id   | None                                                                                                                       |
    | user_id    | d74d05ff121b44bea9216495e7f0df61                                                                                           |
    +------------+----------------------------------------------------------------------------------------------------------------------------+
    ```

    **Configurer le client AWS**

    Installez `awscli` :

    <details>
    <summary>Package Python</summary>

    ```bash
    pip install awscli
    ```

    </details>

    <details>
    <summary>OS Debian</summary>

    ```bash
    sudo apt install awscli
    ```

    </details>

    <details>
    <summary>OS RHEL</summary>

    ```bash
    sudo yum install awscli
    ```

    </details>

    Puis configurez-le avec les identifiants EC2 générés précédemment :

    <details>
    <summary>Via la CLI</summary>

    ```bash
    aws configure
    ```

    Suivez les instructions et saisissez votre clé d'accès et votre clé secrète lorsque cela vous est demandé.

    </details>

    <details>
    <summary>Via les fichiers de configuration</summary>

    ```bash
    cat ~/.aws/credentials
    ```

    ```text
    [default]
    aws_access_key_id = <access_key>
    aws_secret_access_key = <secret_key>
    ```

    ```bash
    cat ~/.aws/config
    ```

    ```text
    [plugins]
    endpoint = awscli_plugin_endpoint
    [default]
    region = <region>
    s3 =
      endpoint_url = https://s3.<region>.cloud.ovh.net
      signature_version = s3v4
    s3api =
      endpoint_url = https://s3.<region>.cloud.ovh.net
    ```

    </details>

    :::info
    Les accès de type *virtual-hosted* et *path-style* sont tous deux pris en charge ; le type *virtual-hosted* est recommandé, car le *path-style* est obsolète depuis le 30 septembre 2020.
    :::
  </Tab>
  <Tab label="Via le client Swift">
    Définissez les variables d'environnement OpenStack :

    ```bash
    source <user_name>-openrc.sh
    ```

    Vérifiez votre configuration :

    ```bash
    swift --help
    ```

    Pour la liste complète des commandes Swift, consultez la [documentation OpenStack](https://docs.openstack.org/python-swiftclient/latest/cli/index.html).
  </Tab>
  <Tab label="Via l'OVHcloud CLI">
    Assurez-vous que l'OVHcloud CLI est installé et configuré avec vos identifiants. Pour les instructions de configuration, consultez la [documentation OVHcloud CLI](/guides/manage-and-operate/cli/getting-started).
  </Tab>
</Tabs>

### Créer un conteneur

:::info
Lors de l'utilisation de l'**API Swift S3**, les noms de buckets doivent respecter les règles suivantes :

- Entre 3 et 63 caractères
- Uniquement des lettres minuscules, des chiffres, des points et des tirets
- Doit commencer par une lettre minuscule ou un chiffre
- Pas de caractères de soulignement, pas de points consécutifs, pas de tirets adjacents à des points
- Ne doit pas être formaté comme une adresse IP (ex. `198.51.100.24`)

:::

<Tabs>
  <Tab label="Via l'espace client OVHcloud">
    Cliquez sur <code className="action">Créer un conteneur d'objets</code>.

    Remplissez le formulaire de création :

    - **Nom du conteneur** : Saisissez un nom pour votre conteneur.
    - **Type de conteneur** : Sélectionnez <code className="action">Swift API</code>.
    - **Localisation** : Choisissez un type de zone de disponibilité (Région 3-AZ, Région 1-AZ ou Local Zone), puis sélectionnez une zone géographique.
    - **Type de conteneur** : Choisissez le type d'accès — **Hébergement statique**, **Privé** ou **Public**.

    :::warning
    Si vous souhaitez lier votre conteneur à un nom de domaine, le nom de votre conteneur ne doit pas contenir `.` ou `_`, et ne doit pas utiliser de majuscules. Pour plus d'informations, consultez le guide « [Lier un conteneur à un nom de domaine](/guides/storage-and-backup/object-storage/pcs-link-domain) ».
    :::

    Vérifiez le panneau récapitulatif, puis cliquez sur <code className="action">Créer</code>.
  </Tab>
  <Tab label="Via l'API Swift S3">
    ```bash
    aws s3 mb s3://<container_name>
    ```

    :::info
    Les buckets S3 ne peuvent être créés que sur la politique PCS (Object Storage).
    :::
  </Tab>
  <Tab label="Via le client Swift">
    Créez le conteneur :

    ```bash
    swift post container1
    ```

    Pour rendre le conteneur accessible publiquement :

    ```bash
    swift post --header "X-Container-Read: .r:*" container1
    ```

    Vérifiez la configuration :

    ```bash
    swift stat container1

    Account: AUTH_b3e26xxxxxxxxxxxxxxxxxxxb0ba29
    Container: container1
    Objects: 0
    Bytes: 0
    Read ACL: .r:*
    Write ACL:
    Sync To:
    Sync Key:
    Accept-Ranges: bytes
    X-Trans-Id: B2210C05:8D93_052711A1:01BB_561CC9DF_1B305:30D7
    X-Storage-Policy: Policy-0
    Connection: close
    X-Timestamp: 1444726875.27475
    Content-Type: text/plain; charset=utf-8
    ```
  </Tab>
  <Tab label="Via l'OVHcloud CLI">
    La création de conteneur n'est pas disponible via l'OVHcloud CLI. Utilisez l'espace client, l'API Swift S3 ou le client Swift à la place.
  </Tab>
</Tabs>

### Lister vos conteneurs

<Tabs>
  <Tab label="Via l'espace client OVHcloud">
    Accédez à <code className="action">Object Storage</code> dans le menu de gauche. Vos conteneurs sont listés sous l'onglet <code className="action">Mes conteneurs</code>.
  </Tab>
  <Tab label="Via l'API Swift S3">
    ```bash
    aws s3 ls
    ```

    :::info
    Si vous avez plusieurs profils configurés, ajoutez `--profile <profile_name>` à la commande.
    :::
  </Tab>
  <Tab label="Via le client Swift">
    ```bash
    swift list
    ```
  </Tab>
  <Tab label="Via l'OVHcloud CLI">
    ```bash
    ovhcloud cloud storage swift list
    ```
  </Tab>
</Tabs>

### Téléverser des objets

<Tabs>
  <Tab label="Via l'espace client OVHcloud">
    Cliquez sur le nom de votre conteneur, puis cliquez sur <code className="action">Ajouter des objets</code> dans l'onglet **Objets**.

    Sélectionnez le fichier à téléverser et cliquez sur <code className="action">Importer</code>.
  </Tab>
  <Tab label="Via l'API Swift S3">
    ```bash
    aws s3 cp /path/to/<object_name> s3://<container_name>/<object_name>
    ```
  </Tab>
  <Tab label="Via le client Swift">
    Téléverser un seul fichier :

    ```bash
    swift upload container1 file.txt
    ```

    Téléverser un dossier entier (un préfixe correspondant au nom du dossier est automatiquement ajouté aux objets) :

    ```bash
    swift upload container1 images/

    images/OVHlogo.png
    images/OVHSummitKeynote.jpg
    ```
  </Tab>
  <Tab label="Via l'OVHcloud CLI">
    Le téléversement d'objets n'est pas disponible via l'OVHcloud CLI. Utilisez l'espace client, l'API Swift S3 ou le client Swift à la place.
  </Tab>
</Tabs>

### Lister les objets d'un conteneur

<Tabs>
  <Tab label="Via l'espace client OVHcloud">
    Cliquez sur le nom de votre conteneur pour visualiser ses objets dans l'onglet **Objets**.
  </Tab>
  <Tab label="Via l'API Swift S3">
    ```bash
    aws s3 ls s3://<container_name>
    ```
  </Tab>
  <Tab label="Via le client Swift">
    ```bash
    swift list container1

    images/OVHSummitKeynote.jpg
    images/OVHlogo.png
    text1.txt
    text2.txt
    text3.txt
    ```

    Filtrer par préfixe :

    ```bash
    swift list container1 --prefix images

    images/OVHSummitKeynote.jpg
    images/OVHlogo.png
    ```

    Si le conteneur est public, les objets sont accessibles directement via URL :

    ```text
    https://storage.gra1.cloud.ovh.net/v1/AUTH_b3e26xxxxxxxxxxxxxxxxxxxb0ba29/container1/images/OVHlogo.png
    ```

    Cette URL est composée d'un endpoint (disponible depuis l'[interface Horizon](/guides/public-cloud/cross-functional/compute-horizon-access-security)), du nom du conteneur et du nom de l'objet (préfixe inclus).
  </Tab>
  <Tab label="Via l'OVHcloud CLI">
    La liste des objets n'est pas disponible via l'OVHcloud CLI. Utilisez l'espace client, l'API Swift S3 ou le client Swift à la place.
  </Tab>
</Tabs>

### Télécharger des objets

<Tabs>
  <Tab label="Via l'espace client OVHcloud">
    Cliquez sur l'icône de téléchargement sur la ligne de l'objet.
  </Tab>
  <Tab label="Via l'API Swift S3">
    ```bash
    aws s3 cp s3://<container_name>/<object_name> .
    ```
  </Tab>
  <Tab label="Via le client Swift">
    Télécharger un seul fichier :

    ```bash
    swift download container1 text1.txt

    text1.txt [auth 0.328s, headers 0.452s, total 0.453s, 0.000 MB/s]
    ```

    Télécharger tous les fichiers avec un préfixe donné :

    ```bash
    swift download container1 --prefix images

    images/OVHlogo.png [auth 0.383s, headers 0.520s, total 0.522s, 0.135 MB/s]
    images/OVHSummitKeynote.jpg [auth 0.371s, headers 0.514s, total 0.559s, 2.657 MB/s]
    ```
  </Tab>
  <Tab label="Via l'OVHcloud CLI">
    Le téléchargement d'objets n'est pas disponible via l'OVHcloud CLI. Utilisez l'espace client, l'API Swift S3 ou le client Swift à la place.
  </Tab>
</Tabs>

### Supprimer des objets et des conteneurs

<Tabs>
  <Tab label="Via l'espace client OVHcloud">
    **Supprimer un objet** : Cliquez sur l'icône de suppression (corbeille) sur la ligne de l'objet et confirmez.

    **Supprimer un conteneur** : Cliquez sur le bouton <code className="action">...</code> sur la ligne du conteneur, puis sélectionnez <code className="action">Supprimer</code> et confirmez.
  </Tab>
  <Tab label="Via l'API Swift S3">
    **Supprimer un objet :**

    ```bash
    aws s3 rm s3://<container_name>/<object_name>
    ```

    **Supprimer un conteneur** (le conteneur doit être vide au préalable) :

    ```bash
    aws s3 rb s3://<container_name>
    ```
  </Tab>
  <Tab label="Via le client Swift">
    **Supprimer un fichier :**

    ```bash
    swift delete container1 text1.txt

    text1.txt
    ```

    Supprimer plusieurs fichiers avec un préfixe :

    ```bash
    swift delete container1 images/*

    images/OVHSummitKeynote.jpg
    images/OVHlogo.png
    ```

    **Supprimer un conteneur** (supprime également tous les objets qu'il contient) :

    ```bash
    swift delete container1

    text2.txt
    text3.txt
    ```
  </Tab>
  <Tab label="Via l'OVHcloud CLI">
    La suppression de conteneurs et d'objets n'est pas disponible via l'OVHcloud CLI. Utilisez l'espace client, l'API Swift S3 ou le client Swift à la place.
  </Tab>
</Tabs>
