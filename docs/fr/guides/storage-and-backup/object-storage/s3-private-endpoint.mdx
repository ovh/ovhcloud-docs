## Objectif

Un **Private Endpoint** permet aux ressources d'un sous-réseau de réseau privé Public Cloud d'accéder à votre Object Storage compatible S3<sup>1</sup> via le réseau OVHcloud, sans Gateway. Votre trafic reste privé, sans connectivité publique nécessaire.

**Ce guide vous explique comment créer un Private Endpoint, y connecter votre client S3 et faire en sorte que vos buckets ne soient accessibles que par ce chemin privé.**

:::info
Private Endpoint est disponible uniquement pour l'Object Storage compatible S3. L'Object Storage basé sur Swift n'est pas pris en charge.
:::

## Prérequis

- Un [projet Public Cloud](/guides/public-cloud/cross-functional/create-a-public-cloud-project) dans votre compte OVHcloud
- Un [réseau privé Public Cloud et un sous-réseau](/guides/public-cloud/network-services/vrack), actifs dans la région où vous souhaitez créer le Private Endpoint, avec une adresse IP libre
- Un [utilisateur et un bucket Object Storage](/guides/storage-and-backup/object-storage/s3-getting-started-with-object-storage)
- Un accès à l'[API OVHcloud](/guides/manage-and-operate/api/first-steps), à l'espace client OVHcloud ou à Terraform

Les clients qui utilisent le Private Endpoint sont simplement des ressources de ce sous-réseau, comme des instances, ou des serveurs Bare Metal connectés via le vRack.

## En pratique

### Fonctionnement

Lorsque vous créez un Private Endpoint, OVHcloud le place dans le sous-réseau de votre choix et lui attribue :

- une adresse IP privée (VIP) dans ce sous-réseau ;
- un nom d'hôte, de la forme `pe-<pe_id>.s3.{region}.endpoint.cloud.ovh.net`.

Vos instances envoient alors leurs requêtes S3 à ce nom d'hôte, au lieu du point de terminaison public d'Object Storage. Vos identifiants (clé d'accès et clé secrète) ne changent pas.

Le trafic est chiffré en TLS de bout en bout, de votre client S3 jusqu'à Object Storage. Le Private Endpoint le transmet sans le déchiffrer.

Un Private Endpoint possède deux identifiants. Veillez à utiliser le bon :

| Identifiant | Exemple | Où le trouver | Utilisé pour |
|---|---|---|---|
| Identifiant du Private Endpoint | `pe-a1b2c3d4` | Dans l'espace client, le champ **ID** de la page de détail du Private Endpoint. Dans l'API, le champ `currentState.endpointId`. Il s'agit aussi de la première partie du nom d'hôte, avant `.s3.` : `pe-` suivi de 8 caractères hexadécimaux générés par OVHcloud, par exemple `pe-a1b2c3d4.s3.gra.endpoint.cloud.ovh.net` | Les politiques d'accès (voir l'étape 5) |
| Identifiant de ressource (UUID) | `5d297126-f4bd-46f9-a4c4-2ffd134121b6` | Le champ `id` de la réponse de l'API | Les appels API uniquement : il s'agit du `{privateEndpointId}` dans les routes |

::::details Utiliser l'API : fonctionnement et routes utilisées dans ce guide

Private Endpoint utilise l'[API v2 OVHcloud](/guides/manage-and-operate/api/apiv2). Au lieu d'exécuter des actions une à une, vous décrivez la configuration souhaitée dans un objet `targetSpec`. OVHcloud l'applique ensuite en arrière-plan. Vous pouvez suivre l'avancement grâce au champ `resourceStatus`, et la liste `currentTasks` indique les opérations en cours.

Les routes utilisées dans ce guide sont les suivantes :

| Méthode | Route | Description |
|---|---|---|
| `GET` | `/v2/publicCloud/project/{projectId}/reference/privateEndpoint/serviceAvailability` | Lister les services et les niveaux de connectivité disponibles |
| `GET` | `/v2/publicCloud/project/{projectId}/privateEndpoint` | Lister les Private Endpoints d'un projet |
| `POST` | `/v2/publicCloud/project/{projectId}/privateEndpoint` | Créer un Private Endpoint |
| `GET` | `/v2/publicCloud/project/{projectId}/privateEndpoint/{privateEndpointId}` | Afficher le détail d'un Private Endpoint |
| `PUT` | `/v2/publicCloud/project/{projectId}/privateEndpoint/{privateEndpointId}` | Renommer un Private Endpoint ou modifier sa description |
| `DELETE` | `/v2/publicCloud/project/{projectId}/privateEndpoint/{privateEndpointId}` | Supprimer un Private Endpoint |
| `GET` | `/v2/publicCloud/project/{projectId}/reference/privateEndpoint/serviceAvailability/{name}` | Afficher la disponibilité d'un service |

:::info
Aucun outil local n'est nécessaire pour exécuter ces appels : vous pouvez les lancer directement depuis la [console API OVHcloud](https://api.eu.ovhcloud.com/console/?section=%2FpublicCloud&branch=v2#post-/publicCloud/project/-projectId-/privateEndpoint). Ouvrez la route, renseignez `projectId` et le corps de la requête, puis cliquez sur <code className="action">Execute</code>. De la même manière, vous pouvez suivre la création de votre Private Endpoint avec la route `GET`, et lister les noms de services et niveaux de connectivité disponibles avec la route `serviceAvailability`.

### Étape 1 - Choisir un niveau de connectivité

Chaque Private Endpoint dispose d'un niveau de connectivité, qui détermine sa bande passante :

| Niveau | Bande passante | Recommandé pour |
|---|---|---|
| S | 500 Mbit/s | Charges de travail à débit modéré (niveau par défaut) |
| M | 2 Gbit/s | Charges de travail à débit plus élevé |
| L | 4 Gbit/s | Transferts de données importants : sauvegardes, analytique, pipelines de machine learning |

Les valeurs de bande passante s'appliquent à la Beta et peuvent évoluer.

:::warning
**Limitations de la Beta.** Pendant la Beta :

- seul le niveau **S** est disponible ;
- vous pouvez créer jusqu'à **2 Private Endpoints par projet**. Si vous avez besoin de davantage, contactez-nous ;
- les Private Endpoints sont **gratuits**, et aucun SLA ne s'applique ;
- Private Endpoint est disponible dans les régions suivantes : GRA, RBX, SBG, EU-WEST-PAR, EU-SOUTH-MIL, LIM et BHS.
:::

<Tabs>
<Tab label="Via l'espace client OVHcloud">

Vous choisissez le niveau lors de la création du Private Endpoint (voir l'étape 2), dans la section **Service & connectivity tier** du formulaire de création :

1. Dans **Service**, sélectionnez `S3`. La liste affiche les services disponibles dans la région du réseau privé sélectionné.
2. Dans **Connectivity tier**, sélectionnez le niveau. Les niveaux sont présentés sous forme de tailles : pendant la Beta, sélectionnez **Size S**.

</Tab>
<Tab label="Via l'API OVHcloud">

Indiquez le niveau dans `service.tier` lors de la création du Private Endpoint (voir l'étape 2), en majuscules : `S`, `M` ou `L`.

Pour connaître les services et niveaux disponibles dans chaque région, utilisez l'appel suivant :

```bash
GET /v2/publicCloud/project/{projectId}/reference/privateEndpoint/serviceAvailability
```

Pour n'afficher que l'Object Storage, ajoutez `/s3` à la fin de la route.

Chaque service liste ses niveaux disponibles dans `tiers[]`. Pour chaque niveau, la réponse indique :

- `name` : la valeur à indiquer dans `service.tier` ;
- `bandwidth` : la bande passante du niveau, en Mbit/s ;
- `location` : la région où le niveau est disponible (`region`, et `availabilityZone` pour les régions comportant plusieurs zones de disponibilité) ;
- `port` et `transport` : le port et le protocole utilisés via le Private Endpoint.

La disponibilité est indiquée par niveau et par région : recherchez votre région dans la réponse avant de choisir un niveau. Par exemple :

```json
[
  {
    "name": "s3",
    "description": "OVHcloud Object Storage",
    "tiers": [
      { "name": "S", "bandwidth": 500, "location": { "region": "GRA11" }, "port": 443, "transport": "TCP" }
    ]
  }
]
```

:::info
Les régions ne portent pas le même nom partout. Dans l'API (`location.region`), utilisez le nom de la région Public Cloud, par exemple `GRA11`. Dans le nom d'hôte et dans le paramètre `region` de votre client S3, utilisez la région Object Storage, par exemple `gra`.
:::

</Tab>

### Étape 2 - Créer le Private Endpoint

Avant de commencer, décidez comment le nom d'hôte du Private Endpoint sera résolu. Vous faites ce choix lors de la création du Private Endpoint, avec l'option **Public DNS** (`publicDnsEnabled` dans l'API) :

| Votre situation | Option Public DNS | Ce que vous faites ensuite |
|---|---|---|
| Vos instances peuvent utiliser un résolveur DNS public | **Activée** | Rien : OVHcloud publie et gère l'enregistrement DNS pour vous. L'enregistrement pointe vers une adresse IP privée, joignable uniquement depuis votre réseau privé. |
| Vos instances ne peuvent pas utiliser de résolveur DNS public, ou vous ne souhaitez pas que l'enregistrement soit public | **Désactivée** (par défaut) | Vous gérez vous-même la résolution, par exemple dans une zone DNS privée. |

Le détail de chaque option est donné à l'étape 3.

<Tabs>
<Tab label="Via l'espace client OVHcloud">

1. Ouvrez <code className="action">Public Cloud</code> et sélectionnez votre projet, puis ouvrez <code className="action">Network</code> > <code className="action">Private Endpoints</code>.
2. Cliquez sur <code className="action">Create a Private Endpoint</code>.
3. Dans la section **Name**, saisissez un nom pour votre Private Endpoint.
4. Dans la section **Connectivity** :
    - sélectionnez votre **Private Network**. La région du Private Endpoint est celle de ce réseau privé ;
    - sélectionnez le **Subnet** dans lequel placer le Private Endpoint ;
    - si vous le souhaitez, saisissez une adresse IP de votre choix dans **VIP selection**. Si vous laissez ce champ vide, une adresse du sous-réseau est attribuée automatiquement.
5. Dans la section **Service & connectivity tier**, sélectionnez le service `S3` et le niveau de connectivité (voir l'étape 1). Pendant la Beta, seul **Size S** est disponible.
6. Dans la section **Public DNS**, activez l'option ou laissez-la désactivée, selon votre choix ci-dessus.
7. Si vous le souhaitez, ajoutez une **Description**.
8. Vérifiez le récapitulatif à droite, puis cliquez sur <code className="action">Create a Private Endpoint</code>.

Le Private Endpoint est créé en arrière-plan et apparaît sur la page <code className="action">Private Endpoints</code>. Il est prêt lorsque son statut est `READY`.

Cliquez sur son nom pour ouvrir sa page de détail, et notez les valeurs suivantes : vous en aurez besoin dans les étapes suivantes.

- **ID**, dans la section *General information* : l'identifiant du Private Endpoint (`pe-…`) ;
- **Endpoint VIP**, dans la section *Connection details* : son adresse IP dans le sous-réseau ;
- **Hostname**, dans la section *Connection details*.

Chaque valeur dispose d'un bouton de copie.

</Tab>
<Tab label="Via l'API OVHcloud">

Utilisez l'appel suivant :

```bash
POST /v2/publicCloud/project/{projectId}/privateEndpoint
```

avec un corps de requête semblable à celui-ci :

```json
{
  "targetSpec": {
    "name": "my-s3-endpoint",
    "description": "Private S3 access for the backup subnet",
    "location": { "region": "GRA11" },
    "service": {
      "name": "s3",
      "tier": "S"
    },
    "network": { "id": "<network_id>" },
    "subnet": { "id": "<subnet_id>" },
    "publicDnsEnabled": false
  }
}
```

| Champ | Description |
|---|---|
| `name`, `description` | Un nom et une description facultative pour votre Private Endpoint. |
| `location.region` | La région de votre réseau privé. |
| `service.name` | Le service à joindre. Seul `s3` est disponible. |
| `service.tier` | Le niveau de connectivité (voir l'étape 1). Pendant la Beta, seul `S` est disponible. |
| `network.id`, `subnet.id` | Les identifiants du réseau privé et du sous-réseau dans lesquels placer le Private Endpoint. Les deux sont obligatoires. |
| `publicDnsEnabled` | `true` pour publier le nom d'hôte du Private Endpoint dans le DNS public, `false` pour gérer vous-même la résolution (voir le choix ci-dessus). |
| `vipAddress` | Facultatif. Une adresse IP privée de votre choix dans le sous-réseau. Elle doit appartenir à une plage privée (RFC 1918). Si vous ne la renseignez pas, une adresse est attribuée automatiquement. |

Le Private Endpoint est créé en arrière-plan : son `resourceStatus` est d'abord `CREATING`. Pour suivre l'avancement, affichez son détail :

```bash
GET /v2/publicCloud/project/{projectId}/privateEndpoint/{privateEndpointId}
```

Le Private Endpoint est prêt lorsque `resourceStatus` vaut `READY` et que `currentTasks` est vide. Son nom d'hôte apparaît alors dans le champ `currentState.hostname`, et son identifiant de Private Endpoint dans le champ `currentState.endpointId`. Notez son adresse IP, son nom d'hôte et son identifiant de Private Endpoint : vous en aurez besoin dans les étapes suivantes.

### Étape 3 - Configurer la résolution de noms

Le point de terminaison public standard d'Object Storage (`s3.{region}.io.cloud.ovh.net`) n'est **pas** redirigé automatiquement vers votre Private Endpoint. Vos applications doivent utiliser explicitement le nom d'hôte du Private Endpoint, par exemple `pe-a1b2c3d4.s3.gra.endpoint.cloud.ovh.net`.

La marche à suivre dépend du choix **Public DNS** effectué à l'étape 2 :

- **Public DNS activé :** vous n'avez rien à configurer. Passez à l'étape 4.
- **Public DNS désactivé :** dans votre service DNS, par exemple une zone DNS privée, faites pointer les noms suivants vers l'adresse IP du Private Endpoint (**Endpoint VIP** dans l'espace client, `currentState.vipAddress` dans l'API) :
    - `pe-<pe_id>.s3.{region}.endpoint.cloud.ovh.net` ;
    - `*.pe-<pe_id>.s3.{region}.endpoint.cloud.ovh.net`, qui couvre les URL incluant le nom du bucket.

### Étape 4 - Connecter votre client S3 au Private Endpoint

Une fois le Private Endpoint à l'état `READY`, remplacez le point de terminaison Object Storage de votre client S3 par le nom d'hôte du Private Endpoint. Dans les exemples ci-dessous, remplacez `pe-a1b2c3d4.s3.gra.endpoint.cloud.ovh.net` par votre propre nom d'hôte.

<Tabs>
<Tab label="AWS CLI">

```bash
aws --endpoint-url https://pe-a1b2c3d4.s3.gra.endpoint.cloud.ovh.net s3 ls
aws --endpoint-url https://pe-a1b2c3d4.s3.gra.endpoint.cloud.ovh.net s3 cp /data/myfile.txt s3://<bucket_name>
```

Pour éviter d'ajouter `--endpoint-url` à chaque commande, vous pouvez enregistrer le point de terminaison dans un profil du fichier `~/.aws/config` :

```ini
[profile private-endpoint]
region = gra
endpoint_url = https://pe-a1b2c3d4.s3.gra.endpoint.cloud.ovh.net
```

</Tab>
<Tab label="boto3 (Python)">

```python
import boto3

s3 = boto3.client(
    "s3",
    endpoint_url="https://pe-a1b2c3d4.s3.gra.endpoint.cloud.ovh.net",
    aws_access_key_id="<access_key>",
    aws_secret_access_key="<secret_key>",
    region_name="gra",
)
s3.list_buckets()
```

</Tab>
<Tab label="s3cmd">

Dans le fichier `~/.s3cfg` :

```ini
host_base = pe-a1b2c3d4.s3.gra.endpoint.cloud.ovh.net
host_bucket = pe-a1b2c3d4.s3.gra.endpoint.cloud.ovh.net
```

</Tab>
</Tabs>

Vous pouvez continuer à utiliser la clé d'accès et la clé secrète de votre utilisateur Object Storage existant.

### Étape 5 - Restreindre l'accès à vos buckets au Private Endpoint

La création d'un Private Endpoint offre à vos instances un chemin privé vers Object Storage, mais elle ne bloque **pas** l'accès depuis le point de terminaison public. Pour que le Private Endpoint soit le seul moyen d'accéder à vos données, ajoutez une restriction à la politique de votre utilisateur Object Storage.

L'instruction suivante refuse toute requête qui ne passe pas par votre Private Endpoint. Remplacez `pe-<pe_id>` par l'identifiant de votre Private Endpoint, affiché dans le champ **ID** de sa page de détail dans l'espace client, ou dans le champ `currentState.endpointId` de l'API :

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyUnlessViaPrivateEndpoint",
      "Effect": "Deny",
      "Action": "s3:*",
      "Resource": "*",
      "Condition": {
        "StringNotEquals": {
          "aws:SourceVpce": "pe-<pe_id>"
        }
      }
    }
  ]
}
```

:::warning
Dans `aws:SourceVpce`, utilisez l'identifiant du Private Endpoint, **préfixe `pe-` compris**. Copiez telle quelle la valeur du champ **ID** de l'espace client, ou de `currentState.endpointId` : elle inclut déjà le préfixe. Par exemple, avec `"endpointId": "pe-9d34106b"`, utilisez `"aws:SourceVpce": "pe-9d34106b"`.

N'utilisez pas l'identifiant de ressource (UUID) renvoyé par l'API, et n'omettez pas le préfixe `pe-`. Sinon, la condition ne correspond jamais et l'utilisateur est bloqué sur **tous** les chemins, y compris via le Private Endpoint.
:::

Si votre utilisateur possède déjà une politique, ajoutez cette instruction à sa liste `Statement` existante plutôt que de la remplacer.

Pour appliquer la politique, utilisez l'une des méthodes suivantes.

<Tabs>
<Tab label="Via l'espace client OVHcloud">

L'espace client ne propose pas encore d'option dédiée aux Private Endpoints, mais vous pouvez modifier la politique de l'utilisateur sous forme de fichier JSON :

1. Dans la section <code className="action">Object Storage</code>, ouvrez l'onglet des utilisateurs et téléchargez la politique actuelle de votre utilisateur (<code className="action">Télécharger le fichier JSON</code>).
2. Ajoutez l'instruction ci-dessus au fichier téléchargé.
3. Importez le fichier modifié sur le même utilisateur (<code className="action">Importer un fichier JSON</code>).

Pour plus de détails, consultez notre guide sur la [gestion des identités et des accès](/guides/storage-and-backup/object-storage/s3-identity-and-access-management).

</Tab>
<Tab label="Via l'AWS CLI">

Enregistrez la politique dans un fichier `policy.json`, puis utilisez la commande `put-user-policy` en ajoutant l'option `--endpoint-url`, afin que la requête soit envoyée à l'Object Storage OVHcloud et non à AWS :

```bash
aws iam put-user-policy \
  --endpoint-url https://s3.<region>.io.cloud.ovh.net \
  --user-name <user_name> \
  --policy-name private-endpoint-only \
  --policy-document file://policy.json
```

| Paramètre | Description |
|---|---|
| `--endpoint-url` | Votre point de terminaison Object Storage, par exemple `https://s3.gra.io.cloud.ovh.net`. |
| `--user-name` | Le nom de l'utilisateur Object Storage à restreindre. |
| `--policy-name` | Un nom de votre choix pour cette politique. |
| `--policy-document` | Le chemin vers votre fichier JSON, précédé de `file://`. |

</Tab>
<Tab label="Via l'API OVHcloud">

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/user/\{userId\}/policy"} />

</Tab>
</Tabs>

:::warning
Une fois cette politique appliquée, l'utilisateur ne peut plus accéder à Object Storage via le point de terminaison public, quel que soit l'endroit d'où il se connecte. Avant de l'appliquer à un utilisateur de production, testez-la sur un utilisateur dédié et vérifiez que vos applications accèdent bien à Object Storage via le Private Endpoint.
:::

### Étape 6 (facultative) - Accéder au Private Endpoint depuis plusieurs sous-réseaux

Un Private Endpoint est placé dans un seul sous-réseau. Si des instances situées dans d'autres sous-réseaux du même réseau privé ont également besoin d'un accès privé à Object Storage, deux options s'offrent à vous :

- **Créer un Private Endpoint par sous-réseau.** C'est l'option la plus simple, sans routage à configurer. Pendant la Beta, les Private Endpoints sont gratuits, mais chacun compte dans la limite de 2 Private Endpoints par projet.
- **Utiliser un seul Private Endpoint et un routeur.** Placez le Private Endpoint dans un sous-réseau, puis faites transiter le trafic des autres sous-réseaux par une instance faisant office de routeur, connectée à ces sous-réseaux. Un seul Private Endpoint dessert alors tous vos sous-réseaux, mais vous devez gérer le routeur vous-même.

<img className="thumbnail" alt="Un seul Private Endpoint dans le sous-réseau A, joint depuis le sous-réseau B via un routeur" src="/images/storage-and-backup/object-storage/s3-private-endpoint/private-endpoint-multiple-subnets.png" loading="lazy" />

Les instances du sous-réseau A accèdent directement au Private Endpoint. Les instances du sous-réseau B y accèdent via le routeur qui relie les deux sous-réseaux.

### Gérer vos Private Endpoints

Les droits de consultation, de création, de modification et de suppression des Private Endpoints sont gérés par l'[IAM OVHcloud](/guides/account-and-service-management/account-information/iam-policies-api). Les actions s'appliquent au projet Public Cloud (type de ressource `publicCloudProject`) :

- `publicCloudProject:apiovh:privateEndpoint/get`
- `publicCloudProject:apiovh:privateEndpoint/create`
- `publicCloudProject:apiovh:privateEndpoint/edit`
- `publicCloudProject:apiovh:privateEndpoint/delete`
- `publicCloudProject:apiovh:reference/privateEndpoint/serviceAvailability/get`

Seuls le nom et la description sont modifiables. Le niveau, le réseau privé et le sous-réseau ne peuvent pas être modifiés après la création : pour les changer, créez un nouveau Private Endpoint, puis supprimez l'ancien.

<Tabs>
<Tab label="Via l'espace client OVHcloud">

Ouvrez <code className="action">Network</code> > <code className="action">Private Endpoints</code>. La page liste les Private Endpoints de votre projet, avec leur région, leur réseau privé, leur sous-réseau, leur service, leur niveau, leur VIP, leur nom d'hôte et leur statut. Utilisez <code className="action">Search</code> et <code className="action">Filters</code> pour en retrouver un.

**Modifier la description :** cliquez sur le nom du Private Endpoint, puis sur l'icône en forme de crayon à côté de **Description**, dans la section *General information*.

**Supprimer un Private Endpoint :** cliquez sur l'icône en forme de corbeille dans la colonne **Actions** de la liste, ou sur <code className="action">Delete</code> dans la page de détail du Private Endpoint.

</Tab>
<Tab label="Via l'API OVHcloud">

**Lister les Private Endpoints d'un projet :**

```bash
GET /v2/publicCloud/project/{projectId}/privateEndpoint
```

**Renommer un Private Endpoint ou modifier sa description :**

Affichez d'abord le détail du Private Endpoint avec un appel `GET` et notez la valeur de son champ `checksum`. Renvoyez ensuite cette valeur avec vos modifications :

```bash
PUT /v2/publicCloud/project/{projectId}/privateEndpoint/{privateEndpointId}
```

```json
{
  "checksum": "<checksum>",
  "targetSpec": {
    "name": "my-s3-endpoint-renamed",
    "description": "Updated description"
  }
}
```

Le `checksum` garantit que personne n'a modifié le Private Endpoint entre-temps. Si c'est le cas, la requête est rejetée avec une erreur `409 Conflict` : affichez à nouveau le détail et relancez la requête avec le nouveau `checksum`.

**Supprimer un Private Endpoint :**

```bash
DELETE /v2/publicCloud/project/{projectId}/privateEndpoint/{privateEndpointId}
```

La suppression s'effectue en arrière-plan : `resourceStatus` vaut `DELETING` jusqu'à la fin de l'opération.

</Tab>
</Tabs>

:::warning
Si la politique de votre utilisateur Object Storage n'autorise l'accès que via ce Private Endpoint (voir l'étape 5), modifiez-la avant de supprimer le Private Endpoint. Sinon, l'utilisateur ne pourra plus accéder à vos buckets.
:::

- la restriction de l'accès à vos buckets via des politiques de bucket ;
- la restriction de l'accès à vos buckets via des politiques IAM OVHcloud, une fois Object Storage intégré à l'IAM OVHcloud.
