## Utiliser la console OVHcloud
Dans la console OVHcloud, ouvrez **Bare Metal Cloud**, cliquez sur <code className="action">Cloud Disk Array</code> sous **Stockage** dans le menu de gauche, puis sur le nom de votre cluster Ceph. L'onglet <code className="action">Vue d'ensemble</code> affiche les tuiles **Informations générales**, **Configuration du service** et **Stockage**.

### Détails du cluster

Explications complémentaires :

| Champ | Description |
|-------|-------------|
| **Alias** (Informations générales) | Nom attribué à votre cluster |
| **Identifiant** (Informations générales) | Identifiant (fsid) de votre cluster, utilisé comme `serviceName` dans l'API |
| **Région** (Informations générales) | Nous proposons actuellement des clusters Ceph à Strasbourg, Gravelines et Beauharnois. |
| **Version** (Informations générales) | Nous proposons actuellement des clusters jusqu'à la version 9.2.1 ([versions officielles de Ceph](https://docs.ceph.com/en/latest/releases/general/)) |
| **Crush tunables** (Configuration du service) | Il s'agit de l'algorithme utilisé pour placer les données. |
| **État de facturation** (Configuration du service) | Actif |
| **Moniteurs** (Configuration du service) | Adresse IP que vous devez utiliser pour joindre vos moniteurs. |
| **Date de création** (Informations générales) | Date de création de votre cluster |
| **Date de modification** (Informations générales) | Date de la dernière tâche appliquée à votre cluster |

La tuile **Stockage** affiche la **Taille totale**, l'**Espace utilisé** et l'**Espace disponible** du cluster. Les opérations en cours sur le cluster sont listées dans l'onglet <code className="action">Activités</code>.

### État de santé du cluster

L'état de santé du cluster est affiché dans la tuile **Configuration du service**.

Explications complémentaires :

| Champ | Description |
|-------|-------------|
| **Santé** | **OK** (HEALTH_OK) signifie que tous les objets sont au bon emplacement et disposent de 3 réplicas. HEALTH_WARN signifie que certains objets sont mal placés (par exemple après une extension) ou que certains objets ne sont pas répliqués trois fois. Dans ce cas, le cluster est en cours de reconstruction |
| **Cluster sain** | **Oui** ou **Non**, indiquant si tout fonctionne correctement sur le cluster Ceph ou non |
| **Availables bytes** | Octets disponibles dans le cluster (avant réplication) |
| **Used bytes** | Octets actuellement utilisés dans le cluster (après réplication) |
| **Space usage [%]** | Pourcentage d'*octets utilisés* par rapport au *nombre total d'octets* |
| **Cluster active tasks** | Liste des tâches lancées par l'utilisateur et actuellement en cours de traitement pour ce cluster |

## Utiliser l'API
Récupérez les détails du cluster Ceph à l'aide d'un simple appel HTTP.

<Api version="v1" section="/dedicated/ceph" method="GET" route={"/dedicated/ceph/\{serviceName\}"} />

Exemple :

```bash
GET /dedicated/ceph/98d166d8-7c88-47b7-9cb6-63acd5a59c15
{
  updateDate: "2016-07-26T09:16:07"
  status: "INSTALLED"
  region: "SBG1"
  serviceName: "98d166d8-7c88-47b7-9cb6-63acd5a59c15"
  state: "ACTIVE"
  createDate: "2016-07-20T08:00:37"
  cephMons: [
    "10.99.187.210"
    "10.99.191.210"
    "10.97.131.210"
  ]
  crushTunables: "OPTIMAL"
  label: "Ceph cluster"
  cephVersion: "9.2.1"
}
```

Récupérez l'état de santé du cluster Ceph :

<Api version="v1" section="/dedicated/ceph" method="GET" route={"/dedicated/ceph/\{serviceName\}/health"} />


```bash
{
  status: "HEALTH_OK"
  availableBytes: 5891996504064
  serviceName: "98d166d8-7c88-47b7-9cb6-63acd5a59c15"
  healthy: true
  usedBytes: 124981248
}
```
