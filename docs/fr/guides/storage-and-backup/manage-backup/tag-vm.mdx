## Objectif

Avec Managed Backup for VMware, c'est un tag vSphere qui décide si une machine virtuelle est sauvegardée, et avec quel Backup plan.

**Ce guide vous explique comment poser, changer ou retirer ce tag, pour une machine ou pour tout un groupe de machines.**

## Prérequis

- Disposer d'un service Managed Backup for VMware actif sur votre infrastructure (voir [Démarrer avec Managed Backup for VMware](/guides/storage-and-backup/manage-backup/overview)).
- Être connecté au client vSphere de votre infrastructure, avec un utilisateur autorisé à attribuer des tags aux machines virtuelles.

## En pratique

:::info
**Quand les tags sont-ils posés, et lequel fait foi ?**

- **Au début de la livraison,** OVHcloud crée dans votre vCenter la catégorie `OvhManagedBackup` et ses trois tags (`standard`, `advanced` et `premium`). Il pose ensuite sur les machines choisies à la commande le tag de leur Backup plan, avant même de déployer le VBR. C'est pourquoi vous pouvez taguer vos machines environ 30 minutes après la commande.
- **OVHcloud déploie ensuite le VBR** et crée les trois jobs de sauvegarde. Toute machine que vous avez taguée entre-temps est sauvegardée dès le premier passage.
- **Ensuite, c'est le tag dans vSphere qui fait foi.** Poser, changer ou retirer un tag se fait dans vSphere : le Manager ne pose plus aucun tag après la commande.
- **Un tag est pris en compte dans l'heure,** et l'espace client se met à jour toutes les heures. La machine est sauvegardée au prochain passage des jobs (chaque soir à 22 h), ou tout de suite si vous lancez une sauvegarde à la demande depuis votre VBR.

:::
### Les règles du tag

| Élément | Valeur |
|---|---|
| Catégorie vSphere | `OvhManagedBackup` |
| Tags disponibles | `standard`, `advanced`, `premium` (en minuscules) |
| Nombre de tags par machine | Un seul : la catégorie n'en accepte pas plus |
| Prise en compte | Dans l'heure, puis la machine est sauvegardée au prochain passage de sauvegarde |

La catégorie `OvhManagedBackup` et ses trois tags sont créés par OVHcloud dans votre vCenter, au début de la livraison du service. Vous n'avez rien à créer.

Vous les retrouvez dans le client vSphere, menu des tags et attributs personnalisés (<code className="action">Tags & Custom Attributes</code>). La vue des catégories (<code className="action">CATEGORIES</code>) liste la catégorie `OvhManagedBackup`. La colonne de cardinalité multiple (**Multiple Cardinality**) y vaut `false` : une machine ne porte qu'un seul tag de cette catégorie.

La vue des tags (<code className="action">TAGS</code>) montre les trois tags `advanced`, `standard` et `premium`.

- **Une machine avec un tag valide** rejoint le job de sauvegarde de son Backup plan, et elle est sauvegardée chaque soir, au démarrage des jobs à 22 h.
- **Une machine sans tag** n'est ni sauvegardée ni facturée. Elle apparaît comme non protégée dans votre espace client.
- **Un tag mal orthographié, en majuscules ou posé dans une autre catégorie** est traité comme une absence de tag : la machine n'est pas protégée.

Les tags posés par OVHcloud au début de la livraison se gèrent ensuite exactement comme ceux que vous posez vous-même.

### Poser un tag sur une machine virtuelle

L'interface du client vSphere est ici en anglais. Les libellés anglais affichés à l'écran sont donnés entre parenthèses.

1. Dans le client vSphere, sélectionnez la machine virtuelle dans l'inventaire, puis ouvrez son onglet Résumé (<code className="action">Summary</code>).
2. Repérez la carte des tags (**Tags**). Tant qu'aucun tag n'est posé, elle indique qu'aucun tag n'est attribué (**No tags assigned**). Cliquez sur Attribuer (<code className="action">ASSIGN</code>) en bas de la carte.
3. Dans la boîte d'attribution de tag (**Assign Tag**), la liste affiche les trois tags de la catégorie `OvhManagedBackup`. Cochez le tag du Backup plan voulu : `standard`, `advanced` ou `premium`.
4. Cliquez sur <code className="action">Attribuer</code>.

   <img className="thumbnail" alt="Boîte d'attribution de tag (Assign Tag) du client vSphere avec les tags advanced, standard et premium de la catégorie OvhManagedBackup, premium étant coché" src="/images/storage-and-backup/manage-backup/tag-vm/01-vsphere-assign-tag.png" loading="lazy" />

   La boîte d'attribution de tag (**Assign Tag**) : le tag `premium` est coché, il reste à cliquer sur Attribuer (<code className="action">ASSIGN</code>).

5. Vérifiez le résultat : la carte des tags de la machine affiche maintenant le tag posé, avec sa catégorie `OvhManagedBackup`.

   <img className="thumbnail" alt="Onglet Résumé (Summary) d'une machine virtuelle dont la carte des tags (Tags) affiche le tag premium de la catégorie OvhManagedBackup" src="/images/storage-and-backup/manage-backup/tag-vm/02-vsphere-vm-tagged.png" loading="lazy" />

   La machine taguée : la carte des tags (**Tags**) affiche `premium`.

Vous pouvez aussi faire un clic droit sur la machine virtuelle dans l'inventaire, puis choisir <code className="action">Tags et attributs personnalisés</code> > <code className="action">Attribuer une balise</code>. La même boîte s'ouvre. Les libellés exacts dépendent de la langue et de la version de votre client vSphere.

### Taguer plusieurs machines en une fois

1. Dans le client vSphere, sélectionnez un dossier, un cluster ou un pool de ressources, puis ouvrez l'onglet des machines virtuelles (<code className="action">VM</code>).
2. Sélectionnez plusieurs machines avec <kbd>Maj</kbd> ou <kbd>Ctrl</kbd>.
3. Faites un clic droit sur la sélection, puis <code className="action">Tags et attributs personnalisés</code> > <code className="action">Attribuer une balise</code>, et choisissez le tag.

### Changer le Backup plan d'une machine

1. Retirez le tag actuel : clic droit sur la machine, <code className="action">Tags et attributs personnalisés</code> > <code className="action">Supprimer une balise</code>.
2. Attribuez le nouveau tag, comme décrit ci-dessus.

- **Les nouvelles sauvegardes** suivent le nouveau plan dès la prochaine exécution du job.
- **Les sauvegardes déjà réalisées** gardent leur plan d'origine, avec sa rétention et son immutabilité, jusqu'à leur expiration. Rien n'est déplacé rétroactivement.
- **Sur la facture**, la période de facturation en cours est facturée au plan le plus élevé atteint (voir [Comprendre votre facturation](/guides/storage-and-backup/manage-backup/billing)).

### Arrêter de protéger une machine

Retirez son tag. La machine quitte son job au prochain passage et n'est plus sauvegardée. Aucune sauvegarde n'est supprimée : les points de restauration existants restent restaurables jusqu'à la fin de leur rétention.

La période de facturation en cours reste facturée pour cette machine. Elle n'est plus facturée à partir de la période suivante.

### Après une restauration

:::warning
**Vérifiez le tag d'une machine restaurée**

Après une restauration, vérifiez dans vSphere le tag de la machine restaurée et reposez-le si besoin. La machine d'origine, elle, reste protégée normalement.
:::

### Machines virtuelles de 8 To ou plus

Les machines virtuelles de 8 To ou plus **ne sont pas prises en charge** : Managed Backup for VMware ne les sauvegarde pas. Elles restent visibles dans la liste de la commande, mais ne peuvent pas recevoir de Backup plan. Une machine de cette taille peut retarder les sauvegardes de vos autres machines.

- **Ne leur posez pas de tag** dans vSphere.
- **Si l'une d'elles porte un tag, retirez-le.** OVHcloud ne le retire jamais automatiquement : tant qu'au moins une machine de ce type est taguée, vous recevez un rappel par e-mail chaque semaine.

### Vérifier le résultat

Dans votre espace client, la **Liste des VMs** du tableau de bord indique pour chaque machine si elle est protégée, son Backup plan et la date de sa dernière sauvegarde. Ces informations sont mises à jour toutes les heures (voir [Suivre votre protection dans l'espace client](/guides/storage-and-backup/manage-backup/manage-dashboard)).

Une machine protégée qui n'affiche encore aucune date de sauvegarde sera sauvegardée au prochain passage des jobs, chaque soir à 22 h. Pour la sauvegarder tout de suite, lancez une sauvegarde à la demande depuis votre VBR (voir [Sauvegarder et restaurer](/guides/storage-and-backup/manage-backup/backup-restore)).
