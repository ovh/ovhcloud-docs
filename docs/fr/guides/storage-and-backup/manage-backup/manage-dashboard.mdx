## Objectif

Votre espace client OVHcloud rassemble sur un seul tableau de bord toutes les infrastructures protégées par Managed Backup for VMware et toutes leurs machines virtuelles.

**Ce guide vous explique comment lire votre tableau de bord, vérifier qu'une machine est bien sauvegardée, accéder à votre VBR et réinitialiser son mot de passe.**

## Prérequis

- Disposer d'au moins un service Managed Backup for VMware.
- Être connecté à votre <ManagerLink to="/">espace client OVHcloud</ManagerLink>.

## En pratique

### Accéder au tableau de bord

Dans l'univers <code className="action">Hosted Private Cloud</code>, ouvrez <code className="action">Backup</code> > <code className="action">Managed Backup for VMware</code>. Le tableau de bord s'ouvre directement sur l'ensemble de votre abonnement. Il comporte deux onglets : <code className="action">Tableau de bord</code> et <code className="action">Facturation</code>.

<img className="thumbnail" alt="Carte Informations générales avec les machines protégées et non protégées, le site secondaire et le lien Réinitialiser le mot de passe du VBR (General information et Reset the VBR password sur la capture)" src="/images/storage-and-backup/manage-backup/manage-dashboard/01-general-information.png" loading="lazy" />

La carte **Informations générales** (**General information** sur la capture) indique le nombre de machines protégées et non protégées, le site secondaire et le lien <code className="action">Réinitialiser le mot de passe du VBR</code> (<code className="action">Reset the VBR password</code>).

<img className="thumbnail" alt="Liste des VMs avec le sélecteur Toutes les infrastructures, le bouton Ajouter une infrastructure, la recherche et les colonnes Nom, Infrastructure, Backup plan, Points de restauration, Dernier point de restauration et Statut (VM list, All infrastructures, Add an infrastructure, Name, Restore points, Last restore point et Status sur la capture)" src="/images/storage-and-backup/manage-backup/manage-dashboard/02-vm-list.png" loading="lazy" />

La **Liste des VMs** (**VM list** sur la capture) affiche une ligne par machine, avec son Backup plan, ses points de restauration et son statut.

### La carte Informations générales

- **Machines virtuelles protégées** : le nombre de machines virtuelles protégées.
- **Machines virtuelles non protégées** : le nombre de machines virtuelles qui ne sont pas protégées.
- **Site secondaire** : le site secondaire de l'infrastructure, en lecture seule.
- <code className="action">Réinitialiser le mot de passe du VBR</code> : le lien qui lance la réinitialisation du mot de passe du VBR (voir plus bas).

### La carte Abonnement

- **Infrastructures** : vos infrastructures protégées, chacune avec son état (par exemple **Actif**).
- **Date de création** : la date à laquelle le service a été créé.
- <code className="action">Ouvrir la console VBR</code> : le lien qui donne accès à la console de votre VBR (voir plus bas).
- <code className="action">Résilier un service de sauvegarde</code> : l'action qui arrête la protection d'une infrastructure (voir [Résilier et réactiver un service](/guides/storage-and-backup/manage-backup/terminate)).

### La liste des machines virtuelles

Sous les cartes, la **Liste des VMs** présente toutes les machines de toutes vos infrastructures. Le sélecteur **Toutes les infrastructures** limite l'affichage à une infrastructure, et le champ **Rechercher** recherche une machine par son nom. La liste n'offre pas d'autre filtre.

| Colonne | Ce qu'elle indique |
|---|---|
| **Nom** | Le nom exact de la machine dans vSphere, avec son identifiant en dessous. |
| **Infrastructure** | L'infrastructure où se trouve la machine. |
| **Backup plan** | Le plan correspondant à son tag : Standard, Advanced ou Premium. Un tiret si la machine n'a pas de tag. |
| **Points de restauration** | Le nombre de points de restauration disponibles pour cette machine. |
| **Dernier point de restauration** | La date de sa dernière sauvegarde. Un tiret si la machine n'a encore jamais été sauvegardée. |
| **Statut** | **Protégée** ou **Non protégée**. Une machine sans tag valide n'est pas protégée. |

:::info
**Repérer une machine qui n'est plus sauvegardée**

L'espace client n'affiche pas d'état d'erreur par machine. Triez la liste sur la colonne **Dernier point de restauration** : les dates les plus anciennes et les machines jamais sauvegardées remontent en tête. Une date plus ancienne que celle des autres machines, ou un tiret, signale une machine à vérifier. Le détail d'un échec se consulte dans la console de votre VBR. Votre VBR vous envoie aussi ses notifications de sauvegarde par e-mail, à l'adresse du compte OVHcloud qui a commandé le service.
:::
Les informations sont mises à jour toutes les heures. Un tag posé dans vSphere apparaît donc dans la liste dans l'heure qui suit.

Les machines de 8 To ou plus ne sont pas prises en charge : Managed Backup for VMware ne les sauvegarde pas. Une machine de cette taille peut retarder les sauvegardes de vos autres machines. Ne la taguez pas, et retirez son tag si elle en porte un (voir [Machines de 8 To ou plus](/guides/storage-and-backup/manage-backup/tag-vm#machines-virtuelles-de-8-to-ou-plus)).

### Le détail d'une machine

Cliquez sur le nom d'une machine pour ouvrir son détail dans un panneau latéral. Il indique :

- **Le badge en haut du panneau :** **Backup plan** suivi du plan (par exemple **Backup plan Standard**) pour une machine taguée, ou **Aucun tag** pour une machine sans tag.
- **Ce qu'il faut faire :** pour une machine taguée, les sauvegardes s'exécutent automatiquement. Pour une machine sans tag, rien n'est sauvegardé tant que vous ne lui posez pas l'un des trois tags dans vSphere. Le tag est pris en compte à la vérification suivante.
- **Points de restauration** : le nombre de points de restauration, ou **Aucun point de restauration**.
- **Backup plan** : le plan de la machine, ou **Aucun**.
- **Taille** et **Tranche de taille** : la taille de sa sauvegarde et sa tranche de taille, sur lesquelles son prix est calculé. L'espace alloué à ses disques n'est jamais pris en compte. Pour une machine jamais sauvegardée, l'écran indique **Pas encore mesurée** et **Inconnue**.
- **Dernier point de restauration** : la date de la dernière sauvegarde, ou **Jamais sauvegardée**.
- **Référence** : la référence de la machine, à communiquer au support si besoin.

### Ouvrir la console de votre VBR

1. Cliquez sur <code className="action">Ouvrir la console VBR</code>. La fenêtre **Console VBR** s'ouvre.
2. Dans le champ **Infrastructure**, choisissez l'infrastructure. Chaque infrastructure a son propre VBR.
3. Copiez l'identifiant affiché à côté de **Identifiant** avec le bouton de copie, puis cliquez sur <code className="action">Ouvrir l'interface web du VBR</code>.

<img className="thumbnail" alt="Fenêtre Console VBR avec le choix de l'infrastructure, l'identifiant avec un bouton pour le copier et le lien Ouvrir l'interface web du VBR (VBR console, Login et Open the VBR web interface sur la capture)" src="/images/storage-and-backup/manage-backup/manage-dashboard/03-vbr-console.png" loading="lazy" />

La fenêtre affiche l'identifiant du VBR choisi, avec un bouton pour le copier, et le lien vers son interface web.

L'action n'est pas proposée tant que le service est en cours de déploiement.

### Réinitialiser le mot de passe de votre VBR

OVHcloud ne conserve pas le mot de passe que vous choisissez. En cas de perte, demandez une réinitialisation :

1. Dans la carte **Informations générales**, cliquez sur <code className="action">Réinitialiser le mot de passe du VBR</code>.
2. Dans la fenêtre **Réinitialiser le mot de passe du VBR**, choisissez dans **Infrastructure** celle dont vous avez perdu le mot de passe. L'**Identifiant** concerné s'affiche.
3. Cliquez sur <code className="action">Envoyer l'e-mail</code>. Le bouton <code className="action">Annuler</code> ferme la fenêtre sans rien envoyer.
4. Ouvrez l'e-mail de réinitialisation, envoyé par votre VBR à l'adresse du compte OVHcloud qui a commandé le service, connectez-vous avec le mot de passe temporaire, puis choisissez un nouveau mot de passe.

- La réinitialisation ne concerne que le VBR choisi, et ne modifie pas les droits du compte.
- La réinitialisation du mot de passe du VBR reste disponible pendant les 35 jours qui suivent une résiliation, pour que vous puissiez encore restaurer.
- La réinitialisation n'est pas proposée pendant le déploiement, ni si une autre est déjà en cours sur ce VBR.

### Protéger une autre infrastructure

Dans la **Liste des VMs**, cliquez sur <code className="action">Ajouter une infrastructure</code> pour lancer une nouvelle commande. Elle se déroule en entier, comme la première (voir [Démarrer](/guides/storage-and-backup/manage-backup/overview)) : une infrastructure déjà protégée ne vous est pas proposée. Le nouveau service apparaît sur le même tableau de bord.

### Ce qui se gère ailleurs

- **Les jobs de sauvegarde :** ils sont créés et planifiés par OVHcloud.
- **Les tags :** le choix du Backup plan se fait dans vSphere.
- **Le stockage :** le prix de chaque machine l'inclut, il n'y a rien à dimensionner.
- **Le site secondaire :** il est choisi à la commande et ne change plus ensuite.
