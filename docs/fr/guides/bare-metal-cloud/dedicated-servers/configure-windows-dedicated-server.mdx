## Objectif

Windows Server est un système d'exploitation pris en charge sur les serveurs dédiés OVHcloud. Une fois installé, vous devez configurer le système Windows afin qu'il puisse utiliser les services réseau et de stockage OVHcloud rattachés au serveur.

Ce guide vous accompagne pour installer Windows Server depuis la console OVHcloud, vous connecter au serveur, puis effectuer la configuration côté Windows nécessaire pour interagir avec les principaux services OVHcloud rattachés à un serveur dédié.

**Dans ce guide, vous allez apprendre à :**

- Installer Windows Server depuis la console OVHcloud
- Vous connecter au serveur avec le Bureau à distance et effectuer la configuration initiale
- Configurer Windows pour utiliser une Additional IP
- Configurer Windows pour utiliser le réseau privé vRack
- Configurer Windows pour utiliser le bloc IPv6 fourni avec le serveur
- Accéder au Backup Storage OVHcloud depuis Windows
- Protéger le serveur avec des sauvegardes managées grâce à OVHcloud Backup Agent

:::warning
La réinstallation d'un système d'exploitation efface toutes les données présentes sur les disques du serveur. Sauvegardez les données que vous souhaitez conserver avant de commencer.
:::

## Prérequis

- Disposer d'un [serveur dédié](/links/bare-metal/bare-metal) dans votre compte OVHcloud
- Disposer d'une licence Windows Server valide. Les licences peuvent être commandées auprès d'OVHcloud ou d'un revendeur externe — consultez le guide « [Gérer vos licences OVHcloud](/guides/bare-metal-cloud/dedicated-servers/windows-key) ».
- Disposer d'un client RDP (Remote Desktop Protocol) sur votre machine locale (le client <code className="action">Connexion Bureau à distance</code> est inclus avec Windows)

## Introduction

Un serveur dédié est un serveur physique (« bare metal ») hébergé dans un centre de données OVHcloud. OVHcloud fournit le matériel, la connexion au réseau public, un réseau privé vRack optionnel et un espace Backup Storage inclus. Vous êtes responsable de l'administration du système d'exploitation installé sur le serveur, y compris de toute la configuration réseau et de stockage dans Windows.

Le tableau ci-dessous présente les principaux services avec lesquels un serveur dédié sous Windows interagit.

{/* CP-STEPS-START:services-overview */}

| Service OVHcloud | Rôle | Où l'activer |
|---|---|---|
| Additional IP | Adresses IP publiques supplémentaires rattachées au serveur | Console OVHcloud — section <code className="action">Réseau</code> du menu de gauche, <code className="action">Adresses IP</code> |
| vRack | Réseau privé de niveau 2 entre les services OVHcloud | Console OVHcloud — section <code className="action">Réseau</code> du menu de gauche, <code className="action">vRack</code> |
| IPv6 | Le bloc IPv6 /64 fourni avec chaque serveur | Fourni automatiquement |
| Backup Storage | Espace de sauvegarde inclus (FTP/CIFS (SMB)/NFS) | Console OVHcloud — <ManagerLink to="/beta/#/bare-metal/dedicated-server">Serveurs dédiés</ManagerLink> > Sélectionnez votre serveur, onglet <code className="action">Stockage distant</code> |
| Backup Agent | Sauvegardes managées quotidiennes vers un vault Object Storage isolé et immuable | Console OVHcloud — section <code className="action">Backup</code> du menu de gauche, <code className="action">Backup Agent</code>. L'onglet <code className="action">Vue d'ensemble</code> du serveur en affiche l'état dans la section **Informations générales**. |

{/* CP-STEPS-END:services-overview */}

### Étape 1 — Installer Windows Server depuis la console OVHcloud <a name="install"></a>

Au cours de cette étape, vous installez (ou réinstallez) Windows Server sur votre serveur dédié. L'installation se pilote entièrement depuis la console OVHcloud.

{/* CP-STEPS-START:install-windows-server */}

Sur l'onglet <code className="action">Vue d'ensemble</code>, dans la section **Informations générales**, cliquez sur <code className="action">Réinstaller</code> à côté de **Système d'exploitation**. La page **Installation / Réinstallation** s'ouvre et vous guide à travers les étapes **Système d'exploitation**, **Partitions**, **Options** et **Récapitulatif** (une étape **RAID** s'ajoute sur les serveurs équipés d'un contrôleur RAID matériel).

:::info
Windows Server nécessite une licence, qui génère des frais supplémentaires. Sans licence Windows Server associée au serveur, les modèles Windows ne sont pas proposés dans la liste des systèmes d'exploitation. Vous pouvez commander une licence auprès d'OVHcloud ou fournir la vôtre. Gérez vos licences dans la section <code className="action">Licences</code> du menu de gauche de la console OVHcloud. Pour plus d'informations, consultez le guide « [Gérer vos licences OVHcloud](/guides/bare-metal-cloud/dedicated-servers/windows-key) ».
:::

:::warning
Cette action est irréversible. Toutes les données présentes sur les disques seront définitivement supprimées.
:::

1. **Système d'exploitation** — dans la liste déroulante **Catégorie**, choisissez la catégorie qui contient le modèle Windows Server souhaité, puis sélectionnez ce modèle dans la liste déroulante **Système d'exploitation**. Si votre serveur dispose de plusieurs groupes de disques, choisissez celui sur lequel installer Windows sous **Choisissez le groupe de disques sur lequel installer l'OS**. Pour définir votre propre grappe ou disposition, cochez **Configurer le RAID matériel** (uniquement sur les serveurs équipés d'un contrôleur RAID matériel) ou **Personnaliser la configuration des partitions**. Pour le RAID logiciel sous Windows, consultez le guide « [Configurer un RAID logiciel sur un serveur Windows](/guides/bare-metal-cloud/dedicated-servers/raid-soft-windows) ».
2. Cliquez sur <code className="action">Suivant</code> pour parcourir les étapes suivantes.
3. À l'étape **Récapitulatif**, vérifiez vos choix, cochez **Je comprends que toutes les données présentes sur les disques seront définitivement supprimées.**, puis cliquez sur <code className="action">Installer</code> pour lancer l'installation.

{/* CP-STEPS-END:install-windows-server */}

Le serveur redémarre et l'installation se termine automatiquement.

### Étape 2 — Vous connecter à votre serveur <a name="connect"></a>

Une fois l'installation terminée, OVHcloud vous envoie un e-mail contenant le nom d'utilisateur et le mot de passe administrateur de votre serveur Windows.

Sur votre machine Windows locale, ouvrez le client <code className="action">Connexion Bureau à distance</code>. Saisissez l'adresse IPv4 de votre serveur, puis votre nom d'utilisateur et votre mot de passe. Un avertissement de certificat apparaît généralement lors de la première connexion — cliquez sur <code className="action">Oui</code> pour continuer.
Vous pouvez utiliser n'importe quel client compatible RDP si votre appareil local ne fonctionne pas sous Windows.

{/* CP-STEPS-START:ipmi-fallback */}

:::tip
Si le protocole RDP est indisponible — par exemple après une erreur de configuration réseau — connectez-vous via la [console Intelligent Platform Management Interface (IPMI)](/guides/bare-metal-cloud/dedicated-servers/ipmi), depuis la section **Connexion au serveur** de l'onglet <code className="action">Serveur</code> de votre serveur dans la console OVHcloud. La console IPMI fonctionne quel que soit l'état de connectivité du système d'exploitation.
:::

{/* CP-STEPS-END:ipmi-fallback */}

Après votre première connexion, modifiez le mot de passe administrateur depuis Windows (dans la session RDP, appuyez sur `Ctrl` + `Alt` + `Fin` > <code className="action">Modifier un mot de passe</code>).

### Étape 3 — Effectuer la configuration initiale de Windows <a name="initial-config"></a>

Avant de connecter le serveur aux autres services OVHcloud, effectuez la configuration de base de Windows.

- Lancez Windows Update et installez les dernières mises à jour.
- Définissez le nom d'hôte du serveur, le fuseau horaire et la disposition du clavier.
- Configurez le pare-feu Windows pour autoriser les services que vous comptez exécuter. Pour une procédure spécifique au pare-feu sous Windows, consultez le guide « [Activer le pare-feu sur un serveur Windows](/guides/bare-metal-cloud/dedicated-servers/activate-port-firewall-soft-win) ».

:::warning
OVHcloud met à votre disposition des services dont vous êtes responsable quant à leur configuration et leur gestion. Si vous avez besoin d'un accompagnement, contactez un [prestataire spécialisé](/links/partner).
:::

### Étape 4 — Configurer Windows pour interagir avec les services OVHcloud <a name="services"></a>

Cette section couvre la configuration côté Windows des services OVHcloud les plus fréquemment rattachés à un serveur dédié. Chaque sous-section est indépendante — ne suivez que celles qui correspondent à votre configuration. Dans chacune, la première partie s'effectue dans la console OVHcloud et la seconde dans Windows Server.

#### 4a — Additional IP

Une Additional IP est une adresse IP publique supplémentaire routée vers votre serveur. Après l'avoir commandée, vous devez la déclarer dans Windows pour que le serveur réponde sur cette adresse.

{/* CP-STEPS-START:additional-ip-cp */}

**Dans la console OVHcloud**

Commandez l'Additional IP depuis la section <code className="action">Réseau</code> du menu de gauche de la console OVHcloud : sélectionnez <code className="action">Adresses IP</code>, cliquez sur <code className="action">Commander une IP</code>, puis sur <code className="action">Commander une IP additionnelle</code>. Pour plus d'informations, consultez la page « [Additional IP](/links/bare-metal/ip) ».

{/* CP-STEPS-END:additional-ip-cp */}

**Dans Windows Server**

1. Ouvrez <code className="action">Panneau de configuration</code> > <code className="action">Centre Réseau et partage</code> > <code className="action">Modifier les paramètres de la carte</code>, puis affichez les propriétés de votre carte réseau.
2. Sélectionnez <code className="action">Protocole Internet version 4 (TCP/IPv4)</code> > <code className="action">Propriétés</code> > <code className="action">Avancé</code>, et ajoutez l'adresse de l'Additional IP.

Sur le réseau OVHcloud, une Additional IP est routée individuellement vers le serveur. Utilisez le masque de sous-réseau et la passerelle qui correspondent à la configuration de l'IP principale de votre serveur.

:::tip
Si vous comptez attribuer l'Additional IP à une machine virtuelle plutôt qu'à l'hôte, consultez le guide « [Configurer un bloc d'IP dans un vRack](/guides/bare-metal-cloud/dedicated-servers/configuring-an-ip-block-in-a-vrack) ».
:::

#### 4b — Réseau privé vRack

Le vRack est un réseau privé de niveau 2 qui permet à votre serveur dédié de communiquer de manière privée avec d'autres services OVHcloud (autres serveurs dédiés, instances Public Cloud, etc.).

{/* CP-STEPS-START:vrack-cp */}

**Dans la console OVHcloud**

Dans la section <code className="action">Réseau</code> du menu de gauche de la console OVHcloud, sélectionnez <code className="action">vRack</code>, puis votre vRack. Dans l'onglet <code className="action">Services rattachés</code>, cliquez sur <code className="action">Attacher un service</code>, sélectionnez **Serveurs dédiés** dans la liste déroulante **Type de service**, puis cliquez sur <code className="action">Rattacher</code> sur la ligne de ce serveur et confirmez.

{/* CP-STEPS-END:vrack-cp */}

**Dans Windows Server**

1. Ouvrez les propriétés de la carte réseau **privée** (la seconde interface, dédiée au vRack).
2. Attribuez une adresse IPv4 privée statique issue de votre plan d'adressage vRack. Laissez la passerelle par défaut vide — le vRack est un réseau de niveau 2 sans passerelle fournie par OVHcloud.

Pour la procédure complète, ainsi que pour la configuration de l'OVHcloud Link Aggregation (OLA, agrégation de liens), consultez le guide « [Configurer le vRack sur un serveur dédié](/guides/bare-metal-cloud/dedicated-servers/vrack-configuring-on-dedicated-server) ».

#### 4c — IPv6

Chaque serveur dédié OVHcloud est livré avec un bloc IPv6 /64. L'adresse n'est pas configurée automatiquement dans Windows et doit être ajoutée manuellement.

{/* CP-STEPS-START:ipv6-cp */}

**Dans la console OVHcloud**

Récupérez votre adresse IPv6, le préfixe et la passerelle depuis l'onglet <code className="action">Connectivité</code> de votre serveur : la section **Interface publique** affiche **IPv6** et **Passerelle IPv6**.

{/* CP-STEPS-END:ipv6-cp */}

**Dans Windows Server**

1. Ouvrez les propriétés de votre carte réseau et sélectionnez <code className="action">Protocole Internet version 6 (TCP/IPv6)</code> > <code className="action">Propriétés</code>.
2. Saisissez l'adresse IPv6, la longueur du préfixe et la passerelle IPv6 par défaut.

Pour les détails d'adressage et la configuration de la passerelle propres à OVHcloud, consultez le guide « [Configuration de l'IPv6](/guides/bare-metal-cloud/dedicated-servers/network-ipv6) ».

#### 4d — Backup Storage

Le Backup Storage est un espace de stockage inclus avec votre serveur dédié. Il est accessible via les protocoles FTP, CIFS (SMB) ou NFS et convient particulièrement comme sauvegarde complémentaire.

{/* CP-STEPS-START:backup-storage-cp */}

**Dans la console OVHcloud**

1. Dans l'onglet <code className="action">Stockage distant</code> de votre serveur, cliquez sur <code className="action">Activer le Backup FTP</code>. Une fois l'espace actif, l'onglet affiche l'adresse du serveur de stockage dans le champ **Nom**. Pour obtenir un mot de passe, cliquez sur <code className="action">Réinitialiser le mot de passe</code> : un nouveau mot de passe est envoyé à l'adresse e-mail de votre compte OVHcloud.
2. Autorisez l'adresse IP de votre serveur à accéder à l'espace : dans la section **Liste des accès**, cliquez sur <code className="action">Ajouter un accès</code>, sélectionnez le bloc IP et les protocoles, puis cliquez sur <code className="action">Ajouter</code>.

{/* CP-STEPS-END:backup-storage-cp */}

**Dans Windows Server**

Accédez à l'espace en utilisant l'un des protocoles pris en charge :

- **CIFS (SMB)** — montez-le en tant que lecteur réseau (<code className="action">Ce PC</code> > <code className="action">Connecter un lecteur réseau</code>).
- **FTP** — connectez-vous avec n'importe quel client FTP, à l'aide des informations de connexion de la console OVHcloud et du mot de passe que vous avez défini.

Pour la procédure d'activation et les protocoles d'accès, consultez le guide « [Backup Storage sur les serveurs dédiés](/guides/bare-metal-cloud/dedicated-servers/services-backup-storage) » et la page « [Backup Storage](/links/bare-metal/backup-storage) ».

#### 4e — Backup Agent

Le Backup Storage est un espace de stockage passif — il ne sauvegarde pas vos données de lui-même. Pour une protection managée et automatisée, OVHcloud propose **Backup Agent**, un service de sauvegarde distinct pour les serveurs Bare Metal. Une fois commandé, vous déployez un agent léger sur votre serveur Windows, qui réalise alors des sauvegardes quotidiennes incrémentielles, chiffrées et immuables vers un vault Object Storage isolé, situé dans une région différente de celle du serveur.

{/* CP-STEPS-START:backup-agent-cp */}

**Dans la console OVHcloud**

Gérez Backup Agent depuis la section <code className="action">Backup</code> du menu de gauche de la console OVHcloud, en sélectionnant <code className="action">Backup Agent</code>. L'état de l'agent pour votre serveur est indiqué sur la ligne **Backup Agent** de la section **Informations générales**, dans l'onglet <code className="action">Vue d'ensemble</code> du serveur. Backup Agent ne peut pas être activé pendant la réinstallation du système d'exploitation d'un serveur Windows : installez l'agent une fois Windows démarré.

{/* CP-STEPS-END:backup-agent-cp */}

**Dans Windows Server**

Une fois l'agent déployé, configurez votre première sauvegarde (données source, planification et rétention).

Pour la procédure complète, consultez le guide « [Backup Agent - Présentation](/guides/storage-and-backup/backup-agent/overview) » et le guide « [Backup Agent - Comment configurer votre première sauvegarde](/guides/storage-and-backup/backup-agent/first-configuration) ».

### Étape 5 — Vérifier la configuration <a name="verify"></a>

Vérifiez que chaque service configuré fonctionne comme prévu.

| Vérification | Comment | Résultat attendu |
|---|---|---|
| Accès RDP | Connectez-vous avec <code className="action">Connexion Bureau à distance</code> sur l'IPv4 principale | Le bureau Windows s'affiche |
| Additional IP | Depuis un hôte externe, exécutez `ping` vers l'Additional IP | Le serveur répond |
| vRack | Depuis un autre membre du vRack, exécutez `ping` vers l'IP privée | Le serveur répond |
| IPv6 | Exécutez `ping -6 ipv6.google.com` depuis le serveur | Vous recevez des réponses |
| Backup Storage | Ouvrez le lecteur CIFS (SMB) monté ou connectez-vous en FTP | Vous pouvez lire et écrire des fichiers |

### Dépannage <a name="troubleshooting"></a>

| Problème | Cause possible | Solution |
|---|---|---|
| La connexion RDP échoue | Règles de pare-feu ou restrictions réseau sur l'appareil local | Vérifiez les paramètres du pare-feu et du réseau locaux ; connectez-vous via la [console IPMI](/guides/bare-metal-cloud/dedicated-servers/ipmi) en secours. |
| Additional IP injoignable | Masque ou passerelle incorrects dans Windows | Vérifiez à nouveau les valeurs saisies dans les paramètres TCP/IPv4 avancés. |
| Membre du vRack injoignable | Mauvais sous-réseau privé ou passerelle définie sur la carte privée | Confirmez le plan d'adressage privé et laissez la passerelle vide. |
| Serveur hors ligne après une modification | Erreur de configuration lors de la mise en place | Démarrez en [mode rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-customer-windows) pour inspecter et réparer la configuration. |
