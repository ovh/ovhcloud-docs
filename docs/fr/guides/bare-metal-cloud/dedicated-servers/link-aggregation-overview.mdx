## Objectif

L'agrégation de liens réunit plusieurs interfaces réseau de votre serveur à l'aide du protocole LACP (Link Aggregation Control Protocol), défini par la norme IEEE 802.3ad. La bande passante disponible augmente et vos liaisons réseau deviennent redondantes : si une liaison tombe en panne, le trafic est automatiquement redirigé vers une autre liaison disponible.

Plusieurs guides traitent de l'agrégation de liens, selon la gamme de votre serveur, son système d'exploitation et le maintien ou non de sa connectivité publique.

**Ce guide explique en quoi l'agrégation par défaut et OVHcloud Link Aggregation (OLA) diffèrent, et vous oriente vers le guide correspondant à votre configuration.**

## Prérequis

- Disposer d'un [serveur dédié](/links/bare-metal/bare-metal) compatible avec l'agrégation de liens, par exemple de gamme **Scale** ou **High Grade**, ou un serveur **Advance** de troisième génération ou plus récent
- Disposer d'un système d'exploitation ou d'un hyperviseur supportant le protocole d'agrégation 802.3ad (LACP)

## En pratique

### Quelles interfaces peuvent être agrégées

Les serveurs des gammes **Scale** et **High Grade** disposent de quatre interfaces réseau. Dans leur configuration par défaut, deux sont publiques et deux sont privées (vRack). Les deux agrégations sont déjà activées sur le réseau OVHcloud : le système d'exploitation n'a plus qu'à créer les agrégats correspondants.

Les autres serveurs compatibles avec l'agrégation de liens disposent d'une seule interface publique et d'une seule interface privée.

### Choisir un mode d'agrégation

[OVHcloud Link Aggregation (OLA)](/guides/bare-metal-cloud/dedicated-servers/ola-enable-manager) est une option que vous activez dans votre espace client OVHcloud : elle réunit toutes les interfaces du serveur en une seule agrégation privée, au lieu de conserver les interfaces publiques et privées séparées.

|Mode|Connectivité publique|
|---|---|
|Par défaut|L'agrégat public, ou l'unique interface publique, porte l'adresse IP publique|
|OLA|Aucune : l'adresse IP publique n'est plus accessible|

Les agrégats créés par chaque mode dépendent du nombre d'interfaces du serveur.

**Quatre interfaces, sur les gammes Scale et High Grade :** par défaut, les deux interfaces publiques forment un agrégat et les deux interfaces privées un autre. Avec OLA, les quatre n'en forment qu'un seul, dédié au vRack.

<img className="thumbnail" alt="Schéma comparant les agrégats par défaut à quatre interfaces et l'agrégat unique avec OLA" src="/images/bare-metal-cloud/dedicated-servers/link-aggregation-overview/four-interfaces.png" loading="lazy" />

**Deux interfaces, une publique et une privée :** par défaut, aucune n'est agrégée. Avec OLA, les deux forment un agrégat unique, dédié au vRack.

<img className="thumbnail" alt="Schéma comparant la configuration par défaut à deux interfaces et l'agrégat unique avec OLA" src="/images/bare-metal-cloud/dedicated-servers/link-aggregation-overview/two-interfaces.png" loading="lazy" />

:::warning
Un serveur dont les interfaces sont intégralement agrégées pour le vRack n'a plus aucune interface réseau publique : il ne peut donc plus atteindre le service de netboot d'OVHcloud. Consultez le guide « [Gestion du reboot de vos serveurs avec la fonctionnalité OVHcloud Link Aggregation](/guides/bare-metal-cloud/dedicated-servers/pxe-with-full-private-dedicated) » avant d'activer OLA.

:::

### Configurer les agrégats pendant l'installation

Sur les serveurs **Scale** et **High Grade**, l'installation peut configurer les agrégats pour vous, afin que le serveur démarre déjà agrégé.

Les agrégats sont **toujours** configurés, et l'option n'est **pas proposée**, sur :

- **Ubuntu Server** 26.04

L'option est proposée, et **désactivée par défaut**, sur :

- **AlmaLinux**
- **Debian**, sauf Debian 11
- **Fedora**
- **Proxmox Virtual Environment** et **Proxmox Backup Server**
- **Rocky Linux**, sauf Rocky Linux 8
- **Ubuntu Server** 22.04 et 24.04
- **Windows Server**, sauf les images Hyper-V
- [Bring Your Own Image (BYOI)](/guides/bare-metal-cloud/dedicated-servers/bring-your-own-image) et [Bring Your Own Linux (BYOLinux)](/guides/bare-metal-cloud/dedicated-servers/bring-your-own-linux)

Pour l'activer :

- dans votre espace client OVHcloud, cochez la case correspondante dans l'assistant d'installation.
- via l'API, renseignez la personnalisation `enableLacpBonding`, comme décrit dans le guide « [Installer un OS via l'API OVHcloud sur un serveur dédié](/guides/bare-metal-cloud/dedicated-servers/api-os-installation) ».

Aucun autre système d'exploitation ne configure les agrégats pendant l'installation : vous devez donc le faire vous-même ensuite.

:::info
L'option peut être activée sur n'importe quel serveur, mais elle n'a d'effet que si le serveur dispose d'interfaces à agréger.

:::

### Configurer les agrégats vous-même

Si votre système d'exploitation ne propose pas l'option à l'installation, ou si vous préférez configurer les agrégats ensuite, suivez le guide correspondant à votre système :

|Système d'exploitation ou contexte|Guide|
|---|---|
|Debian 12 ou plus récent, Ubuntu 24.04 ou plus récent|[Configuration Netplan](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-netplan)|
|Debian 9 à 11, mode rescue et images personnalisées utilisant `ifupdown`|[Configuration ifupdown](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-ifupdown)|
|SLES 15|[Configuration SLES 15](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-sles15)|
|Windows Server 2019 avec OLA|[Configuration du NIC teaming](/guides/bare-metal-cloud/dedicated-servers/ola-enable-w2k19)|
|Proxmox VE|[Réseau Proxmox VE](/guides/bare-metal-cloud/dedicated-servers/proxmox-network-hg-scale)|
|Windows Server avec Hyper-V|[Réseau Hyper-V](/guides/bare-metal-cloud/dedicated-servers/hyperv-network-hg-scale)|

### Comment une agrégation est répartie entre les cartes réseau

Sur les serveurs **Scale** et **High Grade**, une agrégation est répartie entre deux cartes réseau distinctes, afin qu'elle survive à la panne d'une carte entière et non seulement à celle d'un switch. Pour plus d'informations, consultez le guide « [Amélioration de la résilience réseau sur les serveurs Bare Metal](/guides/bare-metal-cloud/dedicated-servers/lacp-resilience-scale-hg) ».
