## Objectif

La technologie OVHcloud Link Aggregation (OLA) est conçue par nos équipes pour augmenter la disponibilité de votre serveur et améliorer l'efficacité de vos connexions réseau. En quelques clics, vous pouvez agréger vos cartes réseau et rendre vos liaisons réseau redondantes. Cela signifie que si une liaison tombe en panne, le trafic est automatiquement redirigé vers une autre liaison disponible.<br/>
L'agrégation utilise le protocole LACP (Link Aggregation Control Protocol), défini par la norme IEEE 802.3ad.

**Découvrez comment configurer OLA dans la console OVHcloud.**

## Prérequis

- Disposer d'un [serveur dédié OVHcloud](/links/bare-metal/bare-metal) de gamme Advance, Scale ou High Grade
- Un système d'exploitation / hyperviseur supportant le protocole d'aggrégation 802.3ad (LACP)

[[cpnav:baremetal-dedicated-servers]]

## En pratique

:::warning
La configuration OLA se fait sur la totalité des interfaces réseaux. Elles formeront un agrégat de type « agrégation privée ».

Suite à la mise en oeuvre d'OLA, l'IP publique ne sera donc plus accessible.

:::


### Configurer OLA dans la console OVHcloud

{/* CP-STEPS-START:configure-ola */}

Pour commencer à configurer OLA, ouvrez l'onglet <code className="action">Connectivité</code> sur la page de gestion de votre serveur.

Dans la section **OVHcloud Link Aggregation (OLA)**, cliquez sur <code className="action">Configurer l'OLA</code>.

Dans la fenêtre **Configurer l'agrégation OLA**, saisissez un nom pour votre agrégation de liens dans le champ **Nommez l'interface**.

Sous ce champ, deux tableaux comparent votre configuration avant et après l'agrégation :
- **Votre interface réseau actuelle** : la configuration actuelle de vos interfaces réseau ;
- **Votre interface réseau après activation** : la configuration simulée de vos interfaces réseau agrégées.

:::warning
Vos interfaces réseau seront déconfigurées et votre serveur perdra sa connectivité pendant la configuration de l'agrégation. Pour que votre réseau fonctionne, vous devez suivre la procédure KVM IPMI détaillée dans la documentation OLA, sans quoi la configuration reste incomplète.
:::

Une fois que vous avez vérifié que la configuration de l'agrégation correspond à vos besoins réseau, cliquez sur <code className="action">Agréger</code> pour procéder.

{/* CP-STEPS-END:configure-ola */}

L'opération peut prendre quelques minutes. Une fois celle-ci terminée, l'étape suivante consiste à configurer les interfaces dans votre système d'exploitation via une liaison NIC ou une équipe NIC. Pour connaître la méthode à appliquer, consultez les guides suivants qui la détaillent pour les systèmes d'exploitation les plus populaires :

- [Comment configurer l'agrégation de liens LACP sur Debian 9 à 11 (ifupdown)](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-ifupdown).
- [Comment configurer le NIC Teaming pour OVHcloud Link Aggregation (OLA) sur Windows Server 2019](/guides/bare-metal-cloud/dedicated-servers/ola-enable-w2k19).
- [Comment configurer l'agrégation de liens LACP dans SLES 15](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-sles15).
- [Comment configurer l'agrégation de liens LACP sur Debian 12 ou plus récent / Ubuntu 24.04 ou plus récent (Netplan)](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-netplan).

### Vérification du statut OLA

{/* CP-STEPS-START:check-ola-status */}

Vous pouvez vérifier le statut de votre agrégation de liens OVHcloud Link Aggregation (OLA) dans l'onglet <code className="action">Connectivité</code> de la page de gestion de votre serveur. Dans la section **OVHcloud Link Aggregation (OLA)**, la ligne **OLA** indique le statut et la ligne **Mode** le type d'agrégation.

Les combinaisons possibles sont les suivantes :
- **Disponible**, mode **Par défaut** : OLA est pris en charge mais n'est pas configuré.
- **Actif**, mode **Full private** : OLA est activé ; toutes les interfaces physiques sont agrégées dans un seul lien privé pour une utilisation vRack.
- **Disponible**, mode **Double LAG** : OLA est pré-activé ; les interfaces physiques sont réparties en deux agrégats distincts (un public, un privé).
- **Modification en cours** : un changement de configuration OLA est en cours d'application.

Si OLA n'est pas pris en charge sur ce modèle de serveur dédié, la section **OVHcloud Link Aggregation (OLA)** affiche **OLA non inclus**, et la ligne **OLA** de la section **Connectivité** de l'onglet <code className="action">Vue d'ensemble</code> du serveur indique **Indisponible**.

:::info
Le mode **Double LAG** est une configuration spécifique généralement réservée aux gammes de serveurs Scale et High-Grade, qui disposent de quatre interfaces réseau physiques.

:::

{/* CP-STEPS-END:check-ola-status */}

### Restauration des valeurs par défaut d'OLA

{/* CP-STEPS-START:restore-ola-default */}

Pour restaurer OLA aux valeurs par défaut, ouvrez l'onglet <code className="action">Connectivité</code> et cliquez sur <code className="action">Réinitialiser</code> dans la section **OVHcloud Link Aggregation (OLA)**. Ce bouton n'apparaît que lorsque OLA est actif en mode **Full private**. Cliquez ensuite sur <code className="action">Confirmer</code> dans la fenêtre **Réinitialiser OVHcloud Link Aggregation**.

L'opération peut prendre quelques minutes.

{/* CP-STEPS-END:restore-ola-default */}
