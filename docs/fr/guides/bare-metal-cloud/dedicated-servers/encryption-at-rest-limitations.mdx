## Objectif

**Ce guide liste les conditions qu'un serveur dédié doit remplir pour utiliser l'Encryption at Rest, ainsi que les limites qui s'appliquent actuellement.**

:::info
Les clés de chiffrement sont générées, stockées et renouvelées par OVHcloud. L'utilisation de vos propres clés n'est pas disponible. Pour plus d'informations, consultez [Qu'est-ce que l'Encryption at Rest sur un serveur dédié ?](./encryption-at-rest-overview)
:::

## Prérequis

- Disposer d'un [serveur dédié](/links/bare-metal/bare-metal) dans votre compte OVHcloud

## En pratique

Les tableaux ci-dessous résument l'éligibilité et les limites. Consultez-les avant d'activer l'Encryption at Rest.

### Éligibilité

Un serveur doit remplir toutes les conditions suivantes :

| Sujet | Condition |
|---|---|
| **Gamme** | Serveurs dédiés Scale. Les autres gammes ne sont pas encore éligibles. [TODO: R-4 — confirm the eligible plans at GA; QA Campaign C1 tested Scale gen 3 Intel (26scaleintel*) and AMD (26scaleamd*)] |
| **Région** | Europe et Canada : datacenters de Roubaix, Gravelines, Strasbourg, Paris, Limburg, Erith, Varsovie, Beauharnois et Toronto. Les autres régions ne sont pas encore disponibles. |
| **Démarrage** | Le serveur démarre via le démarrage réseau standard d'OVHcloud. |
| **Réseau** | OVHcloud Link Aggregation (OLA) n'est pas activé. |
| **État du serveur** | Le serveur est en service. L'Encryption at Rest ne peut pas être activée sur un serveur suspendu ou bloqué. |

Pour vérifier un serveur donné, utilisez la vérification d'éligibilité de l'[API OVHcloud](./encryption-at-rest-api#eligibility-check).

### Incompatibilités

Certaines fonctionnalités ne peuvent pas être combinées avec l'Encryption at Rest :

| Fonctionnalité | Statut |
|---|---|
| **OVHcloud Link Aggregation (OLA)** | Non compatible. Leur utilisation conjointe nécessite la fonctionnalité Private Boot, qui n'est pas encore disponible. D'ici là, les deux fonctionnalités s'excluent mutuellement. |
| **Script de démarrage personnalisé** | Non compatible. |
| **Mode rescue Windows** | Non compatible. Le mode rescue Linux est pris en charge et les disques sont déverrouillés automatiquement, comme lors d'un démarrage normal. |

### Limites

Les limites suivantes s'appliquent :

| Sujet | Limite |
|---|---|
| **Granularité** | Tous les disques du serveur, ou aucun. Vous ne pouvez pas choisir les disques un par un. |
| **Planification** | L'opération démarre immédiatement. Elle ne peut pas être planifiée ni associée à une fenêtre de maintenance. |
| **Durée** | Jusqu'à 24 heures de bout en bout, davantage si une intervention en datacenter est nécessaire. Les autres opérations sur le serveur sont refusées pendant ce temps. |
| **Données** | L'activation efface toutes les données et nécessite une réinstallation du système d'exploitation. La désactivation efface les disques par effacement cryptographique et nécessite également une réinstallation. |

| **Clés** | Gérées uniquement par OVHcloud. Les clés client et le déverrouillage manuel ne sont pas disponibles. |
| **Notifications** | Aucune alerte sur les événements de déverrouillage. |
| **Remplacement de disque** | Un disque remplacé est chiffré au démarrage suivant du serveur. [TODO: confirm the wording with the hardware team] |
