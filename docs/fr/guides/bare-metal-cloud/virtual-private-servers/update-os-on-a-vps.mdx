## Objectif

La mise à jour du système d'exploitation (OS) de votre serveur est essentielle pour maintenir la sécurité, la stabilité et les performances de vos services. Pour savoir si votre version d'OS atteint sa fin de support (*End of Support* / *End of Life*), vous pouvez consulter notre [guide sur le cycle de vie des images](/guides/public-cloud/compute/image-life-cycle).

Deux approches sont possibles :

1. **La mise à niveau en place (*In-Place Upgrade*)** : la méthode la plus rapide et la plus économique. Elle met à jour le système directement sur votre machine existante sans changer d'adresse IP ni transférer vos fichiers.
2. **La migration côte à côte (*Side-by-Side*)** : idéale si vous souhaitez repartir sur un environnement intégralement neuf ou tester la migration en parallèle sans impacter votre production.

**Ce guide vous explique comment mettre à jour l'OS de votre VPS OVHcloud.**

## Prérequis

- Disposer d'un [VPS](/links/bare-metal/vps) dans votre compte OVHcloud
- Avoir un accès SSH root (ou sudo) à votre VPS
- Avoir créé un snapshot (ou disposer d'une sauvegarde quotidienne) avant toute manipulation

## En pratique

### Étape préalable obligatoire : sécurisez votre VPS avec un snapshot

Quelle que soit la méthode choisie, sécurisez vos données avant toute manipulation.

#### 1. La sauvegarde automatique quotidienne (VPS post-août 2025)

Si vous disposez d'un VPS issu de la gamme commercialisée depuis le **7 août 2025**, votre serveur bénéficie d'une sauvegarde automatique quotidienne du système (hors disques additionnels). Cette sauvegarde est conservée pendant **24 heures**. En cas d'imprévu majeur, vous pouvez restaurer l'image automatique la plus récente directement depuis votre espace client OVHcloud.

#### 2. Le snapshot manuel (état exact à l'instant T)

Pour capturer l'état de votre serveur juste avant la mise à jour, créez un **snapshot** depuis votre espace client OVHcloud, comme décrit dans le guide [Utiliser le snapshot](/guides/bare-metal-cloud/virtual-private-servers/using-snapshots-on-a-vps).

Le snapshot est une **option payante** et un seul snapshot peut être actif à la fois sur un VPS. Il enregistre l'état de la machine à un instant précis : données applicatives, fichiers, configurations système et état de l'OS (noyau, paquets, dépendances). Il ne constitue pas pour autant une sauvegarde complète du système. La cohérence du snapshot repose sur l'agent *qemu-guest-agent*, qui n'est pas installé par défaut sur la plupart des distributions : vérifiez sa présence sur votre VPS avant de lancer la mise à jour.

:::info
**Votre filet de sécurité** — Si une interruption survient pendant la mise à jour (coupure réseau, conflit de paquets, incohérence applicative), cliquez sur <code className="action">Restaurer le snapshot</code> (ou appliquez votre dernière sauvegarde quotidienne) dans l'espace client OVHcloud pour réinitialiser votre VPS dans son état d'origine. La restauration **supprime** le snapshot : pour en conserver un, créez-en un nouveau avant tout autre changement.
:::

### Méthode 1 : la mise à niveau en place (*In-Place Upgrade*)

C'est la solution recommandée dans la plupart des cas. Elle s'effectue directement sur votre serveur actuel.

:::warning
**Avertissement important — Serveurs avec Plesk ou cPanel**

Si votre VPS utilise un panneau de gestion **Plesk** ou **cPanel**, ne suivez pas les procédures de mise à niveau directe ci-dessous. Sans les utilitaires dédiés des éditeurs, les outils génériques (Leapp, `dist-upgrade`) risquent de corrompre votre installation et vos licences.

- Pour **Plesk** (passage de CentOS 7 vers AlmaLinux 8) : utilisez le script officiel `centos2alma` proposé par Plesk.
- Pour **cPanel** (passage de CentOS 7 vers AlmaLinux 8) : utilisez l'outil officiel **Elevate** proposé par cPanel.

Ces outils s'adressent aux utilisateurs expérimentés, ne sont pas garantis à 100 % et nécessitent une sauvegarde complète avant toute opération.

Pour toutes les options de migration (y compris les outils automatiques de serveur à serveur), consultez le guide [Fin du support Plesk et cPanel pour VPS](/guides/bare-metal-cloud/virtual-private-servers/eos-cpanel-plesk).

:::

#### Option A : distributions Debian et Ubuntu

##### 1. Créer le snapshot

Ouvrez <ManagerLink to="/#/dedicated/vps">Gestion VPS</ManagerLink>, sélectionnez votre VPS, puis, depuis l'onglet <code className="action">Accueil</code>, descendez jusqu'au cadre « Sauvegarde » et utilisez le menu <code className="action">...</code> de l'option « Snapshot ».

##### 2. Mettre à jour le système actuel

Connectez-vous en SSH à votre VPS et appliquez tous les correctifs disponibles sur votre version actuelle :

```bash
sudo apt update
sudo apt upgrade
sudo apt full-upgrade
```

Examinez les paquets devenus inutiles avant de les supprimer :

```bash
sudo apt --purge autoremove
```

Si un nouveau noyau Linux a été installé, redémarrez le VPS :

```bash
sudo reboot
```

##### 3. Engager la montée de version majeure

<Tabs>
<Tab label="Ubuntu">

Lancez l'outil officiel de Canonical :

```bash
sudo do-release-upgrade
```

Suivez les instructions à l'écran.

</Tab>
<Tab label="Debian">

Exemple : passage de Debian 11 « Bullseye » à Debian 12 « Bookworm ».

1. Sauvegardez vos sources APT actuelles :

```bash
sudo cp -v /etc/apt/sources.list /root/
sudo cp -rv /etc/apt/sources.list.d/ /root/
```

2. Éditez `/etc/apt/sources.list` et remplacez toutes les occurrences du nom de l'ancienne version par la nouvelle. Pour Debian 12, vérifiez également la présence du composant `non-free-firmware` si votre configuration l'utilise :

```bash
sudo nano /etc/apt/sources.list
```

3. Vérifiez les fichiers de `/etc/apt/sources.list.d/` et mettez à jour ou désactivez temporairement les dépôts tiers qui ne proposent pas encore de paquets pour la nouvelle version cible.

4. Actualisez l'index puis lancez la mise à niveau en **2 temps**, sans ajout automatique de `-y` :

```bash
sudo apt update
sudo apt upgrade
sudo apt full-upgrade
```

</Tab>
</Tabs>

:::warning
**Points d'attention pendant l'installation**

- **Écran d'information** (`apt-listchanges`) : si un deux-points (`:`) apparaît en bas d'écran, appuyez sur `q` pour fermer la notice et reprendre la mise à jour.
- **Fichiers de configuration modifiés** : si le système propose de remplacer un fichier de configuration existant, privilégiez la version du mainteneur, puis vérifiez les éventuels fichiers `.dpkg-old` ou `.dpkg-dist` avant de remettre en place vos personnalisations.

:::

##### 4. Redémarrage et vérification

Une fois le processus terminé, redémarrez votre serveur :

```bash
sudo reboot
```

Vérifiez l'OS actif via `cat /etc/os-release`. Si vos services web et applications fonctionnent correctement, vous pouvez supprimer le snapshot depuis l'espace client OVHcloud.

#### Option B : distributions AlmaLinux, Rocky Linux et CentOS Stream

Pour les OS de la famille Red Hat, la transition vers la version 9 utilise le framework ELevate / Leapp.

##### 1. Créer le snapshot

Créez le snapshot depuis <ManagerLink to="/#/dedicated/vps">Gestion VPS</ManagerLink> et attendez la fin de l'opération avant de poursuivre.

##### 2. Mettre à jour les paquets existants

```bash
sudo dnf update -y
sudo reboot
```

##### 3. Installer l'outil de migration ELevate

Installez le dépôt ELevate, puis sélectionnez le paquet de données de votre distribution. Pour **RHEL**, consultez la documentation officielle Red Hat — [mise à niveau avec Leapp](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/8/html/upgrading_from_rhel_7_to_rhel_8/) ou [migration RHEL 8 vers RHEL 9](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/9/html/upgrading_from_rhel_8_to_rhel_9/) — plutôt qu'un paquet de données ELevate.

```bash
# Installation du dépôt ELevate et de l'outil Leapp
sudo dnf install -y https://repo.almalinux.org/elevate/elevate-release-latest-el8.noarch.rpm
sudo yum install -y leapp-upgrade

# Installation du paquet de données selon votre OS (exécutez UNIQUEMENT la ligne concernée) :
sudo yum install -y leapp-data-almalinux    # Pour AlmaLinux
sudo yum install -y leapp-data-rocky        # Pour Rocky Linux
sudo yum install -y leapp-data-centos       # Pour une mise à niveau vers CentOS Stream
```

##### 4. Valider l'éligibilité et lancer la mise à niveau

Avant la mise à niveau, générez l'analyse initiale, lisez le rapport Leapp, répondez aux questions bloquantes, puis lancez la migration :

```bash
# Lancer la pré-vérification du système
sudo leapp preupgrade

# Lire le rapport détaillé avant de continuer
sudo less /var/log/leapp/leapp-report.txt

# Répondre explicitement aux questions bloquantes identifiées par le rapport
sudo leapp answer --section remove_pam_pkcs11_module_check.confirm=True

# Lancer la mise à niveau vers la version 9
sudo leapp upgrade
```

En cas d'erreur bloquante pendant la pré-vérification, corrigez d'abord les points signalés dans `/var/log/leapp/leapp-report.txt`. Pour **RHEL**, référez-vous à la documentation officielle Red Hat sur les migrations majeures avec Leapp.

##### 5. Bascule et finalisation

Redémarrez votre serveur pour exécuter la bascule du noyau vers la version 9 :

```bash
sudo reboot
```

Le premier redémarrage peut durer plusieurs minutes (installation des paquets en arrière-plan et réétiquetage SELinux).

Une fois le système de nouveau accessible, contrôlez la version et nettoyez les paquets de migration :

```bash
# Vérifier la version installée
cat /etc/os-release

# Supprimer les outils de migration et nettoyer le cache
sudo dnf remove -y leapp-upgrade 'leapp-data-*'
sudo dnf autoremove -y
```

### Méthode 2 : la migration côte à côte (*Side-by-Side*)

Cette méthode consiste à déployer un second VPS OVHcloud neuf, à y installer vos services, puis à basculer vos données et votre trafic réseau sans risque d'interruption prolongée.

#### 1. Commander et préparer le nouveau VPS

Depuis le site OVHcloud ou votre espace client OVHcloud, commandez un nouveau VPS avec la version d'OS cible.

Une fois le VPS livré, connectez-vous et installez vos services (serveur web, moteur de base de données, Docker, etc.).

#### 2. Transférer vos données et configurations

- **Bases de données** : exécutez un dump depuis le VPS source (`mysqldump` ou `pg_dump`) puis importez le fichier `.sql` sur le nouveau VPS.
- **Fichiers utilisateurs / web** : synchronisez vos répertoires (ex. `/var/www/` ou `/home/`) de serveur à serveur via `rsync` :

```bash
rsync -avz -e ssh /var/www/ root@IP_DU_NOUVEAU_VPS:/var/www/
```

- **Panneaux de gestion (ex. Plesk, cPanel)** : si votre VPS utilise un panneau de gestion, utilisez son outil de migration intégré (Plesk Migrator / cPanel Transfer Tool) pour automatiser le transfert des comptes et bases, ou suivez le guide [Fin du support Plesk et cPanel pour VPS](/guides/bare-metal-cloud/virtual-private-servers/eos-cpanel-plesk).

#### 3. Tester le nouvel environnement

Avant de basculer vos utilisateurs, vérifiez que votre site ou application fonctionne sur la nouvelle IP (par exemple en adaptant temporairement votre fichier `hosts` local).

#### 4. Basculer le trafic vers le nouveau VPS

- **Si vous utilisez une Additional IP** : dans votre espace client OVHcloud, ouvrez <ManagerLink to="/#/network/ip">IP publiques</ManagerLink> (<code className="action">Network</code> > <code className="action">Adresses IP Publiques</code>), puis basculez l'Additional IP depuis l'ancien VPS vers le nouveau VPS. Certains produits imposent un passage préalable par un **Parking IP**, seul un bloc de taille /32 peut être déplacé vers un VPS et les MAC virtuelles sont temporairement suspendues pendant l'opération : consultez le guide [Déplacer une Additional IP](/guides/bare-metal-cloud/dedicated-servers/move-failover-ip) pour les conditions détaillées.
- **Si vous utilisez les DNS standards** : modifiez les enregistrements DNS (`A` / `AAAA`) de votre nom de domaine pour pointer vers la nouvelle adresse IP de votre nouveau VPS.

#### 5. Résilier l'ancien serveur

Une fois la bascule validée et les délais de propagation DNS écoulés (24 à 48 heures recommandées), vous pouvez résilier l'ancien VPS depuis votre espace client OVHcloud.

### En cas d'incident pendant la procédure

Si votre VPS ne répond plus au réseau ou ne démarre plus après une mise à niveau en place :

1. Ouvrez <ManagerLink to="/#/dedicated/vps">Gestion VPS</ManagerLink> puis sélectionnez le VPS concerné.
2. Dans le cadre « Sauvegarde », utilisez le menu <code className="action">...</code> de l'option « Snapshot » ou appliquez votre sauvegarde automatique la plus récente.
3. Cliquez sur <code className="action">Restaurer le snapshot</code> ou lancez la restauration de la sauvegarde souhaitée.

Votre VPS revient à son état d'origine en quelques minutes.
