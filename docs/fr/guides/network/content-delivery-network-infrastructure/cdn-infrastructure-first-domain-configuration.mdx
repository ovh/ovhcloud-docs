## Objectif

Lors de la première configuration du Content Delivery Network (CDN), il est nécessaire de déclarer vos domaines depuis la console OVHcloud et d'effectuer des configurations vous permettant de l'utiliser de manière optimale.

**Ce guide vous explique les manipulations à effectuer dans la console OVHcloud ainsi que les bonnes pratiques d'utilisation du CDN d'OVHcloud.**

## Prérequis

- Bénéficier du [Content Delivery Network (CDN) d'OVHcloud](https://www.ovhcloud.com/fr/network/cdn/).
- Avoir accès à la gestion de la zone DNS de votre nom de domaine.

[[cpnav:network-cdn]]

## En pratique

### Ajouter le nom de domaine sur le CDN

La première étape de cette configuration est l'ajout du sous-domaine de votre choix au CDN pour que celui-ci accepte les requêtes HTTP(S) pour ce domaine.

{/* CP-STEPS-START:add-domain */}

Ouvrez l'onglet <code className="action">Domaines</code> et cliquez sur <code className="action">Ajouter un domaine</code>. La page **Configuration guidée d'un domaine** s'ouvre et vous accompagne en quatre étapes :

<img className="thumbnail" alt="Onglet Domaines d'un CDN avec le bouton Ajouter un domaine" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/domains-tab.png" loading="lazy" />

1. **Nom de domaine** : saisissez le sous-domaine à servir via le CDN, sous la forme d'un nom de domaine complet (par exemple `www.example.com`), puis cliquez sur <code className="action">Suivant</code>.
2. **Origine (IPv4)** : saisissez l'adresse IPv4 du serveur d'origine qui héberge vos fichiers (votre *backend*), puis cliquez sur <code className="action">Suivant</code>.
3. **Certificat SSL** : choisissez **Let's Encrypt** pour obtenir automatiquement un certificat HTTPS gratuit, ou **Sans SSL** pour servir le domaine uniquement en HTTP (vous pourrez ajouter un certificat plus tard). Cette étape n'apparaît pas si votre CDN possède déjà un certificat. Pour en savoir plus, consultez notre guide sur le [fonctionnement du certificat SSL sur le CDN](/guides/network/content-delivery-network-infrastructure/cdn-infrastructure-ssl-certificate).
4. **Confirmation et déploiement** : vérifiez le récapitulatif, puis cliquez sur <code className="action">Déployer</code>.

<img className="thumbnail" alt="Configuration guidée d'un domaine, étape Nom de domaine" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/guided-setup-step1.png" loading="lazy" />

La page affiche ensuite l'avancement du déploiement : création du domaine, configuration de l'origine et, si vous l'avez choisi, provisionnement du certificat SSL. Une fois le déploiement terminé, elle indique la cible vers laquelle doit pointer l'enregistrement CNAME de votre domaine (de la forme `<votre domaine>.cdn.ovhcloud.com`, par exemple `www.example.com.cdn.ovhcloud.com`). Copiez cette cible, vous en aurez besoin à l'étape suivante. Cliquez sur <code className="action">Terminé</code>. Votre domaine apparaît alors dans l'onglet <code className="action">Domaines</code>, avec son origine et son statut, et vous pouvez commencer à le configurer.

<img className="thumbnail" alt="Fin de la configuration guidée d'un domaine, avec la cible CNAME" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/guided-setup-cname.png" loading="lazy" />

Pour que vos requêtes passent bien par notre infrastructure CDN, vous devez modifier la zone DNS de votre sous-domaine afin qu'un enregistrement CNAME pointe vers cette cible.

:::warning
L'utilisation de l'enregistrement CNAME est importante. Elle permet à la fonction `Bypass` de fonctionner correctement. Si vous utilisez un enregistrement de type A, le CDN sera fonctionnel, mais vous perdrez l'usage du *bypass*.

:::

Si la zone DNS de votre domaine est gérée par OVHcloud, ajoutez cet enregistrement CNAME à la zone depuis la console OVHcloud, en adaptant le sous-domaine à votre configuration : indiquez votre sous-domaine (par exemple `cdn`) et, comme cible, la valeur affichée à la fin de la configuration guidée. Pour savoir comment ajouter un enregistrement, consultez notre guide pour [éditer une zone DNS OVHcloud](/guides/web-cloud/domains/dns-zone-edit).

{/* CP-STEPS-END:add-domain */}

 

### Vérifier qu'un fichier est bien mis en cache
Vous pouvez vérifier qu'un fichier se trouve bien en cache en effectuant une requête à son propos :

```sh
curl -I http://sous.domaine/
```

Vous obtiendrez alors un résultat semblable à celui-ci :

```bash
HTTP/1.1 200 OK
Date: Tue, 09 Jan 2018 10:30:57 GMT
Content-Type: text/plain
Last-Modified: Fri, 29 Dec 2017 13:30:42 GMT
ETag: W/"(5a464382-4ddf"
Expires: Wed, 09 Jan 2019 10:30:58 GMT
X-IPLB-Instance: 5905
Vary: Accept-Encoding
X-CDN-Pop: rbx1
X-CDN-Pop-IP: 51.254.41.128/26
X-Cacheable: Matched cache
Accept-Ranges: bytes
Connection: keep-alive
```

Si votre fichier est bien appelé à partir du cache, vous obtiendrez alors la mention `Matched cache`.

Vous pouvez également retrouver le point de présence (PoP) d'où votre fichier a été appelé (*rbx1* dans notre exemple).

Ce type d'information est également accessible dans votre navigateur web, via l'onglet `Réseau` dans les outils de développement (la touche de raccourci F12). En cliquant sur le fichier que vous souhaitez vérifier, vous retrouvez la réponse HTTP et ses en-têtes.

### Préférer l'utilisation d'un sous-domaine spécifique au CDN à celle du domaine principal

Il est impossible d'effectuer un enregistrement CNAME sur un domaine principal. Il s'agit d'une limitation liée aux normes RFC et celle-ci ne peut pas être contournée au niveau de la zone DNS.

L'attribution d'un nom de domaine spécifique aux fichiers que vous souhaitez avoir en cache vous permet d'avoir une meilleure gestion :

- de vos fichiers : seuls les fichiers appelés sur ce sous-domaine seront mis en cache. Vous pouvez ainsi conserver l'appel de vos fichiers dynamiques ou de ceux que vous ne souhaitez pas mettre en cache sur votre nom de domaine principal. Cela vous permet également de déterminer plus rapidement l'origine d'un défaut d'affichage sur votre site ;

- de votre facturation : l'ensemble du trafic (mis en cache ou non) passant par le CDN étant facturé, cela vous permet de limiter le nombre de requêtes non utiles effectuées vers le CDN pour optimiser l'utilisation de votre quota.

### Les implications liées à un nouveau sous-domaine

Si vous souhaitez configurer un nouveau sous-domaine pour utiliser notre CDN, vous devrez probablement modifier certaines configurations au niveau de votre site et de votre service web.

Assurez-vous d'abord que votre service web répond correctement à ce sous-domaine. Pour cela, vous devez configurer un *vhost* pour ce domaine, soit avec son propre dossier-cible, soit en alias d'un autre nom de domaine.

Si le domaine répond correctement au niveau de votre service web, vous n'avez plus qu'à modifier votre code HTML afin de changer les sources des fichiers qui doivent passer par le CDN et vous assurer que ceux-ci sont bien appelés sur votre sous-domaine.
