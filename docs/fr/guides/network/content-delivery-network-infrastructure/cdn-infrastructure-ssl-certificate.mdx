## Objectif

Il est possible d'ajouter un [certificat SSL](https://www.ovhcloud.com/fr/web-hosting/options/ssl/) à votre offre Content Delivery Network (CDN) afin que vos utilisateurs puissent effectuer des connexions sécurisées, même en passant par le CDN.

**Dans ce guide, nous allons vous détailler le fonctionnement du SSL Let's Encrypt fourni par OVHcloud, ainsi que l'ajout de votre propre certificat.**

## Prérequis

- Posséder l'[offre CDN d'OVHcloud](https://www.ovhcloud.com/fr/network/cdn/).
- Avoir accès à la gestion de la zone DNS de votre domaine.

## En pratique

### Obtenir le certificat Let's Encrypt fourni par OVHcloud pour mes sous-domaines utilisant le CDN

{/* CP-STEPS-START:lets-encrypt-certificate */}

- Si votre CDN ne possède pas encore de certificat, vous pouvez faire créer un certificat Let's Encrypt gratuit au moment d'ajouter un domaine : dans la **Configuration guidée d'un domaine**, choisissez **Let's Encrypt** à l'étape **Certificat SSL**. Vous pouvez aussi le créer à tout moment depuis l'onglet <code className="action">SSL</code> : cliquez sur <code className="action">Ajouter un certificat</code>, sélectionnez **Let's Encrypt (gratuit)**, saisissez un nom pour le certificat et cliquez sur <code className="action">Ajouter un certificat</code>.
- Si votre CDN possède déjà un certificat lorsque vous ajoutez un autre sous-domaine, la configuration guidée passe l'étape SSL : le certificat sera automatiquement régénéré afin d'y inclure le nouveau sous-domaine que vous venez de configurer.

Pour que la création du certificat se déroule correctement, le sous-domaine que vous ajoutez doit pointer correctement vers le CDN, et le port 80 doit être accessible sur le CDN pour la validation Let's Encrypt. Pour vérifier que votre sous-domaine pointe vers le CDN, référez-vous au guide vous indiquant comment effectuer une [première configuration d'un nom de domaine](/guides/network/content-delivery-network-infrastructure/cdn-infrastructure-first-domain-configuration).

Le renouvellement du certificat est effectué de manière automatique dans les 20 jours précédant l'expiration du certificat.

:::warning
Le certificat Let's Encrypt fourni par OVHcloud peut prendre en charge les 100 premiers noms de domaine ou sous-domaines configurés sur le CDN. Si vous souhaitez la prise en charge de plus de 100 domaines, vous devrez configurer votre propre certificat Wildcard/Multi-domaines.
:::

{/* CP-STEPS-END:lets-encrypt-certificate */}

### Mon certificat est en cours de création, quels sont les délais ?

{/* CP-STEPS-START:generation-time */}

Une fois que votre domaine pointe correctement vers le CDN, la génération (ou régénération) d'un certificat Let's Encrypt et son déploiement prennent environ 2 minutes.

Tant qu'une opération SSL est en cours, l'onglet <code className="action">SSL</code> vous l'indique et se rafraîchit automatiquement.

Si la génération prend plus de temps que prévu, l'onglet <code className="action">SSL</code> affiche un message ainsi qu'un lien <code className="action">Voir les opérations SSL</code>, qui liste les opérations SSL de votre CDN dans l'onglet **Opérations**. Vérifiez alors que le nom de domaine configuré sur votre CDN pointe bien vers le CDN et que le port 80 est accessible. Si ce n'est pas le cas, notre robot ne parviendra pas à créer le certificat correctement.

Il n'y a pas de délai d'expiration : tant que vos modifications DNS ne sont pas propagées, la génération reste en attente, puis elle aboutit dès que le domaine pointe vers le CDN. Vous n'avez pas besoin de demander un nouveau certificat.

Une fois le certificat activé, l'onglet <code className="action">SSL</code> l'affiche dans la partie **Informations du certificat** : son nom, son fournisseur (**Let's Encrypt** ou **Certificat personnalisé**), son statut, son nom commun (CN) et ses dates de validité.

{/* CP-STEPS-END:generation-time */}

### Ajouter son propre certificat

{/* CP-STEPS-START:add-own-certificate */}

Si votre CDN ne possède pas encore de certificat, vous pouvez importer votre propre certificat depuis l'onglet <code className="action">SSL</code>, même avant la propagation de vos modifications DNS. Cliquez sur <code className="action">Ajouter un certificat</code>, sélectionnez **Importer un certificat personnalisé**, puis renseignez un nom (facultatif), votre certificat et sa clé privée au format PEM et, si votre autorité de certification l'exige, la chaîne de certificats. Cliquez sur <code className="action">Ajouter un certificat</code> pour valider.

<img className="thumbnail" alt="Onglet SSL d'un CDN sans certificat" src="/images/network/content-delivery-network-infrastructure/ssl-certificate/ssl-tab.png" loading="lazy" />

<img className="thumbnail" alt="Fenêtre Ajouter un certificat" src="/images/network/content-delivery-network-infrastructure/ssl-certificate/ssl-add-certificate.png" loading="lazy" />

Si votre CDN possède déjà un certificat, par exemple un certificat Let's Encrypt, cliquez sur <code className="action">Mettre à jour le certificat</code> dans l'onglet <code className="action">SSL</code>. Renseignez votre nouveau certificat, sa clé privée et, si besoin, sa chaîne, puis cliquez sur <code className="action">Mettre à jour le certificat</code>.

{/* CP-STEPS-END:add-own-certificate */}
