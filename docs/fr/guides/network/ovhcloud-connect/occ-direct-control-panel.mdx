## Objectif

OVHcloud Connect permet d’étendre votre réseau d’entreprise avec votre réseau privé OVHcloud vRack sans passer par la création d’un tunnel VPN à travers Internet. Cette connexion sera ainsi plus rapide, plus fiable et avec une bande passante garantie. 

**Ce guide vous présente la mise en service de l'offre OVHcloud Connect Direct depuis la console OVHcloud**

## Prérequis

:::warning
Pour assurer un fonctionnement correct de ce service, vous devez prendre connaissance des [capacités et limites techniques de l'offre OVHcloud Connect](/guides/network/ovhcloud-connect/occ-limits) et configurer vos équipements réseau en accord avec celles-ci.

:::

- Posséder une [offre OVHcloud Connect Direct](https://www.ovhcloud.com/fr/network/ovhcloud-connect/)
- Disposer d'un [vRack OVHcloud](https://www.ovhcloud.com/fr/network/vrack/)

[[cpnav:network-ovhcloud-connect]]

## En pratique

{/* CP-STEPS-START:cp-access */}

Sélectionnez votre service dans la liste **OVHcloud Connect**.

{/* CP-STEPS-END:cp-access */}

### Étape 1: associer un vRack

{/* CP-STEPS-START:associate-vrack */}

Vous devez commencer par associer un vRack à votre offre. Dans l'onglet **Vue d'ensemble** de votre service, cliquez sur <code className="action">Associer un vRack</code>, sélectionnez un vRack existant dans le menu déroulant, puis cliquez sur <code className="action">Associer</code>.

La page du service affiche alors **Association du vRack en cours** : l'association peut prendre quelques minutes.

{/* CP-STEPS-END:associate-vrack */}

### Étape 2: ajouter une configuration PoP

:::warning
Un changement de configuration PoP de L2 à L3, ou inversement, nécessiterait de supprimer toute la configuration. Nous vous conseillons donc de bien réfléchir à votre choix de configuration avant d'aller plus loin.

:::

:::info
Pour plus de détails sur les différences entre les niveaux L2 et L3, consultez notre [FAQ](/guides/network/ovhcloud-connect/faq).

:::

#### Configuration L2 

{/* CP-STEPS-START:pop-configuration-l2 */}

Une fois votre vRack associé, ouvrez l'onglet <code className="action">Configurer</code> de votre service. La section **Configuration PoP** affiche une ligne par port. Sur la ligne du premier port, cliquez sur <code className="action">Configurer</code>. Dans la fenêtre **Ajouter une configuration PoP**, laissez **L2** sélectionné comme **Type de couche**, puis cliquez sur <code className="action">Ajouter</code>.

La configuration L2 apparaît alors sur la ligne du port, avec **L2** dans la colonne **Couche**.

{/* CP-STEPS-END:pop-configuration-l2 */}

#### Configuration L3 

{/* CP-STEPS-START:pop-configuration-l3 */}

Une fois votre vRack associé, ouvrez l'onglet <code className="action">Configurer</code>. Dans la section **Configuration PoP**, cliquez sur <code className="action">Configurer</code> sur la ligne de votre port, puis sélectionnez **L3** comme **Type de couche** dans la fenêtre **Ajouter une configuration PoP**.

Vous devrez alors saisir les éléments suivants, puis cliquer sur <code className="action">Ajouter</code> :

| Information    | Description |
|:-------:|:------:|
| ASN client    | Votre numéro d'AS BGP, qui est configuré sur votre routeur situé dans le PoP |
| ASN OVHcloud    | Le numéro d'AS OVHcloud qui sera configuré sur les routeurs de OVHcloud Connect situés dans le PoP |
| Sous-réseau de peering (/30)    | Un bloc IPv4 de taille /30, utilisé pour le lien entre votre routeur et le routeur OVHcloud Connect situé dans le PoP |

La ligne du port affiche alors **L3** dans la colonne **Couche**, ainsi que l'**ASN utilisateur**, l'**ASN OVHcloud**, le **Sous-réseau** et le **Statut BGP** de la configuration.

Vous pouvez également ajouter une seconde configuration PoP L3 sur la ligne du second port, avec son propre bouton <code className="action">Configurer</code>.

{/* CP-STEPS-END:pop-configuration-l3 */}

### Étape 3: ajout d'une configuration Zone de disponibilité

#### Configuration L2 

{/* CP-STEPS-START:az-configuration-l2 */}

Lorsque votre configuration PoP est active, cliquez sur <code className="action">Ajouter une configuration AZ</code> dans la section **Configuration des zones de disponibilité**. Dans la fenêtre **Ajouter une configuration AZ**, sélectionnez une zone de disponibilité dans le menu déroulant **Datacentre**, puis cliquez sur <code className="action">Ajouter</code>.

La configuration de la zone de disponibilité apparaît alors dans la section **Configuration des zones de disponibilité**, avec son statut.

Un lien L2 ne porte qu'une seule zone de disponibilité : pour en configurer une autre, supprimez d'abord celle qui est configurée.

{/* CP-STEPS-END:az-configuration-l2 */}

#### Configuration L3 

{/* CP-STEPS-START:az-configuration-l3 */}

Lorsque votre configuration PoP a été définie, cliquez sur <code className="action">Ajouter une configuration AZ</code> dans la section **Configuration des zones de disponibilité**.

Dans la fenêtre **Ajouter une configuration AZ**, sélectionnez une zone de disponibilité dans le menu déroulant **Datacentre**, puis renseignez les informations requises et cliquez sur <code className="action">Ajouter</code>.

| Information    | Description |
|:-------:|:------:|
| ASN OVHcloud    | Le numéro d'AS OVHcloud qui sera configuré sur les routeurs OVHcloud Connect situés dans l'AZ. Ce numéro peut être différent de l'ASN choisi pour le PoP |
| Sous-réseau    |  Un sous-réseau privé configuré dans votre vRack dans l'AZ sélectionnée. Cela peut être un bloc IPv4 de taille /28 ou supérieur |

Vous pouvez ajouter des configurations AZ supplémentaires avec le même bouton <code className="action">Ajouter une configuration AZ</code>, en haut de la section.

Vous devez également ajouter une configuration de routage.

{/* CP-STEPS-END:az-configuration-l3 */}

##### **Ajout d'une configuration de routage**

{/* CP-STEPS-START:add-routing-configuration */}

Cliquez sur le bouton <code className="action">⋮</code> de la zone de disponibilité voulue, puis sur <code className="action">Ajouter une route</code>. Si la zone de disponibilité n'a pas encore de route, vous pouvez aussi cliquer sur le bouton <code className="action">Ajouter une route</code> affiché dans celle-ci.

Dans la fenêtre **Ajouter une route**, choisissez le **Type de route** entre **Statique** et **BGP**.

Si vous choisissez le type BGP, saisissez alors les informations requises :

| Information    | Description |
|:-------:|:------:|
| ASN voisin    | Votre numéro d'AS BGP, qui est configuré sur votre routeur situé dans l'AZ |
| IP voisin    | Adresse IP du voisin BGP de votre routeur dans l'AZ. Cette adresse doit faire partie du sous-réseau renseigné dans la section **Configuration des zones de disponibilité** |

Si vous choisissez le type Statique, saisissez les informations requises :

| Information    | Description |
|:-------:|:------:|
| Sous-réseau cible    | Un préfixe utilisant la notation CIDR |
| Prochain saut    | Adresse IP agissant comme passerelle dans la plage de sous-réseau |

Cliquez ensuite sur <code className="action">Ajouter</code>.

Vous pouvez ajouter plusieurs configurations de routage au sein d'une même zone de disponibilité : elles sont listées dans son tableau **Routage**.

{/* CP-STEPS-END:add-routing-configuration */}

### Suppression des ressources

Chaque ressource (PoP ou AZ) peut être supprimée individuellement, mais la suppression d’une ressource parente telle que AZ ou POP supprimera automatiquement toutes les sous-ressources.

La suppression récursive est plus lente que la suppression séquentielle de chaque ressource.

:::info
Si une configuration AZ est partagée entre au moins deux services OVHcloud Connect, la suppression de la configuration PoP d’un seul service OVHcloud Connect n’affectera pas la ressource AZ.

:::

#### Suppression d'une configuration de routage

{/* CP-STEPS-START:delete-routing-configuration */}

Pour supprimer une configuration de routage, cliquez sur le bouton <code className="action">⋮</code> de la colonne **Actions** de la route à supprimer, dans le tableau **Routage** de sa zone de disponibilité, puis sur <code className="action">Supprimer la route</code>. Dans la fenêtre **Supprimer la route**, cliquez sur <code className="action">Supprimer</code>.

{/* CP-STEPS-END:delete-routing-configuration */}

#### Suppression d'une configuration AZ

{/* CP-STEPS-START:delete-az-configuration */}

Pour supprimer une configuration AZ, cliquez sur le bouton <code className="action">⋮</code> de la configuration AZ à supprimer, puis sur <code className="action">Supprimer la configuration AZ</code>. Dans la fenêtre **Supprimer le centre de données**, cliquez sur <code className="action">Supprimer</code>.

{/* CP-STEPS-END:delete-az-configuration */}

:::info
La suppression d'une configuration AZ entraînera la suppression des configurations de routage liées.

:::

#### Suppression d'une configuration PoP

{/* CP-STEPS-START:delete-pop-configuration */}

Pour supprimer une configuration PoP, dans la section **Configuration PoP**, cliquez sur le bouton <code className="action">⋮</code> de la colonne **Actions** du port à supprimer, puis sur <code className="action">Supprimer la configuration</code>. Dans la fenêtre **Supprimer la configuration**, cliquez sur <code className="action">Supprimer</code>.

{/* CP-STEPS-END:delete-pop-configuration */}

:::info
La suppression d'une configuration PoP entraînera la suppression des configurations AZ et de routage liées.

:::
