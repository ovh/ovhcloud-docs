## Objectif

La surveillance vous permet de vérifier que votre lien et votre session BGP sont sains, de suivre leur activité dans le temps, d’être averti des événements importants et d’obtenir des diagnostics ponctuels. Utilisez-la pour confirmer qu’une nouvelle configuration fonctionne comme prévu et pour recueillir des éléments lors d’un incident. Ce guide présente les outils et les métriques disponibles.

## Outils de surveillance

### Console OVHcloud

{/* CP-STEPS-START:ovhcloud-control-panel */}
La console OVHcloud vous donne accès aux informations suivantes :

| Élément | Description |
|---|---|
| **Statut du lien** (tableau **Configuration PoP**, onglet <code className="action">Configurer</code>) | Indique si le lien physique est actif ou inactif. Affiché uniquement pour les services OVHcloud Connect Direct. |
| **Statuts optiques** (tableau **Configuration PoP**, onglet <code className="action">Configurer</code>) | Niveaux de signal optique IN/OUT sur le port physique (vérifiés toutes les 5 minutes). Affiché uniquement pour les services OVHcloud Connect Direct. |
| **Statut BGP** (tableau **Configuration PoP**, onglet <code className="action">Configurer</code>) | Indique si la session BGP est active ou inactive. Affiché dès qu’au moins un port est configuré en Layer 3. |
| Section **Informations techniques** (onglet <code className="action">Vue d'ensemble</code>) | Point de présence, bande passante, vRack, secteur, circuit, nombre de ports (Direct) et Service Key (Provider). L’état du service est indiqué dans la liste des services. |

L’état de la session BGP ainsi que les routes apprises/annoncées sont obtenus via les diagnostics à la demande décrits ci-dessous.

L’onglet <code className="action">Statistiques</code> du service présente son activité dans le temps sous forme de graphiques. Dans la liste déroulante **Type**, sélectionnez **Traffic réseau**, **Niveaux optiques**, **Routes BGP entrantes** ou **Taux d'erreur** (les niveaux optiques et le taux d’erreur ne sont disponibles que pour les services OVHcloud Connect Direct), puis, dans la liste déroulante **Périodicité**, sélectionnez **Toutes les heures**, **Journalier** ou **Hebdomadaire**.

Pour gérer les notifications d’un service, cliquez sur le bouton en forme de cloche situé sur sa ligne dans la liste des services : la fenêtre **Gestion des notifications** s’ouvre. Vous pouvez y activer ou désactiver quatre notifications : **PoP Interface status** (interface active ou inactive), **BGP status change**, **Optical level degradation** et **Packet loss**. La colonne **Notifications actives** de la liste indique le nombre de notifications activées sur chaque service.
{/* CP-STEPS-END:ovhcloud-control-panel */}

### API OVHcloud

Pour une surveillance programmatique et une intégration avec vos propres outils :

```python
import ovh

client = ovh.Client(endpoint='ovh-eu')

service_name = "your-occ-service-uuid"

# Get service status
service = client.get(f"/ovhCloudConnect/{service_name}")
print(f"Status: {service['status']}")

# List PoP configuration IDs, then fetch each PoP's status
pop_ids = client.get(f"/ovhCloudConnect/{service_name}/config/pop")
for pop_id in pop_ids:
    print(client.get(f"/ovhCloudConnect/{service_name}/config/pop/{pop_id}/status"))
```

> Référence complète de l’API : [eu.api.ovh.com/console](https://eu.api.ovh.com/console/?section=%2FovhCloudConnect&branch=v1)

### Vos propres outils de surveillance

Au-delà des statistiques et des notifications disponibles dans la console OVHcloud, la surveillance continue de votre côté de la connexion s’effectue avec vos propres outils. Sur votre routeur de périphérie et votre pile de surveillance, vous pouvez par exemple :

- **SNMP** — Interrogez les interfaces de votre routeur pour obtenir les compteurs de trafic, les taux d’erreur et l’état des interfaces.
- **Surveillance BGP** — Utilisez des outils tels que `bgpstream`, `exabgp` ou la surveillance intégrée de votre routeur pour suivre la stabilité de la session BGP et les changements de préfixes.
- **Sondes ping / latence** — Mettez en place des pings réguliers ou des mesures de latence entre votre réseau on-premises et les ressources OVHcloud.
- **Plateformes tierces** — Des outils comme Datadog, Zabbix, PRTG ou Grafana peuvent agréger les métriques provenant de votre propre infrastructure.

Ces pratiques génériques, propres au client, ne sont pas des fonctionnalités OVHcloud.

## Diagnostics à la demande

{/* CP-STEPS-START:on-demand-diagnostics */}
Vous pouvez lancer des diagnostics à la demande depuis la console OVHcloud pour obtenir un rapport d’état ponctuel de votre service OVHcloud Connect. Chaque diagnostic s’exécute en temps réel sur les équipements côté OVHcloud et renvoie un résultat que vous pouvez consulter ou télécharger.
{/* CP-STEPS-END:on-demand-diagnostics */}

### Diagnostics disponibles

{/* CP-STEPS-START:available-diagnostics */}
**Mode Layer 3 :**

| Diagnostic | Description |
|---|---|
| **Default** | Récupère l’état de la session BGP et les informations associées. Dans l’espace client, ce diagnostic est déclenché par l’action <code className="action">Check BGP peering</code> sur la configuration PoP. |
| **Routes** | Récupère la table de routage apprise par OVHcloud via BGP (routes reçues de votre côté). |
| **Advertised-Routes** | Récupère la table de routage annoncée par OVHcloud à votre côté. |

**Mode Layer 2 :**

| Diagnostic | Description |
|---|---|
| **MAC Address** | Récupère la liste des adresses MAC vues sur le segment Layer 2 entre vos équipements réseau et le vRack. |

{/* CP-STEPS-END:available-diagnostics */}
### Lancer un diagnostic

{/* CP-STEPS-START:launch-diagnostic */}
1. Ouvrez le service OVHcloud Connect que vous souhaitez diagnostiquer, sur l’onglet <code className="action">Configure</code>.
2. Dans le tableau `PoP configuration`, cliquez sur le bouton points de suspension <code className="action">...</code> sur la ligne du port.
3. Sélectionnez le diagnostic à exécuter — par exemple <code className="action">Check BGP peering</code> en mode Layer 3, ou le diagnostic d’adresses MAC en mode Layer 2.
{/* CP-STEPS-END:launch-diagnostic */}

### Récupérer un résultat

{/* CP-STEPS-START:retrieve-result */}
1. Ouvrez l’onglet <code className="action">Diagnostic</code> du service. Chaque diagnostic y est listé avec son **ID Diagnostic**, sa **Date**, son **Nom**, son **Scope** et son **Statut**. Si un diagnostic que vous venez de lancer n’apparaît pas encore, cliquez sur <code className="action">Rafraîchir</code>.
2. Une fois le diagnostic terminé, cliquez sur le bouton <code className="action">⋮</code> dans la colonne **Actions** de sa ligne.
3. Sélectionnez <code className="action">Voir le résultat</code> pour afficher la sortie dans la fenêtre **Résultat du diagnostic**, ou <code className="action">Télécharger</code> pour l’enregistrer dans un fichier `.txt`.
{/* CP-STEPS-END:retrieve-result */}

### Limites

| Limite | Valeur |
|---|---|
| **Rétention** | Seuls les diagnostics initiés **au cours des sept derniers jours** sont accessibles. Téléchargez et archivez ceux que vous souhaitez conserver. |
| **Limite de débit** | **10 diagnostics par type, par service et par période de 24 heures.** Cela s’applique indépendamment à chaque type de diagnostic (Default, Routes, Advertised-Routes, MAC Address). |

:::info

Les diagnostics sont également disponibles de manière programmatique via l’API OVHcloud sous les endpoints `/ovhCloudConnect/{serviceName}/diagnostic/...`. Consultez la <ApiLink section="/ovhCloudConnect">console API</ApiLink> pour la liste complète.

:::

## Éléments à surveiller

<img className="thumbnail" alt="Éléments à surveiller" src="/images/network/ovhcloud-connect/occ-monitor/fig-1.fr.svg" loading="lazy" />

Surveillez les conditions suivantes dans la console OVHcloud et depuis votre propre outil de supervision :

{/* CP-STEPS-START:what-to-watch-for */}
| Condition | Comment la détecter | Action |
|---|---|---|
| **Lien down** | L’état du port physique passe à « Down » (colonne **Statut du lien** dans la console OVHcloud / votre routeur) | Vérifiez le cross-connect, le SFP et contactez le datacenter ou le fournisseur |
| **Session BGP down** | La colonne **Statut BGP** de la console OVHcloud passe de « Up » à « Down », ou votre routeur n’indique plus la session comme « Established » (vous pouvez aussi lancer le diagnostic **Default**) | Vérifiez la configuration du routeur, l’accessibilité du pair et les règles de pare-feu |
| **Changement du nombre de préfixes** | Augmentation ou diminution inattendue des préfixes reçus/envoyés (lancez les diagnostics **Routes** / **Advertised-Routes**, consultez le graphique **Routes BGP entrantes** de l’onglet **Statistiques** ou vérifiez votre routeur) | Investiguez d’éventuelles fuites de routes ou modifications de configuration |

{/* CP-STEPS-END:what-to-watch-for */}

## Bonnes pratiques

{/* CP-STEPS-START:best-practices */}
- **Surveillez des deux côtés** — Vérifiez le statut et les valeurs optiques dans la console OVHcloud, ainsi que les métriques de trafic/BGP sur votre propre routeur.
- **Établissez une référence pour vos métriques** — Enregistrez la bande passante, la latence et le nombre de préfixes en conditions normales afin de pouvoir détecter les anomalies.
- **Automatisez les alertes de votre côté** — Dans la console OVHcloud, activez les notifications de la fenêtre **Gestion des notifications** : elles couvrent l’état des interfaces, les changements de statut BGP, la dégradation du niveau optique et la perte de paquets. Pour les autres événements critiques, configurez des notifications automatiques dans votre propre pile de surveillance.
- **Lancez des diagnostics au besoin** — Utilisez les diagnostics à la demande pour confirmer l’état BGP et l’échange de routes lors de l’investigation d’un problème.
- **Testez la bascule** — Si votre configuration est redondante (plusieurs PoP, ou des sessions BGP avec votre propre routeur dans chaque zone de disponibilité), testez périodiquement la bascule et vérifiez que la surveillance détecte le basculement.

{/* CP-STEPS-END:best-practices */}
