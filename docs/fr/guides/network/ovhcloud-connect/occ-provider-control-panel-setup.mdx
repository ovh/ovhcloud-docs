## Objectif

OVHcloud Connect Provider est l’option gérée par un opérateur : un opérateur réseau tiers établit le lien physique vers un PoP OVHcloud pour votre compte, ce qui vous évite d’avoir à être présent dans le même datacenter qu’OVHcloud. Il s’agit toujours d’un service Layer 3. Ce guide de démarrage rapide couvre le parcours de bout en bout — de la commande jusqu’à un lien configuré — afin qu’à la fin vous disposiez d’une connexion acheminant du trafic vers vos ressources OVHcloud.

## Avant de commencer

Assurez-vous de disposer de :

- ✅ Un **compte OVHcloud** avec une facturation configurée
- ✅ Un contrat ou un compte chez un **provider pris en charge** (consultez Providers{/* TODO(occ-revamp): restore this link before the final merge, once the revamp guide lands → [Providers](/guides/network/ovhcloud-connect/providers) */})
- ✅ Un **routeur** prenant en charge le peering BGP (OVHcloud Connect Provider est toujours un service Layer 3)
- ✅ Un **plan d’adressage IP** prévu et un **ASN**

### Étape 1 — Commander OVHcloud Connect Provider

{/* CP-STEPS-START:order-occ-provider */}
1. Sur la page OVHcloud Connect de la console OVHcloud, cliquez sur <code className="action">Commander un OVHcloud Connect</code>. La page produit OVHcloud Connect s’ouvre sur le site OVHcloud, dans un nouvel onglet.
2. Sous **OVHcloud Connect Provider**, cliquez sur <code className="action">Commander</code>.
3. À l’étape **Configurez votre OVHcloud Connect Provider**, choisissez votre **Fournisseur**, la **Bande passante** garantie (de 50 Mbit/s à 5 Gbit/s) et le **Point of Presence** (les PoP proposés dépendent du fournisseur), puis cliquez sur <code className="action">Continuer la commande</code>.
4. Vérifiez la tarification et finalisez la commande.
5. OVHcloud génère une **clé de service** destinée à votre provider. Une fois votre service affiché dans la console OVHcloud, vous retrouvez cette clé dans son onglet <code className="action">Vue d’ensemble</code>, tuile **Informations techniques**, sous **Service Key** (la mention **Aucune clé de service générée** s’affiche tant qu’il n’y en a pas ; cliquez sur <code className="action">Régénérer</code> pour en générer une nouvelle).
{/* CP-STEPS-END:order-occ-provider */}

Pour les étapes détaillées, consultez Commander OVHcloud Connect Provider{/* TODO(occ-revamp): restore this link before the final merge, once the revamp guide lands → [Commander OVHcloud Connect Provider](/guides/network/ovhcloud-connect/order-provider) */}.

### Étape 2 — Partager la clé de service

Communiquez la **clé de service** à votre provider. Cette clé permet au provider d’identifier et d’activer la connexion vers OVHcloud pour votre compte.

Dans le portail de votre provider, créez la connexion vers OVHcloud et saisissez la clé de service. Consultez le guide Providers{/* TODO(occ-revamp): restore this link before the final merge, once the revamp guide lands → [Providers](/guides/network/ovhcloud-connect/providers) */}.

### Étape 3 — Le provider provisionne la connexion

Le provider met en place le lien physique et logique entre son infrastructure et le PoP OVHcloud. Cela est généralement rapide (de quelques minutes à quelques heures pour les providers à la demande), mais les délais peuvent varier.

Vous pouvez suivre le statut de la connexion à la fois dans la **console OVHcloud** et dans le **portail de votre provider**.

### Étape 4 — Configurer votre service dans la console OVHcloud

{/* CP-STEPS-START:configure-service */}
Une fois votre service affiché comme « Active » dans la colonne **Statut** de la liste des OVHcloud Connect, ouvrez-le dans la console OVHcloud : sélectionnez <code className="action">Bare Metal Cloud</code> (ou <code className="action">Private Cloud</code>) dans la barre supérieure, accédez à <code className="action">Réseau</code> > <code className="action">OVHcloud Connect</code>, puis sélectionnez votre service. Celui-ci s’ouvre sur l’onglet <code className="action">Vue d’ensemble</code> ; sa configuration se fait depuis l’onglet <code className="action">Configurer</code>. OVHcloud Connect Provider est toujours un service **Layer 3**.
{/* CP-STEPS-END:configure-service */}

#### Associer un vRack

{/* CP-STEPS-START:associate-a-vrack */}
Dans l’onglet <code className="action">Vue d’ensemble</code>, cliquez sur <code className="action">Associer un vRack</code> dans le message **Aucun vRack associé** (ou, dans la tuile **Informations techniques**, cliquez sur <code className="action">Associer</code> à côté de **vRack**). Dans la fenêtre **Associer un vRack**, sélectionnez un vRack existant dans la liste déroulante, puis cliquez sur <code className="action">Associer</code>. Le message **Association du vRack en cours** s’affiche alors sur la page du service : l’association du vRack peut prendre quelques minutes.
{/* CP-STEPS-END:associate-a-vrack */}

Consultez Associer un OVHcloud Connect à votre vRack{/* TODO(occ-revamp): restore this link before the final merge, once the revamp guide lands → [Associer un OVHcloud Connect à votre vRack](/guides/network/ovhcloud-connect/associate-vrack) */}.

#### Ajouter une configuration de PoP (L3)

{/* CP-STEPS-START:add-a-pop-configuration */}
Dans l’onglet <code className="action">Configurer</code>, section **Configuration PoP**, cliquez sur <code className="action">Configurer</code> sur la ligne de votre port (son **État de la configuration** indique **Not Configured**) pour ouvrir la fenêtre **Ajouter une configuration PoP**. Aucun type de couche n’est à choisir : un service provider ne prend en charge que le L3. Renseignez les informations suivantes, puis cliquez sur <code className="action">Ajouter</code> :

| Information | Description |
|---|---|
| ASN client | Votre numéro d’AS BGP, configuré sur votre routeur situé dans le PoP |
| ASN OVHcloud | Le numéro d’AS configuré sur les routeurs OVHcloud Connect situés dans le PoP |
| Sous-réseau de peering (/30) | Un bloc IPv4 en /30, utilisé pour le lien entre votre routeur et le routeur OVHcloud dans le PoP |
{/* CP-STEPS-END:add-a-pop-configuration */}

#### Ajouter une configuration de zone de disponibilité (AZ)

{/* CP-STEPS-START:add-an-az-configuration */}
Dans la section **Configuration des zones de disponibilité**, cliquez sur <code className="action">Ajouter une configuration AZ</code>. Dans la fenêtre **Ajouter une configuration AZ**, sélectionnez la zone de disponibilité dans la liste **Datacentre**, renseignez les informations suivantes, puis cliquez sur <code className="action">Ajouter</code> :

| Information | Description |
|---|---|
| ASN OVHcloud | Le numéro d’AS configuré sur les routeurs OVHcloud Connect dans l’AZ (peut différer de l’ASN du PoP) |
| Sous-réseau | Un sous-réseau privé configuré dans votre vRack dans l’AZ sélectionnée (un bloc IPv4 en /28 ou plus grand) |

Si votre service compte plusieurs configurations PoP, la fenêtre vous demande également de choisir la **Configuration PoP**.
{/* CP-STEPS-END:add-an-az-configuration */}

#### Ajouter une configuration de routage

{/* CP-STEPS-START:add-a-routing-configuration */}
À côté du nom de la zone de disponibilité, cliquez sur le bouton <code className="action">⋮</code>, puis sélectionnez <code className="action">Ajouter une route</code>. Si la zone n’a encore aucune route, vous pouvez aussi cliquer directement sur <code className="action">Ajouter une route</code> dans sa table de routage. Dans la fenêtre **Ajouter une route**, choisissez **BGP** ou **Statique** comme **Type de route** :

- **BGP** — saisissez votre ASN dans **ASN voisin**, ainsi que l’**IP voisin** (l’adresse IP du voisin BGP de votre routeur dans l’AZ, comprise dans le sous-réseau de l’AZ).

- **Statique** — saisissez le **Sous-réseau cible** (un préfixe en notation CIDR) et le **Prochain saut** (une adresse IP de passerelle comprise dans la plage du sous-réseau).

Cliquez sur <code className="action">Ajouter</code> pour valider.

Vous pouvez ajouter plusieurs configurations de routage dans la même zone de disponibilité, dans la limite de 20 routes statiques par datacenter.
{/* CP-STEPS-END:add-a-routing-configuration */}

### Étape 5 — Vérifier la session BGP et le routage

OVHcloud Connect Provider est toujours un service Layer 3 — un peering BGP est établi entre votre routeur (ou celui de votre provider, selon l’offre du provider) et le PoP OVHcloud. Vérifiez dans la console OVHcloud et dans le portail de votre provider que la session est établie et que les routes sont bien échangées.

Consultez Configurer OCC L3 avec BGP{/* TODO(occ-revamp): restore this link before the final merge, once the revamp guide lands → [Configurer OCC L3 avec BGP](/guides/network/ovhcloud-connect/l3-bgp) */} pour des instructions détaillées.

### Étape 6 — Tester et vérifier

{/* CP-STEPS-START:test-and-verify */}
| Vérification | Comment |
|---|---|
| **Statut de la connexion** | Affiche « Active » dans la colonne **Statut** de la liste des OVHcloud Connect dans la console OVHcloud, ainsi que dans le portail du provider |
| **Session BGP** | Établie sur votre routeur ; dans la console OVHcloud, la colonne **Statut BGP** de la section **Configuration PoP** (onglet <code className="action">Configurer</code>) affiche « Up » (« Down » si la session est en échec) |
| **Routes** | Vos préfixes sont visibles côté OVHcloud ; les routes OVHcloud sont visibles de votre côté |
| **Ping** | Envoyez un ping vers une ressource OVHcloud depuis votre réseau |
| **Traceroute** | Vérifiez que le trafic emprunte le lien privé et non Internet |
{/* CP-STEPS-END:test-and-verify */}

## Dépannage

{/* CP-STEPS-START:troubleshooting */}
| Problème | Que vérifier |
|---|---|
| Service bloqué à l’étape « Attente du fournisseur » (pendant sa livraison, un service figure dans l’onglet <code className="action">En cours de livraison</code> de la liste des OVHcloud Connect) | Vérifiez que la clé de service a été correctement saisie côté provider |
| Le provider affiche « Active » mais le **Statut BGP** de votre configuration PoP dans la console OVHcloud indique « Down » | Contactez le support OVHcloud — il peut s’agir d’un délai de provisionnement |
| La session BGP ne s’établit pas | Vérifiez les IPs de peering, l’ASN et l’ID VLAN sur votre routeur, ainsi que les ASN et le sous-réseau de peering dans la section **Configuration PoP** de la console OVHcloud |
| Latence élevée ou perte de paquets | Consultez la page de statut réseau du provider ; exécutez un traceroute pour identifier où se produisent les délais |
{/* CP-STEPS-END:troubleshooting */}
