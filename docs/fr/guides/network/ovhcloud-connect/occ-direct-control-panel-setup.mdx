## Objectif

OVHcloud Connect Direct est l’option auto-gérée : vous êtes propriétaire du cross-connect physique dans un PoP OVHcloud et vous gérez vous-même les niveaux Layer 2 et Layer 3, sans provider tiers. Choisissez cette option lorsque votre équipement (ou un circuit) atteint déjà un datacenter où OVHcloud dispose d’un PoP. Ce guide de démarrage rapide couvre le parcours de bout en bout — de la commande à un lien configuré — afin qu’à la fin vous disposiez d’une connexion privée acheminant du trafic vers vos ressources OVHcloud.

## Avant de commencer

Assurez-vous de disposer de :

- ✅ Un **compte OVHcloud** avec une facturation configurée
- ✅ Un équipement (ou un circuit) dans un **datacenter où OVHcloud dispose d’un PoP** (consultez [Emplacements des PoPs](/guides/network/ovhcloud-connect/pop-locations-regions))
- ✅ Un **routeur** doté d’interfaces fibre optique monomode (avec prise en charge de BGP pour le mode Layer 3)
- ✅ Pour le **Layer 3** : un **plan d’adressage IP** prévu (IPs de peering et préfixes) et un **ASN** public ou privé
- ✅ Pour le **Layer 2** : les **VLANs** que vous souhaitez étendre vers OVHcloud (aucun ASN ni plan d’adressage IP requis)

Connectez-vous à votre <ManagerLink to="/">espace client OVHcloud</ManagerLink>, ouvrez la section <code className="action">Bare Metal Cloud</code>, puis accédez à <code className="action">Network</code> > <code className="action">OVHcloud Connect</code> et sélectionnez votre solution.

### Étape 1 — Commander OVHcloud Connect Direct

1. Sélectionnez <code className="action">OVHcloud Connect Direct</code>.
2. Choisissez votre **emplacement de PoP** et la **bande passante** (par exemple 1, 10 ou 100 Gbps).
3. Renseignez les détails techniques : votre ASN, vos coordonnées et toute instruction particulière pour le datacenter.
4. Vérifiez la tarification et confirmez la commande.

Pour les étapes de commande détaillées, consultez [Commander OVHcloud Connect Direct](/guides/network/ovhcloud-connect/order-direct).

### Étape 2 — Recevoir la LOA

Une fois votre commande validée, OVHcloud vous envoie une **Lettre d’autorisation (LOA)** par e-mail. Ce document contient :

- La référence du datacenter et du rack/cage de l’équipement OVHcloud
- La désignation du port côté OVHcloud
- Les instructions pour l’opérateur du datacenter

### Étape 3 — Installer le cross-connect physique

Remettez la LOA à votre **opérateur de datacenter** (ou prenez-la en charge vous-même si vous gérez votre propre cage). Il installera un câble de brassage en fibre optique entre le port de votre routeur et le port désigné d’OVHcloud.

Cette étape peut prendre quelques jours selon les processus du datacenter.

### Étape 4 — Associer à votre vRack

Reliez votre service OVHcloud Connect à votre **vRack** afin que vos ressources OVHcloud (serveurs, VMs, etc.) puissent communiquer via la connexion privée.

Consultez [Associer un OVHcloud Connect à votre vRack](/guides/network/ovhcloud-connect/associate-vrack).

### Étape 5 — Configurer votre service dans l’espace client OVHcloud

Une fois le lien physique opérationnel, ouvrez votre solution depuis la section <code className="action">Bare Metal Cloud</code> > <code className="action">Network</code> > <code className="action">OVHcloud Connect</code> et configurez-la.

#### Associer un vRack

Si ce n’est pas déjà fait, cliquez sur <code className="action">Associer un vRack</code> et sélectionnez un vRack existant dans le menu déroulant. Un message confirme l’association.

#### Ajouter une configuration de PoP

Dans le tableau `PoP configuration`, cliquez sur <code className="action">Configurer le port</code> pour ouvrir le formulaire **Ajouter une configuration de PoP**, puis définissez le **Type** :

- **L2** — sélectionnez L2 et confirmez. Il s’agit d’un lien point à point transparent (un PoP, une zone de disponibilité).

- **L3** — sélectionnez L3 et renseignez :

| Information | Description |
|---|---|
| User ASN | Votre numéro d’AS BGP, configuré sur votre routeur situé dans le PoP |
| OVHcloud ASN | Le numéro d’AS configuré sur les routeurs OVHcloud Connect situés dans le PoP |
| Subnetwork in /30 | Un bloc IPv4 en /30, utilisé pour le lien entre votre routeur et le routeur OVHcloud dans le PoP |

#### Ajouter une configuration de zone de disponibilité (AZ)

Sous la section `AZ configuration`, cliquez sur <code className="action">Ajouter un AZ</code>, sélectionnez une zone de disponibilité et (pour le L3) renseignez :

| Information | Description |
|---|---|
| OVHcloud ASN | Le numéro d’AS configuré sur les routeurs OVHcloud Connect dans l’AZ (peut différer de l’ASN du PoP) |
| A /28 subnetwork | Un sous-réseau privé configuré dans votre vRack dans l’AZ sélectionnée (un bloc IPv4 de /28 ou plus grand) |

#### Ajouter une configuration de routage

Sur la zone de disponibilité, cliquez sur <code className="action">Règles de routage</code> pour ajouter une configuration de routage, et choisissez **BGP** ou **Static** :

- **BGP** — renseignez votre **User ASN** et l’**IP Neighbour** (l’IP du voisin BGP de votre routeur dans l’AZ, comprise dans le sous-réseau de l’AZ).

- **Static** — renseignez le **Network Focus** (un préfixe en notation CIDR) et le **Next hop** (une IP de passerelle comprise dans la plage du sous-réseau).

Vous pouvez ajouter plusieurs configurations de routage dans la même zone de disponibilité ; le type (BGP ou Static) choisi pour la première s’applique aux autres.

Ensuite, sur **votre routeur**, configurez la session BGP correspondante (ou les routes statiques) et annoncez les préfixes que vous souhaitez atteindre depuis OVHcloud. Pour des conseils de routage détaillés, consultez [Configurer OCC L3 avec BGP](/guides/network/ovhcloud-connect/l3-bgp) ou [Configurer OCC L3 avec des routes statiques](/guides/network/ovhcloud-connect/l3-static).

:::info
La configuration de routage s’applique uniquement au **Layer 3**. En mode **Layer 2**, il n’y a pas de configuration de routage — une fois la configuration de PoP L2 et la configuration de zone de disponibilité actives, vos VLANs sont pontés de manière transparente. Consultez [Configurer OCC L2](/guides/network/ovhcloud-connect/l2).
:::

### Étape 6 — Tester et vérifier

Effectuez ces vérifications pour confirmer que tout fonctionne :

| Vérification | Comment |
|---|---|
| **Lien physique** | Vérifiez que le port apparaît comme « up » dans l’espace client OVHcloud et sur votre routeur. |
| **Session BGP** | Vérifiez que la session est **Established** dans l’espace client OVHcloud et sur votre routeur. |
| **Échange de routes** | Vérifiez que les routes d’OVHcloud apparaissent dans votre table de routage et inversement. |
| **Connectivité** | Envoyez un ping vers une ressource OVHcloud connue (par exemple une VM dans votre vRack) depuis votre réseau on-premises. |
| **Traceroute** | Exécutez un `traceroute` pour vérifier que le trafic emprunte bien le chemin privé (et non Internet). |

Les vérifications de la **session BGP** et de l’**échange de routes** s’appliquent au Layer 3. Pour le **Layer 2**, vérifiez que le port est up et que vos VLANs atteignent vos ressources OVHcloud (vous pouvez également exécuter un diagnostic d’adresse MAC — consultez [Superviser](/guides/network/ovhcloud-connect/monitor)).

## Dépannage

| Problème | Que vérifier |
|---|---|
| Le port apparaît « down » | Câble physique, compatibilité SFP/transceiver, statut du cross-connect côté datacenter |
| Session BGP bloquée en « Active » ou « Idle » | IPs de peering, configuration ASN, règles de pare-feu (port TCP 179) |
| Aucune route échangée | Filtres de préfixes BGP, configuration des route-maps, limites maximum-prefix |
| Impossible de pinguer les ressources OVHcloud | Association au vRack, ID VLAN, configuration des sous-réseaux dans l’AZ |

Si vous ne parvenez pas à résoudre le problème, [ouvrez un ticket de support](/guides/network/ovhcloud-connect/incident-followup) en joignant la sortie BGP, le statut des interfaces et les résultats du traceroute.
