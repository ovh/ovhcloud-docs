## Objectif

OVHcloud Connect Direct est l’option auto-gérée : vous êtes propriétaire du cross-connect physique dans un PoP OVHcloud et vous gérez vous-même les niveaux Layer 2 et Layer 3, sans provider tiers. Choisissez cette option lorsque votre équipement (ou un circuit) atteint déjà un datacenter où OVHcloud dispose d’un PoP. Ce guide de démarrage rapide couvre le parcours de bout en bout — de la commande à un lien configuré — afin qu’à la fin vous disposiez d’une connexion privée acheminant du trafic vers vos ressources OVHcloud.

## Avant de commencer

Assurez-vous de disposer de :

- ✅ Un **compte OVHcloud** avec une facturation configurée
- ✅ Un équipement (ou un circuit) dans un **datacenter où OVHcloud dispose d’un PoP** (consultez Emplacements des PoPs{/* TODO(occ-revamp): restore this link before the final merge, once the revamp guide lands → [Emplacements des PoPs](/guides/network/ovhcloud-connect/pop-locations-regions) */})
- ✅ Un **équipement** doté d’interfaces fibre optique monomode
- ✅ Pour le **Layer 3** : un **plan d’adressage IP** prévu (IPs de peering et préfixes) et un **ASN** public ou privé
- ✅ Pour le **Layer 2** : les **VLANs** que vous souhaitez étendre vers OVHcloud (aucun ASN ni plan d’adressage IP requis)

## Vue d’ensemble des étapes

<img className="thumbnail" alt="Vue d’ensemble des étapes de configuration d’OVHcloud Connect Direct depuis la console OVHcloud" src="/images/network/ovhcloud-connect/occ-direct-control-panel-setup/fig-1.fr.svg" loading="lazy" />

### Étape 1 — Commander OVHcloud Connect Direct

{/* CP-STEPS-START:order-occ-direct */}
1. Sur la page OVHcloud Connect de la console OVHcloud, cliquez sur <code className="action">Commander un OVHcloud Connect</code>. La page produit OVHcloud Connect s’ouvre sur le site OVHcloud, dans un nouvel onglet.
2. Sous **OVHcloud Connect Direct**, cliquez sur <code className="action">Commander</code>.
3. Sur la page **Configurez votre OVHcloud Connect Direct**, choisissez :
    - la **Bande passante** : 1, 10 ou 100 Gbit/s garantis ;
    - le **Nombre de ports** : 1 ou 2 ;
    - le **Point de présence** : sélectionnez sa région (Europe, Amérique du Nord ou Asie/Océanie), puis votre PoP ;
    - la **Période d'engagement** : aucun engagement, 12 mois ou 24 mois.
4. Cliquez sur <code className="action">Continuer la commande</code>, puis finalisez votre commande. Gardez vos informations techniques à portée de main : votre ASN, vos coordonnées et toute instruction particulière pour le datacenter.
{/* CP-STEPS-END:order-occ-direct */}

Pour les étapes de commande détaillées, consultez Commander OVHcloud Connect Direct{/* TODO(occ-revamp): restore this link before the final merge, once the revamp guide lands → [Commander OVHcloud Connect Direct](/guides/network/ovhcloud-connect/order-direct) */}.

### Étape 2 — Recevoir la LOA

Une fois votre commande validée, OVHcloud vous envoie une **Lettre d’autorisation (LOA)** par e-mail. Ce document contient :

- La référence du datacenter et du rack/cage de l’équipement OVHcloud
- La désignation du port côté OVHcloud
- Les instructions pour l’opérateur du datacenter

### Étape 3 — Installer le cross-connect physique

Remettez la LOA à votre **opérateur de datacenter** (ou prenez-la en charge vous-même si vous gérez votre propre cage). Il installera un câble de brassage en fibre optique entre le port de votre routeur et le port désigné d’OVHcloud.

Cette étape peut prendre quelques jours selon les processus du datacenter.

### Étape 4 — Associer à votre vRack

Reliez votre service OVHcloud Connect à votre **vRack** afin que vos ressources OVHcloud (serveurs, VMs, etc.) puissent communiquer via la connexion privée.

Consultez Associer un OVHcloud Connect à votre vRack{/* TODO(occ-revamp): restore this link before the final merge, once the revamp guide lands → [Associer un OVHcloud Connect à votre vRack](/guides/network/ovhcloud-connect/associate-vrack) */}.

### Étape 5 — Configurer votre service dans la console OVHcloud

{/* CP-STEPS-START:configure-service */}
Une fois le lien physique opérationnel, ouvrez votre service dans la console OVHcloud : sélectionnez <code className="action">Bare Metal Cloud</code> (ou <code className="action">Private Cloud</code>) dans la barre supérieure, accédez à <code className="action">Réseau</code> > <code className="action">OVHcloud Connect</code>, puis sélectionnez votre service dans la liste. Sa configuration se fait depuis l’onglet <code className="action">Configurer</code>.
{/* CP-STEPS-END:configure-service */}

#### Associer un vRack

{/* CP-STEPS-START:associate-a-vrack */}
Si ce n’est pas déjà fait, associez un vRack : dans l’onglet <code className="action">Vue d'ensemble</code>, cliquez sur <code className="action">Associer un vRack</code> dans le message **Aucun vRack associé**, ou cliquez sur <code className="action">Associer</code> à côté de **vRack** dans la section **Informations techniques**. Dans la fenêtre **Associer un vRack**, sélectionnez un vRack existant dans la liste déroulante, puis cliquez sur <code className="action">Associer</code>. Le message **Association du vRack en cours** s’affiche alors sur la page du service : l’association du vRack peut prendre quelques minutes.
{/* CP-STEPS-END:associate-a-vrack */}

#### Ajouter une configuration de PoP

{/* CP-STEPS-START:add-a-pop-configuration */}
Dans l’onglet <code className="action">Configurer</code>, rendez-vous dans la section **Configuration PoP**. Sur la ligne de votre port, cliquez sur <code className="action">Configurer</code> pour ouvrir la fenêtre **Ajouter une configuration PoP**, puis définissez le **Type de couche** :

- **L2** — sélectionnez **L2** (choix par défaut) et cliquez sur <code className="action">Ajouter</code>. Il s’agit d’un lien point à point transparent (un PoP, une zone de disponibilité).

- **L3** — sélectionnez **L3**, renseignez les informations suivantes, puis cliquez sur <code className="action">Ajouter</code> :

| Information | Description |
|---|---|
| ASN client | Votre numéro d’AS BGP, configuré sur votre routeur situé dans le PoP |
| ASN OVHcloud | Le numéro d’AS configuré sur les routeurs OVHcloud Connect situés dans le PoP |
| Sous-réseau de peering (/30) | Un bloc IPv4 en /30, utilisé pour le lien entre votre routeur et le routeur OVHcloud dans le PoP |
{/* CP-STEPS-END:add-a-pop-configuration */}

#### Ajouter une configuration de zone de disponibilité (AZ)

{/* CP-STEPS-START:add-an-az-configuration */}
Dans la section **Configuration des zones de disponibilité**, cliquez sur <code className="action">Ajouter une configuration AZ</code>. Dans la fenêtre **Ajouter une configuration AZ**, sélectionnez le **Datacentre** (la zone de disponibilité) et (pour le L3) renseignez :

| Information | Description |
|---|---|
| ASN OVHcloud | Le numéro d’AS configuré sur les routeurs OVHcloud Connect dans l’AZ (peut différer de l’ASN du PoP) |
| Sous-réseau | Un sous-réseau privé configuré dans votre vRack dans l’AZ sélectionnée (un bloc IPv4 de /28 ou plus grand) |

Cliquez sur <code className="action">Ajouter</code> pour valider. Si votre service compte plusieurs configurations PoP, la fenêtre vous demande également de choisir la **Configuration PoP**.

En L2, un service relie un PoP à une seule zone de disponibilité : une fois une AZ configurée, le bouton <code className="action">Ajouter une configuration AZ</code> est désactivé.
{/* CP-STEPS-END:add-an-az-configuration */}

#### Ajouter une configuration de routage

{/* CP-STEPS-START:add-a-routing-configuration */}
À côté du nom de la zone de disponibilité, cliquez sur le bouton <code className="action">⋮</code>, puis sélectionnez <code className="action">Ajouter une route</code> pour ajouter une configuration de routage. Si la zone n’a encore aucune route, vous pouvez aussi cliquer directement sur <code className="action">Ajouter une route</code> dans sa table de routage. Dans la fenêtre **Ajouter une route**, définissez le **Type de route** sur **BGP** ou **Statique** :

- **BGP** — renseignez l’**ASN voisin** (votre ASN) et l’**IP voisin** (l’IP du voisin BGP de votre routeur dans l’AZ, comprise dans le sous-réseau de l’AZ).

- **Statique** — renseignez le **Sous-réseau cible** (un préfixe en notation CIDR) et le **Prochain saut** (une IP de passerelle comprise dans la plage du sous-réseau).

Cliquez sur <code className="action">Ajouter</code> pour valider.

Vous pouvez ajouter plusieurs configurations de routage dans la même zone de disponibilité, dans la limite de 20 routes statiques par datacenter.

Ensuite, sur **votre routeur**, configurez la session BGP correspondante (ou les routes statiques) et annoncez les préfixes que vous souhaitez atteindre depuis OVHcloud. Pour des conseils de routage détaillés, consultez Configurer OCC L3 avec BGP{/* TODO(occ-revamp): restore this link before the final merge, once the revamp guide lands → [Configurer OCC L3 avec BGP](/guides/network/ovhcloud-connect/l3-bgp) */} ou Configurer OCC L3 avec des routes statiques{/* TODO(occ-revamp): restore this link before the final merge, once the revamp guide lands → [Configurer OCC L3 avec des routes statiques](/guides/network/ovhcloud-connect/l3-static) */}.

:::info
La configuration de routage s’applique uniquement au **Layer 3**. En mode **Layer 2**, il n’y a pas de configuration de routage — une fois la configuration de PoP L2 et la configuration de zone de disponibilité actives, vos VLANs sont pontés de manière transparente. Consultez Configurer OCC L2{/* TODO(occ-revamp): restore this link before the final merge, once the revamp guide lands → [Configurer OCC L2](/guides/network/ovhcloud-connect/l2) */}.
:::
{/* CP-STEPS-END:add-a-routing-configuration */}

### Étape 6 — Tester et vérifier

Effectuez ces vérifications pour confirmer que tout fonctionne :

{/* CP-STEPS-START:test-and-verify */}
| Vérification | Comment |
|---|---|
| **Lien physique** | Dans la console OVHcloud, vérifiez que la colonne **Statut du lien** de la section **Configuration PoP** (onglet <code className="action">Configurer</code>) affiche **Up**, et que le port est up sur votre routeur. |
| **Session BGP** | Dans la console OVHcloud, vérifiez que la colonne **Statut BGP** de la section **Configuration PoP** affiche **Up**, et que la session est **Established** sur votre routeur. |
| **Échange de routes** | Vérifiez que les routes d’OVHcloud apparaissent dans votre table de routage et inversement. |
| **Connectivité** | Envoyez un ping vers une ressource OVHcloud connue (par exemple une VM dans votre vRack) depuis votre réseau on-premises. |
| **Traceroute** | Exécutez un `traceroute` pour vérifier que le trafic emprunte bien le chemin privé (et non Internet). |
{/* CP-STEPS-END:test-and-verify */}

Les vérifications de la **session BGP** et de l’**échange de routes** s’appliquent au Layer 3. Pour le **Layer 2**, vérifiez que le port est up et que vos VLANs atteignent vos ressources OVHcloud (vous pouvez également exécuter un diagnostic d’adresse MAC — consultez [Superviser](/guides/network/ovhcloud-connect/occ-monitor)).

## Dépannage

| Problème | Que vérifier |
|---|---|
| Le port apparaît « down » | Câble physique, compatibilité SFP/transceiver, statut du cross-connect côté datacenter |
| Session BGP bloquée en « Active » ou « Idle » | IPs de peering, configuration ASN, règles de pare-feu (port TCP 179) |
| Aucune route échangée | Filtres de préfixes BGP, configuration des route-maps, limites maximum-prefix |
| Impossible de pinguer les ressources OVHcloud | Association au vRack, ID VLAN, configuration des sous-réseaux dans l’AZ |

Si vous ne parvenez pas à résoudre le problème, ouvrez un ticket de support{/* TODO(occ-revamp): restore this link before the final merge, once the revamp guide lands → [ouvrez un ticket de support](/guides/network/ovhcloud-connect/incident-followup) */} en joignant la sortie BGP, le statut des interfaces et les résultats du traceroute.
