## Objectif

Une association Serveur-IP lie l'interface privée d'un serveur dédié à une adresse IP d'un subnet [vRack Services](/guides/network/vrack-services/global). Le service DHCP et netboot de vRack Services attribue alors au serveur la même adresse à chaque démarrage et lui permet de démarrer depuis le réseau privé. Le [démarrage privé](/guides/bare-metal-cloud/dedicated-servers/private-boot) repose sur ces associations : créer une association active le démarrage privé sur le serveur, la supprimer le désactive.

**Ce guide vous explique comment créer, modifier et supprimer des associations Serveur-IP, depuis la console OVHcloud ou avec l'API OVHcloud.**

:::warning
Modifier ou supprimer l'association d'un serveur qui démarre depuis le réseau privé change l'adresse avec laquelle il démarre, ou le fait démarrer depuis le réseau public à son prochain redémarrage.

:::

## Prérequis

- Disposer d'un [vRack Services](/guides/network/vrack-services/global) associé à un <Tooltip term="vrack">vRack</Tooltip>, avec un subnet IPv4 sans VLAN et une plage de service.
- Disposer d'un [serveur dédié](/links/bare-metal/bare-metal) compatible avec le [démarrage privé](/guides/bare-metal-cloud/dedicated-servers/private-boot), dans la même région que le vRack Services, rattaché à son vRack, avec l'OVHcloud Link Aggregation (OLA) activée en mode **Full private**.
- Avoir accès à la <ManagerLink to="/beta/#/network/vrack-services">console OVHcloud</ManagerLink> ou disposer d'identifiants API OVHcloud (consultez le guide « [Premiers pas avec les API OVHcloud](/guides/manage-and-operate/api/first-steps) »).

:::tip
Pour activer le démarrage privé sur un seul serveur, vous pouvez aussi partir de son onglet <code className="action">Connectivité</code> : le formulaire du démarrage privé crée l'association, ainsi que le vRack, le vRack Services ou le sous-réseau nécessaires. Consultez le guide « [Activer le démarrage privé sur un serveur dédié OVHcloud](/guides/bare-metal-cloud/dedicated-servers/private-boot) ».

:::

## En pratique

Cette section présente les règles que doit respecter l'adresse d'une association, puis la gestion des associations depuis la console ou l'API.

### Règles d'adressage

L'adresse IP d'une association doit :

- être une adresse IPv4 du subnet ;
- se trouver hors de la plage de service, réservée aux services gérés par OVHcloud ;
- se trouver hors de la plage BGP du subnet, s'il en a une ;
- ne pas être la première ni la dernière adresse du subnet, qui sont réservées ;
- ne pas être déjà utilisée par une autre association.

Chaque serveur ne peut avoir qu'une seule association. OVHcloud ne peut vérifier que les adresses qu'elle gère : assurez-vous qu'aucune autre machine de votre vRack n'utilise déjà l'adresse, par exemple une machine configurée avec une adresse IP statique.

### Gérer les associations

<Tabs>
<Tab label="Control Panel">

Pendant la bêta, ouvrez la <ManagerLink to="/beta/#/network/vrack-services">console OVHcloud</ManagerLink> à l'aide du bouton <code className="action">Découvrir la console &gt;BETA_</code> en haut à droite, puis sélectionnez votre vRack Services.

Ouvrez l'onglet <code className="action">Subnets</code> et cliquez sur le subnet. Sa page affiche la carte **DHCP & Netboot (association Serveur-IP)**, qui liste chaque association avec son **Nom du serveur** et son **Adresse IP**.

Vous ne pouvez pas ajouter d'association tant que le subnet n'a pas de plage de service, qu'il est tagué avec un VLAN, ou que son vRack Services n'est associé à aucun vRack : la carte indique la condition manquante. Les actions sont aussi indisponibles pendant une mise à jour du vRack Services.

**Créer une association**

1. Cliquez sur <code className="action">Ajouter une association Serveur-IP</code>. Le panneau **Créer une association Serveur-IP** s'ouvre et affiche le **Subnet**.
2. Dans le champ **Serveur associé**, sélectionnez le serveur. La liste ne montre que les serveurs situés dans la même région que le vRack Services, rattachés à son vRack, en mode OLA **Full private** et sans association.
3. Dans le champ **Adresse IP associée**, saisissez l'adresse IP du serveur.
4. Cliquez sur <code className="action">Ajouter une association Serveur-IP</code>.

Le serveur démarre depuis le réseau privé, avec cette adresse, à son prochain redémarrage.

**Modifier une association**

1. Dans la liste, ouvrez le menu d'actions de l'association, puis cliquez sur <code className="action">Modifier</code>.
2. Dans le panneau **Modifier l'association Serveur-IP**, saisissez la nouvelle adresse IP. Le serveur ne peut pas être changé.
3. Cliquez sur <code className="action">Modifier</code>.

Le serveur utilise la nouvelle adresse à son prochain redémarrage.

**Supprimer une association**

1. Dans la liste, ouvrez le menu d'actions de l'association, puis cliquez sur <code className="action">Supprimer</code>.
2. Dans la fenêtre **Supprimer l'association Serveur-IP**, cliquez sur <code className="action">Supprimer</code>.

L'adresse IP est libérée et le démarrage privé est désactivé sur le serveur : il démarre depuis le réseau public à son prochain redémarrage.

</Tab>
<Tab label="OVHcloud API">

Les associations font partie de la configuration du vRack Services : chacune est une entrée de `dedicatedServerInterfaceAssociations`, dans la configuration DHCP de la plage de service du subnet.

1. Listez les interfaces de serveur qui peuvent être associées au vRack Services. Notez l'`uuid` de l'interface du serveur :

<Api version="v2" section="/vrackServices" method="GET" route={"/vrackServices/resource/\{vrackServicesId\}/eligibleDedicatedServerInterfaces"} />

2. Récupérez le `checksum` et le `targetSpec` du vRack Services :

<Api version="v2" section="/vrackServices" method="GET" route={"/vrackServices/resource/\{vrackServicesId\}"} />

3. Renvoyez le `targetSpec` avec votre modification de `services.serviceRange[].dhcp.dedicatedServerInterfaceAssociations`, accompagné du `checksum` récupéré :

<Api version="v2" section="/vrackServices" method="PUT" route={"/vrackServices/resource/\{vrackServicesId\}"} />

| Pour… | Modification dans `dedicatedServerInterfaceAssociations` |
|---|---|
| Créer une association | Ajoutez une entrée `{"uuid": "<uuid de l'interface>", "ip": "<adresse IP>"}`. |
| Modifier une association | Changez l'`ip` de l'entrée. |
| Supprimer une association | Retirez l'entrée. |

Conservez toutes les autres valeurs du `targetSpec` telles que renvoyées par le `GET`. Un corps de requête complet est présenté dans la section « [Activer le démarrage privé avec l'API OVHcloud](/guides/bare-metal-cloud/dedicated-servers/private-boot#api) », et le fonctionnement du `checksum` et du `targetSpec` dans le guide « [vRack Services - Exposer un service managé sur votre vRack](/guides/network/vrack-services/global) ».

4. Suivez la mise à jour jusqu'à ce que le vRack Services soit `READY` :

<Api version="v2" section="/vrackServices" method="GET" route={"/vrackServices/resource/\{vrackServicesId\}/task"} />

Dans le `currentState` du vRack Services, chaque association indique si le netboot est actif (`netboot`). Le `dhcpConfigurationStatus` de la plage de service vaut `READY`, ou `DRAFT` avec la raison `MISSING_DEDICATED_SERVER_INTERFACE_ASSOCIATIONS` lorsque sa configuration DHCP ne contient aucune association.
