## Objectif

Une Additional IP est une adresse IP que vous pouvez basculer d'un service OVHcloud à un autre. La router vers le Load Balancer OVHcloud y achemine le trafic existant sans changer votre adresse IP publique ni attendre la propagation DNS.

**Ce guide explique comment router une Additional IP vers le Load Balancer OVHcloud, soit pour l'ensemble du service, soit pour un seul frontend, depuis la console OVHcloud ou via l'API OVHcloud.**

## Prérequis

- Un <ManagerLink to="/">compte OVHcloud</ManagerLink> actif
- Un Load Balancer OVHcloud configuré — consultez [Commander un Load Balancer](/guides/network/load-balancer-revamp/order-load-balancer)
- Une [Additional IP](/links/network/additional-ip)
- Des identifiants d'API, si vous routez l'IP via l'API OVHcloud — consultez [Prérequis et limitations](/guides/network/load-balancer-revamp/prerequisites-and-limitations)

## Introduction

Vous pouvez router une Additional IP vers le Load Balancer OVHcloud de deux manières :

- La router vers l'**ensemble du service Load Balancer**, ce qui la rend disponible pour tous les frontends.
- La router vers un **seul frontend** : elle ne donne alors accès qu'au service exposé par ce frontend. Vos autres frontends restent accessibles via l'adresse IP principale du Load Balancer.

Choisissez la portée qui correspond à votre migration : une IP à l'échelle du service pour remplacer à l'identique une adresse IP publique existante, ou une IP dédiée si vous voulez qu'un frontend réponde sur sa propre adresse.

Vous pouvez router l'IP via l'API OVHcloud, comme décrit dans les deux premières sections ci-dessous, ou [depuis la console OVHcloud](#route-from-the-console).

> [!INFO]
> Après avoir modifié les Additional IPs associées au Load Balancer, vous devez appliquer la configuration. Pour que l'actualisation réussisse, les conditions suivantes doivent être réunies :
>
> - **Configuration du vRack :** si le Load Balancer se trouve dans un vRack, toutes les fermes de serveurs doivent également se trouver dans le vRack et le Load Balancer doit avoir son VLAN défini. Sinon, aucune ferme ne doit se trouver dans un vRack.
> - **Validité des frontends :** au moins un frontend doit exister, et tous les frontends doivent être valides (activés ou désactivés). Chacun doit disposer d'une route valide avec des règles de routage, d'une redirection ou d'une ferme par défaut.
> - **État de la configuration :** le Load Balancer ne doit pas déjà être en cours d'actualisation. Une seule actualisation peut être traitée à la fois.

## En pratique

### Router une Additional IP vers l'ensemble du Load Balancer

Cette portée rend l'Additional IP disponible pour tous les frontends du Load Balancer. Via l'API OVHcloud, déplacez l'IP vers le Load Balancer, puis vérifiez l'association. Pour effectuer cette opération depuis la console OVHcloud, consultez la section [Router une Additional IP depuis la console OVHcloud](#route-from-the-console).

Commencez par déplacer l'Additional IP vers le service Load Balancer :

<Api version="v1" section="/ip" method="POST" route={"/ip/\{ip\}/move"} />

| Paramètre | Requis | Description | Exemple |
|---|---|---|---|
| `ip` | Oui | L'Additional IP à déplacer, en notation CIDR. | `203.0.113.42/32` |
| `to` (corps) | Oui | Le nom de service du Load Balancer cible. | `loadbalancer-a1b2c3d4` |

> [!INFO]
> L'endpoint `/ip/{ip}/move` fait partie de la section d'API `/ip`. Le champ `to` du corps accepte le nom de service cible. Vous pouvez également récupérer la liste des services vers lesquels une IP peut être déplacée avec `GET /ip/{ip}/move`.

Listez ensuite les Additional IPs déjà routées vers votre Load Balancer afin de confirmer l'association :

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/failover"} />

| Paramètre | Requis | Description | Exemple |
|---|---|---|---|
| `serviceName` | Oui | Le nom de service de votre Load Balancer. | `loadbalancer-a1b2c3d4` |

Une fois l'association confirmée, appliquez la configuration comme décrit dans [Appliquer la configuration](#apply-the-configuration).

### Router une Additional IP dédiée vers un seul frontend

Cette portée rattache l'Additional IP à un seul frontend. L'IP ne donne alors accès qu'au service exposé par ce frontend, tandis que vos autres frontends restent accessibles via l'adresse IP principale du Load Balancer. Les étapes ci-dessous configurent une IP dédiée via l'API OVHcloud. Pour assigner l'IP à un frontend depuis la console OVHcloud, consultez la section [Router une Additional IP depuis la console OVHcloud](#route-from-the-console).

Définissez une ou plusieurs Additional IPs dédiées lorsque vous créez un frontend.

- Protocole HTTP :

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/http/frontend"} />

- Protocole TCP :

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/tcp/frontend"} />

Ou mettez à jour un frontend existant pour y rattacher les Additional IPs dédiées.

- Protocole HTTP :

<Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/http/frontend/\{frontendId\}"} />

- Protocole TCP :

<Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/tcp/frontend/\{frontendId\}"} />

| Paramètre | Requis | Description | Exemple |
|---|---|---|---|
| `serviceName` | Oui | Le nom de service de votre Load Balancer. | `loadbalancer-a1b2c3d4` |
| `frontendId` | Oui | L'identifiant numérique du frontend (appels de mise à jour uniquement). | `42` |
| `dedicatedIpfo` (corps) | Oui | La liste des Additional IPs dédiées à rattacher au frontend. | `["203.0.113.42"]` |

> [!INFO]
> Pour un service UDP, attachez l'Additional IP dédiée à un frontend UDP en utilisant `POST /ipLoadbalancing/{serviceName}/udp/frontend` (ou `PUT` pour en modifier un existant).

Une fois l'appel réussi, appliquez la configuration comme décrit dans [Appliquer la configuration](#apply-the-configuration).

### Router une Additional IP depuis la console OVHcloud

<a name="route-from-the-console"></a>

Vous pouvez également router une Additional IP vers votre Load Balancer et l'assigner à un frontend depuis la console OVHcloud, sans passer par l'API.

1. Ouvrez l'onglet <code className="action">Réseau</code> de votre Load Balancer et rendez-vous dans la section **IPs additionnelles**. Si vous ne disposez pas encore d'une Additional IP, cliquez sur <code className="action">Commander une IP additionnelle</code>.
2. Cliquez sur <code className="action">Attacher une IP</code>. Dans la fenêtre **Attacher une IP additionnelle**, sélectionnez une Additional IP non routée dans la liste déroulante **IP additionnelle**, puis cliquez sur <code className="action">Attacher</code>.
3. Ouvrez l'onglet <code className="action">Frontends</code>, puis cliquez sur <code className="action">Créer un frontend</code>. Pour utiliser plutôt un frontend existant, cliquez sur le bouton <code className="action">⋮</code> dans la colonne **Actions** de sa ligne, puis sur <code className="action">Modifier</code>.
4. Dans la section **Paramètres avancés**, sous **IPs additionnelles**, sélectionnez les Additional IPs que ce frontend utilise. Si aucune n'est sélectionnée, le frontend utilise uniquement l'IP principale du Load Balancer. Cliquez sur <code className="action">Créer le frontend</code>, ou sur <code className="action">Enregistrer les modifications</code> sur la page **Modifier le frontend**.

Appliquez ensuite la configuration comme décrit ci-dessous.

### Appliquer la configuration

<a name="apply-the-configuration"></a>

{/* CP-STEPS-START:apply-configuration */}
Les modifications apportées aux Additional IPs restent en attente jusqu'à ce que vous appliquiez la configuration du Load Balancer. Pour l'appliquer depuis la console OVHcloud, revenez à l'onglet <code className="action">Vue d'ensemble</code> de votre Load Balancer. Dans la section **Informations générales**, sous **Déploiement**, cliquez sur <code className="action">Appliquer N changements</code>, N étant le nombre de modifications en attente.
{/* CP-STEPS-END:apply-configuration */}

> [!WARNING]
> La configuration n'est pas active tant qu'elle n'est pas appliquée. Si les conditions de l'introduction ne sont pas réunies, l'actualisation échoue et la configuration précédente reste en place.
