## Objectif

Retrouvez dans ce document les questions les plus fréquemment posées et les instructions correspondantes pour effectuer des tâches de gestion et de configuration courantes sur votre service OVHcloud Load Balancer.

## FAQ

### Comment configurer mon pare-feu pour accepter le trafic provenant de l'OVHcloud Load Balancer ?

Lorsque vous utilisez le Load Balancer, vos clients ne se connectent pas directement à vos serveurs. Il est recommandé de configurer un pare-feu permettant uniquement le trafic provenant du service OVHcloud Load Balancer.

#### Via l'API OVHcloud

Pour identifier les adresses IP que vous devez autoriser dans votre pare-feu, vous pouvez utiliser l'appel API suivant :

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/natIp"} />


#### Via la console OVHcloud

{/* CP-STEPS-START:firewall-outbound-ips */}

Dans la console OVHcloud, ouvrez votre service Load Balancer. Dans l'onglet <code className="action">Vue d'ensemble</code>, section **Informations générales**, le champ **IPv4 sortantes** liste les plages d'adresses IP que vous devez autoriser dans votre pare-feu, séparées par des virgules.

{/* CP-STEPS-END:firewall-outbound-ips */}

### Comment connaître le statut de mon service ?

Parfois, il peut être utile de connaître le statut de votre service OVHcloud Load Balancer.

#### Via l'API OVHcloud

Pour déterminer le statut de votre service, vous pouvez utiliser l'appel API suivant :

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/status"} />


La réponse indique le statut global du service, ainsi que le détail de vos fermes, frontends et serveurs, chacun avec un total et un décompte par statut.

Les statuts possibles sont :

- `ok` : Fonctionnement normal.
- `warn` : Fonctionnement dégradé.
- `error` : Hors service.
- `unknown` : Statut indéterminé.

#### Via la console OVHcloud

{/* CP-STEPS-START:service-status */}

Dans la console OVHcloud, ouvrez votre service Load Balancer. Le statut de votre Load Balancer est affiché sous forme de badge à côté de son nom, en haut de la page (par exemple, **OK**). Le nom interne de votre service Load Balancer correspond à l'**ID** affiché dans la section **Informations générales** de l'onglet <code className="action">Vue d'ensemble</code>.

{/* CP-STEPS-END:service-status */}

### Comment ajouter une Additional IP à l'OVHcloud Load Balancer ?

Une Additional IP est une adresse IP secondaire qui peut être associée à votre service en plus de votre adresse IP principale. L'Additional IP peut être transférée d'un serveur à un autre en quelques secondes.

#### Via l'API OVHcloud

Pour ajouter une Additional IP à votre service OVHcloud Load Balancer :

<Api version="v1" section="/ip" method="POST" route={"/ip/\{ip\}/move"} />


Appliquez le changement :

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/refresh"} />


#### Via la console OVHcloud

{/* CP-STEPS-START:add-additional-ip */}

Dans la console OVHcloud, ouvrez votre service Load Balancer. Commencez par attacher l'Additional IP à votre Load Balancer : dans l'onglet <code className="action">Réseau</code>, section **IPs additionnelles**, cliquez sur <code className="action">Attacher une IP</code>. Dans la fenêtre **Attacher une IP additionnelle**, sélectionnez l'Additional IP, puis cliquez sur <code className="action">Attacher</code>.

Accédez ensuite à l'onglet <code className="action">Frontends</code> et cliquez sur <code className="action">Créer un frontend</code>. Dépliez les <code className="action">Paramètres avancés</code> et, dans le champ **IPs additionnelles**, sélectionnez les Additional IPs que vous souhaitez ajouter à votre frontend. Renseignez les autres paramètres de votre frontend, puis cliquez sur <code className="action">Créer le frontend</code>.

{/* CP-STEPS-END:add-additional-ip */}

### Comment commander un certificat SSL gratuit ?

#### Via la console OVHcloud

{/* CP-STEPS-START:order-free-ssl */}

Dans la console OVHcloud, ouvrez votre service Load Balancer, accédez à l'onglet <code className="action">SSL</code> et cliquez sur <code className="action">Ajouter un certificat</code>.
Sélectionnez <code className="action">Gratuit (Let's Encrypt)</code> comme **Type de certificat**. Dans le champ **Domaine(s)**, saisissez votre FQDN et cliquez sur <code className="action">Ajouter</code> (ajoutez les noms de domaine un par un), puis cliquez sur <code className="action">Ajouter le certificat</code>.

{/* CP-STEPS-END:order-free-ssl */}

Pour que la commande soit validée, il est nécessaire que le nom de domaine pointe vers votre service OVHcloud Load Balancer.

#### Via l'API OVHcloud

Il est possible de commander un certificat SSL gratuit pour le service OVHcloud Load Balancer.

Pour ce faire, vous pouvez utiliser l'appel API suivant et renseigner votre domaine dans le champ `fqdn` :

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/freeCertificate"} />


Il est possible de commander un certificat multi-domaines ; le champ `fqdn` accepte une entrée de type chaîne de caractères.

Pour que la commande soit validée, il est nécessaire que le nom de domaine pointe vers votre service OVHcloud Load Balancer.

### Comment lister les certificats SSL associés à l'OVHcloud Load Balancer ?

#### Via la console OVHcloud

{/* CP-STEPS-START:list-ssl-certificates */}

Dans la console OVHcloud, ouvrez votre service Load Balancer et accédez à l'onglet <code className="action">SSL</code>. Le tableau **Certificats TLS** liste les certificats associés à ce Load Balancer.

Pour obtenir les détails d'un certificat SSL, cliquez sur le bouton `⋮` dans la colonne **Actions** du certificat souhaité, puis sur <code className="action">Voir les détails</code>. Les détails s'affichent dans la fenêtre **Détails du certificat**.

{/* CP-STEPS-END:list-ssl-certificates */}

#### Via l'API OVHcloud

Pour lister les certificats SSL associés à l'OVHcloud Load Balancer, vous pouvez utiliser l'appel API suivant :

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/ssl"} />


Les certificats SSL commandés (gratuits ou non) apparaîtront comme `built`. Ceux ajoutés par vous-même apparaîtront comme `custom`.

Un certificat SSL apparaissant comme `built_not_routed` est un certificat qui a été commandé et livré, mais dont le domaine ne peut pas être validé. Cela est généralement dû au fait que le domaine ne pointe plus vers le service OVHcloud Load Balancer.

Pour obtenir les détails d'un certificat SSL, vous pouvez utiliser l'appel API suivant :

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/ssl/\{id\}"} />
