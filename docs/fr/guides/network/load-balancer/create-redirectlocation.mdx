## Objectif

Le **Load Balancer OVHcloud** fonctionne par défaut comme un proxy, un intermédiaire entre le trafic client et vos serveurs backend. Il peut également être configuré pour rediriger le trafic client vers un site web tiers. Cette fonctionnalité est essentielle pour des scénarios tels que la **migration de nom de domaine** ou l'application de la **version HTTPS** d'un site web. On parle alors de **redirection HTTP**.

**Ce guide décrit le processus d'intégration de vos services web derrière un Load Balancer OVHcloud utilisant des redirections HTTP.**

## Prérequis

- Posséder une offre [OVHcloud Load balancer](https://www.ovhcloud.com/fr/network/load-balancer/) dans votre compte OVHcloud.
- Avoir accès à l'<ApiLink>API OVHcloud</ApiLink>.

## En pratique

### Présentation

Une redirection HTTP se présente ainsi :

```bash
HTTP/1.1 301 Moved Permanently
Location: http://www.example.org/
Content-Type: text/html
Content-Length: 174
```

Les redirections personnalisées doivent utiliser le format `<scheme>://<net_loc>/<path>;<params>?<query>#<fragment>`. Un frontend dispose d'une redirection par défaut, appliquée lorsqu'aucune route ne correspond à la requête. Pour ajouter d'autres redirections, créez des routes sur le frontend : dans la console OVHcloud, ouvrez la page **Modifier le frontend** d'un frontend HTTP ou HTTPS existant, cliquez sur <code className="action">Ajouter une route</code> puis, dans la fenêtre **Créer une route**, choisissez **Rediriger vers une URL** comme **Type d'action** au lieu de **Router vers une ferme**.

Les redirections personnalisées peuvent être spécifiées via la console OVHcloud ou via l'API, tant sur un nouveau frontend qu'un existant.

### Ajouter une redirection personnalisée depuis la console OVHcloud

Cela peut-être effectué tant sur un nouveau frontend pendant sa création, que sur un frontend existant.

#### Ajout d'un nouveau frontend

{/* CP-STEPS-START:add-new-frontend */}

Dans l'onglet <code className="action">Frontends</code>, cliquez sur <code className="action">Créer un frontend</code> pour en créer un nouveau.

Sur la page **Créer un frontend**, sélectionnez **HTTP** ou **HTTPS** comme **Protocole**.<br/>
Configurez les informations normalement. Il est cependant inutile de sélectionner une ferme, celle-ci ne sera pas utilisée.

Dans la section **Routage**, sous **Route par défaut**, sélectionnez **Rediriger vers une URL** et saisissez votre URL de redirection.

{/* CP-STEPS-END:add-new-frontend */}

#### Édition d'un frontend existant

{/* CP-STEPS-START:edit-existing-frontend */}

Dans l'onglet <code className="action">Frontends</code>, cliquez sur le bouton `⋮` dans la colonne **Actions** du frontend concerné et sélectionnez <code className="action">Modifier</code>.<br/>
Assurez-vous que le frontend choisi utilise bien le protocole `HTTP` ou `HTTPS`. Complétez la configuration si besoin.
Il est cependant inutile de sélectionner une ferme, celle-ci ne sera pas utilisée.

Dans la section **Routage**, sous **Route par défaut**, sélectionnez **Rediriger vers une URL** et saisissez votre URL de redirection.

Une fois le frontend configuré, cliquez sur <code className="action">Créer le frontend</code> ou <code className="action">Enregistrer les modifications</code> selon que vous configurez un nouveau frontend ou un frontend existant.
N'oubliez pas de déployer la configuration.

Pour ce faire, rendez-vous dans l'onglet <code className="action">Vue d'ensemble</code> puis, dans la section **Informations générales**, sous **Déploiement**, cliquez sur <code className="action">Appliquer N changements</code>, N étant le nombre de modifications en attente. Un seul clic applique la configuration à toutes les zones de votre service.

{/* CP-STEPS-END:edit-existing-frontend */}

### Ajouter une redirection personnalisée depuis l'API OVHcloud

Dans l'<ApiLink>API OVHcloud</ApiLink>, les redirections sont spécifiées dans la chaîne de caractère redirectLocation :

**Création d'un nouveau frontend**

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/http/frontend"} />


|Paramètre|Signification|
|---|---|
|serviceName|Identifiant de votre service Load Balancer|
|port|Port(s) d'écoute du frontend|
|zone|Zone de déploiement du frontend|
|redirectLocation|URL de redirection HTTP|

**Mise à jour d'un frontend existant**

<Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/http/frontend/\{frontendId\}"} />


|Paramètre|Signification|
|---|---|
|serviceName|Identifiant de votre service Load Balancer|
|frontendId|Identifiant du frontend à mettre à jour|
|redirectLocation|URL de redirection HTTP|

**Appliquer les modifications**

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/refresh"} />


|Paramètre|Signification|
|---|---|
|serviceName|Identifiant de votre service Load Balancer|
|zone|Zone de déploiement du frontend|
