## Objectif

Ce guide a pour but de vous aider lors de la première prise en main de votre Load Balancer en vous présentant les fonctionnalités principales de l'offre.

## Prérequis

- Posséder une offre [OVHcloud Load balancer](https://www.ovhcloud.com/fr/network/load-balancer/) dans votre compte OVHcloud.

[[cpnav:network-load-balancer]]

## En pratique

### Gérer son Load Balancer dans la console OVHcloud

{/* CP-STEPS-START:manage-lb */}

Dans la console OVHcloud, votre service Load Balancer s'ouvre sur l'onglet <code className="action">Vue d'ensemble</code>. Sur cette page et dans les autres onglets du service, vous trouverez les informations suivantes :

|Menu|Détails|
|---|---|
|Informations générales|Dans l'onglet <code className="action">Vue d'ensemble</code> : l'identifiant de votre Load Balancer, ses zones, son vRack, l'état de **Déploiement** de votre configuration, vos adresses IPv4 et IPv6 ainsi que vos **IPv4 sortantes**. Les boutons <code className="action">Ajouter une zone</code> et <code className="action">Annuler une zone</code> gèrent les zones de disponibilité où se situe votre Load Balancer|
|Abonnement|Dans l'onglet <code className="action">Vue d'ensemble</code> : les détails administratifs de votre offre (offre, date de création, mode et date de renouvellement), avec les boutons <code className="action">Gérer mon abonnement</code> et <code className="action">Résilier</code>|
|Statistiques|L'onglet <code className="action">Statistiques</code> : le nombre de connexions et de requêtes par seconde (moyenne et pic) de votre service, sur une période d'une heure à un mois|
|IPs additionnelles|Les Additional IP liées à votre Load Balancer sont listées dans la section **IPs additionnelles** de l'onglet <code className="action">Réseau</code>|
|Nom et ciphers|Personnalisez le nom de votre offre avec l'icône en forme de crayon située à côté de son nom, en haut de la page. Le profil de chiffrement est personnalisable dans l'onglet <code className="action">SSL</code>|

Pour ajouter des frontends, cliquez sur <code className="action">Créer un frontend</code> dans l'onglet <code className="action">Frontends</code>. Pour ajouter des fermes de serveurs, cliquez sur <code className="action">Créer une ferme</code> dans l'onglet <code className="action">Fermes de serveurs</code>. Une page vous aidera ensuite à configurer chaque partie de votre service.

{/* CP-STEPS-END:manage-lb */}

### Gérer ses frontends

{/* CP-STEPS-START:manage-front-ends */}

Afin d'ajouter des frontends, il vous suffit de vous rendre dans l'onglet <code className="action">Frontends</code> et de cliquer sur <code className="action">Créer un frontend</code>. La page **Créer un frontend** s'ouvre alors.

Détails des éléments d'un frontend :

|Élément|Fonction|
|---|---|
|Nom|Vous pouvez nommer ici votre frontend, afin notamment de l'identifier rapidement si vous en avez plusieurs|
|Protocole|Vous avez le choix entre le HTTP, HTTPS, TCP, TLS et l'UDP|
|Port|Choisissez ici le port d'écoute à utiliser : un port unique (80), plusieurs ports (80,443) ou une plage (8080-8090)|
|Zone|Vous pouvez choisir entre une zone de disponibilité en particulier ou toutes les zones de disponibilité pour la création du frontend. La zone ne peut plus être modifiée ensuite|
|Ferme par défaut (TCP, TLS et UDP)|Si vous avez plusieurs fermes paramétrées, vous pourrez en choisir une par défaut pour chaque frontend|
|Routage (HTTP et HTTPS)|Sous **Route par défaut**, choisissez **Router vers une ferme** pour sélectionner la ferme par défaut du frontend, ou **Rediriger vers une URL** pour ajouter une URL de redirection HTTP|

Vous avez également accès à des paramètres avancés, dans la section **Paramètres avancés** :

|Élément|Fonction|
|---|---|
|IPs additionnelles|Les Additional IP sur lesquelles ce frontend écoute. Elles doivent d'abord être commandées et attachées au Load Balancer dans l'onglet <code className="action">Réseau</code>. Si aucune n'est sélectionnée, le frontend utilise uniquement l'IP principale du Load Balancer|
|IPs autorisées|Liste de blocs CIDR permettant de restreindre l'accès distant au Load Balancer, uniquement en IPv4. Laissez-la vide pour autoriser tous les accès|
|En-tête HTTP (HTTP et HTTPS)|Ajout d'un en-tête HTTP personnalisé à transmettre|

{/* CP-STEPS-END:manage-front-ends */}

### Gérer ses fermes

{/* CP-STEPS-START:manage-clusters */}

Afin d'ajouter une ferme de serveurs, il vous suffit de vous rendre dans l'onglet <code className="action">Fermes de serveurs</code> et de cliquer sur <code className="action">Créer une ferme</code>. La page **Créer une ferme de serveurs** propose des options principales proches de celles du frontend : **Nom d'affichage**, **Zone**, **Protocole** (HTTP, TCP ou UDP) et **Port**. Ses autres options se trouvent dans les sections **Répartition de charge** et **Surveillance** :

|Élément|Fonction|
|---|---|
|Algorithme|Choix entre Premier disponible, Moins de connexions, Round Robin (par défaut), Hash Source ou Hash URI (HTTP uniquement) pour votre balancement d'IP|
|Persistance de session|Le suivi de session peut se faire par cookie (HTTP uniquement) ou IP Source, ou être désactivé (Aucune)|
|Surveillance|Cochez **Activer le health check** pour activer une sonde, puis choisissez son **Type de sonde** (TCP, PGSQL, MYSQL, SMTP, OCO ou HTTP), son **Port** et son **Intervalle (s)** (30 secondes minimum)|

Les sections **Répartition de charge** et **Surveillance** ne sont pas disponibles pour une ferme UDP.

{/* CP-STEPS-END:manage-clusters */}

### Gérer ses serveurs

{/* CP-STEPS-START:manage-servers */}
Une fois votre ferme de serveurs créée, il vous reste à y ajouter des serveurs. Retrouvez ci-dessous le détail des options ainsi que des options avancées :

<img className="thumbnail" alt="Ajout serveur" src="/images/network/load-balancer/use-lb/add_server.png" loading="lazy" />
<img className="thumbnail" alt="Ajout serveur" src="/images/network/load-balancer/use-lb/add_server_advanced.png" loading="lazy" />

|Élément|Fonction|
|---|---|
|Nom|Si vous le souhaitez, vous pouvez nommer votre serveur, afin de l'identifier rapidement quand vous en avez plusieurs|
|Adresse IPv4|Ajout de l'IP du service qui agira comme serveur|
|Port|Port du serveur|
|Serveur de secours|Préciser que ce serveur est un serveur de secours|
|Utiliser la sonde de disponibilité de la ferme|Choisir d'utiliser la sonde validée lors de la création de la ferme|
|Chiffrer les requêtes avec SSL|Chiffrer les requêtes avec un certificat SSL|
|Cookie|Ajout d'un cookie de session personnalisé|
|Chaîne de certification|Ajout d'une chaîne de certification|
|Poids de balancement|Choix du poids de balancement pour la répartition de charge|
|Version du protocole de PROXY|**Uniquement si vous l'avez déjà configuré**, choisissez la version du protocole de PROXY que vous souhaitez utiliser sur ce serveur. <br/> Vous pouvez trouver plus d'informations sur le protocole PROXY et sur son utilisation avec le service OVHcloud Load Balancer dans [ce guide](/guides/network/load-balancer/create-proxyprotocol).|
{/* CP-STEPS-END:manage-servers */}

### Gérer ses certificats SSL

{/* CP-STEPS-START:manage-ssl-certificates */}

Il est possible d'ajouter un certificat SSL au Load Balancer depuis l'onglet <code className="action">SSL</code>, dans la section **Certificats TLS**, avec le bouton <code className="action">Ajouter un certificat</code>. Vous aurez alors deux possibilités : obtenir un certificat Let's Encrypt gratuit ou ajouter un certificat externe.

{/* CP-STEPS-END:manage-ssl-certificates */}

#### Certificat SSL OVHcloud

{/* CP-STEPS-START:order-ssl-certificate */}

Pour obtenir un certificat SSL gratuit, sélectionnez l'onglet <code className="action">SSL</code>, cliquez sur <code className="action">Ajouter un certificat</code> puis sélectionnez **Gratuit (Let's Encrypt)** comme **Type de certificat** :

|Élément|Fonction|
|---|---|
|Type de certificat|**Gratuit (Let's Encrypt)** : un certificat gratuit automatique, renouvelé tous les 90 jours|
|Domaine(s)|Le(s) domaine(s) concerné(s) (Fully Qualified Domain Name). Ajoutez les noms de domaine un par un|

{/* CP-STEPS-END:order-ssl-certificate */}

#### Ajout d'un certificat SSL externe

{/* CP-STEPS-START:add-external-ssl-certificate */}

Si vous possédez déjà votre propre certificat SSL, il vous est possible de l'ajouter directement : dans l'onglet <code className="action">SSL</code>, cliquez sur <code className="action">Ajouter un certificat</code> puis sélectionnez **Personnalisé (upload PEM)** comme **Type de certificat** :

|Élément|Fonction|
|---|---|
|Nom d'affichage|Choisissez si vous le souhaitez un nom à votre certificat, afin de l'identifier rapidement quand vous en avez plusieurs|
|Clé privée (PEM)|Champ d'ajout de la clé privée à ajouter au service (obligatoire)|
|Certificat (PEM)|Champ d'ajout du certificat (obligatoire)|
|Chaîne de certificats (PEM)|Champ d'ajout du certificat racine si nécessaire|

Cliquez ensuite sur <code className="action">Ajouter le certificat</code>.

{/* CP-STEPS-END:add-external-ssl-certificate */}
