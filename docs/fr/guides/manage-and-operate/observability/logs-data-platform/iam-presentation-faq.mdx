## Objectif

Ce guide explique l'intégration de Logs Data Platform avec l'IAM OVHcloud.

## Prérequis

- Un [compte OVHcloud](/guides/account-and-service-management/account-information/ovhcloud-account-creation)
- Un accès au <ManagerLink to="/">espace client OVHcloud</ManagerLink>
- Un [service Logs Data Platform](/links/manage-operate/logs-data-platform)

## En pratique

### En quoi l'IAM est-il utile pour Logs Data Platform ?

Activer l'IAM OVHcloud sur Logs Data Platform délègue l'authentification, la gestion des accès et les permissions à l'IAM OVHcloud. L'utilisation de l'IAM présente plusieurs avantages :

- [Toutes les identités OVHcloud](/guides/manage-and-operate/iam/identities-management) peuvent se connecter avec leurs identifiants à toutes les interfaces web (Graylog/OpenSearch Dashboards). Le compte connecté sera l'identité choisie pour l'accès à l'interface. **Vous n'aurez plus besoin du nom d'utilisateur Logs Data Platform.** L'IAM permet également d'utiliser des [méthodes d'authentification à deux facteurs](/guides/account-and-service-management/account-information/secure-ovhcloud-account-with-2fa) et des [services de fédération](/guides/account-and-service-management/account-information/ovhcloud-account-connect-saml-adfs).
- Les jetons d'API peuvent être aussi bien des [jetons de compte de service](/guides/account-and-service-management/account-information/authenticate-api-with-service-account) que des jetons d'accès personnels, gérés directement via les API de l'IAM OVHcloud.
- Les [groupes de ressources](/guides/account-and-service-management/account-information/iam-policies-api) vous permettent de partager les sous-ressources de Logs Data Platform de manière plus cohérente.
- Les [politiques IAM](/guides/account-and-service-management/account-information/iam-policy-ui) débloquent des cas d'usage avancés impossibles avec les permissions, grâce à des actions granulaires.

### Comment activer l'IAM OVHcloud pour mon compte existant sur Logs Data Platform ?

Si vous disposez d'un service existant, suivez ces étapes :

- Remplacez tous vos **Rôles** et permissions par des [politiques appropriées](/guides/manage-and-operate/observability/logs-data-platform/getting-started-roles-permission).
- Assurez-vous qu'aucun **Rôle** n'est déclaré dans votre service.
- Assurez-vous que votre service ne figure dans aucun **Rôle**.
- Assurez-vous que vous n'avez aucun [jeton](/guides/manage-and-operate/observability/logs-data-platform/tokens).
- Utilisez le bouton dédié <code className="action">Activer l'IAM OVHcloud</code> dans la section **Rôles** du Control Panel de Logs Data Platform.

<img className="thumbnail" alt="Activer l'IAM" src="/images/manage-and-operate/observability/logs-data-platform/iam-presentation-faq/activate_iam_existing_service.png" loading="lazy" />

Une fois l'IAM activé, une nouvelle section **Politiques IAM** remplacera l'ancienne section **Rôles**.

<img className="thumbnail" alt="IAM activé" src="/images/manage-and-operate/observability/logs-data-platform/iam-presentation-faq/activated_iam.png" loading="lazy" />

### Comment activer l'IAM OVHcloud sur un nouveau service ?

Lors de la création d'un nouveau service, vous pouvez directement opter pour l'utilisation de l'IAM et utiliser les [politiques IAM](/guides/account-and-service-management/account-information/iam-policy-ui) pour gérer les droits d'accès.

<img className="thumbnail" alt="Activer l'IAM sur un nouveau service" src="/images/manage-and-operate/observability/logs-data-platform/iam-presentation-faq/activate_iam_new_service.png" loading="lazy" />

Une fois l'IAM activé, vous pouvez librement utiliser n'importe quelle [identité OVHcloud](/guides/manage-and-operate/iam/identities-management) pour interagir avec Logs Data Platform.

### Comment se connecter à Graylog avec l'IAM ?

Lors de la connexion à Graylog, vous pouvez choisir entre l'ancien système nom d'utilisateur/mot de passe (pour les services sans IAM activé) ou n'importe quel fournisseur IAM OVHcloud (EU, CA ou US). Cliquer sur le bouton *Log in* correspondant vous redirige vers le fournisseur IAM OVHcloud approprié pour terminer l'authentification.

### Comment se connecter à OpenSearch Dashboards avec l'IAM ?

Lors de la connexion à OpenSearch Dashboards, sélectionnez le fournisseur lié à votre service OVHcloud. Le bouton *Log in with OVHcloud IAM* vous redirige vers votre fournisseur pour terminer l'authentification.

<img className="thumbnail" alt="Connexion OSD" src="/images/manage-and-operate/observability/logs-data-platform/iam-presentation-faq/osd_iam_eu.png" loading="lazy" />

Une fois cette étape terminée, vous serez redirigé vers l'instance OpenSearch Dashboards, entièrement authentifié.

### Comment se connecter à Grafana avec l'IAM ?

- Si votre fournisseur d'identité est l'IAM OVHcloud, vous pouvez sélectionner l'option **Forward OAuth identity** pour transmettre l'identité connectée à Logs Data Platform.
- Si vous utilisez un autre fournisseur d'authentification, vous pouvez forger un en-tête *Authorization* avec un jeton compatible IAM. Consultez la section suivante pour savoir comment générer ce type de jeton. Le contenu de l'en-tête doit être `Bearer: <Your Token>`. Remplacez `<Your Token>` par la valeur de votre jeton.

<img className="thumbnail" alt="En-tête Grafana" src="/images/manage-and-operate/observability/logs-data-platform/iam-presentation-faq/grafana_header.png" loading="lazy" />

### Comment interagir avec l'API des backends de Logs Data Platform ?

Avec l'IAM activé, les [jetons](/guides/manage-and-operate/observability/logs-data-platform/tokens) sont remplacés par des clés d'API (schéma d'authentification Bearer). Ces clés peuvent être des jetons de [comptes de service](/guides/account-and-service-management/account-information/authenticate-api-with-service-account) ou des jetons d'accès personnels. Utilisez l'API OVHcloud pour générer ces jetons.

<Api version="v1" section="/me" method="POST" route={"/me/identity/user/\\{user\\}/token"} />

Par exemple, si vous êtes sur le cluster gra1, curl peut utiliser ces jetons de la façon suivante :

```bash
ldp@laptop curl -H 'content-type: application/json' --oauth2-bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c  -XGET 'https://gra1.logs.ovh.com:9200/_cluster/health?pretty'
```

### Comment créer des index ou des alias sur les API des backends de Logs Data Platform ?

Tout d'abord, assurez-vous que l'identité que vous souhaitez utiliser dispose de la permission de créer des index et des alias pour le service. Si elle est autorisée, les jetons d'accès personnels ou les clients OAuth2 de compte de service peuvent effectuer des opérations de création/suppression.

:::warning

Le préfixe précédemment utilisé pour les index et les alias était le nom d'utilisateur. Désormais, le préfixe est le **nom du service**. Vous trouverez le nom du service sur la page d'accueil du Control Panel de Logs Data Platform. C'est aussi le suffixe de l'URN d'un service Logs Data Platform. Par exemple :

urn:v1:eu:resource:ldp:**ldp-ab-56945**

:::


Le service est rattaché à un unique Logs Data Platform ; vous ne pourrez donc créer des éléments que sur ce cluster. Par exemple, si ldp-ab-56945 se trouve sur gra1 :

```bash
ldp@laptop curl -k -v -H 'content-type: application/json' --oauth2-bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c  -XPOST 'https://gra1.logs.ovh.com:9200/ldp-ab-56945-i-my-new-index/_doc' -d '{ "user" : "ldp" }'
```

De même, les alias créés via les API OpenSearch doivent être préfixés par l'un de vos services autorisés.
