## Objectif

Logs Data Platform vous offre un système de rétention personnalisé pour vos logs, que vous pouvez ajuster à la création de votre flux. Mais dans certains cas, vous pouvez souhaiter conserver vos logs au-delà de la durée fournie. Cela peut être pour des raisons légales, à des fins d'analyse, ou simplement pour des raisons historiques. La fonctionnalité de stockage longue durée vous permet de générer une archive quotidienne de n'importe quel flux grâce à quelques étapes de configuration simples.

## Prérequis

Comme son nom l'indique, vous aurez besoin d'un flux. Si vous ne savez pas ce qu'est un flux ou si vous n'en avez pas, vous pouvez suivre ce [tutoriel de démarrage rapide](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start). Vous devez modifier la configuration du flux pour activer le stockage à froid. Cliquez sur le bouton Modifier dans le menu pour accéder à la page de configuration du flux.

<img className="thumbnail" alt="Menu des flux" src="/images/manage-and-operate/observability/logs-data-platform/archive-cold-storage/streams-menu-1.png" loading="lazy" />

## En pratique

### Activer le stockage à froid sur un flux

Sur cette page, vous trouverez le commutateur de stockage longue durée. Une fois activé, vous pourrez choisir différentes options :

- L'algorithme de compression. Nous prenons actuellement en charge [GZIP](http://www.gzip.org/), [DEFLATE (aussi appelé zip)](http://www.zlib.net/feldspar.html), [Zstandard](https://facebook.github.io/zstd/) ou [LZMA (utilisé par 7-Zip)](http://www.7-zip.org/7z.html).
- La durée de rétention de vos archives (d'un an à dix ans).
- Le contenu de vos archives : GELF, un champ spécial [X-OVH-TO-FREEZE](/guides/manage-and-operate/observability/logs-data-platform/field-naming-conventions), ou les deux (vous obtiendrez alors deux archives distinctes)
- L'activation de la notification pour chaque nouvelle archive disponible.

Le contenu de votre archive est personnalisable. Par défaut, vous obtenez le contenu complet des logs au format GELF. Mais vous pouvez choisir de n'avoir qu'une archive contenant uniquement la valeur du champ personnalisé LDP X-OVH-TO-FREEZE. Ce champ peut par exemple être utilisé pour conserver vos logs dans un format lisible par un humain ou dans leur format d'origine. Vous pouvez aussi choisir d'avoir les deux archives simultanément : l'archive GELF d'origine et l'archive X-OVH-TO-FREEZE.

<img className="thumbnail" alt="Menu Modifier" src="/images/manage-and-operate/observability/logs-data-platform/archive-cold-storage/edit-1.png" loading="lazy" />

Dès que vous cliquez sur <code className="action">Sauvegarder</code>, le stockage à froid est activé. Voici quelques points supplémentaires à connaître sur cette fonctionnalité :

:::warning
Dès que la fonctionnalité est activée, vos logs seront stockés pendant la durée spécifiée. L'effet est immédiat, la facturation de cette fonctionnalité l'est donc également.

- Désactiver le stockage à froid sur un flux empêchera la production de nouvelles archives, mais ne supprimera pas les archives déjà produites. Ces archives seront conservées pendant la durée configurée.
- Modifier la durée de rétention SUPPRIMERA toute archive dépassant la nouvelle rétention (par exemple, choisir une rétention d'un an supprimera implicitement toutes les archives de plus d'un an).
- Nous générons une archive quotidienne des données vieilles de 2 jours que vous avez envoyées. Ainsi, chaque jour, vous obtiendrez l'archive de l'avant-veille.
- Lorsque vous activez la fonctionnalité pour la première fois, nous ne pouvons pas créer d'archive pour des données antérieures de plus de deux jours à l'activation.
- Supprimer le flux SUPPRIMERA toute archive associée. Le flux doit rester actif pour pouvoir conserver son archive.

:::


### Récupérer les archives

#### Depuis l'espace client OVHcloud

Sur un flux ayant le stockage à froid activé (vous pouvez rapidement le vérifier grâce à la case à cocher archive), vous disposez d'un nouvel élément <code className="action">Archives</code> en bas du menu du flux. Cliquez dessus pour accéder aux pages d'archives. Sur cette page, vous trouverez la liste des archives produites. Chaque archive porte le nom de sa date, ce qui vous permet de retrouver rapidement l'archive d'un jour particulier.

<img className="thumbnail" alt="Page des archives" src="/images/manage-and-operate/observability/logs-data-platform/archive-cold-storage/archive-1.png" loading="lazy" />

Pour chaque archive, vous pouvez utiliser l'action <code className="action">Télécharger</code> pour télécharger directement l'archive.

#### Depuis l'API

Si vous souhaitez télécharger vos logs via l'API (pour les utiliser par exemple dans une plateforme d'analyse Big Data), vous pouvez effectuer toutes ces étapes avec l'<ApiLink>API OVHcloud</ApiLink>.

Vous aurez besoin du nom de service OVHcloud associé à votre compte. Votre nom de service est l'identifiant logs-xxxxx affiché à gauche du Manager OVHcloud.

**Récupérer votre flux à l'aide de l'appel API streams**

- Retourner la liste des flux graylog :

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/output/graylog/stream"} />


> Paramètres :
>
> - `serviceName` : l'identifiant interne de votre service Logs Data Platform (chaîne de caractères)

**Récupérer la liste de vos archives et leurs détails à l'aide des endpoints correspondants**

- Retourner les détails d'une archive spécifiée :

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/output/graylog/stream/\{streamId\}/archive/\{archiveId\}"} />


> Paramètres :
>
> - `serviceName` : l'identifiant interne de votre service Logs Data Platform (chaîne de caractères)
> - `streamId` : le flux dont vous voulez les archives
> - `archiveId` : l'archive dont vous voulez les détails

**Vous pouvez générer une URL de téléchargement temporaire à l'aide de l'endpoint suivant**

- Obtenir une URL temporaire publique pour accéder à l'archive :

<Api version="v1" section="/dbaas/logs" method="POST" route={"/dbaas/logs/\{serviceName\}/output/graylog/stream/\{streamId\}/archive/\{archiveId\}/url"} />


> Paramètres :
>
> - `serviceName` : l'identifiant interne de votre service Logs Data Platform (chaîne de caractères)
> - `streamId` : le flux dont vous voulez les archives.
> - `archiveId` : l'archive dont vous voulez les détails.
>
**Exemple de résultat :**

```bash
{
  "expirationDate": "2024-07-31T12:27:22.797Z",
  "url": "string"
}
```

Le dégivrage de votre archive prendra un certain temps (en fonction de la taille du fichier d'archive). Une fois celui-ci terminé, vous devrez utiliser à nouveau l'appel API. Si votre archive est disponible, vous obtiendrez un résultat de ce type :

#### Depuis ldp-archive-mirror

Pour vous permettre d'obtenir une copie locale de toutes vos archives stockées à froid sur Logs Data Platform, nous avons développé un outil open source qui le fait de manière passive : **ldp-archive-mirror**
La procédure d'installation et de configuration est décrite sur la [page GitHub](https://github.com/ovh/ldp-archive-mirror) correspondante.

#### Contenu de l'archive

Les données que vous récupérez dans l'archive sont par défaut au [format GELF](https://go2docs.graylog.org/4-x/getting_in_log_data/gelf.html?tocpath=Getting%20in%20Log%20Data%7CLog%20Sources%7CGELF%7C_____0#GELFPayloadSpecification). Elles sont ordonnées par le champ timestamp et conservent tous les champs supplémentaires que vous auriez ajoutés (avec votre [collecteur Logstash](/guides/manage-and-operate/observability/logs-data-platform/logstash-input) par exemple).
