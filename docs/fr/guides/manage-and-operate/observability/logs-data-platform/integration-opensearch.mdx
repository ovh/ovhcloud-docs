## Objectif

Comme expliqué dans notre [documentation d'introduction](/guides/manage-and-operate/observability/logs-data-platform/introduction), Logs Data Platform s'appuie fortement sur [OpenSearch](https://github.com/opensearch-project/OpenSearch) pour fonctionner. OpenSearch dispose d'un écosystème riche et permet des requêtes très complexes.

**Cette documentation explique comment utiliser des logiciels tiers s'intégrant avec OpenSearch grâce aux alias.**

## Prérequis

- Accès au <ManagerLink to="/">espace client OVHcloud</ManagerLink>
- Un [compte Logs Data Platform](/links/manage-operate/logs-data-platform)

## En pratique

### Qu'est-ce qu'un alias Logs Data Platform ?

Comme expliqué dans la documentation mentionnée ci-dessus, un *alias* Logs Data Platform est un *index* OpenSearch virtuel. Vous pouvez attacher plusieurs *index* **ou** plusieurs *flux* de logs à un *alias* (mais pas un mélange d'*index* et de *flux*). Dans les deux cas, les *alias* sont en lecture seule.

### Configuration de l'alias

Lorsqu'il est attaché à des *flux* ou des *index*, un *alias* vous permet d'exposer le contenu de vos *flux* exactement comme s'ils étaient stockés dans un seul *index* OpenSearch. Cette fonctionnalité ne peut être utilisée qu'à des fins de lecture/requête.

:::info
Si vous souhaitez ingérer des logs vers un *flux* en utilisant l'API OpenSearch, nous fournissons un input partagé qui fonctionne comme un *index* spécial préconfiguré à cet effet et accessible à tout utilisateur de Logs Data Platform.
Vous pouvez suivre [cette documentation](/guides/manage-and-operate/observability/logs-data-platform/ldp-index) pour l'utiliser.

:::

- Une fois créé, vous pouvez modifier la description, accéder à l'alias via l'UI web OpenSearch ou supprimer l'alias via le bouton <code className="action">...</code>.

#### Attacher un alias à un flux

- Attachez et détachez des *flux* et/ou des *index* à un alias en cliquant sur le bouton <code className="action">...</code> puis sur le bouton <code className="action">Attacher du contenu à l'alias</code>.
- Choisissez ensuite le flux que vous souhaitez attacher à l'alias.

<img className="thumbnail" alt="Attachement de contenu à un alias sur Logs Data Platform" src="/images/manage-and-operate/observability/logs-data-platform/integration-opensearch-api/alias-attach-blurred.png" loading="lazy" />

#### Attacher un alias à un index

Si vous utilisez la [fonctionnalité d'index OpenSearch managé as a service](/guides/manage-and-operate/observability/logs-data-platform/index-as-a-service), vous pouvez également attacher plusieurs *index* à un *alias*. Dans ce cas, attachez l'alias et configurez-le comme décrit ci-dessous.

- Attachez et détachez des *flux* et/ou des *index* à un alias en cliquant sur le bouton <code className="action">...</code> puis sur le bouton <code className="action">Attacher du contenu à l'alias</code>.
- Choisissez ensuite l'onglet des index que vous souhaitez attacher à l'alias.
- Enfin, sélectionnez les index que vous souhaitez attacher à l'alias.

#### Récupérer les identifiants

**Comptes avec IAM activé**

Les [comptes avec IAM activé](/guides/manage-and-operate/observability/logs-data-platform/landing-page-logs-data-platform) disposent de deux moyens d'obtenir des identifiants à la fois pour les API OVHcloud et pour les API des plans de données de Logs Data Platform :

- **Jeton d'accès personnel (PAT)** pour un utilisateur local : [générez un jeton](/guides/manage-and-operate/observability/logs-data-platform/tokens) via la console IAM ou l'API.
- **Jeton de compte de service** : obtenu en créant d'abord un [compte de service](/guides/manage-and-operate/api/manage-service-account) et en utilisant le flux client-credentials OAuth2.

Les deux jetons peuvent être utilisés comme **bearer token** ou avec un **schéma d'authentification basic** en utilisant `pat_jwt_<your_suffix>` comme nom d'utilisateur. Remplacez `<your_suffix>` par la chaîne ASCII de votre choix.

**Comptes historiques (sans IAM)**

- Utilisez le couple traditionnel `<username>` et `<password>`, ou un jeton historique généré depuis l'UI de Logs Data Platform.

### Gestion des accès aux alias

Comme toutes les fonctionnalités de Logs Data Platform, avec IAM activé, les alias peuvent être partagés avec d'autres identités OVHcloud. Si vous n'êtes pas familier avec IAM, nous vous encourageons à lire la [documentation IAM](/guides/account-and-service-management/account-information/iam-policy-ui) ainsi que la documentation spécifique de [gestion des accès IAM](/guides/manage-and-operate/observability/logs-data-platform/landing-page-logs-data-platform) de Logs Data Platform.

Les droits relatifs à la gestion des alias OpenSearch via les **API OVHcloud** sont :

|Droits                                             |Types de produit LDP|Description|
|---------------------------------------------------|-----------------|-----------|
|ldp:apiovh:url/get                                 |service          |Obtenir les URL utiles du service Logs Data Platform|
|ldp:apiovh:output/opensearch/alias/create          |service          |Créer un nouvel alias OpenSearch via l'API OVHcloud|
 ldp:apiovh:output/opensearch/alias/url/get         |alias            |Obtenir les URL d'un alias OpenSearch via l'API OVHcloud|
|ldp:apiovh:output/opensearch/alias/get             |alias            |Obtenir les alias OpenSearch via l'API OVHcloud|
|ldp:apiovh:output/opensearch/alias/edit            |alias            |Mettre à jour un alias OpenSearch via l'API OVHcloud|
|ldp:apiovh:output/opensearch/alias/index/get       |alias            |Obtenir les index OpenSearch attachés à un alias OpenSearch via l'API OVHcloud|
|ldp:apiovh:output/opensearch/alias/index/attach    |alias            |Attacher un index OpenSearch à un alias OpenSearch via l'API OVHcloud|
|ldp:apiovh:output/opensearch/alias/index/detach    |alias            |Détacher un index OpenSearch d'un alias OpenSearch via l'API OVHcloud|
|ldp:apiovh:output/opensearch/alias/stream/get      |alias            |Obtenir les flux attachés à un alias OpenSearch via l'API OVHcloud|
|ldp:apiovh:output/opensearch/alias/stream/attach   |alias            |Attacher un flux à un alias OpenSearch via l'API OVHcloud|
|ldp:apiovh:output/opensearch/alias/stream/detach   |alias            |Détacher un flux d'un alias OpenSearch via l'API OVHcloud|
|ldp:apiovh:output/opensearch/alias/delete          |alias            |Supprimer un alias OpenSearch via l'API OVHcloud|

Les droits relatifs à la gestion des alias OpenSearch via l'**API OpenSearch** sont :

|Droits                                             |Types de produit LDP|Description|
|---------------------------------------------------|-----------------|-----------|
|ldp:opensearch:alias/delete                        |alias            |Supprimer un alias via l'API OpenSearch|
|ldp:opensearch:alias/create                        |alias            |Créer un alias via l'API OpenSearch|
|ldp:opensearch:alias/read                          |alias            |Lire le contenu d'un alias via l'API OpenSearch|

Il n'existe pas de droit lié à l'écriture, car les alias sont en **lecture seule**.

Les utilisateurs historiques peuvent se référer à [cette documentation](/guides/manage-and-operate/observability/logs-data-platform/getting-started-roles-permission).

### Guide récapitulatif rapide pour configurer l'accès aux alias

1\. **Créer un utilisateur local**

Pour créer un utilisateur local, rendez-vous sur la page <ManagerLink to="/#/iam/identities/users">Identités</ManagerLink>. Complétez les champs requis et cliquez sur <code className="action">Confirmer</code> pour créer l'utilisateur.

Consultez la [documentation dédiée](/guides/account-and-service-management/account-information/ovhcloud-users-management) pour plus d'informations sur les utilisateurs.

2\. **Générer un PAT**

Un [jeton d'accès personnel](/guides/manage-and-operate/observability/logs-data-platform/tokens) est nécessaire pour interagir avec Logs Data Platform ou l'API OVHcloud lorsque vous utilisez un utilisateur local. Comme indiqué dans le guide correspondant, vous pouvez en créer un via l'API :

<Api version="v1" section="/me" method="POST" route={"/me/identity/user/\{user\}/token"} />

La réponse contient un champ `access_token`, qui est votre PAT.


3\. **Créer la politique IAM**

Les [politiques IAM](/guides/manage-and-operate/observability/logs-data-platform/landing-page-logs-data-platform) permettent à une identité d'interagir avec les ressources de Logs Data Platform. Créez ou modifiez une politique existante et ajoutez les droits correspondants pour votre utilisateur local.

Consultez le guide ou la documentation IAM pour des informations détaillées sur cette fonctionnalité. N'oubliez pas d'ajouter votre nouvel alias en tant que ressource gérée par cette politique IAM.

Veillez à séparer les droits de service et les droits spécifiques aux alias dans des politiques différentes si nécessaire, car tous les alias héritent des droits appliqués sur un service Logs Data Platform (c'est-à-dire que placer `ldp:opensearch:alias/read` sur une politique de service donne des droits de lecture sur **tous les alias de ce service**).

4\. **Interroger l'alias** à l'aide du bearer token :

```bash
curl -H "Authorization: Bearer <access_token>" \
    "https://<your_cluster>.logs.ovh.com:9200/`<service_name>`-a-<alias>/_search?pretty"
```

Ou, si vous préférez, utilisez le mécanisme d'authentification hybride :

```bash
curl -u "pat_jwt_<any_suffix>:<access_token>" \
    "https://<your_cluster>.logs.ovh.com:9200/`<service_name>`-a-<alias>/_search?pretty"
```

**Exemple pour un utilisateur historique (à titre de référence uniquement)**

```bash
curl -u logs-ab-12345:<password> \
     "https://<your_cluster>.logs.ovh.com:9200/`<username>`-a-<alias>/_search?pretty"
```

### Configuration de l'outil tiers

Pour se connecter à votre alias comme s'il s'agissait d'un index OpenSearch, les outils tiers nécessitent généralement certaines informations :

- Une URL/un port : il s'agit de l'URL de votre cluster, que vous trouverez sur la page d'accueil de votre compte Logs Data Platform sous le nom « Access point » dans la section « Configuration ». Le port est **9200** pour OpenSearch. L'URL obtenue doit être `https://<your_cluster>.logs.ovh.com:9200`.
- Un nom d'index. Il s'agit du nom de votre alias, que vous trouverez dans la colonne de gauche de la page d'accueil de votre alias, comme dans l'image suivante. Il doit ressembler à ceci : `<ldp_service_name>-a-<alias_name>`.

<img className="thumbnail" alt="Nom d'alias sur Logs Data Platform" src="/images/manage-and-operate/observability/logs-data-platform/integration-opensearch-api/alias-name.png" loading="lazy" />

- Un utilisateur : `pat_jwt_<your_suffix>`, une chaîne commençant par `pat_jwt_` comme nom d'utilisateur.
- Un mot de passe : l'`access_token` obtenu via les utilisateurs locaux ou via le flux OAuth2.
