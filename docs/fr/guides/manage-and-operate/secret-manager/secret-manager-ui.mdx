## Objectif

L'objectif de ce guide est de présenter l'utilisation du Secret Manager à travers la console OVHcloud.

## Prérequis

- Disposer d'un [compte client OVHcloud](/guides/account-and-service-management/account-information/ovhcloud-account-creation).
- Pour accéder aux secrets via l'API REST ou l'API compatible HashiCorp Vault KV2, configurez une [méthode d'authentification](/guides/manage-and-operate/kms/okms-authentication-methods) pour votre domaine OKMS (jeton d'accès personnel, compte de service ou certificat d'accès).

[[cpnav:security-secret-manager]]

## En pratique

### Description

Le Secret Manager est un produit vous permettant de stocker de manière sécurisée les credentials, clés d'API, clés SSH ou tout autre type de secret nécessaire au fonctionnement de vos applications.

Un secret est une collection d'une ou plusieurs clés/valeurs regroupées au sein d'une version.
Chaque modification d'un secret amène la création d'une nouvelle version de ce secret, permettant de remonter dans l'historique des modifications du secret.

### Création d'un secret

Dans la console OVHcloud, les secrets se gèrent dans Key & Secret Manager. Dans le menu de gauche, ouvrez <code className="action">Sécurité</code> et cliquez sur <code className="action">Key & Secret Manager</code>. Chaque domaine OKMS dispose d'un onglet <code className="action">Secrets</code>, qui liste les secrets stockés dans ce domaine.

<img className="thumbnail" alt="Secrets tab of an OKMS domain with the Create a secret button" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secrets-tab.png" loading="lazy" />

Pour créer un secret, cliquez sur <code className="action">Créer un secret</code>.

Le formulaire de création ne propose pas de région : le secret est créé dans le domaine OKMS sélectionné dans la liste **Domaine OKMS**, et donc dans la région de ce domaine. Sélectionnez le bon domaine avant de cliquer sur <code className="action">Créer un secret</code>.

:::info
Si vous ne disposez pas encore d'un domaine OKMS dans la région où vous souhaitez créer le secret, créez-en un d'abord : ouvrez la liste **Domaine OKMS**, cliquez sur <code className="action">Créer un domaine</code> et choisissez la région.
Cette activation peut prendre quelques minutes pour être effective.
:::


Indiquez ensuite le **Path** du secret, par exemple **prod/database/MySQL**. Ce Path sert à organiser les secrets de façon hiérarchique.

Puis indiquez le contenu du secret dans la section **Configuration des valeurs**. Le secret contient une liste de clés/valeurs. Par défaut, celles-ci se saisissent une à une dans la vue **Clé valeur** (<code className="action">Ajouter une clé/valeur</code> ajoute une ligne). Dans la vue **JSON**, vous pouvez les saisir au format JSON :

```json
{
    "login": "admin",
    "password": "my_secret_password"
}
```

<img className="thumbnail" alt="Create a secret page with the Path and Values configuration sections" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/create-secret-form.png" loading="lazy" />

:::info
Il n'y a pas de limite dans le nombre de clés/valeurs d'un secret, cependant la taille totale des données ne doit pas dépasser 64 ko.
:::


Une fois le secret créé, celui-ci apparaît dans la liste des secrets de l'onglet **Secrets** du domaine OKMS.

### Gestion des secrets

Une fois un secret créé, la liste des secrets s'affiche dans l'onglet **Secrets** du domaine OKMS, dans la console OVHcloud.
Pour afficher les secrets d'un autre domaine OKMS, sélectionnez-le dans la liste **Domaine OKMS** au-dessus des onglets, où vos domaines sont regroupés par région.

Vous pouvez accéder à la configuration du secret en cliquant sur son Path dans la liste des secrets pour en afficher le contenu, créer une nouvelle version ou le supprimer.

Le tableau de bord du secret affiche plusieurs informations comme les informations générales ainsi que les paramètres s'appliquant au secret :

- **Nombre maximum de versions** : Au-delà de la valeur indiquée, la plus ancienne version est supprimée.
- **Durée d'expiration d'une version** : Au-delà de la durée indiquée, la version est désactivée.
- **CAS (Check-And-Set version control)** : Si activé, vous devez toujours préciser le numéro de version actuelle lors des modifications.

<img className="thumbnail" alt="Secret dashboard with the Values, General information and Configuration sections" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secret-dashboard.png" loading="lazy" />

#### Accéder au contenu d'un secret

Un utilisateur disposant des droits IAM nécessaires peut accéder au contenu d'un secret. Configurez l'authentification et les politiques IAM comme décrit dans [Méthodes d'authentification OKMS](/guides/manage-and-operate/kms/okms-authentication-methods).

:::info
Les droits pour lister une version (**okms:apiovh:secret/get**) sont différents du droit pour récupérer le contenu de cette version (**okms:apiovh:secret/version/getData**)
:::


Pour cela, cliquez sur <code className="action">Révéler la valeur</code> dans la section **Valeurs** du tableau de bord du secret.

La section **Valeurs** se déploie et affiche le contenu de la version la plus récente du secret, sous forme de clés/valeurs ou au format JSON. Chaque valeur peut être copiée.

<img className="thumbnail" alt="Values section showing the key-value pairs of the current version" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secret-values-revealed.png" loading="lazy" />

Un sélecteur permet de naviguer entre les différentes versions du secret ainsi que de consulter le statut de la version sélectionnée.
Si la version est désactivée ou supprimée, aucune valeur n'est affichée.

#### Gestion des versions

Pour accéder aux versions d'un secret, cliquez sur l'onglet <code className="action">Versions</code>. Il liste l'ensemble des versions du secret, avec pour chacune son numéro, sa date de création, sa date d'expiration et son statut.
Chaque modification d'un secret amène la création d'une nouvelle version.

<img className="thumbnail" alt="Versions tab listing the versions of a secret with their status" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secret-versions.png" loading="lazy" />

Une version peut être soit :

- Active : La valeur de cette version est accessible.
- Désactivée : La valeur de cette version est encore présente dans le système mais n'est plus accessible tant que la version n'est pas réactivée.
- Supprimée : La valeur de cette version n'est plus présente dans le système et ne peut plus être restaurée.

Pour chaque version, cliquez sur <code className="action">Révéler la version</code> pour afficher sa valeur. Le bouton `⋮` ouvre un menu permettant de désactiver (<code className="action">Désactiver</code>) ou de réactiver (<code className="action">Réactiver</code>) la version, ou de la supprimer (<code className="action">Supprimer</code>).

Une version supprimée par le paramètre **Nombre maximum de versions** n'apparaît plus dans la liste des versions.

### Gestion du domaine OKMS

Le domaine OKMS du Secret Manager est commun avec le domaine OKMS du Key Management Service.
La création ou la suppression d'un domaine OKMS a donc des conséquences sur les deux produits.

Vous pouvez modifier la configuration des secrets du domaine OKMS depuis son onglet **Vue d'ensemble**, dans la section **Configuration des secrets** (<code className="action">Modifier</code>).

#### Cas du multi-domaine OKMS

Plusieurs domaines OKMS peuvent exister dans une même région. Le domaine OKMS se choisit au préalable, dans la liste **Domaine OKMS** au-dessus des onglets, qui regroupe vos domaines par région. Les secrets que vous affichez ou créez appartiennent au domaine sélectionné dans cette liste : la création d'un secret ne comporte pas d'étape de sélection supplémentaire.

<img className="thumbnail" alt="OKMS domain list with domains grouped by region and the Create domain entry" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/okms-domain-switcher.png" loading="lazy" />

Pour ajouter un domaine OKMS dans une région, cliquez sur <code className="action">Créer un domaine</code> en haut de cette liste, puis choisissez la région.

### Utilisation du Secret Manager par API

Le Secret Manager est accessible par deux jeux d'API différents. Les deux manipulent les mêmes objets — un secret créé par l'une des méthodes est accessible par l'autre.

Avant d'appeler l'une ou l'autre API, configurez une [méthode d'authentification](/guides/manage-and-operate/kms/okms-authentication-methods) et la [politique IAM](/guides/manage-and-operate/kms/okms-authentication-methods#iam-rights-for-okms) requise sur votre domaine OKMS. Pour l'utilisation de l'API REST, un jeton d'accès personnel (PAT) ou un compte de service est recommandé.

- Une [API REST](/guides/manage-and-operate/secret-manager/rest-api) similaire aux standards d'API d'OVHcloud.
- Une [API compatible HashiCorp Vault KV2](/guides/manage-and-operate/secret-manager/kv2-api) apportant une compatibilité avec les applications déjà compatibles avec HashiCorp Vault KV2.
