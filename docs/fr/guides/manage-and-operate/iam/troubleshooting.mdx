## Objectif

L'objectif de ce guide est de présenter les différentes méthodes disponibles pour identifier les actions manquantes dans les politiques IAM

## Prérequis

- Disposer d'un [compte client OVHcloud](/guides/account-and-service-management/account-information/ovhcloud-account-creation).
- Savoir configurer des [politiques d'accès via la console OVHcloud](/guides/account-and-service-management/account-information/iam-policy-ui) ou des [politiques d'accès via API](/guides/account-and-service-management/account-information/iam-policies-api).
- Savoir [envoyer les logs de politiques IAM vers Logs Data Platform](/guides/manage-and-operate/iam/logs-forwarding).

## En pratique

### Dans les réponses HTTP

Lors des appels d'API, il est possible d'obtenir le nom de l'action manquante dans la réponse de la requête HTTP : via le champ `unauthorizedActionsByIAM`.
Dans l'exemple suivant, l'action manquante est "*vps:apiovh:reboot*"

```json
{
  "class": "Client::Forbidden",
  "message": "User not granted for this request",
  "details": {
    "unauthorizedActionsByAuthentication": "",
    "unauthorizedActionsByIAM": "vps:apiovh:reboot"
  }
}
```

Cette réponse est renvoyée par l'appel d'API suivant lorsque les politiques de l'utilisateur n'autorisent pas l'action :

<Api version="v1" section="/vps" method="POST" route={"/vps/\{serviceName\}/reboot"} />

### Dans Logs Data Platform (LDP)

Si la [transmission des logs du compte OVHcloud](/guides/manage-and-operate/iam/logs-forwarding) vers LDP est activée, vous pouvez trouver l'information dans les logs des politiques d'accès.

Dans l'interface de Graylog, faites une recherche sur le login de l'utilisateur concerné et les logs contenant des `unauthorized_actions_array` avec la requête `identities_array:*My_user* AND _exists_:unauthorized_actions_array`.

<img className="thumbnail" alt="Graylog research" src="/images/manage-and-operate/iam/iam-troubleshooting/graylog_research.png" loading="lazy" />

Les logs ainsi filtrés montrent les actions refusées par l'IAM d'OVHcloud pour l'utilisateur.

<img className="thumbnail" alt="Log example" src="/images/manage-and-operate/iam/iam-troubleshooting/IAM_log.png" loading="lazy" />

Ici par exemple, l'utilisateur *Ines* a essayé de réaliser l'action *vps:apiovh:reboot* sans succès.

Il est aussi possible de filtrer la recherche sur `authorized_actions_array` pour lister les actions autorisées par l'IAM d'OVHcloud.
