## Ziel

OVHcloud HA-NAS Dienste ermöglichen Ihnen die Verwaltung zentral gespeicherter Dateien, die über ein Netzwerk zugänglich sind.

**Diese Anleitung erklärt, wie Sie Ihren HA-NAS über die OVHcloud API verwenden.**

## Voraussetzungen

- Sie haben ein [OVHcloud HA-NAS](https://www.ovh.com/de/nas/) in Ihrem Kunden-Account.
- Sie haben sich anhand der [Anleitung zu den ersten Schritten mit der OVHcloud API](/guides/manage-and-operate/api/first-steps) mit der Verwendung der OVHcloud APIv6 vertraut gemacht.

## In der praktischen Anwendung

Alle API-Routen in dieser Anleitung sind im <ApiLink section="/dedicated/nasha">Bereich */dedicated/nasha*</ApiLink> der API-Konsole verfügbar.

:::info
Bei der Verwendung der API sind alle mit einem Stern (\*) gekennzeichneten Felder Pflichtfelder.
:::


### Informationen zu Ihrer Dienstleistung abrufen

Alle Ihre aktiven Dienste können über folgende Route abgerufen werden:

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha"} />


### Erstellung einer Partition

Verwenden Sie die folgende Route, um eine neue Partition zu erstellen:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Der interne Name Ihres HA-NAS |
| `partitionDescription` |  | Optionale Beschreibung |
| `partitionName` | Yes | Ein Name für die Partition |
| `protocol` | Yes | *NFS*, *CIFS* oder *NFS_CIFS* für beide |
| `size` | Yes | Größe der Partition |

Wählen Sie beispielsweise `NFS` als Protokoll mit einer Größe von `10` Gigabyte aus.

### Hinzufügen eines ACL Eintrags zum Zugriff auf die Partition

:::warning
Der Zugriff ist gesperrt, solange er nicht über die ACL gewährt wird. Es können nur IP-Adressen hinzugefügt werden, die mit Ihren OVHcloud Diensten verbunden sind.
:::


Sie können die IP-Adressen, für die der Zugang erlaubt werden kann, über folgende Aufrufe überprüfen:

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/authorizableBlocks"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Der interne Name Ihres HA-NAS Dienstes |
| `partitionName` | Yes | Partitionsname |

Um einen neuen ACL Eintrag zu erstellen, über den Sie auf die Partition zugreifen können, verwenden Sie folgenden Aufruf:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/access"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Der interne Name Ihres HA-NAS |
| `partitionName` | Yes | Partitionsname |
| `ip` | Yes | Die IP-Adresse oder der Adressbereich für den Zugriff |
| `type` | Yes | Typ des ACL Zugangs für diesen Eintrag: *readonly* oder *readwrite* |

:::info
Verwenden Sie die CIDR-Notation für IP-Bereiche, zum Beispiel: 192.0.2.0/24.
:::


### Manuellen Snapshot erstellen

Um einen manuellen Snapshot hinzuzufügen verwenden Sie folgende Route:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/customSnapshot"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Der interne Name Ihres HA-NAS |
| `partitionName` | Yes | Partitionsname |
| `expiration` |  | Ein optionales Ablaufdatum, zum Beispiel: 2022-06-24 (ISO 8601) |
| `name` | Yes | Name des Snapshots |

### Löschung einer Partition

Verwenden Sie die folgende Route, um eine Partition zu löschen:

<Api version="v1" section="/dedicated/nasha" method="DELETE" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Der interne Name Ihres HA-NAS |
| `partitionName` | Yes | Partitionsname |

## Die API mit einem privaten NAS-HA verwenden (Beta) <a name="using-the-api-with-a-private-nas-ha-beta"></a>

:::info
Der private NAS-HA befindet sich derzeit in der Beta-Phase. Seine API-Routen unterscheiden sich von den oben beschriebenen: Sie sind im <ApiLink section="/storage">Bereich */storage*</ApiLink> der API-Konsole verfügbar, und die Partitionen heißen dort **Shares**. Dieser Abschnitt kann sich mit der Weiterentwicklung des Produkts ändern.

:::


Um einen privaten NAS-HA mit Ihrem privaten vRack-Netzwerk zu verbinden, lesen Sie unsere Anleitung "[HA-NAS - Private network configuration (Beta)](/guides/storage-and-backup/file-storage/ha-nas/nas-network-config)".

### Informationen zu Ihrem Dienst abrufen (Beta)

Um Ihre privaten NAS-HA Dienste aufzulisten, verwenden Sie folgende Route:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha"} regions={["eu"]} />


Das Feld `id` der Antwort ist der `serviceName`, den die folgenden Routen verwenden.

Um die `shareId` Ihrer Shares (das Feld `id` der Antwort) abzurufen, verwenden Sie folgende Route:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Die ID Ihres privaten NAS-HA Dienstes |

### Hinzufügen eines ACL Eintrags zum Zugriff auf den Share (Beta)

:::warning
Der Zugriff ist gesperrt, solange er nicht über die ACL gewährt wird.
:::


Um einen neuen ACL Eintrag zu erstellen, über den Sie sich mit Ihrem Share verbinden können, verwenden Sie folgende Route:

<Api version="v1" section="/storage" method="POST" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/acl"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Die ID Ihres privaten NAS-HA Dienstes |
| `shareId` | Yes | Die ID des Shares |
| `accessLevel` | Yes | ACL-Zugriffsebene: *rw* (Lesen und Schreiben) oder *ro* (nur Lesen) |
| `accessTo` | Yes | Die IPv4-Adresse oder der Adressbereich, dem Zugriff gewährt werden soll |

:::info
Verwenden Sie für IP-Bereiche die CIDR-Notation, zum Beispiel: 10.235.0.0/24.
:::


### Den Mountpoint abrufen (Beta)

Um die `accessPathId` der Zugriffspfade eines Shares abzurufen, verwenden Sie folgende Route:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/accessPath"} regions={["eu"]} />


Rufen Sie anschließend die Details eines Zugriffspfads mit folgender Route ab:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/accessPath/\{accessPathId\}"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Die ID Ihres privaten NAS-HA Dienstes |
| `shareId` | Yes | Die ID des Shares |
| `accessPathId` | Yes | Die ID des Zugriffspfads |

Das Feld `path` der Antwort enthält den Exportpfad, den Sie in Ihrem Mount-Befehl verwenden. Wenn ein Share mehrere Zugriffspfade hat, verwenden Sie denjenigen, dessen Feld `preferred` den Wert `true` hat.
