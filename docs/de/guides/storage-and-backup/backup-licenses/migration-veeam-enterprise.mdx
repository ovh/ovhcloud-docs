## Ziel

Das Produkt **Backup Licenses** ersetzt das Angebot **Veeam Enterprise**. Es basiert auf der OVHcloud **Veeam Service Provider Console** (VSPC): Anstatt eine Lizenz über das Kundencenter zu aktivieren, wird Ihr **Veeam Backup & Replication** Server (VBR) mit unserer Console verbunden, die ihm automatisch eine Lizenz zuweist und diese verlängert.

**Diese Anleitung erläutert, was sich zwischen Veeam Enterprise und Backup Licenses ändert, was OVHcloud auf Ihrem VBR-Server tun kann und was nicht, und wie Sie die Migration durchführen.**

## Voraussetzungen

- Sie verfügen über eine aktive **Veeam Enterprise** Lizenz bei OVHcloud.
- Sie verfügen über einen installierten und betriebsbereiten **Veeam Backup & Replication** Server, dessen **öffentliche IP-Adresse** Sie kennen.
- Sie haben Zugang zur VBR Console mit einem Konto, das über **lokale Administrator**-Rechte oder die Rolle **Veeam Backup Administrator** verfügt.
- Sie haben die Anleitung "[Bekannte Einschränkungen](/guides/storage-and-backup/backup-licenses/restrictions)" gelesen: Ihre VBR Version und Ihr Betriebssystem bestimmen, welche Editionen verfügbar sind.

## Was sich ändert

| | Veeam Enterprise | Backup Licenses |
|---|---|---|
| **Lizenzaktivierung** | Manuelle Lizenzaktivierung über das Kundencenter, auf dem Service `backupserverenterprise`. | Automatische Lizenzzuweisung, sobald Ihr VBR mit der OVHcloud VSPC verbunden ist. |
| **Verfügbare Editionen** | Enterprise Plus. | Veeam Enterprise Plus, VDP Foundation, VDP Advanced, VDP Premium. |
| **Betriebssysteme** | Windows. | Windows sowie Linux (Veeam Software Appliance) für die VDP-Editionen. |
| **Monitoring** | Über Ihre eigene VBR Console. | Über Ihre VBR Console und über das VSPC-Portal (Company-Owner-Konto). |
| **Speicher** | In Ihrer Verantwortung. | Mit der ersten Lizenz wird ein "Bundle"-Vault mit 500 GB bereitgestellt. Siehe "[So funktionieren Vaults](/guides/storage-and-backup/backup-licenses/vault)". |

## Handlungsspielraum von OVHcloud auf Ihrem VBR

Wenn Sie Ihren VBR-Server mit der OVHcloud VSPC verbinden, ist es wichtig zu verstehen, was OVHcloud auf Ihrer Veeam-Infrastruktur tun darf und was außerhalb seiner Reichweite bleibt.

**Was OVHcloud über die VSPC tun kann:**

- **Metadaten** zu Ihren Backup-Jobs erfassen (Status, Konfiguration) – ohne auf den Inhalt der Backups zuzugreifen.
- Den **Lizenzverbrauch** pro geschütztem Workload verfolgen.
- Die mit Ihrem Vertrag verbundenen Lizenzen **zuweisen und verwalten**.
- Den **Dienst neu starten** des Management Agents.

**Was OVHcloud nicht tun kann:**

- Auf **Sicherungsdateien oder gesicherte Daten** zugreifen.
- Auf das **Dateisystem** Ihres Servers im Allgemeinen zugreifen.
- Sich per **RDP / Remotedesktop** mit Ihrem Server verbinden.
- Auf **andere Anwendungen** auf dem Server, auf das **Active Directory** zugreifen oder die **Windows-Konfiguration** ändern.
- Einen Backup-Job **starten oder stoppen** oder die **Einstellungen** von VBR-Jobs **ändern**.
- Den **Netzwerkverkehr abfangen** oder Ihre Produktionsdaten exfiltrieren.

## Sicherheit: der Veeam Management Agent

Wenn Sie die Option aktivieren, mit der OVHcloud Ihre VBR-Installation verwalten darf, wird auf dem Server, auf dem Veeam Backup & Replication läuft, ein **Veeam Management Agent** installiert. Dieser Agent stellt die sichere Verbindung zwischen Ihrem VBR und der OVHcloud-Plattform her.

- **Nur ausgehende Kommunikation**: Die Verbindung wird immer vom Agent in Richtung der OVHcloud-Plattform aufgebaut.
- **TCP-Port 6180** und durchgängige **TLS 1.2-Verschlüsselung** für die Daten während der Übertragung.
- **Gegenseitige Authentifizierung** mit digitalen Zertifikaten, einschließlich Prüfung der Zertifikatssperrlisten (CRL), sofern zutreffend.
- Der Agent läuft unter dem **Local System**-Konto unter Windows, ohne **Domänenkonto** und ohne dass für seinen grundlegenden Betrieb ein Active-Directory-Zugriff erforderlich ist.
- **Sie behalten die Kontrolle**: Sie können die Kommunikation unterbrechen (Firewall auf Port 6180, Stoppen des Windows-Dienstes), den Agent wie jedes andere Windows-Programm deinstallieren und den ausgehenden Datenverkehr mit Ihren Netzwerksicherheits-Tools überwachen.

## Netzwerkarchitektur und Datenflüsse

**Auf der Client-Seite, Ihre Infrastruktur:**

- Der **VBR-Server** initiiert die Datenflüsse in Richtung OVHcloud.
- Die **Firewall** muss **ausgehendes TCP 6180** zum OVHcloud Cloud Gateway zulassen. Sie muss es außerdem unserer Infrastruktur erlauben, Ihren Server von der IP-Adresse `79.137.44.43` in Europa bzw. `142.44.140.20` in Kanada aus zu erreichen, über die Ports **TCP 135, 443, 445 und 49152-65535** (Windows-Server) oder **TCP 443** (Linux-Server).
- Die ausgetauschten Daten umfassen: **Job-Status**, **Workload-Anzahl**, **Lizenzverbrauch**, **VBR Version** – und **nicht die Sicherungsdateien** selbst.

**Auf der OVHcloud-Seite:**

- Das **Cloud Gateway** ist der sichere Einstiegspunkt.
- Die **VSPC** übernimmt die Lizenzverwaltung und das Monitoring.
- Ihre Umgebung ist von anderen Kunden **isoliert** (Tenant-Isolation).

## In der praktischen Anwendung

Backup Licenses ist in zwei Universen Ihres Kundencenters verfügbar, Hosted Private Cloud und Bare Metal Cloud, mit identischer Oberfläche. Die Anweisungen in dieser Anleitung gelten für beide.

:::danger
**Sie müssen Ihre Veeam-Enterprise-Lizenz kündigen, bevor Sie Ihren VBR-Server mit der VSPC verbinden.** Dieser Schritt ist obligatorisch.

Bei Veeam Enterprise wird die Lizenz Ihres VBR-Servers von einem durch OVHcloud betriebenen **Veeam Backup Enterprise Manager** Server verwaltet. Solange Ihr VBR-Server daran angebunden ist, kann die VSPC die Backup-Licenses-Lizenz nicht zuweisen. Führen Sie die folgenden Schritte in der angegebenen Reihenfolge aus.

:::

Für die Migration:

- Bestellen Sie Ihre Backup-Licenses-Lizenz.
- Kündigen Sie Ihre Veeam-Enterprise-Lizenz und warten Sie anschließend 24 Stunden.
- Öffnen Sie die erforderlichen Netzwerkverbindungen.
- Verbinden Sie Ihren VBR-Server mit der OVHcloud VSPC.
- Aktivieren Sie die automatische Lizenzaktualisierung auf Ihrem VBR-Server.
- Überprüfen Sie, ob die neue Lizenz übernommen wurde.

### Schritt 1: Ihre Backup-Licenses-Lizenz bestellen

Bestellen Sie im OVHcloud Kundencenter eine Backup-Licenses-Lizenz, indem Sie die gewünschte Edition auswählen, und geben Sie anschließend einen **Namen für Ihren VBR** sowie dessen **öffentliche IP-Adresse** ein.

Die verfügbaren Editionen werden in der Anleitung "[Ihre erste Lizenz bestellen und konfigurieren](/guides/storage-and-backup/backup-licenses/first-configuration)" beschrieben.

Sobald die Bestellung bestätigt ist, erhalten Sie eine **Lieferbestätigungs-E-Mail**, die die URL des Cloud Gateways (`vspc-adv-cgw…`), den Port `6180` sowie Ihre Konten **Company Tenant** und **Company Owner** enthält.

:::warning
Verbinden Sie Ihren VBR-Server noch nicht mit der VSPC: Kündigen Sie zuerst Ihre Veeam-Enterprise-Lizenz (Schritt 2).

:::

### Schritt 2: Ihre Veeam-Enterprise-Lizenz kündigen

Kündigen Sie Ihren Dienst **Veeam Enterprise** (mit der Bezeichnung `backupserverenterprise`) über das OVHcloud Kundencenter. Bei Bedarf finden Sie Hilfe in unserer Anleitung "[Kündigen von OVHcloud Diensten](/guides/account-and-service-management/managing-billing-payments-and-services/how-to-cancel-services)".

:::warning
Kündigen Sie ausschließlich Ihren **früheren Dienst Veeam Enterprise**. Kündigen Sie nicht die soeben bestellte Backup-Licenses-Lizenz, auch wenn Sie die Edition **Veeam Enterprise Plus** gewählt haben.

:::

Nach Ihrer Kündigungsanfrage **warten Sie 24 Stunden**: So lange dauert es, bis Ihr VBR-Server vom Veeam Backup Enterprise Manager von OVHcloud getrennt ist. Fahren Sie erst danach mit Schritt 3 fort.

Wenn nach Ablauf dieser 24 Stunden in Ihrer VBR Console weiterhin ein Popup-Fenster mit der Meldung *The license of this backup server is managed by the Veeam Backup Enterprise Manager* erscheint, wurde Ihr Server nicht getrennt. Lesen Sie in diesem Fall den entsprechenden Punkt im "[Troubleshooting-Guide](/guides/storage-and-backup/backup-licenses/troubleshooting)".

### Schritt 3: Die Netzwerkverbindungen öffnen

Stellen Sie sicher, dass die Server-Firewall – und Ihre Netzwerk-Firewall – Folgendes zulässt:

- **Ausgehend**: von Ihrem VBR-Server zum OVHcloud Cloud Gateway, das in der Lieferbestätigungs-E-Mail angegeben ist (`vspc-adv-cgw…`), auf **Port 6180**.
- **Eingehend**: von der IP-Adresse unserer Infrastruktur zu Ihrem VBR-Server. In Europa lautet diese Adresse `79.137.44.43` und in Kanada `142.44.140.20`. Die freizugebenden Ports hängen vom Betriebssystem des Servers ab:
    - zu einem **Windows**-Server (Veeam Backup & Replication, Veeam Backup Enterprise Manager, Veeam ONE, Veeam Backup for Microsoft 365, Veeam Cloud Connect): **TCP 135, 443, 445 und 49152-65535**, erforderlich für *Remote Scheduled Tasks Management (RPC)*. Dies ermöglicht es der VSPC, den Management-Agenten bereitzustellen.
    - zu einem **Linux**-Server (Veeam Backup & Replication oder Veeam Backup Enterprise Manager): **TCP 443**, erforderlich für die Bereitstellung des Management-Agenten.

### Schritt 4: Ihren VBR-Server mit der VSPC verbinden

Die folgenden Schritte werden **über die Veeam Backup & Replication Console** durchgeführt, nicht über das VSPC-Portal.

#### 4.1 Die Veeam Backup & Replication Console öffnen

Melden Sie sich an dem Server an, auf dem Veeam Backup & Replication installiert ist (oder an einem Rechner, auf dem die VBR Console bereitgestellt ist), und starten Sie anschließend die Console:

- Bei einer **Windows**-Installation: Verbinden Sie sich mit `localhost`.
- Bei einer **Veeam Software Appliance**: Geben Sie die Adresse des VBR-Servers und die Zugangsdaten eines Kontos mit der Rolle Veeam Backup Administrator ein.

:::info
Wenn Ihr VBR auf einer Veeam Software Appliance (Linux) läuft, muss die Remote-Datenerfassung in der **Veeam Host Management Console** aktiviert werden.

:::

#### 4.2 Das Hinzufügen des Service Providers starten

Klicken Sie im Menüband am oberen Rand der Console auf <code className="action">Add Service Provider</code>.

Sie können auch über den Navigationsbereich vorgehen:

1. Öffnen Sie die Ansicht <code className="action">Backup Infrastructure</code>.
2. Suchen Sie den Knoten <code className="action">Service Providers</code>.
3. Klicken Sie mit der rechten Maustaste auf <code className="action">Service Providers</code> und anschließend auf <code className="action">Add Service Provider</code>.

<img className="thumbnail" alt="Hinzufügen eines Service Providers über die VBR-Konsole" src="/images/storage-and-backup/backup-licenses/vbr/bl_vbr_add_service_provider.png" loading="lazy" />

#### 4.3 Die Einstellungen des Service Providers eingeben

Im Schritt <code className="action">Service Provider</code> des Assistenten:

1. **DNS name or IP address**: Geben Sie die URL des OVHcloud Cloud Gateways ein, die Sie in der Lieferbestätigungs-E-Mail erhalten haben (`vspc-adv-cgw…`).
2. **Port**: Geben Sie den von OVHcloud bereitgestellten Port `6180` ein.
3. **Description**: optional, eine Beschreibung zur Identifizierung dieses Providers.
4. Aktivieren Sie das Kontrollkästchen <code className="action">Allow this Veeam Backup & Replication installation to be managed by the service provider</code>.

:::danger
Das Kontrollkästchen <code className="action">Allow this Veeam Backup & Replication installation to be managed by the service provider</code> ist **obligatorisch**. Ohne es wird der Management Agent nicht installiert, Ihr Server erscheint nicht in der VSPC und die Lizenz kann ihm nicht zugewiesen werden.

:::

<img className="thumbnail" alt="Schritt Service Provider des Assistenten mit aktiviertem Kontrollkästchen" src="/images/storage-and-backup/backup-licenses/vbr/bl_wizard_1.png" loading="lazy" />

#### 4.4 Die Zugangsdaten eingeben

Geben Sie im Schritt <code className="action">Credentials</code> die **Company Tenant** Zugangsdaten ein, die Sie in der Lieferbestätigungs-E-Mail erhalten haben, und bestätigen Sie anschließend.

<img className="thumbnail" alt="Schritt Credentials des Assistenten" src="/images/storage-and-backup/backup-licenses/vbr/bl_wizard_2.png" loading="lazy" />

#### 4.5 Den Assistenten abschließen

Der Assistent speichert den Service Provider und aktiviert die Remote-Verwaltung. Klicken Sie auf <code className="action">Next</code>, prüfen Sie die Zusammenfassung und klicken Sie im letzten Schritt auf <code className="action">Finish</code>.

<img className="thumbnail" alt="Zusammenfassung des Assistenten mit der Schaltfläche Finish" src="/images/storage-and-backup/backup-licenses/vbr/bl_wizard_4.png" loading="lazy" />

Der Verwaltungsagent wird auf Ihrem VBR-Server bereitgestellt und die Verbindung zur VSPC ist hergestellt.

:::warning
Auf einem VBR-Server unter **Windows** dauert die Registrierung des Servers nach dem Abschluss des Assistenten **mindestens 15 Minuten**. Während dieser Zeit ist es normal, dass Ihr Server noch nicht in der VSPC erscheint und die neue Lizenz noch nicht angewendet wurde. Warten Sie das Ende dieser Frist ab, bevor Sie mit der Fehlersuche beginnen.

:::

### Schritt 5: Die automatische Lizenzaktualisierung auf Ihrem VBR aktivieren

Damit die VSPC Ihre neue Lizenz zuweisen und anschließend automatisch verlängern kann, muss Ihr VBR-Server seine Lizenz selbstständig aktualisieren und seinen Lizenzverbrauch melden dürfen. Dies aktivieren Sie über ein Kontrollkästchen in Ihrer VBR Console:

1. Öffnen Sie in der Konsole Veeam Backup & Replication das Hauptmenü und klicken Sie auf <code className="action">License</code>.
2. Überprüfen Sie unten im Fenster **License Information**, ob das Kontrollkästchen <code className="action">Update license automatically (enables usage reporting)</code> aktiviert ist. Falls nicht, aktivieren Sie es.

    <img className="thumbnail" alt="Aktiviertes Kontrollkästchen Update license automatically im Fenster License Information" src="/images/storage-and-backup/backup-licenses/vbr/bl_license_auto_update.png" loading="lazy" />

:::danger
Das Kontrollkästchen <code className="action">Update license automatically (enables usage reporting)</code> ist **obligatorisch**. Wenn es nicht aktiviert ist, kann die VSPC die Backup-Licenses-Lizenz Ihrem VBR-Server weder zuweisen noch vor ihrem Ablauf automatisch verlängern. Lassen Sie es aktiviert, solange Sie Backup Licenses nutzen.

:::

### Schritt 6: Die neue Lizenz überprüfen

Überprüfen Sie im selben Fenster **License Information** die folgenden Angaben:

| Feld | Erwarteter Wert |
|---|---|
| **Status** | `Valid` (nicht `Expired`, `Invalid` oder `Not Installed`) |
| **Type** | Der Lizenztyp: `Rental` |
| **Package** | Die von Ihnen bestellte Edition, zum Beispiel `Foundation` oder `Enterprise Plus` |
| **Licensed to** | Die mit der Lizenz verknüpfte Organisation: `OVH` |
| **Points** | Die Anzahl der nutzbaren Punkte, entsprechend Ihrer Bestellung |
| **Expiration date** | Das Ablaufdatum der Lizenz |

<img className="thumbnail" alt="Fenster License Information der VBR-Konsole" src="/images/storage-and-backup/backup-licenses/vbr/bl_license.png" loading="lazy" />

Sie können sich auch mit dem Konto **Company Owner** am VSPC-Portal anmelden und im Bereich <code className="action">Managed Computers</code> > <code className="action">Backup Servers</code> überprüfen, ob Ihr Server mit dem Status `Healthy` angezeigt wird.

<img className="thumbnail" alt="Liste der Backup-Server in der VSPC" src="/images/storage-and-backup/backup-licenses/vspc/bl_vspc_backup_server.png" loading="lazy" />

## Wichtige Hinweise

- **Veeam Enterprise**: Kündigen Sie Ihre Veeam-Enterprise-Lizenz und warten Sie 24 Stunden, **bevor** Sie Ihren VBR-Server mit der VSPC verbinden. Andernfalls kann die VSPC Ihre neue Lizenz nicht zuweisen.
- **Automatische Lizenzaktualisierung**: Lassen Sie das Kontrollkästchen <code className="action">Update license automatically (enables usage reporting)</code> auf Ihrem VBR-Server aktiviert.
- **Verbinden Sie denselben VBR-Server nicht zweimal** mit der VSPC unter Verwendung unterschiedlicher Zugangsdaten: Dies würde die angezeigten Daten verfälschen.
- Wenn auf dem VBR-Server **MFA** aktiviert ist, kann er in der VSPC als `Inaccessible` erscheinen. Siehe [Veeam KB 4431](https://www.veeam.com/kb4431).
- **Firewall**: Stellen Sie sicher, dass Port `6180` ausgehend vom VBR-Server zum Cloud Gateway geöffnet ist.
- **HA-Cluster**: Wenn Ihr VBR der primäre Knoten eines Hochverfügbarkeits-Clusters ist, muss der sekundäre Knoten separat verbunden werden.
