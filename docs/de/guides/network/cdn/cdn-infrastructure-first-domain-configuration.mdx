## Einleitung

Bei der ersten Konfiguration des Content Delivery Network (CDN) müssen zunächst in der OVHcloud Konsole Domains angegeben und bestimmte Einstellungen vorgenommen werden, damit das CDN optimal genutzt werden kann.

**In dieser Anleitung erfahren Sie, welche Einstellungen in der OVHcloud Konsole durchzuführen sind und wie Sie das OVHcloud CDN optimal nutzen.**

## Voraussetzungen

- Sie nutzen das [OVHcloud Content Delivery Network (CDN)](https://www.ovhcloud.com/de/network/cdn/).
- Sie verfügen über die erforderlichen Berechtigungen zur Verwaltung der DNS-Zone Ihrer Domain.

[[cpnav:network-cdn-console]]

## Beschreibung

### Domain zum CDN hinzufügen

Fügen Sie dem CDN zunächst eine Subdomain Ihrer Wahl hinzu, damit es HTTP(S)-Anfragen für diese Domain akzeptiert.

Öffnen Sie den Tab <code className="action">Domains</code> und klicken Sie auf <code className="action">Domain hinzufügen</code>. Die Seite **Geführte Domaineinrichtung** öffnet sich und führt Sie durch vier Schritte:

<img className="thumbnail" alt="Tab Domains eines CDN mit dem Button Domain hinzufügen" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/domains-tab.png" loading="lazy" />

1. **Domainname**: Geben Sie die Subdomain, die Sie über das CDN bereitstellen möchten, als vollqualifizierten Domainnamen ein (zum Beispiel `www.example.com`) und klicken Sie dann auf <code className="action">Weiter</code>.
2. **Ursprung (IPv4)**: Geben Sie die IPv4-Adresse des Ursprungsservers ein, auf dem Ihre Dateien gehostet werden (Ihr *Backend*), und klicken Sie dann auf <code className="action">Weiter</code>.
3. **SSL-Zertifikat**: Wählen Sie **Let's Encrypt**, um automatisch ein kostenloses HTTPS-Zertifikat bereitstellen zu lassen, oder **Kein SSL**, um die Domain nur über HTTP auszuliefern (Sie können später ein Zertifikat hinzufügen). Dieser Schritt entfällt, wenn Ihr CDN bereits über ein Zertifikat verfügt. Weitere Informationen finden Sie in unserer Anleitung zur [Funktionsweise des SSL-Zertifikats auf dem CDN](/guides/network/cdn/cdn-infrastructure-ssl-certificate).
4. **Bestätigen & bereitstellen**: Überprüfen Sie die Zusammenfassung und klicken Sie dann auf <code className="action">Bereitstellen</code>.

<img className="thumbnail" alt="Geführte Domaineinrichtung, Schritt Domainname" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/guided-setup-step1.png" loading="lazy" />

Die Seite zeigt anschließend den Fortschritt der Bereitstellung an: Erstellung der Domain, Konfiguration des Ursprungs und, falls ausgewählt, Bereitstellung des SSL-Zertifikats. Nach Abschluss wird das Ziel angezeigt, auf das der CNAME-Eintrag Ihrer Domain verweisen muss (in der Form `<Ihre Domain>.cdn.ovhcloud.com`, zum Beispiel `www.example.com.cdn.ovhcloud.com`). Kopieren Sie dieses Ziel, da Sie es im nächsten Schritt benötigen. Klicken Sie auf <code className="action">Fertig</code>. Ihre Domain wird dann im Tab <code className="action">Domains</code> mit ihrem Ursprung und ihrem Status angezeigt, und Sie können mit der Konfiguration beginnen.

<img className="thumbnail" alt="Ende der geführten Domaineinrichtung mit dem CNAME-Ziel" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/guided-setup-cname.png" loading="lazy" />

Damit Ihre Anfragen über unsere CDN-Infrastruktur laufen, müssen Sie die DNS-Zone Ihrer Subdomain so bearbeiten, dass ein CNAME-Eintrag auf dieses Ziel verweist.

:::warning
Es ist wichtig, hierzu einen CNAME-Eintrag zu verwenden. Nur mit einem CNAME-Eintrag kann die `Bypass`-Funktion korrekt funktionieren. Wenn Sie einen A-Eintrag verwenden, funktioniert zwar das CDN, aber Sie können die *Bypass*-Funktion nicht nutzen.

:::

Wenn die DNS-Zone Ihrer Domain von OVHcloud verwaltet wird, fügen Sie diesen CNAME-Eintrag in der OVHcloud Konsole zur Zone hinzu und passen Sie dabei die Subdomain an Ihre Konfiguration an: Geben Sie Ihre Subdomain ein (zum Beispiel `cdn`) und als Ziel den Wert, der am Ende der geführten Einrichtung angezeigt wurde. Wie Sie einen Eintrag hinzufügen, erfahren Sie in unserer Anleitung zum [Bearbeiten der OVHcloud DNS-Zone](/guides/web-cloud/domains/dns-zone-edit).

 

### Dateiablage im Cache überprüfen
Um zu überprüfen, ob eine Datei sicher im Cache gespeichert ist, verwenden Sie folgenden Befehl:

```sh
curl -I http://sub.domain/
```

Sie erhalten ein ähnliches Ergebnis wie folgt:

```bash
HTTP/1.1 200 OK
Date: Tue, 09 Jan 2018 10:30:57 GMT
Content-Type: text/plain
Last-Modified: Fri, 29 Dec 2017 13:30:42 GMT
ETag: W/"(5a464382-4ddf"
Expires: Wed, 09 Jan 2019 10:30:58 GMT
X-IPLB-Instance: 5905
Vary: Accept-Encoding
X-CDN-Pop: rbx1
X-CDN-Pop-IP: 51.254.41.128/26
X-Cacheable: Matched cache
Accept-Ranges: bytes
Connection: keep-alive
```

Wenn Ihre Datei korrekt aus dem Cache aufgerufen werden kann, wird Ihnen in der Ausgabe `Matched cache` angezeigt.

Außerdem wird der Präsenzpunkt (PoP) angezeigt, von dem aus Ihre Datei aufgerufen wurde (in unserem Beispiel *rbx1*).

Diese Informationen können Sie auch über Ihren Webbrowser abrufen. Gehen Sie hierzu in den Entwicklertools auf den Tab `Netzwerk` (Funktionstaste F12). Wenn Sie auf die Datei klicken, die Sie überprüfen möchten, werden Ihnen die HTTP-Antwort sowie die zugehörigen Header angezeigt.

### Gründe für die Verwendung einer spezifischen Subdomain anstelle der Hauptdomain

Für die Hauptdomain kann kein CNAME-Eintrag erstellt werden. Diese Einschränkung ist bedingt durch die RFC-Standards, die auf Ebene der DNS-Zone angewendet werden.

Zudem wird die Datei- und Rechnungsverwaltung vereinfacht, wenn Sie den Dateien, die Sie im Cache ablegen möchten, eine bestimmte Subdomain zuweisen.

- Dateiverwaltung: Nur Dateien, die über diese Subdomain aufgerufen werden, werden im Cache gespeichert. So können Sie dynamische Dateien oder solche, die Sie nicht im Cache speichern möchten, weiterhin über Ihre Hauptdomain aufrufen. Dadurch wird es auch einfacher, den Ursprung von Anzeigeproblemen auf Ihrer Website zu ermitteln.
- Rechnungsverwaltung: Der gesamte Traffic (egal ob im Cache gespeichert oder nicht), der über die CDN Infrastruktur läuft, wird Ihnen in Rechnung gestellt. Somit können Sie mithilfe einer spezifischen Subdomain die Anzahl der unnötigen Aufrufe über das CDN reduzieren und Ihren Quota-Verbrauch optimieren.

### Weitere erforderliche Aktionen zur Konfiguration einer neuen Subdomain

Wenn Sie eine neue Subdomain für die Nutzung unseres CDN einrichten möchten, müssen wahrscheinlich einige Parameter auf Ihrer Website und in Ihrem Webservice angepasst werden.

Vergewissern Sie sich zunächst, dass Ihr Webservice korrekt auf die Subdomain reagiert. Richten Sie dazu für diese Domain einen *vhost* ein − entweder mit einem eigenen Zielordner oder als Alias einer anderen Domain.

Wenn die Domain korrekt in Ihrem Webservice reagiert, müssen Sie nur den HTML-Code bearbeiten, um die Quellen der Dateien zu ändern, die über das CDN geleitet werden sollen. Stellen Sie sicher, dass diese korrekt über Ihre Subdomain aufgerufen werden.
