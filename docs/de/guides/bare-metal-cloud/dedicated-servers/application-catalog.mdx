## Ziel

Der Anwendungskatalog ermöglicht es Ihnen, ohne Vorkenntnisse in der Systemadministration eine einsatzbereite Anwendung auf Ihrem OVHcloud Dedicated Server zu installieren. Sie wählen bei der (Neu-)Installation Ihres Servers eine Anwendung aus und füllen anschließend ein kurzes Konfigurationsformular in einer gesicherten Web-Oberfläche aus. Die Anwendung wird nativ auf dem Server installiert, per HTTPS gesichert und innerhalb weniger Minuten bereitgestellt.

**Diese Anleitung erklärt, wie Sie den Anwendungskatalog auf Ihrem OVHcloud Dedicated Server verwenden.**

## Voraussetzungen

- Sie verfügen über einen [Dedicated Server](/links/bare-metal/bare-metal) in Ihrem OVHcloud Kunden-Account.
- Sie sind in Ihrem <ManagerLink to="/">OVHcloud Kundencenter</ManagerLink> angemeldet.
- Sie haben Zugriff auf die <ApiLink>OVHcloud API</ApiLink> (für den Abschnitt "[OVHcloud API](#viaapi)" dieser Anleitung).
- Sie haben Zugriff auf die E-Mail-Adresse Ihres OVHcloud Kunden-Accounts, um den Link zur Konfigurationsoberfläche zu erhalten.
- Sie verfügen über einen Webbrowser, um die Konfigurationsoberfläche nach Abschluss der Installation aufzurufen.

## In der praktischen Anwendung

### Funktionsweise des Anwendungskatalogs

Die Bereitstellung einer Anwendung erfolgt in zwei Schritten:

1. **Auswahl (bei der Installation):** Sie installieren Ihren Server mit einem Image des Anwendungskatalogs (neu) und wählen **eine** Anwendung aus. Hier legen Sie fest, *welche* Anwendung Sie bereitstellen möchten.
2. **Konfiguration (nach dem ersten Start):** Sobald der Server neu gestartet ist, wird automatisch ein Konfigurator für die einmalige Verwendung gestartet, der eine gesicherte Web-Oberfläche auf Port `10143` bereitstellt. Sie füllen ein kurzes Formular aus (zum Beispiel einen Website-Namen und ein Administrator-Passwort), anschließend wird die Anwendung automatisch installiert und per HTTPS veröffentlicht.

Nach erfolgreicher Installation **entfernt sich der Konfigurator vollständig** vom Server: Seine Binärdatei, sein Dienst und seine Arbeitsdaten werden gelöscht. Es bleibt nur Ihre Anwendung, und Sie verfügen über einen vollständigen Root-Zugriff auf den Server.

Die Anwendungen werden **nativ** installiert — mit Systempaketen und `systemd`-Diensten, auf einem Server, der ausschließlich diesem Zweck dient — und nicht innerhalb einer Container-Plattform.

**Technische Einschränkungen:**

- **Nur eine Anwendung** kann über den Anwendungskatalog bereitgestellt werden.
- **Benutzerdefinierte Partitionierung und Hardware-RAID-Konfiguration sind für diese Installation nicht verfügbar.**

:::warning
Das bedeutet nicht, dass Sie keine anderen Anwendungen auf dem Server ausführen können. Es bedeutet, dass nur **EINE** Anwendung über den Katalog installiert werden kann. Wenn Sie weitere Anwendungen ausführen möchten, müssen Sie diese manuell installieren.
:::

### Ihre Anwendung bei der Installation auswählen

Es stehen zwei Bereitstellungsmethoden zur Verfügung, die in den folgenden Tabs beschrieben werden: Installieren Sie Ihre Anwendung über das OVHcloud Kundencenter oder verwenden Sie die OVHcloud API, um die Installation in Ihre eigenen Skripte zu integrieren und Ihre Bereitstellungen zu automatisieren.

1. Wählen Sie Ihren Server unter <code className="action">Bare Metal Cloud</code> > <code className="action">Dedicated Server</code> aus.
2. Klicken Sie im Tab <code className="action">Allgemeine Informationen</code> neben **Betriebssystem (OS)** auf die Schaltfläche <code className="action">...</code> und dann auf <code className="action">Meinen Server neu installieren</code>.

3. Setzen Sie im Fenster **Installation mit einem OVHcloud Template** das Feld **Betriebssystemtyp** auf <code className="action">Distribution fertig zum Gebrauch (graphisches Interface)</code> und wählen Sie dann das Template **Ubuntu Server 24.04 "Noble Numbat" LTS with Application Installer** aus. Wählen Sie **Ziel-Festplattenpool(s)** aus und klicken Sie auf <code className="action">Weiter</code>.

    :::info
    Benutzerdefinierte Partitionierung und Hardware-RAID-Konfiguration sind mit diesem Template nicht verfügbar, daher bleiben diese Optionen deaktiviert.
    :::

    <img className="thumbnail" alt="Wählen Sie das Ubuntu-Template mit Application Installer aus" src="/images/bare-metal-cloud/dedicated-servers/application-catalog/install-02.png" loading="lazy" />

4. Durchlaufen Sie die weiteren Installationsschritte, um die allgemeinen Einstellungen anzugeben, etwa den Hostnamen des Servers und den SSH-Schlüssel, der dem Server hinzugefügt werden soll.
5. Wählen Sie im Schritt **Zu installierende Anwendung** die **einzige Anwendung** aus, die Sie bereitstellen möchten, und klicken Sie dann auf <code className="action">Bestätigen</code>, um die Installation zu starten.

    <img className="thumbnail" alt="Wählen Sie die einzige zu installierende Anwendung aus und bestätigen Sie" src="/images/bare-metal-cloud/dedicated-servers/application-catalog/install-03.png" loading="lazy" />

Der Server wird neu installiert und startet anschließend automatisch den Konfigurator. Folgen Sie nach Abschluss der Installation dem Abschnitt "[Ihre Anwendung konfigurieren und darauf zugreifen](#configure)" weiter unten, um die Einrichtung abzuschließen.

#### Die Installation starten <a name="viaapi"></a>

Um die für Ihren Server verfügbaren Betriebssysteme aufzulisten, verwenden Sie den folgenden API-Aufruf:

<Api version="v1" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/install/compatibleTemplates"} />

In der Antwort sind die Templates des Anwendungskatalogs diejenigen, deren Name mit `-withapp` endet. Entnehmen Sie die Kennung immer diesem Aufruf, anstatt sie fest zu hinterlegen, da sich der Katalog der Templates weiterentwickelt.

Anschließend können Sie die Installation mit dem folgenden API-Aufruf auslösen:

<Api version="v1" section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"} />

Geben Sie das im vorherigen Schritt ermittelte Betriebssystem und die zu installierende Anwendung in der Anpassung `appToInstall` an:

```json
{
  "operatingSystem": "ubuntu2404-withapp",
  "customizations": {
    "hostname": "myApplicationServer",
    "sshKey": "mySshKey",
    "appToInstall": "wordpress"
  }
}
```

Der Wert `appToInstall` ist die Kennung der Anwendung, die Sie bereitstellen möchten — zum Beispiel `wordpress`, `drupal`, `nextcloud`, `prestashop`, `discourse`, `matomo`, `n8n`, `openclaw`, `hestiacp`, `fastpanel`, `coolify`, `dokploy`, `easypanel` oder `game-panel`. Es kann nur eine Anwendung angegeben werden.

Verfolgen Sie die Installationsaufgabe bis zum Abschluss, wie in [Install an OS via the OVHcloud API on a Dedicated Server](/guides/bare-metal-cloud/dedicated-servers/api-os-installation) beschrieben, und fahren Sie dann mit dem Abschnitt "[Ihre Anwendung konfigurieren und darauf zugreifen](#configure)" weiter unten fort.

  </Tab>

### Ihre Anwendung konfigurieren und darauf zugreifen <a name="configure"></a>

Nach der Installation startet Ihr Server automatisch den Konfigurator für die einmalige Verwendung. Für diesen Schritt benötigen Sie keine Kenntnisse in Linux, SSH oder Systemadministration — nur einen Webbrowser.

#### Schritt 1: Den Konfigurator öffnen

Nach Abschluss der Installation erhalten Sie eine E-Mail mit dem Link zu Ihrem Konfigurator. Dieser hat die folgende Form:

```text
https://<ihr-server>:10143/static/deploy.html?app=<anwendung>&token=<token>
```

Öffnen Sie diesen Link in Ihrem Webbrowser. Das darin enthaltene Token authentifiziert Sie, und es wird ein gesichertes Cookie nur für diese Sitzung gespeichert, sodass Sie anschließend im Konfigurator navigieren können, ohne das Token in der Adressleiste zu haben. Wird der Konfigurator ohne gültiges Token geöffnet, erscheint eine `Unauthorized`-Seite.

:::warning
Behandeln Sie diesen Link wie ein Passwort und geben Sie ihn nicht weiter: Er gewährt Zugriff auf die Einrichtungsoberfläche Ihres Servers.
:::

:::info
Wenn Ihr Browser beim allerersten Laden eine Zertifikatswarnung anzeigt, bezieht der Konfigurator noch sein Let's Encrypt-Zertifikat und stellt zwischenzeitlich ein temporäres selbstsigniertes Zertifikat bereit. Warten Sie eine Minute und laden Sie die Seite neu — der Wechsel zum endgültigen Zertifikat erfolgt automatisch.
:::

#### Schritt 2: Das Konfigurationsformular ausfüllen

Der Konfigurator öffnet sich direkt mit der Anwendung, die Sie bei der Installation ausgewählt haben. Je nach Anwendung stellen Sie sie sofort bereit oder füllen zuvor ein kurzes Formular aus:

- **Anwendungen ohne Felder** — Coolify, Dokploy, Easypanel, FastPanel, HestiaCP, Discourse, Matomo und n8n — erzeugen die benötigten Zugangsdaten selbst und zeigen sie am Ende an. Klicken Sie auf <code className="action">Deploy</code>.
- **Anwendungen mit Feldern** — WordPress, Drupal, Nextcloud, PrestaShop, OpenClaw und OVHcloud Game Panel — fragen einige Werte ab, etwa einen Website-Namen, ein Administrator-Passwort oder ein Datenbank-Passwort. Erforderliche Felder sind gekennzeichnet, und optionale Felder können sinnvolle Standardwerte vorschlagen.

Ein Bereich <code className="action">Installation details</code> oberhalb des Formulars listet auf, was installiert wird und warum, zusammen mit einem Link zur offiziellen Dokumentation des Herstellers.

Jedes Feld wird vor dem Start der Bereitstellung geprüft (zum Beispiel muss ein E-Mail-Feld eine gültige E-Mail-Adresse enthalten, und Passwörter haben eine Mindestlänge). Korrigieren Sie alle markierten Felder und senden Sie das Formular erneut ab.

:::tip
Wählen Sie sichere Passwörter: Die hier eingegebenen Werte werden zu den tatsächlichen Zugangsdaten Ihrer Anwendung.
:::

<img className="thumbnail" alt="Konfigurationsformular für eine WordPress-Bereitstellung" src="/images/bare-metal-cloud/dedicated-servers/application-catalog/configurator-form.png" loading="lazy" />

Klicken Sie anschließend auf <code className="action">Deploy</code>.

#### Schritt 3: Die Bereitstellung verfolgen

Der Konfigurator führt die Installation aus und überträgt den Fortschritt in Echtzeit: einen Status (`pending`, dann `running`, dann `completed` oder `failed`), einen Fortschrittsbalken und die Installationsprotokolle. Die von Ihnen im Formular eingegebenen Werte werden in den Protokollen maskiert.

<img className="thumbnail" alt="Fortschritt der Bereitstellung und Protokolle in Echtzeit" src="/images/bare-metal-cloud/dedicated-servers/application-catalog/configurator-progress.png" loading="lazy" />

Eine Bereitstellung dauert in der Regel einige Minuten; umfangreichere Anwendungen wie Discourse benötigen mehr Zeit. Sie können den Tab geöffnet lassen, die Installation wird jedoch auf dem Server fortgesetzt, selbst wenn die Verbindung Ihres Browsers getrennt wird — öffnen Sie Ihren Link erneut, um die Verfolgung fortzusetzen.

:::info
Es wird immer nur eine Bereitstellung gleichzeitig ausgeführt. Wenn bereits eine Bereitstellung läuft und Sie eine weitere starten, führt Sie der Konfigurator zur laufenden Bereitstellung zurück, anstatt eine zweite zu starten. Dies stellt die Regel "eine Anwendung pro Server" sicher.
:::

#### Schritt 4: Ihre Zugangsdaten abrufen

Sobald der Status `completed` erreicht ist, zeigt der Konfigurator eine Erfolgsseite an mit:

- dem Link zu Ihrer Anwendung, auf dem Standard-HTTPS-Port — `https://<ihr-server>/`;
- allen Zugangsdaten oder Informationen, die die Anwendung für Sie erzeugt hat, etwa einen Administrator-Benutzernamen, einen Datenbanknamen oder ein generiertes Passwort.

Während der Installation wird ein kostenloses, automatisch erneuertes [Let's Encrypt](https://letsencrypt.org/de/)-Zertifikat für den Hostnamen Ihres Servers ausgestellt, und die bereitgestellte Anwendung verwaltet dessen Erneuerung selbst.

:::warning
Kopieren Sie Ihre Zugangsdaten sofort. Die Erfolgsseite ist nur während der Kulanzzeit nach einer erfolgreichen Bereitstellung verfügbar (standardmäßig 5 Minuten). Sobald der Konfigurator sich entfernt hat, kann er sie nicht mehr anzeigen — Sie müssten sie dann in der Anwendung selbst abrufen oder den Server neu installieren.
:::

#### Schritt 5: Der Konfigurator entfernt sich

Kurz nach einer erfolgreichen Bereitstellung löscht der Konfigurator seine eigene Binärdatei, seinen Dienst und seine Arbeitsdaten. Ab diesem Zeitpunkt gilt:

- die Oberfläche des Konfigurators auf Port `10143` antwortet nicht mehr — **dies ist das erwartete Verhalten und kein Fehler**;
- Ihre Anwendung, ihre Daten und ihr HTTPS-Zertifikat werden beibehalten;
- auf Ihrem Server läuft nur Ihre Anwendung, ohne verbleibendes Einrichtungswerkzeug und ohne verbleibende Verwaltungsoberfläche.

Sie verfügen über die vollständige Kontrolle über den Server, einschließlich Root-Zugriff über SSH, wenn Sie bei der Installation einen Schlüssel hinzugefügt haben. Der Konfigurator verwaltet ab diesem Zeitpunkt nichts mehr.

:::info
Wenn die Bereitstellung **fehlschlägt**, entfernt sich der Konfigurator *nicht*: Er bleibt verfügbar, damit das Problem anhand der Echtzeit-Protokolle diagnostiziert werden kann. Eine fehlgeschlagene Bereitstellung erfordert in der Regel, den Server neu zu installieren und erneut zu beginnen.
:::

Um eine andere Anwendung bereitzustellen, installieren Sie Ihren Server aus dem Anwendungskatalog neu und wählen Sie die neue Anwendung aus.

### Behebung häufiger Probleme

| Symptom | Ursache | Lösung |
|---|---|---|
| Die Seite des Konfigurators lädt nicht unter `https://<ihr-server>:10143/` | Die Installation ist noch nicht abgeschlossen, oder der eingehende Zugriff auf Port `10143` ist blockiert. | Warten Sie, bis die Installation abgeschlossen ist, und versuchen Sie es erneut. Stellen Sie sicher, dass jede Firewall (einschließlich der OVHcloud [Edge Network Firewall](/guides/bare-metal-cloud/dedicated-servers/firewall-network)) eingehenden Datenverkehr zu Ihrem Server auf Port `10143` zulässt. |
| Die Seite des Konfigurators lädt nach einer erfolgreichen Bereitstellung nicht mehr | Der Konfigurator hat sich wie vorgesehen entfernt. | Dies ist das erwartete Verhalten. Verwenden Sie stattdessen die eigene Adresse Ihrer Anwendung: `https://<ihr-server>/`. |
| `Unauthorized` beim Öffnen des Konfigurators | Das Zugriffstoken fehlt oder ist falsch. | Öffnen Sie den Konfigurator erneut mit genau dem Link und dem Token, die mit Ihrer Installation bereitgestellt wurden. |
| Beim ersten Laden erscheint eine Zertifikatswarnung | Das Let's Encrypt-Zertifikat wurde noch nicht ausgestellt; es wird ein temporäres selbstsigniertes Zertifikat bereitgestellt. | Warten Sie eine Minute und laden Sie die Seite neu. |
| Die Anwendung ist nach der Installation nicht über HTTPS erreichbar | Das Let's Encrypt-Zertifikat konnte nicht ausgestellt werden, in der Regel weil der eingehende Port `80` oder `443` blockiert ist oder der Hostname nicht öffentlich auflöst. | Stellen Sie sicher, dass die Ports `80` und `443` für eingehenden Datenverkehr geöffnet sind und der Hostname Ihres Servers öffentlich auflöst, und installieren Sie den Server bei Bedarf neu. |
| Sie möchten eine zweite Anwendung aus dem Katalog bereitstellen | Über den Katalog kann nur eine Anwendung bereitgestellt werden. | Installieren Sie den Server neu, um eine andere Anwendung bereitzustellen, oder installieren Sie die zusätzliche Anwendung manuell. |
