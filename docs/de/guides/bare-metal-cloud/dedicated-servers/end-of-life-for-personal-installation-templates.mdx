**Dies ist eine wichtige Anleitung. Bitte lesen Sie sie sorgfältig, da Sie künftig betroffen sein können, wenn Sie eine OS-Installation auf einem neuen Dedicated Server oder eine OS-Neuinstallation auf einem bestehenden Dedicated Server anfordern.**

Auch wenn auf dieser Seite die Abschaffung der persönlichen Templates für die OS-Installation auf Dedicated Servern und deren Auswirkungen beschrieben werden, können Sie sicher sein, dass **keine Funktionen verloren gehen**.  
Auch nach der Abschaffung können Sie Betriebssysteme mit **demselben Grad an Anpassung wie bisher** installieren. Darüber hinaus profitieren Kunden, die die API direkt verwenden, von **einem einzigen, vereinfachten API-Aufruf**.

## Ziel

Diese Seite enthält die wichtigsten Informationen zum Plan für die Abschaffung der persönlichen Templates, die für OS-Installationen auf Dedicated Servern verwendet werden. Außerdem finden Sie hier hilfreiche Tipps für Kunden, die die OVHcloud Console oder das Kundencenter von So you Start oder Kimsufi verwenden. Schließlich werden die Vorteile des neuen API-Aufrufs gegenüber dem veralteten API-Aufruf vorgestellt.

## Kontext<a id="context"></a>

OVHcloud entwickelt sich ständig weiter und muss seine Angebote an einen zunehmend resilienten und regulierten Cloud-Markt anpassen. Um diesen neuen Herausforderungen gerecht zu werden, werden die **persönlichen Templates für die OS-Installation auf Dedicated Servern** am **7. Oktober 2025** vollständig abgeschafft.

Mit dieser Funktion konnte eine OS-Installation auf einem Dedicated Server mithilfe eines persönlichen Templates angefordert werden, das die folgenden Elemente enthielt:

- Zu installierendes Betriebssystem
- Partitionierungsschema
- Hardware-RAID-Konfiguration
- Hostname
- Öffentlicher SSH-Schlüssel
- Post-Installationsskript

Um die OS-Installation auf Dedicated Servern sowie die Kommunikation rund um die Migration zu vereinfachen, wurde ein neuer API-Aufruf erstellt: `POST /dedicated/server/{serviceName}/reinstall`. Dieser API-Aufruf ist der Nachfolger der alten Route `POST /dedicated/server/{serviceName}/install/start`. Mit der alten Route konnte eine OS-Installation auf Basis eines OVHcloud Templates **oder eines persönlichen Templates** angefordert werden.

Die alte Route und das Konzept der persönlichen Templates werden abgeschafft. Die neue Route unterstützt nur noch OS-Installationen auf Basis eines OVHcloud Templates. Bitte beachten Sie außerdem, dass der Begriff "OVHcloud Template" schrittweise durch den präziseren Begriff "Betriebssystem" ersetzt wird.

Die Abschaffung der persönlichen Templates erfolgt in 2 Schritten:

### Schritt 1: 17. Juni 2025<a id="step-1"></a>

- Kunden können keine persönlichen Templates mehr **bearbeiten** oder neu **hinzufügen**.
- Kunden mit persönlichen Templates und aktiven Dedicated Server Abonnements erhalten per E-Mail individuelle technische Informationen, die ihnen bei der Migration ihrer persönlichen Templates zum <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>neuen API-Aufruf "/reinstall"</ApiLink> helfen.

### Schritt 2: 7. Oktober 2025<a id="step-2"></a>

- Kunden haben keinen Zugriff mehr auf ihre persönlichen Templates.
- Alle Daten zu persönlichen Templates werden gelöscht.

Bitte beachten Sie, dass Kunden weiterhin über die E-Mail vom 17. Juni 2025 verfügen, die eine auf den Daten ihrer persönlichen Templates basierende technische Dokumentation enthält, um sie bei der Migration zum neuen API-Aufruf zu unterstützen.

## In der praktischen Anwendung <a id="instructions"></a>

Der folgende Abschnitt enthält spezifische Informationen für alle Kunden mit einem Account bei OVHcloud, So you Start oder Kimsufi, je nachdem, ob Sie derzeit die OVHcloud Console oder die API verwenden, um Betriebssysteme auf Ihrem Dedicated Server zu installieren.

### Über die OVHcloud Console oder das Kundencenter von So you Start oder Kimsufi<a id="ux"></a>

Der Assistent `Eines Ihrer Templates installieren` zur Installation eines Betriebssystems auf einem Dedicated Server wurde bereits Mitte April 2025 entfernt. Wenn Sie diesen Assistenten verwendet haben, stehen Ihnen langfristig 3 Möglichkeiten zur Verfügung:

- Weiterhin das Webinterface verwenden (nicht empfohlen, wenn Sie Ihre OS-Installationen automatisieren möchten): Nehmen Sie alle Anpassungen bei jeder Installation manuell im OS-Installationsassistenten vor (ehemals Assistent `Mit einem OVHcloud Template installieren`).
- Ein Skript schreiben, das die API verwendet (am besten für die Automatisierung geeignet, erfordert aber Programmierkenntnisse): Siehe den Abschnitt [OVHcloud, So you Start oder Kimsufi API verwenden](#api) weiter unten.
- Die API-Konsole verwenden (guter Kompromiss): Verwenden Sie den alten API-Aufruf bis zum 17. Juni 2025 und danach den neuen API-Aufruf mit den bereitgestellten Payloads.

Sie können bereits jetzt die Beispiele und Schemata des <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>neuen API-Aufrufs "/reinstall" in der API-Konsole</ApiLink> erkunden und die zugehörige [öffentliche Dokumentation](/guides/bare-metal-cloud/dedicated-servers/api-os-installation) lesen. Nachfolgend finden Sie eine vorübergehende Übergangslösung, die Sie verwenden können, bis Sie am 17. Juni 2025 die Payloads für die neue API-Route per E-Mail erhalten.

#### Übergangslösung für OVHcloud <a id="ux-ovh"></a>

Wie in der [Dokumentation zur OVHcloud API](/guides/manage-and-operate/api/first-steps#verbindung-mit-der-ovhcloud-api) beschrieben, gehen Sie auf der Seite der <ApiLink>OVHcloud API-Konsole</ApiLink> wie folgt vor:

- Klicken Sie oben links auf `Authentication`.
- Wählen Sie `Login with OVHcloud SSO`.
- Geben Sie Ihre OVHcloud Zugangsdaten ein.
- Klicken Sie auf `Authorize`, um API-Aufrufe über die Konsole zu erlauben.

![API](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/login.png)

Führen Sie anschließend den API-Aufruf aus, um eine OS-Installation auf Basis Ihres persönlichen Templates zu starten:

- Wählen Sie `v1`.
- Wählen Sie den Abschnitt `/dedicated/server`.
- Suchen Sie den API-Aufruf `POST /dedicated/server/{serviceName}/install/start` (Sie können den Filter verwenden).
- Geben Sie im Feld `serviceName` den Namen des Dedicated Servers ein, auf dem die Installation erfolgen soll.
- Fügen Sie im Feld `REQUEST BODY` (auch API-Payload genannt) den folgenden JSON-Wert ein (in diesem Beispiel gehen wir davon aus, dass "my-amazing-template" der Name des persönlichen Templates ist, das Sie installieren möchten):

```json
{
  "templateName": "my-amazing-template"
}
```

Wenn Sie Ihre persönlichen Templates und deren Details auflisten möchten, gehen Sie zum Abschnitt `/me` und sehen Sie sich alle `GET` API-Aufrufe unter `/me/installationTemplate` an.

:::danger
**Durch Ausführen des Aufrufs [POST /dedicated/server/\{serviceName\}/install/start](https://api.eu.ovhcloud.com/console/?section=%2Fdedicated%2Fserver&branch=v1#post-/dedicated/server/-serviceName-/install/start) auf einem Dedicated Server werden alle Daten auf diesem Server gelöscht. BITTE VERWENDEN SIE DIESEN API-AUFRUF MIT VORSICHT.**
:::

Klicken Sie dann auf den Button `Execute`, um die OS-Installation zu starten.

![console API](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/screenshot-api-console-workaround.png)

Sie können in der <ManagerLink to="/">OVHcloud Console</ManagerLink> zur Dashboard-Seite des Dedicated Servers zurückkehren, um den Fortschritt der Installation zu verfolgen.

#### Übergangslösungen für So you Start oder Kimsufi <a id="ux-sys-ks"></a>

Öffnen Sie die [API-Konsole von So you Start](https://eu.api.soyoustart.com/console/) oder die [API-Konsole von Kimsufi](https://eu.api.kimsufi.com/console/).

Klicken Sie oben rechts auf `Login` und geben Sie Ihre Zugangsdaten ein. Klicken Sie dann auf den Button `Log in`: Sie sind nun bei der API-Konsole authentifiziert.

- Öffnen Sie den Abschnitt `/dedicated/server`.
- Suchen Sie den API-Aufruf `POST /dedicated/server/{serviceName}/install/start`.
- Geben Sie im Feld `serviceName` den Namen des Dedicated Servers ein, auf dem die Installation erfolgen soll.
- Geben Sie im Feld `templateName` den Namen des persönlichen Templates ein, das Sie installieren möchten.

Wenn Sie Ihre persönlichen Templates und deren Details auflisten möchten, gehen Sie zum Abschnitt `/me` und sehen Sie sich alle `GET` API-Aufrufe unter `/me/installationTemplate` an.

:::danger
**Durch Ausführen des Aufrufs [POST /dedicated/server/\{serviceName\}/install/start](https://eu.api.soyoustart.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) (oder [dieses Aufrufs](https://eu.api.kimsufi.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) für Kimsufi) auf einem Dedicated Server werden alle Daten auf diesem Server gelöscht. BITTE VERWENDEN SIE DIESEN API-AUFRUF MIT VORSICHT.**
:::

Klicken Sie dann auf den Button `Execute`, um die OS-Installation zu starten.

Sie können im [Kundencenter von So you Start](https://eu.soyoustart.com/manager) oder im [Kundencenter von Kimsufi](https://www.kimsufi.com/fr/manager) zur Dashboard-Seite des Dedicated Servers zurückkehren, um den Fortschritt der Installation zu verfolgen.

### OVHcloud, So you Start oder Kimsufi API verwenden <a id="api"></a>

Wenn Sie die APIs von OVHcloud, So you Start oder Kimsufi verwenden, um OS-Installationen auf Basis eines persönlichen Templates zu starten, können Sie den API-Aufruf `POST /dedicated/server/{serviceName}/install/start` bis zum **7. Oktober 2025** weiterhin verwenden.  
Bitte beachten Sie jedoch, dass Sie ab dem **17. Juni 2025** keine persönlichen Templates mehr hinzufügen oder bearbeiten können.

Sie erhalten zwar eine E-Mail mit allen Details zur Migration Ihrer API-Payloads zum <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>neuen API-Aufruf "/reinstall"</ApiLink>, können aber bereits jetzt dessen Beispiele und Schemata in der API-Konsole erkunden (das API-Schema ist für OVHcloud, [So you Start](https://eu.api.soyoustart.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) und [Kimsufi](https://eu.api.kimsufi.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) identisch) und die zugehörige [öffentliche Dokumentation](/guides/bare-metal-cloud/dedicated-servers/api-os-installation) lesen.

Das Ende der persönlichen Templates vereinfacht die OS-Installation auf Dedicated Servern. Der neue API-Aufruf <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>POST /dedicated/server/\{serviceName\}/reinstall</ApiLink> bietet nämlich alle möglichen Anpassungen, die der alte API-Aufruf [POST /dedicated/server/\{serviceName\}/install/start](https://api.eu.ovhcloud.com/console/?section=%2Fdedicated%2Fserver&branch=v1#post-/dedicated/server/-serviceName-/install/start) nicht bieten konnte, ohne zuvor ein persönliches Template unter [/me/installationTemplate](https://api.eu.ovhcloud.com/console/?section=%2Fme&branch=v1#get-/me/installationTemplate) zu definieren.

Der folgende Vergleich veranschaulicht die geringere Anzahl an API-Aufrufen, die für eine komplexe Konfiguration mit Hardware-RAID und benutzerdefinierter Partitionierung erforderlich sind: von `4+n` Aufrufen (wobei `n` die Anzahl der in Ihrem Partitionierungsschema definierten Partitionen ist) auf einen einzigen API-Aufruf.

![Vergleich der API-Aufrufe](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/api-calls-comparison.png)

Wie Sie sehen, wird alles optimiert, und ein aufwendiges Setup entfällt.
