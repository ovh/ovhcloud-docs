## Ziel

Link Aggregation fasst mehrere Netzwerkinterfaces Ihres Servers über das Link Aggregation Control Protocol (LACP) zusammen, das im Standard IEEE 802.3ad definiert ist. Die verfügbare Bandbreite erhöht sich und Ihre Netzwerkverbindungen werden redundant: Wenn eine Verbindung ausfällt, wird der Datenverkehr automatisch auf eine andere verfügbare Verbindung umgeleitet.

Mehrere Anleitungen behandeln Link Aggregation, abhängig von der Serverreihe, dem Betriebssystem und davon, ob die öffentliche Konnektivität erhalten bleibt.

**Diese Anleitung erklärt, wie sich die Standardaggregation und OVHcloud Link Aggregation (OLA) unterscheiden, und verweist Sie auf die Anleitung, die zu Ihrer Konfiguration passt.**

## Voraussetzungen

- Sie verfügen über einen [Dedicated Server](/links/bare-metal/bare-metal), der Link Aggregation unterstützt, beispielsweise aus den Serverreihen **Scale** oder **High Grade** oder einen **Advance** Server der dritten Generation oder neuer
- Sie verfügen über ein Betriebssystem oder einen Hypervisor, der das Aggregationsprotokoll 802.3ad (LACP) unterstützt

## In der praktischen Anwendung

### Welche Interfaces aggregiert werden können

Server der Reihen **Scale** und **High Grade** verfügen über vier Netzwerkinterfaces. In der Standardkonfiguration sind zwei öffentlich und zwei privat (vRack). Beide Aggregationen sind im OVHcloud Netzwerk bereits aktiviert, sodass das Betriebssystem nur noch die entsprechenden Aggregate erstellen muss.

Andere Server, die Link Aggregation unterstützen, verfügen über ein einziges öffentliches und ein einziges privates Interface.

### Einen Aggregationsmodus wählen

[OVHcloud Link Aggregation (OLA)](/guides/bare-metal-cloud/dedicated-servers/ola-enable-manager) ist eine Option, die Sie im OVHcloud Kundencenter aktivieren: Sie fasst alle Interfaces des Servers zu einer einzigen privaten Aggregation zusammen, anstatt die öffentlichen und die privaten Interfaces getrennt zu halten.

|Modus|Öffentliche Konnektivität|
|---|---|
|Standard|Das öffentliche Aggregat oder das einzige öffentliche Interface trägt die öffentliche IP-Adresse|
|OLA|Keine: Die öffentliche IP-Adresse ist nicht mehr erreichbar|

Welche Aggregate die beiden Modi erstellen, hängt von der Anzahl der Interfaces des Servers ab.

**Vier Interfaces, bei den Reihen Scale und High Grade:** Standardmäßig bilden die zwei öffentlichen Interfaces ein Aggregat und die zwei privaten Interfaces ein weiteres. Mit OLA bilden alle vier ein einziges Aggregat für das vRack.

<img className="thumbnail" alt="Schema zum Vergleich der Standardaggregate bei vier Interfaces mit dem einzigen Aggregat unter OLA" src="/images/bare-metal-cloud/dedicated-servers/link-aggregation-overview/four-interfaces.png" loading="lazy" />

**Zwei Interfaces, ein öffentliches und ein privates:** Standardmäßig wird keines der beiden aggregiert. Mit OLA bilden die zwei ein einziges Aggregat für das vRack.

<img className="thumbnail" alt="Schema zum Vergleich der Standardkonfiguration bei zwei Interfaces mit dem einzigen Aggregat unter OLA" src="/images/bare-metal-cloud/dedicated-servers/link-aggregation-overview/two-interfaces.png" loading="lazy" />

:::warning
Ein Server, dessen Interfaces vollständig für das vRack aggregiert sind, verfügt über kein öffentliches Netzwerkinterface mehr und kann daher den Netboot-Dienst von OVHcloud nicht mehr erreichen. Lesen Sie die Anleitung "[Verwaltung des Reboots Ihres Servers mit der Funktion OVHcloud Link Aggregation (EN)](/guides/bare-metal-cloud/dedicated-servers/pxe-with-full-private-dedicated)", bevor Sie OLA aktivieren.

:::

### Die Aggregate während der Installation konfigurieren

Auf **Scale** und **High Grade** Servern kann die Installation die Aggregate für Sie konfigurieren, sodass der Server bereits aggregiert startet.

:::info
Diese Option kann auf jedem Server aktiviert werden, hat aber nur dann eine Auswirkung, wenn der Server über Interfaces verfügt, die aggregiert werden können.

:::

#### Verfügbarkeit je nach Betriebssystem

Die Aggregate werden **immer** konfiguriert und die Option wird **nicht angeboten** bei:

- **Ubuntu Server** 26.04

Die Option wird angeboten und ist **standardmäßig deaktiviert** bei:

- **AlmaLinux**
- **Debian**, außer Debian 11
- **Fedora**
- **Proxmox Virtual Environment** und **Proxmox Backup Server**
- **Rocky Linux**, außer Rocky Linux 8
- **Ubuntu Server** 22.04 und 24.04
- **Windows Server**, außer den Hyper-V Images
- [Bring Your Own Image (BYOI)](/guides/bare-metal-cloud/dedicated-servers/bring-your-own-image) und [Bring Your Own Linux (BYOLinux)](/guides/bare-metal-cloud/dedicated-servers/bring-your-own-linux)

Kein anderes Betriebssystem konfiguriert die Aggregate während der Installation, sodass Sie dies anschließend selbst tun müssen.

#### Die Option aktivieren

- Aktivieren Sie im OVHcloud Kundencenter das entsprechende Kontrollkästchen im Installationsassistenten.
- Setzen Sie über die API die Anpassung `enableLacpBonding`, wie in der Anleitung "[Installation eines Betriebssystems über die OVHcloud API auf einem Dedicated Server (EN)](/guides/bare-metal-cloud/dedicated-servers/api-os-installation)" beschrieben.

Wenn Ihr Betriebssystem die Option bei der Installation nicht anbietet oder wenn Sie die Aggregate lieber anschließend konfigurieren, folgen Sie der Anleitung, die zu Ihrem System passt:

|Debian 9 bis 11, Rescue-Modus und benutzerdefinierte Images mit `ifupdown`|[ifupdown-Konfiguration](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-ifupdown)|
|SLES 15|[SLES 15-Konfiguration](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-sles15)|
|Windows Server 2019 mit OLA|[NIC-Teaming-Konfiguration](/guides/bare-metal-cloud/dedicated-servers/ola-enable-w2k19)|
|Proxmox VE|[Proxmox VE Netzwerk](/guides/bare-metal-cloud/dedicated-servers/proxmox-network-hg-scale)|

### Wie eine Aggregation über die Netzwerkkarten verteilt wird

Auf **Scale** und **High Grade** Servern wird eine Aggregation über zwei verschiedene Netzwerkkarten verteilt, sodass sie den Ausfall einer ganzen Karte übersteht und nicht nur den eines Switches. Weitere Informationen finden Sie in der Anleitung "[Verbesserung der Netzwerkresilienz auf Bare Metal Servern (EN)](/guides/bare-metal-cloud/dedicated-servers/lacp-resilience-scale-hg)".
