## Ziel

Unsere Wartungsinterventionen beschränken sich auf die Hardware Ihres Servers. Nach einer Wartungsintervention können Maßnahmen im Softwarebereich Ihres Servers erforderlich sein.

Diese Anleitung basiert auf Rückmeldungen unserer Teams sowie auf konkreten Anwendungsfällen und listet die erforderlichen Maßnahmen abhängig von Ihrer Installation auf: Betriebssysteme, Hypervisor usw.

Ziel ist es, Sie zu unterstützen und die Auswirkungen auf den Lebenszyklus Ihrer Umgebungen so gering wie möglich zu halten.

## Voraussetzungen

- Sie verfügen über einen [Dedicated Server](/links/bare-metal/bare-metal) in Ihrem Kunden-Account.

<a name="ubuntu"></a>

### Ubuntu/Debian 12+

Wenn Probleme mit der Netzwerkverbindung auftreten (zum Beispiel kein Ping nach einem Austausch des Motherboards), führen Sie die folgenden Schritte aus:

1\. Starten Sie den Server im [Rescue-Modus](/guides/bare-metal-cloud/dedicated-servers/rescue-mode) neu.<br/>
2\. Mounten Sie die Partition `/`:

```bash
root@rescue:~# mount /dev/my_system_disk /mnt
```

Wenn die Datei `70-persistent-net.rules` nicht existiert (siehe den Abschnitt dieser Anleitung zu [den Namen Ihrer Netzwerkinterfaces](#network-interface)), überprüfen Sie die folgenden Dateien im Verzeichnis `/etc/systemd/network/`:

- `50-default.network`
- `50-public-interface.link`

```bash
root@rescue:~# cat /mnt/etc/systemd/network/50-default.network
# This file sets the IP configuration of the primary (public) network device.
# You can also see this as "OSI Layer 3" config.
# It was created by the OVH installer, please be careful with modifications.
# Documentation: man systemd.network or https://www.freedesktop.org/software/systemd/man/systemd.network.html
 
[Match]
MACAddress=xx:xx:xx:xx:xx:xx
 
[Network]
Description=network interface on public network, with default route
DHCP=no
Address=1.2.3.4/24
Gateway=1.2.3.254
IPv6AcceptRA=no
NTP=ntp.ovh.net
DNS=127.0.0.1
DNS=213.186.33.99
DNS=2001:41d0:3:163::1
Gateway=2001:41d0:0203:4bff:ff:ff:ff:ff
 
[Address]
Address=2001:41d0:0203:1234::/64
 
[Route]
Destination=2001:41d0:0203:4bff:ff:ff:ff:ff:ff
Scope=link
root@rescue:~#
root@rescue:~# cat /mnt/etc/systemd/network/50-public-interface.link
# This file configures the relation between network device and device name.
# You can also see this as "OSI Layer 2" config.
# It was created by the OVH installer, please be careful with modifications.
# Documentation: man systemd.link or https://www.freedesktop.org/software/systemd/man/systemd.link.html
 
[Match]
MACAddress=xx:xx:xx:xx:xx:xx
 
[Link]
Description=network interface on public network, with default route
MACAddressPolicy=persistent
NamePolicy=kernel database onboard slot path mac
#Name=eth2    # name under which this interface is known under OVH rescue system
#Name=eno3    # name under which this interface is probably known by systemd
root@rescue:~#
```

3\. Sichern Sie die Dateien und bearbeiten Sie sie, um den neuen Wert Ihrer MAC-Adresse einzutragen:

```bash
root@rescue:~# cp /mnt/etc/systemd/network/50-default.network /mnt/etc/systemd/network/50-default.network.link.bak-`date +%s`
root@rescue:~# cp /mnt/etc/systemd/network/50-public-interface.link /mnt/etc/systemd/network/50-public-interface.link.bak-`date +%s`
root@rescue:~# nano /mnt/etc/systemd/network/50-default.network
root@rescue:~# cat /mnt/etc/systemd/network/50-default.network | grep MACAddress
MACAddress=xx:xx:xx:xx:xx:xx
root@rescue:~#
root@rescue:~# nano /mnt/etc/systemd/network/50-public-interface.link
root@rescue:~#
root@rescue:~# cat /mnt/etc/systemd/network/50-public-interface.link | grep MACAddress
MACAddress=xx:xx:xx:xx:xx:xx
root@rescue:~#
```

4\. Hängen Sie die Partition `/` aus, bevor Sie den Server neu starten.

#### Sonderfälle

In einigen Fällen muss die neue MAC-Adresse in die folgenden Dateien übernommen werden:

- `/mnt/etc/netplan/01-netcfg.yaml`
- `/mnt/etc/netplan/50-cloud-init.yaml`
- `/mnt/etc/systemd/network/10-eno1.link`
- `/mnt/etc/systemd/network/10-eno1.network`

<a name="centos-almalinux"></a>

### CentOS/Alma Linux

Wenn Probleme mit der Netzwerkverbindung auftreten (zum Beispiel kein Ping nach einem Austausch des Motherboards), führen Sie die folgenden Schritte aus:

1\. Starten Sie den Server im [Rescue-Modus](/guides/bare-metal-cloud/dedicated-servers/rescue-mode) neu.<br/>
2\. Mounten Sie die Partition `/`:

```bash
root@rescue:~# mount /dev/my_system_disk /mnt
```

3\. Überprüfen Sie die Konfigurationsdatei `/mnt/etc/sysconfig/network-scripts/ifcfg-eth0`.

4\. Sichern Sie die Dateien und bearbeiten Sie sie, um die MAC-Adresse zu korrigieren:

```bash
root@rescue:~# cp /mnt/etc/sysconfig/network-scripts/ifcfg-eth0 /mnt/etc/sysconfig/network-scripts/ifcfg-eth0.`date +%s`
```

5\. Tragen Sie die neue MAC-Adresse in der Zeile `HWADDR=xx:xx:xx:xx:xx:xx` ein.

6\. Denken Sie daran, die Partition `/` auszuhängen, bevor Sie den Server neu starten.

<a name="smartos"></a>

### SmartOS

Wenn Probleme mit der Netzwerkverbindung auftreten (zum Beispiel kein Ping nach einem Austausch des Motherboards), führen Sie die folgenden Schritte aus:

1\. Starten Sie den Server im [Rescue-Modus](/guides/bare-metal-cloud/dedicated-servers/rescue-mode) neu.<br/>

```bash 
modprobe zfs
root@rescue:~# zpool import -f zones (zpool import to list the pools)
root@rescue:~# zfs set mountpoint=/mnt zones/usbkey
root@rescue:~# zfs mount zones/usbkey
root@rescue:~# cp /mnt/config {,.bak-$(date +"%Y-%m-%d-%H_%M")}
```

2\. Tragen Sie die neue MAC-Adresse in der Zeile `admin_nic` ein:

```bash
root@rescue:~#  vim /mnt/config
```

3\. Vergessen Sie nicht, die Partitionen auszuhängen, bevor Sie den Server im `netboot`-Modus neu starten:

```bash
root@rescue:~# zfs umount -a
root@rescue:~# zfs set mountpoint=`/usbkey` zones/usbkey 
```

Wenn Probleme mit der Netzwerkverbindung auftreten (zum Beispiel kein Ping nach einem Austausch des Motherboards), kann dies an einem Fehler beim Systemstart liegen, der durch den noch vorhandenen alten Wert der MAC-Adresse verursacht wird:

```bash
Aug  8 14:27:20 s22 kernel: [    1.550622] igb 0000:04:00.1 eno2: renamed from eth1

Aug  8 14:27:36 s22 kernel: [   90.444727] eth0: renamed from vethVMV0MH
```

2\. Erstellen Sie die Datei `70-persistent-net.rules` neu und fügen Sie Folgendes hinzu:

```bash
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", NAME="enp3s0f0"
root@rescue:~#
```

<a name="xenserver"></a>

### XenServer

Wenn Probleme mit der Netzwerkverbindung auftreten (zum Beispiel kein Ping nach einem Austausch des Motherboards), ist die MAC-Adresse statisch konfiguriert und muss zurückgesetzt werden.

Gehen Sie wie folgt vor:

1\. Starten Sie den Server im [Rescue-Modus](/guides/bare-metal-cloud/dedicated-servers/rescue-mode) neu und verwenden Sie den Befehl `chroot`:

```bash
root@rescue:~# mount /dev/sda1 /mnt
root@rescue:~# mount -t proc /proc/ /mnt/proc/
root@rescue:~# mount -o bind /sys/ /mnt/sys/
root@rescue:~# mount -o bind /dev/ /mnt/dev/
root@rescue:~# mount -o bind /dev/pts/ /mnt/dev/pts/
root@rescue:~# chroot /mnt
```

2\. Ändern Sie die aktuelle Konfiguration, sodass sie den neuen Einstellungen entspricht:

```bash
[root@rescue /]# xe-reset-networking --device=eth0 --mode=static --ip=xx.xx.xx.xx --netmask=255.255.255.0 --gateway=xx.xx.xx.xxx
```

3\. Sie werden aufgefordert, die Frage mit `yes` zu beantworten. Drücken Sie anschließend die Eingabetaste:

```bash
----------------------------------------------------------------------
!! WARNING !!
  
This command will reboot the host and reset its network configuration.
Any running VMs will be forcefully shutdown.
  
Before completing this command:
- Where possible, cleanly shutdown all VMs running on this host.
```

<a name="esxi"></a>

### ESXi

Nach dem Austausch eines Motherboards können Sie die neuen MAC-Adressen nicht mit den im Rescue-Modus integrierten Tools über die Datei `esxi.conf` ändern.
Dies erfordert einen manuellen Eingriff.

#### Version 7.0 oder höher

Die folgende Vorgehensweise gilt nur für **Versionen 7.0 und höher**. Ab dieser Version ist die Datei state.tgz verschlüsselt.
Sie müssen das Netzwerk über das Menü Direct Console mithilfe Ihres KVM oder IPMI zurücksetzen.

Siehe folgenden Screenshot:

<img className="thumbnail" alt="reset_network" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/restore.png" loading="lazy" />

#### Version 6.7 oder älter

Die im Folgenden beschriebene Vorgehensweise gilt nur für **Versionen 6.7 und älter**.

1\. Starten Sie den Server im [Rescue-Modus](/guides/bare-metal-cloud/dedicated-servers/rescue-mode) neu, um die Partition `/` zu mounten:

```bash
root@rescue:~# mount /dev/sdaX /mnt/
```

2\. Sichern Sie die Datei `state.tgz`

```bash
root@rescue:~# ls /mnt/state.tgz
root@rescue:~# cp /mnt/state.tgz /mnt/state.tgz.`date +%s`
```

3\. Erstellen Sie eine Arbeitsumgebung:

```bash
root@rescue:~# mkdir /home/ovh/esxi
root@rescue:~# WORKINGDIR=/home/ovh/esxi
root@rescue:~# cd $WORKINGDIR
```

4\. Extrahieren Sie den Inhalt von `state.tgz` nach `$WORKINGDIR` und extrahieren Sie anschließend den Inhalt von `local.tgz`.<br/>
5\. Bearbeiten Sie die erhaltene Datei `esx.conf`:

```bash
root@rescue:/home/ovh/esxi# tar xf /mnt/state.tgz -C $WORKINGDIR
root@rescue:/home/ovh/esxi# tar xf /home/ovh/esxi/local.tgz -C $WORKINGDIR
root@rescue:/home/ovh/esxi# vim etc/vmware/esx.conf
```
6\. Ermitteln und ändern Sie die MAC-Adresse für `vmkernelnic`:

```bash
/net/vmkernelnic/child[0000]/mac = "XX:XX:XX:XX:XX:XX"
```

7\. Ermitteln Sie, auf welchem Interface die primäre IP-Adresse verwendet wird:

```bash
/net/vswitch/child[0000]/uplinks/child[0000]/pnic = "vmnicX"
```

8\. Aktualisieren Sie die MAC-Adresse des Hauptinterfaces:

:::warning
Ändern Sie nicht die virtuelle MAC-Adresse.

:::


```bash
/net/pnic/child[0001]/mac = "XX:XX:XX:XX:XX:XX"         <== Primary Interface Mac address
/net/pnic/child[0001]/virtualMac = "00:50:56:XX:XX:XX"  <== Virtual Mac
/net/pnic/child[0001]/name = "vmnic1"
```

:::warning
Wenn ein vRack-Interface vorhanden ist, denken Sie daran, auch dessen MAC-Adresse zu ändern.

:::


9\. Erstellen Sie ein Backup und hängen Sie anschließend die Partition `/` aus:

```bash
root@rescue:/home/ovh/esxi# tar -czf $WORKINGDIR/local.tgz etc/
root@rescue:/home/ovh/esxi# tar -czf /mnt/state.tgz local.tgz
root@rescue:/home/ovh/esxi# umount /mnt
```

#### Sonderfälle

Überprüfen Sie die Reihenfolge Ihrer vmnicX-Deklarationen. Hier ein funktionierendes Beispiel:

```bash
root@rescue:/home/ovh/esxi# cat etc/vmware/esx.conf | grep "/vmkdevmgr/pci"
/vmkdevmgr/pci/m00008901/alias = "vmhba0"
/vmkdevmgr/pci/m00008501/alias = "vmnic0"
/vmkdevmgr/pci/m00008502/alias = "vmnic1"
```

<a name="windows"></a>

### Windows (Hyper-V)

Nach dem Austausch des Motherboards ist der Server erst wieder erreichbar, wenn Sie die MAC-Adressen manuell über den **Geräte-Manager** geändert haben.

Es gibt 2 Methoden:

#### Über IPMI/KVM

1\. Melden Sie sich über das [IPMI/KVM](/guides/bare-metal-cloud/dedicated-servers/ipmi)-Interface als Administrator an.<br/>
2\. Öffnen Sie das Dienstprogramm <code className="action">Ausführen</code> (Windows-Logo-Taste + <code className="action">R</code>) und führen Sie über die Eingabeaufforderung `run` den Befehl `devmgmt.msc` aus:

<img className="thumbnail" alt="win_device_manager" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_device_manager_edited.png" loading="lazy" />

3\. Öffnen Sie <code className="action">Network adapters</code> und wählen Sie den Adapter aus, der `eth0` entspricht.<br/>
4\. Klicken Sie mit der rechten Maustaste auf <code className="action">Properties</code> > <code className="action">Advanced</code>.<br/>
5\. Suchen Sie `Locally Administered Address`.<br/>
6\. Geben Sie den neuen Wert der MAC-Adresse ein (nur Ziffern, ohne Leerzeichen).

<img className="thumbnail" alt="win_advanced" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_advanced_edited.png" loading="lazy" />

#### Über WinPE

1\. Starten Sie den Server im `WinPE`-Modus neu.<br/>
2\. Führen Sie den Befehl `regedit` über die Eingabeaufforderung `run` aus.<br/>
3\. Laden Sie die lokale Registry über die in `WinPE` verfügbare Registry und klicken Sie dann auf <code className="action">HKEY_LOCAL_MACHINE</code>:

<img className="thumbnail" alt="win_regedit_1" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_1_edited.png" loading="lazy" />

4\. Klicken Sie anschließend auf <code className="action">Load Hive...</code>.

<img className="thumbnail" alt="win_regedit_2" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_2_edited.png" loading="lazy" />

:::info
Standardmäßig befinden Sie sich in der Verzeichnisstruktur von WinPE.
Vergessen Sie nicht, zum Laufwerk `C:\` zu wechseln.

:::


5\. Suchen Sie die Registry `SYSTEM`.

<img className="thumbnail" alt="win_load" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_load_edited.png" loading="lazy" />

6\. Sie werden aufgefordert, einen Namen einzugeben. Sie können zum Beispiel `OVH_TEST` wählen.

7\. Suchen Sie den folgenden Registry-Wert:

```bash
"HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Class\{4D36E972-E325-11CE-BFC1-08002BE10318}"
```

:::warning
Solange wir uns in WinPE befinden, sollte der Wert `CurrentControlSet` gleich `CurrentSet001` sein.

:::


Es sollten mehrere Unterschlüssel mit Namen wie diesen angezeigt werden: 0000, 0001 usw.

8\. Klicken Sie auf jeden Unterschlüssel, um den Wert `DriverDesc` zu überprüfen, der Ihrem Netzwerkinterface entsprechen sollte.
Sie können den Namen Ihres Interfaces in einem Terminal mit folgendem Befehl überprüfen:

```bash
ipconfig /all
```

9\. Suchen Sie im rechten Bereich nach den Registry-Einträgen `NetworkAddress` und ersetzen Sie den Wert durch Ihre neue MAC-Adresse. Wenn dieser Eintrag nicht existiert, klicken Sie mit der rechten Maustaste in einen leeren Bereich, um einen Wert vom Typ `String` mit dem Namen `NetworkAddress` zu erstellen.

<img className="thumbnail" alt="win_regedit_3" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_3_edited.png" loading="lazy" />

10\. Um die letzten Änderungen anzuwenden, müssen Sie die Registry entladen. Klicken Sie auf OVH_TEST (zuvor erstellt), klicken Sie dann auf <code className="action">File</code> (oben links) und wählen Sie <code className="action">Unload hive...</code>.

<a name="network-interface"></a>

### Namen Ihrer Netzwerkinterfaces ermitteln

Nach dem Austausch des Motherboards ist der Server nicht erreichbar, da der Controller der Netzwerkinterfaces vom Betriebssystem umbenannt wurde.

1\. Starten Sie den Server im [Rescue-Modus](/guides/bare-metal-cloud/dedicated-servers/rescue-mode) neu, mounten Sie die Partition `/` und verwenden Sie anschließend den Befehl `chroot`:

```bash
root@rescue:~# mount /dev/my_disk /mnt
root@rescue:~# for i in /dev /dev/pts /proc /sys; do mount -B $i /mnt$i; done
root@rescue:~# chroot /mnt
```

2\. Überprüfen Sie, ob die Interfaces geändert wurden. Prüfen Sie in den Logs `var/log/messages` oder `var/log/kern.log`, ob das Interface umbenannt wurde:

```bash
Oct  9 22:25:49 node1 kernel: [    5.479916] ixgbe 0000:03:00.1 eno4: renamed from eth1
Oct  9 22:25:49 node1 kernel: [    5.504285] ixgbe 0000:03:00.0 eno3: renamed from eth0
```

3\. Überprüfen Sie Ihre Konfigurationsdatei `/mnt/etc/udev/rules.d/70-persistent.-net.rules` und ersetzen Sie gegebenenfalls die Werte durch die neuen (MAC-Adressen):

```bash
root@rescue:~# cat /mnt/etc/udev/rules.d/70-persistent-net.rules
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", ATTR{dev_id}=="0x0", ATTR{type}=="1", KERNEL=="eth*", NAME="public"
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", ATTR{dev_id}=="0x0", ATTR{type}=="1", KERNEL=="eth*", NAME="private"
```

4\. Wechseln Sie in das Verzeichnis `/boot/grub/` und erstellen Sie ein Backup der Datei `grub.cfg`.<br/>
5\. Bearbeiten Sie die Datei `/etc/default/grub` und ändern Sie die Zeile, die mit `GRUB_CMDLINE_LINUX` beginnt, wie folgt:

```bash
GRUB_CMDLINE_LINUX="net.ifnames=0 biosdevname=0"
```

6\. Führen Sie den folgenden Befehl aus:

```bash
root@rescue:~# grub-mkconfig -o /boot/grub/grub.cfg
```

7\. Verlassen Sie die `chroot`-Umgebung mit dem Befehl `exit` und hängen Sie alle Partitionen aus:

```bash
root@rescue:~# umount /mnt/sys
root@rescue:~# umount /mnt/proc
root@rescue:~# umount /mnt/dev/pts
root@rescue:~# umount /mnt/dev
root@rescue:~# umount /mnt
```

1\. Starten Sie den Server im [Rescue-Modus](/guides/bare-metal-cloud/dedicated-servers/rescue-mode) neu.<br/>

#### Über das BIOS

- Anwendungsfall: Das installierte System (hier CentOS 6) ist nach dem Austausch der Festplatte nicht mehr bootfähig (im BIOS ist kein EFI-Eintrag sichtbar).

1\. Starten Sie den Server neu, um das BIOS-Menü aufzurufen.

Im *ersten Schritt* werden die Dateien neu generiert, die erforderlich sind, damit Ihre Partition wieder voll funktionsfähig ist:

- Öffnen Sie im BIOS das Menü `boot`:
    - Wählen Sie <code className="action">Add New Boot Option</code>.
    - Wählen Sie unter <code className="action">Path for boot option</code> den Pfad zu Ihrer Partition und das Dateisystem aus, das Ihre Bootpartition enthält.
    - Wählen Sie die Datei `EFI\centos6\bootx64.efi` aus und klicken Sie auf <code className="action">Create</code>.
