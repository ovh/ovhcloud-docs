## Ziel

RAID (Redundant Array of Independent Disks) ist eine Kombination von Techniken, die Datenverluste auf einem Server reduzieren, indem Daten auf mehreren Disks repliziert werden.

Der Standard-RAID-Level der OVHcloud Server ist RAID 1. Dieser verdoppelt das Volumen Ihrer Daten und reduziert so den verfügbaren Speicherplatz.

**Diese Anleitung erklärt, wie Sie die Disks Ihres Servers im RAID 0 Modus konfigurieren, um den maximal nutzbaren Speicherplatz zu verwenden.**

:::warning
Achtung: RAID 0 bietet weder **Fehlertoleranz** noch **Datenredundanz**. Dadurch ist es sehr wahrscheinlich, dass bei einem Ausfall Daten verloren gehen.

:::


## Voraussetzungen

- Sie haben einen [Dedicated Server](/links/bare-metal/bare-metal) mit Hardware-RAID.
- Sie haben administrativen Zugriff (sudo) auf Ihren Server über SSH

## In der praktischen Anwendung

### Die OVHcloud Console verwenden

Klicken Sie im Tab <code className="action">Übersicht</code> Ihres Servers im Bereich **Allgemeine Informationen** in der Zeile **Betriebssystem** auf <code className="action">Neu installieren</code> (<code className="action">Installieren</code> bei einem Server ohne Betriebssystem; die Seite trägt dann den Titel **OS-Installation**). Die Seite **OS-Installation / -Neuinstallation** wird geöffnet.

Wählen Sie im Schritt **Betriebssystem** das gewünschte Betriebssystem in den Drop-down-Listen **Kategorie** und **Betriebssystem** aus.

Setzen Sie einen Haken bei <code className="action">Hardware-RAID konfigurieren</code> und <code className="action">Partitionskonfiguration anpassen</code> und klicken Sie dann auf <code className="action">Weiter</code>. Die Option <code className="action">Hardware-RAID konfigurieren</code> wird nur angeboten, wenn die ausgewählte Festplattengruppe über einen Hardware-RAID-Controller verfügt. Wenn Ihr Server mehrere Festplattengruppen hat, wählen Sie zuerst unter **Wählen Sie die Festplattengruppe, auf der das OS installiert wird** die Gruppe mit dem Hardware-RAID-Controller aus. Andernfalls ist die Option ausgegraut.

Wählen Sie im Schritt **Hardware-RAID** in der Drop-down-Liste **RAID-Modus** den Eintrag <code className="action">RAID 0</code> aus. Die **Anzahl der zu konfigurierenden Datenträger** ist auf alle Festplatten der Gruppe voreingestellt: Behalten Sie diesen Wert bei, um deren gesamte Kapazität zu nutzen. Bei RAID 0 ist die **Anzahl der Arrays** fest auf 1 gesetzt. Klicken Sie auf <code className="action">Weiter</code>.

Konfigurieren Sie im Schritt **Partitionen** die Partitionen nach Bedarf und klicken Sie dann auf <code className="action">Weiter</code>. Füllen Sie den Schritt **Optionen** nach Bedarf aus und klicken Sie auf <code className="action">Weiter</code>.

Setzen Sie abschließend im Schritt **Zusammenfassung** einen Haken bei <code className="action">Ich verstehe, dass alle Daten auf den Festplatten dauerhaft gelöscht werden.</code> und klicken Sie auf <code className="action">Installieren</code>.

Überprüfen Sie nach der Installation Ihres Servers die Größe der Partitionen, indem Sie sich via SSH mit dem Server verbinden und folgenden Befehl ausführen:

```sh
df -h
```

### Rescue-Modus verwenden

Klicken Sie im Tab <code className="action">Übersicht</code> Ihres Servers im Bereich **Allgemeine Informationen** in der Zeile **Boot Mode** auf <code className="action">Rescue-Modus</code>. Der Tab **Server** öffnet sich bei der Einstellung **Boot mode** im Bereich **System**.

Wählen Sie die Option <code className="action">Rescue mode</code> aus und wählen Sie dann in der Drop-down-Liste **Rescue kernel** den Eintrag <code className="action">Customer rescue system (Debian-12-based)</code> aus. Wählen Sie unter **Authentication method** die Option <code className="action">Password</code> aus, um die Zugangsdaten per E-Mail zu erhalten.

Geben Sie im Feld **Rescue email** eine alternative E-Mail-Adresse an, wenn Sie nicht möchten, dass die Zugangsdaten an die Hauptadresse Ihres Kunden-Accounts gesendet werden.

Klicken Sie auf <code className="action">Apply</code>. Überprüfen Sie im Fenster **Apply boot mode change** den aktuellen und den neuen Boot-Modus und klicken Sie dann auf <code className="action">Apply</code>.

Starten Sie den Server nach Abschluss der Änderung neu, damit er im Rescue-Modus startet: Klicken Sie im Fenster **Reboot to apply** auf <code className="action">Reboot now</code>. Wenn Sie den Neustart später durchführen, klicken Sie in der Zeile **Boot Mode** des Bereichs **Allgemeine Informationen** (Tab **Übersicht**) auf den Link <code className="action">Neu starten</code> und anschließend im Bestätigungsfenster auf <code className="action">Reboot</code>.

Sobald Ihr Server neu gestartet wurde, loggen Sie sich via SSH mit den Zugangsdaten für den Rescue-Modus ein, die Ihnen per E-Mail zugesendet wurden.

Geben Sie in der Kommandozeile die folgenden Befehle ein, um die bestehenden RAID-Einstellungen zu löschen. Alle Daten im RAID werden gelöscht:

```sh
MegaCli -CfgLdDel -L0 -a0
MegaCli -CfgLdDel -Lall -aAll
```

Geben Sie folgenden Befehl ein, um die Slot- und Geräte-IDs Ihrer Festplatten abzurufen:

```sh
MegaCli -PdList -aALL | egrep "Slot|Device ID"
```

Geben Sie folgenden Befehl ein, um RAID 0 zu konfigurieren:

```sh
MegaCli -CfgLDAdd -R0[252:0,252:1] -a0
```

In diesem Beispiel ist 252 die ID des Festplattengehäuses.

Nachdem Sie den neuen RAID-Level festgelegt haben, können Sie die Einstellungen mit folgendem Befehl überprüfen:

```sh
MegaCli -LDInfo -Lall -a0 | grep -i size
```
