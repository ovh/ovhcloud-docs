## Ziel

Windows Server ist ein unterstütztes Betriebssystem auf OVHcloud Dedicated Servern. Nach der Installation müssen Sie das Windows-System so konfigurieren, dass es die an den Server angebundenen Netzwerk- und Speicherdienste von OVHcloud nutzen kann.

Diese Anleitung führt Sie durch die Installation von Windows Server über das OVHcloud Kundencenter, den Verbindungsaufbau und die anschließend erforderliche Konfiguration innerhalb von Windows, um mit den wichtigsten an einen Dedicated Server angebundenen OVHcloud Diensten zu interagieren.

**In dieser Anleitung lernen Sie, wie Sie:**

- Windows Server über das Kundencenter installieren
- sich per Remotedesktop mit dem Server verbinden und die Ersteinrichtung abschließen
- Windows für die Nutzung einer Additional IP konfigurieren
- Windows für die Nutzung des privaten vRack-Netzwerks konfigurieren
- Windows für die Nutzung des mit dem Server gelieferten IPv6-Blocks konfigurieren
- vom Windows-System aus auf OVHcloud Backup Storage zugreifen
- den Server mit verwalteten Backups über den OVHcloud Backup Agent schützen

:::warning
Bei der Neuinstallation eines Betriebssystems werden alle Daten auf den Festplatten des Servers gelöscht. Sichern Sie alle Daten, die Sie behalten möchten, bevor Sie beginnen.
:::

## Voraussetzungen

- Sie verfügen über einen [Dedicated Server](/links/bare-metal/bare-metal) in Ihrem OVHcloud Account.
- Sie besitzen eine gültige Windows Server Lizenz. Lizenzen können über OVHcloud bestellt oder von einem externen Wiederverkäufer übernommen werden – weitere Informationen finden Sie in der Anleitung [Verwaltung Ihrer OVHcloud Lizenzen](/guides/bare-metal-cloud/dedicated-servers/windows-key).
- Sie verfügen auf Ihrem lokalen Rechner über einen RDP-Client (Remote Desktop Protocol) (der Client <code className="action">Remotedesktopverbindung</code> ist in Windows enthalten).

## Einführung

Ein Dedicated Server ist ein physischer ("Bare Metal") Server, der in einem OVHcloud Rechenzentrum gehostet wird. OVHcloud stellt die Hardware, die öffentliche Netzwerkanbindung, ein optionales privates vRack-Netzwerk sowie einen kostenlosen Backup Storage-Speicherplatz bereit. Sie sind für die Administration des auf dem Server installierten Betriebssystems verantwortlich, einschließlich der gesamten Netzwerk- und Speicherkonfiguration innerhalb von Windows.

Die Dienste, mit denen ein Windows Dedicated Server üblicherweise interagiert, sind im Folgenden zusammengefasst.

| OVHcloud Dienst | Zweck | Aktivierung |
|---|---|---|
| Additional IP | Zusätzliche öffentliche IP-Adressen, die an den Server gebunden sind | Kundencenter – Menü <code className="action">Network</code>, Bereich <code className="action">IP</code> |
| vRack | Privates Layer-2-Netzwerk zwischen OVHcloud Diensten | Kundencenter – Menü <code className="action">Network</code>, Bereich <code className="action">vRack</code> |
| IPv6 | Der mit jedem Server gelieferte /64-IPv6-Block | Automatisch bereitgestellt |
| Backup Storage | Kostenloser FTP-/CIFS- (SMB)/NFS-Backup-Speicher | Kundencenter – <ManagerLink to="/#/dedicated-servers/server">Dedicated Server</ManagerLink> > Wählen Sie Ihren Server aus, Tab <code className="action">Storage-Backup</code> |
| Backup Agent | Verwaltete tägliche Backups in einem isolierten, unveränderlichen Object Storage-Tresor | Kundencenter – <ManagerLink to="/#/dedicated-servers/server">Dedicated Server</ManagerLink> > Wählen Sie Ihren Server aus, Tab <code className="action">Allgemeine Informationen</code>, Bereich <code className="action">Status der Dienste</code> |

### Schritt 1 — Windows Server über das Kundencenter installieren <a name="install"></a>

In diesem Schritt wird Windows Server auf Ihrem Dedicated Server installiert (oder neu installiert). Die Installation erfolgt vollständig über das Kundencenter.

Öffnen Sie im Tab <code className="action">Allgemeine Informationen</code> neben <code className="action">Betriebssystem (OS)</code> das Aktionsmenü und klicken Sie auf <code className="action">Meinen Server neu installieren</code>. Das Fenster <code className="action">Installation mit einem OVHcloud Template</code> öffnet sich und führt Sie durch 4 Schritte.

:::info
Windows Server erfordert eine Lizenz, für die zusätzliche Kosten anfallen. Ohne eine dem Server zugeordnete Windows Server Lizenz werden die Windows-Templates nicht in der Liste der Betriebssysteme angeboten. Sie können eine Lizenz über OVHcloud bestellen oder Ihre eigene verwenden. Verwalten Sie Ihre Lizenzen unter **Bare Metal Cloud** > **Lizenzen**. Weitere Informationen finden Sie in der Anleitung [Verwaltung Ihrer OVHcloud Lizenzen](/guides/bare-metal-cloud/dedicated-servers/windows-key).
:::

:::warning
Diese Aktion ist unwiderruflich. Alle Daten auf den Festplatten werden endgültig gelöscht.
:::

1. **Betriebssystemtyp** — Legen Sie den <code className="action">Betriebssystemtyp</code> fest und wählen Sie das gewünschte Windows Server Template aus. Die Templates sind nach Kategorie gruppiert (Linux, Windows usw.). Die Windows-Templates werden nur angezeigt, wenn Ihrem Dedicated Server eine Windows Server Lizenz zugeordnet ist (siehe Hinweis oben).
2. **Ziel-Festplattenpool(s)** — Wählen Sie den <code className="action">Ziel-Festplattenpool(s)</code> aus, auf dem Windows installiert wird. Um Ihr eigenes RAID-Array oder Partitionslayout festzulegen, aktivieren Sie <code className="action">Hardware-RAID-Konfiguration anpassen</code> oder <code className="action">Konfiguration der Partitionen anpassen</code>. Details zu Soft-RAID unter Windows finden Sie in der Anleitung [Software-RAID auf einem Windows-Server konfigurieren](/guides/bare-metal-cloud/dedicated-servers/raid-soft-windows).
3. Klicken Sie auf <code className="action">Weiter</code> und folgen Sie den übrigen Schritten des Assistenten, um Ihre Auswahl zu überprüfen. Bestätigen Sie anschließend, um die Installation zu starten.

Der Server startet in das Installationsprogramm neu und der Vorgang wird automatisch abgeschlossen.

### Schritt 2 — Mit dem Server verbinden <a name="connect"></a>

Sobald die Installation abgeschlossen ist, sendet OVHcloud eine E-Mail mit dem Benutzernamen und dem Passwort des Administrators für Ihren Windows-Server.

Öffnen Sie auf Ihrem lokalen Windows-Rechner den Client <code className="action">Remotedesktopverbindung</code>. Geben Sie die IPv4-Adresse Ihres Servers und anschließend Ihren Benutzernamen und Ihr Passwort ein. Beim ersten Verbindungsaufbau erscheint in der Regel eine Zertifikatswarnung — klicken Sie auf <code className="action">Ja</code>, um fortzufahren.
Wenn auf Ihrem lokalen Gerät kein Windows läuft, können Sie einen beliebigen RDP-kompatiblen Client eines Drittanbieters verwenden.

:::tip
Falls RDP nicht verfügbar ist — beispielsweise nach einer fehlerhaften Netzwerkkonfiguration — verbinden Sie sich über die [IPMI-Konsole (Intelligent Platform Management Interface)](/guides/bare-metal-cloud/dedicated-servers/ipmi) über den Tab <code className="action">IPMI / KVM</code> im Kundencenter. Die IPMI-Konsole funktioniert unabhängig vom Konnektivitätsstatus des Betriebssystems.
:::

Ändern Sie nach Ihrer ersten Verbindung das Administrator-Passwort innerhalb von Windows (drücken Sie in der RDP-Sitzung `Strg` + `Alt` + `Ende` > <code className="action">Kennwort ändern</code>).

### Schritt 3 — Die Ersteinrichtung von Windows abschließen <a name="initial-config"></a>

Bevor Sie den Server mit anderen OVHcloud Diensten verbinden, schließen Sie die grundlegende Windows-Einrichtung ab.

- Führen Sie Windows Update aus und installieren Sie die neuesten Updates.
- Legen Sie den Hostnamen des Servers, die Zeitzone und das Tastaturlayout fest.
- Konfigurieren Sie die Windows-Firewall so, dass die Dienste zugelassen werden, die Sie ausführen möchten. Eine Windows-spezifische Anleitung zur Firewall finden Sie in der Anleitung [Firewall auf einem Windows-Server aktivieren](/guides/bare-metal-cloud/dedicated-servers/activate-port-firewall-soft-win).

:::warning
OVHcloud stellt Ihnen Dienste zur Verfügung, für deren Konfiguration und Verwaltung Sie selbst verantwortlich sind. Falls Sie Unterstützung benötigen, wenden Sie sich an einen [spezialisierten Dienstleister](/links/partner).
:::

### Schritt 4 — Windows für die Interaktion mit OVHcloud Diensten konfigurieren <a name="services"></a>

Dieser Abschnitt behandelt die Konfiguration innerhalb von Windows für die OVHcloud Dienste, die am häufigsten an einen Dedicated Server angebunden sind. Jeder Unterabschnitt ist eigenständig — folgen Sie nur den für Ihre Einrichtung relevanten Abschnitten. In jedem Abschnitt erfolgt der erste Teil im OVHcloud Kundencenter und der zweite Teil innerhalb von Windows Server.

#### 4a — Additional IP

Eine Additional IP ist eine zusätzliche öffentliche IP-Adresse, die zu Ihrem Server geroutet wird. Nach der Bestellung müssen Sie sie innerhalb von Windows deklarieren, damit der Server auf dieser Adresse antwortet.

**Im OVHcloud Kundencenter**

Bestellen Sie die Additional IP im Menü <code className="action">Network</code> des Kundencenters, im Bereich <code className="action">IP</code>: Klicken Sie auf <code className="action">IP-Adressen bestellen</code>. Weitere Informationen finden Sie auf der Seite [Additional IP](/links/bare-metal/ip).

**In Windows Server**

1. Öffnen Sie <code className="action">Systemsteuerung</code> > <code className="action">Netzwerk- und Freigabecenter</code> > <code className="action">Adaptereinstellungen ändern</code> und öffnen Sie anschließend die Eigenschaften Ihres Netzwerkadapters.
2. Wählen Sie <code className="action">Internetprotokoll, Version 4 (TCP/IPv4)</code> > <code className="action">Eigenschaften</code> > <code className="action">Erweitert</code> und fügen Sie die Additional IP-Adresse hinzu.

Im OVHcloud Netzwerk wird eine Additional IP einzeln zum Server geroutet. Verwenden Sie die Netzmaske und das Gateway, die der Haupt-IP-Konfiguration Ihres Servers entsprechen.

:::tip
Wenn Sie die Additional IP einer virtuellen Maschine anstelle des Hosts zuweisen möchten, lesen Sie die Anleitung [Einen IP-Block in einem vRack konfigurieren](/guides/bare-metal-cloud/dedicated-servers/configuring-an-ip-block-in-a-vrack).
:::

#### 4b — Privates vRack-Netzwerk

Das vRack ist ein privates Layer-2-Netzwerk, über das Ihr Dedicated Server privat mit anderen OVHcloud Diensten kommunizieren kann (andere Dedicated Server, Public Cloud Instanzen usw.).

**Im OVHcloud Kundencenter**

Öffnen Sie im Menü <code className="action">Network</code> des Kundencenters den Bereich <code className="action">vRack</code>, wählen Sie Ihr vRack aus und fügen Sie diesen Server hinzu.

**In Windows Server**

1. Öffnen Sie die Eigenschaften des **privaten** Netzwerkadapters (die zweite Schnittstelle, die dem vRack zugeordnet ist).
2. Weisen Sie eine statische private IPv4-Adresse aus Ihrem vRack-Adressierungsplan zu. Lassen Sie das Standardgateway leer — das vRack ist ein Layer-2-Netzwerk ohne von OVHcloud bereitgestelltes Gateway.

Die vollständige Vorgehensweise, einschließlich Hinweisen zu OVHcloud Link Aggregation (OLA), finden Sie in der Anleitung [Das vRack auf einem Dedicated Server konfigurieren](/guides/bare-metal-cloud/dedicated-servers/vrack-configuring-on-dedicated-server).

#### 4c — IPv6

Jeder OVHcloud Dedicated Server wird mit einem /64-IPv6-Block geliefert. Die Adresse wird in Windows nicht automatisch konfiguriert und muss manuell hinzugefügt werden.

**Im OVHcloud Kundencenter**

Rufen Sie Ihre IPv6-Adresse, das Präfix und das Gateway im Tab <code className="action">Allgemeine Informationen</code> Ihres Servers ab: Der Bereich <code className="action">Netzwerk</code> zeigt <code className="action">IPv6</code> und <code className="action">IPv6 Gateway</code> an.

**In Windows Server**

1. Öffnen Sie die Eigenschaften Ihres Netzwerkadapters und wählen Sie <code className="action">Internetprotokoll, Version 6 (TCP/IPv6)</code> > <code className="action">Eigenschaften</code>.
2. Geben Sie die IPv6-Adresse, die Präfixlänge und das IPv6-Standardgateway ein.

Details zur Adressierung und zur OVHcloud-spezifischen Gateway-Konfiguration finden Sie in der Anleitung [IPv6-Konfiguration](/guides/bare-metal-cloud/dedicated-servers/network-ipv6).

#### 4d — Backup Storage

Backup Storage ist ein kostenloser Speicherplatz, der in Ihrem Dedicated Server enthalten ist. Der Zugriff kann über FTP, CIFS (SMB) oder NFS erfolgen und eignet sich am besten als ergänzendes Backup-Ziel.

**Im OVHcloud Kundencenter**

1. Klicken Sie im Tab <code className="action">Storage-Backup</code> Ihres Servers auf <code className="action">Storage-Backup aktivieren</code>. Sobald der Speicher aktiv ist, zeigt der Tab die Adresse des FTP-Servers und den Benutzernamen an und ermöglicht es Ihnen, das Passwort für den Speicherplatz festzulegen.
2. Autorisieren Sie die IP-Adresse Ihres Servers für den Zugriff auf den Speicherplatz.

**In Windows Server**

Greifen Sie über eines der unterstützten Protokolle auf den Speicherplatz zu:

- **CIFS (SMB)** — Binden Sie ihn als Netzlaufwerk ein (<code className="action">Dieser PC</code> > <code className="action">Netzlaufwerk verbinden</code>).
- **FTP** — Verbinden Sie sich mit einem beliebigen FTP-Client und verwenden Sie dabei die Verbindungsdaten aus dem Kundencenter und das von Ihnen festgelegte Passwort.

Details zur Aktivierung und zu den Protokollen finden Sie in der Anleitung [Backup Storage auf Dedicated Servern](/guides/bare-metal-cloud/dedicated-servers/services-backup-storage) und auf der Seite [Backup Storage](/links/bare-metal/backup-storage).

#### 4e — Backup Agent

Backup Storage ist ein passiver Speicherplatz — er sichert Ihre Daten nicht von selbst. Für einen verwalteten, automatisierten Schutz bietet OVHcloud **Backup Agent** an, einen separaten Backup-Dienst für Bare Metal Server. Nach der Bestellung installieren Sie einen schlanken Agenten auf Ihrem Windows-Server, der anschließend täglich inkrementelle, verschlüsselte und unveränderliche Backups in einem isolierten Object Storage-Tresor erstellt, der sich in einer anderen Region als der Server befindet.

**Im OVHcloud Kundencenter**

Verwenden Sie im Tab <code className="action">Allgemeine Informationen</code> im Bereich <code className="action">Status der Dienste</code> den Eintrag <code className="action">Backup Agent</code> und klicken Sie auf <code className="action">Backup-Agent verwalten</code>. Sie können ihn auch während der Neuinstallation des Betriebssystems aktivieren.

**In Windows Server**

Sobald der Agent installiert ist, konfigurieren Sie Ihr erstes Backup (Quelldaten, Zeitplan und Aufbewahrung).

Die vollständige Vorgehensweise finden Sie in der [Backup Agent Übersicht](/guides/storage-and-backup/backup-agent/overview) und in der Anleitung [So konfigurieren Sie Ihr erstes Backup](/guides/storage-and-backup/backup-agent/first-configuration).

### Schritt 5 — Die Konfiguration überprüfen <a name="verify"></a>

Vergewissern Sie sich, dass jeder konfigurierte Dienst wie erwartet funktioniert.

| Prüfung | Vorgehensweise | Erwartetes Ergebnis |
|---|---|---|
| RDP-Zugang | Verbinden Sie sich per <code className="action">Remotedesktopverbindung</code> mit der Haupt-IPv4-Adresse | Der Windows-Desktop wird geladen |
| Additional IP | Führen Sie von einem externen Host aus einen `ping` an die Additional IP aus | Der Server antwortet |
| vRack | Führen Sie von einem anderen vRack-Teilnehmer aus einen `ping` an die private IP aus | Der Server antwortet |
| IPv6 | Führen Sie `ping -6 ipv6.google.com` auf dem Server aus | Es werden Antworten empfangen |
| Backup Storage | Öffnen Sie das verbundene CIFS- (SMB) Laufwerk oder verbinden Sie sich über FTP | Dateien können gelesen und geschrieben werden |

### Fehlerbehebung <a name="troubleshooting"></a>

| Problem | Mögliche Ursache | Lösung |
|---|---|---|
| RDP-Verbindung schlägt fehl | Firewall-Regeln oder Netzwerkeinschränkungen auf dem lokalen Gerät | Überprüfen Sie die lokalen Firewall- und Netzwerkeinstellungen; verbinden Sie sich ersatzweise über die [IPMI-Konsole](/guides/bare-metal-cloud/dedicated-servers/ipmi). |
| Additional IP nicht erreichbar | Falsche Maske oder falsches Gateway in Windows | Überprüfen Sie die in den erweiterten TCP/IPv4-Einstellungen eingegebenen Werte erneut. |
| vRack-Gegenstelle nicht erreichbar | Falsches privates Subnetz oder ein auf dem privaten Adapter gesetztes Gateway | Überprüfen Sie den privaten Adressierungsplan und lassen Sie das Gateway leer. |
| Server nach einer Änderung offline | Fehlkonfiguration während der Einrichtung | Booten Sie in den [Rescue-Modus](/guides/bare-metal-cloud/dedicated-servers/rescue-customer-windows), um die Konfiguration zu prüfen und zu reparieren. |
