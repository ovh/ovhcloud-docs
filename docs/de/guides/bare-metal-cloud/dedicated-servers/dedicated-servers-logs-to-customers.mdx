## Ziel

In dieser Anleitung erfahren Sie, wie Sie die Weiterleitung der Logs Ihres OVHcloud Dedicated Servers an Logs Data Platform (LDP) aktivieren. Diese Plattform hilft Ihnen dabei, Ihre Logs zu speichern, zu archivieren, abzufragen und zu visualisieren.

Wenn Sie vor dem Lesen dieser Anleitung mehr über Logs Data Platform erfahren möchten, lesen Sie unsere [Einführung in Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/introduction).

**In dieser Anleitung erfahren Sie, wie Sie:**

- die Logs Ihres Dedicated Servers in Echtzeit einsehen;
- ein Abonnement erstellen, das diese Logs an einen Datenstream von Logs Data Platform weiterleitet;
- die weitergeleiteten Logs abfragen und visualisieren;
- Ihre Abonnements verwalten und löschen.

:::info
Die in dieser Anleitung beschriebenen Logs stammen aus den Vorgängen, die OVHcloud auf Ihrem Server ausführt: **Installation des Betriebssystems**, **Netzwerkboot** und **Netzwerkkonfiguration**. Es handelt sich **nicht** um die Systemlogs, die das Betriebssystem im laufenden Betrieb erzeugt.

Um die von Ihrem eigenen Betriebssystem erzeugten Logs zu zentralisieren, lesen Sie stattdessen die Anleitung zum [Senden von Linux-Logs an Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/log-linux).
:::

## Glossar

- **Logs Data Platform:** eine vollständig verwaltete und gesicherte Plattform zur Log-Verwaltung von OVHcloud. Weitere Informationen finden Sie auf der Seite des Dienstes [Logs Data Platform](/links/manage-operate/ldp).
- **Datenstream (Data Stream):** eine logische Partition von Logs, die Sie in einem LDP-Konto erstellen und zum Erfassen, Anzeigen oder Abfragen Ihrer Logs verwenden. Mehrere Quellen können im selben Datenstream gespeichert werden. Der Datenstream ist die Einheit, mit der eine Log-Pipeline (Aufbewahrungsrichtlinie, Archivierung, Live-Streaming usw.), Zugriffsrechte und Alarmrichtlinien definiert werden.
- **Logs-Weiterleitung (Logs forwarding):** eine in ein OVHcloud Produkt integrierte Funktion, mit der die Logs seiner Dienste in einen *Datenstream* eines LDP-Kontos desselben OVHcloud Kunden-Accounts übertragen werden. Sie müssen sie für jeden Dienst einzeln aktivieren.
- **Abonnement der Logs-Weiterleitung (Logs forwarding Subscription):** Wenn Sie die Logs-Weiterleitung für einen bestimmten OVHcloud Dienst an einen bestimmten LDP-*Datenstream* aktivieren, wird ein *Abonnement* erstellt und mit dem *Datenstream* verknüpft, das Sie anschließend verwalten.

## Voraussetzungen

- Sie verfügen über ein Logs Data Platform (LDP) Konto mit mindestens einem aktiven, konfigurierten *Stream*. Diese Anleitung führt Sie durch alle erforderlichen Schritte: [Schnellstart mit Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start).
    - Wenn Sie nicht mit allen Konfigurationsmöglichkeiten eines LDP-*Streams* vertraut sind, erstellen Sie für diese Anleitung einen neuen Stream mit den Standardoptionen (Indexierung und WebSocket aktiviert, Langzeitspeicherung deaktiviert).
- Sie verfügen über einen betriebsbereiten [OVHcloud Dedicated Server](/guides/bare-metal-cloud/dedicated-servers/getting-started-with-dedicated-server).
- Das LDP-Konto und der Dedicated Server gehören zum selben OVHcloud Kunden-Account.

## Konzepte und Grenzen

**Was sind die Logs eines Dedicated Servers?**

Die weitergeleiteten Logs verfolgen die Vorgänge, die OVHcloud auf Ihrem Server ausführt: Installation des Betriebssystems, Netzwerkboot und Netzwerkkonfiguration.

Die Logs-Weiterleitung ist für alle Dedicated Server Reihen verfügbar.

### Log-Typen

Logs werden nach *Typen* gruppiert, und Sie abonnieren jeden Typ einzeln. Ein Dedicated Server stellt die folgenden Typen bereit:

| Typ | Anzeigename | Beschreibung |
|------|--------------|-------------|
| `install` | Operating system installation logs | Details zur Installation des Betriebssystems auf Ihrem Server. |
| `netboot` | Network boot logs | Übermittlung des iPXE-Bootskripts an Ihren Server, wenn dieser über das Netzwerk startet (Festplatte, Rescue, Installer usw.). |
| `network` | Network configuration logs | Netzwerkvorgänge, die OVHcloud auf Ihrem Server ausführt: Additional IPs, virtuelle MAC-Adressen, vRack, OVHcloud Link Aggregation (OLA) und Bandbreitenrichtlinien. |

Die Liste der auf Ihrem Server verfügbaren Typen können Sie mit dem folgenden API-Aufruf abrufen:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/kind"} />

Um die Details eines Typs abzurufen, einschließlich der zusätzlichen Felder, die er zurückgibt, verwenden Sie den folgenden API-Aufruf:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/kind/\{name\}"} />

### Inhalt der Logs

Zusätzlich zu den Feldern, die allen von Logs Data Platform erfassten Logs gemeinsam sind, gibt jeder Typ die folgenden Felder zurück.

#### Typ `install`

| Feldname | Beschreibung | Datentyp |
|------------|-------------|------|
| `level` | Kritikalitätsstufe des Log-Eintrags gemäß den standardmäßigen Syslog-Schweregraden: `2` (critical), `6` (info). | Number |
| `os` | Auf dem Server installiertes Betriebssystem. | String |
| `serviceName` | Interner Name Ihres Servers im Format `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Aktueller Schritt des Vorgangs: `os-install-start`, `os-install-failed` oder `os-install-ok`. | String |

#### Typ `netboot`

| Feldname | Beschreibung | Datentyp |
|------------|-------------|------|
| `level` | Kritikalitätsstufe des Log-Eintrags gemäß den standardmäßigen Syslog-Schweregraden: `2` (critical), `6` (info). | Number |
| `serviceName` | Interner Name Ihres Servers im Format `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Ergebnis der Anfrage des Bootskripts: `ipxe-request-ok` oder `ipxe-request-error`. | String |

#### Typ `network`

| Feldname | Beschreibung | Datentyp |
|------------|-------------|------|
| `level` | Kritikalitätsstufe des Log-Eintrags gemäß den standardmäßigen Syslog-Schweregraden: `6` (info). | Number |
| `serviceName` | Interner Name Ihres Servers im Format `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Aktueller Schritt des Vorgangs im Format `<operation>-doing` (gestartet) oder `<operation>-ok` (erfolgreich). Vorgänge: `add_ipfo`, `remove_ipfo`, `add_vmac`, `remove_vmac`, `vrack-add`, `vrack-remove`, `ola-group`, `ola-ungroup`, `qos-apply`. | String |

:::info
Die obige Liste der `status`-Werte entspricht dem aktuellen Stand und wird sich im Laufe der Zeit weiterentwickeln.
:::

Informationen zu den Feldern, die allen Logs gemeinsam sind, finden Sie in der Anleitung zur [Namenskonvention für Felder](/guides/manage-and-operate/observability/logs-data-platform/field-naming-conventions).

## In der praktischen Anwendung

Die Aktivierung der Weiterleitung ist kostenlos, die Nutzung des Dienstes Logs Data Platform wird Ihnen jedoch gemäß dem Standardtarif in Rechnung gestellt. Informationen zu den Preisen von LDP finden Sie auf der Seite des Dienstes [Logs Data Platform](/links/manage-operate/ldp).

### Logs-Weiterleitung aktivieren

<Tabs>
<Tab label="Über die OVHcloud Console">

Öffnen Sie in der OVHcloud Console das Universum <code className="action">Bare Metal Cloud</code>, gehen Sie zu <code className="action">Dedizierte Server</code> und wählen Sie den Server aus, dessen Logs Sie weiterleiten möchten.

Klicken Sie auf den Tab <code className="action">Logs</code>.

Der Tab enthält:

- eine Dropdown-Liste **Log-Typ**, in der Sie den Typ der Logs auswählen, die Sie anzeigen oder weiterleiten möchten (`netboot`, `network` oder `install`);
- den Bereich **Live-Stream**, der die Logs Ihres Servers für den ausgewählten Log-Typ in Echtzeit anzeigt;
- den Bereich **Logs**, der Ihre aktiven Abonnements auflistet und in dem Sie neue erstellen können.

Um Ihre Logs an Logs Data Platform weiterzuleiten, wählen Sie den Log-Typ aus und klicken Sie dann im Bereich **Logs** auf <code className="action">Add subscription</code>.

Wenn Sie über mehrere Logs Data Platform Dienste verfügen, wählen Sie im Fenster **Stream abonnieren** einen davon in der Dropdown-Liste **Logs Data Platform-Dienst** aus (bei einem einzigen Dienst wird dieser automatisch ausgewählt). Wählen Sie anschließend den Ziel-Datenstream in der Dropdown-Liste **Stream** aus und klicken Sie auf <code className="action">Abonnieren</code>.

Wenn Ihr Kunden-Account noch keinen Logs Data Platform Dienst hat, weist das Fenster darauf hin und bietet einen Button <code className="action">Logs Data Platform bestellen</code> an. Wenn Ihr Dienst noch keinen Stream hat, erstellen Sie zuerst einen in Logs Data Platform (siehe [Schnellstart mit Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start)).

Nur die **nach** der Erstellung des Abonnements generierten Logs werden an Ihren Datenstream gesendet.

Weitere Informationen zu OVHcloud Service Logs, das von allen kompatiblen OVHcloud Produkten gemeinsam genutzt wird, finden Sie in der Anleitung [Einführung in OVHcloud Service Logs mit Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/service-logs).

</Tab>
<Tab label="OVHcloud API">

Legen Sie in einem Ihrer LDP-Konten den Ziel-*Stream* fest, an den Ihre Logs weitergeleitet werden sollen. Durch das Aktivieren der Weiterleitung wird ein Abonnement für diese Stream-ID erstellt.

#### Schritt 1 - Ziel-Stream (und ID) abrufen

Listen Sie die Datenstreams Ihres Logs Data Platform Kontos auf (geben Sie Ihre LDP-ID im Format `ldp-xx-xxxx` in das Feld `serviceName` ein):

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/output/graylog/stream"} />

Rufen Sie die Details eines Datenstreams ab:

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/output/graylog/stream/\{streamId\}"} />

#### Schritt 2 - Abonnement erstellen

Verwenden Sie den folgenden API-Aufruf, um ein Abonnement zu erstellen:

<Api version="v2" section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/log/subscription"} />

:::info
Ersetzen Sie:

- `serviceName`: Dies ist der interne Name Ihres Dedicated Servers im Format `nsxxxxx.ip-xx-xx-xx.eu`. Sie finden ihn in der Liste der Dedicated Server oder auf der Seite des Servers in der OVHcloud Console oder mit dem folgenden API-Aufruf:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server"} />
:::

Die POST-Anfrage erfordert einen Payload mit:

- `kind`: dem Typ der Logs, die Sie weiterleiten möchten (`install`, `netboot` oder `network`). Siehe [Log-Typen](#log-typen) weiter oben.
- `streamId`: dem Ziel-Datenstream Ihres LDP-Kontos, an den die Logs Ihres Dedicated Servers weitergeleitet werden sollen.

```shell
POST /dedicated/server/{serviceName}/log/subscription
{
  "kind": "install", // Einer der Werte: install, netboot, network.
  "streamId": "198ef9d5-c320-4000-8bee-236623da5b80" // Die streamID des Ziel-Streams.
}
```

Als Antwort erhalten Sie eine `operationId`:

```shell
{
  "operationId": "f550aa1c-89ab-4b1a-81ae-4fba4959966f",
  "serviceName": "ldp-xx-xxxx"
}
```

Mit der `operationId` können Sie die `subscriptionId` für die spätere Verwaltung über den folgenden API-Aufruf abrufen:

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/operation/\{operationId\}"} />

Alternativ können Sie die Abonnements nach Abschluss des Vorgangs mit dem folgenden API-Aufruf abrufen:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/subscription"} />

Sobald Sie die `subscriptionId` haben, können Sie die Details mit dem folgenden API-Aufruf abrufen:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/subscription/\{subscriptionId\}"} />

```shell
GET /dedicated/server/{serviceName}/log/subscription/{subscriptionId}

{
  "createdAt": "2026-08-31T07:42:50.645Z",
  "kind": "string",
  "resource": {
    "name": "string",
    "type": "string"
  },
  "serviceName": "string",
  "streamId": "string",
  "subscriptionId": "198efa11-f150-4000-8e8d-871b1e482b80",
  "updatedAt": "2026-08-31T07:42:50.645Z"
}
```

### Logs Ihres Dedicated Servers verwenden

Ihre Logs werden nun in Ihrem Datenstream von Logs Data Platform erfasst und gespeichert. Sie können sie im Graylog-Webinterface abfragen und Dashboards erstellen.

- Rufen Sie den Benutzernamen Ihres Logs Data Platform Kontos (zum Beispiel `logs-xxxx`) und das zugehörige Passwort ab. Öffnen Sie in der OVHcloud Console <code className="action">Observability</code>, klicken Sie auf <code className="action">Serviceverwaltung</code> und wählen Sie Ihren Logs Data Platform Dienst aus: Der Benutzername wird als **LDP-Benutzername** im Bereich **Allgemeine Informationen** angezeigt (nur bei Diensten, die OVHcloud IAM nicht verwenden). Das Passwort ist dasjenige, das Sie für dieses Konto festgelegt haben. Weitere Informationen finden Sie im [Schnellstart mit Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start).
- Öffnen Sie das Graylog-Webinterface. Sie erreichen es über die Graylog-Dashboards, die in der OVHcloud Console unter <code className="action">Observability</code> > <code className="action">Dashboards</code> aufgeführt sind, oder über Ihren Zugangspunkt, abhängig von der Region Ihres Kontos (für die Region Gravelines zum Beispiel `https://gra1.logs.ovh.com/`).
- Melden Sie sich mit Ihrem Logs Data Platform Benutzernamen und Passwort bei Graylog an.
- Durchsuchen Sie Ihre Logs im Datenstream Ihres Logs Data Platform Kontos. Details zur Suchsyntax finden Sie in der Dokumentation [Search Syntax Reference](https://go2docs.graylog.org/current/making_sense_of_your_log_data/search_syntax_reference.htm).

Weitere Informationen zur Nutzung Ihrer Logs mit Logs Data Platform, etwa zum Einrichten von Alarmen, zur Echtzeitanzeige der Logs über einen WebSocket, zum Erstellen von Visualisierungen mit OpenSearch Dashboards, zur Integration mit der OpenSearch API und zur Verbindung mit Grafana, finden Sie in der [Einführung in Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/introduction).

### Abonnements verwalten

Sie können jederzeit die mit Ihrem Logs Data Platform Datenstream verknüpften Abonnements abrufen und die Weiterleitung deaktivieren, indem Sie Ihr Abonnement für Ihren Stream kündigen. Ihr Logs Data Platform Stream empfängt dann keine Logs Ihres Dedicated Servers mehr.

Die vor der Kündigung des Abonnements gespeicherten Logs werden dadurch nicht gelöscht, da die in einem Log-Stream gespeicherten Daten unveränderlich sind, es sei denn, Sie löschen den gesamten Stream.

Öffnen Sie in der OVHcloud Console den Tab <code className="action">Logs</code> Ihres Servers, suchen Sie das Abonnement anhand seiner Stream-ID im Bereich **Logs** und klicken Sie dann auf das Papierkorb-Symbol in der entsprechenden Zeile. Das Abonnement wird sofort und ohne Bestätigungsfenster gelöscht.

Um Ihr Abonnement über die API zu löschen, verwenden Sie den folgenden Aufruf:

<Api version="v2" section="/dedicated/server" method="DELETE" route={"/dedicated/server/\{serviceName\}/log/subscription/\{subscriptionId\}"} />
