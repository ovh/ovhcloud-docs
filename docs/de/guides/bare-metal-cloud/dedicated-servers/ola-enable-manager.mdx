## Ziel

Die OVHcloud Link Aggregation (OLA) wurde von unseren Teams entwickelt, um die Verfügbarkeit Ihres Servers zu erhöhen und die Effizienz Ihrer Netzwerkverbindungen zu steigern. Mit nur wenigen Klicks können Sie Ihre Netzwerkkarten aggregieren und Ihre Netzwerkverbindungen redundant machen. Wenn also eine Verbindung ausfällt, wird der Datenverkehr automatisch auf eine andere verfügbare Verbindung umgeleitet.<br/>
Die Aggregation verwendet das Link Aggregation Control Protocol (LACP), das im Standard IEEE 802.3ad definiert ist.

**Diese Anleitung erklärt, wie Sie OLA in der OVHcloud Konsole einrichten.**

## Voraussetzungen

- Sie haben einen [Dedicated Server](/links/bare-metal/bare-metal) der Advance, Scale oder High Grade Reihe.
- Sie verwenden ein Betriebssystem / einen Hypervisor mit Unterstützung für das Aggregationsprotokoll 802.3ad (LACP).

[[cpnav:baremetal-dedicated-servers-console]]

## In der praktischen Anwendung

:::warning
OLA wird über alle Netzwerkinterfaces konfiguriert. Sie werden dadurch zu einem Aggregat vom Typ "private aggregation".

Nach der Umsetzung von OLA ist die öffentliche IP nicht mehr verfügbar.

:::


### OLA in der OVHcloud Konsole konfigurieren

Um mit der Konfiguration von OLA zu beginnen, öffnen Sie den Tab <code className="action">Connectivity</code> auf der Verwaltungsseite Ihres Servers.

Klicken Sie im Bereich **OVHcloud Link Aggregation (OLA)** auf <code className="action">Configure OLA</code>.

Geben Sie im Fenster **Configure OLA aggregation** im Feld **Name the interface** einen Namen für Ihre Link-Aggregation ein.

Unterhalb dieses Feldes vergleichen zwei Tabellen Ihre Konfiguration vor und nach der Aggregation:

- **Your current network interface**: die aktuelle Konfiguration Ihrer Netzwerkinterfaces;
- **Your network interface after activation**: die simulierte Konfiguration Ihrer aggregierten Netzwerkinterfaces.

:::warning
Während die Aggregation angewendet wird, wird die Konfiguration Ihrer Netzwerkinterfaces entfernt und Ihr Server verliert seine Konnektivität. Anschließend müssen Sie das Bond in Ihrem Betriebssystem über die KVM-Konsole konfigurieren (siehe [Verwendung der IPMI-Konsole für Dedicated Server](/guides/bare-metal-cloud/dedicated-servers/ipmi) und die Anleitungen zu den Betriebssystemen weiter unten). Ohne diesen Schritt ist die Konfiguration nicht abgeschlossen.
:::

Sobald Sie überprüft haben, dass das Aggregations-Layout Ihren Netzwerkanforderungen entspricht, klicken Sie auf <code className="action">Aggregate</code>, um fortzufahren.

Es kann einige Minuten dauern, bis der Vorgang abgeschlossen ist. Anschließend werden im nächsten Schritt die Schnittstellen in Ihrem Betriebssystem in einem "NIC link" oder einem "NIC team" konfiguriert. In den folgenden Anleitungen finden Sie Informationen zu den beliebtesten Betriebssystemen:

- [Konfigurieren der LACP-Linkaggregation unter Debian 9 bis 11 (ifupdown)](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-ifupdown).
- [Konfigurieren des NIC-Teamings für die OVHcloud Link Aggregation (OLA) unter Windows Server 2019](/guides/bare-metal-cloud/dedicated-servers/ola-enable-w2k19).
- [Konfigurieren der LACP-Linkaggregation unter SLES 15](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-sles15).
- [Konfigurieren der LACP-Linkaggregation unter Debian 12 oder neuer / Ubuntu 24.04 oder neuer (Netplan)](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-netplan).

### OLA-Status prüfen

Sie können den Status Ihrer OVHcloud Link Aggregation (OLA) im Tab <code className="action">Connectivity</code> auf der Verwaltungsseite Ihres Servers überprüfen. Im Bereich **OVHcloud Link Aggregation (OLA)** zeigt die Zeile **OLA** den Status und die Zeile **Mode** den Aggregationstyp an.

Folgende Kombinationen sind möglich:

- **Available**, Modus **Default**: OLA wird unterstützt, ist aber nicht konfiguriert.
- **Active**, Modus **Full private**: OLA ist aktiviert; alle physischen Interfaces werden zu einem einzigen privaten Link für den vRack-Einsatz aggregiert.
- **Available**, Modus **Double LAG**: Die Interfaces sind in zwei Aggregate aufgeteilt (eines öffentlich, eines privat), in einem anderen Layout als dem Standardlayout des Servers.
- **Wird aggregiert...** oder **Wird zurückgesetzt...**: Eine OLA-Änderung wird gerade angewendet; die Zeilen **Mode** und **Virtual interfaces** zeigen bis zum Abschluss einen Strich an.

Wenn OLA von diesem Dedicated-Server-Modell nicht unterstützt wird, zeigt der Bereich **OVHcloud Link Aggregation (OLA)** den Hinweis **OLA nicht enthalten** an, und die Zeile **OLA** im Bereich **Konnektivität** des Tabs <code className="action">Übersicht</code> des Servers zeigt **Unavailable** an.

:::info
Bei Scale und High Grade Servern fasst das Standardlayout die vier Interfaces bereits zu einem öffentlichen und einem privaten Aggregat zusammen; die Konsole zeigt es als **Available**, Modus **Default** an.

:::

### OLA auf die Standardwerte zurücksetzen

Um OLA auf die Standardwerte zurückzusetzen, öffnen Sie den Tab <code className="action">Connectivity</code> und klicken Sie im Bereich **OVHcloud Link Aggregation (OLA)** auf <code className="action">Reset</code>. (Dieser Button wird nur angezeigt, wenn OLA im Modus **Full private** aktiv ist.) Während des Zurücksetzens wird die Konfiguration der Interfaces entfernt und der Server verliert seine Konnektivität. Klicken Sie im Fenster **Reset OVHcloud Link Aggregation** auf <code className="action">Confirm</code>.

Die Operation kann einige Minuten in Anspruch nehmen.
