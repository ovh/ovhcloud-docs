## Ziel

Ein Log ist ein Ereignis, das auf einem Computersystem (Server, Anwendung, Website usw.) aufgezeichnet wird.
Bei einer Website zeichnen Logs in der Regel jede empfangene HTTP-Anfrage, die zurückgegebene Antwort, den Client, der die Anfrage gestellt hat, und die Dauer der Bearbeitung der Anfrage auf.

Ihre **Managed Hosting for WordPress** Lösung generiert Logs für die von ihr gehosteten Websites und leitet sie an [Logs Data Platform](/links/manage-operate/ldp) weiter, wo Sie sie speichern, visualisieren und abfragen können.

Im Gegensatz zu einer reinen Logdatei werden die an Logs Data Platform gesendeten Logs **in einzelne Felder aufgeteilt** (HTTP-Methode, Statuscode, IP-Adresse des Clients, Antwortzeit usw.). Das bedeutet, dass Sie nicht selbst eine einzelne Textzeile auswerten müssen: Jede Information steht bereits als eigenes, durchsuchbares Feld zur Verfügung.

**Erfahren Sie, welche Logs für Ihre Managed Hosting for WordPress Lösung verfügbar sind und wie Sie diese nutzen können.**

## Voraussetzungen

- Sie verfügen über eine [Managed Hosting for WordPress](https://labs.ovhcloud.com/en/managed-wp/) Lösung mit mindestens einer Website.
- Sie haben Zugang zum <ManagerLink to="/">OVHcloud Kundencenter</ManagerLink>.

### Verfügbare Log-Arten

Ihre Managed Hosting for WordPress Lösung leitet zwei verschiedene Arten von Logs an Logs Data Platform weiter:

| Log-Art | Inhalt |
|------------|---------|
| **HTTP access logs** | Ein Eintrag pro HTTP-Anfrage, die von Ihrer Website empfangen wird (Apache Access Log). Dies ist der wichtigste Stream, um Traffic, Fehler und Antwortzeiten zu überwachen. |
| **PHP-FPM logs** | Meldungen, die von der PHP-FPM-Engine ausgegeben werden, die Ihren WordPress-Code ausführt (PHP-Warnungen, Fehler, langsame Skripte usw.). |

Jeder Eintrag wird mit Informationen angereichert, die die zugehörige Website identifizieren, sodass Sie die Logs einer einzelnen Website filtern können, selbst wenn sich mehrere Websites denselben Stream teilen:

- `service_id`: die Kennung Ihres Managed Hosting for WordPress Dienstes.
- `website_id`: die interne Kennung der Website.
- `fqdn`: der Domainname (Virtual Host), an den die Anfrage gerichtet ist.

### Felder der HTTP access logs

Für jede HTTP-Anfrage stehen die folgenden Felder zur Verfügung. Die Feldnamen folgen den [Logs Data Platform Namenskonventionen](/guides/manage-and-operate/observability/logs-data-platform/field-naming-conventions) (EN): Das Suffix gibt an, wie der Wert typisiert und indexiert wird (`_ip` wird geolokalisiert, `_int` ist eine Ganzzahl, `_num` ist eine Zahl, `_date` ist ein Datum).

| Feld | Beispiel | Beschreibung |
|-------|---------|-------------|
| `time` | `2026-06-04T10:04:53.000Z` | Datum, an dem der Eintrag von Logs Data Platform empfangen wurde. |
| `host` | `wp004.eu-west-001` | Hostname des Servers, der das Log generiert hat. |
| `service_id` | `wp-xxxxxxxx` | Kennung Ihres Managed Hosting for WordPress Dienstes. |
| `website_id` | `a1b2c3d4e5` | Interne Kennung der Website. |
| `fqdn` | `www.example.com` | Domainname (Virtual Host), an den die Anfrage gerichtet ist. |
| `remote_host_ip` | `203.0.113.42` | IP-Adresse des Clients. Aufgrund des Suffixes `_ip` wird sie von Logs Data Platform automatisch geolokalisiert (Land, Stadt, Koordinaten usw.). |
| `http_method` | `GET` | HTTP-Methode der Anfrage. |
| `http_path` | `/wp-login.php` | Vom Client angeforderter Pfad. |
| `http_protocol` | `HTTP/1.1` | Verwendetes Protokoll und Version. |
| `http_status_int` | `200` | HTTP-Statuscode der Antwort, als Ganzzahl gespeichert, sodass Sie numerische Vergleiche durchführen können. |
| `bytes_sent` | `1234` | Größe der an den Client gesendeten Antwort, in Bytes. |
| `referer` | `https://www.google.com/` | Wert des Headers `Referer`. |
| `user_agent` | `Mozilla/5.0 (...)` | Wert des Headers `User-Agent`. |
| `request_time` | `04/Jun/2026:10:04:53 +0000` | Uhrzeit, zu der die Anfrage empfangen wurde, in einem lesbaren Format. |
| `request_time_date` | `2026-06-04T10:04:53Z` | Dieselbe Anfragezeit als ISO-8601-Datum (UTC), sodass sie in datumsbasierten Abfragen und Dashboards verwendet werden kann. |
| `request_duration_num` | `114` | Zeit, die für die Bearbeitung der Anfrage benötigt wurde, **in Millisekunden**. Verwenden Sie dieses Feld, um Ihre Antwortzeiten zu überwachen. |
| `message` | `203.0.113.42 - - [04/Jun/2026...]` | Die vollständige rohe Access-Log-Zeile, zur Referenz aufbewahrt. |

### Felder der PHP-FPM logs

Die PHP-FPM-Art ist schlanker und stellt die folgenden Felder bereit:

| Feld | Beschreibung |
|-------|-------------|
| `time` | Datum, an dem der Eintrag von Logs Data Platform empfangen wurde. |
| `host` | Hostname des Servers, der das Log generiert hat. |
| `service_id` | Kennung Ihres Managed Hosting for WordPress Dienstes. |
| `website_id` | Interne Kennung der Website. |
| `message` | Die PHP-FPM-Meldung (Warnung, Fehler, Hinweis usw.). |

### Logs abfragen und analysieren

Sobald Ihre Logs Logs Data Platform erreichen, können Sie sie über die in Ihrer Lösung enthaltene Graylog-Weboberfläche untersuchen, Dashboards erstellen und Alarme einrichten. Für die Grundlagen lesen Sie den Leitfaden [Quick start mit Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start) (EN).

Da die Access Logs in typisierte Felder aufgeteilt sind, können Sie gezielte Suchen direkt über die Graylog-Suchleiste durchführen. Einige Beispiele:

- Anzeigen der Anfragen einer einzelnen Website:

```text
website_id:a1b2c3d4e5
```

- Finden aller Serverfehler (HTTP 5xx):

```text
http_status_int:>=500
```

- Identifizieren langsamer Anfragen, deren Bearbeitung länger als eine Sekunde gedauert hat:

```text
request_duration_num:>1000
```

- Überwachen von Brute-Force-Versuchen auf der WordPress-Anmeldeseite:

```text
http_path:"/wp-login.php" AND http_method:POST
```

- Filtern des Traffics nach dem geolokalisierten Land des Clients (bereitgestellt durch das Suffix `_ip`):

```text
remote_host_ip_country_code:FR
```

:::info
Die HTTP access logs werden in UTC generiert. Verwenden Sie das Feld `request_time_date` (ein ISO-8601-Datum) oder das Feld `time` für jede datumsbasierte Abfrage, Sortierung oder jedes Histogramm.

:::
