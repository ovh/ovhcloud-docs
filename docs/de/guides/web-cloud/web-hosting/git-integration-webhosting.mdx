## Ziel

In der heutigen digitalen Landschaft sind Unternehmen dynamischer und innovativer geworden. Die Fähigkeit, den Code Ihrer Website effizient zu verwalten und einzusetzen, ist entscheidend, um die Wettbewerbsfähigkeit und Nachhaltigkeit Ihrer Marke zu erhalten. Git, das weltweit am häufigsten verwendete Versionsverwaltungssystem, erlaubt die Speicherung des Codes Ihrer Website auf Plattformen wie GitHub, was eine bessere Rückverfolgbarkeit von Änderungen sowie eine schnellere Automatisierung und Bereitstellung ermöglicht. Als OVHcloud Kunde verfügen Sie über eine robuste Infrastruktur für das Hosting Ihrer Website und können gleichzeitig die zahlreichen Vorteile von Git und GitHub für die Entwicklung und Evolution Ihrer Website nutzen.

**Erfahren Sie, wie Sie Git mit Ihrem Webhosting über Ihre OVHcloud Konsole konfigurieren und verwenden.**

## Voraussetzungen

- Sie verfügen über ein [OVHcloud Webhosting](/links/web/hosting).
- Sie haben einen Account auf [GitHub](https://github.com/) und sind eingeloggt.

:::info
Bis dato wird nur die GitHub-Plattform für die Verwendung mit OVHcloud Webhosting-Diensten unterstützt.

:::

#### GitHub-Repository definieren

Geben Sie die Adresse Ihres GitHub-Repositorys ein. Wenn Sie noch kein GitHub-Repository für Ihr Projekt haben, erstellen Sie eines.

So erstellen Sie ein neues Repository:

- Melden Sie sich bei Ihrem GitHub-Account an.
- Klicken Sie oben rechts auf Ihr Profilbild und dann auf <code className="action">Your repositories</code>.
- Klicken Sie auf der rechten Seite des Bildschirms auf <code className="action">New</code>.

Legen Sie einen Namen für Ihr Repository fest und geben Sie die angeforderten Informationen ein.

:::warning
Aktivieren Sie die Option `Add a README file`, damit GitHub Ihr Repository korrekt initialisiert.

:::

Klicken Sie abschließend auf <code className="action">Create Repository</code>.

Kopieren Sie die Adresse Ihres GitHub-Repositorys. Diese muss folgende Form haben:

- `https://github.com/<username>/<repository_name>.git` für ein öffentliches Repository.
- `git@github.com:<username>/<repository_name>.git` für ein privates Repository.

Kehren Sie zum Bereich **Git-Konfiguration** zurück und fügen Sie die Adresse Ihres GitHub-Repositorys in das Feld **Repository** ein. Sie muss das Format `https://github.com/<username>/<repository_name>.git` für ein öffentliches Repository oder `git@github.com:<username>/<repository_name>.git` für ein privates Repository haben. Solange die Adresse keines dieser Formate hat und das Feld **Branch** leer ist, bleibt der Button <code className="action">Konfiguration anwenden</code> inaktiv.

Legen Sie nun den Zweig Ihres GitHub-Repositorys fest. Die Standardverzweigung ist `main`. Wenn Sie jedoch eine andere Verzweigung verwenden möchten, erstellen Sie eine auf GitHub, indem Sie die folgenden Schritte ausführen:

- Melden Sie sich bei Ihrem GitHub-Account an.
- Klicken Sie oben rechts auf Ihr Profilbild und dann auf <code className="action">Your repositories</code>.
- Gehen Sie zum betreffenden GitHub-Repository.
- Klicken Sie auf <code className="action">Main</code> und dann auf <code className="action">View all branches</code>, oder klicken Sie direkt auf den Tab <code className="action">x branch</code>.
- Klicken Sie rechts auf dem Bildschirm auf <code className="action">New branch</code>.
- Geben Sie den Namen der neuen Verzweigung an und bestätigen Sie dies durch Klicken auf <code className="action">Create new branch</code>.

Kehren Sie zum Bereich **Git-Konfiguration** in der OVHcloud Konsole zurück und geben Sie im Feld **Branch** den Namen des gerade erstellten neuen Branches ein.

Wenn Sie die Adresse eines privaten GitHub-Repositorys (Typ `git@github.com:<username>/<repository_name>.git`) eingeben, wird unterhalb des Felds **Repository** ein Kasten **SSH-Schlüssel (privates Repository)** angezeigt.

<img className="thumbnail" alt="Kasten SSH-Schlüssel (privates Repository) für eine private Repository-Adresse" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/configure-ssh-key.png" loading="lazy" />

Um Ihren SSH-Schlüssel zu konfigurieren, folgen Sie dem Schritt "Einen SSH-Schlüssel mit GitHub verbinden (nur für private GitHub-Repositorys)".

#### Einen SSH-Schlüssel mit GitHub verbinden (nur für private GitHub-Repositorys) <a name="linkSSHKey"></a>

:::info
**Warum wird der SSH-Schlüssel nur für ein privates Repository benötigt?**

Wenn Ihr GitHub-Repository öffentlich ist, können die Dateien ohne Authentifizierung abgerufen werden, was bedeutet, dass Git den Code klonen und aktualisieren kann, ohne einen SSH-Schlüssel zu benötigen. Wenn Ihr Repository jedoch privat ist, verlangt GitHub eine Authentifizierung, um darauf zuzugreifen. Der SSH-Schlüssel stellt dann diese sichere Verbindung her und gewährleistet, dass nur autorisierte Benutzer mit dem Repository interagieren können.

:::

:::info
Die Erstellung eines SSH-Schlüssels ist ein wichtiger Schritt, da er eine sichere verschlüsselte Verbindung zwischen dem Verzeichnis Ihrer Website und dem GitHub-Repository herstellt. Dieser Schlüssel stellt sicher, dass Datenübertragungen und Codeänderungen sicher und authentifiziert erfolgen, um unbefugten Zugriff zu verhindern und die Codeintegrität zu gewährleisten.

:::

Kopieren Sie den im Kasten **SSH-Schlüssel (privates Repository)** angezeigten SSH-Schlüssel, indem Sie rechts auf den Kopier-Button klicken.

<img className="thumbnail" alt="Kasten SSH-Schlüssel (privates Repository) und Kopier-Button" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/configure-ssh-key.png" loading="lazy" />

Fügen Sie diesen öffentlichen Schlüssel, wie in der Konsole angegeben, als Deployment-Schlüssel ("Deploy key") in den Einstellungen Ihres GitHub-Repositorys hinzu:

- Loggen Sie sich in Ihren GitHub-Account ein und öffnen Sie das betreffende Repository.
- Klicken Sie auf den Tab <code className="action">Settings</code> des Repositorys und dann in der linken Spalte auf <code className="action">Deploy keys</code>.
- Klicken Sie auf <code className="action">Add deploy key</code>.

Das Formular zum Hinzufügen eines Deployment-Schlüssels wird angezeigt:

- **Title**: Geben Sie eine Beschreibung für Ihren SSH-Schlüssel ein. Sie können diesen Schlüssel zum Beispiel "OVHcloud" nennen.
- **Key**: Fügen Sie Ihren SSH-Schlüssel ein.
- **Allow write access**: Lassen Sie dieses Kästchen deaktiviert, da das Deployment nur Lesezugriff auf Ihr Repository benötigt.

Um die Informationen zu bestätigen, klicken Sie auf <code className="action">Add key</code>. Wenn Sie dazu aufgefordert werden, bestätigen Sie den Zugriff auf Ihren Account in GitHub.

#### Automatische Bereitstellung konfigurieren

Unten im Bereich **Git-Konfiguration** zeigt der Abschnitt **Ihre automatische Bereitstellung konfigurieren** die Webhook-URL mit einem Kopier-Button an. Mit der Konfiguration eines Webhooks kann Ihr GitHub-Repository Ihr OVHcloud Webhosting automatisch über Ereignisse im GitHub-Repository benachrichtigen (neues Deployment, Änderung im Code usw.). Diese Funktion ist besonders nützlich, wenn Sie in einer Gruppe am selben Projekt arbeiten und über alle Änderungen am GitHub-Repository auf dem Laufenden bleiben möchten. Weitere Informationen finden Sie unter [Webhook auf GitHub konfigurieren](#configureWebhook).

#### Git-Zuordnung überprüfen

Bevor Sie den Bereich **Git-Konfiguration** bestätigen, stellen Sie sicher, dass:

- Ihr SSH-Schlüssel als Deployment-Schlüssel Ihres GitHub-Repositorys hinzugefügt wurde (nur privates Repository).
- die Adresse Ihres GitHub-Repositorys korrekt ist. Sie muss das Format `https://github.com/<username>/<repository_name>.git` (öffentliches Repository) oder `git@github.com:<username>/<repository_name>.git` (privates Repository) haben.
- Der Zweigname des GitHub-Repositorys ist korrekt.
- das Stammverzeichnis Ihrer Website leer ist: Andernfalls schlägt das Deployment fehl.

Um die Informationen zu bestätigen, klicken Sie auf <code className="action">Konfiguration anwenden</code>.

### Git-Zuordnung aktivieren

#### Git-Assoziierung - Erfolg

Nachdem Sie auf <code className="action">Konfiguration anwenden</code> geklickt haben, schließt sich der Bereich und eine Meldung bestätigt, dass die Git-Konfiguration angewendet wurde. In der Spalte **Git** der Tabelle im Tab <code className="action">Meine Websites</code> erscheint in der Zeile der betreffenden Website der Hinweis **Wird konfiguriert…**: Git wird aktiviert. Der Vorgang kann einige Minuten dauern, und die Tabelle wird automatisch aktualisiert.

<img className="thumbnail" alt="Spalte Git mit dem Hinweis Wird konfiguriert…" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/git-configuring.png" loading="lazy" />

Sobald die Git-Verknüpfung abgeschlossen ist, wird in der Spalte **Git** der betreffenden Website der Status **Aktiv** angezeigt.

<img className="thumbnail" alt="Spalte Git mit dem Status Aktiv" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/sites-git-column.png" loading="lazy" />

#### Fehler bei der Git-Zuordnung

Wenn in der Spalte **Git** der Tabelle im Tab <code className="action">Meine Websites</code> in der Zeile der Website, die Sie mit Git verknüpfen möchten, der Hinweis **Fehler** erscheint, ist mindestens einer der folgenden Fehler aufgetreten:

- Der SSH-Schlüssel wurde nicht als Deployment-Schlüssel Ihres GitHub-Repositorys hinzugefügt (privates Repository).
- Das Stammverzeichnis der Website war zum Zeitpunkt der Verknüpfung nicht leer.
- Die GitHub-Repository-Adresse ist nicht vorhanden oder falsch.
- Der Zweig des GitHub-Repositorys ist nicht vorhanden, oder der Name ist falsch.

Um die Ursache des Fehlers zu ermitteln, klicken Sie auf den Hinweis **Fehler**. Der Bereich **Fehler beim Git-Deployment** öffnet sich: Es zeigt das konfigurierte Repository und den konfigurierten Branch, häufige Ursachen sowie die Informationen zur letzten Bereitstellung an.

<img className="thumbnail" alt="Bereich Fehler beim Git-Deployment" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/error-drawer.png" loading="lazy" />

Sobald die Ursache behoben ist, wählen Sie eine der Aktionen im Bereich **Was Sie tun können**: <code className="action">Erneut starten</code>, um das Deployment (oder die Verknüpfung) erneut zu starten, <code className="action">Bearbeiten</code>, um die Konfiguration zu korrigieren, oder <code className="action">Löschen</code>, um die Verknüpfung zu löschen, bevor Sie Git erneut verknüpfen.

#### Webhook konfigurieren <a name="configureWebhook"></a>

Melden Sie sich bei Ihrem GitHub-Account an und greifen Sie auf das Repository zu, in dem Sie den Webhook konfigurieren möchten. Gehen Sie auf den Tab <code className="action">Settings</code> und klicken Sie dann im Seitenmenü der Einstellungen auf <code className="action">Webhooks</code>. Klicken Sie auf <code className="action">Add webhook</code>, um auf das Formular zuzugreifen:

- **Payload URL**: Geben Sie die Webhook-URL ein, die Sie aus dem Bereich **Git-Konfiguration** der OVHcloud Konsole kopiert haben.
- **Content type**: Wählen Sie <code className="action">application/json</code> als Content-Typ für die gesendeten Daten.
- **Secret**: Dies ist optional. GitHub wird diese Funktion zum Signieren von Webhook-Nachrichten verwenden und so die Sicherheit erhöhen.
- **SSL Verification**: Wenn Ihre Website HTTPS unterstützt, lassen Sie diese Option aktiviert, um die Sicherheit zu erhöhen.
- **Which events would you like to trigger this webhook?**: Wählen Sie die Ereignisse aus, die den Versand des Webhooks auslösen. Für die automatische Bereitstellung ist <code className="action">Just the Push event</code> (Nur das Push-Ereignis) oft ausreichend, aber Sie können <code className="action">Send me everything</code> auswählen, um Benachrichtigungen für alle Ereignisse zu erhalten.
- **Active**: Vergewissern Sie sich, dass diese Option aktiviert ist, um den Webhook zu aktivieren.

Klicken Sie auf <code className="action">Add webhook</code>, um Ihren neuen Webhook zu speichern und zu aktivieren.

#### Webhook testen

Nachdem Sie Ihren Webhook in GitHub erstellt haben, gehen Sie in die Liste Ihrer Webhooks und wählen Sie den soeben erstellten aus, oder klicken Sie auf <code className="action">Edit</code>.

Klicken Sie auf den Tab <code className="action">Recent Deliveries</code>. Um ein bestimmtes Testereignis zu senden, sendet GitHub normalerweise ein `ping`-Ereignis beim Erstellen des Webhooks, und Sie können die Schaltfläche <code className="action">Redeliver</code> neben dem Ereignis verwenden, um es zu testen.

Wenn der Test erfolgreich war, gibt <code className="action">Response</code> einen Code 200 zurück. Wenn ein Fehlercode zurückgegeben wird (normalerweise 500 oder 400), bedeutet dies, dass Ihr Webhook falsch konfiguriert wurde. Gehen Sie zurück zum Formular zum Hinzufügen eines Webhooks und überprüfen Sie die Informationen, insbesondere die von OVHcloud bereitgestellte Webhook-URL.

#### Webhook verwenden

Sobald Ihr Webhook eingerichtet ist, wird der Code Ihrer Website bei jeder Änderung im GitHub-Repository automatisch aktualisiert. Wenn zum Beispiel ein Kollege Änderungen am GitHub-Repository vornimmt, wird der Code Ihrer Website lokal aktualisiert (auf Ihrem OVHcloud Hosting).

### Fazit

Sie haben den Code Ihrer Website über Ihr GitHub-Repository mit Git verbunden. Sie können nun die am GitHub-Repository vorgenommenen Änderungen auf Ihrem Webhosting deployen oder sie mithilfe des Webhooks automatisiert deployen, die Logs Ihrer Deployments einsehen und zahlreiche Aktionen durchführen. All dies erfolgt mit nur wenigen Klicks über Ihre OVHcloud Konsole.
