## Ziel

Bei der Nutzung von Datenbanken können Unregelmäßigkeiten auftreten. Fehler beim Datenbankzugriff werden entweder direkt auf Ihrer Website oder in Ihrem <ManagerLink to="/">OVHcloud Kundencenter</ManagerLink> sowie im [phpMyAdmin Interface](/guides/web-cloud/web-hosting/sql-create-database) angezeigt.

**Diese Anleitung erklärt, wie Sie Fehler bei der Verwendung von Datenbanken mit OVHcloud Webhostings beheben können.**

:::warning
OVHcloud stellt Ihnen Dienstleistungen zur Verfügung, für deren Konfiguration und Verwaltung Sie die alleinige Verantwortung tragen. Es liegt somit bei Ihnen, sicherzustellen, dass diese ordnungsgemäß funktionieren.

Diese Anleitung soll Sie bei allgemeinen Aufgaben bestmöglich unterstützen. Dennoch empfehlen wir Ihnen, falls Sie Hilfe brauchen, einen [spezialisierten Dienstleister](/links/partner) zu kontaktieren und/oder Ihre Fragen in der OVHcloud Community zu stellen. Leider können wir Ihnen für administrative Aufgaben keine weitergehende technische Unterstützung anbieten. Weitere Informationen finden Sie im Abschnitt [Weiterführende Informationen](#go-further) dieser Anleitung.
:::

## Voraussetzungen

#### Verbindungsdaten Ihrer Datenbank überprüfen <a name="config_file"></a>

Verbinden Sie sich über [FTP](/guides/web-cloud/web-hosting/ftp-connection) mit dem Hosting-Speicherplatz und bearbeiten Sie die Konfigurationsdatei Ihrer Website (bei einer WordPress-Seite wäre es beispielsweise die Datei **wp-config.php** in dem Verzeichnis Ihrer Website).

:::warning
Der Name und der Inhalt der für die Datenbankverbindungsinformationen relevanten Datei hängt von dem für die Website verwendeten CMS ab. Dies liegt nicht im Verantwortungsbereich von OVHcloud.

Wir empfehlen Ihnen daher, die Ressourcen des [CMS-Anbieters](/guides/web-cloud/web-hosting/cms-install-1-click-modules) heranzuziehen oder bei Bedarf einen [spezialisierten Dienstleister](/links/partner) zu kontaktieren. Für externe Dienstleistungen können wir Ihnen leider keine Unterstützung anbieten.
:::

Stellen Sie anschließend die **exakte** Übereinstimmung zwischen den Verbindungsinformationen zu [phpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database#auf-das-phpmyadmin-interface-zugreifen) und denen der Konfigurationsdatei Ihrer Website sicher.

Ändern Sie bei Bedarf das [Passwort Ihrer Datenbank](/guides/web-cloud/web-hosting/sql-change-password).

#### Beispiel für WordPress

Wenn Ihre Website einen Fehler des Typs **"Error establishing a database connection"** ausgibt und die zugehörige Infrastruktur nicht von einer [Störung](https://web-cloud.status-ovhcloud.com/) betroffen ist, loggen Sie sich mit [FTP](/guides/web-cloud/web-hosting/ftp-connection) ein und öffnen Sie dann das Verzeichnis, in dem sich die Website befindet (`www` im Standardfall).

Wenn es sich um eine WordPress Website handelt, öffnen Sie die Datei `wp-config.php`.

```php
define('DB_NAME', 'my_database');

/** MySQL database username */
define('DB_USER', 'my_user');

/** MySQL database password */
define('DB_PASSWORD', 'my_password');

/** MySQL hostname */
define('DB_HOST', 'my_server.mysql.db:port');
```

Klicken Sie auf die Tabs, um die **2** Schritte nacheinander anzuzeigen.

    <img className="thumbnail" alt="Hosting-Pakete" src="/images/assets/screens/control-panel/product-selection/web-cloud/hosting-plans.png" loading="lazy" />
  </Tab>
  <Tab label="Schritt 2">
    Klicken Sie auf den Tab <code className="action">Datenbanken</code> und prüfen Sie die Übereinstimmung der hier angezeigten Elemente mit den Daten in der Datei `wp-config.php`:

    - **my_database** muss dem `Namen der Datenbank` entsprechen;
    - **my_user** muss dem `Benutzernamen` entsprechen;
    - **my_password** entspricht dem [Passwort Ihrer Datenbank](/guides/web-cloud/web-hosting/sql-change-password);
    - **my_server.mysql.db** muss dem entsprechen, was unter `Server-Adresse` angegeben ist.
  </Tab>
</Tabs>

:::info
Wenn Sie mit diesen Änderungen den Zugriff auf Ihre Website nicht wiederherstellen können, legen Sie ein [Datenbank-Backup an](/guides/web-cloud/web-hosting/sql-database-export) und setzen Sie dann in Ihrem <ManagerLink to="/">OVHcloud Kundencenter</ManagerLink> die Datenbank [auf einen früheren Zeitpunkt zurück](/guides/web-cloud/databases/db-restore-import-database#ein-bestehendes-backup-wiederherstellen).

### Überschreitung der Datenbank-Quota

Sie haben eine E-Mail darüber erhalten, dass die Datenmenge Ihrer Datenbank die erlaubte Grenze überschreitet. Ihre Datenbank wurde deshalb auf Read-only gesetzt, was Änderungen an der Website verhindert.

<img className="thumbnail" alt="database-overquota-notification-email" src="/images/assets/screens/email-sending-to-customer/databases/overquota-db.png" loading="lazy" />

Sie können Ihre Datenbank mit drei Methoden entsperren.

#### Methode 1: Ihren Dienst upgraden

Wenn Sie über ein Webhosting **Starter** oder **Basic** verfügen, empfehlen wir Ihnen, auf das [nächsthöhere Hosting-Angebot](/links/web/hosting) umzusteigen. Diese Erweiterung erhöht auch die Größe Ihrer Datenbank, was sie automatisch wieder öffnet. Diese Methode ist die einfachste und erfordert keine besondere technische Kompetenz.

:::warning
Die Vergrößerung Ihrer Datenbank kann auf eine Fehlfunktion im internen Code Ihrer Website zurückzuführen sein.

In diesem Fall wäre ein Wechsel des Webhosting-Abos wirkungslos, da Ihre Datenbank weiter anschwellen würde.

Daher empfehlen wir Ihnen, falls Sie eine plötzliche Vergrößerung Ihrer Datenbank feststellen oder wenn Sie beispielsweise nur einen Blog betreiben, der nicht viel Datenvolumen verbraucht, sobald möglich einen [spezialisierten Dienstleister](/links/partner) zu kontaktieren. Wir werden Ihnen in dieser Angelegenheit nicht weiterhelfen können.
:::

Um diese Änderung durchzuführen, klicken Sie auf die Tabs, um die **3** Schritte nacheinander anzuzeigen.

#### Methode 2: Ihre Daten auf eine größere Datenbank übertragen <a name="method2"></a>

Sie können Ihre Daten auch auf eine neue Datenbank migrieren:

- Wenn nötig, bestellen Sie einen [Datenbank-Dienst](/links/web/hosting-options-startsql) mit höherer Kapazität und [erstellen Sie die neue Datenbank](/guides/web-cloud/web-hosting/sql-create-database);
- [Duplizieren Sie den Inhalt der alten Datenbank](/guides/web-cloud/web-hosting/copy-database) in die neue **oder** führen Sie einen [Export Ihrer Daten](/guides/web-cloud/web-hosting/sql-database-export) durch und [importieren Sie diese](/guides/web-cloud/web-hosting/sql-importing-mysql-database) in die neue Datenbank;
- Integrieren Sie die Login-Daten der neuen Datenbank in die [Konfigurationsdatei](#config_file) Ihrer Website.

:::info
Wenn Sie über ein **Performance**, **Agency**, **Agency Plus** oder **Agency Max** Hosting-Paket verfügen, können Sie auch [kostenlos einen Web Cloud Databases Server aktivieren](/guides/web-cloud/databases/db-getting-started).
:::

### Fehler beim Import von Datenbanken

#### "Access denied for user to database"

>
> **"#1044 - Access denied for user to database"**
>

Diese Fehlermeldung bedeutet, dass die Datenbank, die Sie zu importieren versuchen, Elemente enthält, die auf der Shared Hosting Infrastruktur von OVHcloud nicht zulässig sind.

Vergewissern Sie sich zunächst, dass Ihre Datenbank leer ist. Klicken Sie dazu auf die Tabs, um die **3** Schritte nacheinander anzuzeigen.

<Tabs>
  <Tab label="Schritt 1">
    Gehen Sie auf die Seite <ManagerLink to="/#/web/hosting">Hosting-Pakete</ManagerLink> und wählen Sie das betreffende Webhosting aus.

    <img className="thumbnail" alt="Hosting-Pakete" src="/images/assets/screens/control-panel/product-selection/web-cloud/hosting-plans.png" loading="lazy" />
  </Tab>
  <Tab label="Schritt 2">
    Klicken Sie auf den Tab <code className="action">Datenbanken</code>, dann auf den Button <code className="action">...</code> neben der betreffenden Datenbank und auf <code className="action">Quota neu berechnen</code>.
  </Tab>
  <Tab label="Schritt 3">
    Wenn die Datenbank nicht leer ist, [sichern Sie die vorhandenen Daten](/guides/web-cloud/web-hosting/sql-database-export) und löschen Sie diese, bevor Sie den Import erneut starten.

    Sie können beim [Datenbank-Import](/guides/web-cloud/web-hosting/sql-importing-mysql-database#eigene-backup-datei-uber-das-kundencenter-importieren) auch die Option <code className="action">Aktuelle Datenbank leeren</code> anhaken:

    <img className="thumbnail" alt="import-empty-current-db" src="/images/assets/screens/control-panel/product-selection/web-cloud/web-hosting/databases/import-empty-current-db.png" loading="lazy" />
  </Tab>
</Tabs>

Kontaktieren Sie gegebenenfalls unsere [Community](/links/community) oder einen [spezialisierten Dienstleister](/links/partner). Wir werden Sie in diesem Fall nicht unterstützen können.

:::info
**Welche Elemente im Importskript meiner Datenbank können einen Fehler "#1044 - Access denied for user to database" verursachen?**
:::

Sie können keinen **Trigger** im Importskript Ihrer Datenbank auf den Shared Hosting Servern von OVHcloud verwenden. Importieren Sie in diesem Fall Ihre Datenbank auf einen [Web Cloud Databases Server](/guides/web-cloud/databases/db-getting-started).

Außerdem ist folgende Abfrage nicht zulässig:

```sql
CREATE DATABASE IF NOT EXISTS `Database-Name` DEFAULT CHARACTER SET latin1 COLLATE latin1_swedish_ci;
```

Verwenden Sie stattdessen diese Zeile:

```sql
USE `Database-Name`;
```

Ersetzen Sie `Database-Name` mit dem Namen der Datenbank aus Ihrem <ManagerLink to="/">OVHcloud Kundencenter</ManagerLink>.

#### "MySQL server has gone away"

>
> **"ERROR 2006 : MySQL server has gone away"**
>

Diese Fehlermeldung wird beim [Import einer Datenbank](/guides/web-cloud/databases/db-restore-import-database#eine-lokale-sicherung-importieren) auf einem [Web Cloud Databases Server](/guides/web-cloud/databases/db-getting-started) angezeigt. Dies hängt meist mit der Menge der zu importierenden Daten oder mit einer mangelnden Optimierung der SQL-Abfragen im Importskript zusammen.

Um dieses Problem zu beheben, können Sie folgende Maßnahmen anwenden:

- Erhöhen Sie die [Arbeitsspeicherkapazität (RAM)](/guides/web-cloud/databases/db-configure-optimise-database-server#modify-ram-web-cloud-db). Klicken Sie dazu auf die Tabs, um die **3** Schritte nacheinander anzuzeigen.

<Tabs>
  <Tab label="Schritt 1">
    Gehen Sie auf die Seite <ManagerLink to="/#/web/web/private_database">Web Cloud Databases</ManagerLink> und wählen Sie den betreffenden Dienst aus.

    <img className="thumbnail" alt="Auswahl eines Web Cloud Databases Servers im OVHcloud Kundencenter" src="/images/assets/screens/control-panel/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />
  </Tab>
  <Tab label="Schritt 2">
    Im Tab <code className="action">Allgemeine Informationen</code> finden Sie den Bereich `RAM`.
  </Tab>
  <Tab label="Schritt 3">
    Klicken Sie auf den Button <code className="action">...</code> im Bereich `RAM`, dann auf <code className="action">RAM-Menge ändern</code>.
  </Tab>
</Tabs>

- Splitten Sie Ihre Datenbank, um sie dann über mehrere Operationen statt in einem Schritt zu importieren. (Für Fragen zu den durchzuführenden Operationen kontaktieren Sie unsere [Community](/links/community) oder die [OVHcloud Partner](/links/partner). Für externe Dienstleistungen können wir Ihnen leider keine Unterstützung anbieten.)

- [Optimieren Sie Ihre Datenbank](/guides/web-cloud/databases/db-configure-optimise-database-server#ihre-datenbanken-optimieren) und wiederholen Sie die Export/Import-Operationen.

### Kein Zugriff auf phpMyAdmin

#### "Access denied for user"

>
> **"mysqli::real_connect(): (HY000/1045): Access denied for user"**
>

Diese Fehlermeldung kann bei der Verbindung zu Ihrer Datenbank mit [phpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database#auf-das-phpmyadmin-interface-zugreifen) angezeigt werden. Sie gibt an, dass die eingegebenen Login-Daten falsch sind.

<img className="thumbnail" alt="access_denied_for_user" src="/images/assets/screens/other/web-tools/phpmyadmin/pma-error-hy000-1045.png" loading="lazy" />

Überprüfen Sie in diesem Fall die [eingegebenen Login-Daten](/guides/web-cloud/databases/db-connecting-database-server#in-der-praktischen-anwendung) und ändern Sie bei Bedarf das [Passwort Ihrer Datenbank](/guides/web-cloud/web-hosting/sql-change-password).

#### "Too many connections"

>
> **"mysqli_real_connect(): (HY000/1040): Too many connections"**
>

Die maximale Anzahl an aktiven Verbindungen für die mit den Shared Hosting Angeboten gelieferten Datenbanken ([Start SQL](/links/web/hosting-options-startsql)) beträgt **30**.

Diese Zahl erhöht sich auf **200** für den [Web Cloud Databases Dienst](/guides/web-cloud/databases/db-getting-started). (Diese Einstellung kann im Bereich <code className="action">Konfiguration</code> Ihres Datenbankdienstes geändert werden.)

Eine "Too many connections"-Meldung erscheint bei der [Verbindung über phpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database#auf-das-phpmyadmin-interface-zugreifen), wenn diese maximale Anzahl an Verbindungen überschritten wird.

In dieser Situation müssen Sie [Ihre Datenbanken optimieren](/guides/web-cloud/databases/db-configure-optimise-database-server#ihre-datenbanken-optimieren), um die Anzahl der aktiven Verbindungen zu reduzieren.

:::warning
Wenn Sie Fragen zu den notwendigen Schritten zur Reduzierung der Anzahl aktiver Verbindungen auf Ihrer Datenbank haben, kontaktieren Sie unsere [Community](/links/community) oder die [OVHcloud Partner](/links/partner). Für externe Dienstleistungen können wir Ihnen leider keine Unterstützung anbieten.
:::

### "Name or service not known"

>
> **"mysqli::real_connect(): (HY000/2002): php_network_getaddresses: getaddrinfo failed: Name or service not known"**
>

Diese Fehlermeldung wird bei der [Verbindung über phpMyAdmin](/guides/web-cloud/databases/db-connecting-database-server) angezeigt, wenn der angegebene Servername nicht korrekt ist.

### Anmeldung bei einer Cloud Databases-Datenbank nicht möglich

Ein [Web Cloud Databases](/guides/web-cloud/databases/overview) Server erlaubt es, sich von Ihrem Computer oder einem Server außerhalb der Infrastruktur von OVHcloud mit Ihren Datenbanken zu [verbinden](/guides/web-cloud/databases/db-connecting-database-server).

Wenn diese Verbindung nicht möglich ist, überprüfen Sie zunächst, dass [Ihre öffentliche IP-Adresse autorisiert ist](/guides/web-cloud/databases/db-getting-started), die Verbindung zum Datenbankserver herzustellen.

Wenn dies der Fall ist, wenden Sie sich an Ihren Internetdienstanbieter oder die [OVHcloud Partner](/links/partner). In dieser Situation können wir Ihnen leider keine Unterstützung anbieten.
