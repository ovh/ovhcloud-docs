## Ziel

Ein Receive Connector legt fest, welche Server E-Mails an Ihre Exchange Plattform zustellen dürfen und unter welchen Bedingungen. Damit können Sie Ihrer Exchange Plattform eine externe Anti-Spam-Lösung vorschalten, die auch als Filter-Gateway bezeichnet wird: Die <Tooltip term="mxRecord">MX-Einträge</Tooltip> Ihres Domainnamens verweisen auf dieses Gateway, das die eingehenden E-Mails filtert und anschließend an Exchange weiterleitet.

Der Receive Connector ist für [Private Exchange](/links/web/emails-private-exchange) und [Trusted Exchange](/links/web/emails-trusted-exchange) verfügbar. Er kann ausschließlich über die OVHcloud API erstellt und verwaltet werden.

**Diese Anleitung erklärt, wie Sie einen Receive Connector auf Ihrer Exchange Plattform über die OVHcloud API erstellen, bearbeiten, deaktivieren und löschen.**

:::info
Um die **ausgehenden** E-Mails Ihrer Plattform über einen externen Server zu leiten, verwenden Sie stattdessen einen Send Connector: Lesen Sie dazu unsere Anleitung "[Exchange - Einen Send Connector konfigurieren](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/feature-send-connector)".
:::

## Voraussetzungen

- Sie verfügen über eine [Private Exchange](/links/web/emails-private-exchange) oder [Trusted Exchange](/links/web/emails-trusted-exchange) Plattform.
- Sie haben API-Zugangsdaten auf der <CreateToken rights="GET=/email/exchange&GET=/email/exchange/*&POST=/email/exchange/*&PUT=/email/exchange/*&PATCH=/email/exchange/*&DELETE=/email/exchange/*">Seite zur Erstellung von OVHcloud Tokens</CreateToken> generiert, mit mindestens dem Recht `GET` auf `/email/exchange` und den Rechten `GET`, `POST`, `PUT`, `PATCH` und `DELETE` auf `/email/exchange/*`. Lesen Sie dazu unsere Anleitung "[Erste Schritte mit der OVHcloud API](/guides/manage-and-operate/api/first-steps)".
- Sie kennen die IP-Adressen der Server Ihrer externen Anti-Spam-Lösung, die E-Mails an Exchange zustellen werden. Fragen Sie den Anbieter dieser Lösung danach.

## In der praktischen Anwendung

### Den Standard-Receive-Connector verstehen

Jede Exchange Plattform verfügt über einen Standard-Receive-Connector. Er gehört zu Exchange: Sie können ihn weder bearbeiten noch löschen, sondern nur aktivieren oder deaktivieren. In der API hat seine Eigenschaft `default` den Wert `true`.

Solange er aktiviert ist, nimmt Ihre Plattform alle eingehenden E-Mails an, unabhängig davon, welcher Server sie zustellt: Ein von Ihnen erstellter Receive Connector hat dann keine Wirkung. Damit nur Ihr Gateway E-Mails an Exchange zustellen kann, deaktivieren Sie den Standard-Receive-Connector selbst. Er wird nie automatisch deaktiviert, um eine abrupte Unterbrechung des E-Mail-Empfangs zu vermeiden.

:::warning
**Deaktivieren Sie den Standard-Receive-Connector zuletzt.** Wenn kein anderer aktivierter Connector greift, stoppt seine Deaktivierung den Empfang aller E-Mails auf der Plattform. Überprüfen Sie vor der Deaktivierung, dass Ihr Receive Connector aktiviert ist und die MX-Einträge Ihres Domainnamens auf Ihr Gateway verweisen.
:::

### Pfadparameter ermitteln

Die Aufrufe für den Receive Connector benötigen den Namen der Organisation (`organizationName`) und den Namen des Dienstes (`exchangeService`) Ihrer Plattform. Ermitteln Sie diese der Reihe nach: Der erste der folgenden Aufrufe gibt die Organisation zurück, die der zweite benötigt.

**1. Organisation** (`organizationName`)

Listen Sie die Exchange Organisationen Ihres Accounts mit folgendem API-Aufruf auf:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange"} />

**2. Dienst** (`exchangeService`)

Listen Sie die Exchange Dienste der Organisation mit folgendem API-Aufruf auf:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service"} />

### Receive Connector erstellen

Erstellen Sie den Connector mit folgendem API-Aufruf:

<Api version="v1" section="/email/exchange" method="POST" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector"} regions={["eu"]} />

Füllen Sie im Body der Anfrage die folgenden Felder aus. Nur `name`, `remoteIpRanges` und `requireTls` sind Pflichtfelder.

| Feld | Typ | Beschreibung |
|---|---|---|
| `name` | string | Name des Connectors, höchstens 255 Zeichen |
| `remoteIpRanges` | string[] | IP-Adressen der Server, die E-Mails über diesen Connector zustellen dürfen (siehe unten) |
| `requireTls` | boolean | `true`, um TLS für jede über diesen Connector empfangene E-Mail vorzuschreiben |
| `maxMessageSize` | long | Optional. Maximale Größe einer über diesen Connector empfangenen E-Mail, in MB |
| `enabled` | boolean | Optional. `true`, um den Connector direkt bei seiner Erstellung zu aktivieren (standardmäßig `false`) |

Jeder Eintrag in `remoteIpRanges` kann Folgendes sein:

- eine einzelne IP-Adresse, zum Beispiel `203.0.113.10`;
- ein Netzwerk in CIDR-Notation, zum Beispiel `203.0.113.0/28`;
- ein Adressbereich im Format "Anfang-Ende", einschließlich der Grenzen, zum Beispiel `203.0.113.10-203.0.113.20`.

Es werden sowohl IPv4- als auch IPv6-Adressen akzeptiert.

:::warning
**Einschränkungen für `remoteIpRanges`**

- Dieselbe IP-Adresse kann nicht zu zwei Receive Connectors der Plattform gehören.
- Die gesamte Liste darf 255 Zeichen nicht überschreiten, sobald ihre Einträge durch Kommas verbunden sind. Verwenden Sie lieber ein CIDR-Netzwerk als eine lange Liste einzelner Adressen.

:::

Der Aufruf gibt einen Task zurück: Der Connector ist erstellt, sobald dieser Task abgeschlossen ist.

### Receive Connectors auflisten und anzeigen

Listen Sie die Receive Connectors der Plattform, einschließlich des Standard-Connectors, mit folgendem API-Aufruf auf:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector"} regions={["eu"]} />

Der Aufruf gibt die Liste der Connector-IDs (`id`) zurück. Zeigen Sie die Details eines Connectors mit folgendem API-Aufruf an:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

Zusätzlich zu den bei der Erstellung angegebenen Feldern enthält die Antwort das Feld `id` (die ID des Connectors) sowie das Feld `default`, das beim Standard-Receive-Connector den Wert `true` hat.

### Receive Connector bearbeiten

Um ein oder mehrere Felder zu ändern, ohne die übrigen zu verändern, verwenden Sie folgenden API-Aufruf:

<Api version="v1" section="/email/exchange" method="PATCH" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

Um die gesamte Konfiguration des Connectors zu ersetzen, füllen Sie im folgenden API-Aufruf alle Felder aus:

<Api version="v1" section="/email/exchange" method="PUT" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

:::info
Das Feld `remoteIpRanges` ersetzt die gespeicherte Liste vollständig. Um eine IP-Adresse hinzuzufügen, senden Sie die vollständige Liste: die bestehenden Adressen und die neue Adresse.
:::

Um einen Connector zu aktivieren oder zu deaktivieren, ändern Sie das Feld `enabled`. Beim Standard-Receive-Connector ist dies das einzige Feld, das Sie ändern können: Lesen Sie vor der Deaktivierung den Abschnitt "[Den Standard-Receive-Connector verstehen](#den-standard-receive-connector-verstehen)".

Jede Änderung gibt einen Task zurück: Die Änderung wird wirksam, sobald dieser Task abgeschlossen ist.

### Receive Connector löschen

Löschen Sie einen Connector mit folgendem API-Aufruf:

<Api version="v1" section="/email/exchange" method="DELETE" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

Der Aufruf gibt einen Task zurück: Der Connector ist gelöscht, sobald dieser Task abgeschlossen ist. Sie können den Standard-Receive-Connector nicht löschen.

Wenn Sie den letzten Connector löschen, der nicht der Standard-Receive-Connector ist, wird der Standard-Receive-Connector automatisch wieder aktiviert, um den E-Mail-Empfang nicht zu blockieren. Dieses Verhalten hängt vom Parameter `enableDefaultReceiveConnector` des Aufrufs ab (standardmäßig `true`): Bei `false` bleibt ein deaktivierter Standard-Receive-Connector deaktiviert, und Ihre Plattform empfängt keine E-Mails mehr.
