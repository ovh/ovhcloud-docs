## Ziel

Mit SPF (Sender Policy Framework) kann der empfangende Server überprüfen, ob eine E-Mail von einem vertrauenswürdigen Server gesendet wurde.

<details>

<summary>Warum sollte ich ein SPF für meine E-Mails einrichten?</summary>

- Es hilft dabei, potenziellen Identitätsbetrug über E-Mail-Adressen unter Verwendung Ihres Domainnamens (Spoofing) zu verhindern.
- Sie können es auch verwenden, um die von Ihnen gesendeten E-Mails zu authentifizieren.
- Der SPF wird als Eintrag zur DNS-Zone der Domain hinzugefügt, die zum Versand von E-Mails autorisiert ist.

Diese Prüfung stützt sich auf die Angaben im SPF-Eintrag, einem TXT-Eintrag in der <Tooltip term="dnsZone">DNS-Zone</Tooltip>. Er enthält:

- **Server und/oder IP-Adressen**: Diese werden als legitime Absender-Quellen identifiziert.
- **Ein Qualifikator**: Er teilt dem empfangenden Server mit, wie er mit einer Nachricht aus einer nicht aufgeführten Quelle verfahren soll.

Stellen Sie daher sicher, dass Sie die Absenderquellen, die Sie für den Versand Ihrer E-Mails mit Ihrer Domain verwenden, in den SPF-Eintrag einfügen. Diese Quellen können Ihr eigener E-Mail-Server, der Server Ihres Anbieters oder eine der E-Mail-Lösungen von OVHcloud sein.

> **Beispiel**
>
> Sie senden eine E-Mail von Ihrer Adresse `john.smith@domain.tld`.
>
> Im SPF-Eintrag der Domain `domain.tld` wird nur der ausgehende Server **A** (Outgoing Mail Server **A**) angegeben.
>
> Wenn der empfangende Server (Inbound Mail Server) die E-Mail erhält, fragt er die DNS-Zone Ihrer Domain `domain.tld` ab, um den SPF-Eintrag zu überprüfen.
>
> - Da der ausgehende Server **A** (Outgoing Mail Server **A**) im SPF-Eintrag gut aufgeführt ist, landet die E-Mail wie üblich im Posteingang des Empfängers.
> - Da der ausgehende Server **B** (Outgoing Mail Server **B**) nicht im SPF-Eintrag aufgeführt ist, wird die von diesem Server stammende E-Mail im Posteingang als verdächtig markiert. Je nach den Regeln des Empfangsservers kann dies zu einem Vermerk `[SPAM]` im Betreff der E-Mail, zur Verschiebung in den `Junk-Mail`-Ordner oder zur direkten Löschung führen.
>
> <img className="thumbnail" alt="Schema eines SPF-Abgleichs zwischen dem sendenden Server und dem SPF-Eintrag" src="/images/assets/schemas/emails/spf-records-diagram.png" loading="lazy" />

:::info
SPF bietet nur eine Hilfestellung für alle Server, die E-Mails empfangen. Ob die Angaben im SPF-Eintrag von Domainnamen, über die E-Mails gesendet werden, auch angewendet werden, liegt alleine beim empfangenden Server.

:::

</details>

**Diese Anleitung erklärt, wie Sie einen SPF-Eintrag für Ihre OVHcloud Domain konfigurieren.**

## Voraussetzungen

- Die ausgewählte Domain muss die OVHcloud Konfiguration (d. h. die OVHcloud DNS-Server) verwenden.

[[cpnav:web-domain-dns-zone]]

:::warning
Wenn Ihre Domain keine OVHcloud DNS-Server verwendet, ändern Sie den SPF-Eintrag über das Interface des Dienstleisters, der das DNS Ihrer Domain verwaltet.

Wenn Ihr Domainname bei OVHcloud registriert ist, können Sie über die Seite <ManagerLink to="/beta/#/web-cloud/domains/listing">Domains & DNS</ManagerLink> im betreffenden Domainnamen überprüfen, ob er die OVHcloud Konfiguration verwendet: Der Abschnitt **DNS-Konfiguration** des Tabs <code className="action">Übersicht</code> zeigt dies an.

:::

## In der praktischen Anwendung

### Überprüfung Ihrer aktuellen SPF-Konfiguration

Wenn Ihre Domain OVHcloud DNS-Server verwendet, können Sie überprüfen, ob bereits ein SPF-Eintrag dafür konfiguriert ist.

<details>

<summary>Wie überprüfe ich eine vorhandene SPF-Konfiguration?</summary>

Gehen Sie auf die Seite <ManagerLink to="/beta/#/web-cloud/domains/listing">Domains & DNS</ManagerLink>, wählen Sie den betreffenden Domainnamen aus und klicken Sie dann auf den Tab <code className="action">DNS-Zone</code>.

Die Tabelle auf dieser Seite zeigt die <Tooltip term="dnsZone">DNS-Zone</Tooltip> Ihrer Domain bei OVHcloud an. Jede Zeile der Tabelle repräsentiert einen DNS-Eintrag.

:::info
Überprüfen Sie im Zweifelsfall im Abschnitt **DNS-Konfiguration** des Tabs <code className="action">Übersicht</code>, ob Ihr Domainname die OVHcloud DNS-Server verwendet.

:::

Um die Zeile des OVHcloud SPF-Eintrags zu finden, filtern Sie die Tabelle mit dem Button <code className="action">Filter</code>. Da der Eintrag an zwei verschiedenen Stellen erscheinen kann und der Filter jeweils nur einen Typ anzeigt, filtern Sie zuerst nach <code className="action">TXT</code> und dann nach <code className="action">SPF</code>.

<img className="thumbnail" alt="Button Filter und Liste Eintragstyp der DNS-Zone" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/filter-type.png" loading="lazy" />

Sie erhalten eines der folgenden Ergebnisse.

- **Ein SPF-Eintrag für die E-Mail-Lösungen von OVHcloud wird angezeigt**: Ihre Domain verwendet derzeit die OVHcloud Konfiguration. Wenn Sie diese nicht mehr verwenden möchten, müssen Sie sie im [nächsten Schritt](#modifyspf) bearbeiten.

- **Es wird ein SPF-Eintrag angezeigt, der nicht der Konfiguration von OVHcloud entspricht**: Ihre Domain verwendet bereits einen personalisierten SPF. Ist diese Konfiguration nicht korrekt, bearbeiten Sie sie im [nächsten Schritt](#modifyspf) oder wählen Sie die OVHcloud Konfiguration.

- **Es wird kein SPF-Eintrag angezeigt**: Überprüfen Sie zunächst durch Ändern der Filterung, ob der Eintrag nicht unter dem jeweils anderen Typ (SPF oder TXT) existiert. Wenn in der Zone überhaupt kein SPF-Eintrag angezeigt wird, verwendet Ihre Domain derzeit keinen. Sie können ihn im [nächsten Schritt](#spfrecord) hinzufügen.

:::info
<Region zones={['eu']}>

Ein SPF-Eintrag folgt immer dieser Form: "v=spf1 `Quellen` `Qualifikator`". Der SPF für Dienste von OVHcloud ist zum Beispiel: `v=spf1 include:mx.ovh.com ~all`.

</Region>
<Region zones={['ca', 'apac']}>

Ein SPF-Eintrag folgt immer dieser Form: "v=spf1 `Quellen` `Qualifikator`". Der SPF für Dienste von OVHcloud ist zum Beispiel: `v=spf1 include:mx.ovh.ca ~all`.

</Region>

:::

</details>

### Konfiguration eines neuen SPF-Eintrags <a name="spfrecord"></a>

Klicken Sie über der Tabelle auf <code className="action">Eintrag erstellen</code> und wählen Sie dann in der Liste **Typ** <code className="action">SPF — Zum E-Mail-Versand autorisierte Server</code> aus (Abschnitt **E-Mail-Felder**). Es öffnet sich ein Formular, in dem Sie Ihren SPF-Eintrag Feld für Feld erstellen.

<img className="thumbnail" alt="Formular zum Erstellen eines Eintrags in der DNS-Zone, SPF-Eintrag" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/add-spf-record.png" loading="lazy" />

- **Subdomain**: Dieses Feld ist erforderlich. Geben Sie `@` ein, um den SPF-Eintrag auf den gesamten Domainnamen anzuwenden, oder geben Sie eine Subdomain ein, wenn Sie nur von dieser aus E-Mails versenden.
- **Autorisierungsmechanismen**: Aktivieren Sie die Quellen, die E-Mails für Ihren Domainnamen versenden dürfen.
    - **OVH E-Mail-Server einschließen (include:mx.ovh.com)**: Dieses standardmäßig aktivierte Kästchen autorisiert alle ausgehenden E-Mail-Server von OVHcloud auf einmal, indem es `include:mx.ovh.com` einfügt. Lassen Sie es aktiviert, wenn Sie eine [E-Mail-Lösung von OVHcloud](#ovhcloudspfvalue) verwenden, und prüfen Sie in diesem Abschnitt den für Ihre Zone zu verwendenden Wert.
    - **MX-Server der Domain zulassen (mx)**: Autorisiert die Server, die Ihre E-Mails empfangen, diese auch zu versenden.
    - **IP-Adresse der Domain zulassen (a)**: Autorisiert den Server, der Ihren Domainnamen hostet (nützlich, wenn Ihre Website und Ihre E-Mails dieselbe IP-Adresse teilen, zum Beispiel auf einem Dedicated Server).
- **Zusätzliche Server zulassen (include)**: Fügen Sie die SPF-Domains anderer Anbieter hinzu, die in Ihrem Namen E-Mails versenden (Marketing-Plattform, CRM usw.), damit deren Server als legitim behandelt werden.
- **Zugelassene IPv4-Adressen (ip4)** und **Zugelassene IPv6-Adressen (ip6)**: Fügen Sie bestimmte IP-Adressen oder IP-Bereiche hinzu, die zum Versand von E-Mails berechtigt sind.
- **SPF-Richtlinie**: Wählen Sie, wie empfangende Server eine E-Mail behandeln sollen, die von einer **nicht** aufgeführten Quelle gesendet wurde (siehe unsere Empfehlung unten). Der Wert `~all` ("Akzeptieren, aber als verdächtig markieren") ist vorausgewählt und als **Empfohlen** gekennzeichnet.
- <Tooltip term="ttl">**TTL**</Tooltip>: Belassen Sie sie auf `Standardmäßig` oder legen Sie einen Wert fest.

Der Bereich **Datensatzvorschau** zeigt den Eintrag an, während Sie die Felder ausfüllen. Wenn Sie fertig sind, klicken Sie auf <code className="action">Hinzufügen</code>.

:::tip
Sowohl der Wert `~all` als auch der Wert `-all` der **SPF Policy** sind gültig. Für den bestmöglichen Schutz empfehlen wir Ihnen jedoch dringend `-all`. Dieser fordert die Server, die Ihre E-Mails empfangen, auf, jede Nachricht **abzulehnen**, die von einer nicht in Ihrem SPF-Eintrag aufgeführten Quelle stammt.

Wählen Sie `-all` erst, wenn Sie sicher sind, dass Ihr Eintrag **alle** legitimen Versandquellen auflistet: Ihre OVHcloud E-Mail-Lösung, aber auch jeden Drittanbieter, der in Ihrem Namen E-Mails versendet (Marketing-Plattform, CRM, Ticketing-Tool usw.). Fehlt eine legitime Quelle, werden deren E-Mails abgelehnt. Wenn Sie nicht sicher sind, ob die Liste vollständig ist, verwenden Sie `~all`, der diese E-Mails als verdächtig kennzeichnet, anstatt sie abzulehnen.
:::

:::info
<Region zones={['eu']}>

Für eine E-Mail-Lösung von OVHcloud besteht der minimale SPF-Eintrag einfach darin, das standardmäßig aktivierte Kästchen **OVH E-Mail-Server einschließen (include:mx.ovh.com)** aktiviert zu lassen. Dies ergibt `v=spf1 include:mx.ovh.com ~all` (siehe [OVHcloud SPF-Konfiguration für Shared-E-Mail-Angebote](#ovhcloudspfvalue)).

</Region>
<Region zones={['ca', 'apac']}>

Für eine E-Mail-Lösung von OVHcloud lautet der minimale SPF-Eintrag `v=spf1 include:mx.ovh.ca ~all`: Deaktivieren Sie das standardmäßig aktivierte Kästchen **OVH E-Mail-Server einschließen (include:mx.ovh.com)**, das den europäischen Wert `mx.ovh.com` einfügt, und geben Sie dann `mx.ovh.ca` im Feld **Zusätzlich zu autorisierende Server (include)** ein (siehe [OVHcloud SPF-Konfiguration für Shared-E-Mail-Angebote](#ovhcloudspfvalue)).

</Region>

:::

Wenn Sie bereits über die vollständige SPF-Zeichenfolge verfügen (von Ihrem E-Mail-Dienst bereitgestellt) oder ein Tag benötigen, das im Formular nicht vorhanden ist, geben Sie sie direkt ein: Wählen Sie statt SPF den Typ <Tooltip term="txtRecord">**TXT**</Tooltip> (<code className="action">TXT — Freitext (Verifizierung, SPF...)</code>) aus und fügen Sie den vollständigen Wert `v=spf1 …` in das Feld **Wert** ein, oder verwenden Sie den <code className="action">Erweiterter Modus</code> oben im Formular.

:::info
Die Änderung erfordert eine <Tooltip term="dnsPropagation">Propagationszeit</Tooltip> von 4 bis 24 Stunden, bevor sie voll wirksam ist.

:::

### Bearbeiten eines SPF-Eintrags <a name="modifyspf"></a>

Gehen Sie auf die Seite <ManagerLink to="/beta/#/web-cloud/domains/listing">Domains & DNS</ManagerLink>, wählen Sie den betreffenden Domainnamen aus und klicken Sie dann auf den Tab <code className="action">DNS-Zone</code>.

Die Tabelle zeigt die DNS-Zone Ihres Domainnamens an: Jede Zeile entspricht einem DNS-Eintrag. Suchen Sie Ihren TXT- oder SPF-Eintrag in der Tabelle, klicken Sie auf den Button <code className="action">⋮</code> in der Spalte **Aktionen** und dann auf <code className="action">Ändern</code>. Die Zeile wird zu einem Bearbeitungsformular erweitert.

<img className="thumbnail" alt="Aktionsmenü einer Zeile der DNS-Zone" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/row-actions.png" loading="lazy" />

Weitere Informationen zu den SPF-Feldern finden Sie im Abschnitt [Konfiguration eines neuen SPF-Eintrags](#spfrecord).

### OVHcloud SPF-Konfiguration für Shared-E-Mail-Angebote <a name="ovhcloudspfvalue"></a>

Die allgemeine OVHcloud SPF-Konfiguration gilt für folgende Lösungen:

- <Tooltip term="mxPlan">MX Plan</Tooltip> standalone oder in einem [OVHcloud Webhosting](/links/web/hosting) inklusive
<Region zones={['eu']}>
- [E-Mail Pro](/links/web/email-pro)
</Region>
<Region zones={['eu', 'ca']}>
- [Hosted Exchange](/links/web/emails-hosted-exchange)
</Region>

Die Konfiguration lautet:

<Region zones={['eu']}>

```bash
domain.tld IN TXT "v=spf1 include:mx.ovh.com ~all"
```

</Region>
<Region zones={['ca', 'apac']}>

```bash
domain.tld IN TXT "v=spf1 include:mx.ovh.ca ~all"
```

</Region>

<Region zones={['eu', 'ca']}>

### OVHcloud SPF-Konfiguration für Private Exchange

Geben Sie für Private Exchange die IP-Adressen Ihres Servers mit dem Argument `ip4` (IPv4, Eintrag **A**) und dem Argument `ip6` (IPv6, Eintrag **AAAA**) an.

```bash
domain.tld IN TXT "v=spf1 ip4:203.0.113.1 ip6:2001:db8::1 ~all"
```

<Region zones={['eu']}>

Falls Sie zusätzlich einen [Webhosting-E-Mail-Dienst verwenden](#ovhcloudspfvalue), fügen Sie `include:mx.ovh.com` zum Eintrag hinzu:

```bash
domain.tld IN TXT "v=spf1 ip4:203.0.113.1 ip6:2001:db8::1 include:mx.ovh.com ~all"
```

</Region>
<Region zones={['ca', 'apac']}>

Falls Sie zusätzlich einen [Webhosting-E-Mail-Dienst verwenden](#ovhcloudspfvalue), fügen Sie `include:mx.ovh.ca` zum Eintrag hinzu:

```bash
domain.tld IN TXT "v=spf1 ip4:203.0.113.1 ip6:2001:db8::1 include:mx.ovh.ca ~all"
```

</Region>

<details>

<summary>Wie erhalte ich die IP-Adressen eines Private Exchange Servers?</summary>

Gehen Sie auf die Seite <ManagerLink to="/beta/#/web-cloud/email/exchange">Exchange</ManagerLink> und klicken Sie auf den Dienst, dessen **Angebotstyp** **Private Exchange** ist.

Im Tab <code className="action">Übersicht</code>, Karte **Allgemeine Informationen**, zeigt der Bereich **Server-Diagnostik** die Anzeigen `A` und `AAAA` an. Klicken Sie auf <code className="action">Diagnostik anzeigen</code> und dann im sich öffnenden Bereich auf die Tabs <code className="action">A</code> und <code className="action">AAAA</code>: Notieren Sie den unter **Ziel** angezeigten Wert.

<img className="thumbnail" alt="Bereich Server-Diagnostik eines Private Exchange Dienstes, Tab A und sein Ziel" src="/images/assets/screens/console/product-selection/web-cloud/email-and-collaborative-solutions/exchange/server-diagnostics.png" loading="lazy" />

Wenn die Anzeigen `A` und `AAAA` grün sind, zeigt der Bereich "Automatische Konfiguration ausgeführt" an und gibt die IP-Adressen nicht an. Rufen Sie diese dann über die DNS-Zone des Domainnamens ab, der mit Ihrer Private Exchange Plattform verbunden ist. Notieren Sie dazu zunächst die Adresse des Links **Webmail** in der Karte **Allgemeine Informationen**.

<img className="thumbnail" alt="Karte Allgemeine Informationen eines Private Exchange Dienstes, Webmail-Link und Server-Diagnostik" src="/images/assets/screens/console/product-selection/web-cloud/email-and-collaborative-solutions/exchange/general-information.png" loading="lazy" />

Gehen Sie anschließend auf die Seite <ManagerLink to="/beta/#/web-cloud/domains/listing">Domains & DNS</ManagerLink>, wählen Sie den mit Ihrer Private Exchange Plattform verbundenen Domainnamen aus und klicken Sie dann auf den Tab <code className="action">DNS-Zone</code>. Notieren Sie die IPv4- (Eintrag `A`) und IPv6-Adressen (Eintrag `AAAA`), die der Webmail-URL entsprechen.
