:::info
Der MCP-Server von OVHcloud befindet sich in aktiver Entwicklung. Die Liste der verfügbaren Tools wird regelmäßig erweitert: Eine heute fehlende Funktion kann bereits kurze Zeit später verfügbar sein. Den aktuellen Stand finden Sie im [MCP-Hub von OVHcloud](https://mcp.eu.ovhcloud.com/index.html).
:::

## Ziel

Das **Model Context Protocol** (MCP) ist ein offener Standard, mit dem ein KI-Assistent externe Tools nutzen kann. Der MCP-Server von OVHcloud stellt Ihre OVHcloud Dienste als solche Tools bereit, sodass ein Assistent Ihre Konfiguration in Ihrem Namen lesen und ändern kann.

In der Praxis bedeutet das: Statt sich durch Oberflächen zu klicken oder API-Aufrufe zu schreiben, fragen Sie einfach:

```text
Liste meine Domainnamen auf und sage mir, welche davon in den nächsten 60 Tagen ablaufen.
```

**Diese Anleitung erklärt, wie Sie einen KI-Agenten mit dem MCP-Server von OVHcloud verbinden und damit Ihre Domainnamen, DNS-Einträge und Weiterleitungen verwalten.**

## Voraussetzungen

- In Ihrem <ManagerLink to="/">OVHcloud Kundencenter</ManagerLink> angemeldet sein
- Ein installierter, kompatibler MCP-Client (siehe [Ihren Agenten verbinden](#3--ihren-agenten-mit-mcp-verbinden))
- Ein Browser, um die OAuth2-Anmeldung abzuschließen

## In der praktischen Anwendung

### 1 — Funktionsweise von MCP

Daran sind drei Komponenten beteiligt:

| Komponente | Rolle |
|------------|-------|
| **Ihr KI-Agent** | Der Assistent, mit dem Sie sprechen (ein Terminal-Agent, ein IDE-Chat, Ihre eigene Anwendung) |
| **Der MCP-Server von OVHcloud** | Stellt die verfügbaren *Tools* bereit und führt sie auf Ihrem Konto aus |
| **Ihr OVHcloud Konto** | Die Berechtigungen, die bei jedem Aufruf geprüft werden und festlegen, was der Agent tun darf |

Sie rufen ein Tool nie selbst über seinen Namen auf. Sie beschreiben, was Sie erreichen möchten, der Agent wählt das passende Tool aus und bittet Sie um Bestätigung, bevor etwas geändert wird.

:::warning
Ein mit MCP verbundener KI-Agent handelt mit **Ihren** Berechtigungen. Lesen Sie jede Bestätigungsanfrage, bevor Sie sie annehmen, insbesondere bei Vorgängen, die Einträge löschen oder Nameserver ändern.
:::

### 2 — Der MCP-Hub von OVHcloud

Der [MCP-Hub von OVHcloud](https://mcp.eu.ovhcloud.com/index.html) listet die als MCP-Tools bereitgestellten Dienste auf und ist die Referenz dafür, was aktuell verfügbar ist.

Wählen Sie die URL, die der Region Ihres OVHcloud Kontos entspricht:

| Region | URL des MCP-Servers |
|--------|---------------------|
| Europa | `https://mcp.eu.ovhcloud.com/mcp/{section}` |
| Kanada | `https://mcp.ca.ovhcloud.com/mcp/{section}` |

Ersetzen Sie `{section}` durch den Namen des Bereichs, mit dem Sie sich verbinden möchten, so wie er auf den Karten des Hubs angezeigt wird. Sie verbinden sich immer mit einem bestimmten Bereich: Es gibt keine globale URL, die alle Tools auf einmal bereitstellt.

#### Bereiche für Domainnamen

Zwei Bereiche decken Domainnamen ab, einer pro API-Version:

| Bereich | Bereitgestellte Inhalte |
|---------|-------------------------|
| `v1_domain` | Die Domain-Tools der API v1 |
| `v2_domain` | Die Domain-Tools der API v2 |

Für ein europäisches Konto mit der API v1 lautet die zu verwendende URL also `https://mcp.eu.ovhcloud.com/mcp/v1_domain`.

Die API v1 ist nach wie vor die funktional umfangreichste: `v1_domain` stellt daher mehr Tools bereit als `v2_domain`. Die API v2 wird schrittweise erweitert.

Um die Unterschiede zwischen der API v2 und der API v1 zu verstehen, lesen Sie die Anleitung [OVHcloud API v2 - Principles of operation](/guides/manage-and-operate/api/apiv2#as-code-design).

Sie können den einen, den anderen oder beide Bereiche gleichzeitig hinzufügen. `v1_domain` allein genügt für alle Vorgänge dieser Anleitung.

### 3 — Ihren Agenten mit MCP verbinden

Die Authentifizierung erfolgt über **OAuth2**: Beim ersten Kontakt Ihres Agenten mit dem Server öffnet sich ein Browserfenster mit der OVHcloud Login-Seite. Nach Ihrer Anmeldung verwendet der Agent diese Sitzung für seine MCP-Aufrufe weiter.

:::info
Es ist kein eigener HTTP-Header erforderlich: Die Zugangsdaten liefert der OAuth2-Ablauf. Die Einrichtungshinweise von OVHcloud geben vor, den Header-Bereich Ihrer Client-Konfiguration **leer** zu lassen.
:::

<Tabs>
<Tab label="SHAI">

[SHAI](https://github.com/ovh/shai) ist der Terminal-Agent von OVHcloud. Erforderlich ist Version **0.1.5 oder höher**.

Erstellen Sie die folgende Konfigurationsdatei auf Basis der [Vorlage `.ovh.config`](https://github.com/ovh/shai/blob/main/.ovh.config) aus dem SHAI-Repository:

```bash
$HOME/.config/shai/agents/ovh.config
```

Legen Sie unter `tools.mcp` einen Eintrag pro Bereich an, den Sie nutzen möchten. Dieses Beispiel aktiviert beide API-Versionen:

```json
{
  "name": "ovh",
  "description": "OVH agent with OVH MCP server for cloud management and API calls",
  "tools": {
    "builtin": ["*"],
    "builtin_excluded": [],
    "mcp": {
      "v1_domain": {
        "config": {
          "type": "http",
          "url": "https://mcp.eu.ovhcloud.com/mcp/v1_domain"
        },
        "enabled_tools": ["*"]
      },
      "v2_domain": {
        "config": {
          "type": "http",
          "url": "https://mcp.eu.ovhcloud.com/mcp/v2_domain"
        },
        "enabled_tools": ["*"]
      }
    }
  },
  "system_prompt": "{{CODER_BASE_PROMPT}}",
  "max_tokens": 4096,
  "temperature": 0.3
}
```

Ersetzen Sie die Endpunkte durch die Ihrer Region.

:::info
Tragen Sie keine Zugangsdaten von Hand in diese Datei ein. Nach Ihrer Anmeldung schreibt SHAI selbst ein `access_token` und ein `expires_at` in den `config`-Block jedes Servers. Diese Werte sind persönliche, vertrauliche Zugangsdaten: Nehmen Sie diese Datei niemals in die Versionsverwaltung auf und geben Sie sie nie unverändert weiter.
:::

Starten Sie anschließend den Agenten. Ihr Browser öffnet die OVHcloud Login-Seite; melden Sie sich an, um die Verbindung abzuschließen.

</Tab>
<Tab label="Goose">

Am schnellsten geht es über den [MCP-Hub von OVHcloud](https://mcp.eu.ovhcloud.com/index.html): Suchen Sie die Karte **V1 Domain** (oder **V2 Domain**) und klicken Sie auf die Schaltfläche **Add in Goose**. Goose öffnet sich mit bereits ausgefüllter Erweiterung – Name, Endpunkt und Transport – und Sie müssen nur noch bestätigen.

Die Schaltfläche verwendet den Endpunkt desjenigen Hubs, auf dem Sie sich gerade befinden. Vom europäischen Hub aus richtet sie die Erweiterung daher für `https://mcp.eu.ovhcloud.com` ein: Öffnen Sie für ein Konto in Kanada den Hub Ihrer Region oder folgen Sie der manuellen Einrichtung unten.

**Manuelle Einrichtung.** Fügen Sie in Goose eine neue Erweiterung vom Typ **HTTP** hinzu und geben Sie an:

- **URL**: die URL Ihrer Region mit dem gewünschten Bereich, `https://mcp.eu.ovhcloud.com/mcp/v1_domain` oder `https://mcp.eu.ovhcloud.com/mcp/v2_domain`
- **Headers**: leer lassen

Speichern Sie die Erweiterung. Goose öffnet Ihren Browser für die OVHcloud Anmeldung.

Um beide API-Versionen zu nutzen, erstellen Sie eine zweite Erweiterung mit dem anderen Bereich.

</Tab>
<Tab label="Claude Code">

Fügen Sie einen Server pro Bereich hinzu, mit der URL Ihrer Region:

```bash
claude mcp add --transport http v1_domain https://mcp.eu.ovhcloud.com/mcp/v1_domain
claude mcp add --transport http v2_domain https://mcp.eu.ovhcloud.com/mcp/v2_domain
```

Der erste Befehl allein deckt alle Vorgänge dieser Anleitung ab. Fügen Sie `--scope user` hinzu, damit ein Server in all Ihren Projekten und nicht nur im aktuellen verfügbar ist. Verwenden Sie keine `--header`-Option.

Starten Sie anschließend aus Claude Code heraus die OAuth2-Anmeldung:

```text
/mcp
```

Melden Sie sich im geöffneten Browserfenster bei OVHcloud an. `claude mcp list` zeigt danach `✔ Connected` neben jedem hinzugefügten Server an.

</Tab>
</Tabs>

Um zu prüfen, ob die Verbindung funktioniert, stellen Sie Ihrem Agenten eine Frage, die nur Daten abruft:

```text
Liste meine OVHcloud Domainnamen auf.
```

### 4 — Informationen zu einem Domainnamen anzeigen

Lassen Sie sich zunächst Ihre Domainnamen auflisten und fragen Sie dann die Details zu einem davon ab.

Beispielanfrage:

```text
Zeige mir die Details von mydomain.ovh: Ablaufdatum, Nameserver und ob die Transfersperre aktiv ist.
```

### 5 — Einen Domainnamen bestellen

Die Bestellung eines Domainnamens erfolgt mit dem Tool `order-new-domain-name` aus dem Bereich `v1_domain`.

Beispielanfrage:

```text
Bestelle mydomain.ovh für ein Jahr.
```

Fordern Sie vor jedem Kauf eine **Simulation** an. Das Tool akzeptiert einen Parameter `dryRun`: Auf `true` gesetzt, prüft es die Verfügbarkeit des Namens und berechnet den Preis, **ohne etwas verbindlich zu bestellen oder in Rechnung zu stellen**.

```text
Simuliere die Bestellung von mydomain.ovh für ein Jahr.
```

Ihr Agent zeigt daraufhin das Angebot an – Preis, Laufzeit und die Konfiguration, die auf den Domainnamen angewendet wird – und wartet auf Ihre Zustimmung, bevor er fortfährt.

Sobald Sie das Angebot bestätigt haben, führt der Agent den Aufruf erneut mit `dryRun` auf `false` aus. Die Bestellung wird damit verbindlich: Die API gibt die **URL des Bestellscheins** zurück. Ihr Agent übermittelt Ihnen diese URL direkt in seiner Antwort: Öffnen Sie sie in Ihrem Browser, um die Bestellung zu bezahlen. Sie finden diesen Bestellschein auch im OVHcloud Kundencenter unter <ManagerLink to="/#/billing/orders">Meine Bestellungen</ManagerLink>.

:::info
Der Bestellschein muss **bezahlt** werden, damit die Registrierung an die Registry übermittelt wird. Ihr Agent kann nicht an Ihrer Stelle bezahlen: Folgen Sie der URL des Bestellscheins, die er Ihnen zurückgegeben hat, um die Zahlung vorzunehmen. Solange die Zahlung nicht eingegangen ist, bleibt der Domainname für Dritte verfügbar.
:::

:::warning
Die Bestätigung der Bestellung erzeugt einen echten, kostenpflichtigen Bestellschein in Ihrem OVHcloud Konto. Lesen Sie die Bestätigungsanfrage Ihres Agenten, bevor Sie sie annehmen, und prüfen Sie Domainnamen und Laufzeit: Eine Registrierung lässt sich nicht wie eine Konfigurationsänderung rückgängig machen.
:::

### 6 — Einen DNS-Eintrag ändern

Zugehörige Tools: `create-domain-zone-record`, um einen Eintrag hinzuzufügen, `delete-domain-zone-record`, um einen zu löschen, und `get-domain-zone-details`, um die Zone einzusehen.

Beispielanfragen:

```text
Ändere den A-Eintrag von www.mydomain.ovh auf 203.0.113.42.
```

Sie müssen nicht wissen, welcher Eintragstyp geändert werden muss. Beschreiben Sie das gewünschte Ergebnis: Ihr Agent ermittelt den betroffenen Eintrag, erklärt Ihnen, was er ändern wird, und wartet auf Ihre Zustimmung, bevor er die Änderung anwendet.

```text
Meine Website wird jetzt auf einem Server mit der IP-Adresse 203.0.113.42 gehostet.
Sorge dafür, dass www.mydomain.ovh darauf zeigt.
```

:::warning
Ein geänderter DNS-Eintrag wird erst nach der Aktualisierung der Zone aktiv. Wenn Sie diesen Schritt auslassen, wird Ihre Änderung zwar gespeichert, aber nie angewendet. Bitten Sie Ihren Agenten ausdrücklich darum, die Zone zu aktualisieren, oder prüfen Sie, ob er es getan hat.
:::

Die Propagation im Internet kann anschließend je nach TTL des Eintrags bis zu 24 Stunden dauern.

### 7 — Eine Weiterleitung erstellen

Eine Weiterleitung führt die Besucher Ihres Domainnamens auf eine andere Adresse.

Beispielanfrage:

```text
Leite blog.mydomain.ovh auf https://mydomain.ovh/news weiter. Die Adresse soll im Browser sichtbar bleiben.
```

### 8 — Weitere abgedeckte Vorgänge

Die Bereiche `v1_domain` und `v2_domain` stellen die entsprechenden Routen der OVHcloud API als Tools bereit: **Jeder Vorgang, den Sie über die API für Ihre Domainnamen ausführen können, ist auch über MCP möglich**. Über die oben genannten Aufgaben hinaus umfasst das zum Beispiel:

- DNSSEC: Aktivierung, Deaktivierung und Verwaltung der DS-Einträge
- Transfersperre: Aktivierung und Deaktivierung
- Verwaltung der Kontakte: Inhaber, Administrator-Kontakt, technischer Kontakt und Rechnungskontakt
- Nameserver und Glue Records
- DynHost-Zugangsdaten und -Einträge (dynamisches DNS)
- Sicherung, Wiederherstellung, Import und Export der Zone
- Verwaltung der Aufgaben: Beschleunigung, Abbruch, Neustart
- Abruf des AuthInfo-Codes und Freigabe ausgehender Transfers

Wenn Sie nicht sicher sind, ob ein Vorgang möglich ist, bitten Sie Ihren Agenten, Ihnen zu erklären, was er mit Ihren Domainnamen tun kann.
