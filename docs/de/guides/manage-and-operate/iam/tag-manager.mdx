## Ziel

In dieser Anleitung erfahren Sie, wie Sie Tags auf Ihren OVHcloud Produkten zuweisen und verwalten und wie Sie diese in IAM-Richtlinien verwenden.

## Voraussetzungen

- Sie verfügen über einen [OVHcloud Kunden-Account](/guides/account-and-service-management/account-information/ovhcloud-account-creation).

[[cpnav:iam-tag-management-console]]

## In der praktischen Anwendung

### Tags über die OVHcloud Konsole verwalten

Sie können die Tags Ihrer OVHcloud Produkte entweder über die allgemeine Tag-Verwaltungsoberfläche oder über dedizierte Oberflächen innerhalb der Produkte verwalten.

Tags sind Metadaten in Form von Schlüssel-Wert-Paaren, die zu OVHcloud Ressourcen hinzugefügt werden und in IAM-Richtlinien oder zur Kategorisierung von Ressourcen verwendet werden können.

#### Tag manager

Der <ManagerLink console to="/#/customer/iam/tag-manager">Tag manager</ManagerLink> ist die Oberfläche, über die Sie Ihre Tags für alle Ihre OVHcloud Produkte verwalten können.

Die Seite zeigt alle Tags an, die derzeit auf Ihren Ressourcen gesetzt sind.

<img className="thumbnail" alt="Seite Tag manager mit der Dropdown-Liste Tag-Typ und der Spalte Tag-Typ" src="/images/manage-and-operate/iam/iam-tag-manager/console/tag-manager-01.png" loading="lazy" />

Für jedes Tag zeigt die Liste die Anzahl der mit diesem Tag verknüpften Ressourcen sowie den Tag-Typ an.

Es gibt drei Arten von Tags:

- Benutzerdefiniert: Von Ihnen erstellt und verwaltet.
- Vordefiniert: Von OVHcloud erstellt; Sie sind dafür verantwortlich, diese Art von Tag Ihren Ressourcen zuzuweisen.
- System: Von OVHcloud erstellt und Ihren Ressourcen automatisch zugewiesen (kann nicht gelöscht werden).

Standardmäßig ist die Dropdown-Liste **Tag-Typ** auf <code className="action">Alle Typen</code> eingestellt, und die Seite zeigt auch nicht zugewiesene vordefinierte Tags an. Um die Liste einzugrenzen, wählen Sie in dieser Dropdown-Liste <code className="action">Benutzerdefiniert</code>, <code className="action">Vordefiniert</code>, <code className="action">System</code> oder <code className="action">Nicht zugewiesen</code> aus.

Klicken Sie auf ein Tag, um seine Details mit der Liste der Ressourcen zu öffnen, denen es zugewiesen ist.

<img className="thumbnail" alt="Seite eines Tags mit den Buttons Ressourcen zuweisen und Tag entfernen" src="/images/manage-and-operate/iam/iam-tag-manager/console/tag-manager-02.png" loading="lazy" />

Sie können dieses Tag dann mit dem Button <code className="action">Ressourcen zuweisen</code> weiteren Ressourcen zuweisen. Daraufhin wird die Liste aller Ressourcen des Accounts angezeigt, die eine Mehrfachauswahl ermöglicht.

Ein Suchfeld hilft Ihnen, Ressourcen zu finden.

Um das Tag umgekehrt von Ressourcen zu entfernen, wählen Sie diese in den Details des Tags aus und klicken Sie dann auf <code className="action">Tag entfernen</code>.

#### Dashboard des Produkts

Für einige OVHcloud Produkte wurde eine Oberfläche hinzugefügt, mit der Sie Tags direkt über das Verwaltungs-Dashboard der Ressource verwalten können.

Über die Tag-Verwaltungsoberfläche können Sie der Ressource Tags hinzufügen oder sie von ihr entfernen.

Sie können entweder ein oder mehrere Tags aus der Liste der vordefinierten Tags auswählen oder Ihre eigenen Tags eingeben, indem Sie die Schlüssel und Werte direkt in die Felder eingeben.

### Tags über die API verwalten

Die Tag-Verwaltung ist für alle OVHcloud Produkte in einer einzigen API zentralisiert:

| **Methode** |                **Pfad**                 |         **Beschreibung**          |
| :---------: | :-------------------------------------: | :-------------------------------: |
|    POST     |    /iam/resource/&#123;resourceURN&#125;/tag    |  Einer Ressource ein Tag hinzufügen  |
|     DEL     | /iam/resource/&#123;resourceURN&#125;/tag/&#123;key&#125; |  Ein Tag von einer Ressource entfernen  |

Das Tag muss in folgendem Format angegeben werden:

```json
{
  "key": "environment",
  "value": "production"
}
```

### Tags in IAM-Richtlinien verwenden

Tags können mithilfe der Bedingung `resource.Tag(tag_key)` als Bedingungen in IAM-Richtlinien verwendet werden.

Die folgende Richtlinie gewährt beispielsweise Rechte für alle VPS mit dem Tag `Environment:Production`:

```json
{
  "conditions": {
    "conditions": [
      {
        "operator": "MATCH",
        "values": {
          "resource.Tag(Environment)": "Production"
        }
      }
    ],
    "operator": "AND"
  },
  "description": "Give access to VPS with tag Environment:Production",
  "identities": [
    "urn:v1:eu:identity:group:aa1-ovh/devs"
  ],
  "name": "vps-production",
  "permissions": {
    "allow": [
      {
        "action": "vps:apiovh:*"
      }
    ]
  },
  "resources": [
    {
      "urn": "urn:v1:eu:resource:vps:*"
    }
  ]
}
```
