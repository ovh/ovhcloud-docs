## Ziel

NetBox ist das Referenztool für das physische und logische Inventar Ihrer **OVHcloud On-Prem Cloud Platform (OPCP)**-Infrastruktur. Unter anderem bietet die **Rack-Elevation** eine visuelle, maßstabsgetreue Darstellung eines Racks und der darin installierten Geräte.

**Diese Anleitung erläutert, wie die Rack-Elevation in NetBox gehandhabt wird und welche Informationen sie Ihnen über Ihr OPCP-Rack liefert.**

:::info
Das NetBox-Inventar wird automatisch über die Control Plane der OPCP befüllt; es ist keine manuelle Aktion erforderlich, um Geräte im Rack hinzuzufügen, zu positionieren oder zu ändern.

In OpenStack entspricht ein Node einem physischen Server im OPCP-Rack. In dieser Anleitung bezeichnet der Begriff **Node** daher einen physischen Server.
:::

## Voraussetzungen

- Sie sind Administrator der [OPCP](https://www.ovhcloud.com/de/hosted-private-cloud/onprem-cloud-platform/)-Infrastruktur und haben Zugriff auf die Administrationsoberfläche `admin.dashboard`.
- Sie wissen, wie Sie auf das NetBox-Inventar zugreifen (siehe [OPCP - Node-Inventar anzeigen](/guides/hosted-private-cloud/opcp/how-to-see-node-inventory)).

## Anweisungen

### 1. Was ist eine Rack-Elevation

In NetBox steht ein **Rack** für ein physisches Geräte-Gehäuse in einem Rechenzentrum. Seine Kapazität wird in **Rack-Einheiten (U)** gemessen — ein Standard-Rack ist üblicherweise zwischen 42U und 48U hoch.

Die **Rack-Elevation** ist ein maßstabsgetreues Diagramm dieses Racks. Es zeigt Einheit für Einheit, welches Gerät welche Position belegt, sodass Sie den physischen Aufbau Ihrer OPCP-Infrastruktur nachvollziehen können, ohne vor Ort zu sein.

### 2. Auf die Rack-Elevation in NetBox zugreifen

1. Melden Sie sich an der Administrations-URL `admin.dashboard` an.
2. Klicken Sie auf **NetBox**. Die Rack-Elevation Ihres OPCP-Racks öffnet sich direkt.

<img className="thumbnail" alt="netbox-rack-elevation" src="/images/hosted-private-cloud/opcp/how-to-handle-rack-elevation/01-netbox-rack-elevation.png" loading="lazy" />

**Alternativer Weg:** Wenn Sie die Elevation aus einem anderen Bereich von NetBox erreichen möchten, öffnen Sie den Abschnitt **DCIM**, wählen Sie **Racks** und anschließend Ihr OPCP-Rack, um dessen Detailseite zu öffnen und die Ansicht **Elevation** aufzurufen.

### 3. Die Elevation-Ansicht lesen

Die Elevation-Ansicht vermittelt auf einen Blick mehrere Informationen:

- **Vorder- und Rückseite**: Die Elevation kann von der Vorder- oder der Rückseite des Racks angezeigt werden, sodass Sie auf beiden Seiten montierte Geräte sehen.
- **Position und Höhe der Geräte**: Jedes Gerät wird an der Rack-Einheit (U) dargestellt, an der es montiert ist, und erstreckt sich über die Anzahl der Einheiten, die es physisch belegt.
- **Nummerierung der Einheiten**: Die Rack-Einheiten sind seitlich entlang der Elevation nummeriert. Je nach Rack-Konfiguration kann die Nummerierung vom Boden aufsteigend oder von oben absteigend verlaufen.
- **Farbcodierung nach Rolle**: Geräte werden entsprechend ihrer Rolle eingefärbt (z. B. Server gegenüber Netzwerkgeräten), wodurch sich Gerätetypen leicht unterscheiden lassen.
- **Freier Platz**: Leere Rack-Einheiten werden als verfügbarer Platz angezeigt, was einen schnellen Überblick über die verbleibende Kapazität gibt.

### 4. Wie die Rack-Elevation erzeugt wird

Im Normalbetrieb positionieren Sie Nodes nicht manuell: Ihre Position in der Rack-Elevation wird automatisch durch die **Ironic → NetBox-Synchronisation** erzeugt.

Eine Position wird wie folgt ermittelt:

- Während der Synchronisation wird die Netzwerkverkabelung jedes Nodes aus Ironic ausgelesen — konkret die **Switch-Ports**, mit denen der Node verbunden ist.
- OVHcloud stellt **Positions-Templates** bereit, die einen bestimmten Satz von Switch-Port-Verbindungen einer konkreten Rack-Einheit (U) zuordnen. Diese Templates werden von OVHcloud erstellt und hängen vom **Rack-Typ** ab, der wiederum davon abhängt, wie die Plattform installiert wurde.
- Wenn ein zum Rack-Typ passendes Template existiert und die Verkabelung des Nodes einem seiner Einträge entspricht, wird der Node automatisch an der entsprechenden Rack-Einheit platziert. Diese automatische Position hat Vorrang: Sie **überschreibt** jede manuelle Änderung, und falls die Zieleinheit bereits belegt ist, wird das dort befindliche Gerät zuvor entfernt.

:::info
**Der Rückfallmechanismus ist immer die manuelle Positionierung.** Wenn kein Positions-Template zum Rack-Typ passt — oder wenn für das Rack kein Rack-Typ definiert ist — ändert die Synchronisation die Position der betroffenen Nodes **nicht**. In diesem Fall bleibt jede Position, die Sie in NetBox manuell festlegen, erhalten und wird von der Synchronisation nie überschrieben. Sie können das Gerät dann selbst in der Elevation-Ansicht positionieren, und Ihre Änderung bleibt bei der nächsten Synchronisation erhalten.
:::

Beachten Sie: Wenn für den Rack-Typ zwar ein Template *existiert*, die Verkabelung eines Nodes jedoch keinem seiner Einträge entspricht, bleibt der Node ohne Position in der Elevation. In diesem Fall hilft die manuelle Positionierung **nicht**: Jede von Ihnen festgelegte Position wird bei der nächsten Synchronisation wieder entfernt. Der Node kann erst platziert werden, sobald seine Verkabelung einem Template-Eintrag entspricht.

### 5. Was Ihnen die Rack-Elevation zeigt

Für eine OPCP-Infrastruktur hilft Ihnen die Rack-Elevation dabei:

- **einen Node physisch zu lokalisieren** im Rack für Vor-Ort-Arbeiten wie Wartung oder Verkabelung.
- **die Kapazität einzuschätzen**, indem Sie sehen, welche Einheiten belegt und welche frei sind.
- **die physische und die logische Sicht zusammenzuführen**, indem Sie ein in der Elevation angezeigtes Gerät mit seinem Inventareintrag und seinem OpenStack/Ironic-Status abgleichen.
