## In der praktischen Anwendung

:::info
Die IAM-Funktionen sind derzeit nicht für Hosted Private Cloud VMware vSphere Angebote mit PCI-DSS- oder HDS-Zertifizierung sowie für SecNumCloud-qualifizierte Lösungen verfügbar.
Dasselbe gilt für verwaltete Umgebungen mit aktiviertem NSX und für Public VCF as-a-Service. Die OVHcloud Teams arbeiten an der Anpassung dieser Technologien.

:::


### Wie funktionieren IAM und Hosted Private Cloud - VMware on OVHcloud?

Mit der Aktivierung von OVHcloud IAM wird die Verwaltung des Zugriffs auf den Dienst, der zugehörigen Rollen und ihrer Berechtigungen in vSphere delegiert. Zugriffe und Richtlinien verwalten Sie im IAM-Bereich der OVHcloud Konsole.

Vereinfacht gesagt:

- Eine IAM-Rolle ersetzt einen lokalen vSphere-Benutzer in der Hosted Private Cloud - VMware on OVHcloud.
- Mit einer Richtlinie verknüpfen Sie Ihre OVHcloud Identität mit dieser Rolle.
- IAM-Rollen funktionieren über VMware vSphere-Gruppen.

Folgende Elemente sind erforderlich, damit IAM mit Hosted Private Cloud - VMware on OVHcloud ordnungsgemäß funktioniert:

- Produkte: **vSphere/VMware (Hosted Private Cloud, Service Pack)**.
- Ressourcen: **PCC-XXX**.
- Aktionen: **Verwaltet oder manuell**.
- Benutzer: **Benutzer 1/2/3**.

## FAQ

### Welche Einschränkungen gelten für IAM mit Hosted Private Cloud - VMware on OVHcloud?

:::info
Derzeit kann eine vSphere IAM-Rolle nicht über verwaltete Berechtigungsgruppen verwaltet werden.

:::


IAM befindet sich auf der OVHcloud Plattform derzeit in einer BETA-Version. Infrastrukturen mit erweiterten Sicherheitsoptionen oder einem zertifizierten Dienst (Hosting von Gesundheitsdaten (HDS), Hosting von Bankdaten (PCI-DSS) oder SecNumCloud (SNC)) können OVHcloud IAM derzeit nicht nutzen.

Eine IAM-Rolle kann nur über manuelle Aktionen in einer globalen Richtlinie hinzugefügt werden (Aktion: assumerole -> role_iam). Weitere Informationen finden Sie in der Anleitung "[IAM für VMware on OVHcloud - vSphere-Rolle mit einer IAM-Richtlinie verknüpfen](/guides/hosted-private-cloud/powered-by-vmware/vmware-iam-role-policy)".

### Wie greife ich mit IAM auf die Delegation der vSphere-Rechte zu?

**Verknüpfte Identitäten**, **Ressourcen**, **Ressourcengruppen** und ihre Berechtigungen in den Richtlinien werden über die OVHcloud Konsole verwaltet.

Klicken Sie im Bereich <code className="action">Identitäts- und Zugriffsverwaltung</code> des Seitenmenüs auf <ManagerLink to="/beta/#/customer/iam/identities/users">Identitäten</ManagerLink> oder <ManagerLink to="/beta/#/customer/iam/policies/my-policies">Richtlinien</ManagerLink>.

IAM-Rollen und lokale vSphere-Benutzer verwalten Sie über den Eintrag <code className="action">Managed VMware vSphere</code> unter **Produkte** im Seitenmenü.

Wählen Sie Ihre Infrastruktur aus und öffnen Sie dann den Tab <code className="action">Benutzer</code>.

### Wie viele Rollen sind standardmäßig verfügbar?

Bei der Aktivierung von IAM in Ihrer Hosted Private Cloud - VMware on OVHcloud verfügen Sie über 2 aktive Standardrollen.

### Was ist eine mit einer Richtlinie verknüpfte vSphere IAM-Rolle?

Jede IAM-Rolle in Ihrer Hosted Private Cloud - VMware on OVHcloud entspricht einer Aktion in der Form `pccVMware:vSphere:assumeRole?role_name` in einer IAM-Richtlinie.

Für die Rolle **iam-admin** einer Dedicated Cloud lautet die Aktion beispielsweise: `pccVMware:vSphere:assumeRole?iam-admin.`.

Eine Rolle kann als Benutzervorlage betrachtet werden, mit der Sie PCC-Rechte (vSphere) festlegen. Diese Rechte (diese Rolle) wenden Sie dann in Ihrer OVHcloud Konsole auf einen Benutzer an (IAM, wenn Sie Ihren Benutzer mit einer Richtlinie verknüpft haben).
