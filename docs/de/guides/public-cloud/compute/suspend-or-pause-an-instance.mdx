## Ziel

Bei der Konfiguration einer hochverfügbaren Infrastruktur müssen Sie möglicherweise den Zugriff auf Ihre Instanzen reduzieren, um verschiedene Tests durchzuführen. Mit OpenStack können Sie Ihre Instanz in Shelve versetzen, anhalten (Shutoff), suspendieren oder pausieren. Die zugehörige IP-Adresse bleibt in jedem Fall erhalten.

:::warning
In der OVHcloud Konsole sind nur **Shelve** / **Unshelve** und **Hard stop** (OpenStack-Aktion *stop*, *Shut Off* in Horizon) verfügbar. **Suspend** / **Resume** und **Pause** / **Unpause** sind über die OVHcloud API (v2), in Horizon und über die OpenStack API verfügbar.

:::

**Diese Anleitung erklärt, wie Sie eine Instanz in Shelve versetzen, per Hard stop anhalten, suspendieren oder pausieren.**

## Voraussetzungen

- Sie verfügen über eine [Public Cloud Instanz](/guides/public-cloud/compute/getting-started) mit **stündlicher** Abrechnung.
- Sie haben Zugriff auf das [Horizon Interface](/guides/public-cloud/cross-functional/introducing-horizon).
- Sie haben Kenntnisse der [OpenStack API](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment) und der [OpenStack Variablen](/guides/public-cloud/cross-functional/compute-set-openstack-environment-variables).

## In der praktischen Anwendung

:::warning
**Anwendungsbereich:** Diese Anleitung gilt für alle Public Cloud Instanzen, unabhängig von deren Abrechnungsmodell (stündlich oder monatlich).

**Monatliche Abrechnung:** Bei monatlich abgerechneten Instanzen wird der Monatspreis der Instanz unabhängig von ihrem Status weiter berechnet. Für eine monatlich abgerechnete Instanz in Shelve werden der Monatspreis und zusätzlich der Snapshot berechnet.

**Hinweis:** Solange die Instanz nicht gelöscht wird, entstehen durch jeden Vorgang weiterhin Instanzkosten.

:::

In der folgenden Tabelle finden Sie die auf Ihren Instanzen verfügbaren Optionen in der Übersicht. Klicken Sie auf die Option Ihrer Wahl, um zum entsprechenden Teil der Anleitung zu gelangen. Die OpenStack-Aktion ist jeweils in Klammern angegeben.

|Option|Speicherzustand|Disk-Daten|Host-Ressourcen (CPU/RAM)|Verhalten bei der Wiederaufnahme|Abrechnung|
|---|---|---|---|---|---|
|[Hard stop (*stop*)](#hard-stop-instance)|Verloren|Erhalten|Weiterhin auf dem Host zugewiesen|Kaltstart (das Betriebssystem startet neu)|Die Abrechnung erfolgt zum gleichen Tarif.|
|[Shelve (*shelve*)](#shelve-instance)|Verloren|In einem Snapshot-Image gespeichert|Nach dem Auslagern (*offloaded*) freigegeben|Kaltstart aus dem Snapshot, eventuell auf einem anderen Host|Stündlich abgerechnete Instanzen: Nur der Snapshot wird berechnet. Monatlich abgerechnete Instanzen: der Monatspreis der Instanz zuzüglich des Snapshots.|
|[Pause (*pause*)](#pause-instance)|Im RAM des Hosts erhalten|Erhalten|Weiterhin zugewiesen und belegt|Sofort, genau an der Stelle, an der sie angehalten wurde|Die Abrechnung erfolgt zum gleichen Tarif.|
|[Suspend (*suspend*)](#stop-suspend-instance)|Auf die Disk des Hosts geschrieben|Erhalten|RAM/CPU auf dem Hypervisor freigegeben, Zuweisung bleibt bestehen|Stellt den gespeicherten Zustand wieder her, ähnlich dem Ruhezustand|Die Abrechnung erfolgt zum gleichen Tarif.|

Die IP-Adresse der Instanz bleibt in jedem Fall erhalten.

### Instanz in Shelve versetzen

:::danger
Beachten Sie, dass das Versetzen einer IOPS Instanz oder T1/T2-180 Instanz in Shelve zu Datenverlust auf den NVMe-Passthrough-Disks führt.

Das Versetzen dieses Instanztyps in Shelve führt zu seiner Außerbetriebnahme auf dem Host und somit auf den Passthrough-Disks.

:::

Diese Option erlaubt es Ihnen, die dedizierten Ressourcen Ihrer Public Cloud Instanz freizugeben, während die IP-Adresse bestehen bleibt. Die Daten der lokalen Disk werden in einem automatisch erstellten Snapshot gespeichert, sobald die Instanz in Shelve versetzt wurde. Die im Arbeitsspeicher und anderswo gespeicherten Daten werden nicht gesichert.

<a name="unshelve-instance"></a>

### Unshelve einer Instanz durchführen

Mit dieser Option reaktivieren Sie Ihre Instanz, um sie wieder verwenden zu können. Bitte beachten Sie, dass die Abrechnung nach Abschluss der Operation wieder regulär erfolgt.

:::danger
**Aktionen auf dem Snapshot**

Jede Aktion auf dem Snapshot außer *unshelve* kann für Ihre Infrastruktur sehr gefährlich sein, wenn sie nicht korrekt ausgeführt wird. Wenn Sie ein *Unshelve* einer Instanz durchführen, wird der Snapshot automatisch gelöscht. Es wird nicht empfohlen, eine neue Instanz auf einem Snapshot zu basieren, der beim Versetzen einer Instanz in Shelve erzeugt wurde.

OVHcloud stellt Ihnen Maschinen zur Verfügung, für die Sie verantwortlich sind. Wir haben keinen Zugriff auf diese Maschinen und können sie daher nicht verwalten. Sie sind selbst für die Verwaltung Ihrer Software und Sicherheit verantwortlich. Wenn Sie auf Probleme stoßen oder Zweifel bei der Verwaltung, Nutzung oder Absicherung Ihres Servers haben, empfehlen wir Ihnen, sich an einen [spezialisierten Dienstleister](/links/partner) zu wenden.
:::

<a name="hard-stop-instance"></a>

### Hard stop (*stop*) einer Instanz durchführen

Mit dieser Option halten Sie Ihre Instanz an (OpenStack-Aktion *stop*, *Shut Off* in Horizon). Die Daten auf der Disk bleiben erhalten, der Speicherzustand geht jedoch verloren: Die Instanz startet neu, wenn Sie sie wieder starten. Die der Instanz zugewiesenen Ressourcen, einschließlich der IP-Adresse, bleiben reserviert, und die Abrechnung erfolgt weiterhin zum gleichen Preis.

<Tabs>
  <Tab label="OVHcloud Konsole">
    Klicken Sie im linken Menü Ihres Public Cloud Projekts unter **Compute** auf <code className="action">Instances</code>.

    Klicken Sie auf den Button <code className="action">...</code> rechts neben der Instanz, die Sie anhalten möchten, und anschließend auf <code className="action">Hard stop</code>.

    Nehmen Sie im Fenster **Hard stop der Instanz** die Meldung zur Kenntnis und klicken Sie auf <code className="action">Bestätigen</code>.

    Sobald der Vorgang abgeschlossen ist, wird der Status Ihrer Instanz als **Hard stop (Shutoff)** angezeigt.

    Um die Instanz wieder zu **starten**, klicken Sie auf den Button <code className="action">...</code> rechts neben der Instanz, wählen Sie <code className="action">Starten</code> und klicken Sie dann im Fenster **Instanz starten** auf <code className="action">Bestätigen</code>. In einigen Fällen müssen Sie möglicherweise einen Kaltstart durchführen.

    Sobald der Vorgang abgeschlossen ist, wird der Status Ihrer Instanz als **Aktiv** angezeigt.
  </Tab>
  <Tab label="OVHcloud CLI">
    Geben Sie den folgenden Befehl ein:

    ```shell
    ovhcloud cloud instance stop <instance_id>
    ```

    Um die Instanz wieder zu **starten**, geben Sie den folgenden Befehl ein:

    ```shell
    ovhcloud cloud instance start <instance_id>
    ```
  </Tab>
  <Tab label="OVHcloud API">
    Verwenden Sie den folgenden API-Aufruf, wobei `projectId` die ID Ihres Public Cloud Projekts und `instanceId` die ID der Instanz ist:

    <Api version="v2" section="/publicCloud" method="POST" route={"/publicCloud/project/\{projectId\}/compute/instance/\{instanceId\}/action"} />

    Mit dem folgenden Anfragetext:

    ```json
    {
      "type": "STOP"
    }
    ```

    Um die Instanz **wieder in Betrieb zu nehmen**, verwenden Sie denselben Aufruf mit dem Typ `START`:

    ```json
    {
      "type": "START"
    }
    ```
  </Tab>
  <Tab label="OpenStack/Nova API">
    Sobald Ihre Umgebung bereit ist, geben Sie in der Kommandozeile Folgendes ein:

    ```bash
    ~$ openstack server stop <UUID server>

    =========================================

    ~$ nova stop <UUID server>
    ```

    Um die Instanz wieder zu **starten**, geben Sie in der Kommandozeile Folgendes ein:

    ```bash
    ~$ openstack server start <UUID server>

    =========================================

    ~$ nova start <UUID server>
    ```
  </Tab>
  <Tab label="Horizon">
    Klicken Sie im Horizon-Interface auf das Menü <code className="action">Compute</code> auf der linken Seite und wählen Sie anschließend <code className="action">Instanzen</code> aus. Wählen Sie <code className="action">Shut Off Instance</code> in der Drop-down-Liste für die betreffende Instanz aus.

    Um die Instanz wieder zu **starten**, wählen Sie <code className="action">Start Instance</code> in der Drop-down-Liste für die betreffende Instanz aus.
  </Tab>
</Tabs>

<a name="stop-suspend-instance"></a>

### Instanz suspendieren

Mit dieser Option suspendieren Sie Ihre Instanz: Der Speicherzustand wird auf die Disk des Hosts geschrieben, und RAM/CPU werden auf dem Hypervisor freigegeben, während die Zuweisung bestehen bleibt. Wenn Sie die Instanz wieder aufnehmen, wird der gespeicherte Zustand wiederhergestellt, ähnlich dem Ruhezustand. Die Abrechnung erfolgt zum gleichen Tarif.

Diese Aktion ist in der OVHcloud Konsole nicht verfügbar: Verwenden Sie die OVHcloud API, das Horizon-Interface oder die OpenStack/Nova API.

<Tabs>
  <Tab label="OVHcloud API">
    Verwenden Sie den folgenden API-Aufruf, wobei `projectId` die ID Ihres Public Cloud Projekts und `instanceId` die ID der Instanz ist:

    <Api version="v2" section="/publicCloud" method="POST" route={"/publicCloud/project/\{projectId\}/compute/instance/\{instanceId\}/action"} />

    Mit dem folgenden Anfragetext:

    ```json
    {
      "type": "SUSPEND"
    }
    ```

    Um die Instanz **wieder in Betrieb zu nehmen**, verwenden Sie denselben Aufruf mit dem Typ `RESUME`:

    ```json
    {
      "type": "RESUME"
    }
    ```
  </Tab>
  <Tab label="OpenStack/Nova API">
    Sobald Ihre Umgebung bereit ist, geben Sie in der Kommandozeile Folgendes ein:

    ```bash
    ~$ openstack server suspend <UUID server>

    =========================================

    ~$ nova suspend <UUID server>
    ```

    Um die Instanz **wieder in Betrieb zu nehmen**, geben Sie in der Kommandozeile Folgendes ein:

    ```bash
    ~$ openstack server resume <UUID server>

    =========================================

    ~$ nova resume <UUID server>
    ```
  </Tab>
  <Tab label="Horizon">
    Klicken Sie im Horizon-Interface auf das Menü <code className="action">Compute</code> auf der linken Seite und wählen Sie anschließend <code className="action">Instanzen</code> aus. Wählen Sie <code className="action">Suspend Instance</code> in der Drop-down-Liste für die betreffende Instanz aus.

    <img className="thumbnail" alt="suspend instance Horizon" src="/images/public-cloud/compute/suspend-or-pause-an-instance/suspendinstancehorizon.png" loading="lazy" />

    Es erscheint eine Bestätigungsmeldung, die anzeigt, dass die Instanz suspendiert wurde.

    Um die Instanz **wieder in Betrieb zu nehmen**, führen Sie dieselben Schritte wie oben beschrieben aus. Wählen Sie in der Drop-down-Liste für die betreffende Instanz <code className="action">Resume Instance</code> aus.
  </Tab>
</Tabs>

<a name="pause-instance"></a>

### Instanz pausieren

Diese Aktion ist in der OVHcloud Konsole nicht verfügbar: Verwenden Sie die OVHcloud API, das Horizon-Interface oder die OpenStack/Nova API. Damit können Sie Ihre Instanz *einfrieren*: Der Speicherzustand bleibt im RAM des Hosts erhalten, und die Instanz läuft sofort genau an der Stelle weiter, an der sie angehalten wurde.

<Tabs>
  <Tab label="OVHcloud API">
    Verwenden Sie den folgenden API-Aufruf, wobei `projectId` die ID Ihres Public Cloud Projekts und `instanceId` die ID der Instanz ist:

    <Api version="v2" section="/publicCloud" method="POST" route={"/publicCloud/project/\{projectId\}/compute/instance/\{instanceId\}/action"} />

    Mit dem folgenden Anfragetext:

    ```json
    {
      "type": "PAUSE"
    }
    ```

    Um die Instanz **wieder in Betrieb zu nehmen**, verwenden Sie denselben Aufruf mit dem Typ `UNPAUSE`:

    ```json
    {
      "type": "UNPAUSE"
    }
    ```
  </Tab>
  <Tab label="OpenStack/Nova API">
    Sobald Ihre Umgebung bereit ist, geben Sie in der Kommandozeile Folgendes ein:

    ```bash
    ~$ openstack server pause <UUID server>

    =========================================

    ~$ nova pause <UUID server>
    ```

    Um die Pausierung der Instanz aufzuheben, geben Sie in der Kommandozeile Folgendes ein:

    ```bash
    ~$ openstack server unpause <UUID server>

    =========================================

    ~$ nova unpause <UUID server>
    ```
  </Tab>
  <Tab label="Horizon">

Wählen Sie <code className="action">Pause Instance</code> in der Drop-down-Liste für die betreffende Instanz aus.

    Um die Pausierung der Instanz aufzuheben, führen Sie dieselben Schritte wie oben beschrieben aus. Wählen Sie in der Drop-down-Liste für die betreffende Instanz <code className="action">Resume Instance</code> aus.
  </Tab>
</Tabs>
