## Ziel

Für Ihre auf Block Storage Volumes liegenden wichtigen Daten ist es sinnvoll, Backups zu organisieren. Damit verhindern Sie Datenverluste, etwa aufgrund menschlicher Fehler oder Störungen auf Cluster-Ebene.

Ein **Volume Snapshot** ist ein Wiederherstellungspunkt, der im selben Speichercluster gespeichert ist wie das ursprüngliche Volume. Die Erstellung und Wiederherstellung sind schnell, aber im Falle einer Störung des Clusters können Volume und Snapshot nicht verfügbar sein.<br/>
Die Erstellung eines Volume Snapshots erfordert nicht, dass das Volume von der Instanz getrennt wird.

Ein **Volume Backup** ist ein Image, das auf Ihrem Volume basierend erstellt wird. Dieses wird im Object Storage Cluster des ursprünglichen Volumes gespeichert.
Dieses Maß an Resilienz ist ideal und erlaubt es Ihnen, schnell auf das Volume betreffende Störungen zu reagieren, indem Sie aus dem Backup ein neues Volume erstellen.<br/>
Um ein Volume Backup anzulegen, muss das Volume von der Instanz getrennt werden.

Volume Snapshot und Volume Backup ermöglichen:

- Backups Ihres Volumes mit nur wenigen Klicks zu erstellen und so lange wie nötig aufbewahren.
- Mit Backups den früheren Zustand Ihres Volumes wiederherzustellen.
- Backups als Vorlage zu verwenden, um identische Volumes zu erstellen.

**Diese Anleitung erklärt, wie Sie ein Backup Ihres Block Storage Volumes in der OVHcloud Konsole erstellen.**

## Voraussetzungen

- Sie haben ein [Block Storage Volume](/guides/public-cloud/compute/create-and-configure-an-additional-disk-on-an-instance) in Ihrem [Public Cloud Projekt](/links/public-cloud/public-cloud) erstellt und abgetrennt.

## Einschränkungen

Backups verschlüsselter LUKS-Volume-Typen können nur auf denselben verschlüsselten LUKS-Volume-Typ wiederhergestellt werden.

## In der praktischen Anwendung

Klicken Sie im linken Menü Ihres Public Cloud Projekts unter **Speicher** auf <code className="action">Block Storage</code>. Klicken Sie in der Zeile des betreffenden Volumes auf den Button <code className="action">...</code> und wählen Sie dann <code className="action">Backup erstellen</code>.

:::info
**Um ein Backup zu erstellen, muss ein Volume zuerst von der Instanz abgetrennt werden.**

- Für eine Linux-Umgebung beachten Sie den Abschnitt **Unter Linux** in "[Zusätzliches Volume auf einer Instanz erstellen und konfigurieren](/guides/public-cloud/compute/create-and-configure-an-additional-disk-on-an-instance)".
- Für eine Windows-Umgebung beachten Sie den Abschnitt **Unter Windows** in "[Zusätzliches Volume auf einer Instanz erstellen und konfigurieren](/guides/public-cloud/compute/create-and-configure-an-additional-disk-on-an-instance)".

:::


Geben Sie einen Namen für das Backup ein, beachten Sie die Preisinformationen und klicken Sie dann auf <code className="action">Erstellen</code>.

Sie können ein Backup auch über die Seite **Volume Backup** erstellen: Klicken Sie im linken Menü unter **Speicher** auf <code className="action">Volume Backup</code> und dann auf <code className="action">Volume Backup erstellen</code>. Wählen Sie das Volume unter **Zu sicherndes Volume** aus, geben Sie den Namen des Backups ein und klicken Sie auf <code className="action">Erstellen</code>. Wenn das Volume mit einer Instanz verbunden ist, werden Sie zunächst aufgefordert, es zu trennen (<code className="action">Volume trennen</code>).

Um stattdessen einen Volume Snapshot zu erstellen, folgen Sie der Anleitung "[Volume Snapshot erstellen](/guides/public-cloud/compute/storage-create-volume-snapshot)".

Die Zeit zur Erstellung des Backups, ob Volume Snapshot oder Volume Backup, kann abhängig von der Datenmenge auf dem Volume, der Verwendung der Ressourcen der Instanz sowie anderen hostspezifischen Faktoren mehrere Stunden in Anspruch nehmen.

:::info
**Best Practices:**

- Führen Sie Volume Backups außerhalb Ihrer Produktionsstunden durch.
- Vermeiden Sie die Erstellung von Snapshots zu Spitzenzeiten (04:00 - 22:00 Uhr Pariser Zeit).
- Installieren Sie "qemu-guest", falls nicht schon erfolgt oder versuchen Sie es gegebenenfalls zu deaktivieren.
- Versuchen Sie, den Server während der Erstellung des Snapshots (Begrenzung von I/O, RAM-Verbrauch usw.) nicht zu beanspruchen.
- Auch wenn dies nicht zwingend notwendig ist, ist es besser, Ihr Volume vor Erstellung eines Snapshots abzutrennen.
- Überprüfen Sie regelmäßig, ob Ihre Daten auf dem Volume Snapshot oder Volume Backup intakt sind.

:::


Da ein Volume Snapshot oder ein Volume Backup ein Klon der gesamten Disk ist, hat es unabhängig vom tatsächlichen zugewiesenen Speicherplatz die maximale Größe des ursprünglichen Volumes.

Die Liste Ihrer Volume Snapshots finden Sie auf der Seite <code className="action">Volume Snapshot</code> unter **Speicher** im linken Menü.
Sobald der Volume Snapshot erstellt wurde, erscheint er in dieser Liste.

Die Liste Ihrer Volume Backups finden Sie auf der Seite <code className="action">Volume Backup</code> unter **Speicher** im linken Menü.
Sobald die Erstellung angefordert wurde, wird das Volume Backup zur Liste hinzugefügt.

Klicken Sie beim jeweiligen Volume Snapshot oder Volume Backup auf den Button <code className="action">...</code> und dann auf <code className="action">Löschen</code>, um es zu entfernen, oder auf <code className="action">Volume erstellen</code>, um ein darauf basierendes Volume zu erstellen. Für ein Volume Backup können Sie auch <code className="action">Volume wiederherstellen</code> auswählen.

Weitere Informationen zu diesem Thema finden Sie in unserer [Anleitung zur Erstellung eines Volumes aus einem Volume Snapshot](/guides/public-cloud/compute/storage-create-volume-from-backup).
