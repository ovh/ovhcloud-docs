## Ziel

Mit Reserved Capacity verpflichten Sie sich für einen festen Zeitraum zu einer bestimmten Menge an Rechenkapazität in einer ausgewählten Region und erhalten im Gegenzug einen Rabatt auf den Basispreis. Sie sichern sich so den Zugang zu stark nachgefragten Instanzmodellen und senken Ihre monatlichen Kosten.

**In dieser Anleitung erfahren Sie, wie Sie folgende Aufgaben durchführen:**

- Reservierung erstellen: Region, Modell, Laufzeit und Anzahl der Instanzen auswählen
- Reservierung durch Zahlung der Anzahlung bestätigen
- Status einer Reservierung verfolgen
- Instanzen einer Reservierung verwalten

## Voraussetzungen

- Sie verfügen über ein [Public Cloud Projekt](/guides/public-cloud/cross-functional/create-a-public-cloud-project) in Ihrem OVHcloud Account.
- Sie verfügen über ein gültiges Zahlungsmittel, um die Anzahlung für die Reservierung zu leisten.
- Sie haben Zugriff auf die [OVHcloud API](/guides/manage-and-operate/api/first-steps), wenn Sie die Schritte über die API ausführen möchten.

## Einführung

Mit einer Reservierung verpflichten Sie sich für 12 oder 36 Monate zu einer bestimmten Anzahl eines Instanzmodells in der Region Ihrer Wahl. Im Gegenzug erhalten Sie einen Rabatt auf den monatlichen Basispreis des Modells. Sobald Ihre Reservierung aktiv ist, ist die reservierte Kapazität für die gesamte Laufzeit garantiert.

:::info
Derzeit ist nur das Modell **b300-1990** für Reserved Capacity verfügbar.
:::

### Funktionsweise von Reserved Capacity <a name="how-it-works"></a>

Wenn Sie sich für 1 Jahr oder 3 Jahre verpflichten, erhalten Sie einen Rabatt auf den monatlichen Basispreis. Die gewählte Laufzeit bestimmt den Rabatt und die Anzahlung, die Sie bei der Bestellung leisten:

| Laufzeit | Anzahlung |
|---|---|
| 12 Monate | 1 Monat |
| 36 Monate | 3 Monate |

Ihre monatlichen Zahlungen beginnen mit Monat 1. Die Anzahlung wird bis zum Ende der Laufzeit einbehalten und deckt den letzten Monat bzw. die letzten Monate der Laufzeit ab, sobald alle vorherigen Monate bezahlt sind. Endet die Reservierung vor Ablauf ihrer Laufzeit, verfällt die Anzahlung.

:::info
OVHcloud bucht die reservierte Kapazität erst, wenn Ihre Anzahlung eingegangen ist. Bis dahin ist die Ressource nicht reserviert.
:::

### Reservierung erstellen <a name="create"></a>

Sie können eine Reservierung in der OVHcloud Konsole oder über die OVHcloud API erstellen.

<Tabs>
<Tab label="OVHcloud Konsole">

Klicken Sie auf der Seite **Reserved Capacity** auf <code className="action">Reserve capacity</code>, um die Seite **Create a reservation** zu öffnen.

{/* DRAFT: To screenshot — "Create a reservation" page, with the summary panel on the right. */}

#### Schritt 1 — Reservierung benennen

Behalten Sie im Feld **Reservation name** den vorgeschlagenen Namen bei (zum Beispiel `Reservation-GPU-20261113`) oder geben Sie einen eigenen Namen ein. Der Name darf bis zu 60 Zeichen lang sein und Buchstaben, Ziffern, Unterstriche (`_`) und Bindestriche (`-`) enthalten.

#### Schritt 2 — Region auswählen

Wählen Sie im Abschnitt **Select a region** eine Region aus.

Der Bestand wird bei der Bestellung bestätigt.

{/* DRAFT: To verify — whether the reservation start date can be chosen (the page says "starting now or on a chosen date", but no date field is shown in the sandbox). */}

#### Schritt 3 — Modell auswählen

Wählen Sie im Abschnitt **Select a model** das zu reservierende Instanzmodell aus. Eine Reservierung umfasst nur ein einziges Modell. Für jedes Modell zeigt die Tabelle die GPUs, den gesamten vRAM, den Arbeitsspeicher, die vCores, den Speicherplatz und den Preis ohne MwSt. an.

{/* DRAFT: To verify — the PRD lists stock statuses (Available / Quantity limited / Currently unavailable), which are not displayed in the sandbox. */}

#### Schritt 4 — Laufzeit auswählen

Wählen Sie im Abschnitt **Select the commitment period** die Option <code className="action">12 months</code> oder <code className="action">36 months</code> aus. Für jede Option werden der Rabatt, der monatliche Gesamtbetrag ohne MwSt. und die bei der Bestellung fällige Anzahlung angezeigt.

#### Schritt 5 — Anzahl der Instanzen festlegen und reservieren

Die Zusammenfassung **Instance reservation** rechts auf der Seite wird fortlaufend aktualisiert. Legen Sie die **Number of instances to reserve** mit den Buttons <code className="action">-</code> und <code className="action">+</code> fest und überprüfen Sie dann die Zusammenfassung:

- den Namen der Reservierung sowie das reservierte Modell und die Region;
- die Laufzeit und den zugehörigen Rabatt;
- das Start- und Enddatum der Reservierung;
- den monatlichen Preis ohne MwSt. im Vergleich zum Preis ohne Verpflichtung;
- **Due today**: die Anzahlung.

Klicken Sie auf <code className="action">Reserve</code>. Um die Seite ohne Reservierung zu verlassen, klicken Sie auf <code className="action">Cancel</code>.

Ihre Reservierung wird mit dem Status `Pending` erstellt und behält diesen Status, bis Sie die Anzahlung geleistet haben.

</Tab>
<Tab label="OVHcloud API v2">

Rufen Sie zunächst die ID des zu reservierenden Modells aus der Liste der in Ihrem Projekt verfügbaren Instanz-Flavors ab:

<Api version="v2" section="/publicCloud" method="GET" route={"/publicCloud/project/\{projectId\}/reference/instance/flavor"} />

Erstellen Sie anschließend die Reservierung:

<Api version="v2" section="/publicCloud" method="POST" route={"/publicCloud/project/\{projectId\}/compute/reservation"} />

| Parameter | Erforderlich | Beschreibung | Beispiel |
|---|---|---|---|
| `projectId` (path) | Ja | ID Ihres Public Cloud Projekts. | `5f3b8a9c0d1e2f3a4b5c6d7e8f9a0b1c` |
| `targetSpec.name` | Ja | Name der Reservierung. | `b300-training-eu` |
| `targetSpec.flavor.id` | Ja | ID des zu reservierenden Modells, die Sie im vorherigen Schritt abgerufen haben. | `0a1b2c3d-4e5f-6a7b-8c9d-0e1f2a3b4c5d` |
| `targetSpec.location.region` | Ja | Region, in der die Kapazität reserviert wird. | `EU-WEST-PAR` |
| `targetSpec.location.availabilityZone` | Nein | Verfügbarkeitszone, nur in einer 3-AZ-Region. Wenn Sie das Feld leer lassen, wird die Zone mit dem größten Bestand für das Modell ausgewählt. In anderen Regionen wird der Parameter ignoriert. | `eu-west-par-a` |
| `targetSpec.quantity` | Ja | Anzahl der zu reservierenden Instanzen. | `4` |
| `targetSpec.duration` | Ja | Laufzeit als Dauer im Format ISO 8601. | `P1Y` (12 Monate) oder `P3Y` (36 Monate) |

Beispiel für den Request Body:

```json
{
  "targetSpec": {
    "name": "b300-training-eu",
    "flavor": { "id": "<flavorId>" },
    "location": { "region": "<region>" },
    "quantity": 4,
    "duration": "P1Y"
  }
}
```

Die Antwort enthält die Reservierung mit ihrer `id`. Notieren Sie sich diese, um die Reservierung zu verfolgen und zu verwalten.

### Anzahlung leisten <a name="down-payment"></a>

Nachdem Sie auf <code className="action">Reserve</code> geklickt haben, bleibt Ihre Reservierung im Status `Pending`, bis Sie die Anzahlung geleistet haben: 1 Monat bei einer Laufzeit von 12 Monaten, 3 Monate bei einer Laufzeit von 36 Monaten.

Die Anzahlung wird über einen Bestellschein abgerechnet. Um sie zu bezahlen, gehen Sie zu **Compute** > **Reserved Capacity**, öffnen Sie Ihre Reservierung und klicken Sie dann im Banner **Payment pending** auf <code className="action">View the payment</code>. Das Feld **Down payment** der Reservierung zeigt `Payment not received` an, bis die Zahlung eingegangen ist, und danach `Complete`.

{/* DRAFT: To verify — where "View the payment" leads (purchase order page, payment page) and which payment methods are accepted. */}

:::warning
Sie haben 2 Werktage Zeit, um die Anzahlung zu leisten. Wird sie nicht innerhalb dieser Frist bezahlt, behält sich OVHcloud das Recht vor, Ihre Reservierung zu stornieren.
:::

OVHcloud bucht die Kapazität erst, wenn die Anzahlung eingegangen ist, und prüft zu diesem Zeitpunkt den Bestand erneut:

- Ist die gesamte Menge weiterhin verfügbar, wechselt Ihre Reservierung in den Status `Active`.
- Ist die gesamte Menge nicht mehr verfügbar, wird Ihre Reservierung storniert und Ihre Anzahlung vollständig erstattet. Reservierungen werden nie teilweise bereitgestellt: Wenn Sie zum Beispiel 4 Instanzen reserviert haben und nur 3 verfügbar sind, wird keine Instanz reserviert.

### Status einer Reservierung <a name="statuses"></a>

Jede Reservierung hat einen der folgenden Status:

| Status | Bedeutung |
|---|---|
| `Pending` | Die Reservierung wartet auf die Zahlung ihrer Anzahlung. |
| `Creating` | Die Anzahlung ist eingegangen und die reservierte Kapazität wird eingerichtet. |
| `Active` | Die Reservierung ist in Kraft, unabhängig davon, ob Sie ihre Instanzen nutzen oder nicht. |
| `Ended` | Die Laufzeit ist abgelaufen, aber einige Instanzen sind noch in Betrieb. Diese Instanzen werden ab diesem Zeitpunkt automatisch zum öffentlichen Stundentarif abgerechnet. |
| `Error` | Bei der Reservierung ist ein Fehler aufgetreten, zum Beispiel nach einem Zahlungsproblem. |
| `Cancelled` | Die Reservierung wurde storniert, zum Beispiel weil ihre Anzahlung nicht rechtzeitig bezahlt wurde. |
| `Deleting` | Die Reservierung wird gelöscht. |

### Bestehende Reservierung verwalten <a name="manage"></a>

Sie können Ihre Reservierungen in der OVHcloud Konsole oder über die OVHcloud API verfolgen und reservierte Instanzen bereitstellen.

<Tabs>
<Tab label="OVHcloud Konsole">

Gehen Sie in Ihrem Public Cloud Projekt zu **Compute** > **Reserved Capacity**. Die Liste zeigt für jede Reservierung den Namen und die ID, die Region, das Modell (**Flavor**), die Anzahl der gestarteten im Verhältnis zur Anzahl der reservierten Instanzen (**Launched / reserved**), die Dauer, das Start- und Enddatum sowie den Status an. Klicken Sie auf den Namen einer Reservierung, um deren Seite zu öffnen.

#### Übersicht der Reservierung

Oben auf der Seite werden der Name und der Status der Reservierung angezeigt, gefolgt von:

- **Down payment**: `Payment not received` oder `Complete`;
- **Slot**: das reservierte Modell und die Region, zum Beispiel `B300-1990 · WAW1`;
- **Reserved instances**: die Anzahl der reservierten Instanzen;
- **Commitment**, **Start date** und **End date**.

Diese Informationen können nicht bearbeitet werden.

#### Reservierte Instanzen

Der Abschnitt **Instances** listet die Instanzen auf, die die Reservierung nutzen, mit Name und ID, Region, Modell (**Flavor**), Image, öffentlichen und privaten IP-Adressen, Volumes und Status.

Sie können Instanzen erstellen, sobald die Reservierung den Status `Active` hat. Um eine neue Instanz auf der reservierten Kapazität bereitzustellen, klicken Sie auf <code className="action">Add instance</code>. Der Button ist nicht mehr verfügbar, sobald alle reservierten Instanzen erstellt wurden.

Auf der Seite **Create an instance on your reserved capacity** sind die Region und das Modell durch die Reservierung festgelegt. Konfigurieren Sie die übrigen Einstellungen der Instanz wie gewohnt: Name, Image, SSH-Schlüssel, <Tooltip term="snapshot">Snapshot</Tooltip>-Einstellungen, zusätzlicher Speicher, Netzwerk, öffentliche Konnektivität und Post-Installationsskript. Weitere Informationen zu den einzelnen Einstellungen finden Sie in unserer Anleitung "[Eine Public Cloud Instanz erstellen und darauf zugreifen](/guides/public-cloud/compute/getting-started)".

Die Zusammenfassung zeigt an, wie viele reservierte Slots noch verfügbar sind. Legen Sie die **Number of instances to be created** fest und klicken Sie dann auf <code className="action">Create</code>. Der monatliche Preis dieser Instanzen ist durch die Reservierung abgedeckt, daher ist heute kein Betrag fällig. Optionen wie Speicher, IP-Adressen und Gateways werden wie gewohnt abgerechnet.

Um eine Aktion für eine reservierte Instanz auszuführen, klicken Sie auf den Button <code className="action">...</code> am Ende der entsprechenden Zeile:

| Aktion | Wirkung |
|---|---|
| <code className="action">Details</code> | Öffnet die Seite der Instanz. |
| <code className="action">Create a snapshot</code> | Erstellt einen Snapshot der Instanz. Lesen Sie dazu unsere Anleitung "[Backup einer Instanz erstellen](/guides/public-cloud/compute/save-an-instance)". |
| <code className="action">Create an automatic snapshot</code> | Plant automatische Snapshots der Instanz. |
| <code className="action">Hard stop</code> | Hält die Instanz an, ohne sie zu löschen. |
| <code className="action">Shelve</code> | Setzt die Instanz aus (*shelve*). Lesen Sie dazu unsere Anleitung "[Aussetzen oder Pausieren einer Instanz](/guides/public-cloud/compute/suspend-or-pause-an-instance)". |
| <code className="action">Reboot in rescue mode</code> | Startet die Instanz in einer Rescue-Umgebung neu, um sie zu diagnostizieren oder zu reparieren. Lesen Sie dazu unsere Anleitung "[Rescue-Modus auf einer Public Cloud Instanz aktivieren](/guides/public-cloud/compute/put-an-instance-in-rescue-mode)". |
| <code className="action">Hot reboot (soft)</code> | Startet das Betriebssystem neu, ohne die Stromversorgung zu unterbrechen. |
| <code className="action">Cold reboot (hard)</code> | Startet die Instanz vollständig neu: Ausschalten, dann Einschalten. |
| <code className="action">Reinstall</code> | Installiert das Betriebssystem der Instanz neu. |
| <code className="action">Delete</code> | Löscht die Instanz endgültig. |

:::warning
Die Aktionen <code className="action">Create a snapshot</code>, <code className="action">Create an automatic snapshot</code> und <code className="action">Shelve</code> sichern nur die System-Disk der Instanz: Ihre ephemere Disk wird nicht gesichert. Bei der Wiederherstellung des Snapshots oder der Reaktivierung der Instanz (*unshelve*) wird nur die System-Disk wiederhergestellt, mit einer leeren ephemeren Disk.
:::

Die verfügbaren Aktionen hängen vom Zustand der Instanz ab. Für eine angehaltene Instanz werden zum Beispiel die Aktionen zum Anhalten und Neustarten nicht angeboten.

#### Reservierungen auflisten und anzeigen

Um die Reservierungen Ihres Projekts aufzulisten, verwenden Sie folgenden API-Aufruf:

<Api version="v2" section="/publicCloud" method="GET" route={"/publicCloud/project/\{projectId\}/compute/reservation"} />

Um die Details einer Reservierung anzuzeigen, verwenden Sie folgenden API-Aufruf:

<Api version="v2" section="/publicCloud" method="GET" route={"/publicCloud/project/\{projectId\}/compute/reservation/\{reservationId\}"} />

Die Antwort enthält:

| Feld | Beschreibung |
|---|---|
| `targetSpec` | Ihre Anfrage: Name, Modell, Standort, Menge und Laufzeit. |
| `currentState` | Was tatsächlich reserviert ist, einschließlich des Start- (`startTime`) und Enddatums (`endTime`) der Laufzeit sowie des reservierten Flavors (`flavor`). Das Feld ist leer, solange die Reservierung erstellt wird. |
| `resourceStatus` | Technischer Status der Reservierung, zum Beispiel `CREATING`, `READY` oder `ERROR`. |
| `currentTasks` | Laufende Vorgänge für die Reservierung, mit eventuellen Fehlern. |

{/* DRAFT: To verify — mapping between the API resourceStatus values and the Pending / Creating / Active / Ended / Error / Cancelled / Deleting statuses shown in the Console. */}

#### Reservierte Instanz bereitstellen

Sobald die Reservierung bereit ist, stellt sie in `currentState.flavor` einen eigenen reservierten Flavor bereit. Um die reservierte Kapazität zu nutzen, erstellen Sie Ihre Instanz mit der ID dieses Flavors (`currentState.flavor.id`) in derselben Region und Verfügbarkeitszone wie die Reservierung (`currentState.location`):

<Api version="v2" section="/publicCloud" method="POST" route={"/publicCloud/project/\{projectId\}/compute/instance"} />

| Parameter | Erforderlich | Beschreibung |
|---|---|---|
| `targetSpec.flavor.id` | Ja | ID des reservierten Flavors, ausgelesen aus `currentState.flavor.id`. |
| `targetSpec.location.region` | Ja | Region der Reservierung. |
| `targetSpec.location.availabilityZone` | Nein | Verfügbarkeitszone der Reservierung, in einer 3-AZ-Region. |

Geben Sie die übrigen Parameter (Name, Image, Netzwerke, SSH-Schlüssel) wie für jede andere Instanz an.

### Reservierung stornieren oder beenden <a name="delete"></a>

Sie können eine Reservierung nur selbst stornieren, solange sie den Status `Pending` hat, also bevor Sie die Anzahlung geleistet haben.

<Tabs>
<Tab label="OVHcloud Konsole">

Um eine ausstehende Reservierung zu stornieren, öffnen Sie deren Seite, klicken Sie auf <code className="action">Delete reservation</code> und bestätigen Sie. Dieser Button wird nur angezeigt, solange die Reservierung den Status `Pending` hat.

</Tab>
<Tab label="OVHcloud API v2">

Über die API können Sie eine Reservierung löschen, die den Status `Pending` hat:

<Api version="v2" section="/publicCloud" method="DELETE" route={"/publicCloud/project/\{projectId\}/compute/reservation/\{reservationId\}"} />

</Tab>

:::warning
Sobald eine Reservierung aktiv ist, kann sie weder in der OVHcloud Konsole noch über die API storniert werden. Um eine aktive Reservierung zu beenden oder zu löschen, kontaktieren Sie unser [Support-Team](/links/support).
:::

### Einschränkungen <a name="limitations"></a>

| Einschränkung | Details |
|---|---|
| Verlängerung | Eine Reservierung wird nicht automatisch verlängert. Erstellen Sie nach Ablauf der Laufzeit eine neue Reservierung, um sich für weitere 12 oder 36 Monate zu verpflichten. |
| Teilweise Bereitstellung | Eine Reservierung wird entweder vollständig oder gar nicht bereitgestellt. Ist die gesamte Menge bei Zahlung der Anzahlung nicht mehr verfügbar, wird die Reservierung storniert und die Anzahlung erstattet. |
| Stornierung | Eine Reservierung kann in der OVHcloud Konsole nur storniert werden, solange sie den Status `Pending` hat. Aktive Reservierungen können nur von unserem Support-Team beendet werden. |
