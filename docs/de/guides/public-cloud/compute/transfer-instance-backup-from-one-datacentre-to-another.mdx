## Ziel

Möglicherweise müssen Sie Ihre [Public Cloud Instanz](https://www.ovhcloud.com/de/public-cloud/compute/) von einer OpenStack-Region in eine andere verschieben, entweder weil Sie zu einer neu verfügbaren OpenStack-Region wechseln möchten oder weil Sie von OVHcloud Labs zu Public Cloud migrieren möchten.

**Diese Anleitung erklärt, wie Sie ein Instanz-Backup von einer OpenStack-Region in eine andere übertragen und dabei die Konfiguration und den Zustand der Instanz beibehalten.**

## Voraussetzungen

- Sie verfügen über die OpenStack CLI. Nutzen Sie dazu [unsere Anleitung zur Vorbereitung der Umgebung für die Nutzung der OpenStack API](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment).
- Sie haben eine Anbindung an die OpenStack APIs von OVHcloud.
- Sie verfügen über ausreichend Speicherplatz entsprechend der Größe der Instanz-Disk (für die temporäre Speicherung des Backups).

Diese Umgebung wird als "Jump Host" verwendet, um das Backup von einer Region in eine andere zu übertragen. Dabei kann es sich um eine bei OVHcloud gehostete Instanz oder um Ihr lokales System handeln.

Sie benötigen außerdem eine [Public Cloud Instanz](https://www.ovhcloud.com/de/public-cloud/compute/) in Ihrem OVHcloud Account.

## In der praktischen Anwendung

:::info
Wenn Sie ein Backup mit OpenStack erstellen müssen, lesen Sie unsere Anleitung "[Backup einer Instanz erstellen](/guides/public-cloud/compute/save-an-instance)".
:::

### Schritt 1 - Backup herunterladen

Listen Sie Ihre privaten Images auf, um das Backup zu identifizieren, das Sie übertragen möchten:

```bash
openstack image list --private
```

Laden Sie das Backup in Ihren lokalen Speicher herunter:

```bash
openstack image save --file backup.qcow2 <image-id>
```

### Schritt 2 - Zur Zielregion wechseln

Wenn Sie das Backup in eine andere Region innerhalb desselben Projekts übertragen, aktualisieren Sie `OS_REGION_NAME`:

```bash
export OS_REGION_NAME=<ziel-region>
```

Wenn Sie das Backup in ein anderes Projekt oder einen anderen Account übertragen, laden Sie die entsprechende RC-Datei:

```bash
source openrc.sh
```

### Schritt 3 - Backup in die Zielregion importieren

Der Import-Befehl unterscheidet sich, je nachdem, ob es sich beim Ziel um eine Standard-Region oder eine Local Zone handelt.

#### Standard-Region

```bash
openstack image create \
  --disk-format qcow2 \
  --container-format bare \
  --file backup.qcow2 \
  <image-name>
```

#### Local Zone

Die Namen von Local-Zone-Regionen enthalten `-lz-` (z. B. `eu-central-lz-prg-a`). Sie erfordern `--disk-format raw`. Die Dateiendung der Backup-Datei hat keinen Einfluss auf den Import – der Parameter `--disk-format` legt fest, wie OpenStack die Datei interpretiert.

```bash
openstack image create \
  --disk-format raw \
  --container-format bare \
  --file backup.qcow2 \
  <image-name>
```

:::warning
**Nur für Windows-Images** – Sie müssen die folgenden Eigenschaften hinzufügen, da es andernfalls nicht möglich ist, einen Flavor vom Typ `win-x-x` über das OVHcloud Kundencenter zu verbinden. Dieser Flavor-Typ ist für die Authentifizierung über den [OVHcloud KMS](/guides/manage-and-operate/kms/quick-start) erforderlich.

Fügen Sie die Eigenschaften bei der Erstellung hinzu (Standard-Region):

```bash
openstack image create \
  --disk-format qcow2 \
  --container-format bare \
  --file backup.qcow2 \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <image-name>
```

Fügen Sie die Eigenschaften bei der Erstellung hinzu (Local Zone):

```bash
openstack image create \
  --disk-format raw \
  --container-format bare \
  --file backup.qcow2 \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <image-name>
```

Oder legen Sie sie für ein bereits vorhandenes Image fest:

```bash
openstack image set \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <image-uuid>
```
:::

Um Ihre Instanz aus diesem Backup neu zu erstellen, folgen Sie unserer Anleitung "[Verwenden von Backups zum Erzeugen oder Wiederherstellen von Instanzen](/guides/public-cloud/compute/create-restore-a-virtual-server-with-a-backup)".
:::
