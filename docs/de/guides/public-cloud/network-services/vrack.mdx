## Ziel

OVHcloud [vRack](/links/network/vrack) ist eine Lösung für private Netzwerke, die es unseren Kunden ermöglicht, den Datenverkehr zwischen OVHcloud Dedizierten Servern sowie anderen OVHcloud Diensten zu leiten. Ebenso können Sie [Public Cloud Instanzen](/links/public-cloud/compute) in Ihr privates Netzwerk einfügen, um eine Infrastruktur aus physischen und virtuellen Ressourcen zu erstellen.

**Diese Anleitung erklärt, wie Sie Public Cloud Instanzen in Ihrem vRack konfigurieren.**

## Voraussetzungen

- Sie verfügen über ein [Public Cloud Projekt](/guides/public-cloud/cross-functional/create-a-public-cloud-project) in Ihrem Kunden-Account.
- Sie haben einen [OpenStack User erstellt](/guides/public-cloud/cross-functional/create-and-delete-a-user) (optional).
- Sie haben Grundkenntnisse in Administration und Netzwerkkonfiguration.

## Schnittstellen

Ein vRack erstellen oder eine Instanz in das Netzwerk hinzufügen kann mit dem OVHcloud Kundencenter, der OVHcloud APIv6, der OpenStack API, dem Horizon Interface, der OVHcloud CLI oder Terraform erfolgen.

Wählen Sie die Schnittstelle oder Methode, die am besten zu Ihrem technischen Profil und Ihren Anforderungen passt. Für jede Option beschreibt die folgende Anleitung die notwendigen Schritte.

**Die folgenden Abschnitte beschreiben die verfügbaren Aktionen für jede Schnittstelle/Methode.** <a name="horizon"></a>

<details>

<summary>OVHcloud Kundencenter</summary>


Das <ManagerLink to="/">OVHcloud Kundencenter</ManagerLink> ist ein vollständig visuelles Interface, das ideal geeignet ist, um mehrere VLANs zu verwalten. Sie können außerdem den privaten IP-Bereich anpassen, der standardmäßig in 10.1.0.0/16 liegt.

Das VLAN wird in der ausgewählten Region bereitgestellt. Sie können außerdem Gateways aktivieren oder deaktivieren, DHCP-Verteilungen ermöglichen etc.

Sie können außerdem die Abrechnung Ihrer Dienste im OVHcloud Kundencenter verwalten.

</details>


<details>

<summary>Horizon</summary>


[Horizon](https://horizon.cloud.ovh.net/auth/login/) (unabhängig von OVHcloud) ist die ursprüngliche Implementierung des OpenStack Dashboards, das eine Web-Benutzeroberfläche für OpenStack Dienste bereitstellt, einschließlich Nova, Swift, Keystone etc.

Diese Oberfläche ermöglicht es Ihnen, fast alle OpenStack Aktionen zu verwalten. Verwenden Sie sie, wenn Sie mehr als 2 VLANs verwalten, private Netzwerkschnittstellen zu Ihren Instanzen hinzufügen, benutzerdefinierte Images verwalten müssen etc.

Lesen Sie die Anleitung [Einführung in Horizon](/guides/public-cloud/cross-functional/introducing-horizon), um sich mit Horizon vertraut zu machen.

:::info
Horizon ist zonenbezogen, daher müssen Sie Ihre logische (geografische) Arbeitszone oben links in Ihrer Oberfläche auswählen (GRA5, SBG3, BHS1 etc.).

:::


</details>


<details>

<summary>OVHcloud APIv6</summary>


Jede Aktion, die in Ihrem OVHcloud Kundencenter verfügbar ist, kann auch über die [OVHcloud APIv6](/links/api) durchgeführt werden.  
Sie bietet sogar mehr Möglichkeiten als die grafische Oberfläche.

Die API-Schnittstelle ist weniger visuell als das OVHcloud Kundencenter, ermöglicht Ihnen aber die Durchführung einer großen Anzahl von Aktionen. Sie können Ihr VLAN verwalten und anpassen, Schnittstellen zu Ihren Instanzen hinzufügen oder Server mit hoher Anpassung erstellen.

Sie können sie über [unsere Webseite](/links/api) erreichen, aber auch verwenden, um Ihre PHP- oder Python-Skripte zu erstellen.

Auf diese Weise können Sie grundlegende Aufgaben mit Skripten automatisieren, Ihre eigenen Funktionen optimieren und vieles mehr.

Einige API-Aufrufe erfordern spezifische Eingaben – rufen Sie die erforderlichen Informationen vorab ab.

Lesen Sie die Anleitung [Erste Schritte mit der OVHcloud API](/guides/manage-and-operate/api/first-steps), um mit der OVHcloud APIv6 zu beginnen.

</details>


<details>

<summary>OpenStack API</summary>


Public Cloud Dienste können nach dem Herunterladen und Installieren von OpenStack Tools über Befehlszeilen (Linux oder Windows) verwaltet werden.

Diese Methode erfordert ein gutes Wissen über Linux oder Windows, um sie nutzen zu können, ermöglicht Ihnen aber, die gesamte Leistung von OpenStack zu nutzen.

Je nach Schicht, die Sie verwalten möchten, müssen Sie den Client von Nova (Compute), Neutron (Netzwerk), Glance (Image) oder Swift (Object Storage) verwenden. Der OpenStack Client, die neueste Ergänzung, ermöglicht es Ihnen, fast alle OpenStack Schichten direkt zu verwalten.

Mit der OpenStack API können Sie diese Verwaltung auch über Ihre Skripte automatisieren.

Weitere Informationen zur OpenStack API finden Sie hier:

- [System für die Verwendung der OpenStack API vorbereiten](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment)
- [OpenStack Umgebungsvariablen einrichten](/guides/public-cloud/cross-functional/compute-set-openstack-environment-variables)

Sie können anschließend die OpenStack APIs nach Bedarf verwenden:

- Nova (Compute)
- Glance (Image)
- Cinder (Image)
- Neutron (Netzwerk)

:::info
In einigen Fällen sind die OpenStack APIs einfacher, in anderen verwenden Sie Nova, Neutron etc. direkt.

Darüber hinaus können einige Funktionen je nach Version Ihres Clients und Betriebssystems von der OpenStack API fehlen.  
Diese Anleitung stellt die einfachsten und intuitivsten Optionen vor.  
Lesen Sie die [offizielle OpenStack Dokumentation](https://docs.openstack.org/), um mehr zu erfahren.

:::


</details>


<details>

<summary>OpenStack CLI</summary>


Sie können Ihre OVHcloud Public Cloud Dienste und vRacks direkt über Ihr Linux- oder Windows-Terminal mit der OpenStack CLI verwalten.

Diese Schnittstelle ermöglicht Ihnen die Verwaltung aller OpenStack Schichten:

- Nova: Instanzen (Compute)
- Neutron: Netzwerke
- Glance: Images
- Cinder: Volumes

Die CLI vereinigt diese Funktionen und kann in Ihre Skripte integriert werden, um Ihre Aufgaben zu automatisieren.

Bevor Sie beginnen, lesen Sie:

- [System für die Verwendung der OpenStack API vorbereiten](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment)
- [OpenStack Umgebungsvariablen einrichten](/guides/public-cloud/cross-functional/compute-set-openstack-environment-variables)

:::info
Die OpenStack CLI ist nützlich, um Ihr vRack zu verwalten, aber einige Funktionen können je nach Version des Clients oder Betriebssystems variieren. Verwenden Sie die [offizielle OpenStack-Dokumentation](https://docs.openstack.org/).

:::


</details>


<details>

<summary>Terraform</summary>


Terraform kann ebenfalls verwendet werden, um OVHcloud Infrastrukturen zu verwalten.

Sie müssen den richtigen Terraform-Provider und die richtige Ressource auswählen. Weitere Informationen finden Sie in unserer Anleitung zu [der Verwendung von Terraform mit OVHcloud](/guides/manage-and-operate/terraform/at-ovhcloud).

</details>


<details>

<summary>OVHcloud CLI</summary>


Mit der [OVHcloud CLI](https://github.com/ovh/ovhcloud-cli) können Sie Public Cloud Ressourcen direkt über Ihr Terminal verwalten, darunter private Netzwerke und Instanzschnittstellen.

Bevor Sie beginnen, [installieren und konfigurieren Sie die OVHcloud CLI](https://github.com/ovh/ovhcloud-cli#installation). Legen Sie Ihr Cloud-Projekt mit `--cloud-project <project_id>` fest oder konfigurieren Sie es in Ihrem Profil.

</details>


## In der praktischen Anwendung

### Schritt 1: Aktivieren und Verwalten eines vRacks <a name="activation"></a>

:::warning
Das vRack wird auf der OVHcloud Infrastruktur-Ebene verwaltet, was bedeutet, dass Sie es nur in Ihrem OVHcloud Kundencenter und der OVHcloud APIv6 verwalten können.

:::


<Tabs>
  <Tab label="OVHcloud Kundencenter">
    :::info
    Dies gilt nicht für neu erstellte Projekte, die automatisch mit einem vRack ausgeliefert werden. Um das vRack anzuzeigen, nachdem das Projekt erstellt wurde, gehen Sie in den Bereich <code className="action">Network</code> und klicken Sie auf <code className="action">Private vRack Netzwerk</code>, um das/die vRack(s) anzuzeigen.

    :::

    
    Wenn Sie ein älteres Projekt ohne vRack haben, müssen Sie eines bestellen. Das vRack selbst ist kostenlos und wird innerhalb weniger Minuten ausgeliefert.
    
    Klicken Sie im linken Menü auf <code className="action">Dienst hinzufügen</code> (Warenkorb-Symbol). Nutzen Sie den Filter oben auf der Seite oder scrollen Sie nach unten, um den Dienst <code className="action">vRack</code> zu finden.

Sie werden auf eine andere Seite weitergeleitet, um die Bestellung zu bestätigen. Es wird einige Minuten dauern, bis das vRack in Ihrem Account eingerichtet ist.
    
    Sobald aktiv, finden Sie ihn in Ihrem Kundencenter im Bereich <code className="action">Network</code> > <code className="action">Private vRack Netzwerk</code>, bezeichnet als "pn-xxxxxx".
    
    Klicken Sie auf Ihr vRack, wählen Sie dann aus der Liste der verfügbaren Dienste das Projekt aus, das Sie zum vRack hinzufügen möchten, und klicken Sie auf die Schaltfläche <code className="action">Hinzufügen</code>.
    
    Um die Konfiguration Ihres vRacks über das OVHcloud Kundencenter fortzusetzen, gehen Sie zu [Schritt 2: Ein privates Netzwerk im vRack erstellen](#create-pn-in-vrack), im Tab **OVHcloud Kundencenter**.
  </Tab>
  <Tab label="OVHcloud APIv6">
    **Schritt 1: Aktivieren und Verwalten eines vRacks**
    
    Melden Sie sich über die entsprechende Anleitung ([Erste Schritte mit der OVHcloud API](/guides/manage-and-operate/api/first-steps)) in die OVHcloud APIv6-Schnittstelle an und folgen Sie diesen Schritten:
    
    **Erstellen des Warenkorbs**
    
    <Api version="v1" section="/order" method="POST" route={"/order/cart"} />

    :::info
    Dieser Aufruf erstellt eine ID für Ihren Warenkorb. Sie können so viele Artikel wie gewünscht hinzufügen, bevor Sie ihn bestätigen.
    
    In diesem Fall ist die Bestellung eines vRacks allein kostenlos. Notieren Sie Ihre Warenkorbnummer (cartId), sie wird für den Rest benötigt.

    :::

    
    **Abrufen der erforderlichen Informationen für die vRack-Bestellung**
    
    <Api version="v1" section="/order" method="GET" route={"/order/cart/\\{cartId\\}/vrack"} />

    :::info
    Dieser Aufruf ermöglicht es Ihnen, alle erforderlichen Informationen für die Bestellung des vRacks abzurufen. Kopieren Sie Folgendes:
    
    *cartId*, *duration*, *planCode* und *pricingMode*.

    :::

    
    **Hinzufügen des vRacks zum Warenkorb**
    
    <Api version="v1" section="/order" method="POST" route={"/order/cart/\\{cartId\\}/vrack"} />

    :::info
    Dieser Aufruf fügt das vRack mit den erforderlichen Informationen zum Warenkorb hinzu.
    
    Bei einem vRack wären dies beispielsweise:
    
    cartId: [Ihre Warenkorb-ID]
    
    duration: "P1M"
    
    planCode: "vrack"
    
    pricingMode: "default"
    
    quantity: 1

    :::

    
    Sobald die Bestellung bestätigt ist, erhalten Sie eine Artikelnummer ("itemId"). Behalten Sie sie, falls Sie Änderungen vornehmen müssen, bevor Sie den Warenkorb bestätigen.
    
    **Bestätigen des Warenkorbs**
    
    Sobald alle Artikel in Ihrem Warenkorb sind, bestätigen Sie ihn:
    
    <Api version="v1" section="/order" method="POST" route={"/order/cart/\\{cartId\\}/checkout"} />

    :::info
    Dieser Aufruf bestätigt den Warenkorb und erstellt eine Bestellung ("orderId"). Behalten Sie diese Information, sie ist notwendig, um die Bestellung zu bestätigen.

    :::

    
    **Bestätigen der endgültigen Bestellung**
    
    Um die Bestellung zu bestätigen, wählen Sie aus 2 Optionen:
    
    - Sichtbare URL, wenn der Warenkorb bestätigt ist.  
    URL-Beispiel: https://www.ovh.com/cgi-bin/order/displayOrder.cgi?orderId=12345678&orderPassword=xxxxxxxxxx
    
    - Bestätigen Sie mithilfe dieses Aufrufs:
    
    <Api version="v1" section="/me" method="POST" route={"/me/order/\\{orderId\\}/payWithRegisteredPaymentMean"} />

    :::info
    Selbst bei einer €0-Bestellung müssen Sie eine Zahlung (orderId) simulieren. Ihre Bestellung wird dann bestätigt und die Bearbeitung beginnt.

    :::

    
    Nachdem die kostenlose Bestellung bestätigt wurde, kann es einige Minuten dauern, bis das vRack aktiviert wird.
    
    **Schritt 2: Ihr Public Cloud Projekt dem vRack hinzufügen**
    
    Sobald das vRack aktiv ist, integrieren Sie Ihr(e) Public Cloud Projekt(e) in das vRack.
    
    Folgen Sie unserer Anleitung: [Erste Schritte mit der OVHcloud API](/guides/manage-and-operate/api/first-steps).
    
    Falls die Projekt-ID unbekannt ist, ermöglichen die folgenden Aufrufe, sie abzurufen.
    
    **Identifizieren des Projekts**
    
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project"} />

    :::info
    Dieser Aufruf ruft die Liste der Projekte ab.

    :::

    
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}"} />

    :::info
    Dieser Aufruf identifiziert das Projekt über das Feld "description".

    :::

    
    **Hinzufügen des Projekts zum vRack**
    
    Sobald die Projekt-ID und der vRack-Name bekannt sind, erfolgt die Zuordnung über den folgenden Aufruf:
    
    <Api version="v1" section="/vrack" method="POST" route={"/vrack/\\{serviceName\\}/cloudProject"} />

Füllen Sie die Felder mit den zuvor abgerufenen Informationen aus:
    
    - **serviceName**: vRack-Name in der Form "pn-xxxxxx".
    - **project**: Die Public Cloud Projekt-ID in Form einer 32-stelligen Zeichenkette.
    
    :::info
    Dieser Aufruf initialisiert die Zuordnung des Projekts und des vRacks. Die Task-ID muss anschließend abgerufen werden, um den Fortschritt zu überprüfen.

    :::

    
    **Überprüfen des Fortschritts des Tasks**
    
    Sie können den Fortschritt des Tasks mit diesem Aufruf einsehen:
    
    <Api version="v1" section="/vrack" method="GET" route={"/vrack/\\{serviceName\\}/cloudProject/\\{project\\}"} />

    :::info
    Dieser Aufruf ist optional und ermöglicht nur die Überprüfung des Status des Tasks. Sobald abgeschlossen, können Sie zum nächsten Schritt übergehen.

    :::

  </Tab>
</Tabs>


### Schritt 2: Ein privates Netzwerk im vRack erstellen <a name="create-pn-in-vrack"></a>

Erstellen Sie ein privates Netzwerk mit einem VLAN (virtuelles lokales Netzwerk), damit die verbundenen Instanzen miteinander kommunizieren können.

Mit dem Public Cloud-Dienst können Sie bis zu 4000 VLANs innerhalb eines vRacks erstellen. Das bedeutet, dass Sie jede private IP-Adresse bis zu 4000 Mal verwenden können.  
Somit ist beispielsweise 192.168.0.10 von VLAN 2 anders als die IP 192.168.0.10 von VLAN 42.

Dies ist nützlich, um Ihr vRack über mehrere virtuelle Netzwerke zu segmentieren.

Über das OVHcloud Kundencenter und die OVHcloud APIv6 können Sie alle Einstellungen anpassen: Bereitstellungsmodus und Region, VLAN-Name und -ID, privater IP-Adressbereich (z. B. 10.0.0.0/16), DHCP und Gateway.

:::info
Auf dedizierten Servern wird standardmäßig VLAN 0 verwendet. Die OpenStack Infrastruktur erfordert, dass Sie Ihre VLAN-ID direkt auf der Infrastruktur-Ebene angeben.

Im Gegensatz zu dedizierten Servern ist es nicht notwendig, ein VLAN direkt auf einer Public Cloud-Instanz zu kennzeichnen.

Weitere Informationen zu diesem Thema finden Sie in der Anleitung "[Mehrere vLANs in einem vRack erstellen](/guides/bare-metal-cloud/dedicated-servers/creating-multiple-vlans-in-a-vrack)".

:::


:::warning
vRack wird auf der OVHcloud Infrastruktur-Ebene verwaltet, was bedeutet, dass Sie es nur im OVHcloud Kundencenter und der OVHcloud APIv6 verwalten können.

Da OpenStack nicht auf der gleichen Ebene liegt, können Sie VLANs nicht über Horizon oder OpenStack API anpassen.

:::


<Tabs>
  <Tab label="OVHcloud Kundencenter">
    Sobald Ihr vRack eingerichtet ist, erstellen Sie ein privates Netzwerk.
    
    Klicken Sie im Bereich <code className="action">Public Cloud</code> auf <code className="action">Private Network</code> im linken Menü unter **Network**.
    
    Klicken Sie auf die Schaltfläche <code className="action">Privates Netzwerk hinzufügen</code>. Die folgende Seite ermöglicht es Ihnen, mehrere Einstellungen anzupassen.
    
    Wählen Sie einen Bereitstellungsmodus und die Region aus, in der Sie das private Netzwerk erstellen möchten.

Im nächsten Schritt werden Ihnen mehrere Optionen präsentiert:
    
    <img className="thumbnail" alt="Optionen für die Erstellung des privaten Netzwerks einschließlich VLAN-ID und DHCP-Einstellungen" src="/images/public-cloud/network-services/getting-started-07-creating-vrack/vrack6-2022.png" loading="lazy" />

Im Feld **Name des privaten Netzwerks** legen Sie einen Namen für Ihr privates Netzwerk fest.
    
    **Netzwerkoption Layer 2**
    
    Wenn Sie das Feld <code className="action">VLAN-ID festlegen</code> ankreuzen, können Sie manuell eine VLAN-ID zwischen 0 und 4000 wählen.
    
    Wenn Sie das Feld nicht ankreuzen, wird dem privaten Netzwerk eine zufällige VLAN-ID zugewiesen.
    
    Wenn Sie mit Servern in diesem VLAN kommunizieren möchten, konsultieren Sie die Anleitung: [Mehrere vLANs in einem vRack erstellen](/guides/bare-metal-cloud/dedicated-servers/creating-multiple-vlans-in-a-vrack).
    
    **Verteilungsoptionen für DHCP-Adressen**
    
    Der Standard-DHCP-Bereich ist 10.1.0.0/16. Sie können einen anderen privaten Bereich Ihrer Wahl verwenden oder DHCP für dieses private Netzwerk deaktivieren.
    
    **Netzwerk-Gateway-Optionen**
    
    - **Die erste Adresse einer bestimmten CIDR als Standard-Gateway ankündigen (DHCP-Option 3)**: Wenn diese Option aktiviert ist, bewirbt der DHCP-Server die erste Adresse im CIDR als Standard-Gateway für Geräte, die mit dem Netzwerk verbunden sind.
    - **Ein Gateway zuweisen und sich mit dem privaten Netzwerk verbinden**: Wählen Sie diese Option, wenn Sie beabsichtigen, Instanzen mit einem privaten Netzwerk zu erstellen. Weitere Informationen finden Sie in den folgenden Anleitungen: [Ein privates Netzwerk mit Gateway erstellen](/guides/public-cloud/network-services/create-private-network-gateway) und [Erstellen und Verbinden mit Ihrer ersten Public Cloud-Instanz](/guides/public-cloud/compute/first-steps-with-public-cloud-instance).
    
    :::warning
    Wenn die zweite Option grau ist, bedeutet dies, dass die ausgewählte Region sie nicht unterstützt. Weitere Informationen finden Sie auf unserer [Seite zur Regionenverfügbarkeit](/links/public-cloud/regions-pci).

    :::

    
    Sobald Sie fertig sind, klicken Sie auf <code className="action">Ihr privates Netzwerk konfigurieren</code>, um den Prozess zu starten.
    
    :::info
    Die Erstellung des privaten Netzwerks kann mehrere Minuten dauern.

    :::

  </Tab>
  <Tab label="OVHcloud APIv6">
    Nachdem Sie sich in die [OVHcloud APIv6-Schnittstelle](/links/api) angemeldet haben, folgen Sie diesen Schritten:
    
    **Schritt 1: Abrufen der erforderlichen Informationen**
    
    **Public Cloud Projekt**
    
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project"} />

    :::info
    Dieser Aufruf ruft die Liste der Projekte ab.

    :::

    
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}"} />

    :::info
    Dieser Aufruf identifiziert das Projekt über das Feld "description".

    :::

    
    **vRack**
    
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/vrack"} />

    :::info
    Geben Sie im Feld "serviceName" die ID Ihres Projekts an. Speichern Sie die vRack-ID-Informationen in der Form "pn-xxxxx".

    :::

    
    **Schritt 2: Erstellen des privaten Netzwerks**
    
    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/network/private"} />

    :::info
    Füllen Sie die Felder mit den zuvor abgerufenen Informationen aus:
    
    - **serviceName**: Projekt-ID.
    - **name**: Name Ihres VLANs.
    
    Sie können das Feld "Region" leer lassen, um es für alle Regionen zu aktivieren.
    
    Der VLAN-Bezeichner (vlanId) ist erforderlich, wenn Sie ein bestimmtes VLAN erstellen möchten.

    :::

    
    Die Erstellung dauert einige Momente.
    
    Sie können Ihre VLAN-Informationen mit dem folgenden Aufruf überprüfen:
    
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/network/private"} />

    :::info
    Dieser Aufruf ruft die "networkId" in dieser Form ab: name-vrack_vlanId.
    
    Beispiel: VLAN 42: pn-xxxxxx_42.

    :::

    
    **Schritt 3: Erstellen eines Subnetzes**
    
    Standardmäßig wird folgender IP-Adressbereich verwendet, wenn kein Subnetz hinzugefügt wird:
    
    ```
    10.1.0.0/16
    ```
    
    Wenn Sie die IP-Zuweisung selbst verwalten möchten, erstellen Sie für jede betroffene Region ein Subnetz mit folgendem Aufruf:
    
    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/network/private/\\{networkId\\}/subnet"} />

Füllen Sie die Felder gemäß der folgenden Tabelle aus.
    
    | Feld        | Beschreibung                                                                                           |
    | ----------- | ------------------------------------------------------------------------------------------------------ |
    | serviceName | ID des Projekts.                                                                                       |
    | networkId   | Ihre Netzwerk-ID, die in den vorherigen Schritten ermittelt wurde. Beispiel: pn-xxxxxx_42 für VLAN 42. |
    | dhcp        | Kontrollkästchen zum Aktivieren / Deaktivieren von DHCP im VLAN.                                       |
    | end         | Letzte Adresse des Subnetzes in dieser Region. Beispiel: 192.168.1.50.                                 |
    | network     | IP-Block des Subnetzes. Beispiel: 192.168.1.0/24.                                                      |
    | region      | Beispiel: SBG3.                                                                                        |
    | start       | Erste Adresse des Subnetzes in dieser Region. Beispiel: 192.168.1.15.                                  |
    
    :::info
    In diesem Schritt wird das Subnetz pro Region erstellt. Sie können die Zuweisung privater IP-Adressen dynamisch über DHCP aktivieren oder deaktivieren.
    
    Sie müssen diesen Vorgang für jede Region wiederholen, in der Ihre Instanzen vorhanden sind.

    :::

    
    :::warning
    Achten Sie darauf, die IP-Adressbereiche für die verschiedenen Regionen voneinander zu trennen. Zum Beispiel:
    
    - Von 192.168.0.2 bis 192.168.0.254 für SBG1.
    - Von 192.168.1.2 bis 192.168.1.254 für GRA1.

    :::

### Ein Netzwerkinterface entfernen <a name="removing-a-private-interface"></a>

:::warning
Das Trennen eines Netzwerkinterfaces ist dauerhaft.

Es ist jedoch wichtig zu beachten, dass, wenn Sie die Schnittstelle "Ext-Net" (öffentliche IP) trennen, diese Adresse wieder zur generellen Nutzung freigegeben wird. Sie kann deshalb nicht einfach erneut zugewiesen werden.   
Diese Aktion ist nur erforderlich, wenn Sie Ihren Server im vRack (privates Netzwerk) isolieren möchten oder wenn Sie ihn von einer oder mehreren VLANs trennen möchten.

:::


Um eine Schnittstelle zu trennen, identifizieren Sie zuerst den Port, der an Ihre Instanz angehängt ist:

```bash
openstack port list --server <instance_id>
+--------------------------------------+------+-------------------+-------------------------------------------------------------------------------------------+
| ID                                   | Name | MAC Address       | Fixed IP Addresses                                                                        |
+--------------------------------------+------+-------------------+-------------------------------------------------------------------------------------------+
| 12345678-abcd-ef01-2345-678910abcdef |      | fa:xx:xx:xx:xx:xx | ip_address='192.168.0.xx', subnet_id='301234567-8901-abscdef12345678910abcd'              |
| 09876543-210a-bcde-f098-76543210abcd |      | fa:yy:yy:yy:yy:yy | ip_address='2001:41d0:xxx:xxxx::xxxx', subnet_id='65432109-abcd-ef09-8765-43210abcdef1'   |
+--------------------------------------+------+-------------------+-------------------------------------------------------------------------------------------+
```

Sobald Sie den Port identifiziert haben, trennen Sie ihn:

```bash
openstack server remove port <instance_id> <port_id>
```

Beispiel:

```bash
openstack server remove port 12345678-90ab-cdef-xxxx-xxxxxxxxxxxx 12345678-abcd-ef01-2345-678910abcdef
```
