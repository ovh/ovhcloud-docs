## Ziel

Internet Protocol Version 6 (IPv6) ist die neueste Version des Internet Protocols (IP). IPv6 wurde entwickelt, um das Problem der seit Langem erwarteten Erschöpfung der IPv4-Adressen zu lösen, indem Adressen aus 128 Bit statt der standardmäßigen 32 Bit von IPv4 verwendet werden.

Jede Public Cloud Instanz wird mit einer IPv4-Adresse und einer IPv6-Adresse ausgeliefert.

Bei aktuellen Linux-Distributionen ist die IPv6-Adresse standardmäßig konfiguriert. Bei Windows-Instanzen ist dies nicht der Fall.

**Diese Anleitung erklärt, wie Sie eine IPv6-Adresse auf einer Public Cloud Instanz konfigurieren.**

:::info
Floating IP und Gateway unterstützen IPv6 derzeit nicht. Sie können IPv6 nur mit Instanzen verwenden, die über eine [Basic IP](/guides/public-cloud/network-services/concepts#publicmode) verfügen. In 3-AZ-Regionen kann die IPv6-Adresse einer Basic IP noch nicht über das OVHcloud Kundencenter bereitgestellt werden.

:::

## Voraussetzungen

- Sie verfügen über eine Public Cloud Instanz, wobei das Modell keine Rolle spielt.
- Sie haben administrativen Zugriff (sudo) auf Ihren Server via SSH oder Remotedesktop (Windows).
- Sie verfügen über Grundkenntnisse im Bereich Netzwerke.

## In der praktischen Anwendung

Die folgenden Abschnitte enthalten die Konfigurationen der derzeit von uns angebotenen Distributionen sowie der am häufigsten verwendeten Distributionen/Betriebssysteme. Der erste Schritt besteht immer darin, sich via SSH oder über eine GUI-Anmeldesitzung (RDP für eine Windows-Instanz) mit Ihrem Server zu verbinden.

:::warning
Beachten Sie, dass die IPv6-Adresse bei aktuellen Linux-Distributionen auf unseren Public Cloud Instanzen standardmäßig konfiguriert ist. Überprüfen Sie unbedingt die Konfigurationsdatei des Betriebssystems, bevor Sie Änderungen vornehmen.

:::

### Glossar

Hier finden Sie ein kurzes Glossar der in dieser Anleitung verwendeten Begriffe:

|Glossar|Beschreibung|
|---|---|
|YOUR_IPV6|Die Ihrem Dienst zugewiesene IPv6-Adresse (z. B. 2607:5300:60:62ac:abcd)|
|IPV6_PREFIX|Das Präfix Ihres IPv6-Blocks (z. B. 2607:5300:60:62ac::/128 -> netmask = 128)|
|IPV6_GATEWAY|Das Gateway Ihres IPv6-Blocks (z. B. 2607:5300:60:62ac::1)|

<Tabs>
  <Tab label="Debian (außer Debian 12)">
    Standardmäßig befinden sich die Konfigurationsdateien im Verzeichnis `/etc/network/interfaces.d/`.
    
    Es empfiehlt sich, zur Konfiguration von IPv6 eine separate Konfigurationsdatei im Verzeichnis `/etc/network/interfaces.d/` zu erstellen. In unserem Beispiel heißt die Datei `51-cloud-init-ipv6`:
    
    ```bash
    sudo nano /etc/network/interfaces.d/51-cloud-init-ipv6
    ```
    
    Auf diese Weise bleibt die IPv6-Konfiguration getrennt, und Sie können die Änderungen bei Bedarf einfach rückgängig machen.
    
    Fügen Sie der Datei die folgenden Zeilen hinzu. Ersetzen Sie die generischen Elemente (`YOUR_IPV6`, `IPV6_PREFIX` und `IPV6_GATEWAY`) sowie die Netzwerkschnittstelle (falls Ihr Server nicht **eth0** verwendet) durch Ihre spezifischen Werte:
    
    ```console
    iface eth0 inet6 static
    address YOUR_IPV6
    netmask IPV6_PREFIX
    post-up /sbin/ip -6 route add IPV6_GATEWAY dev eth0
    post-up /sbin/ip -6 route add default via IPV6_GATEWAY dev eth0
    pre-down /sbin/ip -6 route del default via IPV6_GATEWAY dev eth0
    pre-down /sbin/ip -6 route del IPV6_GATEWAY dev eth0
    ```
    
    <details>
    <summary>Beispielkonfiguration</summary>

    ```console
    iface eth0 inet6 static
    address 2607:5300:201:abcd::7c5
    netmask 128
    post-up /sbin/ip -6 route add 2607:5300:201:abcd::1 dev eth0
    post-up /sbin/ip -6 route add default via 2607:5300:201:abcd::1 dev eth0
    pre-down /sbin/ip -6 route del default via 2607:5300:201:abcd::1 dev eth0
    pre-down /sbin/ip -6 route del 2607:5300:201:abcd::1 dev eth0
    ```

    </details>
    
    Starten Sie anschließend Ihren Netzwerkdienst mit einem der folgenden Befehle neu:
    
    ```bash
    sudo service networking restart
    ```
    
    ```bash
    sudo systemctl restart networking
    ```

    Die Konfigurationsdateien für das Netzwerk befinden sich im Verzeichnis `/etc/netplan/`.
    
    Es empfiehlt sich, zur Konfiguration von IPv6 eine separate Konfigurationsdatei im Verzeichnis `/etc/netplan/` zu erstellen. In unserem Beispiel heißt die Datei `51-cloud-init-ipv6.yaml`:
    
    ```bash
    sudo nano /etc/netplan/51-cloud-init-ipv6.yaml
    ```
    
    Auf diese Weise bleibt die IPv6-Konfiguration getrennt, und Sie können die Änderungen bei Bedarf einfach rückgängig machen.
    
    Fügen Sie der Datei die folgenden Zeilen hinzu. Ersetzen Sie die generischen Elemente (`YOUR_IPV6`, `IPV6_PREFIX` und `IPV6_GATEWAY`) sowie die Netzwerkschnittstelle (falls Ihr Server nicht **eth0** verwendet) durch Ihre spezifischen Werte:
    
    ```yaml
    network:
        version: 2
        ethernets:
            eth0:
                dhcp6: no
                match:
                  name: eth0
                addresses:
                  - YOUR_IPV6/IPv6_PREFIX
                routes:
                  - to: ::/0
                    via: IPv6_GATEWAY
    ```
    
    :::warning
    Es ist wichtig, die Ausrichtung jedes Elements dieser Datei genau wie im obigen Beispiel einzuhalten. Verwenden Sie nicht die Tabulatortaste, um die Abstände zu erzeugen. Verwenden Sie ausschließlich die Leertaste.

    :::

  <Tab label="RedHat / CloudLinux / Rocky Linux (8 & 9) / AlmaLinux (8 & 9)">
    Die Konfigurationsdateien für das Netzwerk befinden sich im Verzeichnis `/etc/sysconfig/network-scripts/`. Wir empfehlen Ihnen, zunächst ein Backup der betreffenden Konfigurationsdatei zu erstellen.
    
    In unserem Beispiel heißt die Datei `ifcfg-eth0`. Wir erstellen daher mit den folgenden Befehlen ein Backup der Datei `ifcfg-eth0`. Denken Sie daran, **eth0** bei Bedarf durch Ihre tatsächliche Schnittstelle zu ersetzen.
    
    ```bash
    cd /etc/sysconfig/network-scripts/
    sudo mkdir backup
    sudo cp ifcfg-eth0 backup/ifcfg-eth0
    ```
    
    Mit den folgenden Befehlen können Sie die Änderungen anschließend rückgängig machen:
    
    ```bash
    sudo rm -f /etc/sysconfig/network-scripts/ifcfg-eth0
    sudo cp /etc/sysconfig/network-scripts/backup/ifcfg-eth0 /etc/sysconfig/network-scripts/ifcfg-eth0
    ```
    
    Anschließend bearbeiten wir die Datei `ifcfg-eth0` und fügen nur die Zeilen für die IPv6-Konfiguration des Servers hinzu. Ersetzen Sie die generischen Elemente (`YOUR_IPV6`, `IPV6_PREFIX` und `IPV6_GATEWAY`) durch Ihre spezifischen Werte.
    
    ```console
    IPV6INIT=yes
    IPV6ADDR=YOUR_IPV6/IPV6_PREFIX
    IPV6_DEFAULTGW=IPV6_GATEWAY
    ```
    
    Wir haben die IPv4-Konfiguration ausgelassen, um Verwechslungen zu vermeiden, aber die IPv6-Konfiguration wird in derselben Konfigurationsdatei vorgenommen.

    ```console
    IPV6_DEFAULTGW=2607:5300:201:abcd::1
    ```

    </details>

### Diagnose

Sie haben IPv6 konfiguriert, aber es funktioniert dennoch nicht?

Führen Sie diesen einfachen Test durch, um festzustellen, ob der Fehler in Ihrer Konfiguration oder im Netzwerk von OVHcloud liegt.

Versetzen Sie Ihre Instanz zunächst [in den Rescue-Modus (rescue-pro)](/guides/public-cloud/compute/put-an-instance-in-rescue-mode).

Verwenden Sie anschließend die folgenden Befehlsvorlagen, um IPv6 nicht persistent zu konfigurieren. Ersetzen Sie dabei `YOUR_IPV6`, `IPV6_PREFIX` und `IPV6_GATEWAY` durch Ihre eigenen Angaben:

```bash
ip addr add YOUR_IPV6/IPV6_PREFIX dev eth0
ip -6 route add IPV6_GATEWAY dev eth0
ip -6 route add default via IPV6_GATEWAY dev eth0
```

Testen Sie Ihr Netzwerk erneut über ping6, zum Beispiel:

```bash
ping6 ipv6.google.com
```

Wenn Ihre Instanz antwortet, liegt wahrscheinlich ein Fehler in einem der Schritte vor, die Sie für Ihre ursprüngliche Konfiguration ausgeführt haben.

In jedem Fall können Sie sich mit den oben getesteten Elementen gerne an unser [Support-Team](/links/support-contact) wenden, damit wir unsererseits eine Analyse durchführen können.
