## Ziel

Eine OVHcloud [Gateway](/links/public-cloud/gateway) bietet eine sichere ausgehende Verbindung (SNAT) für Instanzen in einem privaten Netzwerk-Subnetz und ist auf diesem Subnetz erforderlich, um [Floating IPs](/links/public-cloud/floating-ip) für die öffentliche Bereitstellung dieser privaten Ressourcen zu verwenden.

**Diese Anleitung erklärt, wie Sie eine Public Cloud Gateway über das OVHcloud Kundencenter, die OVHcloud API, ovhcloud-cli oder Terraform erstellen, auflisten, bearbeiten und löschen.**

## Voraussetzungen

- Sie verfügen über ein [Public Cloud Projekt](/links/public-cloud/public-cloud) in Ihrem OVHcloud Account.
- Sie verfügen über ein privates Netzwerk mit mindestens einem Subnetz in der Zielregion (siehe [vRack für Public Cloud konfigurieren](/guides/public-cloud/network-services/vrack)).
- **Für die OVHcloud API:** Sie verfügen über OVHcloud API-Zugangsdaten ([Erste Schritte mit der OVHcloud API](/guides/manage-and-operate/api/first-steps)).
- **Für ovhcloud-cli:** Sie haben [ovhcloud-cli](https://github.com/ovh/ovhcloud-cli) installiert und mit Ihren Zugangsdaten konfiguriert.
- **Für Terraform:** Sie haben Terraform installiert und den OVH Provider konfiguriert ([Terraform mit OVHcloud verwenden](/guides/public-cloud/cross-functional/how-to-use-terraform)).

## In der praktischen Anwendung

### Gateway-Modelle

Wählen Sie vor dem Erstellen einer Gateway das Modell aus, das Ihren Anforderungen an die Bandbreite entspricht:

| Modell | Bandbreite |
|--------|------------|
| S | bis zu 200 Mbps |
| M | bis zu 500 Mbps |
| L | bis zu 2 Gbps |
| XL | bis zu 4 Gbps |
| 2XL | bis zu 8 Gbps |
| 3XL | bis zu 16 Gbps |

### Eine Gateway erstellen

<Tabs>
  <Tab label="OVHcloud Kundencenter">
    Klicken Sie in Ihrem Public Cloud Projekt im linken Menü unter **Network** auf <code className="action">Gateway</code> und anschließend auf <code className="action">Gateway erstellen</code>.

    1. **Wählen Sie eine Region aus.** Wählen Sie die Region, in der Ihre privaten Instanzen bereitgestellt werden.
    2. **Wählen Sie eine Größe aus.** Wählen Sie das Gateway-Modell entsprechend Ihren Anforderungen an die Bandbreite (siehe Tabelle oben).
    3. **Benennen und verknüpfen Sie ein Netzwerk.** Geben Sie einen Namen für Ihre Gateway ein und wählen Sie ein bestehendes privates Netzwerk aus der Dropdown-Liste aus, oder klicken Sie auf <code className="action">Privates Netzwerk hinzufügen</code>, um direkt eines zu erstellen.
    4. Klicken Sie auf <code className="action">Gateway erstellen</code>, um zu bestätigen. Die Bereitstellung der Gateway dauert einige Minuten.

    Nach der Erstellung erscheint die Gateway im Bereich <code className="action">Gateway</code> und das zugehörige private Netzwerk ist unter <code className="action">Private Netzwerke</code> sichtbar.

    :::info
    Von der Gateway werden nur Single-Region-Netzwerke unterstützt.

    :::
  </Tab>
  <Tab label="OVHcloud API">
    Öffnen Sie die <ApiLink>OVHcloud API</ApiLink> und verwenden Sie den folgenden Aufruf, um eine Gateway zusammen mit einem neuen privaten Netzwerk und einem Subnetz in einem einzigen Vorgang zu erstellen:

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway"} />

    | Feld | Beschreibung |
    |------|--------------|
    | `serviceName` | Die ID Ihres Public Cloud Projekts |
    | `regionName` | Die Zielregion (z. B. `GRA9`) |
    | `model` | Gateway-Größe: `s`, `m`, `l`, `xl`, `2xl`, `3xl` |
    | `name` | Name Ihrer Gateway |
    | `network.name` | Name des neuen privaten Netzwerks |
    | `network.cidr` | Subnetz-CIDR (z. B. `192.168.1.0/24`) |
    | `network.enableDhcp` | `true`, um DHCP im Subnetz zu aktivieren |
    | `network.ipVersion` | `4` (IPv6 noch nicht unterstützt) |
    | `network.vlanId` | VLAN-Kennung (2–4000) oder leer für eine automatische Zuweisung |

    Der Aufruf gibt ein `cloud.Operation`-Objekt zurück. Um eine Gateway mit einem **bestehenden** Subnetz zu verknüpfen, verwenden Sie:

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/network/\\{networkId\\}/subnet/\\{subnetId\\}/gateway"} />

    Um die ID Ihres Projekts abzurufen:

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project"} />
  </Tab>
  <Tab label="ovhcloud-cli">
    Verwenden Sie `ovhcloud cloud network gateway create` mit der Zielregion und der Option `--wait`, um bis zum Abschluss der Bereitstellung zu warten.

    **Eine Gateway in einem bestehenden privaten Netzwerk erstellen:**

    ```bash
    ovhcloud cloud network gateway create <region> \
      --cloud-project <project_id> \
      --name my-gateway \
      --model s \
      --network-id <network_id> \
      --subnet-id <subnet_id> \
      --wait
    ```

    **Eine Gateway mit einem neuen privaten Netzwerk erstellen:**

    ```bash
    ovhcloud cloud network gateway create <region> \
      --cloud-project <project_id> \
      --name my-gateway \
      --model s \
      --network-name my-network \
      --subnet-cidr 192.168.1.0/24 \
      --subnet-enable-dhcp \
      --wait
    ```

    Verfügbare Modelle: `s`, `m`, `l`, `xl`, `2xl`, `3xl`.
  </Tab>
  <Tab label="Terraform">
    Erstellen Sie eine Terraform-Konfigurationsdatei (z. B. `gateway.tf`) mit den folgenden Ressourcen:

    ```hcl
    resource "ovh_cloud_project_network_private" "mypriv" {
      service_name = "<project_id>"
      vlan_id      = "0"
      name         = "my-network"
      regions      = ["GRA9"]
    }

    resource "ovh_cloud_project_network_private_subnet" "myprivsub" {
      service_name = ovh_cloud_project_network_private.mypriv.service_name
      network_id   = ovh_cloud_project_network_private.mypriv.id
      region       = "GRA9"
      start        = "10.0.0.2"
      end          = "10.0.255.254"
      network      = "10.0.0.0/16"
      dhcp         = true
    }

    resource "ovh_cloud_project_gateway" "gateway" {
      service_name = ovh_cloud_project_network_private.mypriv.service_name
      name         = "my-gateway"
      model        = "s"
      region       = ovh_cloud_project_network_private_subnet.myprivsub.region
      network_id   = tolist(ovh_cloud_project_network_private.mypriv.regions_attributes[*].openstackid)[0]
      subnet_id    = ovh_cloud_project_network_private_subnet.myprivsub.id
    }
    ```

    Wenden Sie die Konfiguration an:

    ```bash
    terraform init
    terraform apply
    ```

    :::info
    Ersetzen Sie `GRA9` durch Ihre Zielregion und `<project_id>` durch die ID Ihres Public Cloud Projekts.

    :::
  </Tab>
</Tabs>

### Ihre Gateways auflisten

<Tabs>
  <Tab label="OVHcloud Kundencenter">
    Klicken Sie in Ihrem Public Cloud Projekt im linken Menü unter **Network** auf <code className="action">Gateway</code>.

    Die Seite listet alle Gateways Ihres Projekts mit ihrer Region, ihrem Modell, ihrem Status und ihrem zugehörigen Netzwerk auf.
  </Tab>
  <Tab label="OVHcloud API">
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway"} />

    | Feld | Beschreibung |
    |------|--------------|
    | `serviceName` | Die ID Ihres Public Cloud Projekts |
    | `regionName` | Die Zielregion |
    | `subnetId` | (Optional) Nach zugehöriger Subnetz-ID filtern |
    | `withSubnets` | (Optional) Subnetz-Details in die Antwort aufnehmen |
  </Tab>
  <Tab label="ovhcloud-cli">
    ```bash
    ovhcloud cloud network gateway list --cloud-project <project_id>
    ```

    Nach Namensmuster filtern:

    ```bash
    ovhcloud cloud network gateway list \
      --cloud-project <project_id> \
      --filter 'name=~"^my-.*"'
    ```
  </Tab>
</Tabs>

### Eine Gateway bearbeiten

Sie können den Namen oder das Modell (Größe) einer bestehenden Gateway ändern.

<Tabs>
  <Tab label="OVHcloud Kundencenter">
    Klicken Sie in der Liste <code className="action">Gateway</code> auf das Menü <code className="action">...</code> neben Ihrer Gateway und wählen Sie dann <code className="action">Bearbeiten</code> aus.

    Ändern Sie den Namen oder wählen Sie ein neues Modell aus und bestätigen Sie anschließend.
  </Tab>
  <Tab label="OVHcloud API">
    <Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway/\\{id\\}"} />

    Übergeben Sie die zu ändernden Felder im Anfragetext (`name`, `model` oder beide).
  </Tab>
  <Tab label="ovhcloud-cli">
    ```bash
    ovhcloud cloud network gateway edit <gateway_id> \
      --cloud-project <project_id> \
      --name new-name \
      --model m
    ```

    Sie können `--name`, `--model` oder beide verwenden.
  </Tab>
  <Tab label="Terraform">
    Ändern Sie das Feld `name` oder `model` in Ihrem Ressourcenblock `ovh_cloud_project_gateway` und wenden Sie anschließend an:

    ```bash
    terraform apply
    ```
  </Tab>
</Tabs>

### Eine Gateway löschen

:::warning
Das Löschen einer Gateway ist unwiderruflich. Instanzen, die sie für ihre ausgehende Verbindung nutzen, verlieren ihren Internetzugang.

:::

<Tabs>
  <Tab label="OVHcloud Kundencenter">
    Klicken Sie in der Liste <code className="action">Gateway</code> auf das Menü <code className="action">...</code> neben Ihrer Gateway, wählen Sie dann <code className="action">Löschen</code> aus und bestätigen Sie.
  </Tab>
  <Tab label="OVHcloud API">
    <Api version="v1" section="/cloud" method="DELETE" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway/\\{id\\}"} />

    Der Aufruf gibt ein `cloud.Operation` zurück. Das Löschen erfolgt asynchron — überprüfen Sie bei Bedarf den Status des Vorgangs:

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/operation/\\{operationId\\}"} />
  </Tab>
  <Tab label="ovhcloud-cli">
    ```bash
    ovhcloud cloud network gateway delete <gateway_id> \
      --cloud-project <project_id>
    ```
  </Tab>
  <Tab label="Terraform">
    Entfernen Sie den Ressourcenblock `ovh_cloud_project_gateway` aus Ihrer Konfigurationsdatei und wenden Sie anschließend an:

    ```bash
    terraform apply
    ```

    Um alle Ressourcen der Konfiguration zu löschen:

    ```bash
    terraform destroy
    ```
  </Tab>
</Tabs>
