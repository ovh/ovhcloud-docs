## Ziel

Ein [Gateway](/links/public-cloud/gateway) bietet eine sichere Methode für ausgehende Verbindungen von den Instanzen Ihres privaten Netzwerks oder die Möglichkeit, Floating IPs mit Ihrer Instanz oder Ihrem Load Balancer für die Bereitstellung von Diensten zu verwenden.

**Diese Anleitung erklärt, wie Sie ein privates Netzwerk mit einem Gateway erstellen.**

## Voraussetzungen

- Sie verfügen über ein [Public Cloud Projekt](/links/public-cloud/public-cloud) in Ihrem OVHcloud Account.
- **Für die OVHcloud API:** Sie verfügen über API-Anmeldedaten ([Erste Schritte mit der OVHcloud API](/guides/manage-and-operate/api/first-steps)).
- **Für die OVHcloud CLI:** Sie haben die [OVHcloud CLI](https://github.com/ovh/ovhcloud-cli) installiert und mit Ihren Anmeldedaten konfiguriert.
- **Für die OpenStack API:** Sie haben eine OpenStack Umgebung konfiguriert ([Vorbereiten der Umgebung](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment)).
- **Für Terraform:** Sie haben Terraform installiert und den OVHcloud Provider konfiguriert ([Verwendung von Terraform](/guides/public-cloud/cross-functional/how-to-use-terraform)).

## In der praktischen Anwendung

### Gateway-Modelle

Bevor Sie ein Gateway erstellen, wählen Sie das Modell, das Ihrem Bandbreitenbedarf entspricht:

| Modell | Bandbreite |
|--------|------------|
| S | bis zu 200 Mbps |
| M | bis zu 500 Mbps |
| L | bis zu 2 Gbps |
| XL | bis zu 4 Gbps |
| 2XL | bis zu 8 Gbps |
| 3XL | bis zu 16 Gbps |

### Privates Netzwerk mit einem Gateway erstellen

    Bearbeiten Sie den Standardnamen Ihres Gateways und wählen Sie ein vorhandenes privates Netzwerk aus der Dropdown-Liste aus.

  <Tab label="OVHcloud API">
    Öffnen Sie die OVHcloud APIv6-Schnittstelle. Lesen Sie bei Bedarf die Anleitung [Erste Schritte mit der OVHcloud API](/guides/manage-and-operate/api/first-steps).

    **Projekt-ID abrufen**

    Wenn die Projekt-ID unbekannt ist, verwenden Sie die folgenden Aufrufe:

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project"} />

    :::info
    Dieser Aufruf ruft die Liste der Projekte ab.
    :::

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}"} />

    :::info
    Dieser Aufruf identifiziert das Projekt über das Feld "description".
    :::

    **Privates Netzwerk mit einem Gateway erstellen**

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway"} />

    Füllen Sie die Felder gemäß der folgenden Tabelle aus:

    | Feld | Beschreibung |
    |------|--------------|
    | `serviceName` | Ihre Projekt-ID |
    | `regionName` | Beispiel: `GRA9` |
    | `model` | Gateway-Größe (`s`, `m`, `l`, `xl`, `2xl`, `3xl`) |
    | `name` | Name für Ihr Gateway (`null` für Standard) |
    | `network.name` | Name für das private Netzwerk (`null` für Standard) |
    | `network.cidr` | IP-Block für Ihr Subnetz (z. B. `192.168.1.0/24`) |
    | `network.enableDhcp` | Kontrollkästchen zum Aktivieren von DHCP |
    | `network.ipVersion` | `4` (IPv6 nicht verfügbar) |
    | `network.vlanId` | Wert zwischen 2 und 4000 oder leer für automatische Zuweisung |

    :::info
    Wiederholen Sie dies für jede Region, in der Ihre privaten Instanzen vorhanden sind.
    :::

    Um die Details Ihres Gateways zu überprüfen:

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway"} />

    Lassen Sie `subnetId` leer, um alle Gateways in der angegebenen Region aufzulisten.
  </Tab>
  <Tab label="OVHcloud CLI">
    Verwenden Sie die [OVHcloud CLI](https://github.com/ovh/ovhcloud-cli), um ein privates Netzwerk mit einem Gateway zu erstellen. Legen Sie Ihr Cloud-Projekt mit `--cloud-project <project_id>` fest oder konfigurieren Sie es in Ihrem Profil.

    **Ein Gateway mit einem neuen privaten Netzwerk erstellen:**

    ```bash
    ovhcloud cloud network gateway create <region> \
      --cloud-project <project_id> \
      --name my-gateway \
      --model s \
      --network-name my-network \
      --subnet-cidr 192.168.1.0/24 \
      --subnet-enable-dhcp \
      --wait
    ```

    **Ein Gateway in einem vorhandenen privaten Netzwerk erstellen:**

    ```bash
    ovhcloud cloud network gateway create <region> \
      --cloud-project <project_id> \
      --name my-gateway \
      --model s \
      --network-id <network_id> \
      --subnet-id <subnet_id> \
      --wait
    ```

    Verfügbare Modelle: `s`, `m`, `l`, `xl`, `2xl`, `3xl`.

    :::info
    Gateway unterstützt nur private Netzwerke mit einer einzelnen Region.
    :::
  </Tab>
  <Tab label="OpenStack API">
    Lesen Sie vor dem Fortfahren die folgenden Anleitungen:

    - [Vorbereiten einer Umgebung für die Verwendung der OpenStack API](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment)
    - [OpenStack Umgebungsvariablen einrichten](/guides/public-cloud/cross-functional/compute-set-openstack-environment-variables)

    **Schritt 1 — Ein Netzwerk und ein Subnetz erstellen**

    ```console
    openstack network create my_network

    openstack subnet create my_subnet --subnet-range <my_private_ip_range/mask> --network my_network --no-dhcp
    ```

    **Schritt 2 — Quality-of-Service-Richtlinien auflisten**

    ```console
    openstack network qos policy list
    +--------------------------------------+---------------+--------+---------+----------------------------------+
    | ID                                   | Name          | Shared | Default | Project                          |
    +--------------------------------------+---------------+--------+---------+----------------------------------+
    | a5524eb5-944e-4106-b209-9478bbdcedab | large_router  | True   | False   | XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX |
    | c210f5b2-db59-4973-a25f-9131195b6bcf | medium_router | True   | False   | XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX |
    | ec0ee74d-a1f3-43f6-87aa-b0e69ef8ce45 | small_router  | True   | False   | XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX |
    +--------------------------------------+---------------+--------+---------+----------------------------------+
    ```

    **Schritt 3 — Den Router erstellen und das Gateway konfigurieren**

    ```console
    openstack router create my_router

    openstack router add subnet my_router my_subnet

    openstack router set --external-gateway Ext-Net --qos-policy QOS_ID_OF_YOUR_CHOICE my_router
    ```

    Wenn Sie den Parameter `--qos-policy` weglassen, wird die `small` Quality of Service angewendet.
  </Tab>
  <Tab label="Terraform">
    Lesen Sie vor dem Fortfahren die Anleitung: [Verwendung von Terraform](/guides/public-cloud/cross-functional/how-to-use-terraform)

    Erstellen Sie eine Terraform-Datei (z. B. `private_network_gateway.tf`) mit folgendem Inhalt:

    ```hcl
    resource "ovh_cloud_project_network_private" "mypriv" {
      service_name = "<project_id>"
      vlan_id      = "0"
      name         = "mypriv"
      regions      = ["GRA9"]
    }

    resource "ovh_cloud_project_network_private_subnet" "myprivsub" {
      service_name = ovh_cloud_project_network_private.mypriv.service_name
      network_id   = ovh_cloud_project_network_private.mypriv.id
      region       = "GRA9"
      start        = "10.0.0.2"
      end          = "10.0.255.254"
      network      = "10.0.0.0/16"
      dhcp         = true
    }

    resource "ovh_cloud_project_gateway" "gateway" {
      service_name = ovh_cloud_project_network_private.mypriv.service_name
      name         = "my-gateway"
      model        = "s"
      region       = ovh_cloud_project_network_private_subnet.myprivsub.region
      network_id   = tolist(ovh_cloud_project_network_private.mypriv.regions_attributes[*].openstackid)[0]
      subnet_id    = ovh_cloud_project_network_private_subnet.myprivsub.id
    }
    ```

    Wenden Sie die Konfiguration an:

    ```console
    terraform apply
    ```
