## Ziel

Sie haben gerade Ihr Public Cloud Projekt erstellt und möchten mehr über das Benutzerinterface in der OVHcloud Konsole erfahren.

**Diese Anleitung erklärt die wichtigsten Bereiche des Public Cloud Interface in der OVHcloud Konsole.**

## Voraussetzungen

- Sie haben ein erstes [Public Cloud Projekt](/guides/public-cloud/cross-functional/create-a-public-cloud-project) erstellt.

[[cpnav:publiccloud-projects-console]]

## In der praktischen Anwendung

Sobald Sie Ihr erstes Public Cloud Projekt erstellt haben, werden Sie auf dessen Startseite in der OVHcloud Konsole weitergeleitet. Der Seitentitel ist der Name Ihres Projekts.

Die Startseite besteht aus Widgets: **Ressourcen**, **Abrechnung**, **Schnellzugriff**, **Meine letzten Tickets**, **Dokumentation und Support**, **Entwickler-Ressourcen** und **Roadmap & Changelog**. Sie können ein Widget über das Symbol in seiner oberen rechten Ecke entfernen, mit <code className="action">Widget hinzufügen</code> ein Widget hinzufügen und mit <code className="action">Layout zurücksetzen</code> die Standardanordnung wiederherstellen.

### Zugriff auf Ihre OVHcloud Account-Informationen

Die Einstellungen Ihres OVHcloud Accounts, Ihre Benachrichtigungen und die Sprache der OVHcloud Konsole sind jederzeit über die obere Leiste erreichbar:

- Klicken Sie auf <code className="action">Kontomenü</code> (das Symbol mit Ihren Initialen rechts in der oberen Leiste), um die Sprache zu ändern, zum dunklen Design zu wechseln, Ihren Account, Ihre Rechnungen, Bestellungen und Zahlungsmittel aufzurufen, den Support zu kontaktieren oder sich abzumelden.
- Klicken Sie auf das Glockensymbol daneben, um Ihre Benachrichtigungen anzuzeigen.

### Ihr Public Cloud Projekt

Da Sie (je nach Ihren Quotas) mehrere Projekte verwenden können, wird der Name des aktuellen Projekts unabhängig vom aufgerufenen Bildschirm immer im Auswahlfeld **Projekt** oben im linken Menü angezeigt. So wissen Sie stets, in welcher Umgebung Sie arbeiten.

Die Projekt-ID kann bei der Verwendung der CLI, bei bestimmten Support-Anfragen oder in anderen Fällen erforderlich sein. So kopieren Sie sie:

1. Klicken Sie oben im linken Menü auf das Auswahlfeld <code className="action">Projekt</code>. Die Liste Ihrer Projekte wird geöffnet, mit der ID jedes Projekts unter seinem Namen.
2. Klicken Sie in der Zeile Ihres Projekts auf das Kopiersymbol.

So benennen Sie Ihr Projekt um:

1. Klicken Sie im linken Menü auf <code className="action">Projektverwaltung</code>.
2. Klicken Sie auf den Tab <code className="action">Einstellungen</code>.
3. Geben Sie im Feld **Projektname** den neuen Namen ein.
4. Klicken Sie auf <code className="action">Bestätigen</code>.

### Das Public Cloud Hauptmenü

Das linke Menü Ihres Projekts gruppiert die Public Cloud Produkte nach Bereichen. Klicken Sie auf einen Bereich, um dessen Produkte anzuzeigen.

|Abschnitt|Beschreibung der Optionen|
|---|---|
|**Compute**|In diesem Bereich können Sie Instanzen starten, also Cloud Server, die *on demand* verfügbar sind, und deren Reservierungen, Backups und Workflows verwalten.|
|**Netzwerk**|In diesem Bereich finden Sie alles, was Sie benötigen, um Ihre Public Cloud Ressourcen untereinander und mit anderen OVHcloud Produkten zu verbinden: private Netzwerke, Subnetze, Private Endpoints, öffentliche IPs, Gateways und Load Balancer.|
|**Serverless**|Dieser Bereich, derzeit in der Alpha-Phase, bietet Serverless-Container und -Funktionen sowie deren Verbrauch und Quotas.|
|**Speicher**|In diesem Bereich finden Sie die verschiedenen Storage-Lösungen (Object Storage, Block Storage, File Storage, Cold Archive, Cloud Archive) sowie die Backups und Snapshots von Volumes, die jeweils einem bestimmten Bedarf und einer bestimmten Nutzung entsprechen.|
|**Container**|Dieser Bereich bietet Ihnen verschiedene Tools zur Automatisierung Ihrer Architekturen und zur Erhöhung der Flexibilität: Managed Kubernetes Service, Managed Private Registry und Managed Rancher Service.|
|**Datenbanken**|Dieser Bereich bietet verwaltete Datenbanken: PostgreSQL, MySQL, MongoDB und Valkey.|
|**Analytics**|Diese Dienste unterstützen Sie bei der Lösung von Big Data und Data Analytics Problemen: Kafka, ClickHouse, OpenSearch, Managed Dashboards, Data Platform und Lakehouse.|
|**AI**|In diesem Bereich finden Sie die OVHcloud Tools für künstliche Intelligenz: AI Notebooks, AI Training, AI Deploy, AI Endpoints und AI Agents.|
|**Quantum**|Dieser Bereich umfasst Dienste rund um Quantencomputing: QPUs und Emulatoren.|

Unter diesen Bereichen geben die Links **Projektverwaltung** und **Kostenstelle** Zugriff auf die Verwaltungswerkzeuge des Projekts (siehe [Die Verwaltungswerkzeuge](#die-verwaltungswerkzeuge)).

Klicken Sie oben im Menü auf <code className="action">Meine Services</code>, um nur die in Ihrem Projekt erstellten Dienste anzuzeigen, und auf <code className="action">Produkte</code>, um zur vollständigen Liste zurückzukehren.

### Shortcuts

Das Widget **Schnellzugriff** auf der Startseite des Projekts bietet Shortcuts zu den nützlichsten Konfigurationsassistenten, etwa <code className="action">Instanz erstellen</code>, <code className="action">Cluster erstellen</code> oder <code className="action">Privates Netzwerk erstellen</code>. Anleitungen finden Sie im Widget **Dokumentation und Support**.

#### Assistent zur Erstellung von Ressourcen

Für jede Ressource, die Sie erstellen möchten, führt Sie eine Konfigurationsseite Abschnitt für Abschnitt durch die Einstellungen, damit Sie die Ressource nach Ihren Bedürfnissen einrichten können.

In den meisten Fällen wählen Sie den Standort der Ressource (ihre Region), das Modell, einige individuelle Parameter und in manchen Fällen den Abrechnungsmodus aus. Die Seite zur Erstellung einer Instanz umfasst zum Beispiel den Namen der Instanz, die Region, das Modell, den Speicher, das Image, den SSH-Schlüssel, die Backup-, Netzwerk- und erweiterten Einstellungen und anschließend den Button <code className="action">Meine Instanz erstellen</code>.

### Die Verwaltungswerkzeuge

In Ihrem Public Cloud Projekt stehen mehrere Verwaltungswerkzeuge zur Konfiguration Ihrer Ressourcen, Benutzer und Einstellungen zur Verfügung. Sie erreichen sie über die beiden Links unten im linken Menü, unterhalb der Produktbereiche: **Projektverwaltung** mit den Konfigurationsoptionen des Projekts (Benutzer, Quotas, Standorte, SSH-Schlüssel, Kontakte, Einstellungen) und **Kostenstelle** mit der Abrechnung.

Um das Horizon-Interface zu öffnen, klicken Sie im Widget **Dokumentation und Support** auf der Startseite des Projekts auf <code className="action">OpenStack Horizon</code>. Horizon ist die [grafische Oberfläche](/guides/public-cloud/cross-functional/introducing-horizon), die üblicherweise für OpenStack verfügbar ist. Sie ist unverändert, sodass Benutzer, die mit diesem Interface vertraut sind, es wie gewohnt verwenden können.

Der Link <code className="action">Projektverwaltung</code> öffnet die folgenden Tabs:

|Tab|Beschreibung|
|---|---|
|**SSH-Schlüssel**|Ein Werkzeug, mit dem Sie Ihre [SSH-Schlüssel](/guides/public-cloud/compute/creating-ssh-keys) zentral verwalten können.|
|**Quotas**|Unser System setzt nach bestimmten Kriterien (Anzahl bereits bezahlter Rechnungen, Verwendung anderer OVHcloud Produkte) Quotas (Limitierungen) für die Anzahl der Ressourcen, die Sie erstellen können, um Zahlungsausfälle zu vermeiden. Standardmäßig erhöht das System Ihre Quotas automatisch, wenn bestimmte Kriterien erfüllt sind. Sie können in diesem Tab jedoch [eine Quota manuell erhöhen](/guides/public-cloud/cross-functional/increasing-public-cloud-quota#manuelle-erhöhung-ihrer-ressourcenquote).|
|**Standorte**|Die Public Cloud ist an mehreren Standorten weltweit verfügbar. Darüber hinaus kann jeder Standort mehrere "Regionen" (ein OpenStack-spezifisches Konzept) umfassen. Für einen europäischen Kunden beispielsweise ist die APAC-Zone (Asien-Pazifik) standardmäßig deaktiviert. Bei Bedarf können Sie in diesem Tab neue Standorte hinzufügen.|
|**Logs**|Hier können Sie die [Logs](/guides/public-cloud/cross-functional/logs-concepts) Ihres Projekts einsehen und an Logs Data Platform weiterleiten.|
|**Kontakte & Rechte**|Neben der Möglichkeit, den technischen Kontakt oder den Rechnungskontakt Ihres Projekts zu ändern, können Sie weitere [Kontakte (OVHcloud Account) hinzufügen](/guides/public-cloud/compute/change-project-contacts), um Ihr Projekt technisch zu verwalten. Sie können auch Benutzer mit Berechtigung *read-only* hinzufügen.|
|**Benutzer**|Ermöglicht die [Erstellung von Benutzern](/guides/public-cloud/cross-functional/create-and-delete-a-user) und die Zuweisung einer Rolle. Diese Benutzer können auch direkt auf die APIs oder das Horizon-Interface zugreifen. Sie können zum Beispiel einen Benutzer für Ihre üblichen Wartungsarbeiten und einen Benutzer für Automatisierungswerkzeuge wie Terraform erstellen.|
|**Einstellungen**|In diesem Tab können Sie die allgemeinen Einstellungen des Projekts konfigurieren, etwa seinen Namen und seine Konfiguration als "Standardprojekt des Accounts", oder Ihr [Public Cloud Projekt löschen](/guides/public-cloud/cross-functional/delete-a-project). Wenn Ihr Account über das Support-Level Business oder Enterprise verfügt, können Sie in diesem Tab außerdem die HDS-Zertifizierung aktivieren.|

Der Link <code className="action">Kostenstelle</code> öffnet die folgenden Tabs:

|Tab|Beschreibung|
|---|---|
|**Aktueller Verbrauch**, **Schätzung meiner nächsten Rechnung**, **Verlauf**|Public Cloud funktioniert nach dem Prinzip *pay as you go*, die Rechnungen werden am Ende des Monats ausgestellt. In [diesen Tabs](/guides/public-cloud/cross-functional/analyze-billing) können Sie Ihren aktuellen Verbrauch verfolgen, eine Prognose für die nächste Rechnung einsehen und natürlich Ihre vorherigen Rechnungen abrufen.|
|**Savings Plan**|Dieses Preismodell bietet Rabatte auf bestimmte Ressourcen, wenn Sie sich für Vertragslaufzeiten von bis zu 36 Monaten entscheiden.|
|**Guthaben & Gutscheine**|In diesem Tab können Sie den Verbrauch eines Gutscheins einsehen, einen Gutschein hinzufügen oder Ihrem Public Cloud Projekt direkt [Guthaben hinzufügen](/guides/account-and-service-management/managing-billing-payments-and-services/add-cloud-credit-to-project).|

### Verwaltung von Dienstleistungen

:::info
Dieser Abschnitt bietet einen Überblick über die Optionen zur Verwaltung Ihrer OVHcloud Dienste, wofür drei Tools zur Verfügung stehen: die OVHcloud Konsole, Horizon und die OpenStack API. Jedes dieser Tools ist auf spezifische Nutzeranforderungen zugeschnitten und bietet Verwaltungsoptionen für alle Anforderungen je nach Ihrem Fachwissen, bevorzugten Verwaltungstypen sowie Ihren Leistungs- und Anpassungsbedürfnissen.

Die folgende Tabelle vergleicht die wichtigsten Merkmale jedes Tools, um Ihnen die Auswahl der passenden Lösung zu erleichtern. Egal ob Sie Anfänger, fortgeschrittener Benutzer oder Automatisierungsexperte sind, dieser Vergleich hilft Ihnen, die Vorteile, die Benutzerfreundlichkeit, die erforderlichen Kompetenzniveaus und die Skalierbarkeit jedes Tools besser zu verstehen.

:::


| Kriterien/Eigenschaften                     | OVHcloud Konsole       | Horizon | OpenStack API |
| ------------------------------------------- | ---------------------- | ------- | ------------- |
| Hauptvorteile                               | Intuitive Benutzeroberfläche, ideal für einen schnellen Einstieg. | Bietet mehr Kontrolle für erfahrene Nutzer mit einer erweiterten Ansicht der Einstellungen. | Vollständige Automatisierung mit nahtloser Integration in andere Tools. |
| Erforderliches Kompetenzniveau              | Für jeden zugänglich, ideal für Anfänger oder einfache Bedürfnisse | Mittelstufe, erfordert eine gewisse Expertise (z.B. Systemadministratoren, Cloud-Ingenieure) | Fortgeschritten, erfordert Skripting-/API-Kenntnisse (Cloud-Architekten, DevOps-Ingenieure, Automatisierungsexperten) |
| Einfache Handhabung                         | Intuitiv und zugänglich | Fortgeschritten, aber visuell | Technisch |
| Individuelle Gestaltung                     | Niedrig - Ideal für schnelle Standardkonfigurationen mit begrenzter erweiterter Kontrolle | Mittelstufe - Grafische Benutzeroberfläche, die erweiterte Einstellungen (Netzwerk, Speicher, etc.) bietet, wenn auch durch die Benutzeroberfläche eingeschränkt. | Sehr hoch - Nahezu vollständige Anpassung über APIs, mit der Möglichkeit, Skripte, automatisierte Workflows und maßgeschneiderte Architekturen zu erstellen. |
| Performance und Skalierbarkeit              | Begrenzte Performance und grundlegende Skalierbarkeit. Geeignet für kleine und nicht kritische Bereitstellungen. Die Skalierbarkeit ist in der Regel manuell und langsamer. Ideal für statische Umgebungen oder kleine Projekte. | Durchschnittliche Performance mit verbessertem Skalierbarkeitsmanagement über die grafische Benutzeroberfläche. Schnellere Skalierbarkeit als mit der OVHcloud Konsole, jedoch begrenzt durch das Interface. Geeignet für mittelgroße Projekte oder Projekte, die eine gewisse Skalierbarkeit erfordern. | Maximale Performance und vollständige Skalierbarkeit. Ermöglicht große, automatisierte und schnelle Deployments über Skripte oder Tools von Drittanbietern. Ideal für dynamische Infrastrukturen, hohe Lasten und Umgebungen, die eine hohe Elastizität erfordern. Empfohlen für kritische Architekturen. |
| Einsatzbereiche (Compute)          | - Erstellung und vereinfachte Verwaltung der virtuellen Maschinen (VMs).<br/> - Größenänderung von VMs nach der Erstellung (Änderung des Flavour-Modells bei laufendem oder kaltem Betrieb, abhängig von den verfügbaren Ressourcen).<br/> - Auswahl der Standardkonfigurationen für die VMs (RAM, CPU, Speicherplatz).<br/> - Verwaltung der wichtigsten Aktionen: Starten, Anhalten und Löschen von VMs.<br/> - Snapshot-Zugriff für schnelle Backups und vereinfachte Wiederherstellungen.<br/> - Zuweisung und Verwaltung von Floating IP-Adressen.<br/> - Erstellung und grundlegende Verwaltung von zusätzlichen Disks.<br/> - Grundlegendes Monitoring der Ressourcen (CPU, Speicher, Speicherplatz). | - Erweiterte Zugriffsverwaltung: Unterstützung der rollenbasierten Zugriffskontrolle (RBAC) für eine sichere Mehrbenutzerverwaltung.<br/> - Fortgeschrittene Netzwerkadministration: Erstellung und Verwaltung komplexer privater Netzwerke, die mit VMs verbunden sind (interne Netzwerke, Subnetze).<br/> - Einsatz von VMs mit spezifischen Netzwerkkonfigurationen, einschließlich der Verwaltung mehrerer Netzwerkschnittstellen.<br/> - Verwendung personalisierter Images für die Erstellung von VMs als Alternative zu den von OVHcloud angebotenen Standard-Images.<br/> - Integration vorkonfigurierter Workflows über Horizon zur Automatisierung von Bereitstellung und Konfiguration. | - Vollständige Automatisierung: Alle in der OVHcloud Konsole und in Horizon verfügbaren Aktionen können über die API durchgeführt werden, mit der Möglichkeit, sie zu automatisieren und zu skriptieren.<br/> - Bereitstellung von Infrastrukturen im Infrastructure as Code (IaC) Modus mit Tools wie Terraform, Ansible oder benutzerdefinierten Skripten.<br/> - Integration mit CI/CD-Pipelines für automatisierte Bereitstellungen (z.B. Integration mit GitLab CI).<br/> - Fortgeschrittene Verwaltung der Ressourcen-Quotas (Anzahl der CPUs, RAM, etc.).<br/> - Dynamische Skalierbarkeit: Automatische Anpassung von Instanzen an die Last über APIs oder Skripte.<br/> - Monitoring und Erfassung personalisierter Metriken über die API, die eine höhere Granularität als das Horizon-Interface oder die OVHcloud Konsole bieten. |
| Einsatzbereiche (Network)          | - Erstellung und Verwaltung von privaten Netzwerken.<br/> - Zuordnung von Floating IPs und Additional IPs.<br/> - Basiskonfiguration für Routing (Basic Routing). | - Erweiterte Verwaltung von Sicherheitsregeln über Sicherheitsgruppen (Security Groups).<br/> - Visualisierung von Netzwerktopologien für eine vereinfachte Verwaltung.<br/> - Vollständige Unterstützung von IPv6-Subnetzen für moderne Konnektivität.<br/> - Konfiguration von QoS-Richtlinien (Quality of Service) zur Priorisierung von Netzwerkressourcen. | - Zugriff auf alle verfügbaren Funktionen in Horizon und in der OVHcloud Konsole.<br/> - Erstellung personalisierter Routen für eine flexiblere Netzwerkverwaltung.<br/> - Genaue Konfiguration der QoS-Richtlinien (Quality of Service).<br/> - Erweiterte Verwaltung von Virtual Router Redundancy Protocol (VRRP) zur Sicherstellung der Redundanz der Router.<br/> - Automatisierung von Netzwerkaktionen mit Skripten (Infrastructure as Code).<br/> - Integration mit Software-Defined Networking (SDN)-Lösungen für ein agiles Netzwerkmanagement. |
| Einsatzbereiche (Storage und Backups) | - Erstellung und Verwaltung von Speichervolumes: Object Storage, Block Storage und File Storage.<br/> - Grundlegende automatische Sicherung (Snapshots) von Volumes, mit der Möglichkeit der Wiederherstellung.<br/> - Die Zuordnung von Speichervolumes zu Instanzen ermöglicht einen vereinfachten Zugriff.<br/> - Verwaltung von Object Storage Containern (Swift) zur Organisation der Daten.<br/> - Visualisierung des Status von Volumes und des verwendeten Speicherplatzes.<br/> - Hinzufügen und Verwalten von Dateien in einem Object Storage. | - Erweiterte Snapshot-Verwaltung: Aufbewahrung, Duplizierung und andere Optionen für eine genaue Kontrolle der Backups.<br/> - Detaillierte Verwaltung der Freigabe von Volumes (Multi-Attach) für mehr Flexibilität.<br/> - Erstellen und Verwalten von geplanten Backups mit anpassbaren Backup-Richtlinien.<br/> - Überwachen der Speicherkontingentnutzung für eine optimale Nachverfolgung des verfügbaren Speicherplatzes. | - Funktionen über Horizon und die OVHcloud Konsole verfügbar.<br/> - Integration und Automatisierung über Skripte (Infrastructure as Code) für eine reibungslose Verwaltung.<br/> - Erweiterte Konfiguration von Netzwerkfreigaben (NFS, CIFS) für mehr Flexibilität bei der Organisation von Dateien.<br/> - Präzise Verwaltung der Objektmetadaten in Object Storage für eine optimale Datenkontrolle.<br/> - Erweiterte Konfiguration der Replikation und Versionierung von Objekten für hohe Verfügbarkeit und umfassende Versionsverwaltung.<br/> - Direkter Zugriff auf die Swift-API für eine nahtlose Integration mit Tools von Drittanbietern.<br/> - Erstellung von benutzerdefinierten Workflows zur Automatisierung und effizienten Verwaltung von Sicherungsprozessen. |
