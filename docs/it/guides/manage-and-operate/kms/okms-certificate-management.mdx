## Procedura

### Descrizione dei certificati di accesso OKMS

Per comunicare con il tuo dominio OKMS, devi disporre di un certificato di accesso. Si tratta di uno dei tre [metodi di autenticazione OKMS](/guides/manage-and-operate/kms/okms-authentication-methods); i certificati sono **obbligatori per KMIP** e consigliati quando è necessaria l'autenticazione client mTLS. Per l'utilizzo dell'API REST, un token di accesso personale (PAT) o un account di servizio è generalmente più semplice da configurare.

Un certificato di accesso è valido solo per il dominio per il quale è stato generato.

:::warning
Solo la generazione del certificato con un CSR è coperta dalla certificazione PCI-DSS.

:::


### Creare un certificato di accesso dal KMS

È possibile creare questo certificato dal menu dedicato del KMS.

La prima parte del modulo ti permette di specificare la sua durata di validità, di selezionare l'algoritmo di firma e di fornire o meno la tua Certificate Signing Request (CSR) nel caso in cui tu possieda una tua chiave privata.

##### Senza fornire una chiave privata

Se non fornisci un CSR, OVHcloud genererà il certificato di accesso e una chiave privata.

<img className="thumbnail" alt="Creare un certificato" src="/images/manage-and-operate/kms/okms-certificate-management/create_certificat_02.png" loading="lazy" />

##### Con un CSR

Se disponi di una tua chiave privata, è possibile utilizzarla fornendo un CSR.

<img className="thumbnail" alt="Creare un certificato" src="/images/manage-and-operate/kms/okms-certificate-management/create_certificat_03.png" loading="lazy" />

La seconda parte del modulo permette di indicare le [identità OVHcloud](/guides/manage-and-operate/iam/identities-management) associate al certificato che permettono di calcolare i diritti di accesso tramite l'[IAM OVHcloud](/guides/account-and-service-management/account-information/iam-policy-ui).

È possibile aggiungere l'identità `root` al certificato per non essere vincolato dall'IAM OVHcloud.

È possibile generare questo certificato lasciando che OVHcloud generi la chiave privata, oppure fornendo la tua Certificate Signing Request (CSR) nel caso in cui tu possieda una tua chiave privata.

##### Senza fornire una chiave privata

Se non fornisci un CSR, OVHcloud genererà il certificato di accesso e una chiave privata.

La generazione del certificato avviene tramite la seguente API:

<Api version="v2" section="/okms" method="POST" route={"/okms/resource/\{okmsId\}/credential"} />

È necessario indicare le seguenti informazioni:

- **name**: il nome del certificato
- **identityURNs**: elenco delle identità OVHcloud in formato URN che saranno fornite all'IAM per il calcolo dei diritti di accesso
- **description**: descrizione del certificato (facoltativo)
- **certificateType**: algoritmo di firma del certificato (ECDSA o RSA) - ECDSA per impostazione predefinita (facoltativo)
- **validity**: durata di validità del certificato in giorni - 365 giorni per impostazione predefinita (facoltativo)

**Esempio di creazione di un certificato con l'account root:**

```json
{
  "description": "My root access credential",
  "identityURNs": [
    "urn:v1:eu:identity:account:xx1111-ovh"
  ],
  "name": "root",
  "validity": 30
}
```

**Esempio di creazione di un certificato con un account utente locale:**

```json
{
  "description": "My access credential",
  "identityURNs": [
    "urn:v1:eu:identity:user:xx1111-ovh/john.smith",
    "urn:v1:eu:identity:group:xx1111-ovh/my_group"
  ],
  "name": "John Smith",
  "validity": 30
}
```

L'API restituisce quindi lo stato di creazione del certificato:

```json

    "urn:v1:eu:identity:group:xx1111-ovh/my_group"

  "certificateType": "ECDSA",
  "status": "CREATING",
  "fromCSR": false,
  "privateKeyPEM": "-----BEGIN EC PRIVATE KEY-----\nMHcCAQEEIDOfWuMVQxl5quoURzThF4zTI9YYTmylSaPjneLBwP+2oAoGCCqGSM49\nAwEHoUQDQgAERd1eMw0YdAD+E9oSymGc4bCL1mfJl0EZwoM2ya/uKFFVFnGMnckg\nXXXXXXXXXXXXXXX==\n-----END EC PRIVATE KEY-----\n",
```
