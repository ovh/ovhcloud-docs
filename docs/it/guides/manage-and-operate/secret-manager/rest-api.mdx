## Obiettivo

L'obiettivo di questa guida è presentare l'utilizzo dell'API REST per il Secret Manager.

## Prerequisiti

- Un [account cliente OVHcloud](/guides/account-and-service-management/account-information/ovhcloud-account-creation).
- Avere [ordinato un dominio OKMS](/guides/manage-and-operate/kms/quick-start) o [creato un primo segreto](/guides/manage-and-operate/secret-manager/secret-manager-ui).
- Avere [configurato un metodo di autenticazione](/guides/manage-and-operate/kms/okms-authentication-methods) per il piano dati OKMS.

## Procedura

### Descrizione

Il Secret Manager è un prodotto che consente di memorizzare in modo sicuro le credenziali, le chiavi API, le chiavi SSH o qualsiasi altro tipo di segreto necessario al funzionamento delle vostre applicazioni.

Un segreto è una raccolta di una o più coppie chiave-valore raggruppate all'interno di una versione.
Ogni modifica di un segreto comporta la creazione di una nuova versione di tale segreto, permettendo di risalire nella cronologia delle modifiche del segreto.

Le API REST sono uno dei due set di API offerti dal Secret Manager, insieme alle [API compatibili con Hashicorp Vault KV2](/guides/manage-and-operate/secret-manager/kv2-api).
Sono progettate per essere simili all'insieme delle API OVHcloud e alle API OKMS per il Key Management Service.

Le API REST possono essere utilizzate tramite le [API centralizzate OVHcloud](/guides/manage-and-operate/api/apiv2) oppure direttamente sul dominio OKMS nella regione.
L'unica differenza risiede nel percorso API esatto:

- API centralizzata OVHcloud: /v2/okms/resource/&#123;okmsId&#125;/secret/&#123;path&#125;
- API regionalizzata OKMS: /api/&#123;okmsId&#125;/v2/secret/&#123;path&#125;

Questa documentazione si concentrerà sulle API del dominio OKMS nella regione.

### Comunicare con il dominio OKMS

La comunicazione con il dominio OKMS per le azioni di cifratura e firma è disponibile tramite l'API.

Poiché il dominio OKMS è regionalizzato, l'accesso all'API avviene direttamente nella sua regione: `https://my-region.okms.ovh.net`.

Ad esempio, per un dominio OKMS creato nella regione **eu-west-rbx**: [https://eu-west-rbx.okms.ovh.net](https://eu-west-rbx.okms.ovh.net).

È possibile comunicare con il dominio OKMS utilizzando:

- L'interfaccia utente Swagger
- La CLI OKMS: [https://github.com/ovh/okms-cli](https://github.com/ovh/okms-cli)
- L'SDK Golang: [https://pkg.go.dev/github.com/ovh/okms-sdk-go](https://pkg.go.dev/github.com/ovh/okms-sdk-go)

Autenticatevi tramite un [token di accesso personale, un account di servizio o un certificato di accesso](/guides/manage-and-operate/kms/okms-authentication-methods). Per l'utilizzo dell'API REST, è consigliato un token di accesso personale (PAT) o un account di servizio.

Per testare le chiamate API in modo interattivo, utilizzate l'[interfaccia Swagger OKMS](/guides/manage-and-operate/kms/okms-authentication-methods#use-the-okms-swagger-ui) all'indirizzo `https://<region>.okms.ovh.net/swagger/`.

### Creare un segreto

Per creare un segreto, potete utilizzare la seguente API:

| **Metodo** |         **Percorso**         | **Descrizione** |
| :--------: | :----------------------: | :-------------: |
|    POST    | /api/&#123;okmsId&#125;/v2/secret/ | Creare un segreto |

L'API si aspetta i seguenti valori:

|        **Campo**         |                                       **Valore**                                        |                                           **Descrizione**                                            |
| :----------------------: | :------------------------------------------------------------------------------------: | :--------------------------------------------------------------------------------------------------: |
|       cas_required       |                                        booleano                                         | Se attivato, è necessario specificare sistematicamente il numero della versione corrente durante le modifiche |
|     custom_metadata      |                                          Json                                          |         Dati aggiuntivi associati al segreto. Questi dati non sono protetti dal segreto         |
| deactivate_version_after | [Duration String](https://developer.hashicorp.com/vault/docs/concepts/duration-format) |                            Durata dopo la quale le versioni vengono disattivate                             |
|       max_versions       |                                        Integer                                         |                              Numero massimo di versioni per il segreto                               |
|           path           |                                         String                                         |                                             Percorso del segreto                                              |
|         version          |                                          Json                                          |                          Contenuto del segreto. È possibile avere JSON nidificati                          |

Ad esempio:

```json
{
  "metadata": {
    "cas_required": true,
    "custom_metadata": {
      "project": "A",
      "team": "X"
    },
    "deactivate_version_after": "10h30m10s",
    "max_versions": 5
  },
  "path": "prod/database/MySQL",
  "version": {
    "data": {
      "login": "admin",
      "password": "my_secret_password",
      "address": {
        "ip": "1.1.1.1"
      },
      "ports": [
        "30",
        "31"
      ]
    }
  }
}
```

### Gestire i segreti

#### Aggiornare i metadati e la configurazione

Una volta creato il segreto, è possibile aggiornare i metadati del segreto o la sua configurazione.

| **Metodo** |           **Percorso**           |     **Descrizione**     |
| :--------: | :----------------------------: | :---------------------: |
|    PUT     | /api/&#123;okmsId&#125;/v2/secret/&#123;path&#125; | Aggiornare un segreto |

L'API si aspetta i seguenti valori:

|        **Campo**         |                                       **Valore**                                        |                                           **Descrizione**                                            |
| :----------------------: | :------------------------------------------------------------------------------------: | :--------------------------------------------------------------------------------------------------: |
|       cas_required       |                                        booleano                                         | Se attivato, è necessario specificare sistematicamente il numero della versione corrente durante le modifiche |
|     custom_metadata      |                                          Json                                          |         Dati aggiuntivi associati al segreto. Questi dati non sono protetti dal segreto         |
| deactivate_version_after | [Duration String](https://developer.hashicorp.com/vault/docs/concepts/duration-format) |                            Durata dopo la quale le versioni vengono disattivate                             |
|       max_versions       |                                        Integer                                         |                              Numero massimo di versioni per il segreto                               |

È inoltre possibile modificare la configurazione predefinita del dominio OKMS per i valori **cas_required**, **deactivate_version_after** e **max_versions** tramite l'API:

| **Metodo** |          **Percorso**           |                   **Descrizione**                    |
| :--------: | :---------------------------: | :--------------------------------------------------: |
|    PUT     | /api/&#123;okmsId&#125;/v2/secretConfig | Configurare la configurazione predefinita del dominio OKMS |

#### Creare una nuova versione

È inoltre possibile modificare il contenuto del segreto, il che comporta la creazione di una nuova versione per tale segreto.
Le nuove versioni possono essere create tramite l'API:

| **Metodo** |               **Percorso**               |            **Descrizione**             |
| :--------: | :------------------------------------: | :------------------------------------: |
|    PUT     |     /api/&#123;okmsId&#125;/v2/secret/&#123;path&#125;     |        Aggiornare un segreto         |
|    PUT     | /api/&#123;okmsId&#125;/v2/secret/&#123;path&#125;/version | Creare una nuova versione di un segreto |

Che la modifica dei **data** del segreto avvenga tramite l'API generale di aggiornamento del segreto o tramite l'API specifica, viene creata una nuova versione del segreto.

Un segreto può contenere tutte le versioni desiderate, entro il limite massimo del parametro **max_versions**.
Se viene raggiunto il numero massimo di versioni, la versione più vecchia viene eliminata automaticamente.

#### Gestire le versioni

È possibile gestire le diverse versioni del segreto tramite l'API:

| **Metodo** |                    **Percorso**                    |           **Descrizione**            |
| :--------: | :----------------------------------------------: | :----------------------------------: |
|    PUT     | /api/&#123;okmsId&#125;/v2/secret/&#123;path&#125;/version/&#123;version&#125; | Aggiornare la versione di un segreto |

L'API si aspetta l'unico valore:

| **Campo** |          **Valore**           |  **Descrizione** |
| :-------: | :---------------------------: | :--------------: |
|   state   | active , deactivated, deleted | active: Il valore di questa versione è accessibile <br/>deactivated: Il valore di questa versione è ancora presente nel sistema ma non è più accessibile finché la versione non viene riattivata <br/>deleted: Il valore di questa versione non è più presente nel sistema e non può essere ripristinato. |
