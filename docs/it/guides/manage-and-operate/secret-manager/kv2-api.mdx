## Obiettivo

L'obiettivo di questa guida è presentare l'utilizzo dell'API compatibile con HashiCorp Vault KV2 per il Secret Manager.

## Prerequisiti

- Disporre di un [account cliente OVHcloud](/guides/account-and-service-management/account-information/ovhcloud-account-creation).
- Avere [ordinato un dominio OKMS](/guides/manage-and-operate/kms/quick-start) o [creato un primo segreto](/guides/manage-and-operate/secret-manager/secret-manager-ui).
- Avere [configurato un metodo di autenticazione](/guides/manage-and-operate/kms/okms-authentication-methods) per il piano dati OKMS.

## Procedura

### Descrizione

Il Secret Manager è un prodotto che ti permette di memorizzare in modo sicuro le credenziali, le chiavi API, le chiavi SSH o qualsiasi altro tipo di segreto necessario al funzionamento delle tue applicazioni.

Un segreto è un insieme di una o più coppie chiave-valore raggruppate all'interno di una versione.
Ogni modifica di un segreto comporta la creazione di una nuova versione di tale segreto, consentendo di risalire nella cronologia delle modifiche del segreto.

Le API compatibili con HashiCorp Vault KV2 sono uno dei due set di API offerti dal Secret Manager, insieme alle [API REST](/guides/manage-and-operate/secret-manager/rest-api).
Sono progettate per essere simili alle API HashiCorp Vault, al fine di garantire la compatibilità con le applicazioni già compatibili con HashiCorp Vault.

### Comunicare con il dominio OKMS

La comunicazione con il dominio OKMS per le operazioni di cifratura e firma è disponibile tramite l'API.

Poiché il dominio OKMS è regionalizzato, l'accesso all'API avviene direttamente nella regione dello stesso: `https://my-region.okms.ovh.net`.

Ad esempio, per un dominio OKMS creato nella regione **eu-west-rbx**: [https://eu-west-rbx.okms.ovh.net](https://eu-west-rbx.okms.ovh.net).

È possibile comunicare con il dominio OKMS utilizzando:

- L'interfaccia utente Swagger
- La CLI OKMS: [https://github.com/ovh/okms-cli](https://github.com/ovh/okms-cli)
- L'SDK Golang: [https://pkg.go.dev/github.com/ovh/okms-sdk-go](https://pkg.go.dev/github.com/ovh/okms-sdk-go)

Autenticati tramite un [token di accesso personale, un account di servizio o un certificato di accesso](/guides/manage-and-operate/kms/okms-authentication-methods). Per l'utilizzo dell'API compatibile con HashiCorp Vault KV2, si consiglia un token di accesso personale (PAT) o un account di servizio.

Per testare le chiamate API in modo interattivo, utilizza l'[interfaccia Swagger OKMS](/guides/manage-and-operate/kms/okms-authentication-methods#use-the-okms-swagger-ui) all'indirizzo `https://<region>.okms.ovh.net/swagger/`.

### Creare un segreto

Per creare un segreto, è possibile utilizzare la seguente API:

| **Metodo** |             **Percorso**              | **Descrizione** |
| :---------: | :---------------------------------: | :-------------: |
|    POST     | /api/&#123;okmsId&#125;/v1/secret/data/&#123;path&#125; | Creare un segreto |

Il percorso del segreto deve essere indicato nel percorso dell'API.

L'API prevede i seguenti valori:

| **Campo** | **Valore** |                        **Descrizione**                        |
| :-------: | :--------: | :-----------------------------------------------------------: |
|   data    |    Json    | Contenuto del segreto. È possibile avere JSON nidificati |
|    cas    |  Integer   |            (opzionale) Versione attuale del segreto             |

Ad esempio:

```json
{
  "data": {
      "login": "admin",
      "password": "my_secret_password",
      "address": {
        "ip": "1.1.1.1"
      },
      "ports": [
        "30",
        "31"
      ]
  },
  "options": {
      "cas": 0
  }
}
```

È inoltre possibile aggiungere metadati al segreto tramite l'API:

| **Metodo** |               **Percorso**                |            **Descrizione**             |
| :---------: | :-------------------------------------: | :------------------------------------: |
|    POST     | /api/&#123;okmsId&#125;/v1/secret/metadata/&#123;path&#125; | Aggiornare i metadati di un segreto |

L'API prevede i seguenti valori:

|        **Campo**         |                                       **Valore**                                        |                                           **Descrizione**                                            |
| :----------------------: | :------------------------------------------------------------------------------------: | :------------------------------------------------------------------------------------------------------------: |
|       cas_required       |                                         booleano                                         | Se attivato, è necessario indicare sistematicamente il numero della versione attuale durante le modifiche |
|     custom_metadata      |                                          Json                                          |          Dati aggiuntivi associati al segreto. Questi dati non sono protetti dal segreto          |
| deactivate_version_after | [Duration String](https://developer.hashicorp.com/vault/docs/concepts/duration-format) |                               Durata dopo la quale le versioni vengono disattivate                                 |
|       max_versions       |                                        Integer                                         |                                   Numero massimo di versioni per il segreto                                    |

Ad esempio:

```json
{
  "cas_required": true,
  "custom_metadata": {
    "project": "A",
    "team": "X"
  },
  "deactivate_version_after": "10h30m10s",
  "max_versions": 5
}
```

### Gestire i segreti

#### Aggiornare i metadati e la configurazione

Una volta creato il segreto, è possibile aggiornare i metadati del segreto e la sua configurazione.

| **Metodo** |               **Percorso**                |            **Descrizione**             |
| :---------: | :-------------------------------------: | :------------------------------------: |
|    PATCH    | /api/&#123;okmsId&#125;/v1/secret/metadata/&#123;path&#125; | Aggiornare i metadati di un segreto |

L'API prevede i seguenti valori:

|        **Campo**         |                                       **Valore**                                       |                                                **Descrizione**                                                 |
| :----------------------: | :------------------------------------------------------------------------------------: | :------------------------------------------------------------------------------------------------------------: |
|       cas_required       |                                         booleano                                         | Se attivato, è necessario indicare sistematicamente il numero della versione attuale durante le modifiche |
|     custom_metadata      |                                          Json                                          |          Dati aggiuntivi associati al segreto. Questi dati non sono protetti dal segreto          |
| deactivate_version_after | [Duration String](https://developer.hashicorp.com/vault/docs/concepts/duration-format) |                               Durata dopo la quale le versioni vengono disattivate                                 |
|       max_versions       |                                        Integer                                         |                                   Numero massimo di versioni per il segreto                                    |

È inoltre possibile modificare la configurazione predefinita del dominio OKMS per i valori **cas_required**, **deactivate_version_after** e **max_versions** tramite l'API:

| **Metodo** |           **Percorso**           |                   **Descrizione**                    |
| :---------: | :----------------------------: | :--------------------------------------------------: |
|    POST     | /api/&#123;okmsId&#125;/v1/secret/config | Configurare la configurazione predefinita del dominio OKMS |

#### Creare una nuova versione

È inoltre possibile modificare il contenuto del segreto, il che comporta la creazione di una nuova versione per tale segreto.
Le nuove versioni possono essere create tramite l'API:

| **Metodo** |             **Percorso**              |     **Descrizione**     |
| :---------: | :---------------------------------: | :---------------------: |
|    PATCH    | /api/&#123;okmsId&#125;/v1/secret/data/&#123;path&#125; | Aggiornare un segreto |

Un segreto può contenere tutte le versioni desiderate, nel limite massimo del parametro **max_versions**.
Se viene raggiunto il numero massimo di versioni, la versione più vecchia viene eliminata automaticamente.

#### Gestire le versioni

È possibile gestire le diverse versioni del segreto tramite più API:

| **Metodo** |              **Percorso**               |               **Descrizione**               |
| :---------: | :-----------------------------------: | :-----------------------------------------: |
|    POST     | /api/&#123;okmsId&#125;/v1/secret/delete/&#123;path&#125; | Disattiva le versioni specificate del segreto |
|   DELETE    |  /api/&#123;okmsId&#125;/v1/secret/data/&#123;path&#125;  |   Disattiva l'ultima versione del segreto   |

Le versioni disattivate di un segreto sono ancora presenti nel Secret Manager, ma il loro contenuto non è più accessibile.

È possibile riattivare una versione tramite l'API:

| **Metodo** |               **Percorso**                |               **Descrizione**               |
| :---------: | :-------------------------------------: | :-----------------------------------------: |
|    POST     | /api/&#123;okmsId&#125;/v1/secret/undelete/&#123;path&#125; | Riattiva le versioni specificate del segreto |

Infine, è possibile eliminare definitivamente una versione tramite l'API:

| **Metodo** |               **Percorso**               |               **Descrizione**               |
| :---------: | :------------------------------------: | :-----------------------------------------: |
|     PUT     | /api/&#123;okmsId&#125;/v1/secret/destroy/&#123;path&#125; | Elimina le versioni specificate del segreto |

È inoltre possibile eliminare definitivamente l'intero segreto con tutte le sue versioni:

| **Metodo** |               **Percorso**               |               **Descrizione**               |
| :---------: | :------------------------------------: | :-----------------------------------------: |
|     DELETE     | /api/&#123;okmsId&#125;/v1/secret/metadata/&#123;path&#125; | Elimina il segreto e le sue versioni |

:::warning
Una versione eliminata non è più presente nel Secret Manager e non può più essere riattivata.

:::
