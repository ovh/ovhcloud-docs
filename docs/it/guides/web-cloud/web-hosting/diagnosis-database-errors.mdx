## Obiettivo

L'utilizzo dei database può causare alcune anomalie sul tuo sito o nella <ManagerLink to="/beta/#/">console OVHcloud</ManagerLink>, oltre che sull'interfaccia [PhpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database).

**Scopri come risolvere gli errori associati ai database sugli hosting condivisi OVHcloud.**

[[fragment:support-scope]]

## Prerequisiti

- Disporre di una soluzione di [hosting web](/links/web/hosting) attiva.
- Utilizzare una delle nostre offerte di database: [Start SQL](/links/web/hosting-options-startsql) o [Web Cloud Databases](/links/web/databases).

#### Verifica le credenziali di connessione al tuo database <a name="config_file"></a>

Accedi in [FTP](/guides/web-cloud/web-hosting/ftp-connection) allo spazio di archiviazione dei file sul tuo hosting e ritrova il file di configurazione del tuo sito (ad esempio, per un sito WordPress, si tratta del file **wp-config.php** situato nella cartella che contiene il tuo sito).

:::warning
La scelta e la configurazione del file contenente le informazioni di connessione al database sono inerenti all'editor del contenuto (CMS) interessato e non a OVHcloud.

In caso di necessità, ti consigliamo di rivolgerti all'editor del [CMS](/guides/web-cloud/web-hosting/cms-install-1-click-modules) utilizzato per creare il tuo sito o di rivolgerti a un [fornitore specializzato](/links/partner). Non saremo in grado di fornirti assistenza al riguardo.
:::

Verifica la corrispondenza **esatta** tra le credenziali di connessione a [phpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database#accedi-allinterfaccia-phpmyadmin) e quelle del file di configurazione del tuo sito.

Modifica, se necessario, la [password del tuo database](/guides/web-cloud/web-hosting/sql-change-password).

#### Esempio per WordPress

Se il tuo sito visualizza un messaggio **"Errore durante la connessione al database"** e non è interessato da un [incidente](https://web-cloud.status-ovhcloud.com/), accedi in [FTP](/guides/web-cloud/web-hosting/ftp-connection) al tuo hosting e apri la directory contenente il tuo sito (di default la cartella `www`).

Se il tuo sito è WordPress, apri il file `wp-config.php`.

```php
define('DB_NAME', 'my_database');

/** MySQL database username */
define('DB_USER', 'my_user');

/** MySQL database password */
define('DB_PASSWORD', 'my_password');

/** MySQL hostname */
define('DB_HOST', 'my_server.mysql.db:port');
```

### Superamento della quota autorizzata del database

Hai ricevuto un'email dai nostri servizi che indica che la quantità di dati sul tuo database supera il limite autorizzato. Il tuo database è quindi passato in sola lettura. In questo modo il sito non può essere modificato.

<img className="thumbnail" alt="database-overquota-notification-email" src="/images/assets/screens/email-sending-to-customer/databases/overquota-db.png" loading="lazy" />

Tre metodi ti permettono di sbloccare il tuo database:

#### Metodo 1: attiva il tuo abbonamento su un'offerta superiore

Se disponi di una formula **Starter** o **Personale**, ti consigliamo di passare all'[offerta di hosting superiore](/links/web/hosting). La modifica dell'abbonamento aumenterà la dimensione del tuo database e la riaprirà automaticamente. Si tratta del metodo più semplice e non richiede particolari competenze tecniche.

:::warning
L'aumento della dimensione del tuo database può essere associato a malfunzionamenti nel codice interno del tuo sito.

Un'anomalia può provocare un aumento permanente della dimensione del tuo database, nel qual caso la modifica dell'offerta di hosting risulterebbe inefficace.

Ti consigliamo quindi di contattare immediatamente un [fornitore specializzato](/links/partner) se riscontri un improvviso aumento nella dimensione del tuo database o se disponi di un sito di tipo "blog" normalmente a basso consumo di dati. Non saremo in grado di fornirti assistenza in merito.
:::

#### Metodo 2: migrare i tuoi dati su un database di dimensione superiore <a name="method2"></a>

:::info
**Quali elementi nello script di importazione del database possono causare un errore "#1044 - Access denied for user to database"?**
:::

Avere un **"trigger"** nello script di importazione del tuo database non è autorizzato sui server di hosting condiviso OVHcloud. In questo caso, importa il tuo database su un server [Web Cloud Databases](/guides/web-cloud/databases/db-getting-started).

Inoltre, la seguente richiesta non è autorizzata:

```sql
CREATE DATABASE IF NOT EXISTS `Database-Name` DEFAULT CHARACTER SET latin1 COLLATE latin1_swedish_ci;
```

Sostituiscila con:

```sql
USE `Database-Name`;
```

(`Database-Name`: inserisci il nome del database indicato nella <ManagerLink to="/beta/#/">console OVHcloud</ManagerLink>)

### Impossibile accedere a phpMyAdmin

#### "Access denied for user"

>
> **"mysqli::real_connect(): (HY000/1045): Access denied for user"**
>

Questo messaggio di errore può comparire durante la connessione al tuo database da [phpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database#accedi-allinterfaccia-phpmyadmin). Indica che gli identificativi inseriti sono errati.

<img className="thumbnail" alt="access_denied_for_user" src="/images/assets/screens/other/web-tools/phpmyadmin/pma-error-hy000-1045.png" loading="lazy" />

In questa situazione, [verifica le credenziali inserite](/guides/web-cloud/databases/db-connecting-database-server#procedura) e, se necessario, modifica la [password del tuo database](/guides/web-cloud/web-hosting/sql-change-password).

#### "Too many connections"

>
> **"mysqli_real_connect(): (HY000/1040): Too many connections"**
>

Il numero massimo di connessioni attive per i database consegnati con hosting condivisi ([Start SQL](/links/web/hosting-options-startsql)) è di **30**.

Questo numero è di **200** per il [servizio Web Cloud Databases](/guides/web-cloud/databases/db-getting-started). (Questo parametro è modificabile nella sezione <code className="action">Configurazione</code> del tuo server database.)

Questo messaggio compare durante la [connessione a phpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database#accedi-allinterfaccia-phpmyadmin) quando viene superato il numero massimo di connessioni.

Per ridurre il numero di connessioni attive, è necessario [ottimizzare i tuoi database](/guides/web-cloud/databases/db-configure-optimise-database-server#ottimizza-i-tuoi-database).

:::warning
Per maggiori informazioni sulle operazioni da effettuare per ridurre il numero di connessioni attive sul database, contatta la nostra [Community di utenti](/links/community) o i [partner OVHcloud](/links/partner). OVHcloud non potrà fornirti alcuna assistenza al riguardo.
:::

### Connessione impossibile su un database Cloud Databases

Disporre di un server [Web Cloud Databases](/guides/web-cloud/databases/landing-page-databases) permette di [accedere ai propri database](/guides/web-cloud/databases/db-connecting-database-server) dal proprio computer o da un server esterno all'infrastruttura OVHcloud.

Se non riesci a effettuare questa connessione, verifica innanzitutto di aver [autorizzato il tuo indirizzo IP pubblico](/guides/web-cloud/databases/db-getting-started) a connettersi al server di database.

Se l'operazione è stata effettuata correttamente, contatta il tuo ISP o i [partner OVHcloud](/links/partner). OVHcloud non sarà in grado di fornirti assistenza in questa situazione.
