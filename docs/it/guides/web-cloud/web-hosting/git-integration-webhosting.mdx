## Obiettivo

Nel panorama digitale di oggi, le società sono sempre più dinamiche e innovative. La capacità di gestire e implementare efficacemente il codice del proprio sito Web è fondamentale per mantenere la competitività e la sostenibilità del marchio. Il Git, il sistema di controllo delle versioni più utilizzato al mondo, permette di archiviare il codice del sito Web su piattaforme come GitHub, permettendo una migliore tracciabilità delle modifiche, una più rapida automazione e deploy. I clienti OVHcloud dispongono di un'infrastruttura solida per ospitare il proprio sito Web e allo stesso tempo possono usufruire dei numerosi vantaggi di Git e GitHub per lo sviluppo e l'evoluzione del proprio sito Web.

**Scopri come configurare e utilizzare Git con il tuo hosting Web dalla console OVHcloud.**

## Prerequisiti

- Disporre di una soluzione di [hosting Web OVHcloud](/links/web/hosting).
- Disporre di un account [GitHub](https://github.com/) ed essere connesso.

:::info
Alla data corrente, solo la piattaforma GitHub è supportata nell'utilizzo con i servizi di hosting Web OVHcloud.

:::

#### Definisci il repository GitHub

Inserisci l'indirizzo del tuo repository GitHub. Se non disponi ancora di un repository GitHub per il tuo progetto, creane uno.

Per creare un nuovo deposito:

- Accedi al tuo account GitHub.
- Clicca sull'immagine del profilo in alto a destra e poi su <code className="action">Your repositories</code>.
- Clicca sul pulsante <code className="action">New</code> a destra.

Definisci un nome per il tuo deposito e inserisci le informazioni richieste.

:::warning
Seleziona l'opzione `Add a README file` per fare in modo che GitHub avvii correttamente il tuo repository.

:::

Infine clicca su <code className="action">Create Repository</code>.

Copia l'indirizzo del tuo repository GitHub. La forma deve essere:

- `https://github.com/<username>/<repository_name>.git` per un deposito pubblico.
- `git@github.com:<username>/<repository_name>.git` per un deposito privato.

Torna al pannello **Configurazione Git** e incolla l'indirizzo del tuo repository GitHub nel campo **Repository**. Deve essere nel formato `https://github.com/<username>/<repository_name>.git` per un repository pubblico, oppure `git@github.com:<username>/<repository_name>.git` per un repository privato. Finché l'indirizzo non ha uno di questi formati e il campo **Branch** è vuoto, il pulsante <code className="action">Applica la configurazione</code> resta inattivo.

Definisci il ramo del tuo repository GitHub. Il ramo predefinito è `main`, ma se vuoi utilizzare un altro ramo, creane uno su GitHub seguendo i passaggi seguenti:

- Accedi al tuo account GitHub.
- Clicca sull'immagine del profilo in alto a destra e poi su <code className="action">Your repositories</code>.
- Clicca sul repository GitHub corrispondente.
- Clicca su <code className="action">Main</code> e poi su <code className="action">View all branches</code>, oppure clicca direttamente sulla scheda <code className="action">x Branch</code>.
- A destra dello schermo visualizzato, clicca su <code className="action">New branch</code>.
- Inserisci il nome del nuovo ramo e conferma cliccando su <code className="action">Create new branch</code>.

Torna al pannello **Configurazione Git** della console OVHcloud e inserisci il nome del nuovo branch appena creato nel campo **Branch**.

Se inserisci l'indirizzo di un repository GitHub privato (di tipo `git@github.com:<username>/<repository_name>.git`), sotto il campo **Repository** appare un riquadro **Chiave SSH (repository privato)**.

<img className="thumbnail" alt="Riquadro Chiave SSH (repository privato) visualizzato per un indirizzo di repository privato" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/configure-ssh-key.png" loading="lazy" />

Per configurare la chiave SSH, consulta lo step "Associare una chiave SSH a GitHub (solo per i repository GitHub privati)" qui sotto.

#### Associare una chiave SSH a GitHub (solo per i repository GitHub privati) <a name="linkSSHKey"></a>

:::info
**Perché la chiave SSH è necessaria solo per un deposito privato?**

Quando il tuo repository GitHub è pubblico, i file possono essere recuperati senza autenticazione, il che significa che Git può clonare e aggiornare il codice senza la necessità di una chiave SSH. Se il tuo repository è privato, GitHub richiede un'autenticazione per accedervi. La chiave SSH permette di stabilire questa connessione protetta e garantire che solo gli utenti autorizzati possano interagire con il repository.

:::

:::info
La generazione di una chiave SSH è uno step cruciale, in quanto stabilisce una connessione sicura e cifrata tra la directory del tuo sito Web e il repository GitHub. Questa chiave garantisce che i trasferimenti di dati e le modifiche del codice avvengano in modo sicuro e autenticato, impedendo gli accessi non autorizzati e garantendo l'integrità del codice.

:::

Copia la chiave SSH visualizzata nel riquadro **Chiave SSH (repository privato)** cliccando sul pulsante di copia a destra.

<img className="thumbnail" alt="Riquadro Chiave SSH (repository privato) e pulsante di copia" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/configure-ssh-key.png" loading="lazy" />

Come indicato nella console, aggiungi questa chiave pubblica come chiave di deployment ("deploy key") nelle impostazioni del tuo repository GitHub:

- Accedi al tuo account GitHub e apri il repository interessato.
- Clicca sulla scheda <code className="action">Settings</code> del repository, poi su <code className="action">Deploy keys</code> nella colonna di sinistra.
- Clicca su <code className="action">Add deploy key</code>.

Viene visualizzato il modulo di aggiunta di una chiave di deployment:

- **Title**: aggiungi una descrizione per la tua chiave SSH. Ad esempio, questa chiave può essere denominata "OVHcloud".
- **Key**: incolla la chiave SSH.
- **Allow write access**: lascia questa casella deselezionata, il deployment richiede solo un accesso in lettura al tuo repository.

Per confermare le informazioni, clicca su <code className="action">Add key</code>. Se richiesto, conferma l'accesso al tuo account in GitHub.

#### Configura il deploy automatico

Nella parte inferiore del pannello **Configurazione Git**, la sezione **Configura il tuo deployment automatico** mostra l'URL del webhook, accompagnato da un pulsante di copia. Configurare un webhook permette al repository GitHub di notificare automaticamente al tuo hosting Web OVHcloud gli eventi che si verificano sul repository GitHub (nuovo deployment, modifica del codice, ecc.). Questa funzionalità è particolarmente utile se lavori in gruppo sullo stesso progetto e vuoi restare aggiornato su tutte le modifiche del repository GitHub. Per maggiori informazioni, scopri come [configurare un webhook su GitHub](#configureWebhook).

#### Confermare l'associazione di Git

Prima di confermare il pannello **Configurazione Git**, assicurati che:

- La tua chiave SSH sia stata aggiunta come chiave di deployment del tuo repository GitHub (solo repository privato).
- L'indirizzo del tuo repository GitHub sia corretto. Deve essere nel formato `https://github.com/<username>/<repository_name>.git` (repository pubblico) o `git@github.com:<username>/<repository_name>.git` (repository privato).
- Il nome del ramo del repository GitHub è corretto.
- La cartella radice del tuo sito web sia vuota: in caso contrario, il deployment non andrà a buon fine.

Per confermare le informazioni, clicca su <code className="action">Applica la configurazione</code>.

### Attivazione dell'associazione di Git

#### Associazione di Git riuscita

Dopo aver cliccato su <code className="action">Applica la configurazione</code>, il pannello si chiude e un messaggio ti conferma che la configurazione Git è stata applicata. Nella colonna **Git** della tabella della scheda <code className="action">I miei siti</code>, sulla riga del sito web interessato appare la dicitura **Configurazione in corso…**: Git è in corso di attivazione. Il processo può richiedere alcuni minuti e la tabella si aggiorna automaticamente.

<img className="thumbnail" alt="Colonna Git con la dicitura Configurazione in corso…" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/git-configuring.png" loading="lazy" />

Quando l'associazione di Git è completata, nella colonna **Git** del sito web interessato appare lo stato **Attivo**.

<img className="thumbnail" alt="Colonna Git con lo stato Attivo" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/sites-git-column.png" loading="lazy" />

#### Errori dell'associazione di Git

Nella colonna **Git** della tabella della scheda <code className="action">I miei siti</code>, se sulla riga del sito web che vuoi associare a Git appare la dicitura **Errore**, significa che si è verificato almeno uno dei seguenti errori:

- La chiave SSH non è stata aggiunta come chiave di deployment del tuo repository GitHub (repository privato).
- La cartella radice del sito web non era vuota al momento dell'associazione.
- L'indirizzo del repository GitHub non esiste o è errato.
- Il ramo del repository GitHub non esiste o il nome è errato.

Per conoscere la causa dell'errore, clicca sulla dicitura **Errore**. Si apre il pannello **Errore di deployment Git**: riporta il repository e il branch configurati, le cause frequenti e le informazioni dell'ultimo deployment.

<img className="thumbnail" alt="Pannello Errore di deployment Git" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/error-drawer.png" loading="lazy" />

Una volta corretta la causa, scegli una delle azioni della sezione **Cosa puoi fare**: <code className="action">Riavvia</code> per riavviare il deployment (o l'associazione), <code className="action">Modifica</code> per correggere la configurazione, oppure <code className="action">Elimina</code> per eliminare l'associazione prima di associare di nuovo Git.

#### Configura il webhook <a name="configureWebhook"></a>

Accedi al tuo account GitHub e accedi al repository su cui vuoi configurare il webhook. Clicca sulla scheda <code className="action">Settings</code> e, nel menu laterale delle impostazioni, clicca su <code className="action">Webhooks</code>. Clicca sul pulsante <code className="action">Add webhook</code> per accedere al modulo:

- **Payload URL**: inserisci l'URL del webhook copiato dal pannello **Configurazione Git** della console OVHcloud.
- **Content type**: scegli <code className="action">application/json</code> come tipo di contenuto per i dati inviati.
- **Secret**: il segreto è facoltativo. GitHub lo utilizzerà per firmare i messaggi inviati dal webhook, migliorando così la sicurezza.
- **SSL verification**: se il tuo sito Web supporta l'HTTPS, lascia questa opzione attiva per una maggiore sicurezza.
- **Which events would you like to trigger this webhook?**: seleziona gli eventi che attiveranno l'invio del webhook. Per un deploy automatico, <code className="action">Just the push event</code> (Solo l'evento push) è spesso sufficiente, ma è possibile scegliere <code className="action">Send me everything</code> per ricevere notifiche per tutti gli eventi.
- **Active**: assicurati che la casella sia selezionata per attivare il webhook.

Clicca su <code className="action">Add webhook</code> per registrare e attivare il nuovo webhook.

#### Testare il tuo webhook

Dopo aver creato il tuo webhook in GitHub, vai nella lista dei tuoi webhook e seleziona quello che hai creato o clicca su <code className="action">Edit</code>.

Clicca sulla scheda <code className="action">Recent Deliveries</code>. Per inviare un evento di prova specifico, GitHub invia in genere un evento `ping` durante la creazione del webhook, ed è possibile utilizzare il pulsante <code className="action">Redeliver</code> accanto a questo evento per testarlo.

Se il test ha funzionato correttamente, la scheda <code className="action">Response</code> restituisce un codice 200. Se viene restituito un codice di errore (generalmente 500 o 400), significa che il tuo webhook è stato configurato male. Tornate al modulo di aggiunta di un webhook e verificate le informazioni, in particolare l'URL del webhook fornito da OVHcloud.

#### Utilizza il webhook

Una volta configurato il tuo webhook, il codice del tuo sito Web verrà aggiornato automaticamente ogni volta che si verificano modifiche sul repository GitHub. Ad esempio, se un collega apporta modifiche al repository GitHub, il codice del sito Web viene aggiornato localmente (sull'hosting OVHcloud).

### Conclusione

Hai appena associato il codice del tuo sito Web a Git, tramite il tuo repository GitHub. A questo punto puoi distribuire le modifiche apportate sul repository GitHub verso il tuo hosting Web o distribuirle in modo automatico grazie al webhook, consultare i log dei deployment ed effettuare diverse azioni, tutto questo dalla console OVHcloud, in pochi clic.
