Gli esempi che seguono indicano che il tuo hosting Web non contiene [certificato SSL](/guides/web-cloud/web-hosting/ssl-on-webhosting) (se il tuo sito non mostra una delle anomalie descritte in questa guida, consulta la sezione ["Per saperne di più"](#go-further)):

**Scopri come risolvere errori di tipo "La tua connessione non è privata".**

## Prerequisiti

- Avere la gestione dei [server DNS](/guides/web-cloud/domains/dns-server-general-information) e della [zona DNS](/guides/web-cloud/domains/dns-zone-general-information) del dominio

## Procedura

Per risolvere questa anomalia, è necessario:

1. determinare l'hosting al quale è associato il tuo dominio, per intervenire sul server giusto;
2. creare, attivare o rinnovare un [certificato SSL](/guides/web-cloud/web-hosting/ssl-on-webhosting) per il tuo dominio sull'hosting in questione.

### 1 - Verifica l'hosting associato al tuo dominio

#### Verifica l'indirizzo IP dell'hosting

I messaggi di errore menzionati [sopra](#objective) non significano necessariamente che il tuo sito è ospitato su una delle nostre [offerte Web Cloud](/links/web/hosting). Dovrai quindi verificare l'indirizzo IP del server al quale è collegato il tuo [dominio](/links/web/domains).

Per recuperare l'indirizzo IP del tuo [hosting OVHcloud](/links/web/hosting), clicca sulle schede qui sotto per visualizzare in sequenza ciascuno dei **2** passaggi.

<Tabs>
  <Tab label="Passaggio 1">
    Accedi alla pagina <ManagerLink to="/beta/#/web-cloud/hosting">Hosting web</ManagerLink>, poi scegli l'hosting Web interessato.

    <img className="thumbnail" alt="Pagina Hosting web ed elenco degli hosting dell'account" src="/images/assets/screens/console/product-selection/web-cloud/hosting-plans.png" loading="lazy" />
  </Tab>
  <Tab label="Passaggio 2">
    L'hosting si apre sulla scheda <code className="action">Panoramica</code>. Nella sezione **Informazioni generali**, troverai le voci **IPv4** e **IPv6**.

    <img className="thumbnail" alt="Sezione Informazioni generali, indirizzi IPv4 e IPv6" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/general-information/ipv4-ipv6.png" loading="lazy" />

    Annota l'indirizzo IPv4 e/o IPv6, con il pulsante di copia situato a destra di ogni indirizzo, poi prosegui nella lettura della guida.
  </Tab>
</Tabs>

#### Verifica l'indirizzo IP nella zona DNS

A questo punto è necessario verificare che l'indirizzo IP indicato nella [zona DNS](/guides/web-cloud/domains/dns-zone-edit) corrisponda a quello del tuo [hosting Web Cloud](/links/web/hosting).

Clicca sulle schede qui sotto per visualizzare in sequenza ciascuno dei **2** passaggi.

<Tabs>
  <Tab label="Passaggio 1">
    Accedi alla pagina <ManagerLink to="/beta/#/web-cloud/domains/listing">Domini e DNS</ManagerLink>, seleziona il dominio interessato, poi apri la scheda <code className="action">Zona DNS</code>.

    <img className="thumbnail" alt="Pagina Domini e DNS ed elenco dei nomi di dominio dell'account" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/listing.png" loading="lazy" />
  </Tab>
  <Tab label="Passaggio 2">
    La tabella mostra un record DNS per riga, con le colonne **Sottodominio**, **Tipo**, **Destinazione** e **TTL (in secondi)**. Per visualizzare solo i record di tipo `A`, clicca su <code className="action">Filtri</code>, poi seleziona <code className="action">A</code> nell'elenco **Tipo di record**.

    <img className="thumbnail" alt="Pulsante Filtri ed elenco Tipo di record della zona DNS" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/filter-type.png" loading="lazy" />

    Annota la **Destinazione** del record di tipo `A` per il tuo dominio.
  </Tab>
</Tabs>

#### Effettua le azioni necessarie

**Clicca sullo scenario corrispondente alla tua situazione per visualizzare il contenuto.**

<details>
<summary>L'indirizzo IP corrisponde a quello del tuo hosting condiviso</summary>

L'indirizzo IP indicato nella [zona DNS](/guides/web-cloud/domains/dns-zone-edit) corrisponde a quello del tuo hosting condiviso. Passa alla [parte 2](#step2).

</details>

<details>
<summary>L'indirizzo IP non riguarda alcun hosting del tuo account ma appare nella lista dei server Web Cloud</summary>

L'indirizzo IP indicato nella zona non riguarda alcun hosting del tuo <ManagerLink to="/">account OVHcloud</ManagerLink>, ma appare nella [lista dei server Web Cloud](/guides/web-cloud/web-hosting/clusters-and-shared-hosting-ip).

Verifica di non possedere un hosting con questo indirizzo IP in uno dei tuoi altri <ManagerLink to="/">account OVHcloud</ManagerLink>, se ne hai creati diversi. Se necessario, contatta il tuo webmaster o i [partner OVHcloud](/links/partner) a questo proposito.

</details>

<details>
<summary>L'indirizzo IP non corrisponde a quello del tuo hosting e non compare nella lista dei server Web Cloud</summary>

L'indirizzo IP indicato nella zona non corrisponde a quello del tuo hosting e non compare nemmeno nella [lista dei server Web Cloud](/guides/web-cloud/web-hosting/clusters-and-shared-hosting-ip).

Contatta il tuo webmaster o i [partner OVHcloud](/links/partner) a questo proposito.

</details>

<details>
<summary>Il tuo dominio utilizza altri server DNS OVHcloud (ns?.ovh.net / dns?.ovh.net)</summary>

Sopra la zona DNS presente nella tua console OVHcloud, un avviso indica "**Questa zona DNS non è autoritativa per il tuo nome di dominio.**": il tuo dominio utilizza altri server [DNS](/guides/web-cloud/domains/dns-zone-edit) e le modifiche effettuate in questa zona non vengono prese in considerazione.

Per sapere quali server DNS utilizza il tuo dominio, apri la scheda <code className="action">Panoramica</code> del dominio e consulta la sezione **Configurazione DNS**: l'elenco **Server DNS che ospitano la zona** li mostra. Se compaiono nella forma "ns **?** .ovh.net" o "dns **?** .ovh.net" (il "**?**" corrisponde al numero del server DNS interessato), si tratta di altri server DNS OVHcloud.

<img className="thumbnail" alt="Sezione Configurazione DNS con la configurazione e l'elenco dei server DNS che ospitano la zona" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/general-information/dns-servers-ovhcloud.png" loading="lazy" />

Modifica i server DNS del tuo dominio in modo che corrispondano a quelli registrati nei record di tipo `NS` della zona. Per effettuare questa operazione, segui le istruzioni di [questa guida](/guides/web-cloud/domains/dns-server-edit).

{/* v8-review: TO DOCUMENT — the « This DNS zone is not authoritative for your domain name. » banner was not seen live (no domain on the test account uses servers other than its zone's); its wording comes from ZoneBanners.tsx and zone.json. Unlike v6, it does not list the DNS servers in use, hence the pointer to the Overview « DNS servers » section. */}

</details>

<details>
<summary>Il tuo dominio utilizza server DNS esterni (non OVHcloud)</summary>

Sopra la zona DNS presente nella tua console OVHcloud, viene visualizzato lo stesso avviso "**Questa zona DNS non è autoritativa per il tuo nome di dominio.**". Nella sezione **Configurazione DNS** della scheda <code className="action">Panoramica</code> del dominio, la riga **Configurazione** indica **Personalizzata** e i server DNS elencati non compaiono nella forma "ns **?** .ovh.net" o "dns **?** .ovh.net".

Contatta il tuo webmaster o i [partner OVHcloud](/links/partner) a questo proposito.

</details>

<details>
<summary>Il tuo dominio non compare nella tua console OVHcloud</summary>

Il tuo dominio non compare nella pagina <ManagerLink to="/beta/#/web-cloud/domains/listing">Domini e DNS</ManagerLink> della tua console OVHcloud.

Questo significa che il tuo dominio non è gestito dalla tua console OVHcloud.

Verifica che non sia gestito da uno degli altri <ManagerLink to="/">account OVHcloud</ManagerLink>, se ne hai creati diversi.

Puoi anche determinare il suo Registrar e i server DNS a cui è associato tramite il nostro tool [WHOIS](/links/web/domains-whois).

Se necessario, contatta il tuo webmaster o i [partner OVHcloud](/links/partner) a questo proposito.

</details>

### 2 - Verifica il certificato SSL del tuo hosting <a name="step2"></a>

Clicca sulle schede qui sotto per visualizzare in sequenza ciascuno dei **2** passaggi.

<Tabs>
  <Tab label="Passaggio 1">
    Accedi alla pagina <ManagerLink to="/beta/#/web-cloud/hosting">Hosting web</ManagerLink>, poi scegli l'hosting Web interessato.

    <img className="thumbnail" alt="Pagina Hosting web ed elenco degli hosting dell'account" src="/images/assets/screens/console/product-selection/web-cloud/hosting-plans.png" loading="lazy" />
  </Tab>
  <Tab label="Passaggio 2">
    Clicca sulla scheda <code className="action">SSL</code>.

    <img className="thumbnail" alt="Scheda SSL di un hosting Web" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/ssl-certificates.png" loading="lazy" />

    Individua il tuo dominio nella colonna **Dominio principale**, poi verifica la sua colonna **Stato**. Se il tuo dominio non appare nella tabella, il tuo hosting non contiene un certificato SSL per questo dominio.

    <img className="thumbnail" alt="Tabella dei certificati SSL e relativa colonna Stato" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/ssl-certificates/tab.png" loading="lazy" />
  </Tab>
</Tabs>

#### Scenario 1: il tuo hosting non contiene un certificato SSL

Attiva un [certificato SSL](/links/web/hosting-options-ssl) sul tuo hosting seguendo le istruzioni di questa [guida](/guides/web-cloud/web-hosting/ssl-on-webhosting).

#### Scenario 2: il certificato SSL del tuo hosting non funziona

Se hai generato un **certificato SSL "Let's Encrypt"**, attiva l'opzione SSL del tuo hosting seguendo le istruzioni di [questa guida](/guides/web-cloud/web-hosting/ssl-on-webhosting).

Se disponi di un **certificato SSL importato** e questo non funziona, contatta il suo provider.

Se hai ordinato uno dei **certificati SSL a pagamento** del nostro partner [SECTIGO](https://sectigo.com/), verifica se hai ricevuto un'email che ti propone di rinnovarlo.
<br/>Se necessario, contatta il [supporto di SECTIGO](https://sectigo.com/support) a questo proposito.
