## Obiettivo

Può capitare che Outlook visualizzi in loop una finestra di connessione Microsoft 365 che richiede le tue credenziali, talvolta accompagnata dal messaggio "Specifica l'account da utilizzare per aprire autodiscover.xml". Questa finestra può ricomparire anche dopo il riavvio di Outlook o la creazione di un nuovo profilo. Eppure la casella email interessata non è ospitata nel cloud Microsoft: si trova su una soluzione Exchange OVHcloud (Hosted Exchange o Exchange dedicato).

Questo comportamento deriva da una funzionalità di Outlook chiamata "Direct Connect to Office 365", che forza il client a interrogare l'autodiscover di Office 365 e cortocircuita quello del tuo server Exchange OVHcloud.

**Questa guida ti spiega come individuare l'origine di queste richieste di connessione ripetute e impedire a Outlook di connettersi a Office 365.**

## Prerequisiti

- Disporre di una [soluzione Exchange OVHcloud](/links/web/emails-hosted-exchange) già installata.
- Disporre dell'applicazione [Outlook classico](https://support.microsoft.com/it-it/Outlook/install-or-reinstall-classic-outlook-on-a-windows-pc) (Outlook 2016, 2019, 2021 o Microsoft 365) su Windows.
- Disporre di un accesso amministratore alla postazione client per modificare il registro di Windows. Non è necessario se applichi la soluzione alternativa descritta più avanti.
- Il record SRV di OVHcloud deve essere configurato correttamente nella zona DNS del nome di dominio. Consulta la nostra guida [Aggiungere un dominio sul servizio Exchange](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-adding-domain).

## Procedura

### Comprendere il problema

Microsoft ha introdotto in Outlook una funzionalità chiamata "Direct Connect to Office 365". Quando è attiva, Outlook si connette direttamente all'autodiscover di Office 365 e ignora l'URL di autodiscover del tuo server Exchange.

Questo server può essere un Exchange installato presso la sede della tua azienda (on-premises) o una soluzione Hosted Exchange OVHcloud. **Una soluzione Hosted Exchange non è ospitata sui server Office 365 / Microsoft 365**: si tratta di un server Exchange ospitato sui server OVHcloud.

Outlook interroga quindi Office 365 pensando che la casella si trovi nel cloud Microsoft, invece di verificare prima l'autodiscover del server Exchange OVHcloud. È questo che provoca le ripetute finestre di connessione Microsoft.

Durante l'aggiunta dell'account, questa ricerca automatica dei parametri (autodiscover) è visibile nel passaggio "Ricerca delle impostazioni del server di posta":

<img className="thumbnail" alt="Assistente di Outlook che cerca i parametri del server di posta durante l'aggiunta di un account" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/outlook-connecting-to-office-365/outlook-add-account-searching-settings.png" loading="lazy" />

### Individuare i sintomi

Probabilmente sei interessato da questo problema se riscontri i seguenti elementi:

- Una finestra di connessione Microsoft 365 viene visualizzata in loop in Outlook e richiede continuamente le credenziali.
- Compare il messaggio "Specifica l'account da utilizzare per aprire autodiscover.xml".

    <img className="thumbnail" alt="Finestra di connessione Microsoft 365 in Outlook che richiede l'account per aprire autodiscover.xml" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/outlook-connecting-to-office-365/outlook-office365-signin-prompt.png" loading="lazy" />

- La finestra persiste dopo il riavvio di Outlook o la creazione di un nuovo profilo Outlook.
- La casella email è però effettivamente ospitata su Exchange OVHcloud e l'autodiscover OVHcloud è configurato correttamente.
- Un messaggio di errore in rosso "Il nome utente potrebbe non essere corretto…" può comparire quando l'account inserito non viene riconosciuto dal tenant Microsoft 365.

    <img className="thumbnail" alt="Messaggio di errore rosso 'Il nome utente potrebbe non essere corretto' nella finestra di connessione Microsoft" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/outlook-connecting-to-office-365/outlook-office365-username-incorrect-error.png" loading="lazy" />

### Verificare che la casella sia effettivamente ospitata su Exchange OVHcloud

Prima di applicare la correzione, verifica che la configurazione lato OVHcloud sia corretta:

- Verifica che il record SRV `_autodiscover` del nome di dominio punti ai server OVHcloud, come indicato nella guida [Aggiungere un dominio sul servizio Exchange](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-adding-domain).

    <img className="thumbnail" alt="Zona DNS del nome di dominio nello Spazio Cliente OVHcloud con il record SRV _autodiscover" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/outlook-connecting-to-office-365/ovhcloud-manager-dns-zone-srv-autodiscover.png" loading="lazy" />

- Avvia una diagnostica dal tuo Spazio Cliente per confermare lo stato dell'account, seguendo la guida [Utilizzo della diagnostica degli errori Exchange](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/diagnostic-advanced).

Se la configurazione OVHcloud è corretta ma le finestre di connessione persistono, la causa si trova lato client: Outlook privilegia l'endpoint Office 365.

### Individuare la causa

Questo comportamento si verifica in 2 situazioni principali:

- **Il nome di dominio è stato dichiarato su un tenant Office 365.** Quando aggiungi un dominio a un tenant Microsoft 365, Microsoft considera che le caselle di questo dominio si trovino nel cloud. Outlook si connette quindi all'autodiscover Office 365 invece di quello di OVHcloud.
- **Un account Microsoft utilizza già lo stesso indirizzo email.** Può trattarsi di un utente di un tenant Microsoft 365, con lo stesso indirizzo o lo stesso UPN. Può altrettanto trattarsi di un **account Microsoft personale** — creato per attivare una licenza Office, per esempio — il cui indirizzo di accesso è il tuo indirizzo Exchange. In entrambi i casi Outlook trova questo account per primo e lo segue, anche se non vi è associata alcuna casella.

:::tip
Se non utilizzi (o non utilizzi più) Office 365 per questo dominio, ricordati anche di eliminare il dominio o l'account interessato dal tenant Microsoft 365. Finché Outlook continua a privilegiare l'endpoint Office 365, resta necessaria una delle due correzioni qui di seguito.
:::

Seguono due correzioni. La **chiave di registro** funziona qualunque sia la causa, ma richiede i diritti di amministratore sul computer. Se il conflitto proviene da un **account Microsoft personale**, modificare il suo indirizzo di accesso elimina la causa e non richiede tali diritti.

### Applicare la correzione: la chiave di registro `ExcludeExplicitO365Endpoint`

Per impedire a Outlook di utilizzare l'endpoint esplicito Office 365 durante l'autodiscover, aggiungi una chiave di registro sulla postazione client.

:::warning
La modifica del registro di Windows è un'operazione delicata. Un errore può impedire al sistema o ad alcune applicazioni di funzionare correttamente. Ti consigliamo di effettuare un backup del registro prima di qualsiasi modifica.
:::

#### Tramite l'Editor del Registro di sistema

1. Apri l'**Editor del Registro di sistema** (`regedit`) nella sessione dell'utente interessato sulla postazione client.

    <img className="thumbnail" alt="Ricerca di Windows che mostra l'applicazione Editor del Registro di sistema e l'opzione Esegui come amministratore" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/outlook-connecting-to-office-365/windows-search-registry-editor-run-as-admin.png" loading="lazy" />

2. Accedi alla chiave seguente. Se la sottochiave `AutoDiscover` non esiste, creala:

```text
HKEY_CURRENT_USER\Software\Microsoft\Office\16.0\Outlook\AutoDiscover
```

Il numero di versione `16.0` corrisponde a Outlook 2016, 2019, 2021 e Microsoft 365.

3. Crea un nuovo **valore DWORD (32 bit)**, chiamalo `ExcludeExplicitO365Endpoint` e assegnagli il valore `1`.
4. Chiudi l'Editor del Registro di sistema.

<img className="thumbnail" alt="Editor del Registro di sistema di Windows che mostra il valore ExcludeExplicitO365Endpoint impostato su 1" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/outlook-connecting-to-office-365/registry-editor-exclude-explicit-o365-endpoint.png" loading="lazy" />

#### Tramite la riga di comando

Puoi anche aggiungere la chiave con un unico comando, in un prompt dei comandi:

```bat
reg add HKEY_CURRENT_USER\Software\Microsoft\Office\16.0\Outlook\AutoDiscover /t REG_DWORD /v ExcludeExplicitO365Endpoint /d 1
```

:::warning
Su Windows 11 con Office 2024 LTSC (e, più in generale, le versioni recenti), la chiave `AutoDiscover` non si trova più nel contesto di sistema ma nel **contesto dell'utente connesso**. Avvia quindi l'Editor del Registro di sistema (o il prompt dei comandi) con la sessione dell'utente interessato, e non come amministratore di un altro account.
:::

### Soluzione alternativa: modificare l'indirizzo di accesso dell'account Microsoft

Se il conflitto proviene da un **account Microsoft personale**, è possibile eliminare la causa invece di aggirarla. Questo metodo non richiede alcun diritto di amministratore sul computer, il che ne fa l'unica opzione su una postazione gestita dal tuo servizio informatico.

1. Crea un alias sul tuo account Exchange OVHcloud, seguendo la nostra guida "[Utilizzare gli alias e i reindirizzamenti email](/guides/web-cloud/email-and-collaborative-solutions/common-email-features/feature-redirections#alias-exchange-emp-mxplan)".
1. Accedi a [account.microsoft.com](https://account.microsoft.com), apri **Le tue info** poi **Gestisci l'accesso a Microsoft**, e aggiungi questo alias al tuo account Microsoft. Il messaggio di verifica arriva nella tua casella Exchange, poiché l'alias punta a essa.
1. Imposta questo alias come alias **principale**, poi rimuovi il tuo indirizzo Exchange dall'account Microsoft.

Outlook non trova più alcun account Microsoft per il tuo indirizzo Exchange e l'autodiscover ricade sul server OVHcloud.

:::warning
Microsoft applica i propri limiti: 10 alias al massimo per account, l'alias principale può essere modificato al massimo due volte a settimana e un indirizzo associato a un account aziendale o scolastico non può diventare principale. Questo metodo vale quindi solo per un account Microsoft personale. Per un tenant Microsoft 365, utilizza la chiave di registro sopra.

:::


### Verificare la connessione a Exchange OVHcloud

Avvia Outlook e verifica che la finestra di connessione Microsoft 365 non compaia più. Outlook si connette ora direttamente al tuo server Exchange OVHcloud, e non a Office 365 / Microsoft 365.

Non è necessario ricreare il profilo Outlook dopo l'aggiunta della chiave di registro.

Per confermare la connessione, apri Outlook classico e osserva la **barra di stato** in basso nella finestra: deve mostrare **Connesso a: Microsoft Exchange**. Outlook comunica quindi con il tuo server Exchange OVHcloud, e non più con Office 365:

<img className="thumbnail" alt="Interfaccia di Outlook classico con la barra di stato che mostra 'Connesso a: Microsoft Exchange' in basso nella finestra" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/outlook-connecting-to-office-365/outlook-classic-status-bar-connected-to-exchange.png" loading="lazy" />

<Region zones={['eu']}>

Per verificare il nome esatto del server (<Tooltip content="Il `?` rappresenta il numero del tuo server Exchange OVHcloud (ad esempio `ex1`, `ex2`, `ex3`…), che varia in base all'infrastruttura che ospita la tua casella.">`ex?.mail.ovh.net`</Tooltip>), tieni premuto il tasto **Ctrl** e fai clic con il pulsante destro del mouse sull'icona di Outlook nell'area di notifica di Windows, quindi seleziona **Stato della connessione**.

</Region>

<Region zones={['ca']}>

Per verificare il nome esatto del server (`ex.mail.ovh.ca`), tieni premuto il tasto **Ctrl** e fai clic con il pulsante destro del mouse sull'icona di Outlook nell'area di notifica di Windows, quindi seleziona **Stato della connessione**.

</Region>

:::danger
Se in seguito prevedi di migrare delle caselle verso Office 365 / Exchange Online, ricordati di **eliminare la chiave di registro `ExcludeExplicitO365Endpoint`**. Finché è presente, impedisce a Outlook di connettersi a Exchange Online.
:::
