## Obiettivo

Un connettore di ricezione indica alla tua piattaforma Exchange quali server sono autorizzati a consegnarle le email e a quali condizioni. Serve a posizionare una soluzione antispam esterna, detta anche gateway di filtraggio, davanti alla piattaforma Exchange: i <Tooltip term="mxRecord">record MX</Tooltip> del tuo dominio puntano verso questo gateway, che filtra le email in entrata e poi le trasmette a Exchange.

Il connettore di ricezione è disponibile per [Private Exchange](/links/web/emails-private-exchange) e [Trusted Exchange](/links/web/emails-trusted-exchange). Si crea e si gestisce esclusivamente con l'API OVHcloud.

**Questa guida ti spiega come creare, modificare, disattivare ed eliminare un connettore di ricezione sulla tua piattaforma Exchange con l'API OVHcloud.**

:::info
Per far passare le email **in uscita** della tua piattaforma da un server esterno, utilizza invece un connettore di invio: consulta la nostra guida "[Exchange - Configurare un connettore di invio](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/feature-send-connector)".
:::

## Prerequisiti

- Disporre di una piattaforma [Private Exchange](/links/web/emails-private-exchange) o [Trusted Exchange](/links/web/emails-trusted-exchange).
- Disporre di credenziali API create nella <CreateToken rights="GET=/email/exchange&GET=/email/exchange/*&POST=/email/exchange/*&PUT=/email/exchange/*&PATCH=/email/exchange/*&DELETE=/email/exchange/*">pagina di generazione dei token OVHcloud</CreateToken>, con almeno il diritto `GET` su `/email/exchange` e i diritti `GET`, `POST`, `PUT`, `PATCH` e `DELETE` su `/email/exchange/*`. Consulta la nostra guida "[Iniziare a utilizzare le API OVHcloud](/guides/manage-and-operate/api/first-steps)".
- Conoscere gli indirizzi IP dei server della tua soluzione antispam esterna che consegneranno le email a Exchange. Richiedili al fornitore di questa soluzione.

## Procedura

### Comprendere il connettore di ricezione predefinito

Ogni piattaforma Exchange dispone di un connettore di ricezione predefinito. Appartiene a Exchange: non puoi né modificarlo né eliminarlo, ma solo attivarlo o disattivarlo. Nell'API, la sua proprietà `default` vale `true`.

:::warning
**Non disattivare il connettore di ricezione predefinito.** Se non si applica nessun altro connettore, la sua disattivazione interrompe la ricezione di tutte le email della piattaforma.
:::

### Trovare i parametri del percorso

Le chiamate del connettore di ricezione richiedono il nome dell'organizzazione (`organizationName`) e il nome del servizio (`exchangeService`) della tua piattaforma. Recuperali nell'ordine: la prima chiamata riportata di seguito fornisce l'organizzazione, necessaria per la seconda.

**1. Organizzazione** (`organizationName`)

Elenca le organizzazioni Exchange del tuo account con la chiamata API riportata di seguito:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange"} />

**2. Servizio** (`exchangeService`)

Elenca i servizi Exchange dell'organizzazione con la chiamata API riportata di seguito:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service"} />

### Creare un connettore di ricezione

Crea il connettore con la chiamata API riportata di seguito:

<Api version="v1" section="/email/exchange" method="POST" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector"} regions={["eu"]} />

Compila i seguenti campi nel corpo della richiesta. Solo `name`, `remoteIpRanges` e `requireTls` sono obbligatori.

| Campo | Tipo | Descrizione |
|---|---|---|
| `name` | string | Nome del connettore, massimo 255 caratteri |
| `remoteIpRanges` | string[] | Indirizzi IP dei server autorizzati a consegnare email tramite questo connettore (vedi sotto) |
| `requireTls` | boolean | `true` per richiedere TLS per tutte le email ricevute da questo connettore |
| `maxMessageSize` | long | Facoltativo. Dimensione massima di un'email ricevuta da questo connettore, in MB |
| `enabled` | boolean | Facoltativo. `true` per attivare il connettore al momento della creazione (`false` per impostazione predefinita) |

Ogni voce di `remoteIpRanges` può essere:

- un singolo indirizzo IP, ad esempio `203.0.113.10`;
- una rete in notazione CIDR, ad esempio `203.0.113.0/28`;
- un intervallo di indirizzi "inizio-fine", estremi inclusi, ad esempio `203.0.113.10-203.0.113.20`.

Sono accettati gli indirizzi IPv4 e IPv6.

:::warning
**Limiti di `remoteIpRanges`**

- Uno stesso indirizzo IP non può comparire in due connettori di ricezione della piattaforma.
- L'elenco completo, una volta unite le sue voci con delle virgole, non deve superare i 255 caratteri. Preferisci una rete CIDR a un lungo elenco di singoli indirizzi.

:::

La chiamata restituisce un task: il connettore viene creato una volta completato il task.

### Elencare e consultare i connettori di ricezione

Elenca i connettori di ricezione della piattaforma, compreso il connettore predefinito, con la chiamata API riportata di seguito:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector"} regions={["eu"]} />

La chiamata restituisce l'elenco degli identificativi (`id`) dei connettori. Consulta i dettagli di un connettore con la chiamata API riportata di seguito:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

Oltre ai campi di creazione, la risposta contiene `id`, l'identificativo del connettore, e `default`, che vale `true` per il connettore di ricezione predefinito.

### Modificare un connettore di ricezione

Per modificare uno o più campi senza toccare gli altri, utilizza la chiamata API riportata di seguito:

<Api version="v1" section="/email/exchange" method="PATCH" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

Per sostituire l'intera configurazione del connettore, compila tutti i campi nella chiamata API riportata di seguito:

<Api version="v1" section="/email/exchange" method="PUT" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

:::info
Il campo `remoteIpRanges` sostituisce l'elenco registrato nella sua interezza. Per aggiungere un indirizzo IP, invia di nuovo l'elenco completo: gli indirizzi esistenti e quello nuovo.
:::

Per attivare o disattivare un connettore, modifica il suo campo `enabled`. Sul connettore di ricezione predefinito, questo è l'unico campo che puoi modificare: consulta l'avviso della sezione "[Comprendere il connettore di ricezione predefinito](#comprendere-il-connettore-di-ricezione-predefinito)".

Ogni modifica restituisce un task: viene applicata una volta completato il task.

### Eliminare un connettore di ricezione

Elimina un connettore con la chiamata API riportata di seguito:

<Api version="v1" section="/email/exchange" method="DELETE" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

La chiamata restituisce un task: il connettore viene eliminato una volta completato il task. Non puoi eliminare il connettore di ricezione predefinito.
