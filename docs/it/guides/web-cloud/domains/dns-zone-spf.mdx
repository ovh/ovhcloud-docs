## Obiettivo

Il record SPF (Sender Policy Framework) permette al server ricevente di verificare che un'email sia stata inviata da un server affidabile.

<details>

<summary>Perché installare il record SPF per le tue email?</summary>

- Permette di prevenire eventuali usurpazioni d'identità provenienti da indirizzi email che utilizzano il tuo nome di dominio (spoofing).
- Permette inoltre di autenticare le email inviate.
- Il record SPF si aggiunge come record nella zona DNS del nome di dominio.

Questa verifica si basa sulle informazioni inserite nel record SPF, che è in realtà un record TXT nella zona DNS. Contiene:

- **indirizzi di server e/o più indirizzi IP**: sono così identificati come fonti di invio legittime;
- **un qualificatore**: indica al server di ricezione come trattare un messaggio non legittimo, cioè proveniente da una fonte non elencata.

Assicurati quindi di dichiarare nel record SPF tutte le sorgenti che utilizzi per inviare email con il tuo nome di dominio: il tuo server di posta, quello del tuo provider o una delle soluzioni email di OVHcloud.

**Esempio**

Invia un'email dal tuo indirizzo `john.smith@domain.tld`.

Solo il server in uscita **A** (Outgoing Mail Server **A**) è dichiarato nel record SPF del nome di dominio `domain.tld`.

Quando il server di ricezione (Inbound Mail Server) riceve l'email, legge il record SPF nella zona DNS di `domain.tld`.

- Il server in uscita **A** (Outgoing Mail Server **A**) è indicato nel record SPF: l'email viene quindi trasmessa normalmente nella casella di ricezione del destinatario.
- Il server in uscita **B** (Outgoing Mail Server **B**) non è indicato nel record SPF: l'email inviata da questo server viene quindi contrassegnata come sospetta nella casella di posta in arrivo. Ciò può comportare l'apposizione di un'indicazione `[SPAM]` nell'oggetto dell'email, l'inserimento in una cartella `Posta indesiderata` o la cancellazione diretta, secondo le regole del server di ricezione.

<img className="thumbnail" alt="Schema del funzionamento di un record SPF tra server di invio e di ricezione" src="/images/assets/schemas/emails/spf-records-diagram.png" loading="lazy" />

:::info
Il record SPF è un'indicazione fornita ai server mail, tra cui anche i tuoi, ed è compito dei server stessi applicare i record SPF appartenenti ai nomi di dominio per conto dei quali ricevono email.

:::

</details>

**Questa guida ti mostra come configurare un record SPF sul tuo nome di dominio in OVHcloud.**

## Prerequisiti

- Il nome di dominio deve utilizzare la configurazione OVHcloud (cioè i server DNS di OVHcloud).

[[cpnav:web-domain-dns-zone-console]]

:::warning
Se il nome di dominio non utilizza i server DNS di OVHcloud, è necessario apportare la modifica del record SPF attraverso l'interfaccia del provider che gestisce la configurazione del nome di dominio.

Se il tuo dominio è registrato in OVHcloud, puoi verificare se utilizza la configurazione OVHcloud dalla pagina <ManagerLink to="/beta/#/web-cloud/domains/listing">Domini e DNS</ManagerLink>, una volta selezionato il dominio interessato: lo indica la sezione **Configurazione DNS** della scheda <code className="action">Panoramica</code>.

:::

## Procedura

### Verifica la tua configurazione SPF attuale

Se il tuo nome di dominio utilizza i server DNS di OVHcloud, puoi verificare se è già configurato un record SPF.

<details>

<summary>Come verificare una configurazione SPF esistente?</summary>

Accedi alla pagina <ManagerLink to="/beta/#/web-cloud/domains/listing">Domini e DNS</ManagerLink>, scegli il dominio interessato, poi clicca sulla scheda <code className="action">Zona DNS</code>.

Questa tabella elenca i record DNS della zona del tuo nome di dominio, uno per riga.

:::info
In caso di dubbi, verifica che il tuo dominio utilizzi i server DNS di OVHcloud nella sezione **Configurazione DNS** della scheda <code className="action">Panoramica</code>.

:::

Per trovare la riga del record SPF OVHcloud, applica un filtro alla tabella con il pulsante <code className="action">Filtri</code>. Poiché il record può comparire in due punti diversi e il filtro mostra un solo tipo alla volta, filtra prima su <code className="action">TXT</code>, poi su <code className="action">SPF</code>.

<img className="thumbnail" alt="Pulsante Filtri ed elenco Tipo di record della zona DNS" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/filter-type.png" loading="lazy" />

Otterrai uno dei seguenti risultati.

- **Viene visualizzato un record SPF corrispondente alla configurazione OVHcloud**: il tuo nome di dominio utilizza già la configurazione OVHcloud. Se non vuoi più utilizzarla, dovrai modificarla nello step successivo.

- **Viene visualizzato un record SPF che non corrisponde alla configurazione OVHcloud**: il tuo nome di dominio utilizza già un SPF personalizzato. Se la configurazione è errata, modificala oppure sostituiscila con la configurazione OVHcloud nello step successivo.

- **Non viene visualizzato alcun record SPF**: verifica prima, modificando il filtro, che il record non esista con l'altro tipo (SPF o TXT). Se non compare alcun record SPF nella zona, il tuo nome di dominio non ne utilizza uno; potrai aggiungerlo nello step successivo.

:::info
<Region zones={['eu']}>

Un SPF è sempre composto dalla forma seguente: "v=spf1 `sorgenti` `qualificatore`". Ad esempio, il record SPF OVHcloud è: `v=spf1 include:mx.ovh.com ~all`.

</Region>
<Region zones={['ca', 'apac']}>

Un SPF è sempre composto dalla forma seguente: "v=spf1 `sorgenti` `qualificatore`". Ad esempio, il record SPF OVHcloud è: `v=spf1 include:mx.ovh.ca ~all`.

</Region>

:::

</details>

### Configura un nuovo record SPF <a name="spfrecord"></a>

Sopra la tabella, clicca su <code className="action">Crea un record</code>, poi, nell'elenco **Tipo**, seleziona <code className="action">SPF — Server autorizzati a inviare e-mail</code> (sezione **Campi email**). Si apre un modulo per costruire il record SPF campo per campo.

<img className="thumbnail" alt="Modulo di creazione del record della zona DNS, record SPF" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/add-spf-record.png" loading="lazy" />

- **Sottodominio**: questo campo è obbligatorio. Inserisci `@` per applicare l'SPF all'intero dominio, oppure inserisci un sottodominio se invii email solo da quest'ultimo.
- **Meccanismi di autorizzazione**: seleziona le fonti autorizzate a inviare email per il tuo dominio.
    - **Includere i server e-mail OVH (include:mx.ovh.com)**: selezionata per impostazione predefinita, questa casella autorizza in un'unica volta tutti i server email in uscita di OVHcloud inserendo `include:mx.ovh.com`. Lasciala selezionata se utilizzi una [soluzione email OVHcloud](#ovhcloudspfvalue) e verifica in quella sezione il valore da utilizzare in base alla tua zona.
    - **Autorizzare i server MX del dominio (mx)**: autorizza i server che ricevono le tue email a inviarle anche.
    - **Autorizzare l'indirizzo IP del dominio (a)**: autorizza il server che ospita il tuo nome di dominio (utile quando il tuo sito web e le tue email condividono lo stesso indirizzo IP, ad esempio su un server dedicato).
- **Server aggiuntivi da autorizzare (include)**: aggiungi i domini SPF di altri provider che inviano email per tuo conto (piattaforma di marketing, CRM, ecc.), in modo che i loro server siano considerati legittimi.
- **Indirizzi IPv4 autorizzati (ip4)** e **Indirizzi IPv6 autorizzati (ip6)**: aggiungi indirizzi IP o blocchi di IP specifici autorizzati a inviare email.
- **Politica SPF**: scegli come i server di ricezione devono trattare un'email inviata da una fonte che **non** è elencata (vedi la nostra raccomandazione qui sotto). Il valore `~all` ("Accettare ma contrassegnare come sospetto") è preselezionato e contrassegnato come **Consigliato**.
- <Tooltip term="ttl">**TTL**</Tooltip>: lascialo su `Predefinito` oppure imposta un valore.

Il riquadro **Anteprima del record** mostra il record in costruzione man mano che compili i campi. Una volta terminato, clicca su <code className="action">Aggiungi</code>.

:::tip
I valori `~all` e `-all` della **Politica SPF** sono entrambi validi, ma per una protezione ottimale ti consigliamo vivamente `-all`, che chiede ai server che ricevono le tue email di **rifiutare** qualsiasi messaggio proveniente da una sorgente non elencata nel tuo record SPF.

Scegli `-all` solo quando sei certo che il tuo record elenchi **tutte** le sorgenti di invio legittime: la tua soluzione email OVHcloud, ma anche qualsiasi servizio di terze parti che invia email per tuo conto (piattaforma di marketing, CRM, strumento di ticketing, ecc.). Se manca una sorgente legittima, le sue email verranno rifiutate. Se non sei certo che l'elenco sia completo, utilizza `~all`, che contrassegna queste email come sospette invece di rifiutarle.
:::

:::info
<Region zones={['eu']}>

Per una soluzione email OVHcloud, il record SPF minimo consiste semplicemente nel lasciare selezionata la casella **Includere i server e-mail OVH (include:mx.ovh.com)**, selezionata per impostazione predefinita: questo produce `v=spf1 include:mx.ovh.com ~all` (consulta [Configurazione SPF OVHcloud per le soluzioni email condivise](#ovhcloudspfvalue)).

</Region>
<Region zones={['ca', 'apac']}>

Per una soluzione email OVHcloud, il record SPF minimo è `v=spf1 include:mx.ovh.ca ~all`: deseleziona la casella **Includere i server e-mail OVH (include:mx.ovh.com)**, selezionata per impostazione predefinita, che inserisce il valore europeo `mx.ovh.com`, poi inserisci `mx.ovh.ca` nel campo **Server supplementari da autorizzare (include)** (consulta [Configurazione SPF OVHcloud per le soluzioni email condivise](#ovhcloudspfvalue)).

</Region>

:::

Se disponi già della stringa SPF completa (fornita dal tuo servizio email) o hai bisogno di un tag non presente nel modulo, inseriscila direttamente: seleziona il tipo <Tooltip term="txtRecord">**TXT**</Tooltip> (<code className="action">TXT — Testo libero (verifica, SPF...)</code>) invece di SPF e incolla il valore completo `v=spf1 …` nel campo **Valore**, oppure utilizza la <code className="action">Modalità avanzata</code>, in cima al modulo.

:::info
La <Tooltip term="dnsPropagation">propagazione</Tooltip> delle modifiche potrebbe richiedere da 4 a 24 ore.

:::

### Modifica un record SPF <a name="modifyspf"></a>

Accedi alla pagina <ManagerLink to="/beta/#/web-cloud/domains/listing">Domini e DNS</ManagerLink>, scegli il dominio interessato, poi clicca sulla scheda <code className="action">Zona DNS</code>.

La tabella mostra la zona DNS del tuo dominio: ogni riga corrisponde a un record DNS. Individua il tuo record TXT o SPF nella tabella, clicca sul pulsante <code className="action">⋮</code> della colonna **Azioni**, poi su <code className="action">Modifica</code>. La riga si espande in un modulo di modifica.

<img className="thumbnail" alt="Menu delle azioni di una riga della zona DNS" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/row-actions.png" loading="lazy" />

Per maggiori informazioni sui campi SPF, consulta la sezione "[Configura un nuovo record SPF](#spfrecord)".

### Configurazione SPF OVHcloud per le soluzioni email condivise <a name="ovhcloudspfvalue"></a>

La configurazione SPF OVHcloud generale si applica alle seguenti soluzioni:

- <Tooltip term="mxPlan">MX Plan</Tooltip> da solo o incluso in un'offerta di [Hosting Web OVHcloud](/links/web/hosting).
<Region zones={['eu']}>
- [Email Pro](/links/web/email-pro).
</Region>
<Region zones={['eu', 'ca']}>
- [Hosted Exchange](/links/web/emails-hosted-exchange).
</Region>

La configurazione è questa:

<Region zones={['eu']}>

```bash
domain.tld IN TXT "v=spf1 include:mx.ovh.com ~all"
```

</Region>
<Region zones={['ca', 'apac']}>

```bash
domain.tld IN TXT "v=spf1 include:mx.ovh.ca ~all"
```

</Region>

<Region zones={['eu', 'ca']}>

### Configurazione SPF OVHcloud per Private Exchange

Per l'offerta Private Exchange, inserisci gli indirizzi IP del tuo server con l'argomento `ip4` (IPv4, record **A**) e l'argomento `ip6` (IPv6, record **AAAA**).

```bash
domain.tld IN TXT "v=spf1 ip4:203.0.113.1 ip6:2001:db8::1 ~all"
```

<Region zones={['eu']}>

Se utilizzi anche [un'offerta email condivisa](#ovhcloudspfvalue), aggiungi `include:mx.ovh.com` al record:

```bash
domain.tld IN TXT "v=spf1 ip4:203.0.113.1 ip6:2001:db8::1 include:mx.ovh.com ~all"
```

</Region>
<Region zones={['ca', 'apac']}>

Se utilizzi anche [un'offerta email condivisa](#ovhcloudspfvalue), aggiungi `include:mx.ovh.ca` al record:

```bash
domain.tld IN TXT "v=spf1 ip4:203.0.113.1 ip6:2001:db8::1 include:mx.ovh.ca ~all"
```

</Region>

<details>

<summary>Come recuperare gli indirizzi IP di un server Private Exchange?</summary>

Accedi alla pagina <ManagerLink to="/beta/#/web-cloud/email/exchange">Exchange</ManagerLink>, poi clicca sul servizio il cui **Tipo di offerta** è **Private Exchange**.

Nella scheda <code className="action">Panoramica</code>, sezione **Informazioni generali**, la parte **Diagnostica del server** mostra gli indicatori `A` e `AAAA`. Clicca su <code className="action">Visualizza diagnostica</code> poi, nel pannello che si apre, sulle schede <code className="action">A</code> e <code className="action">AAAA</code>: annota il valore visualizzato sotto **Destinazione**.

<img className="thumbnail" alt="Pannello Diagnostica del server di un servizio Private Exchange, scheda A e relativa destinazione" src="/images/assets/screens/console/product-selection/web-cloud/email-and-collaborative-solutions/exchange/server-diagnostics.png" loading="lazy" />

Se gli indicatori `A` e `AAAA` sono verdi, il pannello indica "Configurazione automatica completata" e non mostra gli indirizzi IP. Recuperali quindi dalla zona DNS del dominio associato alla tua piattaforma Private Exchange. Per farlo, annota prima l'indirizzo del link **Webmail** della sezione **Informazioni generali**.

<img className="thumbnail" alt="Sezione Informazioni generali di un servizio Private Exchange, link Webmail e diagnostica del server" src="/images/assets/screens/console/product-selection/web-cloud/email-and-collaborative-solutions/exchange/general-information.png" loading="lazy" />

Accedi poi alla pagina <ManagerLink to="/beta/#/web-cloud/domains/listing">Domini e DNS</ManagerLink>, scegli il dominio associato alla tua piattaforma Private Exchange, poi clicca sulla scheda <code className="action">Zona DNS</code>. Recupera gli indirizzi IPv4 (record `A`) e IPv6 (record `AAAA`) corrispondenti all'URL del webmail.

</details>
