:::info
Il server MCP di OVHcloud è in fase di sviluppo attivo. L'elenco degli strumenti disponibili si arricchisce regolarmente: una funzionalità oggi assente può essere disponibile poco dopo. Consulta l'[hub MCP di OVHcloud](https://mcp.eu.ovhcloud.com/index.html) per conoscere l'inventario aggiornato.
:::

## Obiettivo

Il **Model Context Protocol** (MCP) è uno standard aperto che permette a un assistente IA di utilizzare strumenti esterni. Il server MCP di OVHcloud espone i tuoi servizi OVHcloud sotto forma di strumenti, in modo che un assistente possa consultare e modificare la tua configurazione per tuo conto.

In pratica, questo significa che non devi più navigare tra le interfacce né scrivere chiamate API: ti basta chiedere:

```text
Elenca i miei domini e dimmi quali scadono nei prossimi 60 giorni.
```

**Questa guida spiega come collegare un agente IA al server MCP di OVHcloud e utilizzarlo per gestire i tuoi domini, i tuoi record DNS e i tuoi reindirizzamenti.**

## Prerequisiti

- Essere connesso al tuo <ManagerLink to="/">Spazio Cliente OVHcloud</ManagerLink>
- Avere installato un client MCP compatibile (consulta [Collegare il tuo agente](#3--collegare-il-tuo-agente-a-mcp))
- Disporre di un browser per completare l'autenticazione OAuth2

## Procedura

### 1 — Come funziona MCP

Entrano in gioco tre componenti:

| Componente | Ruolo |
|------------|-------|
| **Il tuo agente IA** | L'assistente con cui parli (un agente da terminale, una chat integrata nell'IDE, la tua applicazione) |
| **Il server MCP di OVHcloud** | Pubblica gli *strumenti* disponibili e li esegue sul tuo account |
| **Il tuo account OVHcloud** | I permessi, verificati a ogni chiamata, che determinano ciò che l'agente può fare |

Non richiami mai uno strumento per nome. Descrivi ciò che desideri, l'agente seleziona lo strumento adeguato e ti chiede conferma prima di modificare qualsiasi cosa.

:::warning
Un agente IA collegato a MCP agisce con i **tuoi** permessi. Leggi ogni richiesta di conferma prima di accettarla, in particolare per le operazioni che eliminano record o modificano i server DNS.
:::

### 2 — L'hub MCP di OVHcloud

L'[hub MCP di OVHcloud](https://mcp.eu.ovhcloud.com/index.html) elenca i servizi esposti sotto forma di strumenti MCP ed è il riferimento per sapere cosa è attualmente disponibile.

Scegli l'URL corrispondente alla region del tuo account OVHcloud:

| Region | URL del server MCP |
|--------|--------------------|
| Europa | `https://mcp.eu.ovhcloud.com/mcp/{section}` |
| Canada | `https://mcp.ca.ovhcloud.com/mcp/{section}` |

Sostituisci `{section}` con il nome della sezione a cui desideri collegarti, così come appare sulle schede dell'hub. Ti colleghi sempre a una sezione precisa: non esiste un URL globale che esponga tutti gli strumenti contemporaneamente.

#### Sezioni per i domini

Due sezioni coprono i domini, una per versione dell'API:

| Sezione | Contenuto esposto |
|---------|-------------------|
| `v1_domain` | Gli strumenti per i domini dell'API v1 |
| `v2_domain` | Gli strumenti per i domini dell'API v2 |

L'URL da utilizzare è quindi `https://mcp.eu.ovhcloud.com/mcp/v1_domain` per un account europeo sull'API v1.

Ad oggi, l'API v1 resta la più completa a livello funzionale: `v1_domain` espone quindi un insieme di strumenti più ampio rispetto a `v2_domain`. L'API v2 si arricchisce progressivamente.

Per capire cosa distingue l'API v2 dall'API v1, consulta la guida [OVHcloud API v2 - Principles of operation](/guides/manage-and-operate/api/apiv2#as-code-design).

Puoi aggiungere l'una, l'altra o entrambe contemporaneamente. `v1_domain` da sola è sufficiente per effettuare tutte le operazioni di questa guida.

### 3 — Collegare il tuo agente a MCP

L'autenticazione si basa su **OAuth2**: la prima volta che il tuo agente contatta il server, si apre una finestra del browser sulla pagina di autenticazione OVHcloud. Una volta effettuato l'accesso, l'agente riutilizza quella sessione per le sue chiamate MCP.

:::info
Non è necessario alcun header HTTP personalizzato: le credenziali sono fornite dal flusso OAuth2. Le istruzioni di configurazione di OVHcloud indicano di lasciare **vuota** la sezione degli header nella configurazione del client.
:::

<Tabs>
<Tab label="SHAI">

[SHAI](https://github.com/ovh/shai) è l'agente da terminale di OVHcloud. È richiesta la versione **0.1.5 o successiva**.

Crea il seguente file di configurazione a partire dal [modello `.ovh.config`](https://github.com/ovh/shai/blob/main/.ovh.config) del repository SHAI:

```bash
$HOME/.config/shai/agents/ovh.config
```

Dichiara in `tools.mcp` una voce per ogni sezione che desideri utilizzare. Questo esempio attiva entrambe le versioni dell'API:

```json
{
  "name": "ovh",
  "description": "OVH agent with OVH MCP server for cloud management and API calls",
  "tools": {
    "builtin": ["*"],
    "builtin_excluded": [],
    "mcp": {
      "v1_domain": {
        "config": {
          "type": "http",
          "url": "https://mcp.eu.ovhcloud.com/mcp/v1_domain"
        },
        "enabled_tools": ["*"]
      },
      "v2_domain": {
        "config": {
          "type": "http",
          "url": "https://mcp.eu.ovhcloud.com/mcp/v2_domain"
        },
        "enabled_tools": ["*"]
      }
    }
  },
  "system_prompt": "{{CODER_BASE_PROMPT}}",
  "max_tokens": 4096,
  "temperature": 0.3
}
```

Sostituisci gli endpoint con quelli della tua region.

:::info
Non aggiungere manualmente alcuna credenziale a questo file. Dopo l'accesso, è SHAI stesso a scrivere un `access_token` e un `expires_at` nel blocco `config` di ogni server. Questi valori sono segreti personali: non mettere mai questo file sotto controllo di versione e non condividerlo così com'è.
:::

Avvia poi l'agente. Il browser si apre sulla pagina di autenticazione OVHcloud: accedi per completare la connessione.

</Tab>
<Tab label="Goose">

La via più rapida è l'[hub MCP di OVHcloud](https://mcp.eu.ovhcloud.com/index.html): individua la scheda **V1 Domain** (o **V2 Domain**) e clicca sul pulsante **Add in Goose**. Goose si apre con l'estensione già precompilata (nome, endpoint e transport) e non ti resta che confermare.

Il pulsante utilizza l'endpoint dell'hub che stai consultando. Dall'hub europeo, quindi, configura l'estensione su `https://mcp.eu.ovhcloud.com`: per un account in Canada, apri l'hub della tua region oppure segui la configurazione manuale qui sotto.

**Configurazione manuale.** In Goose, aggiungi una nuova estensione di tipo **HTTP**, poi indica:

- **URL**: l'URL della tua region con la sezione desiderata, `https://mcp.eu.ovhcloud.com/mcp/v1_domain` o `https://mcp.eu.ovhcloud.com/mcp/v2_domain`
- **Headers**: lascia vuoto

Salva l'estensione. Goose apre il browser per l'autenticazione OVHcloud.

Per utilizzare entrambe le versioni dell'API, crea una seconda estensione con l'altra sezione.

</Tab>
<Tab label="Claude Code">

Aggiungi un server per sezione, con l'URL della tua region:

```bash
claude mcp add --transport http v1_domain https://mcp.eu.ovhcloud.com/mcp/v1_domain
claude mcp add --transport http v2_domain https://mcp.eu.ovhcloud.com/mcp/v2_domain
```

Il primo comando da solo copre tutte le operazioni di questa guida. Aggiungi `--scope user` affinché un server sia disponibile in tutti i tuoi progetti e non solo in quello corrente. Non utilizzare alcuna opzione `--header`.

Avvia poi l'autenticazione OAuth2 da Claude Code:

```text
/mcp
```

Accedi a OVHcloud nella finestra del browser che si apre. `claude mcp list` mostra quindi `✔ Connected` accanto a ogni server aggiunto.

</Tab>
</Tabs>

Per verificare che la connessione funzioni, poni al tuo agente una domanda di sola lettura:

```text
Elenca i miei domini OVHcloud.
```

### 4 — Visualizzare le informazioni di un dominio

Inizia chiedendo l'elenco dei tuoi domini, poi richiedi i dettagli di uno di essi.

Esempio di richiesta:

```text
Mostrami i dettagli di mydomain.ovh: data di scadenza, server DNS e stato del blocco del trasferimento.
```

### 5 — Ordinare un dominio

L'ordine di un dominio si effettua con lo strumento `order-new-domain-name`, disponibile nella sezione `v1_domain`.

Esempio di richiesta:

```text
Ordina mydomain.ovh per un anno.
```

Prima di qualsiasi acquisto, chiedi una **simulazione**. Lo strumento accetta un parametro `dryRun`: impostato su `true`, verifica la disponibilità del nome e calcola il prezzo **senza impegnare né fatturare nulla**.

```text
Simula l'ordine di mydomain.ovh per un anno.
```

Il tuo agente mostra quindi il preventivo (prezzo, durata e configurazione che sarà applicata al dominio) e attende la tua approvazione prima di proseguire.

Una volta che hai approvato il preventivo, l'agente ripete la chiamata con `dryRun` impostato su `false`. L'ordine diventa definitivo: l'API restituisce l'**URL del buono d'ordine**. Il tuo agente ti comunica questo URL direttamente nella sua risposta: aprilo nel browser per pagare l'ordine. Trovi questo buono d'ordine anche nel tuo Spazio Cliente OVHcloud, nella sezione <ManagerLink to="/#/billing/orders">I miei ordini</ManagerLink>.

:::info
Il buono d'ordine deve essere **pagato** affinché la registrazione venga trasmessa al registro. Il tuo agente non può pagare al posto tuo: segui l'URL del buono d'ordine che ti ha restituito per effettuare il pagamento. Finché il pagamento non viene incassato, il dominio resta disponibile per un terzo.
:::

:::warning
Confermare l'ordine genera un buono d'ordine reale e a pagamento sul tuo account OVHcloud. Leggi la richiesta di conferma del tuo agente prima di accettarla e verifica il nome del dominio e la durata: una registrazione non si annulla come una modifica di configurazione.
:::

### 6 — Modificare un record DNS

Strumenti associati: `create-domain-zone-record` per aggiungere un record, `delete-domain-zone-record` per eliminarne uno e `get-domain-zone-details` per consultare la zona.

Esempi di richieste:

```text
Modifica il record A di www.mydomain.ovh in 203.0.113.42.
```

Non hai bisogno di sapere quale tipo di record modificare. Descrivi il risultato che ti aspetti: il tuo agente individua il record interessato, ti spiega cosa sta per modificare e attende la tua approvazione prima di applicare la modifica.

```text
Il mio sito è ora ospitato su un server il cui indirizzo IP è 203.0.113.42.
Fai in modo che www.mydomain.ovh punti a quell'indirizzo.
```

:::warning
Un record DNS modificato diventa attivo solo dopo l'aggiornamento della zona. Se ometti questo passaggio, la tua modifica viene registrata ma non viene mai applicata. Chiedi esplicitamente al tuo agente di aggiornare la zona, oppure verifica che lo abbia fatto.
:::

La propagazione su Internet può poi richiedere fino a 24 ore, in base al TTL del record.

### 7 — Creare un reindirizzamento

Un reindirizzamento invia i visitatori del tuo dominio verso un altro indirizzo.

Esempio di richiesta:

```text
Reindirizza blog.mydomain.ovh verso https://mydomain.ovh/notizie, mantenendo l'indirizzo visibile nel browser.
```

### 8 — Le altre operazioni coperte

Le sezioni `v1_domain` e `v2_domain` espongono le route corrispondenti dell'API OVHcloud sotto forma di strumenti: **qualsiasi operazione realizzabile sui tuoi domini tramite l'API lo è anche tramite MCP**. Oltre alle operazioni descritte sopra, questo comprende ad esempio:

- DNSSEC: attivazione, disattivazione e gestione dei record DS
- Protezione contro il trasferimento: blocco e sblocco
- Gestione dei contatti: proprietario, amministratore, tecnico e di fatturazione
- Server DNS e record glue
- Identificativi e record DynHost (DNS dinamico)
- Backup, ripristino, importazione ed esportazione della zona
- Gestione delle operazioni: accelerazione, annullamento, rilancio
- Recupero del codice AuthInfo e approvazione dei trasferimenti in uscita

Se non sei certo che un'operazione sia possibile, chiedi al tuo agente di spiegarti cosa è in grado di fare sui tuoi domini.
