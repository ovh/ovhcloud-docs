## Obiettivo

Le istanze Public Cloud sono facili da implementare e gestire. Tuttavia, in quanto parte dell'ecosistema Public Cloud di OVHcloud, le istanze offrono numerose opzioni di configurazione e possono essere adattate a diversi casi d'uso. Le istruzioni seguenti includono tutti i passaggi necessari (e anche quelli facoltativi) per creare un'istanza nello Spazio Cliente OVHcloud e accedervi da remoto.
Potrete poi approfondire il vostro progetto Public Cloud in base alle vostre esigenze.

**Questa guida vi mostra i primi passi con un'istanza Public Cloud.**

## Prerequisiti

- Un [progetto Public Cloud](/links/public-cloud/public-cloud) nel vostro account OVHcloud

[[cpnav:publiccloud-instances]]

:::tip
Approfittate dei prezzi ridotti impegnandovi per un periodo da 1 a 36 mesi sulle vostre risorse Public Cloud. Per maggiori informazioni, consultate la pagina [Savings Plans](/links/public-cloud/savings-plan).

:::

### Step 1: creare un set di chiavi SSH

Se disponete già di una coppia di chiavi SSH pronta all'uso, potete saltare questo step.

Il [protocollo SSH](/guides/bare-metal-cloud/dedicated-servers/ssh-introduction) permette una comunicazione client-server crittografata. Una **coppia di chiavi SSH** è composta da una chiave pubblica e una chiave privata.

- La **chiave pubblica** viene aggiunta alla vostra istanza Public Cloud (e può anche essere [archiviata nello Spazio Cliente OVHcloud](#step-2-importare-le-chiavi-ssh)).
- La **chiave privata** è archiviata sul vostro dispositivo locale e deve essere protetta da qualsiasi accesso non autorizzato. Solo i dispositivi client con la chiave privata corrispondente possono accedere alla vostra istanza. Per la connessione non è necessaria alcuna password dell'account utente.

Per creare e gestire le vostre chiavi SSH avete 2 opzioni:

- L'interfaccia da riga di comando del vostro OS (semplice client **OpenSSH**).
- Un software aggiuntivo (compatibile con il protocollo **OpenSSH**) con riga di comando o interfaccia grafica.

La maggior parte dei sistemi operativi desktop attuali include nativamente il client **OpenSSH**, accessibile tramite l'applicazione da riga di comando del sistema (`cmd`, `Powershell`, `Terminal`, ecc.). Se non avete familiarità con l'utilizzo delle chiavi SSH come metodo di autenticazione, potete utilizzare le istruzioni di [questa guida](/guides/public-cloud/compute/creating-ssh-keys#create-ssh-key) per creare la vostra coppia di chiavi.

Se utilizzate un altro software, consultate la relativa documentazione utente. Le istruzioni per la soluzione open source `PuTTY` sono disponibili in [questa guida](/guides/web-cloud/web-hosting/ssh-using-putty-on-windows).

### Step 2: Importare le chiavi SSH

Potete archiviare le vostre chiavi SSH pubbliche nel vostro progetto Public Cloud. Non è obbligatorio, ma rende più pratico il processo di creazione dell'istanza.

:::info
Le chiavi SSH archiviate vi permettono di creare le vostre istanze più velocemente nello Spazio Cliente. Per modificare le coppie di chiavi e aggiungere utenti dopo aver creato l'istanza, consultate la guida sulle [chiavi SSH aggiuntive](/guides/public-cloud/compute/configuring-additional-ssh-keys).

Le chiavi SSH pubbliche aggiunte al vostro Spazio Cliente OVHcloud saranno disponibili per i servizi Public Cloud di tutte le [Region](/links/public-cloud/regions-pci). Potete archiviare chiavi crittografate con **RSA**, **ECDSA** e **ED25519**.

:::

### Step 3: preparare la configurazione di rete

Prima di creare la vostra istanza, vi consigliamo di valutare come l'istanza verrà utilizzata in termini di rete.

- Se al momento non avete bisogno di configurare l'istanza con una rete privata, potete passare allo [step 4](#step-4-creare-listanza). Potete attivare la connettività pubblica durante la creazione dell'istanza (si veda **Connettività pubblica** [qui sotto](#networking-modes)).
- Se l'istanza deve essere connessa a una nuova rete privata (OVHcloud [vRack](/links/network/vrack)), tenete presente che la vRack viene creata automaticamente durante la creazione del vostro progetto Public Cloud. Non è quindi necessaria alcuna azione preliminare. Per maggiori informazioni, consultate la [guida sulla vRack Public Cloud](/guides/public-cloud/network-services/vrack).

<a name="networking-modes"></a>

<details>

<summary>Public Cloud Networking - Connettività pubblica</summary>

**Connettività pubblica**

Tutte le istanze vengono create in una rete privata. La connettività pubblica è un'opzione che attivate separatamente. Sono disponibili tre tipi di indirizzi IP pubblici:

- **Basic IP**: indirizzo IP pubblico legato direttamente all'istanza (collegamento diretto alla rete Ext-Net), esposto immediatamente via IPv4/IPv6.
- **Additional IP**: indirizzo IP pubblico indipendente dall'istanza, utilizzato in aggiunta a un Basic IP ([incluso il vostro IP tramite BYOIP](/links/network/byoip)), che può essere associato, dissociato o spostato verso un'altra risorsa (anche al di fuori di Public Cloud). Le istanze con un [Additional IP](/links/network/additional-ip) possono anche essere connesse a una [vRack](/links/network/vrack).
- **Floating IP**: indirizzo IP pubblico riutilizzabile, associato all'istanza tramite un [Gateway](/links/public-cloud/gateway) (o utilizzato con un [Load Balancer](/links/public-cloud/load-balancer)). Come l'Additional IP, può essere dissociato e riassociato in qualsiasi momento, ma è riservato all'uso Public Cloud/cloud-native e richiede un Gateway.

Per maggiori informazioni, consultate le nostre guide nella sezione "[Public Cloud Network Services](/guides/public-cloud/network-services/overview)". La [guida ai concetti](/guides/public-cloud/network-services/concepts) fornisce un'introduzione al Public Cloud Networking, e la [guida ai tipi di IP Public Cloud](/guides/public-cloud/network-services/additional-ip-vs-floating-ip) mette a confronto i tre tipi di indirizzi IP pubblici.

**Local Zones**

In una **Local Zone**, le istanze possono essere esposte a Internet direttamente via IPv4/IPv6. Solo le istanze di una stessa Local Zone possono essere connesse tramite reti private. Le Local Zones non sono compatibili con la [vRack](/links/network/vrack). Nelle Local Zones, DHCP fornisce automaticamente gli indirizzi IP alle vostre istanze.

Per saperne di più, consultate la [pagina web delle Local Zones](/links/public-cloud/local-zones).

</details>

### Step 4: creare l'istanza

<Tabs>
  <Tab label="Spazio Cliente OVHcloud">
    :::info
    Una chiave SSH pubblica è obbligatoria durante la creazione di un'istanza (ad eccezione delle istanze Windows). Consultate lo [step 1](#step-1-creare-un-set-di-chiavi-ssh) e lo [step 2](#step-2-importare-le-chiavi-ssh) se non disponete di chiavi pronte all'uso.

    :::

    Nella **Home page**, cliccate su <code className="action">Crea un'istanza</code>.

    **4.1 Nome**

    Inserite un nome completo per la vostra istanza.

    **4.2 Localizzazione**

    Selezionate una [localizzazione](/links/public-cloud/regions-pci) vicina ai vostri utenti. Se selezionate una **Local Zone**, si applicano limitazioni di rete (si veda lo [Step 3](#networking-modes)). Consultate la guida [Confronto delle modalità di deploy (EN)](/guides/public-cloud/cross-functional/deployment-modes-comparison-resilience-details) per le differenze tra 3-AZ, 1-AZ e Local Zones.

    **4.3 Modello**

    Aprite l'elenco a discesa `Modello di istanza` e selezionate il tipo adatto al vostro caso d'uso. Il modello (flavor) determina le risorse assegnate alla vostra istanza: processore, memoria e capacità associate.

    | Tipo | Risorse garantite | Note sull'utilizzo |
    | :--- | :---: | :--- |
    | Best Sellers | ✓ | Modelli più popolari. |
    | General Purpose | ✓ | Server di sviluppo, applicazioni web o aziendali. |
    | Compute Optimized | ✓ | Codifica video o altri calcoli ad alte prestazioni. |
    | Memory Optimized | ✓ | Database, analisi e calcoli in memoria. |
    | GPU | ✓ | Potenza di elaborazione massivamente parallela per applicazioni specializzate (rendering, big data, deep learning, ecc.). |
    | Discovery | - | Risorse condivise per gli ambienti di test e di sviluppo. |
    | Storage Optimized | ✓ | Ottimizzato per il trasferimento dei dati su disco. |
    | Metal Instances | ✓ | Risorse dedicate con accesso diretto alle risorse di calcolo, storage e rete. |

    :::info
    Le vostre risorse Public Cloud saranno inizialmente limitate. Verificate le vostre quote tramite <code className="action">Quota e Region</code> sotto **Impostazioni** nella barra di navigazione a sinistra. Consultate [la documentazione dedicata](/guides/public-cloud/cross-functional/increasing-public-cloud-quota) per maggiori informazioni.

    Potete **aggiornare** la vostra istanza dopo la creazione per disporre di più risorse. Il passaggio a un modello inferiore, invece, non è possibile con un'istanza standard. Consultate lo **step 4.9** per maggiori dettagli.

    :::

    **4.4 Immagine**

    Selezionate il sistema operativo tramite i menu `Tipo di distribuzione` e `Versione dell'immagine`. Le opzioni disponibili dipendono dal modello e dalla Region scelti.

    **4.5 Chiave SSH** *(non applicabile alle istanze Windows)*

    Selezionate una chiave SSH archiviata nella lista (si veda lo [Step 2](#step-2-importare-le-chiavi-ssh)), oppure cliccate su <code className="action">Crea una nuova chiave SSH</code> per inserire direttamente una chiave pubblica.

    **4.6 Backup**

    I [backup automatici](/guides/public-cloud/compute/save-an-instance) sono attivati per impostazione predefinita. Selezionate la rotazione desiderata (7 o 14 giorni).

    **4.7 Rete**

    La sezione **Impostazioni di rete** si divide in due parti:

    - **Rete privata**: selezionate una rete privata esistente o cliccate su <code className="action">Crea una rete privata</code>. Se la rete privata selezionata non dispone di un gateway, attivate l'interruttore <code className="action">Assegna un gateway</code> per associare automaticamente un gateway.
    - **Attribuire una connettività pubblica**: attivate l'interruttore per assegnare un IP pubblico. Scegliete <code className="action">Basic Public IP</code> (fatturato al secondo, legato alla durata di vita dell'istanza, incompatibile con un gateway) oppure <code className="action">Assegnare un Floating IP (riutilizzabile)</code> (persistente e riutilizzabile).

    Consultate lo [Step 3](#networking-modes) per una panoramica delle opzioni di connettività pubblica.

    **4.8 Fatturazione**

    Scegliete tra fatturazione **mensile** (costo ridotto, non reversibile) e **oraria** (flessibile, [convertibile in mensile](/guides/account-and-service-management/managing-billing-payments-and-services/changing-hourly-monthly-billing) in un secondo momento). La fatturazione oraria prosegue fino all'**eliminazione dell'istanza**. Consultate la [documentazione sulla fatturazione](/guides/public-cloud/cross-functional/analyze-billing).

    **4.9 Impostazioni avanzate** *(opzionale)*

    - **Istanza flessibile**: disco unico da 50 GB, permette il ridimensionamento verso modelli superiori o inferiori.
    - **Script di post-installazione**: aggiungete il vostro [script di post-installazione](/guides/public-cloud/compute/launching-script-when-creating-instance).

    **4.10 Finalizzazione**

    Verificate il riepilogo sul lato destro dello schermo e configurate il numero di istanze. Cliccate su <code className="action">Avvia l'istanza</code>. La consegna può richiedere qualche minuto.
  </Tab>
  <Tab label="API OVHcloud">
    Recuperate gli identificativi necessari:

    ```
    GET /cloud/project/{serviceName}/flavor     → flavorId
    GET /cloud/project/{serviceName}/image      → imageId
    GET /cloud/project/{serviceName}/region     → region
    GET /cloud/project/{serviceName}/sshkey     → sshKeyId
    ```

    Create l'istanza:

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/instance"} />

    Parametri principali:

    - `name`: nome dell'istanza
    - `flavorId`: ID del modello
    - `imageId`: ID dell'immagine OS
    - `region`: Region di deploy
    - `sshKeyId`: ID della chiave SSH (dallo [step 2](#step-2-importare-le-chiavi-ssh))
    - `monthlyBilling`: `true` per una fatturazione mensile

    Consultate la [documentazione API OVHcloud](/guides/manage-and-operate/api/first-steps) per configurare il vostro accesso all'API.
  </Tab>
  <Tab label="CLI OVHcloud">
    Recuperate gli identificativi necessari:

    ```bash
    ovhcloud cloud reference list-flavors --cloud-project <project_id>
    ovhcloud cloud reference list-images --cloud-project <project_id>
    ovhcloud cloud ssh-key list --cloud-project <project_id>
    ```

    Create l'istanza:

    ```bash
    ovhcloud cloud instance create GRA9 \
      --cloud-project <project_id> \
      --name my-instance \
      --boot-from.image <image_id> \
      --flavor <flavor_id> \
      --ssh-key.name my-key \
      --network.public \
      --wait
    ```

    Sostituite `GRA9` con la vostra Region. Per una creazione interattiva con selezione guidata:

    ```bash
    ovhcloud cloud instance create GRA9 \
      --cloud-project <project_id> \
      --editor \
      --image-selector \
      --flavor-selector
    ```

    Verificate lo stato dopo la creazione:

    ```bash
    ovhcloud cloud instance list --cloud-project <project_id>
    ```
  </Tab>
  <Tab label="Terraform">
    Esempio di configurazione completa:

      security_groups = ["default"]

        destination_type      = "local"
        boot_index            = 0
        delete_on_termination = true
      }

      network {
        name = "Ext-Net"
      }
    }
    ```

    Consultate la [guida Terraform per il Public Cloud OVHcloud](/guides/public-cloud/cross-functional/how-to-use-terraform) per la configurazione iniziale del provider e l'autenticazione.
  </Tab>
  <Tab label="CLI OpenStack">
    Recuperate le informazioni necessarie:

    openstack image list --property visibility=public
    openstack keypair list
    ```

    Create l'istanza:

    ```bash

    openstack server show my-instance
    ```

    Consultate la [guida sulla preparazione dell'ambiente OpenStack](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment) per la configurazione iniziale.
  </Tab>
</Tabs>

### Step 5: Connettersi all'istanza

Le istruzioni di questa sezione riguardano le connessioni remote tramite i protocolli **OpenSSH** e **RDP** attraverso una rete pubblica (Internet).

Vi ricordiamo che sono disponibili metodi di accesso alternativi (utilizzati principalmente per la risoluzione dei problemi), accessibili unicamente dallo Spazio Cliente OVHcloud:

- [Console VNC](#54-accesso-console-vnc)
- [Modalità rescue](/guides/public-cloud/compute/put-an-instance-in-rescue-mode)

:::info
Se avete installato un **OS con applicazione**, consultate la nostra [guida sui primi passi con le applicazioni](/guides/public-cloud/compute/apps-first-steps) e la documentazione ufficiale dell'editore dell'OS.

:::

#### 5.1: Verificare lo stato dell'istanza nello Spazio Cliente

Selezionate <code className="action">Istanze</code> nella barra di navigazione a sinistra sotto **Compute**. La vostra istanza è pronta quando lo stato è impostato su `Attivato` nella tabella. Se l'istanza è stata creata di recente e ha uno stato diverso, cliccate sul pulsante "Aggiorna" accanto al filtro di ricerca.

Cliccate sul nome dell'istanza in questa tabella per aprire il <code className="action">Dashboard</code>, dove potete trovare tutte le informazioni relative all'istanza. Per maggiori informazioni sulle funzioni disponibili in questa pagina, consultate la nostra guida sulla [gestione delle istanze nello Spazio Cliente](/guides/public-cloud/compute/first-steps-with-public-cloud-instance).

Un **utente con diritti elevati (*sudo*) viene creato automaticamente** sull'istanza. Il nome utente riflette l'immagine installata, ad esempio "ubuntu", "debian", "fedora", ecc. Potete verificarlo nel <code className="action">Dashboard</code> nella sezione **Reti**.

:::info
Tramite l'OVHcloud CLI, verificate lo stato e recuperate l'indirizzo IP della vostra istanza con:

```bash
ovhcloud cloud instance list --cloud-project <project_id>
```

:::

Se la vostra [coppia di chiavi SSH è configurata correttamente](#step-1-creare-un-set-di-chiavi-ssh), potete ora connettervi all'istanza con l'utente preconfigurato e la vostra chiave SSH. Troverete istruzioni più dettagliate nei paragrafi seguenti.

:::info
L'accesso tramite la **console VNC** su una nuova istanza OS GNU/Linux creata nello Spazio Cliente deve prima essere attivato come descritto nella [sezione della guida qui sotto](#54-accesso-console-vnc).

Questa guida non tratta la rete privata per le istanze. Consultate la nostra documentazione [Public Cloud Network Services](/guides/public-cloud/network-services/overview) a questo proposito.

:::

#### 5.2: Prima connessione su un'istanza con OS GNU/Linux

:::info
Se ricevete messaggi di errore relativi alle vostre **chiavi SSH**, verificate che il vostro dispositivo locale disponga di una chiave SSH privata configurata correttamente utilizzando le informazioni di [questa guida](/guides/public-cloud/compute/creating-ssh-keys#create-ssh-key).<br/>
Se riscontrate ancora difficoltà, potete sostituire la coppia di chiavi con l'aiuto di [questa guida](/guides/public-cloud/compute/replacing-lost-ssh-key-pair).

Se avete creato un'istanza senza chiave SSH, tramite l'[API OVHcloud](/guides/manage-and-operate/api/first-steps) o l'[interfaccia OpenStack Horizon](/guides/public-cloud/compute/create-instance-in-horizon), potete aggiungere una chiave SSH alla vostra istanza solo tramite la [modalità rescue](/guides/public-cloud/compute/put-an-instance-in-rescue-mode) seguendo le istruzioni descritte in [questa guida](/guides/public-cloud/compute/replacing-lost-ssh-key-pair).

:::

Potete accedere alla vostra istanza subito dopo la sua creazione tramite l'interfaccia da riga di comando del vostro computer locale (`Terminal`, `Command prompt`, `Powershell`, ecc.) via SSH.

```bash
ssh username@IPv4_instance
```

Esempio:

```bash
ssh ubuntu@203.0.113.101
```

[In base alla vostra configurazione](#step-1-creare-un-set-di-chiavi-ssh), dovrete inserire una passphrase che protegge la vostra chiave privata o specificare il percorso del file di chiave. Consultate la nostra [guida sulle chiavi SSH](/guides/public-cloud/compute/creating-ssh-keys#multiplekeys) per informazioni dettagliate su questo argomento.

Se utilizzate un altro client SSH, consultate la sua documentazione utente. Un esempio di utilizzo della soluzione open source `PuTTY` è disponibile in [questa guida](/guides/web-cloud/web-hosting/ssh-using-putty-on-windows).

Proseguite allo [step 6 qui sotto](#step-6-primi-passi-su-una-nuova-istanza).

### Step 6: Primi passi su una nuova istanza

:::info
**Istanze Windows**

Non sono necessari passaggi aggiuntivi per le istanze su cui è installato un sistema operativo Windows.

Per maggiori informazioni, consultate la sezione [Per saperne di più](#per-saperne-di-più) qui sotto.

:::

#### 6.1: Gestione degli utenti

:::info
Durante la configurazione degli account utente e dei livelli di autorizzazione su un'istanza, vi consigliamo di utilizzare le informazioni della nostra [guida sull'account utente](/guides/bare-metal-cloud/dedicated-servers/changing-root-password-linux-ds).

:::

##### 6.1.1: Definire una password per l'account utente attuale

Durante la [connessione alla vostra istanza](#step-6-primi-passi-su-una-nuova-istanza), definite una password per l'utente attuale inserendo questo comando:

```bash
sudo passwd
```

Inserite una passphrase, confermate con `Enter` e ripetete.

```console
New password:
Retype new password:
passwd: password updated successfully
```

**Questo è sufficiente per attivare gli accessi tramite la [console VNC](#54-accesso-console-vnc) nel vostro <ManagerLink to="/">Spazio Cliente OVHcloud</ManagerLink>**. Tuttavia, le connessioni SSH remote con questa password restano **disattivate** per impostazione predefinita.

##### 6.1.2: Attivazione della connessione remota tramite password (opzionale)

:::warning
Questo step non è necessario e deve essere eseguito solo se avete un motivo valido per attivare questo tipo di accesso, ad esempio se dovete connettervi temporaneamente all'istanza da un dispositivo sul quale non è archiviata la vostra chiave SSH privata.

L'esempio seguente illustra una soluzione temporanea su un'istanza su cui è installato Ubuntu. Tenete presente che potrebbe essere necessario adattare i comandi in base al vostro sistema operativo. Non è consigliabile mantenere questa configurazione in modo permanente poiché aggiunge un potenziale rischio di sicurezza esponendo il sistema ad attacchi basati su SSH.

:::

Una volta [connessi alla vostra istanza](#step-6-primi-passi-su-una-nuova-istanza), aprite il file di configurazione con un editor di testo. Esempio:

```bash
sudo nano /etc/ssh/sshd_config
```

Modificate la riga `#PasswordAuthentication yes` come segue:

```console
PasswordAuthentication yes
```

Modificate la riga `Include /etc/ssh/sshd_config.d/*.conf` come segue:

```console
#Include /etc/ssh/sshd_config.d/*.conf
```

Salvate il file e chiudete l'editor.

Riavviate il servizio SSH con uno dei comandi seguenti:

```bash
sudo systemctl restart ssh
```

```bash
sudo systemctl restart sshd
```

Ora potete connettervi in SSH con nome utente e password.

Annullate queste modifiche per ripristinare la connessione tramite chiave per l'istanza.

#### 6.2: Chiavi SSH aggiuntive

Se desiderate autorizzare più account utente ad accedere all'istanza, la procedura standard è la seguente:

- Creare l'account sull'istanza.
- Creare una nuova coppia di chiavi SSH sul dispositivo interessato.
- Aggiungere la chiave pubblica all'istanza.

Consultate la nostra [guida dedicata](/guides/public-cloud/compute/configuring-additional-ssh-keys) per una spiegazione dettagliata di questi passaggi.
