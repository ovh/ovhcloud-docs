## Obiettivo

In alcuni casi potrebbe essere necessario spostare la tua [istanza Public Cloud](https://www.ovhcloud.com/it/public-cloud/compute/) da una Region OpenStack a un’altra, sia perché preferisci migrare verso una nuova Region OpenStack disponibile, sia perché vuoi migrare da OVHcloud Labs verso Public Cloud.

**Questa guida ti mostra come migrare un backup di istanza da una Region OpenStack a un’altra, preservandone la configurazione e lo stato.**

## Prerequisiti

- Disporre della CLI OpenStack. Consulta la nostra guida [Come preparare l’ambiente per utilizzare l’API OpenStack](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment).
- Avere una connettività con le API OpenStack di OVHcloud.
- Prevedere spazio di storage sufficiente corrispondente alla dimensione del disco dell’istanza (per lo storage di backup temporaneo).

Questo ambiente verrà utilizzato come "jump host" per trasferire il backup da una Region all’altra. Può trattarsi di un’istanza ospitata in OVHcloud o della tua macchina locale.

Avrai inoltre bisogno di un’[istanza Public Cloud](https://www.ovhcloud.com/it/public-cloud/compute/) sul tuo account OVHcloud.

## Procedura

:::info
Se devi creare un backup con OpenStack, consulta la nostra guida "[Effettuare il backup di un’istanza](/guides/public-cloud/compute/save-an-instance)".
:::

### Fase 1 - Scaricare il backup

Elenca le tue immagini private per identificare il backup da trasferire:

```bash
openstack image list --private
```

Scarica il backup sul tuo storage locale:

```bash
openstack image save --file backup.qcow2 <image-id>
```

### Fase 2 - Passare alla Region di destinazione

Se trasferisci il backup verso un’altra Region all’interno dello stesso progetto, aggiorna `OS_REGION_NAME`:

```bash
export OS_REGION_NAME=<region-destinazione>
```

Se trasferisci il backup verso un altro progetto o account, carica il file RC corrispondente:

```bash
source openrc.sh
```

### Fase 3 - Importare il backup nella Region di destinazione

Il comando di importazione varia a seconda che la Region di destinazione sia una Region standard o una Local Zone.

#### Region standard

```bash
openstack image create \
  --disk-format qcow2 \
  --container-format bare \
  --file backup.qcow2 \
  <nome-immagine>
```

#### Local Zone

I nomi delle Region Local Zone contengono `-lz-` (ad esempio `eu-central-lz-prg-a`). Queste Region richiedono `--disk-format raw`. L’estensione del file di backup non influisce sull’importazione: è il parametro `--disk-format` a indicare a OpenStack come interpretare il file.

```bash
openstack image create \
  --disk-format raw \
  --container-format bare \
  --file backup.qcow2 \
  <nome-immagine>
```

:::warning
**Solo per le immagini Windows**: devi aggiungere le seguenti proprietà, altrimenti non sarà possibile associare un flavor di tipo `win-x-x` dallo Spazio Cliente OVHcloud. Questo tipo di flavor è necessario per l’autenticazione tramite il [KMS OVHcloud](/guides/manage-and-operate/kms/quick-start).

Aggiungi le proprietà al momento della creazione (Region standard):

```bash
openstack image create \
  --disk-format qcow2 \
  --container-format bare \
  --file backup.qcow2 \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <nome-immagine>
```

Aggiungi le proprietà al momento della creazione (Local Zone):

```bash
openstack image create \
  --disk-format raw \
  --container-format bare \
  --file backup.qcow2 \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <nome-immagine>
```

Oppure impostale su un’immagine già esistente:

```bash
openstack image set \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <image-uuid>
```
:::

:::info
Per ricreare la tua istanza a partire da questo backup, consulta la nostra guida "[Crea/ripristina il tuo server virtuale da un backup](/guides/public-cloud/compute/create-restore-a-virtual-server-with-a-backup)".
:::
