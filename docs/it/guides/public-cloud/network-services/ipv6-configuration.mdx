## Obiettivo

Internet Protocol version 6 (IPv6) è la versione più recente dell'Internet Protocol (IP). È stato progettato per risolvere l'esaurimento, previsto da tempo, degli indirizzi IPv4, utilizzando indirizzi a 128 bit anziché i tradizionali 32 bit dell'IPv4.

Ogni istanza Public Cloud viene consegnata con un indirizzo IPv4 e un indirizzo IPv6.

Sulle distribuzioni Linux recenti, l'indirizzo IPv6 è configurato di default. Non è così sulle istanze Windows.

**In questo tutorial vi mostreremo come configurare un indirizzo IPv6 su un'istanza Public Cloud.**

:::info
Al momento, le offerte Floating IP e Gateway non supportano l'IPv6. L'IPv6 è utilizzabile solo con le istanze che dispongono di un [Basic IP](/guides/public-cloud/network-services/concepts#publicmode). Nelle regioni 3-AZ, l'indirizzo IPv6 di un Basic IP non può ancora essere assegnato dallo Spazio Cliente OVHcloud.

:::

## Prerequisiti

- Disporre di un qualsiasi modello di istanza Public Cloud.
- Avere accesso amministrativo (sudo) via SSH o desktop remoto (Windows) al vostro server.
- Possedere conoscenze di base sulle reti.

## Procedura

Le sezioni seguenti contengono le configurazioni delle distribuzioni che proponiamo attualmente, oltre a quelle delle distribuzioni/dei sistemi operativi più comunemente utilizzati. Il primo passaggio consiste sempre nel connettervi al vostro server in SSH o tramite una sessione di connessione GUI (RDP per un'istanza Windows).

:::warning
Tenete presente che, sulle distribuzioni Linux recenti, l'indirizzo IPv6 è configurato di default sulle nostre istanze Public Cloud. Assicuratevi di controllare il file di configurazione del sistema operativo prima di apportare qualsiasi modifica.

### Lessico

Ecco un breve lessico dei termini utilizzati in questo tutorial:

|Lessico|Descrizione|
|---|---|
|YOUR_IPV6|L'indirizzo IPv6 assegnato al vostro servizio (esempio: 2607:5300:60:62ac:abcd)|
|IPV6_PREFIX|Il prefisso del vostro blocco IPv6 (esempio: 2607:5300:60:62ac::/128 -> netmask = 128)|
|IPV6_GATEWAY|Il gateway del vostro blocco IPv6 (esempio: 2607:5300:60:62ac::1)|

<Tabs>
  <Tab label="Debian (tranne Debian 12)">
    Di default, i file di configurazione si trovano nella directory `/etc/network/interfaces.d/`.
    
    La prassi migliore consiste nel creare un file di configurazione separato nella directory `/etc/network/interfaces.d/` per configurare l'IPv6. Nel nostro esempio, il file si chiama `51-cloud-init-ipv6`:
    
    ```bash
    sudo nano /etc/network/interfaces.d/51-cloud-init-ipv6
    ```
    
    In questo modo la configurazione IPv6 resta separata e potete annullare facilmente le modifiche in caso di errore.
    
    Aggiungete le righe seguenti al file. Sostituite gli elementi generici (ossia `YOUR_IPV6`, `IPV6_PREFIX` e `IPV6_GATEWAY`) e l'interfaccia di rete (se il vostro server non utilizza **eth0**) con i vostri valori specifici:
    
    ```console
    iface eth0 inet6 static
    address YOUR_IPV6
    netmask IPV6_PREFIX
    post-up /sbin/ip -6 route add IPV6_GATEWAY dev eth0
    post-up /sbin/ip -6 route add default via IPV6_GATEWAY dev eth0
    pre-down /sbin/ip -6 route del default via IPV6_GATEWAY dev eth0
    pre-down /sbin/ip -6 route del IPV6_GATEWAY dev eth0
    ```
    
    <details>
    <summary>Esempio di configurazione</summary>

    ```console
    iface eth0 inet6 static
    address 2607:5300:201:abcd::7c5
    netmask 128
    post-up /sbin/ip -6 route add 2607:5300:201:abcd::1 dev eth0
    post-up /sbin/ip -6 route add default via 2607:5300:201:abcd::1 dev eth0
    pre-down /sbin/ip -6 route del default via 2607:5300:201:abcd::1 dev eth0
    pre-down /sbin/ip -6 route del 2607:5300:201:abcd::1 dev eth0
    ```

    </details>
    
    Riavviate quindi il servizio di rete con uno dei comandi seguenti:
    
    ```bash
    sudo service networking restart
    ```
    
    ```bash
    sudo systemctl restart networking
    ```

    I file di configurazione di rete si trovano nella directory `/etc/netplan/`.
    
    La prassi migliore consiste nel creare un file di configurazione separato nella directory `/etc/netplan/` per configurare l'IPv6. Nel nostro esempio, il file si chiama `51-cloud-init-ipv6.yaml`:
    
    ```bash
    sudo nano /etc/netplan/51-cloud-init-ipv6.yaml
    ```
    
    In questo modo la configurazione IPv6 resta separata e potete annullare facilmente le modifiche in caso di errore.
    
    Aggiungete le righe seguenti al file. Sostituite gli elementi generici (ossia `YOUR_IPV6`, `IPV6_PREFIX` e `IPV6_GATEWAY`) e l'interfaccia di rete (se il vostro server non utilizza **eth0**) con i vostri valori specifici:
    
    ```yaml
    network:
        version: 2
        ethernets:
            eth0:
                dhcp6: no
                match:
                  name: eth0
                addresses:
                  - YOUR_IPV6/IPv6_PREFIX
                routes:
                  - to: ::/0
                    via: IPv6_GATEWAY
    ```

    :::

  <Tab label="Red Hat / CloudLinux / Rocky Linux (8 & 9) / AlmaLinux (8 & 9)">
    I file di configurazione di rete si trovano nella directory `/etc/sysconfig/network-scripts/`. Vi consigliamo di iniziare effettuando un backup del file di configurazione interessato.
    
    Nel nostro esempio, il file si chiama `ifcfg-eth0`, quindi effettuiamo un backup del file `ifcfg-eth0` con i comandi seguenti. Non dimenticate di sostituire **eth0** con la vostra interfaccia effettiva, se necessario.
    
    ```bash
    cd /etc/sysconfig/network-scripts/
    sudo mkdir backup
    sudo cp ifcfg-eth0 backup/ifcfg-eth0
    ```
    
    Potete quindi annullare le modifiche utilizzando i comandi seguenti:
    
    ```bash
    sudo rm -f /etc/sysconfig/network-scripts/ifcfg-eth0
    sudo cp /etc/sysconfig/network-scripts/backup/ifcfg-eth0 /etc/sysconfig/network-scripts/ifcfg-eth0
    ```
    
    Modifichiamo poi il file `ifcfg-eth0`, aggiungendo solo le righe per la configurazione IPv6 del server. Sostituite gli elementi generici (ossia `YOUR_IPV6`, `IPV6_PREFIX` e `IPV6_GATEWAY`) con i vostri valori specifici.
    
    ```console
    IPV6INIT=yes
    IPV6ADDR=YOUR_IPV6/IPV6_PREFIX
    IPV6_DEFAULTGW=IPV6_GATEWAY
    ```
    
    Abbiamo omesso la configurazione IPv4 per evitare confusione, ma la configurazione IPv6 si effettua nello stesso file di configurazione.

    ```console
    IPV6INIT=yes
    IPV6ADDR=2607:5300:201:abcd::7c5/128
    IPV6_DEFAULTGW=2607:5300:201:abcd::1
    ```

    </details>
    
    Riavviate l'interfaccia di rete con uno dei comandi seguenti:
    
    ```bash
    sudo service networking restart
    ```
    
    ```bash
    sudo systemctl restart networking
    ```

### Diagnostica

Avete configurato il vostro IPv6 ma non funziona nulla?

Per stabilire se il problema dipende dalla vostra configurazione o dalla rete di OVHcloud, effettuate questo semplice test.

Innanzitutto, [riavviate la vostra istanza in modalità di ripristino rescue-pro](/guides/public-cloud/compute/put-an-instance-in-rescue-mode).

Utilizzate quindi i comandi seguenti per configurare il vostro IPv6 in modo non persistente, sostituendo `YOUR_IPV6`, `IPV6_PREFIX` e `IPV6_GATEWAY` con le vostre informazioni:

```bash
ip addr add YOUR_IPV6/IPV6_PREFIX dev eth0
ip -6 route add IPV6_GATEWAY dev eth0
ip -6 route add default via IPV6_GATEWAY dev eth0
```

Testate di nuovo la vostra rete, ad esempio tramite un ping6:

```bash
ping6 ipv6.google.com
```

Se la vostra istanza risponde, è probabile che uno dei passaggi della configurazione iniziale non sia stato seguito scrupolosamente.

In ogni caso, non esitate a inviare una [richiesta di assistenza](/links/support-contact) con gli elementi testati sopra per ottenere un'analisi da parte nostra.
