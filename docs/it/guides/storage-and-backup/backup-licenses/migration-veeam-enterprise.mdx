## Obiettivo

Il prodotto **Backup Licenses** sostituisce l'offerta **Veeam Enterprise**. Si basa sulla **Veeam Service Provider Console** (VSPC) di OVHcloud: invece di attivare una licenza dallo Spazio Cliente OVHcloud, il vostro server **Veeam Backup & Replication** (VBR) viene collegato alla nostra console, che gli assegna e rinnova automaticamente la sua licenza.

**Questa guida spiega cosa cambia tra Veeam Enterprise e Backup Licenses, cosa OVHcloud può o non può fare sul vostro server VBR e come effettuare la migrazione.**

## Prerequisiti

- Disporre di una licenza **Veeam Enterprise** attiva presso OVHcloud.
- Disporre di un server **Veeam Backup & Replication** installato e operativo e conoscere il suo **indirizzo IP pubblico**.
- Collegarvi alla console VBR con un account che dispone dei diritti di **Amministratore locale** o del ruolo **Veeam Backup Administrator**.
- Aver preso visione delle "[Restrizioni note](/guides/storage-and-backup/backup-licenses/restrictions)": la vostra versione di VBR e il vostro sistema operativo determinano le edizioni disponibili.

## Cosa cambia

| | Veeam Enterprise | Backup Licenses |
|---|---|---|
| **Attivazione della licenza** | Attivazione manuale della licenza dallo Spazio Cliente OVHcloud, sul servizio `backupserverenterprise`. | Assegnazione automatica della licenza dopo la connessione del vostro VBR alla VSPC di OVHcloud. |
| **Edizioni disponibili** | Enterprise Plus. | Veeam Enterprise Plus, VDP Foundation, VDP Advanced, VDP Premium. |
| **Sistemi operativi** | Windows. | Windows e Linux (Veeam Software Appliance) per le edizioni VDP. |
| **Monitoraggio** | Dalla vostra console VBR. | Dalla vostra console VBR e dal portale VSPC (account Company Owner). |
| **Storage** | A vostro carico. | Un Vault "bundle" da 500 GB è fornito con la prima licenza. Consultate "[Funzionamento dei Vault](/guides/storage-and-backup/backup-licenses/vault)". |

## Ambito di intervento di OVHcloud sul vostro VBR

Quando collegate il vostro server VBR alla VSPC di OVHcloud, è importante comprendere cosa OVHcloud è autorizzato a fare sulla vostra infrastruttura Veeam e cosa resta fuori dal suo ambito.

**Cosa OVHcloud può fare, tramite la VSPC:**

- Raccogliere **metadati** sui vostri job di backup (stato, configurazione), senza accedere al contenuto dei backup.
- Monitorare il **consumo di licenze** per carico protetto.
- **Assegnare e gestire** le licenze associate al vostro contratto.
- **Riavviare il servizio** dell'agente di gestione.

**Cosa OVHcloud non può fare:**

- Accedere ai **file di backup o ai dati** di cui è stato effettuato il backup.
- Accedere al **file system** del vostro server in generale.
- Connettersi in **RDP / desktop remoto** sul vostro server.
- Accedere alle **altre applicazioni** del server, all'**Active Directory** o modificare la **configurazione Windows**.
- **Avviare o arrestare** un job di backup, né **modificare i parametri** dei job VBR.
- **Intercettare il traffico di rete** o esfiltrare i vostri dati di produzione.

## Sicurezza: l'agente di gestione Veeam

Quando selezionate l'opzione che consente a OVHcloud di gestire la vostra installazione VBR, un **Veeam Management Agent** (agente di gestione) viene installato sul server su cui è in esecuzione Veeam Backup & Replication. Questo agente stabilisce il collegamento sicuro tra il vostro VBR e la piattaforma OVHcloud.

- **Comunicazione solo in uscita**: la connessione è sempre avviata dall'agente verso la piattaforma OVHcloud.
- **Porta TCP 6180** e **crittografia TLS 1.2** end-to-end per i dati in transito.
- **Autenticazione reciproca** tramite certificati digitali, con verifica delle liste di revoca (CRL) se necessario.
- L'agente viene eseguito con l'account **Local System** su Windows, **senza account di dominio** né accesso ad Active Directory richiesti per il suo funzionamento di base.
- **Mantenete il controllo**: potete interrompere la comunicazione (firewall sulla porta 6180, arresto del servizio Windows), disinstallare l'agente come qualsiasi programma Windows e verificare il traffico in uscita con i vostri strumenti di sicurezza di rete.

## Architettura di rete e flussi di dati

**Lato cliente, la vostra infrastruttura:**

- Il **server VBR** avvia i flussi verso OVHcloud.
- Il **firewall** deve autorizzare il **TCP 6180 in uscita** verso il cloud gateway OVHcloud e autorizzare la nostra infrastruttura a raggiungere il vostro server dall'indirizzo IP `79.137.44.43` in Europa.
- I dati scambiati riguardano in particolare: **stato dei job**, **numero di carichi**, **consumo di licenze**, **versione del VBR** — e **non i file di backup** stessi.

**Lato OVHcloud:**

- La **Cloud Gateway** è il punto di ingresso sicuro.
- La **VSPC** assicura la gestione delle licenze e la supervisione.
- Il vostro ambiente è **isolato** dagli altri clienti (tenant isolation).

## Procedura

Ecco le fasi della migrazione:

- Ordinare la vostra licenza Backup Licenses.
- Aprire i flussi di rete necessari.
- Collegare il vostro server VBR alla VSPC di OVHcloud.
- Verificare che la nuova licenza sia applicata.
- Disdire la vostra vecchia licenza Veeam Enterprise.

### Fase 1: Ordinare la vostra licenza Backup Licenses

Dal vostro Spazio Cliente OVHcloud, ordinate una licenza Backup Licenses selezionando l'edizione desiderata, poi indicate un **nome per il vostro VBR** e il suo **indirizzo IP pubblico**.

Il dettaglio delle edizioni disponibili è descritto nella guida "[Ordinare e configurare la vostra prima licenza](/guides/storage-and-backup/backup-licenses/first-configuration)".

Una volta convalidato l'ordine, ricevete un'**e-mail di consegna** contenente l'URL del cloud gateway (`vspc-adv-cgw…`), la porta `6180`, così come i vostri account **Company Tenant** e **Company Owner**.

:::warning
Non disdite la vostra licenza Veeam Enterprise prima di aver verificato che la nuova licenza sia correttamente applicata sul vostro server VBR (fase 4).

:::

### Fase 2: Aprire i flussi di rete

Assicuratevi che il firewall del server — e quello della vostra rete — autorizzi:

- **In uscita**: dal vostro server VBR verso il cloud gateway OVHcloud comunicato nell'e-mail di consegna (`vspc-adv-cgw…`), sulla **porta 6180**.
- **In entrata**: dall'indirizzo IP della nostra infrastruttura verso il vostro server VBR, **senza restrizioni**. In Europa, questo indirizzo è `79.137.44.43`.

### Fase 3: Collegare il vostro server VBR alla VSPC

Le fasi seguenti si svolgono **dalla console Veeam Backup & Replication**, e non dal portale VSPC.

#### 3.1 Aprire la console Veeam Backup & Replication

Collegatevi al server su cui è installato Veeam Backup & Replication (o a una macchina su cui è distribuita la console VBR), poi avviate la console:

- Su un'installazione **Windows**: collegatevi a `localhost`.
- Su una **Veeam Software Appliance**: indicate l'indirizzo del server VBR e le credenziali di un account che dispone del ruolo Veeam Backup Administrator.

:::info
Se il vostro VBR funziona su una Veeam Software Appliance (Linux), la raccolta di dati da remoto deve essere attivata nella **Veeam Host Management Console**.

:::

#### 3.2 Avviare l'aggiunta del fornitore di servizi

Nella barra dei menu (ribbon) in alto nella console, cliccate su <code className="action">Add Service Provider</code>.

Potete anche procedere tramite il pannello di navigazione:

1. Aprite la vista <code className="action">Backup Infrastructure</code>.
2. Individuate il nodo <code className="action">Service Providers</code>.
3. Fate clic con il tasto destro su <code className="action">Service Providers</code> poi cliccate su <code className="action">Add Service Provider</code>.

<img className="thumbnail" alt="Aggiunta di un service provider dalla console VBR" src="/images/storage-and-backup/backup-licenses/vbr/bl_vbr_add_service_provider.png" loading="lazy" />

#### 3.3 Indicare i parametri del fornitore

Alla fase <code className="action">Service Provider</code> della procedura guidata:

1. **DNS name or IP address**: inserite l'URL del cloud gateway OVHcloud ricevuto nell'e-mail di consegna (`vspc-adv-cgw…`).
2. **Port**: inserite la porta comunicata da OVHcloud, `6180`.
3. **Description**: facoltativo, una descrizione per identificare questo fornitore.
4. Selezionate la casella <code className="action">Allow this Veeam Backup & Replication installation to be managed by the service provider</code>.

:::danger
La casella <code className="action">Allow this Veeam Backup & Replication installation to be managed by the service provider</code> è **indispensabile**. Senza di essa, l'agente di gestione non viene installato, il vostro server non appare nella VSPC e la licenza non può essergli assegnata.

:::

<img className="thumbnail" alt="Fase Service Provider della procedura guidata, con la casella di gestione selezionata" src="/images/storage-and-backup/backup-licenses/vbr/bl_wizard_1.png" loading="lazy" />

#### 3.4 Inserire le credenziali

Alla fase <code className="action">Credentials</code>, indicate le credenziali dell'account **Company Tenant** ricevute nell'e-mail di consegna, poi cliccate su <code className="action">Apply</code>.

<img className="thumbnail" alt="Fase Credentials della procedura guidata" src="/images/storage-and-backup/backup-licenses/vbr/bl_wizard_2.png" loading="lazy" />

#### 3.5 Completare la procedura guidata

La procedura guidata registra il service provider e attiva la gestione remota. Cliccate su <code className="action">Next</code>, verificate il riepilogo, poi cliccate su <code className="action">Finish</code> nell'ultima fase.

<img className="thumbnail" alt="Riepilogo della procedura guidata con il pulsante Finish" src="/images/storage-and-backup/backup-licenses/vbr/bl_wizard_4.png" loading="lazy" />

L'agente di gestione viene installato sul vostro server VBR e la connessione verso la VSPC è stabilita.

:::warning
Su un server VBR con **Windows**, la registrazione del server richiede **almeno 15 minuti** dopo la fine della procedura guidata. Durante questo intervallo è normale che il vostro server non sia ancora visibile nella VSPC e che la nuova licenza non sia ancora applicata. Attendete la fine di questo intervallo prima di avviare una diagnosi e prima di risolvere il contratto della vostra licenza Veeam Enterprise.

:::

### Fase 4: Verificare la nuova licenza

Nella console Veeam Backup & Replication, aprite il menu principale e cliccate su <code className="action">License</code>. Nella finestra <code className="action">License Information</code>, verificate i seguenti elementi:

| Campo | Valore atteso |
|---|---|
| **Status** | `Valid` (e non `Expired`, `Invalid` o `Not Installed`) |
| **Type** | Il tipo di licenza: `Rental` |
| **Package** | L'edizione ordinata, per esempio `Foundation` o `Enterprise Plus` |
| **Licensed to** | L'organizzazione associata alla licenza: `OVH` |
| **Points** | Il numero di punti utilizzabili, coerente con il vostro ordine |
| **Expiration date** | La data di scadenza della licenza |

<img className="thumbnail" alt="Finestra License Information della console VBR" src="/images/storage-and-backup/backup-licenses/vbr/bl_license.png" loading="lazy" />

Potete anche connettervi al portale VSPC con l'account **Company Owner** e verificare, nella sezione <code className="action">Managed Computers</code> > <code className="action">Backup Servers</code>, che il vostro server appaia con lo stato `Healthy`.

<img className="thumbnail" alt="Lista dei server di backup nella VSPC" src="/images/storage-and-backup/backup-licenses/vspc/bl_vspc_backup_server.png" loading="lazy" />

### Fase 5: Disdire la vostra licenza Veeam Enterprise

Una volta verificato che la nuova licenza risulta `Valid` sul vostro server VBR, potete risolvere il contratto della vostra vecchia licenza **Veeam Enterprise** dal vostro Spazio Cliente OVHcloud.

Lato Backup Licenses, la risoluzione si effettua dalla scheda <code className="action">Informazioni generali</code>, tramite il link <code className="action">Risolvi la licenza</code>. In questa scheda si trova anche il link <code className="action">Accedi alla VSPC</code>.

<img className="thumbnail" alt="Scheda Informazioni generali del prodotto Backup Licenses" src="/images/storage-and-backup/backup-licenses/control-panel/bl_information_en.png" loading="lazy" />

:::warning
Effettuate questa operazione solo dopo aver confermato che la licenza Backup Licenses è attiva sul vostro VBR. Finché le due licenze coesistono, viene utilizzata solo quella attualmente installata sul VBR.

:::

## Note importanti

- **Non collegate due volte lo stesso server VBR** alla VSPC con credenziali diverse: ciò falserebbe la visualizzazione dei dati.
- Se la **MFA** è attivata sul server VBR, quest'ultimo può apparire come `Inaccessible` nella VSPC. Consultate l'articolo [Veeam KB 4431](https://www.veeam.com/kb4431).
- **Firewall**: assicuratevi che la porta `6180` sia aperta in uscita dal server VBR verso il cloud gateway.
- **Cluster HA**: se il vostro VBR è il nodo primario di un cluster ad alta disponibilità, il nodo secondario deve essere collegato separatamente.
