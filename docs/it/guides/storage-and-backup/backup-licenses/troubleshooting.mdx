## Obiettivo

**Questa pagina elenca i problemi che potete riscontrare sul prodotto Backup Licenses e spiega come risolverli.**

## Prerequisiti

- Aver ordinato una licenza Backup Licenses e ricevuto l'e-mail di consegna. Consultate la nostra guida "[Ordinare e configurare la vostra prima licenza](/guides/storage-and-backup/backup-licenses/first-configuration)" per maggiori informazioni.
- Disporre di un server Veeam Backup & Replication installato e operativo.

[[cpnav:privatecloud-backup-licenses+storage-backup-licenses]]

## Elenco dei possibili problemi

Backup Licenses è disponibile in due universi del vostro Spazio Cliente, Hosted Private Cloud e Bare Metal Cloud, con la stessa interfaccia. Le istruzioni di questa guida valgono per entrambi.

<details>

<summary>Il mio server VBR non appare ancora nella VSPC subito dopo la procedura guidata.</summary>

Su un server VBR con **Windows**, la registrazione del server richiede **almeno 15 minuti** dopo la fine della procedura guidata <code className="action">Add Service Provider</code>. Finché questo intervallo non è trascorso, è normale che il vostro server non sia visibile nella VSPC e che la licenza non sia ancora applicata.

Attendete la fine di questo intervallo prima di procedere con i punti seguenti.

</details>

<details>

<summary>Non riesco a connettere il mio server VBR alla vostra console (VSPC).</summary>

Questo caso corrisponde al fallimento dell'assistente <code className="action">Add Service Provider</code> dalla vostra console Veeam Backup & Replication: la connessione verso la nostra infrastruttura non va a buon fine.

Verificate che **il vostro firewall autorizzi la connessione in uscita dal vostro server VBR verso il nostro server**, ossia verso l'indirizzo DNS del cloud gateway comunicato nella vostra e-mail di consegna (nella forma `vspc-adv-cgw…`), sulla **porta 6180**.

Verificate inoltre che:

- l'indirizzo DNS e la porta inseriti nell'assistente corrispondano esattamente a quelli dell'e-mail di consegna;
- le credenziali **Company Tenant** inserite siano quelle dell'e-mail di consegna;
- il vostro server VBR sia effettivamente in **versione 12 minimo** (consultate le [restrizioni note](/guides/storage-and-backup/backup-licenses/restrictions)).

</details>

<details>

<summary>Il mio server VBR non è ancora connesso dopo la connessione della vostra console (VSPC) al mio VBR.</summary>

Questo caso corrisponde a un assistente completato senza errori, ma a un server che non compare — o compare come non raggiungibile — nella VSPC. La connessione in uscita funziona, è il ritorno verso il vostro server che è bloccato oppure l'agente di gestione che non è stato distribuito.

Verificate i due punti seguenti:

- **Il vostro firewall autorizza la connessione al vostro server dal nostro indirizzo IP, sulle porte necessarie.** In Europa, la nostra infrastruttura raggiunge il vostro server VBR dall'indirizzo `79.137.44.43`. In Canada, l'indirizzo è `142.44.140.20`. Le porte da aprire dipendono dal sistema operativo del server:
    - verso un server **Windows** (Veeam Backup & Replication, Veeam Backup Enterprise Manager, Veeam ONE, Veeam Backup for Microsoft 365, Veeam Cloud Connect): **TCP 135, 443, 445 e 49152-65535**.
    - verso un server **Linux** (Veeam Backup & Replication o Veeam Backup Enterprise Manager): **TCP 443**.
- **Avete effettivamente selezionato l'opzione** <code className="action">Allow this Veeam Backup & Replication installation to be managed by the service provider</code> durante l'aggiunta del provider di servizi. Senza questa opzione, l'agente di gestione non viene installato e il vostro server non può essere gestito dalla VSPC.

Se l'opzione non era stata selezionata, modificate il provider di servizi dalla vostra console VBR (<code className="action">Backup Infrastructure</code> > <code className="action">Service Providers</code> > clic destro > <code className="action">Edit provider</code>), selezionate l'opzione, quindi riavviate l'assistente fino al suo completamento.

<img className="thumbnail" alt="Fase Service Provider della procedura guidata, con la casella di gestione selezionata" src="/images/storage-and-backup/backup-licenses/vbr/bl_wizard_1.png" loading="lazy" />

Per individuare l'origine del blocco, connettetevi al portale VSPC e aprite la sezione <code className="action">Managed Computers</code>, scheda <code className="action">Discovered Computers</code>. Le colonne <code className="action">Connection Status</code>, <code className="action">Deployment Status</code> e <code className="action">Management Agent Status</code> indicano a che punto è l'installazione dell'agente di gestione sul vostro server.

<img className="thumbnail" alt="Scheda Discovered Computers della VSPC" src="/images/storage-and-backup/backup-licenses/vspc/bl_vspc_discovered_computer.png" loading="lazy" />

</details>

<details>

<summary>Il mio server VBR appare come "Inaccessible" nella VSPC.</summary>

Se la **MFA** (autenticazione a due fattori) è attivata sul server VBR connesso, questo può apparire con lo stato `Inaccessible` nella VSPC.

Consultate l'articolo [Veeam KB 4431](https://www.veeam.com/kb4431) per la procedura di risoluzione.

</details>

<details>

<summary>La licenza non appare, non è valida oppure non viene prolungata sul mio server VBR.</summary>

Nella console Veeam Backup & Replication, aprite il menu principale quindi cliccate su <code className="action">License</code> per visualizzare la finestra <code className="action">License Information</code>.

- **Verificate che la casella** <code className="action">Update license automatically (enables usage reporting)</code> **sia selezionata**, in fondo alla finestra. In caso contrario, selezionatela. Questa casella è indispensabile: senza di essa, la VSPC non può né applicare la licenza al vostro server VBR né prolungarla automaticamente prima della sua scadenza.
- Se lo stato non è `Valid`, verificate che il vostro server VBR sia correttamente connesso alla VSPC (consultate i primi punti di questa pagina).
- Verificate che l'edizione visualizzata corrisponda effettivamente a quella che avete ordinato e che il vostro sistema operativo sia compatibile con questa edizione (consultate le [restrizioni note](/guides/storage-and-backup/backup-licenses/restrictions)).
- Se una finestra popup indica che la licenza è gestita dal Veeam Backup Enterprise Manager, consultate il punto successivo.

<img className="thumbnail" alt="Casella Update license automatically selezionata nella finestra License Information" src="/images/storage-and-backup/backup-licenses/vbr/bl_license_auto_update.png" loading="lazy" />

Se il problema persiste nonostante la connessione sia stabilita, [contattate l'assistenza OVHcloud](/links/support-contact) fornendo delle schermate della finestra <code className="action">License Information</code>.

</details>

<details>

<summary>Una finestra popup indica "The license of this backup server is managed by the Veeam Backup Enterprise Manager".</summary>

Questo messaggio significa che il vostro server VBR è ancora associato al **Veeam Backup Enterprise Manager** utilizzato dalla vecchia offerta **Veeam Enterprise** di OVHcloud. Finché è così, la VSPC non può applicare la vostra licenza Backup Licenses.

1. **Disdite il vostro servizio Veeam Enterprise** (`backupserverenterprise`) dal vostro Spazio Cliente OVHcloud, se non l'avete già fatto. Questa disdetta è obbligatoria prima di connettere il vostro server VBR alla VSPC. Se necessario, consultate la nostra guida "[Come disattivare i servizi OVHcloud](/guides/account-and-service-management/managing-billing-payments-and-services/how-to-cancel-services)".
2. **Attendete 24 ore** dopo la vostra richiesta di disdetta: è il tempo necessario affinché il vostro server VBR venga dissociato dall'Enterprise Manager. Il messaggio dovrebbe quindi scomparire.
3. **Se il messaggio è ancora visualizzato dopo 24 ore**, si tratta molto probabilmente di un bug noto di Veeam: nella configurazione del vostro server VBR rimane un riferimento all'Enterprise Manager. Applicate la procedura descritta nell'articolo Veeam "[Removing references to a Veeam Backup Enterprise Manager server](https://community.veeam.com/blogs-and-podcasts-57/removing-references-to-a-veeam-backup-enterprise-manager-server-8877)".

:::warning
- Disdite solo il **vecchio servizio Veeam Enterprise**. Non disdite la vostra licenza Backup Licenses, anche se si tratta dell'edizione **Veeam Enterprise Plus**.
- La procedura Veeam modifica direttamente il database di configurazione del vostro server VBR. Effettuate un backup di questo database (e, idealmente, uno snapshot del server) prima di applicarla, come indicato nell'articolo Veeam.

:::

La procedura completa di migrazione è descritta nella guida "[Migrare da Veeam Enterprise a Backup Licenses](/guides/storage-and-backup/backup-licenses/migration-veeam-enterprise)".

</details>

<details>

<summary>L'indirizzo IP pubblico del mio server VBR è cambiato.</summary>

L'indirizzo IP indicato al momento dell'ordine serve ad autorizzare gli scambi tra la nostra infrastruttura e il vostro server. Se cambia, aggiornatelo dal vostro Spazio Cliente: scheda <code className="action">Server collegati</code>, menu <code className="action">...</code> a destra del server, poi <code className="action">Modificare</code>.

<img className="thumbnail" alt="Menu delle azioni di un server collegato con l'opzione Modificare" src="/images/storage-and-backup/backup-licenses/control-panel/bl_server_edit_en.png" loading="lazy" />

</details>

<details>

<summary>Ho connesso due volte lo stesso server VBR e i dati visualizzati sono incoerenti.</summary>

Non connettete un server VBR già connesso alla VSPC con altre credenziali: questo altera la visualizzazione dei dati nella VSPC.

Eliminate il provider di servizi duplicato dalla vostra console VBR (<code className="action">Backup Infrastructure</code> > <code className="action">Service Providers</code> > clic destro > <code className="action">Remove provider</code>), quindi conservate solo la connessione corrispondente alle vostre credenziali in corso di validità.

</details>

<details>

<summary>Il mio VBR fa parte di un cluster ad alta disponibilità e appare un solo nodo.</summary>

Se il vostro VBR è il nodo **primario** di un cluster ad alta disponibilità, la VSPC lo registra come nodo del cluster. Il nodo **secondario** deve essere connesso separatamente, seguendo la stessa procedura di aggiunta del provider di servizi.

</details>
