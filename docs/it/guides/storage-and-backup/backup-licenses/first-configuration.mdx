## Obiettivo

Il prodotto **Backup Licenses** ti permette di noleggiare licenze Veeam presso OVHcloud per il tuo server **Veeam Backup & Replication** (VBR), sia che si trovi in hosting presso OVHcloud sia nella tua infrastruttura. La licenza viene applicata automaticamente al tuo VBR una volta che quest'ultimo è connesso alla **Veeam Service Provider Console** (VSPC) di OVHcloud.

**Questa guida spiega come ordinare la tua prima licenza Backup Licenses e connettere il tuo server VBR alla VSPC di OVHcloud.**

## Prerequisiti

- Disporre di un account OVHcloud ed essere connesso al tuo Spazio Cliente OVHcloud.
- Disporre di un server **Veeam Backup & Replication** installato e operativo e conoscere il suo **indirizzo IP pubblico**.
- Connetterti alla console VBR con un account che dispone dei diritti di **Amministratore locale** o del ruolo **Veeam Backup Administrator**.

:::info
Consulta la guida "[Restrizioni note](/guides/storage-and-backup/backup-licenses/restrictions)" prima di ordinare: la versione del tuo VBR e il tuo sistema operativo determinano le edizioni di licenza disponibili.

:::

## Procedura

Ecco le fasi per configurare la tua prima licenza:

- Scegliere l'edizione di licenza adatta alle tue esigenze.
- Ordinare la licenza dal tuo Spazio Cliente OVHcloud indicando il nome e l'indirizzo IP del tuo VBR.
- Attendere l'e-mail di consegna contenente le tue informazioni di connessione.
- Aprire i flussi di rete necessari sul tuo firewall.
- Connettere il tuo server VBR alla VSPC di OVHcloud.
- Verificare che la licenza sia correttamente applicata.

### Fase 1: Scegliere l'edizione di licenza

Backup Licenses propone quattro edizioni. La tariffa è espressa **per server, VM, database o blocco di 500 GB di storage** protetti, e le tariffe aggiornate vengono visualizzate al momento dell'ordine nel tuo Spazio Cliente.

| Edizione | Compatibilità | Consigliata per | Funzionalità incluse |
|---|---|---|---|
| **Veeam Enterprise Plus** | VBR V12 e V13, solo su **Windows** | Gli ambienti esistenti su Windows che non necessitano delle funzioni avanzate della Veeam Data Platform. | Backup e ripristino · Vault da 500 Gio interamente gestito da OVHcloud · Base di sicurezza |
| **Veeam Data Platform (VDP) Foundation** | VBR V13, su **Windows o Linux** | Le microimprese/PMI con un parco limitato (da 5 a 30 workload) ed esigenze di backup/ripristino semplici. | Backup e ripristino · Vault da 500 Gio interamente gestito da OVHcloud · Sicurezza e controllo delle autorizzazioni |
| **Veeam Data Platform (VDP) Advanced** | VBR V13, su **Windows o Linux** | Le microimprese/PMI con un parco importante (da 30 a 150 workload), con esigenze di monitoraggio dettagliato e di avvisi proattivi. | Tutto Foundation · Cyber Sicurezza, osservabilità e IA |
| **Veeam Data Platform (VDP) Premium** | VBR V13, su **Windows o Linux** | Le medie e grandi imprese, il settore pubblico e gli ambienti regolamentati con un parco esteso (da 150 a 2000+ workload). | Tutto Advanced · Orchestrazione di DR e conformità |

:::info
Per il dettaglio esaustivo delle funzionalità di ciascuna edizione, consulta il [confronto ufficiale delle edizioni Veeam Data Platform](https://www.veeam.com/fr/products/veeam-data-platform/enterprise-packaging-pricing-options.html?ad=packaging-feature_comparison#comparison).

:::

:::warning
Se il tuo server VBR funziona su una **Veeam Software Appliance** (Linux), sono disponibili solo le edizioni **VDP**. L'edizione Veeam Enterprise Plus è proposta solo su Windows.

:::

### Fase 2: Ordinare la licenza

Dal tuo Spazio Cliente OVHcloud, accedi al prodotto **Backup Licenses** e avvia l'ordine di una nuova licenza.

Durante l'ordine, devi:

1. Selezionare il **tipo di licenza**: Veeam Enterprise Plus, VDP Foundation, VDP Advanced o VDP Premium.
2. Indicare un **nome per il tuo VBR**. Questo nome serve unicamente a identificare il tuo server nelle nostre interfacce: può essere diverso dal nome host reale della macchina.
3. Indicare l'**indirizzo IP pubblico** del tuo server VBR. Questo indirizzo viene utilizzato per autorizzare gli scambi tra la nostra infrastruttura e il tuo server.

Conferma poi l'ordine.

### Fase 3: Ricevere l'e-mail di consegna

Una volta finalizzato l'ordine, ricevi un'**e-mail di consegna** contenente tutte le informazioni necessarie alla connessione:

| Elemento | Descrizione |
|---|---|
| **URL del cloud gateway** | L'indirizzo DNS del gateway cloud OVHcloud, del tipo `vspc-adv-cgw…`. È l'indirizzo che il tuo VBR contatterà. |
| **Port** | La porta utilizzata per la connessione: `6180`. |
| **Company Tenant** | L'account utilizzato per connettere il tuo VBR alla VSPC. |
| **Company Owner** | L'account utilizzato per connetterti al portale VSPC e monitorare i tuoi backup. |

:::warning
Conserva questa e-mail: contiene le credenziali necessarie alle fasi successive e a qualsiasi nuova connessione di un server VBR.

:::

### Fase 4: Aprire i flussi di rete

Prima di connettere il tuo VBR, assicurati che il firewall del server (e quello della tua rete) autorizzi i due flussi seguenti:

- **In uscita**: dal tuo server VBR verso il gateway cloud OVHcloud comunicato nell'e-mail di consegna (`vspc-adv-cgw…`), sulla **porta 6180**.
- **In entrata**: dall'indirizzo IP della nostra infrastruttura verso il tuo server VBR, **senza restrizioni**. In Europa, questo indirizzo è `79.137.44.43`.

:::warning
Se uno di questi due flussi è bloccato, il tuo server VBR non potrà essere connesso o non apparirà correttamente nella VSPC. Consulta la guida "[Guida alla diagnostica e alla risoluzione dei problemi](/guides/storage-and-backup/backup-licenses/troubleshooting)" in caso di problemi.

:::

### Fase 5: Connettere il server VBR alla VSPC

Le fasi seguenti si svolgono **dalla console Veeam Backup & Replication** e non dal portale VSPC.

#### 5.1 Aprire la console Veeam Backup & Replication

Connettiti al server su cui è installato Veeam Backup & Replication (o a una macchina su cui è distribuita la console VBR), quindi avvia la console:

- Su un'installazione **Windows**: connettiti a `localhost`.
- Su una **Veeam Software Appliance**: indica l'indirizzo del server VBR e le credenziali di un account che dispone del ruolo Veeam Backup Administrator.

:::info
Se il tuo VBR funziona su una Veeam Software Appliance (Linux), la raccolta di dati da remoto deve essere attivata nella **Veeam Host Management Console**. Consulta la documentazione Veeam "[Connecting Linux Veeam Backup & Replication Servers](https://helpcenter.veeam.com/docs/vac/provider_admin/vbr_connect_linux.html)" per maggiori informazioni.

:::

#### 5.2 Avviare l'aggiunta del provider di servizi

Nella barra dei menu (ribbon) in alto nella console, clicca su <code className="action">Add Service Provider</code>.

Puoi anche procedere tramite il pannello di navigazione:

1. Apri la vista <code className="action">Backup Infrastructure</code>.
2. Individua il nodo <code className="action">Service Providers</code>.
3. Fai clic con il tasto destro su <code className="action">Service Providers</code>, quindi clicca su <code className="action">Add Service Provider</code>.

#### 5.3 Inserire i parametri del provider

Alla fase <code className="action">Service Provider</code> dell'assistente:

1. **DNS name or IP address**: inserisci l'URL del cloud gateway OVHcloud ricevuto nell'e-mail di consegna (`vspc-adv-cgw…`).
2. **Port**: inserisci la porta comunicata da OVHcloud, `6180`.
3. **Description**: facoltativa, una descrizione per identificare questo provider (ad esempio "OVHcloud — Backup Licenses").
4. Seleziona la casella <code className="action">Allow this Veeam Backup & Replication installation to be managed by the service provider</code>.

:::danger
La casella <code className="action">Allow this Veeam Backup & Replication installation to be managed by the service provider</code> è **indispensabile**. Senza di essa, l'agente di gestione non viene installato, il tuo server non appare nella VSPC e la licenza non può essergli attribuita.

:::

Clicca su <code className="action">Next</code> per passare alla fase successiva.

#### 5.4 Inserire le credenziali

Alla fase <code className="action">Credentials</code>, inserisci le credenziali dell'account **Company Tenant** ricevute nell'e-mail di consegna:

- **Nome utente**: l'identificativo del Company Tenant.
- **Password**: la password associata a questo account.

#### 5.5 Finalizzare l'assistente

Segui le eventuali fasi restanti dell'assistente (variano a seconda della versione di VBR), quindi clicca su <code className="action">Finish</code> all'ultima fase.

L'agente di gestione viene quindi distribuito sul tuo server VBR e la connessione verso la VSPC di OVHcloud viene stabilita.

### Fase 6: Verificare la licenza sul VBR

Una volta stabilita la connessione, verifica che la licenza fornita da OVHcloud sia correttamente installata:

1. Nella console Veeam Backup & Replication, apri il menu principale e clicca su <code className="action">License</code>.
2. Nella finestra <code className="action">License Information</code>, controlla i seguenti elementi:

| Campo | Valore atteso |
|---|---|
| **Status** | `Valid` (e non `Expired`, `Invalid` o `Not Installed`) |
| **Type** | Il tipo di licenza, ad esempio `Rental` |
| **Edition** | L'edizione ordinata, ad esempio `Enterprise Plus` |
| **Licensed to** | L'organizzazione associata alla licenza |
| **Instances** (o **Points**) | Il numero di istanze utilizzabili, coerente con il tuo ordine |
| **Expiration date** | La data di scadenza della licenza |

Se lo stato è `Valid` e le capacità corrispondono al tuo ordine, la licenza è correttamente applicata.

### Fase 7: Verificare la connessione dalla VSPC

Puoi anche controllare la connessione dal portale VSPC, con l'account **Company Owner** ricevuto nell'e-mail di consegna:

1. Connettiti al portale VSPC.
2. Accedi alla sezione <code className="action">Discovery</code>, scheda <code className="action">Backup Servers</code>.
3. Verifica che il tuo server VBR appaia con uno stato coerente (`Healthy` o `Connected`).

## Note importanti

- **Non connettere due volte lo stesso server VBR** alla VSPC con credenziali diverse: questo falserebbe la visualizzazione dei dati.
- Se sul server VBR è attivata la **MFA** (autenticazione a due fattori), quest'ultimo può apparire come `Inaccessible` nella VSPC. Consulta l'articolo [Veeam KB 4431](https://www.veeam.com/kb4431) per la procedura di risoluzione.
- Se il tuo VBR è il nodo primario di un **cluster ad alta disponibilità**, la VSPC lo registra come nodo di cluster: il nodo secondario deve poi essere connesso separatamente.
