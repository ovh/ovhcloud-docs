## Obiettivo

Il servizio NAS-HA OVHcloud ti permette di gestire lo storage di file accessibile da una rete. 

**Questa guida ti mostra come utilizzare il tuo servizio NAS-HA tramite l'API OVHcloud.**

## Prerequisiti

- Un servizio [NAS-HA OVHcloud](https://www.ovh.it/nas/)
- Consulta la nostra guida sui [primi passi con l'API OVHcloud](/guides/manage-and-operate/api/first-steps) per familiarizzare con l'APIv6 OVHcloud

## Procedura

Tutte le rotte API di questa guida sono disponibili nella <ApiLink section="/dedicated/nasha">sezione */dedicated/nasha*</ApiLink> della console API.

:::info
Quando si utilizza l'API, tutti i campi contrassegnati con un asterisco (\*) sono obbligatori.
:::


### Recupera informazioni sul tuo servizio

Tutti i tuoi servizi attivi possono essere recuperati utilizzando la strada seguente:

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha"} />


### Crea una partizione

Per creare una nuova partizione, utilizza la seguente strada:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Il nome interno del tuo servizio NAS |
| `partitionDescription` |  | Descrizione facoltativa |
| `partitionName` | Yes | Un nome per la partizione |
| `protocol` | Yes | *NFS*, *CIFS* o *NFS_CIFS* per entrambi |
| `size` | Yes | La dimensione della partizione |

Scegli `NFS` come protocollo e una dimensione di `10` Gigabyte, ad esempio.

### Aggiunta di un accesso ACL per accedere alla partizione

:::warning
L'accesso è rifiutato di default a meno che non sia concesso tramite l'ACL. Possono essere aggiunti solo gli indirizzi IP associati ai tuoi servizi OVHcloud.
:::


Puoi verificare gli indirizzi IP che possono essere ammessi ad un accesso tramite queste chiamate API:

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/authorizableBlocks"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Il nome interno del tuo servizio NAS |
| `partitionName` | Yes | Nome della partizione |

Per creare un nuovo accesso ACL che ti permetta di connetterti alla tua partizione, utilizza la seguente strada:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/access"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Il nome interno del tuo servizio NAS-HA |
| `partitionName` | Yes | Nome della partizione |
| `ip` | Yes | L'indirizzo IP o la gamma a cui deve essere concesso l'accesso |
| `type` | Yes | Tipo di accesso ACL per questo record: *readonly* o *readwrite* |

:::info
Utilizza il rating CIDR per gli intervalli IP, ad esempio: 192.0.2.0/24.
:::


### Crea uno Snapshot manuale

Per aggiungere uno Snapshot manuale, utilizza la seguente strada:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/customSnapshot"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Il nome interno del tuo servizio NAS-HA |
| `partitionName` | Yes | Nome della partizione |
| `expiration` |  | Una data di scadenza facoltativa, ad esempio: 2022-06-24 (ISO 8601) |
| `name` | Yes | Nome dello snapshot |

### Elimina una partizione

Per eliminare una partizione, utilizza questa pagina:

<Api version="v1" section="/dedicated/nasha" method="DELETE" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Il nome interno del tuo servizio NAS-HA |
| `partitionName` | Yes | Nome della partizione |

## Utilizzare l'API con un NAS-HA privato (Beta) <a name="using-the-api-with-a-private-nas-ha-beta"></a>

:::info
Il NAS-HA privato è attualmente in fase beta. Le sue route API sono diverse da quelle descritte sopra: sono disponibili nella <ApiLink section="/storage">sezione */storage*</ApiLink> della console API, dove le partizioni sono chiamate **shares**. Questa sezione può evolvere con il prodotto.

:::


Per connettere un NAS-HA privato alla tua rete privata vRack, consulta la nostra guida "[HA-NAS - Private network configuration (Beta)](/guides/storage-and-backup/file-storage/ha-nas/nas-network-config)".

### Recupera informazioni sul tuo servizio (Beta)

Per elencare i tuoi servizi NAS-HA privati, utilizza la seguente route:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha"} regions={["eu"]} />


Il campo `id` della risposta è il `serviceName` utilizzato dalle route seguenti.

Per recuperare lo `shareId` delle tue partizioni (il campo `id` della risposta), utilizza la seguente route:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | L'ID del tuo servizio NAS-HA privato |

### Aggiunta di un accesso ACL per accedere alla partizione (Beta)

:::warning
L'accesso è rifiutato di default a meno che non sia concesso tramite l'ACL.
:::


Per creare un nuovo accesso ACL che ti permetta di connetterti alla tua partizione, utilizza la seguente route:

<Api version="v1" section="/storage" method="POST" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/acl"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | L'ID del tuo servizio NAS-HA privato |
| `shareId` | Yes | L'ID della partizione |
| `accessLevel` | Yes | Livello di accesso ACL: *rw* (lettura e scrittura) o *ro* (sola lettura) |
| `accessTo` | Yes | L'indirizzo IPv4 o l'intervallo a cui concedere l'accesso |

:::info
Utilizza la notazione CIDR per gli intervalli IP, ad esempio: 10.235.0.0/24.
:::


### Recupera il punto di montaggio (Beta)

Per recuperare l'`accessPathId` dei percorsi di accesso di una partizione, utilizza la seguente route:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/accessPath"} regions={["eu"]} />


Recupera poi i dettagli di un percorso di accesso con la seguente route:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/accessPath/\{accessPathId\}"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | L'ID del tuo servizio NAS-HA privato |
| `shareId` | Yes | L'ID della partizione |
| `accessPathId` | Yes | L'ID del percorso di accesso |

Il campo `path` della risposta contiene il percorso di esportazione da utilizzare nel tuo comando di montaggio. Se una partizione dispone di più percorsi di accesso, utilizza quello il cui campo `preferred` vale `true`.
