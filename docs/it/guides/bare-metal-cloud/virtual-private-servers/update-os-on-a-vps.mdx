## Objectif

La mise à jour du système d'exploitation (OS) de votre serveur est essentielle pour maintenir la sécurité, la stabilité et les performances de vos services.

Pour réaliser cette opération, deux approches s'offrent à vous :

1. **La mise à niveau en place (*In-Place Upgrade*)** : la méthode la plus rapide et la plus économique. Elle permet de mettre à jour le système directement sur votre machine existante sans changer d'adresse IP ni transférer vos fichiers.
2. **La migration côte à côte (*Side-by-Side*)** : idéale si vous souhaitez repartir sur un environnement intégralement neuf ou tester la migration en parallèle sans impacter votre production.

**Ce guide vous explique comment mettre à jour l'OS de votre VPS OVHcloud.**

## Prérequis

- Disposer d'un [VPS](/links/bare-metal/vps) dans votre compte OVHcloud
- Être connecté à votre <ManagerLink to="/">Espace Client OVHcloud</ManagerLink>
- Avoir un accès SSH root (ou sudo) à votre VPS
- Avoir créé un Snapshot (ou disposer d'une sauvegarde quotidienne) avant toute manipulation

## En pratique

### Étape préalable obligatoire : sécurisez votre VPS avec un Snapshot

Quelle que soit la méthode choisie, la sécurisation de vos données avant toute manipulation est indispensable.

#### 1. La sauvegarde automatique quotidienne (VPS post-août 2025)

Si vous disposez d'un VPS issu de la gamme commercialisée depuis le **7 août 2025**, votre serveur bénéficie de sauvegardes automatiques quotidiennes hébergées sur une infrastructure distante. En cas d'imprévu majeur, vous pouvez restaurer l'image automatique la plus récente directement depuis votre Espace Client.

#### 2. Le Snapshot manuel (pour un état exact à l'instant T)

Pour capturer l'état exact de votre serveur à la minute près (juste avant de lancer la mise à jour), la création d'un **Snapshot** depuis votre Espace Client est vivement recommandée :

- [Utiliser les Snapshots sur un VPS](/guides/bare-metal-cloud/virtual-private-servers/using-snapshots-on-a-vps)

Un Snapshot enregistre l'intégralité de la machine à un instant précis : vos données applicatives, vos fichiers, vos configurations système et l'état complet de l'OS (noyau, paquets, dépendances).

> [!INFO]
> **Votre filet de sécurité** — Si une interruption survient pendant la mise à jour (coupure réseau, conflit de paquets, incohérence applicative), il vous suffit de cliquer sur **Restaurer le Snapshot** (ou d'appliquer votre dernière sauvegarde quotidienne) dans le Manager OVHcloud pour réinitialiser votre VPS dans son état d'origine.

### Méthode 1 : la mise à niveau en place (*In-Place Upgrade*)

C'est la solution recommandée pour la majorité des cas d'usage. Elle s'effectue directement sur votre serveur actuel.

:::warning
**Avertissement important — Serveurs avec Plesk ou cPanel**

Si votre VPS utilise un panneau de gestion **Plesk** ou **cPanel**, ne suivez pas les procédures de mise à niveau directe ci-dessous. L'utilisation d'outils génériques (comme Leapp ou `dist-upgrade`) sans les utilitaires dédiés des éditeurs risque de corrompre votre installation et vos licences.

- Pour **Plesk** : utilisez l'outil officiel `centos2alma` fourni par Plesk.
- Pour **cPanel** : utilisez l'outil officiel **cPanel ELevate**.

Pour connaître toutes les options de migration adaptées (y compris les outils de migration automatique de serveur à serveur), consultez le guide [Fin du support Plesk et cPanel pour VPS](/guides/bare-metal-cloud/virtual-private-servers/eos-cpanel-plesk).

:::

#### Option A : distributions Debian et Ubuntu

##### 1. Créer le Snapshot

Connectez-vous à votre Espace Client OVHcloud, rendez-vous dans la section `Bare Metal Cloud` > `VPS`, puis dans l'onglet Snapshots pour lancer la création de l'image de sécurité.

##### 2. Mettre à jour le système actuel

Connectez-vous en SSH à votre VPS et appliquez les derniers correctifs de votre version actuelle :

```bash
sudo apt update && sudo apt upgrade -y
sudo apt autoremove -y
```

Si un nouveau noyau Linux a été installé, redémarrez le VPS (`sudo reboot`).

##### 3. Engager la montée de version majeure

- **Sur Ubuntu :**

Lancez l'outil officiel d'Canonical :

```bash
sudo do-release-upgrade
```

Suivez les instructions interactives à l'écran.

- **Sur Debian** (ex. passage de Debian 11 « Bullseye » à Debian 12 « Bookworm ») :

1. Éditez le fichier des sources APT :

```bash
sudo nano /etc/apt/sources.list
```

2. Remplacez toutes les occurrences du nom de l'ancien OS par le nouveau (ex. remplacez `bullseye` par `bookworm`, y compris sur les lignes `-updates` et `-security`).
3. Enregistrez (`Ctrl+O`, Entrée) puis quittez (`Ctrl+X`).
4. Actualisez l'index puis lancez la mise à niveau globale :

```bash
sudo apt update
sudo apt dist-upgrade -y
```

##### 4. Points d'attention pendant l'installation

- **Écran d'information** (`apt-listchanges`) : si le terminal s'interrompt avec un deux-points (`:`) en bas d'écran, appuyez sur la touche `q` pour fermer la notice et reprendre la mise à jour.
- **Fichiers de configuration modifiés** : si le système vous demande si vous souhaitez remplacer un fichier de configuration existant, sélectionnez l'option pour conserver votre version locale (*keep the local version currently installed*).

##### 5. Redémarrage et vérification

Une fois le processus terminé, redémarrez votre serveur :

```bash
sudo reboot
```

Vérifiez l'OS actif via `cat /etc/os-release`. Si vos services web/applications fonctionnent correctement, vous pourrez supprimer le Snapshot dans le Manager OVHcloud.

#### Option B : distributions RHEL, AlmaLinux, Rocky Linux et CentOS Stream

Pour les OS de la famille Red Hat, la transition vers la version 9 utilise le framework ELevate / Leapp.

##### 1. Créer le Snapshot

Déclenchez la création du Snapshot depuis votre **Espace Client OVHcloud** et attendez sa finalisation avant de poursuivre.

##### 2. Mettre à jour les paquets existants

```bash
sudo dnf update -y
sudo reboot
```

##### 3. Installer l'outil de migration ELevate

Installez le dépôt ELevate, puis sélectionnez le paquet de données correspondant exactement à votre distribution :

```bash
# Installation du dépôt ELevate et de l'outil Leapp
sudo dnf install -y http://repo.almalinux.org/elevate/elevate-release-latest-el8.noarch.rpm
sudo yum install -y leapp-upgrade

# Installation du paquet de données selon votre OS (exécutez UNIQUEMENT la ligne concernée) :
sudo yum install -y leapp-data-almalinux    # Pour AlmaLinux
sudo yum install -y leapp-data-rocky        # Pour Rocky Linux
sudo yum install -y leapp-data-centos       # Pour CentOS Stream
sudo yum install -y leapp-data-ras          # Pour Red Hat Enterprise Linux (RHEL)
```

##### 4. Valider l'éligibilité et lancer la mise à niveau

Avant d'exécuter la mise à niveau, générez l'analyse initiale, validez automatiquement le fichier de réponses de Leapp pour éviter tout blocage, puis lancez la migration :

```bash
# Lancer la pré-vérification du système
sudo leapp preupgrade

# Valider automatiquement les questions de confirmation Leapp
sudo sed -i 's/# confirm =/confirm = True/g' /var/log/leapp/answerfile

# Lancer la mise à niveau vers la version 9
sudo leapp upgrade
```

En cas d'erreur bloquante pendant la pré-vérification, consultez la liste des points à corriger dans `/var/log/leapp/leapp-report.txt`.

##### 5. Bascule et finalisation

Redémarrez votre serveur pour exécuter la bascule du noyau vers la version 9 :

```bash
sudo reboot
```

Le premier redémarrage peut durer plusieurs minutes (installation des paquets en arrière-plan et re-étiquetage SELinux).

Une fois le système de nouveau accessible, contrôlez la version et nettoyez les paquets de migration :

```bash
# Vérifier la version installée
cat /etc/os-release

# Supprimer les outils de migration et nettoyer le cache
sudo dnf remove -y leapp-upgrade leapp-data-*
sudo dnf autoremove -y
```

### Méthode 2 : la migration côte à côte (*Side-by-Side*)

Cette méthode consiste à déployer un second VPS OVHcloud neuf, à y installer vos services, puis à basculer vos données et votre trafic réseau sans risque d'interruption prolongée.

#### 1. Commander et préparer le nouveau VPS

Depuis le site OVHcloud ou votre Espace Client, commandez une nouvelle instance VPS équipée de la version d'OS cible souhaitée.

Une fois livré, connectez-vous au nouveau VPS et installez vos services (serveur web, moteur de base de données, Docker, etc.).

#### 2. Transférer vos données et configurations

- **Bases de données** : exécutez un dump depuis le VPS source (`mysqldump` ou `pg_dump`) puis importez le fichier `.sql` sur le nouveau VPS.
- **Fichiers utilisateurs / web** : synchronisez vos répertoires (ex. `/var/www/` ou `/home/`) de serveur à serveur via `rsync` :

```bash
rsync -avz -e ssh /var/www/ root@IP_DU_NOUVEAU_VPS:/var/www/
```

- **Panneaux de gestion (ex. Plesk, cPanel)** : si votre VPS utilise un panneau de contrôle, utilisez directement l'outil de migration intégré (Plesk Migrator / cPanel Transfer Tool) pour automatiser le transfert des comptes et bases, ou suivez le guide [Fin du support Plesk et cPanel pour VPS](/guides/bare-metal-cloud/virtual-private-servers/eos-cpanel-plesk).

#### 3. Tester le nouvel environnement

Avant de basculer vos utilisateurs, validez le bon fonctionnement de votre site ou application sur la nouvelle IP (par exemple en adaptant temporairement votre fichier `hosts` local).

#### 4. Basculer le trafic vers le nouveau VPS

- **Si vous utilisez une IP Additionnelle (Failover IP OVHcloud)** : dans votre Espace Client OVHcloud, rendez-vous dans la section `Network` > `Public IP`, puis basculez l'IP Additionnelle depuis l'ancien VPS vers le nouveau VPS. La bascule réseau est instantanée.
- **Si vous utilisez les DNS standards** : modifiez les enregistrements DNS (`A` / `AAAA`) de votre nom de domaine pour pointer vers la nouvelle adresse IP de votre nouveau VPS.

#### 5. Résiliation de l'ancien serveur

Une fois la bascule validée et les délais de propagation DNS écoulés (24 h à 48 h recommandées), vous pourrez résilier l'ancien VPS depuis votre Espace Client.

### En cas d'incident pendant la procédure

Si lors d'une mise à niveau en place votre VPS ne répond plus au réseau ou ne démarre plus :

1. Connectez-vous sur votre **Espace Client OVHcloud**.
2. Allez dans la section de gestion de votre VPS, puis dans l'onglet **Snapshots** (ou **Sauvegardes**).
3. Cliquez sur **Restaurer**.

Votre VPS reviendra à son état exact d'origine en quelques minutes.
