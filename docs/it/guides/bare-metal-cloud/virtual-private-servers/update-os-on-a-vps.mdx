## Obiettivo

Aggiornare il sistema operativo (OS) del tuo server è essenziale per mantenere la sicurezza, la stabilità e le performance dei tuoi servizi. Per sapere se la tua versione del sistema operativo sta raggiungendo la fine del supporto (*End of Support* / *End of Life*), consulta la nostra guida [Public Cloud & VPS - Image and OS life cycle and end of life/support announcements](/guides/public-cloud/compute/image-life-cycle).

Sono possibili due approcci:

1. **L'aggiornamento sul posto (*In-Place Upgrade*)**: il metodo più rapido ed economico. Aggiorna il sistema direttamente sulla macchina esistente senza modificare l'indirizzo IP né trasferire i tuoi file.
2. **La migrazione in parallelo (*Side-by-Side*)**: ideale se desideri ripartire da un ambiente completamente nuovo o testare la migrazione in parallelo senza impattare la produzione.

**Questa guida ti mostra come aggiornare il sistema operativo del tuo VPS OVHcloud.**

## Prerequisiti

- Disporre di un [VPS](/links/bare-metal/vps) nel tuo account OVHcloud
- Disporre di un accesso SSH root (o sudo) al tuo VPS
- Aver creato uno snapshot (o disporre di un backup quotidiano) prima di qualsiasi operazione

## Procedura

### Step preliminare obbligatorio: metti al sicuro il tuo VPS con uno snapshot

Qualunque sia il metodo scelto, metti al sicuro i tuoi dati prima di qualsiasi operazione.

#### 1. Il backup automatico quotidiano (VPS successivi ad agosto 2025)

Se disponi di un VPS della gamma commercializzata a partire dal **7 agosto 2025**, il tuo server beneficia di un backup automatico quotidiano del sistema (esclusi i dischi aggiuntivi). Questo backup è conservato per **24 ore**. In caso di imprevisto importante, puoi ripristinare l'immagine automatica più recente direttamente dal tuo Spazio Cliente OVHcloud.

#### 2. Lo snapshot manuale (stato esatto in un dato momento)

Per catturare lo stato del tuo server subito prima dell'aggiornamento, crea uno **snapshot** dal tuo Spazio Cliente OVHcloud, come descritto nella guida [Usare snapshot su un VPS](/guides/bare-metal-cloud/virtual-private-servers/using-snapshots-on-a-vps).

Lo snapshot è un'**opzione a pagamento** ed è possibile avere un solo snapshot attivo alla volta su un VPS. Registra lo stato della macchina in un momento preciso: dati applicativi, file, configurazioni di sistema e stato del sistema operativo (kernel, pacchetti, dipendenze). Non costituisce tuttavia un backup completo del sistema. La coerenza dello snapshot dipende dal *qemu-guest-agent*, che non è installato per impostazione predefinita sulla maggior parte delle distribuzioni: verifica che sia presente sul tuo VPS prima di avviare l'aggiornamento.

:::info
**La tua rete di sicurezza** — Se durante l'aggiornamento si verifica un'interruzione (interruzione di rete, conflitto tra pacchetti, incoerenza applicativa), clicca su <code className="action">Ripristina lo snapshot</code> (o applica il tuo ultimo backup quotidiano) nello Spazio Cliente OVHcloud per riportare il tuo VPS al suo stato originale. Il ripristino **elimina** lo snapshot: per conservarne uno, creane uno nuovo prima di effettuare qualsiasi altra modifica.
:::

### Metodo 1: l'aggiornamento sul posto (*In-Place Upgrade*)

È la soluzione consigliata nella maggior parte dei casi. Viene effettuata direttamente sul tuo server attuale.

:::warning
**Avvertenza importante — Server con Plesk o cPanel**

Se il tuo VPS utilizza un pannello di gestione **Plesk** o **cPanel**, non seguire le procedure di aggiornamento diretto riportate di seguito. Senza le utility dedicate degli editori, gli strumenti generici (Leapp, `dist-upgrade`) rischiano di danneggiare la tua installazione e le tue licenze.

- Per **Plesk** (passaggio da CentOS 7 a AlmaLinux 8): utilizza lo script ufficiale `centos2alma` fornito da Plesk.
- Per **cPanel** (passaggio da CentOS 7 a AlmaLinux 8): utilizza lo strumento ufficiale **Elevate** fornito da cPanel.

Questi strumenti sono destinati a utenti esperti, non sono garantiti al 100 % e richiedono un backup completo prima di procedere.

Per tutte le opzioni di migrazione (inclusi gli strumenti automatici da server a server), consulta la guida [Fine del supporto Plesk e cPanel per VPS - Garantire la continuità dei servizi](/guides/bare-metal-cloud/virtual-private-servers/eos-cpanel-plesk).

:::

#### Opzione A: distribuzioni Debian e Ubuntu

##### 1. Creare lo snapshot

Apri <ManagerLink to="/#/dedicated/vps">VPS management</ManagerLink>, seleziona il tuo VPS, quindi, dalla scheda <code className="action">Home</code>, scorri verso il basso fino al riquadro "Backup" e utilizza il menu <code className="action">...</code> dell'opzione "Snapshot".

##### 2. Aggiornare il sistema attuale

Connettiti in SSH al tuo VPS e applica tutte le correzioni disponibili per la tua versione attuale:

```bash
sudo apt update
sudo apt upgrade
sudo apt full-upgrade
```

Esamina i pacchetti diventati inutili prima di eliminarli:

```bash
sudo apt --purge autoremove
```

Se è stato installato un nuovo kernel Linux, riavvia il VPS:

```bash
sudo reboot
```

##### 3. Avviare l'aggiornamento alla versione principale

<Tabs>
<Tab label="Ubuntu">

Avvia lo strumento ufficiale di Canonical:

```bash
sudo do-release-upgrade
```

Segui le istruzioni visualizzate sullo schermo.

</Tab>
<Tab label="Debian">

Esempio: passaggio da Debian 11 "Bullseye" a Debian 12 "Bookworm".

1. Effettua un backup delle tue fonti APT attuali:

```bash
sudo cp -v /etc/apt/sources.list /root/
sudo cp -rv /etc/apt/sources.list.d/ /root/
```

2. Modifica `/etc/apt/sources.list` e sostituisci tutte le occorrenze del nome della vecchia versione con quello della nuova. Per Debian 12, verifica anche la presenza del componente `non-free-firmware` se la tua configurazione lo utilizza:

```bash
sudo nano /etc/apt/sources.list
```

3. Verifica i file di `/etc/apt/sources.list.d/` e aggiorna o disattiva temporaneamente i repository di terze parti che non offrono ancora pacchetti per la nuova versione di destinazione.

4. Aggiorna l'indice, quindi avvia l'aggiornamento in **2 fasi**, senza aggiungere automaticamente `-y`:

```bash
sudo apt update
sudo apt upgrade
sudo apt full-upgrade
```

</Tab>
</Tabs>

:::warning
**Punti di attenzione durante l'installazione**

- **Schermata di informazioni** (`apt-listchanges`): se in fondo allo schermo compaiono i due punti (`:`), premi `q` per chiudere l'avviso e riprendere l'aggiornamento.
- **File di configurazione modificati**: se il sistema propone di sostituire un file di configurazione esistente, privilegia la versione del manutentore, quindi verifica gli eventuali file `.dpkg-old` o `.dpkg-dist` prima di ripristinare le tue personalizzazioni.

:::

##### 4. Riavvio e verifica

Una volta terminato il processo, riavvia il tuo server:

```bash
sudo reboot
```

Verifica il sistema operativo attivo con `cat /etc/os-release`. Se i tuoi servizi web e le tue applicazioni funzionano correttamente, puoi eliminare lo snapshot dallo Spazio Cliente OVHcloud.

#### Opzione B: distribuzioni AlmaLinux, Rocky Linux e CentOS Stream

Per i sistemi operativi della famiglia Red Hat, la transizione verso la versione 9 utilizza il framework ELevate / Leapp.

##### 1. Creare lo snapshot

Crea lo snapshot da <ManagerLink to="/#/dedicated/vps">VPS management</ManagerLink> e attendi la fine dell'operazione prima di proseguire.

##### 2. Aggiornare i pacchetti esistenti

```bash
sudo dnf update -y
sudo reboot
```

##### 3. Installare lo strumento di migrazione ELevate

Installa il repository ELevate, quindi seleziona il pacchetto dati della tua distribuzione. Per **RHEL**, consulta la documentazione ufficiale Red Hat — [aggiornamento con Leapp](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/8/html/upgrading_from_rhel_7_to_rhel_8/) o [migrazione da RHEL 8 a RHEL 9](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/9/html/upgrading_from_rhel_8_to_rhel_9/) — piuttosto che un pacchetto dati ELevate.

```bash
# Installazione del repository ELevate e dello strumento Leapp
sudo dnf install -y https://repo.almalinux.org/elevate/elevate-release-latest-el8.noarch.rpm
sudo yum install -y leapp-upgrade

# Installazione del pacchetto dati in base al tuo sistema operativo (esegui SOLO la riga interessata):
sudo yum install -y leapp-data-almalinux    # Per AlmaLinux
sudo yum install -y leapp-data-rocky        # Per Rocky Linux
sudo yum install -y leapp-data-centos       # Per un aggiornamento verso CentOS Stream
```

##### 4. Verificare l'idoneità e avviare l'aggiornamento

Prima dell'aggiornamento, genera l'analisi iniziale, leggi il report Leapp, rispondi alle domande bloccanti, quindi avvia la migrazione:

```bash
# Avviare la verifica preliminare del sistema
sudo leapp preupgrade

# Leggere il report dettagliato prima di continuare
sudo less /var/log/leapp/leapp-report.txt

# Rispondere esplicitamente alle domande bloccanti individuate dal report
sudo leapp answer --section remove_pam_pkcs11_module_check.confirm=True

# Avviare l'aggiornamento verso la versione 9
sudo leapp upgrade
```

In caso di errore bloccante durante la verifica preliminare, correggi prima i punti segnalati in `/var/log/leapp/leapp-report.txt`. Per **RHEL**, fai riferimento alla documentazione ufficiale Red Hat sulle migrazioni di versioni principali con Leapp.

##### 5. Passaggio e finalizzazione

Riavvia il tuo server per eseguire il passaggio del kernel alla versione 9:

```bash
sudo reboot
```

Il primo riavvio può durare diversi minuti (installazione dei pacchetti in background e rietichettatura SELinux).

Una volta che il sistema è di nuovo accessibile, controlla la versione ed elimina i pacchetti di migrazione:

```bash
# Verificare la versione installata
cat /etc/os-release

# Eliminare gli strumenti di migrazione e svuotare la cache
sudo dnf remove -y leapp-upgrade 'leapp-data-*'
sudo dnf autoremove -y
```

### Metodo 2: la migrazione in parallelo (*Side-by-Side*)

Questo metodo consiste nel mettere online un secondo VPS OVHcloud nuovo, installarvi i tuoi servizi, quindi trasferire i tuoi dati e il tuo traffico di rete senza rischio di un'interruzione prolungata.

#### 1. Ordinare e preparare il nuovo VPS

Dal sito OVHcloud o dal tuo Spazio Cliente OVHcloud, ordina un nuovo VPS con la versione del sistema operativo di destinazione.

Una volta consegnato il VPS, connettiti e installa i tuoi servizi (server web, motore di database, Docker, ecc.).

#### 2. Trasferire i tuoi dati e le tue configurazioni

- **Database**: esegui un dump dal VPS di origine (`mysqldump` o `pg_dump`), quindi importa il file `.sql` sul nuovo VPS.
- **File utente/web**: sincronizza le tue directory (ad esempio `/var/www/` o `/home/`) da server a server tramite `rsync`:

```bash
rsync -avz -e ssh /var/www/ root@IP_DEL_NUOVO_VPS:/var/www/
```

- **Pannelli di gestione (ad esempio Plesk, cPanel)**: se il tuo VPS utilizza un pannello di gestione, usa il suo strumento di migrazione integrato (Plesk Migrator / cPanel Transfer Tool) per automatizzare il trasferimento degli account e dei database, oppure segui la guida [Fine del supporto Plesk e cPanel per VPS - Garantire la continuità dei servizi](/guides/bare-metal-cloud/virtual-private-servers/eos-cpanel-plesk).

#### 3. Testare il nuovo ambiente

Prima di trasferire i tuoi utenti, verifica che il tuo sito o la tua applicazione funzioni sul nuovo IP (ad esempio adattando temporaneamente il tuo file `hosts` locale).

#### 4. Trasferire il traffico verso il nuovo VPS

- **Se utilizzi un Additional IP**: nel tuo Spazio Cliente OVHcloud, apri <ManagerLink to="/#/network/ip">Public IP</ManagerLink> (<code className="action">Network</code> > <code className="action">Public IPs</code>), quindi trasferisci l'Additional IP dal vecchio VPS al nuovo VPS. Alcuni prodotti richiedono che l'IP passi prima da un **Parking IP**, solo un blocco /32 può essere spostato verso un VPS e i MAC virtuali sono temporaneamente sospesi durante l'operazione. Consulta la guida [Spostare un Additional IP](/guides/bare-metal-cloud/dedicated-servers/move-failover-ip) per le condizioni dettagliate.
- **Se utilizzi i DNS standard**: modifica i record DNS (`A` / `AAAA`) del tuo nome a dominio in modo che puntino al nuovo indirizzo IP del tuo nuovo VPS.

#### 5. Disattivare il vecchio server

Una volta convalidato il passaggio e trascorsi i tempi di propagazione DNS (si consigliano da 24 a 48 ore), puoi disattivare il vecchio VPS dal tuo Spazio Cliente OVHcloud.

### In caso di problemi durante la procedura

Se il tuo VPS non risponde più in rete o non si avvia più dopo un aggiornamento sul posto:

1. Apri <ManagerLink to="/#/dedicated/vps">VPS management</ManagerLink> e seleziona il VPS interessato.
2. Nel riquadro "Backup", utilizza il menu <code className="action">...</code> dell'opzione "Snapshot" oppure applica il tuo backup automatico più recente.
3. Clicca su <code className="action">Ripristina lo snapshot</code> o avvia il ripristino del backup desiderato.

Il tuo VPS torna al suo stato originale in pochi minuti.
