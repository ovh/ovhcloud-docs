## Obiettivo

L'aggregazione dei collegamenti riunisce più interfacce di rete del tuo server tramite il protocollo LACP (Link Aggregation Control Protocol), definito dallo standard IEEE 802.3ad. La larghezza di banda disponibile aumenta e i tuoi collegamenti di rete diventano ridondati: se un collegamento non funziona, il traffico viene reindirizzato automaticamente verso un altro collegamento disponibile.

Diverse guide trattano l'aggregazione dei collegamenti, in base alla gamma del server, al suo sistema operativo e al mantenimento o meno della connettività pubblica.

**Questa guida spiega in cosa differiscono l'aggregazione predefinita e OVHcloud Link Aggregation (OLA) e ti indirizza verso la guida corrispondente alla tua configurazione.**

## Prerequisiti

- Disporre di un [server dedicato](/links/bare-metal/bare-metal) compatibile con l'aggregazione dei collegamenti, per esempio della gamma **Scale** o **High Grade**, oppure di un server **Advance** di terza generazione o successiva
- Disporre di un sistema operativo o di un hypervisor che supporti il protocollo di aggregazione 802.3ad (LACP)

## Procedura

### Quali interfacce possono essere aggregate

I server delle gamme **Scale** e **High Grade** dispongono di quattro interfacce di rete. Nella configurazione predefinita, due sono pubbliche e due private (vRack). Entrambe le aggregazioni sono già attive sulla rete OVHcloud, per cui il sistema operativo deve solo creare gli aggregati corrispondenti.

Gli altri server compatibili con l'aggregazione dei collegamenti dispongono di una sola interfaccia pubblica e di una sola interfaccia privata.

### Scegliere una modalità di aggregazione

[OVHcloud Link Aggregation (OLA)](/guides/bare-metal-cloud/dedicated-servers/ola-enable-manager) è un'opzione che attivi nello Spazio Cliente OVHcloud: riunisce tutte le interfacce del server in un'unica aggregazione privata, invece di mantenere separate le interfacce pubbliche e quelle private.

|Modalità|Connettività pubblica|
|---|---|
|Predefinita|L'aggregato pubblico, o l'unica interfaccia pubblica, ospita l'indirizzo IP pubblico|
|OLA|Nessuna: l'indirizzo IP pubblico non è più accessibile|

Gli aggregati creati da ciascuna modalità dipendono dal numero di interfacce del server.

**Quattro interfacce, sulle gamme Scale e High Grade:** per impostazione predefinita, le due interfacce pubbliche formano un aggregato e le due interfacce private un altro. Con OLA, tutte e quattro ne formano uno solo, dedicato alla vRack.

<img className="thumbnail" alt="Schema che confronta gli aggregati predefiniti con quattro interfacce e l'aggregato unico con OLA" src="/images/bare-metal-cloud/dedicated-servers/link-aggregation-overview/four-interfaces.png" loading="lazy" />

**Due interfacce, una pubblica e una privata:** per impostazione predefinita, nessuna delle due viene aggregata. Con OLA, le due formano un aggregato unico, dedicato alla vRack.

<img className="thumbnail" alt="Schema che confronta la configurazione predefinita con due interfacce e l'aggregato unico con OLA" src="/images/bare-metal-cloud/dedicated-servers/link-aggregation-overview/two-interfaces.png" loading="lazy" />

:::warning
Un server le cui interfacce sono interamente aggregate per la vRack non dispone più di alcuna interfaccia di rete pubblica e non può quindi più raggiungere il servizio di netboot di OVHcloud. Consulta la guida "[Gestire il riavvio dei tuoi server con la funzionalità OVHcloud Link Aggregation (EN)](/guides/bare-metal-cloud/dedicated-servers/pxe-with-full-private-dedicated)" prima di attivare OLA.

:::

### Configurare gli aggregati durante l'installazione

Sui server **Scale** e **High Grade**, l'installazione può configurare gli aggregati per te, in modo che il server si avvii già aggregato.

Gli aggregati vengono **sempre** configurati, e l'opzione **non viene proposta**, su:

- **Ubuntu Server** 26.04

L'opzione viene proposta ed è **disattivata per impostazione predefinita** su:

- **AlmaLinux**
- **Debian**, tranne Debian 11
- **Fedora**
- **Proxmox Virtual Environment** e **Proxmox Backup Server**
- **Rocky Linux**, tranne Rocky Linux 8
- **Ubuntu Server** 22.04 e 24.04
- **Windows Server**, tranne le immagini Hyper-V
- [Bring Your Own Image (BYOI)](/guides/bare-metal-cloud/dedicated-servers/bring-your-own-image) e [Bring Your Own Linux (BYOLinux)](/guides/bare-metal-cloud/dedicated-servers/bring-your-own-linux)

Per attivarla:

- nello Spazio Cliente OVHcloud, seleziona la casella corrispondente nella procedura guidata di installazione.
- tramite l'API, imposta la personalizzazione `enableLacpBonding`, come descritto nella guida "[Installare un sistema operativo tramite l'API OVHcloud su un server dedicato (EN)](/guides/bare-metal-cloud/dedicated-servers/api-os-installation)".

Nessun altro sistema operativo configura gli aggregati durante l'installazione, per cui dovrai farlo tu successivamente.

:::info
L'opzione può essere attivata su qualsiasi server, ma ha effetto solo se il server dispone di interfacce da aggregare.

:::

### Configurare gli aggregati manualmente

Se il tuo sistema operativo non propone l'opzione durante l'installazione, o se preferisci configurare gli aggregati successivamente, segui la guida corrispondente al tuo sistema:

|Sistema operativo o contesto|Guida|
|---|---|
|Debian 12 o successiva, Ubuntu 24.04 o successiva|[Configurazione Netplan](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-netplan)|
|Debian da 9 a 11, modalità rescue e immagini personalizzate che utilizzano `ifupdown`|[Configurazione ifupdown](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-ifupdown)|
|SLES 15|[Configurazione SLES 15](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-sles15)|
|Windows Server 2019 con OLA|[Configurazione del NIC teaming](/guides/bare-metal-cloud/dedicated-servers/ola-enable-w2k19)|
|Proxmox VE|[Rete Proxmox VE](/guides/bare-metal-cloud/dedicated-servers/proxmox-network-hg-scale)|
|Windows Server con Hyper-V|[Rete Hyper-V](/guides/bare-metal-cloud/dedicated-servers/hyperv-network-hg-scale)|

### Come un'aggregazione è distribuita tra le schede di rete

Sui server **Scale** e **High Grade**, un'aggregazione è distribuita tra due schede di rete distinte, in modo da resistere al guasto di un'intera scheda e non solo a quello di uno switch. Per maggiori informazioni, consulta la guida "[Migliorare la resilienza di rete sui server Bare Metal (EN)](/guides/bare-metal-cloud/dedicated-servers/lacp-resilience-scale-hg)".
