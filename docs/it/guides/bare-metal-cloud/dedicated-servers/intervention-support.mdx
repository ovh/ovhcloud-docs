## Obiettivo

I nostri interventi di manutenzione si limitano esclusivamente all'aspetto hardware del tuo server. In seguito a un intervento di manutenzione, potrebbero essere necessarie alcune azioni da parte tua sulla parte software del server.

Questa documentazione, basata su numerosi feedback e casi d'uso riscontrati dai nostri team, elenca le azioni da intraprendere in base alle tue installazioni: sistemi operativi, hypervisor, ecc.
Il suo obiettivo è accompagnarti e limitare il più possibile l'impatto sul ciclo di vita dei tuoi ambienti.

## Prerequisiti

- Disporre di un [server dedicato](/links/bare-metal/bare-metal).

<a name="ubuntu"></a>

### Ubuntu / Debian 12+

Se riscontri un problema di connettività di rete (ad esempio, nessuna risposta al ping dopo la sostituzione della scheda madre), effettua le seguenti operazioni:

1\. Riavvia il server in [modalità Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).<br/>
2\. Monta la partizione `/`:

```bash
root@rescue:~# mount /dev/my_system_disk /mnt
```
Se il file `70-persistent-net.rules` non esiste (consulta la sezione di questa guida dedicata al [nome delle interfacce di rete](#network-interface)), verifica i seguenti file nella struttura `/etc/systemd/network/`:

- `50-default.network`
- `50-public-interface.link`

```bash
root@rescue:~# cat /mnt/etc/systemd/network/50-default.network
# This file sets the IP configuration of the primary (public) network device.
# You can also see this as "OSI Layer 3" config.
# It was created by the OVH installer, please be careful with modifications.
# Documentation: man systemd.network or https://www.freedesktop.org/software/systemd/man/systemd.network.html
 
[Match]
MACAddress=xx:xx:xx:xx:xx:xx
 
[Network]
Description=network interface on public network, with default route
DHCP=no
Address=1.2.3.4/24
Gateway=1.2.3.254
IPv6AcceptRA=no
NTP=ntp.ovh.net
DNS=127.0.0.1
DNS=213.186.33.99
DNS=2001:41d0:3:163::1
Gateway=2001:41d0:0203:4bff:ff:ff:ff:ff
 
[Address]
Address=2001:41d0:0203:1234::/64
 
[Route]
Destination=2001:41d0:0203:4bff:ff:ff:ff:ff
Scope=link
root@rescue:~#
root@rescue:~# cat /mnt/etc/systemd/network/50-public-interface.link
# This file configures the relation between network device and device name.
# You can also see this as "OSI Layer 2" config.
# It was created by the OVH installer, please be careful with modifications.
# Documentation: man systemd.link or https://www.freedesktop.org/software/systemd/man/systemd.link.html
 
[Match]
MACAddress=xx:xx:xx:xx:xx:xx
 
[Link]
Description=network interface on public network, with default route
MACAddressPolicy=persistent
NamePolicy=kernel database onboard slot path mac
#Name=eth2    # name under which this interface is known under OVH rescue system
#Name=eno3    # name under which this interface is probably known by systemd
root@rescue:~#
```

3\. Effettua un backup dei file e modificali per inserire il nuovo valore dell'indirizzo MAC:

```bash
root@rescue:~# cp /mnt/etc/systemd/network/50-default.network /mnt/etc/systemd/network/50-default.network.link.bak-`date +%s`
root@rescue:~# cp /mnt/etc/systemd/network/50-public-interface.link /mnt/etc/systemd/network/50-public-interface.link.bak-`date +%s`
root@rescue:~# nano /mnt/etc/systemd/network/50-default.network
root@rescue:~# cat /mnt/etc/systemd/network/50-default.network | grep MACAddress
MACAddress=xx:xx:xx:xx:xx:xx
root@rescue:~#
root@rescue:~# nano /mnt/etc/systemd/network/50-public-interface.link
root@rescue:~#
root@rescue:~# cat /mnt/etc/systemd/network/50-public-interface.link | grep MACAddress
MACAddress=xx:xx:xx:xx:xx:xx
root@rescue:~#
```

4\. Ricordati di smontare la partizione `/` prima di riavviare il server.

#### Casi particolari

In alcuni casi è necessario propagare il nuovo indirizzo MAC nei seguenti file:

- `/mnt/etc/netplan/01-netcfg.yaml`
- `/mnt/etc/netplan/50-cloud-init.yaml`
- `/mnt/etc/systemd/network/10-eno1.link`
- `/mnt/etc/systemd/network/10-eno1.network`

<a name="centos-almalinux"></a>

### CentOS / Alma Linux

Se riscontri un problema di connettività di rete (ad esempio, nessuna risposta al ping dopo la sostituzione della scheda madre), effettua le seguenti operazioni:

1\. Riavvia il server in [modalità Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).<br/>
2\. Monta la partizione `/`:

```bash
root@rescue:~# mount /dev/my_system_disk /mnt
```

3\. Verifica il file di configurazione `/mnt/etc/sysconfig/network-scripts/ifcfg-eth0`.

4\. Effettua un backup dei file e modificali per correggere l'indirizzo MAC:

```bash
root@rescue:~# cp /mnt/etc/sysconfig/network-scripts/ifcfg-eth0 /mnt/etc/sysconfig/network-scripts/ifcfg-eth0.`date +%s`
```

5\. Inserisci il nuovo indirizzo MAC nella riga `HWADDR=xx:xx:xx:xx:xx:xx`.

6\. Ricordati di smontare la partizione `/` prima di riavviare il server.

<a name="smartos"></a>

### SmartOS

Se riscontri un problema di connettività di rete (ad esempio, nessuna risposta al ping dopo la sostituzione della scheda madre), effettua le seguenti operazioni:

1\. Riavvia il server in [modalità Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).<br/>

```bash 
modprobe zfs
root@rescue:~# zpool import -f zones (zpool import to list the pools)
root@rescue:~# zfs set mountpoint=/mnt zones/usbkey
root@rescue:~# zfs mount zones/usbkey
root@rescue:~# cp /mnt/config{,.bak-$(date +"%Y-%m-%d-%H_%M")}
```

2\. Inserisci il nuovo indirizzo MAC nella riga `admin_nic`:

```bash
root@rescue:~#  vim /mnt/config
```

3\. Ricordati di smontare le partizioni prima di riavviare il server in modalità `netboot`:

```bash
root@rescue:~# zfs umount -a
root@rescue:~# zfs set mountpoint="/usbkey" zones/usbkey 
```

```bash
root@rescue:~# umount /mnt
root@rescue:~# reboot
```

### Proxmox / Debian (escluse Debian 12 e versioni successive)

Se riscontri un problema di connettività di rete (ad esempio, nessuna risposta al ping dopo la sostituzione della scheda madre), la causa può essere un errore durante l'avvio del sistema, dovuto al vecchio valore dell'indirizzo MAC ancora presente:

Effettua le seguenti operazioni:

1\. Riavvia il server in [modalità Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).

```bash
root@rescue:~# cat /mnt/etc/network/interfaces

# and how to activate them. For more information, see interfaces(5).
 
# The loopback network interface

  bridge-fd 0

  netmask  255.255.255.0
  bridge_ports none
  bridge_stp off
  bridge_fd 0
  post-up echo 1 > /proc/sys/net/ipv4/ip_forward

root@rescue:~# cat /mnt/var/log/messages | grep renamed
Aug  8 14:27:20 s22 kernel: [    1.527563] igb 0000:04:00.0 eno1: renamed from eth0
Aug  8 14:27:20 s22 kernel: [    1.550622] igb 0000:04:00.1 eno2: renamed from eth1

Aug  8 14:27:36 s22 kernel: [   90.444727] eth0: renamed from vethVMV0MH
Aug  8 14:27:40 s22 kernel: [   94.116739] eth0: renamed from vethQWYCXT
```

2\. Ricrea il file `70-persistent-net.rules` e aggiungi:

- Il nome dell'interfaccia di rete presente nel file `/mnt/etc/network/interfaces`.

```bash
root@rescue:~# cat /mnt/etc/udev/rules.d/70-persistent-net.rules
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", NAME="enp3s0f0"
root@rescue:~#
```

<a name="xenserver"></a>

### XenServer

Se riscontri un problema di connettività di rete (ad esempio, nessuna risposta al ping dopo la sostituzione della scheda madre), l'indirizzo MAC è configurato in modo statico e deve essere reimpostato.

Effettua le seguenti operazioni:

1\. Riavvia il server in [modalità Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode) e utilizza il comando `chroot`:

```bash
root@rescue:~# mount /dev/sda1 /mnt
root@rescue:~# mount -t proc /proc/ /mnt/proc/
root@rescue:~# mount -o bind /sys/ /mnt/sys/
root@rescue:~# mount -o bind /dev/ /mnt/dev/
root@rescue:~# mount -o bind /dev/pts/ /mnt/dev/pts/
root@rescue:~# chroot /mnt
```

2\. Modifica la configurazione esistente in modo che corrisponda ai nuovi parametri:

```bash
[root@rescue /]# xe-reset-networking --device=eth0 --mode=static --ip=xx.xx.xx.xx --netmask=255.255.255.0 --gateway=xx.xx.xx.xxx
```

3\. Ti verrà chiesto di rispondere alla domanda con "yes", quindi premi "Invio":

```bash
----------------------------------------------------------------------
!! WARNING !!
  
This command will reboot the host and reset its network configuration.
Any running VMs will be forcefully shutdown.
  
Before completing this command:
- Where possible, cleanly shutdown all VMs running on this host.
- Disable HA if this host is part of a resource pool with HA enabled.
----------------------------------------------------------------------
  
Your network will be re-configured as follows:
  
Management interface:   eth0
IP configuration mode:  static
IP address:             xx.xx.xx.xx
Netmask:                255.255.255.0
Gateway:                xx.xx.xx.xx
Pool master's address:  xx.xx.xx.xx
```

<a name="esxi"></a>

### ESXi

Dopo la sostituzione della scheda madre, non è possibile modificare i nuovi indirizzi MAC nel file `esxi.conf` con gli strumenti integrati nella modalità Rescue.
Sarà quindi necessario intervenire manualmente.

#### Versione 7.0 o successiva

La procedura descritta di seguito riguarda solo le **versioni 7.0 o successive**. A partire da questa versione, il file state.tgz è crittografato.
Reimposta la rete dal menu Direct Console tramite il tuo KVM o IPMI.

Fai riferimento allo screenshot qui sotto:

<img className="thumbnail" alt="reset_network" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/restore.png" loading="lazy" />

#### Versione 6.7 o precedente

La procedura descritta di seguito riguarda solo le **versioni 6.7 o precedenti**.

1\. Riavvia il server in [modalità Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode) per montare la partizione `/`:

```bash
root@rescue:~# mount /dev/sdaX /mnt/
```

2\. Effettua un backup del file `state.tgz`

```bash
root@rescue:~# ls /mnt/state.tgz
root@rescue:~# cp /mnt/state.tgz /mnt/state.tgz.`date +%s`
```

3\. Crea un ambiente di lavoro:

```bash
root@rescue:~# mkdir /home/ovh/esxi
root@rescue:~# WORKINGDIR=/home/ovh/esxi
root@rescue:~# cd $WORKINGDIR
```

4\. Estrai il contenuto di `state.tgz` in `$WORKINGDIR`, quindi estrai il contenuto di `local.tgz`.<br/>
5\. Modifica il file `esx.conf` ottenuto:

```bash
root@rescue:/home/ovh/esxi# tar xf /mnt/state.tgz -C $WORKINGDIR
root@rescue:/home/ovh/esxi# tar xf /home/ovh/esxi/local.tgz -C $WORKINGDIR
root@rescue:/home/ovh/esxi# vim etc/vmware/esx.conf
```
6\. Individua e modifica l'indirizzo MAC di `vmkernelnic`:

```bash
/net/vmkernelnic/child[0000]/mac = "XX:XX:XX:XX:XX:XX"
```

7\. Identifica l'interfaccia su cui è utilizzato l'indirizzo IP principale:

```bash
/net/vswitch/child[0000]/uplinks/child[0000]/pnic = "vmnicX"
```

8\. Aggiorna l'indirizzo MAC dell'interfaccia principale:

:::warning
Non modificare l'indirizzo MAC virtuale.

:::


```bash
/net/pnic/child[0001]/mac = "XX:XX:XX:XX:XX:XX"         <== Primary Interface Mac address
/net/pnic/child[0001]/virtualMac = "00:50:56:XX:XX:XX"  <== Virtual Mac
/net/pnic/child[0001]/name = "vmnic1"
```

:::warning
Se è presente un'interfaccia vRack, ricordati di modificare anche il suo indirizzo MAC.

:::


9\. Effettua un backup, quindi smonta la partizione `/`:

```bash
root@rescue:/home/ovh/esxi# tar -czf $WORKINGDIR/local.tgz etc/
root@rescue:/home/ovh/esxi# tar -czf /mnt/state.tgz local.tgz
root@rescue:/home/ovh/esxi# umount /mnt
```

#### Casi particolari

Verifica l'ordine delle dichiarazioni dei tuoi vmnicX. Ecco un esempio funzionante:

```bash
root@rescue:/home/ovh/esxi# cat etc/vmware/esx.conf | grep "/vmkdevmgr/pci"
/vmkdevmgr/pci/m00008901/alias = "vmhba0"
/vmkdevmgr/pci/m00008501/alias = "vmnic0"
/vmkdevmgr/pci/m00008502/alias = "vmnic1"
```

<a name="windows"></a>

### Windows (Hyper-V)

Dopo la sostituzione della scheda madre, il server non è raggiungibile finché non modifichi manualmente gli indirizzi MAC tramite **Gestione dispositivi**.

Esistono 2 metodi:

#### Tramite IPMI/KVM

1\. Accedi come amministratore dall'interfaccia [IPMI/KVM](/guides/bare-metal-cloud/dedicated-servers/ipmi).<br/>
2\. Apri l'utilità <code className="action">Esegui</code> (tasto logo Windows + <code className="action">R</code>), quindi, tramite il prompt `run`, esegui il comando `devmgmt.msc`:

<img className="thumbnail" alt="win_device_manager" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_device_manager_edited.png" loading="lazy" />

3\. Apri <code className="action">Network adapters</code> e seleziona l'adattatore corrispondente a `eth0`.<br/>
4\. Clicca con il tasto destro su <code className="action">Properties</code> > <code className="action">Advanced</code>.<br/>
5\. Individua `Locally Administered Address`.<br/>
6\. Inserisci il nuovo valore dell'indirizzo MAC (solo cifre, senza spazi).

<img className="thumbnail" alt="win_advanced" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_advanced_edited.png" loading="lazy" />

#### Tramite WinPE

1\. Riavvia il server in modalità `WinPE`.<br/>
2\. Esegui il comando `regedit` tramite il prompt dei comandi `run`.<br/>
3\. Carica il registro locale tramite quello disponibile in `WinPE`, quindi clicca su <code className="action">HKEY_LOCAL_MACHINE</code>:

<img className="thumbnail" alt="win_regedit_1" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_1_edited.png" loading="lazy" />

4\. Clicca quindi su <code className="action">Load Hive...</code>.

<img className="thumbnail" alt="win_regedit_2" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_2_edited.png" loading="lazy" />

:::info
Per impostazione predefinita, ti troverai nella struttura di WinPE.
Ricordati di spostarti sull'unità `C:\`.

:::


5\. Individua il registro `SYSTEM`.

<img className="thumbnail" alt="win_load" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_load_edited.png" loading="lazy" />

6\. Ti verrà chiesto di inserire un nome. Ad esempio, puoi scegliere `OVH_TEST`.

7\. Individua il valore del registro seguente:

```bash
"HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Class\{4D36E972-E325-11CE-BFC1-08002BE10318}"
```

:::warning
Finché sei in WinPE, il valore `CurrentControlSet` dovrebbe essere uguale a `CurrentSet001`.

:::


Dovresti vedere diverse sottochiavi con nomi come questi: 0000, 0001, ecc.

8\. Clicca su ciascuna sottochiave per verificare il valore `DriverDesc`, che deve corrispondere alla tua interfaccia di rete.
Puoi verificare il nome della tua interfaccia da un terminale con il seguente comando:

```bash
ipconfig /all
```

9\. Cerca le voci di registro `NetworkAddress` nel pannello di destra e sostituisci il valore con quello del nuovo indirizzo MAC. Se questa voce non esiste, clicca con il tasto destro in un'area vuota per creare un valore di tipo `String` con il nome `NetworkAddress`.

<img className="thumbnail" alt="win_regedit_3" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_3_edited.png" loading="lazy" />

10\. Per applicare le modifiche recenti è necessario scaricare il registro. Clicca su OVH_TEST (creato in precedenza), poi su <code className="action">File</code> (in alto a sinistra) e seleziona <code className="action">Unload hive...</code>.

<a name="network-interface"></a>

### Individuare il nome delle interfacce di rete

Dopo la sostituzione della scheda madre, il server non è raggiungibile perché il controller delle interfacce di rete è stato rinominato dal sistema operativo.

1\. Riavvia il server in [modalità Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode), monta la partizione `/` e utilizza quindi il comando `chroot`:

```bash
root@rescue:~# mount /dev/my_disk /mnt
root@rescue:~# for i in /dev /dev/pts /proc /sys; do mount -B $i /mnt$i; done
root@rescue:~# chroot /mnt
```

2\. Verifica se le interfacce sono state modificate. Controlla nei log `var/log/messages` o `var/log/kern.log` se l'interfaccia è stata rinominata:

```bash
Oct  9 22:25:49 node1 kernel: [    5.479916] ixgbe 0000:03:00.1 eno4: renamed from eth1
Oct  9 22:25:49 node1 kernel: [    5.504285] ixgbe 0000:03:00.0 eno3: renamed from eth0
```

3\. Verifica il file di configurazione `/mnt/etc/udev/rules.d/70-persistent.-net.rules` e sostituisci i nuovi valori (indirizzi MAC), se necessario:

```bash
root@rescue:~# cat /mnt/etc/udev/rules.d/70-persistent-net.rules
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", ATTR{dev_id}=="0x0", ATTR{type}=="1", KERNEL=="eth*", NAME="public"
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", ATTR{dev_id}=="0x0", ATTR{type}=="1", KERNEL=="eth*", NAME="private"
```

4\. Accedi alla directory `/boot/grub/` e crea un backup del file `grub.cfg`.
5\. Modifica il file `/etc/default/grub` e cambia la riga che inizia con `GRUB_CMDLINE_LINUX` per ottenere quanto segue:

```bash
GRUB_CMDLINE_LINUX="net.ifnames=0 biosdevname=0"
```

6\. Esegui il comando:

```bash
root@rescue:~# grub-mkconfig -o /boot/grub/grub.cfg
```

7\. Esci dall'ambiente `chroot` con il comando `exit` e smonta tutte le partizioni:

```bash
root@rescue:~# umount /mnt/sys
root@rescue:~# umount /mnt/proc
root@rescue:~# umount /mnt/dev/pts
root@rescue:~# umount /mnt/dev
root@rescue:~# umount /mnt
```

#### Tramite il BIOS

- Caso d'uso: il sistema installato (in questo caso CentOS 6) non è più avviabile dopo la sostituzione del disco (nessuna voce EFI è visibile nel BIOS).

1\. Riavvia il server per accedere al menu del BIOS.

La *prima sequenza* consiste nel rigenerare i file necessari per rendere nuovamente operativa la partizione:

- Accedi al menu `boot` del tuo BIOS:
    - Scegli <code className="action">Add New Boot Option</code>.
    - Scegli il percorso della partizione <code className="action">Path for boot option</code> e seleziona il file system che contiene la partizione di avvio.
    - Seleziona il file `EFI\centos6\bootx64.efi`, quindi scegli <code className="action">Create</code>.
