## Obiettivo

Questa guida ti mostra come attivare il trasferimento dei log del tuo server dedicato OVHcloud verso Logs Data Platform (LDP), una piattaforma che ti aiuta a memorizzare, archiviare, interrogare e visualizzare i tuoi log.

Per saperne di più su Logs Data Platform prima di leggere questa guida, consulta la [guida introduttiva a Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/introduction).

**In questa guida imparerai a:**

- Consultare i log del tuo server dedicato in tempo reale.
- Creare un abbonamento che trasferisce questi log verso un flusso di dati Logs Data Platform.
- Interrogare e visualizzare i log trasferiti.
- Gestire ed eliminare i tuoi abbonamenti.

:::info
I log descritti in questa guida provengono dalle operazioni che OVHcloud esegue sul tuo server: **installazione del sistema operativo**, **avvio di rete** e **configurazione di rete**. **Non** si tratta dei log di sistema prodotti dal sistema operativo una volta in funzione.

Per centralizzare i log prodotti dal tuo sistema operativo, consulta la guida "[Inviare i log Linux a Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/log-linux)".
:::

## Glossario

- **Logs Data Platform:** una piattaforma di gestione dei log completamente gestita e protetta da OVHcloud. Per maggiori informazioni, consulta la pagina di presentazione della soluzione [Logs Data Platform](/links/manage-operate/ldp).
- **Flusso di dati (Data Stream):** una partizione logica di log che crei in un account LDP e che utilizzi per acquisire, visualizzare o interrogare i tuoi log. Più sorgenti possono essere memorizzate nello stesso flusso di dati, che costituisce l'unità con cui si definiscono una pipeline di log (politica di conservazione, archiviazione, streaming live, ecc.), i diritti di accesso e le politiche di avviso.
- **Trasferimento dei log:** funzionalità integrata in un prodotto OVHcloud che permette di acquisire i log dei suoi servizi in un *flusso di dati* di un account LDP appartenente allo stesso account OVHcloud. È necessario attivarla per ciascun servizio.
- **Abbonamento al trasferimento dei log:** quando attivi il trasferimento dei log per un determinato servizio OVHcloud verso un determinato *flusso di dati* LDP, viene creato un *Abbonamento* collegato al *flusso di dati*, che potrai poi gestire.

## Prerequisiti

- Disporre di un account Logs Data Platform (LDP) con almeno un *flusso di dati* attivo configurato. Questa guida ti accompagna in tutti i passaggi necessari: [Guida rapida di Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start).
    - Se non conosci tutte le possibilità di configurazione di un *flusso di dati* LDP, creane uno nuovo con le opzioni predefinite (indicizzazione e WebSocket attivati, archiviazione a lungo termine disattivata) per seguire questa guida.
- Disporre di un [server dedicato OVHcloud](/guides/bare-metal-cloud/dedicated-servers/getting-started-with-dedicated-server) operativo.
- L'account LDP e il server dedicato devono appartenere allo stesso account OVHcloud.

## Concetti e limiti

**Quali sono i log di un server dedicato?**

I log trasferiti tracciano le operazioni eseguite da OVHcloud sul tuo server: installazione del sistema operativo, avvio di rete e configurazione di rete.

Il trasferimento dei log è disponibile su tutte le gamme di server dedicati.

### Tipi di log

I log sono raggruppati per *tipi* e ogni tipo richiede un abbonamento distinto. Un server dedicato espone i seguenti tipi:

| Tipo | Nome visualizzato | Descrizione |
|------|-------------|-------------|
| `install` | Operating system installation logs | Dettagli dell'installazione del sistema operativo sul tuo server. |
| `netboot` | Network boot logs | Invio dello script di avvio iPXE al tuo server quando si avvia tramite la rete (disco rigido, rescue, installer, ecc.). |
| `network` | Network configuration logs | Operazioni di rete eseguite da OVHcloud sul tuo server: Additional IP, MAC virtuali, vRack, OVHcloud Link Aggregation (OLA) e politiche di banda. |

Puoi recuperare l'elenco dei tipi disponibili sul tuo server con la seguente chiamata API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/kind"} />

Per ottenere il dettaglio di un tipo, compresi i campi aggiuntivi che restituisce, utilizza la seguente chiamata API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/kind/\{name\}"} />

### Contenuto dei log

Oltre ai campi comuni a tutti i log acquisiti da Logs Data Platform, ogni tipo restituisce i seguenti campi.

#### Tipo `install`

| Nome del campo | Descrizione | Tipo di dato |
|--------------|-------------|----------------|
| `level` | Livello di criticità della voce di log, secondo i valori di gravità syslog standard: `2` (critical), `6` (info). | Number |
| `os` | Sistema operativo installato sul server. | String |
| `serviceName` | Nome interno del tuo server, nel formato `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Fase in corso dell'operazione: `os-install-start`, `os-install-failed` o `os-install-ok`. | String |

#### Tipo `netboot`

| Nome del campo | Descrizione | Tipo di dato |
|--------------|-------------|----------------|
| `level` | Livello di criticità della voce di log, secondo i valori di gravità syslog standard: `2` (critical), `6` (info). | Number |
| `serviceName` | Nome interno del tuo server, nel formato `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Risultato della richiesta dello script di avvio: `ipxe-request-ok` o `ipxe-request-error`. | String |

#### Tipo `network`

| Nome del campo | Descrizione | Tipo di dato |
|--------------|-------------|----------------|
| `level` | Livello di criticità della voce di log, secondo i valori di gravità syslog standard: `6` (info). | Number |
| `serviceName` | Nome interno del tuo server, nel formato `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Fase in corso dell'operazione, nel formato `<operation>-doing` (avviata) o `<operation>-ok` (riuscita). Operazioni: `add_ipfo`, `remove_ipfo`, `add_vmac`, `remove_vmac`, `vrack-add`, `vrack-remove`, `ola-group`, `ola-ungroup`, `qos-apply`. | String |

:::info
L'elenco dei valori di `status` riportato sopra corrisponde allo stato attuale ed è destinato a evolvere.
:::

Per i campi comuni a tutti i log, consulta la guida "[Convenzione di denominazione dei campi](/guides/manage-and-operate/observability/logs-data-platform/field-naming-conventions)".

## Procedura

L'attivazione del trasferimento è gratuita, ma l'utilizzo del servizio Logs Data Platform ti viene fatturato secondo la tariffa standard. Per conoscere le tariffe di LDP, consulta la pagina di presentazione di [Logs Data Platform](/links/manage-operate/ldp).

### Attivare il trasferimento dei log

<Tabs>
<Tab label="Dalla console OVHcloud">

Nella console OVHcloud, apri l'universo <code className="action">Bare Metal Cloud</code>, accedi a <code className="action">Server dedicati</code> e seleziona il server di cui vuoi trasferire i log.

Clicca sulla scheda <code className="action">Log</code>.

La scheda contiene:

- un menu a tendina **Tipo di log**, in cui selezioni il tipo di log da consultare o trasferire (`netboot`, `network` o `install`);
- la sezione **Flusso in diretta**, che mostra in tempo reale i log del tuo server per il tipo selezionato;
- la sezione **Logs**, che elenca i tuoi abbonamenti attivi e ti permette di crearne di nuovi.

Per trasferire i tuoi log verso Logs Data Platform, seleziona il tipo di log, quindi clicca su <code className="action">Add subscription</code> nella sezione **Logs**.

Nella finestra **Abbonarsi a un flusso**, se disponi di più servizi Logs Data Platform, selezionane uno nel menu a tendina **Servizio Logs Data Platform** (se hai un solo servizio, viene selezionato automaticamente). Seleziona poi il flusso di dati di destinazione nel menu a tendina **Flusso** e clicca su <code className="action">Abbonati</code>.

Se il tuo account non dispone ancora di un servizio Logs Data Platform, la finestra lo segnala e propone un pulsante <code className="action">Ordina Logs Data Platform</code>. Se il tuo servizio non ha ancora un flusso, creane prima uno in Logs Data Platform (consulta la [guida rapida di Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start)).

Solo i log generati **dopo** la creazione dell'abbonamento vengono inviati al tuo flusso di dati.

Per maggiori informazioni su OVHcloud Service Logs, comune a tutti i prodotti OVHcloud compatibili, consulta la guida "[Introduzione a OVHcloud Service Logs con Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/service-logs)".

</Tab>
<Tab label="API OVHcloud">

Definisci, in uno dei tuoi account LDP, il *flusso di dati* di destinazione verso cui vuoi trasferire i tuoi log. L'attivazione del trasferimento crea un abbonamento per questo identificativo di flusso.

#### Step 1 - Recuperare il flusso di dati di destinazione (e il relativo identificativo)

Elenca i flussi di dati del tuo account Logs Data Platform (inserisci l'identificativo LDP nel formato `ldp-xx-xxxx` nel campo `serviceName`):

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/output/graylog/stream"} />

Ottieni il dettaglio di un flusso di dati:

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/output/graylog/stream/\{streamId\}"} />

#### Step 2 - Creare l'abbonamento

Utilizza la seguente chiamata API per creare un abbonamento:

<Api version="v2" section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/log/subscription"} />

:::info
Sostituisci:

- `serviceName`: il nome interno del tuo server dedicato, nel formato `nsxxxxx.ip-xx-xx-xx.eu`. È indicato nell'elenco dei server dedicati o nella pagina del server nella console OVHcloud, oppure si ottiene con la seguente chiamata API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server"} />
:::

La richiesta POST richiede un payload contenente:

- `kind`: il tipo di log che vuoi trasferire (`install`, `netboot` o `network`). Consulta la sezione "[Tipi di log](#tipi-di-log)" più sopra.
- `streamId`: il flusso di dati di destinazione del tuo account LDP verso cui trasferire i log del tuo server dedicato.

```shell
POST /dedicated/server/{serviceName}/log/subscription
{
  "kind": "install", // Uno dei tipi: install, netboot, network.
  "streamId": "198ef9d5-c320-4000-8bee-236623da5b80" // Lo streamID dello Stream di destinazione.
}
```

Otterrai un `operationId` in risposta:

```shell
{
  "operationId": "f550aa1c-89ab-4b1a-81ae-4fba4959966f",
  "serviceName": "ldp-xx-xxxx"
}
```

Puoi utilizzare l'`operationId` per recuperare il `subscriptionId` ai fini di una gestione successiva con la seguente chiamata API:

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/operation/\{operationId\}"} />

Una volta terminata l'operazione, puoi anche recuperare gli abbonamenti con la seguente chiamata API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/subscription"} />

Una volta ottenuto il `subscriptionId`, puoi consultarne il dettaglio con la seguente chiamata API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/subscription/\{subscriptionId\}"} />

```shell
GET /dedicated/server/{serviceName}/log/subscription/{subscriptionId}

{
  "createdAt": "2026-08-31T07:42:50.645Z",
  "kind": "string",
  "resource": {
    "name": "string",
    "type": "string"
  },
  "serviceName": "string",
  "streamId": "string",
  "subscriptionId": "198efa11-f150-4000-8e8d-871b1e482b80",
  "updatedAt": "2026-08-31T07:42:50.645Z"
}
```

### Come utilizzare i log del tuo server dedicato

I tuoi log vengono ora acquisiti e memorizzati nel tuo flusso di dati Logs Data Platform. Puoi interrogarli e creare dashboard nell'interfaccia Web di Graylog.

- Recupera il nome utente del tuo account Logs Data Platform (ad esempio `logs-xxxx`) e la relativa password. Nella console OVHcloud, apri <code className="action">Osservabilità</code>, clicca su <code className="action">Gestione del servizio</code> e seleziona il tuo servizio Logs Data Platform: il nome utente è indicato nella riga **Nome utente LDP** della sezione **Informazioni generali** (solo per i servizi che non utilizzano OVHcloud IAM). La password è quella che hai definito per questo account. Consulta la guida "[Guida rapida di Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start)".
- Apri l'interfaccia Web di Graylog. Puoi accedervi dalle dashboard Graylog elencate in <code className="action">Osservabilità</code> > <code className="action">Dashboard</code> della console OVHcloud, oppure tramite il tuo punto di accesso, a seconda della regione del tuo account (ad esempio, alla regione di Gravelines corrisponde `https://gra1.logs.ovh.com/`).
- Accedi a Graylog con il nome utente e la password di Logs Data Platform.
- Effettua le tue ricerche nei log del flusso di dati del tuo account Logs Data Platform. Consulta la documentazione [Search Syntax Reference](https://go2docs.graylog.org/current/making_sense_of_your_log_data/search_syntax_reference.htm) per i dettagli sulla sintassi di ricerca.

Per maggiori informazioni sull'utilizzo dei tuoi log con Logs Data Platform, in particolare sulla configurazione degli avvisi, sulla consultazione dei log in tempo reale tramite WebSocket, sulla creazione di visualizzazioni con OpenSearch Dashboards, sull'integrazione con l'API OpenSearch e sulla connessione a Grafana, consulta la [guida introduttiva a Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/introduction).

### Come gestire i tuoi abbonamenti

In qualsiasi momento puoi recuperare gli abbonamenti collegati al tuo flusso di dati Logs Data Platform e disattivare il trasferimento annullando il tuo abbonamento sullo stream, in modo che quest'ultimo non riceva più i log del tuo server dedicato.

Questa operazione non elimina i log memorizzati prima dell'annullamento dell'abbonamento: i dati memorizzati in un flusso di dati sono immutabili, a meno che tu non elimini il flusso nella sua interezza.

Nella console OVHcloud, apri la scheda <code className="action">Log</code> del tuo server, individua l'abbonamento tramite il suo Stream ID nella sezione **Logs**, quindi clicca sull'icona del cestino nella relativa riga. L'abbonamento viene eliminato immediatamente, senza finestra di conferma.

Per eliminare il tuo abbonamento tramite API, utilizza la seguente chiamata:

<Api version="v2" section="/dedicated/server" method="DELETE" route={"/dedicated/server/\{serviceName\}/log/subscription/\{subscriptionId\}"} />
