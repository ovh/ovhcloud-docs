## Obiettivo

La tecnologia OVHcloud Link Aggregation (OLA) è stata progettata dai team OVHcloud per aumentare la disponibilità dei server e potenziare le connessioni di rete. L’attivazione dell’opzione permette di aggregare in pochi click le schede di rete e rendere i collegamenti ridondati in modo che, in caso di malfunzionamenti, il traffico venga reindirizzato automaticamente verso il collegamento disponibile.<br/>
L'aggregazione utilizza il protocollo LACP (Link Aggregation Control Protocol), definito dallo standard IEEE 802.3ad.

**Questa guida ti mostra come configurare il servizio OLA nella console OVHcloud.**

## Prerequisiti

- Disporre di un [server dedicato OVHcloud](/links/bare-metal/bare-metal) di gamma Advance, Scale o High Grade
- Disporre di un sistema operativo / Hypervisor che supporta il protocollo di aggregazione 802.3ad (LACP)

[[cpnav:baremetal-dedicated-servers-console]]

## Procedura

:::warning
La configurazione OLA viene eseguita su tutte le interfacce di rete. Esse formeranno un aggregato del tipo "aggregazione privata".

Con l'implementazione di OLA, l'IP pubblico non sarà più accessibile.

:::


### Configurare OLA nella console OVHcloud

Per iniziare la configurazione di OLA, apri la scheda <code className="action">Connectivity</code> nella pagina di gestione del tuo server.

Nella sezione **OVHcloud Link Aggregation (OLA)**, clicca su <code className="action">Configure OLA</code>.

Nel pannello **Configure OLA aggregation**, inserisci un nome per la tua aggregazione di link nel campo **Name the interface**.

Sotto questo campo, due tabelle confrontano la tua configurazione prima e dopo l'aggregazione:

- **Your current network interface**: la configurazione attuale delle tue interfacce di rete;
- **Your network interface after activation**: la configurazione simulata delle tue interfacce di rete aggregate.

:::warning
Le tue interfacce di rete verranno deconfigurate e il server perderà la connettività durante l'applicazione dell'aggregazione. Successivamente, dovrai configurare l'aggregato (bond) nel tuo sistema operativo dalla console KVM (consulta la guida "[Come utilizzare la console IPMI con un server dedicato](/guides/bare-metal-cloud/dedicated-servers/ipmi)" e le guide per sistema operativo qui sotto), altrimenti la configurazione resterà incompleta.
:::

Dopo aver verificato che la configurazione dell'aggregazione soddisfi i requisiti di rete, clicca su <code className="action">Aggregate</code> per procedere.

Questa operazione potrebbe richiedere qualche minuto. Lo step successivo consisterà nella configurazione delle interfacce del sistema operativo come NIC bond o NIC team. Per conoscere la procedura da seguire, consulta la nostra documentazione disponibile relativa ai sistemi operativi più diffusi:

- [Come configurare l'aggregazione di link LACP su Debian da 9 a 11 (ifupdown)](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-ifupdown).
- [Come configurare il NIC Teaming per OVHcloud Link Aggregation (OLA) su Windows Server 2019](/guides/bare-metal-cloud/dedicated-servers/ola-enable-w2k19).
- [Come configurare l'aggregazione di link LACP su SLES 15](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-sles15).
- [Come configurare l'aggregazione di link LACP su Debian 12 o versioni successive / Ubuntu 24.04 o versioni successive (Netplan)](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-netplan).

### Verifica dello stato OLA

Puoi verificare lo stato della tua aggregazione di link OVHcloud Link Aggregation (OLA) nella scheda <code className="action">Connectivity</code> della pagina di gestione del tuo server. Nella sezione **OVHcloud Link Aggregation (OLA)**, la riga **OLA** indica lo stato e la riga **Mode** il tipo di aggregazione.

Le combinazioni possibili sono le seguenti:

- **Available**, modalità **Default**: OLA è supportato ma non è configurato.
- **Active**, modalità **Full private**: OLA è attivato; tutte le interfacce fisiche sono aggregate in un unico collegamento privato per l'utilizzo con la vRack.
- **Available**, modalità **Double LAG**: le interfacce sono suddivise in due aggregati (uno pubblico, uno privato) secondo una disposizione diversa da quella predefinita del server.
- **Aggregazione in corso...** o **Ripristino in corso...**: è in corso l'applicazione di una modifica OLA; le righe **Mode** e **Virtual interfaces** mostrano un trattino fino al termine dell'operazione.

Se OLA non è supportato su questo modello di server dedicato, la sezione **OVHcloud Link Aggregation (OLA)** mostra **OLA non incluso** e la riga **OLA** della sezione **Connettività** della scheda <code className="action">Panoramica</code> del server indica **Unavailable**.

:::info
Sui server Scale e High Grade, la disposizione predefinita raggruppa già le quattro interfacce in un aggregato pubblico e un aggregato privato; la console la mostra come **Available**, modalità **Default**.

:::

### Ripristina OLA ai valori predefiniti

Per ripristinare OLA ai valori predefiniti, apri la scheda <code className="action">Connectivity</code> e clicca su <code className="action">Reset</code> nella sezione **OVHcloud Link Aggregation (OLA)**. Questo pulsante è visibile solo quando OLA è attivo in modalità **Full private**. Le interfacce vengono deconfigurate e il server perde la connettività durante il ripristino. Clicca quindi su <code className="action">Confirm</code> nella finestra **Reset OVHcloud Link Aggregation**.

Questa operazione potrebbe richiedere qualche minuto.
