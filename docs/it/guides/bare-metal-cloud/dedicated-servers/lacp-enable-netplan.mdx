## Obiettivo

La tecnologia LACP (Link Aggregation Control Protocol) è progettata per aumentare la disponibilità del tuo server e migliorare l'efficienza delle tue connessioni di rete. Puoi aggregare le tue schede di rete e rendere ridondanti i tuoi link di rete. Ciò significa che, se un link si interrompe, il traffico viene reindirizzato automaticamente verso un altro link disponibile. Grazie all'aggregazione, anche la larghezza di banda disponibile raddoppia.

**Questa guida ti mostra come associare le tue interfacce per utilizzarle per l'aggregazione di link su Debian 12 o versioni successive / Ubuntu 24.04 o versioni successive (configurazione Netplan).**

:::warning
Anche se le immagini Debian 12 (o versioni successive) fornite da OVHcloud utilizzano `Netplan` di default, esistono due eccezioni principali in cui viene utilizzato `ifupdown` (/etc/network/interfaces):

- **Modalità rescue**: pur essendo basata su Debian 12, la modalità rescue si appoggia all'utility `ifupdown`.
- **Immagini personalizzate**: le installazioni Debian effettuate con la tua immagine potrebbero utilizzare ancora `ifupdown` per la configurazione di rete.

Se vuoi configurare l'aggregazione di link in modalità rescue, o su un OS personalizzato basato su `ifupdown`, consulta invece [questa guida](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-ifupdown).

:::

## Procedura

:::info
I valori (indirizzi MAC, indirizzi IP, ecc.) indicati nelle configurazioni e negli esempi seguenti sono forniti a titolo di esempio. Sostituiscili ovviamente con i tuoi.

:::


### Recupero degli indirizzi MAC

Apri la scheda <code className="action">Connectivity</code> del tuo server nella console OVHcloud e prendi nota degli indirizzi MAC di ciascuna interfaccia (pubblica/privata). Si trovano in **Aggregated interface composition**, nelle sezioni **Public interface** e **Interfaccia privata (vRack)**, con i nomi **NIC #1** e **NIC #2**.

:::info
L'interfaccia **pubblica principale** gestisce la connettività pubblica nella configurazione predefinita. Il suo indirizzo MAC corrisponde al valore `aggregationFallback` dell'interfaccia `public`, che puoi recuperare con la rotta API qui di seguito:

<Api version="v1" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/networking"} />

:::


Ora che sai quali indirizzi MAC sono associati a ciascun tipo di interfaccia (pubblica/privata), devi recuperare i nomi delle interfacce.

### Recupero dei nomi delle interfacce

:::info
Se perdi la connessione di rete al tuo server, segui i passaggi "**Aprire un KVM**" di [questa guida](/guides/bare-metal-cloud/dedicated-servers/ipmi).

:::


Per recuperare i nomi delle interfacce, esegui il seguente comando:

```bash
ip a
```

:::info
Questo comando mostrerà numerose interfacce. In caso di difficoltà nel determinare quali sono le tue interfacce fisiche, considera che l'indirizzo IP pubblico del server è associato di default alla prima interfaccia.

:::

Una volta determinati i nomi delle tue interfacce, puoi configurare l'aggregazione delle interfacce nel sistema operativo.

### Configurazione con IP fisso

Sostituisci il contenuto di `/etc/netplan/50-cloud-init.yaml` con quanto segue:

```yaml
network:
    version: 2
    ethernets:
        ens22f0np0:
            match:
                macaddress: a1:b2:c3:d4:e5:c6
        ens22f1np1:
            match:
                macaddress: a1:b2:c3:d4:e5:c7
        ens33f0np0:
            match:
                macaddress: a1:b2:c3:d4:e5:d6
        ens33f1np1:
            match:
                macaddress: a1:b2:c3:d4:e5:d7
    bonds:
        bond0:
            # Indirizzo MAC dell'interfaccia pubblica principale del server
            macaddress: a1:b2:c3:d4:e5:c6
            accept-ra: false
            addresses:
                - 203.0.113.1/32
                - 2001:db8:1:1b00:203:0:112:0/56
            routes:
                - on-link: true
                  to: default
                  via: 100.64.0.1
                - on-link: true
                  to: default
                  via: fe80::1
            nameservers:
                addresses:
                - 213.186.33.99
                - 2001:41d0:3:163::1
            interfaces:
                - ens22f0np0
                - ens22f1np1
            parameters:
                mode: 802.3ad
                lacp-rate: fast
                transmit-hash-policy: layer3+4
        # Facoltativo: configurazione di un aggregato privato
        bond1:
            # Indirizzo MAC della prima interfaccia privata
            macaddress: a1:b2:c3:d4:e5:d6
            accept-ra: false
            interfaces:
                - ens33f0np0
                - ens33f1np1
            parameters:
                mode: 802.3ad
                lacp-rate: fast
                transmit-hash-policy: layer3+4
```

### Applicazione della configurazione

:::info
Il comando `netplan try` non può essere utilizzato durante la configurazione degli aggregati.

:::


Applica la configurazione con il seguente comando:

```bash
sudo netplan apply
```

Potrebbero trascorrere alcuni secondi prima che gli aggregati siano operativi.
