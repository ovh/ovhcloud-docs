**Ti invitiamo a leggere questa guida per intero e con particolare attenzione: potresti essere interessato da questa modifica se richiedi l'installazione di un sistema operativo su un nuovo server dedicato o la reinstallazione del sistema operativo su uno dei tuoi server dedicati.**

Sebbene questa pagina illustri la dismissione dei template personalizzati per l'installazione del sistema operativo (OS) dei server dedicati e il suo impatto, puoi stare tranquillo: **non si perde nessuna funzionalità**.
Dopo questa dismissione, infatti, potrai continuare a installare sistemi operativi con lo **stesso livello di personalizzazione di prima**. Inoltre, i clienti che utilizzano direttamente l'API beneficeranno di **una chiamata API più semplice**.

## Obiettivo

Questa pagina fornisce informazioni chiave sul piano di dismissione dei template personalizzati per l'installazione dell'OS dei server dedicati. Offre inoltre consigli utili per i clienti che utilizzano la console OVHcloud o lo Spazio Cliente So you Start o Kimsufi. Infine, presenta i vantaggi della nuova chiamata API rispetto alla chiamata API obsoleta.

## Contesto <a id="context"></a>

OVHcloud si rinnova costantemente per adattare le proprie offerte a una crescente domanda di resilienza. Per raggiungere questo obiettivo, **tutti i template personalizzati di installazione dell'OS per i server dedicati** saranno eliminati il **7 ottobre 2025**.

Questa funzionalità permetteva di avviare installazioni dell'OS su un server dedicato utilizzando un template personalizzato contenente i seguenti elementi:

- sistema operativo da installare,
- schema di partizionamento,
- configurazione del RAID hardware,
- nome host,
- chiave SSH pubblica,
- script di post-installazione.

Per semplificare l'installazione degli OS sui server dedicati e la comunicazione di questa modifica, è stata creata una nuova chiamata API: `POST /dedicated/server/{serviceName}/reinstall`. Questa chiamata API sostituisce la vecchia route: `POST /dedicated/server/{serviceName}/install/start`. La vecchia route permetteva di avviare un'installazione dell'OS a partire da un template OVHcloud **o da un template personalizzato**.

La vecchia route e il concetto di template personalizzato saranno dismessi. La nuova route permette infatti solo l'installazione dell'OS a partire da un template OVHcloud. Ti ricordiamo inoltre che il termine "template OVHcloud" (*OVHcloud template* in inglese) scomparirà progressivamente a favore del termine "sistema operativo" (o "OS", *Operating System*).

La dismissione dei template personalizzati avverrà in 2 fasi:

### Fase 1: 17 giugno 2025 <a id="step-1"></a>

- I clienti non potranno più **modificare** o **aggiungere** nuovi template personalizzati.
- I clienti che dispongono di uno o più template personalizzati e di almeno un servizio di server dedicato attivo riceveranno via e-mail informazioni tecniche dettagliate e personalizzate per migrare le loro richieste API verso la <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nuova route /reinstall</ApiLink>.

### Fase 2: 7 ottobre 2025 <a id="step-2"></a>

- I clienti non potranno più accedere ai propri template di installazione personalizzati.
- Tutti i dati relativi ai template di installazione personalizzati saranno eliminati.

I clienti potranno comunque ritrovare i dati nell'e-mail del 17 giugno 2025, poiché la documentazione personalizzata inviata è stata generata a partire dai dati dei template personalizzati alla data del 17 giugno 2025.

## Procedura <a id="instructions"></a>

La sezione seguente contiene informazioni specifiche in base alla tua situazione: se disponi di un account OVHcloud, So you Start o Kimsufi e se utilizzi abitualmente la console OVHcloud o l'API per installare gli OS sui tuoi server dedicati.

### Console OVHcloud, Spazio Cliente So you Start o Kimsufi <a id="ux"></a>

Il pulsante `Installa da uno dei tuoi template` è stato rimosso dall'assistente di installazione dell'OS dei server dedicati ad aprile 2025. Se utilizzavi questo pulsante, hai 3 possibilità a lungo termine:

- Continuare a utilizzare l'interfaccia Web (sconsigliato se intendi adottare una strategia di automazione): in questo caso è necessario applicare manualmente tutte le personalizzazioni nell'assistente ogni volta che esegui un'installazione dell'OS.
- Scrivere uno script che utilizzi l'API (consigliato per le automazioni, ma richiede competenze di programmazione): consulta la sezione [API OVHcloud, So you Start o Kimsufi](#api) qui sotto.
- Utilizzare la console API (un buon compromesso): utilizza la vecchia chiamata API fino al 17 giugno 2025, poi la nuova chiamata API con i payload che ti saranno forniti.

Anche se puoi già esplorare esempi e schemi della <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nuova route API /reinstall nella console API</ApiLink> e consultare la [documentazione pubblica](/guides/bare-metal-cloud/dedicated-servers/api-os-installation), ecco una soluzione temporanea che puoi seguire in attesa di ricevere i payload della nuova route API nell'e-mail del 17 giugno 2025.

#### Soluzione alternativa per gli account OVHcloud <a id="ux-ovh"></a>

Come indicato nella [documentazione dell'API OVHcloud](/guides/manage-and-operate/api/first-steps#accedi-alle-api-ovhcloud), nella <ApiLink>pagina delle API OVHcloud</ApiLink>:

- Clicca su `Authentication` in alto a sinistra.
- Clicca poi su `Login with OVHcloud SSO`.
- Inserisci le tue credenziali OVHcloud.
- Clicca sul pulsante `Authorize` per autorizzare le chiamate API da questo sito.

![API](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/login.png)

Esegui quindi la chiamata API per avviare un'installazione dell'OS a partire dal tuo template personalizzato:

- Seleziona `v1`.
- Scegli la sezione `/dedicated/server`.
- Cerca la chiamata API `POST /dedicated/server/{serviceName}/install/start` (puoi utilizzare il filtro).
- Nel campo `serviceName`, inserisci il nome del server dedicato su cui vuoi installare l'OS.
- Nel campo `REQUEST BODY` ("payload API"), inserisci il seguente contenuto JSON (in questo esempio supponiamo che "my-amazing-template" sia il nome del template personalizzato che vuoi installare):

```json
{
  "templateName": "my-amazing-template"
}
```

Se hai bisogno di elencare e visualizzare i dettagli dei tuoi template personalizzati, puoi farlo nella sezione `/me`, tramite le chiamate API di `/me/installationTemplate`.

:::danger
**Eseguire la chiamata API [POST /dedicated/server/\{serviceName\}/install/start](https://api.eu.ovhcloud.com/console/?section=%2Fdedicated%2Fserver&branch=v1#post-/dedicated/server/-serviceName-/install/start) su un server dedicato cancellerà tutti i suoi dati. UTILIZZA QUESTA CHIAMATA API CON CAUTELA.**
:::

Clicca quindi sul pulsante `Execute` per avviare l'installazione dell'OS.

![console API](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/screenshot-api-console-workaround.png)

Puoi tornare alla pagina della dashboard del server dedicato nella <ManagerLink to="/">console OVHcloud</ManagerLink> per seguire l'avanzamento dell'installazione dell'OS.

#### Soluzione alternativa per gli account So you Start o Kimsufi <a id="ux-sys-ks"></a>

Apri la [console API So you Start](https://eu.api.soyoustart.com/console/) o [quella di Kimsufi](https://eu.api.kimsufi.com/console/).

Clicca sul pulsante `Login` in alto a destra e inserisci le tue credenziali. Clicca poi su `Log in`. A questo punto sei autenticato sulla console API.

- Apri la sezione `/dedicated/server`.
- Cerca la chiamata API `POST /dedicated/server/{serviceName}/install/start`.
- Nel campo `serviceName`, inserisci il nome del server dedicato su cui vuoi installare l'OS.
- Nel campo `templateName`, inserisci il nome del template personalizzato che vuoi installare.

Se hai bisogno di elencare e visualizzare i dettagli dei tuoi template personalizzati, puoi farlo nella sezione `/me`, tramite le chiamate API di `/me/installationTemplate`.

:::danger
**Eseguire la chiamata API [POST /dedicated/server/\{serviceName\}/install/start](https://eu.api.soyoustart.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) (o [questa](https://eu.api.kimsufi.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) per Kimsufi) su un server dedicato cancellerà tutti i suoi dati. UTILIZZA QUESTA CHIAMATA API CON CAUTELA.**
:::

Clicca quindi sul pulsante `Execute` per avviare l'installazione dell'OS.

Puoi tornare alla pagina della dashboard del server dedicato nello [Spazio Cliente So you Start](https://eu.soyoustart.com/manager) o [Kimsufi](https://www.kimsufi.com/fr/manager) per seguire l'avanzamento dell'installazione dell'OS.

### Utilizzare le API OVHcloud, So you Start o Kimsufi <a id="api"></a>

Se utilizzi direttamente le chiamate API OVHcloud, So you Start o Kimsufi per avviare le installazioni dell'OS a partire da un template personalizzato, puoi continuare a utilizzare la chiamata API `POST /dedicated/server/{serviceName}/install/start` fino al **7 ottobre 2025**.
Tuttavia, a partire dal **17 giugno 2025** non sarà più possibile aggiungere o modificare i tuoi template personalizzati.

Anche se riceverai un'e-mail con tutti i dettagli sugli adattamenti dei payload API necessari per utilizzare la <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nuova chiamata API /reinstall</ApiLink>, puoi iniziare fin da ora a consultarne lo schema <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nella console API</ApiLink> (lo schema è lo stesso per OVHcloud, [So you Start](https://eu.api.soyoustart.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) e [Kimsufi](https://eu.api.kimsufi.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST)) e a leggerne la [documentazione pubblica](/guides/bare-metal-cloud/dedicated-servers/api-os-installation).

Nel tuo caso, la dismissione dei template personalizzati semplifica l'installazione degli OS sui server dedicati. La <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nuova chiamata API /reinstall</ApiLink> offre infatti tutte le personalizzazioni possibili che la vecchia chiamata API [POST /dedicated/server/\{serviceName\}/install/start](https://api.eu.ovhcloud.com/console/?section=%2Fdedicated%2Fserver&branch=v1#post-/dedicated/server/-serviceName-/install/start) non era in grado di fornire direttamente senza dover prima definire un template personalizzato in [/me/installationTemplate](https://api.eu.ovhcloud.com/console/?section=%2Fme&branch=v1#get-/me/installationTemplate).

Il confronto seguente ti dà un'idea della riduzione del numero di chiamate API ottenuta con la <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nuova chiamata API /reinstall</ApiLink> nel caso di una personalizzazione complessa che coinvolge il RAID hardware e un partizionamento personalizzato: da `4+n` chiamate (dove `n` rappresenta il numero di partizioni definite nello schema di partizionamento) a un'unica chiamata API.

![Confronto tra la vecchia e la nuova chiamata API](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/api-calls-comparison.png)

In questo modo puoi beneficiare di un'esperienza più fluida e intuitiva.
