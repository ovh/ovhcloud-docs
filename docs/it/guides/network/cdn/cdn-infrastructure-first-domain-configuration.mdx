## Obiettivo

Per iniziare a utilizzare il servizio Content Delivery Network (CDN) di OVHcloud, è necessario dichiarare i domini dalla console OVHcloud e configurare alcuni parametri che ne garantiscono un utilizzo ottimale.

**Questa guida ti mostra le operazioni da eseguire nella console OVHcloud per utilizzare la CDN OVHcloud e descrive alcune best practice di utilizzo.**

## Prerequisiti

- Usufruire della [Content Delivery Network (CDN) OVHcloud](https://www.ovhcloud.com/it/network/cdn/).
- Avere accesso alla gestione della zona DNS del dominio.

[[cpnav:network-cdn-console]]

## Procedura

### Aggiungi il dominio sulla CDN

Per prima cosa, è necessario aggiungere un sottodominio alla CDN in modo che possa accettare richieste HTTP(S) per questo dominio.

Apri la scheda <code className="action">Domini</code> e clicca su <code className="action">Aggiungi dominio</code>. Si apre la pagina **Configurazione guidata di un dominio**, che ti accompagna in quattro step:

<img className="thumbnail" alt="Scheda Domini di una CDN con il pulsante Aggiungi dominio" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/domains-tab.png" loading="lazy" />

1. **Nome del dominio**: inserisci il sottodominio da servire tramite la CDN, sotto forma di nome di dominio completo (ad esempio `www.example.com`), poi clicca su <code className="action">Successivo</code>.
2. **Origine (IPv4)**: inserisci l'indirizzo IPv4 del server di origine che ospita i tuoi file (il tuo *backend*), poi clicca su <code className="action">Successivo</code>.
3. **Certificato SSL**: scegli **Let's Encrypt** per ottenere automaticamente un certificato HTTPS gratuito, oppure **Senza SSL** per servire il dominio solo in HTTP (potrai aggiungere un certificato in seguito). Questo step non viene visualizzato se la tua CDN dispone già di un certificato. Per maggiori informazioni, consulta la nostra guida sul [funzionamento del certificato SSL sulla CDN](/guides/network/cdn/cdn-infrastructure-ssl-certificate).
4. **Conferma e distribuisci**: verifica il riepilogo, poi clicca su <code className="action">Distribuisci</code>.

<img className="thumbnail" alt="Configurazione guidata di un dominio, step Nome del dominio" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/guided-setup-step1.png" loading="lazy" />

La pagina mostra quindi l'avanzamento della distribuzione: creazione del dominio, configurazione dell'origine e, se l'hai scelto, provisioning del certificato SSL. Al termine della distribuzione, indica la destinazione verso cui deve puntare il record CNAME del tuo dominio (nella forma `<tuo dominio>.cdn.ovhcloud.com`, ad esempio `www.example.com.cdn.ovhcloud.com`). Copia questa destinazione: ti servirà nello step successivo. Clicca su <code className="action">Completato</code>. Il dominio appare quindi nella scheda <code className="action">Domini</code>, con la sua origine e il suo stato, e puoi iniziare a configurarlo.

<img className="thumbnail" alt="Fine della configurazione guidata di un dominio, con la destinazione CNAME" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/guided-setup-cname.png" loading="lazy" />

Per fare in modo che le richieste inviate passino correttamente per la nostra infrastruttura CDN, modifica la zona DNS del sottodominio in modo che un record CNAME punti verso questa destinazione.

:::warning
La configurazione del record CNAME è importante: permette il corretto funzionamento della funzione `Bypass`. Se utilizzi un record di tipo A, la CDN funzionerà ma il *bypass* non sarà più attivo.

:::

Se la zona DNS del tuo dominio è gestita da OVHcloud, aggiungi questo record CNAME alla zona dalla console OVHcloud, adattando il sottodominio alla tua configurazione: indica il tuo sottodominio (ad esempio `cdn`) e, come destinazione, il valore mostrato al termine della configurazione guidata. Per sapere come aggiungere un record, consulta la nostra guida per [modificare una zona DNS di OVHcloud](/guides/web-cloud/domains/dns-zone-edit).

 

### Verifica che un file sia salvato in cache
Per verificare che un file sia memorizzato nella cache, esegui questo comando:

```sh
curl -I http://sotto.dominio/
```

Viene restituito un risultato di questo tipo:

```bash
HTTP/1.1.200 OK
Date: Tue, 09 Jan 2018 10:30:57 GMT
Content-Type: text/plain
Last-Modified Fri, 29 Dec 2017 13:30:42 GMT
ETag W/"(5a464382-4ddf"
Expires: Wed, 09 Jan 2019 10:30:58 GMT
x-IPLB-Instance/: 5905
Vary: Accept-Encoding
X-CDN-Pop: rbx1
X-CDN-Pop-IP: 51.254.41.128/26
X-Cacheable Matched cache
Accept-Ranges: bytes
Connection: keep-alive
```

Se il tuo file si trova in cache, la risposta del comando conterrà la dicitura `Matched cache`.

Potrai inoltre visualizzare il punto di presenza (PoP) da cui è stato inviato il file (nel nostro esempio, *rbx1*).

Questa informazione è disponibile anche nel browser: su Firefox, ad esempio, si trova nella scheda `Rete` degli strumenti di sviluppo (F12). Cliccando sul file che vuoi verificare, visualizzerai la risposta HTTP e gli header.

### Prediligi l’utilizzo di un sottodominio specifico per la CDN al dominio principale

Aggiungere un record CNAME a un dominio principale non è possibile: questa restrizione è legata agli standard RFC e non può essere evitata a livello di zona DNS.

Inoltre, attribuire un dominio specifico ai file da memorizzare in cache permette di semplificare la gestione di file e fatturazione.

- File: saranno salvati in cache solo i file chiamati su questo sottodominio. In questo modo è possibile conservare la chiamata dei file dinamici o che non desideri mettere in cache sul tuo dominio principale, cosa che permette anche di individuare più rapidamente l’origine di un errore di visualizzazione sul tuo sito. 
- Fatturazione: tutto il traffico (in cache o meno) che passa per la CDN viene fatturato. In questo modo è possibile limitare il numero di richieste inutili effettuate verso la CDN per ottimizzare la quota disponibile. 

### Le conseguenze legate a un nuovo sottodominio

Per configurare un nuovo sottodominio con la nostra CDN, probabilmente sarà necessario modificare alcuni parametri del tuo sito e del tuo servizio Web.

Per prima cosa, assicurati che il servizio Web risponda correttamente al sottodominio. Per effettuare questa verifica, configura un *vhost* per il dominio, con la sua directory di destinazione o con l’alias di un altro dominio.

Se il dominio risponde correttamente nel tuo servizio Web, sarà sufficiente modificare il codice HTML per utilizzare i nuovi indirizzi dei file che passano per la CDN e assicurarti che ricevano le richieste tramite il sottodominio.
