## Wprowadzenie

Celem tego przewodnika jest przedstawienie sposobu korzystania z API REST dla usługi Secret Manager.

## Wymagania początkowe

- [Konto klienta OVHcloud](/guides/account-and-service-management/account-information/ovhcloud-account-creation).
- [Zamówiona domena OKMS](/guides/manage-and-operate/kms/quick-start) lub [utworzony pierwszy sekret](/guides/manage-and-operate/secret-manager/secret-manager-ui).
- [Skonfigurowana metoda uwierzytelniania](/guides/manage-and-operate/kms/okms-authentication-methods) dla płaszczyzny danych OKMS.

## W praktyce

### Opis

Secret Manager to produkt umożliwiający bezpieczne przechowywanie danych uwierzytelniających, kluczy API, kluczy SSH lub dowolnego innego rodzaju sekretu niezbędnego do działania Twoich aplikacji.

Sekret to zbiór jednej lub kilku par klucz-wartość zgrupowanych w ramach jednej wersji.
Każda modyfikacja sekretu powoduje utworzenie nowej wersji tego sekretu, co pozwala cofnąć się w historii zmian sekretu.

API REST to jeden z dwóch zestawów API oferowanych przez Secret Manager, obok [API zgodnego z HashiCorp Vault KV2](/guides/manage-and-operate/secret-manager/kv2-api).
Zostały one zaprojektowane tak, aby były podobne do zestawu API OVHcloud oraz do API OKMS dla Key Management Service.

API REST można używać albo za pośrednictwem [scentralizowanego API OVHcloud](/guides/manage-and-operate/api/apiv2), albo bezpośrednio na domenie OKMS w regionie.
Jedyna różnica polega na dokładnej ścieżce API:

- Scentralizowane API OVHcloud: /v2/okms/resource/&#123;okmsId&#125;/secret/&#123;path&#125;
- Regionalne API OKMS: /api/&#123;okmsId&#125;/v2/secret/&#123;path&#125;

Ta dokumentacja skupia się na API domeny OKMS w regionie.

### Komunikacja z domeną OKMS

Komunikacja z domeną OKMS w celu wykonywania operacji szyfrowania i podpisywania jest dostępna za pośrednictwem API.

Ponieważ domena OKMS jest regionalna, dostęp do API odbywa się bezpośrednio w jej regionie: `https://my-region.okms.ovh.net`.

Na przykład dla domeny OKMS utworzonej w regionie **eu-west-rbx**: [https://eu-west-rbx.okms.ovh.net](https://eu-west-rbx.okms.ovh.net).

Z domeną OKMS można komunikować się za pomocą:

- Interfejsu użytkownika Swagger
- Interfejsu CLI OKMS: [https://github.com/ovh/okms-cli](https://github.com/ovh/okms-cli)
- Pakietu SDK Golang: [https://pkg.go.dev/github.com/ovh/okms-sdk-go](https://pkg.go.dev/github.com/ovh/okms-sdk-go)

Uwierzytelnij się za pomocą [osobistego tokena dostępu, konta serwisowego lub certyfikatu dostępu](/guides/manage-and-operate/kms/okms-authentication-methods). W przypadku korzystania z API REST zalecany jest osobisty token dostępu (PAT) lub konto serwisowe.

Aby interaktywnie przetestować wywołania API, skorzystaj z [interfejsu Swagger OKMS](/guides/manage-and-operate/kms/okms-authentication-methods#use-the-okms-swagger-ui) pod adresem `https://<region>.okms.ovh.net/swagger/`.

### Utworzenie sekretu

Aby utworzyć sekret, możesz skorzystać z następującego API:

| **Metoda** |         **Ścieżka**         | **Opis** |
| :--------: | :----------------------: | :-------------: |
|    POST    | /api/&#123;okmsId&#125;/v2/secret/ | Utworzenie sekretu |

API oczekuje następujących wartości:

|        **Pole**         |                                       **Wartość**                                        |                                           **Opis**                                            |
| :----------------------: | :------------------------------------------------------------------------------------: | :--------------------------------------------------------------------------------------------------: |
|       cas_required       |                                        boolean                                         | Jeśli włączone, przy każdej modyfikacji konieczne jest podanie numeru bieżącej wersji |
|     custom_metadata      |                                          Json                                          |         Dodatkowe dane powiązane z sekretem. Dane te nie są chronione przez sekret         |
| deactivate_version_after | [Duration String](https://developer.hashicorp.com/vault/docs/concepts/duration-format) |                            Czas, po którym wersje są dezaktywowane                             |
|       max_versions       |                                        Integer                                         |                              Maksymalna liczba wersji sekretu                               |
|           path           |                                         String                                         |                                             Ścieżka sekretu                                              |
|         version          |                                          Json                                          |                          Zawartość sekretu. Możliwe są zagnieżdżone struktury JSON                          |

Na przykład:

```json
{
  "metadata": {
    "cas_required": true,
    "custom_metadata": {
      "project": "A",
      "team": "X"
    },
    "deactivate_version_after": "10h30m10s",
    "max_versions": 5
  },
  "path": "prod/database/MySQL",
  "version": {
    "data": {
      "login": "admin",
      "password": "my_secret_password",
      "address": {
        "ip": "1.1.1.1"
      },
      "ports": [
        "30",
        "31"
      ]
    }
  }
}
```

### Zarządzanie sekretami

#### Aktualizacja metadanych i konfiguracji

Po utworzeniu sekretu można zaktualizować jego metadane lub konfigurację.

| **Metoda** |     **Ścieżka**      | **Opis** |
| :--------: | :---------------: | :-------------: |
|    PUT     | /v2/secret/&#123;path&#125; | Aktualizacja sekretu |

API oczekuje następujących wartości:

|        **Pole**         |                                       **Wartość**                                        |                                           **Opis**                                            |
| :----------------------: | :------------------------------------------------------------------------------------: | :--------------------------------------------------------------------------------------------------: |
|       cas_required       |                                        boolean                                         | Jeśli włączone, przy każdej modyfikacji konieczne jest podanie numeru bieżącej wersji |
|     custom_metadata      |                                          Json                                          |         Dodatkowe dane powiązane z sekretem. Dane te nie są chronione przez sekret         |
| deactivate_version_after | [Duration String](https://developer.hashicorp.com/vault/docs/concepts/duration-format) |                            Czas, po którym wersje są dezaktywowane                             |
|       max_versions       |                                        Integer                                         |                              Maksymalna liczba wersji sekretu                               |

Można również zmienić domyślną konfigurację domeny OKMS dla wartości **cas_required**, **deactivate_version_after** i **max_versions** za pomocą API:

| **Metoda** |     **Ścieżka**     |                 **Opis**                  |
| :--------: | :--------------: | :----------------------------------------------: |
|    PUT     | /v2/secretConfig | Ustawienie domyślnej konfiguracji domeny OKMS |

#### Utworzenie nowej wersji

Można również zmodyfikować zawartość sekretu, co wiąże się z utworzeniem nowej wersji tego sekretu.
Nowe wersje można tworzyć za pomocą API:

| **Metoda** |         **Ścieżka**          |         **Opis**          |
| :--------: | :-----------------------: | :------------------------------: |
|    PUT     |     /v2/secret/&#123;path&#125;     |         Aktualizacja sekretu          |
|    PUT     | /v2/secret/&#123;path&#125;/version | Utworzenie nowej wersji sekretu |

Niezależnie od tego, czy modyfikacja **data** sekretu odbywa się za pomocą ogólnego API do aktualizacji sekretu, czy za pomocą dedykowanego API, tworzona jest nowa wersja sekretu.

Sekret może zawierać dowolną liczbę wersji, aż do maksymalnego limitu określonego parametrem **max_versions**.
Jeśli maksymalna liczba wersji zostanie osiągnięta, najstarsza wersja jest automatycznie usuwana.

#### Zarządzanie wersjami

Poszczególnymi wersjami sekretu można zarządzać za pomocą API:

| **Metoda** |              **Ścieżka**               |        **Opis**         |
| :--------: | :---------------------------------: | :----------------------------: |
|    PUT     | /v2/secret/&#123;path&#125;/version/&#123;version&#125; | Aktualizacja wersji sekretu |

API oczekuje jednej wartości:

| **Pole** |           **Wartość**           |                                                                                                                                       **Opis**                                                                                                                                       |
| :-------: | :---------------------------: | :-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------: |
|   state   | active , deactivated, deleted | active: Wartość tej wersji jest dostępna <br/>deactivated: Wartość tej wersji jest nadal obecna w systemie, ale nie jest już dostępna do momentu ponownej aktywacji wersji <br/>deleted: Wartość tej wersji nie jest już obecna w systemie i nie można jej przywrócić. |
