## Wprowadzenie

Celem tego przewodnika jest przedstawienie kroków, które należy wykonać, aby skonfigurować pierwszą usługę Key Management Service (KMS) i utworzyć klucz. Aby wywołać regionalne API płaszczyzny danych, skonfiguruj metodę uwierzytelniania zgodnie z opisem w przewodniku [Metody uwierzytelniania OKMS](/guides/manage-and-operate/kms/okms-authentication-methods).

## W praktyce

### Zamawianie KMS

Każdy KMS jest powiązany z regionem, dzięki czemu klucze w nim przechowywane mają gwarancję pozostania w tym regionie.

Możesz zamówić wiele usług KMS, zarówno w różnych regionach, jak i w tym samym regionie.

Ponieważ opłaty za KMS zależą od liczby przechowywanych w nim kluczy, samo zamówienie KMS nie generuje opłat.

Kliknij przycisk <code className="action">Zamów domenę OKMS</code>.

<img className="thumbnail" alt="Dostęp do menu KMS" src="/images/manage-and-operate/kms/quick-start/access_to_the_KMS_menu_01.png" loading="lazy" />

Wskaż region Twojego KMS.

<img className="thumbnail" alt="Zamawianie KMS" src="/images/manage-and-operate/kms/quick-start/order_kms_01.png" loading="lazy" />

Zamówienie możesz następnie sfinalizować w innej karcie. Jeśli nie otworzyła się ona automatycznie, wyświetlany jest link do zamówienia:

<img className="thumbnail" alt="Zamawianie KMS" src="/images/manage-and-operate/kms/quick-start/order_kms_02.png" loading="lazy" />

#### Tworzenie klucza szyfrowania

W karcie <code className="action">Klucze szyfrowania</code> kliknij przycisk <code className="action">Utwórz Service Key</code>.

<img className="thumbnail" alt="Tworzenie klucza" src="/images/manage-and-operate/kms/quick-start/create_key_01.png" loading="lazy" />

Formularz umożliwia skonfigurowanie klucza oraz wybór jego typu, rozmiaru i zastosowania.

<img className="thumbnail" alt="Tworzenie klucza" src="/images/manage-and-operate/kms/quick-start/create_key_02.png" loading="lazy" />

:::warning
Tylko tworzenie kluczy za pośrednictwem [regionalnych API](/guides/manage-and-operate/kms/kms-usage) jest objęte certyfikacją PCI-DSS.

:::


Po utworzeniu klucza kliknij go, aby uzyskać dostęp do jego szczegółów.

Panel wyświetla właściwości kryptograficzne klucza oraz działania umożliwiające jego zmianę nazwy, dezaktywację lub usunięcie.

Aby ograniczyć ryzyko przypadkowego usunięcia, przed usunięciem klucza należy go dezaktywować.

:::warning
Usuniętego klucza nie można w żaden sposób odzyskać, a jego usunięcie wiąże się z utratą wszystkich danych zaszyfrowanych za jego pomocą. Każde usunięcie należy przeprowadzać z najwyższą ostrożnością.

:::

#### Tworzenie klucza szyfrowania

Klucz możesz utworzyć za pomocą następującego API:

|**Metoda**|**Ścieżka**|**Opis**|
| :-: | :-: | :-: |
|POST|/okms/resource/&#123;okmsId&#125;/serviceKey|Utwórz lub zaimportuj CMK|

API oczekuje następujących wartości:

|**Pole**|**Wartość**|**Opis**|
| :-: | :-: | :-: |
|name|string|Nazwa klucza|
|context|string|Dodatkowe dane uwierzytelniające służące do weryfikacji autentyczności klucza|
|type|oct, RSA, EC|Typ klucza: sekwencja bajtów (oct) dla kluczy symetrycznych, RSA (RSA), Elliptic Curve (EC)|
|size|Integer|Rozmiar klucza - patrz tabela poniżej|
|operations|Array|Zastosowanie klucza - patrz tabela poniżej|
|curve|P-256, P-384, P-521|(opcjonalnie) Krzywa kryptograficzna dla kluczy typu EC|

**Przykład tworzenia klucza symetrycznego:**

```json
{
  "name": "My first AES key",
  "context": "project A",
  "type": "oct",
  "size": 256,
  "operations": [
    "encrypt",
    "decrypt"
  ]
}
```

**Przykład tworzenia klucza asymetrycznego:**

```json
{
  "name": "My first RSA key",
  "context": "project A",
  "type": "RSA",
  "size": 4096,
  "operations": [
    "sign",
    "verify"
  ]
}
```

**Przykład tworzenia klucza EC:**

```json
{
  "name": "My first EC key",
  "context": "project A",
  "type": "EC",
  "operations": [
    "sign",
    "verify"
  ],
  "curve": "P-256"
}
```

W zależności od typu klucza możliwe rozmiary i operacje są następujące:

- **Oct**:
    - rozmiar: 128, 192, 256
    - operacje:
        - encrypt, decrypt
        - wrapKey, unwrapKey
- **RSA**:
    - rozmiar: 2048, 3072, 4096
    - operacje: sign, verify
- **EC**:
    - rozmiar: nie określać
    - curve: P-256, P-384, P-521
    - operacje: sign, verify

:::warning
Tylko tworzenie kluczy za pośrednictwem [regionalnych API](/guides/manage-and-operate/kms/kms-usage) jest objęte certyfikacją PCI-DSS.

:::

### Uwierzytelnianie w płaszczyźnie danych OKMS

Przed wywołaniem regionalnego API REST skonfiguruj metodę uwierzytelniania (Personal Access Token, konto serwisowe lub certyfikat dostępu). Zobacz [Metody uwierzytelniania OKMS](/guides/manage-and-operate/kms/okms-authentication-methods).

W przypadku korzystania z API REST zalecany jest PAT lub konto serwisowe. W przypadku integracji KMIP, które wymagają uwierzytelniania opartego na certyfikatach, wybieraj [certyfikaty dostępu](/guides/manage-and-operate/kms/okms-certificate-management).

### Korzystanie z OVHcloud KMS

Po skonfigurowaniu OVHcloud KMS możesz korzystać z niego na dwa różne sposoby:

- Za pomocą [API REST](/guides/manage-and-operate/kms/kms-usage) do szyfrowania lub podpisywania danych (uwierzytelnianie za pomocą PAT, konta serwisowego lub certyfikatu).
- Za pomocą [protokołu KMIP](/guides/manage-and-operate/kms/kms-kmip) do łączenia produktów kompatybilnych z KMIP (wymagany certyfikat dostępu).
