## W praktyce

:::info
Funkcje IAM nie są obecnie dostępne w ofertach Hosted Private Cloud VMware vSphere z certyfikatem PCI-DSS lub HDS ani w rozwiązaniach z kwalifikacją SecNumCloud.
To samo dotyczy środowisk zarządzanych z włączonym NSX oraz Public VCF as-a-Service. Zespoły OVHcloud pracują nad dostosowaniem tych technologii.

:::


### Jak działają IAM i Hosted Private Cloud - VMware on OVHcloud?

Aktywacja OVHcloud IAM deleguje zarządzanie dostępem do usługi, powiązanymi rolami i ich uprawnieniami w vSphere. Dostępami i politykami zarządzasz w sekcji IAM konsoli OVHcloud.

W uproszczeniu:

- Rola IAM zastępuje lokalnego użytkownika vSphere w Hosted Private Cloud - VMware on OVHcloud.
- Polityka umożliwia powiązanie Twojej tożsamości OVHcloud z tą rolą.
- Role IAM działają z wykorzystaniem grup VMware vSphere.

Oto elementy niezbędne do prawidłowego działania IAM z Hosted Private Cloud - VMware on OVHcloud:

- Produkty: **vSphere/VMware (Hosted Private Cloud, service pack)**.
- Zasoby: **PCC-XXX**.
- Akcje: **Zarządzane lub ręczne**.
- Użytkownicy: **Użytkownik 1/2/3**.

## FAQ

### Jakie są ograniczenia IAM z Hosted Private Cloud - VMware on OVHcloud?

:::info
Obecnie rolą IAM vSphere nie można zarządzać za pomocą zarządzanych grup uprawnień.

:::


IAM jest obecnie dostępny na platformie OVHcloud w wersji BETA. Infrastruktury z opcjami zwiększonego bezpieczeństwa lub z certyfikowaną usługą (hosting danych medycznych (HDS), hosting danych bankowych (PCI-DSS) lub SecNumCloud (SNC)) nie mogą obecnie korzystać z OVHcloud IAM.

Rolę IAM można dodać wyłącznie za pomocą akcji ręcznych w polityce globalnej (akcja: assumerole -> role_iam). Więcej informacji znajdziesz w przewodniku "[IAM dla VMware on OVHcloud - Jak powiązać rolę vSphere z polityką IAM](/guides/hosted-private-cloud/powered-by-vmware/vmware-iam-role-policy)".

### Jak uzyskać dostęp do delegowania uprawnień vSphere za pomocą IAM?

**Powiązanymi tożsamościami**, **zasobami**, **grupami zasobów** i ich uprawnieniami w politykach zarządzasz w konsoli OVHcloud.

W sekcji <code className="action">Zarządzanie tożsamością i dostępem</code> menu bocznego kliknij <ManagerLink to="/beta/#/iam/identities/users">Tożsamości</ManagerLink> lub <ManagerLink to="/beta/#/iam/policies/my-policies">Zasady</ManagerLink>.

Rolami IAM i lokalnymi użytkownikami vSphere zarządzasz za pomocą pozycji <code className="action">Managed VMware vSphere</code> w sekcji **Produkty** menu bocznego.

Wybierz infrastrukturę, a następnie przejdź do zakładki <code className="action">Użytkownicy</code>.

### Ile ról jest dostępnych domyślnie?

Po aktywacji IAM w Twoim Hosted Private Cloud - VMware on OVHcloud dostępne są 2 aktywne role domyślne.

### Czym jest rola IAM vSphere powiązana z polityką?

Każda rola IAM w Twoim Hosted Private Cloud - VMware on OVHcloud odpowiada akcji zapisanej w formacie `pccVMware:vSphere:assumeRole?role_name` w polityce IAM.

Na przykład dla roli **iam-admin** usługi Dedicated Cloud akcja ma postać: `pccVMware:vSphere:assumeRole?iam-admin.`.

Rolę można traktować jako szablon użytkownika, w którym definiujesz uprawnienia PCC (vSphere). Następnie stosujesz te uprawnienia (tę rolę) do użytkownika w Twojej konsoli OVHcloud (IAM, jeśli powiązałeś użytkownika z polityką).
