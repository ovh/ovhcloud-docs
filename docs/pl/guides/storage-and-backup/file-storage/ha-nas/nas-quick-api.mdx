## Wprowadzenie

Usługa NAS-HA OVHcloud pozwala na zarządzanie przestrzenią dyskową plików dostępną z poziomu sieci. 

**Niniejszy przewodnik wyjaśnia, jak korzystać z usługi NAS-HA przy użyciu interfejsu API OVHcloud.**

## Wymagania początkowe

- Usługa [NAS-HA OVHcloud](https://www.ovhcloud.com/pl/storage-solutions/nas-ha/)
- Zapoznaj się z naszym przewodnikiem Pierwsze kroki z [API OVHcloud](/guides/manage-and-operate/api/first-steps), aby zapoznać się z APIv6 OVHcloud

## W praktyce

Wszystkie drogi API w tym przewodniku są dostępne w <ApiLink section="/dedicated/nasha">sekcji */dedicated/nasha*</ApiLink> konsoli API.

:::info
Podczas korzystania z API wszystkie pola oznaczone gwiazdką (\*) są obowiązkowe.
:::


### Pobranie informacji o usłudze

Wszystkie Twoje aktywne usługi można odzyskać przy użyciu następującej drogi:

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha"} />


### Tworzenie partition

Użyj następującej drogi, aby utworzyć nową partycję:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Wewnętrzna nazwa usługi NAS |
| `partitionDescription` |  | Opis opcjonalny |
| `partitionName` | Yes | Nazwa partition |
| `protocol` | Yes | *NFS*, *CIFS* lub *NFS_CIFS* dla |
| `size` | Yes | Rozmiar partition |

Wybierz `NFS` jako protokół i rozmiar `10` Gigabajtów.

### Dodanie wpisu ACL, aby uzyskać dostęp do partition

:::warning
Dostęp nie jest domyślnie udzielany, chyba że jest udzielany za pośrednictwem ACL. Można dodać wyłącznie adresy IP przypisane do Twoich usług OVHcloud.
:::


Możesz sprawdzić adresy IP kwalifikujące się do dostępu za pomocą następujących wywołań API:

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/authorizableBlocks"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Wewnętrzna nazwa usługi NAS-HA |
| `partitionName` | Yes | Nazwa partition |

Aby utworzyć nowy wpis ACL umożliwiający logowanie do partition, użyj następującej drogi:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/access"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Nazwa wewnętrzna usługi NAS-HA |
| `partitionName` | Yes | Nazwa partition |
| `ip` | Yes | Adres IP lub zakres, w jakim należy udzielić dostępu |
| `type` | Yes | Typ dostępu ACL dla tego wpisu: *readonly* lub *readwrite* |

:::info
Użyj ratingu CIDR dla pul IP, na przykład: 192.0.2.0/24.
:::


### Tworzenie ręcznego snapshota

Aby dodać ręczny snapshot, użyj następującej drogi:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/customSnapshot"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Nazwa wewnętrzna usługi NAS-HA |
| `partitionName` | Yes | Nazwa partition |
| `expiration` |  | Fakultatywna data wygaśnięcia, na przykład: 2022-06-24 (ISO 8601) |
| `name` | Yes | Nazwa snapshota |

### Usuwanie partition

Użyj następującej drogi, aby usunąć partycję:

<Api version="v1" section="/dedicated/nasha" method="DELETE" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Nazwa wewnętrzna usługi NAS-HA |
| `partitionName` | Yes | Nazwa partition |

## Korzystanie z API z prywatnym NAS-HA (Beta) <a name="using-the-api-with-a-private-nas-ha-beta"></a>

:::info
Prywatny NAS-HA jest obecnie dostępny w wersji beta. Jego ścieżki API różnią się od opisanych powyżej: są dostępne w <ApiLink section="/storage">sekcji */storage*</ApiLink> konsoli API, a partycje nazywają się tam **shares**. Ta sekcja może ulec zmianie wraz z rozwojem produktu.

:::


Aby połączyć prywatny NAS-HA z Twoją siecią prywatną vRack, zapoznaj się z naszym przewodnikiem "[HA-NAS - Private network configuration (Beta)](/guides/storage-and-backup/file-storage/ha-nas/nas-network-config)".

### Pobranie informacji o usłudze (Beta)

Aby wyświetlić listę Twoich prywatnych usług NAS-HA, użyj następującej ścieżki:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha"} regions={["eu"]} />


Pole `id` odpowiedzi to `serviceName` używany przez poniższe ścieżki.

Aby pobrać `shareId` Twoich udziałów (pole `id` odpowiedzi), użyj następującej ścieżki:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | ID Twojej prywatnej usługi NAS-HA |

### Dodanie wpisu ACL, aby uzyskać dostęp do udziału (Beta)

:::warning
Dostęp jest domyślnie zablokowany, chyba że zostanie udzielony za pośrednictwem ACL.
:::


Aby utworzyć nowy wpis ACL umożliwiający połączenie z Twoim udziałem, użyj następującej ścieżki:

<Api version="v1" section="/storage" method="POST" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/acl"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | ID Twojej prywatnej usługi NAS-HA |
| `shareId` | Yes | ID udziału |
| `accessLevel` | Yes | Poziom dostępu ACL: *rw* (odczyt i zapis) lub *ro* (tylko odczyt) |
| `accessTo` | Yes | Adres IPv4 lub zakres, któremu należy udzielić dostępu |

:::info
Dla zakresów IP użyj notacji CIDR, na przykład: 10.235.0.0/24.
:::


### Pobranie punktu montowania (Beta)

Aby pobrać `accessPathId` ścieżek dostępu udziału, użyj następującej ścieżki:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/accessPath"} regions={["eu"]} />


Następnie pobierz szczegóły ścieżki dostępu za pomocą następującej ścieżki:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/accessPath/\{accessPathId\}"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | ID Twojej prywatnej usługi NAS-HA |
| `shareId` | Yes | ID udziału |
| `accessPathId` | Yes | ID ścieżki dostępu |

Pole `path` odpowiedzi zawiera ścieżkę eksportu, której należy użyć w poleceniu montowania. Jeśli udział ma kilka ścieżek dostępu, użyj tej, której pole `preferred` ma wartość `true`.
