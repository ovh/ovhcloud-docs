## Wprowadzenie

**Valkey** to magazyn danych **w pamięci** o otwartym kodzie źródłowym, zgodny z klientami i protokołami ekosystemu Redis (RESP, REdis Serialization Protocol). Sprawdza się w przypadku wydajnych **pamięci podręcznych**, **sesji**, **lekkich kolejek** i **liczników**.

**Dowiedz się, jak połączyć się z instancją Valkey w Web Cloud Databases: autoryzacja adresów IP, pobranie parametrów połączenia i test z poziomu klienta wiersza poleceń.**

:::warning
Zabezpiecz dostęp do instancji (autoryzowane adresy IP, silne hasła) i przetestuj go w środowisku przedprodukcyjnym przed uruchomieniem produkcyjnym.

:::

## W praktyce

### Część 1 — Autoryzacja adresu IP dostępu

Domyślnie instancja Valkey odrzuca połączenia publiczne. Aby autoryzować (dodać do białej listy) adres IP, z którego się łączysz, zapoznaj się z naszym przewodnikiem "[Web Cloud Databases - Jak autoryzować adres IP?](/guides/web-cloud/databases/db-authorise-ip-mask)"

Powtórz tę operację dla każdego komputera, który ma mieć dostęp do instancji Valkey.

### Część 2 — Przygotowanie parametrów połączenia <a id="get-credentials"></a>

#### Pobranie parametrów połączenia

Kliknij poniższe zakładki, aby wyświetlić kolejne **2** kroki.

<Tabs>
  <Tab label="Krok 1">
    Na liście Twoich usług wybierz odpowiednie rozwiązanie.

    <img className="thumbnail" alt="Lista usług Web Cloud Databases w Panelu klienta OVHcloud" src="/images/assets/screens/control-panel/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />
  </Tab>
  <Tab label="Krok 2">
    W zakładce <code className="action">Informacje ogólne</code> zanotuj następujące informacje:

    - **Nazwa hosta**: na przykład `aaXXXXX-XXX.eu.clouddb.ovh.net`.
    - **Port**: na przykład `6379`.
  </Tab>
</Tabs>

:::info
OVHcloud nie udostępnia portu szyfrowanego przez TLS na serwerach baz danych Redis i Valkey. Komunikacja musi odbywać się wyłącznie przez domyślny, nieszyfrowany port.

:::

#### Ustawienie hasła użytkownika `default`

Instancja Valkey jest dostarczana z użytkownikiem `default`, jedynym dostępnym kontem: użyj go, aby się połączyć.

:::warning
Jego hasło nigdy nie jest wyświetlane w Panelu klienta OVHcloud. Musisz je zmienić co najmniej raz, aby je poznać.

:::

Kliknij poniższe zakładki, aby wyświetlić kolejne **4** kroki.

#### Zapisanie informacji

Zachowaj następujące informacje:

- Nazwa hosta
- Port
- Hasło użytkownika `default`

Są one niezbędne do przetestowania połączenia z instancją z poziomu klienta Valkey lub Twojej aplikacji.

### Część 3 — Test połączenia za pomocą klienta wiersza poleceń

Aby sprawdzić, czy instancja Valkey działa, połącz się z nią po raz pierwszy:

#### Instalacja klienta połączenia

W tym przykładzie używamy klienta `redis-cli`, zgodnego z Valkey i łatwego w instalacji. Możesz użyć dowolnego klienta. Otwórz terminal i wykonaj poniższe polecenie odpowiednie dla Twojego systemu operacyjnego.

<Tabs>
  <Tab label="Debian/Ubuntu">
    ```bash
    sudo apt update && sudo apt -y install redis-tools
    ```
  </Tab>
  <Tab label="AlmaLinux/Rocky">
    ```bash
    sudo dnf -y install redis
    ```
  </Tab>
  <Tab label="macOS">
    Zainstaluj [Homebrew](https://brew.sh/pl/), postępując zgodnie z instrukcjami na stronie, a następnie zainstaluj `redis-cli`:

    ```bash
    brew install redis
    ```
  </Tab>
  <Tab label="Windows">
    W menu Start wpisz `PowerShell`, kliknij wynik prawym przyciskiem myszy, a następnie kliknij <code className="action">Uruchom jako administrator</code>.

    Zainstaluj [Chocolatey](https://chocolatey.org/install), wykonując poniższe polecenie:

    ```powershell
    Set-ExecutionPolicy Bypass -Scope Process -Force; [System.Net.ServicePointManager]::SecurityProtocol = [System.Net.ServicePointManager]::SecurityProtocol -bor 3072; iex ((New-Object System.Net.WebClient).DownloadString('https://community.chocolatey.org/install.ps1'))
    ```

    Zainstaluj `redis-cli`:

    ```powershell
    choco install redis-64 -y
    ```
  </Tab>
</Tabs>

Po zainstalowaniu klienta sprawdź, czy działa, wykonując poniższe polecenie:

```bash
redis-cli --version
```

#### Połączenie z instancją

W terminalu wykonaj poniższe polecenie:

```bash
redis-cli -h <hostname> -p 6379
```

Zastąp `<hostname>` nazwą swojego hosta, a `6379` swoim portem, jeśli jest inny. Aby pobrać te wartości, zapoznaj się z sekcją "[Część 2 — Przygotowanie parametrów połączenia](#get-credentials)".

#### Sprawdzenie, czy wszystko działa

Jeśli połączenie się powiedzie, wyświetli się wiersz poleceń Twojej instancji. Uwierzytelnij się poleceniem `AUTH`, zastępując `<password>` hasłem użytkownika `default`:

```console
aaXXXXX-XXX.eu.clouddb.ovh.net:6379> AUTH <password>
OK
```

Następnie sprawdź, czy serwer odpowiada:

```console
aaXXXXX-XXX.eu.clouddb.ovh.net:6379> PING
```

Baza danych powinna odpowiedzieć:

```console
PONG
```

Wypróbuj również:

```console
aaXXXXX-XXX.eu.clouddb.ovh.net:6379> SET ovh-test-connexion "hello"
aaXXXXX-XXX.eu.clouddb.ovh.net:6379> GET ovh-test-connexion
```

Powinieneś zobaczyć:

```console
"hello"
```

Usuń klucz testowy:

```console
aaXXXXX-XXX.eu.clouddb.ovh.net:6379> DEL ovh-test-connexion
```

Aby wyjść, wpisz:

```console
aaXXXXX-XXX.eu.clouddb.ovh.net:6379> QUIT
```

Jeśli powyższe testy działają, Twoja instancja Valkey jest gotowa do pracy.
