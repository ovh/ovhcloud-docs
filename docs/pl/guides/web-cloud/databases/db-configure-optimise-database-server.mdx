## Wprowadzenie

Za pomocą serwerów baz Web Cloud Databases możesz wpłynąć na globalne parametry serwera. Możesz również wyświetlić aktywność swojego serwera.

**Dowiedz się, jak skonfigurować i zoptymalizować serwer baz danych.**

## Wymagania początkowe

- Posiadanie [instancji Web Cloud Databases](/links/web/databases) (zawartej w ofercie [hostingu www](/links/web/hosting) Performance, Agency, Agency Plus lub Agency Max).

[[cpnav:web-cloud-databases]]

    |Informacja|Szczegóły|

<summary>Autoryzacja adresu IP</summary>

Aby uzyskać dostęp do instancji Web Cloud Databases, należy wskazać adresy IP lub zakresy adresów IP, które mogą się łączyć z Twoimi bazami danych.

Kliknij poniższe karty, aby wyświetlić kolejne **4** kroki.

<Tabs>
  <Tab label="Krok 1">

    <img className="thumbnail" alt="Strona Web Cloud DB z listą instancji na koncie" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />
  </Tab>
  <Tab label="Krok 2">
    Na stronie, która się wyświetli, kliknij zakładkę <code className="action">Autoryzowane IP</code>.

    <img className="thumbnail" alt="Karta Autoryzowane IP instancji Web Cloud DB" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/allowed-ips/tab.png" loading="lazy" />
  </Tab>
  <Tab label="Krok 3">
    Na stronie, która się wyświetli, kliknij przycisk <code className="action">Dodaj IP</code> znajdujący się nad tabelą.

    <img className="thumbnail" alt="Przycisk Dodaj IP nad tabelą autoryzowanych adresów IP" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/allowed-ips/add-ip.png" loading="lazy" />

    :::tip
    Jeśli chcesz zmienić już autoryzowany adres IP lub zakres adresów IP, kliknij w tabeli przycisk <code className="action">⋮</code> w kolumnie **Akcje**, po prawej stronie wiersza odpowiadającego adresowi IP lub zakresowi adresów IP do zmiany, a następnie kliknij <code className="action">Edytuj</code>. Możesz zmienić jego nazwę i uprawnienia; samego adresu IP nie można zmienić.

    <img className="thumbnail" alt="Menu wiersza w tabeli autoryzowanych adresów IP" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/allowed-ips/row-actions-menu.png" loading="lazy" />

    :::

  </Tab>
  <Tab label="Krok 4">
    W oknie **Dodaj adres IP**, które się otworzy, wypełnij następujące pola:

    <img className="thumbnail" alt="Okno Dodaj adres IP i jego pola" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/allowed-ips/add-ip-window.png" loading="lazy" />

    - **IP** (wymagane): Wpisz adres IP (na przykład: `203.0.113.44`) lub zakres adresów IP (na przykład: `203.0.113.0/24`, obejmujący wszystkie adresy IP od `203.0.113.0` do `203.0.113.255`), który chcesz autoryzować w rozwiązaniu Web Cloud Databases.
    - **Nazwa** (wymagane): Możesz tu na przykład wskazać rolę danego adresu IP lub zakresu adresów IP.
    - **Zezwól na dostęp do usługi** (domyślnie zaznaczone): Zaznacz to pole, aby zezwolić adresowi IP lub zakresowi adresów IP na dostęp do baz danych Twojego rozwiązania Web Cloud Databases.
    - **Zezwól na dostęp SFTP**: Zaznacz to pole, aby zezwolić adresowi IP lub zakresowi adresów IP na dostęp do logów Twojego rozwiązania Web Cloud Databases.

    :::warning
    Zdecydowanie odradzamy zaznaczanie pola **Zezwól na dostęp do usługi**, aby zezwolić zakresowi adresów IP `0.0.0.0/0` na dostęp do Twoich baz danych.

    W ten sposób wszystkie istniejące adresy IPv4 uzyskałyby dostęp do Twoich baz danych.

    :::

    Po wpisaniu informacji kliknij przycisk <code className="action">Dodaj</code>.

### Zmiana oferty Web Cloud Databases <a name="modify-ram-web-cloud-db"></a>

:::warning
Jeśli Twoja usługa Web Cloud Databases jest powiązana z hostingiem www **Performance**, **Agency**, **Agency Plus** lub **Agency Max**, musisz wcześniej odłączyć ofertę Web Cloud Databases od hostingu, aby przejść na wyższą ofertę.

Aby odłączyć usługę Web Cloud Databases od hostingu www **Performance**, **Agency**, **Agency Plus** lub **Agency Max**, zapoznaj się z naszym przewodnikiem "[Odłączenie mojego rozwiązania Web Cloud Databases od hostingu WWW](/guides/web-cloud/databases/db-detach-from-web-hosting)".

**Operacja ta jest nieodwracalna, a usługa Web Cloud Databases będzie fakturowana niezależnie od hostingu www Performance, Agency, Agency Plus lub Agency Max.**

:::

Kliknij poniższe karty, aby wyświetlić kolejne **3** kroki.

<Tabs>
  <Tab label="Krok 1">
    Przejdź na stronę <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink>, następnie wybierz odpowiednią instancję.

    <img className="thumbnail" alt="Strona Web Cloud DB z listą instancji na koncie" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />
  </Tab>
  <Tab label="Krok 2">
    Na zakładce <code className="action">Przegląd</code>, wyświetlanej domyślnie, kliknij <code className="action">Zamów więcej RAM</code> w sekcji **Wykorzystanie zasobów**, aby przejść do zamówienia tej zmiany.

    <img className="thumbnail" alt="Link Zamów więcej RAM w sekcji Wykorzystanie zasobów" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/general-information/order-more-ram.png" loading="lazy" />
  </Tab>
  <Tab label="Krok 3">
    Na stronie, która się wyświetli, wybierz żądaną ilość pamięci RAM w sekcji **Oferta RAM**. Pole **Okres zobowiązania** jest narzucone przez ofertę: wyświetla się wyłącznie informacyjnie i nie można go zmienić.

    :::info
    Pozostały okres do wygaśnięcia zostanie naliczony proporcjonalnie. Naliczenie proporcjonalne będzie oparte na dacie wygaśnięcia instancji Web Cloud Databases, a nie na dacie złożenia zamówienia.

    :::

    Zaznacz pole akceptacji regulaminów, a następnie kliknij <code className="action">Złóż zamówienie</code>. Nastąpi przekierowanie w celu sfinalizowania i opłacenia zamówienia. Nowa pamięć RAM zostanie zastosowana po opłaceniu zamówienia, a baza danych może zostać wtedy zrestartowana.

    <img className="thumbnail" alt="Strona zamówienia pamięci RAM z ofertą, okresem zobowiązania, regulaminami i podsumowaniem" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/general-information/order-ram-page.png" loading="lazy" />

    :::warning
    Jeśli aktualnie posiadasz darmową usługę Web Cloud Databases powiązaną z hostingiem Performance, Agency, Agency Plus lub Agency Max, zmiana oferty oznacza utratę jej bezpłatności.

    :::

  </Tab>
</Tabs>

<summary>Instancja MySQL i MariaDB</summary>

Kliknij poniższe karty, aby wyświetlić kolejne **4** kroki.

<Tabs>
  <Tab label="Krok 1">
    Przejdź na stronę <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink>, następnie wybierz odpowiednią instancję.

    <img className="thumbnail" alt="Strona Web Cloud DB z listą instancji na koncie" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />
  </Tab>
  <Tab label="Krok 2">
    Kliknij zakładkę <code className="action">Konfiguracja</code>.

    <img className="thumbnail" alt="Zakładka Konfiguracja instancji Web Cloud DB" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/configuration/tab.png" loading="lazy" />
  </Tab>
  <Tab label="Krok 3">
    Konfiguracja aktualnie zdefiniowana dla Twojej bazy danych jest podzielona na trzy sekcje: **Połączenia**, **Wydajność** i **Zachowanie silnika**. Kliknij <code className="action">Edytuj</code> na dole sekcji zawierającej parametr do zmiany.

    <img className="thumbnail" alt="Sekcje konfiguracji MySQL z linkiem Edytuj" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/configuration/groups.png" loading="lazy" />

    Poniższa tabela przedstawia każdy parametr, który możesz zmienić, oraz wartości, jakie możesz mu przypisać.

    |Parametr|Opis|Wartości konfigurowalne|
    |---|---|---|
    |`max_allowed_packet`|Maksymalny rozmiar pakietu.|Od 1 do 64 MB|
    |`max_user_connections`|Liczba jednoczesnych połączeń autoryzowanych na użytkownika.|Od 50 do 200|
    |`autocommit`|Określa, czy zapytania są automatycznie zatwierdzane (committed), czy nie.|ON lub OFF|
    |`interactive_timeout`|Czas (w sekundach), przez który serwer czeka na działanie w połączeniu interaktywnym przed jego zamknięciem.|Od 60 do 28800 sekund|
    |`innodb_buffer_pool_size`|Rozmiar pamięci buforowej wyrażony w megabajtach.|Wartości proponowane na liście (od 128 MB do 2048 MB)|
    |`max_connections`|Liczba jednoczesnych połączeń autoryzowanych na serwerze baz danych.|Od 100 do 200|
    |`wait_timeout`|Czas (w sekundach), przez który serwer czeka na działanie w połączeniu nieinteraktywnym przed jego zamknięciem.|Od 60 do 28800 sekund|
    |`event_scheduler`|Uruchamia wykonywanie zapytań zaprogramowanych bezpośrednio na serwerze MySQL.|ON lub OFF|
    |`sql_mode`|Wpływa na obsługiwaną składnię SQL oraz sprawdzanie poprawności danych przez MySQL/MariaDB.|Patrz tryby domyślne poniżej|
    |`long_query_time`|Czas (w sekundach), po przekroczeniu którego zapytanie jest rejestrowane jako wolne.|1, 2, 5, 10 lub 60 sekund|
    |`local_infile`|Zezwala lub nie zezwala klientom na ładowanie danych lokalnych.|ON lub OFF|
    |`log_bin_trust_function_creators`|Pozwala użytkownikom bez uprawnień tworzyć funkcje składowane, gdy włączone jest logowanie binarne.|ON lub OFF|

    :::info
    Jeśli na Twojej stronie pojawi się błąd wskazujący `Too many connections`, jest to spowodowane przekroczeniem liczby jednoczesnych połączeń do serwera baz danych. Możesz wówczas zwiększyć zmienną `max_connections`, jeśli nie osiągnęła jeszcze wartości maksymalnej.

    :::

    :::info
    <b>sql_mode</b>:

    &emsp;&emsp;Tryb domyślny dla MariaDB 10.1:
    <pre className="highlight language-console"><code className="language-console">NO_ENGINE_SUBSTITUTION,NO_AUTO_CREATE_USER</code></pre>

    &emsp;&emsp;Tryb domyślny dla MariaDB 10.2 i nowszych wersji:
    <pre className="highlight language-console"><code className="language-console">STRICT_TRANS_TABLES,ERROR_FOR_DIVISION_BY_ZERO,NO_AUTO_CREATE_USER,NO_ENGINE_SUBSTITUTION</code></pre>

    &emsp;&emsp;Tryb domyślny dla MySQL 5.6:
    <pre className="highlight language-console"><code className="language-console">NO_ENGINE_SUBSTITUTION</code></pre>

    &emsp;&emsp;Tryb domyślny dla MySQL 5.7 i nowszych wersji:
    <pre className="highlight language-console"><code className="language-console">ONLY_FULL_GROUP_BY,STRICT_TRANS_TABLES,NO_ZERO_IN_DATE,NO_ZERO_DATE,ERROR_FOR_DIVISION_BY_ZERO,NO_ENGINE_SUBSTITUTION</code></pre>

    Zalecamy, aby zawsze używać trybu domyślnego, chyba że baza danych została zaktualizowana z wersji mającej inny tryb domyślny niż bieżąca wersja.

    :::
  </Tab>
  <Tab label="Krok 4">
    W panelu, który się otworzy, wybierz nowe wartości z list, a następnie kliknij <code className="action">Zastosuj</code>.

    <img className="thumbnail" alt="Panel edycji sekcji Połączenia z ostrzeżeniem o restarcie" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/configuration/edit-drawer.png" loading="lazy" />
  </Tab>
</Tabs>

    <img className="thumbnail" alt="Panel edycji parametru log_min_messages instancji PostgreSQL" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/configuration/edit-drawer-postgresql.png" loading="lazy" />

    - **log_min_messages**: Określa poziomy wiadomości rejestrowanych w logach serwera. Poziomy dostępne dla rozwiązania Web Cloud Databases to:
        - **"WARNING"**: Dostarcza komunikaty ostrzegawcze o potencjalnych problemach.
        - **"ERROR"**: Wysyła błąd, który spowodował anulowanie bieżącego polecenia.
        - **"LOG"**: Rejestruje informacje dla administratorów serwera.
        - **"FATAL"**: Wysyła błąd, który spowodował zakończenie bieżącej sesji.
        - **"PANIC"**: Wysyła błąd, który spowodował zakończenie wszystkich sesji.

    Każdy poziom obejmuje wszystkie następne poziomy. Im wyższy poziom, tym mniej wiadomości jest rejestrowanych w logach serwera.

    Domyślnie jest ustawiona wartość **"WARNING"**, ponieważ zawiera wartości **"ERROR"**, **"LOG"**, **"FATAL"** i **"PANIC"**.

    Możesz również włączyć rozszerzenia dla swoich baz danych. W tym celu kliknij zakładkę <code className="action">Bazy danych</code>, a następnie ikonę w kształcie puzzla przy Twojej bazie danych w kolumnie **Rozszerzenia**.

<summary>Jak poznać dokładną wersję PostgreSQL, której używam?</summary>

```sql
select version();
```

<details>

<summary>Jak poznać dokładną wersję MySQL lub MariaDB, której używam?</summary>

Wprowadź poniższe polecenie w phpMyAdmin, w sekcji **"SQL"**, a następnie kliknij <code className="action">Wykonaj</code>:

```sql
show variables like "version";
```

</details>

- Przed migracją do wyższej wersji upewnij się, że Twoja baza danych jest kompatybilna z wybraną wersją.
- Zmiana zostanie zastosowana w ciągu kilku minut.

:::

:::warning
Nie można przejść bezpośrednio ze starszej wersji do najnowszej.
Korzystanie ze wszystkich wersji pośrednich jest obowiązkowe.

:::

### Optymalizacja baz danych

Utrzymuj bazę danych w dobrym stanie, aby zapewnić jej wysoką wydajność i szybkie zwracanie informacji do skryptów. Wymaga to ustrukturyzowanej i zoptymalizowanej bazy danych.

**Kliknij każdy tytuł, aby wyświetlić jego zawartość.**

<details>

<summary>Indeksowanie bazy danych</summary>

Aby przyspieszyć wyszukiwanie podczas zapytania, należy dodać indeks do pól używanych w klauzulach WHERE.

Przykład: regularnie wyszukujesz osoby w danym mieście. Zaindeksuj pole "city" za pomocą następującego zapytania:

```sql
ALTER TABLE `test` ADD INDEX (`city`);
```

</details>

<details>

<summary>Czyszczenie bazy danych</summary>

Niektóre z Twoich danych nie są już używane? Archiwizując je, zmniejszysz rozmiar tabel, a wyszukiwania będą szybsze.

</details>

<details>

<summary>Ograniczenie wyświetlania</summary>

Ogranicz wyświetlanie rekordów do ustalonej liczby (np. 10 na stronę), korzystając z części LIMIT zapytania SQL.

</details>

<details>

<summary>Grupowanie zapytań</summary>

Zbierz wszystkie zapytania na początku skryptu w poniższy sposób:

```bash
open_connection
request1
request2
...
close_connection
Display...
Process data
Loop through data...
Display...
...
```

</details>

<details>

<summary>Pobieranie tylko niezbędnych danych</summary>

W zapytaniach SQL upewnij się, że wybierasz tylko to, czego potrzebujesz, i nie zapominaj o połączeniach między tabelami.

Przykład:

```sql
(where table1.field = table2.field2)
```

</details>

<details>

<summary>Unikanie opcji zużywających zbyt dużo zasobów</summary>

Unikaj na przykład stosowania **"HAVING"**. Zwiększa to obciążenie zapytań. Podobnie unikaj korzystania z **"GROUP BY"**, chyba że jest to bezwzględnie konieczne.

</details>
