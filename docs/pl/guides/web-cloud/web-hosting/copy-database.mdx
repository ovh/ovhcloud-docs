## Wprowadzenie

Twoja baza danych jest kluczowym elementem w budowaniu dynamicznej strony WWW. W trakcie cyklu życia Twojej strony internetowej, ze względów praktycznych lub technicznych, możesz skopiować zawartość Twojej bazy danych do innej bazy danych [start SQL](/links/web/hosting-options-startsql) lub [Web Cloud Databases](/links/web/databases).

**Dowiedz się, jak skopiować zawartość bazy danych OVHcloud do innej bazy danych OVHcloud.**

:::info
Dzięki tej funkcji bazy danych nie są przenoszone, ale kopiowane. Oryginalna baza danych nie jest automatycznie usuwana, w przeciwieństwie do procesu migracji. Tylko zawartość źródłowej bazy danych jest zduplikowana i kopiowana do docelowej bazy danych.
:::

## Wymagania początkowe

- Posiadanie ofert baz danych [start SQL](/links/web/hosting-options-startsql) i/lub [Web Cloud Databases](/links/web/databases). Obie bazy danych muszą zostać wcześniej utworzone, aby można było korzystać z narzędzia do powielania.
- Wystarczające uprawnienia do wszystkich odpowiednich usług bazodanowych. Więcej informacji znajdziesz w naszym przewodniku [Zarządzanie kontaktami dla usług OVHcloud](/guides/account-and-service-management/account-information/managing-contacts).

## W praktyce

Zanim rozpoczniesz, upewnij się, że:

- Twój **D**ata**b**ase **M**anagement **S**ystem (MySQL, PostgreSQL, etc.) jest taki sam dla obu baz danych (źródłowa i docelowa).
- Wersja DBMS jest taka sama dla obu baz (źródłowej i docelowej). Nawet jeśli kopiowanie może działać z różnymi wersjami, zaleca się korzystanie z tych samych wersji.
- Zawartość źródłowej bazy danych nie może przekraczać rozmiaru docelowej bazy danych.

### Kopiuj zawartość bazy danych

Ta funkcja jest dostępna dla kopiowania:

- bazy danych [Start SQL](/links/web/hosting-options-startsql) (zawartej w niektórych naszych [hostingach](/links/web/hosting) lub [zamówionej osobno](/links/web/hosting-options-startsql));
- bazy danych znajdującej się na serwerze [Web Cloud Databases](/links/web/databases) (zawartej w naszych ofertach [hostingu](/links/web/hosting) **Performance**, **Agency**, **Agency Plus** i **Agency Max** lub [zamówionej osobno](/links/web/databases)).

W zależności od sytuacji ścieżka dostępu do źródłowej bazy danych jest inna.

Docelową bazą danych może być inna baza danych Start SQL lub baza danych zainstalowana na serwerze [Web Cloud Databases](/links/web/databases), zawarta w ofercie [hostingu](/links/web/hosting) **Performance**, **Agency**, **Agency Plus** i **Agency Max** lub [zamówiona oddzielnie](/links/web/databases).

**Kliknij na odpowiednią sytuację, aby wyświetlić zawartość.**

Aby wykonać operację, kliknij poniższe zakładki, aby wyświetlić kolejne **5** kroków.

<Tabs>
  <Tab label="Krok 1">

    <img className="thumbnail" alt="Zakładka Bazy danych i tabela baz danych hostingu" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/databases/tab-no-spotlight.png" loading="lazy" />
  </Tab>
  <Tab label="Krok 3">
    W tabeli kliknij przycisk <code className="action">⁝</code> w kolumnie **Działania**, po prawej stronie bazy danych, której zawartość chcesz skopiować, a następnie <code className="action">Kopiuj bazę danych</code>.

    <img className="thumbnail" alt="Menu wiersza tabeli baz danych" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/databases/row-actions-menu.png" loading="lazy" />
  </Tab>
  <Tab label="Krok 4">
    Po prawej stronie otworzy się panel. Wybierz najpierw typ miejsca docelowego, a następnie bazę danych, która otrzyma kopię.

    - <code className="action">Do bazy danych MySQL</code>: wybierz **Docelowy hosting**, a następnie **Docelową bazę danych**.
    - <code className="action">Do Web Cloud DB</code>: wybierz **Instancję Web Cloud DB**, a następnie **Docelową bazę danych**.

    <img className="thumbnail" alt="Panel Kopiuj bazę danych i listy miejsc docelowych" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/databases/copy-database-window.png" loading="lazy" />

    :::info
    Jeśli wybrany hosting nie zawiera żadnej bazy danych, wyświetla się komunikat **Brak dostępnej bazy danych na tym serwerze** wraz z przyciskiem <code className="action">Utwórz bazę danych</code>. Ten przycisk otwiera zakładkę **Bazy danych** wybranego hostingu, w której możesz utworzyć bazę przed ponownym uruchomieniem kopiowania. W przypadku bazy danych na serwerze Web Cloud DB zapoznaj się z naszym przewodnikiem "[Tworzenie baz danych i użytkowników na serwerze baz danych](/guides/web-cloud/databases/db-create-databases-users)".
    :::

    :::warning
    Jeśli docelowa baza danych nie jest pusta, jej zawartość zostanie nadpisana zawartością źródłowej bazy danych. Panel przypomina o tym przed zatwierdzeniem.
    :::

    Kliknij <code className="action">Anuluj</code>, aby przerwać operację, lub <code className="action">Potwierdź</code>, aby rozpocząć kopiowanie.
  </Tab>
  <Tab label="Krok 5">
    Kopiowanie może potrwać kilka minut. Śledź jego postęp w zakładce <code className="action">Operacje</code>, która zawiera listę operacji hostingu wraz z ich statusem oraz datami rozpoczęcia i zakończenia.
  </Tab>
</Tabs>

### Konfiguracja strony WWW z nową bazą danych

Jeśli chcesz użyć nowej bazy danych, po skopiowaniu źródłowej bazy danych wykonaj ostatnią czynność.

Upewnij się, że kopiowanie zostało zakończone, sprawdzając zakładkę <code className="action">Operacje</code> Twojego hostingu lub Twojej instancji Web Cloud DB, w zależności od źródłowej bazy danych.

Aby połączyć nową bazę danych ze stroną WWW, edytuj plik konfiguracyjny **C**ontent **M**anagement **S**ystem (**CMS**) i wprowadź informacje dotyczące połączenia z nową bazą danych.

:::warning
Zaleca się wykonanie kopii pliku konfiguracyjnego serwisu WWW przed jego modyfikacją. Jest to gwarancja możliwości zastąpienia nowej wersji pliku starą wersją w przypadku niepowodzenia konfiguracji.
:::

Jeśli na przykład korzystasz z modułu WordPress, zmodyfikuj plik konfiguracyjny *wp-config.php* znajdujący się w katalogu głównym Twojego folderu WordPress na przestrzeni dyskowej (FTP) Twojego hostingu, a następnie zaktualizuj następujące pola:

- DB_NAME
- DB_USER
- DB_PASSWORD
- DB_HOST

Aby uzyskać więcej informacji lub skorzystać z innego CMS-a, zapoznaj się z naszym przewodnikiem [Zmiana hasła do bazy danych hostingu WWW](/guides/web-cloud/web-hosting/sql-change-password).

:::info
Kopia bazy danych nie jest migracją. Źródłowa baza danych nadal istnieje, dopóki jej nie usuniesz. Będziesz mógł wówczas ponownie skonfigurować Twoją stronę WWW, używając starej bazy danych.
:::

### Przykłady zastosowania

Mogą wystąpić problemy podczas procesu kopiowania zawartości bazy danych.

**Kliknij na odpowiednią sytuację, aby wyświetlić zawartość.**

<details>
<summary>Baza danych nie wyświetla się na liście</summary>

To powiadomienie oznacza, że posiadasz tylko jedną aktywną bazę danych. Do skopiowania źródłowej bazy danych potrzebna jest również aktywna docelowa baza danych. W tym celu możesz:

- Skonfigurować nową bazę danych dostępną na Twoim hostingu.
- Skonfigurować nową bazę danych na swoim serwerze [Web Cloud Databases](/links/web/databases).
- Zamówić ofertę [start SQL](/links/web/hosting-options-startsql) lub serwer baz danych [Web Cloud Databases](/links/web/databases).

</details>

<details>
<summary>Trwa już wykonywanie operacji</summary>

Ten komunikat oznacza, że dla Twojej bazy danych trwa już wykonywanie zadania. Przejdź do zakładki <code className="action">Operacje</code> i sprawdź, czy wykonujesz już operację. Jeśli tak jest, poczekaj na jej zakończenie, aby w razie potrzeby przesłać kopię bazy danych ponownie.

</details>

<details>
<summary>Baza danych docelowa nie zawiera wystarczającej ilości miejsca</summary>

Docelowa baza danych nie zawiera wystarczającej ilości miejsca. Dostępne są dwa rozwiązania:

- Zamów nową bazę danych [start SQL](/links/web/hosting-options-startsql) dysponującą większą przestrzenią.
- Jeśli posiadasz serwer [Web Cloud Databases](/links/web/databases), zmień ofertę Web Cloud Databases dysponującą większą przestrzenią dyskową.

</details>

<details>
<summary>Źródłowa i docelowa baza danych są niezgodne</summary>

To powiadomienie oznacza, że **D**ata**b**ase **M**anagement **S**ystem (**DBMS**) w źródłowej bazie danych nie jest identyczny z systemem DBMS docelowej bazy danych.

Ten błąd może się pojawić na przykład podczas używania MySQL dla źródłowej bazy danych i PostgreSQL dla docelowej bazy danych.

</details>
