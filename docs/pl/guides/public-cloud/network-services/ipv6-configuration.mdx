## Wprowadzenie

Internet Protocol version 6 (IPv6) to najnowsza wersja protokołu internetowego (IP). Został on zaprojektowany, aby rozwiązać od dawna przewidywany problem wyczerpania adresów IPv4, dzięki wykorzystaniu adresów 128-bitowych zamiast standardowych 32-bitowych adresów IPv4.

Każda instancja Public Cloud jest dostarczana z adresem IPv4 i adresem IPv6.

W nowszych dystrybucjach systemu Linux adres IPv6 jest domyślnie skonfigurowany. Nie dotyczy to instancji Windows.

**Z tego przewodnika dowiesz się, jak skonfigurować adres IPv6 w instancji Public Cloud.**

:::info
Usługi Floating IP i Gateway nie obsługują obecnie protokołu IPv6. Protokołu IPv6 można używać wyłącznie z instancjami, które mają adres [Basic IP](/guides/public-cloud/network-services/concepts#publicmode). W regionach 3-AZ adresu IPv6 powiązanego z adresem Basic IP nie można jeszcze przydzielić z poziomu Panelu klienta OVHcloud.

:::

## Wymagania początkowe

- Instancja Public Cloud (dowolny model)
- Dostęp administracyjny (sudo) do Twojego serwera przez SSH lub pulpit zdalny (Windows)
- Podstawowa znajomość zagadnień sieciowych

## W praktyce

Poniższe sekcje zawierają konfiguracje dla dystrybucji, które obecnie oferujemy, a także dla najczęściej używanych dystrybucji/systemów operacyjnych. Pierwszym krokiem jest zawsze zalogowanie się do serwera przez SSH lub za pomocą sesji logowania GUI (RDP w przypadku instancji Windows).

:::warning
Pamiętaj, że w nowszych dystrybucjach systemu Linux adres IPv6 jest domyślnie skonfigurowany w naszych instancjach Public Cloud. Przed wprowadzeniem jakichkolwiek zmian sprawdź plik konfiguracyjny systemu operacyjnego.

:::

### Słowniczek

Oto krótki słowniczek terminów użytych w tym tutorialu:

|Słowniczek|Opis|
|---|---|
|YOUR_IPV6|Adres IPv6 przypisany do Twojej usługi (np. 2607:5300:60:62ac:abcd)|
|IPV6_PREFIX|Prefiks Twojego bloku IPv6 (np. 2607:5300:60:62ac::/128 -> netmask = 128)|
|IPV6_GATEWAY|Brama Twojego bloku IPv6 (np. 2607:5300:60:62ac::1)|

### Przykłady trwałej konfiguracji

:::info
**Przykłady**

Poniższe informacje mają charakter przykładowy.

Ponieważ jesteś administratorem swoich usług, musisz dostosować te informacje do swojej dystrybucji lub systemu operacyjnego.

:::

:::warning
Przed zmodyfikowaniem pliku konfiguracyjnego zawsze utwórz kopię zapasową oryginału.

:::

Najpierw połącz się z instancją przez SSH.

:::tip
Wybierz zakładkę odpowiadającą Twojemu systemowi operacyjnemu.

:::

<Tabs>
  <Tab label="Debian (z wyjątkiem Debiana 12)">
    Domyślnie pliki konfiguracyjne znajdują się w katalogu `/etc/network/interfaces.d/`.
    
    Najlepszą praktyką jest utworzenie oddzielnego pliku konfiguracyjnego w katalogu `/etc/network/interfaces.d/` w celu skonfigurowania IPv6. W naszym przykładzie plik nosi nazwę `51-cloud-init-ipv6`:
    
    ```bash
    sudo nano /etc/network/interfaces.d/51-cloud-init-ipv6
    ```
    
    Dzięki temu konfiguracja IPv6 jest oddzielona, a w razie potrzeby możesz łatwo wycofać zmiany.
    
    Dodaj do pliku następujące wiersze. Zastąp elementy ogólne (tj. `YOUR_IPV6`, `IPV6_PREFIX` i `IPV6_GATEWAY`) oraz interfejs sieciowy (jeśli Twój serwer nie używa **eth0**) własnymi wartościami:
    
    ```console
    iface eth0 inet6 static
    address YOUR_IPV6
    netmask IPV6_PREFIX
    post-up /sbin/ip -6 route add IPV6_GATEWAY dev eth0
    post-up /sbin/ip -6 route add default via IPV6_GATEWAY dev eth0
    pre-down /sbin/ip -6 route del default via IPV6_GATEWAY dev eth0
    pre-down /sbin/ip -6 route del IPV6_GATEWAY dev eth0
    ```
    
    <details>
    <summary>Przykładowa konfiguracja</summary>

    ```console
    iface eth0 inet6 static
    address 2607:5300:201:abcd::7c5
    netmask 128
    post-up /sbin/ip -6 route add 2607:5300:201:abcd::1 dev eth0
    post-up /sbin/ip -6 route add default via 2607:5300:201:abcd::1 dev eth0
    pre-down /sbin/ip -6 route del default via 2607:5300:201:abcd::1 dev eth0
    pre-down /sbin/ip -6 route del 2607:5300:201:abcd::1 dev eth0
    ```

    </details>
    
    Następnie uruchom ponownie usługę sieciową za pomocą jednego z poniższych poleceń:
    
    ```bash
    sudo service networking restart
    ```
    
    ```bash
    sudo systemctl restart networking
    ```
  </Tab>
  <Tab label="Ubuntu i Debian 12">
    Pliki konfiguracyjne sieci znajdują się w katalogu `/etc/netplan/`.
    
    Najlepszą praktyką jest utworzenie oddzielnego pliku konfiguracyjnego w katalogu `/etc/netplan/` w celu skonfigurowania IPv6. W naszym przykładzie plik nosi nazwę `51-cloud-init-ipv6.yaml`:
    
    ```bash
    sudo nano /etc/netplan/51-cloud-init-ipv6.yaml
    ```
    
    Dzięki temu konfiguracja IPv6 jest oddzielona, a w razie potrzeby możesz łatwo wycofać zmiany.
    
    Dodaj do pliku następujące wiersze. Zastąp elementy ogólne (tj. `YOUR_IPV6`, `IPV6_PREFIX` i `IPV6_GATEWAY`) oraz interfejs sieciowy (jeśli Twój serwer nie używa **eth0**) własnymi wartościami:
    
    ```yaml
    network:
        version: 2
        ethernets:
            eth0:
                dhcp6: no
                match:
                  name: eth0
                addresses:
                  - YOUR_IPV6/IPv6_PREFIX
                routes:
                  - to: ::/0
                    via: IPv6_GATEWAY
    ```
    
    :::warning
    Ważne jest zachowanie wyrównania każdego elementu w tym pliku, tak jak pokazano w powyższym przykładzie. Nie używaj klawisza tabulatora do tworzenia odstępów. Używaj wyłącznie klawisza spacji.

    :::

    <details>
    <summary>Przykładowa konfiguracja</summary>

    ```yaml
    network:
        version: 2
        ethernets:
            eth0:
                dhcp6: no
                match:
                  name: eth0
                addresses:
                  - 2607:5300:201:abcd::7c5/128
                routes:
                  - to: ::/0
                    via: 2607:5300:201:abcd::1
    ```

    </details>
    
    Możesz przetestować konfigurację za pomocą tego polecenia:
    
    ```bash
    sudo netplan try
    ```
    
    Jeśli jest poprawna, zastosuj ją za pomocą następującego polecenia:
    
    ```bash
    sudo netplan apply
    ```
  </Tab>
  <Tab label="RedHat / CloudLinux / Rocky Linux (8 & 9) / AlmaLinux (8 & 9)">
    Pliki konfiguracyjne sieci znajdują się w katalogu `/etc/sysconfig/network-scripts/`. Zalecamy rozpoczęcie od wykonania kopii zapasowej odpowiedniego pliku konfiguracyjnego.
    
    W naszym przykładzie plik nosi nazwę `ifcfg-eth0`, dlatego wykonujemy kopię zapasową pliku `ifcfg-eth0` za pomocą następujących poleceń. Pamiętaj, aby w razie potrzeby zastąpić **eth0** nazwą faktycznie używanego interfejsu.
    
    ```bash
    cd /etc/sysconfig/network-scripts/
    sudo mkdir backup
    sudo cp ifcfg-eth0 backup/ifcfg-eth0
    ```
    
    Pozwoli to później wycofać zmiany za pomocą poniższych poleceń:
    
    ```bash
    sudo rm -f /etc/sysconfig/network-scripts/ifcfg-eth0
    sudo cp /etc/sysconfig/network-scripts/backup/ifcfg-eth0 /etc/sysconfig/network-scripts/ifcfg-eth0
    ```
    
    Następnie edytujemy plik `ifcfg-eth0`, dodając tylko wiersze dotyczące konfiguracji IPv6 serwera. Zastąp elementy ogólne (tj. `YOUR_IPV6`, `IPV6_PREFIX` i `IPV6_GATEWAY`) własnymi wartościami.
    
    ```console
    IPV6INIT=yes
    IPV6ADDR=YOUR_IPV6/IPV6_PREFIX
    IPV6_DEFAULTGW=IPV6_GATEWAY
    ```
    
    Aby uniknąć pomyłek, pominęliśmy konfigurację IPv4, ale konfigurację IPv6 wprowadza się w tym samym pliku konfiguracyjnym.
    
    <details>
    <summary>Przykładowa konfiguracja</summary>

    ```console
    IPV6INIT=yes
    IPV6ADDR=2607:5300:201:abcd::7c5/128
    IPV6_DEFAULTGW=2607:5300:201:abcd::1
    ```

    </details>
    
    Uruchom ponownie interfejs sieciowy za pomocą jednego z poniższych poleceń:
    
    ```bash
    sudo service networking restart
    ```
    
    ```bash
    sudo systemctl restart networking
    ```

### Diagnostyka

Twój adres IPv6 jest skonfigurowany, ale nic nie działa?

Aby ustalić, czy błąd leży po stronie Twojej konfiguracji, czy sieci OVHcloud, wykonaj ten prosty test.

Najpierw [przełącz instancję w tryb rescue-pro](/guides/public-cloud/compute/put-an-instance-in-rescue-mode).

Następnie skonfiguruj tymczasowo IPv6 za pomocą poniższych poleceń wzorcowych, zastępując `YOUR_IPV6`, `IPV6_PREFIX` i `IPV6_GATEWAY` własnymi danymi:

```bash
ip addr add YOUR_IPV6/IPV6_PREFIX dev eth0
ip -6 route add IPV6_GATEWAY dev eth0
ip -6 route add default via IPV6_GATEWAY dev eth0
```

Ponownie przetestuj sieć, na przykład za pomocą polecenia ping6:

```bash
ping6 ipv6.google.com
```

Jeśli instancja odpowiada, prawdopodobnie w jednym z kroków początkowej konfiguracji wystąpił błąd.

W każdym przypadku możesz skontaktować się z naszym [zespołem pomocy technicznej](/links/support-contact), przekazując wyniki powyższych testów, a przeprowadzimy analizę po naszej stronie.
