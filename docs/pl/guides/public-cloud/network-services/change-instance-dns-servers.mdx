## Wprowadzenie

Domyślnie serwerem DNS instancji Public Cloud jest serwer OVHcloud (na przykład 213.186.33.99). Możesz dodać serwer zapasowy lub zastąpić tę konfigurację Twoją. Serwery DNS są skonfigurowane automatycznie przez serwer DHCP i nie można zmienić konfiguracji DNS edytując plik `resolv.conf`.

**Niniejszy przewodnik wyjaśnia, jak zmienić konfigurację DHCP instancji, aby zmienić serwery DNS.**

## W praktyce

Zaloguj się do instancji przez SSH. Więcej informacji na ten temat znajdziesz w przewodniku "[Logowanie do instancji Public Cloud](/guides/public-cloud/compute/getting-started#connect-instance)".

<Tabs>
  <Tab label="Debian / Ubuntu">
    Za pomocą wybranego edytora tekstu zmodyfikuj plik `/etc/dhcp/dhclient.conf`, aby skonfigurować wybrane serwery DNS.

    Zastąp `IP1` i `IP2` adresami IP swoich serwerów DNS, a następnie użyj dyrektywy odpowiadającej Twoim potrzebom:

    - Aby **zastąpić** serwer skonfigurowany domyślnie:

    ```console
    supersede domain-name-servers IP1, IP2;
    ```

    - Aby **nadać priorytet** swoim serwerom DNS względem serwera domyślnego:

    ```console
    prepend domain-name-servers IP1, IP2;
    ```

    - Aby używać swoich serwerów DNS **tylko wtedy, gdy serwer domyślny jest niedostępny**:

    ```console
    append domain-name-servers IP1, IP2;
    ```

    Zapisz plik, a następnie sprawdź, czy konfiguracja została poprawnie zastosowana:

    ```bash
    cat /etc/resolv.conf
    ```

    ```console
    domain openstacklocal
    search openstacklocal
    nameserver IP1
    nameserver IP2
    ```
  </Tab>
  <Tab label="CentOS / Fedora">
    Sprawdź aktualną konfigurację za pomocą polecenia `nmcli`:

    ```bash
    nmcli
    ```

    ```console
    eth0: connected to System eth0
            "Red Hat Virtio"
            ethernet (virtio_net), FA:16:3E:B6:FB:89, hw, mtu 1500
            ip4 default
            inet4 51.77.205.51/32
            route4 0.0.0.0/0
            route4 51.77.205.51/32
            route4 51.77.204.1/32
            inet6 fe80::f816:3eff:feb6:fb89/64
            route6 ff00::/8
            route6 fe80::/64

    lo: non-managed
            "lo"
            loopback (unknown), 00:00:00:00:00:00, sw, mtu 65536

    DNS configuration:
            servers: 127.0.0.1 213.186.33.99
            interface: eth0
    ```

    Pobierz nazwę swojego interfejsu publicznego:

    ```bash
    nmcli connection show
    ```

    ```console
    NAME         UUID                                  TYPE      DEVICE
    System eth0  5fb06bd0-0bb0-7ffb-45f1-d6edd65f3e03  ethernet  eth0
    ```

    Wyłącz automatyczną zmianę serwerów DNS i dodaj swoje serwery DNS (zastąp `System eth0` rzeczywistą wartością, a `IP1`/`IP2` swoimi adresami IP):

    ```bash
    nmcli con mod "System eth0" ipv4.ignore-auto-dns yes
    nmcli con mod "System eth0" ipv4.dns "IP1 IP2"
    ```

    Zastosuj konfigurację:

    ```bash
    nmcli con down "System eth0" && nmcli con up "System eth0"
    ```

    Sprawdź, czy konfiguracja została poprawnie zastosowana:

    ```bash
    nmcli | grep -E 'DNS|server|interface'
    ```

    ```console
    DNS configuration:
            servers: IP1 IP2
            interface: eth0
    ```
  </Tab>
