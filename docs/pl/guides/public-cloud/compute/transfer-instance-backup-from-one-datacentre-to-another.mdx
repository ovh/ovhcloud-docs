## Wprowadzenie

Może zaistnieć potrzeba przeniesienia [instancji Public Cloud](https://www.ovhcloud.com/pl/public-cloud/compute/) z jednego regionu OpenStack do innego, albo dlatego, że wolisz przejść do nowo dostępnego regionu OpenStack, albo dlatego, że chcesz migrować z OVHcloud Labs do Public Cloud.

**Dowiedz się, jak przenieść kopię zapasową instancji z jednego regionu OpenStack do innego, zachowując jednocześnie stan i konfigurację instancji.**

## Wymagania początkowe

- CLI OpenStack. Zapoznaj się z [naszym przewodnikiem opisującym, jak przygotować środowisko do korzystania z API OpenStack](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment).
- Łączność z interfejsami API OpenStack OVHcloud.
- Dostępna przestrzeń dyskowa odpowiadająca rozmiarowi dysku instancji (do tymczasowego przechowywania kopii zapasowej).

Środowisko to będzie używane jako "jump host" do przenoszenia kopii zapasowej z jednego regionu do innego. Może to być instancja hostowana w OVHcloud lub Twoja maszyna lokalna.

Będziesz również potrzebować [instancji Public Cloud](https://www.ovhcloud.com/pl/public-cloud/compute/) na koncie OVHcloud.

## W praktyce

:::info
Jeśli musisz utworzyć kopię zapasową za pomocą OpenStack, zapoznaj się z naszym przewodnikiem "[Tworzenie kopii zapasowej instancji](/guides/public-cloud/compute/save-an-instance)".
:::

### Etap 1 - Pobieranie kopii zapasowej

Wyświetl listę swoich prywatnych obrazów, aby zidentyfikować kopię zapasową, którą chcesz przenieść:

```bash
openstack image list --private
```

Pobierz kopię zapasową do lokalnej przestrzeni dyskowej:

```bash
openstack image save --file backup.qcow2 <image-id>
```

### Etap 2 - Przełączenie na region docelowy

Jeśli przenosisz kopię zapasową do innego regionu w ramach tego samego projektu, zaktualizuj `OS_REGION_NAME`:

```bash
export OS_REGION_NAME=<region-docelowy>
```

Jeśli przenosisz kopię zapasową do innego projektu lub na inne konto, pobierz odpowiedni plik RC:

```bash
source openrc.sh
```

### Etap 3 - Import kopii zapasowej do regionu docelowego

Polecenie importu różni się w zależności od tego, czy region docelowy jest regionem standardowym, czy strefą Local Zone.

#### Region standardowy

```bash
openstack image create \
  --disk-format qcow2 \
  --container-format bare \
  --file backup.qcow2 \
  <nazwa-obrazu>
```

#### Local Zone

Nazwy regionów Local Zone zawierają `-lz-` (na przykład `eu-central-lz-prg-a`). Wymagają one `--disk-format raw`. Rozszerzenie pliku kopii zapasowej nie ma wpływu na import — to parametr `--disk-format` wskazuje OpenStack, jak zinterpretować plik.

```bash
openstack image create \
  --disk-format raw \
  --container-format bare \
  --file backup.qcow2 \
  <nazwa-obrazu>
```

:::warning
**Tylko obrazy Windows** — musisz dodać następujące właściwości, w przeciwnym razie nie będzie można powiązać flavor typu `win-x-x` z poziomu Panelu klienta OVHcloud. Ten typ flavor jest wymagany do uwierzytelnienia w [KMS OVHcloud](/guides/manage-and-operate/kms/quick-start).

Dodaj właściwości podczas tworzenia (region standardowy):

```bash
openstack image create \
  --disk-format qcow2 \
  --container-format bare \
  --file backup.qcow2 \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <nazwa-obrazu>
```

Dodaj właściwości podczas tworzenia (Local Zone):

```bash
openstack image create \
  --disk-format raw \
  --container-format bare \
  --file backup.qcow2 \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <nazwa-obrazu>
```

Możesz też ustawić je dla istniejącego obrazu:

```bash
openstack image set \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <image-uuid>
```
:::

:::info
Aby ponownie utworzyć instancję z tej kopii zapasowej, postępuj zgodnie z naszym przewodnikiem "[Tworzenie / przywracanie serwera wirtualnego na podstawie kopii zapasowej](/guides/public-cloud/compute/create-restore-a-virtual-server-with-a-backup)".
:::
