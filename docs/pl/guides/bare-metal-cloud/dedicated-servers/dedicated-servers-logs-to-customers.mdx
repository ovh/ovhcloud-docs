## Wprowadzenie

Z tego przewodnika dowiesz się, jak włączyć przekazywanie logów serwera dedykowanego OVHcloud do Logs Data Platform (LDP) — platformy, która pomaga przechowywać, archiwizować, przeszukiwać i wizualizować logi.

Jeśli przed lekturą tego przewodnika chcesz dowiedzieć się więcej o Logs Data Platform, zapoznaj się z [przewodnikiem wprowadzającym do Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/introduction).

**Z tego przewodnika dowiesz się, jak:**

- Wyświetlać logi serwera dedykowanego w czasie rzeczywistym.
- Utworzyć subskrypcję, która przekazuje te logi do strumienia danych Logs Data Platform.
- Przeszukiwać i wizualizować przekazane logi.
- Zarządzać subskrypcjami i je usuwać.

:::info
Logi opisane w tym przewodniku pochodzą z operacji, które OVHcloud wykonuje na Twoim serwerze: **instalacji systemu operacyjnego**, **uruchamiania przez sieć** i **konfiguracji sieci**. **Nie** są to logi systemowe generowane przez działający system operacyjny.

Aby centralizować logi generowane przez Twój system operacyjny, zapoznaj się z przewodnikiem dotyczącym [wysyłania logów systemu Linux do Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/log-linux).
:::

## Słowniczek

- **Logs Data Platform:** w pełni zarządzana i zabezpieczona platforma do zarządzania logami oferowana przez OVHcloud. Więcej informacji znajdziesz na stronie usługi [Logs Data Platform](/links/manage-operate/ldp).
- **Strumień danych (Data Stream):** logiczna partycja logów, którą tworzysz na koncie LDP i której używasz do pozyskiwania, wyświetlania lub przeszukiwania logów. W tym samym strumieniu danych można przechowywać logi z wielu źródeł. Jest to jednostka służąca do definiowania potoku logów (polityka przechowywania, archiwizacja, transmisja na żywo itp.), praw dostępu i polityk alertów.
- **Przekazywanie logów (Logs forwarding):** funkcja zintegrowana z produktem OVHcloud, która pozwala pozyskiwać logi jego usług do *strumienia danych* konta LDP należącego do tego samego konta OVHcloud. Należy ją włączyć dla każdej usługi.
- **Subskrypcja przekazywania logów (Logs forwarding Subscription):** po włączeniu przekazywania logów danej usługi OVHcloud do danego *strumienia danych* LDP tworzona jest *subskrypcja* powiązana ze *strumieniem danych*, którą następnie zarządzasz.

## Wymagania początkowe

- Konto Logs Data Platform (LDP) z co najmniej jednym aktywnym, skonfigurowanym *strumieniem*. Wszystkie niezbędne kroki opisano w przewodniku [Pierwsze kroki z Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start).
    - Jeśli nie znasz wszystkich możliwości konfiguracji *strumienia* LDP, na potrzeby tego przewodnika utwórz nowy strumień z opcjami domyślnymi (indeksowanie i WebSocket włączone, długoterminowe przechowywanie wyłączone).
- Działający [serwer dedykowany OVHcloud](/guides/bare-metal-cloud/dedicated-servers/getting-started-with-dedicated-server).
- Konto LDP i serwer dedykowany muszą należeć do tego samego konta OVHcloud.

## Pojęcia i ograniczenia

**Czym są logi serwera dedykowanego?**

Przekazywane logi rejestrują operacje wykonywane przez OVHcloud na Twoim serwerze: instalację systemu operacyjnego, uruchamianie przez sieć i konfigurację sieci.

Przekazywanie logów jest dostępne we wszystkich gamach serwerów dedykowanych.

### Typy logów

Logi są pogrupowane według *typów*, a każdy typ subskrybujesz osobno. Serwer dedykowany udostępnia następujące typy:

| Typ | Nazwa wyświetlana | Opis |
|------|--------------|-------------|
| `install` | Operating system installation logs | Szczegóły instalacji systemu operacyjnego na serwerze. |
| `netboot` | Network boot logs | Dostarczenie skryptu rozruchowego iPXE do serwera, gdy uruchamia się on przez sieć (dysk twardy, rescue, instalator itp.). |
| `network` | Network configuration logs | Operacje sieciowe wykonywane przez OVHcloud na serwerze: Additional IP, wirtualne adresy MAC, vRack, OVHcloud Link Aggregation (OLA) i polityki przepustowości. |

Listę typów dostępnych na serwerze możesz pobrać za pomocą następującego wywołania API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/kind"} />

Aby uzyskać szczegóły danego typu, w tym zwracane przez niego dodatkowe pola, użyj następującego wywołania API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/kind/\{name\}"} />

### Zawartość logów

Oprócz pól wspólnych dla wszystkich logów pozyskiwanych przez Logs Data Platform każdy typ zwraca następujące pola.

#### Typ `install`

| Nazwa pola | Opis | Typ danych |
|------------|-------------|------|
| `level` | Poziom krytyczności wpisu w logu zgodnie ze standardowymi wartościami ważności syslog: `2` (critical), `6` (info). | Number |
| `os` | System operacyjny zainstalowany na serwerze. | String |
| `serviceName` | Wewnętrzna nazwa serwera w formacie `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Bieżący etap operacji: `os-install-start`, `os-install-failed` lub `os-install-ok`. | String |

#### Typ `netboot`

| Nazwa pola | Opis | Typ danych |
|------------|-------------|------|
| `level` | Poziom krytyczności wpisu w logu zgodnie ze standardowymi wartościami ważności syslog: `2` (critical), `6` (info). | Number |
| `serviceName` | Wewnętrzna nazwa serwera w formacie `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Wynik żądania skryptu rozruchowego: `ipxe-request-ok` lub `ipxe-request-error`. | String |

#### Typ `network`

| Nazwa pola | Opis | Typ danych |
|------------|-------------|------|
| `level` | Poziom krytyczności wpisu w logu zgodnie ze standardowymi wartościami ważności syslog: `6` (info). | Number |
| `serviceName` | Wewnętrzna nazwa serwera w formacie `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Bieżący etap operacji w formacie `<operation>-doing` (rozpoczęta) lub `<operation>-ok` (zakończona powodzeniem). Operacje: `add_ipfo`, `remove_ipfo`, `add_vmac`, `remove_vmac`, `vrack-add`, `vrack-remove`, `ola-group`, `ola-ungroup`, `qos-apply`. | String |

:::info
Powyższa lista wartości `status` odzwierciedla stan obecny i będzie się z czasem zmieniać.
:::

Informacje o polach wspólnych dla wszystkich logów znajdziesz w przewodniku dotyczącym [konwencji nazewnictwa pól](/guides/manage-and-operate/observability/logs-data-platform/field-naming-conventions).

## W praktyce

Włączenie przekazywania jest bezpłatne, jednak korzystanie z usługi Logs Data Platform jest rozliczane zgodnie ze standardowym cennikiem. Ceny LDP znajdziesz na stronie usługi [Logs Data Platform](/links/manage-operate/ldp).

### Włączanie przekazywania logów

<Tabs>
<Tab label="Przez konsolę OVHcloud">

W konsoli OVHcloud otwórz uniwersum <code className="action">Bare Metal Cloud</code>, przejdź do sekcji <code className="action">Serwery dedykowane</code>, a następnie wybierz serwer, którego logi chcesz przekazywać.

Kliknij zakładkę <code className="action">Dzienniki</code>.

Zakładka zawiera:

- listę rozwijaną **Typ dziennika**, z której wybierasz typ logów do wyświetlenia lub przekazywania (`netboot`, `network` lub `install`);
- sekcję **Strumień na żywo**, która wyświetla w czasie rzeczywistym logi serwera dla wybranego typu;
- sekcję **Logs**, która zawiera listę aktywnych subskrypcji i umożliwia tworzenie nowych.

Aby przekazywać logi do Logs Data Platform, wybierz typ dziennika, a następnie kliknij <code className="action">Add subscription</code> w sekcji **Logs**.

Jeśli masz kilka usług Logs Data Platform, w oknie **Subskrybuj strumień** wybierz jedną z nich z listy rozwijanej **Usługa Logs Data Platform** (jeśli masz tylko jedną usługę, zostanie ona wybrana automatycznie). Następnie wybierz docelowy strumień danych z listy rozwijanej **Strumień** i kliknij <code className="action">Subskrybuj</code>.

Jeśli Twoje konto nie ma jeszcze usługi Logs Data Platform, okno poinformuje o tym i wyświetli przycisk <code className="action">Zamów Logs Data Platform</code>. Jeśli Twoja usługa nie ma jeszcze strumienia, najpierw utwórz go w Logs Data Platform (zobacz przewodnik [Pierwsze kroki z Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start)).

Do strumienia danych wysyłane są wyłącznie logi wygenerowane **po** utworzeniu subskrypcji.

Więcej informacji o OVHcloud Service Logs, wspólnym dla wszystkich kompatybilnych produktów OVHcloud, znajdziesz w przewodniku [Wprowadzenie do OVHcloud Service Logs z Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/service-logs).

</Tab>
<Tab label="API OVHcloud">

Określ na jednym ze swoich kont LDP docelowy *strumień*, do którego mają być przekazywane logi. Włączenie przekazywania tworzy subskrypcję dla tego identyfikatora strumienia.

#### Etap 1 - Pobierz docelowy strumień (i jego identyfikator)

Wyświetl listę strumieni danych konta Logs Data Platform (wpisz identyfikator LDP w formacie `ldp-xx-xxxx` w polu `serviceName`):

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/output/graylog/stream"} />

Pobierz szczegóły strumienia danych:

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/output/graylog/stream/\{streamId\}"} />

#### Etap 2 - Utwórz subskrypcję

Aby utworzyć subskrypcję, użyj następującego wywołania API:

<Api version="v2" section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/log/subscription"} />

:::info
Zastąp:

- `serviceName`: wewnętrzna nazwa serwera dedykowanego w formacie `nsxxxxx.ip-xx-xx-xx.eu`. Znajdziesz ją na liście serwerów dedykowanych lub na stronie serwera w konsoli OVHcloud albo za pomocą następującego wywołania API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server"} />
:::

Żądanie POST wymaga ładunku (payload) zawierającego:

- `kind`: typ logów, które chcesz przekazywać (`install`, `netboot` lub `network`). Zobacz sekcję [Typy logów](#typy-logów) powyżej.
- `streamId`: docelowy strumień danych konta LDP, do którego mają być przekazywane logi serwera dedykowanego.

```shell
POST /dedicated/server/{serviceName}/log/subscription
{
  "kind": "install", // Jedna z wartości: install, netboot, network.
  "streamId": "198ef9d5-c320-4000-8bee-236623da5b80" // streamID docelowego strumienia.
}
```

W odpowiedzi otrzymasz `operationId`:

```shell
{
  "operationId": "f550aa1c-89ab-4b1a-81ae-4fba4959966f",
  "serviceName": "ldp-xx-xxxx"
}
```

Za pomocą `operationId` możesz pobrać `subscriptionId` na potrzeby dalszego zarządzania, korzystając z następującego wywołania API:

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/operation/\{operationId\}"} />

Możesz też, po zakończeniu operacji, pobrać subskrypcje za pomocą następującego wywołania API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/subscription"} />

Gdy masz już `subscriptionId`, możesz pobrać szczegóły za pomocą następującego wywołania API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/subscription/\{subscriptionId\}"} />

```shell
GET /dedicated/server/{serviceName}/log/subscription/{subscriptionId}

{
  "createdAt": "2026-08-31T07:42:50.645Z",
  "kind": "string",
  "resource": {
    "name": "string",
    "type": "string"
  },
  "serviceName": "string",
  "streamId": "string",
  "subscriptionId": "198efa11-f150-4000-8e8d-871b1e482b80",
  "updatedAt": "2026-08-31T07:42:50.645Z"
}
```

### Korzystanie z logów serwera dedykowanego

Twoje logi są teraz pozyskiwane i przechowywane w strumieniu danych Logs Data Platform. Możesz je przeszukiwać i tworzyć pulpity w interfejsie WWW Graylog.

- Pobierz nazwę użytkownika konta Logs Data Platform (na przykład `logs-xxxx`) i jego hasło. W konsoli OVHcloud otwórz <code className="action">Observability</code>, kliknij <code className="action">Zarządzanie usługą</code> i wybierz usługę Logs Data Platform: nazwa użytkownika jest wyświetlana jako **Nazwa użytkownika LDP** w sekcji **Informacje ogólne** (tylko w przypadku usług, które nie korzystają z OVHcloud IAM). Hasło to hasło ustawione dla tego konta. Zapoznaj się z przewodnikiem [Pierwsze kroki z Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start).
- Otwórz interfejs WWW Graylog. Możesz uzyskać do niego dostęp z pulpitów Graylog wymienionych w sekcji <code className="action">Observability</code> > <code className="action">Pulpity</code> w konsoli OVHcloud lub przez swój punkt dostępu, zależnie od regionu konta (na przykład dla regionu Gravelines jest to `https://gra1.logs.ovh.com/`).
- Zaloguj się do Graylog przy użyciu nazwy użytkownika i hasła Logs Data Platform.
- Przeszukuj logi w strumieniu danych konta Logs Data Platform. Szczegóły dotyczące składni wyszukiwania znajdziesz w dokumentacji [Search Syntax Reference](https://go2docs.graylog.org/current/making_sense_of_your_log_data/search_syntax_reference.htm).

Więcej informacji o korzystaniu z logów w Logs Data Platform, w tym o konfigurowaniu alertów, wyświetlaniu logów w czasie rzeczywistym przez WebSocket, tworzeniu wizualizacji za pomocą OpenSearch Dashboards, integracji z API OpenSearch i łączeniu z Grafaną, znajdziesz w przewodniku [Wprowadzenie do Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/introduction).

### Zarządzanie subskrypcjami

W dowolnym momencie możesz pobrać subskrypcje powiązane ze strumieniem danych Logs Data Platform i wyłączyć przekazywanie, anulując subskrypcję w strumieniu. Strumień Logs Data Platform przestanie wtedy otrzymywać logi serwera dedykowanego.

Nie powoduje to usunięcia logów zapisanych przed anulowaniem subskrypcji, ponieważ dane przechowywane w strumieniu logów są niezmienne, chyba że usuniesz cały strumień.

W konsoli OVHcloud otwórz zakładkę <code className="action">Dzienniki</code> serwera, odszukaj subskrypcję po jej Stream ID w sekcji **Logs**, a następnie kliknij ikonę kosza w jej wierszu. Subskrypcja zostanie usunięta natychmiast, bez okna potwierdzenia.

Aby usunąć subskrypcję za pomocą API, użyj następującego wywołania:

<Api version="v2" section="/dedicated/server" method="DELETE" route={"/dedicated/server/\{serviceName\}/log/subscription/\{subscriptionId\}"} />
