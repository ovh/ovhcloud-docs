## Wprowadzenie

Technologia OVHcloud Link Aggregation (OLA) została zaprojektowana przez nasze zespoły w celu zwiększenia dostępności serwera i wydajności połączeń sieciowych. Za pomocą kilku kliknięć możesz łączyć karty sieciowe i redundantować połączenia sieciowe. Oznacza to, że w przypadku awarii połączenia ruch jest automatycznie przekierowywany do innego dostępnego połączenia.<br/>
Agregacja wykorzystuje protokół LACP (Link Aggregation Control Protocol), zdefiniowany w standardzie IEEE 802.3ad.

**Dowiedz się, jak skonfigurować OLA w konsoli OVHcloud.**

## Wymagania początkowe

- Posiadanie [serwera dedykowanego OVHcloud](/links/bare-metal/bare-metal) z gamy Advance, Scale lub High Grade
- System operacyjny / Hypervisor obsługujący protokół 802.3ad (LACP)

## W praktyce

:::warning
Konfiguracja OLA odbywa się na wszystkich interfejsach sieciowych. Stanowią one agregat typu "agregacja prywatna".

Po wdrożeniu OLA publiczny adres IP nie będzie już dostępny.

:::


### Konfiguracja OLA w konsoli OVHcloud

Aby rozpocząć konfigurację OLA, otwórz zakładkę <code className="action">Connectivity</code> na stronie zarządzania serwerem.

W sekcji **OVHcloud Link Aggregation (OLA)** kliknij <code className="action">Configure OLA</code>.

W panelu **Configure OLA aggregation** wprowadź nazwę swojej agregacji łączy w polu **Name the interface**.

Pod tym polem dwie tabele porównują konfigurację przed agregacją i po niej:

- **Your current network interface**: aktualna konfiguracja interfejsów sieciowych;
- **Your network interface after activation**: symulowana konfiguracja zagregowanych interfejsów sieciowych.

:::warning
Podczas stosowania agregacji konfiguracja interfejsów sieciowych zostanie usunięta, a serwer utraci łączność. Następnie musisz skonfigurować bond w systemie operacyjnym z poziomu konsoli KVM (zapoznaj się z przewodnikiem [Jak korzystać z konsoli IPMI na serwerze dedykowanym](/guides/bare-metal-cloud/dedicated-servers/ipmi) oraz z przewodnikami dotyczącymi systemów operacyjnych poniżej). Bez tego konfiguracja nie jest kompletna.
:::

Po sprawdzeniu, że układ agregacji spełnia wymagania sieciowe, kliknij <code className="action">Aggregate</code>, aby kontynuować.

Może to potrwać kilka minut. Po zakończeniu tej operacji kolejnym krokiem jest skonfigurowanie interfejsów w systemie operacyjnym za pomocą powiązania interfejsów (NIC link) lub zespołu interfejsów (NIC team). Aby poznać metodę, którą należy zastosować, zapoznaj się z poniższymi przewodnikami dotyczącymi najpopularniejszych systemów operacyjnych:

- [Konfiguracja agregacji łączy LACP w systemie Debian 9-11 (ifupdown)](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-ifupdown).
- [Konfiguracja NIC teaming dla OVHcloud Link Aggregation (OLA) w systemie Windows Server 2019](/guides/bare-metal-cloud/dedicated-servers/ola-enable-w2k19).
- [Konfiguracja agregacji łączy LACP w systemie SLES 15](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-sles15).
- [Konfiguracja agregacji łączy LACP w systemie Debian 12 lub nowszym / Ubuntu 24.04 lub nowszym (Netplan)](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-netplan).

### Sprawdzanie statusu OLA

Status OVHcloud Link Aggregation (OLA) możesz sprawdzić w zakładce <code className="action">Connectivity</code> na stronie zarządzania serwerem. W sekcji **OVHcloud Link Aggregation (OLA)** wiersz **OLA** pokazuje status, a wiersz **Mode** typ agregacji.

Możliwe kombinacje:

- **Available**, tryb **Default**: OLA jest obsługiwana, ale nie jest skonfigurowana.
- **Active**, tryb **Full private**: OLA jest włączona; wszystkie fizyczne interfejsy są zagregowane w jedno prywatne łącze do użytku z vRack.
- **Available**, tryb **Double LAG**: interfejsy są podzielone na dwa agregaty (jeden publiczny, jeden prywatny) w układzie innym niż domyślny układ serwera.
- **Trwa agregacja...** lub **Trwa resetowanie...**: trwa wprowadzanie zmiany OLA; wiersze **Mode** i **Virtual interfaces** wyświetlają myślnik do czasu zakończenia operacji.

Jeśli OLA nie jest obsługiwana przez ten model serwera dedykowanego, sekcja **OVHcloud Link Aggregation (OLA)** wyświetla komunikat **OLA nie jest uwzględnione**, a wiersz **OLA** w sekcji **Łączność** zakładki <code className="action">Przegląd</code> serwera pokazuje **Unavailable**.

:::info
Na serwerach Scale i High Grade domyślny układ grupuje już cztery interfejsy w jeden agregat publiczny i jeden agregat prywatny; konsola wyświetla go jako **Available**, tryb **Default**.

:::

### Przywróć OLA do wartości domyślnych

Aby przywrócić domyślne ustawienia OLA, otwórz zakładkę <code className="action">Connectivity</code> i kliknij <code className="action">Reset</code> w sekcji **OVHcloud Link Aggregation (OLA)**. (Ten przycisk jest wyświetlany tylko wtedy, gdy OLA jest aktywna w trybie **Full private**.) Podczas resetowania konfiguracja interfejsów zostaje usunięta, a serwer traci łączność. Kliknij <code className="action">Confirm</code> w oknie **Reset OVHcloud Link Aggregation**.

Może to potrwać kilka minut.
