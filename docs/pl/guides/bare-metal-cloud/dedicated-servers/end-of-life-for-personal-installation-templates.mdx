**To ważna dokumentacja. Przeczytaj ją uważnie, ponieważ zmiany mogą Cię dotyczyć, jeśli zlecasz instalację systemu operacyjnego na nowym serwerze dedykowanym lub reinstalację systemu na posiadanym już serwerze dedykowanym.**

Choć na tej stronie opisano wycofanie własnych szablonów służących do instalacji systemu operacyjnego na serwerach dedykowanych oraz jego skutki, możesz mieć pewność, że **żadna funkcja nie zostanie utracona**.  
Po wycofaniu szablonów nadal będziesz mógł instalować systemy operacyjne z **takim samym poziomem personalizacji jak dotychczas**. Ponadto klienci korzystający bezpośrednio z API zyskają **jedno, uproszczone wywołanie API**.

## Wprowadzenie

Na tej stronie znajdziesz najważniejsze informacje o planie wycofania własnych szablonów używanych do instalacji systemów operacyjnych na serwerach dedykowanych. Zawiera ona również przydatne wskazówki dla klientów korzystających z konsoli OVHcloud lub z panelu klienta So you Start lub Kimsufi. Przedstawia także zalety nowego wywołania API w porównaniu z wycofywanym wywołaniem API.

## Kontekst<a id="context"></a>

OVHcloud nieustannie się rozwija i musi dostosowywać swoje oferty do coraz bardziej odpornego i regulowanego rynku chmury. Aby sprostać tym nowym wyzwaniom, **własne szablony do instalacji systemu operacyjnego na serwerach dedykowanych** zostaną całkowicie wycofane **7 października 2025 r.**

Ta funkcja umożliwiała zlecenie instalacji systemu operacyjnego na serwerze dedykowanym przy użyciu własnego szablonu zawierającego następujące elementy:

- System operacyjny do zainstalowania
- Schemat partycjonowania
- Konfiguracja sprzętowego RAID
- Nazwa hosta
- Publiczny klucz SSH
- Skrypt poinstalacyjny

Aby uprościć instalację systemów operacyjnych na serwerach dedykowanych oraz komunikację dotyczącą migracji, utworzono nowe wywołanie API: `POST /dedicated/server/{serviceName}/reinstall`. To wywołanie API zastępuje dotychczasową ścieżkę: `POST /dedicated/server/{serviceName}/install/start`. Dotychczasowa ścieżka umożliwiała instalację systemu operacyjnego z szablonu OVHcloud **lub z własnego szablonu**.

Dotychczasowa ścieżka oraz pojęcie własnych szablonów zostaną wycofane. Nowa ścieżka obsługuje wyłącznie instalację systemu operacyjnego z szablonu OVHcloud. Pamiętaj również, że termin "szablon OVHcloud" będzie stopniowo zastępowany precyzyjniejszym terminem "system operacyjny".

Wycofanie własnych szablonów nastąpi w 2 etapach:

### Etap 1: 17 czerwca 2025 r.<a id="step-1"></a>

- Klienci nie będą już mogli **edytować** ani **dodawać** nowych własnych szablonów.
- Klienci posiadający własne szablony i aktywne subskrypcje serwerów dedykowanych otrzymają e-mailem spersonalizowane informacje techniczne, które pomogą im przenieść własne szablony do <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nowego wywołania API "/reinstall"</ApiLink>.

### Etap 2: 7 października 2025 r.<a id="step-2"></a>

- Klienci nie będą już mieli dostępu do swoich własnych szablonów.
- Wszystkie dane związane z własnymi szablonami zostaną usunięte.

Pamiętaj, że klienci nadal będą dysponować e-mailem z 19 maja 2025 r. zawierającym dokumentację techniczną przygotowaną na podstawie danych ich własnych szablonów, która pomoże im w migracji do nowego wywołania API.

## W praktyce <a id="instructions"></a>

Poniższa sekcja zawiera szczegółowe informacje dla wszystkich klientów posiadających konto w OVHcloud, So you Start lub Kimsufi, w zależności od tego, czy obecnie instalujesz systemy operacyjne na serwerze dedykowanym za pomocą konsoli OVHcloud, czy za pomocą API.

### Korzystanie z konsoli OVHcloud lub z panelu klienta So you Start lub Kimsufi<a id="ux"></a>

Kreator `Zainstaluj jeden z Twoich szablonów`, służący do instalacji systemu operacyjnego na serwerze dedykowanym, został usunięty już w połowie kwietnia 2025 r. Jeśli korzystałeś z tego kreatora, masz 3 długoterminowe możliwości:

- Dalsze korzystanie z interfejsu WWW (niezalecane, jeśli planujesz automatyzację instalacji systemów operacyjnych): przy każdej instalacji zastosuj ręcznie wszystkie personalizacje w kreatorze instalacji systemu operacyjnego (dawny kreator `Zainstaluj z szablonu OVHcloud`).
- Napisanie skryptu korzystającego z API (najlepsze rozwiązanie do automatyzacji, ale wymaga umiejętności programowania): zapoznaj się z sekcją [Korzystanie z API OVHcloud, So you Start lub Kimsufi](#api) poniżej.
- Korzystanie z konsoli API (dobry kompromis): używaj dotychczasowego wywołania API do 17 czerwca 2025 r., a następnie nowego wywołania API z przekazanymi payloadami.

Możesz już teraz zapoznać się z przykładami i schematami <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nowego wywołania API "/reinstall" w konsoli API</ApiLink> oraz z jego [publiczną dokumentacją](/guides/bare-metal-cloud/dedicated-servers/api-os-installation). Poniżej znajdziesz rozwiązanie tymczasowe, z którego możesz korzystać do czasu otrzymania e-mailem payloadów dla nowej ścieżki API 17 czerwca 2025 r.

#### Rozwiązanie tymczasowe dla OVHcloud <a id="ux-ovh"></a>

Zgodnie z [dokumentacją API OVHcloud](/guides/manage-and-operate/api/first-steps#logowanie-do-api-ovhcloud), na stronie <ApiLink>konsoli API OVHcloud</ApiLink>:

- Kliknij `Authentication` w lewym górnym rogu.
- Wybierz `Login with OVHcloud SSO`.
- Wprowadź swoje dane do logowania OVHcloud.
- Kliknij `Authorize`, aby zezwolić na wykonywanie wywołań API z poziomu konsoli.

![API](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/login.png)

Następnie wykonaj wywołanie API, aby uruchomić instalację systemu operacyjnego z własnego szablonu:

- Wybierz `v1`.
- Wybierz sekcję `/dedicated/server`.
- Znajdź wywołanie API `POST /dedicated/server/{serviceName}/install/start` (możesz użyć filtra).
- W polu `serviceName` wpisz nazwę serwera dedykowanego, na którym ma zostać przeprowadzona instalacja.
- W polu `REQUEST BODY` (czyli payload API) wprowadź następującą wartość JSON (w tym przykładzie zakładamy, że "my-amazing-template" to nazwa własnego szablonu, który chcesz zainstalować):

```json
{
  "templateName": "my-amazing-template"
}
```

Jeśli chcesz wyświetlić listę własnych szablonów i ich szczegóły, przejdź do sekcji `/me` i sprawdź wszystkie wywołania API `GET` w ścieżce `/me/installationTemplate`.

:::danger
**Wykonanie wywołania [POST /dedicated/server/\{serviceName\}/install/start](https://api.eu.ovhcloud.com/console/?section=%2Fdedicated%2Fserver&branch=v1#post-/dedicated/server/-serviceName-/install/start) na serwerze dedykowanym spowoduje usunięcie wszystkich danych zapisanych na tym serwerze. ZACHOWAJ OSTROŻNOŚĆ, KORZYSTAJĄC Z TEGO WYWOŁANIA API.**
:::

Następnie kliknij przycisk `Execute`, aby uruchomić instalację systemu operacyjnego.

![console API](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/screenshot-api-console-workaround.png)

Możesz wrócić do <ManagerLink to="/">konsoli OVHcloud</ManagerLink>, na stronę panelu serwera dedykowanego, aby śledzić postęp instalacji.

#### Rozwiązania tymczasowe dla So you Start lub Kimsufi <a id="ux-sys-ks"></a>

Otwórz [konsolę API So you Start](https://eu.api.soyoustart.com/console/) lub [konsolę API Kimsufi](https://eu.api.kimsufi.com/console/).

Kliknij `Login` w prawym górnym rogu i wprowadź swoje dane do logowania. Następnie kliknij przycisk `Log in`: jesteś teraz uwierzytelniony w konsoli API.

- Otwórz sekcję `/dedicated/server`.
- Znajdź wywołanie API `POST /dedicated/server/{serviceName}/install/start`.
- W polu `serviceName` wpisz nazwę serwera dedykowanego, na którym ma zostać przeprowadzona instalacja.
- W polu `templateName` wpisz nazwę własnego szablonu, który chcesz zainstalować.

Jeśli chcesz wyświetlić listę własnych szablonów i ich szczegóły, przejdź do sekcji `/me` i sprawdź wszystkie wywołania API `GET` w ścieżce `/me/installationTemplate`.

:::danger
**Wykonanie wywołania [POST /dedicated/server/\{serviceName\}/install/start](https://eu.api.soyoustart.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) (lub [tego wywołania](https://eu.api.kimsufi.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) w przypadku Kimsufi) na serwerze dedykowanym spowoduje usunięcie wszystkich danych zapisanych na tym serwerze. ZACHOWAJ OSTROŻNOŚĆ, KORZYSTAJĄC Z TEGO WYWOŁANIA API.**
:::

Następnie kliknij przycisk `Execute`, aby uruchomić instalację systemu operacyjnego.

Możesz wrócić do [panelu klienta So you Start](https://eu.soyoustart.com/manager) lub [panelu klienta Kimsufi](https://www.kimsufi.com/fr/manager), na stronę panelu serwera dedykowanego, aby śledzić postęp instalacji.

### Korzystanie z API OVHcloud, So you Start lub Kimsufi <a id="api"></a>

Jeśli uruchamiasz instalacje systemów operacyjnych z własnego szablonu za pomocą API OVHcloud, So you Start lub Kimsufi, możesz nadal korzystać z wywołania API `POST /dedicated/server/{serviceName}/install/start` do **7 października 2025 r.**  
Pamiętaj jednak, że od **17 czerwca 2025 r.** nie będzie już możliwe dodawanie ani edytowanie własnych szablonów.

Choć otrzymasz e-mail ze wszystkimi szczegółami dotyczącymi migracji payloadów API do <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nowego wywołania API "/reinstall"</ApiLink>, możesz już teraz zapoznać się z jego przykładami i schematami w konsoli API (schemat API jest taki sam dla OVHcloud, [So you Start](https://eu.api.soyoustart.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) i [Kimsufi](https://eu.api.kimsufi.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST)) oraz z jego [publiczną dokumentacją](/guides/bare-metal-cloud/dedicated-servers/api-os-installation).

Wycofanie funkcji własnych szablonów uprości instalację systemów operacyjnych na serwerach dedykowanych. Nowe wywołanie API <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>POST /dedicated/server/\{serviceName\}/reinstall</ApiLink> oferuje bowiem wszystkie możliwe personalizacje, których dotychczasowe wywołanie API [POST /dedicated/server/\{serviceName\}/install/start](https://api.eu.ovhcloud.com/console/?section=%2Fdedicated%2Fserver&branch=v1#post-/dedicated/server/-serviceName-/install/start) nie mogło zapewnić bez wcześniejszego zdefiniowania własnego szablonu w ścieżce [/me/installationTemplate](https://api.eu.ovhcloud.com/console/?section=%2Fme&branch=v1#get-/me/installationTemplate).

Poniższe porównanie pokazuje, o ile zmniejsza się liczba wywołań API potrzebnych do złożonej konfiguracji obejmującej sprzętowy RAID i niestandardowe partycjonowanie: z `4+n` wywołań (gdzie `n` to liczba partycji zdefiniowanych w schemacie partycjonowania) do jednego wywołania API.

![Porównanie wywołań API](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/api-calls-comparison.png)

Jak widać, cały proces jest uproszczony i nie wymaga już czasochłonnej konfiguracji.
