## Wprowadzenie

Nasze interwencje serwisowe ograniczają się do warstwy sprzętowej serwera. Po interwencji serwisowej może być konieczne wykonanie działań w warstwie oprogramowania serwera.

Niniejszy przewodnik, oparty na doświadczeniach naszych zespołów i przypadkach użycia, zawiera listę działań, które należy wykonać w zależności od instalacji: systemu operacyjnego, hypervisora itp.

Jego celem jest wsparcie użytkownika i ograniczenie do minimum wpływu na cykl życia środowisk.

## Wymagania początkowe

- Posiadanie [serwera dedykowanego](/links/bare-metal/bare-metal) na koncie OVHcloud

<a name="ubuntu"></a>

### Ubuntu/Debian 12+

Jeśli występują problemy z łącznością sieciową (na przykład brak odpowiedzi na ping po wymianie płyty głównej), wykonaj następujące kroki:

1\. Uruchom ponownie serwer w [trybie Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).<br/>
2\. Zamontuj partycję `/`:

```bash
root@rescue:~# mount /dev/my_system_disk /mnt
```

Jeśli plik `70-persistent-net.rules` nie istnieje (zapoznaj się z częścią przewodnika dotyczącą [nazw interfejsów sieciowych](#network-interface)), sprawdź następujące pliki w drzewie katalogów `/etc/systemd/network/`:

- `50-default.network`
- `50-public-interface.link`

```bash
root@rescue:~# cat /mnt/etc/systemd/network/50-default.network
# This file sets the IP configuration of the primary (public) network device.
# You can also see this as "OSI Layer 3" config.
# It was created by the OVH installer, please be careful with modifications.
# Documentation: man systemd.network or https://www.freedesktop.org/software/systemd/man/systemd.network.html
 
[Match]
MACAddress=xx:xx:xx:xx:xx:xx
 
[Network]
Description=network interface on public network, with default route
DHCP=no
Address=1.2.3.4/24
Gateway=1.2.3.254
IPv6AcceptRA=no
NTP=ntp.ovh.net
DNS=127.0.0.1
DNS=213.186.33.99
DNS=2001:41d0:3:163::1
Gateway=2001:41d0:0203:4bff:ff:ff:ff:ff
 
[Address]
Address=2001:41d0:0203:1234::/64
 
[Route]
Destination=2001:41d0:0203:4bff:ff:ff:ff:ff:ff
Scope=link
root@rescue:~#
root@rescue:~# cat /mnt/etc/systemd/network/50-public-interface.link
# This file configures the relation between network device and device name.
# You can also see this as "OSI Layer 2" config.
# It was created by the OVH installer, please be careful with modifications.
# Documentation: man systemd.link or https://www.freedesktop.org/software/systemd/man/systemd.link.html
 
[Match]
MACAddress=xx:xx:xx:xx:xx:xx
 
[Link]
Description=network interface on public network, with default route
MACAddressPolicy=persistent
NamePolicy=kernel database onboard slot path mac
#Name=eth2    # name under which this interface is known under OVH rescue system
#Name=eno3    # name under which this interface is probably known by systemd
root@rescue:~#
```

3\. Utwórz kopię zapasową plików i edytuj je, aby wprowadzić nową wartość adresu MAC:

```bash
root@rescue:~# cp /mnt/etc/systemd/network/50-default.network /mnt/etc/systemd/network/50-default.network.link.bak-`date +%s`
root@rescue:~# cp /mnt/etc/systemd/network/50-public-interface.link /mnt/etc/systemd/network/50-public-interface.link.bak-`date +%s`
root@rescue:~# nano /mnt/etc/systemd/network/50-default.network
root@rescue:~# cat /mnt/etc/systemd/network/50-default.network | grep MACAddress
MACAddress=xx:xx:xx:xx:xx:xx
root@rescue:~#
root@rescue:~# nano /mnt/etc/systemd/network/50-public-interface.link
root@rescue:~#
root@rescue:~# cat /mnt/etc/systemd/network/50-public-interface.link | grep MACAddress
MACAddress=xx:xx:xx:xx:xx:xx
root@rescue:~#
```

4\. Odmontuj partycję `/` przed ponownym uruchomieniem serwera.

#### Przypadki szczególne

W niektórych przypadkach konieczne jest wprowadzenie nowego adresu MAC w następujących plikach:

- `/mnt/etc/netplan/01-netcfg.yaml`
- `/mnt/etc/netplan/50-cloud-init.yaml`
- `/mnt/etc/systemd/network/10-eno1.link`
- `/mnt/etc/systemd/network/10-eno1.network`

<a name="centos-almalinux"></a>

### CentOS/Alma Linux

Jeśli występują problemy z łącznością sieciową (na przykład brak odpowiedzi na ping po wymianie płyty głównej), wykonaj następujące kroki:

1\. Uruchom ponownie serwer w [trybie Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).<br/>
2\. Zamontuj partycję `/`:

```bash
root@rescue:~# mount /dev/my_system_disk /mnt
```

3\. Sprawdź plik konfiguracyjny `/mnt/etc/sysconfig/network-scripts/ifcfg-eth0`.

4\. Utwórz kopię zapasową plików i edytuj je, aby poprawić adres MAC:

```bash
root@rescue:~# cp /mnt/etc/sysconfig/network-scripts/ifcfg-eth0 /mnt/etc/sysconfig/network-scripts/ifcfg-eth0.`date +%s`
```

5\. Wprowadź nowy adres MAC w wierszu `HWADDR=xx:xx:xx:xx:xx:xx`.

6\. Pamiętaj, aby odmontować partycję `/` przed ponownym uruchomieniem serwera.

<a name="smartos"></a>

### SmartOS

Jeśli występują problemy z łącznością sieciową (na przykład brak odpowiedzi na ping po wymianie płyty głównej), wykonaj następujące kroki:

1\. Uruchom ponownie serwer w [trybie Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).<br/>

```bash 
modprobe zfs
root@rescue:~# zpool import -f zones (zpool import to list the pools)
root@rescue:~# zfs set mountpoint=/mnt zones/usbkey
root@rescue:~# zfs mount zones/usbkey
root@rescue:~# cp /mnt/config {,.bak-$(date +"%Y-%m-%d-%H_%M")}
```

2\. Wprowadź nowy adres MAC w wierszu `admin_nic`:

```bash
root@rescue:~#  vim /mnt/config
```

3\. Nie zapomnij odmontować partycji przed ponownym uruchomieniem serwera w trybie `netboot`:

```bash
root@rescue:~# zfs umount -a
root@rescue:~# zfs set mountpoint=`/usbkey` zones/usbkey 
```

### FreeBSD

Jeśli występują problemy z łącznością sieciową (na przykład brak odpowiedzi na ping po wymianie płyty głównej), wykonaj następujące kroki:

1\. Uruchom ponownie serwer w trybie rescue-bsd.<br/>
2\. Uruchom polecenie `ifconfig` w wierszu poleceń rescue-bsd.


<a name="proxmox"></a>

### Proxmox/Debian (z wyjątkiem Debian 12+)

Jeśli występują problemy z łącznością sieciową (na przykład brak odpowiedzi na ping po wymianie płyty głównej), może to być związane z błędem podczas uruchamiania systemu, spowodowanym przez wciąż obecną starą wartość adresu MAC:

Wykonaj następujące kroki:

1\. Uruchom ponownie serwer w [trybie Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).

```bash
root@rescue:~# cat /mnt/etc/network/interfaces
# This file describes the network interfaces available on your system
# and how to activate them. For more information, see interfaces(5).
 
# The loopback network interface
auto lo
iface lo inet loopback
 
iface enp3s0f0 inet manual
 
auto vmbr0
iface vmbr0 inet dhcp
  bridge-ports enp3s0f0
  bridge-stp off
  bridge-fd 0
 
auto vmbr1
iface vmbr1 inet static
  address  192.168.22.254
  netmask  255.255.255.0
  bridge_ports none
  bridge_stp off
  bridge_fd 0
  post-up echo 1 > /proc/sys/net/ipv4/ip_forward
root@rescue:~#
root@rescue:~# cat /mnt/var/log/messages | grep renamed
Aug  8 14:27:20 s22 kernel: [    1.527563] igb 0000:04:00.0 eno1: renamed from eth0
Aug  8 14:27:20 s22 kernel: [    1.550622] igb 0000:04:00.1 eno2: renamed from eth1
Aug  8 14:27:34 s22 kernel: [   88.148303] eth0: renamed from vethGRELEP
Aug  8 14:27:36 s22 kernel: [   90.444727] eth0: renamed from vethVMV0MH
Aug  8 14:27:40 s22 kernel: [   94.116739] eth0: renamed from vethQWYCXT
Aug  8 14:27:43 s22 kernel: [   97.469199] eth0: renamed from vethAIWWWX
Aug  8 14:27:48 s22 kernel: [  102.101324] eth0: renamed from vethB2DGCS
Aug  8 14:27:48 s22 kernel: [  102.139437] eth1: renamed from vethRSNNKL

```

2\. Utwórz ponownie plik `70-persistent-net.rules` i dodaj:

- Nazwę interfejsu sieciowego znalezioną w pliku `/mnt/etc/network/interfaces`.
- Nowy adres MAC (widoczny w sekcji **Aggregated interface composition** w zakładce <code className="action">Connectivity</code> w <ManagerLink to="/">konsoli OVHcloud</ManagerLink> lub w wyniku polecenia `ip link`).

```bash
root@rescue:~# cat /mnt/etc/udev/rules.d/70-persistent-net.rules
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", NAME="enp3s0f0"
root@rescue:~#
```

<a name="xenserver"></a>

### XenServer

Jeśli występują problemy z łącznością sieciową (na przykład brak odpowiedzi na ping po wymianie płyty głównej), adres MAC jest skonfigurowany statycznie i należy go zresetować.

Wykonaj następujące kroki:

1\. Uruchom ponownie serwer w [trybie Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode) i użyj polecenia `chroot`:

```bash
root@rescue:~# mount /dev/sda1 /mnt
root@rescue:~# mount -t proc /proc/ /mnt/proc/
root@rescue:~# mount -o bind /sys/ /mnt/sys/
root@rescue:~# mount -o bind /dev/ /mnt/dev/
root@rescue:~# mount -o bind /dev/pts/ /mnt/dev/pts/
root@rescue:~# chroot /mnt
```

2\. Zmień bieżącą konfigurację tak, aby odpowiadała nowym ustawieniom:

```bash
[root@rescue /]# xe-reset-networking --device=eth0 --mode=static --ip=xx.xx.xx.xx --netmask=255.255.255.0 --gateway=xx.xx.xx.xxx
```

3\. Na wyświetlone pytanie odpowiedz `yes`, a następnie naciśnij Enter:

```bash
----------------------------------------------------------------------

This command will reboot the host and reset its network configuration.
Any running VMs will be forcefully shutdown.
  
Before completing this command:
- Where possible, cleanly shutdown all VMs running on this host.
- Disable HA if this host is part of a resource pool with HA enabled.

IP configuration mode:  static

Pool master's address:  xx.xx.xx.xx
  
If you want to change any of the above settings, type 'no' and re-run
the command with appropriate arguments (use --help for a list of options).
  
Type 'yes' to continue.
Type 'no' to cancel.
yes
Stopping xapi...
Reconfiguring eth0...
Updating inventory file...
Running in chroot, ignoring request.
```

4\. Wpisz "exit", aby wyjść z trybu `chroot`, a następnie odmontuj wszystkie partycje:

```bash
root@rescue:~# umount /mnt/sys
root@rescue:~# umount /mnt/proc
root@rescue:~# umount /mnt/dev/pts
root@rescue:~# umount /mnt/dev
root@rescue:~# umount /mnt
```

#### Przypadki szczególne

Należy sprawdzić i dostosować następujące pliki:

- `/mnt/etc/sysconfig/network-scripts/interface-rename-data/static-rules.conf`  
- `/mnt/etc/sysconfig/network-scripts/interface-rename-data/dynamic-rules.json`

<a name="esxi"></a>

### ESXi

Po wymianie płyty głównej nie można zmodyfikować nowych adresów MAC w pliku `esxi.conf` za pomocą narzędzi dostępnych w trybie Rescue.
Konieczna będzie ręczna interwencja.

#### Wersja 7.0 lub nowsza

Poniższa procedura dotyczy wyłącznie **wersji 7.0 i nowszych**. Począwszy od tej wersji plik state.tgz jest zaszyfrowany.
Zresetuj sieć w menu Direct Console za pomocą KVM lub IPMI.

Zapoznaj się z poniższym zrzutem ekranu:

<img className="thumbnail" alt="reset_network" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/restore.png" loading="lazy" />

#### Wersja 6.7 lub starsza

Poniższa procedura dotyczy wyłącznie **wersji 6.7 i starszych**.

1\. Uruchom ponownie serwer w [trybie Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode), aby zamontować partycję `/`:

```bash
root@rescue:~# mount /dev/sdaX /mnt/
```

2\. Utwórz kopię zapasową pliku `state.tgz`

```bash
root@rescue:~# ls /mnt/state.tgz
root@rescue:~# cp /mnt/state.tgz /mnt/state.tgz.`date +%s`
```

3\. Utwórz środowisko robocze:

```bash
root@rescue:~# mkdir /home/ovh/esxi
root@rescue:~# WORKINGDIR=/home/ovh/esxi
root@rescue:~# cd $WORKINGDIR
```

4\. Wyodrębnij zawartość `state.tgz` do `$WORKINGDIR`, a następnie wyodrębnij zawartość `local.tgz`.<br/>
5\. Edytuj otrzymany plik `esx.conf`:

```bash
root@rescue:/home/ovh/esxi# tar xf /mnt/state.tgz -C $WORKINGDIR
root@rescue:/home/ovh/esxi# tar xf /home/ovh/esxi/local.tgz -C $WORKINGDIR
root@rescue:/home/ovh/esxi# vim etc/vmware/esx.conf
```
6\. Zlokalizuj i zmodyfikuj adres MAC dla `vmkernelnic`:

```bash
/net/vmkernelnic/child[0000]/mac = "XX:XX:XX:XX:XX:XX"
```

7\. Ustal, na którym interfejsie używany jest główny adres IP:

```bash
/net/vswitch/child[0000]/uplinks/child[0000]/pnic = "vmnicX"
```

8\. Zaktualizuj adres MAC głównego interfejsu:

:::warning
Nie zmieniaj wirtualnego adresu MAC.

:::


```bash
/net/pnic/child[0001]/mac = "XX:XX:XX:XX:XX:XX"         <== Primary Interface Mac address
/net/pnic/child[0001]/virtualMac = "00:50:56:XX:XX:XX"  <== Virtual Mac
/net/pnic/child[0001]/name = "vmnic1"
```

:::warning
Jeśli istnieje interfejs vRack, pamiętaj, aby zmienić również jego adres MAC.

:::


9\. Utwórz kopię zapasową, a następnie odmontuj partycję `/`:

```bash
root@rescue:/home/ovh/esxi# tar -czf $WORKINGDIR/local.tgz etc/
root@rescue:/home/ovh/esxi# tar -czf /mnt/state.tgz local.tgz
root@rescue:/home/ovh/esxi# umount /mnt
```

#### Przypadki szczególne

Sprawdź kolejność deklaracji vmnicX. Oto działający przykład:

```bash
root@rescue:/home/ovh/esxi# cat etc/vmware/esx.conf | grep "/vmkdevmgr/pci"
/vmkdevmgr/pci/m00008901/alias = "vmhba0"
/vmkdevmgr/pci/m00008501/alias = "vmnic0"
/vmkdevmgr/pci/m00008502/alias = "vmnic1"
```

<a name="windows"></a>

### Windows (Hyper-V)

Po wymianie płyty głównej serwer nie będzie dostępny, dopóki ręcznie nie zmienisz adresów MAC w **Menedżerze urządzeń**.

Dostępne są 2 metody:

#### Przez IPMI/KVM

1\. Zaloguj się jako administrator przez interfejs [IPMI/KVM](/guides/bare-metal-cloud/dedicated-servers/ipmi).<br/>
2\. Otwórz narzędzie <code className="action">Uruchamianie</code> (klawisz z logo Windows + <code className="action">R</code>) i w oknie `run` wykonaj polecenie `devmgmt.msc`:

<img className="thumbnail" alt="win_device_manager" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_device_manager_edited.png" loading="lazy" />

3\. Otwórz <code className="action">Network adapters</code> i wybierz adapter odpowiadający `eth0`.<br/>
4\. Kliknij prawym przyciskiem myszy <code className="action">Properties</code> > <code className="action">Advanced</code>.<br/>
5\. Zlokalizuj `Locally Administered Address`.<br/>
6\. Wprowadź nową wartość adresu MAC (tylko cyfry, bez spacji).

<img className="thumbnail" alt="win_advanced" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_advanced_edited.png" loading="lazy" />

#### Przez WinPE

1\. Uruchom ponownie serwer w trybie `WinPE`.<br/>
2\. Wykonaj polecenie `regedit` w wierszu polecenia `run`.<br/>
3\. Załaduj lokalny rejestr za pośrednictwem rejestru dostępnego w `WinPE`, a następnie kliknij <code className="action">HKEY_LOCAL_MACHINE</code>:

<img className="thumbnail" alt="win_regedit_1" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_1_edited.png" loading="lazy" />

4\. Następnie kliknij <code className="action">Load Hive...</code>.

<img className="thumbnail" alt="win_regedit_2" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_2_edited.png" loading="lazy" />

:::info
Domyślnie znajdujesz się w drzewie katalogów WinPE.
Pamiętaj, aby przejść do dysku `C:\`.

:::


5\. Zlokalizuj rejestr `SYSTEM`.

<img className="thumbnail" alt="win_load" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_load_edited.png" loading="lazy" />

6\. Wprowadź nazwę, gdy system o nią poprosi. Możesz na przykład wybrać `OVH_TEST`.

7\. Zlokalizuj następującą wartość rejestru:

```bash
"HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Class\{4D36E972-E325-11CE-BFC1-08002BE10318}"
```

:::warning
Dopóki pracujemy w WinPE, wartość `CurrentControlSet` powinna być równa `CurrentSet001`.

:::


Powinno być widocznych kilka podkluczy o nazwach takich jak: 0000, 0001 itd.

8\. Kliknij każdy podklucz, aby sprawdzić wartość `DriverDesc`, która powinna odpowiadać Twojemu interfejsowi sieciowemu.
Nazwę interfejsu możesz sprawdzić w terminalu za pomocą następującego polecenia:

```bash
ipconfig /all
```

9\. W prawym panelu odszukaj wpisy rejestru `NetworkAddress` i zmień wartość na nowy adres MAC. Jeśli ten wpis nie istnieje, kliknij prawym przyciskiem myszy w pustym obszarze, aby utworzyć wartość typu `String` o nazwie `NetworkAddress`.

<img className="thumbnail" alt="win_regedit_3" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_3_edited.png" loading="lazy" />

10\. Aby zastosować ostatnie zmiany, należy zwolnić gałąź rejestru. Kliknij OVH_TEST (utworzony wcześniej), następnie kliknij <code className="action">File</code> (w lewym górnym rogu) i wybierz <code className="action">Unload hive...</code>.

<a name="network-interface"></a>

### Identyfikacja nazw interfejsów sieciowych

Po wymianie płyty głównej serwer nie jest dostępny, ponieważ system operacyjny zmienił nazwę kontrolera interfejsów sieciowych.

1\. Uruchom ponownie serwer w [trybie Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode), zamontuj partycję `/`, a następnie użyj polecenia `chroot`:

```bash
root@rescue:~# mount /dev/my_disk /mnt
root@rescue:~# for i in /dev /dev/pts /proc /sys; do mount -B $i /mnt$i; done
root@rescue:~# chroot /mnt
```

2\. Sprawdź, czy interfejsy zostały zmodyfikowane. Sprawdź w logach `var/log/messages` lub `var/log/kern.log`, czy nazwa interfejsu została zmieniona:

```bash
Oct  9 22:25:49 node1 kernel: [    5.479916] ixgbe 0000:03:00.1 eno4: renamed from eth1
Oct  9 22:25:49 node1 kernel: [    5.504285] ixgbe 0000:03:00.0 eno3: renamed from eth0
```

3\. Sprawdź plik konfiguracyjny `/mnt/etc/udev/rules.d/70-persistent.-net.rules` i w razie potrzeby zastąp wartości nowymi (adresy MAC):

```bash
root@rescue:~# cat /mnt/etc/udev/rules.d/70-persistent-net.rules
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", ATTR{dev_id}=="0x0", ATTR{type}=="1", KERNEL=="eth*", NAME="public"
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", ATTR{dev_id}=="0x0", ATTR{type}=="1", KERNEL=="eth*", NAME="private"
```

4\. Przejdź do katalogu `/boot/grub/` i utwórz kopię zapasową pliku `grub.cfg`.<br/>
5\. Edytuj plik `/etc/default/grub` i zmień wiersz zaczynający się od `GRUB_CMDLINE_LINUX` w następujący sposób:

```bash
GRUB_CMDLINE_LINUX="net.ifnames=0 biosdevname=0"
```

6\. Wykonaj polecenie:

```bash
root@rescue:~# grub-mkconfig -o /boot/grub/grub.cfg
```

7\. Wyjdź ze środowiska `chroot` za pomocą polecenia `exit` i odmontuj wszystkie partycje:

```bash
root@rescue:~# umount /mnt/sys
root@rescue:~# umount /mnt/proc
root@rescue:~# umount /mnt/dev/pts
root@rescue:~# umount /mnt/dev
root@rescue:~# umount /mnt
```

### Problemy z partycją EFI

Poniższe kroki dotyczą sytuacji, w której występuje problem z uruchamianiem (boot) związany z partycjami na dyskach.<br/>
Dostępne są 2 metody: przez tryb Rescue lub przez BIOS.

#### Przez tryb Rescue

- Przypadek użycia: zainstalowany system (w tym przypadku Proxmox) nie uruchamia się po wymianie dysku (w BIOS-ie nie jest widoczny żaden wpis EFI).

1\. Uruchom ponownie serwer w [trybie Rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).<br/>
2\. Zlokalizuj dysk z oryginalną partycją EFI:

```bash

root@rescue:~# ls /mnt/EFI/proxmox/grubx64.efi
```

#### Przez BIOS

- Przypadek użycia: zainstalowany system (w tym przypadku CentOS 6) nie uruchamia się po wymianie dysku (w BIOS-ie nie jest widoczny żaden wpis EFI).

1\. Uruchom ponownie serwer, aby wejść do menu BIOS.

*Pierwszy etap* polega na ponownym wygenerowaniu plików niezbędnych do przywrócenia pełnego działania partycji:

- Przejdź do menu `boot` w BIOS-ie:
    - Wybierz <code className="action">Add New Boot Option</code>.
    - Wybierz ścieżkę do partycji w <code className="action">Path for boot option</code> i wybierz system plików zawierający partycję rozruchową.
    - Wybierz plik `EFI\centos6\bootx64.efi` i kliknij <code className="action">Create</code>.

    - Wybierz <code className="action">UEFI Boot Order #1</code>, a następnie <code className="action">CENTOS6</code>, aby ustawić go jako pierwszą opcję rozruchu na bieżącej liście.
