## Wprowadzenie

Katalog aplikacji umożliwia zainstalowanie gotowej do użycia aplikacji na serwerze dedykowanym OVHcloud bez wcześniejszej znajomości administracji systemem. Wybierasz aplikację podczas (ponownej) instalacji serwera, a następnie wypełniasz krótki formularz konfiguracyjny w zabezpieczonym interfejsie internetowym. Aplikacja jest instalowana natywnie na serwerze, zabezpieczona protokołem HTTPS i dostępna w ciągu kilku minut.

**Ten przewodnik wyjaśnia, jak korzystać z katalogu aplikacji na serwerze dedykowanym OVHcloud.**

## Wymagania początkowe

- Posiadanie [serwera dedykowanego](/links/bare-metal/bare-metal) na koncie OVHcloud
- Zalogowanie się do <ManagerLink to="/">Panelu klienta OVHcloud</ManagerLink>
- Posiadanie dostępu do <ApiLink>API OVHcloud</ApiLink> (dla sekcji "[API OVHcloud](#viaapi)" tego przewodnika)
- Posiadanie dostępu do adresu e-mail konta OVHcloud, aby otrzymać link do interfejsu konfiguracji
- Posiadanie przeglądarki internetowej, aby otworzyć interfejs konfiguracji po zakończeniu instalacji

## W praktyce

### Działanie katalogu aplikacji

Wdrożenie aplikacji przebiega w dwóch etapach:

1. **Wybór (podczas instalacji):** instalujesz (ponownie) serwer z obrazem z katalogu aplikacji i wybierasz **jedną** aplikację. To tutaj decydujesz, *którą* aplikację chcesz wdrożyć.
2. **Konfiguracja (po pierwszym uruchomieniu):** po ponownym uruchomieniu serwera automatycznie startuje konfigurator jednorazowego użytku, który udostępnia zabezpieczony interfejs internetowy na porcie `10143`. Wypełniasz krótki formularz (na przykład nazwę witryny i hasło administratora), a następnie aplikacja jest instalowana automatycznie i publikowana przez HTTPS.

Po pomyślnym zakończeniu instalacji konfigurator **całkowicie usuwa się** z serwera: jego plik binarny, usługa i dane robocze zostają usunięte. Pozostaje tylko Twoja aplikacja, a Ty dysponujesz pełnym dostępem root do serwera.

Aplikacje są instalowane **natywnie** — z pakietami systemowymi i usługami `systemd`, na serwerze przeznaczonym wyłącznie do tego celu — a nie w ramach platformy kontenerowej.

**Ograniczenia techniczne:**

- Za pomocą katalogu aplikacji można wdrożyć **tylko jedną aplikację**.
- **Własny podział na partycje i konfiguracja sprzętowego RAID nie są dostępne** dla tej instalacji.

:::warning
Nie oznacza to, że nie możesz uruchamiać innych aplikacji na serwerze. Oznacza to, że za pomocą katalogu można zainstalować tylko **JEDNĄ** aplikację. Jeśli chcesz uruchomić dodatkowe aplikacje, musisz zainstalować je ręcznie.
:::

### Wybór aplikacji podczas instalacji

Dostępne są dwie metody wdrożenia, opisane w poniższych zakładkach: zainstaluj aplikację z Panelu klienta OVHcloud lub użyj API OVHcloud, aby zintegrować instalację z własnymi skryptami i zautomatyzować wdrożenia.

1. Wybierz serwer w sekcji <code className="action">Bare Metal Cloud</code> > <code className="action">Serwery dedykowane</code>.
2. W zakładce <code className="action">Informacje ogólne</code>, obok pozycji **System operacyjny (OS)**, kliknij przycisk <code className="action">...</code>, a następnie <code className="action">Reinstalacja serwera</code>.

3. W oknie **Instalacja szablonu OVHcloud** ustaw pole **Rodzaj systemu operacyjnego** na <code className="action">Gotowy do użytku (interfejs graficzny)</code>, a następnie wybierz szablon **Ubuntu Server 24.04 "Noble Numbat" LTS with Application Installer**. Wybierz **Klaster docelowych dysków** i kliknij <code className="action">Dalej</code>.

    :::info
    Własny podział na partycje i konfiguracja sprzętowego RAID nie są dostępne dla tego szablonu, dlatego te opcje pozostają nieaktywne.

    <img className="thumbnail" alt="Wybierz szablon Ubuntu z Application Installer" src="/images/bare-metal-cloud/dedicated-servers/application-catalog/install-02.png" loading="lazy" />

4. Przejdź kolejne etapy instalacji, aby wprowadzić ustawienia ogólne, takie jak nazwa hosta serwera i klucz SSH, który ma zostać dodany do serwera.
5. Na etapie **Aplikacja do zainstalowania** wybierz z listy rozwijanej **jedyną aplikację**, którą chcesz wdrożyć, a następnie kliknij <code className="action">Zatwierdź</code>, aby uruchomić instalację.

#### Uruchomienie instalacji <a name="viaapi"></a>

Aby wyświetlić listę systemów operacyjnych dostępnych dla Twojego serwera, użyj następującego wywołania API:

<Api version="v1" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/install/compatibleTemplates"} />

W odpowiedzi szablony katalogu aplikacji to te, których nazwa kończy się na `-withapp`. Zawsze pobieraj identyfikator za pomocą tego wywołania, zamiast wpisywać go na stałe, ponieważ katalog szablonów się zmienia.

Następnie możesz uruchomić instalację za pomocą następującego wywołania API:

<Api version="v1" section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"} />

Wskaż system operacyjny uzyskany w poprzednim kroku oraz aplikację do zainstalowania w parametrze `appToInstall`:

```json
{
  "operatingSystem": "ubuntu2404-withapp",
  "customizations": {
    "hostname": "myApplicationServer",
    "sshKey": "mySshKey",
    "appToInstall": "wordpress"
  }
}
```

Wartość `appToInstall` to identyfikator aplikacji, którą chcesz wdrożyć — na przykład `wordpress`, `drupal`, `nextcloud`, `prestashop`, `discourse`, `matomo`, `n8n`, `openclaw`, `hestiacp`, `fastpanel`, `coolify`, `dokploy`, `easypanel` lub `game-panel`. Można wskazać tylko jedną aplikację.

Zrealizuj zadanie instalacji do końca, zgodnie z opisem w przewodniku [Install an OS via the OVHcloud API on a Dedicated Server](/guides/bare-metal-cloud/dedicated-servers/api-os-installation), a następnie przejdź do sekcji "[Konfiguracja aplikacji i dostęp do niej](#configure)" poniżej.

### Konfiguracja aplikacji i dostęp do niej <a name="configure"></a>

Po instalacji serwer automatycznie uruchamia konfigurator jednorazowego użytku. Ten etap nie wymaga żadnej znajomości systemu Linux, SSH ani administracji systemem — wystarczy przeglądarka internetowa.

#### Etap 1: otwarcie konfiguratora

Po zakończeniu instalacji otrzymasz wiadomość e-mail zawierającą link do konfiguratora. Ma on następującą postać:

```text
https://<twoj-serwer>:10143/static/deploy.html?app=<aplikacja>&token=<token>
```

Otwórz ten link w przeglądarce internetowej. Zawarty w nim token uwierzytelnia Cię i zapisywany jest zabezpieczony plik cookie tylko dla tej sesji, dzięki czemu możesz następnie przeglądać konfigurator bez tokenu w pasku adresu. Otwarcie konfiguratora bez prawidłowego tokenu powoduje wyświetlenie strony `Unauthorized`.

:::warning
Traktuj ten link jak hasło i nie udostępniaj go: daje on dostęp do interfejsu instalacji Twojego serwera.
:::

:::info
Jeśli przeglądarka wyświetli ostrzeżenie o certyfikacie przy pierwszym wczytaniu strony, oznacza to, że konfigurator nadal pobiera certyfikat Let's Encrypt i tymczasowo udostępnia certyfikat z podpisem własnym. Odczekaj minutę i odśwież stronę — przejście na certyfikat docelowy odbywa się automatycznie.
:::

#### Etap 2: wypełnienie formularza konfiguracyjnego

Konfigurator otwiera się bezpośrednio na aplikacji wybranej podczas instalacji. W zależności od tej aplikacji wdrażasz ją od razu lub najpierw wypełniasz krótki formularz:

- **Aplikacje bez pól** — Coolify, Dokploy, Easypanel, FastPanel, HestiaCP, Discourse, Matomo i n8n — samodzielnie generują niezbędne identyfikatory i wyświetlają je na końcu. Kliknij <code className="action">Deploy</code>.
- **Aplikacje z polami** — WordPress, Drupal, Nextcloud, PrestaShop, OpenClaw i OVHcloud Game Panel — wymagają podania kilku wartości, takich jak nazwa witryny, hasło administratora lub hasło do bazy danych. Pola obowiązkowe są oznaczone, a pola opcjonalne mogą mieć zaproponowane wartości domyślne.

Panel <code className="action">Installation details</code> nad formularzem przedstawia, co zostanie zainstalowane i dlaczego, wraz z linkiem do oficjalnej dokumentacji producenta.

Każde pole jest sprawdzane przed rozpoczęciem wdrożenia (na przykład pole e-mail musi zawierać prawidłowy adres e-mail, a hasła mają minimalną długość). Popraw oznaczone pola i zatwierdź ponownie.

:::tip
Wybierz silne hasła: wartości wprowadzone w tym miejscu stają się rzeczywistymi danymi dostępowymi Twojej aplikacji.
:::

<img className="thumbnail" alt="Formularz konfiguracyjny dla wdrożenia WordPress" src="/images/bare-metal-cloud/dedicated-servers/application-catalog/configurator-form.png" loading="lazy" />

Następnie kliknij <code className="action">Deploy</code>.

#### Etap 3: monitorowanie wdrożenia

Konfigurator wykonuje instalację i przekazuje jej postęp w czasie rzeczywistym: status (`pending`, następnie `running`, a potem `completed` lub `failed`), pasek postępu oraz logi instalacji. Wartości wprowadzone w formularzu są maskowane w logach.

<img className="thumbnail" alt="Postęp wdrożenia i logi w czasie rzeczywistym" src="/images/bare-metal-cloud/dedicated-servers/application-catalog/configurator-progress.png" loading="lazy" />

Wdrożenie trwa zwykle kilka minut; bardziej rozbudowane aplikacje, takie jak Discourse, potrzebują więcej czasu. Możesz pozostawić zakładkę otwartą, ale instalacja jest kontynuowana na serwerze nawet po rozłączeniu przeglądarki — otwórz link ponownie, aby wznowić monitorowanie.

:::info
Jednocześnie wykonywane jest tylko jedno wdrożenie. Jeśli wdrożenie jest już w toku i uruchomisz kolejne, konfigurator przekieruje Cię do wdrożenia w toku, zamiast rozpoczynać drugie. To właśnie zapewnia zasadę "jedna aplikacja na serwer".
:::

#### Etap 4: uzyskanie danych dostępowych

Gdy status osiągnie wartość `completed`, konfigurator wyświetli stronę powodzenia zawierającą:

- link do Twojej aplikacji, na standardowym porcie HTTPS — `https://<twoj-serwer>/`;
- wszystkie identyfikatory lub informacje wygenerowane przez aplikację, na przykład nazwę użytkownika administratora, nazwę bazy danych lub wygenerowane hasło.

Podczas instalacji dla nazwy hosta Twojego serwera wystawiany jest bezpłatny, automatycznie odnawiany certyfikat [Let's Encrypt](https://letsencrypt.org/pl/), a wdrożona aplikacja samodzielnie zarządza jego odnawianiem.

:::warning
Skopiuj dane dostępowe od razu. Strona powodzenia jest dostępna wyłącznie w okresie karencji następującym po udanym wdrożeniu (domyślnie 5 minut). Po usunięciu się konfiguratora nie może on już ich wyświetlić — trzeba by wtedy pobrać je z samej aplikacji albo ponownie zainstalować serwer.
:::

#### Etap 5: konfigurator usuwa się

Krótko po udanym wdrożeniu konfigurator usuwa własny plik binarny, usługę i dane robocze. Od tego momentu:

- interfejs konfiguratora na porcie `10143` przestaje odpowiadać — **jest to zachowanie oczekiwane, a nie awaria**;
- Twoja aplikacja, jej dane i jej certyfikat HTTPS są zachowane;
- na serwerze działa wyłącznie Twoja aplikacja, bez pozostawionego narzędzia instalacyjnego ani interfejsu administracyjnego.

Dysponujesz pełną kontrolą nad serwerem, w tym dostępem root przez SSH, jeśli podczas instalacji dodałeś klucz. Konfigurator nie zarządza już niczym po tym etapie.

:::info
Jeśli wdrożenie **zakończy się niepowodzeniem**, konfigurator *nie* usuwa się: pozostaje dostępny, aby umożliwić zdiagnozowanie problemu na podstawie logów w czasie rzeczywistym. Nieudane wdrożenie wymaga zwykle ponownej instalacji serwera i rozpoczęcia od nowa.
:::

Aby wdrożyć inną aplikację, zainstaluj ponownie serwer z katalogu aplikacji i wybierz nową aplikację.

### Rozwiązywanie typowych problemów

| Objaw | Przyczyna | Rozwiązanie |
|---|---|---|
| Strona konfiguratora nie wczytuje się pod adresem `https://<twoj-serwer>:10143/` | Instalacja nie została jeszcze zakończona lub ruch wejściowy na port `10143` jest blokowany. | Poczekaj na zakończenie instalacji, a następnie spróbuj ponownie. Upewnij się, że zapora (w tym [Edge Network Firewall](/guides/bare-metal-cloud/dedicated-servers/firewall-network) OVHcloud) zezwala na ruch wejściowy do Twojego serwera na porcie `10143`. |
| Strona konfiguratora przestała się wczytywać po udanym wdrożeniu | Konfigurator usunął się, zgodnie z założeniem. | Jest to zachowanie prawidłowe. Użyj własnego adresu swojej aplikacji: `https://<twoj-serwer>/`. |
| `Unauthorized` przy otwieraniu konfiguratora | Token dostępu jest brakujący lub nieprawidłowy. | Otwórz konfigurator ponownie, używając dokładnie tego linku i tokenu, które zostały dostarczone wraz z instalacją. |
| Przy pierwszym wczytaniu strony pojawia się ostrzeżenie o certyfikacie | Certyfikat Let's Encrypt nie został jeszcze wystawiony; udostępniany jest tymczasowy certyfikat z podpisem własnym. | Odczekaj minutę i odśwież stronę. |
| Aplikacja nie jest dostępna przez HTTPS po instalacji | Certyfikat Let's Encrypt nie mógł zostać wystawiony, zwykle dlatego, że port wejściowy `80` lub `443` jest zablokowany albo nazwa hosta nie jest rozwiązywana publicznie. | Upewnij się, że porty `80` i `443` są otwarte dla ruchu wejściowego, a nazwa hosta Twojego serwera jest rozwiązywana publicznie, a następnie w razie potrzeby zainstaluj serwer ponownie. |
| Chcesz wdrożyć drugą aplikację z katalogu | Za pomocą katalogu można wdrożyć tylko jedną aplikację. | Zainstaluj serwer ponownie, aby wdrożyć inną aplikację, albo zainstaluj dodatkową aplikację ręcznie. |
