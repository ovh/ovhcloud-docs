## Objetivo

Acaba de criar o seu projeto Public Cloud e deseja saber um pouco mais sobre a interface de utilizador na consola OVHcloud.

**Descubra as principais secções da interface Public Cloud na consola OVHcloud.**

## Requisitos

- Ter criado um [primeiro projeto Public Cloud](/guides/public-cloud/cross-functional/create-a-public-cloud-project).

[[cpnav:publiccloud-projects-console]]

## Instruções

Depois de criar o seu primeiro projeto Public Cloud, será redirecionado para a respetiva página inicial na consola OVHcloud. O título da página é o nome do seu projeto.

A página inicial é composta por widgets: **Recursos**, **Faturação**, **Acesso rápido**, **Os meus últimos tickets**, **Documentação e assistência**, **Recursos para desenvolvedores** e **Roadmap & Changelog**. Pode remover um widget com o ícone situado no seu canto superior direito, adicionar um com <code className="action">Adicionar um widget</code> e repor a disposição predefinida com <code className="action">Repor a disposição</code>.

### O acesso às suas informações de conta OVHcloud

Os parâmetros da sua conta OVHcloud, as suas notificações e a língua da consola OVHcloud estão acessíveis a qualquer momento a partir da barra superior:

- Clique em <code className="action">Menu da conta</code> (o ícone com as suas iniciais, à direita da barra superior) para mudar de língua, passar ao tema escuro, aceder à sua conta, às suas faturas, às suas encomendas e aos seus meios de pagamento, contactar o suporte ou terminar a sessão.
- Clique no ícone em forma de sino ao lado para consultar as suas notificações.

### O seu projeto Public Cloud

Uma vez que é possível utilizar vários projetos (consoante as suas quotas), o nome do projeto atual é sempre apresentado no seletor **Projeto**, no topo do menu à esquerda, independentemente do ecrã que visitar, para que saiba em que ambiente está a agir.

O ID do projeto pode ser necessário ao utilizar a CLI, em certos pedidos de suporte ou noutras situações. Para o copiar:

1. No topo do menu à esquerda, clique no seletor <code className="action">Projeto</code>. A lista dos seus projetos abre-se, com o ID de cada projeto sob o respetivo nome.
2. Clique no ícone de cópia situado na linha do seu projeto.

Para alterar o nome do seu projeto:

1. No menu à esquerda, clique em <code className="action">Gestão do projeto</code>.
2. Clique no separador <code className="action">Definições</code>.
3. No campo **Nome do projeto**, introduza o novo nome.
4. Clique em <code className="action">Validar</code>.

### O menu principal Public Cloud

O menu à esquerda do seu projeto agrupa os produtos Public Cloud por secção. Clique numa secção para apresentar os respetivos produtos.

|Secção|Descrição das opções|
|---|---|
|**Compute**|Esta secção permite-lhe iniciar instâncias, os servidores cloud disponíveis a pedido, e gerir as respetivas reservas, cópias de segurança e workflows.|
|**Rede**|Nesta secção, encontrará tudo o que precisa para interligar os seus recursos Public Cloud e para os ligar a outros produtos OVHcloud: redes privadas, sub-redes, private endpoints, IP públicos, gateways e load balancers.|
|**Serverless**|Esta secção, atualmente em alfa, propõe contentores e funções serverless, bem como o respetivo consumo e as respetivas quotas.|
|**Armazenamento**|Nesta secção, encontrará as diferentes soluções de armazenamento (Object Storage, Block Storage, File Storage, Cold Archive, Cloud Archive), bem como as cópias de segurança e os snapshots de volumes, cada uma correspondente a uma necessidade e a uma utilização específicas.|
|**Contentores**|Esta secção propõe-lhe diferentes ferramentas para automatizar as suas arquiteturas e ganhar flexibilidade: Managed Kubernetes Service, Managed Private Registry e Managed Rancher Service.|
|**Bases de dados**|Esta secção propõe bases de dados geridas: PostgreSQL, MySQL, MongoDB e Valkey.|
|**Analytics**|Estes serviços irão ajudá-lo a resolver as suas problemáticas de Big Data e de Data Analytics: Kafka, ClickHouse, OpenSearch, Managed Dashboards, Data Platform e Lakehouse.|
|**AI**|Nesta secção, encontrará as ferramentas da OVHcloud para a inteligência artificial: AI Notebooks, AI Training, AI Deploy, AI Endpoints e AI Agents.|
|**Quantum**|Esta secção agrupa os serviços relacionados com a computação quântica: QPU e emuladores.|

Sob estas secções, as ligações **Gestão do projeto** e **Centro de custos** dão acesso às ferramentas de gestão do projeto (consulte a secção "[Ferramentas de gestão](#ferramentas-de-gestão)").

No topo do menu, clique em <code className="action">Os meus serviços</code> para apresentar apenas os serviços criados no seu projeto e, em seguida, em <code className="action">Produtos</code> para voltar à lista completa.

### Atalhos

O widget **Acesso rápido** da página inicial do projeto propõe-lhe atalhos para os assistentes de configuração mais úteis, como <code className="action">Criar uma instância</code>, <code className="action">Criar um cluster</code> ou <code className="action">Criar uma rede privada</code>. Os guias estão disponíveis no widget **Documentação e assistência**.

#### Auxílios à criação de recursos

Para cada recurso que deseja criar, uma página de configuração acompanha-o, secção após secção, para configurar o recurso de acordo com as suas necessidades.

Na maioria dos casos, deverá escolher a localização do recurso (a sua região), o modelo, alguns parâmetros personalizáveis e, em certos casos, o modo de faturação. Por exemplo, a página de criação de uma instância agrupa o nome da instância, a região, o modelo, o armazenamento, a imagem, a chave SSH, os parâmetros de cópia de segurança, de rede e avançados e, por fim, o botão <code className="action">Criar a minha instância</code>.

### Ferramentas de gestão

No seu projeto Public Cloud, estão disponíveis várias ferramentas de gestão para configurar os seus recursos, utilizadores e parâmetros. Pode aceder-lhes a partir das duas ligações situadas na parte inferior do menu à esquerda, sob as secções de produtos: **Gestão do projeto**, que agrupa as opções de configuração do projeto (utilizadores, quotas, localizações, chaves SSH, contactos, definições), e **Centro de custos**, que agrupa a faturação.

Para abrir a interface Horizon, clique em <code className="action">OpenStack Horizon</code> no widget **Documentação e assistência** da página inicial do projeto. O Horizon é a [interface gráfica](/guides/public-cloud/cross-functional/introducing-horizon) habitualmente disponível no OpenStack. Não é alterada, o que permite aos utilizadores habituados a esta interface encontrar os seus reflexos.

A ligação <code className="action">Gestão do projeto</code> abre os seguintes separadores:

|Separador|Descrição|
|---|---|
|**Chaves SSH**|Uma ferramenta que lhe permite [gerir as suas chaves SSH](/guides/public-cloud/compute/creating-ssh-keys) de forma centralizada.|
|**Quotas**|De acordo com certos critérios (número de faturas já pagas, utilização de outros produtos OVHcloud), o nosso sistema aplica quotas (limites) ao número de recursos que pode criar, com o objetivo de evitar qualquer problema de pagamentos em atraso. Por predefinição, o sistema aumenta as suas quotas automaticamente quando certos critérios são atingidos. No entanto, pode [aumentar manualmente uma quota](/guides/public-cloud/cross-functional/increasing-public-cloud-quota#aumentar-manualmente-o-seu-quota-de-recursos) a partir deste separador.|
|**Localizações**|O Public Cloud está disponível em várias localizações em todo o mundo. Além disso, cada localização pode incluir várias "regiões" (um conceito próprio do OpenStack). Por exemplo, para um cliente europeu, a zona APAC (Ásia-Pacífico) está desativada por predefinição. Se corresponder às suas necessidades, pode adicionar novas localizações a partir deste separador.|
|**Logs**|Permite consultar os [logs](/guides/public-cloud/cross-functional/logs-concepts) do seu projeto e transferi-los para o Logs Data Platform.|
|**Contactos e direitos**|Além da possibilidade de alterar o contacto técnico ou o contacto de faturação do seu projeto, pode [adicionar outros contactos](/guides/public-cloud/compute/change-project-contacts) (conta OVHcloud) para administrar tecnicamente o seu projeto. Também pode adicionar utilizadores apenas em modo de consulta (*read-only*).|
|**Utilizadores**|Permite [criar utilizadores](/guides/public-cloud/cross-functional/create-and-delete-a-user) e atribuir-lhes uma função. Estes utilizadores permitem, nomeadamente, aceder diretamente às API ou à interface Horizon. Por exemplo, pode criar um utilizador para as suas operações de manutenção habituais e um utilizador para as suas ferramentas de automatização, como o Terraform.|
|**Definições**|Este separador permite-lhe configurar os parâmetros gerais do projeto, como o seu nome ou a sua configuração enquanto "projeto predefinido da conta", ou ainda [eliminar o seu projeto Public Cloud](/guides/public-cloud/cross-functional/delete-a-project). Se a sua conta dispuser de um nível de suporte Business ou Enterprise, este separador permite-lhe também ativar a certificação HDS.|

A ligação <code className="action">Centro de custos</code> abre os seguintes separadores:

|Separador|Descrição|
|---|---|
|**Consumo atual**, **Estimativa da minha próxima fatura**, **Histórico**|Uma vez que o Public Cloud funciona em modo *pay as you go*, as faturas são emitidas no final do mês. [Nestes separadores](/guides/public-cloud/cross-functional/analyze-billing), poderá acompanhar o seu consumo atual, ver uma previsão da próxima fatura e, claro, encontrar as suas faturas anteriores.|
|**Savings Plan**|Trata-se de um modelo de preços que oferece descontos no preço de certos recursos, em contrapartida de um compromisso de duração que pode ir até 36 meses.|
|**Créditos e vouchers**|Este separador permite-lhe consultar o consumo de um voucher, adicionar um ou [adicionar crédito](/guides/account-and-service-management/managing-billing-payments-and-services/add-cloud-credit-to-project) diretamente no seu projeto Public Cloud.|

### Gestão dos serviços

:::info
Nesta secção, apresentamos uma visão geral das diferentes opções de gestão dos serviços propostas pela OVHcloud, através de três ferramentas principais: a consola OVHcloud, o Horizon e a API OpenStack. Cada uma destas ferramentas foi concebida para responder a necessidades específicas em função do seu nível de especialização, das suas preferências em termos de gestão, bem como das suas exigências de desempenho e de personalização.

A matriz abaixo compara as principais características de cada ferramenta para o ajudar a escolher a solução que melhor se adapta às suas necessidades. Quer seja um utilizador principiante, intermediário ou especialista em automatização, esta comparação permitir-lhe-á compreender melhor as vantagens, a facilidade de utilização, os níveis de competência necessários e a escalabilidade de cada ferramenta.

:::


| Critérios/Caraterísticas                    | Consola OVHcloud | Horizon | OpenStack API |
| ------------------------------------------- | ---------------------- | ------- | ------------- |
| Principais benefícios                        | Interface intuitiva, ideal para uma utilização rápida. | Proporciona um maior controlo para os utilizadores experientes com uma visualização de definições avançada. | Automatização completa, com integração fluida com outras ferramentas.|
| Nível de competência necessário                 | Acessível a todos, ideal para iniciantes ou necessidades simples | Intermediário, requer uma certa perícia (administradores de sistemas, engenheiros de Cloud...) | Avançado, requer competências em scripting/API (Arquitetos Cloud, Engenheiros DevOps, Peritos em Automatização) |
| Facilidade de utilização                      | Intuitiva e acessível | Avançada, mas visual | Técnico |
| Personalização                            | Baixo - Ideal para configurações standard e rápidas com controlo avançado limitado. | Média - Interface gráfica que oferece configurações avançadas (rede, armazenamento, etc.), embora limitadas pela interface do utilizador. | Altíssima - Personalização quase completa através da API, com a possibilidade de criar scripts, fluxos de trabalho automatizados e arquiteturas à medida. |
| Desempenho e escalabilidade                 | Desempenho limitado e escalabilidade básica. Adequado para implementações pequenas e não críticas. A escalabilidade é geralmente manual e mais lenta. Ideal para ambientes estáticos ou pequenos projetos. | Média de desempenho com escalabilidade melhorada através da GUI. Escalabilidade mais rápida que com a consola OVHcloud, mas limitada pela interface. Adequado para projetos de média dimensão ou que requerem alguma escalabilidade. | Excelente desempenho e escalabilidade completa. Permite implementações massivas, automatizadas e rápidas através de scripts ou ferramentas de terceiros. Ideal para infraestruturas dinâmicas, cargas pesadas e ambientes que requerem uma elevada elasticidade. Recomendado para arquiteturas críticas. |
| Perímetros de utilização (Compute)          | - Criação e gestão simplificada das máquinas virtuais (VM).<br/> - Redimensionamento das VM após criação (modificação do modelo "flavor" a quente ou a frio, consoante os recursos disponíveis).<br/> - Seleção de configurações standard para as VM (RAM, CPU, armazenamento).<br/> - Gestão das ações essenciais: arranque, paragem e eliminação das VM.<br/> - Acesso às snapshots para backups rápidos e restauros simplificados.<br/> - Atribuição e gestão dos endereços Floating IP.<br/> - Criação e administração básica de discos adicionais.<br/> - Supervisão dos recursos com um sistema de monitorização essencial (CPU, memória, armazenamento). | - Gestão avançada de acessos: suporte de controlo de acessos baseado em funções (RBAC) para uma gestão multiutilizador segura.<br/> - Administração avançada da rede: criação e gestão de redes privadas complexas associadas a VM (redes internas, sub-redes).<br/> - Implementação de VM com configurações de rede específicas, incluindo a gestão de várias interfaces de rede.<br/> - Utilização de imagens personalizadas para a criação de VM, em alternativa às imagens standard disponibilizadas pela OVHcloud.<br/> - Integração de fluxos de trabalho pré-configurados via Horizon para automatizar as implementações e configurações. | - Automatização completa: todas as ações disponíveis na consola OVHcloud e no Horizon são realizáveis através da API, com a possibilidade de as automatizar e de as scriptar.<br/> - Implementação de infraestruturas no modo Infrastructure as Code (IaC) graças a ferramentas como Terraform, Ansible ou scripts personalizados.<br/> - Integração com pipelines CI/CD para implementações automatizadas (por exemplo, integração com GitLab CI).<br/> - Gestão avançada de quotas de recursos (número de CPUs, RAM total, etc.).<br/> - Escalabilidade dinâmica: ajuste automático das instâncias em função da carga através da API ou de scripts.<br/> - Monitorização e recolha de métricas personalizadas através da API, oferecendo mais granularidade do que a interface Horizon ou a consola OVHcloud. |
| Perímetros de utilização (Network)          | - Criação e gestão de redes privadas (Private Networks).<br/> - Associação de endereços Floating IP e de endereços Additional IP.<br/> - Configuração de roteamento de base (Basic Routing). | - Gestão avançada de regras de segurança através dos grupos de segurança (Security Groups).<br/> - Visualizar topologias de rede para gestão simplificada.<br/> - Suporte completo das sub-redes IPv6 para uma conectividade moderna.<br/> - Configuração das políticas de QoS (Quality of Service) para priorizar os recursos de rede. | - Acesso a todas as funcionalidades disponíveis na interface Horizon e na consola OVHcloud.<br/> - Criação de rotas personalizadas para uma gestão de rede mais flexível.<br/> - Configuração precisa das políticas QoS (Quality of Service).<br/> - Gestão avançada de VRRP (Virtual Router Redundancy Protocol) para assegurar a redundância dos routers.<br/> - Automatização das ações de rede graças a scripts (Infrastructure as Code).<br/> - Integração com soluções SDN (Software-Defined Networking) para uma gestão ágil da rede. |
| Perímetros de utilização (Storage & Backup) | - Criação e gestão dos volumes de armazenamento: Object Storage, Block Storage e File Storage.<br/> - Backup automático básico (snapshots) dos volumes, com possibilidade de restauro.<br/> - Associação dos volumes de armazenamento às instâncias para um acesso simplificado.<br/> - Gestão dos containers Object Storage (Swift) para organizar os dados.<br/> - Visualização do estado dos volumes e do espaço de armazenamento utilizado.<br/> - Adicionar e gerir ficheiros num Object Storage. | - Gestão avançada de snapshots: retenção, duplicação e outras opções para um controlo preciso dos backups.<br/> - Gestão detalhada de partilhas de volumes (multi-attach) para uma flexibilidade acrescida.<br/> - Criação e gestão de backups agendados com políticas de backup personalizáveis.<br/> - Monitorização da utilização das quotas de armazenamento para um controlo ótimo do espaço disponível. | - Funcionalidades acessíveis através do Horizon e da consola OVHcloud.<br/> - Integração e automatização através de scripts (Infrastructure as Code) para uma gestão fluída.<br/> - Configuração avançada de partilhas de rede (NFS, CIFS) para uma flexibilidade acrescida na organização dos ficheiros.<br/> - Gestão precisa dos metadados dos objetos no Object Storage para um controlo ideal dos dados.<br/> - Configuração avançada da replicação e da versão de objetos para uma alta disponibilidade e uma gestão de versões completa.<br/> - Acesso direto à API Swift para uma integração fluída com ferramentas de terceiros.<br/> - Criação de fluxos de trabalho personalizados para automatizar e gerir eficazmente os processos de cópia de segurança. |
