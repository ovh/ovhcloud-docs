## Objetivo

A consola OVHcloud permite-lhe criar [snapshots das suas instâncias](/guides/public-cloud/compute/save-an-instance) em apenas alguns cliques e automatizar este processo.
Pode querer restaurar a sua instância através de uma snapshot, por exemplo, em caso de manipulação errada realizada na configuração da sua instância. Pode utilizar estas snapshots de instâncias por duas razões principais:

- Criar uma instância com base na snapshot, para duplicar a instância de origem. Por exemplo, se configurar uma infraestrutura de repartição de carga (load balancing).
- Restaurar uma instância a partir de uma snapshot. Por exemplo, se alterações recentes danificaram configurações críticas na instância.

**Saiba como utilizar as suas snapshots para duplicar ou restaurar as suas instâncias.**

## Requisitos

- Ter [uma snapshot de uma instância Public Cloud](/links/public-cloud/instance-backup). Para isso, consulte [o guia relativo à criação de uma snapshot](/guides/public-cloud/compute/save-an-instance).

## Instruções

:::info
Estão disponíveis dois tipos de snapshots:

- Local: armazenada na mesma região que a sua instância.
- Remota: replicada automaticamente noutra região à sua escolha.

As operações de **criação** e de **restauro** de uma instância a partir de uma snapshot remota são inteiramente suportadas através da API OVHcloud, oferecendo uma maior flexibilidade e uma integração facilitada nos seus processos de automatização.

**Nota:** Na consola OVHcloud, pode criar uma instância a partir de qualquer snapshot listada na página **Snapshots de instância**, mas só pode restaurar uma instância existente a partir de uma snapshot armazenada na sua própria região.

:::


### Criar uma instância a partir de uma snapshot

<Tabs>
  <Tab label="Consola OVHcloud">
    No menu à esquerda do seu projeto Public Cloud, clique em <code className="action">Instance Snapshot</code> na secção **Compute**. A página **Snapshots de instância** lista as suas snapshots.

    Clique no botão <code className="action">...</code> na linha da snapshot escolhida e selecione <code className="action">Criar uma instância</code>.

    Abre-se a página **Criar uma instância** com alguns elementos predefinidos:

    - **Localização**: A sua instância será criada na mesma região que a sua snapshot. A região é determinada pela snapshot e não pode ser alterada.
    - **Imagem**: A snapshot está pré-selecionada no separador <code className="action">Snapshots</code> da secção **Selecione uma imagem**.
    - **Modelo**: Apenas os modelos capazes de acolher a sua imagem estarão disponíveis, em função da sua quota.

    Defina o nome da nova instância, a chave SSH e os parâmetros de rede e de faturação e, em seguida, clique no botão <code className="action">Criar a minha instância</code>.

    Para mais informações sobre a criação de uma instância, consulte [este guia](/guides/public-cloud/compute/getting-started).

    :::info
    Para criar uma instância num datacenter diferente do da snapshot, será necessário transferi-la para a zona correspondente. Consulte o [guia sobre a transferência de backup de instância entre datacenters](/guides/public-cloud/compute/transfer-instance-backup-from-one-datacentre-to-another).

    :::

  </Tab>
  <Tab label="API OVHcloud">
    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/instance"} />

Preencha as variáveis:
    
    - **serviceName**: O ID do projeto OVHcloud.
    - **regionName**: O nome da região onde a instância será criada.
    
    Exemplo de corpo da requisição:
    
    ```json
    {
      "billingPeriod": "hourly",
      "bootFrom": {
        "imageId": "5cb8ea68-****-****-****-820be8346***"
      },
      "flavor": {
        "id": "e81b46f8-****-****-****-cad655e65***"
      },
      "name": "newInstance",
      "network": {
        "public": true
      },
      "sshKey": {
        "name": "MySSHKey"
      }
    }
    ```
  </Tab>
  <Tab label="CLI OpenStack">
    Para criar uma instância a partir da sua snapshot, utilize o ID da snapshot como imagem com este comando:
    
    ```bash
    $ openstack server create --key-name SSHKEY --flavor 98c1e679-5f2c-4069-b4da-4a4f7179b758 --image 0a3f5901-2314-438a-a7af-ae984dcbce5c Server1_from_snap
    ```
  </Tab>
  <Tab label="Horizon">
    Na interface Horizon, clique em <code className="action">Compute</code> no menu à esquerda, depois em <code className="action">Images</code>. Procure a imagem desejada e clique no botão <code className="action">Launch</code> à direita da linha da sua imagem.
    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon1.png" loading="lazy" />

Nomeie sua instância no campo dedicado e determine o número de instâncias a criar. Em seguida, clique na aba <code className="action">Flavor</code>.
    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon-2" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon2.png" loading="lazy" />

Escolha o modelo de instância desejado, depois clique na aba <code className="action">Networks</code>.
    
    :::warning
    Se sua instância for um servidor Windows, você deverá selecionar uma flavor do tipo win-xx-xx (por exemplo, win-b2-15) e possuir uma interface pública na rede Ext-Net. Sem essas condições, a autenticação no KMS OVHcloud não será possível, e seu servidor permanecerá com uma [licença não ativada](/guides/public-cloud/compute/activate-windows-license-private-mode). Isso pode resultar em limitações, incluindo a falta de atualizações. Atenção: não é possível redimensionar uma instância Linux (por exemplo, b2-15) para uma instância Windows (como win-b2-15). Para realizar essa transição, será necessário criar uma nova instância.

    :::

    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon-3" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon3.png" loading="lazy" />

Escolha a rede que deseja atribuir, depois clique no botão <code className="action">Launch Instance</code>.
    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon-4" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon4.png" loading="lazy" />

Você pode verificar o status da sua nova instância em <code className="action">Compute</code> no menu à esquerda, depois em <code className="action">Instances</code>.
    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon-5" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon5.png" loading="lazy" />
  </Tab>
</Tabs>


### Restaurar uma instância a partir de uma snapshot

<Tabs>
  <Tab label="Consola OVHcloud">
    No menu à esquerda do seu projeto Public Cloud, clique em <code className="action">Instances</code> na secção **Compute** e, em seguida, clique no nome da instância em causa.

    No cartão **Informações gerais** do separador <code className="action">Visão geral</code>, clique em <code className="action">Editar imagem</code> na linha **Imagem**. Abre-se o painel **Editar imagem**.

    Na secção **Selecionar uma distribuição**, selecione as snapshots e, em seguida, selecione a snapshot a restaurar na secção **Selecionar uma imagem**. Apenas são propostas as snapshots armazenadas na região da instância. Clique em <code className="action">Editar imagem</code> se tiver a certeza de que pretende substituir a imagem atual pela snapshot.

    A instância será reinstalada e reiniciada até que o processo esteja concluído.

    :::warning
    Tal como indicado na mensagem de aviso, todos os dados da instância serão eliminados: nenhum dado adicionado após a criação da snapshot poderá ser recuperado.

    :::

  </Tab>
  <Tab label="API OVHcloud">
    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/instance/\\{instanceId\\}/reinstall"} />

Preencha as variáveis:
    
    - **serviceName**: O ID do projeto OVHcloud.
    - **regionName**: O nome da região onde a instância de origem está localizada.
    - **instanceId**: O ID único da instância.
    
    Exemplo de corpo da requisição:
    
    ```json
    {
      "imageId": "5cb8ea68-****-****-****-820be8346***",
      "imageRegionName": "GRA11"
    }
    ```
  </Tab>
</Tabs>
