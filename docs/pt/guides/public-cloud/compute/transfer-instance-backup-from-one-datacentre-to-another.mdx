## Objetivo

Poderá ser necessário mover a sua [instância Public Cloud](https://www.ovhcloud.com/pt/public-cloud/compute/) de uma região OpenStack para outra, seja porque prefere migrar para uma nova região OpenStack disponível, seja porque pretende migrar do OVHcloud Labs para o Public Cloud.

**Saiba como transferir uma cópia de segurança de uma instância de uma região OpenStack para outra, mantendo a configuração e o estado da instância.**

## Requisitos

- Dispor da CLI OpenStack. Consulte o nosso guia [Como preparar o ambiente para utilizar a API OpenStack](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment).
- Ter conectividade às API OpenStack da OVHcloud.
- Reservar espaço de armazenamento suficiente correspondente ao tamanho do disco da instância (para o armazenamento de backup temporário).

Este ambiente será utilizado como "jump host" para transferir a cópia de segurança de uma região para outra. Pode ser uma instância alojada na OVHcloud ou a sua máquina local.

Também necessitará de uma [instância Public Cloud](https://www.ovhcloud.com/pt/public-cloud/compute/) na sua conta OVHcloud.

## Instruções

:::info
Se precisar de criar uma cópia de segurança com OpenStack, consulte o nosso guia "[Guardar uma instância](/guides/public-cloud/compute/save-an-instance)".
:::

### Etapa 1 - Descarregar a cópia de segurança

Liste as suas imagens privadas para identificar a cópia de segurança que pretende transferir:

```bash
openstack image list --private
```

Descarregue a cópia de segurança para o seu armazenamento local:

```bash
openstack image save --file backup.qcow2 <image-id>
```

### Etapa 2 - Mudar para a região de destino

Se transferir a cópia de segurança para outra região dentro do mesmo projeto, atualize `OS_REGION_NAME`:

```bash
export OS_REGION_NAME=<região-destino>
```

Se transferir a cópia de segurança para outro projeto ou conta, carregue o ficheiro RC correspondente:

```bash
source openrc.sh
```

### Etapa 3 - Importar a cópia de segurança para a região de destino

O comando de importação varia consoante a região de destino seja uma região padrão ou uma Local Zone.

#### Região padrão

```bash
openstack image create \
  --disk-format qcow2 \
  --container-format bare \
  --file backup.qcow2 \
  <nome-imagem>
```

#### Local Zone

Os nomes das regiões Local Zone contêm `-lz-` (por exemplo `eu-central-lz-prg-a`). Estas regiões requerem `--disk-format raw`. A extensão do ficheiro de cópia de segurança não afeta a importação: é o parâmetro `--disk-format` que indica ao OpenStack como interpretar o ficheiro.

```bash
openstack image create \
  --disk-format raw \
  --container-format bare \
  --file backup.qcow2 \
  <nome-imagem>
```

:::warning
**Apenas para imagens Windows**: deve adicionar as seguintes propriedades, caso contrário não será possível associar um flavor do tipo `win-x-x` a partir da Área de Cliente OVHcloud. Este tipo de flavor é necessário para a autenticação através do [KMS OVHcloud](/guides/manage-and-operate/kms/quick-start).

Adicione as propriedades no momento da criação (região padrão):

```bash
openstack image create \
  --disk-format qcow2 \
  --container-format bare \
  --file backup.qcow2 \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <nome-imagem>
```

Adicione as propriedades no momento da criação (Local Zone):

```bash
openstack image create \
  --disk-format raw \
  --container-format bare \
  --file backup.qcow2 \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <nome-imagem>
```

Ou defina-as numa imagem já existente:

```bash
openstack image set \
  --property "_system_cloud_property=windows" \
  --property "distro_family=windows" \
  --property "os_type=windows" \
  <image-uuid>
```
:::

:::info
Para recriar a sua instância a partir desta cópia de segurança, consulte o nosso guia "[Criar / Restaurar um servidor virtual a partir de um backup](/guides/public-cloud/compute/create-restore-a-virtual-server-with-a-backup)".
:::
