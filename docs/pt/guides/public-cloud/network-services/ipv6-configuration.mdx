## Objetivo

O Internet Protocol version 6 (IPv6) é a versão mais recente do Internet Protocol (IP). Foi concebido para resolver o esgotamento, há muito previsto, dos endereços IPv4, utilizando endereços de 128 bits em vez dos tradicionais 32 bits do IPv4.

Cada instância Public Cloud é entregue com um endereço IPv4 e um endereço IPv6.

**Neste tutorial, vamos explicar-lhe como configurar um endereço IPv6 numa instância Public Cloud.**

:::info
Atualmente, as ofertas Floating IP e Gateway não são compatíveis com o IPv6. O IPv6 só pode ser utilizado com as instâncias que dispõem de um [Basic IP](/guides/public-cloud/network-services/concepts#publicmode). Nas regiões 3-AZ, o endereço IPv6 de um Basic IP ainda não pode ser aprovisionado a partir da Área de Cliente OVHcloud.

:::

## Requisitos

- Uma instância Public Cloud, independentemente do modelo.
- Dispor de um acesso de administrador (sudo) ao seu servidor via SSH ou ambiente de trabalho remoto (Windows).
- Dispor de conhecimentos básicos de redes.

## Instruções

As secções seguintes contêm as configurações das distribuições que disponibilizamos atualmente, bem como das distribuições/sistemas operativos mais utilizados. O primeiro passo consiste sempre em ligar-se ao seu servidor via SSH ou através de uma sessão de ligação GUI (RDP para uma instância Windows).

:::warning
Tenha em atenção que o endereço IPv6 está configurado por predefinição nas nossas instâncias Public Cloud, exceto nas instâncias Windows. Certifique-se de que verifica o ficheiro de configuração do sistema operativo antes de efetuar qualquer alteração.

:::

### Léxico

Eis um breve léxico dos termos utilizados neste tutorial:

|Léxico|Descrição|
|---|---|
|YOUR_IPV6|O endereço IPv6 atribuído ao seu serviço (por ex.: 2607:5300:60:62ac:abcd)|
|IPV6_PREFIX|O prefixo do seu bloco IPv6 (por ex.: 2607:5300:60:62ac::/128 -> netmask = 128)|
|IPV6_GATEWAY|A gateway do seu bloco IPv6 (por ex.: 2607:5300:60:62ac::1)|

### Exemplos de configurações persistentes

:::info
**Exemplos**

As informações fornecidas abaixo são dadas a título de exemplo.

Enquanto administrador dos seus serviços, é da sua responsabilidade adaptar estas informações à sua distribuição ou ao seu sistema operativo.

Em primeiro lugar, ligue-se à sua instância via SSH.

:::tip
Selecione o separador correspondente ao seu sistema operativo.

<Tabs>
  <Tab label="Debian (exceto Debian 12)">
    Por predefinição, os ficheiros de configuração estão localizados no diretório `/etc/network/interfaces.d/`.
    
    A melhor prática consiste em criar um ficheiro de configuração separado no diretório `/etc/network/interfaces.d/` para configurar o IPv6. No nosso exemplo, o ficheiro chama-se `51-cloud-init-ipv6`:
    
    ```bash
    sudo nano /etc/network/interfaces.d/51-cloud-init-ipv6
    ```
    
    Isto separa a configuração IPv6 e permite-lhe reverter facilmente as alterações em caso de erro.
    
    Adicione as seguintes linhas ao ficheiro. Substitua os elementos genéricos (ou seja, `YOUR_IPV6`, `IPV6_PREFIX` e `IPV6_GATEWAY`), bem como a interface de rede (se o seu servidor não utilizar **eth0**), pelos seus valores específicos:
    
    ```console
    iface eth0 inet6 static
    address YOUR_IPV6
    netmask IPV6_PREFIX
    post-up /sbin/ip -6 route add IPV6_GATEWAY dev eth0
    post-up /sbin/ip -6 route add default via IPV6_GATEWAY dev eth0
    pre-down /sbin/ip -6 route del default via IPV6_GATEWAY dev eth0
    pre-down /sbin/ip -6 route del IPV6_GATEWAY dev eth0
    ```

    <details>
    <summary>Exemplo de configuração</summary>

    ```console
    iface eth0 inet6 static
    address 2607:5300:201:abcd::7c5
    netmask 128
    post-up /sbin/ip -6 route add 2607:5300:201:abcd::1 dev eth0
    post-up /sbin/ip -6 route add default via 2607:5300:201:abcd::1 dev eth0
    pre-down /sbin/ip -6 route del default via 2607:5300:201:abcd::1 dev eth0
    pre-down /sbin/ip -6 route del 2607:5300:201:abcd::1 dev eth0
    ```

    </details>
    
    Em seguida, reinicie o serviço de rede com um dos seguintes comandos:
    
    ```bash
    sudo service networking restart
    ```
    
    ```bash
    sudo systemctl restart networking
    ```
  </Tab>
  <Tab label="Ubuntu e Debian 12">
    Os ficheiros de configuração de rede estão localizados no diretório `/etc/netplan/`.
    
    A melhor prática consiste em criar um ficheiro de configuração separado no diretório `/etc/netplan/` para configurar o IPv6. No nosso exemplo, o ficheiro chama-se `51-cloud-init-ipv6.yaml`:
    
    ```bash
    sudo nano /etc/netplan/51-cloud-init-ipv6.yaml
    ```
    
    Isto separa a configuração IPv6 e permite-lhe reverter facilmente as alterações em caso de erro.
    
    Adicione as seguintes linhas ao ficheiro. Substitua os elementos genéricos (ou seja, `YOUR_IPV6`, `IPV6_PREFIX` e `IPV6_GATEWAY`), bem como a interface de rede (se o seu servidor não utilizar **eth0**), pelos seus valores específicos:
    
    ```yaml
    network:
        version: 2
        ethernets:
            eth0:
                dhcp6: no
                match:
                  name: eth0
                addresses:
                  - YOUR_IPV6/IPv6_PREFIX
                routes:
                  - to: ::/0
                    via: IPv6_GATEWAY
    ```
    
    :::warning
    É importante respeitar o alinhamento de cada elemento deste ficheiro, tal como representado no exemplo acima. Não utilize a tecla de tabulação para criar o espaçamento. Apenas é necessária a tecla de espaço.

    :::

    <details>
    <summary>Exemplo de configuração</summary>

    ```yaml
    network:
        version: 2
        ethernets:
            eth0:
                dhcp6: no
                match:
                  name: eth0
                addresses:
                  - 2607:5300:201:abcd::7c5/128
                routes:
                  - to: ::/0
                    via: 2607:5300:201:abcd::1
    ```

    </details>
    
    Pode testar a sua configuração através do seguinte comando:
    
    ```bash
    sudo netplan try
    ```
    
    Se estiver correta, aplique-a através do seguinte comando:
    
    ```bash
    sudo netplan apply
    ```

  <Tab label="RedHat / CloudLinux / Rocky Linux (8 & 9) / AlmaLinux (8 & 9)">
    Os ficheiros de configuração de rede estão localizados no diretório `/etc/sysconfig/network-scripts/`. Recomendamos que comece por criar uma cópia de segurança do ficheiro de configuração em questão.
    
    No nosso exemplo, o ficheiro chama-se `ifcfg-eth0`, pelo que fazemos uma cópia de segurança do ficheiro `ifcfg-eth0` utilizando os seguintes comandos. Não se esqueça de substituir **eth0** pela sua interface real, se necessário.
    
    ```bash
    cd /etc/sysconfig/network-scripts/
    sudo mkdir backup
    sudo cp ifcfg-eth0 backup/ifcfg-eth0
    ```
    
    Poderá então reverter as alterações utilizando os comandos abaixo:
    
    ```bash
    sudo rm -f /etc/sysconfig/network-scripts/ifcfg-eth0
    sudo cp /etc/sysconfig/network-scripts/backup/ifcfg-eth0 /etc/sysconfig/network-scripts/ifcfg-eth0
    ```
    
    Em seguida, editamos o ficheiro `ifcfg-eth0`, adicionando apenas as linhas relativas à configuração IPv6 do servidor. Substitua os elementos genéricos (ou seja, `YOUR_IPV6`, `IPV6_PREFIX` e `IPV6_GATEWAY`) pelos seus valores específicos.
    
    ```console
    IPV6INIT=yes
    IPV6ADDR=YOUR_IPV6/IPV6_PREFIX
    IPV6_DEFAULTGW=IPV6_GATEWAY
    ```
    
    Omitimos a configuração IPv4 para evitar qualquer confusão, mas a configuração IPv6 é feita no mesmo ficheiro de configuração.
    
    <details>
    <summary>Exemplo de configuração</summary>

    ```console
    IPV6INIT=yes
    IPV6ADDR=2607:5300:201:abcd::7c5/128
    IPV6_DEFAULTGW=2607:5300:201:abcd::1
    ```

    </details>
    
    Reinicie a interface de rede através de um dos seguintes comandos:
    
    ```bash
    sudo service networking restart
    ```
    
    ```bash
    sudo systemctl restart networking
    ```

### Diagnóstico

Configurou o IPv6, mas nada funciona?

Para determinar se a falha se encontra na sua configuração ou na rede da OVHcloud, efetue este teste simples.

Em primeiro lugar, [passe a sua instância para o modo rescue-pro](/guides/public-cloud/compute/put-an-instance-in-rescue-mode).

Em seguida, utilize os seguintes comandos para configurar o seu IPv6 de forma não persistente, substituindo `YOUR_IPV6`, `IPV6_PREFIX` e `IPV6_GATEWAY` pelas suas próprias informações:

```bash
ip addr add YOUR_IPV6/IPV6_PREFIX dev eth0
ip -6 route add IPV6_GATEWAY dev eth0
ip -6 route add default via IPV6_GATEWAY dev eth0
```

Teste novamente a sua rede através de um ping6, por exemplo:

```bash
ping6 ipv6.google.com
```

Se a sua instância responder, é provável que um dos passos da sua configuração inicial não tenha sido seguido rigorosamente.

Em qualquer caso, não hesite em efetuar um [pedido ao suporte](/links/support-contact) com os elementos testados acima, para obter uma análise da nossa parte.
