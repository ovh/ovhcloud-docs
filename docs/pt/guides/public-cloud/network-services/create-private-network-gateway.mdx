## Objetivo

Uma [Gateway](/links/public-cloud/gateway) oferece um método de ligação de saída segura a partir das suas instâncias em rede privada, ou ainda a possibilidade de utilizar endereços Floating IP com a sua instância ou o seu Load Balancer para a exposição de serviços.

**Saiba como criar uma rede privada com uma Gateway.**

## Requisitos

- Possuir um [projeto Public Cloud](/links/public-cloud/public-cloud) na sua conta OVHcloud
- **Para a API OVHcloud:** identificadores de API ([Primeiros passos com a API OVHcloud](/guides/manage-and-operate/api/first-steps))
- **Para a CLI OVHcloud:** a [CLI OVHcloud](https://github.com/ovh/ovhcloud-cli) instalada e configurada com os seus identificadores
- **Para a API OpenStack:** um ambiente OpenStack configurado ([Preparar o ambiente](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment))
- **Para o Terraform:** o Terraform instalado e o provider OVHcloud configurado ([Como utilizar o Terraform no Public Cloud OVHcloud](/guides/public-cloud/cross-functional/how-to-use-terraform))

## Instruções

### Modelos de Gateway

Antes de criar uma Gateway, escolha o modelo adaptado às suas necessidades de largura de banda:

:::info
Tenha em atenção que, de momento, o tamanho 2XL não está disponível nas regiões de Mumbai, Singapura e Sydney.
:::

| Modelo | Largura de banda |
|--------|------------------|
| S | até 200 Mbps |
| M | até 500 Mbps |
| L | até 2 Gbps |
| XL | até 4 Gbps |
| 2XL | até 8 Gbps |

### Criar uma rede privada com uma Gateway

  <Tab label="API OVHcloud">
    Abra a interface APIv6 OVHcloud. Se necessário, consulte o guia [Primeiros passos com a API OVHcloud](/guides/manage-and-operate/api/first-steps).

    **Recuperar o identificador do projeto**

    Se o identificador do projeto for desconhecido, utilize as seguintes chamadas:

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project"} />

    :::info
    Esta chamada recupera a lista dos projetos.
    :::

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}"} />

    :::info
    Esta chamada identifica o projeto através do campo `description`.
    :::

    **Criar a rede privada com uma Gateway**

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway"} />

    Preencha os campos de acordo com a seguinte tabela:

    | Campo | Descrição |
    |-------|-----------|
    | `serviceName` | O identificador do seu projeto |
    | `regionName` | Por exemplo: `GRA9` |
    | `model` | Tamanho da Gateway (`s`, `m`, `l`, `xl`, `2xl`) |
    | `name` | Nome da sua Gateway (`null` para o nome predefinido) |
    | `network.name` | Nome da rede privada (`null` para o nome predefinido) |
    | `network.cidr` | Bloco de endereços IP da sub-rede (ex.: `192.168.1.0/24`) |
    | `network.enableDhcp` | Marque para ativar o DHCP |
    | `network.ipVersion` | `4` (IPv6 não disponível) |
    | `network.vlanId` | Valor entre 2 e 4000, ou vazio para uma atribuição automática |

    :::info
    Repita a operação para cada região onde estão presentes as suas instâncias privadas.
    :::

    Para verificar os detalhes da sua Gateway:

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway"} />

    Deixe `subnetId` vazio para listar todas as Gateways da região especificada.
  </Tab>
  <Tab label="CLI OVHcloud">
    Utilize a [CLI OVHcloud](https://github.com/ovh/ovhcloud-cli) para criar uma rede privada com uma Gateway. Defina o seu projeto cloud com `--cloud-project <project_id>` ou configure-o no seu perfil.

    **Criar uma Gateway com uma nova rede privada:**

    ```bash
    ovhcloud cloud network gateway create <region> \
      --cloud-project <project_id> \
      --name my-gateway \
      --model s \
      --network-name my-network \
      --subnet-cidr 192.168.1.0/24 \
      --subnet-enable-dhcp \
      --wait
    ```

    **Criar uma Gateway numa rede privada existente:**

    ```bash
    ovhcloud cloud network gateway create <region> \
      --cloud-project <project_id> \
      --name my-gateway \
      --model s \
      --network-id <network_id> \
      --subnet-id <subnet_id> \
      --wait
    ```

    Modelos disponíveis: `s`, `m`, `l`, `xl`, `2xl`.

    :::info
    Apenas as redes privadas de região única são suportadas pela Gateway.
    :::
  </Tab>
  <Tab label="API OpenStack">
    Antes de prosseguir, consulte os seguintes guias:

    - [Preparar o ambiente para utilizar a API OpenStack](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment)
    - [Definir as variáveis de ambiente OpenStack](/guides/public-cloud/cross-functional/compute-set-openstack-environment-variables)

    **Passo 1 — Criar uma rede e uma sub-rede**

    ```console
    openstack network create my_network

    openstack subnet create my_subnet --subnet-range <my_private_ip_range/mask> --network my_network --no-dhcp
    ```

    **Passo 2 — Listar os níveis de qualidade de serviço**

    ```console
    openstack network qos policy list
    +--------------------------------------+---------------+--------+---------+----------------------------------+
    | ID                                   | Name          | Shared | Default | Project                          |
    +--------------------------------------+---------------+--------+---------+----------------------------------+
    | a5524eb5-944e-4106-b209-9478bbdcedab | large_router  | True   | False   | XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX |
    | c210f5b2-db59-4973-a25f-9131195b6bcf | medium_router | True   | False   | XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX |
    | ec0ee74d-a1f3-43f6-87aa-b0e69ef8ce45 | small_router  | True   | False   | XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX |
    +--------------------------------------+---------------+--------+---------+----------------------------------+
    ```

    **Passo 3 — Criar o router e configurar a Gateway**

    ```console
    openstack router create my_router

    openstack router add subnet my_router my_subnet

    openstack router set --external-gateway Ext-Net --qos-policy QOS_ID_OF_YOUR_CHOICE my_router
    ```

    Se não preencher o parâmetro `--qos-policy`, é aplicada a qualidade de serviço `small`.
  </Tab>
  <Tab label="Terraform">
    Antes de começar, consulte o guia: [Como utilizar o Terraform no Public Cloud OVHcloud](/guides/public-cloud/cross-functional/how-to-use-terraform)

    Crie um ficheiro Terraform (por exemplo `private_network_gateway.tf`) com o seguinte conteúdo:

    ```hcl
    resource "ovh_cloud_project_network_private" "mypriv" {
      service_name = "<project_id>"
      vlan_id      = "0"
      name         = "mypriv"
      regions      = ["GRA9"]
    }

    resource "ovh_cloud_project_network_private_subnet" "myprivsub" {
      service_name = ovh_cloud_project_network_private.mypriv.service_name
      network_id   = ovh_cloud_project_network_private.mypriv.id
      region       = "GRA9"
      start        = "10.0.0.2"
      end          = "10.0.255.254"
      network      = "10.0.0.0/16"
      dhcp         = true
    }

    resource "ovh_cloud_project_gateway" "gateway" {
      service_name = ovh_cloud_project_network_private.mypriv.service_name
      name         = "my-gateway"
      model        = "s"
      region       = ovh_cloud_project_network_private_subnet.myprivsub.region
      network_id   = tolist(ovh_cloud_project_network_private.mypriv.regions_attributes[*].openstackid)[0]
      subnet_id    = ovh_cloud_project_network_private_subnet.myprivsub.id
    }
    ```

    Aplique a configuração:

    ```console
    terraform apply
    ```
  </Tab>
