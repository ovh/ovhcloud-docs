## Objetivo

O objetivo deste manual é apresentar as diferentes etapas para implementar o seu primeiro KMS (Key Management Service) e criar uma chave. Para chamar a API REST regional do plano de dados, configure um método de autenticação conforme descrito no manual [Métodos de autenticação OKMS](/guides/manage-and-operate/kms/okms-authentication-methods).

## Requisitos

- Uma [conta de cliente OVHcloud](/guides/account-and-service-management/account-information/ovhcloud-account-creation).

## Instruções

### Encomendar o seu KMS

Cada KMS está associado a uma região, pelo que as chaves aí armazenadas têm a garantia de permanecer nessa região.

É possível encomendar vários KMS, seja em regiões diferentes ou numa mesma região.

Uma vez que a faturação de um KMS se baseia no número de chaves nele armazenadas, encomendar um KMS não gera faturação em si mesmo.

Clique no botão <code className="action">Encomendar um domínio OKMS</code>.

<img className="thumbnail" alt="Acesso ao menu KMS" src="/images/manage-and-operate/kms/quick-start/access_to_the_KMS_menu_01.png" loading="lazy" />

Indique a região do seu KMS.

<img className="thumbnail" alt="Encomendar o KMS" src="/images/manage-and-operate/kms/quick-start/order_kms_01.png" loading="lazy" />

A encomenda deve depois ser finalizada noutro separador. Se este não se tiver aberto automaticamente, é apresentado o link da encomenda:

<img className="thumbnail" alt="Encomendar o KMS" src="/images/manage-and-operate/kms/quick-start/order_kms_02.png" loading="lazy" />

Após alguns segundos, o KMS estará disponível na sua Área de Cliente.

<img className="thumbnail" alt="Encomendar o KMS" src="/images/manage-and-operate/kms/quick-start/order_kms_03.png" loading="lazy" />

#### Criar uma chave de encriptação

No separador <code className="action">Chaves de encriptação</code>, clique no botão <code className="action">Criar uma Service Key</code>.

<img className="thumbnail" alt="Criar uma chave" src="/images/manage-and-operate/kms/quick-start/create_key_01.png" loading="lazy" />

Um formulário permite-lhe configurar a chave, selecionando o seu tipo, o seu tamanho e as suas utilizações.

<img className="thumbnail" alt="Criar uma chave" src="/images/manage-and-operate/kms/quick-start/create_key_02.png" loading="lazy" />

:::warning
Apenas a criação de chaves de encriptação através das [API regionais](/guides/manage-and-operate/kms/kms-usage) está abrangida pela certificação PCI-DSS.

:::


Depois de criada a chave, clique nela para aceder aos seus detalhes.

O painel de controlo apresenta as propriedades criptográficas da chave, bem como as ações que permitem renomeá-la, desativá-la ou eliminá-la.

Para limitar os riscos de eliminação acidental, é necessário desativar a chave antes de a eliminar.

:::warning
Não existe qualquer forma de recuperar uma chave eliminada e a sua eliminação implica a perda dos dados encriptados com a mesma. Por conseguinte, qualquer eliminação deve ser ponderada com a maior precaução.

:::

#### Criar uma chave de encriptação

A criação de uma chave é efetuada através da seguinte API:

|**Método**|**Caminho**|**Descrição**|
| :-: | :-: | :-: |
|POST|/okms/resource/&#123;okmsId&#125;/serviceKey|Criar ou importar uma CMK|

A API espera os seguintes valores:

|**Campo**|**Valor**|**Descrição**|
| :-: | :-: | :-: |
|name|string|Nome da chave|
|context|string|Dado de identificação adicional que permite verificar a autenticidade da chave|
|type|oct, RSA, EC|Tipo de chave: sequência de bytes (oct) para chaves simétricas, RSA (RSA), Elliptic Curve (EC)|
|size|Integer|Tamanho da chave - consulte a tabela de correspondência abaixo|
|operations|Array|Utilização da chave - consulte a tabela de correspondência abaixo|
|curve|P-256, P-384, P-521|(opcional) Curva criptográfica para as chaves de tipo EC|

**Exemplo de criação de chave simétrica:**

```json
{
  "name": "My first AES key",
  "context": "project A",
  "type": "oct",
  "size": 256,
  "operations": [
    "encrypt",
    "decrypt"
  ]
}
```

**Exemplo de criação de chave assimétrica:**

```json
{
  "name": "My first RSA key",
  "context": "project A",
  "type": "RSA",
  "size": 4096,
  "operations": [
    "sign",
    "verify"
  ]
}
```

**Exemplo de criação de chave EC:**

```json
{
  "name": "My first EC key",
  "context": "project A",
  "type": "EC",
  "operations": [
    "sign",
    "verify"
  ],
  "curve": "P-256"
}
```

Os tamanhos e as operações possíveis consoante o tipo de chave são os seguintes:

- **oct**:
    - tamanho: 128, 192, 256
    - operações:
        - encrypt, decrypt
        - wrapKey, unwrapKey
- **RSA**:
    - tamanho: 2048, 3072, 4096
    - operações:
        - sign, verify
        - wrapKey, unwrapKey
- **EC**:
    - tamanho: não especificar
    - curve: P-256, P-384, P-521
    - operações: sign, verify

:::info
Nas chaves RSA, `wrapKey` / `unwrapKey` são mutuamente exclusivas com `sign` / `verify`.
:::

:::warning
Apenas a criação de chaves de encriptação através das [API regionais](/guides/manage-and-operate/kms/kms-usage) está abrangida pela certificação PCI-DSS.

:::

### Autenticar-se no plano de dados OKMS

Antes de chamar a API REST regional, configure um método de autenticação (token de acesso pessoal, conta de serviço ou certificado de acesso). Consulte [Métodos de autenticação OKMS](/guides/manage-and-operate/kms/okms-authentication-methods).

Para a utilização da API REST, recomenda-se um token de acesso pessoal (PAT) ou uma conta de serviço. Dê preferência aos [certificados de acesso](/guides/manage-and-operate/kms/okms-certificate-management) para as integrações KMIP, que exigem uma autenticação por certificado.

### Utilizar o KMS OVHcloud

Depois de inicializado o seu KMS OVHcloud, é possível utilizá-lo de duas formas diferentes:

- Utilizando a [API REST](/guides/manage-and-operate/kms/kms-usage) para encriptar ou assinar os seus dados (autenticação por PAT, conta de serviço ou certificado).
- Utilizando o [protocolo KMIP](/guides/manage-and-operate/kms/kms-kmip) para ligar produtos compatíveis com KMIP (certificado de acesso obrigatório).
