## Instruções

### Descrição dos certificados de acesso OKMS

Para comunicar com o seu domínio OKMS, tem de dispor de um certificado de acesso. Trata-se de um dos três [métodos de autenticação OKMS](/guides/manage-and-operate/kms/okms-authentication-methods); os certificados são **obrigatórios para o KMIP** e recomendados quando é necessária a autenticação de cliente mTLS. Para a utilização da API REST, um token de acesso pessoal (PAT) ou uma conta de serviço é geralmente mais simples de configurar.

Um certificado de acesso só é válido para o domínio para o qual foi gerado.

:::warning
Apenas a geração de certificados com um CSR está abrangida pela certificação PCI-DSS.

:::

É possível gerar este certificado deixando a OVHcloud gerar a chave privada, ou fornecendo o seu Certificate Signing Request (CSR) caso possua a sua própria chave privada.

##### Sem fornecer uma chave privada

Se não fornecer um CSR, a OVHcloud gerará o certificado de acesso, bem como uma chave privada.

A geração do certificado é efetuada através da seguinte API:

<Api version="v2" section="/okms" method="POST" route={"/okms/resource/\{okmsId\}/credential"} />

É necessário indicar as seguintes informações:

- **name**: o nome do certificado
- **identityURNs**: lista de identidades OVHcloud num formato URN que serão fornecidas ao IAM para o cálculo dos direitos de acesso
- **description**: descrição do certificado (facultativo)
- **certificateType**: algoritmo de assinatura do certificado (ECDSA ou RSA) - ECDSA por predefinição (facultativo)
- **validity**: período de validade do certificado em dias - 365 dias por predefinição (facultativo)

**Exemplo de criação de um certificado com a conta root:**

```json
{
  "description": "My root access credential",
  "identityURNs": [
    "urn:v1:eu:identity:account:xx1111-ovh"
  ],
  "name": "root",
  "validity": 30
}
```

**Exemplo de criação de um certificado com uma conta de utilizador local:**

```json
{
  "description": "My access credential",
  "identityURNs": [
    "urn:v1:eu:identity:user:xx1111-ovh/john.smith",
    "urn:v1:eu:identity:group:xx1111-ovh/my_group"
  ],
  "name": "John Smith",
  "validity": 30
}
```

A API devolve, em seguida, o estado de criação do certificado:

```json

  "name": "John Smith",
  "description": "My access credential",

    "urn:v1:eu:identity:user:xx1111-ovh/john.smith",
    "urn:v1:eu:identity:group:xx1111-ovh/my_group"
  ],
  "certificateType": "ECDSA",
  "status": "CREATING",
  "fromCSR": false,
  "privateKeyPEM": "-----BEGIN EC PRIVATE KEY-----\nMHcCAQEEIDOfWuMVQxl5quoURzThF4zTI9YYTmylSaPjneLBwP+2oAoGCCqGSM49\nAwEHoUQDQgAERd1eMw0YdAD+E9oSymGc4bCL1mfJl0EZwoM2ya/uKFFVFnGMnckg\nXXXXXXXXXXXXXXX==\n-----END EC PRIVATE KEY-----\n",
```
