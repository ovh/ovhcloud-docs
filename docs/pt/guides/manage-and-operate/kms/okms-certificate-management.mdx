## Objetivo

O objetivo deste manual é apresentar as diferentes etapas para criar e gerir os seus certificados de acesso OKMS nos seus produtos de Data Security.

## Requisitos

- Dispor de uma [conta de cliente OVHcloud](/guides/account-and-service-management/account-information/ovhcloud-account-creation).
- Ter [encomendado um KMS OVHcloud](/guides/manage-and-operate/kms/quick-start)

[[cpnav:security-kms]]

## Instruções

### Descrição dos certificados de acesso OKMS

Para comunicar com o seu domínio OKMS, tem de dispor de um certificado de acesso. Trata-se de um dos três [métodos de autenticação OKMS](/guides/manage-and-operate/kms/okms-authentication-methods); os certificados são **obrigatórios para o KMIP** e recomendados quando é necessária a autenticação de cliente mTLS. Para a utilização da API REST, um token de acesso pessoal (PAT) ou uma conta de serviço é geralmente mais simples de configurar.

Um certificado de acesso só é válido para o domínio para o qual foi gerado.

:::warning
Apenas a geração de certificados com um CSR está abrangida pela certificação PCI-DSS.

:::


### Criar um certificado de acesso a partir do KMS

<Tabs>
<Tab label="Consola OVHcloud">

Pode criar este certificado a partir do seu domínio OKMS no Key & Secret Manager.

No separador <code className="action">Certificados de acesso</code>, clique em <code className="action">Criar um certificado de acesso</code>.

<img className="thumbnail" alt="Separador Certificados de acesso de um domínio KMS" src="/images/manage-and-operate/kms/okms-certificate-management/console/access-certificates-tab.png" loading="lazy" />

Na secção **Informações gerais**, introduza um **Nome de exibição** para o certificado e, se o desejar, uma **Descrição**.

A secção **Configuração do certificado de acesso** permite-lhe definir o seu período de **Validade**, escolher o **Método de criação** (com ou sem o seu próprio Certificate Signing Request (CSR), caso possua a sua própria chave privada) e escolher o algoritmo de assinatura quando não fornecer um CSR.

#### Sem fornecer uma chave privada

Se não fornecer um CSR, selecione **Não tenho uma chave privada**: a OVHcloud gerará o certificado de acesso, bem como uma chave privada. Poderá então escolher o **Tipo de certificado**, ECDSA (recomendado) ou RSA.

<img className="thumbnail" alt="Formulário de criação de um certificado de acesso sem chave privada" src="/images/manage-and-operate/kms/okms-certificate-management/console/create-access-certificate-form.png" loading="lazy" />

#### Com um CSR

Se dispuser da sua própria chave privada, pode utilizá-la com um CSR: selecione **Já tenho uma chave privada** e, em seguida, cole o seu CSR em formato PEM no campo **Certificate Signing Request (CSR)**.

<img className="thumbnail" alt="Formulário de criação de um certificado de acesso com um CSR" src="/images/manage-and-operate/kms/okms-certificate-management/console/create-access-certificate-csr.png" loading="lazy" />

A secção **Adicionar identidades** permite indicar as [identidades OVHcloud](/guides/manage-and-operate/iam/identities-management) associadas ao certificado que permitem calcular os direitos de acesso através do [IAM OVHcloud](/guides/account-and-service-management/account-information/iam-policy-ui). Selecione **Escolher identidades** para as escolher nas listas **Utilizadores**, **Grupos de utilizadores** e **Contas de serviço**, até 25 identidades.

Pode também selecionar **Anexar identidade raiz** para não ficar limitado pelo IAM OVHcloud: o certificado terá automaticamente direitos de administrador sobre o domínio OKMS. Esta opção destina-se a ambientes de teste.

<img className="thumbnail" alt="Secção Adicionar identidades do formulário do certificado de acesso" src="/images/manage-and-operate/kms/okms-certificate-management/console/create-access-certificate-identities.png" loading="lazy" />

Clique em <code className="action">Criar</code>. Em seguida, é necessário descarregar a chave privada do certificado: clique em <code className="action">Descarregar a chave privada</code>, marque **Confirmo ter descarregado a chave privada** e depois clique em <code className="action">Concluir</code>.

:::danger
A chave privada deixará de estar acessível posteriormente. Em caso de perda, será necessário voltar a gerar um certificado.

:::


:::warning
O campo **privateKeyPEM** deve ser modificado de modo a substituir as ocorrências de `\n` por mudanças de linha.

:::


<img className="thumbnail" alt="Etapa de descarregamento da chave privada após a criação de um certificado de acesso" src="/images/manage-and-operate/kms/okms-certificate-management/create_certificat_05.png" loading="lazy" />

Por fim, pode descarregar a chave pública do certificado a partir da página do certificado: abra o certificado no separador <code className="action">Certificados de acesso</code> e clique em <code className="action">Transferir o certificado</code>.

<img className="thumbnail" alt="Página de um certificado de acesso com o botão Transferir o certificado" src="/images/manage-and-operate/kms/okms-certificate-management/console/access-certificate-download.png" loading="lazy" />

É possível gerar este certificado deixando a OVHcloud gerar a chave privada, ou fornecendo o seu Certificate Signing Request (CSR) caso possua a sua própria chave privada.

#### Sem fornecer uma chave privada

Se não fornecer um CSR, a OVHcloud gerará o certificado de acesso, bem como uma chave privada.

A geração do certificado é efetuada através da seguinte API:

<Api version="v2" section="/okms" method="POST" route={"/okms/resource/\{okmsId\}/credential"} />

É necessário indicar as seguintes informações:

- **name**: o nome do certificado
- **identityURNs**: lista de identidades OVHcloud num formato URN que serão fornecidas ao IAM para o cálculo dos direitos de acesso
- **description**: descrição do certificado (facultativo)
- **certificateType**: algoritmo de assinatura do certificado (ECDSA ou RSA) - ECDSA por predefinição (facultativo)
- **validity**: período de validade do certificado em dias - 365 dias por predefinição (facultativo)

**Exemplo de criação de um certificado com a conta root:**

```json
{
  "description": "My root access credential",
  "identityURNs": [
    "urn:v1:eu:identity:account:xx1111-ovh"
  ],
  "name": "root",
  "validity": 30
}
```

**Exemplo de criação de um certificado com uma conta de utilizador local:**

```json
{
  "description": "My access credential",
  "identityURNs": [
    "urn:v1:eu:identity:user:xx1111-ovh/john.smith",
    "urn:v1:eu:identity:group:xx1111-ovh/my_group"
  ],
  "name": "John Smith",
  "validity": 30
}
```

A API devolve, em seguida, o estado de criação do certificado:

```json
{
  "id": "f18b5e0d-75b8-40a3-9b0e-XXXXXX",
  "name": "John Smith",
  "description": "My access credential",
  "identityURNs": [
    "urn:v1:eu:identity:user:xx1111-ovh/john.smith",
    "urn:v1:eu:identity:group:xx1111-ovh/my_group"
  ],
  "certificateType": "ECDSA",
  "status": "CREATING",
  "fromCSR": false,
  "privateKeyPEM": "-----BEGIN EC PRIVATE KEY-----\nMHcCAQEEIDOfWuMVQxl5quoURzThF4zTI9YYTmylSaPjneLBwP+2oAoGCCqGSM49\nAwEHoUQDQgAERd1eMw0YdAD+E9oSymGc4bCL1mfJl0EZwoM2ya/uKFFVFnGMnckg\nXXXXXXXXXXXXXXX==\n-----END EC PRIVATE KEY-----\n",
  "createdAt": "2024-04-04T12:26:28.856619+02:00",
```

Copie o valor do campo **privateKeyPEM** para um ficheiro **domain.key**

:::


:::warning
O campo **privateKeyPEM** deve ser modificado de modo a substituir as ocorrências de `\n` por mudanças de linha.

:::
