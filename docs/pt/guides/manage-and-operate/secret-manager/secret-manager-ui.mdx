## Objetivo

O objetivo deste guia é apresentar a utilização do Secret Manager através da consola OVHcloud.

## Requisitos

- Dispor de uma [conta de cliente OVHcloud](/guides/account-and-service-management/account-information/ovhcloud-account-creation).
- Para aceder aos segredos através da API REST ou da API compatível com HashiCorp Vault KV2, configure um [método de autenticação](/guides/manage-and-operate/kms/okms-authentication-methods) para o seu domínio OKMS (token de acesso pessoal, conta de serviço ou certificado de acesso).

[[cpnav:security-secret-manager]]

## Instruções

### Descrição

O Secret Manager é um produto que lhe permite armazenar de forma segura as credenciais, chaves de API, chaves SSH ou qualquer outro tipo de segredo necessário ao funcionamento das suas aplicações.

Um segredo é uma coleção de uma ou várias chaves/valores agrupadas numa versão.
Cada modificação de um segredo origina a criação de uma nova versão desse segredo, permitindo recuar no histórico de modificações do segredo.

### Criar um segredo

Na consola OVHcloud, os segredos são geridos no Key & Secret Manager. No menu à esquerda, abra <code className="action">Segurança</code> e clique em <code className="action">Key & Secret Manager</code>. Cada domínio OKMS dispõe de um separador <code className="action">Secrets</code>, que lista os segredos armazenados nesse domínio.

<img className="thumbnail" alt="Separador Secrets de um domínio OKMS com o botão Criar um segredo" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secrets-tab.png" loading="lazy" />

Para criar um segredo, clique em <code className="action">Criar um segredo</code>.

O formulário de criação não permite escolher a região: o segredo é criado no domínio OKMS selecionado na lista **Domínio OKMS** e, por conseguinte, na região desse domínio. Selecione o domínio correto antes de clicar em <code className="action">Criar um segredo</code>.

:::info
Se ainda não dispõe de um domínio OKMS na região onde pretende criar o segredo, crie primeiro um: abra a lista **Domínio OKMS**, clique em <code className="action">Criar um domínio</code> e escolha a região.
A criação do domínio pode demorar alguns minutos.
:::


Indique de seguida o **Path** do segredo, por exemplo **prod/database/MySQL**. Este Path serve para organizar os segredos de forma hierárquica.

Depois, indique o conteúdo do segredo na secção **Configuração dos valores**. O segredo contém uma lista de chaves/valores. Por predefinição, estas são introduzidas uma a uma na vista **Chave valor** (<code className="action">Adicionar uma chave/valor</code> adiciona uma linha). Na vista **JSON**, pode introduzi-las em formato JSON:

```json
{
    "login": "admin",
    "password": "my_secret_password"
}
```

<img className="thumbnail" alt="Página Criar um segredo com as secções Path e Configuração dos valores" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/create-secret-form.png" loading="lazy" />

:::info
Não existe limite quanto ao número de chaves/valores de um segredo, no entanto o tamanho total dos dados não deve exceder 64 KB.
:::


Assim que o segredo é criado, este aparece na lista de segredos do separador **Secrets** do domínio OKMS.

### Gerir os segredos

Assim que um segredo é criado, a lista de segredos é apresentada no separador **Secrets** do domínio OKMS, na consola OVHcloud.
Para apresentar os segredos de outro domínio OKMS, selecione-o na lista **Domínio OKMS** acima dos separadores, onde os seus domínios estão agrupados por região.

Pode aceder à configuração do segredo clicando no respetivo Path na lista de segredos para apresentar o seu conteúdo, criar uma nova versão ou eliminá-lo.

O painel de controlo do segredo apresenta várias informações, como as informações gerais e os parâmetros que se aplicam ao segredo:

- **Número máximo de versões**: Para além do valor indicado, a versão mais antiga é eliminada.
- **Prazo de expiração de uma versão**: Para além do período indicado, a versão é desativada.
- **CAS (Check-And-Set Version Control)**: Se estiver ativado, deve especificar sempre o número da versão atual ao efetuar modificações.

<img className="thumbnail" alt="Painel de controlo do segredo com as secções Valores, Informações gerais e Configuração" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secret-dashboard.png" loading="lazy" />

#### Aceder ao conteúdo de um segredo

Um utilizador que disponha das permissões IAM necessárias pode aceder ao conteúdo de um segredo. Configure a autenticação e as políticas IAM conforme descrito em [Métodos de autenticação OKMS](/guides/manage-and-operate/kms/okms-authentication-methods).

:::info
As permissões para listar uma versão (**okms:apiovh:secret/get**) são diferentes da permissão para obter o conteúdo dessa versão (**okms:apiovh:secret/version/getData**).
:::


Para tal, clique em <code className="action">Revelar o valor</code> na secção **Valores** do painel de controlo do segredo.

A secção **Valores** expande-se e apresenta o conteúdo da versão mais recente do segredo, sob a forma de chaves/valores ou em formato JSON. Cada valor pode ser copiado.

<img className="thumbnail" alt="Secção Valores que apresenta os pares chave/valor da versão atual" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secret-values-revealed.png" loading="lazy" />

Um seletor permite navegar entre as diferentes versões do segredo, bem como consultar o estado da versão selecionada.
Se a versão estiver desativada ou eliminada, não é apresentado nenhum valor.

#### Gerir as versões

Para aceder às versões de um segredo, clique no separador <code className="action">Versões</code>. Este separador lista todas as versões do segredo, com o número, a data de criação, a data de expiração e o estado de cada uma.
Cada modificação de um segredo origina a criação de uma nova versão.

<img className="thumbnail" alt="Separador Versões que lista as versões de um segredo com o respetivo estado" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secret-versions.png" loading="lazy" />

Uma versão pode ser:

- Ativa: O valor desta versão está acessível.
- Desativada: O valor desta versão ainda está presente no sistema, mas já não está acessível enquanto a versão não for reativada.
- Eliminada: O valor desta versão já não está presente no sistema e não pode ser restaurado.

Para cada versão, clique em <code className="action">Revelar a versão</code> para apresentar o respetivo valor. O botão `⋮` abre um menu que permite desativar (<code className="action">Desativar</code>) ou reativar (<code className="action">Reativar</code>) a versão, ou eliminá-la (<code className="action">Eliminar</code>).

Uma versão eliminada pelo parâmetro **Número máximo de versões** já não aparece na lista de versões.

### Gerir o domínio OKMS

O domínio OKMS do Secret Manager é comum ao domínio OKMS do Key Management Service.
A criação ou a eliminação de um domínio OKMS tem, por isso, consequências nos dois produtos.

Pode modificar a configuração dos segredos do domínio OKMS a partir do respetivo separador **Visão geral**, na secção **Configuração dos Secrets** (<code className="action">Modificar</code>).

#### Caso de vários domínios OKMS

Podem existir vários domínios OKMS numa mesma região. O domínio OKMS é escolhido previamente, na lista **Domínio OKMS** acima dos separadores, que agrupa os seus domínios por região. Os segredos que apresenta ou cria pertencem ao domínio selecionado nesta lista: a criação de um segredo não inclui nenhuma etapa de seleção adicional.

<img className="thumbnail" alt="Lista de domínios OKMS com os domínios agrupados por região e a entrada Criar um domínio" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/okms-domain-switcher.png" loading="lazy" />

Para adicionar um domínio OKMS numa região, clique em <code className="action">Criar um domínio</code> no topo desta lista e, de seguida, escolha a região.

### Utilizar o Secret Manager por API

O Secret Manager está acessível através de dois conjuntos de API diferentes. Ambos manipulam os mesmos objetos — um segredo criado por um dos métodos está acessível pelo outro.

Antes de chamar uma ou outra API, configure um [método de autenticação](/guides/manage-and-operate/kms/okms-authentication-methods) e a [política IAM](/guides/manage-and-operate/kms/okms-authentication-methods#iam-rights-for-okms) necessária no seu domínio OKMS. Para a utilização da API REST, recomenda-se um token de acesso pessoal (PAT) ou uma conta de serviço.

- Uma [API REST](/guides/manage-and-operate/secret-manager/rest-api) semelhante aos padrões de API da OVHcloud.
- Uma [API compatível com HashiCorp Vault KV2](/guides/manage-and-operate/secret-manager/kv2-api) que proporciona compatibilidade com as aplicações já compatíveis com HashiCorp Vault KV2.
