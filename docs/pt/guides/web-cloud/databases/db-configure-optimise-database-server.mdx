## Objetivo

Os servidores de bases de dados Web Cloud Databases permitem-lhe modificar os parâmetros globais do seu servidor. Também pode visualizar a atividade do seu servidor.

**Descubra como configurar e otimizar o servidor de bases de dados.**

## Requisitos

- Dispor de uma [instância Web Cloud Databases](/links/web/databases) (incluída numa oferta de [alojamento web](/links/web/hosting) Performance, Agency, Agency Plus ou Agency Max).

[[cpnav:web-cloud-databases]]

<summary>Autorizar um endereço IP</summary>

Para aceder à sua instância Web Cloud Databases, deve indicar os endereços IP ou os intervalos de endereços IP autorizados a ligarem-se às suas bases de dados.

Clique nos separadores abaixo para ver cada um dos **4** passos.

    Na página que se abre, clique no separador <code className="action">IPs autorizados</code>.

    <img className="thumbnail" alt="Separador IPs autorizados de uma instância Web Cloud DB" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/allowed-ips/tab.png" loading="lazy" />
  </Tab>
  <Tab label="Passo 3">
    Na página que aparece, clique no botão <code className="action">Adicionar um IP</code> situado por cima da tabela.

    <img className="thumbnail" alt="Botão Adicionar um IP acima da tabela dos IPs autorizados" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/allowed-ips/add-ip.png" loading="lazy" />

    :::tip
    Se pretender alterar um endereço IP ou um intervalo de endereços IP já autorizado, clique diretamente na tabela no botão <code className="action">⋮</code> da coluna **Ações**, à direita da linha correspondente ao endereço IP ou ao intervalo de endereços IP a alterar e, a seguir, em <code className="action">Editar</code>. Poderá alterar o seu nome e as suas autorizações; o próprio endereço IP não pode ser alterado.

    <img className="thumbnail" alt="Menu de uma linha da tabela dos IPs autorizados" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/allowed-ips/row-actions-menu.png" loading="lazy" />

  </Tab>
  <Tab label="Passo 4">
    Na janela **Adicionar um endereço IP autorizado** que se abre, vários campos devem ser preenchidos:

    <img className="thumbnail" alt="Janela Adicionar um endereço IP autorizado e os seus campos" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/allowed-ips/add-ip-window.png" loading="lazy" />

    - **IP** (obrigatório): Introduza aqui o endereço IP (por exemplo: `203.0.113.44`) ou o intervalo de endereços IP (por exemplo: `203.0.113.0/24`, que representa todos os endereços IP de `203.0.113.0` a `203.0.113.255`) que deseja autorizar na sua solução Web Cloud Databases.
    - **Nome** (obrigatório): Pode, por exemplo, indicar a função do endereço IP ou do intervalo de endereços IP em causa.
    - **Permitir acesso ao serviço** (selecionada por predefinição): Selecione esta caixa para que o endereço IP ou o intervalo de endereços IP seja autorizado a aceder às bases de dados presentes na sua solução Web Cloud Databases.
    - **Permitir acesso SFTP**: Selecione esta caixa para que o endereço IP ou o intervalo de endereços IP seja autorizado a aceder aos logs da sua solução Web Cloud Databases.

    :::warning
    É fortemente desaconselhado selecionar a caixa **Permitir acesso ao serviço** para autorizar o intervalo de endereços IP `0.0.0.0/0` a aceder às suas bases de dados.

    Com efeito, isto permitiria autorizar o acesso às suas bases de dados a todos os endereços IPv4 existentes.

    :::

    Depois de introduzir as informações, clique no botão <code className="action">Adicionar</code>.

### Alterar a sua oferta Web Cloud Databases <a name="modify-ram-web-cloud-db"></a>

:::warning
Se a sua oferta Web Cloud Databases está associada a uma oferta de alojamento web **Performance**, **Agency**, **Agency Plus** ou **Agency Max**, deverá obrigatoriamente e previamente desassociar a oferta Web Cloud Databases do seu alojamento para migrar para uma oferta superior.

Para desassociar uma oferta Web Cloud Databases associada a um alojamento web **Performance**, **Agency**, **Agency Plus** ou **Agency Max**, consulte o nosso guia "[Desassociar a minha solução Web Cloud Databases de um alojamento web](/guides/web-cloud/databases/db-detach-from-web-hosting)".

**Esta ação é irreversível e a oferta Web Cloud Databases será depois faturada independentemente do seu alojamento web Performance, Agency, Agency Plus ou Agency Max.**

:::

  </Tab>

    <img className="thumbnail" alt="Ligação Encomendar mais RAM na secção Utilização de recursos" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/general-information/order-more-ram.png" loading="lazy" />

    :::

    Selecione a caixa de aceitação dos contratos e clique em <code className="action">Efetuar encomenda</code>. Será redirecionado para finalizar e pagar a encomenda. A nova RAM será aplicada depois de a encomenda ser paga, e a base de dados pode ser reiniciada nesse momento.

<details>

<summary>Instância MySQL e MariaDB</summary>

Clique nos separadores abaixo para ver cada um dos **4** passos.

<Tabs>
  <Tab label="Passo 1">
    Aceda à página <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink> e escolha a instância em causa.

    <img className="thumbnail" alt="Página Web Cloud DB e lista das instâncias da conta" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />
  </Tab>
  <Tab label="Passo 2">
    Clique no separador <code className="action">Configuração</code>.

    <img className="thumbnail" alt="Separador Configuração de uma instância Web Cloud DB" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/configuration/tab.png" loading="lazy" />
  </Tab>
  <Tab label="Passo 3">
    A configuração atualmente definida para a sua base de dados está repartida em três secções: **Ligações**, **Desempenho** e **Comportamento do motor**. Clique em <code className="action">Modificar</code> na parte inferior da secção que contém o parâmetro a alterar.

    <img className="thumbnail" alt="Secções de configuração MySQL com a ligação Modificar" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/configuration/groups.png" loading="lazy" />

    A tabela abaixo detalha cada parâmetro modificável, assim como os valores que lhe pode atribuir.

    |Parâmetro|Descrição|Valores configuráveis|
    |---|---|---|
    |`max_allowed_packet`|Tamanho máximo dos pacotes.|De 1 a 64 MB|
    |`max_user_connections`|Número de ligações simultâneas autorizadas por utilizador.|De 50 a 200|
    |`autocommit`|Define se os pedidos são automaticamente validados (committed) ou não.|ON ou OFF|
    |`interactive_timeout`|Tempo (em segundos) durante o qual o servidor aguarda atividade numa ligação interativa antes de a fechar.|De 60 a 28800 segundos|
    |`innodb_buffer_pool_size`|Dimensão da memória tampão, expressa em megabytes.|Valores propostos na lista (de 128 MB a 2048 MB)|
    |`max_connections`|Número de ligações simultâneas autorizadas no servidor de bases de dados.|De 100 a 200|
    |`wait_timeout`|Tempo (em segundos) durante o qual o servidor aguarda atividade numa ligação não interativa antes de a fechar.|De 60 a 28800 segundos|
    |`event_scheduler`|Permite acionar a execução de pedidos programados diretamente no servidor MySQL.|ON ou OFF|
    |`sql_mode`|Afeta a sintaxe SQL suportada e as verificações de validação de dados efetuadas por MySQL/MariaDB.|Consulte os modos predefinidos abaixo|
    |`long_query_time`|Duração (em segundos) a partir da qual um pedido é registado como lento.|1, 2, 5, 10 ou 60 segundos|
    |`local_infile`|Autoriza ou recusa o carregamento de dados locais pelos clientes.|ON ou OFF|
    |`log_bin_trust_function_creators`|Permite aos utilizadores sem privilégios criar funções armazenadas quando o registo binário está ativado.|ON ou OFF|

    :::info
    Quando encontra um erro no seu site a indicar `Too many connections`, isso deve-se à ultrapassagem do número de ligações simultâneas no servidor de bases de dados. Pode então aumentar a variável `max_connections` se esta não estiver no máximo.

    :::

    :::info
    <b>sql_mode</b>:

    &emsp;&emsp;Modo predefinido de MariaDB 10.1:
    <pre className="highlight language-console"><code className="language-console">NO_ENGINE_SUBSTITUTION,NO_AUTO_CREATE_USER</code></pre>

    &emsp;&emsp;Modo predefinido de MariaDB 10.2 e superior:
    <pre className="highlight language-console"><code className="language-console">STRICT_TRANS_TABLES,ERROR_FOR_DIVISION_BY_ZERO,NO_AUTO_CREATE_USER,NO_ENGINE_SUBSTITUTION</code></pre>

    &emsp;&emsp;Modo predefinido de MySQL 5.6:
    <pre className="highlight language-console"><code className="language-console">NO_ENGINE_SUBSTITUTION</code></pre>

    &emsp;&emsp;Modo predefinido de MySQL 5.7 e superior:
    <pre className="highlight language-console"><code className="language-console">ONLY_FULL_GROUP_BY,STRICT_TRANS_TABLES,NO_ZERO_IN_DATE,NO_ZERO_DATE,ERROR_FOR_DIVISION_BY_ZERO,NO_ENGINE_SUBSTITUTION</code></pre>

    Recomendamos que utilize sempre o modo predefinido, exceto se a sua base de dados tiver sido atualizada a partir de uma versão com um modo predefinido diferente da versão atual.

    :::
  </Tab>
  <Tab label="Passo 4">
    No painel que se abre, escolha os novos valores nas listas e clique em <code className="action">Aplicar</code>.

    <img className="thumbnail" alt="Painel de modificação da secção Ligações com o aviso de reinício" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/configuration/edit-drawer.png" loading="lazy" />
  </Tab>
</Tabs>

:::warning
Qualquer alteração requer o reinício do servidor de bases de dados.

:::

  </Tab>

    Na secção **Comportamento do motor**, encontrará a configuração atualmente definida para a sua base de dados. Para a modificar, clique em <code className="action">Modificar</code>, escolha o novo valor e clique em <code className="action">Aplicar</code>.

    <img className="thumbnail" alt="Painel de modificação do parâmetro log_min_messages de uma instância PostgreSQL" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/configuration/edit-drawer-postgresql.png" loading="lazy" />

    - **log_min_messages**: Controla os níveis das mensagens a registar nos logs do servidor. Os níveis disponíveis para uma solução Web Cloud Databases são os seguintes:
        - **"WARNING"**: Fornece mensagens de alerta sobre potenciais problemas.
        - **"ERROR"**: Envia o erro que provocou a anulação de um comando em curso.
        - **"LOG"**: Regista as informações destinadas aos administradores do servidor.
        - **"FATAL"**: Envia o erro que provocou o fim da sessão em curso.
        - **"PANIC"**: Envia o erro que provocou o fim do conjunto das sessões.

    Cada um dos níveis inclui todos os níveis que se seguem. Quanto mais alto for o nível, menos mensagens serão registadas nos logs do servidor.

    Por predefinição, o valor definido é **"WARNING"**, uma vez que inclui os valores **"ERROR"**, **"LOG"**, **"FATAL"** e **"PANIC"**.

    Também pode ativar extensões nas suas bases de dados. Para isso, clique no separador <code className="action">Bases de dados</code> e, em seguida, no ícone em forma de peça de puzzle da sua base de dados, na coluna **Extensões**.

    <img className="thumbnail" alt="Ícone da coluna Extensões na tabela das bases de dados" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/extensions-column.png" loading="lazy" />
  </Tab>

```sql
show variables like "version";
```

### Otimizar as suas bases de dados

Faça a manutenção da sua base de dados para que o seu desempenho permaneça elevado e devolva rapidamente as informações aos scripts. Para tal, é necessário uma base de dados estruturada e otimizada.

**Clique em cada título para ver o seu conteúdo.**

<details>

<summary>Indexar a base de dados</summary>

Para aumentar a rapidez das pesquisas durante um pedido, é necessário indexar os campos utilizados nas cláusulas WHERE.

Exemplo: costuma fazer pesquisas de pessoas relativamente à cidade. Indexe o campo "cidade" com o seguinte pedido:

```sql
ALTER TABLE `test` ADD INDEX (`city`);
```

</details>

<details>

<summary>Limpar a base de dados</summary>

Já não consulta alguns dos seus dados? Se os arquivar, as tabelas ficarão menos cheias e as pesquisas serão mais rápidas.

</details>

<details>

<summary>Limite de exibição</summary>

Limite a exibição dos registos a um número fixo (por exemplo, 10 por página) através da parte LIMIT do pedido SQL.

</details>

<details>

<summary>Agrupamento dos pedidos</summary>

Agrupe os pedidos no início do script da seguinte forma:

```bash
open_connection
request1
request2
...
close_connection
Display...
Process data
Loop through data...
Display...
...
```

</details>

<details>

<summary>Obter apenas dados úteis</summary>

Nos seus pedidos SQL, verifique se seleciona apenas aquilo de que precisa e, sobretudo, se não se esqueceu das ligações entre as tabelas.

Exemplo:

```sql
(where table1.field = table2.field2)
```

</details>

<details>

<summary>Evitar as opções que consomem demasiados recursos</summary>

Evite utilizar **"HAVING"**, por exemplo. Isto torna os pedidos mais pesados. Da mesma forma, evite utilizar **"GROUP BY"**, exceto em caso de verdadeira necessidade.

</details>
