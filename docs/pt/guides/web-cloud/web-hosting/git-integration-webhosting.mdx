## Objetivo

No atual panorama digital, as empresas estão a tornar-se cada vez mais dinâmicas e inovadoras. A capacidade de gerir e implementar eficazmente o código do seu website é essencial para manter a competitividade e a perenidade da sua marca. O Git, o sistema de gestão de versões mais utilizado do mundo, permite armazenar o código do seu website em plataformas como o GitHub, permitindo uma melhor rastreabilidade das modificações, assim como uma automatização e implementações mais rápidas. Enquanto cliente OVHcloud, beneficia de uma infraestrutura robusta para alojar o seu website, enquanto explora as numerosas vantagens do Git e do GitHub para o desenvolvimento e evolução do seu website.

**Saiba como configurar e utilizar o Git com o seu alojamento web a partir da consola OVHcloud.**

## Requisitos

- Ter um serviço de [alojamento web OVHcloud](/links/web/hosting).
- Ter uma conta [GitHub](https://github.com/) e ter acesso à mesma.

:::info
À data, apenas a plataforma GitHub é suportada no âmbito da utilização com os serviços de alojamento Web da OVHcloud.

:::

#### Definir o repositório GitHub

Insira o endereço do seu repositório GitHub. Se você ainda não tem um repositório GitHub para o seu projeto, crie um.

Para criar um novo repositório:

- Ligue-se à sua conta GitHub.
- Clique na sua imagem de perfil no canto superior direito e, a seguir, em <code className="action">Your repositories</code>.
- À direita do ecrã que se abrir, clique em <code className="action">New</code>.

Defina um nome para o seu depósito e preencha as informações necessárias.

:::warning
Marque a opção `Add a README file` para que o GitHub inicialize corretamente o seu repositório.

:::

Por fim, clique em <code className="action">Create Repository</code>.

Copie o endereço do seu repositório GitHub. Esta deve ser da forma:

- `https://github.com/<username>/<repository_name>.git` para um repositório público.
- `git@github.com:<username>/<repository_name>.git` para um repositório privado.

Volte ao painel **Configuração do Git** e cole o endereço do seu repositório GitHub no campo **Repositório**. Deve ter o formato `https://github.com/<username>/<repository_name>.git` para um repositório público, ou `git@github.com:<username>/<repository_name>.git` para um repositório privado. Enquanto o endereço não tiver um destes formatos e o campo **Ramo** estiver vazio, o botão <code className="action">Aplicar configuração</code> permanece inativo.

Agora defina o ramo do seu repositório GitHub. O branch padrão é "main`", mas se você quiser usar outro branch, crie um no GitHub seguindo as etapas abaixo:

- Ligue-se à sua conta GitHub.
- Clique na sua imagem de perfil no canto superior direito e, a seguir, em <code className="action">Your repositories</code>.
- Dirija-se ao repositório GitHub em questão.
- Clique em <code className="action">Main</code> e, em seguida, em <code className="action">View all branches</code>, ou clique diretamente no separador <code className="action">x Branch</code>.
- À direita do ecrã que se abrir, clique em <code className="action">New branch</code>.
- Indique o nome do novo ramo e confirme clicando em <code className="action">Create new branch</code>.

Volte ao painel **Configuração do Git** da consola OVHcloud e indique o nome do novo ramo que acabou de criar no campo **Ramo**.

Se indicar o endereço de um repositório GitHub privado (do tipo `git@github.com:<username>/<repository_name>.git`), é apresentada uma caixa **Chave SSH (repositório privado)** abaixo do campo **Repositório**.

<img className="thumbnail" alt="Caixa Chave SSH (repositório privado) apresentada para um endereço de repositório privado" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/configure-ssh-key.png" loading="lazy" />

Para configurar a chave SSH, consulte a etapa "Associar uma chave SSH ao GitHub (unicamente para os repositórios GitHub privados)" abaixo.

#### Associar uma chave SSH ao GitHub (apenas para os repositórios GitHub privados) <a name="linkSSHKey"></a>

:::info
**Porque é que a chave SSH é necessária apenas para um depósito privado?**

Quando o repositório do GitHub é público, os ficheiros podem ser recuperados sem autenticação, o que significa que o Git pode clonar e atualizar o código sem a necessidade de uma chave SSH. Por outro lado, se o seu repositório é privado, o GitHub exige uma autenticação para aceder. A chave SSH permite estabelecer essa ligação segura e garantir que apenas os utilizadores autorizados podem interagir com o repositório.

:::

:::info
A geração de uma chave SSH é uma etapa crucial, pois estabelece uma ligação segura e encriptada entre o diretório do seu website e o repositório GitHub. Esta chave garante que as transferências de dados e as alterações do código são efetuadas de forma segura e autenticada, evitando o acesso não autorizado e garantindo a integridade do código.

:::

Copie a chave SSH apresentada na caixa **Chave SSH (repositório privado)** clicando no botão de cópia situado à direita.

<img className="thumbnail" alt="Caixa Chave SSH (repositório privado) e botão de cópia" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/configure-ssh-key.png" loading="lazy" />

Como indicado na consola, adicione esta chave pública como chave de implementação ("deploy key") nas definições do seu repositório GitHub:

- Aceda à sua conta GitHub e abra o repositório em causa.
- Clique no separador <code className="action">Settings</code> do repositório e, a seguir, em <code className="action">Deploy keys</code> na coluna da esquerda.
- Clique em <code className="action">Add deploy key</code>.

É apresentado o formulário de adição de uma chave de implementação:

- **Title**: adicione uma descrição para a sua chave SSH. Por exemplo, pode dar o nome "OVHcloud" a esta chave.
- **Key**: cole a sua chave SSH.
- **Allow write access**: deixe esta caixa desmarcada, pois a implementação só necessita de um acesso de leitura ao seu repositório.

Para validar as informações, clique em <code className="action">Add key</code>. Se solicitado, confirme o acesso à sua conta no GitHub.

#### Configurar a implementação automática

Na parte inferior do painel **Configuração do Git**, a secção **Configurar a sua implementação automática** apresenta o URL do webhook, acompanhado de um botão de cópia. Configurar um webhook permite que o seu repositório GitHub notifique automaticamente o seu alojamento web OVHcloud dos eventos que ocorrem no repositório GitHub (nova implementação, alteração no código, etc.). Esta funcionalidade é particularmente útil se trabalhar em grupo no mesmo projeto e quiser estar a par de todas as alterações do repositório GitHub. Para saber mais, descubra como [configurar um webhook no GitHub](#configureWebhook).

#### Validar a associação do Git

Antes de validar o painel **Configuração do Git**, certifique-se de que:

- A sua chave SSH foi adicionada como chave de implementação do seu repositório GitHub (apenas repositório privado).
- O endereço do seu repositório GitHub está correto. Deve ter o formato `https://github.com/<username>/<repository_name>.git` (repositório público) ou `git@github.com:<username>/<repository_name>.git` (repositório privado).
- O nome do ramo do repositório GitHub está correto.
- A pasta raiz do seu site está vazia: caso contrário, a implementação falhará.

Para validar as informações, clique em <code className="action">Aplicar configuração</code>.

### Ativação da associação do Git

#### Sucesso da associação do Git

Depois de clicar em <code className="action">Aplicar configuração</code>, o painel fecha-se e uma mensagem confirma que a configuração Git foi aplicada. Na coluna **Git** da tabela do separador <code className="action">Os meus sites</code>, a menção **A configurar…** aparece na linha do site em causa: o Git está a ser ativado. O processo pode demorar vários minutos e a tabela é atualizada automaticamente.

<img className="thumbnail" alt="Coluna Git com a menção A configurar…" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/git-configuring.png" loading="lazy" />

Quando a associação do Git estiver concluída, o estado **Ativo** aparece na coluna **Git** do site em causa.

<img className="thumbnail" alt="Coluna Git com o estado Ativo" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/sites-git-column.png" loading="lazy" />

#### Erros da associação do Git

Na coluna **Git** da tabela do separador <code className="action">Os meus sites</code>, se a menção **Erro** aparecer na linha do site que pretende associar ao Git, significa que ocorreu pelo menos um dos seguintes erros:

- A chave SSH não foi adicionada como chave de implementação do seu repositório GitHub (repositório privado).
- A pasta raiz do site não estava vazia no momento da associação.
- O endereço do repositório GitHub não existe ou está errado.
- O ramo do repositório GitHub não existe ou o seu nome está errado.

Para conhecer a causa do erro, clique na menção **Erro**. Abre-se o painel **Erro de implementação Git**: este recorda o repositório e o ramo configurados, as causas frequentes e as informações da última implementação.

<img className="thumbnail" alt="Painel Erro de implementação Git" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/error-drawer.png" loading="lazy" />

Depois de corrigida a causa, escolha uma das ações da parte **O que pode fazer**: <code className="action">Relançar</code> para relançar a implementação (ou a associação), <code className="action">Modificar</code> para corrigir a configuração, ou <code className="action">Eliminar</code> para eliminar a associação antes de associar novamente o Git.

#### Configurar o webhook <a name="configureWebhook"></a>

Aceda à sua conta GitHub e ao repositório onde pretende configurar o webhook. Aceda ao separador <code className="action">Settings</code> e, no menu lateral dos parâmetros, clique em <code className="action">Webhooks</code>". Clique no botão <code className="action">Add webhook</code> para aceder ao formulário:

- **Payload URL**: introduza o URL do webhook copiado a partir do painel **Configuração do Git** da consola OVHcloud.
- **Content type**: escolha <code className="action">application/json</code> como tipo de conteúdo para os dados enviados.
- **Secret**: o segredo é facultativo. O GitHub irá utilizá-lo para assinar as mensagens enviadas pelo webhook, reforçando assim a segurança.
- **SSL verification**: se o seu website suporta o HTTPS, deixe esta opção ativada para uma segurança acrescida.
- **Which events would you like to trigger this webhook?**: selecione os eventos que irão despoletar o envio do webhook. Para uma implementação automática, <code className="action">Just the push event</code> (apenas o evento push) é frequentemente suficiente, mas pode escolher <code className="action">Send me everything</code> para receber notificações para todos os eventos.
- **Active**: certifique-se de que a caixa está selecionada para ativar o webhook.

Clique em <code className="action">Add webhook</code> para guardar e ativar o seu novo webhook.

#### Testar o seu webhook

Depois de criar o seu webhook no GitHub, vá à lista dos seus webhooks e selecione o que acabou de criar, ou clique em <code className="action">Edit</code>.

No ecrã que vai aparecer, clique no separador <code className="action">Recent Deliveries</code>. Para enviar um evento de teste especificamente, o GitHub normalmente envia um evento `ping` quando o webhook é criado, e você pode usar o botão <code className="action">Redeliver</code> ao lado deste evento para testá-lo.

Se o teste tiver sido executado, o separador <code className="action">Response</code> devolve um código 200. Se um código de erro for devolvido (geralmente 500 ou 400), isso significa que o webhook foi mal configurado. Volte para o formulário de adição de um webhook e verifique as informações, especificamente o URL do webhook fornecido pela OVHcloud.

#### Utilizar o webhook

Depois de configurar o webhook, o código do site será atualizado automaticamente sempre que ocorrerem alterações no repositório GitHub. Por exemplo, se um dos seus colegas efetuar alterações no repositório GitHub, o código do seu website será atualizado localmente (no seu alojamento OVHcloud).

### Conclusão

Acabou de associar o código do seu website com o Git, através do seu repositório GitHub. Agora pode implementar as modificações realizadas no repositório GitHub para o seu alojamento web ou implementá-las de forma automatizada graças ao webhook, consultar os logs das suas implementações e efetuar múltiplas ações, tudo a partir da consola OVHcloud, em apenas alguns cliques.
