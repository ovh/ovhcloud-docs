## Objetivo

Um conector de receção indica à sua plataforma Exchange quais os servidores autorizados a entregar-lhe e-mails e em que condições. Serve para colocar uma solução antispam externa, também chamada gateway de filtragem, à frente da sua plataforma Exchange: os <Tooltip term="mxRecord">registos MX</Tooltip> do seu nome de domínio apontam para esta gateway, que filtra os e-mails de entrada e, em seguida, os transmite ao Exchange.

O conector de receção está disponível para [Private Exchange](/links/web/emails-private-exchange) e [Trusted Exchange](/links/web/emails-trusted-exchange). Só pode ser criado e gerido com a API OVHcloud.

**Este guia explica como criar, modificar, desativar e eliminar um conector de receção na sua plataforma Exchange com a API OVHcloud.**

:::info
Para fazer passar os e-mails **de saída** da sua plataforma por um servidor externo, utilize antes um conector de envio: consulte o nosso guia "[Exchange - Configurar um conector de envio](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/feature-send-connector)".
:::

## Requisitos

- Dispor de uma plataforma [Private Exchange](/links/web/emails-private-exchange) ou [Trusted Exchange](/links/web/emails-trusted-exchange).
- Dispor de credenciais API geradas na <CreateToken rights="GET=/email/exchange&GET=/email/exchange/*&POST=/email/exchange/*&PUT=/email/exchange/*&PATCH=/email/exchange/*&DELETE=/email/exchange/*">página de criação de tokens OVHcloud</CreateToken>, com, no mínimo, o direito `GET` em `/email/exchange` e os direitos `GET`, `POST`, `PUT`, `PATCH` e `DELETE` em `/email/exchange/*`. Consulte o nosso guia "[Primeiros passos com as API OVHcloud](/guides/manage-and-operate/api/first-steps)".
- Conhecer os endereços IP dos servidores da sua solução antispam externa que vão entregar os e-mails ao Exchange. Peça-os ao prestador desta solução.

## Instruções

### Compreender o conector de receção predefinido

Cada plataforma Exchange dispõe de um conector de receção predefinido. Pertence ao Exchange: não o pode modificar nem eliminar, apenas ativar ou desativar. Na API, a sua propriedade `default` tem o valor `true`.

:::warning
**Não desative o conector de receção predefinido.** Se nenhum outro conector se aplicar, a sua desativação interrompe a receção de todos os e-mails da plataforma.
:::

### Encontrar os parâmetros de caminho

As chamadas do conector de receção precisam do nome da organização (`organizationName`) e do nome do serviço (`exchangeService`) da sua plataforma. Obtenha-os por ordem: a primeira chamada abaixo fornece a organização, necessária para a segunda.

**1. Organização** (`organizationName`)

Liste as organizações Exchange da sua conta com a chamada API abaixo:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange"} />

**2. Serviço** (`exchangeService`)

Liste os serviços Exchange da organização com a chamada API abaixo:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service"} />

### Criar um conector de receção

Crie o conector com a chamada API abaixo:

<Api version="v1" section="/email/exchange" method="POST" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector"} regions={["eu"]} />

Preencha os seguintes campos no corpo do pedido. Todos são obrigatórios.

| Campo | Tipo | Descrição |
|---|---|---|
| `name` | string | Nome do conector, 255 caracteres no máximo |
| `remoteIpRanges` | string[] | Endereços IP dos servidores autorizados a entregar e-mails através deste conector (ver abaixo) |
| `requireTls` | boolean | `true` para exigir TLS para todos os e-mails recebidos por este conector |
| `maxMessageSize` | long | Tamanho máximo de um e-mail recebido por este conector, em MB |
| `enabled` | boolean | `true` para ativar o conector logo após a sua criação |

Cada entrada de `remoteIpRanges` pode ser:

- um único endereço IP, por exemplo `203.0.113.10`;
- uma rede em notação CIDR, por exemplo `203.0.113.0/28`;
- um intervalo de endereços "início-fim", com ambos os limites incluídos, por exemplo `203.0.113.10-203.0.113.20`.

São aceites endereços IPv4 e IPv6.

:::warning
**Limites de `remoteIpRanges`**

- Um mesmo endereço IP não pode constar de dois conectores de receção da plataforma.
- A lista completa, depois de unidas as suas entradas por vírgulas, não pode exceder 255 caracteres. Prefira uma rede CIDR a uma longa lista de endereços individuais.

:::

A chamada devolve uma tarefa: o conector é criado quando esta tarefa estiver concluída.

### Listar e consultar os conectores de receção

Liste os conectores de receção da plataforma, incluindo o conector predefinido, com a chamada API abaixo:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector"} regions={["eu"]} />

A chamada devolve a lista dos identificadores (`id`) dos conectores. Consulte os detalhes de um conector com a chamada API abaixo:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

Além dos campos de criação, a resposta contém `id`, o identificador do conector, e `default`, que tem o valor `true` para o conector de receção predefinido.

### Modificar um conector de receção

Para modificar um ou vários campos sem alterar os restantes, utilize a chamada API abaixo:

<Api version="v1" section="/email/exchange" method="PATCH" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

Para substituir toda a configuração do conector, preencha todos os campos na chamada API abaixo:

<Api version="v1" section="/email/exchange" method="PUT" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

:::info
O campo `remoteIpRanges` substitui a lista registada na sua totalidade. Para adicionar um endereço IP, envie novamente a lista completa: os endereços existentes e o novo.
:::

Para ativar ou desativar um conector, modifique o seu campo `enabled`. No conector de receção predefinido, é o único campo que pode modificar: consulte o aviso da secção "[Compreender o conector de receção predefinido](#compreender-o-conector-de-receção-predefinido)".

Cada modificação devolve uma tarefa: é aplicada quando esta tarefa estiver concluída.

### Eliminar um conector de receção

Elimine um conector com a chamada API abaixo:

<Api version="v1" section="/email/exchange" method="DELETE" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

A chamada devolve uma tarefa: o conector é eliminado quando esta tarefa estiver concluída. Não pode eliminar o conector de receção predefinido.
