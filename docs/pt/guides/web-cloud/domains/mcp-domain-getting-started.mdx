:::info
O servidor MCP da OVHcloud encontra-se em desenvolvimento ativo. A lista de ferramentas disponíveis é enriquecida regularmente: uma funcionalidade hoje ausente pode estar disponível pouco tempo depois. Consulte o [hub MCP da OVHcloud](https://mcp.eu.ovhcloud.com/index.html) para conhecer o inventário atualizado.
:::

## Objetivo

O **Model Context Protocol** (MCP) é uma norma aberta que permite a um assistente de IA utilizar ferramentas externas. O servidor MCP da OVHcloud expõe os seus serviços OVHcloud sob a forma de ferramentas, para que um assistente possa consultar e alterar a sua configuração em seu nome.

Na prática, isto significa que deixa de ter de navegar pelas interfaces ou de escrever chamadas à API: basta pedir:

```text
Lista os meus nomes de domínio e diz-me quais expiram nos próximos 60 dias.
```

**Este guia explica como ligar um agente de IA ao servidor MCP da OVHcloud e utilizá-lo para gerir os seus nomes de domínio, os seus registos DNS e os seus reencaminhamentos.**

## Requisitos

- Ter acesso à <ManagerLink to="/">Área de Cliente OVHcloud</ManagerLink>
- Ter instalado um cliente MCP compatível (consulte [Ligar o seu agente](#3--ligar-o-seu-agente-ao-mcp))
- Dispor de um navegador para concluir a autenticação OAuth2

## Instruções

### 1 — Como funciona o MCP

Estão envolvidos três componentes:

| Componente | Função |
|------------|--------|
| **O seu agente de IA** | O assistente com quem fala (um agente de terminal, um chat integrado no IDE, a sua própria aplicação) |
| **O servidor MCP da OVHcloud** | Publica as *ferramentas* disponíveis e executa-as na sua conta |
| **A sua conta OVHcloud** | As permissões, verificadas em cada chamada, que determinam o que o agente pode fazer |

Nunca invoca uma ferramenta pelo nome. Descreve o que pretende, o agente seleciona a ferramenta adequada e pede-lhe confirmação antes de alterar seja o que for.

:::warning
Um agente de IA ligado ao MCP atua com as **suas** permissões. Leia cada pedido de confirmação antes de o aceitar, em especial nas operações que eliminam registos ou alteram os servidores DNS.
:::

### 2 — O hub MCP da OVHcloud

O [hub MCP da OVHcloud](https://mcp.eu.ovhcloud.com/index.html) reúne os serviços expostos sob a forma de ferramentas MCP e é a referência para saber o que está atualmente disponível.

Escolha o URL correspondente à região da sua conta OVHcloud:

| Região | URL do servidor MCP |
|--------|---------------------|
| Europa | `https://mcp.eu.ovhcloud.com/mcp/{section}` |
| Canadá | `https://mcp.ca.ovhcloud.com/mcp/{section}` |

Substitua `{section}` pelo nome da secção à qual pretende ligar-se, tal como aparece nos cartões do hub. Liga-se sempre a uma secção específica: não existe um URL global que exponha todas as ferramentas de uma só vez.

#### Secções para os nomes de domínio

Duas secções abrangem os nomes de domínio, uma por versão da API:

| Secção | Conteúdo exposto |
|--------|------------------|
| `v1_domain` | As ferramentas de domínio da API v1 |
| `v2_domain` | As ferramentas de domínio da API v2 |

O URL a utilizar é, portanto, `https://mcp.eu.ovhcloud.com/mcp/v1_domain` para uma conta europeia na API v1.

Atualmente, a API v1 continua a ser a mais completa em termos de funcionalidades: `v1_domain` expõe, por isso, um conjunto de ferramentas mais alargado do que `v2_domain`. A API v2 vai sendo enriquecida progressivamente.

Para compreender o que distingue a API v2 da API v1, consulte o guia [OVHcloud API v2 - Principles of operation](/guides/manage-and-operate/api/apiv2#as-code-design).

Pode adicionar uma, outra ou ambas em simultâneo. A `v1_domain` só por si é suficiente para realizar todas as operações deste guia.

### 3 — Ligar o seu agente ao MCP

A autenticação utiliza **OAuth2**: na primeira vez que o seu agente contacta o servidor, abre-se uma janela do navegador na página de autenticação da OVHcloud. Depois de iniciar sessão, o agente reutiliza essa sessão para as suas chamadas MCP.

:::info
Não é necessário qualquer cabeçalho HTTP personalizado: as credenciais são fornecidas pelo fluxo OAuth2. As instruções de configuração da OVHcloud indicam que deve deixar **vazia** a secção de cabeçalhos da configuração do seu cliente.
:::

<Tabs>
<Tab label="SHAI">

O [SHAI](https://github.com/ovh/shai) é o agente de terminal da OVHcloud. É necessária a versão **0.1.5 ou superior**.

Crie o seguinte ficheiro de configuração a partir do [modelo `.ovh.config`](https://github.com/ovh/shai/blob/main/.ovh.config) do repositório do SHAI:

```bash
$HOME/.config/shai/agents/ovh.config
```

Declare em `tools.mcp` uma entrada por cada secção que pretenda utilizar. Este exemplo ativa ambas as versões da API:

```json
{
  "name": "ovh",
  "description": "OVH agent with OVH MCP server for cloud management and API calls",
  "tools": {
    "builtin": ["*"],
    "builtin_excluded": [],
    "mcp": {
      "v1_domain": {
        "config": {
          "type": "http",
          "url": "https://mcp.eu.ovhcloud.com/mcp/v1_domain"
        },
        "enabled_tools": ["*"]
      },
      "v2_domain": {
        "config": {
          "type": "http",
          "url": "https://mcp.eu.ovhcloud.com/mcp/v2_domain"
        },
        "enabled_tools": ["*"]
      }
    }
  },
  "system_prompt": "{{CODER_BASE_PROMPT}}",
  "max_tokens": 4096,
  "temperature": 0.3
}
```

Substitua os pontos de acesso pelos da sua região.

:::info
Não adicione manualmente qualquer credencial a este ficheiro. Depois de iniciar sessão, é o próprio SHAI que escreve um `access_token` e um `expires_at` no bloco `config` de cada servidor. Estes valores são segredos pessoais: nunca coloque este ficheiro num repositório nem o partilhe tal como está.
:::

Inicie em seguida o agente. O seu navegador abre-se na página de autenticação da OVHcloud; inicie sessão para concluir a ligação.

</Tab>
<Tab label="Goose">

A via mais rápida é o [hub MCP da OVHcloud](https://mcp.eu.ovhcloud.com/index.html): localize o cartão **V1 Domain** (ou **V2 Domain**) e clique no botão **Add in Goose**. O Goose abre-se com a extensão já preenchida — nome, ponto de acesso e transporte — bastando confirmar.

O botão utiliza o ponto de acesso do hub que está a consultar. A partir do hub europeu, configura portanto a extensão em `https://mcp.eu.ovhcloud.com`: para uma conta no Canadá, abra o hub da sua região ou siga a configuração manual abaixo.

**Configuração manual.** No Goose, adicione uma nova extensão do tipo **HTTP** e indique:

- **URL**: o URL da sua região com a secção pretendida, `https://mcp.eu.ovhcloud.com/mcp/v1_domain` ou `https://mcp.eu.ovhcloud.com/mcp/v2_domain`
- **Headers**: deixe vazio

Guarde a extensão. O Goose abre o seu navegador para a autenticação na OVHcloud.

Para utilizar ambas as versões da API, crie uma segunda extensão com a outra secção.

</Tab>
<Tab label="Claude Code">

Adicione um servidor por secção, com o URL da sua região:

```bash
claude mcp add --transport http v1_domain https://mcp.eu.ovhcloud.com/mcp/v1_domain
claude mcp add --transport http v2_domain https://mcp.eu.ovhcloud.com/mcp/v2_domain
```

O primeiro comando, por si só, abrange todas as operações deste guia. Acrescente `--scope user` para que um servidor fique disponível em todos os seus projetos e não apenas no atual. Não utilize qualquer opção `--header`.

Em seguida, a partir do Claude Code, inicie a autenticação OAuth2:

```text
/mcp
```

Inicie sessão na OVHcloud na janela do navegador que se abre. O comando `claude mcp list` mostra depois `✔ Connected` junto a cada servidor adicionado.

</Tab>
</Tabs>

Para confirmar que a ligação funciona, coloque uma pergunta apenas de leitura ao seu agente:

```text
Lista os meus nomes de domínio OVHcloud.
```

### 4 — Consultar as informações de um nome de domínio

Comece por pedir a lista dos seus domínios e peça depois os detalhes de um deles.

Exemplo de pedido:

```text
Mostra-me os detalhes de mydomain.ovh: data de expiração, servidores DNS e estado do bloqueio de transferência.
```

### 5 — Encomendar um nome de domínio

A encomenda de um nome de domínio efetua-se com a ferramenta `order-new-domain-name`, disponível na secção `v1_domain`.

Exemplo de pedido:

```text
Encomenda mydomain.ovh por um ano.
```

Antes de comprar seja o que for, peça uma **simulação**. A ferramenta aceita um parâmetro `dryRun`: definido como `true`, verifica a disponibilidade do nome e calcula o preço **sem contratar nem faturar nada**.

```text
Simula a encomenda de mydomain.ovh por um ano.
```

O seu agente apresenta então o orçamento — preço, duração e configuração que será aplicada ao domínio — e aguarda a sua aprovação antes de prosseguir.

Assim que validar o orçamento, o agente repete a chamada com `dryRun` a `false`. A encomenda passa a ser definitiva: a API devolve o **URL da nota de encomenda**. O seu agente transmite-lhe esse URL diretamente na sua resposta: abra-o no seu navegador para pagar a encomenda. Encontrará igualmente esta nota de encomenda na sua Área de Cliente OVHcloud, na secção <ManagerLink to="/#/billing/orders">Encomendas</ManagerLink>.

:::info
A nota de encomenda deve ser **paga** para que o pedido de registo seja transmitido ao registo da extensão. O seu agente não pode pagar em seu lugar: siga o URL da nota de encomenda que este lhe devolveu para efetuar o pagamento. Enquanto o pagamento não for efetuado, o nome de domínio permanece disponível para terceiros.
:::

:::warning
Validar a encomenda gera uma nota de encomenda real e faturável na sua conta OVHcloud. Leia o pedido de confirmação do seu agente antes de o aceitar e verifique o nome de domínio e a duração: um registo não se anula como uma alteração de configuração.
:::

### 6 — Modificar um registo DNS

Ferramentas associadas: `create-domain-zone-record` para adicionar um registo, `delete-domain-zone-record` para eliminar um e `get-domain-zone-details` para consultar a zona.

Exemplos de pedidos:

```text
Altera o registo A de www.mydomain.ovh para 203.0.113.42.
```

Não precisa de saber que tipo de registo deve ser alterado. Descreva o resultado que espera: o seu agente identifica o registo em causa, explica-lhe o que vai alterar e aguarda a sua aprovação antes de aplicar a alteração.

```text
O meu site está agora alojado num servidor cujo endereço IP é 203.0.113.42.
Faz com que www.mydomain.ovh aponte para ele.
```

:::warning
Um registo DNS modificado só fica ativo após a atualização da zona. Se omitir esta etapa, a sua alteração fica registada, mas nunca é aplicada. Peça explicitamente ao seu agente para atualizar a zona ou verifique se o fez.
:::

A propagação na Internet pode depois demorar até 24 horas, consoante o TTL do registo.

### 7 — Criar um reencaminhamento

Um reencaminhamento envia os visitantes do seu domínio para outro endereço.

Exemplo de pedido:

```text
Reencaminha blog.mydomain.ovh para https://mydomain.ovh/noticias, mantendo o endereço visível no navegador.
```

### 8 — As outras operações abrangidas

As secções `v1_domain` e `v2_domain` expõem as rotas correspondentes da API da OVHcloud sob a forma de ferramentas: **qualquer operação que possa realizar nos seus nomes de domínio através da API está igualmente disponível através do MCP**. Para além das tarefas acima, isto abrange, por exemplo:

- DNSSEC: ativação, desativação e gestão dos registos DS
- Proteção de transferência: bloqueio e desbloqueio
- Gestão dos contactos: proprietário, administrador, técnico e de faturação
- Servidores DNS e registos glue
- Identificadores e registos DynHost (DNS dinâmico)
- Cópia de segurança, reposição, importação e exportação da zona
- Gestão das tarefas: aceleração, cancelamento, relançamento
- Obtenção do código AuthInfo e aprovação das transferências de saída

Se não tiver a certeza de que uma operação é possível, peça ao seu agente que lhe explique o que é capaz de fazer com os seus nomes de domínio.
