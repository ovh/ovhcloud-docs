## Objetivo

O serviço NAS-HA da OVHcloud permite-lhe gerir ficheiros acessíveis a partir de uma rede.

**Este guia dá-lhe uma ideia da utilização do seu serviço NAS-HA através da API OVHcloud.**

## Requisitos

- Um serviço [NAS-HA OVHcloud](https://www.ovhcloud.com/pt/storage-solutions/nas-ha/)
- Consulte o nosso guia dos [primeiros passos com a API OVHcloud](/guides/manage-and-operate/api/first-steps) para se familiarizar com a APIv6 OVHcloud

## Instruções

Todas as rotas API deste guia estão disponíveis na <ApiLink section="/dedicated/nasha">secção */dedicated/nasha*</ApiLink> da consola API.

:::info
Ao utilizar a API, todos os campos assinalados com um asterisco (\*) são obrigatórios.
:::


### Obter informações sobre o seu serviço

Todos os seus serviços ativos podem ser recuperados utilizando a seguinte rota:

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha"} />


### Criação de uma partição

Utilize a seguinte rota para criar uma nova partição:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Nome interno do seu serviço NAS |
| `partitionDescription` |  | Descrição facultativa |
| `partitionName` | Yes | Um nome para a partição |
| `protocol` | Yes | *NFS*, *CIFS* ou *NFS_CIFS* para ambos |
| `size` | Yes | O tamanho da partição |

Escolha `NFS` como protocolo e um tamanho de `10` Gigabytes, por exemplo.

### Adicionar uma entrada ACL para aceder à partição

:::warning
O acesso é recusado por predefinição, exceto se for concedido através do ACL. Apenas os endereços IP ligados aos seus serviços OVHcloud podem ser adicionados.
:::


Pode verificar os endereços IP elegíveis para um acesso através das chamadas API seguintes:

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/authorizableBlocks"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Nome interno do seu serviço NAS |
| `partitionName` | Yes | Nome da partição |

Para criar uma nova entrada ACL que lhe permita ligar-se à sua partição, utilize a seguinte rota:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/access"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Nome interno do serviço NAS-HA |
| `partitionName` | Yes | Nome da partição |
| `ip` | Yes | O endereço IP ou a gama de acesso |
| `type` | Yes | Tipo de acesso ACL para esta entrada: *readonly* ou *readwrite* |

:::info
Utilize a notação CIDR para as gamas IP, por exemplo: 192.0.2.0/24.
:::


### Criar uma snapshot manual

Para adicionar uma snapshot manual, utilize a seguinte rota:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/customSnapshot"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Nome interno do serviço NAS-HA |
| `partitionName` | Yes | Nome da partição |
| `expiration` |  | Uma data de expiração facultativa, por exemplo: 2022-06-24 (ISO 8601) |
| `name` | Yes | Nome da snapshot |

### Eliminação de uma partição

Utilize a seguinte rota para eliminar uma partição:

<Api version="v1" section="/dedicated/nasha" method="DELETE" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Nome interno do serviço NAS-HA |
| `partitionName` | Yes | Nome da partição |
