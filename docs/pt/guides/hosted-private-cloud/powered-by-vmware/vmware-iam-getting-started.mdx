## Instruções

:::info
Atualmente, não é possível beneficiar das funcionalidades IAM nas ofertas Hosted Private Cloud VMware vSphere com certificação PCI-DSS ou HDS, nem nas soluções qualificadas SecNumCloud.
O mesmo se aplica aos ambientes geridos com o NSX ativado e ao Public VCF as-a-Service. As equipas da OVHcloud estão a trabalhar na adaptação destas tecnologias.

:::


### Como funcionam o IAM e o Hosted Private Cloud - VMware on OVHcloud?

A ativação do OVHcloud IAM delega a gestão do acesso ao serviço, das funções associadas e das respetivas permissões no vSphere. Pode gerir os acessos e as políticas a partir da secção IAM da consola OVHcloud.

Para simplificar:

- Uma função IAM substitui um utilizador local do vSphere no Hosted Private Cloud - VMware on OVHcloud.
- Uma política permite associar a sua identidade OVHcloud a esta função.
- As funções IAM funcionam através dos grupos do VMware vSphere.

Eis os elementos necessários para o bom funcionamento do IAM com o Hosted Private Cloud - VMware on OVHcloud:

- Produtos: **vSphere/VMware (Hosted Private Cloud, service pack)**.
- Recursos: **PCC-XXX**.
- Ações: **Geridas ou manuais**.
- Utilizadores: **Utilizador 1/2/3**.

## FAQ

### Quais são as limitações do IAM com o Hosted Private Cloud - VMware on OVHcloud?

:::info
Até à data, uma função IAM do vSphere não pode ser gerida através dos grupos de permissões geridas.

:::


O IAM encontra-se atualmente numa versão BETA na plataforma OVHcloud. As infraestruturas com opções de segurança reforçada ou com um serviço certificado (alojamento de dados de saúde (HDS), alojamento de dados bancários (PCI-DSS) ou SecNumCloud (SNC)) não podem atualmente utilizar o OVHcloud IAM.

Uma função IAM só pode ser adicionada através de ações manuais numa política global (ação: assumerole -> role_iam). Para mais informações, consulte o guia "[IAM para VMware on OVHcloud - Como associar uma função vSphere a uma política IAM](/guides/hosted-private-cloud/powered-by-vmware/vmware-iam-role-policy)".

### Como posso aceder à delegação de permissões do vSphere com o IAM?

As **identidades associadas**, os **recursos**, os **grupos de recursos** e as respetivas permissões nas políticas são geridos a partir da consola OVHcloud.

Na secção <code className="action">Gestão de identidades e acessos</code> do menu lateral, clique em <ManagerLink to="/beta/#/iam/identities/users">Identidades</ManagerLink> ou <ManagerLink to="/beta/#/iam/policies/my-policies">Políticas</ManagerLink>.

Pode gerir as funções IAM e os utilizadores locais do vSphere a partir da entrada <code className="action">Managed VMware vSphere</code>, em **Produtos** no menu lateral.

Selecione a sua infraestrutura e aceda ao separador <code className="action">Utilizadores</code>.

### Quantas funções estão disponíveis por predefinição?

Ao ativar o IAM no seu Hosted Private Cloud - VMware on OVHcloud, dispõe de 2 funções predefinidas ativas.

### O que é uma função IAM do vSphere associada a uma política?

Cada função IAM do seu Hosted Private Cloud - VMware on OVHcloud corresponde a uma ação escrita no formato `pccVMware:vSphere:assumeRole?role_name` numa política IAM.

Por exemplo, para a função **iam-admin** de um Dedicated Cloud, a ação é: `pccVMware:vSphere:assumeRole?iam-admin.`.

Uma função pode ser considerada um modelo de utilizador com o qual define permissões PCC (vSphere) e aplica estas permissões (esta função) a um utilizador na sua consola OVHcloud (IAM, se tiver associado o seu utilizador a uma política).
