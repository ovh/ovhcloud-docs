## Objetivo

A atualização do sistema operativo (SO) do seu servidor é essencial para manter a segurança, a estabilidade e o desempenho dos seus serviços. Para saber se a sua versão de SO está a chegar ao fim do suporte (*End of Support* / *End of Life*), consulte o nosso [guia sobre o ciclo de vida das imagens](/guides/public-cloud/compute/image-life-cycle).

Existem duas abordagens possíveis:

1. **A atualização no local (*In-Place Upgrade*)**: o método mais rápido e mais económico. Atualiza o sistema diretamente na sua máquina existente, sem alterar o endereço IP nem transferir os seus ficheiros.
2. **A migração lado a lado (*Side-by-Side*)**: ideal se pretender recomeçar num ambiente totalmente novo ou testar a migração em paralelo, sem afetar a sua produção.

**Este guia explica-lhe como atualizar o SO do seu VPS OVHcloud.**

## Requisitos

- Dispor de um [VPS](/links/bare-metal/vps) na sua conta OVHcloud
- Dispor de acesso SSH root (ou sudo) ao seu VPS
- Ter criado um snapshot (ou dispor de um backup diário) antes de qualquer manipulação

## Instruções

### Etapa prévia obrigatória: proteja o seu VPS com um snapshot

Independentemente do método escolhido, proteja os seus dados antes de qualquer manipulação.

#### 1. O backup automático diário (VPS posteriores a agosto de 2025)

Se dispuser de um VPS da gama comercializada desde **7 de agosto de 2025**, o seu servidor beneficia de um backup automático diário do sistema (excluindo os discos adicionais). Este backup é conservado durante **24 horas**. Em caso de imprevisto grave, pode restaurar a imagem automática mais recente diretamente a partir da sua Área de Cliente OVHcloud.

#### 2. O snapshot manual (estado exato num dado momento)

Para capturar o estado do seu servidor imediatamente antes da atualização, crie um **snapshot** a partir da sua Área de Cliente OVHcloud, conforme descrito no guia [Utilizar snapshots num alojamento VPS](/guides/bare-metal-cloud/virtual-private-servers/using-snapshots-on-a-vps).

O snapshot é uma **opção paga** e apenas pode estar ativo um snapshot de cada vez num VPS. Regista o estado da máquina num momento preciso: dados aplicacionais, ficheiros, configurações do sistema e estado do SO (kernel, pacotes, dependências). Não constitui, no entanto, uma cópia de segurança completa do sistema. A coerência do snapshot depende do *qemu-guest-agent*, que não está instalado por predefinição na maioria das distribuições: verifique se está presente no seu VPS antes de iniciar a atualização.

:::info
**A sua rede de segurança** — Se ocorrer uma interrupção durante a atualização (falha de rede, conflito de pacotes, incoerência aplicacional), clique em <code className="action">Restaurar snapshot</code> (ou aplique o seu último backup diário) na Área de Cliente OVHcloud para repor o seu VPS no estado original. A restauração **elimina** o snapshot: para conservar um, crie um novo antes de efetuar qualquer outra alteração.
:::

### Método 1: a atualização no local (*In-Place Upgrade*)

Esta é a solução recomendada na maioria dos casos. É efetuada diretamente no seu servidor atual.

:::warning
**Aviso importante — Servidores com Plesk ou cPanel**

Se o seu VPS utilizar um painel de gestão **Plesk** ou **cPanel**, não siga os procedimentos de atualização direta indicados abaixo. Sem os utilitários dedicados dos editores, as ferramentas genéricas (Leapp, `dist-upgrade`) podem corromper a sua instalação e as suas licenças.

- Para o **Plesk** (passagem de CentOS 7 para AlmaLinux 8): utilize o script oficial `centos2alma` fornecido pela Plesk.
- Para o **cPanel** (passagem de CentOS 7 para AlmaLinux 8): utilize a ferramenta oficial **Elevate** fornecida pela cPanel.

Estas ferramentas destinam-se a utilizadores experientes, não são garantidas a 100 % e exigem uma cópia de segurança completa antes de prosseguir.

Para conhecer todas as opções de migração (incluindo as ferramentas automáticas de servidor para servidor), consulte o guia [Fim do suporte Plesk e cPanel para VPS - Assegurar a continuidade dos seus serviços](/guides/bare-metal-cloud/virtual-private-servers/eos-cpanel-plesk).

:::

#### Opção A: distribuições Debian e Ubuntu

##### 1. Criar o snapshot

Abra <ManagerLink to="/#/dedicated/vps">VPS management</ManagerLink>, selecione o seu VPS e, em seguida, no separador <code className="action">Página Inicial</code>, desça até à caixa "Backup" e utilize o menu <code className="action">...</code> da opção "Snapshot".

##### 2. Atualizar o sistema atual

Ligue-se ao seu VPS através de SSH e aplique todas as correções disponíveis para a sua versão atual:

```bash
sudo apt update
sudo apt upgrade
sudo apt full-upgrade
```

Analise os pacotes que deixaram de ser necessários antes de os eliminar:

```bash
sudo apt --purge autoremove
```

Se tiver sido instalado um novo kernel Linux, reinicie o VPS:

```bash
sudo reboot
```

##### 3. Iniciar a atualização de versão principal

<Tabs>
<Tab label="Ubuntu">

Execute a ferramenta oficial da Canonical:

```bash
sudo do-release-upgrade
```

Siga as instruções apresentadas no ecrã.

</Tab>
<Tab label="Debian">

Exemplo: passagem de Debian 11 "Bullseye" para Debian 12 "Bookworm".

1. Faça um backup das suas fontes APT atuais:

```bash
sudo cp -v /etc/apt/sources.list /root/
sudo cp -rv /etc/apt/sources.list.d/ /root/
```

2. Edite o ficheiro `/etc/apt/sources.list` e substitua todas as ocorrências do nome da versão antiga pelo nome da nova. No caso do Debian 12, verifique também a presença do componente `non-free-firmware` se a sua configuração o utilizar:

```bash
sudo nano /etc/apt/sources.list
```

3. Verifique os ficheiros de `/etc/apt/sources.list.d/` e atualize ou desative temporariamente os repositórios de terceiros que ainda não disponibilizam pacotes para a nova versão pretendida.

4. Atualize o índice e, em seguida, execute a atualização em **2 fases**, sem acrescentar automaticamente `-y`:

```bash
sudo apt update
sudo apt upgrade
sudo apt full-upgrade
```

</Tab>
</Tabs>

:::warning
**Pontos a ter em atenção durante a instalação**

- **Ecrã de informação** (`apt-listchanges`): se surgirem dois pontos (`:`) na parte inferior do ecrã, prima `q` para fechar o aviso e retomar a atualização.
- **Ficheiros de configuração modificados**: se o sistema propuser substituir um ficheiro de configuração existente, dê preferência à versão do mantenedor e verifique depois os eventuais ficheiros `.dpkg-old` ou `.dpkg-dist` antes de repor as suas personalizações.

:::

##### 4. Reinício e verificação

Assim que o processo estiver concluído, reinicie o seu servidor:

```bash
sudo reboot
```

Verifique o SO ativo através de `cat /etc/os-release`. Se os seus serviços web e aplicações funcionarem corretamente, pode eliminar o snapshot a partir da Área de Cliente OVHcloud.

#### Opção B: distribuições AlmaLinux, Rocky Linux e CentOS Stream

No caso dos SO da família Red Hat, a transição para a versão 9 utiliza a framework ELevate / Leapp.

##### 1. Criar o snapshot

Crie o snapshot a partir de <ManagerLink to="/#/dedicated/vps">VPS management</ManagerLink> e aguarde o fim da operação antes de prosseguir.

##### 2. Atualizar os pacotes existentes

```bash
sudo dnf update -y
sudo reboot
```

##### 3. Instalar a ferramenta de migração ELevate

Instale o repositório ELevate e selecione depois o pacote de dados da sua distribuição. No caso do **RHEL**, consulte a documentação oficial da Red Hat — [atualização com o Leapp](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/8/html/upgrading_from_rhel_7_to_rhel_8/) ou [migração de RHEL 8 para RHEL 9](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/9/html/upgrading_from_rhel_8_to_rhel_9/) — em vez de um pacote de dados ELevate.

```bash
# Instalação do repositório ELevate e da ferramenta Leapp
sudo dnf install -y https://repo.almalinux.org/elevate/elevate-release-latest-el8.noarch.rpm
sudo yum install -y leapp-upgrade

# Instalação do pacote de dados consoante o seu SO (execute APENAS a linha correspondente):
sudo yum install -y leapp-data-almalinux    # Para AlmaLinux
sudo yum install -y leapp-data-rocky        # Para Rocky Linux
sudo yum install -y leapp-data-centos       # Para uma atualização para CentOS Stream
```

##### 4. Validar a elegibilidade e iniciar a atualização

Antes da atualização, gere a análise inicial, leia o relatório do Leapp, responda às questões bloqueantes e inicie depois a migração:

```bash
# Executar a pré-verificação do sistema
sudo leapp preupgrade

# Ler o relatório detalhado antes de continuar
sudo less /var/log/leapp/leapp-report.txt

# Responder explicitamente às questões bloqueantes identificadas no relatório
sudo leapp answer --section remove_pam_pkcs11_module_check.confirm=True

# Iniciar a atualização para a versão 9
sudo leapp upgrade
```

Em caso de erro bloqueante durante a pré-verificação, corrija primeiro os pontos assinalados em `/var/log/leapp/leapp-report.txt`. No caso do **RHEL**, consulte a documentação oficial da Red Hat sobre as migrações de versão principal com o Leapp.

##### 5. Comutação e finalização

Reinicie o seu servidor para executar a comutação do kernel para a versão 9:

```bash
sudo reboot
```

O primeiro reinício pode demorar vários minutos (instalação dos pacotes em segundo plano e reetiquetagem SELinux).

Assim que o sistema estiver novamente acessível, verifique a versão e limpe os pacotes de migração:

```bash
# Verificar a versão instalada
cat /etc/os-release

# Eliminar as ferramentas de migração e limpar a cache
sudo dnf remove -y leapp-upgrade 'leapp-data-*'
sudo dnf autoremove -y
```

### Método 2: a migração lado a lado (*Side-by-Side*)

Este método consiste em implementar um segundo VPS OVHcloud novo, instalar nele os seus serviços e comutar depois os seus dados e o seu tráfego de rede sem risco de uma interrupção prolongada.

#### 1. Encomendar e preparar o novo VPS

A partir do site da OVHcloud ou da sua Área de Cliente OVHcloud, encomende um novo VPS com a versão de SO pretendida.

Assim que o VPS estiver entregue, ligue-se e instale os seus serviços (servidor web, motor de base de dados, Docker, etc.).

#### 2. Transferir os seus dados e configurações

- **Bases de dados**: execute um dump a partir do VPS de origem (`mysqldump` ou `pg_dump`) e importe depois o ficheiro `.sql` para o novo VPS.
- **Ficheiros de utilizador / web**: sincronize os seus diretórios (por exemplo, `/var/www/` ou `/home/`) de servidor para servidor através do `rsync`:

```bash
rsync -avz -e ssh /var/www/ root@IP_DO_NOVO_VPS:/var/www/
```

- **Painéis de gestão (por exemplo, Plesk, cPanel)**: se o seu VPS utilizar um painel de gestão, recorra à respetiva ferramenta de migração integrada (Plesk Migrator / cPanel Transfer Tool) para automatizar a transferência das contas e das bases de dados, ou siga o guia [Fim do suporte Plesk e cPanel para VPS - Assegurar a continuidade dos seus serviços](/guides/bare-metal-cloud/virtual-private-servers/eos-cpanel-plesk).

#### 3. Testar o novo ambiente

Antes de comutar os seus utilizadores, verifique se o seu site ou aplicação funciona no novo IP (por exemplo, adaptando temporariamente o seu ficheiro `hosts` local).

#### 4. Comutar o tráfego para o novo VPS

- **Se utilizar uma Additional IP**: na sua Área de Cliente OVHcloud, abra <ManagerLink to="/#/network/ip">Public IP</ManagerLink> (<code className="action">Network</code> > <code className="action">Public IPs</code>) e comute depois a Additional IP do VPS antigo para o novo VPS. Alguns produtos exigem que o IP passe primeiro por um **Parking IP**, apenas um bloco /32 pode ser migrado para um VPS e os MAC virtuais são temporariamente suspensos durante a operação. Consulte o guia [Migrar um Additional IP](/guides/bare-metal-cloud/dedicated-servers/move-failover-ip) para as condições detalhadas.
- **Se utilizar os DNS padrão**: modifique os registos DNS (`A` / `AAAA`) do seu nome de domínio para que apontem para o novo endereço IP do seu novo VPS.

#### 5. Rescindir o servidor antigo

Assim que a comutação estiver validada e os prazos de propagação DNS tiverem decorrido (recomendam-se 24 a 48 horas), pode rescindir o VPS antigo a partir da sua Área de Cliente OVHcloud.

### Em caso de incidente durante o procedimento

Se o seu VPS deixar de responder na rede ou de arrancar após uma atualização no local:

1. Abra <ManagerLink to="/#/dedicated/vps">VPS management</ManagerLink> e selecione depois o VPS em causa.
2. Na caixa "Backup", utilize o menu <code className="action">...</code> da opção "Snapshot" ou aplique o seu backup automático mais recente.
3. Clique em <code className="action">Restaurar snapshot</code> ou inicie a restauração do backup pretendido.

O seu VPS regressa ao estado original em poucos minutos.
