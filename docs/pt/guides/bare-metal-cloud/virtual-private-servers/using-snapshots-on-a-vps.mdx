## Objetivo

Criar um snapshot é uma forma simples e rápida de garantir o funcionamento de um sistema antes de proceder a alterações que podem ter consequências indesejadas e imprevisíveis como, por exemplo, testar uma nova configuração ou software. Não constitui, no entanto, uma estratégia completa de backup do sistema.

**Saiba como ativar e utilizar a opção snapshot a partir da consola OVHcloud.**

:::info
Antes de aplicar as opções de backup, recomendamos que consulte as [páginas e perguntas frequentes do produto](/links/bare-metal/vps-options) para obter uma comparação de preços e outras informações.

:::


## Requisitos

- um [serviço VPS](/links/bare-metal/vps) OVHcloud já instalado

:::warning
Esta funcionalidade está atualmente indisponível para os servidores privados virtuais nas [Local Zones](/links/bare-metal/vps-lz).

:::

## Instruções

### Passo 1: Subscrever a opção snapshot

No separador <code className="action">Visão geral</code>, desça até à secção **Backup**.  
Se a linha **Snapshot** indicar "Ativado", passe diretamente para a etapa 2. Se indicar "Desativado", clique no link <code className="action">Encomendar um snapshot</code> por baixo da linha **Snapshot**.

<img className="thumbnail" alt="Secção Backup de um VPS na consola OVHcloud, com o link Encomendar um snapshot" src="/images/bare-metal-cloud/virtual-private-servers/using-snapshots-on-a-vps/console/snapshot_vps_step1b.png" loading="lazy" />

No painel que se abre, tome nota da informação relativa ao preço e depois clique em <code className="action">Encomendar</code>. Será então guiado através do processo de encomenda que será confirmado com o envio de um e-mail.

Para rescindir a opção, clique no link <code className="action">Rescindir</code> por baixo da linha **Snapshot** e, em seguida, clique em <code className="action">Confirmar</code> na janela **Rescindir a opção Snapshot**.

:::warning
A rescisão produz efeito na data de renovação da opção e não pode ser anulada.
:::

<img className="thumbnail" alt="Linha Snapshot de um VPS na consola OVHcloud, com o link Rescindir" src="/images/bare-metal-cloud/virtual-private-servers/using-snapshots-on-a-vps/console/snapshot_vps_cancel.png" loading="lazy" />

### Passo 2: Obter um snapshot

Uma vez ativada a opção, clique no link <code className="action">Efetuar um Snapshot</code> por baixo da linha **Snapshot**. Na janela **Efetuar um Snapshot**, pode introduzir uma descrição que será associada ao seu snapshot e, em seguida, clique em <code className="action">Confirmar</code>.

:::warning
O seu VPS não fica acessível durante a criação do snapshot e qualquer snapshot anterior será perdido.
:::

A duração da criação do snapshot depende do espaço de armazenamento utilizado. Em seguida, atualize a página para ver a data de criação na linha **Snapshot** da secção **Backup**.

### Passo 3: Apagar/restaurar um snapshot

Uma vez que apenas é permitido ter um snapshot ativado de cada vez, o snapshot existente terá de ser eliminado antes de criar um novo. Basta clicar no link <code className="action">Eliminar Snapshot</code> por baixo da linha **Snapshot** e, em seguida, em <code className="action">Eliminar Snapshot</code> na janela que aparece para confirmar.

<img className="thumbnail" alt="Linha Snapshot de um VPS na consola OVHcloud, com os respetivos links de snapshot" src="/images/bare-metal-cloud/virtual-private-servers/using-snapshots-on-a-vps/console/snapshot_vps_step2.png" loading="lazy" />

Se tem a certeza de que pretende restaurar o seu VPS para o estado do snapshot, clique em <code className="action">Restaurar Snapshot</code> e confirme o restauro na janela que aparece.

:::warning
O restauro do snapshot apaga a versão atual do seu VPS e repõe-no no estado do snapshot. Esta ação é irreversível.
:::

:::danger
Tenha em atenção que quando restaurar um VPS a partir de um instantâneo, este será eliminado. Se deseja conservar a mesma imagem, deve tomar uma nova antes de efetuar modificações no sistema restaurado.

Se a função snapshot é demasiado limitada para o seu projeto, a opção [Backups automatizados](/guides/bare-metal-cloud/virtual-private-servers/using-automated-backups-on-a-vps) é uma alternativa.

:::


### Descarregar uma snapshot

O snapshot em curso pode ser recuperado através de um link de download. Clique no link <code className="action">Fazer download do Snapshot</code> por baixo da linha **Snapshot**.

<img className="thumbnail" alt="Secção Backup de um VPS na consola OVHcloud, com o link Fazer download do Snapshot" src="/images/bare-metal-cloud/virtual-private-servers/using-snapshots-on-a-vps/console/snapshot_vps03.png" loading="lazy" />

:::info
Se o seu VPS é de uma gama antiga, é possível que receba uma mensagem de erro, pois a opção não está disponível nos VPS antigos. O seu VPS é de uma gama antiga se o seu modelo de atribuição for semelhante a: *vpsXXXX.ovh.net* (em que *X* representa um número). Pode verificar esta referência de servidor no cabeçalho da página do seu VPS na <ManagerLink to="/">consola OVHcloud</ManagerLink>.

:::


No painel **Fazer download do Snapshot**, clique em <code className="action">Gerar o link de download</code>.

<img className="thumbnail" alt="Painel Fazer download do Snapshot na consola OVHcloud, com o botão Gerar o link de download" src="/images/bare-metal-cloud/virtual-private-servers/using-snapshots-on-a-vps/console/snapshot_vps04.png" loading="lazy" />

Depois de alguns segundos, surge uma mensagem de sucesso. Abaixo, pode copiar o comando completo de download num clique e, em seguida, executá-lo no seu terminal.

<img className="thumbnail" alt="Painel Fazer download do Snapshot na consola OVHcloud com o comando de download gerado" src="/images/bare-metal-cloud/virtual-private-servers/using-snapshots-on-a-vps/console/snapshot_vps05.png" loading="lazy" />

O tamanho do snapshot também é apresentado na secção **Informações**.

Note que o link de download expirará após **24 horas**.

O comando de download utiliza um `curl` no seguinte formato:

```bash
curl "https://storage.sbg.cloud.ovh.net/v1/AUTH_f5fgh4674dd706f15f6ffgf4z667d3f4g5f05/glance/5ceg3f93-8b49-436b-aefe-4185f9fc3f78?
temp_url_sig=f508cacda60256d5f211ddddf3f81130e935f0e4&temp_url_expires=1678247579" --output vps-x11x11xyy.vps.ovh.net --fail
```

Este comando deve funcionar a partir de qualquer terminal de linha de comando. No entanto, quando utilizar o Windows *PowerShell*, deverá ajustar o comando da seguinte forma:

```powershell
curl -Uri "https://storage.sbg.cloud.ovh.net/v1/AUTH_f5fgh4674dd706f15f6ffgf4z667d3f4g5f05/glance/5ceg3f93-8b49-436b-aefe-4185f9fc3f78?
temp_url_sig=f508cacda60256d5f211ddddf3f81130e935f0e4&temp_url_expires=1678247579" -OutFile vps-x11x11xyy.vps.ovh.net
```

<img className="thumbnail" alt="snapshotvps" src="/images/bare-metal-cloud/virtual-private-servers/using-snapshots-on-a-vps/snapshot_vps06.png" loading="lazy" />

:::info
Para evitar o consumo de espaço de armazenamento excessivo, desaconselhamos o download das snapshots diretamente para o VPS.

O ficheiro descarregado pode ser importado para um Projeto Public Cloud enquanto imagem (QCOW2) via [OpenStack](/guides/public-cloud/compute/overview). (Consulte um exemplo de utilização em [este manual](/guides/public-cloud/compute/upload-own-image).)

:::


### Boas práticas para a criação de uma snapshot

#### Configuração do agente QEMU num VPS

As snapshots são imagens instantâneas do seu sistema em execução (“live snapshots”). Para garantir a disponibilidade do seu sistema aquando da criação da snapshot, o agente QEMU é utilizado para preparar o sistema de ficheiros ao processo.

O *qemu-guest-agent* necessário não está instalado por predefinição na maioria das distribuições. Além disso, as restrições de licença podem impedir a OVHcloud de o incluir nas imagens de SO disponíveis. Por conseguinte, recomenda-se que verifique e instale o agente caso não esteja ativo no seu VPS. Ligue-se ao seu VPS em SSH e siga as instruções abaixo, em função do seu sistema operativo.

##### **Distribuições Debian (Debian, Ubuntu)**

Utilize o seguinte comando para verificar se o sistema está corretamente configurado para as snapshots:

```bash
file /dev/virtio-ports/org.qemu.guest_agent.0
/dev/virtio-ports/org.qemu.guest_agent.0: symbolic link to ../vport2p1
```

Se o resultado for diferente (“No such file or directory”), instale a última versão do pacote:

```bash
sudo apt-get update
sudo apt-get install qemu-guest-agent
```

Inicie o serviço para garantir que está a ser executado:

```bash
sudo service qemu-guest-agent start
```

##### **Distribuições Redhat (CentOS, Fedora)**

Utilize o seguinte comando para verificar se o sistema está corretamente configurado para as snapshots:

```bash
file /dev/virtio-ports/org.qemu.guest_agent.0
/dev/virtio-ports/org.qemu.guest_agent.0: symbolic link to ../vport2p1
```

Se o resultado for diferente (“No such file or directory”), instale e ative o agente:

```bash
sudo yum install qemu-guest-agent
sudo chkconfig qemu-guest-agent on
```

Inicie o agente e verifique que está a ser executado:

```bash
sudo service qemu-guest-agent start
sudo service qemu-guest-agent status
```

##### **Windows**

Pode instalar o agente através de um ficheiro MSI, disponível no site do projeto Fedora: [https://fedorapeople.org/groups/virt/virtio-win/direct-downloads/latest-qemu-ga/](https://fedorapeople.org/groups/virt/virtio-win/direct-downloads/latest-qemu-ga/)

Verifique que o serviço está a ser executado graças ao seguinte comando *PowerShell*:

```powershell
PS C:\Users\Administrator> Get-Service QEMU-GA

Status   Name               DisplayName
------   ----               -----------
Running  QEMU-GA            QEMU Guest Agent
```
