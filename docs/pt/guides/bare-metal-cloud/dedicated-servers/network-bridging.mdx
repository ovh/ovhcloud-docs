## Objetivo

A ligação em rede no modo bridge pode ser utilizada para configurar as suas máquinas virtuais. São necessárias algumas modificações para que a configuração funcione na nossa rede.

**Este guia mostra-lhe como utilizar o modo bridge para configurar o acesso à Internet das suas máquinas virtuais.**

## Requisitos

* Possuir um servidor dedicado com um hipervisor instalado (Citrix Xen Server, Proxmox, por exemplo).
* Dispor de, pelo menos, um endereço [Additional IP](https://www.ovhcloud.com/pt/network/additional-ip/) encaminhado para o servidor.

## Instruções

As etapas de base são sempre as mesmas, independentemente dos sistemas utilizados:

* criação de um endereço MAC virtual para um [Additional IP](https://www.ovhcloud.com/pt/network/additional-ip/);
* definir o endereço MAC da máquina virtual (VM) para este novo endereço;
* configurar **o endereço IP**, **a máscara de rede**, **o gateway** e **a rota para o gateway** no interior da máquina virtual.

Para este exemplo, utilizaremos os seguintes valores nos nossos exemplos de código. Estes deverão ser substituídos pelos seus próprios valores:

* "SERVER_IP": o endereço IP principal do seu servidor;
* "ADDITIONAL_IP": o seu endereço Additional IP;
* "GATEWAY_IP": o endereço do seu gateway predefinido.

### Configurar as máquinas virtuais <a name="configurationsteps"></a>

:::warning
Tenha em atenção que os exemplos seguintes pressupõem que está ligado como utilizador com privilégios limitados, daí a utilização de *sudo* antes de cada comando. Se estiver ligado como *root*, não precisa de o fazer.

:::


:::tip
Selecione o separador correspondente ao seu sistema operativo.

:::


<Tabs>
  <Tab label="Debian">
    Por predefinição, o ficheiro de configuração de rede da máquina virtual encontra-se em `/etc/network/interfaces`.
    
    Depois de ligado à shell da sua máquina virtual, execute o seguinte comando para identificar o nome da sua interface:
    
    ```bash
    ls /sys/class/net
    ```
    
    Em seguida, faça uma cópia do ficheiro de configuração, para poder reverter a qualquer momento:
    
    ```bash
    sudo cp /etc/network/interfaces /etc/network/interfaces.bak
    ```
    
    Em caso de erro, poderá reverter através dos comandos abaixo:
    
    ```bash
    sudo rm -f /etc/network/interfaces
    sudo cp /etc/network/interfaces.bak /etc/network/interfaces
    ```
    
    Modifique o ficheiro para que reflita a configuração abaixo, substituindo `INTERFACE_NAME`, `ADDITIONAL_IP` e `GATEWAY_IP` pelos seus próprios valores.
    
    ```bash
    sudo nano /etc/network/interfaces
    ```
    
    ```console
    auto lo
    iface lo inet loopback
    
    # The primary network interface
    auto INTERFACE_NAME
    iface INTERFACE_NAME inet static
    address ADDITIONAL_IP
    netmask 255.255.255.255
    gateway GATEWAY_IP
    ```

#### Resolução de problemas

Se não conseguir estabelecer uma ligação entre a sua máquina virtual e a rede pública e suspeitar de um problema de rede, reinicie o servidor em modo rescue e configure a interface de rede do gateway diretamente no anfitrião.

Para tal, depois de reiniciar o seu servidor em modo rescue, introduza os seguintes comandos:

```bash
ip link add name test-bridge link eth0 type macvlan
ip link set dev test-bridge address MAC_ADDRESS
ip link set test-bridge up
ip addr add ADDITIONAL_IP/32 dev test-bridge
```

Substitua "MAC_ADDRESS" pelo endereço MAC virtual gerado no painel de controlo e "ADDITIONAL_IP" pelo Additional IP real.

Em seguida, basta efetuar um ping ao seu Additional IP a partir do exterior. Se funcionar, é provável que exista um erro de configuração na máquina virtual ou no anfitrião que impede o Additional IP de funcionar em modo normal. Se, pelo contrário, o IP continuar sem funcionar, abra um pedido de assistência através do [centro de ajuda](https://help.ovhcloud.com/csm?id=csm_cases_requests).
