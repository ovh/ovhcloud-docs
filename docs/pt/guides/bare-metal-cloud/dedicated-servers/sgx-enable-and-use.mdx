## Objetivo

A ativação das Intel Software Guard Extensions (SGX) no seu servidor permite executar aplicações compatíveis com SGX. As Intel SGX fornecem funcionalidades avançadas de encriptação de segurança de hardware e memória RAM, para isolar partes específicas de código e dados para cada aplicação.

**Este guia explica como ativar a funcionalidade SGX a partir da antiga Área de Cliente OVHcloud, através da API OVHcloud ou no BIOS do seu servidor.**

## Requisitos

- Acesso à <ApiLink>API OVHcloud</ApiLink> (opcional)
- Ter um servidor dedicado compatível com [a opção SGX](/links/bare-metal/sgx) no seu conta OVHcloud
- Dispor das credenciais recebidas por e-mail após a instalação
- Ubuntu 24.04 ou equivalente está instalado no servidor

### Ativar SGX

Pode ativar o SGX a partir da antiga Área de Cliente OVHcloud, através da API OVHcloud ou a partir do BIOS do seu servidor.

<Tabs>
  <Tab label="Via área de cliente OVHcloud">
    **Ativar SGX**
    
    Na <ManagerLink legacy-v6 to="/#/dedicated-servers/server">antiga Área de Cliente OVHcloud</ManagerLink>, selecione o seu servidor.
    
    A partir do separador <code className="action">Informações gerais</code>, no quadro **Funcionalidades de nível avançado**, clique em <code className="action">...</code> ao lado da menção **Segurança - Intel SGX (Software Guard Extensions)** e selecione <code className="action">Ativar SGX</code> no menu suspenso.

No ecrã seguinte, clique no botão <code className="action">Ativar</code>.

Pode escolher ativar o SGX com uma quantidade específica de memória reservada ou permitindo que a sua aplicação reserve automaticamente a memória de que necessita. Após a sua escolha, clique em <code className="action">Confirmar</code>.

Uma janela de confirmação aparecerá. Confirme que compreendeu que a ativação da tecnologia Intel SGX provocará um reinício do seu servidor.

    :::warning
    Isto provocará um ou mais reinícios do seu servidor, dependendo do seu modelo.

    :::

  <Tab label="Via API OVHcloud">
    **1 - Conexão à consola API**
    
    Na página das <ApiLink>API OVHcloud</ApiLink>:
    
    - Clique em <code className="action">Authentication</code> no canto superior esquerdo.
    - Clique depois em <code className="action">Login with OVHcloud SSO</code>.
    - Introduza as suas credenciais OVHcloud.
    - Clique no botão <code className="action">Authorize</code> para autorizar as chamadas às APIs a partir deste site.
    
    **2 - Ativar SGX**
    
    Obtenha o nome do seu servidor na lista devolvida pela seguinte chamada:
    
    <Api version="v1" section="/dedicated/server" method="GET" route={"/dedicated/server"} />

Verifique se o seu serviço dispõe da opção SGX utilizando esta chamada:
    
    <Api version="v1" section="/dedicated/server" method="GET" route={"/dedicated/server/\\{serviceName\\}/biosSettings/sgx"} />

Exemplo de resposta:

```json
{
  "prmrr": "128",
  "status": "disabled"
}
```

Ative o SGX utilizando o nome do servidor:
    
    :::warning
    Isto provocará um ou mais reinícios do seu servidor, dependendo do seu modelo.

    :::

    
    <Api version="v1" section="/dedicated/server" method="POST" route={"/dedicated/server/\\{serviceName\\}/biosSettings/sgx/configure"} />

`status` aceita `enabled`, `software controlled` (o SGX é habilitado previamente e depois ativado diretamente pela sua aplicação) ou `disabled`. Com `enabled` ou `software controlled`, pode definir a memória de processador reservada (PRMRR, em MB) em `prmrr`.

Por exemplo, defina o *request body* da seguinte forma:

```json
{
  "prmrr": "128",
  "status": "enabled"
}
```

Exemplo de resposta:

```json
{
  "taskId": 169664982,
  "function": "ipmi/configureSGX",
  "status": "init"
}
```

Verifique o progresso da tarefa de configuração chamando este ponto final com o *taskId* devolvido pela chamada anterior:
    
    <Api version="v1" section="/dedicated/server" method="GET" route={"/dedicated/server/\\{serviceName\\}/task/\\{taskId\\}"} />

Exemplo de resposta:

```json
{
  "taskId": 169664982,
  "function": "ipmi/configureSGX",
  "status": "done"
}
```

Pode verificar que o estado está ativado:
    
    <Api version="v1" section="/dedicated/server" method="GET" route={"/dedicated/server/\\{serviceName\\}/biosSettings/sgx"} />

Exemplo de resposta:

```json
{
  "status": "enabled",
  "prmrr": "128"
}
```

    **1 - Iniciar uma sessão Remote KVM**
    
    Na consola OVHcloud, selecione o servidor no qual pretende ativar o SGX e abra o respetivo separador <code className="action">Server</code>. Na secção **Server connection**, clique em <code className="action">Access console (KVM)</code> na linha **KVM over IP** e, em seguida, em <code className="action">Request access</code> na janela **Access KVM console**. Quando a janela apresentar **Access ready**, clique em <code className="action">Open console</code>: o KVM abre-se num novo separador do navegador.
    
    Se o IPMI do seu servidor não disponibilizar um KVM no navegador (HTML5), a linha apresenta, em vez disso, <code className="action">A partir de applet java (KVM)</code>: clique neste botão e, em seguida, em <code className="action">Preparar a applet java</code>. A consola descarrega um ficheiro `.jnlp`: abra-o com o Java Web Start (é necessário ter um ambiente de execução Java instalado no seu computador).

**2 - Ativar SGX**
    
    Em seguida, a partir do KVM, inicie um reinício do servidor e entre no BIOS (normalmente premindo a tecla <code className="action">DEL</code> ou <code className="action">F2</code>).
    
    No BIOS, dirija-se à parte `Advanced` > `Processor Configuration`.
    
    Ative as Opções TME e SGX e configure o tamanho PRMRR desejado:

Guarde as alterações premindo a tecla <code className="action">F10</code>. Uma janela de confirmação aparecerá, confirme com a opção `Yes`.
    
    O seu servidor reiniciará depois no seu sistema operativo.

### Instalar a pilha de software SGX

Use os seguintes comandos para instalar o SDK da Intel para poder desenvolver e executar aplicações SGX.

Primeiro, instale algumas dependências:

```bash
sudo apt update
sudo apt install autoconf automake build-essential cmake debhelper git libcurl4-openssl-dev libprotobuf-dev libssl-dev libtool lsb-release ocaml ocamlbuild protobuf-compiler python-is-python3 reprepro wget perl unzip pkgconf libboost-dev libboost-system-dev libboost-thread-dev libsystemd0
```

Em seguida, descarregue o código fonte e prepare os submódulos e os binários prontos a usar:

```bash
BASE_DIR=/opt/intel
[[ -d $BASE_DIR ]] || sudo mkdir -p $BASE_DIR && sudo chown `whoami` $BASE_DIR
cd $BASE_DIR
 
git clone https://github.com/intel/linux-sgx.git
 
cd linux-sgx
git checkout sgx_2.26
make preparation
```

Construa e instale o SDK SGX:

```bash
make sdk_install_pkg
$ ./linux/installer/bin/sgx_linux_x64_sdk_2.26.100.0.bin --prefix=$BASE_DIR/
```

### Testar a aplicação de exemplo no modo simulador

Para construir e executar o código de exemplo *LocalAttestation* no modo simulador:

```bash
BASE_DIR=/opt/intel
cd $BASE_DIR/sgxsdk/SampleCode/LocalAttestation/
source $BASE_DIR/sgxsdk/environment
 
make clean
SGX_MODE=SIM make
cd bin
./app
succeed to load enclaves.
succeed to establish secure channel.
Succeed to exchange secure message...
Succeed to close Session...
```

### Construir e instalar o PSW Intel SGX

O software Intel SGX Platform Software (PSW) fornece bibliotecas de software que permitem executar aplicações SGX no modo hardware. Para criar o repositório Debian local que aloja os pacotes, execute os seguintes comandos:

```bash
BASE_DIR=/opt/intel
cd $BASE_DIR/linux-sgx
make deb_local_repo
```

Crie o seguinte ficheiro para adicionar o repositório local de pacotes Debian ao sistema de configuração dos repositórios:

```bash
$ cat /etc/apt/sources.list.d/sgx.sources
Types: deb
URIs: file:/opt/intel/linux-sgx/linux/installer/deb/sgx_debian_local_repo
Suites: noble
Components: main
trusted: yes
```

Em seguida, instale os seguintes pacotes:

```bash
sudo apt update
sudo apt-get install libsgx-epid libsgx-quote-ex libsgx-dcap-ql
```
