## Objetivo

Este guia explica como ativar a transferência dos logs do seu servidor dedicado OVHcloud para a Logs Data Platform (LDP), uma plataforma que o ajuda a armazenar, arquivar, consultar e visualizar os seus logs.

Para saber mais sobre a Logs Data Platform antes de ler este guia, consulte o [guia de introdução à Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/introduction).

**Neste guia, aprenderá a:**

- Consultar os logs do seu servidor dedicado em tempo real.
- Criar uma subscrição que transfere esses logs para um fluxo de dados Logs Data Platform.
- Consultar e visualizar os logs transferidos.
- Gerir e eliminar as suas subscrições.

:::info
Os logs descritos neste guia provêm das operações que a OVHcloud efetua no seu servidor: **instalação do sistema operativo**, **arranque pela rede** e **configuração de rede**. **Não** se trata dos logs de sistema produzidos pelo sistema operativo depois de este estar em funcionamento.

Para centralizar os logs produzidos pelo seu próprio sistema operativo, consulte o guia "[Enviar os logs Linux para a Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/log-linux)".
:::

## Glossário

- **Logs Data Platform:** uma plataforma de gestão de logs totalmente gerida e protegida pela OVHcloud. Para mais informações, consulte a página de apresentação da solução [Logs Data Platform](/links/manage-operate/ldp).
- **Fluxo de dados (Data Stream):** uma partição lógica de logs que cria numa conta LDP e que utiliza para ingerir, visualizar ou consultar os seus logs. Várias fontes podem ser armazenadas no mesmo fluxo de dados, que é a unidade que permite definir um pipeline de logs (política de retenção, arquivo, streaming em direto, etc.), direitos de acesso e políticas de alerta.
- **Transferência de logs:** funcionalidade integrada num produto OVHcloud para ingerir os logs dos seus serviços num *fluxo de dados* de uma conta LDP pertencente à mesma conta OVHcloud. Deve ativá-la para cada serviço.
- **Subscrição da transferência de logs:** ao ativar a transferência de logs de um determinado serviço OVHcloud para um determinado *fluxo de dados* LDP, é criada uma *Subscrição* associada ao *fluxo de dados*, que poderá depois gerir.

## Requisitos

- Dispor de uma conta Logs Data Platform (LDP) com, pelo menos, um *fluxo de dados* ativo configurado. Este guia acompanha-o em todas as etapas necessárias: [Início rápido com a Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start).
    - Se não conhecer todas as possibilidades de configuração de um *fluxo de dados* LDP, crie um novo com as opções predefinidas (indexação e WebSocket ativados, armazenamento de longa duração desativado) para seguir este guia.
- Dispor de um [servidor dedicado OVHcloud](/guides/bare-metal-cloud/dedicated-servers/getting-started-with-dedicated-server) operacional.
- A conta LDP e o servidor dedicado devem pertencer à mesma conta OVHcloud.

## Conceitos e limites

**Quais são os logs de um servidor dedicado?**

Os logs transferidos registam as operações realizadas pela OVHcloud no seu servidor: instalação do sistema operativo, arranque pela rede e configuração de rede.

A transferência de logs está disponível em todas as gamas de servidores dedicados.

### Tipos de logs

Os logs estão agrupados por *tipos*, e cada tipo é objeto de uma subscrição distinta. Um servidor dedicado expõe os seguintes tipos:

| Tipo | Nome apresentado | Descrição |
|------|-------------|-------------|
| `install` | Operating system installation logs | Detalhes da instalação do sistema operativo no seu servidor. |
| `netboot` | Network boot logs | Envio do script de arranque iPXE para o seu servidor quando este arranca pela rede (disco rígido, rescue, instalador, etc.). |
| `network` | Network configuration logs | Operações de rede realizadas pela OVHcloud no seu servidor: Additional IP, MAC virtuais, vRack, OVHcloud Link Aggregation (OLA) e políticas de largura de banda. |

Pode obter a lista dos tipos disponíveis no seu servidor com a seguinte chamada API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/kind"} />

Para obter os detalhes de um tipo, incluindo os campos adicionais que devolve, utilize a seguinte chamada API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/kind/\{name\}"} />

### Conteúdo dos logs

Além dos campos comuns a todos os logs ingeridos pela Logs Data Platform, cada tipo devolve os seguintes campos.

#### Tipo `install`

| Nome do campo | Descrição | Tipo de dado |
|--------------|-------------|----------------|
| `level` | Nível de criticidade da entrada de log, segundo os valores de severidade syslog padrão: `2` (critical), `6` (info). | Number |
| `os` | Sistema operativo instalado no servidor. | String |
| `serviceName` | Nome interno do seu servidor, no formato `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Etapa em curso da operação: `os-install-start`, `os-install-failed` ou `os-install-ok`. | String |

#### Tipo `netboot`

| Nome do campo | Descrição | Tipo de dado |
|--------------|-------------|----------------|
| `level` | Nível de criticidade da entrada de log, segundo os valores de severidade syslog padrão: `2` (critical), `6` (info). | Number |
| `serviceName` | Nome interno do seu servidor, no formato `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Resultado do pedido do script de arranque: `ipxe-request-ok` ou `ipxe-request-error`. | String |

#### Tipo `network`

| Nome do campo | Descrição | Tipo de dado |
|--------------|-------------|----------------|
| `level` | Nível de criticidade da entrada de log, segundo os valores de severidade syslog padrão: `6` (info). | Number |
| `serviceName` | Nome interno do seu servidor, no formato `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Etapa em curso da operação, no formato `<operation>-doing` (iniciada) ou `<operation>-ok` (bem-sucedida). Operações: `add_ipfo`, `remove_ipfo`, `add_vmac`, `remove_vmac`, `vrack-add`, `vrack-remove`, `ola-group`, `ola-ungroup`, `qos-apply`. | String |

:::info
A lista de valores de `status` acima corresponde ao estado atual e irá evoluir ao longo do tempo.
:::

Para os campos comuns a todos os logs, consulte o guia "[Convenção de nomenclatura dos campos](/guides/manage-and-operate/observability/logs-data-platform/field-naming-conventions)".

## Instruções

A ativação da transferência é gratuita, mas a utilização do serviço Logs Data Platform é-lhe faturada segundo a tabela de preços padrão. Para conhecer os preços da LDP, consulte a página de apresentação da [Logs Data Platform](/links/manage-operate/ldp).

### Ativar a transferência de logs

<Tabs>
<Tab label="Através da consola OVHcloud">

Na consola OVHcloud, abra o universo <code className="action">Bare Metal Cloud</code>, aceda a <code className="action">Servidores dedicados</code> e selecione o servidor cujos logs pretende transferir.

Clique no separador <code className="action">Registos</code>.

O separador inclui:

- uma lista pendente **Tipo de registo**, na qual seleciona o tipo de logs a consultar ou a transferir (`netboot`, `network` ou `install`);
- a secção **Fluxo em direto**, que apresenta em tempo real os logs do seu servidor para o tipo selecionado;
- a secção **Logs**, que lista as suas subscrições ativas e permite criar novas.

Para transferir os seus logs para a Logs Data Platform, selecione o tipo de registo e clique em <code className="action">Add subscription</code> na secção **Logs**.

Na janela **Subscrever um fluxo**, se dispuser de vários serviços Logs Data Platform, selecione um na lista pendente **Serviço Logs Data Platform** (com um único serviço, este é selecionado automaticamente). Selecione depois o fluxo de dados de destino na lista pendente **Fluxo** e clique em <code className="action">Subscrever</code>.

Se a sua conta ainda não tiver nenhum serviço Logs Data Platform, a janela indica-o e propõe um botão <code className="action">Encomendar Logs Data Platform</code>. Se o seu serviço ainda não tiver nenhum fluxo, crie um previamente na Logs Data Platform (consulte o [guia de início rápido da Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start)).

Apenas os logs gerados **depois** da criação da subscrição são enviados para o seu fluxo de dados.

Para saber mais sobre o OVHcloud Service Logs, comum a todos os produtos OVHcloud compatíveis, consulte o guia "[Introdução ao OVHcloud Service Logs com a Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/service-logs)".

</Tab>

Defina, numa das suas contas LDP, o *fluxo de dados* de destino para o qual pretende transferir os seus logs. A ativação da transferência cria uma subscrição para este identificador de fluxo.

#### Etapa 1 - Obter o fluxo de dados de destino (e o seu identificador)

Liste os fluxos de dados da sua conta Logs Data Platform (introduza o identificador LDP no formato `ldp-xx-xxxx` no campo `serviceName`):

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/output/graylog/stream"} />

Obtenha os detalhes de um fluxo de dados:

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/output/graylog/stream/\{streamId\}"} />

#### Etapa 2 - Criar a sua subscrição

Utilize a seguinte chamada API para criar uma subscrição:

<Api version="v2" section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/log/subscription"} />

:::info
Substitua:

- `serviceName`: o nome interno do seu servidor dedicado, no formato `nsxxxxx.ip-xx-xx-xx.eu`. Pode encontrá-lo na lista de servidores dedicados ou na página do servidor na consola OVHcloud, ou obtê-lo com a seguinte chamada API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server"} />
:::

O pedido POST requer um payload com:

- `kind`: o tipo de log que pretende transferir (`install`, `netboot` ou `network`). Consulte a secção "[Tipos de logs](#tipos-de-logs)" acima.
- `streamId`: o fluxo de dados de destino da sua conta LDP para o qual pretende transferir os logs do seu servidor dedicado.

```shell
POST /dedicated/server/{serviceName}/log/subscription
{
  "kind": "install", // Um dos tipos: install, netboot, network.
  "streamId": "198ef9d5-c320-4000-8bee-236623da5b80" // O streamID do Stream de destino.
}
```

Obterá um `operationId` como resposta:

```shell
{
  "operationId": "f550aa1c-89ab-4b1a-81ae-4fba4959966f",
  "serviceName": "ldp-xx-xxxx"
}
```

Pode utilizar o `operationId` para obter o `subscriptionId` para efeitos de gestão posterior com a seguinte chamada API:

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/operation/\{operationId\}"} />

Depois de concluída a operação, pode também obter as subscrições com a seguinte chamada API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/subscription"} />

Depois de obter o `subscriptionId`, pode consultar os respetivos detalhes com a seguinte chamada API:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/subscription/\{subscriptionId\}"} />

```shell
GET /dedicated/server/{serviceName}/log/subscription/{subscriptionId}

{
  "createdAt": "2026-08-31T07:42:50.645Z",
  "kind": "string",
  "resource": {
    "name": "string",
    "type": "string"
  },
  "serviceName": "string",
  "streamId": "string",
  "subscriptionId": "198efa11-f150-4000-8e8d-871b1e482b80",
  "updatedAt": "2026-08-31T07:42:50.645Z"
}
```

### Como utilizar os logs do seu servidor dedicado

Os seus logs são agora ingeridos e armazenados no seu fluxo de dados Logs Data Platform. Pode consultá-los e criar dashboards na interface web do Graylog.

- Obtenha o nome de utilizador da sua conta Logs Data Platform (por exemplo, `logs-xxxx`) e a respetiva palavra-passe. Na consola OVHcloud, abra <code className="action">Observabilidade</code>, clique em <code className="action">Gestão do serviço</code> e selecione o seu serviço Logs Data Platform: o nome de utilizador figura na linha **Nome de utilizador LDP** da secção **Informações gerais** (apenas para os serviços que não utilizam o OVHcloud IAM). A palavra-passe é a que definiu para esta conta. Consulte o guia "[Início rápido com a Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start)".
- Abra a interface web do Graylog. Pode aceder-lhe a partir dos dashboards Graylog listados em <code className="action">Observabilidade</code> > <code className="action">Dashboards</code> da consola OVHcloud, ou através do seu ponto de acesso, consoante a região da sua conta (por exemplo, à região de Gravelines corresponde `https://gra1.logs.ovh.com/`).
- Ligue-se ao Graylog com o seu nome de utilizador e a sua palavra-passe Logs Data Platform.
- Efetue as suas pesquisas nos logs do fluxo de dados da sua conta Logs Data Platform. Consulte a documentação [Search Syntax Reference](https://go2docs.graylog.org/current/making_sense_of_your_log_data/search_syntax_reference.htm) para conhecer os detalhes da sintaxe de pesquisa.

Para saber mais sobre a exploração dos seus logs com a Logs Data Platform, nomeadamente a configuração de alertas, a consulta dos logs em tempo real via WebSocket, a criação de visualizações com OpenSearch Dashboards, a integração com a API OpenSearch e a ligação ao Grafana, consulte o [guia de introdução à Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/introduction).

### Como gerir as suas subscrições

A qualquer momento, pode obter as subscrições associadas ao seu fluxo de dados Logs Data Platform e desativar a transferência cancelando a sua subscrição no seu stream, para que este deixe de receber os logs do seu servidor dedicado.

Esta operação não elimina os logs armazenados antes do cancelamento da subscrição: os dados armazenados num fluxo de dados são imutáveis, salvo se eliminar o fluxo na totalidade.

Na consola OVHcloud, abra o separador <code className="action">Registos</code> do seu servidor, localize a subscrição pelo seu Stream ID na secção **Logs** e clique no ícone do caixote do lixo na respetiva linha. A subscrição é eliminada imediatamente, sem janela de confirmação.

Para eliminar a sua subscrição com a API, utilize a seguinte chamada:

<Api version="v2" section="/dedicated/server" method="DELETE" route={"/dedicated/server/\{serviceName\}/log/subscription/\{subscriptionId\}"} />
