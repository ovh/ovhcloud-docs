## Objetivo

As nossas intervenções de manutenção limitam-se exclusivamente à componente de hardware do seu servidor. Após uma intervenção de manutenção, poderão ser necessárias ações da sua parte na componente de software do seu servidor.

Esta documentação, baseada em numerosos casos práticos e situações encontradas pelas nossas equipas, enumera as ações a realizar em função das suas instalações: sistemas operativos, hipervisor, etc.
Tem como objetivo acompanhá-lo e limitar tanto quanto possível o impacto no ciclo de vida dos seus ambientes.

## Requisitos

- Dispor de um [servidor dedicado](/links/bare-metal/bare-metal).

<a name="ubuntu"></a>

### Ubuntu / Debian 12+

Se tiver um problema de conectividade de rede (por exemplo, ausência de resposta ao ping após a substituição da placa-mãe), efetue as seguintes ações:

1\. Reinicie o servidor em [modo rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).<br/>
2\. Monte a partição `/`:

```bash
root@rescue:~# mount /dev/my_system_disk /mnt
```
Se o ficheiro `70-persistent-net.rules` não existir (consulte a secção deste guia sobre [o nome das suas interfaces de rede](#network-interface)), verifique os seguintes ficheiros na árvore `/etc/systemd/network/`:

- `50-default.network`
- `50-public-interface.link`

```bash
root@rescue:~# cat /mnt/etc/systemd/network/50-default.network
# This file sets the IP configuration of the primary (public) network device.
# You can also see this as "OSI Layer 3" config.
# It was created by the OVH installer, please be careful with modifications.
# Documentation: man systemd.network or https://www.freedesktop.org/software/systemd/man/systemd.network.html
 
[Match]
MACAddress=xx:xx:xx:xx:xx:xx
 
[Network]
Description=network interface on public network, with default route
DHCP=no
Address=1.2.3.4/24
Gateway=1.2.3.254
IPv6AcceptRA=no
NTP=ntp.ovh.net
DNS=127.0.0.1
DNS=213.186.33.99
DNS=2001:41d0:3:163::1
Gateway=2001:41d0:0203:4bff:ff:ff:ff:ff
 
[Address]
Address=2001:41d0:0203:1234::/64
 
[Route]
Destination=2001:41d0:0203:4bff:ff:ff:ff:ff
Scope=link
root@rescue:~#
root@rescue:~# cat /mnt/etc/systemd/network/50-public-interface.link
# This file configures the relation between network device and device name.
# You can also see this as "OSI Layer 2" config.
# It was created by the OVH installer, please be careful with modifications.
# Documentation: man systemd.link or https://www.freedesktop.org/software/systemd/man/systemd.link.html
 
[Match]
MACAddress=xx:xx:xx:xx:xx:xx
 
[Link]
Description=network interface on public network, with default route
MACAddressPolicy=persistent
NamePolicy=kernel database onboard slot path mac
#Name=eth2    # name under which this interface is known under OVH rescue system
#Name=eno3    # name under which this interface is probably known by systemd
root@rescue:~#
```

3\. Faça uma cópia de segurança dos ficheiros e edite-os para introduzir o novo valor do seu endereço MAC:

```bash
root@rescue:~# cp /mnt/etc/systemd/network/50-default.network /mnt/etc/systemd/network/50-default.network.link.bak-`date +%s`
root@rescue:~# cp /mnt/etc/systemd/network/50-public-interface.link /mnt/etc/systemd/network/50-public-interface.link.bak-`date +%s`
root@rescue:~# nano /mnt/etc/systemd/network/50-default.network
root@rescue:~# cat /mnt/etc/systemd/network/50-default.network | grep MACAddress
MACAddress=xx:xx:xx:xx:xx:xx
root@rescue:~#
root@rescue:~# nano /mnt/etc/systemd/network/50-public-interface.link
root@rescue:~#
root@rescue:~# cat /mnt/etc/systemd/network/50-public-interface.link | grep MACAddress
MACAddress=xx:xx:xx:xx:xx:xx
root@rescue:~#
```

4\. Não se esqueça de desmontar a partição `/` antes de reiniciar o servidor.

#### Casos específicos

Em alguns casos, é necessário propagar o novo endereço MAC para os seguintes ficheiros:

- `/mnt/etc/netplan/01-netcfg.yaml`
- `/mnt/etc/netplan/50-cloud-init.yaml`
- `/mnt/etc/systemd/network/10-eno1.link`
- `/mnt/etc/systemd/network/10-eno1.network`

<a name="centos-almalinux"></a>

### CentOS / Alma Linux

Se tiver um problema de conectividade de rede (por exemplo, ausência de resposta ao ping após a substituição da placa-mãe), efetue as seguintes ações:

1\. Reinicie o servidor em [modo rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).<br/>
2\. Monte a partição `/`:

```bash
root@rescue:~# mount /dev/my_system_disk /mnt
```

3\. Verifique o ficheiro de configuração `/mnt/etc/sysconfig/network-scripts/ifcfg-eth0`.

4\. Faça uma cópia de segurança dos ficheiros e edite-os para corrigir o endereço MAC:

```bash
root@rescue:~# cp /mnt/etc/sysconfig/network-scripts/ifcfg-eth0 /mnt/etc/sysconfig/network-scripts/ifcfg-eth0.`date +%s`
```

5\. Introduza o novo endereço MAC na linha `HWADDR=xx:xx:xx:xx:xx:xx`.

6\. Não se esqueça de desmontar a partição `/` antes de reiniciar o servidor.

<a name="smartos"></a>

### SmartOS

Se tiver um problema de conectividade de rede (por exemplo, ausência de resposta ao ping após a substituição da placa-mãe), efetue as seguintes ações:

1\. Reinicie o servidor em [modo rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).<br/>

```bash 
modprobe zfs
root@rescue:~# zpool import -f zones (zpool import to list the pools)
root@rescue:~# zfs set mountpoint=/mnt zones/usbkey
root@rescue:~# zfs mount zones/usbkey
root@rescue:~# cp /mnt/config{,.bak-$(date +"%Y-%m-%d-%H_%M")}
```

2\. Introduza o novo endereço MAC na linha `admin_nic`:

```bash
root@rescue:~#  vim /mnt/config
```

3\. Não se esqueça de desmontar as partições antes de reiniciar o servidor em modo `netboot`:

```bash
root@rescue:~# zfs umount -a
root@rescue:~# zfs set mountpoint="/usbkey" zones/usbkey 
```

```bash
root@rescue-bsd:~ #
```

### Proxmox / Debian (exceto Debian 12 e versões posteriores)

Se tiver um problema de conectividade de rede (por exemplo, ausência de resposta ao ping após a substituição da placa-mãe), este pode estar relacionado com um erro durante o arranque do sistema, causado pelo antigo valor do endereço MAC que ainda está presente:

Efetue as seguintes ações:

1\. Reinicie o servidor em [modo rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).

```bash
root@rescue:~# cat /mnt/etc/network/interfaces
# This file describes the network interfaces available on your system
# and how to activate them. For more information, see interfaces(5).
 
# The loopback network interface
auto lo
iface lo inet loopback
 
iface enp3s0f0 inet manual
 
auto vmbr0
iface vmbr0 inet dhcp
  bridge-ports enp3s0f0
  bridge-stp off
  bridge-fd 0
 
auto vmbr1
iface vmbr1 inet static
  address  192.168.22.254
  netmask  255.255.255.0
  bridge_ports none
  bridge_stp off
  bridge_fd 0
  post-up echo 1 > /proc/sys/net/ipv4/ip_forward
root@rescue:~#
root@rescue:~# cat /mnt/var/log/messages | grep renamed
Aug  8 14:27:20 s22 kernel: [    1.527563] igb 0000:04:00.0 eno1: renamed from eth0
Aug  8 14:27:20 s22 kernel: [    1.550622] igb 0000:04:00.1 eno2: renamed from eth1
Aug  8 14:27:34 s22 kernel: [   88.148303] eth0: renamed from vethGRELEP
Aug  8 14:27:36 s22 kernel: [   90.444727] eth0: renamed from vethVMV0MH
Aug  8 14:27:40 s22 kernel: [   94.116739] eth0: renamed from vethQWYCXT
Aug  8 14:27:43 s22 kernel: [   97.469199] eth0: renamed from vethAIWWWX
Aug  8 14:27:48 s22 kernel: [  102.101324] eth0: renamed from vethB2DGCS

```

2\. Volte a criar o ficheiro `70-persistent-net.rules` e adicione:

- O nome da interface de rede indicado no ficheiro `/mnt/etc/network/interfaces`.
- O novo endereço MAC (visível em **Aggregated interface composition**, no separador <code className="action">Connectivity</code> da <ManagerLink to="/">consola OVHcloud</ManagerLink>, ou no resultado do comando `ip link`).

```bash
root@rescue:~# cat /mnt/etc/udev/rules.d/70-persistent-net.rules
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", NAME="enp3s0f0"
root@rescue:~#
```

<a name="xenserver"></a>

### XenServer

Se tiver um problema de conectividade de rede (por exemplo, ausência de resposta ao ping após a substituição da placa-mãe), o endereço MAC está configurado de forma estática e deve ser reinicializado.

Efetue as seguintes ações:

1\. Reinicie o servidor em [modo rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode) e utilize o comando `chroot`:

```bash
root@rescue:~# mount /dev/sda1 /mnt
root@rescue:~# mount -t proc /proc/ /mnt/proc/
root@rescue:~# mount -o bind /sys/ /mnt/sys/
root@rescue:~# mount -o bind /dev/ /mnt/dev/
root@rescue:~# mount -o bind /dev/pts/ /mnt/dev/pts/
root@rescue:~# chroot /mnt
```

2\. Altere a configuração atual para que corresponda aos novos parâmetros:

```bash
[root@rescue /]# xe-reset-networking --device=eth0 --mode=static --ip=xx.xx.xx.xx --netmask=255.255.255.0 --gateway=xx.xx.xx.xxx
```

3\. Ser-lhe-á pedido que responda à pergunta com "yes" e, em seguida, prima "Enter":

```bash
----------------------------------------------------------------------
!! WARNING !!
  
This command will reboot the host and reset its network configuration.
Any running VMs will be forcefully shutdown.
  
Before completing this command:
- Where possible, cleanly shutdown all VMs running on this host.
- Disable HA if this host is part of a resource pool with HA enabled.
----------------------------------------------------------------------
  
Your network will be re-configured as follows:
  
Management interface:   eth0
IP configuration mode:  static
IP address:             xx.xx.xx.xx
Netmask:                255.255.255.0
Gateway:                xx.xx.xx.xx
Pool master's address:  xx.xx.xx.xx
```

4\. Escreva "exit" para sair do modo `chroot` e, em seguida, desmonte todas as partições:

```bash
root@rescue:~# umount /mnt/sys
```

<a name="esxi"></a>

### ESXi

Após a substituição da placa-mãe, não é possível modificar os novos endereços MAC no ficheiro `esxi.conf` com as ferramentas integradas no modo rescue.
Será, portanto, necessário intervir manualmente.

#### Versão 7.0 ou superior

O procedimento descrito abaixo aplica-se apenas às **versões 7.0 ou superiores**. A partir desta versão, o ficheiro state.tgz é encriptado.
Reinicialize a rede a partir do menu Direct Console através do seu KVM ou IPMI.

Consulte a captura de ecrã abaixo:

<img className="thumbnail" alt="reset_network" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/restore.png" loading="lazy" />

#### Versão 6.7 ou inferior

O procedimento descrito abaixo aplica-se apenas às **versões 6.7 ou inferiores**.

1\. Reinicie o servidor em [modo rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode) para montar a partição `/`:

```bash
root@rescue:~# mount /dev/sdaX /mnt/
```

2\. Faça uma cópia de segurança do ficheiro `state.tgz`

```bash
root@rescue:~# ls /mnt/state.tgz
root@rescue:~# cp /mnt/state.tgz /mnt/state.tgz.`date +%s`
```

3\. Crie um ambiente de trabalho:

```bash
root@rescue:~# mkdir /home/ovh/esxi
root@rescue:~# WORKINGDIR=/home/ovh/esxi
root@rescue:~# cd $WORKINGDIR
```

4\. Extraia o conteúdo de `state.tgz` para `$WORKINGDIR` e, em seguida, extraia o conteúdo de `local.tgz`.<br/>
5\. Edite o ficheiro `esx.conf` obtido:

```bash
root@rescue:/home/ovh/esxi# tar xf /mnt/state.tgz -C $WORKINGDIR
root@rescue:/home/ovh/esxi# tar xf /home/ovh/esxi/local.tgz -C $WORKINGDIR
root@rescue:/home/ovh/esxi# vim etc/vmware/esx.conf
```
6\. Identifique e modifique o endereço MAC de `vmkernelnic`:

```bash
/net/vmkernelnic/child[0000]/mac = "XX:XX:XX:XX:XX:XX"
```

7\. Identifique em que interface é utilizado o endereço IP principal:

```bash
/net/vswitch/child[0000]/uplinks/child[0000]/pnic = "vmnicX"
```

8\. Atualize o endereço MAC da interface principal:

:::warning
Não modifique o endereço MAC virtual.

:::


```bash
/net/pnic/child[0001]/mac = "XX:XX:XX:XX:XX:XX"         <== Primary Interface Mac address
/net/pnic/child[0001]/virtualMac = "00:50:56:XX:XX:XX"  <== Virtual Mac
/net/pnic/child[0001]/name = "vmnic1"
```

:::warning
Se existir uma interface vRack, não se esqueça de modificar também o respetivo endereço MAC.

:::


9\. Faça uma cópia de segurança e, em seguida, desmonte a partição `/`:

```bash
root@rescue:/home/ovh/esxi# tar -czf $WORKINGDIR/local.tgz etc/
root@rescue:/home/ovh/esxi# tar -czf /mnt/state.tgz local.tgz
root@rescue:/home/ovh/esxi# umount /mnt
```

#### Casos específicos

Verifique a ordem das declarações dos seus vmnicX. Eis um exemplo funcional:

```bash
root@rescue:/home/ovh/esxi# cat etc/vmware/esx.conf | grep "/vmkdevmgr/pci"
/vmkdevmgr/pci/m00008901/alias = "vmhba0"
/vmkdevmgr/pci/m00008501/alias = "vmnic0"
/vmkdevmgr/pci/m00008502/alias = "vmnic1"
```

<a name="windows"></a>

### Windows (Hyper-V)

Após a substituição da placa-mãe, o servidor não estará acessível enquanto não modificar manualmente os endereços MAC através do **Gestor de Dispositivos**.

Existem 2 métodos:

#### Através do IPMI/KVM

1\. Ligue-se como administrador a partir da interface [IPMI/KVM](/guides/bare-metal-cloud/dedicated-servers/ipmi).<br/>
2\. Abra o utilitário <code className="action">Executar</code> (tecla do logótipo do Windows + <code className="action">R</code>) e, através da linha de comandos `run`, execute o comando `devmgmt.msc`:

<img className="thumbnail" alt="win_device_manager" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_device_manager_edited.png" loading="lazy" />

3\. Abra <code className="action">Network adapters</code> e selecione o adaptador correspondente a `eth0`.<br/>
4\. Clique com o botão direito em <code className="action">Properties</code> > <code className="action">Advanced</code>.<br/>
5\. Localize `Locally Administered Address`.<br/>
6\. Introduza o novo valor do endereço MAC (apenas algarismos, sem espaços).

<img className="thumbnail" alt="win_advanced" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_advanced_edited.png" loading="lazy" />

#### Através do WinPE

1\. Reinicie o servidor em modo `WinPE`.<br/>
2\. Execute o comando `regedit` através da linha de comandos `run`.<br/>
3\. Carregue o registo local através do registo disponível no `WinPE` e, em seguida, clique em <code className="action">HKEY_LOCAL_MACHINE</code>:

<img className="thumbnail" alt="win_regedit_1" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_1_edited.png" loading="lazy" />

4\. Em seguida, clique em <code className="action">Load Hive...</code>.

<img className="thumbnail" alt="win_regedit_2" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_2_edited.png" loading="lazy" />

:::info
Por predefinição, estará na árvore do WinPE.
Não se esqueça de navegar até à unidade `C:\`.

:::


5\. Localize o registo `SYSTEM`.

<img className="thumbnail" alt="win_load" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_load_edited.png" loading="lazy" />

6\. Ser-lhe-á pedido que introduza um nome. Pode, por exemplo, escolher `OVH_TEST`.

7\. Localize o valor do seguinte registo:

```bash
"HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Class\{4D36E972-E325-11CE-BFC1-08002BE10318}"
```

:::warning
Enquanto estivermos no WinPE, o valor `CurrentControlSet` deverá ser igual a `CurrentSet001`.

:::


Deverá ver várias subchaves com nomes como estes: 0000, 0001, etc.

8\. Clique em cada subchave para verificar o valor `DriverDesc`, que deve corresponder à sua interface de rede.
Pode verificar o nome da sua interface a partir de um terminal com o seguinte comando:

```bash
ipconfig /all
```

9\. Procure as entradas de registo `NetworkAddress` no painel da direita e substitua o valor pelo do seu novo endereço MAC. Se esta entrada não existir, clique com o botão direito numa zona vazia para criar um valor do tipo `String` com o nome `NetworkAddress`.

<img className="thumbnail" alt="win_regedit_3" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_3_edited.png" loading="lazy" />

10\. Será necessário descarregar o registo para aplicar as alterações recentes. Clique em OVH_TEST (criado anteriormente), clique em <code className="action">File</code> (no canto superior esquerdo) e selecione <code className="action">Unload hive...</code>.

<a name="network-interface"></a>

### Identificar o nome das suas interfaces de rede

Após a substituição da placa-mãe, o servidor não está acessível porque o controlador das interfaces de rede foi renomeado pelo sistema operativo.

1\. Reinicie o servidor em [modo rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-mode), monte a partição `/` e, em seguida, utilize o comando `chroot`:

```bash
root@rescue:~# mount /dev/my_disk /mnt
root@rescue:~# for i in /dev /dev/pts /proc /sys; do mount -B $i /mnt$i; done
root@rescue:~# chroot /mnt
```

2\. Verifique se as interfaces foram modificadas. Consulte os logs `var/log/messages` ou `var/log/kern.log` para verificar se a interface foi renomeada:

```bash
Oct  9 22:25:49 node1 kernel: [    5.479916] ixgbe 0000:03:00.1 eno4: renamed from eth1
Oct  9 22:25:49 node1 kernel: [    5.504285] ixgbe 0000:03:00.0 eno3: renamed from eth0
```

3\. Verifique o seu ficheiro de configuração `/mnt/etc/udev/rules.d/70-persistent.-net.rules` e substitua os novos valores (endereços MAC), se necessário:

```bash
root@rescue:~# cat /mnt/etc/udev/rules.d/70-persistent-net.rules
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", ATTR{dev_id}=="0x0", ATTR{type}=="1", KERNEL=="eth*", NAME="public"
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", ATTR{dev_id}=="0x0", ATTR{type}=="1", KERNEL=="eth*", NAME="private"
```

4\. Aceda ao diretório `/boot/grub/` e crie uma cópia de segurança do ficheiro `grub.cfg`.
5\. Edite o ficheiro `/etc/default/grub` e modifique a linha que começa por `GRUB_CMDLINE_LINUX` para obter o seguinte:

```bash
GRUB_CMDLINE_LINUX="net.ifnames=0 biosdevname=0"
```

6\. Execute o comando:

```bash
root@rescue:~# grub-mkconfig -o /boot/grub/grub.cfg
```

7\. Saia do ambiente `chroot` com o comando `exit` e desmonte todas as partições:

```bash
root@rescue:~# umount /mnt/sys
root@rescue:~# umount /mnt/proc
root@rescue:~# umount /mnt/dev/pts
root@rescue:~# umount /mnt/dev
root@rescue:~# umount /mnt
```

### Problemas relacionados com a sua partição EFI

Os passos seguintes são indicados se tiver um problema de arranque (boot) relacionado com as partições presentes nos seus discos.<br/>

#### Através do modo rescue

#### Através do BIOS

- Caso de utilização: o sistema instalado (neste caso, CentOS 6) deixou de arrancar após a substituição do disco (nenhuma entrada EFI está visível no BIOS).

1\. Reinicie o servidor para aceder ao menu do BIOS.

A *1.ª sequência* consiste em regenerar os ficheiros necessários para tornar a sua partição novamente operacional:

- Aceda ao menu `boot` do seu BIOS:
    - Escolha <code className="action">Add New Boot Option</code>.
    - Escolha o caminho da sua partição <code className="action">Path for boot option</code> e selecione o sistema de ficheiros que contém a sua partição de arranque.
    - Selecione o ficheiro `EFI\centos6\bootx64.efi` e escolha <code className="action">Create</code>.

    - Escolha <code className="action">UEFI Boot Order #1</code> e, em seguida, selecione <code className="action">CENTOS6</code> para o posicionar como primeira opção de arranque na lista ativa.
