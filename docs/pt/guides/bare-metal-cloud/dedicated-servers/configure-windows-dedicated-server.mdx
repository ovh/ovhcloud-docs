## Objetivo

O Windows Server é um sistema operativo suportado nos servidores dedicados OVHcloud. Depois de instalado, deve configurar o sistema Windows para que este possa utilizar os serviços de rede e de armazenamento OVHcloud associados ao servidor.

Este guia acompanha-o na instalação do Windows Server a partir da Área de Cliente OVHcloud, na ligação ao servidor e, em seguida, na configuração do lado do Windows necessária para interagir com os principais serviços OVHcloud associados a um servidor dedicado.

**Neste guia, vai aprender a:**

- Instalar o Windows Server a partir da Área de Cliente
- Ligar-se ao servidor com o Ambiente de Trabalho Remoto e efetuar a configuração inicial
- Configurar o Windows para utilizar uma Additional IP
- Configurar o Windows para utilizar a rede privada vRack
- Configurar o Windows para utilizar o bloco IPv6 fornecido com o servidor
- Aceder ao Backup Storage OVHcloud a partir do Windows
- Proteger o servidor com cópias de segurança geridas através do OVHcloud Backup Agent

:::warning
A reinstalação de um sistema operativo elimina todos os dados presentes nos discos do servidor. Faça uma cópia de segurança dos dados que pretende conservar antes de começar.
:::

## Requisitos

- Ter um [servidor dedicado](/links/bare-metal/bare-metal) na sua conta OVHcloud
- Ter uma licença válida do Windows Server. As licenças podem ser encomendadas junto da OVHcloud ou de um revendedor externo — consulte o guia [Gerir as suas licenças OVHcloud](/guides/bare-metal-cloud/dedicated-servers/windows-key).
- Ter um cliente RDP (Remote Desktop Protocol) na sua máquina local (o cliente <code className="action">Ligação ao Ambiente de Trabalho Remoto</code> está incluído no Windows)

## Introdução

Um servidor dedicado é um servidor físico ("bare metal") alojado num centro de dados OVHcloud. A OVHcloud fornece o hardware, a ligação à rede pública, uma rede privada vRack opcional e um espaço Backup Storage incluído. É responsável pela administração do sistema operativo instalado no servidor, incluindo toda a configuração de rede e de armazenamento no Windows.

A tabela abaixo apresenta os principais serviços com os quais um servidor dedicado com Windows interage.

| Serviço OVHcloud | Função | Onde ativar |
|---|---|---|
| Additional IP | Endereços IP públicos adicionais associados ao servidor | Área de Cliente — menu <code className="action">Network</code>, secção <code className="action">IP</code> |
| vRack | Rede privada de nível 2 entre os serviços OVHcloud | Área de Cliente — menu <code className="action">Network</code>, secção <code className="action">vRack</code> |
| IPv6 | O bloco IPv6 /64 fornecido com cada servidor | Fornecido automaticamente |
| Backup Storage | Espaço de cópia de segurança incluído (FTP/CIFS (SMB)/NFS) | Área de Cliente — <ManagerLink to="/#/dedicated-servers/server">Servidores dedicados</ManagerLink> > Selecione o seu servidor, separador <code className="action">Backup Storage</code> |
| Backup Agent | Cópias de segurança geridas diárias para um vault Object Storage isolado e imutável | Área de Cliente — <ManagerLink to="/#/dedicated-servers/server">Servidores dedicados</ManagerLink> > Selecione o seu servidor, separador <code className="action">Informações gerais</code>, secção <code className="action">Estado dos serviços</code> |

### Etapa 1 — Instalar o Windows Server a partir da Área de Cliente <a name="install"></a>

Nesta etapa, instala (ou reinstala) o Windows Server no seu servidor dedicado. A instalação é totalmente controlada a partir da Área de Cliente.

No separador <code className="action">Informações gerais</code>, ao lado de <code className="action">Sistema operativo (SO)</code>, abra o menu de ações e clique em <code className="action">Reinstalar o meu servidor</code>. A janela <code className="action">Instalação a partir de um template OVHcloud</code> abre-se e guia-o em 4 etapas.

:::info
O Windows Server requer uma licença, que gera custos adicionais. Sem uma licença do Windows Server associada ao servidor, os modelos Windows não são propostos na lista de sistemas operativos. Pode encomendar uma licença junto da OVHcloud ou fornecer a sua. Faça a gestão das suas licenças em **Bare Metal Cloud** > **Licenças**. Para mais informações, consulte o guia [Gerir as suas licenças OVHcloud](/guides/bare-metal-cloud/dedicated-servers/windows-key).
:::

:::warning
Esta ação é irreversível. Todos os dados presentes nos discos serão eliminados definitivamente.
:::

1. **Tipo de SO** — defina o <code className="action">Tipo de SO</code> e selecione o modelo do Windows Server pretendido. Os modelos são agrupados por categoria (Linux, Windows, etc.). Os modelos Windows só aparecem se estiver associada uma licença do Windows Server ao seu servidor dedicado (ver a nota acima).
2. **Conjunto de discos de destino** — escolha o <code className="action">Conjunto de discos de destino</code> no qual o Windows será instalado. Para definir a sua própria matriz ou disposição, ative <code className="action">Personalizar a configuração do RAID por Hardware</code> ou <code className="action">Personalizar a configuração das partições</code>. Para o RAID por software no Windows, consulte o guia [Configurar um RAID por software num servidor Windows](/guides/bare-metal-cloud/dedicated-servers/raid-soft-windows).
3. Clique em <code className="action">Seguinte</code> e siga as etapas restantes do assistente para verificar as suas escolhas, depois confirme para iniciar a instalação.

O servidor reinicia e a instalação termina automaticamente.

### Etapa 2 — Ligar-se ao seu servidor <a name="connect"></a>

Assim que a instalação terminar, a OVHcloud envia-lhe um e-mail com o nome de utilizador e a palavra-passe de administrador do seu servidor Windows.

Na sua máquina Windows local, abra o cliente <code className="action">Ligação ao Ambiente de Trabalho Remoto</code>. Introduza o endereço IPv4 do seu servidor e, em seguida, o seu nome de utilizador e a sua palavra-passe. Normalmente, aparece um aviso de certificado na primeira ligação — clique em <code className="action">Sim</code> para continuar.
Pode utilizar qualquer cliente compatível com RDP se o seu dispositivo local não funcionar com Windows.

:::tip
Se o protocolo RDP estiver indisponível — por exemplo, após um erro de configuração de rede — ligue-se através da [consola Intelligent Platform Management Interface (IPMI)](/guides/bare-metal-cloud/dedicated-servers/ipmi) a partir do separador <code className="action">IPMI / KVM</code> da Área de Cliente. A consola IPMI funciona independentemente do estado de conectividade do sistema operativo.
:::

Após a sua primeira ligação, altere a palavra-passe de administrador a partir do Windows (na sessão RDP, prima `Ctrl` + `Alt` + `Fim` > <code className="action">Alterar uma palavra-passe</code>).

### Etapa 3 — Efetuar a configuração inicial do Windows <a name="initial-config"></a>

Antes de ligar o servidor aos outros serviços OVHcloud, efetue a configuração de base do Windows.

- Inicie o Windows Update e instale as atualizações mais recentes.
- Defina o nome de anfitrião do servidor, o fuso horário e a disposição do teclado.
- Configure a firewall do Windows para autorizar os serviços que pretende executar. Para um procedimento específico da firewall no Windows, consulte o guia [Ativar a firewall num servidor Windows](/guides/bare-metal-cloud/dedicated-servers/activate-port-firewall-soft-win).

:::warning
A OVHcloud coloca à sua disposição serviços cuja configuração e gestão são da sua responsabilidade. Se necessitar de ajuda, contacte um [prestador especializado](/links/partner).
:::

### Etapa 4 — Configurar o Windows para interagir com os serviços OVHcloud <a name="services"></a>

Esta secção abrange a configuração do lado do Windows dos serviços OVHcloud mais frequentemente associados a um servidor dedicado. Cada subsecção é independente — siga apenas as que correspondem à sua configuração. Em cada uma, a primeira parte é efetuada na Área de Cliente OVHcloud e a segunda no Windows Server.

#### 4a — Additional IP

Uma Additional IP é um endereço IP público adicional encaminhado para o seu servidor. Depois de a encomendar, deve declará-la no Windows para que o servidor responda nesse endereço.

**Na Área de Cliente OVHcloud**

Encomende a Additional IP a partir do menu <code className="action">Network</code> da Área de Cliente, na secção <code className="action">IP</code>: clique em <code className="action">Encomendar endereços IP</code>. Para mais informações, consulte a página [Additional IP](/links/bare-metal/ip).

**No Windows Server**

1. Abra <code className="action">Painel de Controlo</code> > <code className="action">Centro de Rede e Partilha</code> > <code className="action">Alterar definições da placa</code>, depois apresente as propriedades da sua placa de rede.
2. Selecione <code className="action">Protocolo Internet Versão 4 (TCP/IPv4)</code> > <code className="action">Propriedades</code> > <code className="action">Avançado</code> e adicione o endereço da Additional IP.

Na rede OVHcloud, uma Additional IP é encaminhada individualmente para o servidor. Utilize a máscara de sub-rede e o gateway que correspondem à configuração do IP principal do seu servidor.

:::tip
Se pretende atribuir a Additional IP a uma máquina virtual em vez do anfitrião, consulte o guia [Configurar um bloco de IP num vRack](/guides/bare-metal-cloud/dedicated-servers/configuring-an-ip-block-in-a-vrack).
:::

#### 4b — Rede privada vRack

O vRack é uma rede privada de nível 2 que permite ao seu servidor dedicado comunicar de forma privada com outros serviços OVHcloud (outros servidores dedicados, instâncias Public Cloud, etc.).

**Na Área de Cliente OVHcloud**

A partir do menu <code className="action">Network</code> da Área de Cliente, abra a secção <code className="action">vRack</code>, selecione o seu vRack e adicione este servidor.

**No Windows Server**

1. Abra as propriedades da placa de rede **privada** (a segunda interface, dedicada ao vRack).
2. Atribua um endereço IPv4 privado estático proveniente do seu plano de endereçamento vRack. Deixe o gateway por defeito vazio — o vRack é uma rede de nível 2 sem gateway fornecido pela OVHcloud.

Para o procedimento completo, bem como para a configuração da OVHcloud Link Aggregation (OLA, agregação de ligações), consulte o guia [Configurar o vRack num servidor dedicado](/guides/bare-metal-cloud/dedicated-servers/vrack-configuring-on-dedicated-server).

#### 4c — IPv6

Cada servidor dedicado OVHcloud é fornecido com um bloco IPv6 /64. O endereço não é configurado automaticamente no Windows e deve ser adicionado manualmente.

**Na Área de Cliente OVHcloud**

Obtenha o seu endereço IPv6, o prefixo e o gateway a partir da secção <code className="action">Rede</code> do separador <code className="action">Informações gerais</code> do seu servidor, que apresenta <code className="action">IPv6</code> e <code className="action">Gateway IPv6</code>.

**No Windows Server**

1. Abra as propriedades da sua placa de rede e selecione <code className="action">Protocolo Internet Versão 6 (TCP/IPv6)</code> > <code className="action">Propriedades</code>.
2. Introduza o endereço IPv6, o comprimento do prefixo e o gateway IPv6 por defeito.

Para os detalhes de endereçamento e a configuração do gateway específicos da OVHcloud, consulte o guia [Configuração do IPv6](/guides/bare-metal-cloud/dedicated-servers/network-ipv6).

#### 4d — Backup Storage

O Backup Storage é um espaço de armazenamento incluído com o seu servidor dedicado. É acessível através dos protocolos FTP, CIFS (SMB) ou NFS e é particularmente adequado como cópia de segurança complementar.

**Na Área de Cliente OVHcloud**

1. No separador <code className="action">Backup Storage</code> do seu servidor, clique em <code className="action">Ativar backup storage</code>. Uma vez ativo, o separador apresenta o endereço do servidor FTP e o identificador, e permite-lhe definir a palavra-passe do espaço.
2. Autorize o endereço IP do seu servidor a aceder ao espaço.

**No Windows Server**

Aceda ao espaço utilizando um dos protocolos suportados:

- **CIFS (SMB)** — monte-o como uma unidade de rede (<code className="action">Este PC</code> > <code className="action">Ligar unidade de rede</code>).
- **FTP** — ligue-se com qualquer cliente FTP, utilizando os dados de ligação da Área de Cliente e a palavra-passe que definiu.

Para o procedimento de ativação e os protocolos de acesso, consulte o guia [Backup Storage nos servidores dedicados](/guides/bare-metal-cloud/dedicated-servers/services-backup-storage) e a página [Backup Storage](/links/bare-metal/backup-storage).

#### 4e — Backup Agent

O Backup Storage é um espaço de armazenamento passivo — não faz a cópia de segurança dos seus dados por si só. Para uma proteção gerida e automatizada, a OVHcloud propõe o **Backup Agent**, um serviço de cópia de segurança distinto para os servidores Bare Metal. Uma vez encomendado, implementa um agente leve no seu servidor Windows, que realiza então cópias de segurança diárias, incrementais, encriptadas e imutáveis para um vault Object Storage isolado, situado numa região diferente da do servidor.

**Na Área de Cliente OVHcloud**

No separador <code className="action">Informações gerais</code>, na secção <code className="action">Estado dos serviços</code>, utilize a entrada <code className="action">Backup Agent</code> e clique em <code className="action">Gerir Agente de Backup</code>. Também o pode ativar durante a reinstalação do sistema operativo.

**No Windows Server**

Uma vez implementado o agente, configure a sua primeira cópia de segurança (dados de origem, agendamento e retenção).

Para o procedimento completo, consulte o guia [Backup Agent - Apresentação](/guides/storage-and-backup/backup-agent/overview) e o guia [Backup Agent - Como configurar a sua primeira cópia de segurança](/guides/storage-and-backup/backup-agent/first-configuration).

### Etapa 5 — Verificar a configuração <a name="verify"></a>

Verifique se cada serviço configurado funciona conforme esperado.

| Verificação | Como | Resultado esperado |
|---|---|---|
| Acesso RDP | Ligue-se com <code className="action">Ligação ao Ambiente de Trabalho Remoto</code> no IPv4 principal | O ambiente de trabalho do Windows é apresentado |
| Additional IP | A partir de um anfitrião externo, execute `ping` para a Additional IP | O servidor responde |
| vRack | A partir de outro membro do vRack, execute `ping` para o IP privado | O servidor responde |
| IPv6 | Execute `ping -6 ipv6.google.com` a partir do servidor | Recebe respostas |
| Backup Storage | Abra a unidade CIFS (SMB) montada ou ligue-se por FTP | Pode ler e escrever ficheiros |

### Resolução de problemas <a name="troubleshooting"></a>

| Problema | Causa possível | Solução |
|---|---|---|
| A ligação RDP falha | Regras de firewall ou restrições de rede no dispositivo local | Verifique as definições de firewall e de rede locais; ligue-se através da [consola IPMI](/guides/bare-metal-cloud/dedicated-servers/ipmi) como alternativa. |
| Additional IP inacessível | Máscara ou gateway incorretos no Windows | Verifique novamente os valores introduzidos nas definições avançadas de TCP/IPv4. |
| Membro do vRack inacessível | Sub-rede privada incorreta ou gateway definido na placa privada | Confirme o plano de endereçamento privado e deixe o gateway vazio. |
| Servidor offline após uma alteração | Erro de configuração durante a implementação | Arranque em [modo rescue](/guides/bare-metal-cloud/dedicated-servers/rescue-customer-windows) para inspecionar e reparar a configuração. |
