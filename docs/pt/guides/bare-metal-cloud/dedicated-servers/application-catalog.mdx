## Objetivo

O catálogo de aplicações permite-lhe instalar uma aplicação pronta a utilizar no seu servidor dedicado OVHcloud, sem conhecimentos prévios de administração de sistemas. Escolhe uma aplicação durante a (re)instalação do servidor e, em seguida, preenche um breve formulário de configuração numa interface web segura. A aplicação é instalada de forma nativa no servidor, protegida por HTTPS e disponibilizada em poucos minutos.

**Este guia explica como utilizar o catálogo de aplicações no seu servidor dedicado OVHcloud.**

## Requisitos

- Dispor de um [servidor dedicado](/links/bare-metal/bare-metal) na sua conta OVHcloud
- Ter iniciado sessão na sua <ManagerLink to="/">Área de Cliente OVHcloud</ManagerLink>
- Dispor de acesso à <ApiLink>API OVHcloud</ApiLink> (para a secção "[API OVHcloud](#viaapi)" deste guia)
- Ter acesso ao endereço de e-mail da sua conta OVHcloud, para receber a ligação para a interface de configuração
- Dispor de um navegador web para aceder à interface de configuração após a conclusão da instalação

## Instruções

### Funcionamento do catálogo de aplicações

A implementação de uma aplicação decorre em duas etapas:

1. **Seleção (durante a instalação):** o utilizador (re)instala o servidor com uma imagem do catálogo de aplicações e seleciona **uma única** aplicação. É aqui que escolhe *qual* a aplicação que deseja implementar.
2. **Configuração (após o primeiro arranque):** depois de o servidor reiniciar, um configurador de utilização única é iniciado automaticamente e disponibiliza uma interface web segura na porta `10143`. Preenche um breve formulário (por exemplo, um nome de site e uma palavra-passe de administrador) e, em seguida, a aplicação é instalada automaticamente e publicada por HTTPS.

Após a conclusão da instalação com êxito, o configurador **elimina-se por completo** do servidor: o respetivo binário, o serviço e os dados de trabalho são eliminados. Fica apenas a sua aplicação e dispõe de um acesso root completo ao servidor.

As aplicações são instaladas de forma **nativa** — com pacotes de sistema e serviços `systemd`, num servidor dedicado exclusivamente a esta utilização — e não numa plataforma de contentores.

**Limitações técnicas:**

- Através do catálogo de aplicações, é possível implementar **uma única aplicação**.
- O **particionamento personalizado e a configuração do RAID de hardware não estão disponíveis** para esta instalação.

:::warning
Isto não significa que não possa executar outras aplicações no servidor, mas que apenas **UMA** aplicação pode ser implementada através do catálogo. Se desejar executar outras aplicações, deverá instalá-las manualmente.
:::

#### Iniciar a instalação <a name="viaapi"></a>

Para listar os sistemas operativos disponíveis para o seu servidor, utilize a seguinte chamada:

<Api version="v1" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/install/compatibleTemplates"} />

Na resposta, os templates do catálogo de aplicações são aqueles cujo nome termina em `-withapp`. Obtenha sempre o identificador através desta chamada em vez de o inserir de forma fixa, uma vez que o catálogo de templates evolui.

Em seguida, pode iniciar a instalação utilizando a seguinte chamada:

<Api version="v1" section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"} />

Indique o sistema operativo obtido no passo anterior e a aplicação a instalar na personalização `appToInstall`:

```json
{
  "operatingSystem": "ubuntu2404-withapp",
  "customizations": {
    "hostname": "myApplicationServer",
    "sshKey": "mySshKey",
    "appToInstall": "wordpress"
  }
}
```

O valor `appToInstall` corresponde ao identificador da aplicação a implementar, por exemplo `wordpress`, `drupal`, `nextcloud`, `prestashop`, `discourse`, `matomo`, `n8n`, `openclaw`, `hestiacp`, `fastpanel`, `coolify`, `dokploy`, `easypanel` ou `game-panel`. Apenas pode ser indicada uma aplicação.

Acompanhe a tarefa de instalação até ao fim, tal como descrito no guia [Install an OS via the OVHcloud API on a Dedicated Server](/guides/bare-metal-cloud/dedicated-servers/api-os-installation) e, em seguida, prossiga com a secção "[Configurar a sua aplicação e aceder a ela](#configure)" abaixo.

</Tabs>

### Configurar a sua aplicação e aceder a ela <a name="configure"></a>

Após a instalação, o servidor arranca automaticamente o configurador de utilização única. Esta etapa não exige qualquer competência de Linux, SSH ou administração de sistemas: basta um navegador web.

#### Etapa 1: abrir o configurador

Após a conclusão da instalação, recebe um e-mail com a ligação para o seu configurador. Apresenta-se da seguinte forma:

```text
https://<o-seu-servidor>:10143/static/deploy.html?app=<aplicacao>&token=<token>
```

Abra esta ligação no seu navegador web. O token que contém autentica-o e é registado um cookie de sessão seguro: pode então navegar no configurador sem o token na barra de endereços. Abrir o configurador sem um token válido apresenta uma página `Unauthorized`.

:::warning
Trate esta ligação como uma palavra-passe e não a partilhe: dá acesso à interface de instalação do seu servidor.
:::

:::info
Se o navegador apresentar um aviso de certificado no primeiro carregamento, o configurador está ainda a obter o respetivo certificado Let's Encrypt e apresenta, nesse intervalo, um certificado autoassinado temporário. Aguarde um minuto e recarregue a página: a mudança para o certificado definitivo é automática.
:::

#### Etapa 2: preencher o formulário de configuração

O configurador abre diretamente na aplicação que selecionou durante a instalação. Consoante essa aplicação, implementa-a imediatamente ou preenche primeiro um breve formulário:

- **As aplicações sem campos** — Coolify, Dokploy, Easypanel, FastPanel, HestiaCP, Discourse, Matomo e n8n — geram autonomamente as credenciais necessárias e apresentam-nas no final. Clique em <code className="action">Deploy</code>.
- **As aplicações com campos** — WordPress, Drupal, Nextcloud, PrestaShop, OpenClaw e OVHcloud Game Panel — solicitam alguns valores, como um nome de site, uma palavra-passe de administrador ou uma palavra-passe de base de dados. Os campos obrigatórios são assinalados e os campos facultativos podem propor valores predefinidos.

Um painel <code className="action">Installation details</code>, situado acima do formulário, detalha o que vai ser instalado e por que motivo, com uma ligação para a documentação oficial do editor.

Cada campo é validado antes do início da implementação (por exemplo, um campo de e-mail deve conter um endereço válido e as palavras-passe têm um comprimento mínimo). Corrija os campos assinalados e valide novamente.

:::tip
Escolha palavras-passe robustas: os valores introduzidos aqui tornam-se as credenciais reais da sua aplicação.
:::

<img className="thumbnail" alt="Formulário de configuração para uma implementação WordPress" src="/images/bare-metal-cloud/dedicated-servers/application-catalog/configurator-form.png" loading="lazy" />

Em seguida, clique em <code className="action">Deploy</code>.

#### Etapa 3: acompanhar a implementação

O configurador executa a instalação e transmite o respetivo progresso em tempo real: um estado (`pending`, depois `running` e, em seguida, `completed` ou `failed`), uma barra de progresso e os registos de instalação. Os valores que introduziu no formulário são ocultados nos registos.

<img className="thumbnail" alt="Progresso da implementação e registos em tempo real" src="/images/bare-metal-cloud/dedicated-servers/application-catalog/configurator-progress.png" loading="lazy" />

Uma implementação demora geralmente alguns minutos; as aplicações mais pesadas, como o Discourse, demoram mais tempo. Pode deixar o separador aberto, mas a instalação prossegue no servidor mesmo que o navegador se desligue: reabra a sua ligação para retomar o acompanhamento.

:::info
É executada apenas uma implementação de cada vez. Se uma implementação já estiver em curso e iniciar outra, o configurador remete-o para a que está em curso em vez de iniciar uma segunda. É isto que garante a regra "uma única aplicação por servidor".
:::

#### Etapa 4: obter os seus dados de acesso

Quando o estado atinge `completed`, o configurador apresenta uma página de êxito que contém:

- a ligação para a sua aplicação, na porta HTTPS padrão — `https://<o-seu-servidor>/`;
- as credenciais ou as informações geradas pela aplicação, por exemplo um nome de utilizador administrador, um nome de base de dados ou uma palavra-passe gerada.

Durante a instalação, é emitido um certificado [Let's Encrypt](https://letsencrypt.org/) gratuito e renovado automaticamente para o nome de host do servidor, e a aplicação implementada gere autonomamente a respetiva renovação.

:::warning
Copie imediatamente as suas credenciais. A página de êxito está disponível apenas durante o período de tolerância que se segue a uma implementação com êxito (5 minutos por predefinição). Depois de o configurador se eliminar, já não as pode apresentar: seria então necessário obtê-las a partir da própria aplicação ou reinstalar o servidor.
:::

#### Etapa 5: o configurador elimina-se

Pouco depois de uma implementação com êxito, o configurador elimina o próprio binário, o serviço e os dados de trabalho. A partir desse momento:

- a interface do configurador na porta `10143` deixa de responder — **este é o comportamento esperado e não uma falha**;
- a sua aplicação, os respetivos dados e o certificado HTTPS são conservados;
- o servidor executa apenas a sua aplicação, sem qualquer ferramenta de instalação nem interface de administração residual.

Dispõe do controlo total do servidor, incluindo um acesso root por SSH se adicionou uma chave durante a instalação. O configurador deixa de gerir o que quer que seja após esta etapa.

:::info
Se a implementação **falhar**, o configurador *não* se elimina: permanece acessível para que o problema possa ser diagnosticado a partir dos registos em tempo real. Uma implementação falhada exige geralmente reinstalar o servidor e começar de novo.
:::

Para implementar outra aplicação, reinstale o servidor a partir do catálogo de aplicações e selecione a nova aplicação.

### Resolução de problemas frequentes

| Sintoma | Causa | Solução |
|---|---|---|
| A página do configurador não carrega no endereço `https://<o-seu-servidor>:10143/` | A instalação ainda não terminou ou o acesso de entrada à porta `10143` está bloqueado. | Aguarde o fim da instalação e tente novamente. Certifique-se de que a firewall (incluindo o [Edge Network Firewall](/guides/bare-metal-cloud/dedicated-servers/firewall-network) OVHcloud) autoriza o tráfego de entrada para o servidor na porta `10143`. |
| A página do configurador deixou de carregar após uma implementação com êxito | O configurador eliminou-se, conforme previsto. | Este comportamento é normal. Utilize o endereço da sua aplicação: `https://<o-seu-servidor>/`. |
| `Unauthorized` ao abrir o configurador | O token de acesso está ausente ou é incorreto. | Reabra o configurador utilizando exatamente a ligação e o token fornecidos com a instalação. |
| É apresentado um aviso de certificado no primeiro carregamento | O certificado Let's Encrypt ainda não foi emitido; é apresentado um certificado autoassinado temporário. | Aguarde um minuto e recarregue a página. |
| A aplicação não está acessível por HTTPS após a instalação | Não foi possível emitir o certificado Let's Encrypt, geralmente porque a porta de entrada `80` ou `443` está bloqueada ou porque o nome de host não é resolvido. | Verifique se as portas `80` e `443` estão abertas na entrada e se o nome de host do servidor é resolvido publicamente e, em seguida, reinstale se necessário. |
| Deseja implementar uma segunda aplicação a partir do catálogo | Através do catálogo, é possível implementar apenas uma aplicação. | Reinstale o servidor para implementar outra aplicação ou instale a aplicação adicional manualmente. |
