**Leia este manual na íntegra e com particular atenção, pois poderá ser afetado se pedir a instalação de um sistema operativo num novo servidor dedicado ou a reinstalação do sistema operativo num dos seus servidores dedicados.**

Embora esta página explique a descontinuação dos modelos pessoais para a instalação do sistema operativo (SO) dos servidores dedicados e o respetivo impacto, pode ficar descansado: **não há qualquer perda de funcionalidades**.
Com efeito, após esta descontinuação, poderá continuar a instalar sistemas operativos com o **mesmo nível de personalização que anteriormente**. Além disso, os clientes que utilizam diretamente a API beneficiarão de **uma chamada API mais simples**.

## Objetivo

Esta página fornece informações essenciais sobre o plano de descontinuação dos modelos pessoais para a instalação do SO dos servidores dedicados. Oferece também conselhos úteis para os clientes que utilizam a consola OVHcloud ou a Área de Cliente So you Start ou Kimsufi. Por fim, apresenta as vantagens da nova chamada API em relação à chamada API obsoleta.

## Contexto <a id="context"></a>

A OVHcloud reinventa-se constantemente para adaptar as suas ofertas a uma procura crescente de resiliência. Para atingir este objetivo, **os modelos pessoais de instalação do SO para os servidores dedicados** serão todos suprimidos a **7 de outubro de 2025**.

Esta funcionalidade permitia iniciar tarefas de instalação do SO num servidor dedicado utilizando um modelo pessoal que continha os seguintes elementos:

- sistema operativo a instalar,
- esquema de particionamento,
- configuração do RAID por hardware,
- nome de host,
- chave SSH pública,
- script de pós-instalação.

Para simplificar a instalação dos SO nos servidores dedicados, bem como a comunicação desta alteração, foi criada uma nova chamada API: `POST /dedicated/server/{serviceName}/reinstall`. Esta chamada API sucede à antiga rota: `POST /dedicated/server/{serviceName}/install/start`. A antiga rota permitia lançar uma instalação do SO a partir de um modelo OVHcloud **ou de um modelo pessoal**.

Esta antiga rota, bem como a noção de modelo pessoal, serão descontinuadas. Com efeito, a nova rota apenas permite a instalação do SO a partir de um modelo OVHcloud. Tenha também em conta que a designação "modelo OVHcloud" (*OVHcloud template* em inglês) irá desaparecer progressivamente em favor do termo "sistema operativo" (ou "SO").

A descontinuação dos modelos pessoais será efetuada em 2 etapas:

### Etapa 1: 17 de junho de 2025 <a id="step-1"></a>

- Os clientes deixarão de poder **editar** ou **adicionar** novos modelos pessoais.
- Os clientes que tenham um ou vários modelos pessoais e pelo menos um serviço de servidor dedicado ativo receberão por e-mail informações técnicas detalhadas e personalizadas para migrar os seus pedidos API para a <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nova rota /reinstall</ApiLink>.

### Etapa 2: 7 de outubro de 2025 <a id="step-2"></a>

- Os clientes deixarão de poder aceder aos seus modelos de instalação pessoais.
- Todos os dados relacionados com os modelos de instalação pessoais serão eliminados.

Tenha em conta que os clientes poderão continuar a encontrar os dados no e-mail de 17 de junho de 2025, uma vez que a documentação personalizada enviada foi gerada a partir dos dados dos modelos pessoais à data de 17 de junho de 2025.

## Instruções <a id="instructions"></a>

A secção abaixo contém informações específicas consoante a sua situação: se tem uma conta OVHcloud, So you Start ou Kimsufi e se costuma utilizar a consola OVHcloud ou a API para instalar os SO nos seus servidores dedicados.

### Consola OVHcloud, Área de Cliente So you Start ou Kimsufi <a id="ux"></a>

O botão `Instalar a partir de um dos seus modelos` foi suprimido do assistente de instalação do SO dos servidores dedicados em abril de 2025. Se utilizava este botão, dispõe de 3 possibilidades a longo prazo:

- Continuar a utilizar a interface web (não recomendado se pretende adotar uma estratégia de automatização), o que implica aplicar manualmente todas as personalizações no assistente sempre que efetuar uma instalação do SO.
- Escrever um script que utilize a API (recomendado para as automatizações, mas requer conhecimentos de programação): consulte a secção [API OVHcloud, So you Start ou Kimsufi](#api) abaixo.
- Utilizar a consola API (um bom compromisso): utilize a antiga chamada API até 17 de junho de 2025 e, em seguida, a nova chamada API com os payloads que lhe forem fornecidos.

Embora já possa explorar exemplos e esquemas da <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nova rota API /reinstall na consola API</ApiLink> e ler a [documentação pública](/guides/bare-metal-cloud/dedicated-servers/api-os-installation), apresentamos a seguir uma solução temporária que pode seguir enquanto aguarda os payloads da nova rota API no e-mail de 17 de junho de 2025.

#### Solução alternativa para as contas OVHcloud <a id="ux-ovh"></a>

Tal como indicado na [documentação da API OVHcloud](/guides/manage-and-operate/api/first-steps#ligar-se-às-api-ovhcloud), na <ApiLink>página das API OVHcloud</ApiLink>:

- Clique em `Authentication` no canto superior esquerdo.
- Clique depois em `Login with OVHcloud SSO`.
- Introduza as suas credenciais OVHcloud.
- Clique no botão `Authorize` para autorizar as chamadas API a partir deste site.

![API](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/login.png)

Em seguida, execute a chamada API para lançar uma instalação do SO a partir do seu modelo pessoal:

- Selecione `v1`.
- Escolha a secção `/dedicated/server`.
- Procure a chamada API `POST /dedicated/server/{serviceName}/install/start` (pode utilizar o filtro).
- No campo `serviceName`, introduza o nome do servidor dedicado no qual pretende instalar o SO.
- No campo `REQUEST BODY` ("payload API"), introduza o seguinte conteúdo JSON (neste exemplo, partimos do princípio de que "my-amazing-template" é o nome do modelo pessoal que pretende instalar):

```json
{
  "templateName": "my-amazing-template"
}
```

Se precisar de listar e consultar os detalhes dos seus modelos pessoais, pode fazê-lo na secção `/me`, através das chamadas API de `/me/installationTemplate`.

:::danger
**Executar a chamada API [POST /dedicated/server/\{serviceName\}/install/start](https://api.eu.ovhcloud.com/console/?section=%2Fdedicated%2Fserver&branch=v1#post-/dedicated/server/-serviceName-/install/start) num servidor dedicado irá apagar todos os seus dados. UTILIZE ESTA CHAMADA API COM PRECAUÇÃO.**
:::

Clique depois no botão `Execute` para lançar a tarefa de instalação do SO.

![console API](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/screenshot-api-console-workaround.png)

Pode voltar à página do painel de controlo do servidor dedicado na <ManagerLink to="/">consola OVHcloud</ManagerLink> para acompanhar a progressão da tarefa de instalação do SO.

#### Solução alternativa para as contas So you Start ou Kimsufi <a id="ux-sys-ks"></a>

Abra a [consola API So you Start](https://eu.api.soyoustart.com/console/) ou [a da Kimsufi](https://eu.api.kimsufi.com/console/).

Clique no botão `Login` no canto superior direito e introduza as suas credenciais. Em seguida, clique em `Log in`. Ficará então autenticado na consola API.

- Abra a secção `/dedicated/server`.
- Procure a chamada API `POST /dedicated/server/{serviceName}/install/start`.
- No campo `serviceName`, introduza o nome do servidor dedicado no qual pretende instalar o SO.
- No campo `templateName`, introduza o nome do modelo pessoal que pretende instalar.

Se precisar de listar e consultar os detalhes dos seus modelos pessoais, pode fazê-lo na secção `/me`, através das chamadas API de `/me/installationTemplate`.

:::danger
**Executar a chamada API [POST /dedicated/server/\{serviceName\}/install/start](https://eu.api.soyoustart.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) (ou [esta](https://eu.api.kimsufi.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) para a Kimsufi) num servidor dedicado irá apagar todos os seus dados. UTILIZE ESTA CHAMADA API COM PRECAUÇÃO.**
:::

Clique depois no botão `Execute` para lançar a tarefa de instalação do SO.

Pode voltar à página do painel de controlo do servidor dedicado na [Área de Cliente So you Start](https://eu.soyoustart.com/manager) ou [Kimsufi](https://www.kimsufi.com/fr/manager) para acompanhar a progressão da tarefa de instalação do SO.

### Utilizar as API OVHcloud, So you Start ou Kimsufi <a id="api"></a>

Se utiliza diretamente as chamadas API OVHcloud, So you Start ou Kimsufi para lançar as instalações do SO a partir de um modelo pessoal, pode continuar a utilizar a chamada API `POST /dedicated/server/{serviceName}/install/start` até **7 de outubro de 2025**.
No entanto, tenha em conta que, a partir de **17 de junho de 2025**, deixará de ser possível adicionar ou modificar os seus modelos pessoais.

Embora vá receber um e-mail com todos os detalhes sobre as adaptações dos payloads API a efetuar para utilizar a <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nova chamada API /reinstall</ApiLink>, pode começar desde já a consultar o seu esquema <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>na consola API</ApiLink> (o esquema é o mesmo para a OVHcloud, a [So you Start](https://eu.api.soyoustart.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) e a [Kimsufi](https://eu.api.kimsufi.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST)) e a ler a respetiva [documentação pública](/guides/bare-metal-cloud/dedicated-servers/api-os-installation).

No seu caso, a descontinuação dos modelos pessoais simplifica a instalação dos SO nos servidores dedicados. Com efeito, a <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nova chamada API /reinstall</ApiLink> oferece todas as personalizações possíveis que a antiga chamada API [POST /dedicated/server/\{serviceName\}/install/start](https://api.eu.ovhcloud.com/console/?section=%2Fdedicated%2Fserver&branch=v1#post-/dedicated/server/-serviceName-/install/start) não conseguia fornecer diretamente sem ter de definir previamente um modelo pessoal em [/me/installationTemplate](https://api.eu.ovhcloud.com/console/?section=%2Fme&branch=v1#get-/me/installationTemplate).

A comparação seguinte dá-lhe uma ideia da redução do número de chamadas API proporcionada pela <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nova chamada API /reinstall</ApiLink> no caso de uma personalização complexa que envolva RAID por hardware e um particionamento personalizado: de `4+n` chamadas (em que `n` representa o número de partições definidas no esquema de particionamento) para uma única chamada API.

![Comparação entre a antiga e a nova chamada API](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/api-calls-comparison.png)

Beneficia assim de uma experiência mais fluida e intuitiva.
