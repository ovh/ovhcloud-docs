## Objetivo

Este guia apresenta o painel Anti-DDoS e oferece uma visão geral das contramedidas desencadeadas pela infraestrutura Anti-DDoS da OVHcloud quando é detetada uma atividade de rede maliciosa. Descreve também as proteções adicionais que pode implementar para manter os seus serviços operacionais. Durante os eventos de deteção, estão disponíveis gráficos de tráfego para cada endereço IP, para o ajudar a visualizar a situação.

## Requisitos

- Um serviço OVHcloud exposto num endereço IP público dedicado ([Servidor dedicado](/links/bare-metal/bare-metal), [VPS](/links/bare-metal/vps), [Instância Public Cloud](/links/public-cloud/public-cloud), [Hosted Private Cloud](/links/hosted-private-cloud/vmware), [Additional IP](/links/network/additional-ip), etc.)
- Estar ligado à <ManagerLink to="/beta/#/customer/security/anti-ddos">consola OVHcloud</ManagerLink>.

## Instruções

### Segurança de rede

A infraestrutura Anti-DDoS da OVHcloud é um sistema de defesa distribuído e com várias camadas contra ciberataques. É composta por vários pontos de presença na periferia da rede e por centros de depuração que analisam o tráfego de entrada e limpam o tráfego malicioso. Associada ao [Edge Network Firewall](/guides/bare-metal-cloud/dedicated-servers/firewall-network) e à [proteção Anti-DDoS Game](/guides/bare-metal-cloud/dedicated-servers/firewall-game-ddos), protege uma vasta gama de serviços.

A infraestrutura Anti-DDoS analisa permanentemente o tráfego de entrada (deteção) e, se necessário, redireciona-o para os nossos centros de depuração situados em datacenters de todo o mundo (mitigação). O tráfego é então analisado em profundidade e os pacotes maliciosos são filtrados antes de o tráfego chegar ao seu servidor ou serviço.

Para as cargas de trabalho com tráfego de rede intenso cujo tráfego legítimo se pode assemelhar a um ataque, como os servidores VPN, os servidores de jogos ou os nós Solana, pode aplicar um perfil de tráfego de rede aos seus endereços IP. A definição de perfis apenas afina a forma como o seu tráfego é analisado e mitigado: os seus serviços continuam protegidos. Para mais informações, consulte o nosso guia sobre a [definição de perfis Anti-DDoS](/guides/bare-metal-cloud/dedicated-servers/anti-ddos-vac-profiling).

#### O que acontece quando um ataque atinge o endereço IP do meu serviço?

Sempre que é detetado um ataque num endereço IP do seu serviço, é avisado por e-mail de que o respetivo tráfego foi redirecionado através da infraestrutura Anti-DDoS. Também pode acompanhar estes períodos, com detalhes adicionais, no painel Anti-DDoS.

Durante a fase beta, abra a <ManagerLink to="/beta/#/customer/security/anti-ddos">consola OVHcloud</ManagerLink> através do botão <code className="action">Descobrir a consola &gt;BETA_</code> no canto superior direito. Quando ocorre um ataque, este aparece no **Painel Anti-DDoS** (<code className="action">Segurança</code> > <code className="action">Anti-DDoS</code>) e o contador **Ataques em andamento** do endereço IP visado aumenta. O estado de **Mitigação DDoS** de cada endereço IP é indicado na respetiva página: na página **Endereços IP**, clique no endereço IP e consulte a secção **Segurança de rede** do separador <code className="action">Visão geral</code>.

:::info
Para saber como a OVHcloud mitiga os ataques DDoS, consulte a nossa página sobre a [mitigação de ataques DDoS](/links/security/mitigation).

:::

:::warning
A lógica de proteção baseia-se nos endereços IP públicos associados a um servidor ou a um serviço. Por conseguinte, as estatísticas e os gráficos são calculados e apresentados por endereço IP.

:::

### Estado Anti-DDoS dos seus endereços IP

Durante a fase beta, abra a <ManagerLink to="/beta/#/network/ip">consola OVHcloud</ManagerLink> através do botão <code className="action">Descobrir a consola &gt;BETA_</code> no canto superior direito. A página **Endereços IP** lista os seus endereços IP públicos. As colunas **Alerta IP**, **Edge Firewall** e **Game Firewall** desta página indicam o estado de cada endereço IP. O estado Anti-DDoS de cada endereço IP é indicado na respetiva página.

- Para consultar o estado Anti-DDoS de um endereço IP, clique nele na lista. No separador <code className="action">Visão geral</code>, a secção **Segurança de rede** indica o seu estado de **Mitigação DDoS**, **Automático**: a infraestrutura Anti-DDoS protege automaticamente este endereço IP caso seja detetado um ataque.

    A mesma secção indica o estado **Anti-Spam** e **Anti-Hack** do endereço IP, bem como uma ligação <code className="action">Painel de controlo Anti-DDoS</code> para o respetivo tráfego.

- A coluna **Edge Firewall** indica o estado do Edge Network Firewall:
    - **Ativado** - O Edge Network Firewall **filtra** o tráfego de entrada para este endereço IP.
    - **Desativado** - O tráfego só passa pelo Edge Network Firewall quando é detetado um ataque. A firewall é então ativada automaticamente.

    Para configurar as respetivas regras, clique no estado na coluna, ou clique no endereço IP e abra o separador <code className="action">Edge Firewall</code>.

- A coluna **Game Firewall** (apenas para os [servidores dedicados OVHcloud **Game**](/links/bare-metal/game)) pode indicar:
    - **Disponível** - O Game Firewall está disponível, mas ainda não está configurado. Configure as suas regras de proteção de jogos para que se apliquem a este endereço IP.
    - **Configurado** - O Game Firewall está configurado para este endereço IP.
    - **—** - O Game Firewall não está disponível para este endereço IP, o que significa que este não está associado a um servidor de uma gama compatível.

    Para o configurar, clique no endereço IP e abra o separador <code className="action">Game Firewall</code>.

- A coluna **Alerta IP** pode indicar **IP bloqueado (anti-hack)** ou **IP bloqueado (anti-spam)**.

### Painel Anti-DDoS

Durante a fase beta, abra a <ManagerLink to="/beta/#/customer/security/anti-ddos">consola OVHcloud</ManagerLink> através do botão <code className="action">Descobrir a consola &gt;BETA_</code> no canto superior direito e aceda a <code className="action">Segurança</code> > <code className="action">Anti-DDoS</code>. O **Painel Anti-DDoS** lista os ataques passados e em curso que visam os seus endereços IP. Pode filtrar a lista por serviço e por período (<code className="action">Dia</code>, <code className="action">Semana</code>, <code className="action">Mes</code> ou <code className="action">Ano</code>).

A tabela contém as seguintes colunas:

- **Data de deteção** - Carimbo de data/hora da primeira deteção do ataque.
- **Data de término** - Carimbo de data/hora do fim da mitigação pelo centro de depuração.
- **IP de destino** - O endereço IP visado pelo ataque.
- **Vetores de ataque** - Os tipos de ataques detetados, como os ataques UDP ou TCP.

**O período de retenção do registo de ataques é de um ano.**

:::warning
Os endereços IP de origem dos eventos detetados não são apresentados. Estes são geralmente falsificados (*spoofed*): um ataque DDoS pode apresentar outras origens que não aquelas de onde realmente provém. Estas informações seriam, por isso, enganadoras ou inutilizáveis.

:::

Clique num ataque da lista para abrir o endereço IP visado. O separador <code className="action">Visão geral</code> resume os ataques dos últimos 60 dias: ataques totais, em curso e mitigados, e ataques por tipo. O separador <code className="action">Trafego</code> apresenta um gráfico do tráfego para o seu endereço IP durante os eventos de deteção, em bits por segundo (**BPS**) ou em pacotes por segundo (**PPS**). Fora destes eventos, o separador está vazio.

O gráfico apresenta o tráfego **Legitimo** transmitido ao seu endereço IP e o tráfego **Filtrado** rejeitado durante os ataques. São também apresentadas estatísticas de mitigação básicas para o período selecionado, como o número de eventos, os pacotes rejeitados, a largura de banda limpa e o número de ataques detetados.

**O período de retenção dos dados de tráfego é de 60 dias.**

## FAQ

### Porque é que alguns ataques não são visíveis no painel Anti-DDoS?

Consoante a natureza de um ataque, podem ser tomadas diferentes medidas para eliminar a ameaça da melhor forma. Em ambos os casos, os ataques são mitigados o mais perto possível da sua origem:

- Quando um ataque chega à rede OVHcloud (**externo**), o respetivo tráfego é redirecionado para os centros de depuração Anti-DDoS para ser limpo: o ataque é, por isso, visível no painel.
- Os ataques provenientes do interior da rede OVHcloud (**internos**) são geridos pelas nossas equipas de segurança. A mitigação consiste então em bloquear a origem do ataque, o que não é reportado pelos sistemas da infraestrutura Anti-DDoS.

### Nenhum ataque aparece no painel Anti-DDoS. Isto é normal?

Sim. Significa que nenhum ataque suspeito visou os seus endereços IP públicos durante o período selecionado.

### Porque é que não são apresentados gráficos nem dados para um endereço IP que introduzo?

Estes dados só estão disponíveis para os endereços IP públicos durante os eventos de deteção automática da infraestrutura Anti-DDoS, quando o tráfego é redirecionado através de um centro de depuração.

### Porque é que o gráfico de tráfego não está disponível para alguns ataques do painel Anti-DDoS?

Os dados de tráfego só estão disponíveis para os últimos 60 dias, ao passo que pode consultar os ataques do último ano.

### Um ataque ao meu serviço persiste. Como posso proteger melhor o meu servidor?

Alguns ataques podem ser tão específicos que a infraestrutura Anti-DDoS não consegue detetá-los e limpá-los automaticamente. Nesse caso, a firewall configurada no seu servidor é a sua melhor opção. Recomendamos também que transfira algumas regras de firewall do seu servidor para a periferia da nossa rede, com o Edge Network Firewall. Para saber como configurar as respetivas regras, consulte o nosso guia sobre o [Edge Network Firewall](/guides/bare-metal-cloud/dedicated-servers/firewall-network).

Se os ataques não forem completamente mitigados, também pode tornar a deteção mais agressiva para os seus endereços IP, aplicando-lhes um perfil de tráfego de rede com uma sensibilidade mais elevada. Para mais informações, consulte o nosso guia sobre a [definição de perfis Anti-DDoS](/guides/bare-metal-cloud/dedicated-servers/anti-ddos-vac-profiling).

### O meu serviço está a ser atacado e tenho problemas no meu servidor. Que mais posso fazer?

A infraestrutura Anti-DDoS foi concebida para proteger da forma mais eficaz possível uma vasta gama de serviços. Em alguns casos específicos, pode ser necessário um ajuste adicional, por exemplo para a adaptar à natureza ou à dimensão da sua aplicação.

Pode ajustar a proteção por si próprio com a definição de perfis Anti-DDoS, atualmente em fase beta: aplique aos seus endereços IP um perfil de tráfego de rede e um nível de sensibilidade adaptados à sua carga de trabalho. Para mais informações, consulte o nosso guia sobre a [definição de perfis Anti-DDoS](/guides/bare-metal-cloud/dedicated-servers/anti-ddos-vac-profiling).

Se nenhum perfil corresponder à sua carga de trabalho, ou se o problema persistir, aceda ao nosso [Centro de Ajuda](/links/support-contact) e procure a ação adequada na categoria "Ataque de rede e/ou Anti-DDoS".

#### Fornecer informações à OVHcloud

Sempre que o nosso sistema Anti-DDoS precisar de ser ajustado, deve fornecer-nos as seguintes informações para que possamos compreender o seu caso e ajudá-lo:

- Serviço alojado no servidor em causa
- Data e hora de início do ataque
- Data e hora de fim do ataque
- Endereço(s) IP em causa
- Serviço, protocolo e porta utilizados pelo serviço em causa
- Dimensão do serviço (XS: 1-10, S: 10-100, M: 100-1k, L: 1-10k, XL: 10-100k, XXL: mais de 100k clientes ligados)
- Outros serviços alojados no servidor
- Outras portas utilizadas no servidor
- Existem outros serviços em endereços IP distintos: Sim/Não
- Em caso afirmativo, quais
- Há tráfego legítimo a ser rejeitado: Sim/Não
- A ligação ao servidor foi perdida: Sim/Não
- Que tipo de tráfego legítimo está a ser rejeitado

:::info
Em alguns casos, poderemos pedir-lhe uma captura de tráfego adicional.

Para realizar esta captura, execute o seguinte comando em Linux:

```bash
tcpdump -w capture-ovh -c 100000 port not ssh
```

Se utilizar Windows, utilize o [Wireshark](https://www.wireshark.org/) e capture 100 000 pacotes.

Pode anexar o ficheiro ao seu ticket de suporte ou carregá-lo na nossa solução de partilha de ficheiros, seguindo o guia "[Partilhar ficheiros com a ferramenta Plik](/guides/account-and-service-management/account-information/use-plik)", e depois partilhar a ligação do ficheiro carregado no seu ticket de suporte.

:::
