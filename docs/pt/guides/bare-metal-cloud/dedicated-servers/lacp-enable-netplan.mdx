## Objetivo

A tecnologia LACP (Link Aggregation Control Protocol) foi concebida para aumentar a disponibilidade do seu servidor e melhorar a eficiência das suas ligações de rede. Pode agregar as suas placas de rede e tornar as suas ligações de rede redundantes. Isto significa que, se uma ligação falhar, o tráfego é automaticamente redirecionado para outra ligação disponível. Graças à agregação, a largura de banda disponível é também duplicada.

**Este guia explica como agregar as suas interfaces para as utilizar na agregação de ligações em Debian 12 ou mais recente / Ubuntu 24.04 ou mais recente (configuração Netplan).**

:::warning
Embora as imagens Debian 12 (ou mais recentes) fornecidas pela OVHcloud utilizem `Netplan` por predefinição, existem duas exceções importantes em que é utilizado `ifupdown` (/etc/network/interfaces):

- **Modo rescue**: Embora seja baseado em Debian 12, o modo rescue utiliza a ferramenta `ifupdown`.
- **Imagens personalizadas**: As instalações Debian efetuadas com a sua própria imagem podem continuar a utilizar `ifupdown` para a configuração de rede.

Se pretender configurar a agregação de ligações em modo rescue, ou num SO personalizado que utilize `ifupdown`, consulte antes [este guia](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-ifupdown).

:::

## Instruções

:::info
Os valores (endereços MAC, endereços IP, etc.) indicados nas configurações e exemplos abaixo são apenas exemplos. Deve, naturalmente, substituí-los pelos seus próprios valores.

:::


### Obtenção dos endereços MAC

Abra o separador <code className="action">Connectivity</code> do seu servidor na consola OVHcloud e anote os endereços MAC de cada interface (pública/privada). Estes aparecem em **Aggregated interface composition**, nas secções **Public interface** e **Interface privada (vRack)**, com os nomes **NIC #1** e **NIC #2**.

:::info
A interface **pública principal** gere a conectividade pública na configuração predefinida. O seu endereço MAC corresponde ao valor `aggregationFallback` da interface `public`, que pode obter com a seguinte rota de API:

<Api version="v1" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/networking"} />

:::


Agora que sabe quais os endereços MAC associados a cada tipo (público/privado) de interface, deve obter os nomes das interfaces.

### Obtenção dos nomes das interfaces

:::info
Se perder a ligação de rede ao seu servidor, siga os passos "**Abrir um KVM**" [deste guia](/guides/bare-metal-cloud/dedicated-servers/ipmi).

:::


Para obter os nomes das interfaces, execute o seguinte comando:

```bash
ip a
```

:::info
Este comando irá apresentar várias interfaces. Se tiver dificuldade em determinar quais são as suas interfaces físicas, o endereço IP público do servidor continua associado por predefinição à primeira interface.

:::

Depois de determinar os nomes das suas interfaces, pode configurar a agregação de interfaces no sistema operativo.

### Configuração de IP fixo

Substitua o conteúdo de `/etc/netplan/50-cloud-init.yaml` pelo seguinte:

```yaml
network:
    version: 2
    ethernets:
        ens22f0np0:
            match:
                macaddress: a1:b2:c3:d4:e5:c6
        ens22f1np1:
            match:
                macaddress: a1:b2:c3:d4:e5:c7
        ens33f0np0:
            match:
                macaddress: a1:b2:c3:d4:e5:d6
        ens33f1np1:
            match:
                macaddress: a1:b2:c3:d4:e5:d7
    bonds:
        bond0:
            # Endereço MAC da interface pública principal do servidor
            macaddress: a1:b2:c3:d4:e5:c6
            accept-ra: false
            addresses:
                - 203.0.113.1/32
                - 2001:db8:1:1b00:203:0:112:0/56
            routes:
                - on-link: true
                  to: default
                  via: 100.64.0.1
                - on-link: true
                  to: default
                  via: fe80::1
            nameservers:
                addresses:
                - 213.186.33.99
                - 2001:41d0:3:163::1
            interfaces:
                - ens22f0np0
                - ens22f1np1
            parameters:
                mode: 802.3ad
                lacp-rate: fast
                transmit-hash-policy: layer3+4
        # Opcional: configuração de um agregado privado
        bond1:
            # Endereço MAC da primeira interface privada
            macaddress: a1:b2:c3:d4:e5:d6
            accept-ra: false
            interfaces:
                - ens33f0np0
                - ens33f1np1
            parameters:
                mode: 802.3ad
                lacp-rate: fast
                transmit-hash-policy: layer3+4
```

### Aplicação da configuração

:::info
O comando `netplan try` não pode ser utilizado na configuração de agregados.

:::


Aplique a configuração com o seguinte comando:

```bash
sudo netplan apply
```

Os agregados podem demorar alguns segundos a ficar operacionais.
