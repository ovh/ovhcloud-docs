## Objetivo

El servicio NAS-HA de OVHcloud le permite gestionar el almacenamiento de archivos al que se puede acceder desde una red. 

**Esta guía explica cómo utilizar un servicio NAS-HA a través de la API de OVHcloud.**

## Requisitos

- Un servicio [NAS-HA de OVHcloud](https://www.ovhcloud.com/es-es/storage-solutions/nas-ha/)
- Consulte nuestra guía de [primeros pasos con la API de OVHcloud](/guides/manage-and-operate/api/first-steps) para familiarizarse con la APIv6 de OVHcloud.

## Procedimiento

Todas las rutas API de esta guía están disponibles en la <ApiLink section="/dedicated/nasha">sección */dedicated/nasha*</ApiLink> de la consola API.

:::info
Al utilizar la API, todos los campos marcados con asterisco (\*) son obligatorios.
:::


### Obtener información sobre el servicio

Todos los servicios activos se pueden recuperar utilizando la siguiente ruta:

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha"} />


### Creación de una partition

Utilice la siguiente ruta para crear una nueva partition:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Nombre interno del servicio NAS |
| `partitionDescription` |  | Descripción opcional |
| `partitionName` | Yes | Un nombre para la partition |
| `protocol` | Yes | *NFS*, *CIFS* o *NFS_CIFS* para ambos |
| `size` | Yes | El tamaño de la partition |

Elija `NFS` como protocolo y un tamaño de `10` Gigabytes, por ejemplo.

### Añadir un registro ACL para acceder a la partition

:::warning
El acceso se denegará por defecto, salvo que se conceda a través del ACL. Solo es posible añadir las direcciones IP asociadas a los servicios de OVHcloud.
:::


Puede comprobar las direcciones IP que pueden acceder a través de las siguientes llamadas a la API:

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/authorizableBlocks"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Nombre interno del servicio NAS |
| `partitionName` | Yes | Nombre de la partition |

Para crear una nueva entrada ACL que le permita conectarse a su partition, utilice la siguiente ruta:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/access"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Nombre interno del servicio NAS-HA |
| `partitionName` | Yes | Nombre de la partition |
| `ip` | Yes | La dirección IP o rango al que debe concederse el acceso |
| `type` | Yes | Tipo de acceso ACL para este registro: *readonly* o *readwrite* |

:::info
Utilice la notación CIDR para los rangos IP, por ejemplo: 192.0.2.0/24.
:::


### Crear un snapshot manual

Para añadir un snapshot manual, utilice la siguiente ruta:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/customSnapshot"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Nombre interno del servicio NAS-HA |
| `partitionName` | Yes | Nombre de la partition |
| `expiration` |  | Fecha de expiración opcional, por ejemplo: 2022-06-24 (ISO 8601) |
| `name` | Yes | Nombre del snapshot |

### Eliminación de una partition

Utilice la siguiente ruta para eliminar una partition:

<Api version="v1" section="/dedicated/nasha" method="DELETE" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | Nombre interno del servicio NAS-HA |
| `partitionName` | Yes | Nombre de la partition |

## Utilizar la API con un NAS-HA privado (Beta) <a name="using-the-api-with-a-private-nas-ha-beta"></a>

:::info
El NAS-HA privado se encuentra actualmente en fase beta. Sus rutas de la API son diferentes de las descritas anteriormente: están disponibles en la <ApiLink section="/storage">sección */storage*</ApiLink> de la consola API, donde las particiones se denominan **shares**. Esta sección puede evolucionar con el producto.

:::


Para conectar un NAS-HA privado a su red privada vRack, consulte nuestra guía "[HA-NAS - Private network configuration (Beta)](/guides/storage-and-backup/file-storage/ha-nas/nas-network-config)".

### Obtener información sobre el servicio (Beta)

Para listar sus servicios NAS-HA privados, utilice la siguiente ruta:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha"} regions={["eu"]} />


El campo `id` de la respuesta es el `serviceName` que utilizan las rutas siguientes.

Para obtener el `shareId` de sus particiones (el campo `id` de la respuesta), utilice la siguiente ruta:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | El ID de su servicio NAS-HA privado |

### Añadir un registro ACL para acceder a la partición (Beta)

:::warning
El acceso se deniega por defecto, salvo que se conceda a través de la ACL.
:::


Para crear una nueva entrada ACL que le permita conectarse a su partición, utilice la siguiente ruta:

<Api version="v1" section="/storage" method="POST" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/acl"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | El ID de su servicio NAS-HA privado |
| `shareId` | Yes | El ID de la partición |
| `accessLevel` | Yes | Nivel de acceso ACL: *rw* (lectura y escritura) o *ro* (solo lectura) |
| `accessTo` | Yes | La dirección IPv4 o el rango al que debe concederse el acceso |

:::info
Utilice la notación CIDR para los rangos de IP, por ejemplo: 10.235.0.0/24.
:::


### Obtener el punto de montaje (Beta)

Para obtener el `accessPathId` de las rutas de acceso de una partición, utilice la siguiente ruta:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/accessPath"} regions={["eu"]} />


A continuación, obtenga los detalles de una ruta de acceso con la siguiente ruta:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/accessPath/\{accessPathId\}"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | El ID de su servicio NAS-HA privado |
| `shareId` | Yes | El ID de la partición |
| `accessPathId` | Yes | El ID de la ruta de acceso |

El campo `path` de la respuesta contiene la ruta de exportación que debe utilizar en su comando de montaje. Si una partición tiene varias rutas de acceso, utilice aquella cuyo campo `preferred` sea `true`.
