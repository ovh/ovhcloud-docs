## Objetivo

**Esta guía explica cómo funciona IAM en su Hosted Private Cloud - VMware on OVHcloud**.

## Procedimiento

:::info
Por el momento, no es posible beneficiarse de las funcionalidades IAM en las soluciones Hosted Private Cloud VMware vSphere con certificación PCI-DSS o HDS, ni en las soluciones cualificadas SecNumCloud.
Lo mismo ocurre con los entornos gestionados con NSX activado y con Public VCF as-a-Service. Los equipos de OVHcloud están trabajando en la adaptación de estas tecnologías.

:::


### ¿Cómo funcionan IAM y Hosted Private Cloud - VMware on OVHcloud?

La activación de OVHcloud IAM delega la gestión del acceso al servicio, los roles asociados y sus permisos en vSphere. Puede gestionar los accesos y las políticas desde la sección IAM de la consola de OVHcloud.

Para simplificar:

- Un rol IAM sustituye a un usuario local de vSphere en el Hosted Private Cloud - VMware on OVHcloud.
- Una política permite asociar su identidad de OVHcloud a este rol.
- Los roles IAM funcionan mediante grupos de VMware vSphere.

Estos son los elementos necesarios para que IAM funcione correctamente con Hosted Private Cloud - VMware on OVHcloud:

- Productos: **vSphere/VMware (Hosted Private Cloud, service pack)**.
- Recursos: **PCC-XXX**.
- Acciones: **Gestionadas o manuales**.
- Usuarios: **Usuario 1/2/3**.

## FAQ

### ¿Cuáles son las limitaciones de IAM con Hosted Private Cloud - VMware on OVHcloud?

:::info
Por el momento, un rol IAM de vSphere no puede gestionarse mediante grupos de permisos gestionados.

:::


IAM se encuentra actualmente en versión BETA en la plataforma de OVHcloud. Las infraestructuras con opciones de seguridad reforzada o un servicio certificado (alojamiento de datos de salud (HDS), alojamiento de datos bancarios (PCI-DSS) o SecNumCloud (SNC)) no pueden utilizar OVHcloud IAM por el momento.

Un rol IAM solo puede añadirse mediante acciones manuales en una política global (acción: assumerole -> role_iam). Para más información, consulte la guía "[IAM para VMware on OVHcloud - Cómo asociar un rol de vSphere a una política IAM](/guides/hosted-private-cloud/powered-by-vmware/vmware-iam-role-policy)".

### ¿Cómo accedo a la delegación de permisos de vSphere con IAM?

Las **identidades asociadas**, los **recursos**, los **grupos de recursos** y sus permisos en las políticas se gestionan desde la consola de OVHcloud.

En la sección <code className="action">Gestión de identidades y accesos</code> del menú lateral, haga clic en <ManagerLink console to="/#/customer/iam/identities/users">Identidades</ManagerLink> o <ManagerLink console to="/#/customer/iam/policies/my-policies">Políticas</ManagerLink>.

Puede gestionar los roles IAM y los usuarios locales de vSphere desde la entrada <code className="action">Managed VMware vSphere</code>, en **Productos** del menú lateral.

Seleccione su infraestructura y abra la pestaña <code className="action">Usuarios</code>.

### ¿Cuántos roles hay disponibles por defecto?

Al activar IAM en su Hosted Private Cloud - VMware on OVHcloud, dispone de 2 roles activos por defecto.

### ¿Qué es un rol IAM de vSphere vinculado a una política?

Cada rol IAM de su Hosted Private Cloud - VMware on OVHcloud corresponde a una acción escrita con el formato `pccVMware:vSphere:assumeRole?role_name` en una política IAM.

Por ejemplo, para el rol **iam-admin** de un Dedicated Cloud, la acción es: `pccVMware:vSphere:assumeRole?iam-admin.`.

Un rol puede considerarse como una plantilla de usuario con la que se definen los permisos PCC (vSphere). Después, estos permisos (este rol) se aplican a un usuario en su consola de OVHcloud (IAM, si ha vinculado su usuario a una política).
