## Objetivo

Para empezar a utilizar la solución Content Delivery Network (CDN) de OVHcloud, es necesario declarar los dominios desde la consola de OVHcloud y configurar ciertos parámetros para poder utilizar este servicio de manera óptima.

**Esta guía explica qué acciones debe realizar en la consola de OVHcloud para poder utilizar la CDN de OVHcloud e incluye buenas prácticas de uso.**

## Requisitos

- Tener contratada la solución [CDN de OVHcloud](https://www.ovhcloud.com/es-es/network/cdn/).
- Tener acceso a la gestión de la zona DNS del dominio.

[[cpnav:network-cdn-console]]

## Procedimiento

### Añadir el dominio a la CDN

En primer lugar, es necesario añadir el subdominio a la CDN para que esta última acepte las peticiones HTTP(S) relativas al mismo.

Abra la pestaña <code className="action">Dominios</code> y haga clic en <code className="action">Añadir dominio</code>. Se abrirá la página **Configuración guiada de un dominio**, que le guiará en cuatro pasos:

<img className="thumbnail" alt="Pestaña Dominios de una CDN con el botón Añadir dominio" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/domains-tab.png" loading="lazy" />

1. **Nombre de dominio**: introduzca el subdominio que quiera servir a través de la CDN, en forma de nombre de dominio completo (por ejemplo, `www.example.com`), y haga clic en <code className="action">Siguiente</code>.
2. **Origen (IPv4)**: introduzca la dirección IPv4 del servidor de origen que aloja sus archivos (su *backend*) y haga clic en <code className="action">Siguiente</code>.
3. **Certificado SSL**: seleccione **Let's Encrypt** para obtener automáticamente un certificado HTTPS gratuito, o **Sin SSL** para servir el dominio únicamente en HTTP (podrá añadir un certificado más adelante). Este paso no aparece si su CDN ya dispone de un certificado. Para más información, consulte nuestra guía sobre el [funcionamiento del certificado SSL en la CDN](/guides/network/cdn/cdn-infrastructure-ssl-certificate).
4. **Confirmar y desplegar**: compruebe el resumen y haga clic en <code className="action">Desplegar</code>.

<img className="thumbnail" alt="Configuración guiada de un dominio, paso Nombre de dominio" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/guided-setup-step1.png" loading="lazy" />

A continuación, la página muestra el progreso del despliegue: creación del dominio, configuración del origen y, si lo ha elegido, aprovisionamiento del certificado SSL. Una vez finalizado el despliegue, indica el destino al que debe apuntar el registro CNAME de su dominio (con el formato `<su dominio>.cdn.ovhcloud.com`, por ejemplo `www.example.com.cdn.ovhcloud.com`). Copie este destino, ya que lo necesitará en el siguiente paso. Haga clic en <code className="action">Finalizado</code>. El dominio aparecerá entonces en la pestaña <code className="action">Dominios</code>, con su origen y su estado, y podrá empezar a configurarlo.

<img className="thumbnail" alt="Final de la configuración guiada de un dominio, con el destino CNAME" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/guided-setup-cname.png" loading="lazy" />

Para que las peticiones pasen correctamente por nuestra infraestructura CDN, debe modificar la zona DNS del subdominio para que un registro CNAME apunte a este destino.

:::warning
La creación del registro CNAME es importante, ya que permite que la función *bypass* funcione correctamente. Si utiliza un registro de tipo A, el servicio CDN funcionará, pero no podrá disfrutar de la función *bypass*.

:::

Si la zona DNS de su dominio está gestionada por OVHcloud, añada este registro CNAME a la zona desde la consola de OVHcloud, adaptando el subdominio a su configuración: indique su subdominio (por ejemplo, `cdn`) y, como destino, el valor mostrado al final de la configuración guiada. Para saber cómo añadir un registro, consulte nuestra guía [Editar una zona DNS de OVHcloud](/guides/web-cloud/domains/dns-zone-edit).

 

### Comprobar que un archivo está en caché
Para comprobar que un archivo esté almacenado en la caché, ejecute el siguiente comando:

```sh
curl -I http://sub.dominio/
```

Obtendrá un resultado similar al siguiente:

```bash
HTTP/1.1 200 OK
Date: Tue, 09 Jan 2018 10:30:57 GMT
Content-Type: text/plain
Last-Modified: Fri, 29 Dec 2017 13:30:42 GMT
ETag: W/"(5a464382-4ddf"
Expires: Wed, 09 Jan 2019 10:30:58 GMT
X-IPLB-Instance: 5905
Vary: Accept-Encoding
X-CDN-Pop: rbx1
X-CDN-Pop-IP: 51.254.41.128/26
X-Cacheable: Matched cache
Accept-Ranges: bytes
Connection: keep-alive
```

Si el archivo se envía desde la caché, podrá ver **Matched cache** en la respuesta del comando.

También puede ver el punto de presencia (PoP) desde el que se envía el archivo (**rbx1** en el ejemplo).

Esta información también puede obtenerse utilizando el navegador. Por ejemplo, en Firefox se encuentra en las herramientas de desarrollo, seleccionando <code className="action">Red</code> (atajo de teclado: F12). Al hacer clic en el archivo que quiera comprobar, podrá ver la respuesta HTTP y sus cabeceras.

### Razones para utilizar un subdominio específico para la CDN en lugar del dominio principal

No es posible añadir un registro CNAME a un dominio principal. Se trata de una limitación impuesta por las normas RFC, que no es posible eludir a nivel de la zona DNS.

Además, atribuir un dominio específico a los archivos que quiera almacenar en caché le facilitará la gestión tanto de los archivos como de la facturación:

- **Archivos:** Solo se guardarán en caché los archivos cuya petición se envíe desde el subdominio. De este modo, podrá conservar en el dominio principal los archivos dinámicos o aquellos que no quiera guardar en caché. Por otro lado, así también podrá determinar rápidamente el origen de un problema de visualización en su sitio web.
- **Facturación:** Todo el tráfico (almacenado en caché o no) que pasa por la CDN se factura. De esta forma es posible limitar el número de peticiones no útiles que se realizan hacia la CDN para optimizar su uso.

### Otras acciones necesarias para configurar un nuevo subdominio en la CDN

Si quiere configurar un nuevo subdominio para utilizar la CDN, seguramente deberá modificar determinados parámetros en el sitio web y el servicio web.

En primer lugar, asegúrese de que su servicio web responde correctamente al subdominio. Para ello, configure un *vhost* para dicho dominio, ya sea con su propia carpeta de destino o como alias de otro dominio.

Si el dominio responde correctamente en su servicio web, solo tendrá que editar el código HTML para modificar el origen de los archivos que deben pasar por la CDN y, por último, asegurarse de que reciben las peticiones enviadas a través del subdominio.
