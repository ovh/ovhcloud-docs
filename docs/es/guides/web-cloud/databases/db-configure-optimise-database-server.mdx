## Objetivo

Los servidores de bases de datos Web Cloud Databases le permiten modificar los parámetros globales de su servidor. También puede consultar la actividad de su servidor.

**Esta guía explica cómo configurar y optimizar su servidor de bases de datos.**

## Requisitos

- Disponer de una [instancia Web Cloud Databases](/links/web/databases) (incluida en un plan de [alojamiento web](/links/web/hosting) Performance, Agency, Agency Plus o Agency Max).

[[cpnav:web-cloud-databases]]

    |Información|Detalles|
    |---|---|
    |Estado|Muestra si la instancia está iniciada, reiniciándose o suspendida. Su instancia debe estar iniciada para poder realizar acciones en ella.|

Si no sabe si el sistema utilizado es el correcto, tenga en cuenta que el más habitual es "MySQL", aunque existen otros (PostgreSQL, MariaDB, Valkey). Por ejemplo, si su sitio web es un WordPress, un sistema MySQL es perfectamente adecuado. Asegúrese de que su sitio web es compatible con la versión elegida.|
    |Región|Muestra la región del centro de datos en el que se ha creado la instancia. Asegúrese de que la región de su instancia sea la misma que la del alojamiento web de OVHcloud en el que esté, o vaya a estar, alojado su sitio web.|
    |Host|Muestra el servidor de OVHcloud en el que se ha creado su instancia. Se trata de una información inherente a la infraestructura de OVHcloud y puede utilizarse en nuestras comunicaciones relacionadas con las [incidencias de OVHcloud](https://web-cloud.status-ovhcloud.com/).|

    |RAM|Muestra la memoria RAM disponible para su instancia, así como los posibles desbordamientos de memoria. Su servidor de bases de datos dispone de recursos dedicados y garantizados: su memoria RAM. Si lo necesita, puede ampliarla con el enlace **Pedir más RAM**.|
    |Cuota de almacenamiento|Muestra el espacio ocupado por sus datos respecto al espacio incluido en su plan.|

    :::warning
    Le desaconsejamos firmemente marcar la casilla **Permitir acceso al servicio** para autorizar el intervalo de direcciones IP `0.0.0.0/0` a acceder a sus bases de datos.

    En efecto, esto permitiría autorizar el acceso a sus bases de datos a todas las direcciones IPv4 existentes.

Para desvincular una solución Web Cloud Databases asociada a un alojamiento web **Performance**, **Agency**, **Agency Plus** o **Agency Max**, consulte nuestra guía "[Desvincular mi solución Web Cloud Databases de un alojamiento web](/guides/web-cloud/databases/db-detach-from-web-hosting)".

**Esta acción es irreversible y la solución Web Cloud Databases se facturará de forma independiente de su alojamiento web Performance, Agency, Agency Plus o Agency Max.**

:::

<summary>Instancia MySQL y MariaDB</summary>

Haga clic en las pestañas de abajo para ver cada uno de los **4** pasos.

<Tabs>
  <Tab label="Paso 1">
    Acceda a la página <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink> y seleccione la instancia correspondiente.

    <img className="thumbnail" alt="Página Web Cloud DB y lista de las instancias de la cuenta" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />
  </Tab>
  <Tab label="Paso 2">
    Haga clic en la pestaña <code className="action">Configuración</code>.

    <img className="thumbnail" alt="Pestaña Configuración de una instancia Web Cloud DB" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/configuration/tab.png" loading="lazy" />
  </Tab>
  <Tab label="Paso 3">
    La configuración actualmente establecida para su base de datos se reparte en tres secciones: **Conexiones**, **Rendimiento** y **Comportamiento del motor**. Haga clic en <code className="action">Modificar</code> en la parte inferior de la sección que contiene el parámetro que quiera cambiar.

    <img className="thumbnail" alt="Secciones de configuración de MySQL con el enlace Modificar" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/configuration/groups.png" loading="lazy" />

    La siguiente tabla detalla cada parámetro modificable, así como los valores que puede asignarle.

    |Parámetro|Descripción|Valores configurables|
    |---|---|---|
    |`max_allowed_packet`|Tamaño máximo de los paquetes.|De 1 a 64 MB|
    |`max_user_connections`|Número de conexiones simultáneas autorizadas por usuario.|De 50 a 200|
    |`autocommit`|Define si las peticiones se validan automáticamente (committed) o no.|ON u OFF|
    |`interactive_timeout`|Tiempo (en segundos) que el servidor espera actividad en una conexión interactiva antes de cerrarla.|De 60 a 28800 segundos|
    |`innodb_buffer_pool_size`|Tamaño de la memoria intermedia, expresado en megabytes.|Valores propuestos en la lista (de 128 MB a 2048 MB)|
    |`max_connections`|Número de conexiones simultáneas autorizadas en el servidor de bases de datos.|De 100 a 200|
    |`wait_timeout`|Tiempo (en segundos) que el servidor espera actividad en una conexión no interactiva antes de cerrarla.|De 60 a 28800 segundos|
    |`event_scheduler`|Permite activar la ejecución de consultas programadas directamente en el servidor MySQL.|ON u OFF|
    |`sql_mode`|Afecta a la sintaxis SQL soportada y a las verificaciones de validación de datos realizadas por MySQL/MariaDB.|Consulte los modos predeterminados que figuran a continuación|
    |`long_query_time`|Duración (en segundos) a partir de la cual una consulta se registra como lenta.|1, 2, 5, 10 o 60 segundos|
    |`local_infile`|Autoriza o rechaza la carga de datos locales por parte de los clientes.|ON u OFF|
    |`log_bin_trust_function_creators`|Permite a los usuarios sin privilegios crear funciones almacenadas cuando el registro binario está activado.|ON u OFF|

    :::info
    Cuando aparece un error en su sitio web que indica `Too many connections`, se debe a que se ha superado el número de conexiones simultáneas en su servidor de bases de datos. Puede aumentar la variable `max_connections` si no está al máximo.

    :::

    :::info
    <b>sql_mode</b>:

    &emsp;&emsp;Modo por defecto de MariaDB 10.1:
    <pre className="highlight language-console"><code className="language-console">NO_ENGINE_SUBSTITUTION,NO_AUTO_CREATE_USER</code></pre>

    &emsp;&emsp;Modo por defecto de MariaDB 10.2 y versiones superiores:
    <pre className="highlight language-console"><code className="language-console">STRICT_TRANS_TABLES,ERROR_FOR_DIVISION_BY_ZERO,NO_AUTO_CREATE_USER,NO_ENGINE_SUBSTITUTION</code></pre>

    &emsp;&emsp;Modo por defecto de MySQL 5.6:
    <pre className="highlight language-console"><code className="language-console">NO_ENGINE_SUBSTITUTION</code></pre>

    &emsp;&emsp;Modo por defecto de MySQL 5.7 y versiones superiores:
    <pre className="highlight language-console"><code className="language-console">ONLY_FULL_GROUP_BY,STRICT_TRANS_TABLES,NO_ZERO_IN_DATE,NO_ZERO_DATE,ERROR_FOR_DIVISION_BY_ZERO,NO_ENGINE_SUBSTITUTION</code></pre>

    Le recomendamos que utilice siempre el modo por defecto, excepto si su base de datos se ha actualizado desde una versión con un modo por defecto diferente al de la versión actual.

    :::
  </Tab>
  <Tab label="Paso 4">
    En el panel que se abre, elija los nuevos valores en las listas y haga clic en <code className="action">Aplicar</code>.

  </Tab>
</Tabs>

:::

    <img className="thumbnail" alt="Panel de modificación del parámetro log_min_messages de una instancia PostgreSQL" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/configuration/edit-drawer-postgresql.png" loading="lazy" />

    - **log_min_messages**: Controla los niveles de mensajes que se registran en los logs del servidor. Los niveles disponibles para una solución Web Cloud Databases son:
        - **"WARNING"**: Proporciona mensajes de advertencia sobre posibles problemas.
        - **"ERROR"**: Envía el error que ha provocado la cancelación de un comando en curso.
        - **"LOG"**: Registra la información destinada a los administradores del servidor.
        - **"FATAL"**: Envía el error que ha provocado el final de la sesión en curso.
        - **"PANIC"**: Envía el error que ha provocado el final de todas las sesiones.

    Cada nivel incluye todos los niveles posteriores. Cuanto mayor sea el nivel, menos mensajes se registrarán en los logs del servidor.

    Por defecto, el valor definido es **"WARNING"**, ya que incluye los valores **"ERROR"**, **"LOG"**, **"FATAL"** y **"PANIC"**.

    También puede activar extensiones en sus bases de datos. Para ello, haga clic en la pestaña <code className="action">Bases de datos</code> y, a continuación, en el icono en forma de pieza de puzle de su base de datos en la columna **Extensiones**.

    <img className="thumbnail" alt="Icono de la columna Extensiones en la tabla de las bases de datos" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/extensions-column.png" loading="lazy" />

<summary>¿Cómo puedo conocer la versión exacta de PostgreSQL que utilizo?</summary>

Introduzca este comando en phpPgAdmin haciendo clic en **su base de datos**, en la sección **"SQL"**, y haga clic en <code className="action">Ejecutar</code>:

```sql
select version();
```

</details>

<details>

<summary>¿Cómo puedo conocer la versión exacta de MySQL o MariaDB que utilizo?</summary>

```sql
show variables like "version";
```

</details>

### Optimizar las bases de datos

Es recomendable mantener su base de datos para que ofrezca un buen rendimiento y devuelva la información a los scripts con rapidez. Para ello, es necesaria una base de datos estructurada y optimizada.

**Haga clic en cada título para ver su contenido.**

<details>

<summary>Indexar la base de datos</summary>

Para aumentar la velocidad de búsqueda en una consulta, es necesario indexar los campos utilizados en las cláusulas WHERE.

Ejemplo: realiza regularmente una búsqueda de personas por ciudad. Indexe el campo "city" con la siguiente consulta:

```sql
ALTER TABLE `test` ADD INDEX (`city`);
```

</details>

<details>

<summary>Purgar la base de datos</summary>

¿Algunos de sus datos ya no se consultan? Archívelos: sus tablas estarán menos saturadas y las búsquedas serán más rápidas.

</details>

<details>

<summary>Limitación de visualización</summary>

Limite la visualización de los registros a un número determinado (por ejemplo, 10 por página) con la parte LIMIT de su consulta SQL.

</details>

<details>

<summary>Agrupar las consultas</summary>

Agrupe sus consultas al inicio del script de esta forma:

```bash
open_connection
request1
request2
...
close_connection
Display...
Process data
Loop through data...
Display...
...
```

</details>

<details>

<summary>Obtener solo los datos útiles</summary>

En sus consultas SQL, compruebe que solo seleccione lo que necesite y que no haya olvidado los enlaces entre las tablas.

Ejemplo:

```sql
(where table1.field = table2.field2)
```

</details>

<details>

<summary>Evitar opciones que consuman demasiados recursos</summary>

Evite usar **"HAVING"**, por ejemplo, ya que incrementa sus consultas. Del mismo modo, evite usar **"GROUP BY"**, a menos que sea estrictamente necesario.

</details>
