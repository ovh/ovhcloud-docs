## Objetivo

Un conector de recepción indica a su plataforma Exchange qué servidores están autorizados a entregarle correos electrónicos y en qué condiciones. Sirve para situar una solución antispam externa, también llamada pasarela de filtrado, delante de su plataforma Exchange: los <Tooltip term="mxRecord">registros MX</Tooltip> de su dominio apuntan a esta pasarela, que filtra los correos electrónicos entrantes y, a continuación, los transmite a Exchange.

El conector de recepción está disponible para [Private Exchange](/links/web/emails-private-exchange) y [Trusted Exchange](/links/web/emails-trusted-exchange). Solo se puede crear y gestionar con la API de OVHcloud.

**Esta guía explica cómo crear, modificar, desactivar y eliminar un conector de recepción en su plataforma Exchange con la API de OVHcloud.**

:::info
Para que los correos electrónicos **salientes** de su plataforma pasen por un servidor externo, utilice en su lugar un conector de envío: consulte nuestra guía "[Exchange - Configurar un conector de envío](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/feature-send-connector)".
:::

## Requisitos

- Disponer de una plataforma [Private Exchange](/links/web/emails-private-exchange) o [Trusted Exchange](/links/web/emails-trusted-exchange).
- Disponer de credenciales API creadas en la <CreateToken rights="GET=/email/exchange&GET=/email/exchange/*&POST=/email/exchange/*&PUT=/email/exchange/*&PATCH=/email/exchange/*&DELETE=/email/exchange/*">página de generación de tokens de OVHcloud</CreateToken>, con al menos el derecho `GET` sobre `/email/exchange` y los derechos `GET`, `POST`, `PUT`, `PATCH` y `DELETE` sobre `/email/exchange/*`. Consulte nuestra guía "[Primeros pasos con las API de OVHcloud](/guides/manage-and-operate/api/first-steps)".
- Conocer las direcciones IP de los servidores de su solución antispam externa que entregarán los correos electrónicos a Exchange. Solicíteselas al proveedor de esta solución.

## Procedimiento

### Comprender el conector de recepción predeterminado

Cada plataforma Exchange dispone de un conector de recepción predeterminado. Pertenece a Exchange: no puede modificarlo ni eliminarlo, solo activarlo o desactivarlo. En la API, su propiedad `default` tiene el valor `true`.

Mientras esté activado, su plataforma acepta todos los correos electrónicos entrantes, sea cual sea el servidor que los entregue: un conector de recepción creado por usted no tiene entonces ningún efecto. Para que solo su pasarela pueda entregar correos electrónicos a Exchange, desactive manualmente el conector predeterminado. Nunca se desactiva automáticamente, para evitar una interrupción brusca de la recepción.

:::warning
**Desactive el conector predeterminado en último lugar.** Si no se aplica ningún otro conector activado, su desactivación interrumpe la recepción de todos los correos electrónicos de la plataforma. Antes de desactivarlo, compruebe que su conector de recepción está activado y que los registros MX de su dominio apuntan a su pasarela.
:::

### Obtener los parámetros de la ruta

Las llamadas del conector de recepción necesitan el nombre de la organización (`organizationName`) y el nombre del servicio (`exchangeService`) de su plataforma. Obténgalos en orden: la primera llamada que se indica a continuación proporciona la organización, necesaria para la segunda.

**1. Organización** (`organizationName`)

Liste las organizaciones Exchange de su cuenta con la llamada a la API que se indica a continuación:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange"} />

**2. Servicio** (`exchangeService`)

Liste los servicios Exchange de la organización con la llamada a la API que se indica a continuación:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service"} />

### Crear un conector de recepción

Cree el conector con la llamada a la API que se indica a continuación:

<Api version="v1" section="/email/exchange" method="POST" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector"} regions={["eu"]} />

Complete los siguientes campos en el cuerpo de la petición. Solo `name`, `remoteIpRanges` y `requireTls` son obligatorios.

| Campo | Tipo | Descripción |
|---|---|---|
| `name` | string | Nombre del conector, 255 caracteres como máximo |
| `remoteIpRanges` | string[] | Direcciones IP de los servidores autorizados a entregar correos electrónicos a través de este conector (véase más abajo) |
| `requireTls` | boolean | `true` para exigir TLS para todos los correos electrónicos recibidos por este conector |
| `maxMessageSize` | long | Opcional. Tamaño máximo de un correo electrónico recibido por este conector, en MB |
| `enabled` | boolean | Opcional. `true` para activar el conector en cuanto se cree (`false` por defecto) |

Cada entrada de `remoteIpRanges` puede ser:

- una sola dirección IP, por ejemplo `203.0.113.10`;
- una red en notación CIDR, por ejemplo `203.0.113.0/28`;
- un rango de direcciones "inicio-fin", con ambos extremos incluidos, por ejemplo `203.0.113.10-203.0.113.20`.

Se aceptan direcciones IPv4 e IPv6.

:::warning
**Límites de `remoteIpRanges`**

- Una misma dirección IP no puede figurar en dos conectores de recepción de la plataforma.
- La lista completa, una vez unidas sus entradas con comas, no debe superar los 255 caracteres. Es preferible utilizar una red CIDR en lugar de una larga lista de direcciones individuales.

:::

La llamada devuelve una tarea: el conector se crea una vez finalizada esta tarea.

### Listar y consultar los conectores de recepción

Liste los conectores de recepción de la plataforma, incluido el conector predeterminado, con la llamada a la API que se indica a continuación:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector"} regions={["eu"]} />

La llamada devuelve la lista de identificadores (`id`) de los conectores. Consulte los detalles de un conector con la llamada a la API que se indica a continuación:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

Además de los campos de creación, la respuesta contiene `id`, el identificador del conector, y `default`, cuyo valor es `true` para el conector de recepción predeterminado.

### Modificar un conector de recepción

Para modificar uno o varios campos sin cambiar los demás, utilice la llamada a la API que se indica a continuación:

<Api version="v1" section="/email/exchange" method="PATCH" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

Para sustituir toda la configuración del conector, complete todos los campos en la llamada a la API que se indica a continuación:

<Api version="v1" section="/email/exchange" method="PUT" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

:::info
El campo `remoteIpRanges` sustituye la lista registrada en su totalidad. Para añadir una dirección IP, vuelva a enviar la lista completa: las direcciones existentes y la nueva.
:::

Para activar o desactivar un conector, modifique su campo `enabled`. En el conector de recepción predeterminado, es el único campo que puede modificar: antes de desactivarlo, consulte la sección "[Comprender el conector de recepción predeterminado](#comprender-el-conector-de-recepción-predeterminado)".

Cada modificación devuelve una tarea: se aplica una vez finalizada esta tarea.

### Eliminar un conector de recepción

Elimine un conector con la llamada a la API que se indica a continuación:

<Api version="v1" section="/email/exchange" method="DELETE" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

La llamada devuelve una tarea: el conector se elimina una vez finalizada esta tarea. No puede eliminar el conector de recepción predeterminado.

Si elimina el último conector distinto del predeterminado, el conector predeterminado se reactiva automáticamente para no bloquear la recepción de correos electrónicos. Este comportamiento depende del parámetro `enableDefaultReceiveConnector` de la llamada (`true` por defecto): con `false`, un conector predeterminado desactivado permanece desactivado y su plataforma deja de recibir correos electrónicos.
