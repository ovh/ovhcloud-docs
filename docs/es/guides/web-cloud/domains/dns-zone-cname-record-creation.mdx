## Objetivo

Un registro CNAME permite asociar un subdominio a un nombre de dominio o subdominio sin tener que especificar una dirección IP. Esto significa que el subdominio será redirigido a la dirección IP del nombre de dominio o subdominio de destino, sin necesidad de configuración adicional.

Por ejemplo, si crea un registro CNAME para *www.domain.tld* que apunta a *domain.tld*, *www.domain.tld* utilizará la misma dirección IP que *domain.tld*.

Los registros CNAME son útiles para evitar tener que modificar las direcciones IP de sus subdominios. También pueden utilizarse para configurar servicios como los servidores de correo.

**Descubra cómo añadir un registro CNAME a la zona DNS de OVHcloud.**

> **¿Ya tiene un registro de tipo CNAME en su zona DNS?** Siga nuestra guía "[Editar una zona DNS de OVHcloud](/guides/web-cloud/domains/dns-zone-edit)".

## Requisitos

- Tener un [nombre de dominio](/links/web/domains).
- Tener una zona DNS asociada al nombre de dominio en OVHcloud.

:::warning
**Añadir, modificar o eliminar registros DNS en una zona DNS activa es una operación delicada.**
En caso de duda, contacte con un [proveedor especializado](/links/partner).

## Procedimiento

### Añadir un registro DNS de tipo CNAME para el subdominio de un nombre de dominio

Haga clic en las pestañas de abajo para ver cada uno de los **5** pasos.

<Tabs>
  <Tab label="Paso 1">
    Acceda a la página <ManagerLink to="/beta/#/web-cloud/domains/listing">Dominios y DNS</ManagerLink> y elija el dominio correspondiente.

    <img className="thumbnail" alt="Página Dominios y DNS y lista de los nombres de dominio de la cuenta" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/listing.png" loading="lazy" />
  </Tab>
  <Tab label="Paso 2">
    Haga clic en la pestaña <code className="action">Zona DNS</code> y, encima de la tabla, en <code className="action">Agregar una entrada</code>.

    <img className="thumbnail" alt="Pestaña Zona DNS de un dominio y botón Agregar una entrada" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/zone-overview.png" loading="lazy" />
  </Tab>
  <Tab label="Paso 3">
    En el formulario que se abre encima de la tabla, seleccione `CNAME — Alias hacia otro dominio` en la lista **Tipo**.

    <img className="thumbnail" alt="Lista Tipo del formulario Agregar una entrada, tipo CNAME seleccionado" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/add-entry-type-list-cname.png" loading="lazy" />
  </Tab>
  <Tab label="Paso 4">
    En el campo **Subdominio**, introduzca el subdominio correspondiente (por ejemplo: `www` para `www.domain.tld`). En el campo **Destino (nombre de host)**, introduzca el dominio o subdominio al que desee apuntar (por ejemplo: `domain.tld`): la consola añade ella misma el punto final.

    <img className="thumbnail" alt="Formulario Agregar una entrada de la zona DNS, registro CNAME del subdominio www hacia domain.tld" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/add-cname-record.png" loading="lazy" />
  </Tab>
  <Tab label="Paso 5">
    Compruebe la **Vista previa del registro** y haga clic en <code className="action">Agregar</code>.
  </Tab>
</Tabs>

La propagación del cambio por toda la red DNS puede tardar hasta **24** horas.

### Casos especiales

Haga clic en los siguientes enlaces para obtener más información:

<details>

<summary>Registros CNAME y TXT para un mismo subdominio</summary>

No configure al mismo tiempo un registro CNAME y un registro TXT para el mismo subdominio. Esto puede dar lugar a resultados aleatorios en la resolución DNS, ya que sólo se puede devolver una respuesta por consulta DNS.

Por ejemplo, si tiene los siguientes registros para *www.domain.tld*:

- Un registro CNAME que apunta a *domain.tld*.
- Un registro TXT con un valor específico.

Una consulta DNS para *www.domain.tld* devolverá el destino del registro CNAME o el valor del registro TXT de forma aleatoria.

</details>

<details>

<summary>CNAME en un nombre de dominio de su propia zona DNS</summary>

Por convención, **los registros de tipo CNAME no pueden utilizarse en un nombre de dominio de su propia zona DNS**. En efecto, el nombre de dominio debe apuntar obligatoriamente directamente a una dirección IP con un registro de tipo [A](/guides/web-cloud/domains/dns-zone-a-record-creation) para una IPv4, o [AAAA](/guides/web-cloud/domains/dns-zone-aaaa-record-creation) para una IPv6.

Siguiendo el ejemplo anterior, no podrá crear un registro de tipo CNAME para el nombre de dominio *domain.tld* en la zona DNS que haya creado para este nombre de dominio.
No obstante, podrá crear registros de tipo CNAME para todos los subdominios (por ejemplo, *subdomain.domain.tld* o *www.domain.tld*) del nombre de dominio *domain.tld* en la zona DNS creada para *domain.tld*.

En la consola de OVHcloud, si introduce `@` en el campo **Subdominio** de un registro CNAME, el botón <code className="action">Agregar</code> permanece desactivado y el formulario muestra el mensaje "Un registro CNAME no puede crearse en la raíz del dominio (@). Puede utilizar el apuntamiento SVCB."

</details>
