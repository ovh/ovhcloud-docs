Consulte el [hub MCP de OVHcloud](https://mcp.eu.ovhcloud.com/index.html) para conocer el inventario actualizado.

## Objetivo

El **Model Context Protocol** (MCP) es un estándar abierto que permite a un asistente de IA utilizar herramientas externas. El servidor MCP de OVHcloud expone sus servicios de OVHcloud en forma de herramientas, de modo que un asistente pueda consultar y modificar su configuración en su nombre.

En la práctica, esto significa que ya no tiene que navegar por las interfaces ni escribir llamadas a la API. Basta con preguntar:

```text
Enumera mis nombres de dominio e indícame cuáles caducan en los próximos 60 días.
```

**Esta guía explica cómo conectar un agente de IA al servidor MCP de OVHcloud y utilizarlo para gestionar sus nombres de dominio, sus registros DNS y sus redirecciones.**

## Requisitos

- Estar conectado a su <ManagerLink to="/">área de cliente de OVHcloud</ManagerLink>
- Tener instalado un cliente MCP compatible (consulte [Conectar su agente](#3--conectar-su-agente-a-mcp))
- Disponer de un navegador para completar la autenticación OAuth2

## Procedimiento

### 1 — Cómo funciona MCP

Intervienen tres componentes:

| Componente | Función |
|------------|---------|
| **Su agente de IA** | El asistente con el que habla (un agente de terminal, un chat integrado en el IDE, su propia aplicación) |
| **El servidor MCP de OVHcloud** | Publica las *herramientas* disponibles y las ejecuta sobre su cuenta |
| **Su cuenta de OVHcloud** | Los permisos, verificados en cada llamada, que determinan lo que el agente puede hacer |

Usted nunca invoca una herramienta por su nombre. Describe lo que desea, el agente selecciona la herramienta adecuada y le pide confirmación antes de modificar nada.

:::warning
Un agente de IA conectado a MCP actúa con **sus** permisos. Lea cada solicitud de confirmación antes de aceptarla, especialmente en las operaciones que eliminan registros o modifican los servidores DNS.
:::

### 2 — El hub MCP de OVHcloud

El [hub MCP de OVHcloud](https://mcp.eu.ovhcloud.com/index.html) recoge los servicios expuestos en forma de herramientas MCP y es la referencia para saber qué está disponible actualmente.

Elija la URL correspondiente a la región de su cuenta de OVHcloud:

| Región | URL del servidor MCP |
|--------|----------------------|
| Europa | `https://mcp.eu.ovhcloud.com/mcp/{section}` |
| Canadá | `https://mcp.ca.ovhcloud.com/mcp/{section}` |

Sustituya `{section}` por el nombre de la sección a la que desea conectarse, tal y como aparece en las tarjetas del hub. Siempre se conecta a una sección concreta: no existe una URL global que exponga todas las herramientas a la vez.

#### Secciones para los nombres de dominio

Dos secciones cubren los nombres de dominio, una por versión de la API:

| Sección | Contenido expuesto |
|---------|--------------------|
| `v1_domain` | Las herramientas de dominio de la API v1 |
| `v2_domain` | Las herramientas de dominio de la API v2 |

Así pues, la URL que debe utilizarse es `https://mcp.eu.ovhcloud.com/mcp/v1_domain` para una cuenta europea en la API v1.

A día de hoy, la API v1 sigue siendo la más completa en cuanto a funcionalidades: `v1_domain` expone por tanto un conjunto de herramientas más amplio que `v2_domain`. La API v2 se enriquece progresivamente.

Para entender qué diferencia la API v2 de la API v1, consulte la guía [OVHcloud API v2 - Principles of operation](/guides/manage-and-operate/api/apiv2#as-code-design).

Puede añadir una, otra o ambas simultáneamente. `v1_domain` por sí sola basta para realizar todas las operaciones de esta guía.

### 3 — Conectar su agente a MCP

La autenticación utiliza **OAuth2**: la primera vez que su agente contacta con el servidor, se abre una ventana del navegador en la página de conexión de OVHcloud. Una vez que haya iniciado sesión, el agente reutiliza esa sesión para sus llamadas MCP.

:::info
No se requiere ninguna cabecera HTTP personalizada: las credenciales las proporciona el flujo OAuth2. Las instrucciones de configuración de OVHcloud indican que hay que dejar **vacía** la sección de cabeceras de la configuración de su cliente.
:::

<Tabs>
<Tab label="SHAI">

[SHAI](https://github.com/ovh/shai) es el agente de terminal de OVHcloud. Se requiere la versión **0.1.5 o superior**.

Cree el siguiente archivo de configuración a partir de la [plantilla `.ovh.config`](https://github.com/ovh/shai/blob/main/.ovh.config) del repositorio de SHAI:

```bash
$HOME/.config/shai/agents/ovh.config
```

Declare en `tools.mcp` una entrada por cada sección que desee utilizar. Este ejemplo activa ambas versiones de la API:

```json
{
  "name": "ovh",
  "description": "OVH agent with OVH MCP server for cloud management and API calls",
  "tools": {
    "builtin": ["*"],
    "builtin_excluded": [],
    "mcp": {
      "v1_domain": {
        "config": {
          "type": "http",
          "url": "https://mcp.eu.ovhcloud.com/mcp/v1_domain"
        },
        "enabled_tools": ["*"]
      },
      "v2_domain": {
        "config": {
          "type": "http",
          "url": "https://mcp.eu.ovhcloud.com/mcp/v2_domain"
        },
        "enabled_tools": ["*"]
      }
    }
  },
  "system_prompt": "{{CODER_BASE_PROMPT}}",
  "max_tokens": 4096,
  "temperature": 0.3
}
```

Sustituya los puntos de acceso por los de su región.

:::info
No añada ninguna credencial a este archivo manualmente. Tras iniciar sesión, es el propio SHAI el que escribe un `access_token` y un `expires_at` en el bloque `config` de cada servidor. Estos valores son secretos personales: no incluya nunca este archivo en un repositorio ni lo comparta tal cual.
:::

A continuación, inicie el agente. Su navegador se abrirá en la página de conexión de OVHcloud; inicie sesión para completar la conexión.

</Tab>
<Tab label="Goose">

La vía más rápida es el [hub MCP de OVHcloud](https://mcp.eu.ovhcloud.com/index.html): localice la tarjeta **V1 Domain** (o **V2 Domain**) y haga clic en el botón **Add in Goose**. Goose se abrirá con la extensión ya rellenada —nombre, punto de acceso y transporte— y solo tendrá que confirmar.

El botón utiliza el punto de acceso del hub que esté consultando. Desde el hub europeo, configura por tanto la extensión con `https://mcp.eu.ovhcloud.com`: si su cuenta está en Canadá, abra el hub de su región o siga la configuración manual que se indica a continuación.

**Configuración manual.** En Goose, añada una nueva extensión de tipo **HTTP** e indique:

- **URL**: la URL de su región con la sección deseada, `https://mcp.eu.ovhcloud.com/mcp/v1_domain` o `https://mcp.eu.ovhcloud.com/mcp/v2_domain`
- **Headers**: deje este campo vacío

Guarde la extensión. Goose abrirá su navegador para iniciar sesión en OVHcloud.

Para utilizar ambas versiones de la API, cree una segunda extensión con la otra sección.

</Tab>
<Tab label="Claude Code">

Añada un servidor por sección, con la URL de su región:

```bash
claude mcp add --transport http v1_domain https://mcp.eu.ovhcloud.com/mcp/v1_domain
claude mcp add --transport http v2_domain https://mcp.eu.ovhcloud.com/mcp/v2_domain
```

El primer comando basta por sí solo para todas las operaciones de esta guía. Añada `--scope user` para que un servidor esté disponible en todos sus proyectos y no solo en el actual. No utilice ninguna opción `--header`.

A continuación, desde Claude Code, inicie la autenticación OAuth2:

```text
/mcp
```

Inicie sesión en OVHcloud en la ventana del navegador que se abre. `claude mcp list` mostrará entonces `✔ Connected` junto a cada servidor añadido.

</Tab>
</Tabs>

Para comprobar que la conexión funciona, plantee a su agente una pregunta de solo lectura:

```text
Enumera mis nombres de dominio de OVHcloud.
```

### 4 — Mostrar la información de un nombre de dominio

Empiece por pedir la lista de sus dominios y solicite después los detalles de uno de ellos.

Ejemplo de petición:

```text
Muéstrame los detalles de mydomain.ovh: fecha de expiración, servidores DNS y estado del bloqueo de transferencia.
```

### 5 — Contratar un nombre de dominio

La contratación de un nombre de dominio se realiza con la herramienta `order-new-domain-name`, disponible en la sección `v1_domain`.

Ejemplo de petición:

```text
Contrata el dominio mydomain.ovh durante un año.
```

Antes de comprar nada, pida una **simulación**. La herramienta acepta un parámetro `dryRun`: con el valor `true`, comprueba la disponibilidad del nombre y calcula el precio **sin contratar ni facturar nada**.

```text
Simula la contratación de mydomain.ovh durante un año.
```

Su agente mostrará entonces el presupuesto —precio, duración y configuración que se aplicará al dominio— y esperará su conformidad antes de continuar.

Una vez validado el presupuesto, el agente repite la llamada con `dryRun` en `false`. El pedido pasa a ser firme: la API devuelve la **URL de la orden de pedido**. Su agente le facilita esa URL directamente en su respuesta: ábrala en su navegador para pagar el pedido. También encontrará esta orden de pedido en el área de cliente de OVHcloud, en la sección <ManagerLink to="/#/billing/orders">Mis pedidos</ManagerLink>.

:::info
La orden de pedido debe estar **pagada** para que la solicitud se transmita al registro. Su agente no puede pagar en su lugar: siga la URL de la orden de pedido que le ha devuelto para efectuar el pago. Mientras no se haya cobrado el importe, el nombre de dominio seguirá estando disponible para un tercero.
:::

:::warning
Validar el pedido genera una orden de pedido real y facturable en su cuenta de OVHcloud. Lea la solicitud de confirmación de su agente antes de aceptarla y compruebe el nombre de dominio y la duración: un registro no se puede deshacer como si fuera una modificación de configuración.
:::

### 6 — Modificar un registro DNS

Herramientas asociadas: `create-domain-zone-record` para añadir un registro, `delete-domain-zone-record` para eliminar uno y `get-domain-zone-details` para consultar la zona.

Ejemplos de peticiones:

```text
Cambia el registro A de www.mydomain.ovh a 203.0.113.42.
```

No necesita saber qué tipo de registro hay que modificar. Describa el resultado que espera: su agente identificará el registro afectado, le explicará qué va a cambiar y esperará su conformidad antes de aplicarlo.

```text
Mi sitio web está alojado ahora en un servidor cuya dirección IP es 203.0.113.42.
Haz que www.mydomain.ovh apunte a él.
```

:::warning
Un registro DNS modificado no se activa hasta que se actualiza la zona. Si omite este paso, su modificación quedará guardada pero nunca se aplicará. Pida explícitamente a su agente que actualice la zona o compruebe que lo ha hecho.
:::

Después, la propagación por Internet puede tardar hasta 24 horas, en función del TTL del registro.

### 7 — Crear una redirección

Una redirección envía a los visitantes de su dominio hacia otra dirección.

Ejemplo de petición:

```text
Redirige blog.mydomain.ovh a https://mydomain.ovh/noticias, manteniendo visible la dirección en el navegador.
```

### 8 — Las demás operaciones cubiertas

Las secciones `v1_domain` y `v2_domain` exponen las rutas correspondientes de la API de OVHcloud en forma de herramientas: **cualquier operación que pueda realizarse sobre sus nombres de dominio a través de la API está también disponible mediante MCP**. Más allá de las tareas anteriores, esto abarca, por ejemplo:

- DNSSEC: activación, desactivación y gestión de los registros DS
- Protección de transferencia: bloqueo y desbloqueo
- Gestión de los contactos: titular, administrador, técnico y de facturación
- Servidores DNS y registros glue
- Usuarios y registros DynHost (DNS dinámico)
- Copia de seguridad, restauración, importación y exportación de la zona
- Gestión de las tareas: aceleración, cancelación, relanzamiento
- Obtención del código AuthInfo y aprobación de las transferencias salientes

Si no está seguro de que una operación sea posible, pida a su agente que le explique lo que es capaz de hacer con sus nombres de dominio.
