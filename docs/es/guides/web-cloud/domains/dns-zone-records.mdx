## Objetivo

El **DNS** (**D**omain **N**ame **S**ystem) es un conjunto de elementos (servidores DNS, zonas DNS, etc.) que permiten asociar un nombre de dominio a una dirección IP.

Le recomendamos que consulte nuestras guías "[Todo sobre los servidores DNS](/guides/web-cloud/domains/dns-server-general-information)" y "[Todo sobre la zona DNS](/guides/web-cloud/domains/dns-zone-general-information)" en este orden.

La zona DNS de un nombre de dominio es el archivo de configuración del nombre de dominio. Consta de información técnica, denominada *registros DNS*. La zona DNS actúa como un centro de referencia para el nombre de dominio.

Esta guía explica los distintos tipos de registros DNS disponibles en una zona DNS gestionada de OVHcloud. Complementa las siguientes guías:

- [Crear una zona DNS de OVHcloud](/guides/web-cloud/domains/dns-zone-create)
- [Editar una zona DNS de OVHcloud](/guides/web-cloud/domains/dns-zone-edit)
- [Gestionar el historial de una zona DNS de OVHcloud](/guides/web-cloud/domains/dns-zone-history)
- [Eliminar una zona DNS de OVHcloud](/guides/web-cloud/domains/dns-zone-deletion)

**Descubra los distintos tipos de registro DNS disponibles en una zona DNS de OVHcloud.**

## Procedimiento

### Los registros DNS

**La [edición de una zona DNS](/guides/web-cloud/domains/dns-zone-edit) es una operación delicada**: una modificación errónea puede, por ejemplo, dejar inaccesible su sitio web o bloquear la recepción de correos en sus direcciones de correo electrónico.

La siguiente lista detalla la función y las características específicas de cada registro, para ayudarle a manejar mejor sus operaciones DNS.

#### Registros de punteo <a name="pointer-records"></a>

Haga clic en la pestaña del registro que le interese.

<Tabs>
  <Tab label="A">
    **A**ddress

    Conecta un nombre de dominio a una dirección IPv4 `X.X.X.X` (donde las `X` son cifras entre `0` y `255`). Por ejemplo, la dirección IPv4 del servidor en el que está alojado el sitio web.
  </Tab>
  <Tab label="AAAA">
    Cuatro letras **A**, ya que este registro está codificado en cuatro veces más bits que el campo **A** histórico.

    Conecta un nombre de dominio a una dirección IPv6. Por ejemplo, la dirección IPv6 del servidor en el que está alojado el sitio web.

    :::info
    Las direcciones IPv6 se están desplegando progresivamente para paliar la falta de direcciones IPv4 debido a la continua expansión de los usos digitales. La codificación en 128 bits de las direcciones IPv6 permite ofrecer un mayor número de direcciones IP.

    No obstante, si su servidor ya dispone de una IPv4, le recomendamos que dé prioridad al uso de esta frente a la IPv6.

    En efecto, las IPv6 todavía no se han interpretado correctamente en toda la red de Internet, lo que puede provocar perturbaciones de visualización o de acceso.
    :::

  </Tab>
  <Tab label="CNAME">
    **C**anonical **NAME**

    Utiliza la dirección IP de otro nombre de dominio creando un enlace llamado alias. Por ejemplo, si *www.domain.tld* es un alias de *domain.tld*, significa que *www.domain.tld* utilizará la dirección IP de *domain.tld*.

    :::danger
    Un registro TXT que utilice el mismo nombre de dominio o subdominio que un registro CNAME perturba el funcionamiento de este último. El registro CNAME solo funcionará parcialmente o en absoluto.
    :::

    :::warning
    Por convenio, los registros CNAME no pueden ser utilizados directamente por un nombre de dominio en su propia zona DNS. En efecto, solo el nombre de dominio debe apuntar obligatoriamente y directamente a una dirección IP con un registro de tipo A (o AAAA si se trata de una IPv6).

    Para seguir el ejemplo anterior, no podrá crear un registro CNAME para el nombre de dominio *domain.tld* en la zona DNS que haya creado para este nombre de dominio.
    No obstante, podrá crear registros CNAME con todos los subdominios (ejemplos: *subdomain.domain.tld* o *www.domain.tld*) del dominio *domain.tld* en la zona DNS creada para *domain.tld*.

    Si quiere profundizar más técnicamente en este asunto, puede encontrar, al final de esta página, [un caso especial de uso relativo a los CNAME y las zonas DNS creadas para subdominios](#cnameusecase).
    :::

  </Tab>
  <Tab label="DNAME">
    **D**elegation **NAME**

    Permite generar un "alias" para todos los subdominios de un nombre de dominio. Evita tener que multiplicar los registros CNAME, ya que cada uno de ellos solo redirige un subdominio a un único destino.

    Ejemplo: creando un registro DNAME de *domain.tld* a *ovh.com*, todos los subdominios de *domain.tld* (como *dname.domain.tld* y *xxx.domain.tld*) se redirigirán a los subdominios de *ovh.com* (como: *dname.ovh.com* y *xxx.ovh.com*).

    Dicho de otro modo, el registro DNAME indica que *dname.domain.tld* y *xxx.domain.tld* deben mostrar los resultados de *dname.ovh.com* y *xxx.ovh.com*, respectivamente.

    :::warning
    En cambio, *domain.tld* como nombre de dominio no mostrará el destino del nombre de dominio *ovh.com*, ya que el registro DNAME solo es válido para los subdominios de los nombres de dominio definidos en el registro DNAME.

    Además, si el subdominio objetivo *xxx.ovh.com* no apunta a ninguna parte, el registro DNAME tampoco mostrará nada para *xxx.domain.tld*.
    :::

    :::tip
    El registro DNAME suele utilizarse para cambiar el nombre de la empresa. También puede configurarse cuando un usuario dispone de varias extensiones de nombres de dominio (.es, .net, .com, .info...) para redirigirlos entre sí fácilmente.
    :::

  </Tab>
  <Tab label="NS">
    **N**ame **S**erver

    <Region zones={['eu']}>
    Define los servidores DNS asociados a su zona DNS. Por ejemplo, si los registros NS de su zona DNS muestran los servidores *dnsXX.ovh.net* y *nsXX.ovh.net*, debe utilizarlos en la pestaña <code className="action">Servidores DNS</code> del área de cliente de OVHcloud. Consulte nuestra guía "[Modificar los servidores DNS de un dominio en OVHcloud](/guides/web-cloud/domains/dns-server-edit)" para más información.
    </Region>

    <Region zones={['ca', 'apac']}>
    Define los servidores DNS asociados a su zona DNS. Por ejemplo, si los registros NS de su zona DNS muestran los servidores *dnsXX.ovh.ca* y *nsXX.ovh.ca*, debe utilizarlos en la pestaña <code className="action">Servidores DNS</code> del área de cliente de OVHcloud. Consulte nuestra guía "[Modificar los servidores DNS de un dominio en OVHcloud](/guides/web-cloud/domains/dns-server-edit)" para más información.
    </Region>

    :::warning
    Si [edita una zona DNS de OVHcloud](/guides/web-cloud/domains/dns-zone-edit), no modifique los registros NS de su zona DNS en favor de servidores DNS externos a OVHcloud a través del menú <code className="action">Acciones sobre mi zona</code> > <code className="action">Modificar en modo textual</code>. Esta zona DNS funciona **únicamente** con los servidores DNS de OVHcloud.
    :::

  </Tab>
</Tabs>

#### Registros de correo <a name="mail-records"></a>

Haga clic en la pestaña del registro que le interese.

<Tabs>
  <Tab label="MX">
    **M**ail e**X**changer

    Conecta un nombre de dominio a un servidor de correo.

    <Region zones={['eu']}>
    Por ejemplo, la dirección *10 mx1.mail.ovh.net* corresponde a uno de los servidores de correo de OVHcloud cuando usted dispone de una solución de correo de OVHcloud.
    </Region>

    <Region zones={['ca', 'apac']}>
    Por ejemplo, la dirección *10 mx1.mail.ovh.ca* corresponde a uno de los servidores de correo de OVHcloud cuando usted dispone de una solución de correo de OVHcloud.
    </Region>

    Es probable que su proveedor de correo disponga de varios servidores de correo: cree por tanto un registro MX para cada uno de ellos. Consulte nuestra guía "[Configurar un registro MX para la gestión del correo](/guides/web-cloud/domains/dns-zone-mx)".

    :::warning
    En general, le recomendamos que utilice solo uno o más servidores de un mismo proveedor de correo en su zona DNS.
    De hecho, si ya tiene servicios de correo con otro proveedor de correo y añade al mismo tiempo (sin sustituir) los servidores de correo de su nuevo proveedor de correo, puede recibir mensajes de correo al azar en uno de sus dos proveedores.
    :::

  </Tab>
  <Tab label="SPF">
    **S**ender **P**olicy **F**ramework

    <Region zones={['eu']}>
    Permite evitar posibles usurpaciones de identidad en las direcciones de correo electrónico que utilizan su nombre de dominio (*spoofing*). Por ejemplo, el registro `v=spf1 include:mx.ovh.com ~all` indica que solo los servidores de envío asociados a su solución de correo de OVHcloud pueden considerarse legítimos por el servidor de recepción. Puede introducir este registro en forma de registro TXT o a través de nuestro sistema de configuración automática.
    </Region>

    <Region zones={['ca', 'apac']}>
    Permite evitar posibles usurpaciones de identidad en las direcciones de correo electrónico que utilizan su nombre de dominio (*spoofing*). Por ejemplo, el registro `v=spf1 include:mx.ovh.ca ~all` indica que solo los servidores de envío asociados a su solución de correo de OVHcloud pueden considerarse legítimos por el servidor de recepción. Puede introducir este registro en forma de registro TXT o a través de nuestro sistema de configuración automática.
    </Region>

    Consulte nuestra guía "[Mejorar la seguridad del correo electrónico mediante el registro SPF](/guides/web-cloud/domains/dns-zone-spf)" para más información.
  </Tab>
  <Tab label="DKIM">
    **D**omain**K**eys **I**dentified **M**ail

    Permite verificar la autenticidad del nombre de dominio del remitente y garantizar la integridad del mensaje de correo electrónico enviado. El registro DKIM se presenta como una clave de varios caracteres. La clave DKIM la proporciona su proveedor de correo electrónico (si esta funcionalidad la ofrece este último). Puede introducirla en forma de registro TXT.

    Consulte nuestra guía "[Mejorar la seguridad del correo electrónico mediante un registro DKIM](/guides/web-cloud/domains/dns-zone-dkim)" para más información.
  </Tab>
  <Tab label="DMARC">
    **D**omain-based **M**essage **A**uthentication, **R**eporting and **C**onformance

    Contribuye a la autenticación del correo en combinación con los métodos SPF y/o DKIM. Su proveedor de correo electrónico le comunica este valor (si esta funcionalidad la ofrece este último), y está al menos asociado a un registro SPF o DKIM.

    Consulte nuestra guía "[Mejorar la seguridad del correo electrónico mediante el registro DMARC](/guides/web-cloud/domains/dns-zone-dmarc)" para más información.
  </Tab>
</Tabs>

#### Registros extendidos <a name="extended-records"></a>

Haga clic en la pestaña del registro que le interese.

<Tabs>
  <Tab label="TXT">
    **T**e**XT**

    Permite añadir el valor que desee en formato de texto a la zona DNS del nombre de dominio. Este registro suele utilizarse en procesos de verificación, validación o seguridad.

    :::warning
    El registro TXT está limitado a 255 caracteres. No obstante, en algunos casos puede dividir su valor en varios registros. Cuando el proveedor le pida que introduzca un valor superior al límite de 255 caracteres, deberá ponerse en contacto con su proveedor.

    Sin embargo, este límite no existe si utiliza la funcionalidad <code className="action">Modificar en modo textual</code> descrita en la guía "[Editar una zona DNS de OVHcloud](/guides/web-cloud/domains/dns-zone-edit)" (para usuarios experimentados).
    :::

  </Tab>
  <Tab label="SRV">
    **S**e**RV**ice resource

    Indica la dirección del servidor que gestiona un servicio, por ejemplo un servidor SIP o un servidor de configuración automática de un cliente de correo.
  </Tab>
  <Tab label="CAA">
    **C**ertification **A**uthority **A**uthorization

    Permite indicar las autoridades de certificación autorizadas a emitir certificados SSL para un nombre de dominio.

    :::warning
    Si configura una entrada CAA para un nombre de dominio, esta configuración también se aplicará a **todos los subdominios** del mismo nombre de dominio.

    Si utiliza un certificado SSL Let's Encrypt con su nombre de dominio en un plan de hosting de OVHcloud y utiliza un registro CAA, este último impedirá la regeneración del certificado SSL Let's Encrypt.
    :::

  </Tab>
  <Tab label="NAPTR">
    **N**ame **A**uthority **P**oin**T**e**R**

    Utilizado en telecomunicaciones para dirigir una petición emitida desde un terminal móvil hacia un servidor. Puede asociar un registro SRV para generar dinámicamente los URIs (Uniform Resource Identifier) de destino.
  </Tab>
  <Tab label="LOC">
    **LOC**ation

    Utilizado para indicar la posición geográfica (especialmente la latitud, la longitud y la altitud).
  </Tab>
  <Tab label="SSHFP">
    **S**ecure **SH**ell **F**inger**P**rint

    Utilizado para indicar la huella de una clave pública SSH.
  </Tab>
  <Tab label="TLSA">
    **T**ransport **L**ayer **S**ecurity **A**uthentication

    Utilizado para indicar la huella de un certificado SSL/TLS. Permite conservar el *hash* de un certificado directamente en la zona DNS de su nombre de dominio a través de un registro DNS.

    Este registro se utiliza en el marco del protocolo **D**NS-based **A**uthentication of **N**amed **E**ntities (DANE).

    El protocolo DANE permite que un cliente (navegador de Internet, cliente de correo electrónico, cliente FTP, cliente SSH, etc.) consulte el registro TLSA. Así, se asegura de que un certificado SSL/TLS utilizado para un nombre de dominio sea el que certifique el mismo nombre de dominio.

    Si lo necesita, puede consultar más información en la página web del [**I**nternet **E**ngineering **T**ask **F**orce (**IETF**)](https://datatracker.ietf.org/doc/html/rfc6698) (EN).
  </Tab>
  <Tab label="RP">
    **R**esponsible **P**erson

    Este registro permite indicar la dirección de correo electrónico de la persona responsable del nombre de dominio. Este registro también puede combinarse con un registro DNS de tipo TXT para proporcionar más información.

    Si es necesario, puede encontrar más detalles en el sitio web de la [**I**nternet **E**ngineering **T**ask **F**orce (**IETF**)](https://datatracker.ietf.org/doc/html/rfc1183#section-2) (EN).
  </Tab>
  <Tab label="SVCB">
    **S**er**V**i**C**e **B**inding

    Este registro DNS puede agrupar varias informaciones para permitir una conexión más rápida y eficiente a su sitio web. También permite, por ejemplo, indicar directamente al navegador que el sitio web es compatible con HTTP/2 o HTTP/3, que debe priorizar el uso de una dirección IP (IPv4 y/o IPv6) mencionada como parámetro o incluso pasar por un puerto de acceso específico. Esto permite al navegador recuperar varias informaciones en una sola solicitud.

    Este registro dispone de **2** modos:

    - **Modo Alias**: este modo se activa cuando especifica una prioridad igual a 0. A diferencia de los registros DNS de tipo CNAME, permite redirigir un nombre de dominio desde su propia zona DNS (apex) hacia otro nombre de dominio o subdominio.
    - **Modo Servicio**: este modo se activa cuando especifica una prioridad distinta de 0. Es en este modo donde podrá definir los parámetros que desee aplicar a su nombre de dominio (ejemplos de parámetros: *alpn="h2,h3"*, *ipv4hint="203.0.113.0"*, *ipv6hint="2001:db8:1:1b00:203:0:113:0"*, *port="XXXX"*, etc.). En modo **Servicio**, puede aplicar estos parámetros directamente a su nombre de dominio, incluso si este no se utiliza como alias de otro nombre de dominio.

    Si es necesario, puede encontrar más detalles en el sitio web de la [**I**nternet **E**ngineering **T**ask **F**orce (**IETF**)](https://datatracker.ietf.org/doc/html/rfc9460) (EN).
  </Tab>
  <Tab label="HTTPS">
    **H**yper **T**ext **T**ransfer **P**rotocol **S**ecure

    Este registro funciona como el registro DNS de tipo SVCB, pero, a diferencia de este, es más específico para el protocolo HTTP. Puede agrupar varias informaciones para permitir una conexión más rápida y eficiente a su sitio web. También permite, por ejemplo, indicar directamente al navegador que el sitio web es compatible con HTTP/2 o HTTP/3, que debe priorizar el uso de una dirección IP (IPv4 y/o IPv6) mencionada como parámetro o incluso pasar por un puerto de acceso específico. Esto permite al navegador recuperar varias informaciones en una sola solicitud.

    Este registro dispone de **2** modos:

    - **Modo Alias**: este modo se activa cuando especifica una prioridad igual a 0. A diferencia de los registros DNS de tipo CNAME, permite redirigir un nombre de dominio desde su propia zona DNS (apex) hacia otro nombre de dominio o subdominio.
    - **Modo Servicio**: este modo se activa cuando especifica una prioridad distinta de 0. Es en este modo donde podrá definir los parámetros que desee aplicar a su nombre de dominio (ejemplos de parámetros: *alpn="h2,h3"*, *ipv4hint="203.0.113.0"*, *ipv6hint="2001:db8:1:1b00:203:0:113:0"*, *port="XXXX"*, etc.). En modo **Servicio**, puede aplicar estos parámetros directamente a su nombre de dominio, incluso si este no se utiliza como alias de otro nombre de dominio.

    Si es necesario, puede encontrar más detalles en el sitio web de la [**I**nternet **E**ngineering **T**ask **F**orce (**IETF**)](https://datatracker.ietf.org/doc/html/rfc9460) (EN).

    :::tip
    A continuación, puede encontrar un ejemplo práctico de configuración de un alias (apex) mediante un registro DNS de tipo HTTPS:

    El sitio web **domain.tld** está alojado detrás de una infraestructura CDN (por ejemplo: **cdn.provider.tld**).
    Gracias al registro DNS de tipo HTTPS, el nombre de dominio **domain.tld** puede indicar directamente a los navegadores compatibles que el servicio HTTPS debe resolverse en el proveedor del CDN **cdn.provider.tld**. Esto sin redirecciones ni gestión manual de direcciones IP.

    Para ello, el registro DNS de tipo HTTPS debe indicar:

    - En prioridad: *0*.
    - En destino: *cdn.provider.tld*.
    - En ajustes: **Deje el campo vacío**.

    De esta manera, será la resolución de **cdn.provider.tld** la que indique los parámetros a utilizar para **domain.tld**.
    :::

  </Tab>
</Tabs>

#### Caso particular de uso: el uso de los registros CNAME <a name="cnameusecase"></a>

Algunos usuarios crean zonas DNS directamente para el subdominio de un nombre de dominio (por ejemplo, *subdomain-with-its-own-DNS-zone.domain.tld*). La regla indicada en la pestaña "CNAME" de la sección "[Registros de punteo](#pointer-records)" también se aplica en este caso.

La zona DNS está creada para el subdominio (en nuestro ejemplo, *subdomain-with-its-own-DNS-zone.domain.tld*), por lo que este último está considerado como un nombre de dominio de pleno derecho en su zona DNS.

Por ello, en este caso concreto no puede crear un registro CNAME para *subdomain-with-its-own-DNS-zone.domain.tld* en la zona DNS que haya creado para dicho subdominio. No obstante, puede crear registros CNAME como *subdomain.subdomain-with-its-own-DNS-zone.domain.tld* o *xxx.subdomain-with-its-own-DNS-zone.domain.tld*.
