## Objetivo

El uso de las bases de datos puede provocar una serie de anomalías en su sitio web o en la <ManagerLink to="/beta/#/">consola de OVHcloud</ManagerLink>, así como en la interfaz [PhpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database).

**Descubra cómo solucionar los errores relacionados con las bases de datos de los alojamientos compartidos de OVHcloud.**

[[fragment:support-scope]]

## Requisitos

- Disponer de un [plan de hosting OVHcloud](/links/web/hosting).
- Utilizar uno de nuestros productos de bases de datos: [Start SQL](/links/web/hosting-options-startsql) o [Web Cloud Databases](/links/web/databases).

[[cpnav:web-hosting+web-cloud-databases]]

#### Comprobar las claves de conexión a su base de datos <a name="config_file"></a>

Conéctese al espacio de almacenamiento de archivos de su alojamiento mediante [FTP](/guides/web-cloud/web-hosting/ftp-connection) y consulte el archivo de configuración de su sitio web (por ejemplo, para un sitio web WordPress, se trata del archivo **wp-config.php** situado en el directorio que contiene su sitio web).

:::warning
La elección y configuración del archivo que contiene la información de conexión a la base de datos es inherente al editor de contenidos (CMS) correspondiente y no a OVHcloud.

Si necesita ayuda, le recomendamos que se ponga en contacto con el editor del [CMS](/guides/web-cloud/web-hosting/cms-install-1-click-modules) utilizado para crear su sitio web o con un [proveedor especializado](/links/partner). No podremos asistirle en este asunto.
:::

Compruebe la coincidencia **exacta** entre los identificadores de conexión a [phpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database#acceder-a-la-interfaz-phpmyadmin) y los del fichero de configuración de su sitio web.

Cambie, si es necesario, la [contraseña de su base de datos](/guides/web-cloud/web-hosting/sql-change-password).

#### Ejemplo para WordPress

Si su sitio web muestra un mensaje **"Error al conectarse a la base de datos"** y no se ve afectado por un [incidente](https://web-cloud.status-ovhcloud.com/), conéctese a [FTP](/guides/web-cloud/web-hosting/ftp-connection) a su alojamiento y abra el directorio que contiene su sitio web (por defecto es el directorio `www`).

Si se trata de un sitio web WordPress, abra el archivo `wp-config.php`.

```php
define('DB_NAME', 'my_database');

/** MySQL database username */
define('DB_USER', 'my_user');

/** MySQL database password */
define('DB_PASSWORD', 'my_password');

/** MySQL hostname */
define('DB_HOST', 'my_server.mysql.db:port');
```

### Superación del límite autorizado de la base de datos

Nuestros servicios le han enviado por correo electrónico un mensaje indicándole que la cantidad de datos en la base de datos supera el límite autorizado. La base de datos ha pasado a ser de solo lectura. Esto impide realizar cambios en el sitio web.

<img className="thumbnail" alt="database-overquota-notification-email" src="/images/assets/screens/email-sending-to-customer/databases/overquota-db.png" loading="lazy" />

Desbloquee la base de datos de tres formas distintas:

#### Método 1: cambiar la suscripción a un plan superior

Si dispone de una fórmula **Starter** o **Personal**, le recomendamos que cambie a un [plan de hosting superior](/links/web/hosting). Este cambio de suscripción aumentará el tamaño de la base de datos, lo que la reabrirá automáticamente. Este método es el más sencillo y no necesita conocimientos técnicos específicos.

:::warning
El aumento del tamaño de la base de datos puede deberse a un fallo de funcionamiento en el código interno del sitio web.

Una anomalía puede conllevar un aumento permanente del tamaño de la base de datos, en cuyo caso el cambio de plan de hosting sería ineficaz.

Si detecta un aumento repentino en el tamaño de su base de datos o si tiene un sitio web de tipo "blog" que normalmente no consume datos, le recomendamos que contacte inmediatamente con un [proveedor especializado](/links/partner). No podremos ofrecerle soporte sobre este tema.
:::

Para realizar este cambio, haga clic en las pestañas siguientes para ver cada una de las **2** etapas.

  </Tab>

#### Método 2: migrar sus datos a una base de datos de tamaño superior <a name="method2"></a>

También puede migrar sus datos a una nueva base de datos:

- Contrate, si es necesario, una [base de datos](/links/web/hosting-options-startsql) de mayor tamaño y lance su [creación](/guides/web-cloud/web-hosting/sql-create-database);
- [Duplique el contenido de la antigua base de datos](/guides/web-cloud/web-hosting/copy-database) en la nueva **o** realice una [exportación de sus datos](/guides/web-cloud/web-hosting/sql-database-export) y a continuación [impórtelos](/guides/web-cloud/web-hosting/sql-importing-mysql-database) en la nueva base de datos;
- Integre las claves de la nueva base de datos en el [archivo de configuración](#config_file) de su sitio web.

:::info
Si dispone de un alojamiento **Performance**, **Agency**, **Agency Plus** o **Agency Max**, también puede [activar gratis un servidor Web Cloud Databases](/guides/web-cloud/databases/db-getting-started).
:::

### Memoria RAM rebasada (solo Web Cloud Databases)

En la pestaña <code className="action">Vista general</code> de su instancia [Web Cloud DB](/guides/web-cloud/databases/db-getting-started), la sección **Uso de recursos** indica los desbordamientos de memoria. Cuando contabiliza uno o varios, su instancia ha consumido demasiados recursos en la infraestructura de OVHcloud.

Para aumentar la cantidad de memoria RAM, haga clic en las pestañas siguientes para ver cada una de las **3** etapas.

<Tabs>
  <Tab label="Etapa 1">
    Acceda a la página <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink> y seleccione la instancia correspondiente.
  </Tab>
  <Tab label="Etapa 2">
    En la pestaña <code className="action">Vista general</code>, localice la sección **Uso de recursos**. Indica la **RAM** actual de la instancia, la **Saturación CPU**, la **Cuota de almacenamiento** y señala los desbordamientos de memoria: **Ninguna saturación de memoria**, o el número de desbordamientos detectados.

    <img className="thumbnail" alt="Sección Uso de recursos de una instancia Web Cloud DB" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/resource-usage.png" loading="lazy" />
  </Tab>
  <Tab label="Etapa 3">
    Haga clic en <code className="action">Pedir más RAM</code> en la parte inferior de esta sección.

    :::warning
    Aumentar la memoria RAM de una instancia Web Cloud DB es un **pedido de pago**, no un simple ajuste. El proceso que se abre le permite elegir una oferta de RAM, aceptar los contratos y validar un pedido que se le redirigirá a pagar. La nueva cantidad de RAM solo se aplica una vez pagado el pedido, y la instancia puede reiniciarse en ese momento.
    :::

    El detalle de esta operación se describe en nuestra guía «[Configurar su servidor de bases de datos](/guides/web-cloud/databases/db-configure-optimise-database-server#modify-ram-web-cloud-db)».
  </Tab>
</Tabs>

:::warning
Para aumentar la RAM, el Web Cloud Databases no debe activarse a través de un hosting **Performance**, **Agency**, **Agency Plus** o **Agency Max**. Si quiere aumentar la cantidad de memoria RAM de una base de datos incluida en estos [planes de hosting](/links/web/hosting), deberá desvincularla primero.

Para desvincular la base de datos, consulte nuestra guía "[Desvincular mi solución Web Cloud Databases de un alojamiento web](/guides/web-cloud/databases/db-detach-from-web-hosting)".
:::

También puede optimizar su base de datos siguiendo las instrucciones de nuestra guía "[Configurar su servidor de bases de datos](/guides/web-cloud/databases/db-configure-optimise-database-server#optimizar-las-bases-de-datos)".

:::info
Si tiene dificultades para reducir el uso de los recursos en su servidor de bases de datos y no quiere aumentarlos, contacte con nuestra [comunidad de usuarios](/links/community) o con los [partners de OVHcloud](/links/partner). No podremos asistirle en este asunto.
:::

### Errores de importación de bases de datos

#### "Access denied for user to database"

>
> **"#1044 - Access denied for user to database"**
>

Este mensaje de error significa que la base de datos que está intentando importar contiene elementos no autorizados en la infraestructura compartida de OVHcloud.

En primer lugar, asegúrese de que la base de datos esté vacía. Para ello, haga clic en las pestañas para ver sucesivamente cada una de las **3** etapas.

<Tabs>
  <Tab label="Etapa 1">
    Acceda a la página <ManagerLink to="/beta/#/web-cloud/hosting">Alojamiento web</ManagerLink> y elija el alojamiento web correspondiente.

    <img className="thumbnail" alt="Página Alojamiento web y lista de los alojamientos de la cuenta" src="/images/assets/screens/console/product-selection/web-cloud/hosting-plans.png" loading="lazy" />
  </Tab>
  <Tab label="Etapa 2">
    Haga clic en la pestaña <code className="action">Bases de datos</code> y luego en el botón <code className="action">⁝</code> de la columna **Acciones**, a la derecha de la base de datos correspondiente, y en <code className="action">Recalcular cuota</code>. La columna **Cuota** le indicará entonces el espacio realmente ocupado.

    <img className="thumbnail" alt="Menú de una línea de la tabla de bases de datos" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/databases/row-actions-menu.png" loading="lazy" />
  </Tab>
  <Tab label="Etapa 3">
    Si la base de datos no está vacía, [guarde los datos presentes](/guides/web-cloud/web-hosting/sql-database-export) y después elimínelos antes de reanudar la operación de importación.

    También puede marcar la casilla <code className="action">Vaciar la base de datos antes de la importación</code> justo antes de [iniciar la importación](/guides/web-cloud/web-hosting/sql-importing-mysql-database#importar-una-copia-de-seguridad-desde-el-área-de-cliente):

    <img className="thumbnail" alt="Ventana de importación y casilla Vaciar la base de datos antes de la importación" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/databases/import-sql-file-window.png" loading="lazy" />
  </Tab>
</Tabs>

Si lo necesita, puede ponerse en contacto con nuestra [comunidad de usuarios](/links/community) o con un [proveedor especializado](/links/partner). No podremos asistirle en la corrección de esta anomalía.

:::info
**¿Qué elementos del script de importación de mi base de datos pueden causar un error "#1044 - Access denied for user to database"?**
:::

Tener un **"trigger"** en el script de importación de su base de datos no está autorizado en los servidores de alojamiento compartido de OVHcloud. En ese caso, importe la base de datos en un servidor [Web Cloud Databases](/guides/web-cloud/databases/db-getting-started).

Por otro lado, no está permitida la siguiente petición:

```sql
CREATE DATABASE IF NOT EXISTS `Database-Name` DEFAULT CHARACTER SET latin1 COLLATE latin1_swedish_ci;
```

Sustituya por:

```sql
USE `Database-Name`;
```

(`Database-Name`: indique el nombre de la base de datos que aparece en la <ManagerLink to="/beta/#/">consola de OVHcloud</ManagerLink>)

- [Optimice su base de datos](/guides/web-cloud/databases/db-configure-optimise-database-server#optimizar-las-bases-de-datos) y luego repita las operaciones de exportación/importación.

### No se ha podido acceder a phpMyAdmin

#### "Access denied for user"

>
> **"mysqli::real_connect(): (HY000/1045): Access denied for user"**
>

Este mensaje de error puede aparecer al conectarse a la base de datos por [phpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database#acceder-a-la-interfaz-phpmyadmin). Indica que los identificadores introducidos son incorrectos.

<img className="thumbnail" alt="access_denied_for_user" src="/images/assets/screens/other/web-tools/phpmyadmin/pma-error-hy000-1045.png" loading="lazy" />

En ese caso, [compruebe los identificadores indicados](/guides/web-cloud/databases/db-connecting-database-server#procedimiento) y cambie si es necesario la [contraseña de su base de datos](/guides/web-cloud/web-hosting/sql-change-password).

#### "Too many connections"

>
> **"mysqli_real_connect(): (HY000/1040): Too many connections"**
>

El número máximo de conexiones activas para las bases de datos entregadas con los alojamientos compartidos ([Start SQL](/links/web/hosting-options-startsql)) es de **30**.

Este número es de **200** para el [servicio Web Cloud Databases](/guides/web-cloud/databases/db-getting-started). (Puede cambiar este parámetro en la sección <code className="action">Configuración</code> de su servicio de base de datos).

Este mensaje aparece durante la [conexión a phpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database#acceder-a-la-interfaz-phpmyadmin) cuando se supera el número máximo de conexiones.

En ese caso, deberá [optimizar las bases de datos](/guides/web-cloud/databases/db-configure-optimise-database-server#optimizar-las-bases-de-datos) para reducir el número de conexiones activas.

:::warning
Para más información sobre las operaciones que debe realizar para reducir el número de conexiones activas a la base de datos, contacte con nuestra [comunidad](/links/community) o con los [partners de OVHcloud](/links/partner). Nosotros no podremos asistirle en este asunto.
:::

### No es posible conectarse a una base de datos Cloud Databases

Tener un servidor [Web Cloud Databases](/guides/web-cloud/databases/landing-page-databases) le permite [conectarse a sus bases de datos](/guides/web-cloud/databases/db-connecting-database-server) desde su ordenador o un servidor externo a la infraestructura de OVHcloud.

Si esta conexión no es posible, compruebe primero que ha [autorizado su dirección IP pública](/guides/web-cloud/databases/db-getting-started) a conectarse al servidor de bases de datos.

Si esta operación se ha realizado correctamente, póngase en contacto con su proveedor de acceso a Internet o con los [partners de OVHcloud](/links/partner). No podremos asistirle en esta situación.
