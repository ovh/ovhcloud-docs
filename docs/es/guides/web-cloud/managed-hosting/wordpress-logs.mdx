## Objetivo

Un log es un evento registrado en un sistema informático (servidor, aplicación, sitio web, etc.).
En el caso de un sitio web, los logs registran generalmente cada petición HTTP recibida, la respuesta devuelta, el cliente que originó la petición y el tiempo necesario para procesarla.

Su solución **Managed Hosting for WordPress** genera logs para los sitios web que aloja y los transfiere a [Logs Data Platform](/links/manage-operate/ldp), donde puede almacenarlos, visualizarlos y consultarlos.

A diferencia de un archivo de logs sin procesar, los logs enviados a Logs Data Platform están **divididos en campos individuales** (método HTTP, código de estado, dirección IP del cliente, tiempo de respuesta, etc.). Por lo tanto, no tiene que analizar usted mismo una única línea de texto: cada información ya está disponible en forma de un campo dedicado y consultable.

**Descubra qué logs están disponibles para su solución Managed Hosting for WordPress y cómo utilizarlos.**

## Requisitos

- Disponer de una solución [Managed Hosting for WordPress](https://labs.ovhcloud.com/en/managed-wp/) con al menos un sitio web.
- Haber iniciado sesión en su <ManagerLink to="/">área de cliente de OVHcloud</ManagerLink>.
- Tener conocimientos básicos sobre [Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/introduction) (EN).

### Flujos de logs disponibles

Su solución Managed Hosting for WordPress transfiere dos tipos distintos de logs a Logs Data Platform:

| Flujo de logs | Contenido |
|--------------|---------|
| **Logs de acceso HTTP** | Una entrada por cada petición HTTP recibida por su sitio web (log de acceso de Apache). Es el flujo principal para supervisar el tráfico, los errores y los tiempos de respuesta. |
| **Logs PHP-FPM** | Mensajes emitidos por el motor PHP-FPM que ejecuta su código WordPress (advertencias de PHP, errores, scripts lentos, etc.). |

Cada entrada se enriquece con información que identifica el sitio web afectado, lo que le permite filtrar los logs de un solo sitio aunque varios sitios compartan el mismo flujo:

- `service_id`: el identificador de su servicio Managed Hosting for WordPress.
- `website_id`: el identificador interno del sitio web.
- `fqdn`: el nombre de dominio (host virtual) al que se dirige la petición.

### Campos de los logs de acceso HTTP

Para cada petición HTTP están disponibles los siguientes campos. Los nombres de los campos respetan las [convenciones de nomenclatura de Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/field-naming-conventions) (EN): el sufijo indica el tipo y la indexación del valor (`_ip` está geolocalizado, `_int` es un entero, `_num` es un número, `_date` es una fecha).

| Campo | Ejemplo | Descripción |
|-------|---------|-------------|
| `time` | `2026-06-04T10:04:53.000Z` | Fecha de recepción de la entrada por Logs Data Platform. |
| `host` | `wp004.eu-west-001` | Nombre de host del servidor que generó el log. |
| `service_id` | `wp-xxxxxxxx` | Identificador de su servicio Managed Hosting for WordPress. |
| `website_id` | `a1b2c3d4e5` | Identificador interno del sitio web. |
| `fqdn` | `www.example.com` | Nombre de dominio (host virtual) al que se dirige la petición. |
| `remote_host_ip` | `203.0.113.42` | Dirección IP del cliente. Gracias al sufijo `_ip`, se geolocaliza automáticamente mediante Logs Data Platform (país, ciudad, coordenadas, etc.). |
| `http_method` | `GET` | Método HTTP de la petición. |
| `http_path` | `/wp-login.php` | Ruta solicitada por el cliente. |
| `http_protocol` | `HTTP/1.1` | Protocolo y versión utilizados. |
| `http_status_int` | `200` | Código de estado de la respuesta HTTP, almacenado como entero para permitir las comparaciones numéricas. |
| `bytes_sent` | `1234` | Tamaño de la respuesta enviada al cliente, en bytes. |
| `referer` | `https://www.google.com/` | Valor de la cabecera `Referer`. |
| `user_agent` | `Mozilla/5.0 (...)` | Valor de la cabecera `User-Agent`. |
| `request_time` | `04/Jun/2026:10:04:53 +0000` | Hora de recepción de la petición, en un formato legible. |
| `request_time_date` | `2026-06-04T10:04:53Z` | La misma hora de la petición en forma de fecha ISO 8601 (UTC), utilizable en las consultas y los cuadros de mando basados en la fecha. |
| `request_duration_num` | `114` | Tiempo necesario para procesar la petición, **en milisegundos**. Utilice este campo para supervisar sus tiempos de respuesta. |
| `message` | `203.0.113.42 - - [04/Jun/2026...]` | La línea de log de acceso sin procesar completa, conservada como referencia. |

### Campos de los logs PHP-FPM

El flujo PHP-FPM es más ligero y expone los siguientes campos:

| Campo | Descripción |
|-------|-------------|
| `time` | Fecha de recepción de la entrada por Logs Data Platform. |
| `host` | Nombre de host del servidor que generó el log. |
| `service_id` | Identificador de su servicio Managed Hosting for WordPress. |
| `website_id` | Identificador interno del sitio web. |
| `message` | El mensaje PHP-FPM (advertencia, error, aviso, etc.). |

### Consultar y analizar sus logs

Una vez que sus logs estén presentes en Logs Data Platform, podrá explorarlos a través de la interfaz web Graylog incluida con su solución, crear cuadros de mando y configurar alertas. Para conocer las nociones básicas, consulte la guía [Primeros pasos con Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start) (EN).

Como los logs de acceso están divididos en campos tipados, puede realizar búsquedas específicas directamente desde la barra de búsqueda de Graylog. Algunos ejemplos:

- Mostrar las peticiones de un solo sitio web:

```text
website_id:a1b2c3d4e5
```

- Encontrar todos los errores de servidor (HTTP 5xx):

```text
http_status_int:>=500
```

- Identificar las peticiones lentas que han tardado más de un segundo en procesarse:

```text
request_duration_num:>1000
```

- Supervisar los intentos de fuerza bruta en la página de inicio de sesión de WordPress:

```text
http_path:"/wp-login.php" AND http_method:POST
```

- Filtrar el tráfico por país geolocalizado del cliente (proporcionado por el sufijo `_ip`):

```text
remote_host_ip_country_code:FR
```

:::info
Los logs de acceso HTTP se generan en UTC. Utilice el campo `request_time_date` (una fecha ISO 8601) o el campo `time` para cualquier consulta, ordenación o histograma basado en la fecha.

:::
