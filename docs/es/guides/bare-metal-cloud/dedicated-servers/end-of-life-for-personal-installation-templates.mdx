**Le recomendamos que lea esta guía en su totalidad y con especial atención, ya que podría verse afectado si solicita la instalación de un sistema operativo en un nuevo servidor dedicado o la reinstalación del sistema operativo en uno de sus servidores dedicados.**

Aunque esta página explica la retirada de las plantillas personales para la instalación del sistema operativo (SO) de los servidores dedicados y sus consecuencias, puede estar tranquilo: **no se pierde ninguna funcionalidad**.
De hecho, tras esta retirada, podrá seguir instalando sistemas operativos con el **mismo nivel de personalización que antes**. Además, los clientes que utilizan directamente la API se beneficiarán de **una llamada a la API más sencilla**.

## Objetivo

Esta página ofrece información clave sobre el plan de retirada de las plantillas personales para la instalación del SO en los servidores dedicados. También ofrece consejos útiles para los clientes que utilizan la consola de OVHcloud o el área de cliente de So you Start o Kimsufi. Por último, presenta las ventajas de la nueva llamada a la API con respecto a la llamada a la API obsoleta.

## Contexto <a id="context"></a>

OVHcloud se reinventa constantemente para adaptar sus ofertas a una demanda creciente de resiliencia. Para alcanzar este objetivo, **las plantillas personales de instalación del SO para los servidores dedicados** se suprimirán en su totalidad el **7 de octubre de 2025**.

Esta funcionalidad permitía iniciar tareas de instalación del SO en un servidor dedicado utilizando una plantilla personal que contenía los siguientes elementos:

- sistema operativo que se va a instalar,
- esquema de particionamiento,
- configuración del RAID por hardware,
- nombre de host,
- llave SSH pública,
- script de postinstalación.

Para simplificar la instalación de los sistemas operativos en los servidores dedicados, así como la comunicación de este cambio, se ha creado una nueva llamada a la API: `POST /dedicated/server/{serviceName}/reinstall`. Esta llamada a la API sustituye a la antigua ruta: `POST /dedicated/server/{serviceName}/install/start`. Esta antigua ruta permitía lanzar una instalación del SO a partir de una plantilla de OVHcloud **o de una plantilla personal**.

Esta antigua ruta, así como el concepto de plantilla personal, se retirarán. La nueva ruta solo permite instalar el SO a partir de una plantilla de OVHcloud. Tenga en cuenta también que el término "plantilla de OVHcloud" (*OVHcloud template* en inglés) irá desapareciendo progresivamente en favor del término "sistema operativo" (o "SO").

La retirada de las plantillas personales se realizará en 2 etapas:

### Etapa 1: 17 de junio de 2025 <a id="step-1"></a>

- Los clientes ya no podrán **editar** ni **añadir** nuevas plantillas personales.
- Los clientes que tengan una o varias plantillas personales y al menos un servicio de servidor dedicado activo recibirán por e-mail información técnica detallada y personalizada para migrar sus peticiones a la API hacia la <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nueva ruta /reinstall</ApiLink>.

### Etapa 2: 7 de octubre de 2025 <a id="step-2"></a>

- Los clientes ya no podrán acceder a sus plantillas de instalación personales.
- Se eliminarán todos los datos relacionados con las plantillas de instalación personales.

Tenga en cuenta que los clientes podrán seguir consultando los datos en el e-mail del 17 de junio de 2025, ya que la documentación personalizada enviada se generó a partir de los datos de las plantillas personales en fecha 17 de junio de 2025.

## Procedimiento <a id="instructions"></a>

La siguiente sección contiene información específica según su situación: si tiene una cuenta de OVHcloud, So you Start o Kimsufi y si suele utilizar la consola de OVHcloud o la API para instalar los sistemas operativos en sus servidores dedicados.

### Consola de OVHcloud, área de cliente de So you Start o Kimsufi <a id="ux"></a>

El botón `Instalar a partir de una de sus plantillas` se suprimió del asistente de instalación del SO de los servidores dedicados en abril de 2025. Si utilizaba este botón, dispone de 3 opciones a largo plazo:

- Seguir utilizando la interfaz web (no recomendado si tiende hacia una estrategia de automatización), lo que requiere aplicar manualmente todas las personalizaciones en el asistente cada vez que realice una instalación del SO.
- Escribir un script que utilice la API (recomendado para las automatizaciones, pero requiere conocimientos de programación): consulte la sección [API de OVHcloud, So you Start o Kimsufi](#api) más abajo.
- Utilizar la consola de la API (buen compromiso): utilice la antigua llamada a la API hasta el 17 de junio de 2025 y, a continuación, la nueva llamada a la API con los payloads que se le proporcionarán.

Aunque ya puede explorar ejemplos y esquemas de la <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nueva ruta de la API /reinstall en la consola de la API</ApiLink> y leer la [documentación pública](/guides/bare-metal-cloud/dedicated-servers/api-os-installation), a continuación le ofrecemos una solución temporal que puede seguir mientras espera recibir los payloads de la nueva ruta de la API en el e-mail del 17 de junio de 2025.

#### Solución alternativa para las cuentas de OVHcloud <a id="ux-ovh"></a>

Tal y como se indica en la [documentación de la API de OVHcloud](/guides/manage-and-operate/api/first-steps#conectarse-a-la-api-de-ovhcloud), en la <ApiLink>página de la API de OVHcloud</ApiLink>:

- Haga clic en `Authentication` en la esquina superior izquierda.
- A continuación, haga clic en `Login with OVHcloud SSO`.
- Introduzca sus claves de acceso de OVHcloud.
- Haga clic en el botón `Authorize` para autorizar las llamadas a la API desde este sitio.

![API](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/login.png)

A continuación, ejecute la llamada a la API para iniciar una instalación del SO a partir de su plantilla personal:

- Seleccione `v1`.
- Elija la sección `/dedicated/server`.
- Busque la llamada a la API `POST /dedicated/server/{serviceName}/install/start` (puede utilizar el filtro).
- En el campo `serviceName`, introduzca el nombre del servidor dedicado en el que quiera instalar el SO.
- En el campo `REQUEST BODY` ("payload de la API"), introduzca el siguiente contenido JSON (en este ejemplo, suponemos que "my-amazing-template" es el nombre de la plantilla personal que quiere instalar):

```json
{
  "templateName": "my-amazing-template"
}
```

Si necesita listar y ver los detalles de sus plantillas personales, puede hacerlo en la sección `/me`, mediante las llamadas a la API de `/me/installationTemplate`.

:::danger
**Ejecutar la llamada a la API [POST /dedicated/server/\{serviceName\}/install/start](https://api.eu.ovhcloud.com/console/?section=%2Fdedicated%2Fserver&branch=v1#post-/dedicated/server/-serviceName-/install/start) en un servidor dedicado borrará todos sus datos. UTILICE ESTA LLAMADA A LA API CON PRECAUCIÓN.**
:::

A continuación, haga clic en el botón `Execute` para iniciar la tarea de instalación del SO.

![console API](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/screenshot-api-console-workaround.png)

Puede volver a la página del panel de control del servidor dedicado en <ManagerLink to="/">la consola de OVHcloud</ManagerLink> para seguir el progreso de la tarea de instalación del SO.

#### Solución alternativa para las cuentas de So you Start o Kimsufi <a id="ux-sys-ks"></a>

Abra la [consola de la API de So you Start](https://eu.api.soyoustart.com/console/) o [la de Kimsufi](https://eu.api.kimsufi.com/console/).

Haga clic en el botón `Login` en la esquina superior derecha e introduzca sus claves de acceso. A continuación, haga clic en `Log in`. Ya estará autenticado en la consola de la API.

- Abra la sección `/dedicated/server`.
- Busque la llamada a la API `POST /dedicated/server/{serviceName}/install/start`.
- En el campo `serviceName`, introduzca el nombre del servidor dedicado en el que quiera instalar el SO.
- En el campo `templateName`, introduzca el nombre de la plantilla personal que quiera instalar.

Si necesita listar y ver los detalles de sus plantillas personales, puede hacerlo en la sección `/me`, mediante las llamadas a la API de `/me/installationTemplate`.

:::danger
**Ejecutar la llamada a la API [POST /dedicated/server/\{serviceName\}/install/start](https://eu.api.soyoustart.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) (o [esta](https://eu.api.kimsufi.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) para Kimsufi) en un servidor dedicado borrará todos sus datos. UTILICE ESTA LLAMADA A LA API CON PRECAUCIÓN.**
:::

A continuación, haga clic en el botón `Execute` para iniciar la tarea de instalación del SO.

Puede volver a la página del panel de control del servidor dedicado en el [área de cliente de So you Start](https://eu.soyoustart.com/manager) o de [Kimsufi](https://www.kimsufi.com/fr/manager) para seguir el progreso de la tarea de instalación del SO.

### Utilizar las API de OVHcloud, So you Start o Kimsufi <a id="api"></a>

Si utiliza directamente las llamadas a las API de OVHcloud, So you Start o Kimsufi para iniciar las instalaciones del SO a partir de una plantilla personal, puede seguir utilizando la llamada a la API `POST /dedicated/server/{serviceName}/install/start` hasta el **7 de octubre de 2025**.
No obstante, tenga en cuenta que a partir del **17 de junio de 2025** ya no será posible añadir ni modificar sus plantillas personales.

Aunque recibirá un e-mail con todos los detalles sobre las adaptaciones de los payloads de la API necesarias para utilizar la <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nueva llamada a la API /reinstall</ApiLink>, puede empezar desde ahora a consultar su esquema <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>en la consola de la API</ApiLink> (el esquema es el mismo para OVHcloud, [So you Start](https://eu.api.soyoustart.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST) y [Kimsufi](https://eu.api.kimsufi.com/console/#/dedicated/server/%7BserviceName%7D/install/start~POST)) y a leer su [documentación pública](/guides/bare-metal-cloud/dedicated-servers/api-os-installation).

En su caso, la retirada de las plantillas personales simplifica la instalación de los sistemas operativos en los servidores dedicados. En efecto, la <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nueva llamada a la API /reinstall</ApiLink> ofrece todas las personalizaciones posibles que la antigua llamada a la API [POST /dedicated/server/\{serviceName\}/install/start](https://api.eu.ovhcloud.com/console/?section=%2Fdedicated%2Fserver&branch=v1#post-/dedicated/server/-serviceName-/install/start) no podía proporcionar directamente sin tener que definir previamente una plantilla personal en [/me/installationTemplate](https://api.eu.ovhcloud.com/console/?section=%2Fme&branch=v1#get-/me/installationTemplate).

La siguiente comparación le da una idea de la reducción del número de llamadas a la API que aporta la <ApiLink section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"}>nueva llamada a la API /reinstall</ApiLink> en el caso de una personalización compleja que implique RAID por hardware y un particionamiento personalizado: de `4+n` llamadas (donde `n` representa el número de particiones definidas en el esquema de particionamiento) a una única llamada a la API.

![Comparación entre la antigua y la nueva llamada a la API](/images/guides/bare-metal-cloud/dedicated-servers/end-of-life-for-personal-installation-templates/api-calls-comparison.png)

De este modo, disfrutará de una experiencia más fluida e intuitiva.
