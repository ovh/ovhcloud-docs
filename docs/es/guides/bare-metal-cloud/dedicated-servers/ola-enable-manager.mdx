## Objetivo

La tecnología OVHcloud Link Aggregation (OLA) ha sido diseñada por nuestros equipos para aumentar la disponibilidad de su servidor y mejorar la eficiencia de sus conexiones de red. En solo unos clics, puede agregar sus tarjetas de red y hacer que sus enlaces de red sean redundantes. Esto significa que, si un enlace se cae, el tráfico se redirige automáticamente hacia otro enlace disponible.<br/>
La agregación utiliza el protocolo LACP (Link Aggregation Control Protocol), definido por el estándar IEEE 802.3ad.

**Descubra cómo configurar OLA en su área de cliente de OVHcloud.**

## Requisitos

- Tener un [servidor dedicado OVHcloud](https://www.ovhcloud.com/es-es/bare-metal/) de las gamas Advance, Scale o High Grade.
- Tener un sistema operativo/hipervisor que soporta el protocolo de agregación 802.3ad (LACP).

## Procedimiento

:::warning
La configuración OLA se realiza en todas las interfaces de red. Formarán un agregado de tipo "agregación privada".

Tras la implementación de OLA, la IP pública dejará de estar accesible.

:::


### Configurar OLA en el área de cliente de OVHcloud

Para comenzar la configuración de OLA, abra la pestaña <code className="action">Interfaces de red</code> en la página de administración de su servidor.

Haga clic en el botón <code className="action">Agregación de redes</code> en la sección **Controladores de interfaz de red (NIC)**.

Se le mostrarán dos tablas:
- A la izquierda, la configuración actual de sus interfaces de red;
- A la derecha, la configuración simulada de sus interfaces de red agregadas.

En el campo situado debajo de las tablas, introduzca un nombre para su agregación de enlaces.

Una vez que haya verificado que la configuración de la agregación cumple con sus requisitos de red, haga clic en <code className="action">Activar la agregación</code> para continuar.

La operación puede tardar unos minutos. Cuando haya terminado, el paso siguiente será configurar las interfaces de su sistema operativo con un vínculo NIC o un equipo NIC. Para saber cómo proceder, puede consultar las siguientes guías diseñadas para los sistemas operativos más populares:

- [Cómo configurar la agregación de enlaces LACP en Debian 9 a 11 (ifupdown)](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-ifupdown).
- [Cómo configurar el NIC Teaming para OVHcloud Link Aggregation (OLA) en Windows Server 2019](/guides/bare-metal-cloud/dedicated-servers/ola-enable-w2k19).
- [Cómo configurar la agregación de enlaces LACP en SLES 15](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-sles15).
- [Cómo configurar la agregación de enlaces LACP en Debian 12 o superior / Ubuntu 24.04 o superior (Netplan) (EN)](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-netplan).

### Verificar el estado de OLA

Puede verificar el estado de su agregación de enlaces (OLA) en la pestaña <code className="action">Interfaces de red</code>. En la parte inferior de la sección **Tráfico**, localice la fila **OVHcloud Link Aggregation**.

Existen cuatro posibles etiquetas de estado:
- **No disponible**: OLA no es compatible con este modelo de servidor dedicado.
- **Disponible**: OLA es compatible pero no está configurado.
- **Activo - Full private**: OLA está activado; todas las interfaces físicas están agregadas en un único enlace privado para uso de vRack.
- **Activo - Double LAG**: OLA está preactivado; las interfaces físicas se dividen en dos agregados separados (uno público, uno privado).

:::info
**Nota:** El estado **Activo - Double LAG** es una configuración específica generalmente reservada para las gamas de servidores Scale y High-Grade, que cuentan con cuatro interfaces de red físicas.

:::

### Restaurar OLA a los valores predeterminados

Para restablecer OLA a los valores predeterminados, haga clic en el botón <code className="action">Desagrupar redes</code> en la sección **Controladores de interfaz de red (NIC)**. Haga clic en <code className="action">Confirmar</code> en el menú contextual.

La operación puede tardar unos minutos.
