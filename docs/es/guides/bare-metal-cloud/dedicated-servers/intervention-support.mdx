## Objetivo

Nuestras intervenciones de mantenimiento se limitan únicamente al aspecto material de su servidor. Tras una intervención de mantenimiento, es posible que tenga que realizar algunas acciones en la parte de software de su servidor.

Esta guía, basada en numerosas experiencias y casos de uso encontrados por nuestros equipos, enumera las acciones que debe realizar en función de su instalación: sistemas operativos, hipervisor, etc.
Su objetivo es acompañarle y limitar en la medida de lo posible el impacto en el ciclo de vida de sus entornos.

## Requisitos

- Disponer de un [servidor dedicado](/links/bare-metal/bare-metal).

<a name="ubuntu"></a>

### Ubuntu / Debian 12+

Si tiene problemas de conectividad de red (por ejemplo, no hay respuesta al ping tras la sustitución de la placa base), realice las siguientes acciones:

1\. Reinicie el servidor en [modo de rescate](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).<br/>
2\. Monte la partición `/`:

```bash
root@rescue:~# mount /dev/my_system_disk /mnt
```
Si el archivo `70-persistent-net.rules` no existe (consulte la sección de esta guía sobre [el nombre de sus interfaces de red](#network-interface)), compruebe los siguientes archivos en el árbol `/etc/systemd/network/`:

- `50-default.network`
- `50-public-interface.link`

```bash
root@rescue:~# cat /mnt/etc/systemd/network/50-default.network
# This file sets the IP configuration of the primary (public) network device.
# You can also see this as "OSI Layer 3" config.
# It was created by the OVH installer, please be careful with modifications.
# Documentation: man systemd.network or https://www.freedesktop.org/software/systemd/man/systemd.network.html
 
[Match]
MACAddress=xx:xx:xx:xx:xx:xx
 
[Network]
Description=network interface on public network, with default route
DHCP=no
Address=1.2.3.4/24
Gateway=1.2.3.254
IPv6AcceptRA=no
NTP=ntp.ovh.net
DNS=127.0.0.1
DNS=213.186.33.99
DNS=2001:41d0:3:163::1
Gateway=2001:41d0:0203:4bff:ff:ff:ff:ff
 
[Address]
Address=2001:41d0:0203:1234::/64
 
[Route]
Destination=2001:41d0:0203:4bff:ff:ff:ff:ff
Scope=link
root@rescue:~#
root@rescue:~# cat /mnt/etc/systemd/network/50-public-interface.link
# This file configures the relation between network device and device name.
# You can also see this as "OSI Layer 2" config.
# It was created by the OVH installer, please be careful with modifications.
# Documentation: man systemd.link or https://www.freedesktop.org/software/systemd/man/systemd.link.html
 
[Match]
MACAddress=xx:xx:xx:xx:xx:xx
 
[Link]
Description=network interface on public network, with default route
MACAddressPolicy=persistent
NamePolicy=kernel database onboard slot path mac
#Name=eth2    # name under which this interface is known under OVH rescue system
#Name=eno3    # name under which this interface is probably known by systemd
root@rescue:~#
```

3\. Haga una copia de seguridad de los archivos y edítelos para introducir el nuevo valor de su dirección MAC:

```bash
root@rescue:~# cp /mnt/etc/systemd/network/50-default.network /mnt/etc/systemd/network/50-default.network.link.bak-`date +%s`
root@rescue:~# cp /mnt/etc/systemd/network/50-public-interface.link /mnt/etc/systemd/network/50-public-interface.link.bak-`date +%s`
root@rescue:~# nano /mnt/etc/systemd/network/50-default.network
root@rescue:~# cat /mnt/etc/systemd/network/50-default.network | grep MACAddress
MACAddress=xx:xx:xx:xx:xx:xx
root@rescue:~#
root@rescue:~# nano /mnt/etc/systemd/network/50-public-interface.link
root@rescue:~#
root@rescue:~# cat /mnt/etc/systemd/network/50-public-interface.link | grep MACAddress
MACAddress=xx:xx:xx:xx:xx:xx
root@rescue:~#
```

4\. No olvide desmontar la partición `/` antes de reiniciar el servidor.

#### Casos particulares

En algunos casos, es necesario propagar la nueva dirección MAC a los siguientes archivos:

- `/mnt/etc/netplan/01-netcfg.yaml`
- `/mnt/etc/netplan/50-cloud-init.yaml`
- `/mnt/etc/systemd/network/10-eno1.link`
- `/mnt/etc/systemd/network/10-eno1.network`

<a name="centos-almalinux"></a>

### CentOS / Alma Linux

Si tiene problemas de conectividad de red (por ejemplo, no hay respuesta al ping tras la sustitución de la placa base), realice las siguientes acciones:

1\. Reinicie el servidor en [modo de rescate](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).<br/>
2\. Monte la partición `/`:

```bash
root@rescue:~# mount /dev/my_system_disk /mnt
```

3\. Compruebe el archivo de configuración `/mnt/etc/sysconfig/network-scripts/ifcfg-eth0`.

4\. Haga una copia de seguridad de los archivos y edítelos para corregir la dirección MAC:

```bash
root@rescue:~# cp /mnt/etc/sysconfig/network-scripts/ifcfg-eth0 /mnt/etc/sysconfig/network-scripts/ifcfg-eth0.`date +%s`
```

5\. Introduzca la nueva dirección MAC en la línea `HWADDR=xx:xx:xx:xx:xx:xx`.

6\. No olvide desmontar la partición `/` antes de reiniciar el servidor.

<a name="smartos"></a>

### SmartOS

Si tiene problemas de conectividad de red (por ejemplo, no hay respuesta al ping tras la sustitución de la placa base), realice las siguientes acciones:

1\. Reinicie el servidor en [modo de rescate](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).<br/>

```bash 
modprobe zfs
root@rescue:~# zpool import -f zones (zpool import to list the pools)
root@rescue:~# zfs set mountpoint=/mnt zones/usbkey
root@rescue:~# zfs mount zones/usbkey
root@rescue:~# cp /mnt/config{,.bak-$(date +"%Y-%m-%d-%H_%M")}
```

2\. Introduzca la nueva dirección MAC en la línea `admin_nic`:

```bash
root@rescue:~#  vim /mnt/config
```

3\. No olvide desmontar las particiones antes de reiniciar el servidor en modo `netboot`:

```bash
root@rescue:~# zfs umount -a
root@rescue:~# zfs set mountpoint="/usbkey" zones/usbkey 
```

```bash
root@rescue:~# umount /mnt
root@rescue:~# reboot
```

### Proxmox / Debian (excepto Debian 12 y versiones posteriores)

Si tiene problemas de conectividad de red (por ejemplo, no hay respuesta al ping tras la sustitución de la placa base), puede deberse a un error durante el arranque del sistema, causado por el antiguo valor de la dirección MAC, que sigue presente:

Realice las siguientes acciones:

1\. Reinicie el servidor en [modo de rescate](/guides/bare-metal-cloud/dedicated-servers/rescue-mode).

```bash
root@rescue:~# cat /mnt/etc/network/interfaces
# This file describes the network interfaces available on your system
# and how to activate them. For more information, see interfaces(5).
 
# The loopback network interface
auto lo
iface lo inet loopback
 
iface enp3s0f0 inet manual
 
auto vmbr0
iface vmbr0 inet dhcp
  bridge-ports enp3s0f0
  bridge-stp off
  bridge-fd 0

iface vmbr1 inet static
  address  192.168.22.254
  netmask  255.255.255.0
  bridge_ports none
  bridge_stp off
  bridge_fd 0
  post-up echo 1 > /proc/sys/net/ipv4/ip_forward
root@rescue:~#
root@rescue:~# cat /mnt/var/log/messages | grep renamed
Aug  8 14:27:20 s22 kernel: [    1.527563] igb 0000:04:00.0 eno1: renamed from eth0
Aug  8 14:27:20 s22 kernel: [    1.550622] igb 0000:04:00.1 eno2: renamed from eth1
Aug  8 14:27:34 s22 kernel: [   88.148303] eth0: renamed from vethGRELEP
Aug  8 14:27:36 s22 kernel: [   90.444727] eth0: renamed from vethVMV0MH
Aug  8 14:27:40 s22 kernel: [   94.116739] eth0: renamed from vethQWYCXT
Aug  8 14:27:43 s22 kernel: [   97.469199] eth0: renamed from vethAIWWWX
Aug  8 14:27:48 s22 kernel: [  102.101324] eth0: renamed from vethB2DGCS
Aug  8 14:27:48 s22 kernel: [  102.139437] eth1: renamed from vethRSNNKL

```

2\. Vuelva a crear el archivo `70-persistent-net.rules` y añada:

- El nombre de la interfaz de red que figura en el archivo `/mnt/etc/network/interfaces`.
- La nueva dirección MAC (visible en **Aggregated interface composition**, en la pestaña <code className="action">Connectivity</code> de la <ManagerLink to="/">consola de OVHcloud</ManagerLink>, o en la salida del comando `ip link`).

```bash
root@rescue:~# cat /mnt/etc/udev/rules.d/70-persistent-net.rules
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", NAME="enp3s0f0"
root@rescue:~#
```

<a name="xenserver"></a>

### XenServer

Si tiene problemas de conectividad de red (por ejemplo, no hay respuesta al ping tras la sustitución de la placa base), la dirección MAC está configurada de forma estática y debe reinicializarse.

Realice las siguientes acciones:

1\. Reinicie el servidor en [modo de rescate](/guides/bare-metal-cloud/dedicated-servers/rescue-mode) y utilice el comando `chroot`:

```bash
root@rescue:~# mount /dev/sda1 /mnt
root@rescue:~# mount -t proc /proc/ /mnt/proc/
root@rescue:~# mount -o bind /sys/ /mnt/sys/
root@rescue:~# mount -o bind /dev/ /mnt/dev/
root@rescue:~# mount -o bind /dev/pts/ /mnt/dev/pts/
root@rescue:~# chroot /mnt
```

2\. Modifique la configuración actual para que corresponda a los nuevos parámetros:

```bash
[root@rescue /]# xe-reset-networking --device=eth0 --mode=static --ip=xx.xx.xx.xx --netmask=255.255.255.0 --gateway=xx.xx.xx.xxx
```

```bash
Reconfiguring eth0...
Updating inventory file...
Running in chroot, ignoring request.
```

4\. Escriba "exit" para salir del modo `chroot` y desmonte todas las particiones:

```bash
root@rescue:~# umount /mnt/sys
root@rescue:~# umount /mnt/proc
root@rescue:~# umount /mnt/dev/pts
root@rescue:~# umount /mnt/dev
root@rescue:~# umount /mnt
```

#### Casos particulares

Es necesario comprobar y adaptar los siguientes archivos:

- `/mnt/etc/sysconfig/network-scripts/interface-rename-data/static-rules.conf`  
- `/mnt/etc/sysconfig/network-scripts/interface-rename-data/dynamic-rules.json`

<a name="esxi"></a>

### ESXi

Tras la sustitución de la placa base, no es posible modificar las nuevas direcciones MAC en el archivo `esxi.conf` con las herramientas integradas en el modo de rescate.
Por lo tanto, será necesario intervenir manualmente.

#### Versión 7.0 o superior

El siguiente procedimiento solo se aplica a las **versiones 7.0 o superiores**. A partir de esta versión, el archivo state.tgz está cifrado.
Reinicialice la red desde el menú Direct Console a través de su KVM o IPMI.

Consulte la siguiente captura de pantalla:

<img className="thumbnail" alt="reset_network" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/restore.png" loading="lazy" />

#### Versión 6.7 o inferior

El siguiente procedimiento solo se aplica a las **versiones 6.7 o inferiores**.

1\. Reinicie el servidor en [modo de rescate](/guides/bare-metal-cloud/dedicated-servers/rescue-mode) para montar la partición `/`:

```bash
root@rescue:~# mount /dev/sdaX /mnt/
```

2\. Haga una copia de seguridad del archivo `state.tgz`

```bash
root@rescue:~# ls /mnt/state.tgz
root@rescue:~# cp /mnt/state.tgz /mnt/state.tgz.`date +%s`
```

3\. Cree un entorno de trabajo:

```bash
root@rescue:~# mkdir /home/ovh/esxi
root@rescue:~# WORKINGDIR=/home/ovh/esxi
root@rescue:~# cd $WORKINGDIR
```

4\. Extraiga el contenido de `state.tgz` en `$WORKINGDIR` y, a continuación, extraiga el contenido de `local.tgz`.<br/>
5\. Edite el archivo `esx.conf` obtenido:

```bash
root@rescue:/home/ovh/esxi# tar xf /mnt/state.tgz -C $WORKINGDIR
root@rescue:/home/ovh/esxi# tar xf /home/ovh/esxi/local.tgz -C $WORKINGDIR
root@rescue:/home/ovh/esxi# vim etc/vmware/esx.conf
```
6\. Identifique y modifique la dirección MAC de `vmkernelnic`:

```bash
/net/vmkernelnic/child[0000]/mac = "XX:XX:XX:XX:XX:XX"
```

7\. Identifique en qué interfaz se utiliza la dirección IP principal:

```bash
/net/vswitch/child[0000]/uplinks/child[0000]/pnic = "vmnicX"
```

8\. Actualice la dirección MAC de la interfaz principal:

:::warning
No modifique la dirección MAC virtual.

:::


```bash
/net/pnic/child[0001]/mac = "XX:XX:XX:XX:XX:XX"         <== Primary Interface Mac address
/net/pnic/child[0001]/virtualMac = "00:50:56:XX:XX:XX"  <== Virtual Mac
/net/pnic/child[0001]/name = "vmnic1"
```

:::warning
Si hay una interfaz vRack, no olvide modificar también su dirección MAC.

:::


9\. Haga una copia de seguridad y desmonte la partición `/`:

```bash
root@rescue:/home/ovh/esxi# tar -czf $WORKINGDIR/local.tgz etc/
root@rescue:/home/ovh/esxi# tar -czf /mnt/state.tgz local.tgz
root@rescue:/home/ovh/esxi# umount /mnt
```

#### Casos particulares

Compruebe el orden de las declaraciones de sus vmnicX. Este es un ejemplo funcional:

```bash
root@rescue:/home/ovh/esxi# cat etc/vmware/esx.conf | grep "/vmkdevmgr/pci"
/vmkdevmgr/pci/m00008901/alias = "vmhba0"
/vmkdevmgr/pci/m00008501/alias = "vmnic0"
/vmkdevmgr/pci/m00008502/alias = "vmnic1"
```

<a name="windows"></a>

### Windows (Hyper-V)

Tras la sustitución de la placa base, no es posible acceder al servidor hasta que modifique manualmente las direcciones MAC a través del **Administrador de dispositivos**.

Existen 2 métodos:

#### A través de IPMI/KVM

1\. Inicie sesión como administrador desde la interfaz [IPMI/KVM](/guides/bare-metal-cloud/dedicated-servers/ipmi).<br/>
2\. Abra la utilidad <code className="action">Ejecutar</code> (tecla del logotipo de Windows + <code className="action">R</code>) y, en el prompt `run`, ejecute el comando `devmgmt.msc`:

<img className="thumbnail" alt="win_device_manager" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_device_manager_edited.png" loading="lazy" />

3\. Abra <code className="action">Network adapters</code> y seleccione el adaptador correspondiente a `eth0`.<br/>
4\. Haga clic derecho en <code className="action">Properties</code> > <code className="action">Advanced</code>.<br/>
5\. Busque `Locally Administered Address`.<br/>
6\. Introduzca el nuevo valor de la dirección MAC (solo cifras, sin espacios).

<img className="thumbnail" alt="win_advanced" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_advanced_edited.png" loading="lazy" />

#### A través de WinPE

1\. Reinicie el servidor en modo `WinPE`.<br/>
2\. Ejecute el comando `regedit` en el prompt `run`.<br/>
3\. Cargue el registro local a través del disponible en `WinPE` y haga clic en <code className="action">HKEY_LOCAL_MACHINE</code>:

<img className="thumbnail" alt="win_regedit_1" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_1_edited.png" loading="lazy" />

4\. A continuación, haga clic en <code className="action">Load Hive...</code>.

<img className="thumbnail" alt="win_regedit_2" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_2_edited.png" loading="lazy" />

:::info
Por defecto, se encontrará en el árbol de WinPE.
No olvide desplazarse a la unidad `C:\`.

:::


5\. Busque el registro `SYSTEM`.

<img className="thumbnail" alt="win_load" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_load_edited.png" loading="lazy" />

6\. Se le pedirá que introduzca un nombre. Por ejemplo, puede elegir `OVH_TEST`.

7\. Busque el valor del siguiente registro:

```bash
"HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Class\{4D36E972-E325-11CE-BFC1-08002BE10318}"
```

:::warning
Mientras estemos en WinPE, el valor `CurrentControlSet` debería ser igual a `CurrentSet001`.

:::


Debería ver varias subclaves con nombres como estos: 0000, 0001, etc.

8\. Haga clic en cada subclave para comprobar el valor `DriverDesc`, que debe corresponder a su interfaz de red.
Puede comprobar el nombre de su interfaz desde un terminal con el siguiente comando:

```bash
ipconfig /all
```

9\. Busque las entradas de registro `NetworkAddress` en el panel derecho y sustituya el valor por el de su nueva dirección MAC. Si esta entrada no existe, haga clic derecho en una zona vacía para crear un valor de tipo `String` con el nombre `NetworkAddress`.

<img className="thumbnail" alt="win_regedit_3" src="/images/bare-metal-cloud/dedicated-servers/intervention-support/win_regedit_3_edited.png" loading="lazy" />

10\. Será necesario descargar el registro para aplicar los cambios recientes. Haga clic en OVH_TEST (creado anteriormente), haga clic en <code className="action">File</code> (arriba a la izquierda) y seleccione <code className="action">Unload hive...</code>.

<a name="network-interface"></a>

### Identificar el nombre de sus interfaces de red

Tras la sustitución de la placa base, no es posible acceder al servidor porque el sistema operativo ha renombrado el controlador de las interfaces de red.

1\. Reinicie el servidor en [modo de rescate](/guides/bare-metal-cloud/dedicated-servers/rescue-mode), monte la partición `/` y utilice el comando `chroot`:

```bash
root@rescue:~# mount /dev/my_disk /mnt
root@rescue:~# for i in /dev /dev/pts /proc /sys; do mount -B $i /mnt$i; done
root@rescue:~# chroot /mnt
```

2\. Compruebe si las interfaces se han modificado. Consulte en los logs `var/log/messages` o `var/log/kern.log` si la interfaz se ha renombrado:

```bash
Oct  9 22:25:49 node1 kernel: [    5.479916] ixgbe 0000:03:00.1 eno4: renamed from eth1
Oct  9 22:25:49 node1 kernel: [    5.504285] ixgbe 0000:03:00.0 eno3: renamed from eth0
```

3\. Compruebe el archivo de configuración `/mnt/etc/udev/rules.d/70-persistent.-net.rules` y sustituya los nuevos valores (direcciones MAC) si es necesario:

```bash
root@rescue:~# cat /mnt/etc/udev/rules.d/70-persistent-net.rules
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", ATTR{dev_id}=="0x0", ATTR{type}=="1", KERNEL=="eth*", NAME="public"
SUBSYSTEM=="net", ACTION=="add", DRIVERS=="?*", ATTR{address}=="xx:xx:xx:xx:xx:xx", ATTR{dev_id}=="0x0", ATTR{type}=="1", KERNEL=="eth*", NAME="private"
```

4\. Acceda al directorio `/boot/grub/` y cree una copia de seguridad del archivo `grub.cfg`.
5\. Edite el archivo `/etc/default/grub` y modifique la línea que empieza por `GRUB_CMDLINE_LINUX` para obtener lo siguiente:

```bash
GRUB_CMDLINE_LINUX="net.ifnames=0 biosdevname=0"
```

6\. Ejecute el comando:

```bash
root@rescue:~# grub-mkconfig -o /boot/grub/grub.cfg
```

7\. Salga del entorno `chroot` con el comando `exit` y desmonte todas las particiones:

```bash
root@rescue:~# umount /mnt/sys
root@rescue:~# umount /mnt/proc
root@rescue:~# umount /mnt/dev/pts
root@rescue:~# umount /mnt/dev
root@rescue:~# umount /mnt
```

#### A través de la BIOS

- Caso de uso: el sistema instalado (en este caso, CentOS 6) ya no puede arrancar tras la sustitución del disco (no hay ninguna entrada EFI visible en la BIOS).

1\. Reinicie el servidor para acceder al menú de la BIOS.

La *1.ª secuencia* consiste en regenerar los archivos necesarios para que su partición vuelva a estar operativa:

- Acceda al menú `boot` de su BIOS:
    - Seleccione <code className="action">Add New Boot Option</code>.
    - Elija la ruta de su partición <code className="action">Path for boot option</code> y seleccione el sistema de archivos que contiene su partición de arranque.
    - Seleccione el archivo `EFI\centos6\bootx64.efi` y elija <code className="action">Create</code>.
