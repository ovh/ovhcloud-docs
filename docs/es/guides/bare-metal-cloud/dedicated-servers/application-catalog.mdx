## Objetivo

El catálogo de aplicaciones le permite instalar una aplicación lista para usar en su servidor dedicado de OVHcloud, sin conocimientos previos de administración de sistemas. Usted elige una aplicación durante la (re)instalación del servidor y, a continuación, rellena un breve formulario de configuración en una interfaz web segura. La aplicación se instala de forma nativa en el servidor, protegida mediante HTTPS y disponible en unos minutos.

**Esta guía explica cómo utilizar el catálogo de aplicaciones en su servidor dedicado de OVHcloud.**

## Requisitos

- Disponer de un [servidor dedicado](/links/bare-metal/bare-metal) en su cuenta de OVHcloud
- Haber iniciado sesión en su <ManagerLink to="/">área de cliente de OVHcloud</ManagerLink>
- Disponer de acceso a la <ApiLink>API de OVHcloud</ApiLink> (para la sección "[API de OVHcloud](#viaapi)" de esta guía)
- Tener acceso a la dirección de correo electrónico de su cuenta de OVHcloud, para recibir el enlace a la interfaz de configuración
- Disponer de un navegador web para acceder a la interfaz de configuración una vez finalizada la instalación

:::warning
Igual que en una instalación de sistema operativo clásica, una nueva instalación con el catálogo de aplicaciones borrará todos los datos presentes en el servidor. Haga una copia de seguridad de los datos que desee conservar antes de empezar.
:::

## Procedimiento

### Funcionamiento del catálogo de aplicaciones

El despliegue de una aplicación se realiza en dos etapas:

1. **Selección (durante la instalación):** usted (re)instala su servidor con una imagen del catálogo de aplicaciones y selecciona **una sola** aplicación. Es aquí donde elige *qué* aplicación desea desplegar.
2. **Configuración (después del primer arranque):** una vez reiniciado el servidor, se inicia automáticamente un configurador de un solo uso que pone a disposición una interfaz web segura en el puerto `10143`. Usted rellena un breve formulario (por ejemplo, un nombre de sitio web y una contraseña de administrador) y, a continuación, la aplicación se instala automáticamente y se publica mediante HTTPS.

Una vez completada correctamente la instalación, el configurador **se elimina por completo** del servidor: su binario, su servicio y sus datos de trabajo se borran. Solo queda su aplicación, y usted dispone de un acceso root completo al servidor.

Las aplicaciones se instalan de forma **nativa** — con paquetes del sistema y servicios `systemd`, en un servidor dedicado exclusivamente a este uso — y no dentro de una plataforma de contenedores.

**Limitaciones técnicas:**

- Solo se puede desplegar **una única aplicación** mediante el catálogo de aplicaciones.
- El **particionado personalizado y la configuración del RAID hardware no están disponibles** para esta instalación.

:::warning
Esto no significa que no pueda ejecutar otras aplicaciones en el servidor, sino que solo se puede desplegar **UNA** aplicación mediante el catálogo. Si desea ejecutar otras aplicaciones, deberá instalarlas manualmente.
:::

### Seleccionar su aplicación durante la instalación

Hay dos métodos de despliegue disponibles, descritos en las pestañas siguientes: instale su aplicación desde el área de cliente de OVHcloud o utilice la API de OVHcloud para integrar la instalación en sus propios scripts y automatizar sus despliegues.

1. Seleccione su servidor en <code className="action">Bare Metal Cloud</code> > <code className="action">Servidores dedicados</code>.

    :::info

#### Iniciar la instalación <a name="viaapi"></a>

Para consultar los sistemas operativos disponibles para su servidor, utilice la siguiente llamada:

<Api version="v1" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/install/compatibleTemplates"} />

En la respuesta, las plantillas del catálogo de aplicaciones son aquellas cuyo nombre termina en `-withapp`. Obtenga siempre el identificador mediante esta llamada en lugar de codificarlo de forma fija, ya que el catálogo de plantillas evoluciona.

A continuación, puede iniciar la instalación utilizando la siguiente llamada:

<Api version="v1" section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/reinstall"} />

Indique el sistema operativo obtenido en el paso anterior y la aplicación que desea instalar en la personalización `appToInstall`:

```json
{
  "operatingSystem": "ubuntu2404-withapp",
  "customizations": {
    "hostname": "myApplicationServer",
    "sshKey": "mySshKey",
    "appToInstall": "wordpress"
  }
}
```

El valor `appToInstall` corresponde al identificador de la aplicación que desea desplegar, por ejemplo `wordpress`, `drupal`, `nextcloud`, `prestashop`, `discourse`, `matomo`, `n8n`, `openclaw`, `hestiacp`, `fastpanel`, `coolify`, `dokploy`, `easypanel` o `game-panel`. Solo se puede indicar una aplicación.

Complete la tarea de instalación hasta el final, tal y como se describe en la guía [Install an OS via the OVHcloud API on a Dedicated Server](/guides/bare-metal-cloud/dedicated-servers/api-os-installation) y, a continuación, prosiga con la sección "[Configurar su aplicación y acceder a ella](#configure)" que figura más abajo.

  </Tab>
</Tabs>

### Configurar su aplicación y acceder a ella <a name="configure"></a>

Después de la instalación, su servidor arranca automáticamente el configurador de un solo uso. Esta etapa no requiere ningún conocimiento de Linux, SSH ni administración de sistemas: basta con un navegador web.

#### Etapa 1: abrir el configurador

Una vez finalizada la instalación, recibirá un correo electrónico con el enlace a su configurador. Tiene la siguiente forma:

```text
https://<su-servidor>:10143/static/deploy.html?app=<aplicacion>&token=<token>
```

Abra este enlace en su navegador web. El token que contiene le autentica y se registra una cookie de sesión segura: a continuación, podrá navegar por el configurador sin el token en la barra de direcciones. Al abrir el configurador sin un token válido aparece una página `Unauthorized`.

:::warning
Trate este enlace como una contraseña y no lo comparta: da acceso a la interfaz de instalación de su servidor.
:::

:::info
Si su navegador muestra una advertencia de certificado durante la primera carga, significa que el configurador todavía está obteniendo su certificado Let's Encrypt y presenta entretanto un certificado autofirmado temporal. Espere un minuto y vuelva a cargar la página: el cambio al certificado definitivo es automático.
:::

#### Etapa 2: rellenar el formulario de configuración

El configurador se abre directamente en la aplicación que haya seleccionado durante la instalación. Según la aplicación, podrá desplegarla inmediatamente o deberá rellenar primero un breve formulario:

- **Las aplicaciones sin campos** — Coolify, Dokploy, Easypanel, FastPanel, HestiaCP, Discourse, Matomo y n8n — generan por sí mismas las credenciales necesarias y las muestran al final. Haga clic en <code className="action">Deploy</code>.
- **Las aplicaciones con campos** — WordPress, Drupal, Nextcloud, PrestaShop, OpenClaw y OVHcloud Game Panel — solicitan algunos valores, como un nombre de sitio web, una contraseña de administrador o una contraseña de base de datos. Los campos obligatorios están señalados y los campos opcionales pueden proponer valores predeterminados.

Un panel <code className="action">Installation details</code>, situado sobre el formulario, detalla lo que se va a instalar y por qué, con un enlace a la documentación oficial del editor.

Cada campo se valida antes de iniciar el despliegue (por ejemplo, un campo de correo electrónico debe contener una dirección válida y las contraseñas tienen una longitud mínima). Corrija los campos señalados y valide de nuevo.

:::tip
Elija contraseñas robustas: los valores que introduzca aquí serán las credenciales reales de su aplicación.
:::

<img className="thumbnail" alt="Formulario de configuración para un despliegue de WordPress" src="/images/bare-metal-cloud/dedicated-servers/application-catalog/configurator-form.png" loading="lazy" />

A continuación, haga clic en <code className="action">Deploy</code>.

#### Etapa 3: seguir el despliegue

El configurador ejecuta la instalación y transmite su progreso en tiempo real: un estado (`pending`, después `running` y luego `completed` o `failed`), una barra de progreso y los registros de instalación. Los valores que haya introducido en el formulario aparecen enmascarados en los registros.

<img className="thumbnail" alt="Progreso del despliegue y registros en tiempo real" src="/images/bare-metal-cloud/dedicated-servers/application-catalog/configurator-progress.png" loading="lazy" />

Un despliegue tarda normalmente unos minutos; las aplicaciones más pesadas, como Discourse, requieren más tiempo. Puede dejar la pestaña abierta, pero la instalación continúa en el servidor incluso si su navegador se desconecta: vuelva a abrir su enlace para retomar el seguimiento.

:::info
Solo se ejecuta un despliegue a la vez. Si ya hay un despliegue en curso y usted inicia otro, el configurador le devuelve al que está en curso en lugar de iniciar un segundo. Esto es lo que garantiza la regla "una sola aplicación por servidor".
:::

#### Etapa 4: obtener sus datos de acceso

Cuando el estado alcanza el valor `completed`, el configurador muestra una página de confirmación que incluye:

- el enlace a su aplicación, en el puerto HTTPS estándar — `https://<su-servidor>/`;
- las credenciales o la información generadas por la aplicación, por ejemplo un nombre de usuario administrador, un nombre de base de datos o una contraseña generada.

Durante la instalación se emite un certificado [Let's Encrypt](https://letsencrypt.org/es/) gratuito y renovado automáticamente para el nombre de host de su servidor, y la aplicación desplegada gestiona por sí misma su renovación.

:::warning
Copie sus credenciales inmediatamente. La página de confirmación solo está disponible durante el periodo de gracia posterior a un despliegue correcto (5 minutos por defecto). Una vez que el configurador se haya eliminado, ya no podrá mostrarlas: habría que recuperarlas entonces desde la propia aplicación o reinstalar el servidor.
:::

#### Etapa 5: el configurador se elimina

Poco después de un despliegue correcto, el configurador borra su propio binario, su servicio y sus datos de trabajo. A partir de ese momento:

- la interfaz del configurador en el puerto `10143` deja de responder — **es el comportamiento previsto y no un fallo**;
- su aplicación, sus datos y su certificado HTTPS se conservan;
- su servidor solo ejecuta su aplicación, sin ninguna herramienta de instalación ni interfaz de administración residual.

Dispone del control total del servidor, incluido un acceso root por SSH si añadió una clave durante la instalación. El configurador ya no gestiona nada más allá de esta etapa.

:::info
Si el despliegue **falla**, el configurador *no* se elimina: sigue estando accesible para que el problema pueda diagnosticarse a partir de los registros en tiempo real. Un despliegue fallido suele requerir reinstalar el servidor y volver a empezar.
:::

Para desplegar otra aplicación, reinstale su servidor desde el catálogo de aplicaciones y seleccione la nueva aplicación.

### Resolución de problemas frecuentes

| Síntoma | Causa | Solución |
|---|---|---|
| La página del configurador no se carga en la dirección `https://<su-servidor>:10143/` | La instalación aún no ha finalizado o el acceso entrante al puerto `10143` está bloqueado. | Espere a que finalice la instalación y vuelva a intentarlo. Compruebe que su firewall (incluido el [Edge Network Firewall](/guides/bare-metal-cloud/dedicated-servers/firewall-network) de OVHcloud) permita el tráfico entrante hacia su servidor en el puerto `10143`. |
| La página del configurador ya no se carga después de un despliegue correcto | El configurador se ha eliminado, según lo previsto. | Este comportamiento es normal. Utilice la dirección de su aplicación: `https://<su-servidor>/`. |
| `Unauthorized` al abrir el configurador | El token de acceso falta o es incorrecto. | Vuelva a abrir el configurador utilizando exactamente el enlace y el token facilitados con su instalación. |
| Aparece una advertencia de certificado en la primera carga | El certificado Let's Encrypt aún no se ha emitido; se presenta un certificado autofirmado temporal. | Espere un minuto y vuelva a cargar la página. |
| La aplicación no es accesible mediante HTTPS después de la instalación | El certificado Let's Encrypt no se ha podido emitir, normalmente porque el puerto entrante `80` o `443` está bloqueado o porque el nombre de host no se resuelve. | Compruebe que los puertos `80` y `443` estén abiertos para el tráfico entrante y que el nombre de host de su servidor se resuelva públicamente y, a continuación, reinstale el servidor si es necesario. |
| Desea desplegar una segunda aplicación desde el catálogo | Solo se puede desplegar una aplicación mediante el catálogo. | Reinstale el servidor para desplegar otra aplicación o instale la aplicación adicional manualmente. |
