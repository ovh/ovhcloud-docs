## Objetivo

El objetivo de esta guía es presentar las distintas etapas para configurar su primer KMS (Key Management Service) y crear una clave. Para llamar a la API REST regional del plano de datos, configure un método de autenticación tal como se describe en la guía [Métodos de autenticación OKMS](/guides/manage-and-operate/kms/okms-authentication-methods).

## Requisitos

- Una [cuenta de cliente de OVHcloud](/guides/account-and-service-management/account-information/ovhcloud-account-creation).

## Procedimiento

### Solicitar su KMS

Cada KMS está asociado a una región, de modo que las claves almacenadas en ella tienen la garantía de permanecer en dicha región.

Es posible solicitar varios KMS, ya sea en regiones diferentes o en una misma región.

Como la facturación de un KMS se basa en el número de claves almacenadas en él, solicitar un KMS no genera facturación en sí mismo.

Haga clic en el botón <code className="action">Contratar un dominio OKMS</code>.

<img className="thumbnail" alt="Acceso al menú KMS" src="/images/manage-and-operate/kms/quick-start/access_to_the_KMS_menu_01.png" loading="lazy" />

Indique la región de su KMS.

<img className="thumbnail" alt="Solicitar el KMS" src="/images/manage-and-operate/kms/quick-start/order_kms_01.png" loading="lazy" />

A continuación, debe finalizar el pedido en otra pestaña. Si esta no se ha abierto automáticamente, se muestra el enlace del pedido:

<img className="thumbnail" alt="Solicitar el KMS" src="/images/manage-and-operate/kms/quick-start/order_kms_02.png" loading="lazy" />

Al cabo de unos segundos, el KMS estará disponible en su área de cliente.

<img className="thumbnail" alt="Solicitar el KMS" src="/images/manage-and-operate/kms/quick-start/order_kms_03.png" loading="lazy" />

#### Crear una clave de cifrado

En la pestaña <code className="action">Claves de cifrado</code>, haga clic en el botón <code className="action">Crear una Service Key</code>.

<img className="thumbnail" alt="Crear una clave" src="/images/manage-and-operate/kms/quick-start/create_key_01.png" loading="lazy" />

Un formulario le permite configurar la clave seleccionando su nivel de protección, su tipo, su tamaño y sus usos.

<img className="thumbnail" alt="Crear una clave" src="/images/manage-and-operate/kms/quick-start/create_key_02.png" loading="lazy" />

:::warning
Solo la creación de claves de cifrado a través de las [API regionales](/guides/manage-and-operate/kms/kms-usage) está cubierta por la certificación PCI-DSS.

:::


Una vez creada la clave, haga clic en ella para acceder a sus detalles.

El panel de control muestra las propiedades criptográficas de la clave, así como las acciones que permiten renombrarla, desactivarla o eliminarla.

Para limitar los riesgos de eliminación accidental, es necesario desactivar la clave antes de eliminarla.

:::warning
No existe ninguna forma de recuperar una clave eliminada, y su eliminación conlleva la pérdida de los datos cifrados con ella. Por lo tanto, toda eliminación debe considerarse con la mayor precaución.

:::

#### Crear una clave de cifrado

La creación de una clave se realiza mediante la siguiente API:

|**Método**|**Ruta**|**Descripción**|
| :-: | :-: | :-: |
|POST|/okms/resource/&#123;okmsId&#125;/serviceKey|Crear o importar una CMK|

La API espera los siguientes valores:

|**Campo**|**Valor**|**Descripción**|
| :-: | :-: | :-: |
|name|string|Nombre de la clave|
|context|string|Dato de identificación adicional que permite verificar la autenticidad de la clave|
|type|oct, RSA, EC|Tipo de clave: secuencia de bytes (oct) para claves simétricas, RSA (RSA), Elliptic Curve (EC)|
|size|Integer|Tamaño de la clave - consulte la tabla de correspondencia siguiente|
|operations|Array|Uso de la clave - consulte la tabla de correspondencia siguiente|
|curve|P-256, P-384, P-521|(opcional) Curva criptográfica para las claves de tipo EC|
|protectionLevel|SOFTWARE, HSM|(opcional) Nivel de protección de la clave: `SOFTWARE` (predeterminado) — las operaciones criptográficas se ejecutan en software; `HSM` — las operaciones se ejecutan en hardware especializado compartido (HSM). Las claves HSM no pueden utilizarse para [BYOK](/guides/manage-and-operate/kms/import-export-keys-byok).|

**Ejemplo de creación de clave simétrica:**

```json
{
  "name": "My first AES key",
  "context": "project A",
  "type": "oct",
  "size": 256,
  "operations": [
    "encrypt",
    "decrypt"
  ]
}
```

**Ejemplo de creación de clave asimétrica:**

```json
{
  "name": "My first RSA key",
  "context": "project A",
  "type": "RSA",
  "size": 4096,
  "operations": [
    "sign",
    "verify"
  ]
}
```

**Ejemplo de creación de clave EC:**

```json
{
  "name": "My first EC key",
  "context": "project A",
  "type": "EC",
  "operations": [
    "sign",
    "verify"
  ],
  "curve": "P-256"
}
```

**Ejemplo de creación de clave protegida por HSM:**

```json
{
  "name": "My HSM-backed AES key",
  "context": "project A",
  "type": "oct",
  "size": 256,
  "protectionLevel": "HSM",
  "operations": [
    "encrypt",
    "decrypt"
  ]
}
```

Los tamaños y operaciones posibles según el tipo de clave son los siguientes:

- **oct**:
    - tamaño: 128, 192, 256
    - operaciones:
        - encrypt, decrypt
        - wrapKey, unwrapKey
- **RSA**:
    - tamaño: 2048, 3072, 4096
    - operaciones:
        - sign, verify
        - wrapKey, unwrapKey
- **EC**:
    - tamaño: no especificar
    - curve: P-256, P-384, P-521
    - operaciones: sign, verify

:::info
En las claves RSA, `wrapKey` / `unwrapKey` son mutuamente excluyentes con `sign` / `verify`.
:::

:::warning
Solo la creación de claves de cifrado a través de las [API regionales](/guides/manage-and-operate/kms/kms-usage) está cubierta por la certificación PCI-DSS.

:::

### Autenticarse en el plano de datos OKMS

Antes de llamar a la API REST regional, configure un método de autenticación (token de acceso personal, cuenta de servicio o certificado de acceso). Consulte [Métodos de autenticación OKMS](/guides/manage-and-operate/kms/okms-authentication-methods).

Para el uso de la API REST, se recomienda un token de acceso personal (PAT) o una cuenta de servicio. Utilice preferentemente los [certificados de acceso](/guides/manage-and-operate/kms/okms-certificate-management) para las integraciones KMIP, que requieren una autenticación mediante certificado.

### Utilizar el KMS de OVHcloud

Una vez que su KMS de OVHcloud esté inicializado, es posible utilizarlo de dos maneras diferentes:

- Utilizando la [API REST](/guides/manage-and-operate/kms/kms-usage) para cifrar o firmar sus datos (autenticación mediante PAT, cuenta de servicio o certificado).
- Utilizando el [protocolo KMIP](/guides/manage-and-operate/kms/kms-kmip) para conectar productos compatibles con KMIP (certificado de acceso obligatorio).
