## Objetivo

El objetivo de esta guía es presentar las diferentes etapas para crear y gestionar sus certificados de acceso OKMS en sus productos de Data Security.

## Procedimiento

### Descripción de los certificados de acceso OKMS

Para comunicarse con su dominio OKMS, debe disponer de un certificado de acceso. Se trata de uno de los tres [métodos de autenticación OKMS](/guides/manage-and-operate/kms/okms-authentication-methods); los certificados son **obligatorios para KMIP** y se recomiendan cuando se necesita la autenticación de cliente mTLS. Para el uso de la API REST, un token de acceso personal (PAT) o una cuenta de servicio suele ser más sencillo de configurar.

Un certificado de acceso solo es válido para el dominio para el que ha sido generado.

:::warning
Solo la generación de certificados con un CSR está cubierta por la certificación PCI-DSS.

:::


### Crear un certificado de acceso desde el KMS

<Tabs>
<Tab label="Área de cliente de OVHcloud">

Es posible crear este certificado desde el menú dedicado del KMS.

En la pestaña <code className="action">Certificados de acceso</code>, haga clic en el botón <code className="action">Crear un certificado de acceso</code>.

<img className="thumbnail" alt="Crear un certificado" src="/images/manage-and-operate/kms/okms-certificate-management/create_certificat_01.png" loading="lazy" />

La primera parte del formulario le permite especificar su periodo de validez, seleccionar el algoritmo de firma, así como proporcionar o no su Certificate Signing Request (CSR) en caso de que disponga de su propia clave privada.

##### Sin proporcionar una clave privada

Si no proporciona un CSR, OVHcloud generará el certificado de acceso así como una clave privada.

<img className="thumbnail" alt="Crear un certificado" src="/images/manage-and-operate/kms/okms-certificate-management/create_certificat_02.png" loading="lazy" />

##### Con un CSR

Si dispone de su propia clave privada, es posible utilizarla proporcionando un CSR.

<img className="thumbnail" alt="Crear un certificado" src="/images/manage-and-operate/kms/okms-certificate-management/create_certificat_03.png" loading="lazy" />

La segunda parte del formulario permite indicar las [identidades de OVHcloud](/guides/manage-and-operate/iam/identities-management) asociadas al certificado que permiten calcular los derechos de acceso mediante el [IAM de OVHcloud](/guides/account-and-service-management/account-information/iam-policy-ui).

Es posible añadir la identidad `root` al certificado para no estar limitado por el IAM de OVHcloud.

<img className="thumbnail" alt="Crear un certificado" src="/images/manage-and-operate/kms/okms-certificate-management/create_certificat_04.png" loading="lazy" />

A continuación, es necesario descargar la clave privada del certificado.

:::danger
La clave privada ya no será accesible posteriormente. En caso de pérdida, será necesario volver a generar un certificado.

:::


:::warning
El campo **privateKeyPEM** debe modificarse para reemplazar las apariciones de `\n` por retornos de carro.

:::


<img className="thumbnail" alt="Crear un certificado" src="/images/manage-and-operate/kms/okms-certificate-management/create_certificat_05.png" loading="lazy" />

Por último, es posible descargar la clave pública del certificado desde el panel de control.

<img className="thumbnail" alt="Crear un certificado" src="/images/manage-and-operate/kms/okms-certificate-management/create_certificat_06.png" loading="lazy" />

Es posible generar este certificado dejando que OVHcloud genere la clave privada, o proporcionando su Certificate Signing Request (CSR) en caso de que disponga de su propia clave privada.

##### Sin proporcionar una clave privada

Si no proporciona un CSR, OVHcloud generará el certificado de acceso así como una clave privada.

La generación del certificado se realiza mediante la siguiente API:

<Api version="v2" section="/okms" method="POST" route={"/okms/resource/\{okmsId\}/credential"} />

Es necesario indicar la siguiente información:

- **name**: el nombre del certificado
- **identityURNs**: lista de identidades de OVHcloud en formato URN que se proporcionarán al IAM para el cálculo de los derechos de acceso
- **description**: descripción del certificado (opcional)
- **certificateType**: algoritmo de firma del certificado (ECDSA o RSA) - ECDSA por defecto (opcional)
- **validity**: periodo de validez del certificado en días - 365 días por defecto (opcional)

**Ejemplo de creación de un certificado con la cuenta root:**

```json
{
  "description": "My root access credential",
  "identityURNs": [
    "urn:v1:eu:identity:account:xx1111-ovh"
  ],
  "name": "root",
  "validity": 30
}
```

**Ejemplo de creación de un certificado con una cuenta de usuario local:**

```json
{
  "description": "My access credential",
  "identityURNs": [
    "urn:v1:eu:identity:user:xx1111-ovh/john.smith",
    "urn:v1:eu:identity:group:xx1111-ovh/my_group"
  ],
  "name": "John Smith",
  "validity": 30
}
```

A continuación, la API devuelve el estado de creación del certificado:

```json

  "name": "John Smith",
  "description": "My access credential",
  "identityURNs": [
    "urn:v1:eu:identity:user:xx1111-ovh/john.smith",
    "urn:v1:eu:identity:group:xx1111-ovh/my_group"
  ],
  "certificateType": "ECDSA",
  "status": "CREATING",
  "fromCSR": false,
  "privateKeyPEM": "-----BEGIN EC PRIVATE KEY-----\nMHcCAQEEIDOfWuMVQxl5quoURzThF4zTI9YYTmylSaPjneLBwP+2oAoGCCqGSM49\nAwEHoUQDQgAERd1eMw0YdAD+E9oSymGc4bCL1mfJl0EZwoM2ya/uKFFVFnGMnckg\nXXXXXXXXXXXXXXX==\n-----END EC PRIVATE KEY-----\n",
```

:::

Si dispone de su propia clave privada, es posible utilizarla proporcionando un CSR.
