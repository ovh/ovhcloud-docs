## Objetivo

El objetivo de esta guía es presentar la utilización del Secret Manager a través de la consola de OVHcloud.

## Requisitos

- Disponer de una [cuenta de cliente de OVHcloud](/guides/account-and-service-management/account-information/ovhcloud-account-creation).
- Para acceder a los secretos mediante la API REST o la API compatible con HashiCorp Vault KV2, configure un [método de autenticación](/guides/manage-and-operate/kms/okms-authentication-methods) para su dominio OKMS (token de acceso personal, cuenta de servicio o certificado de acceso).

[[cpnav:security-secret-manager]]

## Procedimiento

### Descripción

El Secret Manager es un producto que le permite almacenar de forma segura las credenciales, claves de API, claves SSH o cualquier otro tipo de secreto necesario para el funcionamiento de sus aplicaciones.

Un secreto es una colección de una o varias claves/valores agrupadas dentro de una versión.
Cada modificación de un secreto conlleva la creación de una nueva versión de ese secreto, lo que permite retroceder en el historial de modificaciones del secreto.

### Crear un secreto

En la consola de OVHcloud, los secretos se gestionan en Key & Secret Manager. En el menú de la izquierda, abra <code className="action">Seguridad</code> y haga clic en <code className="action">Key & Secret Manager</code>. Cada dominio OKMS dispone de una pestaña <code className="action">Secrets</code>, que lista los secretos almacenados en ese dominio.

<img className="thumbnail" alt="Pestaña Secrets de un dominio OKMS con el botón Crear un secreto" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secrets-tab.png" loading="lazy" />

Para crear un secreto, haga clic en <code className="action">Crear un secreto</code>.

El formulario de creación no permite elegir la región: el secreto se crea en el dominio OKMS seleccionado en la lista **Dominio OKMS** y, por tanto, en la región de ese dominio. Seleccione el dominio correcto antes de hacer clic en <code className="action">Crear un secreto</code>.

:::info
Si todavía no dispone de un dominio OKMS en la región en la que desea crear el secreto, cree uno primero: abra la lista **Dominio OKMS**, haga clic en <code className="action">Crear un dominio</code> y elija la región.
La creación del dominio puede tardar unos minutos.
:::


Indique a continuación el **Path** del secreto, por ejemplo **prod/database/MySQL**. Este Path sirve para organizar los secretos de forma jerárquica.

Después, indique el contenido del secreto en la sección **Configuración de valores**. El secreto contiene una lista de claves/valores. Por defecto, se introducen uno a uno en la vista **Clave de valor** (<code className="action">Añadir una clave/valor</code> añade una línea). En la vista **JSON**, puede introducirlos en formato JSON:

```json
{
    "login": "admin",
    "password": "my_secret_password"
}
```

<img className="thumbnail" alt="Página Crear un secreto con las secciones Path y Configuración de valores" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/create-secret-form.png" loading="lazy" />

:::info
No hay límite en cuanto al número de claves/valores de un secreto, sin embargo el tamaño total de los datos no debe superar los 64 KB.
:::


Una vez creado el secreto, este aparece en la lista de secretos de la pestaña **Secrets** del dominio OKMS.

### Gestionar los secretos

Una vez creado un secreto, la lista de secretos se muestra en la pestaña **Secrets** del dominio OKMS, en la consola de OVHcloud.
Para mostrar los secretos de otro dominio OKMS, selecciónelo en la lista **Dominio OKMS** situada encima de las pestañas, donde sus dominios están agrupados por región.

Puede acceder a la configuración del secreto haciendo clic en su Path en la lista de secretos para mostrar su contenido, crear una nueva versión o eliminarlo.

El panel de control del secreto muestra varias informaciones, como la información general así como los parámetros que se aplican al secreto:

- **Número máximo de versiones**: Más allá del valor indicado, se elimina la versión más antigua.
- **Periodo de expiración de una versión**: Más allá de la duración indicada, la versión se desactiva.
- **CAS («Check-And-Set Version Control»)**: Si está activado, debe especificar siempre el número de versión actual al realizar modificaciones.

<img className="thumbnail" alt="Panel de control del secreto con las secciones Valores, Información general y Configuración" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secret-dashboard.png" loading="lazy" />

#### Acceder al contenido de un secreto

Un usuario que disponga de los derechos IAM necesarios puede acceder al contenido de un secreto. Configure la autenticación y las políticas IAM como se describe en [Métodos de autenticación OKMS](/guides/manage-and-operate/kms/okms-authentication-methods).

:::info
Los derechos para listar una versión (**okms:apiovh:secret/get**) son diferentes del derecho para recuperar el contenido de esa versión (**okms:apiovh:secret/version/getData**).
:::


Para ello, haga clic en <code className="action">Revelar el valor</code> en la sección **Valores** del panel de control del secreto.

La sección **Valores** se despliega y muestra el contenido de la versión más reciente del secreto, en forma de claves/valores o en formato JSON. Cada valor puede copiarse.

<img className="thumbnail" alt="Sección Valores que muestra los pares clave/valor de la versión actual" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secret-values-revealed.png" loading="lazy" />

Un selector permite navegar entre las diferentes versiones del secreto, así como consultar el estado de la versión seleccionada.
Si la versión está desactivada o eliminada, no se muestra ningún valor.

#### Gestionar las versiones

Para acceder a las versiones de un secreto, haga clic en la pestaña <code className="action">Versiones</code>. En ella se enumeran todas las versiones del secreto, con el número, la fecha de creación, la fecha de expiración y el estado de cada una.
Cada modificación de un secreto conlleva la creación de una nueva versión.

<img className="thumbnail" alt="Pestaña Versiones que lista las versiones de un secreto con su estado" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secret-versions.png" loading="lazy" />

Una versión puede ser:

- Activa: El valor de esta versión es accesible.
- Desactivada: El valor de esta versión sigue presente en el sistema pero ya no es accesible mientras la versión no se reactive.
- Eliminada: El valor de esta versión ya no está presente en el sistema y no puede restaurarse.

Para cada versión, haga clic en <code className="action">Revelar la versión</code> para mostrar su valor. El botón `⋮` abre un menú que permite desactivar (<code className="action">Desactivar</code>) o reactivar (<code className="action">Reactivar</code>) la versión, o eliminarla (<code className="action">Eliminar</code>).

Una versión eliminada por el parámetro **Número máximo de versiones** ya no aparece en la lista de versiones.

### Gestionar el dominio OKMS

El dominio OKMS del Secret Manager es común con el dominio OKMS del Key Management Service.
La creación o la eliminación de un dominio OKMS tiene, por tanto, consecuencias en ambos productos.

Puede modificar la configuración de los secretos del dominio OKMS desde su pestaña **Vista general**, en la sección **Configuración de los Secrets** (<code className="action">Modificar</code>).

#### Caso de varios dominios OKMS

Pueden existir varios dominios OKMS en una misma región. El dominio OKMS se elige previamente en la lista **Dominio OKMS** situada encima de las pestañas, que agrupa sus dominios por región. Los secretos que muestra o crea pertenecen al dominio seleccionado en esa lista: la creación de un secreto no incluye ningún paso de selección adicional.

<img className="thumbnail" alt="Lista de dominios OKMS con los dominios agrupados por región y la entrada Crear un dominio" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/okms-domain-switcher.png" loading="lazy" />

Para añadir un dominio OKMS en una región, haga clic en <code className="action">Crear un dominio</code> en la parte superior de esta lista y, a continuación, elija la región.

### Utilizar el Secret Manager mediante API

El Secret Manager es accesible mediante dos conjuntos de API diferentes. Ambos manipulan los mismos objetos: un secreto creado por uno de los métodos es accesible por el otro.

Antes de llamar a una u otra API, configure un [método de autenticación](/guides/manage-and-operate/kms/okms-authentication-methods) y la [política IAM](/guides/manage-and-operate/kms/okms-authentication-methods#iam-rights-for-okms) requerida en su dominio OKMS. Para la utilización de la API REST, se recomienda un token de acceso personal (PAT) o una cuenta de servicio.

- Una [API REST](/guides/manage-and-operate/secret-manager/rest-api) similar a los estándares de API de OVHcloud.
- Una [API compatible con HashiCorp Vault KV2](/guides/manage-and-operate/secret-manager/kv2-api) que aporta compatibilidad con las aplicaciones ya compatibles con HashiCorp Vault KV2.
