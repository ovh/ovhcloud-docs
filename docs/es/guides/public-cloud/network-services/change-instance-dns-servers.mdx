## Objetivo

Por defecto, el servidor DNS configurado en las instancias de Public Cloud será el de OVHcloud (213.186.33.99, por ejemplo).<br/>
Puede añadir un servidor secundario o sustituir esta configuración por la suya. Sin embargo, los servidores DNS son configurados automáticamente por un servidor DHCP y no podrá modificar la configuración DNS editando el archivo `resolv.conf`.

**Esta guía explica cómo cambiar la configuración DHCP de una instancia para cambiar los servidores DNS.**

:::warning
OVHcloud le ofrece servicios cuya configuración y gestión son responsabilidad suya. Por lo tanto, usted deberá asegurarse de que estos servicios funcionen correctamente.

Esta guía le ayudará a realizar las tareas más habituales. No obstante, si tiene dificultades o dudas con respecto a la administración, el uso o la instalación de un servicio en un servidor, le recomendamos que contacte con un [proveedor de servicios especializado](/links/partner).
:::

## Procedimiento

Conéctese a su instancia por SSH. Para más información, consulte la guía "[Conectarse a una instancia de Public Cloud](/guides/public-cloud/compute/getting-started#connect-instance)".

<Tabs>
  <Tab label="Debian / Ubuntu">
    Con el editor de texto que desee, edite el archivo `/etc/dhcp/dhclient.conf` para configurar los servidores DNS que desee.

    Sustituya `IP1` e `IP2` por las direcciones IP de sus servidores DNS y, a continuación, utilice la directiva adaptada a sus necesidades:

    - Para **sustituir** el servidor DNS configurado por defecto:

    ```console
    supersede domain-name-servers IP1, IP2;
    ```

    - Para **preferir** sus servidores DNS al configurado por defecto:

    ```console
    prepend domain-name-servers IP1, IP2;
    ```

    - Para utilizar sus servidores DNS **únicamente si el servidor por defecto no está disponible**:

    ```console
    append domain-name-servers IP1, IP2;
    ```

    Guarde el archivo y, a continuación, compruebe que la configuración se haya aplicado correctamente:

    ```bash
    cat /etc/resolv.conf
    ```

    ```console
    domain openstacklocal
    search openstacklocal
    nameserver IP1
    nameserver IP2
    ```
  </Tab>
  <Tab label="CentOS / Fedora">
    Compruebe la configuración actual con el comando `nmcli`:

    ```bash
    nmcli
    ```

    ```console
    eth0: connected to System eth0
            "Red Hat Virtio"
            ethernet (virtio_net), FA:16:3E:B6:FB:89, hw, mtu 1500
            ip4 default
            inet4 51.77.205.51/32
            route4 0.0.0.0/0
            route4 51.77.205.51/32
            route4 51.77.204.1/32
            inet6 fe80::f816:3eff:feb6:fb89/64
            route6 ff00::/8
            route6 fe80::/64

    lo: non-managed
            "lo"
            loopback (unknown), 00:00:00:00:00:00, sw, mtu 65536

    DNS configuration:
            servers: 127.0.0.1 213.186.33.99
            interface: eth0
    ```

    Obtenga el nombre de su interfaz pública:

    ```bash
    nmcli connection show
    ```

    ```console
    NAME         UUID                                  TYPE      DEVICE
    System eth0  5fb06bd0-0bb0-7ffb-45f1-d6edd65f3e03  ethernet  eth0
    ```

    Desactive la modificación automática de los DNS y añada sus servidores DNS (sustituya `System eth0` por el valor real y `IP1`/`IP2` por sus direcciones IP):

    ```bash
    nmcli con mod "System eth0" ipv4.ignore-auto-dns yes
    nmcli con mod "System eth0" ipv4.dns "IP1 IP2"
    ```

    Aplique la configuración:

    ```bash
    nmcli con down "System eth0" && nmcli con up "System eth0"
    ```

    Compruebe que la configuración se aplique correctamente:

    ```bash
    nmcli | grep -E 'DNS|server|interface'
    ```

    ```console
    DNS configuration:
            servers: IP1 IP2
            interface: eth0
    ```
  </Tab>
