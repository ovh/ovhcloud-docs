## Objetivo

Una [Gateway](/links/public-cloud/gateway) ofrece un método de conexión saliente segura desde sus instancias en red privada, o incluso la posibilidad de utilizar direcciones Floating IP con su instancia o su Load Balancer para la exposición de servicios.

**Aprenda a crear una red privada con una Gateway.**

## Requisitos

- Tener un [proyecto Public Cloud](/links/public-cloud/public-cloud) en su cuenta de OVHcloud
- **Para la API de OVHcloud:** identificadores de API ([Primeros pasos con la API de OVHcloud](/guides/manage-and-operate/api/first-steps))
- **Para la CLI OVHcloud:** la [CLI OVHcloud](https://github.com/ovh/ovhcloud-cli) instalada y configurada con sus identificadores
- **Para Terraform:** Terraform instalado y el provider OVHcloud configurado ([Cómo utilizar Terraform en el Public Cloud de OVHcloud](/guides/public-cloud/cross-functional/how-to-use-terraform))
- **Para la API OpenStack:** un entorno OpenStack configurado ([Preparar el entorno](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment))

## Procedimiento

### Modelos de Gateway

Antes de crear una Gateway, elija el modelo adaptado a sus necesidades de ancho de banda:

:::info
Tenga en cuenta que, actualmente, el tamaño 2XL no está disponible en las regiones de Mumbai, Singapur y Sydney.
:::

| Modelo | Ancho de banda |
|--------|----------------|
| S | hasta 200 Mbps |
| M | hasta 500 Mbps |
| L | hasta 2 Gbps |
| XL | hasta 4 Gbps |
| 2XL | hasta 8 Gbps |

### Crear una red privada con una Gateway

<Tabs>
  <Tab label="Consola de OVHcloud">
    **Paso 1 — Acceder a la creación**

    Haga clic en <code className="action">Gateway</code> en el menú de la izquierda, en **Red**.

    Tenga en cuenta que es necesario haber activado el vRack antes de continuar. Si no dispone de uno, consulte la sección [activación del vRack](/guides/public-cloud/network-services/vrack#activation) de la guía correspondiente.

    A continuación, haga clic en el botón <code className="action">Crear un servicio Gateway</code>.

    **Paso 2 — Asignar un nombre a la Gateway y seleccionar la región y el tamaño**

    Introduzca el **Nombre del servicio Gateway**. En **Seleccionar una región**, elija preferentemente la región donde se encuentran sus instancias privadas (puede **Filtrar un modo de despliegue**).

    A continuación, seleccione el tamaño de su Gateway en **Seleccionar el tamaño** (consulte la tabla de modelos anterior).

    **Paso 3 — Asociar una red privada**

    En la sección **Asociar a una red privada específica**, seleccione una red privada existente en **Seleccionar una red privada**.

    :::info
    Solo las redes privadas de región única son compatibles con Gateway.
    :::

    También puede hacer clic en <code className="action">Crear una red privada</code> para crear una nueva red privada sobre la marcha: introduzca el **Nombre de la red privada**, el **vLAN ID** y el **CIDR**, e indique si debe marcarse **DHCP activado**.

    **Paso 4 — Confirmar la creación**

    Haga clic en <code className="action">Crear un servicio Gateway</code> para iniciar el despliegue. La creación puede tardar varios minutos.

    Una vez finalizada la creación, la red privada es visible en la sección <code className="action">Private Network</code> del menú **Red**, y la Gateway aparece en la sección <code className="action">Gateway</code>.
  </Tab>
  <Tab label="API de OVHcloud">
    Acceda a la interfaz APIv6 de OVHcloud. Si lo necesita, consulte la guía [Primeros pasos con la API de OVHcloud](/guides/manage-and-operate/api/first-steps).

    **Recuperar el identificador del proyecto**

    Si el identificador del proyecto es desconocido, utilice las siguientes llamadas:

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project"} />

    :::info
    Esta llamada recupera la lista de proyectos.
    :::

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}"} />

    :::info
    Esta llamada identifica el proyecto mediante el campo `description`.
    :::

    **Crear la red privada con una Gateway**

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway"} />

    Rellene los campos según la siguiente tabla:

    | Campo | Descripción |
    |-------|-------------|
    | `serviceName` | El identificador de su proyecto |
    | `regionName` | Por ejemplo: `GRA9` |
    | `model` | Tamaño de la Gateway (`s`, `m`, `l`, `xl`, `2xl`) |
    | `name` | Nombre de su Gateway (`null` para el nombre predeterminado) |
    | `network.name` | Nombre de la red privada (`null` para el nombre predeterminado) |
    | `network.cidr` | Bloque de direcciones IP de la subred (ej.: `192.168.1.0/24`) |
    | `network.enableDhcp` | Marque para activar el DHCP |
    | `network.ipVersion` | `4` (IPv6 no disponible) |
    | `network.vlanId` | Valor entre 2 y 4000, o vacío para una asignación automática |

    :::info
    Repita la operación para cada región donde estén presentes sus instancias privadas.
    :::

    Para comprobar los detalles de su Gateway:

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway"} />

    Deje `subnetId` vacío para listar todas las Gateways de la región especificada.
  </Tab>
  <Tab label="CLI OVHcloud">
    Utilice la [CLI OVHcloud](https://github.com/ovh/ovhcloud-cli) para crear una red privada con una Gateway. Defina su proyecto cloud con `--cloud-project <project_id>` o configúrelo en su perfil.

    **Crear una Gateway con una nueva red privada:**

    ```bash
    ovhcloud cloud network gateway create <region> \
      --cloud-project <project_id> \
      --name my-gateway \
      --model s \
      --network-name my-network \
      --subnet-cidr 192.168.1.0/24 \
      --subnet-enable-dhcp \
      --wait
    ```

    **Crear una Gateway en una red privada existente:**

    ```bash
    ovhcloud cloud network gateway create <region> \
      --cloud-project <project_id> \
      --name my-gateway \
      --model s \
      --network-id <network_id> \
      --subnet-id <subnet_id> \
      --wait
    ```

    Modelos disponibles: `s`, `m`, `l`, `xl`, `2xl`.

    :::info
    Solo las redes privadas de región única son compatibles con Gateway.
    :::
  </Tab>
  <Tab label="Terraform">
    Antes de comenzar, consulte la guía: [Cómo utilizar Terraform en el Public Cloud de OVHcloud](/guides/public-cloud/cross-functional/how-to-use-terraform)

    Cree un archivo Terraform (por ejemplo, `private_network_gateway.tf`) con el siguiente contenido:

    ```hcl
    resource "ovh_cloud_project_network_private" "mypriv" {
      service_name = "<project_id>"
      vlan_id      = "0"
      name         = "mypriv"
      regions      = ["GRA9"]
    }

    resource "ovh_cloud_project_network_private_subnet" "myprivsub" {
      service_name = ovh_cloud_project_network_private.mypriv.service_name
      network_id   = ovh_cloud_project_network_private.mypriv.id
      region       = "GRA9"
      start        = "10.0.0.2"
      end          = "10.0.255.254"
      network      = "10.0.0.0/16"
      dhcp         = true
    }

    resource "ovh_cloud_project_gateway" "gateway" {
      service_name = ovh_cloud_project_network_private.mypriv.service_name
      name         = "my-gateway"
      model        = "s"
      region       = ovh_cloud_project_network_private_subnet.myprivsub.region
      network_id   = tolist(ovh_cloud_project_network_private.mypriv.regions_attributes[*].openstackid)[0]
      subnet_id    = ovh_cloud_project_network_private_subnet.myprivsub.id
    }
    ```

    Aplique la configuración:

    ```console
    terraform apply
    ```
  </Tab>
  <Tab label="API OpenStack">
    Antes de continuar, consulte las siguientes guías:

    - [Preparar el entorno para utilizar la API OpenStack](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment)
    - [Definir las variables de entorno de OpenStack](/guides/public-cloud/cross-functional/compute-set-openstack-environment-variables)

    **Paso 1 — Crear una red y una subred**

    ```console
    openstack network create my_network

    openstack subnet create my_subnet --subnet-range <my_private_ip_range/mask> --network my_network --no-dhcp
    ```

    **Paso 2 — Listar los niveles de calidad de servicio**

    ```console
    openstack network qos policy list
    +--------------------------------------+---------------+--------+---------+----------------------------------+
    | ID                                   | Name          | Shared | Default | Project                          |
    +--------------------------------------+---------------+--------+---------+----------------------------------+
    | a5524eb5-944e-4106-b209-9478bbdcedab | large_router  | True   | False   | XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX |
    | c210f5b2-db59-4973-a25f-9131195b6bcf | medium_router | True   | False   | XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX |
    | ec0ee74d-a1f3-43f6-87aa-b0e69ef8ce45 | small_router  | True   | False   | XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX |
    +--------------------------------------+---------------+--------+---------+----------------------------------+
    ```

    **Paso 3 — Crear el router y configurar la Gateway**

    ```console
    openstack router create my_router

    openstack router add subnet my_router my_subnet

    openstack router set --external-gateway Ext-Net --qos-policy QOS_ID_OF_YOUR_CHOICE my_router
    ```

    Si no indica el parámetro `--qos-policy`, se aplica la calidad de servicio `small`.
  </Tab>
