## Objetivo

Una [Gateway](/links/public-cloud/gateway) de OVHcloud proporciona una conectividad saliente segura (SNAT) para las instancias de una subred privada y es necesaria en dicha subred para utilizar las [Floating IPs](/links/public-cloud/floating-ip) para la exposición pública de estos recursos privados.

**Esta guía le explica cómo crear, mostrar, modificar y eliminar una Gateway Public Cloud desde el área de cliente de OVHcloud, la API de OVHcloud, ovhcloud-cli o Terraform.**

## Requisitos

- Tener un [proyecto Public Cloud](/links/public-cloud/public-cloud) en su cuenta de OVHcloud
- Disponer de una red privada con al menos una subred en la región de destino (consulte [Configurar vRack para Public Cloud](/guides/public-cloud/network-services/vrack))
- **Para la API de OVHcloud:** credenciales de la API de OVHcloud ([Primeros pasos con las API de OVHcloud](/guides/manage-and-operate/api/first-steps))
- **Para ovhcloud-cli:** [ovhcloud-cli](https://github.com/ovh/ovhcloud-cli) instalado y configurado con sus credenciales
- **Para Terraform:** Terraform instalado y el proveedor OVH configurado ([Cómo utilizar Terraform con OVHcloud](/guides/public-cloud/cross-functional/how-to-use-terraform))

## Procedimiento

### Modelos de Gateway

Antes de crear una Gateway, elija el modelo que se corresponda con sus necesidades de ancho de banda:

| Modelo | Ancho de banda |
|--------|----------------|
| S | hasta 200 Mbps |
| M | hasta 500 Mbps |
| L | hasta 2 Gbps |
| XL | hasta 4 Gbps |
| 2XL | hasta 8 Gbps |
| 3XL | hasta 16 Gbps |

### Crear una Gateway

<Tabs>
  <Tab label="Área de cliente de OVHcloud">
    Desde su proyecto Public Cloud, haga clic en <code className="action">Gateway</code> en el menú de la izquierda, en **Network**, y luego haga clic en <code className="action">Crear una Gateway</code>.

    1. **Seleccione una región.** Elija la región en la que están desplegadas sus instancias privadas.
    2. **Seleccione un tamaño.** Elija el modelo de Gateway en función de sus necesidades de ancho de banda (consulte la tabla anterior).
    3. **Asigne un nombre y asocie una red.** Introduzca un nombre para su Gateway y seleccione una red privada existente en la lista desplegable, o haga clic en <code className="action">Añadir una red privada</code> para crear una directamente.
    4. Haga clic en <code className="action">Crear una Gateway</code> para confirmar. El aprovisionamiento de la Gateway tarda unos minutos.

    Una vez creada, la Gateway aparece en la sección <code className="action">Gateway</code> y la red privada asociada es visible en <code className="action">Redes privadas</code>.

    :::info
    La Gateway solo admite redes privadas de una única región.

    :::
  </Tab>
  <Tab label="API de OVHcloud">
    Conéctese a la [API de OVHcloud](https://api.ovh.com/console/) y utilice la siguiente llamada para crear una Gateway junto con una nueva red privada y una subred en una sola operación:

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway"} />

    | Campo | Descripción |
    |-------|-------------|
    | `serviceName` | El identificador de su proyecto Public Cloud |
    | `regionName` | La región de destino (p. ej.: `GRA9`) |
    | `model` | Tamaño de la Gateway: `s`, `m`, `l`, `xl`, `2xl`, `3xl` |
    | `name` | Nombre de su Gateway |
    | `network.name` | Nombre de la nueva red privada |
    | `network.cidr` | CIDR de la subred (p. ej.: `192.168.1.0/24`) |
    | `network.enableDhcp` | `true` para activar el DHCP en la subred |
    | `network.ipVersion` | `4` (IPv6 aún no disponible) |
    | `network.vlanId` | Identificador VLAN (2–4000), o vacío para una asignación automática |

    La llamada devuelve un objeto `cloud.Operation`. Para asociar una Gateway a una subred **existente**, utilice:

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/network/\\{networkId\\}/subnet/\\{subnetId\\}/gateway"} />

    Para obtener el identificador de su proyecto:

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project"} />
  </Tab>
  <Tab label="ovhcloud-cli">
    Utilice `ovhcloud cloud network gateway create` con la región de destino y la opción `--wait` para esperar a que finalice el aprovisionamiento.

    **Crear una Gateway en una red privada existente:**

    ```bash
    ovhcloud cloud network gateway create <region> \
      --cloud-project <project_id> \
      --name my-gateway \
      --model s \
      --network-id <network_id> \
      --subnet-id <subnet_id> \
      --wait
    ```

    **Crear una Gateway con una nueva red privada:**

    ```bash
    ovhcloud cloud network gateway create <region> \
      --cloud-project <project_id> \
      --name my-gateway \
      --model s \
      --network-name my-network \
      --subnet-cidr 192.168.1.0/24 \
      --subnet-enable-dhcp \
      --wait
    ```

    Modelos disponibles: `s`, `m`, `l`, `xl`, `2xl`, `3xl`.
  </Tab>
  <Tab label="Terraform">
    Cree un archivo de configuración de Terraform (p. ej.: `gateway.tf`) con los siguientes recursos:

    ```hcl
    resource "ovh_cloud_project_network_private" "mypriv" {
      service_name = "<project_id>"
      vlan_id      = "0"
      name         = "my-network"
      regions      = ["GRA9"]
    }

    resource "ovh_cloud_project_network_private_subnet" "myprivsub" {
      service_name = ovh_cloud_project_network_private.mypriv.service_name
      network_id   = ovh_cloud_project_network_private.mypriv.id
      region       = "GRA9"
      start        = "10.0.0.2"
      end          = "10.0.255.254"
      network      = "10.0.0.0/16"
      dhcp         = true
    }

    resource "ovh_cloud_project_gateway" "gateway" {
      service_name = ovh_cloud_project_network_private.mypriv.service_name
      name         = "my-gateway"
      model        = "s"
      region       = ovh_cloud_project_network_private_subnet.myprivsub.region
      network_id   = tolist(ovh_cloud_project_network_private.mypriv.regions_attributes[*].openstackid)[0]
      subnet_id    = ovh_cloud_project_network_private_subnet.myprivsub.id
    }
    ```

    Aplique la configuración:

    ```bash
    terraform init
    terraform apply
    ```

    :::info
    Sustituya `GRA9` por su región de destino y `<project_id>` por el identificador de su proyecto Public Cloud.

    :::
  </Tab>
</Tabs>

### Mostrar sus Gateways

<Tabs>
  <Tab label="Área de cliente de OVHcloud">
    Desde su proyecto Public Cloud, haga clic en <code className="action">Gateway</code> en el menú de la izquierda, en **Network**.

    La página muestra todas las Gateways de su proyecto con su región, modelo, estado y red asociada.
  </Tab>
  <Tab label="API de OVHcloud">
    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway"} />

    | Campo | Descripción |
    |-------|-------------|
    | `serviceName` | El identificador de su proyecto Public Cloud |
    | `regionName` | La región de destino |
    | `subnetId` | (Opcional) Filtrar por identificador de subred asociada |
    | `withSubnets` | (Opcional) Incluir los detalles de las subredes en la respuesta |
  </Tab>
  <Tab label="ovhcloud-cli">
    ```bash
    ovhcloud cloud network gateway list --cloud-project <project_id>
    ```

    Filtrar por patrón de nombre:

    ```bash
    ovhcloud cloud network gateway list \
      --cloud-project <project_id> \
      --filter 'name=~"^my-.*"'
    ```
  </Tab>
</Tabs>

### Modificar una Gateway

Puede modificar el nombre o el modelo (tamaño) de una Gateway existente.

<Tabs>
  <Tab label="Área de cliente de OVHcloud">
    Desde la lista <code className="action">Gateway</code>, haga clic en el menú <code className="action">...</code> situado junto a su Gateway y, a continuación, seleccione <code className="action">Editar</code>.

    Modifique el nombre o seleccione un nuevo modelo y, a continuación, confirme.
  </Tab>
  <Tab label="API de OVHcloud">
    <Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway/\\{id\\}"} />

    Transmita los campos que desea modificar en el cuerpo de la solicitud (`name`, `model` o ambos).
  </Tab>
  <Tab label="ovhcloud-cli">
    ```bash
    ovhcloud cloud network gateway edit <gateway_id> \
      --cloud-project <project_id> \
      --name new-name \
      --model m
    ```

    Puede utilizar `--name`, `--model` o ambos.
  </Tab>
  <Tab label="Terraform">
    Modifique el campo `name` o `model` en su bloque de recurso `ovh_cloud_project_gateway` y, a continuación, aplique:

    ```bash
    terraform apply
    ```
  </Tab>
</Tabs>

### Eliminar una Gateway

:::warning
La eliminación de una Gateway es irreversible. Las instancias que la utilizan para su conectividad saliente perderán su acceso a internet.

:::

<Tabs>
  <Tab label="Área de cliente de OVHcloud">
    Desde la lista <code className="action">Gateway</code>, haga clic en el menú <code className="action">...</code> situado junto a su Gateway, seleccione <code className="action">Eliminar</code> y confirme.
  </Tab>
  <Tab label="API de OVHcloud">
    <Api version="v1" section="/cloud" method="DELETE" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway/\\{id\\}"} />

    La llamada devuelve un `cloud.Operation`. La eliminación es asíncrona — compruebe el estado de la operación si es necesario:

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/operation/\\{operationId\\}"} />
  </Tab>
  <Tab label="ovhcloud-cli">
    ```bash
    ovhcloud cloud network gateway delete <gateway_id> \
      --cloud-project <project_id>
    ```
  </Tab>
  <Tab label="Terraform">
    Elimine el bloque de recurso `ovh_cloud_project_gateway` de su archivo de configuración y, a continuación, aplique:

    ```bash
    terraform apply
    ```

    Para eliminar todos los recursos de la configuración:

    ```bash
    terraform destroy
    ```
  </Tab>
</Tabs>
