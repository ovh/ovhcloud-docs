## Objetivo

El protocolo de Internet versión 6 (IPv6) es la versión más reciente del protocolo de Internet (IP). Está diseñado para resolver el agotamiento de las direcciones IPv4, previsto desde hace tiempo, utilizando direcciones de 128 bits en lugar de los 32 bits tradicionales de IPv4.

Cada instancia de Public Cloud se entrega con una dirección IPv4 y una dirección IPv6.

En las distribuciones Linux recientes, la dirección IPv6 está configurada por defecto. No es el caso en las instancias Windows.

**En este tutorial le explicamos cómo configurar una dirección IPv6 en una instancia de Public Cloud.**

:::info
Actualmente, las ofertas Floating IP y Gateway no son compatibles con IPv6. IPv6 solo puede utilizarse con las instancias que disponen de una [Basic IP](/guides/public-cloud/network-services/concepts#publicmode). En las regiones 3-AZ, la dirección IPv6 de una Basic IP todavía no puede aprovisionarse desde el área de cliente de OVHcloud.

:::

## Requisitos

- Tener una instancia de Public Cloud, independientemente del modelo.
- Tener acceso de administrador (sudo) a su servidor por SSH o escritorio remoto (Windows).
- Tener conocimientos básicos de redes.

## Procedimiento

Las siguientes secciones contienen las configuraciones de las distribuciones que ofrecemos actualmente, así como de las distribuciones/sistemas operativos más utilizados. El primer paso consiste siempre en conectarse al servidor por SSH o mediante una sesión de conexión GUI (RDP para una instancia Windows).

:::warning
Tenga en cuenta que, en las distribuciones Linux recientes, la dirección IPv6 está configurada por defecto en nuestras instancias de Public Cloud. Asegúrese de comprobar el archivo de configuración del sistema operativo antes de realizar cualquier cambio.

:::

### Léxico

A continuación encontrará un breve léxico de los términos utilizados en este tutorial:

|Léxico|Descripción|
|---|---|
|YOUR_IPV6|La dirección IPv6 asignada a su servicio (p. ej.: 2607:5300:60:62ac:abcd)|
|IPV6_PREFIX|El prefijo de su bloque IPv6 (p. ej.: 2607:5300:60:62ac::/128 -> netmask = 128)|
|IPV6_GATEWAY|La puerta de enlace de su bloque IPv6 (p. ej.: 2607:5300:60:62ac::1)|

### Ejemplos de configuraciones persistentes

:::info
**Ejemplos**

La información que se indica a continuación se ofrece a modo de ejemplo.

Como administrador de sus servicios, le corresponde adaptar esta información a su distribución o a su sistema operativo.

:::

:::warning
Antes de modificar un archivo de configuración, cree siempre una copia de seguridad del original para poder restaurarlo en caso de problema.

:::

En primer lugar, conéctese a su instancia por SSH.

:::tip
Seleccione la pestaña correspondiente a su sistema operativo.

:::

<Tabs>
  <Tab label="Debian (excepto Debian 12)">
    Por defecto, los archivos de configuración se encuentran en el directorio `/etc/network/interfaces.d/`.
    
    La práctica recomendada es crear un archivo de configuración independiente en el directorio `/etc/network/interfaces.d/` para configurar la IPv6. En nuestro ejemplo, nuestro archivo se llama `51-cloud-init-ipv6`:
    
    ```bash
    sudo nano /etc/network/interfaces.d/51-cloud-init-ipv6
    ```
    
    Esto separa la configuración IPv6 y le permite revertir fácilmente los cambios en caso de error.
    
    Añada las siguientes líneas al archivo. Sustituya los elementos genéricos (es decir, `YOUR_IPV6`, `IPV6_PREFIX` y `IPV6_GATEWAY`), así como la interfaz de red (si su servidor no utiliza **eth0**), por sus valores específicos:
    
    ```console
    iface eth0 inet6 static
    address YOUR_IPV6
    netmask IPV6_PREFIX
    post-up /sbin/ip -6 route add IPV6_GATEWAY dev eth0
    post-up /sbin/ip -6 route add default via IPV6_GATEWAY dev eth0
    pre-down /sbin/ip -6 route del default via IPV6_GATEWAY dev eth0
    pre-down /sbin/ip -6 route del IPV6_GATEWAY dev eth0
    ```
    
    <details>
    <summary>Ejemplo de configuración</summary>

    ```console
    iface eth0 inet6 static
    address 2607:5300:201:abcd::7c5
    netmask 128
    post-up /sbin/ip -6 route add 2607:5300:201:abcd::1 dev eth0
    post-up /sbin/ip -6 route add default via 2607:5300:201:abcd::1 dev eth0
    pre-down /sbin/ip -6 route del default via 2607:5300:201:abcd::1 dev eth0
    pre-down /sbin/ip -6 route del 2607:5300:201:abcd::1 dev eth0
    ```

    </details>
    
    A continuación, reinicie el servicio de red con uno de los siguientes comandos:
    
    ```bash
    sudo service networking restart
    ```
    
    ```bash
    sudo systemctl restart networking
    ```
  </Tab>
  <Tab label="Ubuntu y Debian 12">
    Los archivos de configuración de red se encuentran en el directorio `/etc/netplan/`.
    
    La práctica recomendada es crear un archivo de configuración independiente en el directorio `/etc/netplan/` para configurar la IPv6. En nuestro ejemplo, nuestro archivo se llama `51-cloud-init-ipv6.yaml`:
    
    ```bash
    sudo nano /etc/netplan/51-cloud-init-ipv6.yaml
    ```
    
    Esto separa la configuración IPv6 y le permite revertir fácilmente los cambios en caso de error.
    
    Añada las siguientes líneas al archivo. Sustituya los elementos genéricos (es decir, `YOUR_IPV6`, `IPV6_PREFIX` y `IPV6_GATEWAY`), así como la interfaz de red (si su servidor no utiliza **eth0**), por sus valores específicos:
    
    ```yaml
    network:
        version: 2
        ethernets:
            eth0:
                dhcp6: no
                match:
                  name: eth0
                addresses:
                  - YOUR_IPV6/IPv6_PREFIX
                routes:
                  - to: ::/0
                    via: IPv6_GATEWAY
    ```
    
    <details>
    <summary>Ejemplo de configuración</summary>

    ```yaml
    network:
        version: 2
        ethernets:
            eth0:
                dhcp6: no
                match:
                  name: eth0
                addresses:
                  - 2607:5300:201:abcd::7c5/128
                routes:
                  - to: ::/0
                    via: 2607:5300:201:abcd::1
    ```

    </details>
    
    :::warning
    Es importante respetar la alineación de cada elemento de este archivo tal y como se muestra en el ejemplo anterior. No utilice la tecla de tabulación para crear el espaciado. Solo es necesaria la barra espaciadora.

    :::

    Puede probar su configuración con el siguiente comando:
    
    ```bash
    sudo netplan try
    ```
    
    Si es correcta, aplíquela con el siguiente comando:
    
    ```bash
    sudo netplan apply
    ```
  </Tab>
  <Tab label="RedHat / CloudLinux / Rocky Linux (8 & 9) / AlmaLinux (8 & 9)">
    Los archivos de configuración de red se encuentran en el directorio `/etc/sysconfig/network-scripts/`. Le recomendamos que empiece por hacer una copia de seguridad del archivo de configuración correspondiente.
    
    En nuestro ejemplo, nuestro archivo se llama `ifcfg-eth0`, por lo que hacemos una copia de seguridad del archivo `ifcfg-eth0` con los siguientes comandos. No olvide sustituir **eth0** por su interfaz real si es necesario.
    
    ```bash
    cd /etc/sysconfig/network-scripts/
    sudo mkdir backup
    sudo cp ifcfg-eth0 backup/ifcfg-eth0
    ```
    
    De este modo, podrá revertir los cambios con los siguientes comandos:
    
    ```bash
    sudo rm -f /etc/sysconfig/network-scripts/ifcfg-eth0
    sudo cp /etc/sysconfig/network-scripts/backup/ifcfg-eth0 /etc/sysconfig/network-scripts/ifcfg-eth0
    ```
    
    A continuación, editamos el archivo `ifcfg-eth0` y añadimos únicamente las líneas de la configuración IPv6 del servidor. Sustituya los elementos genéricos (es decir, `YOUR_IPV6`, `IPV6_PREFIX` y `IPV6_GATEWAY`) por sus valores específicos.
    
    ```console
    IPV6INIT=yes
    IPV6ADDR=YOUR_IPV6/IPV6_PREFIX
    IPV6_DEFAULTGW=IPV6_GATEWAY
    ```
    
    Hemos omitido la configuración IPv4 para evitar confusiones, pero la configuración IPv6 se realiza en el mismo archivo de configuración.
    
    <details>
    <summary>Ejemplo de configuración</summary>

    ```console
    IPV6INIT=yes
    IPV6ADDR=2607:5300:201:abcd::7c5/128
    IPV6_DEFAULTGW=2607:5300:201:abcd::1
    ```

    </details>
    
    Reinicie la interfaz de red con uno de los siguientes comandos:
    
    ```bash
    sudo service networking restart
    ```
    
    ```bash
    sudo systemctl restart networking
    ```
  </Tab>

    En nuestro ejemplo, nuestro archivo se llama `cloud-init-eth0.nmconnection`, por lo que hacemos una copia del archivo `cloud-init-eth0.nmconnection` con los siguientes comandos. No olvide sustituir **eth0** por su interfaz real si es necesario.
    
    ```bash
    cd /etc/NetworkManager/system-connections/
    sudo mkdir backup
    sudo cp cloud-init-eth0.nmconnection backup/cloud-init-eth0.nmconnection

    A continuación, editamos el archivo `cloud-init-eth0.nmconnection` y añadimos únicamente las líneas de la configuración IPv6 del servidor. Sustituya los elementos genéricos (es decir, `YOUR_IPV6`, `IPV6_PREFIX` y `IPV6_GATEWAY`) por sus valores específicos.

    method=manual

    address1=YOUR_IPV6/IPV6_PREFIX
    route1=::/0,IPV6_GATEWAY

    Hemos omitido la configuración IPv4 para evitar confusiones, pero la configuración IPv6 se realiza en el mismo archivo de configuración.

    may-fail=true
    address1=2607:5300:201:abcd::7c5/128
    route1=::/0,2607:5300:201:abcd::1
    ```

    </details>

### Diagnóstico

¿Ha configurado su IPv6 pero no funciona nada?

Para determinar si el fallo se encuentra en su configuración o en la red de OVHcloud, realice esta sencilla prueba.

En primer lugar, [ponga su instancia en modo de rescate rescue-pro](/guides/public-cloud/compute/put-an-instance-in-rescue-mode).

A continuación, utilice los siguientes comandos para configurar su IPv6 de forma no persistente, sustituyendo `YOUR_IPV6`, `IPV6_PREFIX` y `IPV6_GATEWAY` por sus propios datos:

```bash
ip addr add YOUR_IPV6/IPV6_PREFIX dev eth0
ip -6 route add IPV6_GATEWAY dev eth0
ip -6 route add default via IPV6_GATEWAY dev eth0
```

Vuelva a probar su red, por ejemplo mediante un ping6:

```bash
ping6 ipv6.google.com
```

Si su instancia responde, es probable que alguno de los pasos de su configuración inicial no se haya seguido rigurosamente.

En cualquier caso, no dude en enviar una [solicitud a nuestro equipo de soporte](/links/support-contact) con los elementos probados anteriormente para que podamos analizarlos.
