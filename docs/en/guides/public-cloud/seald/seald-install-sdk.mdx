## Objective

This guide walks you through installing the Seald SDK (`@seald-io/sdk`) via npm, importing it correctly for your target platform (Browser, Node.js/Electron, or React Native), and instantiating it in your application.

It does not cover identity creation or encryption — those are addressed in the platform-specific quick start guides listed in the [Go further](#go-further) section.

## Requirements

- A Seald account — use the [staging dashboard](https://dashboard.staging-0.seald.io/) for development, or contact Seald to create a production account.
- Node.js and npm installed on your workstation.
- The following credentials from the Seald administration dashboard:
    - `appId`: the unique UUID for your application.
    - `apiURL`: the API server URL (staging only; omit in production).
    - `keyStorageURL`: the SSKS server URL (staging only; omit in production — required only if you use an identity storage plugin).
    - `JWTSecretId` and `JWTSecret`: JWT credentials for generating user identity tokens.

## Instructions

The Seald SDK is distributed as a set of npm packages. Install the core package, optionally add one or both identity storage plugins, then follow the import and configuration instructions for your target platform.

### Step 1 — Install the npm packages

**Install the core package:**

```bash
npm i -S @seald-io/sdk
```

**Install the identity storage plugins you need:**

```bash
# Password-based identity storage
npm i -S @seald-io/sdk-plugin-ssks-password

# Two-man rule identity storage
npm i -S @seald-io/sdk-plugin-ssks-2mr
```

:::warning
If you configure neither an identity storage plugin nor a persistent local database, the user's cryptographic identity will not be saved anywhere. Any data encrypted with that identity becomes irrecoverable as soon as the browser tab or application is closed.
:::

### Step 2 — Import the SDK

<Tabs>
<Tab label="Browser">

The SDK provides three browser build variants. Choose the one that matches your bundler configuration.

**Polyfilled (recommended for standard webpack/bundler setups)**

Use this variant if your bundler does not already provide Node.js polyfills:

```javascript
import SealdSDK from '@seald-io/sdk' // if your bundler resolves the "browser" field (Webpack 5)
// or equivalently:
import SealdSDK from '@seald-io/sdk/browser'
// or explicitly:
import SealdSDK from '@seald-io/sdk/browser/seald-sdk.polyfilled.js'
```

**Library (recommended when you manage webpack polyfills yourself)**

This variant produces a smaller bundle but requires you to configure polyfills manually in webpack:

```javascript
import SealdSDK from '@seald-io/sdk/browser-library'
// or explicitly:
import SealdSDK from '@seald-io/sdk/browser/seald-sdk.js'
```

Add the following to your `webpack.config.js` (install the listed packages as `devDependencies` first: `assert path-browserify events constants-browserify os-browserify util stream-browserify process buffer timers-browserify`):

```javascript
module.exports = {
  node: { global: true },
  resolve: {
    fallback: {
      assert: require.resolve('assert/'),
      fs: false,
      path: require.resolve('path-browserify'),
      events: require.resolve('events/'),
      constants: require.resolve('constants-browserify'),
      os: require.resolve('os-browserify/browser'),
      util: require.resolve('util/'),
      stream: require.resolve('readable-stream'),
      crypto: false
    }
  },
  plugins: [
    new webpack.ProvidePlugin({
      process: 'process/browser',
      Buffer: ['buffer', 'Buffer'],
      setImmediate: ['timers-browserify', 'setImmediate'],
      clearImmediate: ['timers-browserify', 'clearImmediate']
    })
  ]
}
```

**Bundle (no bundler — direct `<script>` tag)**

Copy `@seald-io/sdk/browser/seald-sdk.browser.js` into your project and include it via a `<script>` tag. The SDK is then accessible as `window.SealdSDK`.

**Plugin imports (browser — polyfilled variant)**

```javascript
import SealdSDKPluginSSKSPassword from '@seald-io/sdk-plugin-ssks-password'
import SealdSDKPluginSSKS2MR from '@seald-io/sdk-plugin-ssks-2mr'
```

:::warning
Hot-reload and hot-restart must be disabled when using the Seald SDK with a persistent local database. Keeping them active can corrupt the local database.
:::

<Tab label="React Native">

**1. Install peer dependencies (exact versions required)**

```bash
npm i -S \
  @react-native-async-storage/async-storage@2.1.0 \
  @seald-io/react-native-scrypt@1.2.3 \
  react-native-quick-crypto@0.7.11 \
  @craftzdog/react-native-buffer@6.0.5 \
  react-native-quick-base64@2.1.2 \
  readable-stream@4.7.0
```

:::warning
The Seald SDK does **not** work with Expo Go because it relies on native dependencies. Use a [Development Build](https://docs.expo.dev/get-started/set-up-your-environment/?mode=development-build&buildEnv=local) instead.
:::

**2. Add the global Buffer polyfill**

Add the following import as early as possible in your application entry point (e.g. `index.js`):

```javascript
import { Buffer } from '@craftzdog/react-native-buffer'
global.Buffer = Buffer
```

**3. Configure module resolution**

Choose one of the two approaches below.

*Option A — Metro config (`metro.config.js`):*

```javascript
config.resolver.resolveRequest = (context, moduleName, platform) => {
  if (moduleName === 'crypto') {
    return context.resolveRequest(context, 'react-native-quick-crypto', platform)
  }
  if (moduleName === 'buffer') {
    return context.resolveRequest(context, '@craftzdog/react-native-buffer', platform)
  }
  if (moduleName === 'stream') {
    return context.resolveRequest(context, 'readable-stream', platform)
  }
  return context.resolveRequest(context, moduleName, platform)
}
```

*Option B — Babel plugin (`babel.config.js`):*

Install `babel-plugin-module-resolver` first, then add:

```javascript
module.exports = {
  presets: ['module:metro-react-native-babel-preset'],
  plugins: [
    ['module-resolver', {
      alias: {
        crypto: 'react-native-quick-crypto',
        stream: 'readable-stream',
        buffer: '@craftzdog/react-native-buffer'
      }
    }]
  ]
}
```

**4. Import the SDK**

Metro automatically resolves the `react-native` field from the package manifest:

```javascript
import SealdSDK from '@seald-io/sdk'
```

**Plugin imports (React Native)**

```javascript
import SealdSDKPluginSSKSPassword from '@seald-io/sdk-plugin-ssks-password'
import SealdSDKPluginSSKS2MR from '@seald-io/sdk-plugin-ssks-2mr'
```

### Step 3 — Instantiate the SDK

Call the `SealdSDK` factory with your application credentials, then call `initialize()` before performing any SDK operations.

**Without plugins:**

```javascript
const seald = SealdSDK({ appId, apiURL })
await seald.initialize()
```

**With identity storage plugins:**

```javascript
const seald = SealdSDK({
  appId,
  apiURL,
  plugins: [
    SealdSDKPluginSSKSPassword(keyStorageURL),
    SealdSDKPluginSSKS2MR(keyStorageURL)
  ]
})
await seald.initialize()
```

> [!INFO]
> In production, omit the `apiURL` and `keyStorageURL` parameters. They are only required when connecting to the staging environment.
