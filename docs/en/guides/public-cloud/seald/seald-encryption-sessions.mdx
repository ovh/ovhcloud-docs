## Objective

This guide explains how to use encryption sessions to encrypt multiple messages or files with a shared symmetric key. An encryption session is ideal for chat threads, document collaboration, or any scenario where a group of data shares the same recipients. Using a session reduces the number of API calls compared to encrypting each item independently.

## Requirements

- An active Seald account with an `appId` and `apiURL`.
- The `@seald-io/sdk` package installed and initialised. See the [Install the Seald SDK](/guides/public-cloud/seald/seald-install-sdk) guide.
- All recipients must have existing Seald identities and their `sealdId` values must be known.

## Instructions

This section covers creating a session, encrypting and decrypting messages and files, managing recipients, and caching sessions to optimise performance.

### Step 1 — Create an encryption session

Call `sdk.createEncryptionSession` with the list of authorised recipients. The session creator becomes the administrator, with exclusive revocation rights by default:

```javascript
const session = await seald.createEncryptionSession(
  {
    sealdIds: [mySealdId, user2SealdId]  // users who can decrypt messages in this session
  },
  {
    metadata: 'my-session'  // optional, non-encrypted, visible in the admin dashboard
  }
)

// session.sessionId identifies this session — store it if needed
```

### Step 2 — Encrypt and decrypt messages

Use the session object to encrypt messages. Recipients retrieve the same session to decrypt them:

```javascript
// Encrypt a message
const encrypted = await session.encryptMessage('Secret message')
// Returns a JSON string containing sessionId and encrypted data

// Retrieve the session from an encrypted message (no need to store the session ID separately)
const retrievedSession = await seald.retrieveEncryptionSession({ encryptedMessage: encrypted })

// Or retrieve by session ID
const retrievedSession2 = await seald.retrieveEncryptionSession({ sessionId: session.sessionId })

// Decrypt the message
const clearText = await retrievedSession.decryptMessage(encrypted)
```

> [!INFO]
> **Raw mode:** Pass `{ raw: true }` to `encryptMessage` to get only the ciphertext without the session ID prefix. In this case, store the `sessionId` separately and pass it explicitly when decrypting: `decryptMessage(encrypted, { raw: true, sessionId })`.

### Step 3 — Encrypt and decrypt files with a session

A session also exposes `encryptFile` and `decryptFile`, which reuse the session key across multiple files:

```javascript
// Encrypt a file
const encryptedBuffer = await session.encryptFile(
  Buffer.from('File content', 'utf8'),
  { filename: 'document.txt' }
)

// Decrypt — the session can be retrieved automatically from the encrypted file header
const { data, filename } = await seald.decryptFile(encryptedBuffer)
```

### Step 4 — Add and revoke recipients

Any recipient with the `forward` right (granted by default) can add new recipients:

```javascript
await session.addRecipients({ sealdIds: [user3SealdId] })
```

Only the session creator has the `revoke` right by default. Use `revokeRecipients` to remove a specific recipient, or `revoke` to revoke the entire session:

```javascript
// Revoke a specific recipient
await session.revokeRecipients({ sealdIds: [user3SealdId] })

// Revoke the entire session and all its encrypted content
await session.revoke()
```

### Step 5 — Enable session caching (optional)

To reduce network calls during decryption, enable the session cache at SDK initialisation by setting `encryptionSessionCacheTTL` (in milliseconds):

```javascript
const seald = SealdSDK({
  appId,
  apiURL,
  encryptionSessionCacheTTL: 30 * 60 * 1000  // cache valid for 30 minutes
})
```

Once enabled, `retrieveEncryptionSession` reads from the cache automatically. Pass `useCache: false` to force a network call:

```javascript
const sessionCached   = await seald.retrieveEncryptionSession({ sessionId })             // uses cache
const sessionFresh    = await seald.retrieveEncryptionSession({ sessionId, useCache: false }) // network call
```

To also control the cache cleanup interval:

```javascript
const seald = SealdSDK({
  appId,
  apiURL,
  encryptionSessionCacheTTL: 30 * 60 * 1000,
  encryptionSessionCacheCleanupInterval: 10 * 60 * 1000  // clean expired entries every 10 minutes
})

// Trigger a manual cleanup
await seald.utils.cleanCache()
```

> [!INFO]
> **Persistent localStorage cache (browser only):** Import `createLocalStorageEncryptionSessionCache` from `@seald-io/sdk` and pass it to `createEncryptionSessionCache`. This requires a persistent local database (`databasePath` + `databaseKey`). See the [Configure a persistent local database](/guides/public-cloud/seald/seald-local-database) guide.
>
> ```javascript
> import SealdSDK, { createLocalStorageEncryptionSessionCache } from '@seald-io/sdk'
>
> const seald = SealdSDK({
>   appId, apiURL, databasePath, databaseKey,
>   encryptionSessionCacheTTL: 30 * 60 * 1000,
>   createEncryptionSessionCache: createLocalStorageEncryptionSessionCache
> })
> ```
