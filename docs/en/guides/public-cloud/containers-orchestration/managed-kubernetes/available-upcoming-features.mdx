## Recent Features

### Custom router and disabled public exposure of nodes and workloads (Available)

Standard clusters created since October 13, 2026 can use your own router or firewall as the default gateway of the nodes, without an OVHcloud managed gateway, and can be created with the public exposure of their nodes and workloads disabled (no Floating IPs, no public Load Balancers). On every new Standard cluster, the traffic between the nodes and the control plane now uses a private path operated by OVHcloud. These options are set when creating the cluster, from the OVHcloud Control Panel or the OVHcloud API.

For more information, see:

- [Using a custom gateway on an OVHcloud Managed Kubernetes cluster](/guides/public-cloud/containers-orchestration/managed-kubernetes/vrack-custom-gateway#use-your-own-router-or-firewall-standard-plan)
- [Known limits - Custom router and disabled public exposure of nodes and workloads](/guides/public-cloud/containers-orchestration/managed-kubernetes/known-limits#custom-router-and-disabled-public-exposure-of-nodes-and-workloads)

### LUKS Encrypted Persistent Volumes (Available)

OVHcloud Managed Kubernetes now supports LUKS encrypted block storage volumes using OVHcloud Managed Keys (OMK). This feature is available in specific regions.

For more information, see:

- [Datacenters, nodes and storage flavors - LUKS Encrypted Storage Classes](/guides/public-cloud/containers-orchestration/managed-kubernetes/datacenters-nodes-storage-flavors#luks-encrypted-storage-classes)
- [LUKS encrypted volumes documentation](/guides/public-cloud/containers-orchestration/managed-kubernetes/known-limits#luks-encrypted-persistent-volumes)
- [Complete tutorial on creating encrypted Persistent Volumes](https://blog.ovhcloud.com/create-encrypted-persistent-volumes-on-ovhcloud-managed-kubernetes-clusters-with-luks/)
