## Objective

You have just created your Public Cloud project, and you would like to find out more about the user interface in the OVHcloud Console.

**Explore the main sections of the Public Cloud interface in the OVHcloud Console.**

## Requirements

- A [Public Cloud project](/guides/public-cloud/cross-functional/create-a-public-cloud-project)

[[cpnav:publiccloud-projects]]

## Instructions

{/* CP-STEPS-START:cp-access */}
Once you have created your first Public Cloud project, you are redirected to its home page in the OVHcloud Console. The page title is the name of your project.

The home page is made up of widgets: **Resources**, **Billing**, **Quick access**, **My last tickets**, **Documentation and support**, **Developer resources** and **Roadmap & Changelog**. You can remove a widget with the icon in its top-right corner, add one with <code className="action">Add a widget</code> and restore the default layout with <code className="action">Reset layout</code>.
{/* CP-STEPS-END:cp-access */}

### Access to your OVHcloud account information

{/* CP-STEPS-START:account-information */}
Your OVHcloud account settings, your notifications and the language of the OVHcloud Console are accessible at any time from the top bar:

- Click <code className="action">Account menu</code> (the icon with your initials, at the right of the top bar) to change the language, switch to the dark theme, open your account, bills, orders and payment methods, contact support or log out.
- Click the bell icon next to it to view your notifications.
{/* CP-STEPS-END:account-information */}

### Your Public Cloud project

{/* CP-STEPS-START:project-name-and-id */}
Because you can use multiple projects (depending on your quotas), the name of the current project is always displayed in the **Project** selector at the top of the left-hand menu, regardless of which screen you are visiting, so you know what environment you are acting on.

The project ID may be required when using the CLI, for certain support requests or otherwise. To copy it:

1. At the top of the left-hand menu, click the <code className="action">Project</code> selector. The list of your projects opens, with the ID of each project under its name.
2. Click <code className="action">Copy project id</code> on the row of your project.

To rename your project:

1. In the left-hand menu, click <code className="action">Project Management</code>.
2. Click the <code className="action">Settings</code> tab.
3. In the **Project name** field, enter the new name.
4. Click <code className="action">Confirm</code>.
{/* CP-STEPS-END:project-name-and-id */}

### The Public Cloud main menu

{/* CP-STEPS-START:main-menu */}
The left-hand menu of your project groups the Public Cloud products by section. Click a section to display its products.

|Section|Options description|
|---|---|
|**Compute**|This section allows you to start instances, which are cloud servers available on demand, and to manage their reservations, backups and workflows.|
|**Network**|In this section, you will find everything you need to interconnect your Public Cloud resources, and to connect them to other OVHcloud products: private networks, subnets, private endpoints, public IPs, gateways and load balancers.|
|**Serverless**|This section, currently in alpha, offers serverless containers and functions, and their usage and quotas.|
|**Storage**|In this section, you will find the different storage solutions (Object Storage, Block Storage, File Storage, Cold Archive, Cloud Archive) and the volume backups and snapshots, each corresponding to a specific need and use.|
|**Containers**|This section offers you various tools to automate your architectures and gain flexibility: Managed Kubernetes Service, Managed Private Registry and Managed Rancher Service.|
|**Databases**|This section offers managed databases: PostgreSQL, MySQL, MongoDB and Valkey.|
|**Analytics**|These services will help you solve your Big Data and Data Analytics problems: Kafka, ClickHouse, OpenSearch, Managed Dashboards, Data Platform and Lakehouse.|
|**AI**|In this section, you will find the OVHcloud artificial intelligence tools: AI Notebooks, AI Training, AI Deploy, AI Endpoints and AI Agents.|
|**Quantum**|This section includes services related to quantum computing: QPUs and emulators.|

Below these sections, the **Project Management** and **Cost center** links give access to the project's management tools (see [Management tools](#management-tools)).

At the top of the menu, click <code className="action">My services</code> to list only the services created in your project, and <code className="action">Products</code> to come back to the full list.
{/* CP-STEPS-END:main-menu */}

### Shortcuts

{/* CP-STEPS-START:shortcuts */}
The **Quick access** widget of the project home page provides shortcuts to the most useful configuration wizards, such as <code className="action">Create an instance</code>, <code className="action">Create a cluster</code> or <code className="action">Create a private network</code>. Guides are available in the **Documentation and support** widget.
{/* CP-STEPS-END:shortcuts */}

#### Assistance for the creation of resources

{/* CP-STEPS-START:resource-creation-wizard */}
For each resource you want to create, a configuration page guides you through the settings, section by section, so that you can set up the resource according to your needs.

Most of the time, you will have to choose the location of the resource (its region), the model, some customisable settings and, in some cases, the billing method. For example, the page for creating an instance groups the instance name, the region, the model, the storage, the image, the SSH key, the backup, network and advanced settings, then the <code className="action">Create my instance</code> button.
{/* CP-STEPS-END:resource-creation-wizard */}

### Management tools

{/* CP-STEPS-START:management-tools */}
In your Public Cloud project, several management tools are available to configure your resources, users and settings. You can access them from the two links at the bottom of the left-hand menu, below the product sections: **Project Management**, which includes the project configuration options (users, quotas, locations, SSH keys, contacts, settings), and **Cost center**, which includes billing.

To open the Horizon interface, click <code className="action">OpenStack Horizon</code> in the **Documentation and support** widget of the project home page. Horizon is the [graphical interface](/guides/public-cloud/cross-functional/introducing-horizon) usually available on OpenStack. It is not altered, which allows users who are used to this interface to easily navigate it.

The <code className="action">Project Management</code> link opens the following tabs:

|Tab|Description|
|---|---|
|**SSH keys**|A tool that allows you to [manage your SSH keys](/guides/public-cloud/compute/creating-ssh-keys) in a centralised way.|
|**Quotas**|Based on certain criteria (number of bills already paid, use of other OVHcloud products), our system sets quotas (limits) on the number of resources you can create, in order to avoid any outstanding amounts. By default, the system increases your quotas automatically when certain criteria are met. However, you can [manually increase a quota](/guides/public-cloud/cross-functional/increasing-public-cloud-quota#increasing-your-resources-quota-manually) from this tab.|
|**Locations**|Public Cloud is available in several locations around the world. Furthermore, each location can contain several “regions” (a concept unique to OpenStack). For example, for a European customer, the APAC (Asia Pacific) zone is disabled by default. If it suits your needs, you can add new locations from this tab.|
|**Logs**|Allows you to view the [logs](/guides/public-cloud/cross-functional/logs-concepts) of your project and to forward them to Logs Data Platform.|
|**Contacts & Rights**|In addition to changing the technical contact or billing contact for your project, you will have the option of [adding other contacts](/guides/public-cloud/compute/change-project-contacts) (OVHcloud account) to manage your project technically. You can also add users in read-only mode.|
|**Users**|Allows you to [create users](/guides/public-cloud/cross-functional/create-and-delete-a-user) and assign them a role. These users can also access the APIs or the Horizon interface directly. For example, you can create a user for your standard maintenance operations, and a user for your automation tools, such as Terraform.|
|**Settings**|With this tab, you can configure the project’s general settings, such as its name, its configuration as a "default project for the account", or [delete your Public Cloud project](/guides/public-cloud/cross-functional/delete-a-project). If your account has a Business or Enterprise support level, this tab also lets you enable HDS certification.|

The <code className="action">Cost center</code> link opens the following tabs:

|Tab|Description|
|---|---|
|**Current usage**, **Estimate of my next invoice**, **History**|Since the Public Cloud is based on *pay as you go*, invoices are issued at the end of the month. In [these tabs](/guides/public-cloud/cross-functional/analyze-billing), you can track your current usage, see a forecast for the next invoice, and of course see your previous invoices.|
|**Savings Plan**|This is a pricing model that offers discounts on specific resources when you opt for commitment periods of up to 36 months.|
|**Credits & vouchers**|This tab allows you to view the consumption of a voucher, add a voucher, or [add credit](/guides/account-and-service-management/managing-billing-payments-and-services/add-cloud-credit-to-project) directly to your Public Cloud project.|
{/* CP-STEPS-END:management-tools */}

### Services management

:::info
In this section, we present an overview of the different service management options offered by OVHcloud, through three main tools: the OVHcloud Console, Horizon and the OpenStack API. Each of these tools has been designed to meet specific needs according to your level of expertise, management preferences, and performance and customization requirements.

The matrix below compares the key features of each tool to help you choose the solution best suited to your needs. Whether you're a beginner, intermediate user or automation expert, this comparison will help you better understand the benefits, ease of use, skill levels required, and scalability of each tool.

:::


| Criteria/Characteristics                   | OVHcloud Console | Horizon | OpenStack API |
| ------------------------------------------ | ---------------------- | ------- | ------------- |
| Key benefits | Intuitive interface, ideal for quick start-up. | Increased control for experienced users, with an advanced view of parameters. | Complete automation, with seamless integration with other tools.
| Skill level required                       | Accessible to all, ideal for beginners or simple needs | Intermediate, requires some expertise (System Administrators, Cloud Engineers, etc.) | Advanced, requires scripting/API skills (Cloud Architects, DevOps Engineers, Automation Experts) |
| Ease of use                                | Intuitive and accessible | Advanced but visual | Technical |
| Customisation                            | Low - Ideal for fast, standard configurations, with limited advanced control. |  Medium - Graphical interface offering advanced settings (network, storage, etc.), albeit restricted by the user interface. | Very high - Virtually complete customization via API, with the ability to create scripts, automated workflows and customized architectures. |
| Performance and scalability                | Limited performance and basic scalability. Suitable for small or non-critical deployments. Scalability is generally manual and slower. Ideal for static environments or small projects. | Average performance with improved scalability management via GUI. Faster scalability than in the OVHcloud Console, but limited by the interface. Suitable for medium-sized projects or those requiring scalability. |  Optimal performance and complete scalability. Enables rapid, automated mass deployments via scripts or third-party tools. Ideal for dynamic infrastructures, heavy loads and environments requiring high elasticity. Recommended for mission-critical architectures. |
| Perimeters of use (Compute)                | - Simplified creation and management of virtual machines (VMs).<br/> - Resize VMs after creation (hot or cold modification of the flavor model, depending on available resources).<br/> - Select standard VM configurations (RAM, CPU, storage).<br/> - Management of essential actions: start, stop and delete VMs.<br/> - Access to snapshots for fast backups and simplified restores.<br/> - Assign and manage Floating IP addresses.<br/> - Creation and basic administration of additional disks.<br/> - Essential resource monitoring (CPU, memory, storage). | - Advanced access management: support for role-based access control (RBAC) for secure multi-user management.<br/> - Advanced network administration: creation and management of complex private networks associated with VMs (internal networks, subnets).<br/> - Deploy VMs with specific network configurations, including management of multiple network interfaces.<br/> - Use of customised images for VM creation, as an alternative to the standard images offered by OVHcloud.<br/> - Integration of pre-configured workflows via Horizon to automate deployment and configuration. | - Complete automation: all actions available in the OVHcloud Console and Horizon can be carried out via the API, with the option of automating and scripting them.<br/> - Infrastructure deployment in Infrastructure as Code (IaC) mode, using tools such as Terraform, Ansible or customized scripts.<br/> - Integration with CI/CD pipelines for automated deployments (e.g. integration with GitLab CI).<br/> - Advanced resource quota management (number of CPUs, total RAM, etc.).<br/> - Dynamic scalability: automatic adjustment of instances according to load via API or scripts.<br/> - Monitoring and collection of customised metrics via API, offering greater granularity than Horizon or OVHcloud Console interfaces. |
| Perimeters of use (Network)                | - Create and manage private networks.<br/> - Association of Floating IP addresses and additional IP addresses.<br/> - Basic Routing configuration. | - Advanced management of security rules via Security Groups.<br/> - Visualization of network topologies for simplified management.<br/> - Full IPv6 subnet support for modern connectivity.<br/> - Configuration of QoS (Quality of Service) policies to prioritize network resources. | - Access to all Horizon and OVHcloud Console functionalities.<br/> - Create customized routes for more flexible network management.<br/> - Precise configuration of QoS (Quality of Service) policies.<br/> - Advanced VRRP (Virtual Router Redundancy Protocol) management to ensure router redundancy.<br/> - Automation of network actions through scripting (Infrastructure as Code).<br/> - Integration with SDN (Software-Defined Networking) solutions for agile network management. |
| Perimeters of use (Storage & backup)       | - Create and manage storage volumes: Object Storage, Block Storage and File Storage.<br/> - Basic automatic backup (snapshots) of volumes, with the option of restoring them.<br/> - Association of storage volumes with instances for simplified access.<br/> - Object Storage (Swift) containers to organize data.<br/> - Visualize volume status and used storage space.<br/> - Add and manage files in Object Storage. | - Advanced snapshot management: retention, duplication and other options for precise backup control.<br/> - Detailed multi-attach management for greater flexibility.<br/> - Creation and management of scheduled backups with customisable backup policies.<br/> - Monitoring of storage quota usage for optimal monitoring of available space. | - Features accessible via Horizon and the OVHcloud Console.<br/> - Integration and automation via scripts (Infrastructure as Code) for seamless management.<br/> - Advanced configuration of network shares (NFS, CIFS) for greater flexibility in file organisation.<br/> - Precise management of object metadata in Object Storage for optimal data control.<br/> - Advanced configuration of object replication and versioning for high availability and complete version management.<br/> - Direct access to Swift API for seamless integration with third-party tools.<br/> - Customised workflows to automate and efficiently manage backup processes. |
