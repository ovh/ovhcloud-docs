## Objective

The SQL queries of a Lakehouse, from the data console or from your tools, run on a Compute Pool. By default, the shared Compute Pool of the region runs them. A dedicated Compute Pool reserves compute for your Lakehouse.

**This guide explains how to add a dedicated Compute Pool, size it and suspend it.**

## Requirements

- A Lakehouse in your Public Cloud project. See [Lakehouse - Getting started](/guides/public-cloud/data-analytics/lakehouse/lakehouse-getting-started).
- Access to the <ManagerLink to="/">OVHcloud Control Panel</ManagerLink>.

## Instructions

In the OVHcloud Control Panel, open your Public Cloud project, go to **Analytics** > **Lakehouse**, click the name of your Lakehouse and open the **Compute Pools** tab.

![Compute Pools tab with the shared Compute Pool and the button to add a dedicated one](/images/guides/public-cloud/data-analytics/lakehouse/compute-pools/compute-pools.png)

The **Shared Compute Pool** card shows the JDBC URL and the Trino command line of the Lakehouse. This SQL address never changes, whether a dedicated Compute Pool is added, resized or deleted.

### Adding a dedicated Compute Pool

Click **Add a dedicated Compute Pool** and fill in the form:

![Form to add a dedicated Compute Pool with its size, workers and idle suspend delay](/images/guides/public-cloud/data-analytics/lakehouse/compute-pools/compute-pool-add.png)

- **Name**: 3 to 63 lowercase letters, digits or underscores, starting with a letter. It cannot be changed afterwards.
- **Size**: the profile of each worker, from XS (1 vCPU, 8 GiB) to L (8 vCPU, 64 GiB). The form shows the memory available to each query.
- **Minimum workers** and **Maximum workers**: between 1 and 50; the Compute Pool adjusts its number of workers within this range.
- **Idle suspend (minutes)**: after this number of minutes without a query, the Compute Pool suspends itself. `0` keeps it running; the maximum is 1440.

The form shows how many compute units the Compute Pool uses, the coordinator counting as one node, and the limit of the region. A Lakehouse can have one dedicated Compute Pool.

Click **Add**. The Compute Pool starts in about two to three minutes. Once it is running, every SQL query of the Lakehouse runs on it.

:::warning
SQL queries are refused while the Compute Pool starts. Wait until it is running before sending queries, or make your tools retry.
:::

### Suspending and resuming

A dedicated Compute Pool suspends itself after its idle delay. You can also suspend it from its card.

The next SQL query resumes it. Resuming takes one to two minutes, during which queries fail with an error such as `502 Bad Gateway` or `CATALOG_NOT_FOUND`: retry them once the Compute Pool is running again.

### Deleting the dedicated Compute Pool

When you delete the dedicated Compute Pool, the SQL queries of the Lakehouse run again on the shared Compute Pool, at the same address.
