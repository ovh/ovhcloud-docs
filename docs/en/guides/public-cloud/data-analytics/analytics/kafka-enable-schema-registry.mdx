## Objective

Apache Kafka is an open-source, distributed event streaming platform designed for real-time, large-scale data processing with high scalability, durability, and low latency.

The Schema Registry stores the schemas of your messages and lets producers and consumers agree on their format.

This guide explains how to enable the Schema Registry for your Kafka service from the OVHcloud Control Panel or the OVHcloud API, and how to register a first schema.

## Requirements

- A [Public Cloud project](/links/public-cloud/public-cloud) in your OVHcloud account
- A [Kafka service](/guides/public-cloud/data-analytics/analytics/kafka-create-cluster) [accepting incoming connections](/guides/public-cloud/data-analytics/analytics/kafka-incoming-connections) from your IP address, with at least one user
- To use the API: access to the [OVHcloud API](/guides/manage-and-operate/api/first-steps)

## Instructions

### Enabling the Schema Registry

<Tabs>
  <Tab label="OVHcloud Control Panel">
    {/* CP-STEPS-START:enable-schema-registry */}
    Go to the <code className="action">Configuration</code> tab of your Kafka service. Scroll to the Kafka-specific section and click the Schema Registry toggle to enable it.

    ![Enable the Schema Registry](/images/public-cloud/data-analytics/analytics/kafka-enable-schema-registry/kafka_enable_schema_registry.png)

    The Schema Registry can be disabled with the same toggle.
    {/* CP-STEPS-END:enable-schema-registry */}
  </Tab>
  <Tab label="OVHcloud API">
    Update your service with `schemaRegistry` set to `true` (or `false` to disable the Schema Registry):

    <Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}"} />

    ```json
    {
      "schemaRegistry": true
    }
    ```
  </Tab>
</Tabs>

### Retrieving the Schema Registry endpoint

Once the Schema Registry is enabled, a `kafkaSchemaRegistry` endpoint is added to your service. You can find it in the `endpoints` list of the service details:

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}"} />

```json
{
  "component": "kafkaSchemaRegistry",
  "domain": "kafka-xxxxxxxx-xxxxxxxxx.database.cloud.ovh.net",
  "port": 20189,
  "scheme": "https",
  "ssl": true,
  "uri": "https://<username>:<password>@kafka-xxxxxxxx-xxxxxxxxx.database.cloud.ovh.net:20189"
}
```

The Schema Registry uses HTTPS with the CA certificate of your service, and the username and password of a Kafka user.

### Granting access to the Schema Registry

A user needs a Schema Registry ACL to read or register schemas. Without one, every request returns `401 Unauthorized`.

For example, to let the user `app-orders` register schemas for the `orders-value` subject, create the following ACL:

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}/schemaRegistryAcl"} />

```json
{
  "username": "app-orders",
  "resource": "Subject:orders-value",
  "permission": "schema_registry_write"
}
```

See the [ACL guide](/guides/public-cloud/data-analytics/analytics/kafka-configure-acl) for the available permissions and resources.

### Registering and listing schemas

Download the CA certificate of your service as `ca.pem` (see [Connect to a Kafka cluster with CLI](/guides/public-cloud/data-analytics/analytics/kafka-connect-cluster-cli)), then register an Avro schema for the `orders-value` subject:

```bash
curl --cacert ca.pem -u 'app-orders:<password>' \
  -H 'Content-Type: application/vnd.schemaregistry.v1+json' \
  -X POST https://<host>:<port>/subjects/orders-value/versions \
  -d '{"schema":"{\"type\":\"record\",\"name\":\"Order\",\"fields\":[{\"name\":\"amount\",\"type\":\"int\"}]}"}'
```

The Schema Registry returns the identifier of the schema:

```json
{"id":1}
```

List the subjects the user can access:

```bash
curl --cacert ca.pem -u 'app-orders:<password>' https://<host>:<port>/subjects
```

```json
["orders-value"]
```
