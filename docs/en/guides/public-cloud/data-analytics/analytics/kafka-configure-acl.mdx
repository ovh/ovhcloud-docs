## Objective

Apache Kafka is an open-source, distributed event streaming platform designed for real-time, large-scale data processing with high scalability, durability, and low latency.

A Kafka user has no access to your topics until you grant it access with an access control list (ACL). This guide explains how to create topic ACLs from the OVHcloud Control Panel or the OVHcloud API, and Schema Registry ACLs from the OVHcloud API.

## Requirements

- A [Public Cloud project](/links/public-cloud/public-cloud) in your OVHcloud account
- A [Kafka service](/guides/public-cloud/data-analytics/analytics/kafka-create-cluster) [accepting incoming connections](/guides/public-cloud/data-analytics/analytics/kafka-incoming-connections), with at least one user and one topic
- To use the API: access to the [OVHcloud API](/guides/manage-and-operate/api/first-steps)

## Instructions

### Default access

When your service is created, the preconfigured admin user `avnadmin` has the `admin` permission on all topics (`*`) and can write to the Schema Registry once it is enabled.

Any user you create afterwards has **no access**. Until you add an ACL for this user, producing to or consuming from a topic fails with the error `TOPIC_AUTHORIZATION_FAILED`.

We recommend creating one user per application and granting each user only the topics and the permission it needs.

### Permissions

For a user and a topic (or all topics with `*`), you can grant one of the following permissions:

- **admin**: full access to the topic, including its management
- **read**: consume messages from the topic
- **write**: produce messages to the topic
- **readwrite**: produce and consume messages

The list of permissions available on your service is also returned by the API:

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}/permissions"} />

```json
{
  "names": ["admin", "read", "write", "readwrite"],
  "topic": ["admin", "read", "write", "readwrite"],
  "schemaRegistry": ["schema_registry_read", "schema_registry_write"]
}
```

### Configuring topic ACLs

  <Tab label="OVHcloud Control Panel">
    {/* CP-STEPS-START:configure-acls-on-topics */}
    In the <code className="action">ACL</code> tab, click the <code className="action">Add an ACL</code> button:

    ![Enable ACLs](/images/public-cloud/data-analytics/analytics/kafka-configure-acl/kafka_acl.v2.png)

    Select the user, enter the topic name (or `*` for all topics) and choose the permission:

    ![Define ACLs](/images/public-cloud/data-analytics/analytics/kafka-configure-acl/kafka_add_entry1.v2.png)
    {/* CP-STEPS-END:configure-acls-on-topics */}
  </Tab>
  <Tab label="OVHcloud API">
    Create an ACL:

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}/topicAcl"} />

    ```json
    {
      "username": "app-orders",
      "topic": "orders",
      "permission": "readwrite"
    }
    ```

    The API returns the ACL with its identifier:

    ```json
    {
      "id": "1f2e3d4c-5b6a-4789-9abc-def012345678",
      "username": "app-orders",
      "topic": "orders",
      "permission": "readwrite"
    }
    ```

    List and delete ACLs:

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}/topicAcl"} />

    <Api version="v1" section="/cloud" method="DELETE" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}/topicAcl/\{aclId\}"} />

    :::info
    The older `/acl` routes manage the same ACLs as the `/topicAcl` routes.
    :::
  </Tab>

### Configuring Schema Registry ACLs with the API

Once the [Schema Registry is enabled](/guides/public-cloud/data-analytics/analytics/kafka-enable-schema-registry), a user also needs a Schema Registry ACL to read or register schemas.

Two permissions are available:

- **schema_registry_read**: read schemas
- **schema_registry_write**: read and register schemas

The resource is either:

- `Subject:<subject name>`, for example `Subject:orders-value`, or `Subject:*` for all subjects;
- `Config:`, for the global compatibility configuration of the Schema Registry.

By default, `avnadmin` has the `schema_registry_write` permission on `Config:` and on `Subject:*`.

Create a Schema Registry ACL:

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}/schemaRegistryAcl"} />

```json
{
  "username": "app-orders",
  "resource": "Subject:orders-value",
  "permission": "schema_registry_write"
}
```

With this ACL, `app-orders` can register schemas for the `orders-value` subject. The Schema Registry behaves as follows for any user:

- without any Schema Registry ACL, every request returns `401 Unauthorized`;
- a subject not covered by its ACLs is reported as not found (`404`).

List and delete Schema Registry ACLs:

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}/schemaRegistryAcl"} />

<Api version="v1" section="/cloud" method="DELETE" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}/schemaRegistryAcl/\{aclId\}"} />
