## Introduction

[AI Endpoints](/links/public-cloud/ai-endpoints) is a serverless platform provided by OVHcloud that offers easy access to a selection of world-renowned, pre-trained AI models. The platform is designed to be simple, secure, and intuitive, making it an ideal solution for developers who want to enhance their applications with AI capabilities without extensive AI expertise or concerns about data privacy.

**Decision Models** are designed to answer typed questions about a text, with **calibrated probabilities**. Instead of generating free-form text that you then have to parse, you describe the questions you want to ask and receive structured answers that you can plug directly into your application logic (routing, moderation, triage, analytics, etc.).

You can ask three types of questions, detailed in [Question types](#question-types): `choice` picks one option, `score` rates the text on ordered levels and `noul` answers yes or no.

Decision Models are available through the `/v1/systemone` endpoint, which follows the **System One** format created by TypeSafe. Clients already written for this format only need a new base URL, an AI Endpoints API key and the name of a model from our [Catalog](/links/public-cloud/ai-endpoints-catalog) to work with AI Endpoints. The OpenAI-compatible `/v1/decisions` endpoint is not available yet.

## Quickstart

The endpoint is available at the following URL:

```text
https://oai.endpoints.kepler.ai.cloud.ovh.net/api/v1/systemone
```

A request contains three elements:

- `model`: the decision model to use.
- `state`: what you want to ask questions about. This is usually a text, but it can also be any JSON object (a ticket, an email, a document...), which is sent to the model as JSON text.
- `questions`: an object where each key is the name you give to a question, and each value describes the question (its `type` and its criteria).

### Ask a single question

This first example classifies a customer message into a department.

<Tabs>
  <Tab label="Python">
    ```python
    import os
    import requests

    url = "https://oai.endpoints.kepler.ai.cloud.ovh.net/api/v1/systemone"
    headers = {
        "Authorization": f"Bearer {os.getenv('OVH_AI_ENDPOINTS_ACCESS_TOKEN')}",
        "Content-Type": "application/json"
    }
    payload = {
        "model": "clef-flash",
        "state": "Hello, I would like to download the invoice of the previous month for my Public Cloud project. Where can I find it?",
        "questions": {
            "department": {
                "type": "choice",
                "criteria": {
                    "billing": "Payments, invoices and refunds",
                    "technical": "Technical questions about a service",
                    "sales": None
                }
            }
        }
    }

    response = requests.post(url, json=payload, headers=headers)

    if response.status_code == 200:
        print(response.json())
    else:
        print("Error:", response.status_code, response.text)
    ```

### Ask several questions at once

You can ask several questions about the same text in a single request. Each question is identified by its key in `questions`, and its answer comes back under the same key in `answers`.

The following example combines the three question types on a single customer message:

<Tabs>
  <Tab label="Python">
    ```python
    import os
    import requests

    url = "https://oai.endpoints.kepler.ai.cloud.ovh.net/api/v1/systemone"
    headers = {
        "Authorization": f"Bearer {os.getenv('OVH_AI_ENDPOINTS_ACCESS_TOKEN')}",
        "Content-Type": "application/json"
    }
    payload = {
        "model": "clef-flash",
        "state": "Hi, I just deployed my first Public Cloud instance and I would like to enable automatic backups before launching my website next week. How can I set this up, and what does it cost?",
        "questions": {
            "department": {
                "type": "choice",
                "criteria": {
                    "billing": "Invoice, payment or subscription issues",
                    "technical": "Technical questions about a service",
                    "sales": "Pricing, offers or product questions"
                }
            },
            "frustration": {
                "type": "score",
                "criteria": [
                    "Calm, just stating facts",
                    "Frustrated but civil",
                    "Very angry, strong language"
                ]
            },
            "is_urgent": {
                "type": "noul",
                "instructions": "The message conveys urgency or time-sensitivity"
            }
        }
    }

    response = requests.post(url, json=payload, headers=headers)

    if response.status_code == 200:
        for question, answer in response.json()["answers"].items():
            print(question, answer)
    else:
        print("Error:", response.status_code, response.text)
    ```

## Question types

### Choice

A `choice` question picks **one option** among a list that you define.

```json
"department": {
  "type": "choice",
  "instructions": "Which department should handle this message?",
  "criteria": {
    "billing": "Invoice, payment or subscription issues",
    "technical": "Technical questions about a service",
    "sales": null
  }
}
```

- `criteria` is an object where each **key is an option** and each **value is a description** that helps the model understand what the option means.
- The description can be `null` when the name of the option is self-explanatory. Precise descriptions generally lead to more reliable answers.
- `instructions` states what is asked. It is optional for a `choice` question but recommended.
- The **order matters**: keep a stable order and do not sort the options differently from one request to another.

The answer contains the selected `choice`, the `probabilities` of every option (which sum up to 1), and the `confidence` in the selected choice, between 0 and 1 (the higher the value, the greater the certainty):

```json
{
  "type": "choice",
  "choice": "sales",
  "confidence": 0.4986,
  "probabilities": { "billing": 0.033, "technical": 0.4684, "sales": 0.4986 }
}
```

### Score

A `score` question rates the text on **ordered levels**.

```json
"frustration": {
  "type": "score",
  "instructions": "How frustrated is the customer?",
  "criteria": [
    "Calm, just stating facts",
    "Frustrated but civil",
    "Very angry, strong language"
  ]
}
```

- `criteria` is an **ordered list** describing each level of the scale, from the lowest to the highest. The first item is level `0`, the second is level `1`, and so on. Provide between 2 and 10 levels.
- `instructions` states what is asked. It is optional for a `score` question but recommended.
- The **order matters**, so do not reorder the levels from one request to another.

The answer contains the `score`, a `legend` that maps each level to its description, the `probabilities` of every level, and the `confidence`, between 0 and 1 (the higher the value, the greater the certainty):

```json
{
  "type": "score",
  "score": 0.0251,
  "confidence": 0.9767,
  "legend": {
    "0": "Calm, just stating facts",
    "1": "Frustrated but civil",
    "2": "Very angry, strong language"
  },
  "probabilities": { "0": 0.9767, "1": 0.0216, "2": 0.0017 }
}
```

The `score` is a **continuous value** between the lowest and the highest level. It is the average of the levels weighted by their probability (here, `0 × 0.9767 + 1 × 0.0216 + 2 × 0.0017 ≈ 0.03`), which allows you to distinguish a text clearly sitting on a level from a text sitting between two levels.

### Noul

A `noul` question answers a **yes or no** question about the text.

```json
"is_urgent": {
  "type": "noul",
  "instructions": "The message conveys urgency or time-sensitivity"
}
```

- `instructions` is a statement describing the property to check. The answer is the probability that this statement is true for the text. It is required for a `noul` question.
- `criteria` is optional. It can be omitted, or contain the optional keys `"true"` and `"false"` to describe what each answer means.

The answer contains a single value between `0` and `1`:

```json
{
  "type": "noul",
  "noul": 0.07
}
```

A value close to `1` means that the statement is very likely true, a value close to `0` means that it is very likely false.

## Endpoint Limitations

- Decision Models read **text only**: images, audio and unknown fields in the request are rejected.
- A `choice` question accepts 2 to 255 options and a `score` question 2 to 10 levels.
- The context of `clef-flash` is 16,384 tokens, including the state and the questions.
- Rate limits are described in the [AI Endpoints - Features, Capabilities and Limitations](/guides/public-cloud/ai-machine-learning/ai-endpoints-capabilities) guide.
- The quality of the answers depends on how clear your criteria and instructions are. Use distinct options and precise descriptions.
