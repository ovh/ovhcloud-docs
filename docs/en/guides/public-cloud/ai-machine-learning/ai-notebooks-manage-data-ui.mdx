## Objective

This guide shows how to access Object Storage data from your [**notebooks**](/guides/public-cloud/ai-machine-learning/ai-notebooks-definition) via the OVHcloud Console.

## Requirements

- a [Public Cloud project](/links/public-cloud/public-cloud) in your OVHcloud account
- access to the <ManagerLink to="/">OVHcloud Console</ManagerLink>
- a Public Cloud user with `Administrator` or `AI Operator` role, see [here](/guides/public-cloud/ai-machine-learning/ai-users) for more information

## Upload data to your Object Storage

First, you need to push some data to the `Object Storage` before accessing it from the notebook.

Click <code className="action">Object Storage</code> under **Storage** in the left-hand menu of your Public Cloud project. Your containers are listed in the <code className="action">Containers</code> tab.

:::info
You can upload different types of data: datasets, code, notebooks, connection weights, text or csv files, etc.

:::

Let's assume that a file named `my-dataset.zip` exists locally on your computer and contains your dataset. You will be able to upload it into an object container in your Object Storage by following these steps.

### 1- Create your container

In the <code className="action">Containers</code> tab, click <code className="action">Create an object container</code>. Select the **Container type** (Swift or **S3-compatible API**), name your container `my-dataset`, then select the deployment mode and the region, and click <code className="action">Create</code>.

:::info
To optimize the download and upload times, we advise you to store your data in the same place as your notebook (`GRA` or `BHS`).

:::

:::warning
To attach an S3<sup>1</sup> compatible bucket to your notebook, you first need to declare it as a datastore in the <code className="action">S3 volumes</code> tab of the **Configuration** page of AI Notebooks. Find out more in the [S3 compatible Object Storage guide](/guides/public-cloud/ai-machine-learning/ai-s3-compliance).

:::

If you want to know more about the different storage solutions, refer to this page.

You have created your container to host your dataset. You are now ready to load your data!

### 2- Add objects to your container

In the <code className="action">Containers</code> tab, click the name of your container `my-dataset`: its <code className="action">Objects</code> tab opens. Click <code className="action">Add an object</code>, then click <code className="action">Browse files</code>, select your local `my-dataset.zip` file and click <code className="action">Upload</code>.

You will now see your `my-dataset.zip` file displayed in your object container.

:::info
You can also create a new empty `my-weights` container in which you can save your **connection weights** (or your **validated model**) at the end of your training.

:::

We assume that we now have two object containers available:

- `my-dataset`, containing the file `my-dataset.zip`
- `my-weights`, empty

You are now ready to launch a notebook with your data!

## Launch a notebook with attached data

To launch an AI notebook, click <code className="action">AI Notebooks</code> under **AI** in the left-hand menu of your Public Cloud project, then click <code className="action">Create a notebook</code>.

For the name, flavor, framework and editor of your notebook, please refer to this [tutorial](/guides/public-cloud/ai-machine-learning/ai-notebooks-definition).

### Choose the notebook region

In the **Region** section, you can choose between *2 datacenters* for the storage of your notebook: `GRA` or `BHS`.

### Attach container or a Git repository

You can attach your different types of data to your notebook in the **Advanced configuration** section of the creation page.

To attach a container, turn on the **Volumes** switch and click <code className="action">Add a volume</code>. In the **Add a datastore volume** dialog, select the **Datastore** that holds your container, then the **Container** (you can also create a new one on the fly by typing its name), enter the **Mount path** and choose the **Permission**. Then click <code className="action">Add</code>.

#### Access with Read-Only permissions

You can load the container `my-dataset` in the `/workspace/dataset` directory, with the **Read only** permission.

You will not be able to modify the dataset from this notebook because you loaded it with **Read only** permission.

**Read only** permissions are to ensure you don't modify your data by mistake. If you want to modify data from your
notebooks, to store a trained neural network for example, you can use the **Read / write** permission instead.

#### Access with Read-Write permissions

Similarly to the **Read only** mode, you can load data with the **Read / write** permission: for example, load the container `my-weights` in the `/workspace/weights` directory.

Once you have some data that you want to save from the notebook to Object Storage (connection weights in this example), you can simply write it to the `/workspace/weights` folder.

This folder will be uploaded to your Object Storage when you stop your notebook.

As long as your notebook is in the **Stopping** state, this means that the upload is still in progress. Once the state changes to **Stopped**, it means all the data was uploaded to your Object Storage.

#### Attach a public Git repository

If Python code, notebooks or other files are available on a public GitHub repository, you can attach them to your notebook.
To be able to edit and make changes easily, use the **Read / write** permission.

Turn on the **Git Public** switch and click <code className="action">Add a repository</code>. Enter the URL in the **Public git repository** field, then the **Mount path** (for example `/workspace/git-hub-repository`) and the **Permission**, and click <code className="action">Add</code>.

:::warning
To make your repository URL valid, don't forget to add a `.git` at the end of the GitHub repository URL.

:::

#### Use cached volumes

When loading large files from the `Object Storage`, it can take some time to download to your notebooks. In these cases, you can cache the volumes so that it does not need to be downloaded again when you start new notebooks that use the same data.

To do so, tick **Cache the volume close to the instance** in the **Add a datastore volume** dialog.

Cached volumes will be deleted at least 72 hours after the last notebook using it has stopped.
Note that the cache is shared with all users in your project. The main consequence you need to be careful about
is the fact that if someone else modifies the data in your cached volume, you will also see the modifications on your side.

### Launch and access the notebook

Your notebook is now ready to be launched with your data! The attached volumes are listed in the summary of the creation page. Click <code className="action">Create the notebook</code>.

Once the notebook is created, its attached volumes are listed in its <code className="action">Containers</code> tab. You can add or detach volumes from this tab while the notebook is stopped.

You can read the [Getting started](/guides/public-cloud/ai-machine-learning/ai-notebooks-definition) page to know how to find this URL.

As soon as you access your notebook, you will see your different folders containing your data.
