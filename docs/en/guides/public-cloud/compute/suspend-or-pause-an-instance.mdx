## Objective

As part of the configuration of a high-availability infrastructure, you may need to cut access to your instances to perform different tests. OpenStack allows you to shelve, stop (shutoff), suspend or pause your instance. In each case, your IP is maintained.

:::warning
In the OVHcloud Console, only **Shelve** / **Unshelve** and **Hard stop** (OpenStack *stop*, *Shut Off* in Horizon) are available. **Suspend** / **Resume** and **Pause** / **Unpause** are available with the OVHcloud API (v2), in Horizon and with the OpenStack API.

:::

**This guide explains how to shelve, hard stop, suspend or pause your instance.**

## Requirements

- An [OVHcloud Public Cloud instance](/guides/public-cloud/compute/getting-started) on **hourly** billing
- Access to the [Horizon interface](/guides/public-cloud/cross-functional/introducing-horizon)
- Knowledge of [OpenStack API](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment) and [OpenStack variables](/guides/public-cloud/cross-functional/compute-set-openstack-environment-variables)

[[cpnav:publiccloud-instances]]

## Instructions

:::warning
**Scope:** This guide applies to all Public Cloud instances, regardless of their billing model (hourly or monthly).

**Monthly billing:** For instances billed monthly, the monthly price of the instance continues to be billed regardless of the instance status. A shelved monthly instance is billed its monthly price plus the snapshot.

**Note:** As long as the instance is not deleted, any operation will continue to incur instance charges.

:::

{/* CP-STEPS-START:options-table */}
The table below allows you to differentiate the options available on your instances. Click the option of your choice below to continue reading this guide. The OpenStack action is given in brackets.

|Option|Memory state|Disk data|Host resources (CPU/RAM)|Resume behaviour|Billing|
|---|---|---|---|---|---|
|[Hard stop (*stop*)](#hard-stop-instance)|Lost|Preserved|Still allocated on the host|Cold boot (the OS restarts)|You are billed at the same rate.|
|[Shelve (*shelve*)](#shelve-instance)|Lost|Saved in a snapshot image|Released once offloaded|Cold boot from the snapshot, possibly on another host|Hourly instances: only the snapshot is billed. Monthly instances: the monthly price of the instance plus the snapshot.|
|[Pause (*pause*)](#pause-instance)|Kept in host RAM|Preserved|Still allocated and consumed|Instant, exactly where it was|You are billed at the same rate.|
|[Suspend (*suspend*)](#stop-suspend-instance)|Written to disk on the host|Preserved|RAM/CPU freed on the hypervisor, allocation kept|Restores the saved state, like hibernation|You are billed at the same rate.|

In each case, the IP address of the instance is maintained.

{/* CP-STEPS-END:options-table */}

### Shelve an instance

:::danger
Please note that shelving an IOPS or T1/T2-180 instance will result in the loss of data on the NVMe passthrough drives.

Shelving this type of instance leads to its decommissioning from the host, and therefore from the disks in passthrough.

:::

This option releases the resources dedicated to your Public Cloud instance, but the IP address will remain. The data on your local disk will be stored in a snapshot automatically created once the instance is shelved. Data stored in the memory and elsewhere will not be retained.

{/* CP-STEPS-START:shelve-instance */}
<Tabs>
  <Tab label="OVHcloud Console">
    In the left-hand menu of your Public Cloud project, click <code className="action">Instances</code> under **Compute**.

    Click on the <code className="action">...</code> button to the right of the instance you want to shelve, then click on <code className="action">Shelve</code>.

    In the **Shelve your instance** window, take note of the message and click on <code className="action">Confirm</code>.

    Once the process is completed, the status of your instance will appear as **Shelve**.

    To view the snapshot, click on <code className="action">Instance Snapshot</code> under **Compute** in the left-hand menu. A snapshot named *xxxxx-shelved* will now be visible.
  </Tab>
  <Tab label="OVHcloud CLI">
    Before proceeding, we recommend consulting these guides:

    - [Getting started with the OVHcloud CLI](/guides/manage-and-operate/cli/getting-started)

    Type the following command:

    ```shell
    ovhcloud cloud instance shelve <instance_id>
    ```
  </Tab>
  <Tab label="OVHcloud API">
    Use the following API call, where `projectId` is the ID of your Public Cloud project and `instanceId` the ID of the instance:

    <Api version="v2" section="/publicCloud" method="POST" route={"/publicCloud/project/\{projectId\}/compute/instance/\{instanceId\}/action"} />

    With the following request body:

    ```json
    {
      "type": "SHELVE"
    }
    ```
  </Tab>
  <Tab label="OpenStack/Nova APIs">
    Before proceeding, we recommend consulting these guides:

    - [Prepare the environment to use the OpenStack API](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment)
    - [Set OpenStack environment variables](/guides/public-cloud/cross-functional/compute-set-openstack-environment-variables)

    Once your environment is ready, type the following at the command line:

    ```bash
    openstack server shelve <UUID server>

    =====================================

    nova shelve <UUID server>
    ```
  </Tab>
  <Tab label="Horizon">
    To proceed, you need to [log in to the Horizon interface](https://horizon.cloud.ovh.net/auth/login/):

    - To log in with OVHcloud Single Sign-On: open your Public Cloud project in the <ManagerLink to="/">OVHcloud Console</ManagerLink> and click <code className="action">OpenStack Horizon</code> in the **Documentation and support** widget of the project home page.

    - To log in with a specific OpenStack user: open the [Horizon login page](https://horizon.cloud.ovh.net/auth/login/) and enter the [OpenStack user credentials](/guides/public-cloud/cross-functional/create-and-delete-a-user) previously created, then click on <code className="action">Connect</code>.

    If you have deployed instances in different regions, make sure you are in the correct region. You can verify this on the top left corner in the Horizon interface.

    <img className="thumbnail" alt="horizon interface" src="/images/public-cloud/compute/suspend-or-pause-an-instance/firstaccesshorizon.png" loading="lazy" />

    Click on the <code className="action">Compute</code> menu on the left side and select <code className="action">Instances</code>. Select <code className="action">Shelve Instance</code> in the drop list for the corresponding instance.

    <img className="thumbnail" alt="shelve instance" src="/images/public-cloud/compute/suspend-or-pause-an-instance/shelveinstancehorizon.png" loading="lazy" />

    Once the process is completed, your instance will now appear as *Shelved Offloaded*.

    <img className="thumbnail" alt="shelved instance" src="/images/public-cloud/compute/suspend-or-pause-an-instance/newinstancestatushorizon.png" loading="lazy" />

    To view the snapshot, in the <code className="action">Compute</code> menu, click on <code className="action">Images</code>.

    <img className="thumbnail" alt="snapshot" src="/images/public-cloud/compute/suspend-or-pause-an-instance/snapshothorizon.png" loading="lazy" />
  </Tab>
</Tabs>

<a name="unshelve-instance"></a>

### Unshelve an instance

This option reactivates your instance so that you can continue using it. Once this is done, regular billing resumes.

:::danger
**Actions on the snapshot**

Any actions on the snapshot other than *unshelve* can be very dangerous for your infrastructure in case of misuse. Once you *unshelve* an instance, the snapshot is automatically deleted. It is not recommended to deploy a new instance from any snapshot created as a result of shelving an instance.

OVHcloud is providing you with machines that you are responsible for. We have no access to these machines, and therefore cannot manage them. You are responsible for your own software and security management. If you experience any issues or doubts when it comes to managing, using or securing your server, we recommend that you contact a [specialist service provider](/links/partner).
:::

<Tabs>
  <Tab label="OVHcloud Console">

    Click on the <code className="action">...</code> button to the right of the instance, then click on <code className="action">Unshelve</code>.

    In the **Unshelve your instance** window, click on <code className="action">Confirm</code>.

    Once the process is completed, the status of your instance will appear as **Active**.
  </Tab>
  <Tab label="OVHcloud CLI">
    Type the following command:

    ```shell
    ovhcloud cloud instance unshelve <instance_id>
    ```
  </Tab>
  <Tab label="OVHcloud API">
    Use the following API call, where `projectId` is the ID of your Public Cloud project and `instanceId` the ID of the instance:

    <Api version="v2" section="/publicCloud" method="POST" route={"/publicCloud/project/\{projectId\}/compute/instance/\{instanceId\}/action"} />

    With the following request body:


  <Tab label="Horizon">

    <img className="thumbnail" alt="unshelve instance" src="/images/public-cloud/compute/suspend-or-pause-an-instance/unshelveinstancehorizon.png" loading="lazy" />

<a name="hard-stop-instance"></a>

### Hard stop (*stop*) an instance

This option stops your instance (OpenStack *stop* action, *Shut Off* in Horizon). The data on the disk is preserved, but the memory state is lost: the instance reboots when you start it again. The resources dedicated to the instance remain reserved, including the IP address, and you are still billed at the same price.

{/* CP-STEPS-START:turn-off-instance */}
<Tabs>
  <Tab label="OVHcloud Console">
    In the left-hand menu of your Public Cloud project, click <code className="action">Instances</code> under **Compute**.

    Click on the <code className="action">...</code> button to the right of the instance you want to stop, then click on <code className="action">Hard stop</code>.

    In the **Hard stop your instance** window, take note of the message and click on <code className="action">Confirm</code>.

    Once the process is completed, the status of your instance will appear as **Hard stop (Shutoff)**.

    To **start** the instance again, click on the <code className="action">...</code> button to the right of the instance and select <code className="action">Start</code>, then click on <code className="action">Confirm</code> in the **Start your instance** window. In some cases, you might need to do a cold reboot.

    Once the process is completed, the status of your instance will appear as **Active**.
  </Tab>
  <Tab label="OVHcloud CLI">
    Type the following command:

    ```shell
    ovhcloud cloud instance stop <instance_id>
    ```

    To **start** the instance again, type the following command:

    ```shell
    ovhcloud cloud instance start <instance_id>
    ```
  </Tab>
  <Tab label="OVHcloud API">
    Use the following API call, where `projectId` is the ID of your Public Cloud project and `instanceId` the ID of the instance:

    <Api version="v2" section="/publicCloud" method="POST" route={"/publicCloud/project/\{projectId\}/compute/instance/\{instanceId\}/action"} />

    With the following request body:

    ```json
    {
      "type": "STOP"
    }
    ```

    To **resume** the instance, use the same call with the `START` type:

    ```json
    {
      "type": "START"
    }
    ```
  </Tab>
  <Tab label="OpenStack/Nova APIs">
    Once your environment is ready, type the following at the command line:

    ```bash
    ~$ openstack server stop <UUID server>

    =========================================

    ~$ nova stop <UUID server>
    ```

    To **start** the instance again, type the following at the command line:

    ```bash
    ~$ openstack server start <UUID server>

    =========================================

    ~$ nova start <UUID server>
    ```
  </Tab>
  <Tab label="Horizon">
    In the Horizon interface, click on the <code className="action">Compute</code> menu on the left and then select <code className="action">Instances</code>. Select <code className="action">Shut Off Instance</code> in the drop list for the corresponding instance.

    To **start** the instance again, select <code className="action">Start Instance</code> in the drop list for the corresponding instance.
  </Tab>
</Tabs>

{/* CP-STEPS-END:turn-off-instance */}
<a name="stop-suspend-instance"></a>

### Suspend an instance

This option suspends your instance: the memory state is written to disk on the host, and the RAM/CPU are freed on the hypervisor while the allocation is kept. When you resume the instance, the saved state is restored, like hibernation. You are billed at the same rate.

This action is not available in the OVHcloud Console: use the OVHcloud API, the Horizon interface or the OpenStack/Nova API.

<Tabs>
  <Tab label="OVHcloud API">
    Use the following API call, where `projectId` is the ID of your Public Cloud project and `instanceId` the ID of the instance:

    <Api version="v2" section="/publicCloud" method="POST" route={"/publicCloud/project/\{projectId\}/compute/instance/\{instanceId\}/action"} />

    With the following request body:

    ```json
    {
      "type": "SUSPEND"
    }
    ```

    To **resume** the instance, use the same call with the `RESUME` type:

    ```json
    {
      "type": "RESUME"
    }
    ```
  </Tab>
  <Tab label="OpenStack/Nova APIs">
    Once your environment is ready, type the following at the command line:

    ```bash
    ~$ openstack server suspend <UUID server>

    =========================================

    ~$ nova suspend <UUID server>
    ```

    To **resume** the instance, type the following at the command line:

    ```bash
    ~$ openstack server resume <UUID server>

    =========================================

    ~$ nova resume <UUID server>
    ```
  </Tab>
  <Tab label="Horizon">
    In the Horizon interface, click on the <code className="action">Compute</code> menu on the left and then select <code className="action">Instances</code>. Select <code className="action">Suspend Instance</code> in the drop list for the corresponding instance.

    <img className="thumbnail" alt="suspend instance Horizon" src="/images/public-cloud/compute/suspend-or-pause-an-instance/suspendinstancehorizon.png" loading="lazy" />

    The confirmation message will appear, indicating that the instance has been suspended.

    To **resume** the instance, perform the same steps as mentioned above. In the drop list for the corresponding instance select <code className="action">Resume Instance</code>.
  </Tab>
</Tabs>

<a name="pause-instance"></a>

### Pause an instance

This action is not available in the OVHcloud Console: use the OVHcloud API, the Horizon interface or the OpenStack/Nova API. It allows you to *freeze* your instance: the memory state is kept in the host RAM, and the instance resumes instantly, exactly where it was.

<Tabs>
  <Tab label="OVHcloud API">
    Use the following API call, where `projectId` is the ID of your Public Cloud project and `instanceId` the ID of the instance:

    <Api version="v2" section="/publicCloud" method="POST" route={"/publicCloud/project/\{projectId\}/compute/instance/\{instanceId\}/action"} />

    With the following request body:

    ```json
    {
      "type": "PAUSE"
    }
    ```

    To **resume** the instance, use the same call with the `UNPAUSE` type:

    ```json
    {
      "type": "UNPAUSE"
    }
    ```
  </Tab>
  <Tab label="OpenStack/Nova APIs">
    Once your environment is ready, type the following at the command line:

    ```bash
    ~$ openstack server pause <UUID server>

    =========================================

    ~$ nova pause <UUID server>
    ```

    To **unpause** the instance, type the following at the command line:

    ```bash
    ~$ openstack server unpause <UUID server>

    =========================================

    ~$ nova unpause <UUID server>
    ```
  </Tab>
  <Tab label="Horizon">
    In the Horizon interface, click on the <code className="action">Compute</code> menu on the left and then select <code className="action">Instances</code>. Select <code className="action">Pause Instance</code> in the drop list for the corresponding instance.

    <img className="thumbnail" alt="Pause instance" src="/images/public-cloud/compute/suspend-or-pause-an-instance/pauseinstancehorizon.png" loading="lazy" />

    The confirmation message will appear, indicating that the instance has been paused.

    To **unpause** the instance, perform the same steps as mentioned above. In the drop list for the corresponding instance select <code className="action">Resume Instance</code>.
  </Tab>
</Tabs>
