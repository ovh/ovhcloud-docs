## Objective

You can create a single snapshot of an instance or configure a schedule in order to automate your instance snapshots. Snapshots can be used to restore your instance to a previous state or to create a new, identical instance.

**This guide explains how to create manual and automatic snapshots of a Public Cloud instance.**

## Requirements

- A [Public Cloud instance](/links/public-cloud/public-cloud) in your OVHcloud account
- OpenStack CLI. Use [our guide to know how to prepare the environment to use the OpenStack API](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment). (optional)

[[cpnav:publiccloud-instances]]

## Instructions

### Creating a snapshot of an instance

:::warning
This option is only available through a **Cold Snapshot** for Metal instances. During this process, the Metal instance will be switched to rescue-mode, and once the snapshot is performed, the instance will reboot back to normal mode.

:::


:::info
Two types of snapshot are available:

- Local: A local snapshot is stored in the same region as your instance.
- Remote: A remote snapshot automatically creates a copy of the local snapshot in a different region of your choice.

Each snapshot is billed separately — the remote snapshot will be charged based on the storage pricing of the selected remote region.

**Note:** Local Zones are not eligible for remote snapshots.

:::

    </details>

    The instance is suspended for a few seconds while the snapshot is taken. It is not possible to monitor the snapshot progress in real time. However, in the **Instance snapshots** page (<code className="action">Instance Snapshot</code> under **Compute** in the left-hand menu), the status of the snapshot is displayed during the process.

    Once the snapshot is complete, it will be available on the **Instance snapshots** page and in the <code className="action">Snapshots</code> tab of the instance.

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/instance/\\{instanceId\\}/snapshot"} />

    - **instanceId**: The unique instance ID.
    - **regionName**: The region name where the source instance is located.
    - **serviceName**: The OVHcloud project ID.
    - **distantRegionName (optional)**: The remote region name where the remote snapshot will be stored.
    - **distantSnapshotName (optional)**: The name of the remote snapshot to create in the remote region.
    - **snapshotName**: The name of the local snapshot to create.
    
    :::info
    Only create a remote snapshot if the parameters related to the remote region (**distantRegionName** and **distantSnapshotName**) are provided.

    :::

### Creating an automatic snapshot of an instance

:::info
If you want to automate this functionality directly via OpenStack, you can create a Mistral workflow associated with a cron trigger.

:::


{/* CP-STEPS-START:create-automated-backup */}
In the left-hand menu of your Public Cloud project, click <code className="action">Instances</code> under **Compute**. Click on the <code className="action">...</code> button to the right of the instance and select <code className="action">Create an automatic snapshot</code>.

The **Create a schedule** page opens. You can configure the following settings:
{/* CP-STEPS-END:create-automated-backup */}

#### **The workflow** 

{/* CP-STEPS-START:automated-backup-workflow */}
The schedule creates an automatic snapshot of the instance and its primary volume. There is no workflow type to choose.
{/* CP-STEPS-END:automated-backup-workflow */}

#### **The resource** 

{/* CP-STEPS-START:automated-backup-resource */}
In the **Select a target resource** section, you can select the instance to snapshot.
{/* CP-STEPS-END:automated-backup-resource */}

#### **The name** 

{/* CP-STEPS-START:automated-backup-name */}
In the **Name your schedule** section, enter a name for the automatic snapshot schedule. Take note of the pricing information in the summary on the right, then create the schedule with <code className="action">Create</code>.
{/* CP-STEPS-END:automated-backup-name */}

#### **The schedule**

{/* CP-STEPS-START:automated-backup-schedule */}
In the **Define scheduling** section, you can set up a custom schedule (**Custom**, in UNIX cron format, UTC) or choose one of the default frequencies:

- **Rotation 7**: daily snapshot with retention of the last 7 snapshots
- **Rotation 14**: daily snapshot with retention of the last 14 snapshots

<details>

<summary>**Adding a remote snapshot**</summary>


Enable <code className="action">Add a remote snapshot</code>, select a location, review the pricing information, and click the <code className="action">Create</code> button.

</details>
{/* CP-STEPS-END:automated-backup-schedule */}


### Managing snapshots and schedules

{/* CP-STEPS-START:manage-backups-schedules */}
Schedules are listed and deleted on the **Workflow management** page: click <code className="action">Workflow</code> under **Compute** in the left-hand menu.

Your instance snapshots are managed on the **Instance snapshots** page: click <code className="action">Instance Snapshot</code> under **Compute** in the left-hand menu.
{/* CP-STEPS-END:manage-backups-schedules */}

:::warning
The instance snapshot option must be deleted separately if you no longer wish to be billed for it. Deleting an instance does not delete the options attached to it.

:::


:::warning
**Note that you cannot delete an instance snapshot if an instance that has been spawned from this snapshot is running at the time of the delete action.**

:::
