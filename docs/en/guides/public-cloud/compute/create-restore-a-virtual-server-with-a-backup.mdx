## Objective

The OVHcloud Console enables you to [create snapshots of your instances](/guides/public-cloud/compute/save-an-instance) within a few clicks, as well as automating this process.
You can make use of these instance snapshots for two basic purposes:

- Creating a new instance with the snapshot as a template in order to duplicate the original instance, for example if you are configuring a load balancing infrastructure.
- Restoring instances from a snapshot, for example if recent changes broke critical configurations on the instance.

**This guide explains how to use snapshots to duplicate and restore your instances.**

## Requirements

- A snapshot of a [Public Cloud instance](/links/public-cloud/instance-backup)

[[cpnav:publiccloud-instance-backup]]

## Instructions

{/* CP-STEPS-START:backup-types-note */}
:::info
Two types of snapshots are available:

- Local: Stored in the same region as your instance.
- Distant: Automatically replicated in another region of your choice.

The operations of **creating** and **restoring** an instance from a distant snapshot are fully supported via the OVHcloud API, offering greater flexibility and effortless integration into your automation processes.

**Note:** In the OVHcloud Console, you can create an instance from any snapshot listed on the **Instance snapshots** page, but you can only restore an existing instance from a snapshot stored in its own region.

:::
{/* CP-STEPS-END:backup-types-note */}


### Creating an instance from a snapshot

{/* CP-STEPS-START:create-instance-from-backup */}
<Tabs>
  <Tab label="OVHcloud Console">
    In the left-hand menu of your Public Cloud project, click <code className="action">Instance Snapshot</code> under **Compute**. The **Instance snapshots** page lists your snapshots.

    Click the <code className="action">...</code> button in the row of the relevant snapshot, then select <code className="action">Create an instance</code>.

    The **Create an instance** page opens with some elements pre-defined:

    - **Region**: Your instance will be created in the same region as your snapshot. The region is determined by the snapshot and cannot be changed.
    - **Image**: The snapshot is preselected in the <code className="action">Snapshots</code> tab of the **Select an image** section.
    - **Model**: Only the models that are compatible with your image are available, depending on your quota.

    Choose the new instance's name, SSH key, network and billing settings, then click the <code className="action">Create my instance</code> button.

    For further information on creating an instance, please refer to [this guide](/guides/public-cloud/compute/getting-started).

    :::info
    In order to create the instance in a different data centre, you will first need to transfer the snapshot to the appropriate region. Please refer to our guide to [transferring an instance backup](/guides/public-cloud/compute/transfer-instance-backup-from-one-datacentre-to-another).

    :::

  </Tab>
  <Tab label="OVHcloud API">
    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/instance"} />

Fill in the variables:
    
    - **serviceName** : The OVHcloud project ID.
    - **regionName** : The region name where the instance will be located.
    
    Example of the request body:
    
    ```json
    {
      "billingPeriod": "hourly",
      "bootFrom": {
        "imageId": "5cb8ea68-****-****-****-820be8346***"
      },
      "flavor": {
        "id": "e81b46f8-****-****-****-cad655e65***"
      },
      "name": "newInstance",
      "network": {
        "public": true
      },
      "sshKey": {
        "name": "MySSHKey"
      }
    }
    ```
  </Tab>
  <Tab label="OpenStack CLI">
    To create an instance from your snapshot, use the snapshot ID as the image with this command:
    
    ```bash
    $ openstack server create --key-name SSHKEY --flavor 98c1e679-5f2c-4069-b4da-4a4f7179b758 --image 0a3f5901-2314-438a-a7af-ae984dcbce5c Server1_from_snap
    ```
  </Tab>
  <Tab label="Horizon">
    In the Horizon interface, click on <code className="action">Compute</code> in the left-hand menu, then on <code className="action">Images</code>. Find the desired image and click the <code className="action">Launch</code> button to the right of your image line. 
    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon1.png" loading="lazy" />

Name your instance in the dedicated field and determine the number of instances to create. Then click the <code className="action">Flavor</code> tab.
    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon-2" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon2.png" loading="lazy" />

Choose the desired instance model, then click the <code className="action">Networks</code> tab.
    
    :::warning
    If your instance is a Windows server, you must select a flavor of type win-xx-xx (for example, win-b2-15) and have a public interface on the Ext-Net network. Without these conditions, authentication with the OVHcloud KMS will not be possible, and your server will remain with an [unactivated licence](/guides/public-cloud/compute/activate-windows-license-private-mode). This could lead to limitations, including the absence of updates. Please note that it is not possible to resize a Linux instance (such as b2-15) to a Windows instance (such as win-b2-15). To make this transition, you need to recreate a new instance.

    :::

    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon-3" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon3.png" loading="lazy" />

Choose the network you wish to assign to it, then click the <code className="action">Launch Instance</code> button.
    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon-4" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon4.png" loading="lazy" />

You can find the status of your new instance in <code className="action">Compute</code> in the left-hand menu, then on <code className="action">Instances</code>.
    
    <img className="thumbnail" alt="public-cloud-instance-backup-horizon-5" src="/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/restorebackuphorizon5.png" loading="lazy" />
  </Tab>
</Tabs>
{/* CP-STEPS-END:create-instance-from-backup */}


### Restoring an instance from a snapshot

{/* CP-STEPS-START:restore-instance-from-backup */}
<Tabs>
  <Tab label="OVHcloud Console">
    In the left-hand menu of your Public Cloud project, click <code className="action">Instances</code> under **Compute**, then click on the name of the relevant instance.

    In the **General information** card of the <code className="action">Overview</code> tab, click <code className="action">Edit image</code> on the **Image** row. The **Edit image** panel opens.

    In the **Select a distribution** section, select the snapshots, then select the snapshot to restore in the **Select an image** section. Only the snapshots stored in the region of the instance are offered. Click on <code className="action">Edit image</code> if you are certain that you want to overwrite the current image with the snapshot.

    The instance will be reinstalled and restarted until the process is completed.

    :::warning
    As stated in the warning message, all data on the instance will be deleted: any data added after the snapshot creation will be lost.

    :::

  </Tab>
  <Tab label="OVHcloud API">
    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/instance/\\{instanceId\\}/reinstall"} />

Fill in the variables:
    
    - **serviceName** : The OVHcloud project ID.
    - **regionName** : The region name where the source instance is located.
    - **instanceId** : The unique instance ID.
    
    Example of the request body:
    
    ```json
    {
      "imageId": "5cb8ea68-****-****-****-820be8346***",
      "imageRegionName": "GRA11"
    }
    ```
  </Tab>
</Tabs>
{/* CP-STEPS-END:restore-instance-from-backup */}
