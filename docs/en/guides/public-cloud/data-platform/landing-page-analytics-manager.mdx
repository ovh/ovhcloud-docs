## What is the Analytics Manager?

The Analytics Manager is where project data becomes answers. It queries the [tables](/guides/public-cloud/data-platform/lakehouse-manager-tables) held in the Lakehouse Manager, through a no-code builder or a SQL editor, and turns the results into charts and dashboards.

<img className="thumbnail" alt="Index1" src="/images/public-cloud/data-platform/product/am/picts/homepage-am.png" loading="lazy" />

A query is both the unit of work and the unit of reuse. Queries are saved, named and versioned, so one definition backs a chart, a dashboard tile and an API endpoint instead of being rewritten in each. Queries run on cloud-native engines, and read either the tables in the lakehouse or, where a [source is marked as directly queryable](/guides/public-cloud/data-platform/connectors-sources-configure#make-your-data-source-directly-queryable), the external system itself.

[Dashboards](/guides/public-cloud/data-platform/analytics-manager-dashboards) assemble saved queries on a page for end users, and can be published beyond the people who built them. [History](/guides/public-cloud/data-platform/analytics-manager-history) records every execution with its performance metrics, which is where a slow dashboard gets diagnosed. [Settings](/guides/public-cloud/data-platform/analytics-manager-settings) holds the repositories and the query cache.

The Analytics Manager is also the seam between roles. Data engineers land and model the tables, analysts write the queries, and application developers consume them through [Application Services](/guides/public-cloud/data-platform/landing-page-app-services), which serves any saved query as a live endpoint under IAM authentication.
