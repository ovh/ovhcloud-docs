## Objective

This guide walks you through loading two years of orders from an online store, about 1 million order lines, into the Lakehouse, merging them into a single table and cleaning them with a Custom action. You upload the files with [Connectors](/guides/public-cloud/data-platform/connectors-sources-upload-files), create the tables in [Lakehouse Manager](/guides/public-cloud/data-platform/lakehouse-manager-tables), then merge and clean the orders with [Data Processing Engine](/guides/public-cloud/data-platform/dpe-actions-load).

By the end you will have the table `online_retail_ii_clean`, ready to query from Apache Superset. The second part of the guide, [Build the sales dashboard in Superset](/guides/public-cloud/data-platform/tutorials-ecommerce-sales-superset-dashboard), turns it into a sales dashboard.

## Requirements

To follow this guide you need:

- A Data Platform project. This guide uses a project named `ecommerce-sales`.
- The files below: the orders of the store, one file per year, and the cleaning script of the Custom action.

| **Type** | **Name** |
| --- | --- |
| Orders, December 2009 to December 2010 | <a className="rp-link" href="/images/public-cloud/data-platform/getting-further/ecommerce-sales/resources/online_retail_II_200910.xlsx" download>online_retail_II_200910.xlsx</a> |
| Orders, December 2010 to December 2011 | <a className="rp-link" href="/images/public-cloud/data-platform/getting-further/ecommerce-sales/resources/online_retail_II_201011.xlsx" download>online_retail_II_201011.xlsx</a> |
| Cleaning Python script | <a className="rp-link" href="/images/public-cloud/data-platform/getting-further/ecommerce-sales/resources/online_retail_cleaning.py" download>online_retail_cleaning.py</a> |

:::info
**About the data:** the orders come from [Online Retail II](https://archive.ics.uci.edu/dataset/502/online+retail+ii), UCI Machine Learning Repository, licensed under CC BY 4.0 (DOI 10.24432/C5CG6D). The UCI publishes it as one workbook with one sheet per year; each sheet is saved as its own file.
:::

We recommend completing the [Getting Started guides](/guides/public-cloud/data-platform/landing-page-getting-started) first. This guide assumes you are comfortable with the main components of Data Platform.

## Instructions

### Step 1: Upload the files

1. Open **Connectors** > **Sources** and create a new source of type *File Upload*.
2. Name it `online_retail_ii`.
3. Drop `online_retail_II_200910.xlsx` and `online_retail_II_201011.xlsx` in the *Files* area.
4. Click **Create**.

<img className="thumbnail" alt="The File Upload source named online_retail_ii with the two yearly Excel files added" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/connectors-file-upload.png" loading="lazy" />

### Step 2: Analyze the files

1. Open **Connectors** > **Analyzer**.
2. Select the source `online_retail_ii`, then the file `online_retail_II_200910.xlsx`.
3. Click **Extract metadata**.
4. Do the same for `online_retail_II_201011.xlsx`.

The [Analyzer](/guides/public-cloud/data-platform/connectors-analyzer-extract-metadata) detects eight attributes: `invoice`, `stockcode`, `description`, `quantity`, `invoicedate`, `price`, `customer_id` and `country`. Check that `invoice` and `stockcode` are detected as **String**: invoice numbers such as `C489449` and product codes such as `85123A` are not numbers.

<img className="thumbnail" alt="The Analyzer showing the eight attributes detected in online_retail_II_200910.xlsx" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/connectors-analyzer.png" loading="lazy" />

### Step 3: Create the tables

#### Create one table per year

1. Open **Lakehouse Manager** > **Tables**.
2. Click **New table** > **Create from a Connectors source**.

<img className="thumbnail" alt="The New table menu in Lakehouse Manager with the Create from a Connectors source option" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/lakehouse-new-table.png" loading="lazy" />

3. Select the file `online_retail_II_200910.xlsx` from the source `online_retail_ii`, then click **Next**.

<img className="thumbnail" alt="Selection of the file online_retail_II_200910.xlsx from the source online_retail_ii" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/lakehouse-create-table-from-connector.png" loading="lazy" />

4. Keep the default settings and click **Create**. The table is named `online_retail_ii_200910`, in the dataset `default_dataset`.

<img className="thumbnail" alt="The default table settings, with the name online_retail_ii_200910 and the three automatic options turned on" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/lakehouse-create-table-settings.png" loading="lazy" />

5. Repeat with `online_retail_II_201011.xlsx`. The table is named `online_retail_ii_201011`.

Both tables appear with 8 attributes and about 525k and 542k rows.

<img className="thumbnail" alt="The two yearly tables listed in Lakehouse Manager with their row counts" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/lakehouse-yearly-tables.png" loading="lazy" />

#### Create the table for all orders

1. [Duplicate](/guides/public-cloud/data-platform/lakehouse-manager-manage-tables#duplicate) the table `online_retail_ii_200910`. Hover over its row and click the **Duplicate** icon.

<img className="thumbnail" alt="The Duplicate icon on the row of the table online_retail_ii_200910 in Lakehouse Manager" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/lakehouse-duplicate-table.png" loading="lazy" />

2. Name the new table `online_retail_ii`, in the dataset `default_dataset`, and click **Create**.
3. [Build](/guides/public-cloud/data-platform/lakehouse-manager-manage-tables#build-table) the table.

The table has the same 8 attributes, and no rows yet.

<img className="thumbnail" alt="The empty table online_retail_ii with the same 8 attributes as the yearly tables" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/lakehouse-empty-table.png" loading="lazy" />

### Step 4: Merge the two years

#### Create the Load actions

1. Open **Data Processing Engine** > **Actions** and click **New action**.
2. Search for `load`, select the *Load* action and click **Select**.

<img className="thumbnail" alt="The Load action selected in the list of action types" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-load-action.png" loading="lazy" />

3. Fill in the action:

| Setting | Value |
|---|---|
| Source table | `online_retail_II_200910.xlsx` from `online_retail_ii` |
| Destination | `online_retail_ii` from `default_dataset` |
| Attributes | each source attribute mapped to the destination attribute of the same name |

4. Click **Create**.

<img className="thumbnail" alt="The Load action settings mapping online_retail_II_200910.xlsx to the table online_retail_ii" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-load-action-settings.png" loading="lazy" />

5. Create a second *Load* action, with `online_retail_II_201011.xlsx` as source and the same destination.

The list of actions shows your two *Load* actions, next to the two actions generated automatically when you created the yearly tables.

<img className="thumbnail" alt="The list of actions with the two new Load actions and the two generated ones" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-actions.png" loading="lazy" />

#### Run both actions with a workflow

1. In **Data Processing Engine** > **Workflows**, click **New workflow**.
2. Name it `Merge`.
3. In *Stage 1*, add your two *Load* actions.
4. Click **Create**, then run the workflow.

<img className="thumbnail" alt="The Merge workflow with the two Load actions in Stage 1" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-workflow.png" loading="lazy" />

The workflow takes a couple of minutes. When its status turns green, open **Lakehouse Manager** > **Tables**: `online_retail_ii` holds the rows of both yearly tables, **1,067,371 rows**.

<img className="thumbnail" alt="The list of workflows with the Merge workflow run completed" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-workflow-list.png" loading="lazy" />

:::warning
Run the `Merge` workflow once. Running it again may add the same order lines a second time. After each run, check that `online_retail_ii` holds 1,067,371 rows.
:::

### Step 5: Clean the orders

#### Create the clean table

1. In **Lakehouse Manager** > **Tables**, duplicate `online_retail_ii`.
2. Name the new table `online_retail_ii_clean` and build it.

You now have four tables. `online_retail_ii_clean` has the same 8 attributes and no rows yet.

<img className="thumbnail" alt="The four tables of the guide listed in Lakehouse Manager" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/lakehouse-all-tables.png" loading="lazy" />

#### Create the cleaning action

1. In **Data Processing Engine** > **Actions**, click **New action**.
2. Search for `custom`, select the *Custom* action and click **Select**.

<img className="thumbnail" alt="The Custom action selected in the list of action types" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-custom-action.png" loading="lazy" />

3. Fill in the action:

| Setting | Value |
|---|---|
| Action name | `online_retail_cleaning` |
| Function name | `online_retail_cleaning` |
| Development language | `Python 3.11` |
| Python requirements | `pandas` |
| File | upload `online_retail_cleaning.py` |

4. Click **Create**, then run the action.

<img className="thumbnail" alt="The Custom action online_retail_cleaning with its function name, language, requirements and uploaded file" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-cleaning-action.png" loading="lazy" />

:::info
**Note:** the function name is the entry point of the script and must be `online_retail_cleaning`. The other functions of the file are helpers: setting one of them as the function name returns `'Event' object is not subscriptable`.
:::

The action reads `online_retail_ii`, applies the cleaning rules and writes the result to `online_retail_ii_clean`. Open its logs: each rule reports how many rows it affects, and the last line gives the number of rows written to `online_retail_ii_clean`: **1,021,128 rows**.

| Rule | A row is removed when |
|---|---|
| 1. Exact duplicates | it is identical to another row on the 8 columns |
| 2. Invalid invoice number | the invoice is not 6 digits, with an optional `C` |
| 3. Invalid stock code | the stock code is not 5 digits, with optional letters |
| 4. Missing description | the description is empty |
| 5. Inconsistent quantity | a sale is not positive, or a cancellation is not negative |
| 6. Zero or negative price | the price is not strictly positive |
| 7. Missing invoice date | the date is empty |

A last step, **8. Harmonized descriptions**, gives each stock code its most frequent description, so a product never shows under two names.

#### Create an action to empty the clean table

The cleaning action adds rows to `online_retail_ii_clean`. Before running it again, empty the table with a [Delete action](/guides/public-cloud/data-platform/dpe-actions-delete).

1. Click **New action**, search for `delete` and select the *Delete* action.
2. In *Table list*, move `online_retail_ii_clean` to *Table to empty*.
3. Click **Create**.

<img className="thumbnail" alt="The Delete action with online_retail_ii_clean in the Table to empty list" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/dpe-delete-action.png" loading="lazy" />

To clean the data again, run this *Delete* action first, then `online_retail_cleaning`.

### Step 6: Connect Superset

All the data is now ready in the Lakehouse. To analyze it, create an Apache Superset application:

1. Create a Trino connection by following the [Trino consumer](/guides/public-cloud/data-platform/connectors-consumers-trino) guide.
2. Create the application and connect it to Trino by following Steps 1 to 3 of [Deploy Apache Superset](/guides/public-cloud/data-platform/tutorials-install-apache-superset).

#### Create the dataset in Superset

1. In Superset, open **Datasets** and click **+ Dataset**.
2. Select the database connection you created, named `Trino DP` in this guide, then the schema `default_dataset` and the table `online_retail_ii_clean`.
3. Check the columns, then click **Create and explore dataset**.

<img className="thumbnail" alt="The Superset dataset form with the database, the schema default_dataset and the table online_retail_ii_clean selected" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/superset-dataset-selection.png" loading="lazy" />

Every chart of the dashboard then starts from **Charts** > **+ Chart**: choose the dataset `online_retail_ii_clean`, then the chart type.

<img className="thumbnail" alt="The Superset chart creation screen with the dataset online_retail_ii_clean selected" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/superset-charts.png" loading="lazy" />

Continue with [Build the sales dashboard in Superset](/guides/public-cloud/data-platform/tutorials-ecommerce-sales-superset-dashboard).

## Good to know

- **You can connect a real store.** This guide uses a public dataset, uploaded as files. To analyze the orders of your own store, create a [Shopify](/guides/public-cloud/data-platform/connectors-sources-shopify) or [Stripe](/guides/public-cloud/data-platform/connectors-sources-stripe) source instead of the File Upload source: in **Connectors** > **Sources**, both appear in the *New source* window. The tables and the cleaning script then follow the attributes of that source.

<img className="thumbnail" alt="The New source window with the Stripe and Shopify connectors" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/connectors-new-source-shopify-stripe.png" loading="lazy" />

## What you have built

You have a raw table with every order line of the store, a clean table that follows the dataset description, and a Superset dataset on top of it.

The next part, [Build the sales dashboard in Superset](/guides/public-cloud/data-platform/tutorials-ecommerce-sales-superset-dashboard), turns the clean table into a dashboard: key figures, revenue over time, best-selling products, sales by country and customer loyalty.
