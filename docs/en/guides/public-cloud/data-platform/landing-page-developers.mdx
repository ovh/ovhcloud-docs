## What you can do programmatically

Everything a Data Platform project does through its interface can also be done in code. This section is written for people building on the platform rather than operating it.

The [Data Platform APIs](/guides/public-cloud/data-platform/landing-page-developers-apis) are the programmatic alternative to the interface: REST endpoints for buckets and for the Identity Access Manager, available to any user and authenticated with project credentials.

Three SDKs cover three jobs:

| SDK | Language | Main context of use |
| :-- | :------: | :------------------ |
| [Custom Actions](/guides/public-cloud/data-platform/landing-page-developers-python-sdk) | Python | [Custom actions](/guides/public-cloud/data-platform/dpe-actions-custom) and [integrated Jupyter notebooks](/guides/public-cloud/data-platform/dpe-notebooks) |
| Front APP | ReactJS | Custom dashboards inside a deployed app |
| Front API | NodeJS | Customizing the API an app calls |

The Custom Actions SDK is the one most projects use: it runs inside Custom actions, Custom PySpark actions and notebooks, and it is how a job reads and writes datasets, tables and buckets.

:::warning
Both Front SDKs are being replaced. Their current documentation stays on the legacy site until the new ones ship. See [the Front SDKs signpost](/guides/public-cloud/data-platform/developers-front-sdks).
:::

The stack behind all of this: [Docker](https://docs.docker.com/) runs every process and deployed component, [Python 3](https://www.python.org/downloads/) backs the data processing and data science components, and [NodeJS](https://nodejs.org/en/) backs the API and app components, which matters if you intend to develop against them locally.
