## Objective

**Custom Sources** let you bring your own connector for an API that Data Platform has no connector for. Your **coding agent** writes and tests the connector on your machine, guided by a skill you download from Data Platform. You upload the result as a **package**, Data Platform checks it and publishes it, and anyone in the project can then create sources from it.

A source built on a custom connector works like any other source: it appears in the *Sources* list, its metadata is extracted, and it feeds [Load actions](/guides/public-cloud/data-platform/dpe-actions-load), tables and lineage. Nothing sets it apart except the name of its connector.

<img className="thumbnail" alt="The Custom Sources page with the Download skill and Upload connector buttons above the list of the project's connectors" src="/images/public-cloud/data-platform/product/connectors/custom-sources/picts/custom-sources-overview.png" loading="lazy" />

### Custom Sources or HTTP REST

The [HTTP REST connector](/guides/public-cloud/data-platform/connectors-sources-rest) already covers APIs you can describe in a form. Use a custom source when that is not enough, and the API needs Python to be read:

- pagination that HTTP REST cannot follow;
- several calls to build one record;
- responses that must be reshaped before they are loaded;
- an authentication scheme HTTP REST does not support.

A custom connector is never built or edited in Data Platform. The package is the connector: its code, its endpoints and its credential fields come from the package, and they change only when you upload a new one.

## Requirements

- An AI coding agent on your machine, to build the connector.
- The documentation of the API, or an OpenAPI file or cURL examples, and valid credentials if the API needs them.
- The permission to write sources in the project, see [Permissions](#permissions).

## Instructions

### Download the skill

In the Connectors service, open *Custom Sources* and click **Download skill**. The skill is a folder you give to your coding agent. It holds:

| Content | What it is for |
|---|---|
| `SKILL.md` | The instructions the agent follows, from the API documentation to the finished package |
| An example package | A complete connector to start from |
| `reference/package-format.md`, `reference/connector-contract.md` | The format of a package and the functions a connector must provide |
| `harness/` | A runner that executes the connector the way an extraction job does, the checks Data Platform runs at upload, and the command that builds the package |

You can download the skill again at any time from the same page.

### Build and test the connector with your agent

Give the skill folder to your coding agent and ask it to build a connector for your API. Following the skill, the agent:

1. Checks that a custom source is the right tool, rather than HTTP REST.
2. Asks you for the API documentation, the data you want and how authentication works.
3. Writes the connector: a manifest, `forepaas.json`, and a Python module.
4. Runs the connector against the real API, with credentials you export as `CUSTOM_SOURCE_<KEY>` environment variables. Credential values are never written in a file.
5. Runs the same checks Data Platform runs at upload, then builds the package, a `.tgz` file.
6. Tells you what the connector extracts, which credential fields it declares, which warnings remain and what it could not run.

The test runs on your machine, against the real API: Data Platform never sees your credentials while the connector is built.

### Upload the connector

On the *Custom Sources* page, click **Upload connector**, then drop the `.tgz` file in the window or click to pick it. Data Platform runs its checks and shows the endpoints it found, with:

- **errors**, which block the upload: fix them with your agent and upload the new package;
- **warnings**, which do not block it: read them, and fix them with your agent if they apply to you.

<img className="thumbnail" alt="The Upload connector window listing the endpoints found in the package, with the check results and the Add button" src="/images/public-cloud/data-platform/product/connectors/custom-sources/picts/custom-sources-upload.png" loading="lazy" />

Click **Add**. The connector is published at once and its page opens. You can create a source from it right away, or later from the same page.

A package is refused when it declares a dependency other than a Python dependency, contains a script, or holds a file other than the manifest, the Python module and the icon. Its technical name cannot be the name of a connector built into Data Platform.

### Review and edit the connector

Open a connector from the *Custom Sources* list. Its page has two tabs:

- **Definition**: the result of the checks, with any remaining warning, then the identity of the connector, its connection (base URL, authentication method), its credential fields and its endpoints with their parameters.
- **Code**: the Python code that runs in the extraction jobs.

<img className="thumbnail" alt="The page of a custom connector, with the Export, Connect to the source and Upload new version buttons and the Definition tab" src="/images/public-cloud/data-platform/product/connectors/custom-sources/picts/custom-sources-details.png" loading="lazy" />

You can change three things in Data Platform: the **display name** (up to 200 characters), the **description** (up to 2,000 characters) and the **icon**. A **Save** button appears when you change one of them. Everything else comes from the package and is read-only: to change the code, the endpoints, the credential fields or the authentication, update the connector with your agent and upload a new version.

The **technical name** cannot change. It identifies the connector, and an upload with the same technical name replaces it.

### Create a source from the connector

On the page of the connector, click **Connect to the source**. You can also click **New Source** in the *Sources* list: custom connectors are listed under the *Custom source* category of the store, next to the built-in ones.

The standard source wizard opens. Name the source, fill in the credential fields the connector declares, pick the endpoints and their parameters, then save. See [Configure your connector](/guides/public-cloud/data-platform/connectors-sources-configure) for the steps that follow, from metadata extraction to loading.

### Update a connector

1. On the page of the connector, click **Export**. The package downloads, without any credential value. Keep it as a backup.
2. Give the exported package to your agent, with the skill, and ask for the change. The agent keeps the technical name, tests every endpoint, runs the checks and builds a new package.
3. Click **Upload new version** and upload the new package. It replaces the previous one.

Sources on the connector run the new code from their next job. If something breaks, upload the package you exported in step 1 again.

Uploading a package with the same technical name from **Upload connector** on the *Custom Sources* page also replaces the connector: the window offers to replace it, never to create a second one. **Upload new version** refuses a package whose technical name is different.

### Share a connector with another project

Click **Export** on the page of the connector, then upload the package in the other project with **Upload connector**. The same connector is published there. Credential values are not part of the package: each source in the other project needs its own.

### Delete a connector

To delete a connector, click **Delete** in the *Custom Sources* list. The page of the connector has no delete button.

:::warning
**Sources that use the connector stop working.** When sources depend on the connector, the confirmation lists them by name. Once the connector is deleted, these sources are kept as orphans, flagged in the *Sources* list, and their next job fails with a message naming the missing connector. {/* verify: the orphan flag in the Sources list is listed as remaining frontend work in the handover; confirm it ships on 2026-11-02 */}
:::

### Permissions

Custom Sources use the existing source permissions of the [Identity Access Manager](/guides/public-cloud/data-platform/iam-roles-conditions). There is no dedicated role. {/* verify: the exact service, resource and action names of the source permissions in the IAM */}

| To do this | You need |
|---|---|
| See the *Custom Sources* page, the connectors and their code | *Source* read |
| Upload a connector or a new version, change its display name, description or icon | *Source* write |
| Delete a connector | *Source* delete |
| Create a source from a custom connector | The same right as for any other source |

Without source rights, the *Custom Sources* page and the *Custom source* store category are not shown. With read rights only, the page and the connectors are visible, and **Save**, **Upload connector**, **Upload new version** and **Delete** are disabled.

### Good to know

- **The code runs in your project's extraction jobs only**, like a built-in connector. It never runs in a shared Data Platform service.
- **Credentials are declared as secret fields** in the package and filled in when you create a source. Their values are never part of a package, including an exported one.
- **A new version applies to every source on the connector** from their next job. If the new package drops an endpoint that a source uses, the upload does not warn you: that source's next job fails. {/* verify: the handover lists a warning at upload for a dropped endpoint as undecided; confirm the behaviour on 2026-11-02 */}
- **There is no version history** in Data Platform. Export the connector before you upload a new version, so you can restore it.

### Troubleshooting

| Symptom | Where to look |
|---|---|
| "The upload shows errors and **Add** is disabled" | Each error names the file, field or value at fault. Give the errors to your agent, then upload the new package. Running the checks with the harness before uploading catches the same errors. |
| "The upload is refused because the name is taken by a built-in connector" | Ask your agent to change the technical name in `forepaas.json`, then build and upload the package again. |
| "**Upload new version** refuses the package" | The technical name differs from the connector's. Start the change from the exported package, so the agent keeps the technical name. |
| "A source fails after a new version was uploaded" | Check that the new package still has the endpoints the source uses. Upload the previous package again to restore the connector. |
| "A source's job fails naming a missing connector" | Its connector was deleted. Upload the connector again with the same technical name, or create the source on another connector. {/* verify: that re-uploading the same technical name reattaches orphaned sources */} |
