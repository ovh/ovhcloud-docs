## Objective

The *Data Quality PySpark action* evaluates the [quality rules](/guides/public-cloud/data-platform/lakehouse-manager-data-quality) of one Lakehouse Manager table on Spark executors, and sends the result to the Lakehouse Manager as a report, one entry per rule. The report updates the quality status of the table. It runs the same rules, gives the same results and fails the job under the same conditions as the [Data Quality](/guides/public-cloud/data-platform/dpe-actions-data-quality) action, for tables too large for a worker.

Use it when the report of a Data Quality run carries `suggested_package: data-quality-pyspark`, or when you already know the table is too large: the Data Quality action suggests it above 1,000,000,000 cells (rows times columns) by default.

Like any other action, it can be run on demand, scheduled with a cron trigger, or placed in a [workflow](/guides/public-cloud/data-platform/dpe-workflows).

## Requirements

- A Lakehouse Manager table with at least one active quality rule. The rules are read from the Lakehouse Manager at each run.
- The Spark 4.1.2 image, the only one that carries the rule engine (Python 3.13).

## Configure the action

### Parameters

| Parameter | Required | Description |
|---|---|---|
| **Table** (`table`) | Yes | The table to check, written `dwh/<dataset>/<table>`, for example `dwh/events/clicks` |
| **Spark version** (`spark_version`) | Yes | The Spark image the job runs on. Only `4.1.2` carries the rule engine |
| **Critical failures allowed** (`max_criticals`) | No | The job fails when more rules than this end critical. When not set, only a [mandatory](/guides/public-cloud/data-platform/lakehouse-manager-data-quality#severity-and-thresholds) rule ending critical fails the job |
| **Warnings allowed** (`max_warnings`) | No | The job fails when more rules than this end in warning. When not set, warnings never fail the job |

The action has no engine choice: every rule runs on Spark, `custom_sql` rules included. Their expression is written in the Trino SQL dialect, as for the Data Quality action, and translated to Spark SQL.

The table is read at its current snapshot (`VERSION AS OF`), once per run, so all rules see the same data even if a load runs at the same time.

Size the Spark resources to the table, see [Resources](/guides/public-cloud/data-platform/dpe-jobs-resources).

### Example payload

To create the action through the API, send the action body to the Data Processing Engine API. The `polar-data` connector module is required next to the action:

```json
{
  "displayName": "Quality of events (Spark)",
  "repository": "<repository id>",
  "repositoryVersion": "<repository version id>",
  "action": "data-quality-pyspark",
  "language": "pyspark",
  "modules": [
    {"type": "action", "id": "data-quality-pyspark", "version": "latest"},
    {"type": "connector", "id": "polar-data", "version": "latest"}
  ],
  "parameters": {"table": "dwh/events/clicks", "spark_version": "4.1.2", "max_criticals": 0},
  "environment": {"fpu": {"size": 2, "instances": 1}}
}
```

## When the job fails

The report is always sent first: a failed job still has its report in the Lakehouse Manager, with the reason of each result, and the [quality status of the table](/guides/public-cloud/data-platform/lakehouse-manager-data-quality#table-quality-status) is updated whatever the result of the job. The job result and the table status are two different things: an optional rule ending critical makes the table critical without failing the job.

The job fails when:

- more rules end critical than **Critical failures allowed**, or, when that parameter is not set, a mandatory rule ends critical;
- more rules end in warning than **Warnings allowed**, when that parameter is set;
- no rule at all could be evaluated, for example when the table cannot be read.

The job passes when the table has no active rule, or when the table was never loaded: each rule then reports `no_data` with the reason "This table has no data yet: it was never loaded".

Results that never fail the job:

- `not_evaluated` and `no_data` results, as long as at least one rule could be evaluated;
- a rule on a column the table no longer has. It is reported in warning, with the reason "Column `<name>` is no longer in the table", and it is not counted in **Warnings allowed**. Update or delete the rule.
