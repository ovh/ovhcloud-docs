## What is a consumer?

A consumer is an external tool granted read access to project data. Where [sources](/guides/public-cloud/data-platform/landing-page-connectors-sources) bring data in, consumers expose it back out: a BI report built on project tables, a lineage backend receiving OpenLineage events, or any SQL client connecting through Trino.

<img className="thumbnail" alt="consumer" src="/images/public-cloud/data-platform/product/connectors/consumers/picts/consumers-home.png" loading="lazy" />

Creating one is a single step. Under **New consumer**, pick the tool from the store, and the platform registers a matching [IAM application](/guides/public-cloud/data-platform/iam-application-authentication) in the project with the OAuth redirect URLs and secrets already configured for it. [Trino consumers](/guides/public-cloud/data-platform/connectors-consumers-trino) are the exception: they are created from their own **Trino consumers** section rather than that button.

Power BI and OpenLineage support one consumer each per project. Trino consumers have no such limit, so create as many as you need, each with its own connection string.

Access is then governed entirely by the project's [Identity Access Manager](/guides/public-cloud/data-platform/landing-page-iam). People connecting from the external tool authenticate against project IAM and see only the tables and queries their [roles and groups](/guides/public-cloud/data-platform/landing-page-iam-users) allow, which means every external user, including people who never open the platform itself, has to exist in the project's IAM. Granting the *Analytics Consumer* role gives full read access to the project's data.

:::warning
Permissions are not scoped per consumer. A role that grants access to a table grants it through every consumer attached to the project.
:::
