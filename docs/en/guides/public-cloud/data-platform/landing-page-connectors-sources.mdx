## What is a source?

A source is a registered connection to an external system: the credentials, the network access, and the set of objects that system exposes. Registering a source moves no data. It records how to reach the system, so the [Analyzer](/guides/public-cloud/data-platform/landing-page-connectors-analyzer) can inspect it and the [Data Processing Engine](/guides/public-cloud/data-platform/landing-page-dpe) can load from it later.

Sources are chosen from the connector Store, which carries connectors for file storage systems, database engines, network protocols, streaming and IoT brokers, social platforms and analytics tools. Around twenty of them have their own guide covering the fields and permissions that connector needs. The rest follow the same configuration pattern.

Two paths open once a source is registered. The usual one imports a copy of the data into the project, by [creating](/guides/public-cloud/data-platform/lakehouse-manager-tables#create-a-table) and [loading](/guides/public-cloud/data-platform/dpe-actions-load) a [table](/guides/public-cloud/data-platform/lakehouse-manager-tables). The alternative, available on a subset of connectors, marks the source as directly queryable so the [Analytics Manager](/guides/public-cloud/data-platform/landing-page-analytics-manager) runs SQL against it in place, with no copy held on the platform.

Sources are organized in folders. Registering credentials is deliberately separate from analyzing and loading the data, so the two can sit with different teams and different [IAM roles](/guides/public-cloud/data-platform/iam-roles-conditions).
