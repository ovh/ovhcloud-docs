## Objective

This tutorial walks you through turning the cleaned order lines of an online store into a Superset dashboard: key figures, revenue over time, best-selling products, sales by country and customer loyalty.

It is the second part of [Prepare online store orders for a sales dashboard](/guides/public-cloud/data-platform/tutorials-ecommerce-sales). Superset queries the Lakehouse through [Trino](/guides/public-cloud/data-platform/connectors-consumers-trino), so all SQL on this page is in the **Trino dialect**.

## Requirements

To follow this tutorial you need:

- The table `online_retail_ii_clean` in the dataset `default_dataset` of your project, produced by the cleaning Custom action in [the first part](/guides/public-cloud/data-platform/tutorials-ecommerce-sales#step-5-clean-the-orders).
- An Apache Superset application connected to your project. If you have not deployed it yet, follow [Deploy Apache Superset](/guides/public-cloud/data-platform/tutorials-install-apache-superset).
- The Superset dataset `online_retail_ii_clean`, created in [Step 6 of the first part](/guides/public-cloud/data-platform/tutorials-ecommerce-sales#step-6-connect-superset).

## Instructions

### Step 1: Create the customer datasets in SQL Lab

The customer charts need one row per customer or per return visit, which a chart cannot compute from order lines. You prepare these rows once, with two queries saved as virtual datasets.

#### Create the virtual dataset customer_summary

1. Open **SQL** > **SQL Lab**.
2. Select your database and the schema `default_dataset`.
3. Paste the query below and click **Run**.
4. In the query toolbar, click the **Save or Overwrite Dataset** icon and save the dataset as `customer_summary`.

```sql
WITH purchase_days AS (
    SELECT DISTINCT customer_id, CAST(invoicedate AS DATE) AS purchase_day
    FROM default_dataset.online_retail_ii_clean
    WHERE customer_id IS NOT NULL
      AND invoice NOT LIKE 'C%'
),
customers AS (
    SELECT
        customer_id,
        COUNT(*)          AS purchase_days,
        MIN(purchase_day) AS first_purchase,
        MAX(purchase_day) AS last_purchase
    FROM purchase_days
    GROUP BY customer_id
)
SELECT
    customer_id,
    purchase_days,
    LEAST(purchase_days, 10)                                   AS purchase_days_capped,
    CASE WHEN purchase_days >= 2 THEN 1 ELSE 0 END             AS is_repeat,
    first_purchase,
    last_purchase,
    date_diff('day', last_purchase, DATE '2011-12-09')         AS days_since_last_purchase,
    CASE
        WHEN date_diff('day', last_purchase, DATE '2011-12-09') <= 90  THEN '1. Active (90 days)'
        WHEN date_diff('day', last_purchase, DATE '2011-12-09') <= 180 THEN '2. At risk (91 to 180 days)'
        WHEN date_diff('day', last_purchase, DATE '2011-12-09') <= 365 THEN '3. Lapsed (181 to 365 days)'
        ELSE '4. Lost (over a year)'
    END                                                        AS recency_segment
FROM customers
```

The result has one row per identified customer: **5,852 rows**.

<img className="thumbnail" alt="SQL Lab with the customer_summary query, the Save or Overwrite Dataset icon in the query toolbar and the first of the 5.85k result rows" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/superset-sql-lab-customer-summary.png" loading="lazy" />

#### Create the virtual dataset purchase_intervals

Repeat the same steps with the query below, and save it as `purchase_intervals`.

```sql
WITH purchase_days AS (
    SELECT DISTINCT customer_id, CAST(invoicedate AS DATE) AS purchase_day
    FROM default_dataset.online_retail_ii_clean
    WHERE customer_id IS NOT NULL
      AND invoice NOT LIKE 'C%'
),
with_previous AS (
    SELECT
        customer_id,
        purchase_day,
        lag(purchase_day) OVER (PARTITION BY customer_id ORDER BY purchase_day) AS previous_purchase
    FROM purchase_days
)
SELECT
    customer_id,
    purchase_day,
    date_diff('day', previous_purchase, purchase_day) AS days_since_previous_purchase
FROM with_previous
WHERE previous_purchase IS NOT NULL
```

The result has one row per return visit: **27,026 rows**.

:::info
**Note:** in SQL Lab, select the schema first. Without it, Trino returns `Schema must be specified when session schema is not set`. You can also prefix the table, as in the queries above: `default_dataset.online_retail_ii_clean`.
:::

### Step 2: Add calculated columns to online_retail_ii_clean

Open **Datasets**, edit `online_retail_ii_clean`, then go to the *Calculated columns* tab. For each column below, click **Add item**, then fill in its name and SQL expression. Start with `revenue`, the simpler one. Click **Save** once both columns are added.

<img className="thumbnail" alt="The Superset dataset list with online_retail_ii_clean, the two virtual datasets and the Edit icon on online_retail_ii_clean" src="/images/public-cloud/data-platform/getting-further/ecommerce-sales/picts/superset-datasets-list.png" loading="lazy" />

#### Add revenue

| Setting | Value |
|---|---|
| Column name | `revenue` |
| SQL expression | `quantity * price` |

`revenue` is the amount of each order line. A cancellation has a negative quantity, so its revenue is negative, and a plain sum gives the net revenue. Every amount in the dashboard is built on this column.

### Step 8: Create and assemble the dashboard

1. Open **Dashboards** and click **+ Dashboard**. The new dashboard opens in edit mode.
2. Click its title and rename it `Online store sales`.
3. Add a header `Key figures`, drag the four key figure tiles from the right panel and place them on one row.
4. Add a header `Trends and breakdowns`, then a tabs component with four tabs: `Customers`, `Time`, `Products` and `Geography`.
5. Drag each of the other charts from the right panel into its tab. In the *Customers* tab, put the three tiles on one row, the two bar charts side by side and the histogram at full width.
6. Click **Save**.

## What you have built

You have a dashboard that answers the questions of an online store manager: how much the store sells and to how many customers, how sales evolve over the year, which products and countries matter, and how often customers come back.

From here you can add dashboard filters on `country` or on a date range, or apply the same pipeline to your own order data. For another Superset dashboard built on Data Platform, see the [FOCUS and Apache Superset use case](/guides/public-cloud/data-platform/tutorials-finops-focus-superset).
