## Objective

The resources tab allows you to manage the **query engine** of your Project, i.e. the technology powering SQL analytics in the Project.

It executes queries on one or several [tables](/guides/public-cloud/data-platform/lakehouse-manager-tables), and is able to distribute the query processing on multiple worker instances.

<img className="thumbnail" alt="resources1" src="/images/public-cloud/data-platform/product/am/picts/resources-deactivated.png" loading="lazy" />

You can activate one query engine per Project, in order to use the advanced features of the Analytics Manager.

## Manage the query engine

### No query engine

By default, newly created Projects have **no query engine activated**. You can activate it manually on the resources page.

Without a query engine activated, you can still do the following:

- Create and run queries using the [visual mode](/guides/public-cloud/data-platform/analytics-manager-queries-visual-builder), on a single [dataset](/guides/public-cloud/data-platform/lakehouse-manager-datasets)
- Deploy and use [applications in Application Services](/guides/public-cloud/data-platform/landing-page-app-services-apps)
- [Connect](/guides/public-cloud/data-platform/developers-python-sdk-reference#the-connect-function) to your data from a [Data Processing Engine](/guides/public-cloud/data-platform/landing-page-dpe) action.
- Connect to the [datasets](/guides/public-cloud/data-platform/lakehouse-manager-datasets) directly from outside the Project  - *coming soon!*

However, it is impossible to do the following without a query engine:

- Create and run queries using the [SQL mode](/guides/public-cloud/data-platform/analytics-manager-queries-sql-editor) 
- Query (and join) data spread on multiple [datasets](/guides/public-cloud/data-platform/lakehouse-manager-datasets), or even on [directly queryable sources](/guides/public-cloud/data-platform/connectors-sources-configure#make-your-data-source-directly-queryable)
- Create [dashboards](/guides/public-cloud/data-platform/analytics-manager-dashboards)
- View the query [history](/guides/public-cloud/data-platform/analytics-manager-history) and detailed query execution metrics
- Implement fine-grained [permissions](/guides/public-cloud/data-platform/iam-roles-conditions) on the tables and access to the data they contain - *coming soon!*

## Manage instances

You can manage the number of parallel worker instances within a Trino cluster. There will also always be a coordinator, which distributes queries in the cluster.

<img className="thumbnail" alt="resources1" src="/images/public-cloud/data-platform/product/am/picts/resources-horizontal1.png" loading="lazy" />

If you only have one instance in your cluster, the coordinator will also be a worker.

<img className="thumbnail" alt="resources1" src="/images/public-cloud/data-platform/product/am/picts/resources-horizontal2.png" loading="lazy" />

You can also scale your query engine vertically and allocate **more computing power** to it by increasing the number of [Data Platform Units](/guides/public-cloud/data-platform/manage-pricing) (DPU) of each instance. The DPU is a unit of general processing capability, representing access to approximately *1 vCPU* and *4 GB of RAM*, based on hardware availability.
