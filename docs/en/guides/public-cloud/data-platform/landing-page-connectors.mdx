## Where data enters the project

Connectors holds every external system the project reads from, the rules applied to incoming data, and the external tools allowed to read results back out.

Three areas divide the work. **Sources** register the connection to an external system: credentials, network access, and the objects that source exposes. The **Analyzer** inspects those objects before anything is loaded, extracting metadata and applying blueprint rules so structure and formatting are settled at the door. **Consumers** point the other way, exposing project data to external tools such as Power BI, an OpenLineage backend, or any SQL client through Trino.

The split between registering a connection and loading its data is deliberate: credentials can stay with one team and data modelling with another. Registration happens here. Loading happens in the [Data Processing Engine](/guides/public-cloud/data-platform/landing-page-dpe), into tables held by the [Lakehouse Manager](/guides/public-cloud/data-platform/landing-page-lakehouse-manager).
