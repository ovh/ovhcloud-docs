## Objective

On the Platform, a **Project** is a cloud environment with dedicated resources that contains all the components required to manage your data's lifecycle, from ingestion to restitution. The physical data, in turn, is stored in a dataset linked to the Project.

## What can I do in a Project

Projects are the the hub in which you access all the platform services as well as your data. The tasks that are necessary to build a data application into production are all automated, such as:

- getting an entire team to work on the same environment, with different access rights to the data or the modules
- building a logical database schema, without being linked to a specific database
- automating the data collection, ETL-ing and visualization
- monitoring the cloud infrastructure and its performances

:::info
In general, one Project can answer one or a range of specific use cases. You can use several Projects in order to work on different environments (staging, production...) for the same use case.
:::

## What services are included in a Project

A Project is a flexble environment composed of multiple services, meaning you can add services in your Project as you wish. These services are separated into categories and only the *Admin tools* services are mandatory for your project to run, all the others you may add according to your needs.

<img className="thumbnail" alt="What services are included in a Project — Project home" src="/images/public-cloud/data-platform/product/project/picts/project_home.png" loading="lazy" />

- **Data Analytics**: collection, data warehousing and processing, and querying.
  - The [Connectors](/guides/public-cloud/data-platform/landing-page-connectors)
  - The [Lakehouse Manager](/guides/public-cloud/data-platform/landing-page-lakehouse-manager)
  - The [Data Processing Engine](/guides/public-cloud/data-platform/landing-page-dpe)
  - The [Analytics Manager](/guides/public-cloud/data-platform/landing-page-analytics-manager)
- **Application Services** : API gateways and data visualization.
  - The [APIs](/guides/public-cloud/data-platform/landing-page-app-services-apis)
  - The [APPs](/guides/public-cloud/data-platform/landing-page-app-services-apps)
- **Admin Tools**: resources management and access control.
  - The [Control Center](/guides/public-cloud/data-platform/landing-page-control-center)
  - The [Identity Access Manager](/guides/public-cloud/data-platform/landing-page-iam)

## How to allocate resources in a Project?

Projects were designed from scratch to scale easily as the requirements of your data Project evolve. You can independently **scale horizontally and vertically** in any component of your choice in just a few clicks, for example in the [preferences](/guides/public-cloud/data-platform/dpe-jobs-resources) of a [Data Processing Engine workflow](/guides/public-cloud/data-platform/dpe-workflows). Deployed instances, such as [APIs](/guides/public-cloud/data-platform/landing-page-app-services-apis) and [applications](/guides/public-cloud/data-platform/landing-page-app-services-apps) can also be scaled independently.

Each component in your Project will consume [resources](/guides/public-cloud/data-platform/manage-pricing) when it is actively running (either through a job or a deployment).

:::info
Even when it is idle, your Project uses a handful of DPUs by default. You can manage this amount in [Control Center](/guides/public-cloud/data-platform/landing-page-control-center).
:::
