## What sits outside a project

An **organization** is the boundary for identity and billing. It holds the team members who can reach Data Platform, the certificates and domains shared across projects, the quotas that cap what projects may consume, and the billing accounts the consumption is charged to. Every project belongs to exactly one organization.

A **project** is created from the organization, in a chosen cloud region, and is deleted from there too. Its subdomain and configuration identifiers are what external tools and code use to address it, so they turn up in almost every API call and connection string in this documentation.

**Pricing** explains what is metered and what is not: the compute unit, the components that hold it, storage and query volumes, and where to watch cost before it becomes a surprise.

:::info
Permissions for these actions are not granted here. Creating and deleting projects, inviting people and changing organization settings are all governed by the [Identity Access Manager](/guides/public-cloud/data-platform/landing-page-iam).
:::
