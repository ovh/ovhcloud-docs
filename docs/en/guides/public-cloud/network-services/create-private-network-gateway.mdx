## Objective

A [Gateway](/links/public-cloud/gateway) offers a secure outbound connection method from your private network instances or the ability to use Floating IPs with your instance or Load Balancer for service exposition.

**Learn how to create a private network with a Gateway.**

## Requirements

- A [Public Cloud project](/links/public-cloud/public-cloud) in your OVHcloud account
- **For the OVHcloud API:** API credentials ([First steps with the OVHcloud API](/guides/manage-and-operate/api/first-steps))
- **For the OVHcloud CLI:** the [OVHcloud CLI](https://github.com/ovh/ovhcloud-cli) installed and configured with your credentials
- **For Terraform:** Terraform installed and the OVHcloud provider configured ([How to use Terraform](/guides/public-cloud/cross-functional/how-to-use-terraform))
- **For the OpenStack API:** an OpenStack environment configured ([Preparing the environment](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment))

## Instructions

### Gateway models

Before creating a Gateway, choose the model suited to your bandwidth needs:

:::info
Please note that, at this time, size 2XL is not available within the Mumbai, Singapore, and Sydney regions.
:::

| Model | Bandwidth |
|-------|-----------|
| S | up to 200 Mbps |
| M | up to 500 Mbps |
| L | up to 2 Gbps |
| XL | up to 4 Gbps |
| 2XL | up to 8 Gbps |

### Create a private network with a Gateway

<Tabs>
  <Tab label="OVHcloud Console">
    **Step 1 — Access the creation page**

    Click <code className="action">Gateway</code> in the left-hand menu under **Network**.

    You must have an active vRack before proceeding. If you do not have a vRack, consult the [vRack activation](/guides/public-cloud/network-services/vrack#activation) section of the relevant guide.

    Then click <code className="action">Create a Gateway</code>.

    **Step 2 — Name the Gateway and select the region and size**

    Enter a **Gateway name**. In **Select a region**, choose the region where your private instances are located (you can **Filter a deployment mode**).

    Then select the size of your Gateway in **Select size** (see the models table above).

    **Step 3 — Attach a private network**

    In the **Attach to a specific private network** section, select an existing private network in **Select a private network**.

    :::info
    Only single-region private networks are supported by Gateway.
    :::

    You can also click <code className="action">Create a private network</code> to create a new private network inline: enter a **Private network name**, a **vLAN ID** and a **CIDR**, and choose whether **DHCP enabled** is ticked.

    **Step 4 — Confirm creation**

    Click <code className="action">Create a gateway</code> to start the deployment. The creation may take several minutes.

    Once done, the private network is visible in the <code className="action">Private Network</code> section under **Network**, and the Gateway appears in the <code className="action">Gateway</code> section.
  </Tab>
  <Tab label="OVHcloud API">
    Open the OVHcloud APIv6 interface. If needed, consult the guide [First steps with the OVHcloud API](/guides/manage-and-operate/api/first-steps).

    **Retrieve the project ID**

    If the project ID is unknown, use the following calls:

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project"} />

    :::info
    This call retrieves the list of projects.
    :::

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}"} />

    :::info
    This call identifies the project via the `description` field.
    :::

    **Create the private network with a Gateway**

    <Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway"} />

    Fill in the fields according to the following table:

    | Field | Description |
    |-------|-------------|
    | `serviceName` | Your project ID |
    | `regionName` | Example: `GRA9` |
    | `model` | Gateway size (`s`, `m`, `l`, `xl`, `2xl`) |
    | `name` | Name for your Gateway (`null` for default) |
    | `network.name` | Name for the private network (`null` for default) |
    | `network.cidr` | IP block for your subnet (e.g. `192.168.1.0/24`) |
    | `network.enableDhcp` | Check box to enable DHCP |
    | `network.ipVersion` | `4` (IPv6 not available) |
    | `network.vlanId` | Value between 2 and 4000, or empty for automatic assignment |

    :::info
    Repeat for each region where your private instances are present.
    :::

    To verify the details of your Gateway:

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\\{serviceName\\}/region/\\{regionName\\}/gateway"} />

    Leave `subnetId` blank to list all Gateways in the specified region.
  </Tab>
  <Tab label="OVHcloud CLI">
    Use the [OVHcloud CLI](https://github.com/ovh/ovhcloud-cli) to create a private network with a Gateway. Set your cloud project with `--cloud-project <project_id>` or configure it in your profile.

    **Create a Gateway with a new private network:**

    ```bash
    ovhcloud cloud network gateway create <region> \
      --cloud-project <project_id> \
      --name my-gateway \
      --model s \
      --network-name my-network \
      --subnet-cidr 192.168.1.0/24 \
      --subnet-enable-dhcp \
      --wait
    ```

    **Create a Gateway in an existing private network:**

    ```bash
    ovhcloud cloud network gateway create <region> \
      --cloud-project <project_id> \
      --name my-gateway \
      --model s \
      --network-id <network_id> \
      --subnet-id <subnet_id> \
      --wait
    ```

    Available models: `s`, `m`, `l`, `xl`, `2xl`.

    :::info
    Only single-region private networks are supported by Gateway.
    :::
  </Tab>
  <Tab label="Terraform">
    Before proceeding, consult the guide: [How to use Terraform](/guides/public-cloud/cross-functional/how-to-use-terraform)

    Create a Terraform file (e.g. `private_network_gateway.tf`) with the following content:

    ```hcl
    resource "ovh_cloud_project_network_private" "mypriv" {
      service_name = "<project_id>"
      vlan_id      = "0"
      name         = "mypriv"
      regions      = ["GRA9"]
    }

    resource "ovh_cloud_project_network_private_subnet" "myprivsub" {
      service_name = ovh_cloud_project_network_private.mypriv.service_name
      network_id   = ovh_cloud_project_network_private.mypriv.id
      region       = "GRA9"
      start        = "10.0.0.2"
      end          = "10.0.255.254"
      network      = "10.0.0.0/16"
      dhcp         = true
    }

    resource "ovh_cloud_project_gateway" "gateway" {
      service_name = ovh_cloud_project_network_private.mypriv.service_name
      name         = "my-gateway"
      model        = "s"
      region       = ovh_cloud_project_network_private_subnet.myprivsub.region
      network_id   = tolist(ovh_cloud_project_network_private.mypriv.regions_attributes[*].openstackid)[0]
      subnet_id    = ovh_cloud_project_network_private_subnet.myprivsub.id
    }
    ```

    Apply the configuration:

    ```console
    terraform apply
    ```
  </Tab>
  <Tab label="OpenStack API">
    Before proceeding, consult the following guides:

    - [Preparing an environment for using the OpenStack API](/guides/public-cloud/cross-functional/compute-prepare-openstack-api-environment)
    - [Setting OpenStack environment variables](/guides/public-cloud/cross-functional/compute-set-openstack-environment-variables)

    **Step 1 — Create a network and subnet**

    ```console
    openstack network create my_network

    openstack subnet create my_subnet --subnet-range <my_private_ip_range/mask> --network my_network --no-dhcp
    ```

    **Step 2 — List quality of service policies**

    ```console
    openstack network qos policy list
    +--------------------------------------+---------------+--------+---------+----------------------------------+
    | ID                                   | Name          | Shared | Default | Project                          |
    +--------------------------------------+---------------+--------+---------+----------------------------------+
    | a5524eb5-944e-4106-b209-9478bbdcedab | large_router  | True   | False   | XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX |
    | c210f5b2-db59-4973-a25f-9131195b6bcf | medium_router | True   | False   | XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX |
    | ec0ee74d-a1f3-43f6-87aa-b0e69ef8ce45 | small_router  | True   | False   | XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX |
    +--------------------------------------+---------------+--------+---------+----------------------------------+
    ```

    **Step 3 — Create the router and configure the Gateway**

    ```console
    openstack router create my_router

    openstack router add subnet my_router my_subnet

    openstack router set --external-gateway Ext-Net --qos-policy QOS_ID_OF_YOUR_CHOICE my_router
    ```

    If you omit the `--qos-policy` parameter, the `small` quality of service is applied.
  </Tab>
</Tabs>
