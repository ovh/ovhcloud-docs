## Objective

**This page lists the known limitations of the Public IPs, Floating IP and Basic IP: performance limitations, functional limitations with their workarounds, and quotas.**

## Performance limitations

A public IP has no model or size. The bandwidth of an instance depends on its flavor: see [Instance bandwidth](/guides/public-cloud/network-services/known-limits#instance-bandwidth).

## Functional limitations

### No Floating IP in a Local Zone

Floating IPs are not available in a Local Zone. Public connectivity relies entirely on each instance's Basic IP, which is bound to the instance: no public address can be moved from one instance to another.

**Workaround:** none for a movable address. The Basic IP still provides inbound and outbound connectivity.

### No IPv6 on Basic IP in EU-WEST-PAR and EU-SOUTH-MIL

In the EU-WEST-PAR and EU-SOUTH-MIL regions, an instance created with a Basic IP only gets IPv4, while in the other regions its public interface carries both an IPv4 and an IPv6 address. These two regions use a separate public network for IPv6, `ext-net-v6`, to which the instance is not attached.

**Workaround:** attach the instance to the `ext-net-v6` network with the OpenStack API.

## Quotas

Floating IPs are limited by the **Floating IPs** quota of your project, per region. See [Quotas](/guides/public-cloud/network-services/known-limits#quotas).
