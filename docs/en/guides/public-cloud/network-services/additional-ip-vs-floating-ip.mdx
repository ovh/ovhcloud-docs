## Objective

Infrastructure resources can be exposed to the Internet via their own public IP addresses. In the Public Cloud universe, these are **Basic IP** addresses. For services created on such an infrastructure it is however not recommended to use these IP addresses to expose services themselves.

When a service should be optimised for scalability or agility, its public IP address should not be linked to a particular server or virtual machine. For such cases, separate reserved IP addresses are the best way to make services publicly available.

In the Public Cloud universe you can use either **Additional IP** (previously labelled as Failover IP) or **Floating IP** to achieve this.

Both services provide a flexible way to manage public access to your services. They can stay infrastructure-agnostic and be scaled up or migrated whenever needed.

**This guide explains the differences between these three types of public IP addresses.**

## Public Cloud IP concepts

### Basic IP

A Basic IP is the public IP address an instance receives when it is attached directly to **Ext-Net**, the public network managed by OVHcloud in each region. You get a Basic IP when you choose the **Public Mode** of networking for an instance.

A Basic IP is delivered as a pair of addresses, one IPv4 and one IPv6, in every region, including 3-AZ regions and Local Zones. Each address can be deleted separately; deleting one does not delete the other.

A Basic IP is tied to the instance it was created for. It cannot be moved to another instance or network service, and deletion is the only action available on it. If you delete a Basic IP, or detach the Ext-Net interface from the instance, the address is released for good and cannot be reassigned to you. For an address that must outlive a specific instance, use an Additional IP or a Floating IP instead.

Typical use cases are instances that need direct Internet access without extra configuration: test and development environments, standalone servers, or instances that also use an Additional IP (which requires Public Mode).

A Basic IP is billed separately from the instance it is attached to, on an hourly basis.

Other network services do not use Basic IP:

- A Load Balancer is exposed to the Internet through a Floating IP only.
- A Gateway gets its own public IP on Ext-Net, which it uses as its external network. This IP comes with the Gateway: it is not an option you choose, and it cannot be detached or deleted on its own. It is billed separately from the Gateway.

For more information:

- Public Mode and Private Mode of networking are described in the [Public Cloud Networking Concepts](/guides/public-cloud/network-services/concepts) page and in the [How to create a Public Cloud instance and connect to it](/guides/public-cloud/compute/getting-started#networking-modes) guide.
- Detaching the Ext-Net interface of an instance connected to a vRack is covered in the [Configuring vRack for Public Cloud](/guides/public-cloud/network-services/vrack) guide.
- Ext-Net as the Floating IP pool is covered in the [Public Cloud Network Services FAQ](/guides/public-cloud/network-services/faq).
- Ext-Net reserves an internal range that your private subnets should not use; see the [known limits](/guides/public-cloud/network-services/known-limits#openstack-router-and-floating-ip-routing-conflict).

### Additional IP (previously labelled as Failover IP)

This type of public IP address is available for services of all relevant OVHcloud universes: Bare Metal Cloud (for bare metal servers), Public Cloud (with OpenStack) or Hosted Private Cloud (with VMware or Nutanix for example).

They are designed to be used in cross-product scenarios, for example in failover operations or hybrid cloud use cases. They are billed on a monthly basis.

Once an Additional IP address is available in your Control Panel, it can be attached/detached or moved between servers and Public Cloud instances. Manual changes may be needed on the backend side to apply new IP configurations.

Please note that in the Public Cloud universe, Additional IP can only be used with instances in the **Public Mode** of networking (having public IPs in the external network).

More information about configuring Additional IP addresses is available in [this guide](/guides/public-cloud/network-services/configure-additional-ip).

### Floating IP

This type of public IP address is only available for [Public Cloud services](/links/public-cloud/public-cloud), designed for cloud-native use cases and especially automation (e.g. Terraform, Ansible). They serve to expose a private instance or a private network service (Load Balancer for example) to the public network.

The backend (instance/Load Balancer) system configuration when using Floating IP is entirely automatic (via DHCP protocol), no manual setup is needed. However, they require a Gateway in order to map a public IP address to an instance or network service.

Please note that Floating IP can only be used with instances in the **Private Mode** of networking (within a specific private network inside a given region).

Floating IP is billed per second on a pay-as-you-go basis.

More information about configuring Floating IP is available on the [Public Cloud Networking Concepts page](/guides/public-cloud/network-services/concepts).

### How to obtain public IP addresses in the OVHcloud Control Panel

In the **Network** section of the left-hand menu, select <code className="action">Public IPs</code>. Here you can manage Additional IP and Floating IP addresses according to your needs. The <code className="action">Basic IP</code> tab lists the Basic IP addresses of your project, with their region, associated resource and status. From this tab, you can delete a Basic IP.

Basic IP addresses are not ordered from this page: you get one by creating an instance in Public Mode.

Depending on your choice, you can select from the different regions and further configuration options are available.

:::warning
The pricing methods depend on the use of the IP you choose. Basic IP usage is billed hourly, separately from its instance, Additional IP usage is billed monthly, while Floating IP usage is billed per second.

:::
