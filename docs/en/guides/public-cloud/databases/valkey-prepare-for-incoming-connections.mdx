## Objective

Public Cloud Databases allow you to focus on building and deploying cloud applications while OVHcloud takes care of the database infrastructure and maintenance in operational conditions.

**This guide explains how to configure your Valkey instance to accept incoming connections.**

## Requirements

- A [Public Cloud project](/links/public-cloud/public-cloud) in your OVHcloud account
- A Valkey service running on your OVHcloud Public Cloud Databases ([this guide](/guides/public-cloud/databases/getting-started) can help you to meet this requirement)

[[cpnav:publiccloud-databases]]

## Instructions

### Configure your Valkey instance to accept incoming connections

Before making a connection, we need to verify that our Valkey instance is correctly configured.

Click on <code className="action">Databases</code> in the left-hand navigation bar and select your Valkey instance.

#### Step 1: Verify your user roles and password

Select the <code className="action">Users</code> tab. Verify that you have a user with sufficient rights and a password. A `default` user exists on every new service.

The password of a user is displayed only once, when the user is created, and cannot be retrieved later. If you don't remember the user's password, you can either create a new user or regenerate the password of an existing user: click on the <code className="action">...</code> button on the right of the user, then on <code className="action">Reset password</code>. Be careful! By doing so you will need to update all the places where you already use this user/password pair.

To create a new user, click on <code className="action">Add user</code>, fill the form, then click on <code className="action">Create User</code>. Each field accepts several values:

- **Username**: the name of the user.
- **Keys**: the key patterns the user can access, for example `cache:*`.
- **Categories**: the command categories allowed (`+`) or denied (`-`), for example `+@read`, `+@write`, `+@connection`.
- **Commands**: individual commands allowed (`+`) or denied (`-`), for example `-flushall`.
- **Channels**: the pub/sub channel patterns the user can access, for example `news:*`.

In our example, we create a user called *app-user* with the following rights:

- Keys:
    - **cache:\*** (only keys starting with `cache:`)
- Categories:
    - **+@read** (read commands)
    - **+@write** (write commands)
    - **+@connection** (connection commands such as `PING`, `HELLO` or `AUTH`)
    - **+@pubsub** (pub/sub commands, needed in addition to a channel pattern to publish or subscribe)
- Commands:
    - **-flushall** (forbids the `FLUSHALL` command)
- Channels:
    - **news:\*** (only channels starting with `news:`)

With these rights, any access to a key outside `cache:*` is refused with the error `NOPERM No permissions to access a key`.

Once created or updated, the user must have the `READY` status in the OVHcloud Control Panel.

To change the rights of an existing user, click on the <code className="action">...</code> button on the right of the user, then on <code className="action">Edit</code>. The new rights apply immediately, without reconnecting. You can also manage them [with the API](/guides/public-cloud/databases/valkey-update-acls).

:::info
Follow the [Valkey ACL documentation](https://valkey.io/topics/acl/) and the [Valkey commands documentation](https://valkey.io/commands/) to learn more.

Follow this [guide](/guides/public-cloud/databases/valkey-capabilities#users-and-roles) to learn more about users and roles capabilities and limitations.

:::


#### Step 2: Authorise incoming connections from the service

:::warning
For security reasons the default network configuration doesn't allow any incoming connections. It is thus critical you authorise the suitable IP addresses in order to successfully access your database.

:::


Select the <code className="action">Configuration</code> tab, then locate the `IPs` section. IP addresses must be authorised here before they can connect to your database.

Enter an IP address or a CIDR block in the **IP address or IP/mask** field, add a description to identify its origin, then click on <code className="action">Add</code>. In our example, we enter `203.0.113.10/32`. The <code className="action">Current IP</code> shortcut adds the public IP address from which you are browsing the OVHcloud Control Panel.

Click on <code className="action">Save changes</code> to apply your changes. You can remove an authorised IP from the same section, then save your changes.

:::warning
You can enter `0.0.0.0/0` to allow connections from any address. Your service then becomes reachable from the entire Internet, and only the username/password pair protects your data. Please use it carefully.

:::


#### Collect required information

Select the <code className="action">Dashboard</code> tab to find the connection details in the `Connection information` section: host, port and service URI.

The URI has the form `valkeys://<username>:<password>@<host>:<port>`. TLS is mandatory: connections without TLS are refused. The server certificate is signed by a public certification authority, so you do not need to download a CA certificate to connect.

Select the <code className="action">Users</code> tab to get the username.
