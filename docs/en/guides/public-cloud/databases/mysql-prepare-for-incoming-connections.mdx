## Objective

Public Cloud Databases allow you to focus on building and deploying cloud applications while OVHcloud takes care of the database infrastructure and maintenance in operational conditions.

**This guide explains how to configure your MySQL instance to accept incoming connections.**

## Requirements

- A [Public Cloud project](/links/public-cloud/public-cloud) in your OVHcloud account
- A MySQL database running on your OVHcloud Public Cloud Databases ([this guide](/guides/public-cloud/databases/getting-started) can help you to meet this requirement)

[[cpnav:publiccloud-databases]]

## Instructions

### Configure your MySQL instance to accept incoming connections

Before making a connection, we need to verify that our MySQL instance is correctly configured.

Click on <code className="action">Databases</code> in the left-hand navigation bar and select your MySQL instance.

#### Step 1: Verify your users and password

Select the <code className="action">Users</code> tab. Verify that you have a user with sufficient rights and a configured password. If you don't remember the user's password, you can either create a new user or regenerate the password of an existing user.

:::warning
Be careful! By doing so you will need to update all the places where you already use this user/password pair.

:::


This first user **avnadmin** is pre-configured during the service installation and comes with the following grants:

```sql
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, RELOAD, PROCESS, REFERENCES, INDEX, ALTER, SHOW DATABASES, CREATE TEMPORARY TABLES, LOCK TABLES, EXECUTE, REPLICATION SLAVE, REPLICATION CLIENT, CREATE VIEW, SHOW VIEW, CREATE ROUTINE, ALTER ROUTINE, CREATE USER, EVENT, TRIGGER ON *.* TO "avnadmin"@"%" WITH GRANT OPTION

GRANT REPLICATION_APPLIER,ROLE_ADMIN ON *.* TO "avnadmin"@"%" WITH GRANT OPTION
```

You can display the current grants of a user with the `SHOW GRANTS FOR 'avnadmin'@'%';` SQL command.

You can add more users by clicking on the button <code className="action">Add user</code>.

Enter a username then click <code className="action">Create User</code>. MySQL users have no roles: only a name is required. The password is generated and displayed once at creation. Note it down, as it cannot be retrieved later.

:::warning
A user created from the Control Panel receives the same privileges as **avnadmin**: it can read and write all your databases, create databases and users, and grant its own privileges to others. Do not give such a user to an application.

For an application, create a dedicated user in SQL, limited to what it needs, for example while connected as **avnadmin**:

```sql
CREATE USER 'myuser'@'%' IDENTIFIED BY '<strong-password>';
GRANT SELECT, INSERT, UPDATE, DELETE ON mydatabase.* TO 'myuser'@'%';
```

User privileges cannot be managed from the OVHcloud Control Panel or the OVHcloud API. See the [official MySQL documentation](https://dev.mysql.com/doc/refman/8.4/en/grant.html) for the full `GRANT` syntax.

:::

:::info
You can delete a user or reset its password via the <code className="action">...</code> button on the right of the user in the users table, then <code className="action">Delete</code> or <code className="action">Reset password</code>. A user cannot be modified after its creation.

Users created directly in SQL (`CREATE USER`) do not appear in the OVHcloud Control Panel or the OVHcloud API, and cannot be managed from there.

:::


#### Step 2: Authorise incoming connections from the MySQL client

By default, a Public Cloud Databases service does not accept any connection from the outside world. This helps prevent intrusive connection attempts.

:::warning
As long as no IP address is authorised, your service is unreachable, even though it appears as available in the OVHcloud Control Panel: connection attempts fail, usually with a timeout and no explicit error message on the client side.

:::

Select the <code className="action">Configuration</code> tab, then locate the `IPs` section.

Enter an IP address or a CIDR block in the `IP address or IP/mask` field, add a description to identify its origin, then click <code className="action">Add</code>. In our example, we enter `203.0.113.10/32`.

Two shortcuts are available above the input field:

- <code className="action">Current IP</code>: adds the public IP address from which you are browsing the OVHcloud Control Panel. Convenient for a development workstation, provided your address is static.
- <code className="action">OVHcloud Data Platform IP</code>: adds the addresses required for OVHcloud Data Platform services to reach your database.

Validate the changes by clicking the <code className="action">Save changes</code> button.

:::warning
You can enter `0.0.0.0/0` to allow connections from any address. Your service then becomes reachable from the entire Internet, and only the username/password pair protects your data. Reserve this for tests, and prefer restricted CIDR blocks or the [vRack private network](/guides/public-cloud/databases/configure-vrack) for production environments.

:::

:::info
A dynamic IP address changes periodically: if your workstation or outbound gateway does not have a static address, your connections will stop working without any change on your side. In that case, authorise your provider's CIDR block, or use an egress point with a static address.

:::


#### Collect required information

Select the <code className="action">Dashboard</code> tab to find the connection details in the `Connection information` section: host, port, protocol, SSL mode, connection URI and the CA certificate (`Certificate` field). The port is specific to each service, and the SSL mode is mandatory: your client must connect using TLS.

Select the <code className="action">Databases</code> tab to get the database name (`defaultdb` by default).

Select the <code className="action">Users</code> tab to get the username.
