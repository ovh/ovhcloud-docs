## Objective

**This guide explains how to create a managed MongoDB database service from the OVHcloud Console and how to connect to it.**

## Requirements

- A [Public Cloud project](/links/public-cloud/public-cloud) in your OVHcloud account

[[cpnav:publiccloud-databases|en]]

## Instructions

In the left-hand menu of your Public Cloud project, click <code className="action">MongoDB</code> under **Databases**, then click <code className="action">Create a service</code>. The **Create a managed database** page opens.

### Selecting the database engine

Under **Database engine**, select **MongoDB**. You can change the version to install under **Version**.

### Selecting a region

Under **Select a region**, select the region where your service will be deployed.

### Selecting a service plan

Under **Plan**, select the plan that suits your needs:

- **Production**: a 3-node cluster, backed up daily with a 7-day retention.
- **Advanced**: a 3- to 7-node cluster (including an optional analytics node), backed up daily with a 30-day retention and point-in-time recovery over the last 24 hours.

For a detailed comparison of the plans, read the [Capabilities and Limitations guide](/guides/public-cloud/databases/mongodb-concept-capabilities).

### Selecting the node template

Under **Node type**, select the node template. It defines the compute resources (vCores and RAM) of each node in your cluster. Refer to the [price page](/links/public-cloud/prices-mongodb) for details on node types and their specifications.

### Sizing your cluster

Under **Nodes**, adjust the number of nodes (depending on the plan). If the node template offers a storage range, select the additional storage under **Storage**.

### Configuring the network

Under **Network**, select the network type:

- **Public network**: your service is reachable over the Internet.
- **Private network (vRack)**: your service is only reachable from the private network you select (**Private network** and **Subnet** fields). The network and subnet must exist before you create the service.

You can also add **IP restrictions** now (<code className="action">Add an IP</code>, <code className="action">Add my current IP</code>) or once the service is created.

### Reviewing and creating the service

Review the **Summary**. The name of your cluster is automatically generated; you can change it in the **Name** field before creating the service, or later.

Click on the <code className="action">Create the database</code> button. The <code className="action">API and Terraform equivalent</code> button shows the equivalent API call and Terraform configuration.

Within a few minutes, your MongoDB service will be deployed.

### Configuring connectivity

Once the service is up and running you will be able to configure it to accept incoming connections. A [dedicated guide](/guides/public-cloud/databases/mongodb-manage-control-panel) is available to help you configure your service after installation.

### Testing the service

When the service is running and accepting incoming connections, the next step is to access the service. The common way to do so is to use **MongoDB Compass** to connect to the service, following [this guide](/guides/public-cloud/databases/mongodb-connect-compass).

If **MongoDB Compass** is not your preferred method, read these other guides to connect to the service:

- [Connect with CLI](/guides/public-cloud/databases/mongodb-connect-cli)
- [Connect with Python](/guides/public-cloud/databases/mongodb-connect-python)
- [Connect with PHP](/guides/public-cloud/databases/mongodb-connect-php)

Other integration examples can be found on the following repository: [https://github.com/ovh/public-cloud-databases-examples/tree/main/databases/mongodb](https://github.com/ovh/public-cloud-databases-examples/tree/main/databases/mongodb).
