## Objective

Learn how to switch your Public Cloud Database service between public network (Internet) and private network (vRack) without recreating the service.

## Requirements

- A [Public Cloud project](/links/public-cloud/public-cloud) in your OVHcloud account
- Access to the <ApiLink>OVHcloud API</ApiLink> (create your credentials by consulting [this guide](/guides/manage-and-operate/api/first-steps))
- An existing Public Cloud Database service in `READY` status

## Considerations

- The network update triggers a service rebuild. Your database will be temporarily unavailable during the transition.
- When switching from private to public network, existing IP restrictions are cleared. You will need to reconfigure them after the switch.
- Ensure your service is in `READY` status before initiating a network change. The request will be rejected if the service is in another state (e.g. `UPDATING`, `CREATING`).

## Instructions

### Switch from public to private network

To move your database service to a private network, send a PUT request with the **networkId** (vRack network ID) and **subnetId** (vRack subnet ID):

<Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\{serviceName\}/database/mongodb/\{clusterId\}"} />

Include the following fields in the request body:

```json
{
  "networkId": "<private-network-uuid>",
  "subnetId": "<subnet-uuid>"
}
```

:::info
Replace `mongodb` in the route with your engine type (e.g. `postgresql`, `mysql`, `valkey`).
:::

The service **status** transitions to `UPDATING`. Monitor it using:

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/mongodb/\{clusterId\}"} />

Once the **status** returns to `READY`, your service is available on the private network.

### Switch from private to public network

To move your database service back to the public network, send a PUT request with **networkId** and **subnetId** set to `null`:

<Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\{serviceName\}/database/mongodb/\{clusterId\}"} />

Include the following fields in the request body:

```json
{
  "networkId": null,
  "subnetId": null
}
```

:::warning
Switching to the public network clears all existing IP restrictions. After the service returns to `READY` status, reconfigure your authorised IPs.
:::

### Reconfigure IP restrictions

After a network switch, existing IP restrictions are cleared. Once the service returns to `READY`, reconfigure them by sending a PUT request with the **ipRestrictions** field:

<Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\{serviceName\}/database/mongodb/\{clusterId\}"} />

```json
{
  "ipRestrictions": [
    {
      "ip": "203.0.113.0/24",
      "description": "My allowed network"
    }
  ]
}
```

:::warning
Until IP restrictions are reconfigured, no client can connect to your service. For security, the default network configuration blocks all incoming connections.
:::

### Verify the network configuration

After the service returns to `READY`, confirm the network type:

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/mongodb/\{clusterId\}"} />

The **networkType** field in the response indicates the current configuration: `public` or `private`.
