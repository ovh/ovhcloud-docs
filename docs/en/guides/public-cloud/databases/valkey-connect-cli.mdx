## Objective

Public Cloud Databases allow you to focus on building and deploying cloud applications while OVHcloud takes care of the database infrastructure and maintenance in operational conditions.

**This guide explains how to connect to a Valkey service instance with a Command Line Interface (CLI).**

## Requirements

- Access to the <ManagerLink to="/">OVHcloud Control Panel</ManagerLink>;
- A [Public Cloud project](/links/public-cloud/public-cloud) in your OVHcloud account;
- A Valkey service running on your OVHcloud Public Cloud Databases ([this guide](/guides/public-cloud/databases/getting-started) can help you to meet this requirement)
- [Configure your Valkey service](/guides/public-cloud/databases/valkey-prepare-for-incoming-connections) to accept incoming connections

## Concept

A Valkey service can be managed through multiple ways.
One of the easiest, yet powerful, is to use a Command Line Interface (CLI), also known as a Console or Terminal.
To interact correctly with the instance, we need to first install something called a client, in order to connect and control the Valkey service remotely.
It's a Client-Server interaction.

## Instructions

### Installing valkey-cli on your client

:::info
`valkey-cli` is the official Valkey client. It is shipped with the Valkey packages.

:::


You first need to install a software to interact with your instance remotely. This official software can be installed on various supports like your own computer, a VPS, a virtual machine... The only rule is to be able to reach the public network (Internet) and have sufficient privilege to install it.

Depending on your operating system:

- **macOS** (Homebrew): `brew install valkey`
- **Debian / Ubuntu**: `sudo apt install valkey-tools`
- **Fedora / RHEL**: `sudo dnf install valkey`
- **Alpine Linux**: `apk add valkey-cli`
- **Docker**: the official `valkey/valkey` image contains `valkey-cli`, for example `docker run -it --rm valkey/valkey valkey-cli --version`
- **Windows**: `valkey-cli` is not available natively. Use it from [WSL](https://learn.microsoft.com/windows/wsl/install) (with one of the Linux commands above) or from Docker.

For other installation methods, refer to the official [Valkey installation documentation](https://valkey.io/topics/installation/).

Check that the client is installed:

```console
$ valkey-cli --version
valkey-cli 9.1.2
```

The version number depends on your package. Your client must support TLS, which is the case of the packages listed above.

:::info
`redis-cli` and other Redis-compatible clients can also connect to your Valkey service, with the same options.

:::

We are now ready to learn how to connect to our instance.

### Connection

Get the host, the port and the URI of your service in the <code className="action">Dashboard</code> tab, `Connection information` section, as explained in the [Configure incoming connections](/guides/public-cloud/databases/valkey-prepare-for-incoming-connections) guide.

:::warning
TLS is mandatory: connections without TLS are refused. Always use the `valkeys://` scheme (or the `--tls` option). The server certificate is signed by a public certification authority, so you do not need to download a CA certificate or to add a `--cacert` option.

:::

In your terminal, type:

```console
valkey-cli --tls -u valkeys://<username>:<password>@<host>:<port> PING
```

Don't forget you need to modify the username, password, host and port.

The result should look like this:

```console
$ valkey-cli --tls -u valkeys://<username>:<password>@<host>:<port> PING
Warning: Using a password with '-a' or '-u' option on the command line interface may not be safe.
PONG
```

It means that the instance is running and responding to your command.

To be in interactive mode, run the same command without any Valkey command at the end:

```console
valkey-cli --tls -u valkeys://<username>:<password>@<host>:<port>
```

In our example, it will look like this:

```console
$ valkey-cli --tls -u valkeys://<username>:<password>@<host>:<port>
Warning: Using a password with '-a' or '-u' option on the command line interface may not be safe.
<host>:<port>> PING
PONG
<host>:<port>> HELLO

```

Congratulations! You are now fully able to interact with your instance!

:::tip
Use `PING` or `HELLO` to test a connection. `INFO` is refused to users whose permissions do not include it.

:::

#### Avoid the password on the command line

With the `-u` option, the password stays in your shell history and is visible in the list of processes, hence the warning displayed by `valkey-cli`. To avoid it, use one of these methods:

- Connect without credentials, then authenticate inside the interactive session:

    ```console
    $ valkey-cli --tls -h <host> -p <port>
    <host>:<port>> AUTH <username> <password>
    OK
    ```

- Let `valkey-cli` prompt for the password, which is not displayed:

    ```console
    $ valkey-cli --tls -h <host> -p <port> --user <username> --askpass
    Please input password:
    ```

:::warning
Do not put only the username in the URI (`valkeys://<username>@<host>:<port>`): `valkey-cli` reads the value before `@` as a password, and authentication fails.

:::

### valkey-cli usage

You can manage your instance using the command line interface in interactive mode or by setting parameters as `valkey-cli` arguments.

Please follow the official [valkey-cli documentation](https://valkey.io/topics/cli/) and the [list of Valkey commands](https://valkey.io/commands/).

### In the event of connection or command execution issues

If you do not authenticate, every command is refused with a `NOAUTH` error:

```console
$ valkey-cli --tls -h <host> -p <port> PING
(error) NOAUTH Authentication required.
```

If the username or the password is wrong, authentication fails with a `WRONGPASS` error:

```console
WRONGPASS invalid username-password pair or user is disabled.
```

Check the username in the <code className="action">Users</code> tab of your service. The password is displayed only once, at creation: if you lost it, reset it from the <code className="action">Users</code> tab.

If the user is authenticated but its permissions (ACL) do not allow the key, the command or the channel, you will get a `NOPERM` response:

```console
<host>:<port>> GET foo
(error) NOPERM No permissions to access a key
```

In this case, review the keys, categories, commands and channels allowed to your user, in the <code className="action">Users</code> tab or with the [API](/guides/public-cloud/databases/valkey-update-acls). For further reading, please refer to the [official Valkey ACL documentation](https://valkey.io/topics/acl/).
