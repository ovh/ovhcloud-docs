## Objective

A semantic search finds texts by their meaning rather than by their exact words. Each text is turned into a vector, called an *embedding*, by an embedding model. Texts with similar meanings get similar vectors, so a question can be matched with the passages that answer it, even when they share no words.

This tutorial builds such a search end to end, entirely on OVHcloud:

- [AI Endpoints](/guides/public-cloud/ai-machine-learning/ai-endpoints-getting-started) turns your texts and your questions into vectors;
- a Public Cloud Databases for PostgreSQL service stores them with the `vector` extension (pgvector) and finds the closest ones with an HNSW index.

It also covers what you need to know before you start: the rights needed in PostgreSQL, the number of texts per request, and the column type to choose according to the model.

## Requirements

- A [Public Cloud project](/links/public-cloud/public-cloud) in your OVHcloud account.
- A [Public Cloud Databases for PostgreSQL](/links/public-cloud/databases) service, version 17 or 18, that accepts connections from your machine (the [Configure incoming connections](/guides/public-cloud/databases/postgresql-prepare-for-incoming-connections) guide explains how to authorise your IP address).
- Command-line access to your service with the `avnadmin` user (the [Connect using the CLI](/guides/public-cloud/databases/postgresql-connect-cli) guide can help you to meet this requirement).
- An AI Endpoints API key (see [Getting started with AI Endpoints](/guides/public-cloud/ai-machine-learning/ai-endpoints-getting-started)).
- A Python 3 environment with the `psycopg2-binary` package.

:::info
On a project shared through IAM, only users with administrator rights can create an AI Endpoints API key. If you cannot create one, ask your project administrator.

Without a key, AI Endpoints accepts 2 requests per minute per model: enough to try the examples below, not to process a corpus.

:::

## Instructions

### Step 1 - Preparing the database

#### Installing the extension

Connect as `avnadmin` to the database you will use, for example `defaultdb`, and install the extension. Its name in SQL is `vector`:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

#### Creating an application user with its own schema

Do not use `avnadmin` in your application: create a dedicated user **in SQL, as `avnadmin`**, and give it its own schema:

```sql
CREATE ROLE "rag_app" LOGIN;
CREATE SCHEMA "rag" AUTHORIZATION "rag_app";
```

Then set its password with psql's `\password` meta-command:

```console
defaultdb=> \password rag_app
```

:::warning
A user created from the <code className="action">Users</code> tab of the OVHcloud Console or with the API cannot create tables: it gets `permission denied for schema public`, including in a database created from the OVHcloud Console. The schema owned by `rag_app` above solves this. For more ways to grant privileges, see [Manage users, roles and privileges](/guides/public-cloud/databases/postgresql-users-roles-grants).

:::

### Step 2 - Choosing the model and the column type

AI Endpoints offers several embedding models. The size of their vectors, called the *dimension*, determines which column type you can index:

| Model | Dimension | Context | Column type to index |
|---|---|---|---|
| `bge-m3` | 1,024 | 8,192 tokens | `vector(1024)` |
| `bge-multilingual-gemma2` | 3,584 | 8,192 tokens | `halfvec(3584)` |
| `Qwen3-Embedding-8B` | 4,096, or less with the `dimensions` parameter | 32,768 tokens | `vector(N)` with `dimensions` set to N, at most 2,000 |

The HNSW index of pgvector accepts:

- up to **2,000 dimensions** on a `vector` column. Beyond that, index creation fails with `column cannot have more than 2000 dimensions for hnsw index`;
- up to **4,000 dimensions** on a `halfvec` column, which stores each value on 2 bytes instead of 4.

`Qwen3-Embedding-8B` returns 4,096 dimensions by default, above both limits. Add the `dimensions` parameter to the request, for example `"dimensions": 1024`, to receive shorter vectors that fit a `vector` column.

This tutorial uses `bge-m3`, which is multilingual and the fastest of the three.

#### Creating the table

Connect as `rag_app` and create the table in its schema (for `bge-multilingual-gemma2`, declare `emb halfvec(3584)` instead of `emb vector(1024)`):

```sql
CREATE TABLE rag.docs (
  id   int PRIMARY KEY,
  body text,
  emb  vector(1024)
);
```

### Step 3 - Turning your texts into vectors

AI Endpoints exposes an OpenAI-compatible embeddings route. Send at most **25 texts per request**: beyond that, the request is rejected with an HTTP 400 error, `given batch size overflow maximal one`.

```python
import json
import os
import urllib.request

URL = "https://oai.endpoints.kepler.ai.cloud.ovh.net/v1/embeddings"
KEY = os.environ["AI_ENDPOINT_API_KEY"]
BATCH = 25  # maximum number of texts per request


def embed(texts, model="bge-m3", dimensions=None):
    body = {"model": model, "input": texts}
    if dimensions:  # Qwen3-Embedding-8B only
        body["dimensions"] = dimensions
    req = urllib.request.Request(
        URL,
        data=json.dumps(body).encode(),
        headers={"Content-Type": "application/json", "Authorization": "Bearer " + KEY},
    )
    return [e["embedding"] for e in json.load(urllib.request.urlopen(req))["data"]]


def embed_all(texts, **kwargs):
    vectors = []
    for i in range(0, len(texts), BATCH):
        vectors += embed(texts[i:i + BATCH], **kwargs)
    return vectors
```

With an API key, AI Endpoints accepts 400 requests per minute per model. To embed a large corpus faster, send several batches in parallel within this limit.

### Step 4 - Loading the vectors into PostgreSQL

```python
import psycopg2
from psycopg2.extras import execute_values

texts = [
    "The museum opens every day from 9 am to 6 pm, except on Mondays.",
    "Children under 12 enter for free when accompanied by an adult.",
    "Guided tours of the medieval wing start at 10 am and 3 pm.",
]

conn = psycopg2.connect(
    host="<service-host>", port=20184, dbname="defaultdb",
    user="rag_app", password=os.environ["PG_PASSWORD"], sslmode="require",
)
cur = conn.cursor()

vectors = embed_all(texts)
execute_values(
    cur,
    "INSERT INTO rag.docs (id, body, emb) VALUES %s",
    [(i, t, str(v)) for i, (t, v) in enumerate(zip(texts, vectors))],
)
conn.commit()
```

Replace `<service-host>` and the port with the values shown in the **Connection information** section of your service.

Once the data is loaded, create the HNSW index for the cosine distance (for a `halfvec` column, use `halfvec_cosine_ops`):

```sql
CREATE INDEX ON rag.docs USING hnsw (emb vector_cosine_ops);
```

:::info
Building the index after loading is faster than updating it row by row. Rows inserted later are added to the index automatically.

:::

### Step 5 - Searching by meaning

Turn the question into a vector with the **same model**, then sort the rows by cosine distance (`<=>`):

```python
question = "Is it free for kids?"
q = embed([question])[0]

cur.execute(
    "SELECT id, body, emb <=> %s::vector(1024) AS distance "
    "FROM rag.docs ORDER BY distance LIMIT 3",
    (str(q),),
)
for row in cur.fetchall():
    print(row)
```

The passage about children comes first, even though it shares no words with the question.

To check that the index is used, prefix the query with `EXPLAIN ANALYZE`. On a table of a few rows, as here, PostgreSQL prefers to read the whole table and the plan shows a `Seq Scan` followed by a `Sort`. On a real corpus, or after `SET enable_seqscan = off;` in your session, the plan shows an `Index Scan` on the HNSW index, here `docs_emb_idx`.

:::info
Always use the same model, and the same `dimensions` value for `Qwen3-Embedding-8B`, for your texts and for your questions. Vectors from two different models cannot be compared.

:::
