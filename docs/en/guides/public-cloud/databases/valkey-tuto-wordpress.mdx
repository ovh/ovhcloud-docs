## Objective

Do you have a CMS website or blog, perhaps powered by WordPress? Learn how to speed up page load times and SQL queries using a Valkey service! In this tutorial, we will set up a Valkey service for your CMS data. All users, even administrators and especially visitors, will directly benefit from a better performance of the website.

### CMS platform

For this tutorial we propose to use the WordPress CMS, running on Linux Ubuntu with MySQL as the main database. To get the object cache we will use a Public Cloud Database for Valkey and the WordPress plugin Redis Object Cache, which is compatible with Valkey.

## Requirements

This tutorial requires:

- A running WordPress
- A WordPress administrator account to install a plugin
- A [PHP client](https://valkey.io/clients/) supported by the plugin (in this tutorial: PhpRedis)
- An OVHcloud Public Cloud database for Valkey

## Instructions

### Tutorial technical environment

This tutorial is based on the following software components:

- Linux Ubuntu 24.04 LTS / Apache 2.4 / PHP 8.3 / MySQL 8.0
- WordPress: 7.1
- PhpRedis: 5.3.7 (package `php-redis` of Ubuntu 24.04)
- Redis Object Cache: 3.0
- Valkey: one of the versions listed in the [Valkey capabilities](/guides/public-cloud/databases/valkey-capabilities) guide

The screenshots were taken with earlier releases of WordPress and of the plugin: your interface may differ slightly.

### Configuring your CMS: WordPress

If you need to install WordPress, please refer to the official guide: [WordPress How To Install](https://developer.wordpress.org/advanced-administration/before-install/howto-install/).

Once done, we will set up the WordPress backend correctly.
For the next steps, let's consider that you have an up and running WordPress system on a LAMP (Linux, Apache, MySQL, PHP) platform.

### PHP client: PhpRedis

As WordPress is based on PHP, we will need a PHP client compatible with Valkey. We propose to use one of the main [PHP clients](https://valkey.io/clients/): PhpRedis.

As TLS is required to secure the connection to the OVHcloud Public Cloud database for Valkey, we have to use the v5.3.x release of PhpRedis or above.

Please check that PhpRedis is installed, with a compliant release:

- If you do have SSH access to your WordPress server you can use the following command:

```bash
dpkg -l php-redis
```
In case it is not available on your system, please install it:

```bash
sudo apt install php-redis
sudo systemctl restart apache2
```
- If you don't have SSH access to the system, use the phpinfo() function and do a search on the `redis` module (the PhpRedis extension) as in the following example:

### Configure WordPress to connect to the Valkey service

#### Modify wp-config.php

Before activating the Redis Object Cache plugin, it is required to configure the Valkey service connection parameters.
By default, this plugin looks for a service hosted in the same server as your WordPress.
It's not our case scenario here, since the Valkey service is hosted in OVHcloud Public Cloud Databases.

We will follow the official plugin documentation to define the remote server: [Redis Object Cache configuration](https://github.com/rhubarbgroup/redis-cache/blob/develop/README.md).
This has to be done in the WordPress configuration file (**wp-config.php** located in /var/www/wordpress/ in our example) and add the following lines, replacing `<host>`, `<port>`, `<username>` and `<password>` with the values of your service (host and port are displayed in the <code className="action">Connection information</code> section of the <code className="action">Dashboard</code> tab of your service in the Control Panel):

```php
define( 'WP_REDIS_CLIENT', 'phpredis' );
define( 'WP_REDIS_SCHEME', 'tls' );
define( 'WP_REDIS_HOST', '<host>' );
define( 'WP_REDIS_PORT', <port> );
define( 'WP_REDIS_PASSWORD', [ '<username>', '<password>' ] );
define( 'WP_REDIS_SSL_CONTEXT', [
    'verify_peer' => true,
    'verify_peer_name' => true,
]);
define( 'WP_REDIS_PREFIX', 'myvps_' );
```

The `tls` scheme is mandatory: the Valkey service refuses unencrypted connections. The server certificate is signed by a public certification authority, so no certificate needs to be downloaded: keep the certificate verification enabled (`verify_peer` and `verify_peer_name` set to `true`) and never disable it.

The user defined in `WP_REDIS_PASSWORD` must be allowed by its ACL to read and write the keys used by the plugin (for example the key pattern `myvps_*` if you use the prefix above).

#### Key prefix

The key prefix (`WP_REDIS_PREFIX`, which replaces the deprecated `WP_CACHE_KEY_SALT` constant) is not mandatory, even more if you have only one application using a Valkey service, but if you have several WordPress sites, it will be useful to determine **what-pushes-what**.

#### Set an eviction policy suited to caching

By default, the `valkey_maxmemory_policy` advanced parameter of your service is set to `noeviction`: when the memory is full, Valkey rejects new writes and the plugin can no longer store objects in the cache. For a cache use case such as this one, we recommend setting this parameter to `allkeys-lru`, so that Valkey evicts the least recently used keys when memory is full.

To modify this parameter, follow the guide [Configure the advanced parameters for Public Cloud Databases](/guides/public-cloud/databases/advanced-configuration). Changing the advanced configuration may restart the service.

#### Check that authorised IPs are updated

Do not forget to add the IP address of your WordPress server to the authorised IPs of the Valkey service. To do so, follow the guide [Configure incoming connections of a Public Cloud Databases for Valkey service](/guides/public-cloud/databases/valkey-prepare-for-incoming-connections).

### Checking performance boost

#### Validate that cache is populated

If you can use a CLI to query the Valkey service (see [How to connect to a Valkey service with CLI](/guides/public-cloud/databases/valkey-connect-cli)), you can check that information populated to it after browsing some WordPress pages.

In our case:

```bash
valkey-cli --tls -u valkeys://<username>:<password>@<host>:<port>
```

#### Install a query monitoring plugin

If you want to have more information about how the cache has impacted the performance, you can measure the gain in response delay directly with your browser. You can also see more details using an additional WordPress plugin like [Query Monitor](https://wordpress.org/plugins/query-monitor/).

Using a simple WordPress site populated with poor content and a very limited number of posts, let's take a look at the improvement.

#### Two main benefits using a Valkey service

As seen, using a Valkey service you will see a performance gain for your CMS. It will be even more efficient as soon as your site stores more and larger data. You will also directly benefit from the fact that the MySQL server will be less stressed with the load/concurrent accesses, which will offer the opportunity to handle more and more users.
