## Objective

This guide lists all the supported advanced parameters that allow you to configure your Public Cloud Databases for Valkey according to your use cases.

## Requirements

- A [Public Cloud project](/links/public-cloud/public-cloud) in your OVHcloud account
- A database running on your OVHcloud Public Cloud Databases ([this guide](/guides/public-cloud/databases/getting-started) can help you to meet this requirement)
- Access to your <ManagerLink to="/">OVHcloud Control Panel</ManagerLink> or to the <ApiLink>OVHcloud API</ApiLink>

## Instructions

:::warning
Advanced parameters can also be managed with Terraform, through the `advanced_configuration` argument (key/value pairs) of the [`ovh_cloud_project_database`](https://registry.terraform.io/providers/ovh/ovh/latest/docs/resources/cloud_project_database) resource.

:::

Please refer to this [guide](/guides/public-cloud/databases/advanced-configuration#using-the-ovhcloud-control-panel) to find out how to change your advanced parameters from the OVHcloud Control Panel.

### Using API

Please refer to this [guide](/guides/public-cloud/databases/advanced-configuration#using-api) to find out how to change your advanced parameters from the OVHcloud API.

### Advanced parameters for Valkey

Below you can find the advanced parameters available for a Valkey service:

:::info
The table below lists the advanced parameters available for a Valkey service. Your service shows the exact list, with the allowed values, in the <code className="action">Configuration</code> tab of the Control Panel and through the API.

Changing the advanced configuration may cause the service to restart. This is the case for `valkey_io_threads` and `valkey_number_of_databases`: change them during a low-traffic period.
:::

| Parameters |
|------------|
|**valkey_acl_channels_default** `string`<br/>values: `allchannels`, `resetchannels`<br/>Determines default pub/sub channels' ACL for new users if ACL is not supplied. When this option is not defined, all_channels is assumed to keep backward compatibility. This option doesn't affect Valkey configuration acl-pubsub-default.<br/>|
|**valkey_active_defrag_ignore_bytes** `long`<br/>min: `1048576` max: `1073741824`<br/>default: `104857600`<br/>Minimum amount of fragmentation waste, in bytes, before active defragmentation starts. Only takes effect when `valkey_activedefrag` is enabled.<br/>|
|**valkey_active_defrag_threshold_lower** `long`<br/>min: `1` max: `100`<br/>default: `10`<br/>Minimum percentage of fragmentation before active defragmentation starts. Only takes effect when `valkey_activedefrag` is enabled.<br/>|
|**valkey_active_expire_effort** `long`<br/>min: `1` max: `10`<br/>default: `1`<br/>Valkey reclaims expired keys both when accessed and in the background. The background process scans for expired keys to free memory. Increasing the active-expire-effort setting (default 1, max 10) uses more CPU to reclaim expired keys faster, reducing memory usage but potentially increasing latency.<br/>|
|**valkey_activedefrag** `boolean`<br/>default: `false`<br/>Enable active memory defragmentation. When enabled, Valkey relocates objects off sparsely-used memory pages to reduce fragmentation and return memory to the operating system. Defragmentation runs on the main thread and consumes CPU, so it may increase latency under load.<br/>|
|**valkey_io_threads** `long`<br/>min: `1` max: `256`<br/>Set Valkey IO thread count. Changing this will cause a restart of the Valkey service.<br/>|
|**valkey_lfu_decay_time** `long`<br/>min: `1` max: `120`<br/>default: `1`<br/>LFU maxmemory-policy counter decay time in minutes<br/>|
|**valkey_lfu_log_factor** `long`<br/>min: `0` max: `100`<br/>default: `10`<br/>Counter logarithm factor for volatile-lfu and allkeys-lfu maxmemory-policies<br/>|
|**valkey_maxmemory_policy** `string`<br/>values: `allkeys-lfu`, `allkeys-lru`, `allkeys-random`, `noeviction`, `volatile-lfu`, `volatile-lru`, `volatile-random`, `volatile-ttl`<br/>default: `noeviction`<br/>Valkey maxmemory-policy<br/>|
|**valkey_notify_keyspace_events** `string`<br/>default: `""`<br/>Set notify-keyspace-events option<br/>|
|**valkey_number_of_databases** `long`<br/>min: `1` max: `128`<br/>Set number of Valkey databases. Changing this will cause a restart of the Valkey service.<br/>|
|**valkey_persistence** `string`<br/>values: `off`, `rdb`<br/>Controls whether Valkey writes RDB dumps to disk. With `rdb`, RDB dumps are written for backups on the backup schedule and, if `frequent_snapshots` is enabled, every 10 minutes so the service can recover recent data after a restart. With `off`, no RDB dumps are written at all: backups and forking are unavailable, `frequent_snapshots` and `backup_hour`/`backup_minute` have no effect, and all data is lost if the service restarts or is powered off.<br/>|
|**valkey_pubsub_client_output_buffer_limit** `long`<br/>min: `32` max: `262144`<br/>Set output buffer limit for pub / sub clients in MB. The value is the hard limit, the soft limit is 1/4 of the hard limit. When setting the limit, be mindful of the available memory in the selected service plan.<br/>|
|**valkey_ssl** `boolean`<br/>default: `true`<br/>Require SSL to access Valkey<br/>|
|**valkey_timeout** `long`<br/>min: `0` max: `2073600`<br/>default: `300`<br/>Valkey idle connection timeout in seconds<br/>|
|**valkey_version** `string`<br/>values: `8.1`, `9.1`<br/>Valkey major version<br/>|
