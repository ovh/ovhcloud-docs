## Objective

Public Cloud Databases allow you to focus on building and deploying cloud applications while OVHcloud takes care of the database infrastructure and maintenance in operational conditions.

**This guide explains how to configure your PostgreSQL instance to accept incoming connections.**

## Requirements

- A [Public Cloud project](/links/public-cloud/public-cloud) in your OVHcloud account
- A PostgreSQL database running on your OVHcloud Public Cloud Databases ([this guide](/guides/public-cloud/databases/getting-started) can help you to meet this requirement)

[[cpnav:publiccloud-databases|en]]

## Instructions

### Configure your PostgreSQL instance to accept incoming connections

Before making a connection, we need to verify that our PostgreSQL instance is correctly configured.

In the left-hand menu of your Public Cloud project, click <code className="action">PostgreSQL</code> under **Databases**, then click the name of your PostgreSQL service.

#### Step 1: Verify your user roles and password

Select the <code className="action">Users</code> tab. Verify that you have a user with sufficient rights and a configured password. If you don't remember the user's password, you can either create a new user or regenerate the password of an existing user. Be careful! By doing so you will need to update all the places where you already use this user/password pair.

This first user **avnadmin** comes with the following privileges:

```console
  LOGIN
  NOSUPERUSER
  INHERIT
  CREATEDB
  CREATEROLE
  REPLICATION
```

We rely on official PostgreSQL roles and privileges. You can manage them yourself via CLI or code.
So far, **user grants and privileges management are not supported via the OVHcloud Console or the OVHcloud API**.

See the [Manage users, roles and privileges](/guides/public-cloud/databases/postgresql-users-roles-grants) guide for the scope of the `replication` privilege, the default behaviour of a new user and the usual `GRANT` commands. The [official PostgreSQL documentation](https://www.postgresql.org/docs/current/database-roles.html) describes all available roles.

To reset the **avnadmin** password, click on the <code className="action">...</code> button on the row of the user, then on <code className="action">Reset password</code>.

To create a new user, click on <code className="action">Add a user</code>, fill in the form in the **Add a user** panel, then click on <code className="action">Create</code>.

Once created or updated, the user must have the `READY` status in the OVHcloud Console.

:::warning
Creating a user does not give it access to your data. The user can connect to the database, but has no read or write privileges on your tables until you grant them in SQL.

:::

#### Step 2: Authorise incoming connections from the PostgreSQL client

By default, a Public Cloud Databases service does not accept any connection from the outside world. This helps prevent intrusive connection attempts.

:::warning
As long as no IP address is authorised, your service is unreachable, even though it appears as available in the OVHcloud Console: connection attempts fail, usually with a timeout and no explicit error message on the client side.

:::

Select the <code className="action">Configuration</code> tab, then locate the **IP restrictions** section.

Click <code className="action">Add</code>, enter an IP address or a CIDR block in the **IP block (CIDR)** field and a description to identify its origin, then click <code className="action">Save</code>. In our example, we enter `203.0.113.10/32`.

Two shortcuts are available next to the add button:

- <code className="action">Add my current IP</code>: adds the public IP address from which you are browsing the OVHcloud Console. Convenient for a development workstation, provided your address is static.
- <code className="action">Add OVHcloud Data Platform</code>: adds the addresses required for OVHcloud Data Platform services to reach your database.

:::warning
You can enter `0.0.0.0/0` to allow connections from any address. Your service then becomes reachable from the entire Internet, and only the username/password pair protects your data. Reserve this for tests, and prefer restricted CIDR blocks or the vRack private network for production environments.

:::

:::info
A dynamic IP address changes periodically: if your workstation or outbound gateway does not have a static address, your connections will stop working without any change on your side. In that case, authorise your provider's CIDR block, or use an egress point with a static address.

:::


#### Collect required information

Select the <code className="action">Overview</code> tab to find the connection details in the **Connection details** card: host, port, protocol, connection URI and the CA certificate of the service (<code className="action">Download (.pem)</code>).

Select the <code className="action">Databases</code> tab to get the database name.

Select the <code className="action">Users</code> tab to get the username.
