## Objective

This guide presents two complementary methods for backing up an SNC Cloud Platform instance:

*   **Full system backup**: a snapshot of the system volume is turned into an image, which can be kept, downloaded off-platform for external backup, or used to recreate an identical instance (_clone_).
*   **Application data backup**: a tool such as [Restic](https://restic.readthedocs.io/en/stable/) automates backups of your instance data to Object Storage. The backups can be used to restore your data in the event of a problem.

## Requirements

- An instance
- For the snapshot/clone method: access to the OpenStack console (_Horizon_) or a configured `openstack` CLI (see [Creating an SNC Cloud Platform instance and connecting to it](/guides/hosted-private-cloud/cloud-platform/create-instance) for CLI installation and configuration)
- For the Restic method:
    - An Access Key generated for Object Storage
    - **Restic** installed
    - **S3cmd** installed and configured with the Access Key

## Backup and cloning via a volume snapshot

For reference, a volume is attached to every instance as the system disk.
The operation therefore consists globally of backing up this volume, then creating a new instance from that backup.
In detail, this involves:

*   creating a snapshot of the volume
*   creating a volume from that snapshot
*   uploading this volume as an image
*   cleaning up the previously created volume and snapshot (if they are no longer needed)

An instance can then be created from that image.

These operations cannot be performed from the SNC Regional Panel for now. You must use the OpenStack console (_Horizon_) or the _openstack_ CLI.

### Using the OpenStack console (Horizon)

Log in to the OpenStack console by clicking the "_Open horizon_" button from the OVHcloud Control Panel.

![Open horizon button in the OVHcloud Control Panel](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-17_16-0-1.png)

Go to the _Instances_ menu and click on the instance to back up (the _test_ instance in this example).

![Instances list with the test instance](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_10-32-36.png)

Go to the bottom of the instance details page, in the _Volumes Attached_ section, and click the attached volume.

![Volumes Attached section showing the volume attached to the instance](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_10-33-34.png)

The volume can also be found in the _Volumes_ menu by searching for the volume attached to the instance.

![Volumes menu with the volume attached to the instance](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_10-35-25.png)

Then create a snapshot of the volume:

![Create Snapshot action on the volume](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_15-16-34.png)

Name it and start the snapshot creation.
The operation is almost immediate.

:::warning
Creating a snapshot of a mounted, in-use volume is indeed _crash consistent_, but not _application consistent_.
To guarantee 100% consistency of the backed-up data, it is recommended to stop the instance beforehand.
:::

![Snapshot creation form](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_15-18-40.png)

Go to the _Snapshots_ menu and create a volume from the snapshot.

![Snapshots menu with the create volume action](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_15-20-31.png)

Name it and leave the other values unchanged. Start the volume creation.
The operation is almost immediate.

![Volume creation from snapshot form](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_15-21-35.png)

In this example, the volume will be saved into the images. This can be used, for example, to download the image locally for external backup.

Choose the "_Upload to Image_" action in the volume's list of actions.

![Upload to Image action in the volume actions list](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_15-24-24.png)

Name the image, and keep "_Raw_" as the disk format. Start the upload.

![Upload to image form with Raw disk format](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_15-25-37.png)

The volume switches to the "_Uploading_" status. Depending on the volume size, image creation can take more or less time.
Wait until the image is fully created.

The previously created volume and snapshot can be deleted (the volume first, then the snapshot) if they will not be reused.

To create a new instance from the image, go to the _Images_ menu and click the "_Launch_" action for the image.

![Launch action on the image in the Images menu](/images/hosted-private-cloud/cloud-platform/snc-cloud-platform-save-instance/image-2026-6-26_15-28-49.png)

The instance creation menus are then offered, as described in [Creating an SNC Cloud Platform instance and connecting to it](/guides/hosted-private-cloud/cloud-platform/create-instance).

In summary:

*   in the _Details_ menu, name the instance and choose _nova-vm_ as the "Availability Zone"
*   in the _Source_ menu, click _Yes_ for "Create New Volume" and set the appropriate size
*   choose the flavor in the _Flavor_ menu
*   choose _Ext-Net_ as the network
*   do not choose a keypair, the configuration will not be applied. The instance's `authorized_keys` file will not be modified

then launch the instance creation by clicking "_Launch Instance_" and wait for the instance to reach the "_Running_" state.

At instance startup, _cloud-init_ will detect that the instance has changed and will reinstall the proper network configuration.
Then connect to the instance with its public IP address.

### Using the CLI (_openstack_)

Refer to [Creating an SNC Cloud Platform instance and connecting to it](/guides/hosted-private-cloud/cloud-platform/create-instance) for details on installing and configuring the _openstack_ CLI.

Retrieve the volume attached to the instance:

```bash
$ openstack volume list
+--------------------------------------+------------------+-----------+------+-------------------------------------+
| ID                                   | Name             | Status    | Size | Attached to                         |
+--------------------------------------+------------------+-----------+------+-------------------------------------+
...
| 7b643b08-7e98-4280-81fa-3f96569e8ef1 |                  | in-use    |   20 | Attached to test on /dev/sda        |
...
+--------------------------------------+------------------+-----------+------+-------------------------------------+
```

Create a snapshot of this volume.

:::warning
There is a limitation with the cinder API and the `--force` option: the API version must be forced for the option to be properly taken into account.
:::

```bash
$ OS_VOLUME_API_VERSION=3.71 openstack volume snapshot create --force --volume 7b643b08-7e98-4280-81fa-3f96569e8ef1 test-snapshot
+-------------+--------------------------------------+
| Field       | Value                                |
+-------------+--------------------------------------+
| created_at  | 2026-06-26T15:11:26.201472           |
| description | None                                 |
| id          | aaab4422-de3e-436d-897c-c7ddd0b1cadc |
| name        | test-snapshot                        |
| properties  |                                      |
| size        | 20                                   |
| status      | creating                             |
| volume_id   | 7b643b08-7e98-4280-81fa-3f96569e8ef1 |
+-------------+--------------------------------------+
```

Then create the volume from this snapshot:

```bash
$ openstack volume create --snapshot test-snapshot test-volume
...
```

And create an image from this volume:

```bash
$ openstack image create --volume test-volume test-image
+---------------------+--------------------------------------+
| Field               | Value                                |
+---------------------+--------------------------------------+
| container_format    | bare                                 |
| disk_format         | raw                                  |
| display_description | None                                 |
| id                  | 0092c933-283c-4890-9bca-a445bcaf40fd |
| image_id            | 026968e1-7930-4c3c-a63c-cc3bfac8ac6b |
| image_name          | test-image                           |
| protected           | False                                |
| size                | 20                                   |
| status              | uploading                            |
| updated_at          | 2026-06-26T15:13:01.457308           |
| visibility          | private                              |
| volume_type         | public_standard                      |
+---------------------+--------------------------------------+
```

Wait for the image to become ready (_active_).

```bash
$ openstack image show test-image -f value -c status
active
```

The previously created volume and snapshot can be deleted if they will no longer be used.

```bash
$ openstack volume delete test-volume
$ openstack volume snapshot delete test-snapshot
```

An instance can now be created from this image. Then retrieve its IP address, and once it is ready, connect to it.

```bash
$ openstack server create --flavor b3-8 --image "test-image" --boot-from-volume 20 --network Ext-Net test-restore
...
$ openstack server show test-restore -f value -c status -c addresses
{'Ext-Net': ['xx.xx.xx.xx']}
ACTIVE
$ ssh debian@xx.xx.xx.xx hostname
test-restore
```

## Backing up data with Restic (Object Storage)

:::info
The Restic backup tool is used to describe one possible method for performing backups.
You are free to choose the solution that suits you best.
:::


### Creating a bucket to store the backups

Enter the following command:

```bash
$ s3cmd mb s3://backup
```

### Initialising the backup repository

Start by choosing a password to encrypt your backups. In this guide, GPG is used for this purpose:

```bash
$ gpg --gen-random --armor 1 20
```

Make a note of this password in a safe place, along with your S3<sup>1</sup> credentials. Next, the Restic configuration will be placed in environment variables. This includes sensitive information, such as your S3 secret and the repository password. As a result, make sure that the following commands **do not appear** in your shell history file. Adjust the contents of the environment variables according to your bucket name, the region, and your user's API credentials.

```bash
unset HISTFILE
export AWS_DEFAULT_REGION="eu-west-rbx-snc"
export AWS_ACCESS_KEY_ID="06bd244758d047eea26eb9cc1e572be7"
export AWS_SECRET_ACCESS_KEY="55db67712e594cd8a557abfd7a33a743"
export RESTIC_REPOSITORY="s3:https://s3-beta.eu-west-rbx-snc.cloud.snc.ovh.net/backup"
export RESTIC_PASSWORD="BYhISmzRvIPMwvbzgl8ROQ=="
```

Once the environment is configured, the Restic command can be called to initialise the repository:

```bash
$ restic init
created restic repository 821bcf92bf at s3:https://s3-beta.eu-west-rbx-snc.cloud.snc.ovh.net/backup

Please note that knowledge of your password is required to access
the repository. Losing your password means that your data is
irrecoverably lost.
```

Restic is now ready to be used with S3. Try creating a backup:

```bash
$ restic backup /var/log/
repository 821bcf92 opened (repository version 2) successfully, password is correct
no parent snapshot found, will read all files
error: open /var/log/btmp: permission denied
error: Open: open /var/log/private: permission denied

Files:          30 new,     0 changed,     0 unmodified
Dirs:            7 new,     0 changed,     0 unmodified
Added to the repository: 745.784 MiB (173.112 MiB stored)

processed 30 files, 750.189 MiB in 0:04
snapshot 38e47b16 saved
```

```bash
$ restic snapshots
repository 821bcf92 opened (repository version 2) successfully, password is correct
ID        Time                 Host        Tags        Paths
---------------------------------------------------------------
38e47b16  2025-12-22 00:24:23  demo                  /var/log
---------------------------------------------------------------
1 snapshots
```

:::info
A snapshot has been created.
:::


Check the contents of the bucket:

```bash
$ s3cmd la
                          DIR  s3://backup/data/
                          DIR  s3://backup/index/
                          DIR  s3://backup/keys/
                          DIR  s3://backup/snapshots/
2025-12-22 00:22          155  s3://backup/config
```

:::info
A backup has been created and stored in the S3 bucket.
:::
