## Objective

This documentation describes how to **protect, back up, and restore a Prism Central instance** using the **Point-in-Time Backup** feature to **OVHcloud S3-compatible Object Storage**.

The solution relies on:

- A **secure OVHcloud S3<sup>1</sup> bucket** (Object Lock, versioning, lifecycle).
- An **automated periodic backup** of the Prism Central configuration.
- A **full restoration** possible in case of major incident.

### Overview & Benefits

#### Main features

- Point-in-Time backup of Prism Central to an OVHcloud S3 bucket.
- Automatic creation of **periodic restore points (RPO)**.
- Full restoration from Prism Element.
- Centralized management from **Prism Central**.

#### Benefits

- Strong protection of critical Nutanix management data.
- Backup externalization outside the cluster.
- Data compliance and immutability.
- Simplicity of operation and administration.

## Prerequisites

- **Prism Central** version pc.7.5 or later.
- **Prism Element** must be operational.

## Instructions

### Preparing the environment

#### Creating the Object Storage container (bucket)

To create the container, you must first create a Public Cloud project. Refer to our guide: [Creating your first OVHcloud Public Cloud project](/guides/public-cloud/cross-functional/create-a-public-cloud-project).

{/* CP-STEPS-START:create-object-storage-container */}

Create an object container. In your Public Cloud project, click <code className="action">Object Storage</code> under **Storage** in the left-hand menu, then, on the <code className="action">Containers</code> tab, click <code className="action">Create an object container</code>. If the project has no Object Storage container yet, the OVHcloud Console opens a getting-started page instead: click <code className="action">Create a bucket</code>.

In the **Container type** section, select **S3-compatible API**. In the **Container name** section, specify a name for your container. In the **Deployment mode** section, tick **3-AZ** (for more resilience) or **1-AZ**: these boxes only filter the regions listed below.

Then select the region in the **Region** section. With a 3-AZ region, the form also shows an **Offsite Replication** section, which this guide does not use.

:::warning
Select a region different from that of your cluster.

:::

Enable the following features:

- Enable the **Versioning** switch.
- Then enable the **Object Lock** switch, which is only available once versioning is enabled, and tick the **I understand that Object Lock cannot be disabled later.** box.

In the **Encryption** section, **Server-side encryption (SSE-OMK)** is selected by default. Disable encryption by selecting **No encryption**.

In the **User** section, select an existing user from the list, or create a user: click <code className="action">Create a user</code>, enter a name in the **Name** field of the **Create a user** window, for example *admin-mst-gra*, and click <code className="action">Create</code>.

The window then displays the credentials of the new user: **User**, **Access key** and **Secret key**. Note this information.

Click <code className="action">Create</code> to create the container.

Once the container is created, click its name on the <code className="action">Containers</code> tab and configure the retention: in the **Security** section of the <code className="action">Overview</code> tab, click <code className="action">Edit retention</code> next to **Object Lock**. In the **Object Lock options** panel, select **Apply a default retention**, choose the **Retention mode** (**Governance** or **Compliance**) and set the **Retention period** in days or years. Then click <code className="action">Confirm</code>.

{/* CP-STEPS-END:create-object-storage-container */}

#### Configuring the "bucket lifecycle"

- Expire current objects version after: 31 days.
- Expire previous/noncurrent objects version after: 1 day.
- Delete expired delete markers: 1 day.
- Delete expired failed/incomplete multipart uploads: 1 day.

Install and configure the AWS CLI client, refer to our guide: [Getting Started with Object Storage](/guides/storage-and-backup/object-storage/s3-getting-started-with-object-storage).

Run this command by customizing the variables `BUCKET_NAME`, `ENDPOINT_URL` and `PROFILE`:

```bash
BUCKET_NAME='prism-central-backup'
ENDPOINT_URL='https://s3.rbx.io.cloud.ovh.net/'
PROFILE='rbx'

aws s3api put-bucket-lifecycle-configuration \
  --bucket ${BUCKET_NAME} \
  --lifecycle-configuration '{
    "Rules": [
      {
        "ID": "ExpireCurrentVersions",
        "Status": "Enabled",
        "Expiration": {
          "Days": 31
        },
        "Filter": {}
      },
      {
        "ID": "ExpireNoncurrentVersions",
        "Status": "Enabled",
        "NoncurrentVersionExpiration": {
          "NoncurrentDays": 1
        },
        "Filter": {}
      },
      {
        "ID": "DeleteExpiredDeleteMarkers",
        "Status": "Enabled",
        "Expiration": {
          "ExpiredObjectDeleteMarker": true
        },
        "Filter": {}
      },
      {
        "ID": "AbortIncompleteMultipartUpload",
        "Status": "Enabled",
        "AbortIncompleteMultipartUpload": {
          "DaysAfterInitiation": 1
        },
        "Filter": {}
      }
    ]
  }' \
  --endpoint-url ${ENDPOINT_URL} \
  --profile ${PROFILE}
```

### Procedure – Configuring Prism Central Point-in-Time Backup

#### Accessing the configuration

1\. Log in to the **Prism Central** web console.
2\. From the **Application Switcher**, select the **Infrastructure** application, then click the **Settings** icon.
3\. Click on **Prism Central Settings**, then navigate to **General > Prism Central Backups**.
4\. Click on **Go to Point-in-Time Backup > Protect Now**.

<img className="thumbnail" alt="09 Prism Central Backup" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/83-backup-pc-s3/pc-br9.png" loading="lazy" />

:::info
The system supports **only one Point-in-Time backup target at a time**.

If a Point-in-Time backup is already configured, the **Protect Now** button does not appear.

:::


#### Configuring the backup target

5\. The **Protect Prism Central** window appears and indicates:

- The services whose data is backed up.
- The services not backed up.

For the detailed list, refer to:

- *Supported Services for PCBR*.
- *Unsupported Services for PCBR – Implementation Considerations and Limitations*.

6\. Click on **Continue**, then fill in the following parameters:

- **Endpoint Type**: `Other S3-Compliant Object Store`.
- **IP Address or Host Name (HTTPS Only)**: IP address or hostname of the Object Storage "Endpoint" on the container dashboard (**without https://**).
- **Bucket Name**: Name of the bucket.
- **Access Key**: Access key.
- **Secret Access Key**: Secret key.
- **Restore Point Objects (RPO)**: Frequency of creation of restore points (in hours).

<img className="thumbnail" alt="10 Prism Central Backup" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/83-backup-pc-s3/pc-br10.png" loading="lazy" />

<img className="thumbnail" alt="11 Prism Central Backup" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/83-backup-pc-s3/pc-br11.png" loading="lazy" />

#### Details on RPO

- The **RPO** corresponds to the frequency of creation of restore points.
- The **first restore point is created immediately**.
- Supported values are: `1, 2, 4, 6, 8, 12 or 24 hours`.
- Up to **30 days of restore points** are retained for Prism Central restoration.

7\. Click on **Proceed**.

#### Synchronization and backup status

The system synchronizes Prism Central configuration data to the S3 bucket.

- During synchronization:
    - The displayed status is **Sync in Progress** in the *Prism Central Backups* dashboard.
- Once synchronization is complete:
    - The status changes to **Synced**.
    - The date and time of the last synchronization are displayed.

:::info
The first backup starts immediately after validating the S3 target and lasts **at least 15 minutes**.

:::


- After the first backup:
    - Synchronizations continue automatically
    - Restore points are created according to the configured RPO cycle
