## Objective

**This guide will show you how to interconnect two Nutanix clusters Provided by OVHcloud across the same vRack in two remote OVHcloud sites. In this guide, the connection is made between the Gravelines and Roubaix datacentres.** 

:::warning
OVHcloud provides services for which you are responsible, with regard to their configuration and management. It is therefore your responsibility to ensure that they work properly.

This guide is designed to assist you as much as possible with common tasks. Nevertheless, we recommend contacting a specialist provider if you experience any difficulties or doubts when it comes to managing, using or setting up a service on a server.

:::

## Requirements

- You must be connected to your clusters via Prism Central.

[[cpnav:privatecloud-nutanix-console+network-vrack-console+network-load-balancer-console|en]]

## Instructions

We are going to interconnect two remote Nutanix clusters, one in Gravelines and the other in Roubaix through the same vRack.<br/>
See our [vRack overview](/links/network/vrack) to learn more about the OVHcloud vRack solution.

### Preparing both clusters before interconnection

Before connecting the two clusters, ensure that they use different IP addresses (except for the gateway) on the same IP address range.<br/>
In our guide, we will use the address range `192.168.0.0/22`.

 The Gravelines cluster uses these addresses:

- Server 1: **CVM** VM address `192.168.2.1`, **AHV** hypervisor IP address `192.168.2.21`.
- Server 2: **CVM** VM address `192.168.2.2`, **AHV** hypervisor IP address `192.168.2.22`.
- Server 3: **CVM** VM address '192.168.2.3', **AHV** hypervisor IP address `192.168.2.23`.
- Virtual address of **Prism Element**: `192.168.2.100`.
- **Prism Central** IP address:`192.168.2.101`.
- Gateway: `192.168.2.254`.
- Cluster version: `6.1`.

The Roubaix cluster uses these addresses:

- Server 1: **CVM** VM address `192.168.1.1`, **AHV** hypervisor IP address `192.168.1.21`.
- Server 2: **CVM** VM address `192.168.1.2`, **AHV** hypervisor IP address `192.168.1.22`.
- Server 3: **CVM** VM address `192.168.1.3`, **AHV** hypervisor IP address `192.168.1.23`.
- Virtual address of **Prism Element**: `192.168.1.100`.
- **Prism Central** IP address:`192.168.1.101`.
- Gateway: `192.168.2.254`.
- Cluster version: `6.1`.

Use our guide on [customised redeployment of your Cluster](/guides/hosted-private-cloud/nutanix-on-ovhcloud/cluster-custom-redeployment).

:::info
The guide mentioned above will help you redeploy both clusters. However, you can only redeploy one, the most important thing is not to have the same identical IP addresses across the network, except for the OVHgateway.

:::


### Shutting down the OVHgateway virtual machine.

The outgoing internet connection is provided by OVHgateway virtual machines with the same private IP address on both sites. We will stop the OVHcloud Virtual Machine Gateway in Roubaix. This virtual machine will no longer be needed.

The outgoing internet connection will be restored when the connection through the **vRack** is made.

Log in to the cluster **Prism Central** interface located in Roubaix. 

Go to the virtual machine management section, select `OVHgateway` from the <code className="action">Actions</code> menu and click <code className="action">Guest Shutdown</code>.

<img className="thumbnail" alt="01 OVHgateway Shutdown 01" src="/images/hosted-private-cloud/nutanix-on-ovhcloud/45-vrack-interconnection/01-ovhgateway-shutdown01.png" loading="lazy" />

Access to Prism Central is maintained using the Load Balancer.

### Configuring vRacks

{/* CP-STEPS-START:configuring-vracks */}

This operation involves deleting the vRack assignment in Roubaix and then extending the vRack from Gravelines to Roubaix. You can modify the vRack in the OVHcloud Console.

{/* CP-STEPS-END:configuring-vracks */}
#### Deleting Roubaix vRack elements.

{/* CP-STEPS-START:delete-roubaix-vrack-elements */}

Select the Roubaix cluster in the `Nutanix` category. On its <code className="action">Overview</code> tab, note the name of the vRack shown in the **vRack** row of the **Network** section.

In the side menu, open **Network**, click <code className="action">vRack</code>, then click the vRack concerned and open its <code className="action">Attached services</code> tab. The table lists all the elements that are in your vRack:

 - Dedicated servers
 - IPs
 - the Load Balancer

 Write them down. The services are detached one at a time: on the row of each service, click <code className="action">Detach</code>, then confirm in the window that opens. Repeat this for every service.

:::warning
This operation may take a few minutes, please wait during this period.

:::

{/* CP-STEPS-END:delete-roubaix-vrack-elements */}
### Adding deleted items from the Roubaix vRack into the Gravelines vRack

{/* CP-STEPS-START:add-roubaix-elements-to-gravelines-vrack */}

Choose the Gravelines cluster from the `Nutanix` category and, on its <code className="action">Overview</code> tab, note the name of the vRack in the **vRack** row of the **Network** section.

In the side menu, open **Network**, click <code className="action">vRack</code>, then select the Gravelines vRack. Click the <code className="action">Attached services</code> tab, then <code className="action">Attach a service</code>. The **Eligible services** page opens.

Attach these elements from the Roubaix cluster:

- Physical servers
- the public IP.

In the **Service type** drop-down list, select **Dedicated Servers**, then click <code className="action">Attach</code> on the row of each physical server. Then select **Additional IPv4 blocks** and click <code className="action">Attach</code> on the row of the public IP block.

:::warning
This operation may take a few minutes, please wait during this period.

:::


:::info
Adding the public address is not mandatory but it will make it available for future needs.

:::

The **vRack** that was only used by the servers in the Gravelines cluster is now used on both sites and contains:

- The physical servers of the two clusters.
- The public IP addresses of the two clusters.
- The Gravelines Load Balancer, used for Prism Central.

Outgoing Internet access on the Roubaix site is again available through the vRack and the OVHgateway virtual machine in Gravelines. Access to Prism Central for the Roubaix cluster is currently inaccessible.

{/* CP-STEPS-END:add-roubaix-elements-to-gravelines-vrack */}
### Modifying the Roubaix Load Balancer

We will reconfigure the Roubaix Load Balancer to work with the vRack shared by both sites, so that it can access Prism Central for the Roubaix cluster.

{/* CP-STEPS-START:modify-roubaix-load-balancer */}

In the side menu, open **Network**, click <code className="action">Load Balancer</code>, then select the Roubaix Load Balancer.

Go to the <code className="action">Network</code> tab. Since the Roubaix Load Balancer was detached from its vRack in the previous section, its former private network no longer exists: detaching the vRack removes all the private network configurations of the Load Balancer.

In the **vRack** section, click <code className="action">Attach a vRack</code>. In the **Attach a vRack** window, select the vRack that is common to both sites, and click <code className="action">Attach</code>.

In the **Private Networks** section, click <code className="action">Add Private Network</code>. The **Add Private Network** page opens.

Choose these values:

- **Display name** (optional): Private network name.
- **VLAN**: Nutanix management network VLAN, normally 1.
- **Subnet (CIDR)**: Private network LAN 192.168.0.0/22.
- **NAT IP**: Address range used by the Load Balancer 192.168.2.128/27.

:::warning
The range chosen for **NAT IP** should not be used by other elements of the private network, particularly the range taken by the Gravelines Load Balancer.

:::

Then click <code className="action">Add Private Network</code>.

Link the server farm to this private network: go to the <code className="action">Server farms</code> tab, open the <code className="action">⋮</code> menu of the `NutaCluster-all` farm and click <code className="action">Edit</code>. On the **Edit Server Farm** page, select the new network in the **Private Network** field, then click <code className="action">Save Changes</code>.

Your changes are pending until you apply them. Go to the <code className="action">Overview</code> tab and, in the **General information** section, under **Deployment**, click <code className="action">Apply N changes</code>, where N is the number of pending changes. A single click applies the configuration to every zone of your Load Balancer.

The Load Balancer is connected to the vRack shared by both sites, and access to Prism Central for the Roubaix cluster is then available.

{/* CP-STEPS-END:modify-roubaix-load-balancer */}
