## Objective

**This guide shows IT Admins how to use the OPCP Admin Console to create Organizations, deploy services from the Service Catalog and enable them for Organizations.**

The **OPCP Admin Console** is the Cloud Store interface for IT Admins. For an overview of Cloud Store and its concepts, read our guide [Getting started with Cloud Store](/guides/hosted-private-cloud/opcp/cloudstore-getting-started).

## Requirements

- The **URL** of the OPCP Admin Console and your login credentials, provided during service delivery. These credentials are managed in the OPCP Admin Console Keycloak.
- Bare-metal hosts enrolled in OPCP Core and assigned to OpenStack projects, with available hosts for the services you plan to deploy.

## Instructions

### Logging in to the OPCP Admin Console

Navigate to the **URL** of the OPCP Admin Console and click <code className="action">Log in</code>.

<img className="thumbnail" alt="OPCP Admin Console login page" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/admin_console_login.png" loading="lazy" />

You are redirected to the **Keycloak** authentication page. You have two options to authenticate:

- Enter your credentials directly in the Keycloak login form.
- Use the <code className="action">OPCP-SSO</code> button to authenticate through the federated OPCP Core Keycloak. This option allows users already registered in OPCP Core to log in without managing a separate set of credentials. It is required to manage Host Pools, as the user is then identified against OpenStack.

<img className="thumbnail" alt="OPCP Admin Console Keycloak login form" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/admin_console_keycloak_login.png" loading="lazy" />

Once authenticated, you land on the home page of the OPCP Admin Console.

<img className="thumbnail" alt="OPCP Admin Console home page" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/admin_console_home.png" loading="lazy" />

The side bar gives access to the following areas:

| Section | Content |
|---------|---------|
| **Services** | Each deployed service, as a shortcut to its Service Deployments. |
| **Management** | <code className="action">Organizations</code>, <code className="action">Service Catalog</code> and <code className="action">Deployments</code>. |
| **External links** | <code className="action">OPCP Dashboard</code>, to reach the OPCP Core tools. |

### Creating an Organization

An **Organization** is an isolated environment, for example a company, a department or a team. Create it before enabling services for it.

1. Go to <code className="action">Management</code> > <code className="action">Organizations</code>. The list shows each Organization with its admin and status. The icons of the `Actions` column open the OPCP Cloud Console of the Organization and its Keycloak administration console.

    <img className="thumbnail" alt="List of Organizations" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/organizations.png" loading="lazy" />

2. Click <code className="action">Create a new organization</code>.
3. Enter the **Organization name**, for example `dpt-real-estate`.
4. Enter the **Organization Admin**: email, first name and last name.

    <img className="thumbnail" alt="Organization creation form" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/organization_creation_form.png" loading="lazy" />

5. Click <code className="action">Create</code>. The Organization is `pending`, then `active`.

The platform automatically:

- creates a dedicated Keycloak realm named `account-{name}`;
- creates the Organization Admin user. Their login is their email address;
- sets a first-login default password, defined when Cloud Store was installed. The Organization Admin must change it at first login.

:::warning
No email is sent to the Organization Admin. Once the Organization is `active`, send them their credentials yourself, as described in the [Handing over to the Organization](#handing-over-to-the-organization) section below.
:::

### Deploying a service

A **Service Deployment** runs a service on bare-metal hosts that you allocate into **Host Pools**. It is deployed once, and you can then enable it for as many Organizations as needed.

1. Go to <code className="action">Management</code> > <code className="action">Service Catalog</code>. The catalog shows the services available on your platform, their latest version and whether they are deployed.

    <img className="thumbnail" alt="Service Catalog" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/service_catalog.png" loading="lazy" />

2. Open a service. The page lists its existing Service Deployments. Click <code className="action">New deployment</code>.

    <img className="thumbnail" alt="Service Deployments of a service" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/service_deployments.png" loading="lazy" />

3. **Choose the version of your service**, then click <code className="action">Next</code>.

    <img className="thumbnail" alt="Choosing the service version" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/deploy_version.png" loading="lazy" />

4. **Allocate the host pools**. For each Host Pool required by the service, for example `controllers` for the Control Plane and `computes` for the Data Plane, select the OpenStack project and the hosts to use. The prerequisites of the service (number and type of hosts) are displayed above the list.

    <img className="thumbnail" alt="Allocating the Host Pools" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/deploy_host_pools.png" loading="lazy" />

5. **Configure your service** with the properties defined by the service.
6. Click <code className="action">Deploy</code>.

:::info
Only hosts available in OpenStack are listed. The selected hosts are wiped and reinstalled during the deployment.
:::

Service deployment is **asynchronous**: the console confirms that the deployment has started, and provisioning runs in the background through Kubernetes and OpenTofu.

### Following a Service Deployment

All Service Deployments are collected in <code className="action">Management</code> > <code className="action">Deployments</code>. They also appear under the service name in the side bar.

The page of a Service Deployment shows its version, its status and the following tabs:

<img className="thumbnail" alt="Service Deployment page" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/deployment_detail.png" loading="lazy" />

| Tab | Content |
|-----|---------|
| **Enabled services** | The Organizations this Service Deployment is enabled for. <code className="action">Enable a service</code> enables it for another Organization. |
| **Host pools** | The hosts of each Host Pool: name, management IP, manufacturer, model, CPU, RAM and disk. |
| **Outputs** | Endpoints and files produced by the service. |
| **Settings** | The configuration chosen at deployment. |

<img className="thumbnail" alt="Host Pools of a Service Deployment" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/deployment_host_pools.png" loading="lazy" />

#### Scaling capacity

To add hosts to a Service Deployment, open its <code className="action">⋮</code> menu and choose <code className="action">Expand capacity</code>. Select available hosts from its OpenStack project, then confirm. The same action exists on Enabled Services that have a dedicated Host Pool.

Scaling is asynchronous: Kubernetes reconciles the configuration and provisions the new hosts.

### Enabling a service for an Organization

Enabling a Service Deployment for an Organization creates an **Enabled Service**. It makes the service visible in the OPCP Cloud Console of the Organization, and the platform creates the necessary Keycloak resources (client, roles and groups) in the Organization's realm, so that only the users of that Organization can access the service.

The Service Deployment must be `deployed` and the Organization must exist.

1. Open the Service Deployment, tab <code className="action">Enabled services</code>, and click <code className="action">Enable a service</code>. You can also start from the page of an Organization.
2. **Name your enabled service** and select the **Organization**. If you do not enter a name, the technical ID is used.

    <img className="thumbnail" alt="Enabling a service for an Organization" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/enable_service_form.png" loading="lazy" />

3. **Allocate the host pool** when the service needs a dedicated Data Plane for the Organization. For services whose Data Plane is shared between Organizations, this step is marked `not applicable`.
4. **Configure your enabled service** with the properties defined by the service.
5. Confirm. The Enabled Service is deploying, then `deployed`.

The page of an Organization lists its Enabled Services, with their Service Deployment and service type.

<img className="thumbnail" alt="Organization page" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/organization_detail.png" loading="lazy" />

### Handing over to the Organization

Once the Enabled Service is deployed, the Organization's users find it in the OPCP Cloud Console. From the Organization page, you can open the Enabled Service: its `Outputs` tab shows the technical data of its deployment. Services can add their own tabs, such as `Compute`.

<img className="thumbnail" alt="Outputs of an Enabled Service" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/enabled_service_outputs.png" loading="lazy" />

Then send the Organization Admin:

- the **OPCP Cloud Console URL**: in <code className="action">Management</code> > <code className="action">Organizations</code>, the house icon opens it with the Organization already selected;
- their **login**: the email address entered when creating the Organization;
- the **first-login default password** defined at Cloud Store installation.

:::warning
The first-login default password is shared and defined at installation. The Organization Admin must change it at their first login.
:::

The Organization Admin can then follow our guide [OPCP Cloud Console](/guides/hosted-private-cloud/opcp/cloud-console-getting-started).

### Managing IAM on the OPCP Admin Console Keycloak

To manage users, roles and groups on the OPCP Admin Console Keycloak, first assign the `cloudstore-admins` role to your user in the **OPCP Core Keycloak**.

1. Log in to the OPCP Core Keycloak administration console.
2. Navigate to the user you want to grant IAM management rights to.
3. In the <code className="action">Role mappings</code> tab, assign the `cloudstore-admins` client role.

<img className="thumbnail" alt="Assigning the cloudstore-admins role in OPCP Core Keycloak" src="/images/hosted-private-cloud/opcp/admin-console-getting-started/opcp_keycloak_cloud_store_admins_role.png" loading="lazy" />

Once this role is assigned, the user has the permissions needed to administer the OPCP Admin Console Keycloak, including managing realms, clients, users and roles.
