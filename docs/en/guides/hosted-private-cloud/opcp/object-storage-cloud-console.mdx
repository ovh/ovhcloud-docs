## Objective

**This guide shows Organization users how to get S3<sup>1</sup> access keys, create buckets and upload objects with the Object Storage service, in its web interface and with the S3 API.**

## Requirements

- Access to the OPCP Cloud Console, as described in the guide [OPCP Cloud Console](/guides/hosted-private-cloud/opcp/cloud-console-getting-started).
- The **Object Storage** service enabled for your Organization by your IT Admin, as described in the guide [Deploying Object Storage](/guides/hosted-private-cloud/opcp/object-storage-admin-console).
- To use the S3 API: an S3 client, for example the [AWS CLI](https://aws.amazon.com/cli/), [S3cmd](https://s3tools.org/s3cmd) or [Cyberduck](https://cyberduck.io/).

## Instructions

### What the service offers in the Alpha

| Resource | What you can do |
|----------|-----------------|
| **Access keys** | Create S3 access keys and revoke them. The secret of a key is shown only once, when you create it. |
| **Buckets** | Create and delete buckets. Turn on versioning, set lifecycle rules that delete old objects, publish a bucket as a static website. |
| **Objects** | Upload files and folders, create folders, download, copy, move, rename and delete objects. Set their content type and cache headers. Share an object with a temporary signed URL. Restore an older version of an object. |

You manage these resources in the web interface of the service, or with any S3 client.

### Opening the service

In the sidebar of the OPCP Cloud Console, open the service. It appears under the name your IT Admin gave it when enabling it for your Organization.

The <code className="action">Console</code> link in the header of the service, also shown in its <code className="action">Overview</code> tab, opens the web interface of Object Storage in a new browser tab. This guide describes this interface.

<img className="thumbnail" alt="Object Storage service in the OPCP Cloud Console, with the Console link in its header" src="/images/hosted-private-cloud/opcp/object-storage-cloud-console/service_console_link.png" loading="lazy" />

The web interface has three tabs:

| Tab | Content |
|-----|---------|
| <code className="action">Buckets</code> | Your buckets and their objects. |
| <code className="action">Connect</code> | The S3 endpoint, and how to set up the Cyberduck and S3cmd clients. |
| <code className="action">Access Keys</code> | Your S3 access keys. |

<img className="thumbnail" alt="Buckets tab of the Object Storage web interface, with the S3 endpoint and the list of buckets" src="/images/hosted-private-cloud/opcp/object-storage-cloud-console/bucket_list.png" loading="lazy" />

### Getting S3 access keys

An access key is a pair of an **access key** and a **secret key**. S3 clients use it to authenticate.

1. Open the <code className="action">Access Keys</code> tab and click <code className="action">Request new Access Key</code>.
2. Optionally, give the key a name that tells where you use it.
3. Click <code className="action">Request new Access Key</code>.
4. Copy the **Access Key** and the **Secret Key**, then click <code className="action">Copy Secret & Close</code>.

:::warning
The secret key is shown only once and cannot be retrieved afterwards. Store it in a safe place. If you lose it, revoke the key and create a new one.

:::

To revoke a key, open its menu in the list of access keys and choose to revoke it. Applications that use it can no longer access your buckets.

Every access key gives full access to all buckets of your Organization.

<img className="thumbnail" alt="Access Keys tab of the Object Storage web interface, with the list of access keys" src="/images/hosted-private-cloud/opcp/object-storage-cloud-console/access_keys.png" loading="lazy" />

### Connection details

S3 clients need three values:

| Value | Where to find it |
|-------|------------------|
| **Endpoint** | The <code className="action">Connect</code> tab, or the top of the <code className="action">Buckets</code> tab, for example `https://s3.object-storage-<id>.<your domain>`. |
| **Region** | `opcp-s3`. |
| **Access key and secret key** | See [Getting S3 access keys](#getting-s3-access-keys). |

Both URL styles work: `https://<endpoint>/<bucket>` and `https://<bucket>.<endpoint>`.

### Creating a bucket and uploading objects in the web interface

1. Open the <code className="action">Buckets</code> tab and click <code className="action">Create bucket</code>.
2. Enter a **Bucket name**. Use only lowercase letters, numbers, periods or dashes. Bucket names are unique across the whole platform, so your choice may already be taken.
3. Click <code className="action">Create bucket</code>.
4. Open the bucket. Drag and drop files into it, or use <code className="action">Upload files</code> or <code className="action">Upload folders</code>. Use <code className="action">Create folder</code> to organise your objects.

<img className="thumbnail" alt="Objects of a bucket in the Object Storage web interface, with the upload buttons" src="/images/hosted-private-cloud/opcp/object-storage-cloud-console/object_list.png" loading="lazy" />

In the bucket, the menu of each object lets you download, copy, move, rename or delete it, change its settings, or create a <code className="action">Signed URL</code>: a temporary link, valid from 5 minutes to 1 week, that gives access to the object without credentials.

### Creating a bucket and uploading objects with the S3 API

The examples below use the AWS CLI.

1\. **Configure the AWS CLI** with your access key:

```bash
aws configure --profile opcp
# AWS Access Key ID: <access key>
# AWS Secret Access Key: <secret key>
# Default region name: opcp-s3
# Default output format: json
```

2\. **Create a bucket and upload an object:**

```bash
ENDPOINT=https://s3.object-storage-<id>.<your domain>
aws --profile opcp --endpoint-url "$ENDPOINT" s3 mb s3://my-bucket
aws --profile opcp --endpoint-url "$ENDPOINT" s3 cp ./report.pdf s3://my-bucket/
aws --profile opcp --endpoint-url "$ENDPOINT" s3 ls s3://my-bucket/
```

If your platform uses its own certificate authority, add `--ca-bundle <file with the certificate of the authority>` to each command. Your IT Admin can give you that certificate.

The <code className="action">Connect</code> tab describes how to set up Cyberduck and S3cmd with the same values.

### Bucket settings

Open a bucket and choose <code className="action">Settings</code> to change its settings:

| Setting | What it does |
|---------|--------------|
| **Bucket Versioning** | Keeps the older versions of each object when it is changed or deleted. You can restore an older version, or delete it. |
| **Bucket Lifecycle configuration** | Rules that delete objects after a number of days, optionally only those whose name starts with a prefix. They can also delete the older versions of objects and incomplete uploads. With versioning on, deleted objects first go to the <code className="action">Lifecycle Bin</code>, where you can restore them or delete them for good. |
| **Static Website Hosting** | Publishes the bucket as a website, with an index document and an error document. |

<img className="thumbnail" alt="Settings of a bucket: static website hosting, versioning and lifecycle rules" src="/images/hosted-private-cloud/opcp/object-storage-cloud-console/bucket_settings.png" loading="lazy" />

:::warning
**Static Website Hosting** makes all current and future objects of the bucket publicly accessible to anyone who can reach the platform, without credentials.

:::

### Which S3 features work in the Alpha

The service is built on Ceph RGW, which supports most of the S3 API. The web interface of the service relies on the following features:

- Creating, listing and deleting buckets and objects, multipart uploads.
- Bucket versioning and lifecycle rules.
- Static website hosting.
- Presigned URLs.

For the differences between Object Storage on OPCP and in OVHcloud regions, see [Object Storage features and specifications on OPCP](/guides/hosted-private-cloud/opcp/s3-opcp-limitations).

### Known limitations

The Alpha has the following known limitations:

| What you notice | What to do |
|-----------------|------------|
| Every access key gives full access to all buckets of the Organization. There are no per-user or per-bucket permissions. | Treat each access key as a key to all your data. Revoke keys you no longer use. |
| A bucket name is refused as already taken. | Bucket names are unique across the platform: choose another name. |
| The capacity of the service is limited, and its data can be lost when the service is upgraded. | Do not store data you need to keep in the Alpha. |

The following features are not available in the Alpha:

- Encryption of objects with keys managed by the platform (SSE-S3, SSE-KMS).
- Quotas and usage reporting per Organization.
- Access policies per user.
