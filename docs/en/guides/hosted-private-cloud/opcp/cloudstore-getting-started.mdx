## Objective

**This guide shows you how to log in to the OPCP Admin Console, understand its key concepts, and perform initial operations such as creating Organizations, deploying services and enabling them for Organizations.**

The **OPCP Admin Console** (formerly CloudStore) is the central management interface for IT Admins, deployed on top of [On-Premise Cloud Platform (**OPCP**)](/guides/hosted-private-cloud/opcp/getting-started). It is used to manage Organizations, deploy services, and control access across the platform, so that IT Admins can offer cloud-native services to their customers from a marketplace-based Catalog.

## Requirements

- The **URL** of your OPCP Admin Console, provided during service delivery.
- Login credentials (username and password) provided during service delivery. These credentials are managed through **Keycloak**, the identity and access management solution used by the platform.

## Instructions

### Logging in to the OPCP Admin Console

Navigate to the **URL** provided for your OPCP Admin Console. You will be presented with a login page.

<img className="thumbnail" alt="OPCP Admin Console login page" src="/images/hosted-private-cloud/opcp/cloudstore-getting-started/cloudstore_login.png" loading="lazy" />

Click the login button to be redirected to the **Keycloak** authentication page. You have two options to authenticate:

- Enter your credentials directly in the Keycloak login form.
- Use the <code className="action">OPCP-SSO</code> button to authenticate through the federated OPCP Core Keycloak. This option allows users already registered in OPCP Core to log in without managing a separate set of credentials.

<img className="thumbnail" alt="OPCP Admin Console Keycloak login form" src="/images/hosted-private-cloud/opcp/cloudstore-getting-started/keycloak_l2_login.png" loading="lazy" />

Once authenticated, the interface obtains an OIDC access token that is used for all subsequent operations.

### OPCP Admin Console dashboard

After logging in, you will be redirected to the OPCP Admin Console dashboard.

<img className="thumbnail" alt="OPCP Admin Console dashboard" src="/images/hosted-private-cloud/opcp/cloudstore-getting-started/cloudstore_dashboard.png" loading="lazy" />

From the dashboard, you can access the following key areas:

- **Catalog**: Browse the services available on the platform (e.g., VCF) and deploy them onto the infrastructure.
- **Deployments**: Monitor the Service Deployments running on the infrastructure and enable them for Organizations.
- **Organizations**: Create and manage the isolated environments of your customers or internal teams.
- **IAM management**: Configure users and permissions within Keycloak.

### Key concepts

Before using the OPCP Admin Console, it is important to understand its main concepts.

#### Roles

The platform distinguishes between two interfaces, each with its own audience:

- The **OPCP Admin Console** is used by **IT Admins**, who operate the platform: they deploy services onto the infrastructure, enable them for Organizations, and create and manage Organizations.
- The **OPCP Cloud Console** (formerly Landing Zone Manager) is the self-service interface used by **Organization Admins** and **Organization Users**, who consume the services enabled for their Organization.

| Role | Responsibilities |
|------|------------------|
| IT Admin | Create Organizations, deploy services, enable services for Organizations |
| Service Packager | Build, maintain and publish services to the Catalog, define their versions and descriptions |
| Organization Admin | Manage an Organization: users, User Groups, identity provider, Projects and access |
| Organization User | Create and consume Cloud Resources in the Projects they are assigned to |

#### Service Deployments and Enabled Services

Each service published in the Catalog is used in two stages:

- A **Service Deployment** is an instance of the service deployed onto the infrastructure, with a specific version and allocated hardware. It runs the **Control Plane** of the service, which manages its lifecycle and handles cross-Organization orchestration. A single Service Deployment can be enabled for multiple Organizations.
- An **Enabled Service** is a Service Deployment activated for a specific Organization. It makes the service visible in that Organization's OPCP Cloud Console. Enabling a service grants access only: no Cloud Resource is created at this point, except for services that cannot be shared between Organizations, which get a dedicated **Data Plane** for each Organization.

This model allows IT Admins to offer the same service to multiple customers, each Organization keeping its own isolated access while sharing the same Service Deployment.

### Creating an Organization

An **Organization** is an isolated customer environment — for example a company or a department — with its own OPCP Cloud Console, users, Projects and Enabled Services. Each Organization gets its own Keycloak realm, providing complete IAM isolation. Organizations must be created before services can be enabled for them.

To create an Organization:

1. From the OPCP Admin Console dashboard, navigate to the <code className="action">Organizations</code> section.
2. Click on <code className="action">Create Organization</code>.
3. Fill in the required fields: Organization name, Organization Admin full name, and Organization Admin email address.

    <img className="thumbnail" alt="Organization creation form" src="/images/hosted-private-cloud/opcp/cloudstore-getting-started/account_creation_form.png" loading="lazy" />

4. Submit the form.

The platform automatically:

- Creates a dedicated Keycloak realm named `account-{name}`.
- Creates an Organization Admin user with the `account-admin` role.
- Sets up a temporary password (the Organization Admin will be prompted to change it on first login).
- Configures a `landing-zone` client for OPCP Cloud Console access.

### Deploying and enabling a service

Making a service available to an Organization is a two-step process: first **deploy** the service onto the infrastructure, then **enable** the Service Deployment for one or more Organizations.

#### Step 1 — Deploy a service

1. Navigate to the <code className="action">Catalog</code> from the dashboard.

    <img className="thumbnail" alt="Catalog" src="/images/hosted-private-cloud/opcp/cloudstore-getting-started/service_catalog.png" loading="lazy" />

2. Select the service you want to deploy.
3. Click <code className="action">Deploy</code>.
4. Choose the version and configure the required properties.
5. Select the Hosts Pool on which the service will be deployed.
6. Submit the form.

:::info
Service deployment is **asynchronous**. The interface will confirm that the deployment has started, but provisioning happens in the background through Kubernetes and Terraform. You can monitor the deployment status from the <code className="action">Deployments</code> section.
:::


#### Step 2 — Enable the service for an Organization

Once the Service Deployment is active and at least one Organization exists:

1. Navigate to the Service Deployment detail view in the <code className="action">Deployments</code> section.
2. Click <code className="action">Enable</code>.
3. Select the target Organization.
4. Configure the required properties, if any.
5. For services that require a dedicated Data Plane, select the Hosts Pool reserved for the Organization.
6. Submit the form.

When a service is enabled, the platform automatically creates the necessary Keycloak resources (client-id, roles, and groups) in the target Organization’s realm, ensuring that only authorised users of that Organization can access the service.

:::info
Like service deployment, enabling a service is **asynchronous**. Any infrastructure provisioning is handled by Kubernetes and Terraform in the background.
:::


### Scaling capacity

You can add or remove hosts from a Service Deployment or a dedicated Data Plane to adjust capacity.

1. Navigate to the Service Deployment or Enabled Service page.
2. Click <code className="action">Expand capacity</code>.
3. Select the hosts to add.
4. Submit the form.

The scaling operation is asynchronous. Kubernetes reconciles the configuration and provisions resources on the updated hosts.

### Authentication and Security Zones

The platform separates authentication into two **Security Zones**, each backed by its own Keycloak instances:

| Security Zone | Keycloak instance | Users | Purpose |
|---------------|-------------------|-------|---------|
| Admin Security Zone | OPCP Core Keycloak | DC operators, Super admins | Infrastructure-level identity |
| Admin Security Zone | OPCP Admin Console Keycloak | IT Admins, Service Packagers | Platform management |
| Public Security Zone | Per-Organization Keycloak realms | Organization Admins, Organization Users | Service access |

- Within the **Admin Security Zone**, the OPCP Admin Console Keycloak is federated with the OPCP Core Keycloak. This means rights granted on OpenStack projects in OPCP Core are carried through to the OPCP Admin Console.
- The **Public Security Zone** relies on an independent Keycloak instance managed by the OPCP Admin Console API. Each Organization gets its own isolated realm.

:::info
The **Public Security Zone** is provided by the [OPCP Cloud Console](/guides/hosted-private-cloud/opcp/landing-zone-manager-create-user-account), a separate OPCP product responsible for managing Organization user accounts. Its Keycloak stack is **not federated** with the Admin Security Zone Keycloak instances (OPCP Core and OPCP Admin Console).
:::

#### Managing IAM on the OPCP Admin Console Keycloak

To be able to manage users, roles, and groups on the OPCP Admin Console Keycloak, first assign the `cloudstore-admins` role to your user in the **OPCP Core Keycloak**.

1. Log in to the OPCP Core Keycloak administration console.
2. Navigate to the user you want to grant IAM management rights to.
3. In the <code className="action">Role mappings</code> tab, assign the `cloudstore-admins` client role.

<img className="thumbnail" alt="Assigning the cloudstore-admins role in OPCP Core Keycloak" src="/images/hosted-private-cloud/opcp/cloudstore-getting-started/opcp_keycloak_cloudstore_admins_role.png" loading="lazy" />

Once this role is assigned, the user will have the necessary permissions to administer the OPCP Admin Console Keycloak, including managing realms, clients, users, and roles.

### The OPCP Cloud Console

The **OPCP Cloud Console** is the self-service interface for Organization Admins and Organization Users. It shows the Enabled Services of their Organization.

Organization Admins invite and remove users, configure User Groups, connect the company identity provider (SSO), create Projects, and assign users or User Groups to Projects with a role: **Project Writer** (full access) or **Project Reader** (view only). Organization Users then open their Projects and create Cloud Resources, such as virtual machines, volumes or databases.

Users authenticate through their Organization-specific Keycloak realm (Public Security Zone) and can only access the services enabled for their Organization. The OPCP Cloud Console retrieves the list of Enabled Services and filters them based on user permissions.
