## Objective

**This guide introduces Cloud Store, its two consoles and the concepts you need before you start using it.**

**Cloud Store** is the management platform of [On-Premise Cloud Platform (**OPCP**)](/guides/hosted-private-cloud/opcp/getting-started). It runs on top of OPCP Core and the OPCP hardware, and lets you deploy cloud services on your bare-metal hosts and make them available to the companies, departments or teams that use them.

## Requirements

- An OPCP platform with Cloud Store, delivered by OVHcloud.
- The **URL** of the OPCP Admin Console and your login credentials, provided during service delivery.

## Instructions

### The two Cloud Store consoles

Cloud Store has two interfaces, one per audience:

| Console | For | Purpose |
|---------|-----|---------|
| **OPCP Admin Console** | IT Admins | Create Organizations, deploy services from the Service Catalog and enable them for Organizations. |
| **OPCP Cloud Console** | Organization Admins and Organization Users | Use the services enabled for the Organization and create Cloud Resources, such as virtual machines, volumes or buckets. |

Each console has its own guide:

- [OPCP Admin Console](/guides/hosted-private-cloud/opcp/admin-console-getting-started)
- [OPCP Cloud Console](/guides/hosted-private-cloud/opcp/cloud-console-getting-started)

### Roles

| Role | Console | Responsibilities |
|------|---------|------------------|
| IT Admin | OPCP Admin Console | Creates Organizations, deploys services and enables them for Organizations. |
| Service Packager | — | Builds, maintains and publishes services to the Service Catalog, and defines their versions and descriptions. |
| Organization Admin | OPCP Cloud Console | Created with the Organization. Manages the users of the Organization. |
| Organization User | OPCP Cloud Console | Uses the services enabled for the Organization and creates Cloud Resources. |

### Key concepts

#### Organization

An **Organization** is an isolated environment in which a group of users consumes the services enabled for it. It usually represents a company, a department or a team. Each Organization gets its own Keycloak realm, which isolates its identities from the other Organizations.

#### Service Catalog and Service Deployments

The **Service Catalog** lists the services available on your platform, for example Compute and Block Storage or Object Storage. From the catalog, the IT Admin deploys a chosen version of a service onto the infrastructure. The result is a **Service Deployment**. All Service Deployments are collected in the <code className="action">Deployments</code> section of the OPCP Admin Console.

A service can have several Service Deployments, for example one per region or data centre.

#### Host Pools, Control Plane and Data Planes

When deploying a service, the IT Admin allocates bare-metal hosts into **Host Pools**. A Host Pool is a group of hosts that serves one role of the Service Deployment:

- the **Control Plane**, which manages the service and its lifecycle;
- one or more **Data Planes**, which run the workloads and Cloud Resources of the Organizations;
- or both roles together, in a single converged pool, as with Ceph-style storage services.

To scale the Control Plane or a Data Plane, add hosts to the corresponding Host Pool.

#### Enabled Services

An **Enabled Service** is a Service Deployment enabled for one Organization. It makes the service visible in that Organization's OPCP Cloud Console, and the Organization is assigned to one or more Data Planes of the Service Deployment. Depending on the service, a Data Plane is shared by several Organizations or dedicated to a single one: services that cannot be shared get a dedicated Host Pool for each Organization.

### Typical journeys

1. **Service deployment**: the IT Admin logs in to the OPCP Admin Console, opens the Service Catalog, selects a service and deploys it. They choose a version, allocate the Host Pools and configure the service.
2. **Organization creation**: the IT Admin opens <code className="action">Organizations</code>, creates an Organization for the customer and defines its Organization Admin (email, first name, last name).
3. **Service enablement**: the IT Admin enables the Service Deployment for the Organization, from the Service Deployment page or from the Organization page.
4. **Cloud Console usage**: the Organization Admin logs in to the OPCP Cloud Console and manages the users of the Organization. Organization Users open the Enabled Services and create Cloud Resources.

### Authentication and Security Zones

The platform separates authentication into two **Security Zones**, each backed by its own Keycloak instances:

| Security Zone | Keycloak instance | Users | Purpose |
|---------------|-------------------|-------|---------|
| Admin Security Zone | OPCP Core Keycloak | DC operators, Super admins | Infrastructure-level identity |
| Admin Security Zone | OPCP Admin Console Keycloak | IT Admins, Service Packagers | Platform management |
| Public Security Zone | One Keycloak realm per Organization | Organization Admins, Organization Users | OPCP Cloud Console and Enabled Services |

- Within the **Admin Security Zone**, the OPCP Admin Console Keycloak is federated with the OPCP Core Keycloak: rights granted on OpenStack projects in OPCP Core are carried through to the OPCP Admin Console.
- The **Public Security Zone** relies on an independent Keycloak instance managed by the OPCP Admin Console API. It is not federated with the Admin Security Zone, and each Organization's realm is isolated from the others.
