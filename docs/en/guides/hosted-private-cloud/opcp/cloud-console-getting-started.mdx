## Objective

**This guide shows Organization Admins and Organization Users how to log in to the OPCP Cloud Console, use the services enabled for their Organization, and create the user accounts of the Organization.**

The **OPCP Cloud Console** is the Cloud Store interface for Organizations. For an overview of Cloud Store and its concepts, read the guide [Getting started with Cloud Store](/guides/hosted-private-cloud/opcp/cloudstore-getting-started).

## Requirements

- An Organization created by your IT Admin, with at least one Enabled Service.
- The **URL** of the OPCP Cloud Console, your login (your email address) and the first-login default password, provided by your IT Admin or your Organization Admin.
- HTTPS access (TCP/443) to the OPCP Cloud Console URL from your workstation.

## Instructions

### Logging in to the OPCP Cloud Console

1. Navigate to the **URL** of the OPCP Cloud Console. If the URL does not already include your Organization, enter the **Organization name** and click <code className="action">Continue</code>.

    <img className="thumbnail" alt="Choosing the Organization" src="/images/hosted-private-cloud/opcp/cloud-console-getting-started/cloud_console_organization.png" loading="lazy" />

2. The login form of your Organization opens and shows the selected Organization. Enter your email address and password, then click <code className="action">Sign in</code>.

    <img className="thumbnail" alt="OPCP Cloud Console login form" src="/images/hosted-private-cloud/opcp/cloud-console-getting-started/cloud_console_login.png" loading="lazy" />

3. At first login, set a new password.

:::warning
The first-login default password is shared and defined at deployment time. Change it as soon as you log in for the first time.
:::

#### Logging out

To log out, click your user badge at the top right, then choose the logout option in the menu.

The session expires after 30 minutes of inactivity, and at the latest 10 hours after you log in.

### Using the Enabled Services

The side bar lists the Enabled Services of your Organization, that is the services your IT Admin has enabled for it.

<img className="thumbnail" alt="OPCP Cloud Console home page" src="/images/hosted-private-cloud/opcp/cloud-console-getting-started/cloud_console_home.png" loading="lazy" />

Open a service to see its version and its tabs:

- **Overview** shows the **Outputs** of the service: what you need to connect to it with your own tools, for example an `openrc.sh` file for the OpenStack CLI and the region name.
- **Service tabs**: each service can add its own tabs to manage its Cloud Resources, for example `Compute` for virtual machines or `Buckets` for Object Storage.

<img className="thumbnail" alt="Outputs of a Compute and Block Storage service" src="/images/hosted-private-cloud/opcp/cloud-console-getting-started/cloud_console_compute_overview.png" loading="lazy" />

<img className="thumbnail" alt="Buckets of an Object Storage service" src="/images/hosted-private-cloud/opcp/cloud-console-getting-started/cloud_console_object_storage.png" loading="lazy" />

### Creating a user account

The Organization Admin creates the user accounts of the Organization in the Organization's **Keycloak realm**. Each Organization has its own realm, isolated from the other Organizations: any identity operation (adding users, configuring federation, defining roles) is performed in the realm of the target Organization.

<img className="thumbnail" alt="Users of an Organization realm" src="/images/hosted-private-cloud/opcp/cloud-console-getting-started/organization_realm_users.png" loading="lazy" />

1. Open the Keycloak administration console of your Organization and log in as Organization Admin. Your IT Admin can give you its URL: in the OPCP Admin Console, under <code className="action">Management</code> > <code className="action">Organizations</code>, the shield icon of your Organization opens it, as does the <code className="action">IAM Admin Console</code> link on the Organization page.
2. Go to <code className="action">Users</code> and click <code className="action">Add user</code>.
3. Fill in the username, email, first name and last name. The email is the user's **login**. Add the `Update Password` required user action.
4. Click <code className="action">Create</code>.
5. Send the user the OPCP Cloud Console URL, their email and the first-login default password.

To remove access for a user, turn off their `Enabled` toggle.

From the same realm, the Organization Admin can also configure user groups (<code className="action">Groups</code>), connect the company identity provider (<code className="action">Identity providers</code>) or an LDAP / Active Directory directory (<code className="action">User federation</code>).

:::info
Services declare their own roles and groups, which the platform creates in the realm when they are enabled for the Organization. Compute and Block Storage and Object Storage do not create groups or per-user rights: every user of the Organization can use them.
:::

### How Organizations are mapped in Keycloak

:::info
The OPCP Cloud Console runs on its **own dedicated Keycloak stack**, independent from the OPCP Core Keycloak and from the OPCP Admin Console Keycloak. It is not federated with these instances: identities, realms and credentials managed for the OPCP Cloud Console are fully isolated from the administrators of the other OPCP identity layers.
:::

Every Organization automatically gets a dedicated realm, named `account-{name}`. This design ensures:

- independent configuration of authentication flows per Organization;
- separate user bases and role mappings per realm.
