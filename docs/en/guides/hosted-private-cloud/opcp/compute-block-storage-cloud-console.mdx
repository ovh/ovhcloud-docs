## Objective

**This guide shows Organization users how to create instances (virtual machines), block storage volumes and private networks with the Compute and Block Storage service in the OPCP Cloud Console.**

## Requirements

- Access to the OPCP Cloud Console, as described in the guide [OPCP Cloud Console](/guides/hosted-private-cloud/opcp/cloud-console-getting-started).
- The **Compute and Block Storage** service enabled for your Organization by your IT Admin, as described in the guide [Deploying and scaling Compute and Block Storage](/guides/hosted-private-cloud/opcp/compute-block-storage-admin-console).
- An SSH public key: the instance creation form requires one.

## Instructions

### What the service offers in the Alpha

| Resource | What you can do |
|----------|-----------------|
| **Instances** | Create, start, shut off, reboot and delete virtual machines. Open their console in the browser. Change their flavor. |
| **Block Storage** | Create volumes, attach them to instances and detach them. Every instance boots from a volume. Increasing the size of a volume is only possible in Horizon or with the OpenStack CLI. |
| **Private Networks** | Create networks that are isolated from the other Organizations, and connect instances to them. |
| **SSH keys** | Store the public keys injected into new instances. |

You manage these resources in the service Console, in Horizon for the cases the Console does not cover yet, or with the OpenStack CLI.

### Opening the service

In the sidebar of the OPCP Cloud Console, open the service. It appears under the name your IT Admin gave it when enabling it for your Organization.

The header of the service shows two links:

- <code className="action">Console</code> opens the web interface of Compute and Block Storage. This guide describes this interface.
- <code className="action">Horizon</code> opens the OpenStack Horizon interface, for the cases the Console does not cover yet.

In the Console, the menu gives access to your resources:

| Menu | Content |
|------|---------|
| <code className="action">Compute</code> > <code className="action">Instances</code> | Your instances. |
| <code className="action">Storage</code> > <code className="action">Block Storage</code> | Your volumes. |
| <code className="action">Network</code> > <code className="action">Private Networks</code> | Your private networks. |

Your user settings are in the menu of the user icon at the top right, under <code className="action">User settings</code>:

| Page | Content |
|------|---------|
| <code className="action">SSH keys</code> | Your SSH public keys. |
| <code className="action">API access</code> | The API endpoints and your application credentials, to use the OpenStack API. |

### Using the OpenStack CLI

1. In the Console, open the user icon > <code className="action">User settings</code> > <code className="action">API access</code> and create an **application credential**. Note its ID and secret: the secret is shown only once.
2. In the OPCP Cloud Console, open the <code className="action">Outputs</code> tab of the service and copy the **OpenRC** output into a file named `openrc.sh`.
3. In `openrc.sh`, replace `<application credential ID>` with the ID of your application credential.
4. Load the file with `source openrc.sh` and enter the secret of the application credential when asked.

You can then use the `openstack` command, as described in the guide [How to setup an instance using the OpenStack CLI](/guides/hosted-private-cloud/opcp/how-to-setup-instance-from-cli).

### Flavors and images

A **flavor** sets the number of vCPUs and the amount of RAM of an instance. In the Alpha, use the `cb-` flavors. Their name gives the family, the number of vCPUs and the RAM in GB.

| Family | Flavors (vCPU / RAM) |
|--------|----------------------|
| General purpose (`cb-b-`) | `cb-b-2-8` (2 / 8 GB), `cb-b-4-16` (4 / 16 GB), `cb-b-8-32` (8 / 32 GB) |
| Compute optimized (`cb-c-`) | `cb-c-2-4` (2 / 4 GB), `cb-c-4-8` (4 / 8 GB), `cb-c-8-16` (8 / 16 GB) |
| Memory optimized (`cb-r-`) | `cb-r-2-16` (2 / 16 GB), `cb-r-4-32` (4 / 32 GB), `cb-r-8-64` (8 / 64 GB) |

The flavors have no local disk: the system disk of an instance is a block storage volume, whose size you choose.

:::warning
Only the `cb-` flavors can run Compute and Block Storage instances. With the OpenStack CLI or Horizon, an instance created with another flavor stays in the `scheduling` state.

:::

The Alpha offers the following images:

| Image | Default user |
|-------|--------------|
| `Debian 12 BMPOD` | `debian` |
| `Debian 13 BMPOD` | `debian` |
| `CentOS 9 BMPOD` | `cloud-user` |

### Adding an SSH key

1. Open the user icon at the top right, then <code className="action">User settings</code> > <code className="action">SSH keys</code>.
2. Add a new key, give it a name and paste your **public** key, for example the content of `~/.ssh/id_ed25519.pub`.

You can also create the key directly in the instance creation form, with <code className="action">New SSH key</code>.

### Creating a private network

1. Go to <code className="action">Network</code> > <code className="action">Private Networks</code> and click <code className="action">Create network</code>.
2. Enter a **Name** and the **Network address**, for example `192.168.1.0/24`.
3. Keep **DHCP** on, so that instances get their IP address automatically.
4. Optionally, open <code className="action">Advanced settings</code> to set the IP allocation pools, the DNS name servers or host routes.
5. Click <code className="action">Create</code>.

:::info
In the Alpha, private networks cannot be connected to the internet. Leave <code className="action">Connect to Public Internet</code> off.

:::

### Creating an instance

1. Go to <code className="action">Compute</code> > <code className="action">Instances</code> and click <code className="action">Create instance</code>.
2. Enter a **Name**.
3. Choose a **Flavor** in one of the `cb-` families.
4. Keep the **Isolation** on <code className="action">Shared</code>. Dedicated hypervisors are not available in the Alpha.
5. Under **Storage**, choose the **image** and the size of the system volume. The volume is created with the instance.
6. Under **Network**, select your private network.
7. Under **Access & Security**, select your SSH key. An SSH key is required.
8. Optionally, under <code className="action">Advanced settings</code>, add user data (a cloud-init script run at first boot), for example to set a password for the VNC console (see [Connecting to an instance](#connecting-to-an-instance)).
9. Confirm the creation.

The instance is `building`, then `active`.

### Connecting to an instance

In the Alpha, instances cannot be reached from outside the platform: there is no public IP address and no floating IP, so you cannot connect to them over SSH from your workstation.

- **In the browser**: in the list of instances, choose <code className="action">VNC</code> to open the console of the instance in the browser.
- **Between instances**: an instance can reach the other instances of the same private network, for example `ssh debian@192.168.1.10` with the default user of the image.

The images allow login with an SSH key only. To log in through the VNC console, set a password for the default user when you create the instance, with user data such as:

```yaml
#cloud-config
password: <your-password>
chpasswd:
  expire: false
```

:::warning
In the Alpha, the Console passes the user data to the instance as it is, but OpenStack expects it base64-encoded. Encode the script before pasting it into the <code className="action">Customization script</code> field:

```bash
base64 -i cloud-config.yaml        # macOS
base64 -w 0 cloud-config.yaml      # Linux
```

:::

### Creating and attaching a volume

1. Go to <code className="action">Storage</code> > <code className="action">Block Storage</code> and click <code className="action">Create</code>.
2. Enter a **Name** and a **Size**.
3. Choose a **Source**: <code className="action">No source</code> for an empty volume, an image, or another volume to copy.
4. Optionally, turn on <code className="action">Attach to instance after creation</code> and select the instance.
5. Click <code className="action">Create</code>.

To attach an existing volume, open the instance and add the volume to it, or attach it from the volume page. The volume then appears in the instance as a new disk (for example `/dev/vdb`): format and mount it from the operating system.

To detach a volume, open it and choose <code className="action">Detach volume</code>. The system volume of an instance cannot be detached.

### Connecting an instance to a network

To connect an existing instance to another private network:

- from the network: open it in <code className="action">Private Networks</code> and attach the instance;
- or from the instance: open it and add the network.

The instance gets a new network interface with an address from that network. To disconnect it, choose <code className="action">Detach instance</code> on the network.

### What is not in the Alpha yet

The following features are not available in the Alpha:

- Public access to instances: no internet connection for private networks, no floating IP addresses, no SSH access from outside the platform.
- Increasing the size of a volume in the Console: use Horizon or the OpenStack CLI.
- User data in the Console: it must be pasted base64-encoded (see [Connecting to an instance](#connecting-to-an-instance)).
- Volume snapshots, and extending a volume that is encrypted and attached.
- Dedicated hypervisors for an Organization.
- Bare-metal instances and GPU instances.
- Backups to Object Storage.
- Monitoring and alerts for instances.
