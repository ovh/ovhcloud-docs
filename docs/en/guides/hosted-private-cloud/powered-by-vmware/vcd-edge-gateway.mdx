## Objective

An Edge Gateway is the network component that connects your Public VCF as-a-Service organisation to the public network. It is essential for your virtual machines to access the Internet.

**This guide explains how to configure your first Edge Gateway upon delivery of Public VCF as-a-Service, and how to create, edit and delete Edge Gateways from the OVHcloud Console.**

:::warning
Edge Gateways are managed exclusively from the OVHcloud Console. This feature is not available in the VMware Cloud Director interface.
:::

## Requirements

{/* CP-STEPS-START:requirements-ip-block */}

- A **Public VCF as-a-Service Advanced** offer (the Edge Gateway feature is not available with the Standard offer)
- An IP block (IP Space) linked to your Advanced organisation. You can order one from the <code className="action">General information</code> tab of your organisation in the OVHcloud Console: in the **Number of IP Spaces** row, click <code className="action">Order IP Spaces</code>. An IP block can only be linked to a single Advanced organisation (this feature is not available for Standard organisations)

{/* CP-STEPS-END:requirements-ip-block */}

## Instructions

{/* CP-STEPS-START:access-edge-gateway */}

Select your organisation, open the <code className="action">Virtual Datacenters</code> tab, select your **Virtual Datacenter** and click the <code className="action">Edge Gateway</code> tab. This tab is only shown for the Virtual Datacenters of an Advanced organisation (commercial range **NSX**).

{/* CP-STEPS-END:access-edge-gateway */}

### Configure your first Edge Gateway upon delivery

{/* CP-STEPS-START:configure-first-edge-gateway */}

When your Public VCF as-a-Service organisation is delivered, an Edge Gateway is automatically created and associated with your IP block. It appears in the <code className="action">Edge Gateway</code> tab of your Virtual Datacenter in the OVHcloud Console.

{/* CP-STEPS-END:configure-first-edge-gateway */}

This Edge Gateway is ready, but for your virtual machines to access the public network, you must create a **NAT rule** on this Edge Gateway from the VMware Cloud Director interface.

### Configure a NAT rule on your Edge Gateway

Log in to your **VMware Cloud Director** interface, then go to <code className="action">Networking</code> > <code className="action">Edge Gateways</code>. Click your Edge Gateway, then the <code className="action">NAT</code> tab and click <code className="action">New</code>.

The two most common rule types are:

<Tabs noSync>
  <Tab label="SNAT — outbound Internet access">
    A **SNAT (Source NAT)** rule allows your virtual machines to access the Internet. Outbound traffic is translated from the VM's private IP address to a public IP address from your IP block.

    **When to use it?** To allow your VMs to initiate connections to the Internet (updates, downloads, API calls, etc.).

    Fill in the following fields:

    | Field | Value |
    |---|---|
    | **Name** | Rule name (e.g. `snat-to-internet`) |
    | **Action** | `SNAT` |
    | **Source IP** | IP address or range of your VMs' private network (e.g. `192.168.1.0/24`) |
    | **Translated IP** | Public IP address from your IP block |
    | **Port** *(optional)* | Source port to translate (e.g. `443`). If left empty, applies to all traffic |

  </Tab>
  <Tab label="DNAT — inbound access to a VM">
    A **DNAT (Destination NAT)** rule allows external users to access a service hosted on one of your virtual machines. Inbound traffic is redirected from a public IP address to the VM's private IP address.

    **When to use it?** To expose a service on the Internet (website, SSH server, application, etc.).

    Fill in the following fields:

    | Field | Value |
    |---|---|
    | **Name** | Rule name (e.g. `dnat-web-server`) |
    | **Action** | `DNAT` |
    | **Destination IP** | Public IP address from your IP block |
    | **Translated IP** | Private IP address of the target VM (e.g. `192.168.1.10`) |
    | **Port** *(optional)* | Destination port to redirect to the VM (e.g. `80` for HTTP, `443` for HTTPS) |

  </Tab>
</Tabs>

Click <code className="action">Save</code> to apply the rule. It takes effect immediately.

:::info
You can create several NAT rules on the same Edge Gateway and enable or disable them individually as needed.
:::

### Configure firewall rules

By default, a firewall rule blocks all traffic on your Edge Gateway. You must create allow rules for traffic to pass through.

From the **VMware Cloud Director** interface, go to <code className="action">Networking</code> > <code className="action">Edge Gateways</code>. Click your Edge Gateway, then the <code className="action">Firewall</code> tab and click <code className="action">New</code>.

Fill in the following fields:

| Field | Description |
|---|---|
| **Name** | Rule name (e.g. `allow-outbound`) |
| **Direction** | `IN-OUT` to allow outbound traffic, `IN` for inbound only |
| **Source** | Source IP or `Any` for all origins |
| **Destination** | Destination IP or `Any` for all destinations |
| **Service** | Relevant port and protocol (e.g. `TCP:443`) or `Any` for all traffic |
| **Action** | `Allow` to permit, `Drop` to block |

:::warning
Rules are evaluated from top to bottom. Place your allow rules **before** the default block rule, otherwise traffic will be blocked before reaching your rules.
:::

Click <code className="action">Save</code> to apply.

### Create a new Edge Gateway

{/* CP-STEPS-START:create-edge-gateway */}

You can create up to **5 Edge Gateways** per Virtual Datacenter. Each Edge Gateway needs an IP Space that is not yet assigned to another Edge Gateway.

From the <code className="action">Edge Gateway</code> tab, click <code className="action">Add an Edge Gateway</code>.

In the **New Edge Gateway** panel, fill in the requested information:

| Field | Description |
|---|---|
| **Edge Gateway name** | Your Edge Gateway's name (can be changed later) |
| **IP Space** | IP block to assign to this Edge Gateway (block delivered with the organisation or ordered additionally) |

Click <code className="action">Create the Edge Gateway</code> to confirm.

:::info
In your VMware Cloud Director interface, the IP block assigned to your Edge Gateway is visible as an **IP Space** object. An IP block can only be assigned to one Edge Gateway at a time. Deleting an IP Space in the VCD interface does not detach the IP block from your organisation in the OVHcloud Console. To associate your organisation's IP Spaces with another service, contact OVHcloud support: this action is not yet available in the OVHcloud Console.
:::

{/* CP-STEPS-END:create-edge-gateway */}

### Edit an Edge Gateway

{/* CP-STEPS-START:edit-edge-gateway */}

You can edit the name and the IP block (IP Space) assigned to an existing Edge Gateway.

From the <code className="action">Edge Gateway</code> tab, open the ⋮ menu (**Actions** column) of the relevant Edge Gateway, then:

- to change its name, click <code className="action">Edit name</code>, enter the new **Edge Gateway name** and click <code className="action">Edit</code> to confirm;
- to change its IP block, click <code className="action">Edit the IP Space</code>, select the new **IP Space** and click <code className="action">Edit</code> to confirm.

:::warning
Changing the IP block assigned to an Edge Gateway may temporarily interrupt the network connectivity of the virtual machines that use it.
:::

{/* CP-STEPS-END:edit-edge-gateway */}

### Delete an Edge Gateway

{/* CP-STEPS-START:delete-edge-gateway */}

From the <code className="action">Edge Gateway</code> tab, open the ⋮ menu (**Actions** column) of the Edge Gateway to delete, then click <code className="action">Delete</code>. In the **Delete the Edge Gateway** window, confirm with <code className="action">Delete</code>.

:::warning
Deleting an Edge Gateway is irreversible: all its network services and configurations are permanently deleted. All virtual machines connected through this Edge Gateway will immediately lose their access to the public network.
:::

{/* CP-STEPS-END:delete-edge-gateway */}
