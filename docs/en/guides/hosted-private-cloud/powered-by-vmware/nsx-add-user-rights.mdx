## Objective

This guide explains how to add read rights to a user so they can access the NSX-T web console of your Hosted Private Cloud - VMware on OVHcloud.

These rights are granted from the <ManagerLink console to="/">OVHcloud Console</ManagerLink>.

## Requirements

- A subscription to a [Hosted Private Cloud](/links/hosted-private-cloud/vmware) plan with the **"Network Security Virtualization"** or **"Software-Defined Datacenter"** options
- You must be the administrator contact of the VMware infrastructure on OVHcloud, as this contact receives the login credentials.
- You must have completed the steps in this documentation: [Getting started with NSX](/guides/hosted-private-cloud/powered-by-vmware/nsx-first-steps)

[[cpnav:privatecloud-vmware-vsphere-console|en]]

## Instructions

### Step 1 - Enabling NSX-T

{/* CP-STEPS-START:enable-nsx-t */}

<details>

<summary>How do I enable the NSX-T interface for my user?</summary>

There is no separate NSX permission to enable on the user in the OVHcloud Console. Access to the NSX-T web interface is granted per datacentre, by the **Access to V(x)Lans / GENEVE** right of the user you want to access it with (see Step 3).

</details>

{/* CP-STEPS-END:enable-nsx-t */}
### Step 2 - Adding NSX-T rights

{/* CP-STEPS-START:add-nsx-t-rights */}

<details>

<summary>How do I add the rights for my user?</summary>

In the OVHcloud Console, go to **Private Cloud** › **Managed VMware vSphere** and select your service (`pcc-XXX-XXX-XXX-XXX`) in the list. Go to the <code className="action">Users</code> tab and locate the user with whom you want to access the NSX-T web interface.

The user's **Edit** window (⋮ menu of the **Actions** column, then <code className="action">Edit</code>) holds no NSX-T right: the rights that give access to NSX-T are set per datacentre, as described in Step 3.

</details>

{/* CP-STEPS-END:add-nsx-t-rights */}

### Step 3 - Adding NSX-T rights to the Datacentres

{/* CP-STEPS-START:add-rights-datacentres */}

<details>

<summary>How do I add the rights to the Datacentres?</summary>

All that is left to do is modify the rights for each desired datacenter. In the OVHcloud Console, go to **Private Cloud** › **Managed VMware vSphere**, select your service (`pcc-XXX-XXX-XXX-XXX`), then go to the <code className="action">Users</code> tab. Open the ⋮ menu (**Actions** column) of the user and click <code className="action">View/Edit the rights for each DC</code>. On the row of the datacenter, open the ⋮ menu (**Actions** column) and click <code className="action">Modify rights</code>.

The **Editing rights** window then opens. Choose the necessary rights from the 3 main lists: **vSphere access** / **Access to the VM Network** / **Access to V(x)Lans / GENEVE**. The window also holds the **Host and storage management** checkbox.

<br/><br/>
The following rights are available: <strong>Operator</strong> / <strong>None</strong> / <strong>Read-only</strong> in all three lists, <strong>Read/Write</strong> in **vSphere access** only and <strong>Administrator</strong> in **Access to V(x)Lans / GENEVE** only.
<br/><br/>
Only <strong>Read-only</strong> access in **Access to V(x)Lans / GENEVE** is required to access the NSX-T web interface.
<br/><br/>
From **Access to V(x)Lans / GENEVE**, select <strong>Read-only</strong>, then click <code className="action">Save</code>.
<br/><br/>
If you want to make changes in the NSX-T web interface, additional rights will then be required, such as <strong>Operator</strong> or <strong>Administrator</strong>.

</details>

{/* CP-STEPS-END:add-rights-datacentres */}
### Step 4 - Accessing the NSX-T interface

{/* CP-STEPS-START:access-nsx-t-interface */}

<details>

<summary>How do I access the NSX-T web interface?</summary>

The OVHcloud Console does not link to the NSX-T web interface. In the Console, go to **Private Cloud** › **Managed VMware vSphere** and select your service (`pcc-XXX-XXX-XXX-XXX`): on its <code className="action">Dashboard</code> tab, the **Options** section shows whether the **Network and security virtualisation (NSX-T)** option is enabled and on which datacenter it is hosted. The address of the NSX-T web interface is returned by the OVHcloud API, as described in Step 5. Once you have that address, log in to the NSX-T web interface with your user:

### Step 5 - Useful information

You can check whether NSX-T is enabled on your Datacenter. You can also find your NSX-T URL and its version:

#### Via the OVHcloud API

<Api version="v1" section="/dedicatedCloud" method="GET" route={"/dedicatedCloud/\{serviceName\}/nsxt"} />


> **Parameters:**
>
> serviceName: The reference of your PCC in the form `pcc-XX-XX-XX-XX`.
>

Example response:

```shell
{
  "version": "4.1.1.0.0-22224312",
  "state": "enabled",
  "url": "https://nsxt.pcc-XX-X-X-X.ovh.X",
  "datacentersState": [
    {
      "id": 1542,
      "state": "disabled"
    },
    {
      "state": "enabled",
      "id": 1345
    }
  ]
}
```
