## Objective

The OVHcloud vRack feature makes it possible to connect different cloud services with each other, within one or more secure private networks (VLANs).

**This guide explains how to set the solution up with a Hosted Private Cloud infrastructure.**

## Requirements

- A [vRack](/links/network/vrack) service in your account or order one if needed
- Being an administrative contact of your [Hosted Private Cloud infrastructure](/links/hosted-private-cloud/enterprise) to receive login credentials
- A user account with access to vSphere (created in the <ManagerLink console to="/">OVHcloud Console</ManagerLink>)

[[cpnav:network-vrack-console]]

## Instructions

### OVHcloud Console

{/* CP-STEPS-START:ovhcloud-control-panel */}

After your [Hosted Private Cloud infrastructure](/links/hosted-private-cloud/enterprise) is delivered, its "datacenter" is included in a vRack. To display it in the OVHcloud Console, go to **Network** › <code className="action">vRack</code>, select your vRack from the list, then open the <code className="action">Attached services</code> tab.

You can move the "datacenter" of your Private Cloud to another vRack: on its **Private Cloud Datacenter** row, click <code className="action">Move</code>. In the **Moving a Private Cloud datacenter** window, select the **Destination vRack**, then click <code className="action">Move</code>. This operation results in around 5 minutes of downtime.

{/* CP-STEPS-END:ovhcloud-control-panel */}

### vSphere client

In the vSphere client, you can find vRack-capable VLANs in the `Networks` section, located in the *vrack* folder.

:::tip
By default, OVHcloud delivers an infrastructure with 11 VLANs included (VLAN10 to VLAN20).

:::


<img className="thumbnail" alt="vlan" src="/images/hosted-private-cloud/powered-by-vmware/using-private-cloud-in-vrack/vRackVsphere.png" loading="lazy" />

You can change their settings or create them again by following [this guide](/guides/hosted-private-cloud/powered-by-vmware/create-vlan).

You can then assign these *Distributed Port Groups* to the network interfaces of your virtual machines.
