## Objective

**This guide covers the basic operations on virtual machines (VMs) in the vCenter of your Private VCF as-a-Service Workload Domain: creating a VM, deploying it from the content library, cloning it and turning it into a template.**

## Requirements

- A delivered [Private VCF as-a-Service](/links/hosted-private-cloud/private-vcf-aas-3-az) Workload Domain.
- Access to the vCenter of your Workload Domain with an administrator account.

## Instructions

### Before you start

Whichever way you create a VM, three choices matter in particular on Private VCF as-a-Service:

| Choice | What to know |
|---|---|
| **Storage policy** | It decides how the VM is protected. In 3-AZ, choose a policy that mirrors across both sites if the VM must survive the loss of an AZ (see [Managing your cluster's vSAN storage](/guides/hosted-private-cloud/powered-by-vmware/private-vcf/vsan-storage#storage-policies)). |
| **Network** | Connect the VM to a port group of your vRack or to an NSX segment. The platform port groups are not visible (see [Configuring your cluster's network](/guides/hosted-private-cloud/powered-by-vmware/private-vcf/network-configuration)). |
| **Placement** | In 3-AZ, put the VM in the VM group of the AZ where it must run. Otherwise, DRS places it freely in either AZ. |

### Creating a VM

1. In vCenter, open the <code className="action">Hosts and Clusters</code> view.
2. Right-click your cluster, then click <code className="action">New Virtual Machine</code>.
3. Choose <code className="action">Create a new virtual machine</code>, then click <code className="action">Next</code>.
4. Name the VM and choose its folder.
5. Select your cluster as the compute resource.
6. Select the VM's storage policy, then the `<cluster>-ds-vsan01` datastore.
7. Keep the default compatibility.
8. Choose the guest operating system family and version.
9. Set the hardware: number of vCPUs, memory, disk size, network adapter and its network. To install the system from an ISO image, attach it to the CD/DVD drive and tick <code className="action">Connect At Power On</code>.
10. Check the summary, then click <code className="action">Finish</code>.

Power on the VM, open its console from the <code className="action">Summary</code> tab and install the operating system. Then install **VMware Tools**, which lets vCenter shut the VM down cleanly and read its IP address.

:::tip
To upload an ISO image, browse the datastore and use <code className="action">Upload Files</code>, or add it to the content library.
:::

### Deploying a VM from the content library

Your Workload Domain is delivered with a content library, synchronised when the hosts are delivered. You can also add your own templates and images to it.

1. Open <code className="action">Content Libraries</code> from the vCenter main menu, then the library.
2. In the <code className="action">Templates</code> tab, right-click a template, then click <code className="action">New VM from This Template</code>.
3. Follow the wizard: name, folder, cluster, storage policy and network, as for a creation.
4. Customise the hardware if needed before clicking <code className="action">Finish</code>.

### Cloning a VM

Cloning creates a full copy of an existing VM, with its disks and its configuration.

1. Right-click the VM, then click <code className="action">Clone</code> > <code className="action">Clone to Virtual Machine</code>.
2. Name the clone and choose its folder, then the cluster.
3. Select the clone's storage policy. It can differ from the source VM's.
4. Choose the clone options:
    - **Customize the operating system**: applies a customisation specification, to change the host name, the IP address or the system identifier;
    - **Customize this virtual machine's hardware**: changes the clone's hardware;
    - **Power on virtual machine after creation**: starts the clone at the end of the operation.
5. Check the summary, then click <code className="action">Finish</code>.

:::warning
A clone that is not customised keeps the same host name and the same static IP address as the source VM. Do not start both on the same network without changing one of them.
:::

### Creating a template

A template is a reference copy that does not start: it is used to deploy identical VMs.

- **Clone to Template**: right-click the VM, then <code className="action">Clone</code> > <code className="action">Clone to Template</code>. The source VM is kept.
- **Convert to Template**: right-click a powered-off VM, then <code className="action">Template</code> > <code className="action">Convert to Template</code>. The VM becomes a template and no longer exists as a VM.
- **Clone to Library**: right-click the VM, then <code className="action">Clone</code> > <code className="action">Clone as Template to Library</code>, to store the template in your content library.

To deploy a VM from a template in the inventory, right-click the template, then click <code className="action">New VM from This Template</code>.

If you install Windows Server or SQL Server under an OVHcloud licence (SPLA), OVHcloud records their usage every hour, from the licence declared on each VM. After a clone or a deployment from a template, check the licence declared on the new VM.
