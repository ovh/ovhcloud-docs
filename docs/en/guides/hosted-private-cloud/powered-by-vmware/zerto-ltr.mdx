## Objective

This guide explains the purpose of the **LTR (Long Term Retention)** feature in Zerto and how to configure it to retain your recovery points for an extended period.

This feature allows you to:

- Associate an OVHcloud Object Storage bucket with Zerto for long-term retention.
- Define the data immutability policy.
- Secure the configuration with proper connection information.
- Easily recover the configuration in case of failure.

## Prerequisites

- Have an active Managed VMware vSphere service with Zerto enabled.
- Have an OVHcloud Object Storage bucket.
- Have S3<sup>1</sup> credentials associated with this bucket (access key and secret key).

{/* CP-STEPS-START:cp-access */}

:::info
To configure LTR, go to the **DRP** tab of your data centre in Managed VMware vSphere, then click <code className="action">LTR</code>.
:::

## In practice

### Step 1: Understanding the requested information

{/* CP-STEPS-START:understand-requested-information */}

When adding an LTR bucket (**Add an LTR bucket** window) or editing one (**Edit the LTR bucket** window), the following fields are used:

| Field | Status | Details |
|:--|:--|:--|
| **Bucket name** | Required | Name of the OVHcloud Object Storage bucket. It is also used as the name of the repository in Zerto. A name already in use is refused. |
| **Endpoint URL** | Required | URL of the S3 endpoint for the bucket region. |
| **Access key** | Required | S3 access key for the bucket. |
| **Secret key** | Required | S3 secret key for the bucket. |
| **Enable immutability** | Optional | Protects data against deletion or modification during the defined period. |
| **Immutability type** | Conditional | Shown when **Enable immutability** is on: **Period** or **Per VPG Retention Policy** (default). |
| **Number of days** | Conditional | Required if **Immutability type** is **Period** (30 to 90 days). |

The repository type (`highPerformance` or `standard`) is not entered: it is derived from the endpoint URL. It corresponds to the Object Storage bucket class and can be managed from the Object Storage interface.

When editing a bucket, leave the key fields empty to keep the current values.

{/* CP-STEPS-END:understand-requested-information */}

### Step 2: Configure immutability

{/* CP-STEPS-START:configure-immutability */}

To configure immutability, turn on **Enable immutability**, then choose an **Immutability type**:

- **Period**: you explicitly define a duration in days.
- **Per VPG Retention Policy** (default): the duration is driven by the Zerto retention policy.

If you choose **Period**, set **Number of days** to a value between **30 and 90 days**.

{/* CP-STEPS-END:configure-immutability */}

### Step 3: Verify the Object Lock requirement

{/* CP-STEPS-START:verify-object-lock */}

**Object Lock** must be enabled on the OVHcloud Object Storage bucket.

Without this configuration, long-term retention cannot function correctly.

The **Add an LTR bucket** window repeats this requirement and states that only OVHcloud Object Storage buckets are supported.

:::warning
If Object Lock is not enabled, LTR configuration may fail or not guarantee the expected immutability.
:::

{/* CP-STEPS-END:verify-object-lock */}

### Step 4: Use up-to-date region endpoints

{/* CP-STEPS-START:use-region-endpoints */}

Verify that the endpoint entered matches the OVHcloud region of your bucket.

The **Endpoint URL** field is free text: enter the full URL of the region's S3 endpoint, in the format `https://s3.<region>.io.cloud.ovh.net` (for example, `https://s3.gra.io.cloud.ovh.net`). Region endpoints may change; always use the most recent values.

{/* CP-STEPS-END:use-region-endpoints */}

### Step 5: Manage configuration failures

{/* CP-STEPS-START:manage-configuration-failures */}

If a configuration attempt fails:

- An error message indicates that the LTR bucket could not be added.
- The add window closes: click <code className="action">Add a bucket</code> again (or <code className="action">+ Add an existing bucket</code> if no bucket is configured yet) to make another attempt.

Configuring a bucket can take up to 15 minutes. During this time, you cannot add a new bucket.

{/* CP-STEPS-END:manage-configuration-failures */}

### Step 6: Understanding the state without a configured bucket

{/* CP-STEPS-START:state-without-bucket */}

When no bucket is associated, the **LTR** view displays:

- The message **No LTR repository configured**, explaining that an OVHcloud Object Storage bucket must be linked to your Zerto environment to enable long-term retention.
- A <code className="action">Create an OVHcloud bucket</code> link redirecting to OVHcloud Object Storage:
  - If you have a single Public Cloud project, it opens the Object Storage section of that project in the OVHcloud Console; if you have several, it opens the list of your Public Cloud projects.
  - Otherwise, it opens the Object Storage page on the OVHcloud website.
- A <code className="action">+ Add an existing bucket</code> button that opens the **Add an LTR bucket** window.

{/* CP-STEPS-END:state-without-bucket */}

### Step 7: Manage existing buckets

{/* CP-STEPS-START:manage-existing-buckets */}

The configured buckets are listed in a table (columns **Bucket name**, **Number of days**, **Endpoint** and **Actions**). For each bucket, the ⋮ menu (**Actions** column) offers the following actions:

- <code className="action">Edit</code>: modify the bucket configuration (**Edit the LTR bucket** window).
- <code className="action">Delete</code>: delete the bucket configuration.

{/* CP-STEPS-END:manage-existing-buckets */}
