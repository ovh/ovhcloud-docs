## Objective

The **LTR (Long Term Retention)** feature allows Zerto to retain your backups over the long term, in an OVHcloud Object Storage bucket.

**This guide explains how to add, view, edit and delete this long-term retention bucket.**

:::warning
**The LTR bucket is declared in the OVHcloud console, not in the Zerto interface.**

The bucket (S3<sup>1</sup> object storage) is added only from the **DRP** tab of your datacenter in the OVHcloud console. There is no equivalent step to perform in the Zerto interface to link this bucket to your service.
:::

## What is done in the OVHcloud console and in Zerto

| | OVHcloud console | Zerto interface |
|:--|:--|:--|
| Declare the long-term retention bucket (add, edit, delete) | Yes, this is where | No |
| Enter the bucket, endpoint and S3 keys | Yes | No |
| Enable data immutability | Yes | No |
| Control how long the recovery points of your VPGs are retained | No | Yes, with the Zerto retention policy |

## Prerequisites

- Have a Managed VMware vSphere service with Zerto enabled on the relevant datacenter.
- Have an OVHcloud Object Storage bucket, of the **High Performance** or **Standard** class (both are supported). Only OVHcloud Object Storage buckets are accepted.
- Have enabled **Object Lock** on this bucket (see step 2).
- Have the S3<sup>1</sup> credentials associated with this bucket (access key and secret key).

## In practice

### Step 1: Access the LTR tab in the OVHcloud console

1. Log in to the OVHcloud console.
2. Open <code className="action">Hosted Private Cloud</code> > <code className="action">Managed VMware vSphere</code>, then select your service.
3. Select the relevant datacenter.
4. Open the <code className="action">DRP</code> tab (Disaster recovery plan).
5. In the button group, click <code className="action">LTR</code>.

<img className="thumbnail" alt="DRP tab of the datacenter, with the LTR button selected" src="/images/hosted-private-cloud/powered-by-vmware/zerto-ltr/ltr-tab.png" loading="lazy" />

### Step 2: Prepare your Object Storage bucket

If no bucket is configured, the LTR page displays the message "No LTR repository configured" and two buttons:

<img className="thumbnail" alt="LTR page with no bucket configured" src="/images/hosted-private-cloud/powered-by-vmware/zerto-ltr/ltr-no-bucket.png" loading="lazy" />

- <code className="action">Create an OVHcloud bucket</code>: opens the Object Storage bucket order. If you have a Public Cloud project, you land in the Object Storage section of the console; otherwise, on the Object Storage page of the OVHcloud website.
- <code className="action">Add an existing bucket</code>: opens the add form (step 3).

When creating the bucket:

- Choose its class: **High Performance** or **Standard**. Both are supported.
- Enable **Object Lock**, without which long-term retention cannot function correctly.
- Create an S3 user and keep its access key and secret key.

:::warning
If Object Lock is not enabled on the bucket, the LTR configuration may fail or not guarantee the expected immutability.
:::

### Step 3: Add the bucket

Click <code className="action">Add an existing bucket</code> (or <code className="action">Add a bucket</code> if a bucket is already configured). The **Add an LTR bucket** window opens:

<img className="thumbnail" alt="Add an LTR bucket window" src="/images/hosted-private-cloud/powered-by-vmware/zerto-ltr/ltr-add-bucket.png" loading="lazy" />

Fill in the required fields:

| Field | Details |
|:--|:--|
| Bucket name | Name of the OVHcloud Object Storage bucket. |
| Endpoint URL | S3 endpoint for the bucket region, for example `https://s3.gra.io.cloud.ovh.net`. |
| Access key | S3 access key for the bucket. |
| Secret key | S3 secret key for the bucket. |

Verify that the endpoint matches the OVHcloud region of your bucket.

You do not need to specify the bucket class (High Performance or Standard): the console detects it automatically.

If needed, enable **Enable immutability** (see step 4), then click <code className="action">Add</code>.

:::warning
Configuring the bucket may take up to 15 minutes. During this time, you cannot add another bucket.
:::

If the configuration fails, an error message is displayed and the add form remains available: correct the information (first the endpoint, the S3 keys and Object Lock) and try again.

### Step 4: Enable immutability (optional)

The **Enable immutability** option protects data against deletion or modification during the defined period. Once enabled, choose an immutability type (**Immutability type**):

<img className="thumbnail" alt="Immutability options of an LTR bucket" src="/images/hosted-private-cloud/powered-by-vmware/zerto-ltr/ltr-immutability.png" loading="lazy" />

- **Period**: you explicitly define a duration in the **Number of days** field, with a value between **30 and 90 days**.
- **Per VPG Retention Policy**: the duration is driven by the retention policy defined in Zerto for each VPG.

### Step 5: View, edit and delete a bucket

Once the bucket is configured, the table on the LTR page shows its name (**Bucket name**), the duration in days (**Number of days**) and its **Endpoint**.

<img className="thumbnail" alt="Table of configured LTR buckets" src="/images/hosted-private-cloud/powered-by-vmware/zerto-ltr/ltr-bucket-list.png" loading="lazy" />

To act on a bucket, click the menu at the end of the row (**Actions** column):

<img className="thumbnail" alt="Actions menu of an LTR bucket: Edit and Delete" src="/images/hosted-private-cloud/powered-by-vmware/zerto-ltr/ltr-actions-menu.png" loading="lazy" />

- <code className="action">Edit</code>: modify the bucket configuration.
- <code className="action">Delete</code>: delete the bucket. Confirm with <code className="action">Confirm</code>.

<img className="thumbnail" alt="LTR bucket deletion confirmation" src="/images/hosted-private-cloud/powered-by-vmware/zerto-ltr/ltr-delete-bucket.png" loading="lazy" />
