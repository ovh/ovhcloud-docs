## Objective

On a VMware SecNumCloud service, the SPN (SecurePrivateNetwork) groups the subnets used by your virtual machines. An SPN subnet is a layer-2 segment with an IPv4 prefix and **no VLAN tag**.

**This guide explains how to connect virtual machines to an SPN subnet: create a distributed port group on the vRack dVS, connect the virtual machines to it, then configure their IP address and default gateway.**

## Requirements

- A VMware SecNumCloud service with an SPN and a subnet attached to it (see the [SPN Concept](/guides/hosted-private-cloud/powered-by-vmware/snc-connectivity-concepts-spn) guide)
- The IPv4 prefix of the subnet
- A user account with access to vSphere and the specific rights for Networking
- A virtual machine to connect

## Instructions

An SPN subnet follows these rules (see the [SPN Concept](/guides/hosted-private-cloud/powered-by-vmware/snc-connectivity-concepts-spn) guide):

- the first three IP addresses of the subnet are reserved for OVHcloud: the first one is the VIP, the other two are the OVHcloud routers
- the subnet has no VLAN tag
- as the subnet has no VLAN tag, there can be only one SPN segment per VMware Virtual Datacenter

In a static routing configuration, the first IP address of the subnet is therefore the default gateway of your virtual machines, and their own addresses must be chosen after the three reserved ones.

In the examples of this guide, the subnet is `192.0.2.0/24`: the default gateway is `192.0.2.1` and the virtual machine uses `192.0.2.10`.

### Step 1 — Creating the distributed port group

Create only one port group for the SPN in a given Virtual Datacenter. Go to your vSphere client's <code className="action">Networking</code> view and select your datacenter. In the <code className="action">Networks</code> tab, open <code className="action">Distributed Switches</code>, right-click the **dVS** ending in *-vrack*, select <code className="action">Distributed Port Group</code> and then <code className="action">New Distributed Port Group...</code>.

<img className="thumbnail" alt="Context menu of the -vrack dVS showing New Distributed Port Group" src="/images/hosted-private-cloud/powered-by-vmware/snc-connectivity-spn-vmware-configuration/new-distributed-port-group.png" loading="lazy" />

Name your **port group** so that it identifies the SPN subnet (for example `SPN`). The *Location* field shows the dVS ending in *-vrack*. Click <code className="action">Next</code>.

<img className="thumbnail" alt="Port group name and location in the New Distributed Port Group wizard" src="/images/hosted-private-cloud/powered-by-vmware/snc-connectivity-spn-vmware-configuration/port-group-name.png" loading="lazy" />

### Step 2 — Configuring the port group

The settings are those of the [How to create a VLAN](/guides/hosted-private-cloud/powered-by-vmware/create-vlan) guide, with two differences: the number of ports keeps its default value (8), and the VLAN type must be **None**, because an SPN subnet has no VLAN tag.

- **Port binding**: Static binding (reserving and assigning the port to a virtual machine)
- **Port allocation**: Elastic (ports are added automatically when all of them are in use)
- **Number of ports**: 8 (default value)
- **VLAN type**: **None**. No VLAN ID is requested.
- Check the option <code className="action">Customize default policies configuration</code>.

<img className="thumbnail" alt="Port group configuration with the VLAN type None" src="/images/hosted-private-cloud/powered-by-vmware/snc-connectivity-spn-vmware-configuration/port-group-vlan-none.png" loading="lazy" />

On the next pages of the wizard, keep the default values, except on the *Teaming and failover* page.

The default security settings (*Reject* for the first 3, *MAC Learning* disabled) can be adapted to your needs.

<img className="thumbnail" alt="Security settings of the port group in the New Distributed Port Group wizard" src="/images/hosted-private-cloud/powered-by-vmware/snc-connectivity-spn-vmware-configuration/port-group-security.png" loading="lazy" />

Leave *Traffic shaping* disabled.

<img className="thumbnail" alt="Traffic shaping settings of the port group, left disabled" src="/images/hosted-private-cloud/powered-by-vmware/snc-connectivity-spn-vmware-configuration/port-group-traffic-shaping.png" loading="lazy" />

In the failover order, select the `lag1` uplink as the only *Active* uplink (connection between the virtual network and the physical network) and move the other uplinks (`*-vrack_up1`, `*-vrack_up2`, `*-vrack_up3`) to *Unused uplinks*. Leave the *Load balancing* value unchanged: when a link aggregation group (LAG) is the only active uplink, the load balancing mode of the LAG replaces that of the port group.

:::warning
Be careful when configuring the failover order: it is necessary to set the `lag1` uplink to *Active*, otherwise no communication between the hosts will be possible.

:::

<img className="thumbnail" alt="Teaming and failover settings with lag1 as the only active uplink" src="/images/hosted-private-cloud/powered-by-vmware/snc-connectivity-spn-vmware-configuration/port-group-teaming-failover.png" loading="lazy" />

Leave `NetFlow` disabled.

<img className="thumbnail" alt="NetFlow setting of the port group, left disabled" src="/images/hosted-private-cloud/powered-by-vmware/snc-connectivity-spn-vmware-configuration/port-group-netflow.png" loading="lazy" />

Leave the `Block All Ports` value at `No`.

<img className="thumbnail" alt="Block all ports setting of the port group, left at No" src="/images/hosted-private-cloud/powered-by-vmware/snc-connectivity-spn-vmware-configuration/port-group-block-all-ports.png" loading="lazy" />

Review the summary: the VLAN ID is empty (`--`) since the subnet has no VLAN tag. Click <code className="action">Finish</code> to confirm the creation.

<img className="thumbnail" alt="Summary of the new port group, with an empty VLAN ID" src="/images/hosted-private-cloud/powered-by-vmware/snc-connectivity-spn-vmware-configuration/port-group-summary.png" loading="lazy" />

The new port group appears under the dVS ending in *-vrack*.

<img className="thumbnail" alt="New port group listed under the dVS ending in -vrack" src="/images/hosted-private-cloud/powered-by-vmware/snc-connectivity-spn-vmware-configuration/port-group-created.png" loading="lazy" />

### Step 3 — Connecting the virtual machines to the port group

Right-click the virtual machine and select <code className="action">Edit Settings</code>. For the network adapter, open the drop-down list and select <code className="action">Browse...</code>.

<img className="thumbnail" alt="Network adapter drop-down list with the Browse option in Edit Settings" src="/images/hosted-private-cloud/powered-by-vmware/configure-ip-on-vm/04vlanBis.png" loading="lazy" />

In the **Select Network** window, select the port group created in step 1 (the screenshot shows another network as an example), then click <code className="action">OK</code>.

<img className="thumbnail" alt="Select Network window listing the networks available for the adapter" src="/images/hosted-private-cloud/powered-by-vmware/configure-ip-on-vm/05vlan.png" loading="lazy" />

Make sure the connection box of the network adapter is ticked, then click <code className="action">OK</code> to save the virtual machine settings.

### Step 4 — Configuring the IP address and the default gateway

In the virtual machine, configure:

- an IP address of the subnet, after the three reserved ones (for example `192.0.2.10`)
- the subnet mask matching the prefix (for example `255.255.255.0` for a `/24`)
- in a static routing configuration, the **first IP address of the subnet** as the default gateway (for example `192.0.2.1`)

:::info
If BGP is enabled on the SPN, VRRP is disabled and the first IP address of the subnet is no longer reachable. The default gateway of your virtual machines is then your own router, which establishes the eBGP sessions with the two OVHcloud routers. See the "BGP configuration" section of the [SPN Concept](/guides/hosted-private-cloud/powered-by-vmware/snc-connectivity-concepts-spn#bgp-configuration) guide.

:::

  <Tab label="Linux">
    Here is an example of a configuration on the Debian distribution. Edit the `/etc/network/interfaces` file (the name of the interface can differ):

    <img className="thumbnail" alt="Linux IP configuration of eth0 in the /etc/network/interfaces file" src="/images/hosted-private-cloud/powered-by-vmware/configure-ip-on-vm/linux_private.PNG" loading="lazy" />

    ```sh
    auto eth0
    iface eth0 inet static
    address 192.0.2.10
    netmask 255.255.255.0
    gateway 192.0.2.1
    ```

    Restart the network service with `systemctl restart networking`.

    You can check the configuration with `ip a`, and the default gateway with `ip route`.
