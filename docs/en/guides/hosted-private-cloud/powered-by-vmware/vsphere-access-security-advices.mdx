## Objective

To ensure optimal security for your system, we recommend limiting access to it. We offer a number of different methods for this.

**Find out how to secure access to your vSphere web client quickly and easily, using our tips below.**

## Requirements

- A [Hosted Private Cloud infrastructure](/links/hosted-private-cloud/vmware).

[[cpnav:privatecloud-vmware-vsphere-console]]

## Instructions

### Restrict access by IP address

This first method involves restricting access based on the user's IP address. For this purpose, we recommend continuing to work with a registration system that uses whitelisting. This technique refuses access by default for all IP addresses. You can then manually add the IPs that require access to your infrastructure.

{/* CP-STEPS-START:restrict-access-ip */}

Select your service, then click the <code className="action">Access control</code> tab. In this tab, you will see a table listing all authorised IP addresses and blocks. To add new ones, click <code className="action">Associate an IP block</code>. In the **Add a security rule** window, enter the IP address or click <code className="action">Use my current IP address</code>, add a description, then click <code className="action">Next</code> and <code className="action">Confirm</code>.

{/* CP-STEPS-END:restrict-access-ip */}

### Create specific users

{/* CP-STEPS-START:create-users */}

We highly recommend creating personal accounts for each user that requires access to your infrastructure. You can also do this from your service, in the <code className="action">Users</code> tab. To add new users, click <code className="action">Create User</code>.

When you create a new user, we recommend that you set a password for it.

:::info
To ensure that your data is secure, your password must meet the criteria listed below:

- It must contain at least eight characters.
- It must contain at least three character types.
- It must not contain a dictionary word.
- It must not contain any personal information (e.g. your first name, surname or date of birth).
- It must not be used as a password by any other user accounts.
- It must be stored in a password manager.
- It must be changed every three months.
- It must not be identical to any previously used passwords.

:::

You can then manage each user's rights from the ⋮ menu (**Actions** column) of the user, by selecting <code className="action">View/Edit the rights for each DC</code>.

{/* CP-STEPS-END:create-users */}

### Limit session times

When users finish a session, we recommend closing the session accordingly. To limit connection time, you can set a session expiry duration.

{/* CP-STEPS-START:limit-session-times */}

To do this, go to the <code className="action">Managed VMware vSphere</code> section, select your service, then click the <code className="action">Access control</code> tab. In the **Session settings** section, click <code className="action">Edit</code> on the **Session timeout** row. In the **Edit the session timeout** window, enter the time (in minutes) before a session expires, or tick **No session timeout** to disable session expiry. Click <code className="action">Next</code>, then <code className="action">Confirm</code>.

{/* CP-STEPS-END:limit-session-times */}
