## Objective

Global vSphere permissions allow you to define a user's rights on your Hosted Private Cloud service. From the OVHcloud Console, you can enable or disable these options for each user.

This guide explains how to manage these global permissions.

## Requirements

- An active [Hosted Private Cloud service](/links/hosted-private-cloud/vmware)
- A [vSphere user](/guides/hosted-private-cloud/powered-by-vmware/vsphere-interface-connection) already created on your service

[[cpnav:privatecloud-vmware-vsphere-console]]

## Instructions

### Access the user rights management

{/* CP-STEPS-START:access-user-rights */}

1. From your vSphere service, go to the <code className="action">Users</code> tab.

2. Open the ⋮ menu (**Actions** column) of the relevant user and click <code className="action">Edit</code>.

{/* CP-STEPS-END:access-user-rights */}

### Configure global permissions

{/* CP-STEPS-START:configure-global-permissions */}

In the **Edit** window, below the user's details (first name, surname, email and telephone number), the **Permissions** section groups the options that correspond to the global permissions.

1. Tick or untick the permissions according to the rights you want to grant to the user.

2. Click <code className="action">Save</code> to confirm the change.

{/* CP-STEPS-END:configure-global-permissions */}

### Available permissions

{/* CP-STEPS-START:available-permissions */}

The **Permissions** section of the user edit window offers the following options:

| Permission                  | Description                                                                                                                                                                                                                                                      |
|-----------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Token validator**         | Allows the user to validate operations that require a validation token. This permission is generally useful when two-factor authentication (2FA) is enabled on the service, for example as part of certain certifications such as Healthcare Data Hosting (HDS). |
| **IP**                      | Allows the user to manage the IP addresses associated with the service.                                                                                                                                                                                          |
| **Failover IP**             | Allows the user to manage the IP Failover addresses associated with the service.                                                                                                                                                                                 |
| **Encryption management**   | Allows the user to manage virtual machine encryption (KMS).                                                                                                                                                                                                      |

There is no separate permission for NSX: access to the NSX network management interface is granted per datacentre, by the **Access to V(x)Lans / GENEVE** right described below.

{/* CP-STEPS-END:available-permissions */}

### Manage rights by datacenter

In addition to the global service permissions, you can also define rights for each virtual datacenter in your Hosted Private Cloud.

{/* CP-STEPS-START:manage-rights-by-datacenter */}

1. From the <code className="action">Users</code> tab, open the ⋮ menu (**Actions** column) of the relevant user and click <code className="action">View/Edit the rights for each DC</code>.

2. The page that opens lists the user's rights with one row per datacenter (columns **Datacenter**, **vSphere access**, **Host and storage management**, **Access to the VM Network** and **Access to V(x)Lans / GENEVE**). Locate the datacenter row, open its ⋮ menu (**Actions** column) and click <code className="action">Modify rights</code>.

3. In the **Editing rights** window, set the rights, then click <code className="action">Save</code>.

{/* CP-STEPS-END:manage-rights-by-datacenter */}

#### Rights reference

{/* CP-STEPS-START:rights-reference */}

**vSphere access** — global user rights on vSphere.

| Right        | Description                          |
|--------------|--------------------------------------|
| `None`       | No access                            |
| `Operator`   | Reserved for OVHcloud administrators |
| `Read-only`  | Read-only access                     |
| `Read/Write` | Read and write access                |

**Access to the VM Network** — management rights over the public network section ("VM Network" in vSphere).

| Right       | Description                                     |
|-------------|-------------------------------------------------|
| `None`      | No access                                       |
| `Operator`  | Allows VMs to be configured on a public network |
| `Read-only` | Read-only access                                |

**Access to V(x)Lans / GENEVE** — management rights over the private network section (VXLAN for Dedicated Cloud, VLAN for SDDC and Hosted Private Cloud Premier packs).

| Right           | Description                                                                                            |
|-----------------|--------------------------------------------------------------------------------------------------------|
| `None`          | No access                                                                                              |
| `Operator`      | Allows VMs to be configured on a private network                                                       |
| `Administrator` | Allows port groups to be managed on the virtual switch (create, modify, delete). SDDC and Premier only |
| `Read-only`     | Read-only access                                                                                       |

**Host and storage management** — when enabled, the user can add or delete hosts and storage via the OVHcloud plugin in the vSphere client.

{/* CP-STEPS-END:rights-reference */}

### Restricting access to specific vSphere objects

The permissions above apply to the whole service (vSphere cluster) or to a single virtual datacenter. To restrict a user to specific objects in the vSphere inventory — a virtual machine, a datastore or a folder — use the [granular rights on vSphere objects](/guides/hosted-private-cloud/powered-by-vmware/vsphere-granular-rights).
