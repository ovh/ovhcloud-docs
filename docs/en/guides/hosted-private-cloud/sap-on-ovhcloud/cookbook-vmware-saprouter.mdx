## Instructions

### Network Firewall configuration

OVHcloud provides a firewall and anti-DDoS solution, the Network Firewall. This option protects you against potential attacks from the public network. We advise you to enable it for your public IP address which you will use in this configuration.

If you didn't create a Network Firewall and a firewall rule for the public IP address used by your NSX gateway, follow these steps to do it. If you are familiar with the Network Firewall, you can skip the first three steps.

<Tabs>
  <Tab label="Step 1">
    Log in to your <ManagerLink to="/">OVHcloud Control Panel</ManagerLink>, open the <code className="action">Bare Metal Cloud</code> tab, then in the <code className="action">Network</code> menu click <code className="action">IP</code>.
    
    In our [First steps with NSX](/guides/hosted-private-cloud/powered-by-vmware/nsx-first-steps) guide, the [Displaying the HA VIP virtual IP address](/guides/hosted-private-cloud/powered-by-vmware/nsx-first-steps#displaying-the-ha-vip-virtual-ip-address) chapter shows you the way to get the public IP address held by your NSX gateway.
    
    Expand the IPv4 address block, select the IPv4 address used by your NSX gateway and click on <code className="action">Create Firewall</code>.
    
    <img className="thumbnail" alt="create_firewall" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/network-firewall/1_create_firewall.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    Click on <code className="action">Configure the firewall</code> to open the edition window of your Network Firewall.
    
    <img className="thumbnail" alt="configure_firewall" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/network-firewall/2_configure_firewall.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    We advise you to create 2 default rules in your Network Firewall.
    
    Click on <code className="action">Add a rule</code> then set these parameters:
    
    1. Parameters for the first rule:
         - Priority: 0
         - Action: Authorise
         - Protocol: TCP
         - Flags: ESTABLISHED
    
    We suggest that you authorise the TCP protocol from all IP addresses with the flag `ESTABLISHED`. This is to check that the packet is from a previous opened/initiated session. If you don't authorise it, the server won't receive TCP packets from SYN/ACK requests.
    
    
    <ol start="2"><li>Parameters for the second rule :<ul><li>Priority: 19</li><li>Action: Refuse</li><li>Protocol: IPv4</li></ul></li></ol>
    We recommend refusing all IPv4 traffic which wasn't authorised by any prior rule.
    
    <img className="thumbnail" alt="standard_rules" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/network-firewall/3_standard_rules.png" loading="lazy" />
  </Tab>
  <Tab label="Step 4">
    Create the rule to allow the connection from the SAP support infrastructure.
    
    Click on <code className="action">Add a rule</code> then set these parameters:
    
    - Priority: 1
    - Action: Authorise
    - Protocol: TCP
    - IP source: 194.39.131.34/32
    - Destination port: 3299
    - Flags: None
    
    
    <img className="thumbnail" alt="create_rule" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/network-firewall/4_create_rule.png" loading="lazy" style={{ maxWidth: '349px' }} />
    
    Find more information about the SAP support public IP address on the [SAP support website](https://support.sap.com/en/tools/connectivity-tools/saprouter/install-saprouter.html?anchorId=section_498561288).
  </Tab>
  <Tab label="Step 5">
    After a few seconds, the rule is enabled.
    
    <img className="thumbnail" alt="rule_3299" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/network-firewall/5_rule_3299.png" loading="lazy" />
  </Tab>
  <Tab label="Step 6">
    Click on the <code className="action">Back</code> button, select the IP address where you have set up the rule and click on <code className="action">Enable the firewall</code>.
    
    <img className="thumbnail" alt="enable_firewall" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/network-firewall/6_enable_firewall.png" loading="lazy" />
  </Tab>
</Tabs>


### NSX gateway configuration

The NSX gateway is the gateway between Internet and your SAP infrastructure hosts on your VMware on OVHcloud solution. You must configure the NSX gateway to allow the connection from SAP support to your SAP infrastructure via SAProuter.

#### Firewall

We recommend doing a network filtering on your NSX gateway, in addition of the network filtering done by the previously configured Network Firewall.

This network filtering on your NSX gateway allows you to secure your SAProuter if the Network Firewall was to be disabled on your public IP address.

<Tabs>
  <Tab label="Step 1">
    Connect to your VMware on OVHcloud solution and click on the NSX tile.
    
    <img className="thumbnail" alt="nsx_interface" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/nsx/1_nsx_interface.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    Click on the <code className="action">Security</code> tab then, in the <code className="action">Policy Management</code> category, click on <code className="action">Gateway Firewall</code> and select your T0 gateway "ovh-T0-xxxx".
    
    <img className="thumbnail" alt="nsx_firewall" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/nsx/2_nsx_firewall.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    Click on <code className="action">Add policy</code> and give it a name (example: SAP). Inside this policy, you can also set all SAP firewall rules.
    
    Select your new policy and click on <code className="action">Add a rule</code>.
    
    <img className="thumbnail" alt="nsx_firewall_policy" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/nsx/3_nsx_firewall_policy.png" loading="lazy" />
  </Tab>
  <Tab label="Step 4">
    Set the following parameters:
    
    - Name: SAP support
    - Sources: 194.39.131.34/32
    - Destinations: *Private IP address of your SAProuter*
    - Services: TCP - Destination: 3299
    - Action: Allow
    
    <img className="thumbnail" alt="nsx_firewall_rule" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/nsx/4_nsx_firewall_rule.png" loading="lazy" />
  </Tab>
  <Tab label="Step 5">
    Once the rule has been created, click on <code className="action">Publish</code> to update the configuration on the NSX gateway.
  </Tab>
</Tabs>


#### NAT

The SAProuter doesn't have a public IP address. You must apply the configuration to route the traffic on the port tcp/3299 from the public IP address held by your NSX gateway to your SAProuter.

You must create a Destination Network Address Translation (DNAT) rule.

This part shows you the steps to create a DNAT rule on an NSX gateway.

<Tabs>
  <Tab label="Step 1">
    Click on the <code className="action">Networking</code> tab then, in the <code className="action">Network Services</code> category, click on <code className="action">NAT</code>.
    
    <img className="thumbnail" alt="nsx_nat" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/nsx/1_nsx_nat.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    Select your T0 gateway "ovh-T0-xxxx" then click on <code className="action">Add NAT rule</code>.
    
    Set the following parameters:
    
    - Nom: SAP Support
    - Action: DNAT
    - Source IP : 194.39.131.34/32
    - Destination IP | Port : *Public IP address of your NSX gateway* | 3299
    - Translated IP | Port : *Private IP address of your SAProuter* | *Empty*
    
    <img className="thumbnail" alt="nsx_nat_rule" src="/images/hosted-private-cloud/sap-on-ovhcloud/cookbook-vmware-saprouter/nsx/2_nsx_nat_rule.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    Once the DNAT rule has been created, click on <code className="action">Publish</code> to update the configuration on the NSX gateway.
  </Tab>
</Tabs>


Now the traffic originating from the public IP address 194.39.131.34/32 held by SAP to your public IP address of your NSX gateway on the tcp/3299 port will be routed to your SAProuter.

### SAProuter installation

To install the SAProuter service on your dedicated virtual machine, we recommend following [instructions provided by the SAP support](https://support.sap.com/en/tools/connectivity-tools/saprouter/install-saprouter.html). Some steps must be done on your SAP Support Launchpad to secure the connection between SAP support and the SAProuter.

We advise updating your SAProuter as often as you can and deploying it in a monitored and isolated network of your SAP infrastructure. The SAProuter should communicate with your SAP infrastructure on restricted ports.

Find more information about the firewall rule with an NSX gateway in [our guide](/guides/hosted-private-cloud/powered-by-vmware/nsx-manage-gateway-firewall).
