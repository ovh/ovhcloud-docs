## Introduction

The SAP pre-installation wizard offered by OVHcloud simplifies the deployment of an SAP system on your VMware service on OVHcloud already configured in your customer account. It allows you to set up SAP NetWeaver 7.50 or S/4HANA environments, either in ABAP or Java configuration, and according to standard, distributed, or highly available schemes.

:::info
It is essential to note that the term "pre-installation" here refers to the installation of the technical stack only. This includes the SAP HANA database as well as the SAP NetWeaver 7.50 or S/4HANA technical stack. After this pre-installation phase, you will need to install the specific SAP module for your needs and finalize the configurations as part of a post-installation.

:::

## First Steps

{/* CP-STEPS-START:cp-access */}
On the <code className="action">Features</code> tab of the <code className="action">SAP Features Hub</code>, the **SAP pre-installation assistant** card offers two links: <code className="action">Start a pre-installation</code> opens the configuration page, and <code className="action">List of pre-installations</code> opens the <code className="action">Pre-installations</code> tab.

On the configuration page, you can fill in every value by hand, or click <code className="action">Bring in a configuration document</code> to import a previously created JSON file. This file can be generated from the schema of our API or come from a previous installation, allowing you to pre-fill the information and speed up the process.

<Api version="v1" section="/dedicatedCloud" method="POST" route={"/dedicatedCloud/\{serviceName\}/sap"} />
{/* CP-STEPS-END:cp-access */}

**Requirements**

- You must have a VMware on OVHcloud service<sup>1</sup> already deployed in your customer account.
- A Public Cloud project must be created in your OVHcloud account.
    - In this Public Cloud project, an Object Storage container must be created to store your SAP sources<sup>2</sup>.
- A DHCP server must be configured in the network where you want to deploy your SAP system for the OVHcloud virtual machine<sup>3</sup> that will be deployed during the installation process.

It is essential to note that our SAP pre-installation wizard only supports installations using the SAP HANA database. Therefore, only SAPEXEDB sources for SAP HANA are supported. All other SAPEXEDB files must be removed from your Object Storage container if they were selected via the SAP Maintenance Planner.

In the case of an SAP S/4HANA Java installation, also download and deposit the DATA_UNITS files (available via Software Center > INSTALLATIONS & UPGRADES > By Alphabetical Index (A-Z) > S > SAP S/4HANA > &#123;VERSION&#125; > INSTALLATION AND UPGRADE > 5XXXXX.ZIP) into your Object Storage container.

<sup>1</sup> *If you want to deploy a production SAP system, we strongly recommend using our SAP HANA on Private Cloud range. This solution is specifically designed and certified to host SAP systems with an SAP HANA database.*

<sup>2</sup> *OVHcloud is not authorized to provide the required SAP sources for an installation. Therefore, we ask you to store your SAP sources in an OVHcloud Object Storage container. To do this, use the SAP Maintenance Planner tool to generate the list and download the set of SAP sources necessary for your desired installation. Don't forget to deposit the SAPCAR executable in your Object Storage container.*

<sup>3</sup> *When deploying your SAP system, a dedicated virtual machine named "ovhcloud-sap-wizard" will be deployed in your VMware on OVHcloud service. This virtual machine is essential for orchestrating the entire installation process. It is equipped with 2 vCPUs, 1 GB of RAM, and 30 GB of storage. At the end of the installation process, whether successful or failed, this virtual machine will be automatically deleted.*

## Step-by-Step

The **Configure a pre-installation** page holds 7 sections. Fill them in from top to bottom: some lists stay empty until you have chosen a value in an earlier section (the VMware on OVHcloud service, then the datacentre). The **Summary** panel shows whether each section is complete.

### Target infrastructure

{/* CP-STEPS-START:step-1 */}
Select the **VMware on OVHcloud service** that you want to use for your SAP installation. Choose the **Datacentre**, as well as the **Cluster** that will host your SAP virtual machines.
{/* CP-STEPS-END:step-1 */}

### Installation definition

{/* CP-STEPS-START:step-2 */}
Choose the type of SAP installation you want to perform: the **Application version** (SAP NetWeaver 7.50 or S/4HANA), the **Application type** (ABAP or Java) and the **Deployment type** (standard, distributed, or highly available). The values offered come from what the selected VMware service declares it can install. The deployment type determines the number of application servers and the role of each one in the **Virtual machines** section. If you change it later, the application servers already configured are discarded.
{/* CP-STEPS-END:step-2 */}

### System details

{/* CP-STEPS-START:step-3 */}
Provide the SAP system identifiers (**SAP SID** and **SAP HANA SID**) and the four passwords that will be used during the installation: **SAP MASTER** (used for all SAP users requested by the installer, such as DDIC or sapadm), **SIDadm**, **SAP HANA MASTER** and **SAP HANA SYSTEM**.
{/* CP-STEPS-END:step-3 */}

### Installation sources

{/* CP-STEPS-START:step-4 */}
Enter the information for the OVHcloud Object Storage container hosting the necessary SAP sources for this installation: **Container ID**, **Endpoint** (an OVHcloud Object Storage S3<sup>4</sup> endpoint, such as `https://s3.gra.io.cloud.ovh.net`), **Access key** and **Secret key**. Ensure that the container only contains the content generated by the SAP Maintenance Planner corresponding to the version (NetWeaver 7.50 or S/4HANA) and application type (ABAP or Java) selected. The **Access key** and **Secret key** are those of an Object Storage user with read rights on this container.
{/* CP-STEPS-END:step-4 */}

### OS configurations

{/* CP-STEPS-START:step-5 */}
Enter the operating system parameters for your virtual machines, starting with the **Domain name**. A private domain, such as `mydomain.local`, is valid.

The **SUSE licence key** is optional, but the <code className="action">Perform an OS package update before installation</code> option only becomes available once you enter one.

Under **Host firewall**, you can enable the firewall at the operating system level of your virtual machines, separately for the central services, the application servers and the SAP HANA database. If enabled, an `SAP` zone will be created in the `firewalld` service, authorizing selected network communications.
{/* CP-STEPS-END:step-5 */}

### Virtual machines

{/* CP-STEPS-START:step-6 */}
Enter the information for configuring and sizing your virtual machines. The section has three parts:

- the network settings: **VMware port group**, **Netmask** and **Default gateway**;
- the **SAP HANA server**: **OVA model**, **Datastore**, **Thick storage policy**, then the virtual machine's name, root password, IPv4 address, instance number, virtual CPUs and RAM;
- the **Application servers**: their OVA model and datastore, then one card per server. Click <code className="action">Add a server</code> to add one, up to 12 application servers.

We strongly recommend using the vSAN datastore for the virtual machine hosting the SAP HANA database, offering optimized performance. For SAP application servers, you have the option to use an NFS datastore (ssd-XXXXXX).

It is also recommended to create and select your Thick storage policy for your SAP HANA virtual machine. You can find information related to this storage policy in our [documentation](/guides/hosted-private-cloud/sap-on-ovhcloud/cookbook-sap-hana-template-vmware) in the "Configuring advanced settings" chapter, point 5.

:::warning
It is not possible to apply a Thick storage policy on NFS datastores (ssd-XXXXXX). Therefore, if you select an NFS datastore for your SAP HANA machine, the Thin storage policy will be used.

:::


All virtual machines must be deployed in the same subnet. This subnet must have Internet access to allow downloading SAP sources from your OVHcloud Object Storage container, as well as updating operating system packages if you enabled this option. The port group you choose must also provide DHCP: the pre-installation fails at its first stage on a network without DHCP.

You can choose a different OVA/OVF virtual machine template for your SAP HANA database and for your SAP application servers, as well as a different datastore. However, it is not possible to deploy your SAP application servers on different OVA/OVF virtual machine templates and datastores. Additionally, if you decide to deploy your virtual machines with different OVA/OVF templates, the SUSE licence is not activated.
{/* CP-STEPS-END:step-6 */}

### Optional SAP features

{/* CP-STEPS-START:step-7 */}
This section lets you activate 2 OVHcloud features: the backup agent for SAP HANA and the export of SAP logs to Logs Data Platform. Each switch reveals the fields to fill in.

**Back SAP HANA databases up with the OVHcloud Backint agent**

We invite you to review the prerequisites in our [documentation](/guides/hosted-private-cloud/sap-on-ovhcloud/cookbook-install-ovhcloud-backint-agent).

**Send SAP logs to OVHcloud Logs Data Platform**

We invite you to review the chapters Logs Data Platform, Data stream, and collection tools in our [documentation](/guides/hosted-private-cloud/sap-on-ovhcloud/cookbook-sap-logs-on-ovhcloud-logs-data-platform-solution-setup).
{/* CP-STEPS-END:step-7 */}

### Summary and submission

{/* CP-STEPS-START:step-8 */}
Check the information in each section to avoid any issues during the pre-installation. The **Summary** panel shows each section as complete or incomplete.

Once every section is complete, you can export this configuration in JSON format with <code className="action">Take the configuration out</code>. You can later import it into a new configuration with <code className="action">Bring in a configuration document</code>, pre-filling the information.

:::warning
The exported file contains every value you entered in readable form, including the SAP account passwords, the virtual machines' root passwords, the Object Storage secret keys and the Logs Data Platform certificate. Store it accordingly.

:::

Then click <code className="action">Submit the configuration</code>. Submitting provisions the virtual machines and installs SAP on them: from that point, the configuration can no longer be changed.

You then follow the pre-installation from its own page, which shows its progress stage by stage, what is being installed, and its timestamps. A failed pre-installation is never resumed or restarted: starting again means a new configuration and a new submission. You can also find the list of all your pre-installations and their details in the <code className="action">Pre-installations</code> tab of the <code className="action">SAP Features Hub</code>.
{/* CP-STEPS-END:step-8 */}

## Troubleshooting Common Issues

<details>

<summary>The error message indicates that the requested configuration exceeds the capabilities of my datacenter.</summary>


If you have recently deleted virtual machines to free up capacity within your datacenter, it may be that the capacity information has not yet been updated. Please wait a few minutes before trying again. If the problem persists, do not hesitate to contact OVHcloud support for assistance.

</details>


<details>

<summary>The imported JSON file contains syntax errors.</summary>


Ensure that the JSON file is correctly formatted. You can use a JSON validator to check the file's validity before importing it into the wizard.

</details>


<details>

<summary>The SAP sources are not accessible from the Object Storage container.</summary>


Check that the Object Storage container is correctly configured and that the access permissions are appropriate. An Object Storage user with read rights is necessary for downloading the sources to your virtual machines.

</details>


<details>

<summary>The allocated memory parameters for the virtual machines are insufficient.</summary>


Increase the amount of RAM allocated to the virtual machines based on SAP's requirements for your configuration. Consult SAP documentation for recommendations on memory.

</details>


<details>

<summary>An error message indicates that an internal error occurred during installation, and I cannot start a new installation because a previous task is still in progress.</summary>


If an internal error occurs and the task status has not been correctly updated, please delete the task in question via our API.

<Api version="v1" section="/dedicatedCloud" method="DELETE" route={"/dedicatedCloud/\{serviceName\}/sap/\{taskId\}"} />

This action will remove the task in error that is blocking new installations. Also, delete the virtual machines that were created by the failed installation task.

</details>


## Frequently Asked Questions (FAQ)

<details>

<summary>Can I use a VMware on OVHcloud service other than the SAP HANA on Private Cloud range?</summary>


Although our SAP pre-installation wizard is optimized for the SAP HANA on Private Cloud range, it is possible to use a VMware on OVHcloud service from another range. However, we strongly recommend the SAP HANA on Private Cloud range for a solution specifically designed and certified to host SAP systems with an SAP HANA database.

</details>


<details>

<summary>Can I use my OVA/OVF virtual machine templates to deploy the SAP system?</summary>


You cannot currently use your OVA/OVF virtual machine templates to deploy your SAP system via our wizard.

</details>


<details>

<summary>Can I resume my installation if it failed?</summary>


In the event of an installation failure, you will not be able to resume the installation. You will need to delete the constructed SAP system and launch a new installation. If necessary, you can also contact [OVHcloud support](https://help.ovhcloud.com/csm?id=csm_get_help) for assistance.

</details>


<details>

<summary>Can I add an SAP application server to an existing SAP system?</summary>


The OVHcloud SAP pre-installation wizard does not support adding additional components to an existing SAP system.

</details>
