## Objective

With OVHcloud, you can create additional local users with read or write access to your customer account. This means that you can grant other members of your company access to your OVHcloud services, without having to resort to risky practices like sharing passwords or two-factor authentication details.

:::info
User management is different from contact management. A user will have an access to all sections of the OVHcloud Console according to the level of rights granted.

The purpose of contact management is to delegate full management of the administrative, technical and billing aspects of one or more services on your OVHcloud account. For further information on contact management, please refer to [this guide](/guides/account-and-service-management/account-information/managing-contacts).

:::


**This guide details the privileges a local user can hold, as well as the method for adding and managing users.**

## Requirements

- An active OVHcloud account

[[cpnav:iam-identities]]

## Instructions

### Understanding identities

Local users are one of the types of identities that can be set up on your OVHcloud account. Other account types are described in the [related documentation](/guides/manage-and-operate/iam/identities-management).

### User management

#### Add a user

{/* CP-STEPS-START:add-a-user */}

From the **Local users** tab of the <ManagerLink to="/beta/#/iam/identities/users">Identities</ManagerLink> page, click on <code className="action">Create a local user</code>.

In the **Create a local user** panel, complete the required fields. Click <code className="action">Create</code> to create the user.

<img className="thumbnail" alt="Create a local user panel with Username, Email, Password, Main group, Additional groups and Description" src="/images/account-and-service-management/account-information/ovhcloud-users-management/console/usersmanagement2.png" loading="lazy" />

| Field | Details |
|--|--|
| Username | Enter the user's name or their role, for example. |
| Email | Enter the user's full email address. |
| Password | Set the user password. The user can then change this password once their access has been created. <br/>We also suggest reading our [guide on password management](/guides/account-and-service-management/account-information/manage-ovh-password) to define this password. |
| Main group | Choose a group from those available (see table below). |
| Additional groups | You can also add the user to other groups. |
| Description | You can add a user description (such as their role within the company). |

**Default group details:**

| Group (role) | Details |
|--|--|
| UNPRIVILEGED (Read-only) | Gives read access to the OVHcloud Console and all of its sections. |
| DEFAULT (Regular) | Gives write access to the OVHcloud Console and all of its sections, **except for** user management. |
| ADMIN (Admin) | Gives write access to the OVHcloud Console and all of its sections, **including** user management. |

The user then gets their own ID made up of your NIC handle and their username, with the two values separated by a "/". The form shows this ID below the **Username** field.

Example: **aa00000-ovh/johnsmith**.

<img className="thumbnail" alt="Login information box and ID preview below Username in the Create a local user panel" src="/images/account-and-service-management/account-information/ovhcloud-users-management/console/usersmanagement3.png" loading="lazy" />

The user you have created can then log in to the <ManagerLink to="/beta/#/">OVHcloud Console</ManagerLink> using this ID.

{/* CP-STEPS-END:add-a-user */}

They can also change their password and secure their own access to your account by enabling two-factor authentication (this is only for their access as a user). To find out how to enable two-factor authentication, you can refer to [this guide](/guides/account-and-service-management/account-information/secure-ovhcloud-account-with-2fa).

#### Manage users

{/* CP-STEPS-START:manage-users */}

You can edit, disable or delete a user by clicking on the <code className="action">⋮</code> button in the **Actions** column of the user's row, then on <code className="action">Edit user</code>, <code className="action">Disable user</code> or <code className="action">Delete user</code>. A disabled user can be enabled again from the same menu.

<img className="thumbnail" alt="Open user row menu with Edit user, Disable user, Manage tokens and Delete user" src="/images/account-and-service-management/account-information/ovhcloud-users-management/console/usersmanagement4.png" loading="lazy" />

When you edit a user you can update their email address, group and description.

<img className="thumbnail" alt="Edit user panel with the Username, Email, Main group, Additional groups and Description fields" src="/images/account-and-service-management/account-information/ovhcloud-users-management/console/usersmanagement6.png" loading="lazy" />

{/* CP-STEPS-END:manage-users */}

### Group management

#### Add a group

{/* CP-STEPS-START:add-a-group */}

To add a group, go to the <code className="action">User groups</code> tab, then click the <code className="action">Create a group</code> button.

<img className="thumbnail" alt="User groups tab of the Identities page, with the Create a group button" src="/images/account-and-service-management/account-information/ovhcloud-users-management/console/usersmanagement7.png" loading="lazy" />

In the **Create a group** panel, complete the required fields. Click <code className="action">Create</code> to create the group.

<img className="thumbnail" alt="Create a group panel with the Name, Role and Description fields" src="/images/account-and-service-management/account-information/ovhcloud-users-management/console/usersmanagement8.png" loading="lazy" />

Groups give a default privilege level for the users they contain, according to the role you choose:

| Role | Details |
|--|--|
| None | Gives no access to the OVHcloud Console if no IAM policy is set up. |
| Read-only | Gives read access to the OVHcloud Console and all of its sections. |
| Regular | Gives write access to the OVHcloud Console and all of its sections, **except for** user management. |
| Admin | Gives write access to the OVHcloud Console and all of its sections, **including** user management. |

{/* CP-STEPS-END:add-a-group */}

#### Manage groups

{/* CP-STEPS-START:manage-groups */}

You can update or remove a group by clicking on the <code className="action">⋮</code> button in the **Actions** column of the group's row, then on <code className="action">Edit group</code> or <code className="action">Delete group</code>. These actions are not available for the default groups UNPRIVILEGED, DEFAULT and ADMIN.

<img className="thumbnail" alt="Group row menu with Edit group and Delete group, opened from the ⋮ button" src="/images/account-and-service-management/account-information/ovhcloud-users-management/console/usersmanagement9.png" loading="lazy" />

When you edit a group you can update its description and role.

<img className="thumbnail" alt="Edit group panel with the Name, Role and Description fields" src="/images/account-and-service-management/account-information/ovhcloud-users-management/console/usersmanagement10.png" loading="lazy" />

{/* CP-STEPS-END:manage-groups */}

### Rights management

On top of the role associated to user groups, you can fine-tune access privileges using OVHcloud IAM.
OVHcloud IAM policies management is covered by the [dedicated guide](/guides/account-and-service-management/account-information/iam-policy-ui).
