## Objective

This guide will explain how to provide specific access rights to users of an OVHcloud account.

The access management of OVHcloud is based on a policy management system. It is possible to write different policies that give users access to specific features on the products linked to an OVHcloud account.

In detail, a policy contains:

- One or more **identities** targeted by this policy. 
    - It can be account IDs, users or user groups (like the ones used in [Federation](/guides/account-and-service-management/account-information/ovhcloud-account-connect-saml-adfs) - other SSO guides are available). 
- One or more **resources** impacted by this policy. 
    - A resource is an OVHcloud product that will be impacted by this policy (a domain name, a Nutanix server, a Load Balancer, etc.).
- One or more **actions** allowed or excepted by this policy.
    - Actions are the specific rights affected by this policy (reboot a server, create an email account, cancel a subscription, etc.)
 
For example, we can create a policy to give to a user called John, for a VPS, access to the action "reboot".

**This guide explains in detail how these policies can be declared using the OVHcloud Console, and how to list the identities, resources and actions available for them.**

## Requirements

- You have an [OVHcloud account](/guides/account-and-service-management/account-information/ovhcloud-account-creation).
- You know [how to manage account users](/guides/account-and-service-management/account-information/ovhcloud-users-management).
- You have one or more OVHcloud products linked to this OVHcloud account (Load Balancer, domain name, VPS, etc.).

## Instructions

### Accessing the IAM menu

{/* CP-STEPS-START:access-iam-menu */}

Open the <ManagerLink to="/beta/#/iam/policies/my-policies">My policies</ManagerLink> page.

<img className="thumbnail" alt="My policies page with the My policies, OVHcloud policies and Resource groups tabs" src="/images/account-and-service-management/account-information/iam-policy-ui/console/access_to_the_IAM_menu_01.png" loading="lazy" />

To [create a policy](#creating-a-policy), click <code className="action">Create a policy</code> above the list of your policies. Users are listed on the <ManagerLink to="/beta/#/iam/identities/users">Identities</ManagerLink> page, in the **Local users** tab, where you can [create users](/guides/account-and-service-management/account-information/ovhcloud-users-management) with the <code className="action">Create a local user</code> button.

:::info
The <code className="action">OVHcloud policies</code> tab shows the list of all the OVHcloud Managed policies. These policies are automatically created by OVHcloud to convert the preexisting `NIC Tech` and `NIC Admin` delegation on the new IAM feature.

Customers are not allowed to edit or delete these policies.

:::

The policies you have created are in the first tab, <code className="action">My policies</code>.

<img className="thumbnail" alt="My policies and OVHcloud policies tabs above the list of policies" src="/images/account-and-service-management/account-information/iam-policy-ui/console/access_to_the_IAM_menu_03.png" loading="lazy" />

Each policy is displayed with its name, its description, the number of identities linked to it, the number of resources it covers, the number of actions it allows, its creation date and the date of its last update.

{/* CP-STEPS-END:access-iam-menu */}

### Managing policies

#### Creating a policy

{/* CP-STEPS-START:create-policy */}

Click the <code className="action">Create a policy</code> button.

The **Create a policy** page opens. It has five sections: **Policy information**, **Identities**, **Product types**, **Conditions** and **Actions**. On the right, the **Summary** section holds the <code className="action">Create a policy</code> and <code className="action">Cancel</code> buttons.

<img className="thumbnail" alt="Create a policy page, Policy information section with the Name and Description fields" src="/images/account-and-service-management/account-information/iam-policy-ui/console/create_a_policy_01.png" loading="lazy" />

- **Name** (mandatory), in the **Policy information** section: This is the name that will appear in the interfaces. The name should be unique. It can contain letters, digits and the characters `-`, `/`, `_` and `+` only: spaces are not allowed.
- **Description** (optional), in the same section: A free text describing the policy.
- **Identities**: Select the identities affected by this policy. It's possible to target more than one identity type: each type has its own tab (**Users**, **Groups**, **Service accounts** and **Other OVHcloud accounts**).
- **Product types**: Select the type of product to define the scope of the policy. One or more product types can be included in the same policy.
- **Resources** and **Resource groups**, in the **Product types** section: Add resources or resource groups to be covered by the policy. The resources available are filtered by the product type selected beforehand.
- **Actions**.

**There are 4 different ways to add actions:**

{/* CP-STEPS-END:create-policy */}

##### 1 - Activating the "Allow every action" option

{/* CP-STEPS-START:activate-authorise-all-actions */}

<img className="thumbnail" alt="Allow every action switch and its description in the Actions section" src="/images/account-and-service-management/account-information/iam-policy-ui/console/create_a_policy_02.png" loading="lazy" />

When you enable the **Allow every action** option, you allow all actions on every product type. This includes all existing actions as well as actions added in the future.

{/* CP-STEPS-END:activate-authorise-all-actions */}

##### 2 - Selecting a group of managed permissions

{/* CP-STEPS-START:select-managed-permission-groups */}

We provide permission groups that are preconfigured and managed by OVHcloud. You can select one or more groups by selecting them from the available list, in the **Managed permissions groups** field.

<img className="thumbnail" alt="Managed permissions groups field in the Actions section of the Create a policy page" src="/images/account-and-service-management/account-information/iam-policy-ui/console/create_a_policy_05.png" loading="lazy" />

Details of the content of the managed permission groups are available in the [associated documentation](/guides/account-and-service-management/account-information/iam-permission-groups).

In the OVHcloud Console, managed permission groups cannot be combined with individual actions in the same policy: selecting a managed group replaces the individual action selection, and selecting or adding an individual action clears the managed groups.

{/* CP-STEPS-END:select-managed-permission-groups */}

##### 3 - Adding actions manually

{/* CP-STEPS-START:add-actions-manually */}

If you know the action name, you can add it manually: enter it in the **Manually add actions** field, then click <code className="action">Add</code>.

<img className="thumbnail" alt="Manually add actions field with its Add button in the Actions section" src="/images/account-and-service-management/account-information/iam-policy-ui/console/create_a_policy_03.png" loading="lazy" />

You can use a wildcard at the beginning or at the end of the action name with `*`.

For example, adding `vps:apiovh:ips/*` will grant the following rights:

- **vps:apiovh:ips/edit**
- **vps:apiovh:ips/delete**
- **vps:apiovh:ips/get**

{/* CP-STEPS-END:add-actions-manually */}

##### 4 - Selecting actions from the list

{/* CP-STEPS-START:select-actions-from-list */}

Finally, you can select actions from the list: once you have selected a product type, expand one of its categories and tick the actions you want to allow.

<img className="thumbnail" alt="Actions of a product type, with the Search field and the READ category expanded" src="/images/account-and-service-management/account-information/iam-policy-ui/console/create_a_policy_04.png" loading="lazy" />

The available actions depend on the resource type and are grouped by category:

- **CREATE**: Action that allows you to create something on a product (*e.g. Create a support ticket*).
- **READ**: List products and show information about a product (*e.g. List a VPS IP*).
- **EDIT**: Action to change something existing on a product (*e.g. Edit TCP route of a Load Balancer*).
- **OPERATE**: Apply changes to the infrastructure related to the product (*e.g. Reboot a dedicated server*).
- **DELETE**: Action that allows you to delete something on a product (*e.g. Delete a Public Cloud instance*).

The list can also include a **NOTIFICATION** category, as it does for the **OVHcloud customer account** product type.

A search field is available to help identify a specific action on the list.

{/* CP-STEPS-END:select-actions-from-list */}

:::info
Actions related to ordering and billing are not yet available in the OVHcloud IAM.

:::


#### Conditions on policies

{/* CP-STEPS-START:conditions-on-policies */}

It's possible to add conditions on IAM policies.

A policy with conditions is valid only if all conditions are validated.

It's possible to add conditions on these elements:

- A resource tag
- The resource name
- The product type
- The IP of the request
- The day of the week
- The date
- The time

To add a condition, click <code className="action">Add a condition</code> in the **Conditions** section, select the element in the **Type** list and an **Operator** (**Equals**, **Starts with** or **Ends with**), enter the **Value** (for a tag, also its **Tag key**), then click <code className="action">Add</code>.

<img className="thumbnail" alt="Conditions section with the Type, Operator, Tag key and Value fields of a new condition" src="/images/account-and-service-management/account-information/iam-policy-ui/console/conditions.png" loading="lazy" />

Once added, each condition is listed with its type, its operator and its value. To write conditions with the API syntax, see [our guide on IAM policies with the API](/guides/account-and-service-management/account-information/iam-policies-api).

{/* CP-STEPS-END:conditions-on-policies */}

#### Editing a policy

{/* CP-STEPS-START:edit-policy */}

To edit an existing policy, click the <code className="action">⋮</code> button in the **Actions** column, to the right of the policy, and click <code className="action">Edit policy</code>.

<img className="thumbnail" alt="Menu of a policy row with the Edit policy and Delete policy entries" src="/images/account-and-service-management/account-information/iam-policy-ui/console/editing_a_policy.png" loading="lazy" />

Then you can change the scope of the policy.

{/* CP-STEPS-END:edit-policy */}

#### Deleting a policy

{/* CP-STEPS-START:delete-policy */}

To delete an existing policy, click the <code className="action">⋮</code> button in the **Actions** column, to the right of the policy, and click <code className="action">Delete policy</code>.

A popup window will ask you to confirm the deletion.

{/* CP-STEPS-END:delete-policy */}

#### Policies targeting other OVHcloud customer accounts

Access policies can target other OVHcloud customer accounts.  
The targeted account of this policy will be able to manage the rights received that way on its own policies, but will never be able to override the rights set on the access policy.

For example, an account **xx1111-ovh** gives rights on `vps:apiovh:ips/*` to account **xx2222-ovh**:  
Account **xx2222-ovh** will be able to give the right `vps:apiovh:ips/delete` to its own users, but will never be able to grant the right `vps:apiovh:reboot`.

Access to the support will still be reserved to the owner of the resource.

### Managing identities

{/* CP-STEPS-START:manage-identities */}

To manage the identities available for policies, go to the <ManagerLink to="/beta/#/iam/identities/users">Identities</ManagerLink> page.

{/* CP-STEPS-END:manage-identities */}

### Managing resource groups

Policies can target resource groups instead of resources. These resource groups can assemble resources from different products, for example to set up a test environment.

#### Creating a resource group

{/* CP-STEPS-START:create-resource-group */}

To create a resource group, go to the <ManagerLink to="/beta/#/iam/policies/my-policies">Policies</ManagerLink> section, then click the <code className="action">Resource groups</code> tab:

<img className="thumbnail" alt="Resource groups tab of the Policies section, with the Create a resource group button" src="/images/account-and-service-management/account-information/iam-policy-ui/console/resource_groups.png" loading="lazy" />

Click <code className="action">Create a resource group</code>. The **Create a resource group** panel opens.

<img className="thumbnail" alt="Create a resource group panel with the Name, Product types and Resources fields" src="/images/account-and-service-management/account-information/iam-policy-ui/console/resource_groups_form.png" loading="lazy" />

- **Name**: This is the name that will appear in the interfaces. The name should be unique. It can contain letters, numbers and the characters `-`, `/`, `_` and `+` only: spaces are not allowed.
- **Product types**: The list of product types concerned by this resource group.
- **Resources**: The list of resources the group will contain, up to 100 resources.

{/* CP-STEPS-END:create-resource-group */}

#### Editing a resource group

{/* CP-STEPS-START:edit-resource-group */}

To edit a resource group, click on its name in the list. The group's page opens: click <code className="action">Edit resource group</code>.

You can also click the <code className="action">⋮</code> button in the **Actions** column, to the right of the group, then <code className="action">Edit resource group</code>.

{/* CP-STEPS-END:edit-resource-group */}

#### Deleting a resource group

{/* CP-STEPS-START:delete-resource-group */}

To delete an existing resource group, click the <code className="action">⋮</code> button in the **Actions** column, to the right of the group, and click <code className="action">Delete Group</code>. The same button is on the group's page.

A popup window will ask you to confirm the deletion.

{/* CP-STEPS-END:delete-resource-group */}
