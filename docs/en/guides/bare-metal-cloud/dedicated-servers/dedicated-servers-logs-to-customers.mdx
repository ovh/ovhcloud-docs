## Objective

This guide explains how to enable the forwarding of the logs of your OVHcloud Dedicated Server to Logs Data Platform (LDP), a platform that helps you store, archive, query and visualise your logs.

To find out more about Logs Data Platform before reading this guide, refer to the [Logs Data Platform introduction guide](/guides/manage-and-operate/observability/logs-data-platform/introduction).

**In this guide, you will learn how to:**

- View the logs of your Dedicated Server in real time.
- Create a subscription that forwards those logs to a Logs Data Platform data stream.
- Query and visualise the forwarded logs.
- Manage and delete your subscriptions.

:::info
The logs described in this guide come from the operations that OVHcloud performs on your server: **operating system installation**, **network boot** and **network configuration**. They are **not** the system logs produced by the operating system once it is running.

To centralise the logs produced by your own operating system, refer to the guide on [sending Linux logs to Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/log-linux) instead.
:::

## Glossary

- **Logs Data Platform:** a fully managed and secured log management platform by OVHcloud. For more information, consult the [Logs Data Platform](/links/manage-operate/ldp) service page.
- **Data Stream:** a logical partition of logs that you create in an LDP account and use when ingesting, viewing or querying your logs. Multiple sources can be stored in the same data stream, and it is the unit used to define a log pipeline (retention policy, archiving, live streaming, etc.), access rights and alert policies.
- **Logs forwarding:** a feature integrated into an OVHcloud product to ingest the logs of its services into a *Data Stream* of an LDP account in the same OVHcloud account. You must enable it for each service.
- **Logs forwarding Subscription:** when you enable logs forwarding for a given OVHcloud service to a given LDP *Data Stream*, a *Subscription* is created and attached to the *Data Stream*, which you then manage.

## Requirements

- A Logs Data Platform (LDP) account with at least one active *Stream* configured. This guide will walk you through all the necessary steps: [Quick start for Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start).
    - If you are not familiar with all the LDP *Stream* configuration possibilities, create a new one with the default options (indexing and WebSocket enabled, long-term storage disabled) for this guide.
- An up-and-running [OVHcloud Dedicated Server](/guides/bare-metal-cloud/dedicated-servers/getting-started-with-dedicated-server).
- Both the LDP account and the Dedicated Server must belong to the same OVHcloud account.

## Concepts and limits

**What are the logs of a Dedicated Server?**

The forwarded logs trace the operations carried out by OVHcloud on your server: operating system installation, network boot and network configuration.

Logs forwarding is available on all Dedicated Server ranges.

### Log kinds

Logs are grouped into *kinds*, and you subscribe to each kind separately. A Dedicated Server exposes the following kinds:

| Kind | Display name | Description |
|------|--------------|-------------|
| `install` | Operating system installation logs | Details of the installation of the operating system on your server. |
| `netboot` | Network boot logs | Delivery of the iPXE boot script to your server when it boots over the network (hard disk, rescue, installer, etc.). |
| `network` | Network configuration logs | Network operations carried out by OVHcloud on your server: Additional IPs, virtual MACs, vRack, OVHcloud Link Aggregation (OLA) and bandwidth policies. |

You can retrieve the list of kinds available on your server with the following API call:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/kind"} />

To get the details of one kind, including the additional fields it returns, use the following API call:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/kind/\{name\}"} />

### Log contents

In addition to the fields common to every log ingested by Logs Data Platform, each kind returns the following fields.

#### `install` kind

| Field name | Description | Type |
|------------|-------------|------|
| `level` | Criticality level of the log entry, following the standard syslog severity values: `2` (critical), `6` (info). | Number |
| `os` | Operating system installed on the server. | String |
| `serviceName` | Internal name of your server, in the form `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Current step of the operation: `os-install-start`, `os-install-failed` or `os-install-ok`. | String |

#### `netboot` kind

| Field name | Description | Type |
|------------|-------------|------|
| `level` | Criticality level of the log entry, following the standard syslog severity values: `2` (critical), `6` (info). | Number |
| `serviceName` | Internal name of your server, in the form `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Result of the boot script request: `ipxe-request-ok` or `ipxe-request-error`. | String |

#### `network` kind

| Field name | Description | Type |
|------------|-------------|------|
| `level` | Criticality level of the log entry, following the standard syslog severity values: `6` (info). | Number |
| `serviceName` | Internal name of your server, in the form `nsxxxxx.ip-xx-xx-xx.eu`. | String |
| `status` | Current step of the operation, in the form `<operation>-doing` (started) or `<operation>-ok` (successful). Operations: `add_ipfo`, `remove_ipfo`, `add_vmac`, `remove_vmac`, `vrack-add`, `vrack-remove`, `ola-group`, `ola-ungroup`, `qos-apply`. | String |

:::info
The list of `status` values above is the current one and will evolve over time.
:::

For the fields common to every log, refer to the [field naming convention](/guides/manage-and-operate/observability/logs-data-platform/field-naming-conventions) guide.

## Instructions

The forwarding activation is free of charge, but you will be charged for the usage of the Logs Data Platform service as per the standard price plan. For LDP pricing, refer to the [Logs Data Platform](/links/manage-operate/ldp) service page.

### Enabling logs forwarding

{/* CP-STEPS-START:enable-logs-forwarding */}

<Tabs>
<Tab label="Via the OVHcloud Console">

In the OVHcloud Console, open the <code className="action">Bare Metal Cloud</code> universe, go to <code className="action">Dedicated servers</code>, then select the server whose logs you want to forward.

Click the <code className="action">Logs</code> tab.

The tab contains:

- a **Log type** drop-down list, from which you select the kind of logs you want to view or forward (`netboot`, `network` or `install`);
- the **Live tail** section, which displays the logs of your server in real time for the selected log type;
- the **Logs** section, which lists your active subscriptions and lets you create new ones.

To forward your logs to Logs Data Platform, select the log type, then click <code className="action">Add subscription</code> in the **Logs** section.

In the **Subscribe to a stream** window, select your Logs Data Platform account from the **Logs Data Platform service** drop-down list, then select the target data stream from the **Stream** drop-down list. Click <code className="action">Subscribe</code>.

Only the logs generated **after** the subscription is created are sent to your data stream.

For more information on OVHcloud Service Logs, shared by all compatible OVHcloud products, refer to the [Introduction to OVHcloud Service Logs with Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/service-logs) guide.

</Tab>
<Tab label="OVHcloud API">

Define, in one of your LDP accounts, the target *Stream* to which you want your logs forwarded. Enabling the forwarding creates a subscription for this stream ID.

#### Step 1 - Retrieve your target Stream (and ID)

List the data streams of your Logs Data Platform account (enter your LDP ID in the form `ldp-xx-xxxx` into the `serviceName` field):

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/output/graylog/stream"} />

Get the details of a data stream:

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/output/graylog/stream/\{streamId\}"} />

#### Step 2 - Create your subscription

Use the following API call to create a subscription:

<Api version="v2" section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/log/subscription"} />

:::info
Replace:

- `serviceName`: this is the internal name of your Dedicated Server, in the form `nsxxxxx.ip-xx-xx-xx.eu`. You can find it in the dedicated server list or on the server page in the OVHcloud Console or using the following API call:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server"} />
:::

The POST request has a payload that requires:

- `kind`: the kind of log you want to forward (`install`, `netboot` or `network`). See [Log kinds](#log-kinds) above.
- `streamId`: the target data stream of your LDP account to which you want your Dedicated Server logs forwarded.

```shell
POST /dedicated/server/{serviceName}/log/subscription
{
  "kind": "install", // One of: install, netboot, network.
  "streamId": "198ef9d5-c320-4000-8bee-236623da5b80" // The streamID of the targeted Stream.
}
```

You will get an `operationId` in response:

```shell
{
  "operationId": "f550aa1c-89ab-4b1a-81ae-4fba4959966f",
  "serviceName": "ldp-xx-xxxx"
}
```

You can use the `operationId` to retrieve the `subscriptionId` for further management purposes using the following API call:

<Api version="v1" section="/dbaas/logs" method="GET" route={"/dbaas/logs/\{serviceName\}/operation/\{operationId\}"} />

Alternatively, once the operation is finished, retrieve the subscriptions with the following API call:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/subscription"} />

Once you have the `subscriptionId`, you can get the details using the following API call:

<Api version="v2" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/log/subscription/\{subscriptionId\}"} />

```shell
GET /dedicated/server/{serviceName}/log/subscription/{subscriptionId}

{
  "createdAt": "2026-08-31T07:42:50.645Z",
  "kind": "string",
  "resource": {
    "name": "string",
    "type": "string"
  },
  "serviceName": "string",
  "streamId": "string",
  "subscriptionId": "198efa11-f150-4000-8e8d-871b1e482b80",
  "updatedAt": "2026-08-31T07:42:50.645Z"
}
```

### Using your Dedicated Server logs

Now that your logs are ingested and stored in your Logs Data Platform data stream, you can query them and build dashboards in the Graylog web interface.

{/* CP-STEPS-START:retrieve-ldp-credentials */}

- Retrieve the username of your Logs Data Platform account (for example `logs-xxxx`) and its password. In the OVHcloud Console, open <code className="action">Observability</code>, click <code className="action">Service management</code> and select your Logs Data Platform service: the username is shown as **LDP username** in the **General information** section (services that do not use OVHcloud IAM only). The password is the one you set for this account. You can refer to the [Quick start for Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/getting-started-quick-start).
- Open the Graylog web UI. You can reach it from the Graylog dashboards listed under <code className="action">Observability</code> > <code className="action">Dashboards</code> in the OVHcloud Console, or using your access point, depending on your account region (for example, the Gravelines region is `https://gra1.logs.ovh.com/`).
- Log in to Graylog using your Logs Data Platform username and password.
- Search through your logs across the data stream of your Logs Data Platform account. Refer to the [Search Syntax Reference](https://go2docs.graylog.org/current/making_sense_of_your_log_data/search_syntax_reference.htm) documentation for details on the search syntax.

{/* CP-STEPS-END:retrieve-ldp-credentials */}

For more details about how to use your logs with Logs Data Platform, including how to set up alerts, view the logs in real time through a WebSocket, build visualisations with OpenSearch Dashboards, integrate with the OpenSearch API and connect with Grafana, refer to the [Introduction to Logs Data Platform](/guides/manage-and-operate/observability/logs-data-platform/introduction).

### Managing your subscriptions

At any time, you can retrieve the subscriptions attached to your Logs Data Platform data stream and disable the forwarding by cancelling your subscription on your stream, so that your Logs Data Platform stream no longer receives your Dedicated Server logs.

This does not delete the logs stored before the subscription was cancelled, as the data stored in a log stream is immutable unless you delete the entire stream.

To delete your subscription, use the following API call:

<Api version="v2" section="/dedicated/server" method="DELETE" route={"/dedicated/server/\{serviceName\}/log/subscription/\{subscriptionId\}"} />
