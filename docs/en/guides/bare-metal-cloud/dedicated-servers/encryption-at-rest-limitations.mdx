## Objective

**This guide lists the conditions a dedicated server must meet to use Encryption at Rest, and the limitations that currently apply.**

:::info
The encryption keys are generated, stored and rotated by OVHcloud. Using your own keys is not available. For more information, read [What is Encryption at Rest on a dedicated server?](./encryption-at-rest-overview)
:::

## Requirements

- A [dedicated server](/links/bare-metal/bare-metal) in your OVHcloud account

## Instructions

The tables below summarise eligibility and limitations. Check them before you enable Encryption at Rest.

### Eligibility

A server must meet every condition below:

| Topic | Condition |
|---|---|
| **Range** | Scale dedicated servers. Other ranges are not eligible yet. [TODO: R-4 — confirm the eligible plans at GA; QA Campaign C1 tested Scale gen 3 Intel (26scaleintel*) and AMD (26scaleamd*)] |
| **Region** | Europe and Canada: Roubaix, Gravelines, Strasbourg, Paris, Limburg, Erith, Warsaw, Beauharnois and Toronto datacentres. Other regions are not available yet. |
| **Boot** | The server boots through the standard OVHcloud network boot. |
| **Network** | OVHcloud Link Aggregation (OLA) is not enabled. |
| **Server state** | The server is in service. Encryption at Rest cannot be enabled on a suspended or blocked server. |

To check a given server, use the eligibility check of the [OVHcloud API](./encryption-at-rest-api#eligibility-check).

### Incompatibilities

Some features cannot be combined with Encryption at Rest:

| Feature | Status |
|---|---|
| **OVHcloud Link Aggregation (OLA)** | Not compatible. Using both requires the Private Boot feature, which is not available yet. Until then, the two features are mutually exclusive. |
| **Custom boot script** | Not compatible. |
| **Windows rescue mode** | Not compatible. The Linux rescue mode is supported, and the disks are unlocked automatically, as at a normal boot. |

### Limitations

The following limitations apply:

| Topic | Limitation |
|---|---|
| **Granularity** | All the disks of the server, or none. You cannot select disks one by one. |
| **Scheduling** | The operation starts immediately. It cannot be scheduled or tied to a maintenance window. |
| **Duration** | Up to 24 hours from end to end, longer if an intervention in the datacentre is needed. Other operations on the server are refused while it runs. |
| **Data** | Enabling erases all the data and requires an OS reinstall. Disabling erases the disks through a cryptographic erase and also requires an OS reinstall. |

| **Keys** | Managed by OVHcloud only. Customer keys and manual unlocking are not available. |
| **Notifications** | No alerts on unlock events. |
