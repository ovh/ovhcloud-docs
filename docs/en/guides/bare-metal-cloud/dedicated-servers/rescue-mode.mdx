## Objective

Rescue mode is a tool provided by OVHcloud that allows you to boot into a temporary operating system for the purpose of diagnosing and resolving issues on your server.

Usual tasks the rescue mode is appropriate for include:

- [Resetting your user password](/guides/bare-metal-cloud/dedicated-servers/replacing-user-password)
- [Diagnosing network problems](/guides/bare-metal-cloud/dedicated-servers/hardware-diagnose)
- Repairing a broken operating system
- Fixing a software firewall misconfiguration
- [Testing disk performance](/guides/bare-metal-cloud/dedicated-servers/hardware-diagnose)
- [Testing CPU and RAM](/guides/bare-metal-cloud/dedicated-servers/hardware-diagnose)

:::warning
Backing up your data should be the first step in rescue mode if you do not already have recent backups available.

If you have any services still online, rescue mode will interrupt them as the machine is being rebooted into the auxiliary rescue environment.

:::


**This guide explains how to boot a server into rescue mode and how to use it.**

## Requirements

- A [dedicated server](/links/bare-metal/bare-metal) in your OVHcloud account

[[cpnav:baremetal-dedicated-servers|en]]

## Instructions

{/* CP-STEPS-START:instructions-open-server */}

To use rescue mode, you need to change the server's **Boot mode** setting. Then the server has to be restarted.

Click on your server's name. The server opens on the <code className="action">Overview</code> tab, where the **General information** section shows the server's current boot mode.

{/* CP-STEPS-END:instructions-open-server */}

### Activating rescue mode

{/* CP-STEPS-START:activate-rescue */}

In the **General information** section, click the <code className="action">Rescue mode</code> link on the **Boot Mode** row. The **Server** tab opens on the **Boot mode** setting of the **System** section. You can also click the <code className="action">Server</code> tab and go to the **Boot mode** setting directly.

{/* CP-STEPS-END:activate-rescue */}

<a name="netboot"></a>

#### 1: Rescue mode options

{/* CP-STEPS-START:rescue-mode-options */}

In the **Boot mode** setting, select the <code className="action">Rescue mode</code> option.

The available options for rescue mode depend on the server type and the **operating system** installed. They are listed in the **Rescue kernel** drop-down list:

- Customer rescue system (always available)
- Rescue system for Windows (available for Windows servers)
- [iPXE](https://ipxe.org) / ipxe-shell (external open-source tool, depending on your server)
- [Legacy Windows rescue system](#windows_legacy) (deprecated WinPE system, only relevant if your server does not meet the requirements for the current rescue system for Windows)

:::info
The instructions below will only cover the **customer rescue system** which is the most commonly used option.

Please refer to our [dedicated guide for a detailed explanation on using the **rescue system for Windows**](/guides/bare-metal-cloud/dedicated-servers/rescue-customer-windows).

:::


From the **Rescue kernel** drop-down list, select <code className="action">Customer rescue system (Debian-12-based)</code>.

{/* CP-STEPS-END:rescue-mode-options */}

#### 2: Authentication options

{/* CP-STEPS-START:authentication-options */}

The next choice, under **Authentication method**, determines the method of authentication for the SSH connection to the rescue mode system. This is mainly a matter of convenience since each rescue mode session is meant to be transitory and will be discarded once you reboot the server from its disk.

- **Password**: You will be sent login credentials via email.
- **SSH key**: You can use a public authentication key of your choice (compatible formats: `RSA`, `ECDSA`, `ED25519`).

Click on the relevant tab for your connection method:

<Tabs>
  <Tab label="Password authentication">
    Under **Authentication method**, select <code className="action">Password</code>.

The rescue mode notification email including its login details will be sent to the contact email address of your OVHcloud account. To use a different email address, enter it in the **Rescue email** field.
  </Tab>
  <Tab label="Key authentication">
    Under **Authentication method**, select <code className="action">SSH key</code>.

Select a key from the **SSH key** drop-down list. It lists the public keys registered in your OVHcloud account, so you need to have at least one [public key stored in the OVHcloud Console](/guides/bare-metal-cloud/dedicated-servers/import-keys-control-panel) already. To register a key, click <code className="action">Add SSH key</code> in the **SSH keys** row of the **Server connection** section (**Server** tab).
    
    To find out more about this topic, consult our guides:
    
    - [How to create and use keys for SSH authentication](/guides/bare-metal-cloud/dedicated-servers/creating-ssh-keys)
    - [How to create and use keys for SSH authentication with PuTTY](/guides/web-cloud/web-hosting/ssh-using-putty-on-windows)
    
    :::tip
    You can add a default public key for the customer rescue system to a server via the OVHcloud API. See the [guide section below](#rescuessh) for details.

    :::

  </Tab>
</Tabs>

{/* CP-STEPS-END:authentication-options */}


#### 3: Final steps to activate rescue mode

{/* CP-STEPS-START:activate-final-steps */}

Click <code className="action">Apply</code> at the bottom of the **Boot mode** setting. In the **Apply boot mode change** window, check the current and new boot modes, then click <code className="action">Apply</code>.

The new boot mode takes effect at the next reboot.

The final step is to restart the server. In the **Reboot to apply** window, click <code className="action">Reboot now</code>. If you reboot later, click the <code className="action">Reboot</code> link on the **Boot Mode** row of the **General information** section (**Overview** tab), then click <code className="action">Reboot</code> in the confirmation window.

This "hard reboot" will take a few minutes to complete. You can check the current status in the <code className="action">Activities</code> tab.

:::info
After you have finished your actions in rescue mode, remember to change the **Boot mode** setting back to <code className="action">Boot from hard disk</code> before restarting the server.

:::

{/* CP-STEPS-END:activate-final-steps */}


### Accessing your server in rescue mode via SSH

{/* CP-STEPS-START:access-service-emails */}

Once you have received the email informing you that rescue mode is enabled, you can log on to the rescue mode system and access your server.  
This email is also available in the <ManagerLink to="/">OVHcloud Console</ManagerLink> as soon as it is sent. Open the account menu in the top right-hand corner, then click <code className="action">My messages</code> under **Quick access**. The email is listed in the **Messages** tab of the **Communications** page.

{/* CP-STEPS-END:access-service-emails */}

:::info
Your SSH client will normally block the connection at first due to a mismatch of the ECDSA fingerprint. This is normal because the rescue mode uses its own temporary SSH server. To resolve this, you need to edit the file `known_hosts` of your local `.ssh` folder.  
You have two options:

- **Delete the fingerprint from the file.** Your SSH client will then add a new fingerprint entry for the server when you are no longer using rescue mode. For a detailed explanation, refer to the section "Login and fingerprint" in our [SSH introduction guide](/guides/bare-metal-cloud/dedicated-servers/ssh-introduction).

- **Temporarily disable the fingerprint.** Open the file `known_hosts` with a text editor and identify the fingerprint string of your server by its IP address. Add the character `#` at the start of the line. As a result, this line is now a "comment" and will be ignored by applications reading the file. Remember to revert this change before switching the boot mode back to the hard disk.

:::


Click on the relevant tab for your selected connection method:

<Tabs>
  <Tab label="Password authentication">
    Open the command line application on your local device and enter the following command:
    
    ```bash
    ssh root@SERVER_IP
    ```
    
    Example:
    
    ```bash
    ssh root@203.0.113.100
    ```
    
    Enter the temporary rescue mode password when prompted.
    
    ```console
    root@ns9356771.ip-203-0-113.eu's password:
    root@rescue-customer-eu (ns9356771.ip-203-0-113.eu) ~ #
    ```
    
    Find more information about SSH connections in our [SSH introduction guide](/guides/bare-metal-cloud/dedicated-servers/ssh-introduction).  
    You can also use any SSH connection tool, such as [PuTTY](/guides/web-cloud/web-hosting/ssh-using-putty-on-windows).
  </Tab>
  <Tab label="Key authentication">
    Open the command line application on your local device and enter the following command:
    
    ```bash
    ssh -i USER_FOLDER/.ssh/KEY_FILE_NAME root@SERVER_IP
    ```
    
    Example:
    
    ```bash
    ssh -i ~/.ssh/MyAuthKey root@203.0.113.100
    ```
    
    If prompted, enter your password to decrypt the private key file.
    
    To learn more about this topic, consult our guides:
    
    - [How to create and use keys for SSH authentication](/guides/bare-metal-cloud/dedicated-servers/creating-ssh-keys)
    - [How to create and use keys for SSH authentication with PuTTY](/guides/web-cloud/web-hosting/ssh-using-putty-on-windows)
  </Tab>
</Tabs>



### Mounting partitions to access your files

Unless you intend to configure the server's disks in a way that requires them to be detached (unmounted), you need to first **mount the system partition** in order to access your data from rescue mode.

Firstly, list all partitions in order to retrieve the name of the partition you need to mount:

```bash
lsblk
```

Output examples:

```console
NAME      MAJ:MIN RM  SIZE RO TYPE  MOUNTPOINT
sda         8:0    0  1.8T  0 disk
├─sda1      8:1    0  511M  0 part
├─sda2      8:2    0  1.8T  0 part
│ └─md127   9:127  0  1.8T  0 raid1
├─sda3      8:3    0  512M  0 part
└─sda4      8:4    0    2M  0 part
sdb         8:16   0  1.8T  0 disk
├─sdb1      8:17   0  511M  0 part
├─sdb2      8:18   0  1.8T  0 part
│ └─md127   9:127  0  1.8T  0 raid1
└─sdb3      8:19   0  512M  0 part
```

```console
NAME        MAJ:MIN RM   SIZE RO TYPE  MOUNTPOINT
nvme1n1     259:0    0 894.3G  0 disk
├─nvme1n1p1 259:2    0   511M  0 part
├─nvme1n1p2 259:3    0     1G  0 part
│ └─md2       9:2    0  1022M  0 raid1
├─nvme1n1p3 259:4    0 892.3G  0 part
│ └─md3       9:3    0 892.1G  0 raid1
└─nvme1n1p4 259:5    0   512M  0 part
nvme0n1     259:1    0 894.3G  0 disk
├─nvme0n1p1 259:6    0   511M  0 part
├─nvme0n1p2 259:7    0     1G  0 part
│ └─md2       9:2    0  1022M  0 raid1
├─nvme0n1p3 259:8    0 892.3G  0 part
│ └─md3       9:3    0 892.1G  0 raid1
├─nvme0n1p4 259:9    0   512M  0 part
└─nvme0n1p5 259:10   0     2M  0 part
```

Then mount the pertinent partition accordingly:

```bash
mount /dev/PARTITION_NAME /MOUNT_POINT/
```

The partition to mount should be easily identifiable by the **SIZE** indicated in the table (`sda2` in the first example, `nvme1n1p3` in the second). However, in a [softRAID configuration](/guides/bare-metal-cloud/dedicated-servers/raid-soft) (a default `raid1` in the examples), you will need to use the identifier of the RAID volume (`mdX`).  
Using the folder name `mnt` as mount point, for the first example the `mount` command would therefore be as follows:

```bash
mount /dev/md127 /mnt/
```

Command to enter for the second example:

```bash
mount /dev/md3 /mnt/
```

:::warning
The examples above are merely illustrating the necessary steps based on a typical server configuration. The information in the output table depends on your server's hardware and its partition scheme. When in doubt, consult the documentation of your operating system.

If you require professional assistance with server administration, consider the details in the [Go further](#gofurther) section of this guide.

:::


To see more technical information about the server's disks and partitions, enter:

```bash
fdisk -l
```

Some tasks may require that disks or partitions are detached. To do this, use the unmount command:

```bash
umount /mnt
```

#### VMware - Mounting a datastore

<details>

<summary>Unfold this section</summary>


You can mount a VMware datastore in a similar way as described in the previous segment.

List your partitions in order to retrieve the name of the datastore partition:

```bash
lsblk
```

```bash
fdisk -l
```

Mount the partition with the following command, replacing `sdbX` with the value identified in the previous step:

```bash
vmfs-fuse /dev/sdbX /mnt
```

If you have `VMFS 6` datastores, access the `sbin` folder and create the mount folder:

```bash
cd /usr/local/sbin/
mkdir /mnt/datastore
```

List your partitions in order to retrieve the name of the datastore partition:

```bash
lsblk
```

```bash
fdisk -l
```

Mount the partition with the following command, replacing `sdbX` with the value identified in the previous step:

```bash
vmfs6-fuse /dev/sdbX /mnt/datastore/
```

</details>


Once the mounting operation is done, you can access your files and carry out troubleshooting tasks inside the folder you have defined as mount point. Example:

```bash
cd /mnt
```

Certain operations on the file system (such as configuring user accounts) will require an additional step. Create a temporary `chroot` environment at the mount point with this command:

```bash
chroot /mnt/
```

You should now be able now apply all necessary changes to your system, for example to [regain server access](#gofurther).

### Link Aggregation configuration in rescue mode

Link Aggregation (LACP) is highly beneficial, as it increases your server's total bandwidth while providing network redundancy in case a network interface fails.

Although rescue mode is based on the Debian 12 operating system, its network configuration relies on the `ifupdown` utility, instead of `Netplan`.

If you have a server that supports link aggregation and you wish to configure it in rescue mode, please refer to [this guide](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-ifupdown).

### Exiting rescue mode

If relevant, return to the rescue mode login shell by entering:

```bash
exit
```

{/* CP-STEPS-START:exit-rescue */}

In the <ManagerLink to="/">OVHcloud Console</ManagerLink>, go to the [Boot mode](#netboot) setting of your server's **Server** tab, select <code className="action">Boot from hard disk</code> and click <code className="action">Apply</code>. Click <code className="action">Apply</code> again in the **Apply boot mode change** window.

You can now restart the server from the rescue mode shell:

```bash
reboot
```

Alternatively, click <code className="action">Reboot now</code> in the **Reboot to apply** window, or use the <code className="action">Reboot</code> link on the **Boot Mode** row of the **General information** section in the OVHcloud Console.

{/* CP-STEPS-END:exit-rescue */}

### How to add a default authentication key for rescue mode

<details>

<summary>Unfold this section</summary>


To speed up the process, you can add a public key as default for rescue mode SSH access to your server. This is only possible via the [OVHcloud API](/guides/manage-and-operate/api/first-steps).

To do this in the API web console, open the following API endpoint:

<Api version="v1" section="/dedicated/server" method="PUT" route={"/dedicated/server/\{serviceName\}"} />

Enter the internal name of your server (`ns1111111.ip-203-0-113.eu`) in the appropriate field.

Then edit the text field below as follows:

```bash
{
  "rescueSshKey": "string"
}
```

Replace `string` with your full public key string.

The result should look as shown in the following example:

<img className="thumbnail" alt="rescue key example" src="/images/bare-metal-cloud/dedicated-servers/rescue-mode/rescue-mode-008.png" loading="lazy" />

When you have entered your values correctly, click the button <code className="action">EXECUTE</code>.

This key is then used for SSH access to the customer rescue system when you [activate rescue mode](#netboot).

</details>
