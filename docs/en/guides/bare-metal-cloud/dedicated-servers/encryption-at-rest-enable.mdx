## Objective

Encryption at Rest encrypts all the disks of your Dedicated Server in hardware, with keys managed by OVHcloud. **This guide explains how to enable or disable Encryption at Rest from the OVHcloud Console and how to follow the operation.**

:::info
The encryption keys are generated, stored and rotated by OVHcloud. Using your own keys is not available. For more information, read [What is Encryption at Rest on a dedicated server?](/guides/bare-metal-cloud/dedicated-servers/encryption-at-rest-overview)

:::

:::danger
**Enabling or disabling Encryption at Rest erases all the data on the server.** Once the operation is complete, you must reinstall the operating system. Back up your data before you start: backing it up is your responsibility.

:::

## Requirements

- A [Dedicated Server](/links/bare-metal/bare-metal) on an eligible range and in an eligible region (see [Encryption at Rest requirements and limitations](/guides/bare-metal-cloud/dedicated-servers/encryption-at-rest-limitations))
- OVHcloud Link Aggregation (OLA) not enabled on the server
- A backup of your data

## Instructions

This section walks you through enabling Encryption at Rest, following the operation, and disabling it.

### Enabling Encryption at Rest

Open the <code className="action">Server</code> tab. The **Encryption at rest** line of the **Hardware** card shows the current state of the encryption.

1. Click <code className="action">Activate Encryption at rest</code>.
2. In the **Encryption at rest activation** window, read the warnings: operation duration, protection scope, OS reinstallation and data erasure.
3. Enter `ACTIVATE` in the confirmation field.
4. Click <code className="action">Activate Encryption at rest</code> to start the operation.

If OLA is enabled on the server, or if the server is suspended or blocked, the activation is not available. For more details, see [Encryption at Rest requirements and limitations](/guides/bare-metal-cloud/dedicated-servers/encryption-at-rest-limitations).

### Following the operation

The operation is asynchronous. The **Encryption at rest** line of the **Hardware** card shows its status:

| Status | Meaning |
|---|---|
| **Inactive** | Encryption at Rest is not enabled on the server. |
| **In progress** | An enabling or disabling operation is running. The server restarts on its own one or more times. |
| **Active** | The disks are encrypted and unlock automatically at each boot. |
| **Error** | The operation did not succeed and the server keeps its previous state. Try again, or contact support if the error persists. |

The operation can take up to 24 hours. If a datacentre intervention is needed, the operation stays in progress until the intervention is over, which can take longer. You do not need to do anything during the operation. While it runs, other operations on the server (reinstallation, reboot, etc.) are refused.

### Reinstalling the operating system

When the operation succeeds, the server restarts in rescue mode and you receive an email. The status shows **Active** (**Inactive** after disabling). Reinstall the operating system to put the server back into service. Then restore your data from your backup.

### Disabling Encryption at Rest

Disabling Encryption at Rest cryptographically erases the disks: the data is not decrypted in place. Back up your data before you start.

On the <code className="action">Server</code> tab, the **Encryption at rest** line of the **Hardware** card shows **Active**.

1. Click <code className="action">Deactivate Encryption at rest</code>.
2. In the **Encryption at rest deactivation** window, read the warnings: operation duration, server restart, end of the protection, OS reinstallation and data erasure.
3. Enter `DEACTIVATE` in the confirmation field.
4. Click <code className="action">Deactivate Encryption at rest</code> to start the operation.

The operation takes up to 24 hours. The server restarts and stays unavailable until it comes back up. The status shows **In progress**, then **Inactive** once the operation is complete. Then reinstall the operating system.

If the status shows **Error** while the disks are still encrypted, the <code className="action">Deactivate Encryption at rest</code> button stays available: you can request the operation again.
