## Objective

Encryption at Rest encrypts all the disks of your dedicated server in hardware, with keys managed by OVHcloud. **This guide explains how to enable Encryption at Rest from the <ManagerLink to="/">OVHcloud Console</ManagerLink> and how to follow the operation.**

:::info
The encryption keys are generated, stored and rotated by OVHcloud. Using your own keys is not available. For more information, read [What is Encryption at Rest on a dedicated server?](./encryption-at-rest-overview)
:::

:::danger
**Enabling Encryption at Rest erases all the data on the server.** Once the operation is complete, you must reinstall the operating system. Back up your data before you start: backing it up is your responsibility.
:::

## Requirements

- A [dedicated server](/links/bare-metal/bare-metal) on an eligible range and in an eligible region (see [Encryption at Rest requirements and limitations](./encryption-at-rest-limitations))
- OVHcloud Link Aggregation (OLA) not enabled on the server
- A backup of your data

## Instructions

This section walks you through enabling Encryption at Rest, then following the operation until the server is ready to be reinstalled.

### Enable Encryption at Rest

Select your server, then find the **Hardware** card on the server dashboard. The **Encryption at rest** line shows the current state of the encryption.

1. Click <code className="action">Activate Encryption at rest</code>.
2. In the **Encryption at rest activation** window, read the warnings: operation duration, protection scope, OS reinstallation and data erasure.
3. Enter `ACTIVATE` in the confirmation field.
4. Click <code className="action">Activate Encryption at rest</code> to start the operation.

If OLA is enabled on the server, or if the server is suspended or blocked, the activation is not available. For more details, see [Encryption at Rest requirements and limitations](./encryption-at-rest-limitations).

### Follow the operation

{/* REVIEW SK-2772: labels and statuses checked against the Console release deployed on 16 Nov 2026 (dedicated app 0.89.8, EU/CA/US): activation only, Enabled/Disabled. */}

The operation is asynchronous. The **Encryption at rest** line of the **Hardware** card shows its status:

| Status | Meaning |
|---|---|
| **Disabled** | Encryption at Rest is not enabled on the server. |
| **In progress** | The operation is running. The server restarts on its own one or more times. |
| **Enabled** | The disks are encrypted and unlock automatically at each boot. |
| **Error** | The operation did not succeed and the server keeps its previous state. Try again, or contact support if the error persists. |

The operation can take up to 24 hours. If a datacentre intervention is needed, the operation stays in progress until it is over, which can take longer. You do not need to do anything during the operation. While it runs, other operations on the server (reinstallation, reboot, etc.) are refused.

### Reinstall the operating system

When the operation succeeds, the server restarts in rescue mode and you receive an e-mail. The status shows **Enabled**. Reinstall the operating system to put the server back into service. Then restore your data from your backup.

### Disable Encryption at Rest

Disabling Encryption at Rest erases the disks through a cryptographic erase: the data is not decrypted in place. Back up your data before you start.

On the **Hardware** card, the **Encryption at rest** line shows **Active**.

1. Click <code className="action">Deactivate Encryption at rest</code>.
2. In the **Encryption at rest deactivation** window, read the warnings: operation duration, server restart, end of the protection, OS reinstallation and data erasure.
3. Enter `DEACTIVATE` in the confirmation field.
4. Click <code className="action">Deactivate Encryption at rest</code> to start the operation.

The operation takes up to 24 hours. The server restarts and stays unavailable until it comes back up. The status shows **In progress**, then **Inactive** once the operation is complete. Then reinstall the operating system.

If the status shows **Error** while the disks are still encrypted, the <code className="action">Deactivate Encryption at rest</code> button stays available: you can request the operation again.
