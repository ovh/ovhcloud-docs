## Objective

If you are configuring your dedicated server as a DNS server, you can make use of the OVHcloud Secondary DNS service to host a secondary zone. This way, DNS for your domain will remain available even if the primary DNS server should become unresponsive.

**This guide explains how to add your domain name in the OVHcloud Console in order to utilise an OVHcloud Secondary DNS server.**

## Requirements

- A domain name to which you have administrative access
- A [dedicated server](/links/bare-metal/bare-metal) in your OVHcloud account

:::warning
OVHcloud is providing you with services for which you are responsible, with regard to their configuration and management. You are therefore responsible for ensuring they function correctly.

This guide is designed to assist you in common tasks as much as possible. Nevertheless, we recommend that you contact a [specialist service provider](/links/partner) if you have difficulties or doubts concerning the administration, usage or implementation of services on a server.

:::

## Instructions

### Adding a domain name <a name="addingdomain"></a>

{/* CP-STEPS-START:add-domain */}


On the page of your dedicated server, click the <code className="action">Connectivity</code> tab. In the **DNS** section, under **Secondary DNS**, click <code className="action">Add a domain</code>.

In the **Add secondary DNS** window, follow the three steps:

1. Enter the domain name to add in the **Domain name** field, then click <code className="action">Next</code>.
2. Optionally, select the server IP address that will act as master from the **Master IP (optional)** drop-down list. Access is authorised per IP block. Click <code className="action">Next</code>.
3. Review your configuration, then click <code className="action">Add</code>. To change a value before confirming, click <code className="action">Previous</code>.

After you click <code className="action">Add</code>, the domain name is added to the OVHcloud Secondary DNS server.

Added domain names are listed under **Secondary DNS**. The **DNS server** column shows the name of the secondary DNS server next to each domain name. To delete a domain name, click the trash icon in the **Actions** column of its row.

{/* CP-STEPS-END:add-domain */}

:::info
Other actions required to configure your own DNS for your domain(s) usually include:

- Configuring a DNS service (such as *BIND*)
- Configuring GLUE records
- Authorising zone transfers

Please refer to the corresponding manuals and external knowledge resources if you need further instructions for these administrative tasks.

:::


### Verifying authorisation for the domain name <a name="verifyingdomain"></a>

{/* CP-STEPS-START:verify-domain */}


It is necessary to confirm your authorisation to manage the domain name before it can be added to OVHcloud Secondary DNS. This is achieved via an automated DNS lookup on the subdomain *ownercheck.yourdomainname*. A unique string of characters is generated for this purpose.

The **Add secondary DNS** window in the OVHcloud Console does not display this value. To retrieve it, use the following API call, indicating the internal server name (example: `ns3956771.ip-169-254-10.eu`) and the domain name in the `domain` parameter:

<Api version="v1" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/secondaryDnsNameDomainToken"} />

The response contains the record type (`TXT`), the subdomain (`ownercheck`) and the value to use.

- If the domain is managed by an external registrar or uses external DNS servers, log in to the control panel of your DNS provider and add a TXT record with the subdomain "ownercheck" and this value.

- If the domain is managed by OVHcloud as its registrar and it uses OVHcloud DNS servers, follow the instructions in [this guide](/guides/web-cloud/domains/dns-zone-edit) to add the TXT record in the <ManagerLink to="/">OVHcloud Console</ManagerLink>.

After successfully adding the TXT record to the domain name's DNS zone, repeat the [steps above](#addingdomain) and finish the process.

{/* CP-STEPS-END:verify-domain */}
