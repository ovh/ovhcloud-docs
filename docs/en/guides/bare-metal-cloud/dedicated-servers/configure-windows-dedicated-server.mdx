## Objective

Windows Server is a supported operating system on OVHcloud Dedicated Servers. Once installed, you must configure the Windows system so that it can use the OVHcloud network and storage services attached to the server.

This guide walks you through installing Windows Server from the OVHcloud Control Panel, connecting to it, and then performing the Windows-side configuration needed to interact with the main OVHcloud services bound to a dedicated server.

**In this guide, you will learn how to:**

- Install Windows Server from the Control Panel
- Connect to the server with Remote Desktop and complete the initial setup
- Configure Windows to use an Additional IP
- Configure Windows to use the vRack private network
- Configure Windows to use the IPv6 block delivered with the server
- Access OVHcloud Backup Storage from Windows

:::warning
Reinstalling an operating system erases all data on the server disks. Back up any data you want to keep before starting.
:::

## Requirements

- A [Dedicated Server](/links/bare-metal/bare-metal) in your OVHcloud account
- Access to the <ManagerLink to="/">OVHcloud Control Panel</ManagerLink>
- A valid Windows Server licence. Licences can be ordered through OVHcloud or applied from an external reseller — refer to the [Managing your OVHcloud licences](/guides/bare-metal-cloud/dedicated-servers/windows-key) guide.
- A Remote Desktop Protocol (RDP) client on your local machine (the <code className="action">Remote Desktop Connection</code> client is included with Windows)

## Introduction

A dedicated server is a physical ("bare metal") server hosted in an OVHcloud data centre. OVHcloud provides the hardware, the public network connection, an optional vRack private network, and a complimentary Backup Storage space. You are responsible for administering the operating system installed on the server, including all network and storage configuration inside Windows.

The services a Windows dedicated server commonly interacts with are summarised below.

| OVHcloud service | Purpose | Where it is enabled |
|---|---|---|
| Additional IP | Extra public IP addresses bound to the server | Control Panel — <code className="action">Network</code> tab |
| vRack | Private layer-2 network between OVHcloud services | Control Panel — <code className="action">Network</code> tab |
| IPv6 | The /64 IPv6 block delivered with every server | Delivered automatically |
| Backup Storage | Complimentary FTP/CIFS/NFS backup space | Control Panel — <code className="action">Hardware</code> tab |

### Step 1 — Install Windows Server from the Control Panel <a name="install"></a>

This step installs (or reinstalls) Windows Server on your dedicated server. The installation is driven entirely from the Control Panel.

Log in to the <ManagerLink to="/">OVHcloud Control Panel</ManagerLink> and navigate to **Bare Metal Cloud** > **Dedicated Servers**, then select your server. Open the <code className="action">System</code> tab.
Next to the operating system, click <code className="action">Install</code> (or <code className="action">Reinstall</code> if an operating system is already present). The <code className="action">Operating system installation</code> window opens and walks you through four steps.

:::warning
This action is irreversible. All data on the disks will be permanently deleted.
:::

1. **Operating system** — set <code className="action">Category</code> to a Windows category, then choose the Windows Server version from the <code className="action">Distribution</code> and <code className="action">Operating system</code> lists.
2. **Hardware RAID** — choose the RAID configuration on which Windows will be installed. For Soft RAID details on Windows, refer to the [Configuring software RAID on a Windows server](/guides/bare-metal-cloud/dedicated-servers/raid-soft-windows) guide.
3. **Partitions** — accept the default partition scheme, or enable <code className="action">Customize partition configuration</code> to define your own layout.
4. **Options** — review the summary and confirm any Windows-specific options.
Click <code className="action">Install</code> to start the installation. The server reboots into the installer and the process completes automatically.

:::info
Windows Server requires a licence, which generates additional fees. You can order a licence through OVHcloud or supply your own. Manage your licences under **Bare Metal Cloud** > **Licences**. For more information, refer to the [Managing your OVHcloud licences](/guides/bare-metal-cloud/dedicated-servers/windows-key) guide.
:::

### Step 2 — Connect to your server <a name="connect"></a>

Once the installation is complete, OVHcloud sends an email containing the administrator username and password for your Windows server.

On your local Windows machine, open the <code className="action">Remote Desktop Connection</code> client. Enter the IPv4 address of your server, then your username and password. A certificate warning usually appears the first time you connect — click <code className="action">Yes</code> to continue.
You can use any third-party RDP-compatible client if your local device does not run Windows.

:::tip
If RDP is unavailable — for example after a network misconfiguration — connect through the [Intelligent Platform Management Interface (IPMI) console](/guides/bare-metal-cloud/dedicated-servers/ipmi) from the <code className="action">Server</code> tab in the Control Panel (the <code className="action">Server connection</code> section). The IPMI console works regardless of the operating system's connectivity state.
:::

After your first connection, change the administrator password. For the procedure, refer to the [Changing the administrator password on Windows](/guides/bare-metal-cloud/dedicated-servers/changing-admin-password-on-windows) guide.

### Step 3 — Complete the initial Windows configuration <a name="initial-config"></a>

Before connecting the server to other OVHcloud services, complete the basic Windows setup.

- Run Windows Update and install the latest updates.
- Set the server host name, time zone and keyboard layout.
- Configure the Windows Firewall to allow the services you intend to run. For a Windows-specific firewall walkthrough, refer to the [Activating the firewall on a Windows server](/guides/bare-metal-cloud/dedicated-servers/activate-port-firewall-soft-win) guide.

:::warning
OVHcloud provides you with services for which you are responsible for the configuration and management. If you need specialised assistance, contact a [specialist service provider](/links/partner).
:::

### Step 4 — Configure Windows to interact with OVHcloud services <a name="services"></a>

This section covers the Windows-side configuration for the OVHcloud services most commonly attached to a dedicated server. Each sub-section is independent — follow only the ones relevant to your setup. In each one, the first part is done in the OVHcloud Control Panel and the second part inside Windows Server.

#### 4a — Additional IP

An Additional IP is an extra public IP address routed to your server. After ordering it, you must declare it inside Windows for the server to answer on that address.

**In the OVHcloud Control Panel**

Order the Additional IP from the <code className="action">Network</code> tab of your server (the <code className="action">Additional IPs</code> section). For more information, see the [Additional IP](/links/bare-metal/ip) page.

**In Windows Server**

1. Open <code className="action">Control Panel</code> > <code className="action">Network and Sharing Center</code> > <code className="action">Change adapter settings</code>, then open the properties of your network adapter.
2. Select <code className="action">Internet Protocol Version 4 (TCP/IPv4)</code> > <code className="action">Properties</code> > <code className="action">Advanced</code>, and add the Additional IP address.

On the OVHcloud network, an Additional IP is routed individually to the server. Use the netmask and gateway that match your server's main IP configuration.
:::tip
If you intend to assign the Additional IP to a virtual machine rather than the host, refer to the [Configuring an IP block in a vRack](/guides/bare-metal-cloud/dedicated-servers/configuring-an-ip-block-in-a-vrack) guide.
:::

#### 4b — vRack private network

The vRack is a private layer-2 network that lets your dedicated server communicate privately with other OVHcloud services (other dedicated servers, Public Cloud instances, and so on).

**In the OVHcloud Control Panel**

In the <code className="action">Network</code> tab of your server, click <code className="action">Attach a vRack</code> and select the target vRack.
**In Windows Server**

1. Open the properties of the **private** network adapter (the second interface, dedicated to the vRack).
2. Assign a static private IPv4 address from your vRack addressing plan. Leave the default gateway empty — the vRack is a layer-2 network with no OVHcloud-provided gateway.

For the full procedure, including OLA (link aggregation) considerations, refer to the [Configuring the vRack on a dedicated server](/guides/bare-metal-cloud/dedicated-servers/vrack-configuring-on-dedicated-server) guide.

#### 4c — IPv6

Every OVHcloud dedicated server is delivered with a /64 IPv6 block. The address is not configured automatically in Windows and must be added manually.

**In the OVHcloud Control Panel**

Retrieve your IPv6 address, prefix and gateway from the <code className="action">Network</code> tab of your server (the <code className="action">IP Addresses</code> section shows <code className="action">IPv6</code> and <code className="action">Gateway IPv6</code>).

**In Windows Server**

1. Open the properties of your network adapter and select <code className="action">Internet Protocol Version 6 (TCP/IPv6)</code> > <code className="action">Properties</code>.
2. Enter the IPv6 address, the prefix length, and the IPv6 default gateway.

For the addressing details and the gateway configuration specific to OVHcloud, refer to the [IPv6 configuration](/guides/bare-metal-cloud/dedicated-servers/network-ipv6) guide.
#### 4d — Backup Storage

Backup Storage is a complimentary storage space included with your dedicated server. It can be accessed over FTP, CIFS or NFS and is best used as a complementary backup target.

**In the OVHcloud Control Panel**

1. In the <code className="action">Hardware</code> tab of your server, click <code className="action">Enable backup storage</code>. Once active, the tab shows the FTP server address and username, and lets you set the password for the space.
2. Authorise your server's IP address to access the space.

**In Windows Server**

Access the space using one of the supported protocols:

- **CIFS** — map it as a network drive (<code className="action">This PC</code> > <code className="action">Map network drive</code>).
- **FTP** — connect with any FTP client, using the connection details from the Control Panel and the password you set.

For activation and protocol details, refer to the [Backup Storage on dedicated servers](/guides/bare-metal-cloud/dedicated-servers/services-backup-storage) guide and the [Backup Storage](/links/bare-metal/backup-storage) page.

### Step 5 — Verify the configuration <a name="verify"></a>

Confirm that each configured service works as expected.

| Check | How | Expected result |
|---|---|---|
| RDP access | Connect with <code className="action">Remote Desktop Connection</code> to the main IPv4 | Windows desktop loads |
| Additional IP | From an external host, `ping` the Additional IP | The server replies |
| vRack | From another vRack member, `ping` the private IP | The server replies |
| IPv6 | Run `ping -6 ipv6.google.com` from the server | Replies are received |
| Backup Storage | Open the mapped CIFS drive or connect over FTP | Files can be read and written |

### Troubleshooting <a name="troubleshooting"></a>

| Issue | Possible cause | Solution |
|---|---|---|
| RDP connection fails | Firewall rules or network restrictions on the local device | Verify local firewall and network settings; connect through the [IPMI console](/guides/bare-metal-cloud/dedicated-servers/ipmi) as a fallback. |
| Additional IP not reachable | Incorrect mask or gateway in Windows | Re-check the values entered in the advanced TCP/IPv4 settings. |
| vRack peer unreachable | Wrong private subnet or a gateway set on the private adapter | Confirm the private addressing plan and leave the gateway empty. |
| Server offline after a change | Misconfiguration during setup | Boot into [rescue mode](/guides/bare-metal-cloud/dedicated-servers/rescue-customer-windows) to inspect and repair the configuration. |
