## Objective

Windows Server is a supported operating system on OVHcloud Dedicated Servers. Once installed, you must configure the Windows system so that it can use the OVHcloud network and storage services attached to the server.

This guide walks you through installing Windows Server from the OVHcloud Console, connecting to it, and then performing the Windows-side configuration needed to interact with the main OVHcloud services bound to a dedicated server.

**In this guide, you will learn how to:**

- Install Windows Server from the OVHcloud Console
- Connect to the server with Remote Desktop and complete the initial setup
- Configure Windows to use an Additional IP
- Configure Windows to use the vRack private network
- Configure Windows to use the IPv6 block delivered with the server
- Access OVHcloud Backup Storage from Windows
- Protect the server with managed backups using OVHcloud Backup Agent

:::warning
Reinstalling an operating system erases all data on the server disks. Back up any data you want to keep before starting.
:::

## Requirements

- A [Dedicated Server](/links/bare-metal/bare-metal) in your OVHcloud account
- A valid Windows Server licence. Licences can be ordered through OVHcloud or applied from an external reseller — refer to the [Managing your OVHcloud licences](/guides/bare-metal-cloud/dedicated-servers/windows-key) guide.
- A Remote Desktop Protocol (RDP) client on your local machine (the <code className="action">Remote Desktop Connection</code> client is included with Windows)

## Introduction

A dedicated server is a physical ("bare metal") server hosted in an OVHcloud data centre. OVHcloud provides the hardware, the public network connection, an optional vRack private network, and a complimentary Backup Storage space. You are responsible for administering the operating system installed on the server, including all network and storage configuration inside Windows.

The services a Windows dedicated server commonly interacts with are summarised below.

{/* CP-STEPS-START:services-overview */}

| OVHcloud service | Purpose | Where it is enabled |
|---|---|---|
| Additional IP | Extra public IP addresses bound to the server | OVHcloud Console — <code className="action">Network</code> section of the left-hand menu, <code className="action">IP addresses</code> |
| vRack | Private layer-2 network between OVHcloud services | OVHcloud Console — <code className="action">Network</code> section of the left-hand menu, <code className="action">vRack</code> |
| IPv6 | The /64 IPv6 block delivered with every server | Delivered automatically |
| Backup Storage | Complimentary FTP/CIFS (SMB)/NFS backup space | OVHcloud Console — <ManagerLink to="/beta/#/bare-metal/dedicated-server">Dedicated servers</ManagerLink> > Select your server, <code className="action">Remote storage</code> tab |
| Backup Agent | Managed daily backups to an isolated, immutable Object Storage vault | OVHcloud Console — <code className="action">Backup</code> section of the left-hand menu, <code className="action">Backup Agent</code>. The server's <code className="action">Overview</code> tab shows its status in the **General information** section. |

{/* CP-STEPS-END:services-overview */}

### Step 1 — Install Windows Server from the OVHcloud Console <a name="install"></a>

In this step, you install (or reinstall) Windows Server on your dedicated server. The installation is driven entirely from the OVHcloud Console.

{/* CP-STEPS-START:install-windows-server */}

On the <code className="action">Overview</code> tab, in the **General information** section, click <code className="action">Reinstall</code> next to **OS**. The **OS Installation / Reinstallation** page opens and walks you through the steps **Operating system**, **Partitions**, **Options** and **Summary** (a **RAID** step is added on servers with a hardware RAID controller).

:::info
Windows Server requires a licence, which generates additional fees. Without a Windows Server licence attached to the server, the Windows templates are not offered in the operating-system list. You can order a licence through OVHcloud or supply your own. Manage your licences in the <code className="action">Licences</code> section of the left-hand menu of the OVHcloud Console. For more information, refer to the [Managing your OVHcloud licences](/guides/bare-metal-cloud/dedicated-servers/windows-key) guide.
:::

:::warning
This action is irreversible. All data on the disks will be permanently deleted.
:::

1. **Operating system** — in the **Category** drop-down list, choose the category that contains the Windows Server template you want, then select the template in the **Operating System** drop-down list. If your server has several disk groups, choose the one on which Windows will be installed under **Choose the disk group to install the OS on**. To define your own array or layout, tick **Configure hardware RAID** (only on servers with a hardware RAID controller) or **Customise partition configuration**. For Soft RAID details on Windows, refer to the [Configuring software RAID on a Windows server](/guides/bare-metal-cloud/dedicated-servers/raid-soft-windows) guide.
2. Click <code className="action">Next</code> to go through the remaining steps.
3. In the **Summary** step, review your choices, tick **I understand that all data on the disks will be permanently deleted.**, then click <code className="action">Install</code> to start the installation.

{/* CP-STEPS-END:install-windows-server */}

The server reboots into the installer and the process completes automatically.

### Step 2 — Connect to your server <a name="connect"></a>

Once the installation is complete, OVHcloud sends an email containing the administrator username and password for your Windows server.

On your local Windows machine, open the <code className="action">Remote Desktop Connection</code> client. Enter the IPv4 address of your server, then your username and password. A certificate warning usually appears the first time you connect — click <code className="action">Yes</code> to continue.
You can use any third-party RDP-compatible client if your local device does not run Windows.

{/* CP-STEPS-START:ipmi-fallback */}

:::tip
If RDP is unavailable — for example after a network misconfiguration — connect through the [Intelligent Platform Management Interface (IPMI) console](/guides/bare-metal-cloud/dedicated-servers/ipmi), from the **Server connection** section of the <code className="action">Server</code> tab of your server in the OVHcloud Console. The IPMI console works regardless of the operating system's connectivity state.
:::

{/* CP-STEPS-END:ipmi-fallback */}

After your first connection, change the administrator password from within Windows (in the RDP session, press `Ctrl` + `Alt` + `End` > <code className="action">Change a password</code>).

### Step 3 — Complete the initial Windows configuration <a name="initial-config"></a>

Before connecting the server to other OVHcloud services, complete the basic Windows setup.

- Run Windows Update and install the latest updates.
- Set the server host name, time zone and keyboard layout.
- Configure the Windows Firewall to allow the services you intend to run. For a Windows-specific firewall walkthrough, refer to the [Activating the firewall on a Windows server](/guides/bare-metal-cloud/dedicated-servers/activate-port-firewall-soft-win) guide.

:::warning
OVHcloud provides you with services for which you are responsible for the configuration and management. If you need assistance, contact a [specialist service provider](/links/partner).
:::

### Step 4 — Configure Windows to interact with OVHcloud services <a name="services"></a>

This section covers the Windows-side configuration for the OVHcloud services most commonly attached to a dedicated server. Each sub-section is independent — follow only the ones relevant to your setup. In each one, the first part is done in the OVHcloud Console and the second part inside Windows Server.

#### 4a — Additional IP

An Additional IP is an extra public IP address routed to your server. After ordering it, you must declare it inside Windows for the server to answer on that address.

{/* CP-STEPS-START:additional-ip-cp */}

**In the OVHcloud Console**

Order the Additional IP from the <code className="action">Network</code> section of the left-hand menu of the OVHcloud Console: select <code className="action">IP addresses</code>, click <code className="action">Order an IP</code>, then <code className="action">Order an Additional IP</code>. For more information, see the [Additional IP](/links/bare-metal/ip) page.

{/* CP-STEPS-END:additional-ip-cp */}

**In Windows Server**

1. Open <code className="action">Control Panel</code> > <code className="action">Network and Sharing Center</code> > <code className="action">Change adapter settings</code>, then open the properties of your network adapter.
2. Select <code className="action">Internet Protocol Version 4 (TCP/IPv4)</code> > <code className="action">Properties</code> > <code className="action">Advanced</code>, and add the Additional IP address.

On the OVHcloud network, an Additional IP is routed individually to the server. Use the netmask and gateway that match your server's main IP configuration.

:::tip
If you intend to assign the Additional IP to a virtual machine rather than the host, refer to the [Configuring an IP block in a vRack](/guides/bare-metal-cloud/dedicated-servers/configuring-an-ip-block-in-a-vrack) guide.
:::

#### 4b — vRack private network

The vRack is a private layer-2 network that lets your dedicated server communicate privately with other OVHcloud services (other dedicated servers, Public Cloud instances, and so on).

{/* CP-STEPS-START:vrack-cp */}

**In the OVHcloud Console**

In the <code className="action">Network</code> section of the left-hand menu of the OVHcloud Console, select <code className="action">vRack</code>, then your vRack. On the <code className="action">Attached services</code> tab, click <code className="action">Attach a service</code>, select **Dedicated Servers** in the **Service type** drop-down list, then click <code className="action">Attach</code> on the row of this server and confirm.

{/* CP-STEPS-END:vrack-cp */}

**In Windows Server**

1. Open the properties of the **private** network adapter (the second interface, dedicated to the vRack).
2. Assign a static private IPv4 address from your vRack addressing plan. Leave the default gateway empty — the vRack is a layer-2 network with no OVHcloud-provided gateway.

For the full procedure, including OVHcloud Link Aggregation (OLA) considerations, refer to the [Configuring the vRack on a dedicated server](/guides/bare-metal-cloud/dedicated-servers/vrack-configuring-on-dedicated-server) guide.

#### 4c — IPv6

Every OVHcloud dedicated server is delivered with a /64 IPv6 block. The address is not configured automatically in Windows and must be added manually.

{/* CP-STEPS-START:ipv6-cp */}

**In the OVHcloud Console**

Retrieve your IPv6 address, prefix and gateway from the <code className="action">Connectivity</code> tab of your server: the **Public interface** section shows **IPv6** and **Gateway IPv6**.

{/* CP-STEPS-END:ipv6-cp */}

**In Windows Server**

1. Open the properties of your network adapter and select <code className="action">Internet Protocol Version 6 (TCP/IPv6)</code> > <code className="action">Properties</code>.
2. Enter the IPv6 address, the prefix length, and the IPv6 default gateway.

For the addressing details and the gateway configuration specific to OVHcloud, refer to the [IPv6 configuration](/guides/bare-metal-cloud/dedicated-servers/network-ipv6) guide.

#### 4d — Backup Storage

Backup Storage is a complimentary storage space included with your dedicated server. It can be accessed over FTP, CIFS (SMB) or NFS and is best used as a complementary backup target.

{/* CP-STEPS-START:backup-storage-cp */}

**In the OVHcloud Console**

1. On the <code className="action">Remote storage</code> tab of your server, click <code className="action">Activate Backup FTP</code>. Once active, the tab shows the storage server address in the **Name** field. To get a password for the space, click <code className="action">Reset password</code>: a new password is sent to the email address of your OVHcloud account.
2. Authorise your server's IP address to access the space: in the **Access list** section, click <code className="action">Add an access</code>, select the IP block and the protocols, then click <code className="action">Add</code>.

{/* CP-STEPS-END:backup-storage-cp */}

**In Windows Server**

Access the space using one of the supported protocols:

- **CIFS (SMB)** — map it as a network drive (<code className="action">This PC</code> > <code className="action">Map network drive</code>).
- **FTP** — connect with any FTP client, using the connection details from the OVHcloud Console and the password you set.

For activation and protocol details, refer to the [Backup Storage on dedicated servers](/guides/bare-metal-cloud/dedicated-servers/services-backup-storage) guide and the [Backup Storage](/links/bare-metal/backup-storage) page.

#### 4e — Backup Agent

Backup Storage is a passive storage space — it does not back up your data by itself. For managed, automated protection, OVHcloud offers **Backup Agent**, a separate backup service for Bare Metal servers. Once ordered, you deploy a lightweight agent on your Windows server, which then performs daily incremental, encrypted and immutable backups to an isolated Object Storage vault located in a different region from the server.

{/* CP-STEPS-START:backup-agent-cp */}

**In the OVHcloud Console**

Manage Backup Agent from the <code className="action">Backup</code> section of the left-hand menu of the OVHcloud Console, by selecting <code className="action">Backup Agent</code>. The status of the agent for your server is shown in the **Backup Agent** row of the **General information** section, on the <code className="action">Overview</code> tab of the server. Backup Agent cannot be enabled during the OS reinstallation of a Windows server: install the agent once Windows is running.

{/* CP-STEPS-END:backup-agent-cp */}

**In Windows Server**

Once the agent is deployed, configure your first backup (source data, schedule and retention).

For the full procedure, refer to the [Backup Agent overview](/guides/storage-and-backup/backup-agent/overview) and the [How to configure your first backup](/guides/storage-and-backup/backup-agent/first-configuration) guide.

### Step 5 — Verify the configuration <a name="verify"></a>

Confirm that each configured service works as expected.

| Check | How | Expected result |
|---|---|---|
| RDP access | Connect with <code className="action">Remote Desktop Connection</code> to the main IPv4 | Windows desktop loads |
| Additional IP | From an external host, `ping` the Additional IP | The server replies |
| vRack | From another vRack member, `ping` the private IP | The server replies |
| IPv6 | Run `ping -6 ipv6.google.com` from the server | Replies are received |
| Backup Storage | Open the mapped CIFS (SMB) drive or connect over FTP | Files can be read and written |

### Troubleshooting <a name="troubleshooting"></a>

| Issue | Possible cause | Solution |
|---|---|---|
| RDP connection fails | Firewall rules or network restrictions on the local device | Verify local firewall and network settings; connect through the [IPMI console](/guides/bare-metal-cloud/dedicated-servers/ipmi) as a fallback. |
| Additional IP not reachable | Incorrect mask or gateway in Windows | Re-check the values entered in the advanced TCP/IPv4 settings. |
| vRack peer unreachable | Wrong private subnet or a gateway set on the private adapter | Confirm the private addressing plan and leave the gateway empty. |
| Server offline after a change | Misconfiguration during setup | Boot into [rescue mode](/guides/bare-metal-cloud/dedicated-servers/rescue-customer-windows) to inspect and repair the configuration. |
