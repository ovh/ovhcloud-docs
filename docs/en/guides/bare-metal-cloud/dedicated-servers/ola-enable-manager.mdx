## Objective

OVHcloud Link Aggregation (OLA) technology is designed by our teams to increase your server’s availability, and boost the efficiency of your network connections. In just a few clicks, you can aggregate your network cards and make your network links redundant. This means that if one link goes down, traffic is automatically redirected to another available link.<br/>
Aggregation uses the Link Aggregation Control Protocol (LACP), defined by the IEEE 802.3ad standard.

**This guide explains how to configure OLA in the OVHcloud Console.**

## Requirements

- A [dedicated server](/links/bare-metal/bare-metal) from the Advance, Scale, or High Grade ranges in your OVHcloud account
- An Operating System / Hypervisor that supports the 802.3ad aggregation protocol (LACP)

[[cpnav:baremetal-dedicated-servers|en]]

## Instructions

:::warning
OLA is configured on all network interfaces. They will form a “private aggregation”.

Following the implementation of OLA, the public IP will no longer be accessible.

:::


### Configuring OLA in the OVHcloud Console

{/* CP-STEPS-START:configure-ola */}

To start configuring OLA, open the <code className="action">Connectivity</code> tab on your server's management page.

In the **OVHcloud Link Aggregation (OLA)** section, click <code className="action">Configure OLA</code>.

In the **Configure OLA aggregation** window, enter a name for your link aggregation in the **Name the interface** field.

Below this field, two tables compare your configuration before and after aggregation:
- **Your current network interface**: the current configuration of your network interfaces;
- **Your network interface after activation**: the simulated configuration of your aggregated network interfaces.

:::warning
Your network interfaces will be unconfigured, and connectivity to your server is lost while the aggregation is being configured. For your network to work, you must follow the KVM IPMI procedure detailed in the OLA documentation. Without it, the configuration is not complete.
:::

Once you have verified that the aggregation layout matches your network requirements, click <code className="action">Aggregate</code> to proceed.

{/* CP-STEPS-END:configure-ola */}

This may take a few minutes. Once it is complete, the next step is to configure the interfaces in your operating system via a NIC link or NIC team. For the method to use, refer to the following guides for the most popular operating systems:

- [How to configure LACP link aggregation on Debian 9 to 11 (ifupdown)](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-ifupdown).
- [How to configure NIC teaming for OVHcloud Link Aggregation (OLA) on Windows Server 2019](/guides/bare-metal-cloud/dedicated-servers/ola-enable-w2k19).
- [How to configure LACP link aggregation on SLES 15](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-sles15).
- [How to configure LACP link aggregation on Debian 12 or newer / Ubuntu 24.04 or newer (Netplan)](/guides/bare-metal-cloud/dedicated-servers/lacp-enable-netplan).

### Checking the OLA status

{/* CP-STEPS-START:check-ola-status */}

You can verify your OVHcloud Link Aggregation (OLA) status in the <code className="action">Connectivity</code> tab of your server's management page. In the **OVHcloud Link Aggregation (OLA)** section, the **OLA** row shows the status and the **Mode** row shows the aggregation type.

The possible combinations are:
- **Available**, mode **Default**: OLA is supported but is not configured.
- **Active**, mode **Full private**: OLA is enabled; all physical interfaces are aggregated into a single private link for vRack use.
- **Available**, mode **Double LAG**: OLA is pre-enabled; physical interfaces are split into two separate aggregates (one public, one private).
- **Modifying**: an OLA configuration change is in progress.

If OLA is not supported on this dedicated server model, the **OVHcloud Link Aggregation (OLA)** section displays **OLA not included**, and the **OLA** row of the **Connectivity** section on the server's <code className="action">Overview</code> tab shows **Unavailable**.

:::info
The **Double LAG** mode is a specific configuration typically reserved for Scale and High-Grade server ranges, which feature four physical network interfaces.

:::

{/* CP-STEPS-END:check-ola-status */}

### Restoring OLA to default values

{/* CP-STEPS-START:restore-ola-default */}

To restore OLA to the default values, open the <code className="action">Connectivity</code> tab and click <code className="action">Reset</code> in the **OVHcloud Link Aggregation (OLA)** section. (This button is only shown when OLA is active in **Full private** mode.) Click <code className="action">Confirm</code> in the **Reset OVHcloud Link Aggregation** window.

This may take a few minutes.

{/* CP-STEPS-END:restore-ola-default */}
