## Objective

This guide explains the Network Security Dashboard and gives an overview of the countermeasures triggered by the OVHcloud Anti-DDoS infrastructure when malicious network activity is detected. It also describes the additional protections you can implement to keep your services up and running. Traffic charts are available on the dashboard for the periods when the scrubbing centres were active, to help you visualise the situation.

## Requirements

- An OVHcloud service exposed on a dedicated public IP address ([Dedicated Server](/links/bare-metal/bare-metal), [VPS](/links/bare-metal/vps), [Public Cloud instance](/links/public-cloud/public-cloud), [Hosted Private Cloud](/links/hosted-private-cloud/vmware), [Additional IP](/links/network/additional-ip), etc.)

## Instructions

### Network security

The OVHcloud Anti-DDoS infrastructure is a multi-layered, distributed defence system against cyberattacks. It consists of multiple edge locations and scrubbing centres that analyse incoming traffic and clean up malicious traffic. Together with the [Edge Network Firewall](/guides/bare-metal-cloud/dedicated-servers/firewall-network) and the [GAME DDoS protection](/guides/bare-metal-cloud/dedicated-servers/firewall-game-ddos), it protects a wide range of services.

The Anti-DDoS infrastructure constantly analyses incoming traffic (detection) and, when needed, redirects it through our scrubbing centres located in data centres around the world (mitigation). The traffic is then analysed in depth, and malicious packets are filtered out before the traffic reaches your server or service.

For network-intensive workloads whose legitimate traffic can look like an attack, such as VPN servers, game servers or Solana nodes, you can apply a network traffic profile to your IP addresses. Profiling only refines how your traffic is analysed and mitigated: the default protection of your services stays in place. For more information, see our guide on [Anti-DDoS profiling](/guides/bare-metal-cloud/dedicated-servers/anti-ddos-vac-profiling).

#### What happens when an attack reaches my service's IP address?

Every time an attack is detected towards an IP address of your service, you are notified by email that its traffic has been rerouted through the Anti-DDoS infrastructure. You can also monitor these periods, with additional details, on the Network Security Dashboard.

During an attack, in the <code className="action">Manage IPs</code> section of your Control Panel, the IP address shows **Active** in the **Anti-DDoS** column and **IP attacked (Anti-DDoS Mitigation)** in the **IP Alert** column.

:::info
To find out how OVHcloud mitigates DDoS attacks, see our [DDoS attack mitigation](/links/security/mitigation) page.
:::

:::warning
The protection logic is based on the public IP addresses associated with a server or service. As a result, statistics and charts are calculated and displayed on a per-IP basis.
:::

### Network security notifications

In the <code className="action">Manage IPs</code> section, the **Anti-DDoS**, **Edge Firewall** and **Game firewall** columns show the protection status of each IP address, and the **IP Alert** column shows its ongoing alerts.

- The **Anti-DDoS** column can show:
    - **Automatic** - The Anti-DDoS infrastructure automatically protects this IP address if an attack is detected.
    - **Active** - Suspicious traffic has been detected, and the scrubbing centres are **actively mitigating** the attack.
    - **Permanent** - The scrubbing centre is **permanently enabled** for this IP address. Use this mode with caution.
    - **In progress** - The Anti-DDoS configuration is being changed. The change is applied within a few moments.

- The **Edge Firewall** column shows the status of the Edge Network Firewall:
    - **Enabled** - The Edge Network Firewall is **filtering** incoming traffic to this IP address.
    - **Disabled** - Traffic only goes through the Edge Network Firewall when an attack is detected. The firewall is then activated automatically.
    - **In progress** - The Edge Network Firewall configuration is being changed. The change is applied within a few moments.

    To configure its rules, click the status, or click the `...` button at the end of the row, then <code className="action">Configure Edge Network Firewall</code>.

- The **Game firewall** column (only for [OVHcloud **Game** dedicated servers](/links/bare-metal/game)) can show:
    - **Available** - The GAME firewall is available but not configured yet. Configure your game rules to enable the protection.
    - **Configured** - The GAME firewall is configured for this IP address.
    - **In progress** - The GAME firewall configuration is being changed. The change is applied within a few moments.
    - **(empty)** - The GAME firewall is not available for this IP address, which means it is not configured on a supported product range.

    To configure it, click the status, or click the `...` button at the end of the row, then <code className="action">Configure Game firewall</code>.

- The **IP Alert** column can show **IP attacked (Anti-DDoS Mitigation)**, **IP blocked (anti-hack)** or **IP blocked (anti-spam)**.

### Network Security Dashboard

In the **Scrubbing Centre activity log** tab, you can find all the information about past and ongoing attacks.

The table contains the following columns:

- **Detection time** - Timestamp of the first attack detection.
- **End time** - Timestamp of when the scrubbing centre finished mitigating.
- **Destination IP** - The IP address targeted by the attack.
- **Attack vectors** - The types of attacks detected, such as UDP or TCP attacks.

**The data retention period for the scrubbing centre activity log is 1 year.**

:::warning
The source IP addresses of detected events are not displayed. They are usually spoofed (a DDoS attack can show sources other than the ones it really comes from), so this information would be misleading or unusable.
:::

In the **Traffic graphs** tab, a graph shows the traffic to your IP address, in bits per second (bps) or packets per second (pps).

It shows the malicious traffic that was dropped (**in red**) and the clean traffic delivered to your IP address (**in green**). Basic mitigation statistics are also displayed for the selected IP address and period, such as the number of attacks detected, the volume of traffic (or packets) cleaned during attacks, and the number of times the scrubbing centres inspected your traffic (number of events).

**The data retention period for the traffic graphs is 2 months.**

## FAQ

### Why are some attacks not shown on the Network Security Dashboard?

Depending on the nature of an attack, different actions may be taken to best eliminate the threat. In both cases, attacks are mitigated as close to their origin as possible:

- When an attack comes into the OVHcloud network (**external**), its traffic is redirected to the Anti-DDoS scrubbing centres for cleaning, and it is therefore visible on the dashboard.
- Attacks originating from inside the OVHcloud network (**internal**) are handled by our security teams. Mitigation focuses on blocking the origin of the attack, which is not reported by the Anti-DDoS infrastructure systems.

### No data is displayed in the scrubbing centre activity log. Is this normal?

Yes. It means that no suspected attack has targeted your public IP addresses.

### Why is no traffic graph or data shown for an IP address I enter?

This data is only available for public IP addresses during automatic detection events of the Anti-DDoS infrastructure, when traffic is redirected through a scrubbing centre.

### Why is the traffic graph not available for some entries of the scrubbing centre activity log?

Traffic graph data is only available for the past 2 months, while log entries can be reviewed for the past year.

### An attack on my service is persisting. How can I better protect my server?

Some attacks may be so specific that the Anti-DDoS infrastructure cannot detect and clean them automatically. In such cases, the firewall configured on your server is your best option. We also recommend moving some of your server firewall rules to the edge of our network with the Edge Network Firewall. For more information on configuring its rules, see our [Edge Network Firewall](/guides/bare-metal-cloud/dedicated-servers/firewall-network) guide.

If attacks are not mitigated thoroughly enough, you can also make detection more aggressive for your IP addresses by applying a network traffic profile with a higher sensitivity. For more information, see our guide on [Anti-DDoS profiling](/guides/bare-metal-cloud/dedicated-servers/anti-ddos-vac-profiling).

### My service is under attack and I am experiencing problems on my server. What else can I do?

The Anti-DDoS infrastructure is designed to protect a wide range of services as efficiently as possible. In some specific cases, it may need additional tuning, for example to match the nature or the size of your application.

You can tune it yourself with Anti-DDoS profiling, currently in Beta: apply a network traffic profile and a sensitivity level adapted to your workload to your IP addresses. For more information, see our guide on [Anti-DDoS profiling](/guides/bare-metal-cloud/dedicated-servers/anti-ddos-vac-profiling).

If no profile matches your workload, or if the problem persists, visit our [Help Centre](/links/support-contact) and search for the appropriate action in the "network attack and/or Anti-DDoS related" category.

#### Provide OVHcloud with information

Whenever our Anti-DDoS system needs adjusting, you must provide us with the following details so that we can understand your case and help you:

- Service hosted on the affected server
- Date and time when the attack started
- Date and time when the attack finished
- Affected IP address(es)
- Service, protocol and port used by the affected service
- Size of the service (XS: 1-10, S: 10-100, M: 100-1k, L: 1-10k, XL: 10-100k, XXL: 100k+ connected clients)
- Other services hosted on the server
- Other ports used on the server
- Are there other services on separate IP addresses: Yes/No
- If yes, which IP addresses
- Is legitimate traffic being dropped: Yes/No
- Was the connection to the server lost: Yes/No
- Which type of legitimate traffic is being dropped

:::info
In some cases, we may ask you for an additional traffic capture.

To create this capture, run the following command on Linux:

```bash
tcpdump -w capture-ovh -c 100000 port not ssh
```

If you are using Windows, use [Wireshark](https://www.wireshark.org/) and capture 100,000 packets.

You can either attach the file to your support ticket or upload it to our file-sharing solution by following [this guide](/guides/account-and-service-management/account-information/use-plik), then share the link to the uploaded file in your support ticket.
:::
