## Objective

When you configure the Content Delivery Network (CDN) for the first time, you need to declare your domains in the OVHcloud Console and configure the network in a way that is optimal for your usage.

**This guide explains how to do this in the OVHcloud Console, and provides instructions on how to use the OVHcloud CDN properly.**

## Requirements

- an [OVHcloud Content Delivery Network (CDN)](https://www.ovhcloud.com/en-gb/network/cdn/) solution
- the permissions needed to manage your domain’s DNS zone

## Instructions

### Add a domain name on the CDN.

The first step of this configuration involves adding your subdomain to the CDN, so that it accepts HTTP(S) requests.

{/* CP-STEPS-START:add-domain */}

Open the <code className="action">Domains</code> tab and click <code className="action">Add domain</code>. The **Guided domain setup** page opens and takes you through four steps:

<img className="thumbnail" alt="Domains tab of a CDN with the Add domain button" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/domains-tab.png" loading="lazy" />

1. **Domain name**: enter the subdomain you want to serve through the CDN, as a fully qualified domain name (for example, `www.example.com`), then click <code className="action">Next</code>.
2. **Origin (IPv4)**: enter the IPv4 address of the origin server that hosts your files (your back end), then click <code className="action">Next</code>.
3. **SSL certificate**: choose **Let's Encrypt** to have a free HTTPS certificate provisioned automatically, or **No SSL** to serve the domain over HTTP only (you can add a certificate later). This step is skipped if your CDN already has a certificate. For more information, read our guide on [adding an SSL certificate on the CDN](/guides/network/content-delivery-network-infrastructure/cdn-infrastructure-ssl-certificate).
4. **Confirm & deploy**: check the summary, then click <code className="action">Deploy</code>.

<img className="thumbnail" alt="Guided domain setup, Domain name step" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/guided-setup-step1.png" loading="lazy" />

The page shows the progress of the deployment: creation of the domain, configuration of the origin and, if you chose it, provisioning of the SSL certificate. Once it is complete, it displays the target to which your domain's CNAME record must point (in the form `<your domain>.cdn.ovhcloud.com`, for example `www.example.com.cdn.ovhcloud.com`). Copy this target: you need it in the next step. Click <code className="action">Done</code>. Your domain then appears in the <code className="action">Domains</code> tab, with its origin and status, and you can start configuring it.

<img className="thumbnail" alt="End of the guided domain setup, showing the CNAME target" src="/images/network/content-delivery-network-infrastructure/first-domain-name-configuration/guided-setup-cname.png" loading="lazy" />

To ensure that your requests go through our CDN infrastructure, you need to modify your subdomain's DNS zone so that a CNAME record points to this target.

:::warning
It is important to use the CNAME record for this, as it makes the `Bypass` function work correctly. If you use an A record instead, the CDN will work, but the *bypass* function will not.

:::

If your domain's DNS zone is managed by OVHcloud, add this CNAME record to the zone from the OVHcloud Console, adapting the subdomain to your configuration: enter your subdomain (for example, `cdn`) and, as the target, the value displayed at the end of the guided setup. To find out how to add a record, read our guide on [editing an OVHcloud DNS zone](/guides/web-cloud/domains/dns-zone-edit).

{/* CP-STEPS-END:add-domain */}

 

### Check that a file has been stored in the cache.

You can check that a file has been stored in the cache by performing a request:

```sh
curl -I http://sub.domain/
```

The result it returns will be something like this:

```bash
HTTP/1.1 200 OK
Date: Tue, 09 Jan 2018 10:30:57 GMT
Content-Type: text/plain
Last-Modified: Fri, 29 Dec 2017 13:30:42 GMT
ETag: W/"(5a464382-4ddf"
Expires: Wed, 09 Jan 2019 10:30:58 GMT
X-IPLB-Instance: 5905
Vary: Accept-Encoding
X-CDN-Pop: rbx1
X-CDN-Pop-IP: 51.254.41.128/26
X-Cacheable: Matched cache
Accept-Ranges: bytes
Connection: keep-alive
```

If your file has been properly called from the cache, you will receive the `Matched cache` result.

You will also see the point of presence (PoP) your file has been called from (*rbx1* in our example).

You can also access this information from your web browser, via the `Network` tab in the development tools (keyboard shortcut: F12). By clicking on the file you want to check, you will see the HTTP response and its headers.

### Set a preference for using a subdomain specific to the CDN over the primary domain.

You cannot add a CNAME record to a primary domain. This is the result of a limitation related to RFC standards, and cannot be avoided on a DNS zone level.

By attributing a specific domain name to the files that you would like to cache, you can manage them more easily.

- **For files:** Only the files called on this subdomain will be cached. This way, you can keep the name of your dynamic files, as well as the files you do not want to cache on your primary domain. This will also help you determine the origin of any display issues on your website.
- **For billing:** Since all of the traffic (cached or uncached) that passes through the CDN is billed, you can limit the number of redundant requests made via the CDN to optimise your quota usage.

### Keep in mind the consequences of adding a new subdomain.

If you would like to configure a new subdomain to use our CDN, you will probably need to modify some of your website’s configurations.

Before you proceed, check that your web service responds correctly to the subdomain. To do this, you will need to configure a *vhost* for this domain, either with its own destination folder, or under the alias of another domain name.

If the domain responds correctly to your web service, you simply need to modify your HTML code so that it changes the sources of files that pass through the CDN, and ensure that they are named correctly on your subdomain.
