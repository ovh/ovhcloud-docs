## Objective

The **OVHcloud Load Balancer** operates by default as a proxy. It can also be configured to redirect client traffic to a third-party website. This functionality is essential for scenarios such as **domain name migration** or enforcing the **HTTPS version** of a website. This is known as **HTTP redirection**.

**This guide outlines the process for integrating your web services behind an OVHcloud Load Balancer utilizing HTTP redirections.**

## Requirements

- Have an [OVHcloud Load Balancer](https://www.ovhcloud.com/en-gb/network/load-balancer/) offer in your OVHcloud account.
- Have access to the <ApiLink>OVHcloud API</ApiLink>.

## Instructions

### Overview

An HTTP redirect looks like this:

```bash
HTTP/1.1 301 Moved Permanently
Location: http://www.example.org/
Content-Type: text/html
Content-Length: 174
```

Custom redirects must be formatted as `<scheme>://<net_loc>/<path>;<params>?<query>#<fragment>`. A frontend has one default redirect, used when no route matches the request. To add more redirects, create routes on the frontend: in the OVHcloud Console, open the **Edit Frontend** page of an existing HTTP or HTTPS frontend, click <code className="action">Add route</code> and, in the **Create Route** window, set the **Action type** to **Redirect to URL** instead of **Route to farm**.

Custom redirects can be specified via the OVHcloud Console or via the API, on a new or existing frontend.

### Adding a custom redirect from the OVHcloud Console

This can be done either on a new frontend during its creation, or on an existing frontend.

#### Adding a new frontend

{/* CP-STEPS-START:add-new-frontend */}

In the <code className="action">Frontends</code> tab, click <code className="action">Create frontend</code> to create a new one.

On the **Create Frontend** page, select **HTTP** or **HTTPS** as the **Protocol**.<br/>
Configure the information as usual. However, it is unnecessary to select a farm, as it will not be used.

In the **Routing** section, under **Default route**, select **Redirect to URL** and enter your redirect URL.

{/* CP-STEPS-END:add-new-frontend */}

#### Editing an existing frontend

{/* CP-STEPS-START:edit-existing-frontend */}

In the <code className="action">Frontends</code> tab, click the `⋮` button in the **Actions** column of the relevant frontend and select <code className="action">Edit</code>.<br/>
Make sure the selected frontend is of the `HTTP` or `HTTPS` protocol. Complete the configuration if necessary.
However, it is unnecessary to select a farm, as it will not be used.

In the **Routing** section, under **Default route**, select **Redirect to URL** and enter your redirect URL.

Once the frontend is configured, click <code className="action">Create Frontend</code> or <code className="action">Save changes</code> depending on whether you are configuring a new frontend or an existing one.
Do not forget to deploy the configuration.

To do this, go to the <code className="action">Overview</code> tab and, in the **General information** section, under **Deployment**, click <code className="action">Apply N changes</code>, where N is the number of pending changes. A single click applies the configuration to every zone of your service.

{/* CP-STEPS-END:edit-existing-frontend */}

### Adding a custom redirect from the OVHcloud API

In the <ApiLink>OVHcloud API</ApiLink>, redirects are specified in the redirectLocation string:

**Creating a new frontend**

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/http/frontend"} />


|Parameter|Meaning|
|---|---|
|serviceName|Identifier of your Load Balancer service|
|port|Port(s) of the frontend|
|zone|Deployment zone of the frontend|
|redirectLocation|HTTP redirect URL|

**Updating an existing frontend**

<Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/http/frontend/\{frontendId\}"} />


|Parameter|Meaning|
|---|---|
|serviceName|Identifier of your Load Balancer service|
|frontendId|Identifier of the frontend to update|
|redirectLocation|HTTP redirect URL|

**Applying the changes**

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/refresh"} />


|Parameter|Meaning|
|---|---|
|serviceName|Identifier of your Load Balancer service|
|zone|Deployment zone of the frontend|
