## Objective

The OVHcloud Load Balancer can distribute SMTP traffic across several backend mail servers. Because SMTP is a TCP-based protocol, you do this with a TCP server farm and a TCP frontend listening on port 25.

**This guide explains how to set up a TCP service for SMTP on your OVHcloud Load Balancer: create the server farm, attach your mail servers, add the frontend, and apply the configuration.**

:::warning
This guide assumes a working knowledge of the SMTP protocol and of mail server operation. Configuring the mail servers themselves remains your responsibility.
:::

## Requirements

- An OVHcloud Load Balancer service in your account
- Access to the <ManagerLink to="/">OVHcloud Console</ManagerLink>
- A Postfix-type SMTP service installed and configured on each backend server
- Familiarity with the components of the Load Balancer — see Configure server farms{/* TODO(iplb-revamp): restore this link before the final merge, once the revamp guide lands → [Configure server farms](/guides/network/load-balancer/configure-server-farms) */} and Configure frontends{/* TODO(iplb-revamp): restore this link before the final merge, once the revamp guide lands → [Configure frontends](/guides/network/load-balancer/configure-frontends) */}

## Introduction

Each protocol family in the OVHcloud Load Balancer (HTTP, TCP, and UDP) has its own frontends, server farms, and servers. SMTP runs over TCP, so the whole configuration uses the TCP family.

The order in which you create the components matters: the server farm must exist before you can attach servers to it, and the frontend references the farm as its default target. The procedure below follows this order.

:::info
Configuration changes are staged until you apply them. They become visible to your users only after you apply the configuration. This lets you prepare a complete change set and apply it in one operation.
:::

## Instructions

### Step 1 — Create the TCP server farm

The server farm groups your backend mail servers and manages how traffic is balanced across them.

{/* CP-STEPS-START:create-tcp-farm */}
<Tabs>
<Tab label="Console">

1. Log in to the <ManagerLink to="/">OVHcloud Console</ManagerLink>. In the top bar, select <code className="action">Bare Metal Cloud</code> (or <code className="action">Private Cloud</code>), then open <code className="action">Network</code> > <code className="action">Load Balancer</code> in the left menu and select your service.
2. Select the <code className="action">Server farms</code> tab and click <code className="action">Create farm</code>.
3. On the **Create Server Farm** page, select **TCP** from the **Protocol** drop-down list.
4. Set the **Port** to `25`. If you leave the port empty, the farm reuses the port of the associated frontend.
5. From the **Zone** drop-down list, select the zone of your service, or keep **All zones**. The zone cannot be changed once the farm is created.
6. Optionally, in the **Health check** section, select **Enable health check probe** and set **Probe type** to **SMTP** so the Load Balancer monitors your mail servers' availability. The probe **Port** defaults to the farm port and the **Interval (s)** must be at least 30 seconds; you can also set a **Match** condition.
7. Click <code className="action">Create Farm</code> to confirm.

The new farm appears as a card in the <code className="action">Server farms</code> tab.

</Tab>
<Tab label="OVHcloud API">

Create a TCP server farm:

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm"} />

| Parameter | Required | Description | Example |
|---|---|---|---|
| `serviceName` | Yes | The identifier of your Load Balancer service. | `loadbalancer-xxxxx` |
| `port` (body) | No | Listening port for the farm. Use 25 for standard SMTP. | `25` |
| `zone` (body) | Yes | Zone in which the farm is created. | `all` |
| `balance` (body) | No | Load balancing algorithm. | `roundrobin` |

To review or manage existing TCP farms:

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm"} />

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}"} />

<Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}"} />

<Api version="v1" section="/ipLoadbalancing" method="DELETE" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}"} />

</Tab>
</Tabs>
{/* CP-STEPS-END:create-tcp-farm */}

### Step 2 — Add your mail servers to the farm

Declare each backend SMTP server as a member of the TCP farm.

{/* CP-STEPS-START:add-mail-servers */}
<Tabs>
<Tab label="Control Panel">

1. In the <code className="action">Server Farms</code> tab, click the farm you created to display its servers.
2. Click <code className="action">Add server</code>.
3. Enter the **IPv4 address** of the backend server, set its **Status**, and select the **ProxyProtocol version**. These fields are mandatory.
4. Leave the server **Port** empty to inherit the port defined on the farm. Set a port only in advanced cases, as it overrides the farm port for this server.
5. Click <code className="action">Add server</code> to confirm.

:::warning
Set the **ProxyProtocol version** to `v1` so that your SMTP service can retrieve the real source IP of incoming connections. Postfix is compatible with the PROXY protocol.
:::

The server appears in the server list below the farm.

</Tab>
<Tab label="OVHcloud API">

Add a server to the TCP farm:

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}/server"} />

| Parameter | Required | Description | Example |
|---|---|---|---|
| `serviceName` | Yes | The identifier of your Load Balancer service. | `loadbalancer-xxxxx` |
| `farmId` | Yes | The identifier of the TCP farm. | `12345` |
| `address` (body) | Yes | IPv4 address of the backend server. | `203.0.113.10` |
| `status` (body) | Yes | Administrative status of the server. | `active` |
| `proxyProtocolVersion` (body) | No | PROXY protocol version. Use `v1` to preserve the source IP. | `v1` |

To review or manage existing servers:

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}/server"} />

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}/server/\{serverId\}"} />

<Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}/server/\{serverId\}"} />

<Api version="v1" section="/ipLoadbalancing" method="DELETE" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}/server/\{serverId\}"} />

</Tab>
</Tabs>
{/* CP-STEPS-END:add-mail-servers */}

### Step 3 — Create the TCP frontend

The frontend exposes your SMTP service to the Internet and forwards incoming traffic to the farm.

{/* CP-STEPS-START:create-tcp-frontend */}
<Tabs>
<Tab label="Console">

1. Select the <code className="action">Frontends</code> tab and click <code className="action">Create frontend</code>.
2. On the **Create Frontend** page, select **TCP** from the **Protocol** drop-down list.
3. Set the **Port** to `25` for a standard SMTP service and select the **Zone**. To expose several ports, enter a comma-separated list (`25,587`) or a range in the `<start_port>-<end_port>` format.
4. From the **Default Farm** drop-down list, select the farm created in Step 1. The farm and the frontend must use the same zone.
5. If you routed Additional IPs to your Load Balancer, you can attach the frontend to one or more specific Additional IPs in the **Advanced settings** section.
6. Click <code className="action">Create Frontend</code> to confirm.

The frontend appears in the list under the <code className="action">Frontends</code> tab.

</Tab>
<Tab label="OVHcloud API">

Create a TCP frontend:

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/tcp/frontend"} />

| Parameter | Required | Description | Example |
|---|---|---|---|
| `serviceName` | Yes | The identifier of your Load Balancer service. | `loadbalancer-xxxxx` |
| `port` (body) | Yes | Listening port. Use 25 for standard SMTP. | `25` |
| `zone` (body) | Yes | Zone in which the frontend is created. | `all` |
| `defaultFarmId` (body) | No | The TCP farm to route traffic to by default. | `12345` |

To review or manage existing frontends:

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/tcp/frontend"} />

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/tcp/frontend/\{frontendId\}"} />

<Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/tcp/frontend/\{frontendId\}"} />

<Api version="v1" section="/ipLoadbalancing" method="DELETE" route={"/ipLoadbalancing/\{serviceName\}/tcp/frontend/\{frontendId\}"} />

</Tab>
</Tabs>
{/* CP-STEPS-END:create-tcp-frontend */}

### Step 4 — Apply the configuration

Your changes are staged until you apply them. The configuration is then applied to every zone of the service at once.

{/* CP-STEPS-START:apply-configuration */}
<Tabs>
<Tab label="Console">

Return to the <code className="action">Overview</code> tab of your Load Balancer service and apply the pending changes. The configuration becomes visible to your users only once applied.

:::info
In the **General information** section, under **Deployment**, click <code className="action">Apply N changes</code>, where N is the number of pending changes. A single click applies the pending configuration to every zone of the service.
:::

</Tab>
<Tab label="OVHcloud API">

Apply (refresh) the pending configuration:

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/refresh"} />

| Parameter | Required | Description | Example |
|---|---|---|---|
| `serviceName` | Yes | The identifier of your Load Balancer service. | `loadbalancer-xxxxx` |

</Tab>
</Tabs>
{/* CP-STEPS-END:apply-configuration */}

### Step 5 — Configure Postfix for the PROXY protocol

To make Postfix compatible with the PROXY protocol forwarded by the Load Balancer, add the following option to the Postfix `main.cf` configuration file on each backend server:

```bash
smtp_upstream_proxy_protocol = haproxy
```

Restart the Postfix daemon to apply the change.

:::tip
The PROXY protocol version configured here (`haproxy`) must match the ProxyProtocol version set on the server in Step 2. Use version `v1` on both sides.
:::

### Step 6 — Verify the configuration

After completing the steps above, you have a functional Load Balancer service in front of your SMTP servers. Verify it by connecting to your Load Balancer's IP address as if it were an SMTP server.

```console
telnet <load-balancer-ip> 25
```

A successful connection returns the SMTP banner of one of your backend mail servers.
