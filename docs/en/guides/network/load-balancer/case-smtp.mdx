## Objective

**This guide outlines how to configure the OVHcloud Load Balancer to distribute traffic across multiple SMTP servers.**

## Requirements

- An [OVHcloud Load balancer](https://www.ovhcloud.com/en-gb/network/load-balancer/) service in your OVHcloud account.
- A Postfix-type SMTP service installed and configured on your servers.

[[cpnav:network-load-balancer|en]]

## Instructions

:::warning
This guide assumes a working knowledge of SMTP protocol and service operation.
:::


As a reminder, each protocol (HTTP, TCP and UDP) in the OVHcloud Load Balancer service has its own associated front-ends, farms and servers.

:::warning
The order in which elements are created is important. In particular, the server farms must be configured before servers can be attached to them.
:::


{/* CP-STEPS-START:cp-access */}

In the OVHcloud Console, your Load Balancer service opens on the <code className="action">Overview</code> tab. The features detailed below are spread across its tabs: <code className="action">Frontends</code>, <code className="action">Server farms</code>, <code className="action">SSL</code>, <code className="action">Network</code>, <code className="action">Logs</code>, <code className="action">Statistics</code>, <code className="action">Operations</code> and <code className="action">Quotas</code>.

{/* CP-STEPS-END:cp-access */}

Via the OVHcloud API, use the following call:

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing"} />


For more information on the API features, you can refer to [the following guide](/guides/network/load-balancer/use-api-reference).

### Add a server farm

A TCP server farm must be added to the service; this component manages traffic balancing across the servers.

#### Via the OVHcloud Console

{/* CP-STEPS-START:add-server-farm */}

In the <code className="action">Server farms</code> tab, click <code className="action">Create farm</code>. On the **Create Server Farm** page, select **TCP** from the **Protocol** drop-down list.

Fill in the fields. For a basic configuration, set the **Port** and the **Zone** (**All zones** by default; the zone cannot be changed once the farm is created). For SMTP, port 25 is used. If no ports are specified, your OVHcloud Load Balancer will automatically use the same port as the corresponding front-end.

Optionally, you can add an SMTP probe on your farm: in the **Health check** section, tick **Enable health check probe**, then select **SMTP** from the **Probe type** drop-down list.

Click <code className="action">Create Farm</code> once you have filled in the fields.

Your server farm appears in the <code className="action">Server farms</code> tab.

{/* CP-STEPS-END:add-server-farm */}

### Add a server

A server must now be added to the server farm.

#### Via the OVHcloud Console

{/* CP-STEPS-START:add-server */}
In the <code className="action">Farms</code> tab, select the farm you want to add a server to by clicking on the corresponding line. The list of servers already configured in the farm will appear beneath the list of farms, along with the <code className="action">Add a server</code> button. Click this button to add a new server.

The mandatory fields are the *IPv4 address*, *Status*, and *ProxyProtocol version*. If a server port is configured, it will override the port defined in the farm. To keep the configuration as standard as possible and easy to maintain, we recommend only using this parameter in advanced cases.

:::warning
It is important to configure ProxyProtocol in version v1 so that you can retrieve the real source IP on your SMTP service. Postfix is compatible with this protocol.
:::

Click on <code className="action">Add</code> once you have filled in the fields.

Your server should appear in the server list, in the <code className="action">Farms</code> tab, just below the list of farms.

### Add a front-end

A <code className="action">front-end</code> must now be added to the service and connected to the server farm. The front-end is the component of your OVHcloud Load Balancer that exposes your service to the internet.

#### Via the OVHcloud Console

{/* CP-STEPS-START:add-front-end */}

Go to the <code className="action">Frontends</code> tab and click <code className="action">Create frontend</code>. On the **Create Frontend** page, select **TCP** from the **Protocol** drop-down list.

Fill in the fields. For a basic configuration, set the **Port** (25 for a standard SMTP service), the **Zone** and the **Default Farm**. A front-end has no probe setting: the probe configured on your farm applies. If you want your service to be available across several ports at once, you can specify a list of ports, separated by commas, or a port range, in the format "`<start_port>`-`<end_port>`".

If you have routed Additional IPs to your OVHcloud Load Balancer service, you can also attach a front-end to one or more specific Additional IPs, in the **Additional IPs** field of the **Advanced settings** section.

From the **Default Farm** drop-down list, select the farm you created earlier.

Click <code className="action">Create Frontend</code> once the fields are filled.

Your front-end appears in the list, in the <code className="action">Frontends</code> tab.

{/* CP-STEPS-END:add-front-end */}

### Apply the modifications

Modifications made to your OVHcloud Load Balancer must be **explicitly applied** in each of the zones configured for your service. They will only become visible to your users at this point. This process allows for complex configuration changes to be prepared and applied only when fully ready.

If you have several zones, the same configuration must be applied to each.

#### Via the OVHcloud Console

{/* CP-STEPS-START:apply-modifications */}

Go to the <code className="action">Overview</code> tab of your OVHcloud Load Balancer. In the **General information** section, under **Deployment**, click <code className="action">Apply N changes</code>, where N is the number of pending changes. A single click applies the configuration to every zone of your service. You can follow the deployment in the <code className="action">Operations</code> tab.

{/* CP-STEPS-END:apply-modifications */}

#### Via the OVHcloud API

- Refresh a zone:

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/refresh"} />


### Postfix configuration

To make Postfix compatible with HAProxy *ProxyProtocol*, an option is required in the postfix main.cf configuration file:

```bash
smtp_upstream_proxy_protocol = haproxy
```

The Postfix daemon must then be restarted.
