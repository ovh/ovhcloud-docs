## Objective

**This guide outlines how to configure the OVHcloud Load Balancer to distribute traffic across multiple SMTP servers.**

## Requirements

- An [OVHcloud Load balancer](https://www.ovhcloud.com/en-gb/network/load-balancer/) service in your OVHcloud account.
- Being logged in to your <ManagerLink to="/">OVHcloud Control Panel</ManagerLink>.
- A Postfix-type SMTP service installed and configured on your servers.

### OVHcloud Control Panel Access

- **Direct link:** <ManagerLink to="/#/dedicated/iplb">Load Balancer</ManagerLink>
- **Navigation path:** <code className="action">Network</code> > <code className="action">Load Balancer</code> > Select your service

## Instructions

:::warning
This guide assumes a working knowledge of SMTP protocol and service operation.
:::


As a reminder, each protocol (HTTP, TCP and UDP) in the OVHcloud Load Balancer service has its own associated front-ends, farms and servers.

:::warning
The order in which elements are created is important. In particular, the server farms must be configured before servers can be attached to them.
:::


In the Control Panel, you will see the features detailed below:

<img className="thumbnail" alt="OVHcloud Load Balancer service" src="/images/network/load-balancer/case-smtp/iplb_service.png" loading="lazy" />

Via the OVHcloud API, use the following call:

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing"} />


For more information on the API features, you can refer to [the following guide](/guides/network/load-balancer/use-api-reference).

### Add a server farm

A TCP server farm must be added to the service; this component manages traffic balancing across the servers.

#### Via the OVHcloud Control Panel

In the <code className="action">Farms</code> tab for servers, click on the <code className="action">+TCP/TLS</code> button.

Fill in the fields. The mandatory fields for a basic configuration are *Port* and *Zone*. For SMTP, port 25 is used. If no ports are specified, your OVHcloud Load Balancer will automatically use the same port as the corresponding front-end.

Optionally, you can add an SMTP probe on your farm.

<img className="thumbnail" alt="Add a server farm via the Control Panel" src="/images/network/load-balancer/case-smtp/add_farm.png" loading="lazy" />

Click on <code className="action">Add</code> once you have filled in the fields.

Your server farm should appear in the list, in the <code className="action">Farms</code> tab.

<img className="thumbnail" alt="Details of the server farm created" src="/images/network/load-balancer/case-smtp/resume_farm.png" loading="lazy" />

#### Via the OVHcloud API

- List of TCP server farms:

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm"} />


- Details of a specific TCP server farm:

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}"} />


- Add a new TCP server farm:

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm"} />


- Modify a specific server farm:

<Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}"} />


- Delete a specific server farm:

<Api version="v1" section="/ipLoadbalancing" method="DELETE" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}"} />


### Add a server

A server must now be added to the server farm.

#### Via the OVHcloud Control Panel

In the <code className="action">Farms</code> tab, select the farm you want to add a server to by clicking on the corresponding line. The list of servers already configured in the farm will appear beneath the list of farms, along with the <code className="action">Add a server</code> button. Click this button to add a new server.

The mandatory fields are the *IPv4 address*, *Status*, and *ProxyProtocol version*. If a server port is configured, it will override the port defined in the farm. To keep the configuration as standard as possible and easy to maintain, we recommend only using this parameter in advanced cases.

:::warning
It is important to configure ProxyProtocol in version v1 so that you can retrieve the real source IP on your SMTP service. Postfix is compatible with this protocol.
:::


<img className="thumbnail" alt="Add a server to a farm." src="/images/network/load-balancer/case-smtp/add_server.png" loading="lazy" />

Click on <code className="action">Add</code> once you have filled in the fields.

Your server should appear in the server list, in the <code className="action">Farms</code> tab, just below the list of farms.

<img className="thumbnail" alt="Details of the server created." src="/images/network/load-balancer/case-smtp/resume_server.png" loading="lazy" />

### Add a front-end

A <code className="action">front-end</code> must now be added to the service and connected to the server farm. The front-end is the component of your OVHcloud Load Balancer that exposes your service to the internet.

#### Via the OVHcloud Control Panel

Go to the <code className="action">+ Front-ends</code> tab, and click <code className="action">+TCP/TLS</code>.

Fill in the fields. The mandatory fields for a basic configuration are *Port* (25 for a standard SMTP service), *Zone*, *Default farm* and *Probe* (if a probe was configured on your farm). If you want your service to be available across several ports at once, you can specify a list of ports, separated by commas, or a port range, in the format "`<start_port>`-`<end_port>`".

If you have routed Additional IPs to your OVHcloud Load Balancer service, you can also attach a front-end to one or more specific Additional IPs.

Ensure the farm you created earlier is specified as the “default farm”.

<img className="thumbnail" alt="Add a front-end" src="/images/network/load-balancer/case-smtp/add_frontend.png" loading="lazy" />

Click <code className="action">Add</code> once the fields are filled.

Your front-end must appear in the list, in the <code className="action">Front-ends</code> tab.

<img className="thumbnail" alt="Details of the front-end created" src="/images/network/load-balancer/case-smtp/resume_frontend.png" loading="lazy" />

### Apply the modifications

Modifications made to your OVHcloud Load Balancer must be **explicitly applied** in each of the zones configured for your service. They will only become visible to your users at this point. This process allows for complex configuration changes to be prepared and applied only when fully ready.

If you have several zones, the same configuration must be applied to each.

#### Via the OVHcloud Control Panel

Go to the homepage for the OVHcloud Load Balancer, and click <code className="action">Apply:Zone</code> for each of the zones concerned.

#### Via the OVHcloud API

- Refresh a zone:

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/refresh"} />


### Postfix configuration

To make Postfix compatible with HAProxy *ProxyProtocol*, an option is required in the postfix main.cf configuration file:

```bash
smtp_upstream_proxy_protocol = haproxy
```

The Postfix daemon must then be restarted.
