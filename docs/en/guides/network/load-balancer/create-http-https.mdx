## Objective

This guide aims to help you create your first HTTP/HTTPS service using the OVHcloud Load Balancer offer. We will configure a simple OVHcloud Load Balancer service to distribute HTTP traffic for a service, such as a website.

A frontend will be created to listen on port 80, while another will listen on port 443 with an SSL/TLS certificate. These frontends will be configured to direct their traffic to a common HTTP farm. This farm can have one or more servers, depending on the chosen / adapted configuration.

As a reminder, the OVHcloud Load Balancer service is composed of 4 elementary parts:

- the `frontends`;
- the `farms` of servers and their `servers`;
- the advanced `routes` between Frontends and Server Farms;
- the `SSL/TLS` certificates allowing TCP and/or HTTP connections to be encrypted.

## Requirements

- Have an [OVHcloud Load balancer](https://www.ovhcloud.com/en-gb/network/load-balancer/) offer in your OVHcloud account
- Have a configured farm
- Have a configured frontend
- Have an SSL certificate

### Add a server farm <a name="farm"></a>

We will add an HTTP server farm to our service. This part is responsible for distributing traffic to the servers.

#### From the OVHcloud Console

{/* CP-STEPS-START:add-server-farm */}

In the <code className="action">Server farms</code> tab, click <code className="action">Create farm</code>. The **Create Server Farm** page opens.

Fill in the fields. For a simple configuration, select the **Protocol** (HTTP) and the **Zone** (a single zone or **All zones**; the zone cannot be changed once the farm is created). It is recommended to explicitly define a **Port**, generally port 80 for a web service. If no port is specified, your OVHcloud Load Balancer will automatically use the same port as the corresponding frontend and the probes may not work as expected.

If you add several servers in your farm, it is recommended to configure an HTTP probe: in the **Health check** section, tick **Enable health check probe**, then select **HTTP** from the **Probe type** drop-down list. When a probe is configured, the OVHcloud Load Balancer service can automatically disable a server that is down or under maintenance, in order not to affect visitors.

Click <code className="action">Create Farm</code> once you have filled in the fields.

Your server farm appears in the <code className="action">Server farms</code> tab.

{/* CP-STEPS-END:add-server-farm */}

### Add a server <a name="server"></a>

We will now add a server to our server farm.

#### From the OVHcloud Console

{/* CP-STEPS-START:add-server */}

Still in the <code className="action">Server farms</code> tab, find the farm to which you want to add a server and click its <code className="action">Add server</code> button. The **Add Server** page opens.

Only the **Address** field (the IPv4 address of the server) is mandatory. If a server does not use the same port as the one defined above in the farm, it is possible to override it in the **Port** field of the server. However, in order to maintain the most homogeneous and maintainable configuration possible, it is recommended to use this parameter only in advanced cases.

Click <code className="action">Add Server</code> once you have filled in the fields.

Your server appears in the farm's **Servers** list, in the <code className="action">Server farms</code> tab.

### Add a frontend <a name="frontend"></a>

We will now add a `frontend` to our service and connect it to our server farm. The frontend is the part of your OVHcloud Load Balancer that is used to expose your service on the Internet. At first, we will configure it in HTTP only, without an SSL/TLS certificate.

#### From the OVHcloud Console

{/* CP-STEPS-START:add-frontend */}

In the <code className="action">Frontends</code> tab, click <code className="action">Create frontend</code>. The **Create Frontend** page opens.

Fill in the fields. For a simple configuration, set the **Protocol** (HTTP), the **Port** (80 for a standard HTTP web service) and the **Zone**. If you want your service to be available on several ports at the same time, you can specify a list of ports separated by commas or a range of ports in the form "START_PORT-END_PORT". To send the traffic to your server farm, go to the **Routing** section, select **Route to farm** under **Default route**, then select your farm.

If you have routed Additional IPs to your OVHcloud Load Balancer service, you can also attach a frontend to one or more specific Additional IPs, in the **Additional IPs** field of the **Advanced settings** section.

Click <code className="action">Create Frontend</code> once you have filled in the fields.

Your frontend appears in the list, in the <code className="action">Frontends</code> tab.

{/* CP-STEPS-END:add-frontend */}

### Add an SSL/TLS certificate <a name="certificate"></a>

The previous section described the general configuration for an HTTP frontend. This section describes the additional steps to enable support for the HTTPS protocol on an HTTP frontend. In particular, you will need to:

- switch the frontend to port 443, the standard port for the HTTPS protocol;
- configure an SSL/TLS certificate to authenticate and encrypt the connections.

Whether you choose a configuration via the API or via the OVHcloud Console, you will have a choice between 2 strategies for your SSL/TLS certificates. This choice depends on your needs as well as the current solutions in place:

- Import an existing SSL/TLS certificate.
- Order an automatically managed SSL/TLS certificate. The ordering of DV and EV certificates will be available soon.

If you choose to import an SSL/TLS certificate that you have ordered and managed yourself, you will have to renew it periodically yourself and update it in your OVHcloud Load Balancer service. Most certificates are valid for 1 year. Some may be valid for longer. Let's Encrypt certificates are valid for 3 months. It is recommended to use the service managed automatically by your OVHcloud Load Balancer for Let's Encrypt certificates in order not to accidentally miss a deadline.

If you choose a certificate managed by your OVHcloud Load Balancer service, it will be automatically ordered, validated, installed and renewed periodically by your OVHcloud Load Balancer.<br/>
For the validation and renewal operations to work, the domain(s) you are ordering this certificate for must be routed to your OVHcloud Load Balancer service. This implies that the *A* and *AAAA* fields of your domain point respectively to the IPv4 and IPv6 of your OVHcloud Load Balancer or one of its Additional IPs. During the order, you will receive an email that will guide you through the validation steps.

:::info
To ensure service continuity when switching your domain to the IP of your OVHcloud Load Balancer service to validate your certificate, a good practice is to first configure and fully test the HTTP configuration on port 80. This way, your site remains accessible without interruption.
If your site already has an HTTPS connection and you want to migrate to certificates managed by your OVHcloud Load Balancer service, you can import your existing certificates, configure and test your HTTPS Frontend and finally order a new certificate for the same domain. It will be automatically taken into account before your old certificate expires.

:::


The certificates configured on your OVHcloud Load Balancer service are automatically available for all frontends of your OVHcloud Load Balancer service that use the **HTTPS** protocol.

#### TLS 1.3 support

With the constant evolution of security standards on the Internet, OVHcloud is committed to providing the most recent and secure technologies for your services. The OVHcloud Load Balancer now supports TLS 1.3.

##### **What is TLS 1.3?**

TLS 1.3 is the latest version of the TLS protocol, offering significant improvements in terms of security and performance compared to TLS 1.2. The key advantages include a faster *handshake* process, thus reducing the time needed to establish secure connections, and the use of safer encryption suites to strengthen the security of transmitted data.

##### **Why use TLS 1.3 with OVHcloud Load Balancer?**

By integrating TLS 1.3, your OVHcloud Load Balancer will benefit from enhanced security and improved performance, ensuring an optimal user experience for your visitors. The reduction in *handshake* time speeds up page loading, while the security improvements ensure that your data is protected with the most recent and secure standards.

#### From the OVHcloud Console

{/* CP-STEPS-START:add-ssl-certificate */}

The list of SSL/TLS certificates configured on your OVHcloud Load Balancer service is in the <code className="action">SSL</code> tab, in the **TLS Certificates** section. Both options mentioned above start from the <code className="action">Add Certificate</code> button: on the **Add Certificate** page, the **Certificate type** sets whether you import an existing certificate (**Custom (upload PEM)**) or get a Let's Encrypt certificate managed automatically by your OVHcloud Load Balancer service (**Free (Let's Encrypt)**).

If you choose to import an existing SSL/TLS certificate, click <code className="action">Add Certificate</code> and select **Custom (upload PEM)** as the **Certificate type**. The **Private Key (PEM)** and **Certificate (PEM)** fields are mandatory.

Click <code className="action">Add Certificate</code> once the fields are filled in. Your certificate will then appear in the certificate list.

To add a Let's Encrypt certificate, click <code className="action">Add Certificate</code>, select **Free (Let's Encrypt)** as the **Certificate type**, enter your domain in the **Domain(s)** field (one domain name at a time), then click <code className="action">Add Certificate</code>. Make sure the domain points to your OVHcloud Load Balancer service and follow the emails you receive. You will then see the certificate appear in the list of available certificates.

Once your certificate(s) are configured, you can create an HTTPS frontend, on the same model as the HTTP frontend created above: select **HTTPS** as the **Protocol**, use port 443 and select your certificate in the **TLS Certificate** field.<br/>
Optionally, you can also tick **Enable HSTS** in the **Advanced settings** section. If this option is enabled, browsers will record that this website should *never again* be visited without HTTPS after their first visit in HTTPS. This strengthens overall security by protecting against "Man-in-the-middle" attacks in which a malicious actor could make your website appear unavailable in HTTPS and force your visitors to switch to "HTTP".

{/* CP-STEPS-END:add-ssl-certificate */}

:::warning
Although the added security is significant, it is recommended to wait a while before enabling this option, to make sure there are no side effects in HTTPS. Indeed, once HSTS is enabled, there is no going back.

:::

### Apply the changes <a name="apply"></a>

The changes made to your OVHcloud Load Balancer service must be *explicitly applied*. Only then will they be visible to your visitors. This allows a complex configuration change to be made in a single step.

In the OVHcloud Console, a single action applies the changes to all the zones of your service. Via the API, the refresh call applies to one zone: if you have several zones, make the call for each of them.

#### From the OVHcloud Console

{/* CP-STEPS-START:apply-changes */}

Go to the <code className="action">Overview</code> tab of your OVHcloud Load Balancer service. In the **General information** section, under **Deployment**, click <code className="action">Apply N changes</code>, where N is the number of pending changes. A single click applies the configuration to every zone of your service. You can follow the deployment in the <code className="action">Operations</code> tab.

{/* CP-STEPS-END:apply-changes */}

#### From the OVHcloud API

- Refresh a zone:

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/refresh"} />
