## Objective

This guide explains the integration of Logs Data Platform with OVHcloud IAM.

## Requirements

- An [OVHcloud account](/guides/account-and-service-management/account-information/ovhcloud-account-creation)
- A [Logs Data Platform service](/links/manage-operate/ldp)

[[cpnav:logs-data-platform-console|en]]

## Instructions

### How is IAM useful for Logs Data Platform?

Enabling OVHcloud IAM on Logs Data Platform delegates authentication, access management, and permissions to OVHcloud IAM. There are several benefits to using IAM:

- [All OVHcloud identities](/guides/manage-and-operate/iam/identities-management) can connect using their credentials to all Web UIs (Graylog/OpenSearch Dashboards). The connected account will be the identity chosen for UI access. **You will no longer need the Logs Data Platform username**. IAM enables also the use of [two-factor authentication methods](/guides/account-and-service-management/account-information/secure-ovhcloud-account-with-2fa) and [Federation Services](/guides/account-and-service-management/account-information/ovhcloud-account-connect-saml-adfs).
- API tokens can be both [service account tokens](/guides/account-and-service-management/account-information/authenticate-api-with-service-account) and Personal Access Tokens handled directly with OVHcloud IAM APIs.
- [Resource groups](/guides/account-and-service-management/account-information/iam-policies-api) allow you to share Logs Data Platform sub resources in a more cohesive way.
- [IAM Policies](/guides/account-and-service-management/account-information/iam-policy-ui) unlock advanced use cases which are not possible with permissions, thanks to fine-grained actions.

### How to enable OVHcloud IAM for my existing account in Logs Data Platform?

If you have an existing service, follow these steps:

{/* CP-STEPS-START:enable-iam-existing-service */}

- Replace all your **Roles** and permissions with [appropriate policies](/guides/manage-and-operate/observability/logs-data-platform/iam-access-management).
- Ensure you have no **Roles** declared in your service.
- Ensure your service is not in any **Roles**.
- Ensure you don't have any [tokens](/guides/manage-and-operate/observability/logs-data-platform/tokens).
- In the OVHcloud Console, go to <code className="action">Observability</code> > <code className="action">Service management</code>, select your service in the **Service** selector and open the <code className="action">Roles</code> tab. Click <code className="action">Switch to OVHcloud IAM</code>, then confirm with <code className="action">Enable OVHcloud IAM</code> in the window that opens.

:::warning

Enabling OVHcloud IAM is irreversible: once it is enabled, you cannot go back to roles.

:::

Once IAM is activated, a new **IAM Policies** tab replaces the previous **Roles** and **Tokens** tabs.

<img className="thumbnail" alt="Service management page with the IAM Policies tab of an IAM-enabled service" src="/images/manage-and-operate/observability/logs-data-platform/iam-presentation-faq/console/iam-policies-tab.png" loading="lazy" />

{/* CP-STEPS-END:enable-iam-existing-service */}

### How to enable OVHcloud IAM on a new service?

{/* CP-STEPS-START:enable-iam-new-service */}

When a new service is created, it waits in the **To configure** state until you set up its authentication: you can directly opt in to using IAM and use [IAM policies](/guides/account-and-service-management/account-information/iam-policy-ui) to handle access rights. In the OVHcloud Console, go to <code className="action">Observability</code> > <code className="action">Service management</code>, select the new service in the **Service** selector and click <code className="action">Set up account</code> in the banner at the top of the page. In the **Account setup** window, keep <code className="action">IAM authentication</code> selected and click <code className="action">Confirm</code>.

<img className="thumbnail" alt="Account setup window of a new service with IAM authentication selected" src="/images/manage-and-operate/observability/logs-data-platform/iam-presentation-faq/console/account-setup-iam.png" loading="lazy" />

{/* CP-STEPS-END:enable-iam-new-service */}

Once IAM has been activated, you can freely use any [OVHcloud identities](/guides/manage-and-operate/iam/identities-management) to interact with Logs Data Platform.

### How to connect to Graylog with IAM?

When connecting to Graylog, you can choose between the legacy username/password system (for services without IAM activated) or any OVHcloud IAM providers (EU, CA, or US). Clicking the corresponding *Log in* button redirects you to the appropriate OVHcloud IAM provider to complete authentication.

### How to connect to OpenSearch Dashboards with IAM?

When connecting to OpenSearch Dashboards, select the provider linked to your OVHcloud service. The *Log in with OVHcloud IAM* button redirects you to your provider to complete authentication.

<img className="thumbnail" alt="OSD login" src="/images/manage-and-operate/observability/logs-data-platform/iam-presentation-faq/osd_iam_eu.png" loading="lazy" />

Once completed, you will be redirected back to the OpenSearch Dashboard instance fully authenticated.

### How to connect to Grafana with IAM?

- If your Identity Provider is the OVHcloud IAM, you can select the option **Forward OAuth identity** to forward the identity connected to the Logs Data Platform.
- If you use another authentication provider, you can forge an *Authorization* header with an IAM compatible token. See the next section to see how to generate that kind of token. The content of the header must be `Bearer: <Your Token>`. Replace `<Your Token>` with the value of your token.

<img className="thumbnail" alt="Grafana header" src="/images/manage-and-operate/observability/logs-data-platform/iam-presentation-faq/grafana_header.png" loading="lazy" />

### How to interact with Logs Data Platform backends API?

With IAM enabled, [tokens](/guides/manage-and-operate/observability/logs-data-platform/tokens) are replaced by API keys (Bearer authentication scheme). These keys can be tokens from [service accounts](/guides/account-and-service-management/account-information/authenticate-api-with-service-account) or Personal Access Tokens. Use the OVHcloud API to generate these tokens.

<Api version="v1" section="/me" method="POST" route={"/me/identity/user/\\{user\\}/token"} />

For example if you are on gra1 cluster, curl can use these tokens in the following way:

```bash
ldp@laptop curl -H 'content-type: application/json' --oauth2-bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c  -XGET 'https://gra1.logs.ovh.com:9200/_cluster/health?pretty'
```

### How to create indices or aliases on Logs Data Platform backend APIs?

First, ensure the identity you want to use has permission to create indices and aliases for the service. If authorized, Personal Access Tokens or service account OAuth2 clients can perform creation/deletion operations.

{/* CP-STEPS-START:find-service-name */}

:::warning

The previous prefix for indices and aliases was the username. Now the prefix is the **service name**. You will find the service name in the **ID** field of your service's **General information** tab, under <code className="action">Observability</code> > <code className="action">Service management</code> in the OVHcloud Console. It is also the suffix of a Logs Data Platform service URN. For example:

urn:v1:eu:resource:ldp:**ldp-ab-56945**

:::

{/* CP-STEPS-END:find-service-name */}


The service is tied to a unique Logs Data Platform so you will be allowed to create items only on this cluster. For example if ldp-ab-56945 is on gra1:

```bash
ldp@laptop curl -k -v -H 'content-type: application/json' --oauth2-bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c  -XPOST 'https://gra1.logs.ovh.com:9200/ldp-ab-56945-i-my-new-index/_doc' -d '{ "user" : "ldp" }'
```

Similarly aliases created through OpenSearch APIs must be prefixed by one of your allowed services.
