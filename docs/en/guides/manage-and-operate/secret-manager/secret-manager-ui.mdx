## Objective

The objective of this guide is to present the use of the Secret Manager through the OVHcloud Console.

## Requirements

- An [OVHcloud customer account](/guides/account-and-service-management/account-information/ovhcloud-account-creation).
- To access secrets via the REST or HashiCorp Vault KV2 compliant API, configure an [authentication method](/guides/manage-and-operate/kms/okms-authentication-methods) for your OKMS domain (Personal Access Token, service account, or access certificate).

[[cpnav:security-secret-manager]]

## Instructions

### Description

The Secret Manager is a product that allows you to securely store credentials, API keys, SSH keys, or any other type of secret necessary for the operation of your applications.

A secret is a collection of one or more key-value pairs grouped within a version.
Each modification of a secret creates a new version of that secret, allowing you to go back in the history of changes to the secret.

### Creating a Secret

{/* CP-STEPS-START:create-secret */}

In the OVHcloud Console, secrets are managed in Key & Secret Manager. In the left-hand menu, open <code className="action">Security</code> and click <code className="action">Key & Secret Manager</code>. Each OKMS domain has a <code className="action">Secrets</code> tab, which lists the secrets stored in that domain.

<img className="thumbnail" alt="Secrets tab of an OKMS domain with the Create a secret button" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secrets-tab.png" loading="lazy" />

To create a secret, click <code className="action">Create a secret</code>.

There is no region to select in the creation form: the secret is created in the OKMS domain selected in the **OKMS domain** list, and therefore in that domain's region. Select the right domain before you click <code className="action">Create a secret</code>.

:::info
If you do not have an OKMS domain yet in the region where you want to create the secret, create one first: open the **OKMS domain** list, click <code className="action">Create domain</code> and choose the region.
This activation may take a few minutes to take effect.
:::


Indicate the **Path** of the secret, for example **prod/database/MySQL**. This path is used to organise the secrets into a hierarchy.

Then indicate the content of the secret in the **Values configuration** section. The secret contains a list of key-value pairs. By default, they are entered one by one in the **Key value** view (<code className="action">Add a key/value</code> adds a row). In the **JSON** view, you can enter them in JSON format:

```json
{
    "login": "admin",
    "password": "my_secret_password"
}
```

<img className="thumbnail" alt="Create a secret page with the Path and Values configuration sections" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/create-secret-form.png" loading="lazy" />

:::info
There is no limit to the number of key-value pairs in a secret, however the total data size must not exceed 64 KB.
:::


Once the secret is created, it appears in the list of secrets in the **Secrets** tab of the OKMS domain.

{/* CP-STEPS-END:create-secret */}

### Managing Secrets

{/* CP-STEPS-START:manage-secrets */}

Once a secret is created, the list of secrets is displayed in the **Secrets** tab of the OKMS domain, in the OVHcloud Console.
To display the secrets of another OKMS domain, select it from the **OKMS domain** list above the tabs, where your domains are grouped by region.

You can access the configuration of the secret by clicking its path in the list of secrets to display its content, create a new version, or delete it.

The secret dashboard displays several pieces of information, such as general information and parameters applying to the secret:

- **Maximum number of versions**: Beyond the indicated value, the oldest version is deleted.
- **Duration of version validity**: Beyond the indicated period, the version is disabled.
- **CAS (Check-And-Set Version Control)**: If activated, you must always specify the current version number when making changes.

<img className="thumbnail" alt="Secret dashboard with the Values, General information and Configuration sections" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secret-dashboard.png" loading="lazy" />

{/* CP-STEPS-END:manage-secrets */}

#### Accessing the Content of a Secret

A user with the necessary IAM rights can access the content of a secret. Configure authentication and IAM policies as described in [OKMS authentication methods](/guides/manage-and-operate/kms/okms-authentication-methods).

:::info
The rights to list a version (**okms:apiovh:secret/get**) are different from the right to retrieve the content of this version (**okms:apiovh:secret/version/getData**).
:::


{/* CP-STEPS-START:access-secret-content */}

To do this, click on <code className="action">Reveal the value</code> in the **Values** section of the secret dashboard.

The **Values** section expands and displays the content of the most recent version of the secret, as key-value pairs or in JSON format. Each value can be copied.

<img className="thumbnail" alt="Values section showing the key-value pairs of the current version" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secret-values-revealed.png" loading="lazy" />

A selector allows you to navigate between different versions of the secret, and view the status of the selected version.
If the version is disabled or deleted, no value is displayed.

{/* CP-STEPS-END:access-secret-content */}

#### Managing Versions

{/* CP-STEPS-START:manage-versions */}

To access the versions of a secret, click the <code className="action">Versions</code> tab. It lists all versions of the secret, each with its number, creation date, expiration date and status.
Each modification of a secret creates a new version.

<img className="thumbnail" alt="Versions tab listing the versions of a secret with their status" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/secret-versions.png" loading="lazy" />

A version can be either:

- Active: The value of this version is accessible.
- Deactivated: The value of this version is still present in the system but is no longer accessible until the version is reactivated.
- Deleted: The value of this version is no longer present in the system and cannot be restored.

For each version, click <code className="action">Reveal the version</code> to display its value. The `⋮` button opens a menu to disable (<code className="action">Disable</code>) or reactivate (<code className="action">Reactivate</code>) the version, or delete it (<code className="action">Delete</code>).

A version deleted by the **Maximum number of versions** parameter no longer appears in the list of versions.

{/* CP-STEPS-END:manage-versions */}

### Managing the OKMS Domain

The OKMS domain of the Secret Manager is shared with the OKMS domain of the Key Management Service.
Creating or deleting an OKMS domain therefore has consequences for both products.

You can modify the secrets configuration of the OKMS domain from its **Overview** tab, in the **Secrets configuration** section (<code className="action">Modify</code>).

#### Multi-OKMS Domain Case

{/* CP-STEPS-START:multi-okms-domain */}

Several OKMS domains can exist in the same region. The OKMS domain is chosen beforehand, from the **OKMS domain** list above the tabs, which groups your domains by region. The secrets you display or create belong to the domain selected in this list: there is no additional selection step when creating a secret.

<img className="thumbnail" alt="OKMS domain list with domains grouped by region and the Create domain entry" src="/images/manage-and-operate/secret-manager/secret-manager-ui/console/okms-domain-switcher.png" loading="lazy" />

To add an OKMS domain in a region, click <code className="action">Create domain</code> at the top of this list, then choose the region.

{/* CP-STEPS-END:multi-okms-domain */}

### Using the Secret Manager via API

The Secret Manager is accessible via two different API sets. Both manipulate the same objects — a secret created by one method is accessible by the other.

Before calling either API, configure an [authentication method](/guides/manage-and-operate/kms/okms-authentication-methods) and the required [IAM policy](/guides/manage-and-operate/kms/okms-authentication-methods#iam-rights-for-okms) on your OKMS domain. For REST API usage, a Personal Access Token or service account is recommended.

- A [REST API](/guides/manage-and-operate/secret-manager/rest-api) similar to OVHcloud's standard APIs.
- A [HashiCorp Vault KV2 compliant API](/guides/manage-and-operate/secret-manager/kv2-api) providing compatibility with applications already compatible with HashiCorp Vault KV2.
