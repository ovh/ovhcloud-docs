## Objective

The purpose of this guide is to show you the steps to follow to configure and manage the OKMS access certificate for your Data Security products.

## Requirements

- An [OVHcloud customer account](/guides/account-and-service-management/account-information/ovhcloud-account-creation).
- An [OVHcloud KMS ordered](/guides/manage-and-operate/kms/quick-start)

[[cpnav:security-kms]]

## Instructions

### OKMS access certificate description

To communicate with your OKMS domain, you need an access certificate. This is one of three [OKMS authentication methods](/guides/manage-and-operate/kms/okms-authentication-methods); certificates are **required for KMIP** and recommended when mTLS client authentication is needed. For REST API usage, a Personal Access Token or service account is usually simpler to set up.

An access certificate is only valid for the domain for which it was generated.

:::warning
Only the certificate creation with a CSR is covered by the PCI-DSS certification.

:::


### Create an access certificate from the KMS

<Tabs>
<Tab label="OVHcloud Console">

You can create this certificate from your OKMS domain in Key & Secret Manager.

In the <code className="action">Access certificates</code> tab, click on <code className="action">Create an access certificate</code>.

<img className="thumbnail" alt="Access certificates tab of a KMS domain" src="/images/manage-and-operate/kms/okms-certificate-management/console/access-certificates-tab.png" loading="lazy" />

In the **General information** section, enter a **Display name** for the certificate and, optionally, a **Description**.

The **Access certificate configuration** section allows you to set its **Validity** duration, choose the **Creation method** (with or without your own Certificate Signing Request (CSR), if you have your own private key), and choose the signature algorithm when you do not provide a CSR.

#### Without providing a private key

If you do not provide a CSR, select **I don't have a private key**: OVHcloud will generate the certificate and a private key as well. You can then choose the **Certificate type**, ECDSA (recommended) or RSA.

<img className="thumbnail" alt="Create an access certificate form without a private key" src="/images/manage-and-operate/kms/okms-certificate-management/console/create-access-certificate-form.png" loading="lazy" />

#### With a CSR

If you have your own private key, you can use it with a CSR: select **I already have a private key**, then paste your PEM-encoded CSR in the **Certificate Signing Request (CSR)** field.

<img className="thumbnail" alt="Create an access certificate form with a CSR" src="/images/manage-and-operate/kms/okms-certificate-management/console/create-access-certificate-csr.png" loading="lazy" />

The **Add user IDs** section allows you to specify the [OVHcloud identities](/guides/manage-and-operate/iam/identities-management) associated with the certificate used to calculate access rights via the [OVHcloud IAM](/guides/account-and-service-management/account-information/iam-policy-ui). Select **Choose identities** to pick them from the **Users**, **User groups** and **Service accounts** lists, up to 25 identities.

You can also select **Attach root identity** so as not to be constrained by the OVHcloud IAM: the certificate will automatically have admin rights on the OKMS domain. This option is intended for test environments.

<img className="thumbnail" alt="Add user IDs section of the access certificate form" src="/images/manage-and-operate/kms/okms-certificate-management/console/create-access-certificate-identities.png" loading="lazy" />

Click on <code className="action">Create</code>. You then need to download the private key of the certificate: click on <code className="action">Download private key</code>, tick **I have downloaded the private key**, then click on <code className="action">Finish</code>.

:::danger
The private key will no longer be accessible at a later stage. If you lose it, you will need to regenerate a certificate.

:::


:::warning
The **privateKeyPEM** field needs to be edited so that all instances of `\n` are replaced by carriage returns.

:::


<img className="thumbnail" alt="Private key download step after creating an access certificate" src="/images/manage-and-operate/kms/okms-certificate-management/create_certificat_05.png" loading="lazy" />

Finally, you can download the public key of the certificate from its page: open the certificate from the <code className="action">Access certificates</code> tab, then click on <code className="action">Download certificate</code>.

<img className="thumbnail" alt="Access certificate page with the Download certificate button" src="/images/manage-and-operate/kms/okms-certificate-management/console/access-certificate-download.png" loading="lazy" />

</Tab>
<Tab label="OVHcloud API">

You can generate this certificate by letting OVHcloud generate the private key, or by providing your Certificate Signing Request (CSR) in case you have your own private key.

#### Without providing a private key

If you do not provide a CSR, OVHcloud will generate the access certificate along with a private key.

You can generate a certificate via the following API call:

<Api version="v2" section="/okms" method="POST" route={"/okms/resource/\{okmsId\}/credential"} />

The following information is required:

- **name**: the name of the certificate
- **identityURNs**: list of OVHcloud identities in URN format that will be provided to the IAM for calculating access rights
- **description**: certificate description (optional)
- **certificateType**: certificate signature algorithm (ECDSA or RSA) - ECDSA by default (optional)
- **validity**: certificate validity duration in days - 365 days by default (optional)

**Example of certificate creation with root account:**

```json
{
  "description": "My root access credential",
  "identityURNs": [
    "urn:v1:eu:identity:account:xx1111-ovh"
  ],
  "name": "root",
  "validity": 30
}
```

**Example of certificate creation with local user:**

```json
{
  "description": "My access credential",
  "identityURNs": [
    "urn:v1:eu:identity:user:xx1111-ovh/john.smith",
    "urn:v1:eu:identity:group:xx1111-ovh/my_group"
  ],
  "name": "John Smith",
  "validity": 30
}
```

The API then returns the certificate creation status:

```json
{
  "id": "f18b5e0d-75b8-40a3-9b0e-XXXXXX",
  "name": "John Smith",
  "description": "My access credential",
  "identityURNs": [
    "urn:v1:eu:identity:user:xx1111-ovh/john.smith",
    "urn:v1:eu:identity:group:xx1111-ovh/my_group"
  ],
  "certificateType": "ECDSA",
  "status": "CREATING",
  "fromCSR": false,
  "privateKeyPEM": "-----BEGIN EC PRIVATE KEY-----\nMHcCAQEEIDOfWuMVQxl5quoURzThF4zTI9YYTmylSaPjneLBwP+2oAoGCCqGSM49\nAwEHoUQDQgAERd1eMw0YdAD+E9oSymGc4bCL1mfJl0EZwoM2ya/uKFFVFnGMnckg\nXXXXXXXXXXXXXXX==\n-----END EC PRIVATE KEY-----\n",
```

Copy the value of the **privateKeyPEM** field to a **domain.key** file

#### With a CSR

If you have your own private key, it is possible to use it by providing a CSR.

You can generate a certificate via the following API call:

<Api version="v2" section="/okms" method="POST" route={"/okms/resource/\{okmsId\}/credential"} />

The following information is required:

- **name**: the name of the certificate
- **identityURNs**: list of OVHcloud identities in URN format that will be provided to the IAM for calculating access rights

- **csr**: the content of the CSR

:::warning
The CSR must be in JSON format. The CSR file must be edited so that there are no carriage returns; instead, `\n` will have to be inserted where the line breaks were previously (see the example below).
