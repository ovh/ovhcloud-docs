## Objective

**This page lists the issues you may encounter with the Backup Licenses product, and how to solve them.**

## Requirements

- A Backup Licenses licence that you have ordered and for which you have received the delivery email. See our "[Ordering and configuring your first licence](/guides/storage-and-backup/backup-licenses/first-configuration)" guide for more information.
- A Veeam Backup & Replication server, installed and operational.

## List of possible issues

<details>

<summary>My VBR server does not appear in the VSPC right after the wizard.</summary>

On a VBR server running **Windows**, enrolling the server takes **at least 15 minutes** after the <code className="action">Add Service Provider</code> wizard completes. Until this delay has elapsed, it is normal for your server not to appear in the VSPC, and for the licence not to be applied yet.

Wait for this delay to elapse before working through the points below.

</details>

<details>

<summary>I cannot connect my VBR server to your console (VSPC).</summary>

This covers the case where the <code className="action">Add Service Provider</code> wizard fails in your Veeam Backup & Replication console: the connection to our infrastructure does not go through.

Check that **your firewall allows the outbound connection from your VBR server to our server**, that is, to the cloud gateway DNS address provided in your delivery email (in the form `vspc-adv-cgw…`), on **port 6180**.

Also check that:

- the DNS address and port entered in the wizard exactly match those in the delivery email;
- the **Company Tenant** credentials you entered are those from the delivery email;
- your VBR server runs **version 12 or higher** (see the [known restrictions](/guides/storage-and-backup/backup-licenses/restrictions)).

</details>

<details>

<summary>My VBR server is still not connected after our console (VSPC) connected to it.</summary>

This covers the case where the wizard completed without an error, but the server does not appear — or appears as unreachable — in the VSPC. The outbound connection works; it is the return path to your server that is blocked, or the management agent that was not deployed.

Check the following two points:

- **Your firewall allows connections to your server from our IP address.** In Europe, our infrastructure reaches your VBR server from the address `79.137.44.43`, without restriction.
- **You ticked the** <code className="action">Allow this Veeam Backup & Replication installation to be managed by the service provider</code> **option** when adding the service provider. Without this option, the management agent is not installed and your server cannot be managed from the VSPC.

If the option was not ticked, edit the service provider from your VBR console (<code className="action">Backup Infrastructure</code> > <code className="action">Service Providers</code> > right-click > <code className="action">Edit provider</code>), tick the option, then run the wizard through to completion.

<img className="thumbnail" alt="Service Provider step of the wizard, with the management checkbox ticked" src="/images/storage-and-backup/backup-licenses/vbr/bl_wizard_1.png" loading="lazy" />

To pinpoint where the connection is stuck, log in to the VSPC portal and open the <code className="action">Managed Computers</code> section, <code className="action">Discovered Computers</code> tab. The <code className="action">Connection Status</code>, <code className="action">Deployment Status</code> and <code className="action">Management Agent Status</code> columns show how far the management agent deployment has got on your server.

<img className="thumbnail" alt="Discovered Computers tab in the VSPC" src="/images/storage-and-backup/backup-licenses/vspc/bl_vspc_discovered_computer.png" loading="lazy" />

</details>

<details>

<summary>My VBR server appears as "Inaccessible" in the VSPC.</summary>

If **MFA** (multi-factor authentication) is enabled on the connected VBR server, it may appear with the `Inaccessible` status in the VSPC.

See [Veeam KB 4431](https://www.veeam.com/kb4431) for the resolution procedure.

</details>

<details>

<summary>The licence does not appear, or is invalid, on my VBR server.</summary>

In the Veeam Backup & Replication console, open the main menu and click <code className="action">License</code> to display the <code className="action">License Information</code> window.

- If the status is not `Valid`, first check that your VBR server is correctly connected to the VSPC (see the first two points on this page).
- Check that the edition displayed matches the one you ordered, and that your operating system is compatible with that edition (see the [known restrictions](/guides/storage-and-backup/backup-licenses/restrictions)).

If the issue persists while the connection is established, [contact OVHcloud support](/links/support-contact), providing screenshots of the <code className="action">License Information</code> window.

<img className="thumbnail" alt="License Information window in the VBR console" src="/images/storage-and-backup/backup-licenses/vbr/bl_license.png" loading="lazy" />

</details>

<details>

<summary>The public IP address of my VBR server has changed.</summary>

The IP address entered at order time is what allows traffic between our infrastructure and your server. If it changes, update it from your Control Panel: <code className="action">Linked servers</code> tab, <code className="action">...</code> menu to the right of the server, then <code className="action">Edit</code>.

<img className="thumbnail" alt="Linked server actions menu with the Edit option" src="/images/storage-and-backup/backup-licenses/control-panel/bl_server_edit_en.png" loading="lazy" />

</details>

<details>

<summary>I connected the same VBR server twice and the data displayed is inconsistent.</summary>

Do not connect a VBR server that is already connected to the VSPC using different credentials: this skews the data displayed in the VSPC.

Remove the duplicate service provider from your VBR console (<code className="action">Backup Infrastructure</code> > <code className="action">Service Providers</code> > right-click > <code className="action">Remove provider</code>), then keep only the connection matching your currently valid credentials.

</details>

<details>

<summary>My VBR is part of a high availability cluster and only one node appears.</summary>

If your VBR is the **primary** node of a high availability cluster, the VSPC registers it as a cluster node. The **secondary** node must be connected separately, following the same service provider procedure.

</details>
