## Using the OVHcloud Console
In the OVHcloud Console, open **Bare Metal Cloud**, click <code className="action">Cloud Disk Array</code> under **Storage** in the left-hand menu, then click the name of your Ceph cluster. The <code className="action">Overview</code> tab shows the **General information**, **Service configuration** and **Storage** tiles.

### Cluster details

Additional explanations:

| Field | Description |
|-------|-------------|
| **Alias** (General information) | Name given to your cluster |
| **Identifier** (General information) | Identifier (fsid) of your cluster, used as `serviceName` in the API |
| **Region** (General information) | We currently deliver Ceph clusters on Strasbourg, Gravelines and Beauharnois. |
| **Version** (General information) | We currently deliver clusters up to version 9.2.1 ([official Ceph releases](https://docs.ceph.com/en/latest/releases/general/)) |
| **Crush tunables** (Service configuration) | It's the algorithm used to place datas. |
| **Billing status** (Service configuration) | Active |
| **Monitors** (Service configuration) | IP that you have to use to reach your monitors. |
| **Creation date** (General information) | Creation date of your cluster |
| **Last modified date** (General information) | Date of the last task applied to your cluster |

The **Storage** tile shows the **Total size**, **Used space** and **Available space** of the cluster. Operations in progress on the cluster are listed in the <code className="action">Activities</code> tab.

### Cluster health

The health of the cluster is shown in the **Service configuration** tile.

Additional explanations:

| Field | Description |
|-------|-------------|
| **Health** | **OK** (HEALTH_OK) means that every object is at the right place and have 3 replicates. HEALTH_WARN means that some objects are misplaced (like after a growth) or that some object are not replicated three times. In this case cluster is recovering |
| **Healthy cluster** | **Yes** or **No**, indicating if everything is ok with Ceph cluster or not |
| **Available bytes** | Free bytes available in the cluster (before replication) |
| **Used bytes** | Bytes currently used in the cluster (after replication) |
| **Space usage [%]** | Percentage of *used bytes* in relation to *total bytes* |
| **Cluster active tasks** | List of user-initiated tasks that are currently being processed for this cluster |

## Using API
Get Ceph cluster details with a simple HTTP call.

<Api version="v1" section="/dedicated/ceph" method="GET" route={"/dedicated/ceph/\{serviceName\}"} />

Example:

```bash
GET /dedicated/ceph/98d166d8-7c88-47b7-9cb6-63acd5a59c15
{
  updateDate: "2016-07-26T09:16:07"
  status: "INSTALLED"
  region: "SBG1"
  serviceName: "98d166d8-7c88-47b7-9cb6-63acd5a59c15"
  state: "ACTIVE"
  createDate: "2016-07-20T08:00:37"
  cephMons: [
    "10.99.187.210"
    "10.99.191.210"
    "10.97.131.210"
  ]
  crushTunables: "OPTIMAL"
  label: "Ceph cluster"
  cephVersion: "9.2.1"
}
```

Get Ceph cluster health:

<Api version="v1" section="/dedicated/ceph" method="GET" route={"/dedicated/ceph/\{serviceName\}/health"} />


```bash
{
  status: "HEALTH_OK"
  availableBytes: 5891996504064
  serviceName: "98d166d8-7c88-47b7-9cb6-63acd5a59c15"
  healthy: true
  usedBytes: 124981248
}
```
