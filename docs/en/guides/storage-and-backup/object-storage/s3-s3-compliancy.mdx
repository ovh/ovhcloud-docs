## Objective

OVHcloud Object Storage is compatible with the S3<sup>1</sup> API, so you can use your usual tools, SDKs and applications with it. However, not every S3 feature is available, and availability can differ between deployment modes.

**This guide helps you check, at a glance, whether a feature you need is supported, and what to use instead when it is not.**

## How to read this guide

Availability is given for two deployment modes:

- **Regions**: 1-AZ and 3-AZ Regions.
- **Local Zones**: Object Storage deployed in OVHcloud Local Zones, closer to your end users.

To learn more about deployment modes, read our guide [Comparison of Object Storage Deployment Modes](/guides/storage-and-backup/object-storage/s3-regions-comparison). To find the deployment mode of a given location, read [Object Storage - Endpoints and geoavailability](/guides/storage-and-backup/object-storage/s3-location).

| Symbol | Meaning |
|--------|---------|
| ✅ | Supported |
| ⚠️ | Partially supported: some operations or options of the feature are not available (see the [detailed list](#detailed-list-of-supported-s3-api-operations)) |
| ❌ | Not supported |

When a feature that is not supported in Regions is tracked on our [public roadmap](https://github.com/orgs/ovh/projects/16/views/1?sliceBy%5Bvalue%5D=Public+Cloud+Storage), the issue number is shown next to the symbol, for example ❌ ([#827](https://github.com/ovh/public-cloud-roadmap/issues/827)). Open the issue to check its current status, follow it, vote for it with a 👍 reaction and share your use case in the comments.

A feature with no issue number is not tracked on the public roadmap yet. This does not mean that it will never be implemented. If a feature matters to you, [open a new issue](https://github.com/ovh/public-cloud-roadmap/issues) to tell us about it. The public roadmap covers Regions only; it does not cover Local Zones.

:::info
Roadmap information is provided for guidance only and may change without notice. It does not constitute a commitment to deliver a feature by a given date.
:::

## Feature not supported? What to use instead

| If you need… | Use instead |
|--------------|-------------|
| **Bucket policies** | In Regions: [user policies](/guides/storage-and-backup/object-storage/s3-identity-and-access-management) attached to your Object Storage users, combined with [ACLs](/guides/storage-and-backup/object-storage/s3-bucket-acl). In Local Zones, user policies are not supported: all access keys of a project can access all buckets (see [Local Zones specifications](/guides/storage-and-backup/object-storage/s3-local-zones-limitations)). |
| **Block public access** | Buckets and objects are private by default. Only grant public access explicitly, using [ACLs](/guides/storage-and-backup/object-storage/s3-bucket-acl) or [presigned URLs](/guides/storage-and-backup/object-storage/s3-share-object-externally) for temporary sharing. |
| **SSE-KMS encryption** | [SSE-OMK](/guides/storage-and-backup/object-storage/s3-encrypt-your-objects-with-sse-c) if you want OVHcloud to manage the keys, or [SSE-C](/guides/storage-and-backup/object-storage/s3-encrypt-your-objects-with-sse-c) if you want to manage them yourself. |
| **Intelligent tiering** | [Lifecycle transition rules](/guides/storage-and-backup/object-storage/s3-bucket-lifecycle) to move objects to a lower-cost [storage class](/guides/storage-and-backup/object-storage/s3-choosing-the-right-storage-class-for-your-needs) after a set number of days. |
| **Bucket inventory** | List your objects with the `ListObjectsV2` or `ListObjectVersions` operations, for example with the AWS CLI or [rclone](/guides/storage-and-backup/object-storage/s3-rclone). |
| **Audit of requests made to a bucket** | [Server access logging](/guides/storage-and-backup/object-storage/s3-server-access-logging) (Regions only). |
