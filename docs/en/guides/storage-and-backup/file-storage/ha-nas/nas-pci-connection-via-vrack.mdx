## Objective

Mount a HA-NAS NFS volume from a Public Cloud instance using a private vRack network.

This ensures that all data traffic remains on the private network, with no Internet exposure.

:::info
The HA-NAS volume and the Public Cloud instance must be located in the same region (e.g. RBX, GRA, or SBG), as OpenStack private networks are regional.

:::


## Requirements

- An [HA-NAS](/links/storage/nas-ha) service in your OVHcloud account.
- An [OVHcloud Public Cloud instance](/guides/public-cloud/compute/getting-started) in the same region.
- An active [vRack Private Network](/guides/public-cloud/network-services/vrack) in the same region.

## Overview

The diagram below illustrates how a HA-NAS volume connects to a Public Cloud instance through a private vRack network.

<img className="thumbnail" alt="global schema" src="/images/storage-and-backup/file-storage/ha-nas/nas-pci-connection-via-vrack/architecture.png" loading="lazy" />

1. Critical Match — VLAN ID

    The VLAN ID (e.g. `1900`) must be identical in both the Public Cloud private network and the vRack Services configuration.

2. Critical Match — Subnet CIDR

    The subnet CIDR (e.g. `10.235.0.0/24`) must also match across both services to ensure they operate within the same logical network in the vRack.

3. Info — Service address range

    The service address range (e.g. `10.235.0.240/28`) is a reserved subset of the main subnet. These IPs are exclusively used by HA-NAS service endpoints (e.g. `10.235.0.241`) and must not be assigned to instances.

4. Security — ACL Rule

    The HA-NAS volume’s Access Control List (ACL) must explicitly authorize the private IP of any instance requiring access (e.g. `10.235.0.15`).

5. Concept — vRack Services

    vRack Services acts as a secure network bridge, allowing managed services such as HA-NAS outside your Public Cloud project to connect seamlessly to your private vRack network.

## Instructions

### Step 1 - Associate the Public Cloud project with the vRack

Before deploying your HA-NAS volume through a private vRack network, your Public Cloud project must first be associated with a vRack.

This association enables private networking between your Public Cloud instances and OVHcloud managed services such as HA-NAS.

Follow the procedure described in the **step 1: activating and managing a vRack** in our guide "[Configuring vRack for Public Cloud](/guides/public-cloud/network-services/vrack)".

### Step 2 - Create a Private Network in Your Public Cloud Project <a name="step2"></a>

To connect your Public Cloud instance to a HA-NAS volume via vRack, first provision a dedicated private network within your project. 

This isolated network enables secure communication between your instances and OVHcloud storage resources through the vRack architecture. 

Follow the procedure described in the **step 2: creating a private network in the vRack** in our guide "[Configuring vRack for Public Cloud](/guides/public-cloud/network-services/vrack)".

### Step 3 — Launch the Instance on the Private Network

Deploy your Public Cloud instance within the private network you created. Ensure it is connected to the correct subnet to enable secure communication over the vRack. 

Follow the procedure described in the **step 3: integrating an instance into vRack** in our guide "[Configuring vRack for Public Cloud](/guides/public-cloud/network-services/vrack)".

Ensure that an IP address is assigned to the instance in the selected subnet (e.g. `10.235.0.15`).

### Step 4 - Create a vRack Service resource for HA-NAS

There are two ways to create a vRack Service resource for your HA-NAS volume.

Both methods achieve the same goal: securely connecting your HA-NAS service to your vRack and Public Cloud instances.

<details>

<summary>First method: creating via vRack Services</summary>


A vRack Service resource acts as a network adapter, connecting managed services like HA-NAS to your vRack and its private subnet.

For detailed guidance, see OVHcloud’s official documentation: [vRack Services - Exposing a Managed Service on your vRack](/guides/network/vrack-services/global).

1. In the OVHcloud Console, open **Bare Metal Cloud**, then click <code className="action">vRack Services</code> under **Network** in the left-hand menu.

2. Click <code className="action">Order a vRack Service</code>.

3. Select the same **Region** as your vRack, Public Cloud instance and HA-NAS service. Then click <code className="action">Order a vRack Service</code>. <a name="step4-a-region-selection"></a>

4. Click <code className="action">No thanks, I already have a vRack</code>, tick the box to accept the terms and conditions, then click <code className="action">Confirm</code>.

5. Then, locate your newly created vRack Services in the list and click its name.

6. Configure the vRack Services as follows:

    - vRack: in the **General information** tile of the <code className="action">Overview</code> tab, click <code className="action">Attach a vRack</code>, select the same vRack used for your Public Cloud project, then click <code className="action">Attach</code>.

    - Create a subnet: in the <code className="action">Subnets</code> tab, click <code className="action">Add a subnet</code> and fill in the form.

        :::info
        Ensure the CIDR matches your Public Cloud private network.

        :::


        - **CIDR**: e.g. `10.235.0.0/24`.
        - **Service range**: e.g. `10.235.0.240/28`.
            - Reserved subset of the private subnet for assigning IPs to managed HA-NAS services within the vRack.
        - **VLAN**: select **Use a VLAN** and enter the same **VLAN number** as your Public Cloud private network (see [Step 2](#step2)).
        - Click <code className="action">Add a subnet</code>.

    - Create a Service Endpoint: in the <code className="action">Endpoints</code> tab, click <code className="action">Create an endpoint</code>. Select **NAS-HA** as the **Service type**, select your HA-NAS service in **Managed service** and your **Subnet**, then click <code className="action">Create an endpoint</code>.

</details>


<details>

<summary>Second method: creating via the NAS-HA section</summary>


1. Click the name of your HA-NAS service in the list.

2. In the **Network configuration** tile of the <code className="action">Overview</code> tab, click <code className="action">Configure network</code>.

3. Select your vRack in the **vRack** field.

4. If no vRack Services have been created yet, click <code className="action">Activate vRack Services</code> and follow the [first method: creating via vRack Services](#step4-a-region-selection) from the third point.

5. If you have already created a vRack Services, select it in the **vRack Services** field, select your **Subnet**, then click <code className="action">Configure network</code>.

</details>


### Step 5 — Connect the HA-NAS volume to the vRack

Once the previous steps are completed successfully, all volumes created in your HA-NAS service will automatically reside within your vRack and its dedicated subnet, making them immediately accessible to your Public Cloud instances.

### Step 6 — Configure access control (ACLs)

In the <code className="action">ACL</code> tab of your HA-NAS volume, click <code className="action">Add a rule</code>:

- In **IP address**, add the IP or CIDR range authorized to mount the volume:

    - To allow a single instance, enter the instance's IP address, for example: `10.235.0.15`.
    - To allow all instances within the subnet, enter the subnet address, for example: `10.235.0.0/24`.

- Set the desired **Access level**: **Read/Write** or **Read only**, then click <code className="action">Add</code>.

:::info
**Recommendation:** Use individual IPs whenever possible to enhance security.

:::


After applying the ACLs, verify network connectivity from your Public Cloud instance:

```bash
ping <YOUR-HA-NAS-SERVICE-IP>
```

### Step 7 — Mount the volume

You can mount your HA-NAS volume via NFS or via CIFS. You will need the following values:

| Argument | Description |
|---|---|
| `<YOUR-HA-NAS-SERVICE-IP>` | The IP address of your Service Endpoint, displayed in the **Network configuration** tile of your HA-NAS service (e.g. `10.235.0.241`) |
| `<NFS_PATH>` | The path to the volume, consisting of the service name and the partition name (e.g. `zpool-123456/partition01`) |
| `<CIFS_PATH>` | The path to the volume, consisting of the service name and the partition name separated by `_` (e.g. `zpool-123456_partition01`) |

:::warning
The NFS user is `root` and the SMB/CIFS user is `nobody`. Changing permissions with one of these users may generate conflicts with the permissions set by the other protocol.

:::


#### Mounting via NFS

1. Install the NFS client on your Public Cloud instance:

    ```bash
    sudo apt install -y nfs-common
    ```

2. Mount the HA-NAS volume:

    ```bash
    sudo mkdir -p /mnt/ha-nas
    sudo mount -t nfs <YOUR-HA-NAS-SERVICE-IP>:/<NFS_PATH> /mnt/ha-nas
    df -h /mnt/ha-nas
    ```

    **Example:**

    ```bash
    sudo mount -t nfs 10.235.0.241:/zpool-123456/partition01 /mnt/ha-nas
    ```

HA-NAS supports NFSv3 and NFSv4. If no version is specified, your NFS client uses the latest version it supports. To force a version, add the `-o vers=3` (or `vers=4`, `vers=4.1`, `vers=4.2`) option. For more information, and for the instructions for other operating systems, see our guide "[Mounting HA-NAS via NFS share](/guides/storage-and-backup/file-storage/ha-nas/nas-nfs)".

#### Mounting via CIFS

**From a Linux instance**

1. Install the CIFS utilities on your Public Cloud instance:

    ```bash
    sudo apt install -y cifs-utils
    ```

2. Mount the HA-NAS volume:

    ```bash
    sudo mkdir -p /mnt/ha-nas
    sudo mount -t cifs -o uid=root,gid=100,dir_mode=0700,username=root,password= //<YOUR-HA-NAS-SERVICE-IP>/<CIFS_PATH> /mnt/ha-nas
    ```

**From a Windows instance**

Open **Windows PowerShell** and run the following command:

```bash
net use z: \\<YOUR-HA-NAS-SERVICE-IP>\<CIFS_PATH>
```

**Example:**

```bash
net use z: \\10.235.0.241\zpool-123456_partition01
```

For more information, including how to resolve the Windows errors `System error 1272` and `System error 3227320323`, see our guide "[Mount your HA-NAS via a CIFS share](/guides/storage-and-backup/file-storage/ha-nas/nas-cifs)".

### Step 8 — Enable Automatic NFS Mount on Boot (optional)

To ensure your HA-NAS volume mounted via NFS mounts automatically at startup, add the following entry to the `/etc/fstab` file:

```bash
<YOUR-HA-NAS-SERVICE-IP>:/<NFS_PATH> /mnt/ha-nas nfs rw 0 0
```

Then test the configuration:

```bash
sudo umount /mnt/ha-nas
sudo mount -a
```

If no errors occur, the HA-NAS volume will now automatically mount on boot.

## Expected Result

- The instance can access the HA-NAS volume via `<YOUR-HA-NAS-SERVICE-IP>`.
- All communication occurs privately within the vRack.
- The NFS or CIFS mount is fully functional, and the NFS mount is persistent across reboots.

## Troubleshooting

| Symptom                            | Likely Cause                                              | Resolution                                                                                                                                     |
| ---------------------------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| mount.nfs: No route to host        | Instance and HA-NAS not in the same region, or wrong VLAN ID. | Ensure the instance, HA-NAS, and vRack Services are in the same region. Recreate the vRack Service using the same VLAN ID as the private network. |
| mount.nfs: access denied by server | HA-NAS ACL missing or incorrect.                              | Add the instance IP (e.g. `10.235.0.x`) or subnet (e.g. `10.235.0.0/24`) with protocol NFSv3 and Read/Write access.                          |
| mount command hangs indefinitely   | Wrong NFS version or unresponsive endpoint.                | Use: `-o vers=3,timeo=600,retrans=2` to force NFSv3 and define timeouts.                                                                       |
| mount succeeds but no read/write   | ACLs or POSIX permissions too strict.                      | Adjust ACLs or update volume-level permissions.                                                                                               |
| mount works, but not after reboot  | Missing `/etc/fstab` entry.                                  | Add: `<YOUR-HA-NAS-SERVICE-IP>:/<NFS_PATH> /mnt/ha-nas nfs rw 0 0`.                                                           | 
| vRack Services shows "Inactive"    | Service not yet provisioned.                               | Wait for provisioning to complete, or reconfigure it from the **Network configuration** tile of your HA-NAS service.                                                   |
