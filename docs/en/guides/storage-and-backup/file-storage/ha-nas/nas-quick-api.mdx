## Objective

The OVHcloud HA-NAS service allows you to manage file storage that can be accessed over a network. 

**This guide provides an overview of how to use your HA-NAS service via the OVHcloud API.**

## Requirements

- An OVHcloud [HA-NAS service](https://www.ovhcloud.com/en-gb/storage-solutions/nas-ha/)
- Consulting the [OVHcloud API first steps guide](/guides/manage-and-operate/api/first-steps) to familiarise yourself with the OVHcloud APIv6

## Instructions

All API routes in this guide are available in the <ApiLink section="/dedicated/nasha">*/dedicated/nasha* section</ApiLink> of the API console.

:::info
When using the API, all fields marked with an asterisk (\*) are required.
:::


### Retrieving information about your service

All your active services can be retrieved by using the following route:

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha"} />


### Creating a partition

Use the following route to create a new partition:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | The internal name of your HA-NAS service |
| `partitionDescription` |  | Optional description |
| `partitionName` | Yes | A name for the partition |
| `protocol` | Yes | *NFS*, *CIFS*, or *NFS_CIFS* for both |
| `size` | Yes | The size of the partition |

Choose `NFS` as protocol and a size of `10` Gigabytes, for example.

### Adding an ACL entry to access the partition

:::warning
Access is denied by default unless granted via the ACL. Only IP addresses attached to your OVHcloud services can be added.
:::


You can verify the IP addresses that are eligible for access via the following API calls:

<Api version="v1" section="/dedicated/nasha" method="GET" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/authorizableBlocks"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | The internal name of your HA-NAS service |
| `partitionName` | Yes | Name of the partition |

To create a new ACL entry that will allow you to connect to your partition, use the following route:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/access"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | The internal name of your HA-NAS service |
| `partitionName` | Yes | Name of the partition |
| `ip` | Yes | The IP address or range to be granted access |
| `type` | Yes | ACL access type for this entry: *readonly* or *readwrite* |

:::info
Use CIDR notation for IP ranges, for example: 192.0.2.0/24.
:::


### Creating a manual snapshot

To add a manual snapshot, use the following route:

<Api version="v1" section="/dedicated/nasha" method="POST" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}/customSnapshot"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | The internal name of your HA-NAS service |
| `partitionName` | Yes | Name of the partition |
| `expiration` |  | An optional expiration date, for example: 2022-06-24 (ISO 8601) |
| `name` | Yes | A name for the snapshot |

### Deleting a partition

Use the following route to delete a partition:

<Api version="v1" section="/dedicated/nasha" method="DELETE" route={"/dedicated/nasha/\{serviceName\}/partition/\{partitionName\}"} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | The internal name of your HA-NAS service |
| `partitionName` | Yes | Name of the partition |

## Using the API with a Private NAS-HA (Beta)

:::info
Private NAS-HA is currently in beta phase. Its API routes differ from those described above: they are available in the <ApiLink section="/storage">*/storage* section</ApiLink> of the API console, and the partitions are called **shares** there. This section may change as the product evolves.

:::


To connect a Private NAS-HA to your vRack private network, see our guide "[HA-NAS - Private network configuration (Beta)](/guides/storage-and-backup/file-storage/ha-nas/nas-network-config)".

### Retrieving information about your service (Beta)

To list your Private NAS-HA services, use the following route:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha"} regions={["eu"]} />


The `id` field of the response is the `serviceName` used by the routes below.

To retrieve the `shareId` of your shares (the `id` field of the response), use the following route:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | The ID of your Private NAS-HA service |

### Adding an ACL entry to access the share (Beta)

:::warning
Access is denied by default unless granted via the ACL.
:::


To create a new ACL entry that will allow you to connect to your share, use the following route:

<Api version="v1" section="/storage" method="POST" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/acl"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | The ID of your Private NAS-HA service |
| `shareId` | Yes | The ID of the share |
| `accessLevel` | Yes | ACL access level: *rw* (read and write) or *ro* (read-only) |
| `accessTo` | Yes | The IPv4 address or range to be granted access |

:::info
Use CIDR notation for IP ranges, for example: 10.235.0.0/24.
:::


### Retrieving the mount point (Beta)

To retrieve the `accessPathId` of the access paths of a share, use the following route:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/accessPath"} regions={["eu"]} />


Then retrieve the details of an access path with the following route:

<Api version="v1" section="/storage" method="GET" route={"/storage/nasha/\{serviceName\}/share/\{shareId\}/accessPath/\{accessPathId\}"} regions={["eu"]} />


| Parameter | Required | Description |
|-----------|----------|-------------|
| `serviceName` | Yes | The ID of your Private NAS-HA service |
| `shareId` | Yes | The ID of the share |
| `accessPathId` | Yes | The ID of the access path |

The `path` field of the response contains the export path to use in your mount command. If a share has several access paths, use the one whose `preferred` field is `true`.
