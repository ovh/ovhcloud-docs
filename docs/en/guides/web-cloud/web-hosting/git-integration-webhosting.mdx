## Objective

In today's digital landscape, companies are becoming increasingly dynamic and innovative. The ability to effectively manage and deploy your website's code is vital to maintaining your brand's competitiveness and sustainability. Git, the most widely used version control system in the world, allows you to store your website's code on platforms like GitHub, allowing for better change traceability, as well as faster automation and deployments. As an OVHcloud customer, you benefit from a robust infrastructure to host your website, while leveraging the many benefits of Git and GitHub for website development and scalability.

**Find out how to configure and use Git with your web hosting plan from the OVHcloud Console.**

## Requirements

- An [OVHcloud Web Hosting](/links/web/hosting) plan.
- A [GitHub](https://github.com/) account on which you must be logged in.

:::info
To date, only the GitHub platform is supported for use with OVHcloud Web Hosting services.

:::

#### Set GitHub repository

Enter the address of your GitHub repository. If you don't have a GitHub repository for your project yet, create one.

To create a new repository:

- Log in to your GitHub account.
- Click on your profile picture in the top right-hand corner, then on <code className="action">Your repositories</code>.
- On the right of the screen that appears, click <code className="action">New</code>.

Define a name for your deposit and fill in the requested information.

:::warning
Tick the option `Add a README file` for GitHub to correctly initialise your repository.

:::

Finally, click <code className="action">Create Repository</code>.

Copy the address of your GitHub repository. It must be of the form:

- `https://github.com/<username>/<repository_name>.git` for a public repository.
- `git@github.com:<username>/<repository_name>.git` for a private repository.

Go back to the **Git configuration** panel and paste the address of your GitHub repository into the **Repository** field. It must be of the form `https://github.com/<username>/<repository_name>.git` for a public repository, or `git@github.com:<username>/<repository_name>.git` for a private repository. As long as the address does not have one of these formats and the **Branch** field is empty, the <code className="action">Apply configuration</code> button remains inactive.

Now define the branch of your GitHub repository. The default branch is `main`, but if you want to use another branch, create one on GitHub by following the steps below:

- Log in to your GitHub account.
- Click on your profile picture in the top right-hand corner, then on <code className="action">Your repositories</code>.
- Go to the relevant GitHub repository.
- Click <code className="action">Main</code>, then <code className="action">View all branches</code>, or directly click <code className="action">x Branch</code>.
- To the right of the screen that appears, click <code className="action">New branch</code>.
- Enter the name of the new branch and confirm by clicking <code className="action">Create new branch</code>.

Go back to the **Git configuration** panel in the OVHcloud Console and enter the name of the new branch you have just created in the **Branch** field.

If you enter the address of a private GitHub repository (of type `git@github.com:<username>/<repository_name>.git`), an **SSH key (private repository)** box appears under the **Repository** field.

<img className="thumbnail" alt="SSH key (private repository) box displayed for a private repository address" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/configure-ssh-key.png" loading="lazy" />

To configure your SSH key, please refer to the "Attach an SSH key to GitHub (only for private GitHub repositories)" step below.

#### Attach an SSH key to GitHub (only for private GitHub repositories) <a name="linkSSHKey"></a>

:::info
**Why is the SSH key required only for a private deposit?**

When your GitHub repository is public, files can be retrieved without authentication, which means Git can clone and update code without the need for an SSH key. However, if your repository is private, GitHub requires authentication to access it. The SSH key can then be used to establish this secure connection and guarantee that only authorized users can interact with the repository.

:::

:::info
Generating an SSH key is a crucial step, as it establishes a secure and encrypted connection between your website's directory and the GitHub repository. This key ensures that data transfers and code changes are done in a secure and authenticated manner, preventing unauthorized access and ensuring code integrity.

:::

Copy the SSH key displayed in the **SSH key (private repository)** box by clicking the copy button on the right.

<img className="thumbnail" alt="SSH key (private repository) box and copy button" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/configure-ssh-key.png" loading="lazy" />

As indicated in the Console, add this public key as a deploy key in the settings of your GitHub repository:

- Log in to your GitHub account and go to the repository concerned.
- Click the <code className="action">Settings</code> tab of the repository, then <code className="action">Deploy keys</code> in the left-hand column.
- Click <code className="action">Add deploy key</code>.

The form for adding a deploy key appears:

- **Title**: add a description for your SSH key. For example, you can name this key "OVHcloud".
- **Key**: Paste your SSH key.
- **Allow write access**: leave this box unticked, as deployment only requires read access to your repository.

To confirm the information, click <code className="action">Add key</code>. If prompted, confirm access to your account in GitHub.

#### Configure automatic deployment

At the bottom of the **Git configuration** panel, the **Configure your automatic deployment** section displays the webhook URL, along with a copy button. By configuring a webhook, your GitHub repository can automatically notify your OVHcloud web hosting plan of events that occur on the GitHub repository (new deployment, changes in code, etc.). This feature is especially useful if you work as a group on the same project and want to stay up to date with all changes to the GitHub repository. To find out more, read how to [configure a webhook on GitHub](#configureWebhook).

#### Validate Git association

Before validating the **Git configuration** panel, make sure that:

- Your SSH key has been added as a deploy key of your GitHub repository (private repository only).
- The address of your GitHub repository is correct. It must be of the form `https://github.com/<username>/<repository_name>.git` (public repository) or `git@github.com:<username>/<repository_name>.git` (private repository).
- The name of the GitHub repository branch is correct.
- Your website's root folder is empty: otherwise, the deployment will fail.

To confirm the information, click <code className="action">Apply configuration</code>.

### Enabling Git association

#### Successful association of Git

Once you have clicked <code className="action">Apply configuration</code>, the panel closes and a message confirms that the Git configuration has been applied. In the **Git** column of the table in the <code className="action">My sites</code> tab, the **Configuring…** label appears on the row of the website concerned: Git is being enabled. The process may take several minutes, and the table updates automatically.

<img className="thumbnail" alt="Git column with the Configuring… label" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/git-configuring.png" loading="lazy" />

When the Git association is complete, the **Active** status appears in the **Git** column for the website concerned.

<img className="thumbnail" alt="Git column with the Active status" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/sites-git-column.png" loading="lazy" />

#### Git association errors

In the **Git** column of the table in the <code className="action">My sites</code> tab, if the **Error** label appears on the row of the website you want to associate with Git, at least one of the following errors has occurred:

- The SSH key has not been added as a deploy key of your GitHub repository (private repository).
- The website's root folder was not empty at the time of the association.
- The GitHub repository address does not exist or is incorrect.
- The branch of the GitHub repository does not exist or its name is incorrect.

To find out the cause of the error, click the **Error** label. The **Git deployment error** panel opens: it shows the configured repository and branch, the common causes, and the latest deployment information.

<img className="thumbnail" alt="Git deployment error panel" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/my-websites/git/error-drawer.png" loading="lazy" />

Once the cause has been corrected, choose one of the actions in the **What you can do** section: <code className="action">Retry</code> to restart the deployment (or the association), <code className="action">Edit</code> to correct the configuration, or <code className="action">Delete</code> to delete the association before associating Git again.

#### Configure the <a name="configureWebhook"></a> webhook

Log in to your GitHub account, and go to the repository where you want to configure the webhook. Go to the <code className="action">Settings</code> tab, then in the settings side menu, click <code className="action">Webhooks</code>. Click the <code className="action">Add webhook</code> button to access the form:

- **Payload URL**: enter the webhook URL copied from the **Git configuration** panel in the OVHcloud Console.
- **Content type**: Choose <code className="action">application/json</code> as the content type for the data sent.
- **Secret**: The secret is optional. GitHub will use it to sign messages sent by the webhook, enhancing security.
- **SSL verification**: If your website supports HTTPS, leave this option enabled for increased security.
- **Which events would you like to trigger this webhook?**: Select the events that will trigger the webhook to be sent. For automatic deployment, <code className="action">Just the push event</code> is often enough, but you can choose <code className="action">Send me everything</code> to receive notifications for all events.
- **Active**: Make sure that the box is ticked to enable the webhook.

Click <code className="action">Add webhook</code> to save and activate your new webhook.

#### Test your webhook

Once you have created your webhook in GitHub, go to the list of your webhooks and select the one you have just created, or click <code className="action">Edit</code>.

On the screen that appears, click on the <code className="action">Recent Deliveries</code> tab. To send a test event specifically, GitHub usually sends a `ping` event when creating the webhook, and you can use the <code className="action">Redeliver</code> button next to this event to test it.

If the test has worked, the <code className="action">Response</code> tab returns a code of 200. If an error code is returned (usually 500 or 400), this means that your webhook has been misconfigured. Return to the form for adding a webhook, and check the information, specifically the webhook URL provided by OVHcloud.

#### Use the webhook

Once your webhook has been set up, your website's code will be updated automatically whenever changes occur on the GitHub repository. For example, if changes are made by one of your colleagues on the GitHub repository, then your website code will be updated locally (on your OVHcloud hosting plan).

### Conclusion

You have just linked your website code with Git, via your GitHub repository. You can now deploy the changes made on the GitHub repository to your web hosting plan, or deploy them in an automated way using the webhook. You can also view your deployment logs and perform multiple actions in just a few clicks via the OVHcloud Console.
