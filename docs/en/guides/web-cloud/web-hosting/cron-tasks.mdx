## Objective

On your OVHcloud web hosting, you can use scripts to automate certain operations. A scheduled task ("cron job") runs your scripts at specific times, automatically.

**This guide explains how to create cron jobs to automate scheduled tasks on a web hosting plan.**

[[fragment:support-scope]]

## Requirements

- An [OVHcloud web hosting plan](/links/web/hosting)

[[cpnav:web-hosting]]

## Instructions

### Creating an automated task

Click on the tabs below to view each of the **4** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/hosting">Web Hosting</ManagerLink> page, then choose the web hosting plan concerned.

    <img className="thumbnail" alt="Web Hosting page and list of the account's hosting plans" src="/images/assets/screens/console/product-selection/web-cloud/hosting-plans.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    Click on the <code className="action">Cron</code> tab.

    <img className="thumbnail" alt="Cron tab of a web hosting plan" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/cron/tab.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    You will see an overview of your scheduled tasks and their settings: each task is shown as a box indicating its command, its **Status**, its **Frequency**, its **Language** and the report **Email**.

    To create a cron job, click on the <code className="action">Create a task</code> button.

    <img className="thumbnail" alt="Scheduled task boxes and Create a task button" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/cron/tasks.png" loading="lazy" />
  </Tab>
  <Tab label="Step 4">
    Customise the task settings in the **Create a cron task** panel that appears.

    <img className="thumbnail" alt="Create a cron task panel in Simple mode" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/cron/create-task.png" loading="lazy" />

    |Option|Description|
    |---|---|
    |Command|Define the path to the file containing your script, relative to the root of your hosting plan. Example: www/jobs/cron.php|
    |Frequency|Define how often the task runs (see below).|
    |Language|Select the PHP version the script is using.|
    |Description|Enter a description to keep track of what your tasks do.|
    |Report email|If necessary, enter the email address to which a report will be sent in case of an execution error.|

    The task is enabled as soon as it is created. If you do not want it to run straight away, disable it afterwards (see the section [Modify or delete a scheduled task](#modify-or-delete-a-scheduled-task)).

    For the **Frequency**, the interface offers two modes:

    - **Simple**: choose a predefined frequency from the list (every hour, every day at midnight or noon, every Monday at midnight, the 1st of each month at midnight).
    - **Advanced**: enter an expression as you would in a *crontab*, whose positions correspond, in order, to **Min**, **Hour**, **Day**, **Month** and **Weekday**. The interface translates the expression into plain language above the field and reminds you of the role of the characters `*` (any value), `,` (list separator), `-` (range of values) and `/` (step). For example, `0 * * * *` runs the task **once an hour every day**, at minute 0.

    <img className="thumbnail" alt="Frequency in Advanced mode with the cron expression and its translation" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/cron/create-task-advanced.png" loading="lazy" />

    :::info
    The **Day** position allows you to define execution frequencies on a monthly cycle.

    The **Weekday** position allows you to define additional execution frequencies, but on a weekly cycle.
    :::

    You can switch between the two modes during configuration. Please also note the [limitations when scheduling a task on a web hosting plan](#limitations-of-web-hosting-tasks).

    If everything is correct, click on <code className="action">Create</code>.

    The task will be ready within a few minutes. You can then modify all of its settings or delete the task using the <code className="action">⋮</code> button at the top right of its box.
  </Tab>
</Tabs>

### Limitations of web hosting tasks

|Functionality|Description|
|---|---|
|Hourly scheduling|Minutes are ignored by the hosting plan: a task can only be executed once an hour, which is the highest repetition frequency that can be specified. In **Advanced** mode, enter a fixed minute (for example `0`): the interface tells you if this is not the case.|
|Running time|The time limit for a task is 60 minutes. If a script exceeds this running time, it will be stopped automatically by the system.|
|Variables|You can only define variables in a script. Adding them to the URL calling the script will not work (Example: www/jobs/cron.php?variable=value).|
|Data limit|A task can only generate up to 5 MB of data (*stdin/stderr*). For example, if a script writes data into a .txt file, the execution will be stopped automatically once the file reaches 5 MB in size.|
|Scripts producing errors|If a script is faulty, it will be automatically disabled after 10 failed execution attempts. The error report will only be sent when the 10 attempts have failed.<br/>Correct your script according to the error report received, then reactivate the cron task from the <code className="action">Cron</code> tab (click <code className="action">⋮</code> in the task box, then <code className="action">Enable</code>).|
|Execution reports|Reports will be sent to your selected email address only once a day (during night hours).|

### Troubleshooting

#### Testing your script with a web browser

A simple test to see if your script will produce an error is to run it in a web browser. For example, if the file path of your script is "www/cron.php" and your hosting domain is "mypersonaldomain.ovh", you would use the URL "http://<i></i>mypersonaldomain.ovh/cron.php". If no error is showing up but the script is not performing as expected, follow up with the suggestions below.

#### Verifying the usage of absolute paths

Always make sure to use absolute paths to files in your scripts. The "DIR" constant, for example, can help to receive the current path in PHP scripts ([PHP documentation](https://www.php.net/manual/en/language.constants.predefined.php)).

#### Checking your execution logs

In your web hosting's logs, accessible from the <ManagerLink to="/beta/#/">OVHcloud Console</ManagerLink>, you will see the log category labelled "cron".

Please refer to [this guide](/guides/web-cloud/web-hosting/logs-and-statistics) for details.
