## Objective

Using your databases may cause a number of anomalies on your website or in the <ManagerLink to="/beta/#/">OVHcloud Console</ManagerLink>, as well as on the [PhpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database) interface.

**Find out how to troubleshoot database errors with OVHcloud Web Hosting plans.**

## Requirements

- An [OVHcloud Web Hosting plan](/links/web/hosting).
- An OVHcloud database service: [Start SQL](/links/web/hosting-options-startsql) or [Web Cloud Databases](/links/web/databases).

#### Verify login credentials for your database <a name="config_file"></a>

Log in to the file storage space of your Web Hosting plan by [FTP](/guides/web-cloud/web-hosting/ftp-connection) and find your website's configuration file (for example, a WordPress website will have a **wp-config.php** file located in the folder containing your website).

:::warning
The name and content of the file relevant for database connection information depends on the CMS used for the website. This does not lie in the scope of responsibility of OVHcloud.

We recommend that you contact the publisher of the [CMS](/guides/web-cloud/web-hosting/cms-install-1-click-modules) concerned or a [specialised service provider](/links/partner) if necessary. We will not be able to assist you with this.
:::

Then check the **exact** match between the login details for [phpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database#accessing-the-phpmyadmin-interface) and the login details for your website's configuration file.

If necessary, change your [database password](/guides/web-cloud/web-hosting/sql-change-password).

#### Example for WordPress

If your website displays an **"Error establishing a database connection"** message and your hosting cluster is not affected by an [incident](https://web-cloud.status-ovhcloud.com/), log in to the [FTP storage space](/guides/web-cloud/web-hosting/ftp-connection) of your hosting and open the directory containing your website (by default, this is the `www` folder).

If this is a WordPress site, open the file `wp-config.php`.

```php
define('DB_NAME', 'my_database');

/** MySQL database username */
define('DB_USER', 'my_user');

/** MySQL database password */
define('DB_PASSWORD', 'my_password');

/** MySQL hostname */
define('DB_HOST', 'my_server.mysql.db:port');
```

Click on the tabs below to view each of the **2** steps in succession.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/hosting">Web Hosting</ManagerLink> page, then choose the web hosting plan concerned.

    <img className="thumbnail" alt="Web Hosting page and list of the account's hosting plans" src="/images/assets/screens/console/product-selection/web-cloud/hosting-plans.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    Click on the <code className="action">Databases</code> tab, then check that the columns of the table match the values in the `wp-config.php` file:

    - **my_database** and **my_user** must both match what is shown in the **Username** column: on a database included with your web hosting plan, the database name is identical to the username;
    - **my_password** corresponds to your [database password](/guides/web-cloud/web-hosting/sql-change-password);
    - **my_server.mysql.db** must match what is shown in the **Database name** column, which has exactly this form.

    :::warning
    The **Server address** column is **not** the value to enter in `DB_HOST`. It shows the infrastructure server hosting your database (for example `mysqlXXX.euXXX`), useful for checking for an incident, and not the connection address of your database. To find out more, see our guide "[How to identify your database server](/guides/web-cloud/web-hosting/sql-find-server)".
    :::

    <img className="thumbnail" alt="Databases tab and columns of the databases table" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/databases/tab-no-spotlight.png" loading="lazy" />
  </Tab>
</Tabs>

:::info
If these actions do not restore access to your website, [back up your database](/guides/web-cloud/web-hosting/sql-database-export) and then [restore it to an earlier date](/guides/web-cloud/databases/db-restore-import-database#restoring-an-existing-backup) from the <ManagerLink to="/beta/#/">OVHcloud Console</ManagerLink>.

Contact a [specialised service provider](/links/partner) if necessary. We will not be able to assist you with this.
:::

### You have exceeded the authorised quota

You have received an email notification stating that the amount of data on your database exceeds the authorised limit. Your database has therefore been switched to read-only mode. This will prevent your website from being modified.

<img className="thumbnail" alt="database-overquota-notification-email" src="/images/assets/screens/email-sending-to-customer/databases/overquota-db.png" loading="lazy" />

There are three ways you can unblock your database in this situation.

#### Method 1: Upgrade your subscription

If you have a **Starter** or **Personal** Web Hosting plan, we recommend that you switch to the [high-performance offer](/links/web/hosting). This subscription change will increase the size of your database which will automatically reopen it. This method is the simplest and does not require any particular technical expertise.

:::warning
The increase of the size of your database may be linked to a malfunction in your website's internal code.

In this case, changing your Web Hosting plan would be ineffective, as your database will continue to fill up.

If you notice a sudden increase in the size of your database, or if you have a "blog" type site that normally does not use much data, we advise you to contact a [specialised service provider](/links/partner) as soon as possible. We will not be able to provide you with support on this matter.
:::

To make this change, click on the tabs below to view each of the **2** steps.

  </Tab>

#### Method 2: Migrate your data to a larger database <a name="method2"></a>

You can also migrate your data to a new database:

- Order a larger [database service](/links/web/hosting-options-startsql) if necessary, then [create the new database](/guides/web-cloud/web-hosting/sql-create-database);
- [Duplicate the content of the old database](/guides/web-cloud/web-hosting/copy-database) to the new database **or** perform an [export of your data](/guides/web-cloud/web-hosting/sql-database-export), then [import your data](/guides/web-cloud/web-hosting/sql-importing-mysql-database) in the new database;
- Integrate the credentials of the new database into the [configuration file](#config_file) of your site.

:::info
If you have a **Performance**, **Agency**, **Agency Plus** or **Agency Max** Web Hosting plan, you can also [activate a free Web Cloud Databases service](/guides/web-cloud/databases/db-getting-started).

### RAM overflows (Web Cloud Databases only)

In the <code className="action">Overview</code> tab of your [Web Cloud DB](/guides/web-cloud/databases/db-getting-started) instance, the **Resource usage** section reports memory overflows. When it counts one or more, your instance has consumed too many resources on the OVHcloud infrastructure.

To increase the amount of RAM, click on the tabs below to view each of the **3** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink> page, then select the instance concerned.
  </Tab>
  <Tab label="Step 2">
    In the <code className="action">Overview</code> tab, find the **Resource usage** section. It shows the instance's current **RAM**, the **CPU throttle**, the **Storage quota**, and reports memory overflows: **No memory saturation**, or the number of overflows detected.

    <img className="thumbnail" alt="Resource usage section of a Web Cloud DB instance" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/resource-usage.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    Click <code className="action">Order more RAM</code> at the bottom of this section.

    :::warning
    Increasing the RAM of a Web Cloud DB instance is a **paid order**, not a simple setting. The ordering process that opens has you choose a RAM offer, accept the contracts, then confirm an order that you will be redirected to pay for. The new amount of RAM is only applied once the order has been paid, and the instance may restart at that point.
    :::

    This operation is described in detail in our guide "[Configuring your database server](/guides/web-cloud/databases/db-configure-optimise-database-server#modify-ram-web-cloud-db)".
  </Tab>
</Tabs>

:::warning
To increase the amount of RAM, the database needs to be a standalone service and not one of those included with a **Performance**, **Agency**, **Agency Plus** or **Agency Max** web hosting plan. If you want to increase the amount of RAM of a database included in these [web hosting offers](/links/web/hosting), you first need to detach it.

To detach the database, refer to our guide "[How to detach the Web Cloud Databases solution from a web hosting plan](/guides/web-cloud/databases/db-detach-from-web-hosting)".
:::

You can also optimise your database by following the instructions of our guide "[Configuring your database server](/guides/web-cloud/databases/db-configure-optimise-database-server#optimise-your-databases)".

:::info
If you experience any difficulties in decreasing the use of resources on your database server, please contact our [community of users](/links/community) or [OVHcloud partners](/links/partner). We will not be able to assist you with this.
:::

### Database import errors

#### "Access denied for user to database"

>
> **"#1044 - Access denied for user to database"**
>

This error message means that the database you are trying to import contains elements that are not authorised on the OVHcloud shared infrastructure.

First make sure that your database is empty. To do this, click on the tabs below to view each of the **3** steps in succession.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/hosting">Web Hosting</ManagerLink> page, then choose the web hosting plan concerned.

    <img className="thumbnail" alt="Web Hosting page and list of the account's hosting plans" src="/images/assets/screens/console/product-selection/web-cloud/hosting-plans.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    Click on the <code className="action">Databases</code> tab, then on the <code className="action">⁝</code> button in the **Actions** column, to the right of the database concerned, and on <code className="action">Recalculate quota</code>. The **Quota** column then shows you the space actually used.

    <img className="thumbnail" alt="Menu of a row in the databases table" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/databases/row-actions-menu.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    If the database is not empty, [back up the existing data](/guides/web-cloud/web-hosting/sql-database-export) then delete it before relaunching the import operation.

    You can also tick the <code className="action">Empty the database before import</code> box just before [launching the import](/guides/web-cloud/web-hosting/sql-importing-mysql-database#import-your-own-backup-via-your-control-panel):

    <img className="thumbnail" alt="Import window and Empty the database before import box" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/databases/import-sql-file-window.png" loading="lazy" />
  </Tab>
</Tabs>

If necessary, contact our [user community](/links/community) or a [specialised service provider](/links/partner) for more information. We will not be able to assist you in correcting this issue.

:::info
**Which elements in my database import script can cause a "#1044 - Access denied for user to database" error?**
:::

You cannot have a **"trigger"** in your database's import script on OVHcloud shared hosting servers. In this situation, import your database to a [Web Cloud Databases server](/guides/web-cloud/databases/db-getting-started).

The following query is also not allowed:

```sql
CREATE DATABASE IF NOT EXISTS `Database-Name` DEFAULT CHARACTER SET latin1 COLLATE latin1_swedish_ci;
```

Use this line instead:

```sql
USE `Database-Name`;
```

(`Database-Name`: enter the database name shown in the <ManagerLink to="/beta/#/">OVHcloud Console</ManagerLink>)

    <img className="thumbnail" alt="Resource usage section of a Web Cloud DB instance" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/resource-usage.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    Click <code className="action">Order more RAM</code> at the bottom of this section.

    :::warning
    Increasing the RAM of a Web Cloud DB instance is a **paid order**, not a simple setting. The ordering process that opens has you choose a RAM offer, accept the contracts, then confirm an order that you will be redirected to pay for. The new amount of RAM is only applied once the order has been paid, and the instance may restart at that point.
    :::

- Split your database in order to import it through multiple operations instead of one. (For any questions on the necessary steps, contact our [community](/links/community) or [OVHcloud partners](/links/partner). We will not be able to assist you with this.)

- [Optimise your database](/guides/web-cloud/databases/db-configure-optimise-database-server#optimise-your-databases), then repeat the export/import operations.

### Unable to access phpMyAdmin

#### "Access denied for user"

>
> **"mysqli::real_connect(): (HY000/1045): Access denied for user"**
>

This error message may appear when connecting to your database by [phpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database#accessing-the-phpmyadmin-interface). It indicates that the credentials entered are incorrect.

<img className="thumbnail" alt="access_denied_for_user" src="/images/assets/screens/other/web-tools/phpmyadmin/pma-error-hy000-1045.png" loading="lazy" />

In this situation, [check the credentials entered](/guides/web-cloud/databases/db-connecting-database-server#instructions) and change your [database password](/guides/web-cloud/web-hosting/sql-change-password) if necessary.

#### "Too many connections"

>
> **"mysqli_real_connect(): (HY000/1040): Too many connections"**
>

The maximum number of active connections for databases delivered with a shared hosting ([Start SQL](/links/web/hosting-options-startsql)) is **30**.

This number increases to **200** for the [Web Cloud Databases service](/guides/web-cloud/databases/db-getting-started). (This setting can be modified in the <code className="action">Configuration</code> section of your database service.)

A "Too many connections" error when [connecting to phpMyAdmin](/guides/web-cloud/web-hosting/sql-create-database#accessing-the-phpmyadmin-interface) appears if this maximum number of connections is exceeded.

In this situation, you will need to [optimise your databases](/guides/web-cloud/databases/db-configure-optimise-database-server#optimise-your-databases) in order to reduce the number of active connections.

:::warning
If you have any questions about the changes you need to make in order to reduce the number of active connections to your database, please contact our [community](/links/community) or [OVHcloud partners](/links/partner). We will not be able to assist you in this regard.
:::
