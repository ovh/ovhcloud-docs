## Objective

You have just purchased an Email Pro solution, which gives you affordable professional email addresses to support or start up your business.

**This guide explains the steps to correctly configure your Email Pro solution.**

## Requirements

- An [Email Pro](https://www.ovhcloud.com/en-gb/emails/email-pro/) solution
- An email confirming that your Email Pro solution has been set up
- A domain name

## Instructions

### Step 1: Add your domain name

:::info
The name of an Email Pro service in the OVHcloud Console begins with *emailpro-*, contains part of your NIC handle, and ends with a number (1 for the first Email Pro service installed, 2 for the second, etc.).

:::


After ordering your Email Pro service, go to the <ManagerLink to="/beta/#/web-cloud/email">Emails</ManagerLink> page in the OVHcloud Console. In the left-hand menu, expand <code className="action">Emails</code> and click <code className="action">Exchange</code>: your Email Pro services are listed there, with "Email Pro" in the **Offer type** column. Click the name of your service.

As long as no domain is associated with your service, it opens straight to the **Add a domain** page. To add a domain to a service that already has one, go to the <code className="action">Associated domains</code> tab, then click on the <code className="action">Add a domain</code> button above the table.

You will need to choose an option:

- **Select a domain from the list**: Then choose your domain from the **Domain name** drop-down menu. Only the domain names that you manage in the OVHcloud Console are displayed. If the domain name is registered with OVHcloud but does not appear in the list, use the "Enter a domain name not managed by your OVH account" option instead.
- **Enter a domain name not managed by your OVH account**: Choose this option if the domain name concerned is registered with OVHcloud but configurable from another OVHcloud customer account, **or** if your domain name is registered with another registrar. For the Email Pro service to work correctly, you must be able to modify the domain name's configuration (its DNS zone).

<img className="thumbnail" alt="Email Pro Add a domain page with the Select a domain from the list option" src="/images/web-cloud/email-and-collaborative-solutions/email-pro/first-config/console/emailpro-01.png" loading="lazy" />

Once the domain name is specified, the **Configuration** section appears just below.

<img className="thumbnail" alt="Configuration section with the Recommended configuration and Custom configuration options" src="/images/web-cloud/email-and-collaborative-solutions/email-pro/first-config/console/emailpro-02.png" loading="lazy" />

- **If you have entered a domain name not managed by OVHcloud**: Non-authoritative mode will be configured by default.

- **If you have selected a domain name managed by OVHcloud from the list**, you will need to choose between two configurations, which correspond to the domain's two operating modes.
    - **Recommended configuration** (**authoritative** mode): Choose this if Email Pro is the only email solution you use with your domain name. As soon as the configuration is saved, all emails sent to your domain name are routed to this service, and you cannot use another email solution with it.
    - **Custom configuration** (**non-authoritative** mode): Choose this if you use the Email Pro solution **and another email solution** with your domain name.

The mode applied to each domain is then displayed in the **Mode** column of the table in the <code className="action">Associated domains</code> tab.

> **Understanding Authoritative and Non-Authoritative Modes**
>
> - When an email is sent to your Email Pro (*Inbound mail server Email Pro*) platform in **authoritative** mode, this means that all of your domain name’s email addresses are only hosted on this platform. <br/> <br/> For example, if you send an email to the address *mary.johnson@mydomain.ovh*, the Email Pro server *Inbound mail server Email Pro* will send a failure message to the sender, because that address does not exist on the Email Pro server "*Inbound mail server Email Pro*".
> - When an email is sent to your Email Pro (*Inbound mail server Email Pro*) email platform in **non-authoritative** mode, this means that the email addresses for your domain name are divided between your main email platform (*Inbound mail server Email Pro*) and another email service (*Inbound mail server MX Plan*). <br/> <br/> For example, if you send an email to the address *mary.johnson@mydomain.ovh*, the Email Pro "*Inbound mail server Email Pro*" will send the email to the MX Plan server *Inbound mail server MX Plan* so that it can deliver it.
>
> <img className="thumbnail" alt="Add Domain" src="/images/web-cloud/email-and-collaborative-solutions/email-pro/first-config/authoritative-mode.png" loading="lazy" />
>

:::warning
If this domain name is already declared in **authoritative** mode on another email platform, adding it with the **Recommended configuration** is rejected. For both platforms to coexist, the domain name must be in **non-authoritative** mode on each of them: choose the **Custom configuration** here, then switch the domain name to **non-authoritative** mode on the other platform.

:::


If you choose the **Custom configuration**, fill in the **Target email server URL** field according to the other email service you use:

- **OVHcloud email (Exchange or MX Plan)**: Keep the default value, "*mx1.mail.ovh.net*" (works the same way with *mx0.mail.ovh.net*, *mx2.mail.ovh.net*, *mx3.mail.ovh.net*, *mx4.mail.ovh.net*).
- **Email external to OVHcloud (email solution from another provider, private email server)**: In the **Target email server URL** field, enter the host name of the incoming server for this external service, and ensure that it authorises email requests from your Email Pro service.

This choice is not final: you can change the mode later in the OVHcloud Console.

**If you have selected a domain name managed by OVHcloud**, it can be configured automatically. With the **Custom configuration**, four checkboxes appear below the **Target email server URL** field. They are ticked by default: untick any record you do not want configured automatically.

<img className="thumbnail" alt="Custom configuration with the Target email server URL field and the DNS record auto-configuration checkboxes" src="/images/web-cloud/email-and-collaborative-solutions/email-pro/first-config/console/emailpro-03.png" loading="lazy" />

- **Automatically configure the MX record (reception)**: A DNS record for the email servers required to receive emails on your domain name.
- **Automatically configure the SRV record (autodiscover)**: A DNS record that automatically configures your email software when you add your email address to it.
- **Automatically configure the SPF record**: A DNS record that specifies the servers authorised to send emails for your domain name. Refer to our guide on [How to improve email security with an SPF record](/guides/web-cloud/domains/dns-zone-spf) for more information.
- **Automatically configure and enable the DKIM record**: Setting up an encrypted digital signature to secure email exchanges. Refer to our guide on [How to improve email security with a DKIM record](/guides/web-cloud/domains/dns-zone-dkim) for more information.

**For a domain name not managed by OVHcloud**, configure its DNS zone manually by following Step 2 of this guide.

Once you have made your choices, click on the <code className="action">Save the configuration</code> button (<code className="action">Add</code> if you went through the <code className="action">Associated domains</code> tab) to start adding the domain.

### Step 2: Configure your domain name

Once you have added the domain name as an associated domain, check its configuration using the table that pops up.

You can use the **Diagnostic** column to check the domain name's DNS configuration. A red box will appear if these configurations need to be changed. There are two possibilities:

- **Automatic configuration when you add an OVHcloud domain name**: If you have just made the change, it may take a few hours before it is displayed in <ManagerLink to="/">the OVHcloud Console</ManagerLink>.

- **Manual configuration for a domain name not managed by OVHcloud**: Click on the <code className="action">⋮</code> button to the right of the domain's row, then on <code className="action">Diagnostics</code> to view the changes you will need to make. The page that opens has one tab per record (MX, SRV, SPF and DKIM), showing its status and the record expected in your DNS zone.
    - *For a CNAME* record, you can use our guide on "[Creating a CNAME record when adding an associated domain](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-dns-cname)".
    - *For an MX* record, please refer to our guide on "[Adding an MX record to your domain name’s configuration](/guides/web-cloud/domains/dns-zone-mx)".
    - *For an SRV* record, modify your DNS zone using the information in the <code className="action">SRV</code> tab of this page. You can use our guide on "[Editing an OVHcloud DNS zone](/guides/web-cloud/domains/dns-zone-edit)" to add this record.
    - *For an SPF* record, modify your DNS zone using the information in the <code className="action">SPF</code> tab. You can use our guide on "[How to improve email security with an SPF record](/guides/web-cloud/domains/dns-zone-spf)" to add this record.
    - *For a DKIM* record, modify your DNS zone using the information in the <code className="action">DKIM</code> tab. You can refer to our guide on "[How to improve email security with a DKIM record](/guides/web-cloud/domains/dns-zone-dkim)" to add this record.

<img className="thumbnail" alt="Associated domains tab, with a domain's ⋮ menu open on the Diagnostics entry" src="/images/web-cloud/email-and-collaborative-solutions/email-pro/first-config/console/emailpro-04.png" loading="lazy" />

### Step 3: Configure the Email Pro accounts

To configure your email accounts, go to the <code className="action">Accounts</code> tab. The table displays the accounts that you have ordered in this format: "*@configureme.me*".

To configure them, click on the <code className="action">⋮</code> button to the right of the account's row, then on <code className="action">Edit</code>.

<img className="thumbnail" alt="Accounts tab, with an email account's ⋮ menu open on the Edit entry" src="/images/web-cloud/email-and-collaborative-solutions/email-pro/first-config/console/emailpro-05.png" loading="lazy" />

Fill in the fields of the **Edit an Email Pro account** panel.

- **Email account**: Enter the name that your email address will bear (your first name.surname, for example), and select the domain in question from the list.

:::warning
The name of your email address must meet the following conditions:

- Minimum 2 characters
- Maximum 32 characters
- No accents
- No special characters, except for the following characters: `.`, `,`, `-` and `_`

:::


- **First name**: Enter a first name.
- **Last name**: Enter a last name.
- **Display name**: Enter the name that will be displayed as a sender when emails are sent from this address.
- **Password** and **Confirmation**: Set a strong password of at least 10 characters, including at least one number, one upper-case letter and one special character (for example `$`, `!` or `&`). For security reasons, we recommend not using the same password twice, choosing one that does not contain any personal information (e.g. your surname, first name and date of birth), and renewing it regularly.

:::warning
The password must meet the following requirements:

- Minimum 10 characters
- Maximum 30 characters
- No accents

:::


Once the information is complete, click on the <code className="action">Edit</code> button in the panel to start configuring the account.

:::info
Repeat this step as necessary according to the number of accounts you have. You can order additional accounts using the <code className="action">Order accounts</code> button.

:::


### Step 4: Use your email addresses

Once you have configured your accounts, you can start using them straight away. To do this, OVHcloud offers a web application, available at [OVHcloud Webmail](https://www.ovhcloud.com/en-gb/mail/). You will need to enter your email address and password to log in.

If this is your first time logging in to OWA with this email address, you will be prompted to set the interface language and time zone. Next, click <code className="action">Save</code> to continue.

:::info
Time zones are listed according to [the UTC (Coordinated Universal Time) standard](https://en.wikipedia.org/wiki/Coordinated_Universal_Time#/media/File:World_Time_Zones_Map.png), not in alphabetical order of cities.

**Example**: For Western Europe, it is UTC +1 (Brussels, Copenhagen, Madrid, Paris).

:::


If you would like to configure your email address on an email client or device (e.g. a smartphone or tablet), you can refer to our [configuration guides](/guides/web-cloud/email-and-collaborative-solutions/email-pro/landing-page-email-pro). If you simply need the information required to configure your Email Pro account, the settings to use are listed below:

|Server type|Server name|Security type|Port|
|---|---|---|---|
|Incoming|pro?.mail.ovh.net|SSL/TLS|993|
|Outgoing|pro?.mail.ovh.net|STARTTLS|587|

:::info
In our example, we use the server name: pro?.mail.ovh.net. Replace the "?" with the server number of your Email Pro service.

In the <code className="action">Overview</code> tab, which opens by default, the server name is shown on the **Server** line of the **General information** section.

:::
