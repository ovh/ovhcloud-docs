## Objective

When you add a domain name to your email service, you may be asked to configure a CNAME record in the DNS zone. The purpose of this procedure is to ensure that the domain name concerned is legitimate for use on the email service.

:::info
If the domain name, i.e. its DNS zone, is managed in the same customer account as the email service, configuring the CNAME record is not necessary.

:::


**Find out how to validate your domain name for your email service by adding a CNAME record.**

## Instructions

### Why create a CNAME record?

The CNAME record is used here as an alias, it points to a target that itself points to an IP address. This record is not mapped to an email service.

<Region zones={['eu']}>

The CNAME record is used as a validation code (token) for our [**Hosted Exchange**](/links/web/emails-hosted-exchange) and [**Email Pro**](/links/web/email-pro) solutions. It is added to the DNS zone of the domain name you want to validate for use with your emails. The purpose is to check that the user of the email service is authorised to use the domain name they are adding.

</Region>

<Region zones={['ca']}>

The CNAME record is used as a validation code (token) for our [**Hosted Exchange**](/links/web/emails-hosted-exchange) solution. It is added to the DNS zone of the domain name you want to validate for use with your emails. The purpose is to check that the user of the email service is authorised to use the domain name they are adding.

</Region>

You have created accounts (**contact**, **john.smith** and **mary.johnson** in this example) that will have email addresses associated with them.<br/>
The domain name **mydomain.ovh** has been added to the email service (please refer to the guide on [Adding a domain name to your email service](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-adding-domain)).<br/>
The email service generates a unique validation code ("**abcd1-check**" in our example).<br/>
If the DNS zone for the domain name **mydomain.ovh** is not managed in the same OVHcloud customer account, or is managed from an external interface, this code must then be added as a CNAME record. This record is represented by the blue box in the example.<br/>
The email service automatically checks the DNS records of the domain name **mydomain.ovh** for the validation code.

<img className="thumbnail" alt="email" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-dns-cname/email-dns-conf-cname01.png" loading="lazy" />

As soon as the email service reads the validation code in the DNS zone of the domain name **mydomain.ovh**, it becomes possible to use the addresses **contact@mydomain.ovh**, **john.smith@mydomain.ovh** and **mary.johnson@mydomain.ovh**.

### Step 1 - Understand the OVHcloud CNAME diagnostic <a name="step1"></a>

The **CNAME** diagnostic badge appears in the <code className="action">Associated domains</code> tab of your email service after you have added your domain name.

<img className="thumbnail" alt="Associated domains tab, orange CNAME badge in the Diagnostic column of a domain to validate" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-dns-cname/console/cname_exchange_diagnostic.png" loading="lazy" />

In the example above, the badge is orange. Here are the possible reasons for this diagnostic:

- **The domain name declared is not managed in the same OVHcloud customer account as your email service**: Follow [step 3](#step3) after logging in to the OVHcloud Console with the customer account that manages the domain name's DNS zone.
- **The domain name declared uses DNS servers not provided by OVHcloud**: The domain name is registered with OVHcloud, but you are using custom DNS servers. To check this, select the domain name concerned in the <code className="action">Domains & DNS</code> section of the left-hand menu. In the <code className="action">Overview</code> tab, opened by default, check the **Configuration** line of the **DNS configuration** section. If it says "Custom", you need to log in to the management interface of the DNS servers listed under **DNS servers hosting the zone**, in the same section.

<img className="thumbnail" alt="DNS configuration section of a domain name's Overview tab" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-dns-cname/console/email-dns-conf-cname02.png" loading="lazy" />

- **The domain name declared is not registered with OVHcloud and does not use OVHcloud DNS servers**. Your domain name is registered at another registrar. You will need to contact your domain name provider to verify how to access the DNS zone configuration.

### Step 2 - Retrieve the validation code <a name="step2"></a>

Open the <code className="action">Associated domains</code> tab and hover over the orange **CNAME** badge in the **Diagnostic** column.

The CNAME record to create is described in the **Owner verification** box that appears next to the badge.

<img className="thumbnail" alt="Owner verification box of the CNAME badge, with the record to create and its target" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-dns-cname/console/cname_exchange_informations.png" loading="lazy" />

Note the validation code displayed under **CNAME record to create** (`a1bcd-check`, followed by your domain name, in the example above). The value displayed under **Target**, `ovh.com`, is the one this record must point to.

:::warning
You have 48 hours to create this CNAME record.

:::

### Step 3 - Create the CNAME record <a name="step3"></a>

Select the tab that corresponds to the interface you are using:

<Tabs>
  <Tab label="In the OVHcloud Console">
    Click <code className="action">Domains & DNS</code>, then the domain name concerned. Then select the <code className="action">DNS Zone</code> tab.

Your DNS zone configuration will appear. To add a CNAME record, click the <code className="action">Create a record</code> button.

In the form, select **CNAME** from the **Type** drop-down menu, then fill in the fields with the information noted in [step 2](#step2).

For example, if the validation code is "**a1bcd-check**", enter it in the **Subdomain** field. Then enter "**ovh.com.**" in the **Target (hostname)** field, making sure to keep the trailing "**.**".

Check the information entered, then click <code className="action">Add</code>.
    
    :::warning
    The modification is usually applied within a few minutes but might require a propagation time up to 24 hours.

    :::

  </Tab>
  <Tab label="From an interface external to OVHcloud">
    Log in to the interface that manages the domain name’s DNS zone and add a CNAME record to it, with the following settings:
    
    - **Sub-domain**: Enter the value in the form "**xxxxx-check**", replacing the "**x**" with the unique code noted in [step 2](#step2) of this guide.
    - **Target**: Enter the value "**ovh.com.**", keeping in mind the trailing "**.**" (if your input interface has not added it automatically).
    
    Confirm this change in your DNS zone.
    
    :::warning
    The modification is usually applied within a few minutes but might require a propagation time up to 24 hours.

    :::

    
    Here is an example of a DNS response after adding a validation CNAME record:
    
    ```text
    ab1cd-check.mydomain.ovh. 3600	IN	CNAME	ovh.com.
    ```
  </Tab>
</Tabs>


To check that your email service has read the CNAME record, go back to its <code className="action">Associated domains</code> tab. If the **CNAME** badge no longer appears in the **Diagnostic** column, the domain name is validated. If not, the propagation may not be complete yet.

<img className="thumbnail" alt="Associated domains tab, validated domain without a CNAME badge in the Diagnostic column" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/exchange-dns-cname/console/cname_exchange_diagnostic_green.png" loading="lazy" />
