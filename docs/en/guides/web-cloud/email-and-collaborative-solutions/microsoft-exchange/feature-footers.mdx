## Objective

In the OVHcloud Console, you can create universal signatures (footers) for email addresses using the same domain ("corporate" signature). They will be attached automatically to emails sent from a user's account.

**This guide explains how to create an automatic signature using the OVHcloud Console.**

## Instructions

Click the <code className="action">Settings</code> tab of your service, then open the **Footers** section.

<img className="thumbnail" alt="Settings tab of an Exchange service, Footers section open with its table" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/feature-footers/console/exchange-footer-step1.png" loading="lazy" />

The table lists your associated domains: each one can have its own footer template. Click the <code className="action">⋮</code> button to the right of the domain concerned, then <code className="action">Add</code> to open the editor on the **Add a signature** page.

<img className="thumbnail" alt="⋮ menu of a domain in the Footers section, with the Add action" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/feature-footers/console/exchange-footer-step2.png" loading="lazy" />

The editor offers variables that correspond to the data of the user's account. You can, for example, compose a generic closing message and add an appropriate sign-off or some contact information below it, using the variables. Select a variable from the **Insert a variable** list, then click the <code className="action">Insert a variable</code> button to add it into the editing pane.

The footer is written in HTML, which allows for some formatting options. Use the toolbar above the editing pane to customise your signature (bold, italic, underline, lists, size, colour, alignment) and to add a link or an image to it. An image must be hosted at a public address: enter this address in the **Image address** field of the **Insert an image** panel, which opens with the image button of the toolbar, then click <code className="action">Insert</code>.

{/* v8-gap: CG-030 (oversight) — v6 « Source »: showed the footer's HTML code in the editor so it could be checked */}

<img className="thumbnail" alt="Add a signature page, with the variable list and the toolbar" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/feature-footers/console/exchange-footer-step4.png" loading="lazy" />

Tick the **Enable signature only for external sends** box to prevent adding this footer to emails sent between users on the same domain. Once the signature is finished, click <code className="action">Save</code>, at the bottom of the page. It will then be attached to emails sent from this domain's accounts.

To edit or delete a signature, click the <code className="action">⋮</code> button to the right of the domain in the **Footers** section, then <code className="action">Edit</code> or <code className="action">Delete</code>.

Please take the following specifics into consideration before applying signatures for users:

- Apart from "First name", "Surname", and "Display name", the account details cannot be edited from the OVHcloud Console but need to be specified in the user's OWA ("Options", "General", "My account").

<img className="thumbnail" alt="exchangesig" src="/images/web-cloud/email-and-collaborative-solutions/microsoft-exchange/feature-footers/exchange-footer-step5.png" loading="lazy" />

- The signature will be added to the email's body without gap, meaning it is advisable to begin the signature with at least one empty line.
- It is not indicated in OWA whether a footer is enabled on this domain and there is **no synchronisation**. If users add their [own signatures](/guides/web-cloud/email-and-collaborative-solutions/using-the-outlook-web-app-webmail/email-owa#adding-a-signature), emails will include both the individual and the domain-wide footer.
- The editor supports HTML formatting, hyperlinks, images, etc. However, signatures should not rely on these options too heavily. Recipients may use email clients that prevent HTML and embedded images, or the signatures will appear in a different way than intended. Note that HTML tags will be completely removed if a message is sent as "Plain text" from OWA.
- "Initials" are not active on the service. Adding this variable will have no effect.
