## Objective

A receive connector tells your Exchange platform which servers are allowed to deliver emails to it, and under which conditions. It lets you place an external anti-spam solution, also called a filtering gateway, in front of your Exchange platform: the <Tooltip term="mxRecord">MX records</Tooltip> of your domain name point to this gateway, which filters incoming emails and then passes them on to Exchange.

The receive connector is available for [Private Exchange](/links/web/emails-private-exchange) and [Trusted Exchange](/links/web/emails-trusted-exchange). It can only be created and managed with the OVHcloud API.

**This guide explains how to create, modify, disable and delete a receive connector on your Exchange platform with the OVHcloud API.**

:::info
To route the **outgoing** emails of your platform through an external server, use a send connector instead: see our guide "[Exchange - Configure a send connector](/guides/web-cloud/email-and-collaborative-solutions/microsoft-exchange/feature-send-connector)".
:::

## Requirements

- A [Private Exchange](/links/web/emails-private-exchange) or [Trusted Exchange](/links/web/emails-trusted-exchange) platform.
- API credentials created on the <CreateToken rights="GET=/email/exchange&GET=/email/exchange/*&POST=/email/exchange/*&PUT=/email/exchange/*&PATCH=/email/exchange/*&DELETE=/email/exchange/*">OVHcloud token creation page</CreateToken>, with at least the `GET` right on `/email/exchange` and the `GET`, `POST`, `PUT`, `PATCH` and `DELETE` rights on `/email/exchange/*`. Refer to our guide "[First Steps with the OVHcloud APIs](/guides/manage-and-operate/api/first-steps)".
- The IP addresses of the servers of your external anti-spam solution that will deliver emails to Exchange. Ask the provider of this solution for them.

## Instructions

### Understanding the default receive connector

Every Exchange platform has a default receive connector. It belongs to Exchange: you can neither modify nor delete it, only enable or disable it. In the API, its `default` property is `true`.

:::warning
**Do not disable the default receive connector.** If no other connector applies, disabling it stops the reception of all emails on the platform.
:::

### Finding the path parameters

The receive connector calls need the organisation name (`organizationName`) and the service name (`exchangeService`) of your platform. Retrieve them in order: the first call below returns the organisation, which the second one needs.

**1. Organisation** (`organizationName`)

List the Exchange organisations of your account with the API call below:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange"} />

**2. Service** (`exchangeService`)

List the Exchange services of the organisation with the API call below:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service"} />

### Creating a receive connector

Create the connector with the API call below:

<Api version="v1" section="/email/exchange" method="POST" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector"} regions={["eu"]} />

Fill in the following fields in the request body. All of them are required.

| Field | Type | Description |
|---|---|---|
| `name` | string | Name of the connector, 255 characters at most |
| `remoteIpRanges` | string[] | IP addresses of the servers allowed to deliver emails through this connector (see below) |
| `requireTls` | boolean | `true` to require TLS for every email received through this connector |
| `maxMessageSize` | long | Maximum size of an email received through this connector, in MB |
| `enabled` | boolean | `true` to enable the connector as soon as it is created |

Each `remoteIpRanges` entry can be:

- a single IP address, for example `203.0.113.10`;
- a network in CIDR notation, for example `203.0.113.0/28`;
- a "start-end" address range, bounds included, for example `203.0.113.10-203.0.113.20`.

Both IPv4 and IPv6 addresses are accepted.

:::warning
**Limits of `remoteIpRanges`**

- The same IP address cannot be part of two receive connectors of the platform.
- The whole list, once its entries are joined by commas, must not exceed 255 characters. Prefer a CIDR network to a long list of single addresses.

:::

The call returns a task: the connector is created once this task is complete.

### Listing and viewing receive connectors

List the receive connectors of the platform, default connector included, with the API call below:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector"} regions={["eu"]} />

The call returns the list of connector IDs (`id`). View the details of a connector with the API call below:

<Api version="v1" section="/email/exchange" method="GET" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

In addition to the creation fields, the response contains `id`, the ID of the connector, and `default`, which is `true` for the default receive connector.

### Modifying a receive connector

To modify one or more fields without changing the others, use the API call below:

<Api version="v1" section="/email/exchange" method="PATCH" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

To replace the whole configuration of the connector, fill in every field in the API call below:

<Api version="v1" section="/email/exchange" method="PUT" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

:::info
The `remoteIpRanges` field replaces the stored list as a whole. To add an IP address, send the complete list: the existing addresses and the new one.
:::

To enable or disable a connector, change its `enabled` field. On the default receive connector, this is the only field you can change: see the warning in the "[Understanding the default receive connector](#understanding-the-default-receive-connector)" section.

Each change returns a task: it takes effect once this task is complete.

### Deleting a receive connector

Delete a connector with the API call below:

<Api version="v1" section="/email/exchange" method="DELETE" route={"/email/exchange/\{organizationName\}/service/\{exchangeService\}/receiveConnector/\{id\}"} regions={["eu"]} />

The call returns a task: the connector is deleted once this task is complete. You cannot delete the default receive connector.
