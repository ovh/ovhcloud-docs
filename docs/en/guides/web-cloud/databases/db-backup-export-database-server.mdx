## Objective

Your database can contain a large amount of essential information for your website. It is therefore vital to be able to back it up or export it.

**Find out how to back up and export your database from your database server.**

## Requirements

- A [Web Cloud Databases instance](/links/web/databases) (included in a [Web Hosting](/links/web/hosting) Performance, Agency, Agency Plus or Agency Max plan).

[[cpnav:web-cloud-databases]]

## Instructions

:::info
[Web Cloud Databases](/links/web/databases) solutions do not provide access to the database management system itself, but to the databases hosted on it.

- There is no super user "root" access.
- Generic SQL commands work normally, and software such as HeidiSQL, SQuirreL SQL or Adminer is fully compatible.

:::

### Backing up and exporting a database from the OVHcloud Console <a name="sauvegarder-et-exporter-une-base-de-données-depuis-lespace-client"></a>

:::info
- Backups are automatically performed once a day on all your databases.
- Automatic and manual backups are kept for 30 days. After this period, they are automatically deleted. The deletion date of each backup is shown in the database's list of backups.

:::

#### Creating a manual backup

Click on the tabs below to view each of the **3** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink> page, then select the instance concerned.

    <img className="thumbnail" alt="Web Cloud DB page and list of the account's instances" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    Click on the <code className="action">Databases</code> tab.

    In the **Backups** column, the number corresponds to the number of available backups for each database.

    <img className="thumbnail" alt="Databases tab of a Web Cloud DB instance" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/tab.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    In the table, click the <code className="action">⋮</code> button in the **Actions** column, to the right of the database concerned, then click <code className="action">Back up now</code>.

    <img className="thumbnail" alt="Menu of a row in the Web Cloud DB databases table" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/row-actions-menu.png" loading="lazy" />

    The backup starts immediately, without confirmation. The message **Backup started** is displayed.
  </Tab>
</Tabs>

#### Exporting a backup

Click on the tabs below to view each of the **4** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink> page, then select the instance concerned.

    <img className="thumbnail" alt="Web Cloud DB page and list of the account's instances" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    Click on the <code className="action">Databases</code> tab.

    In the **Backups** column, the number corresponds to the number of available backups for each database.

    <img className="thumbnail" alt="Databases tab of a Web Cloud DB instance" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/tab.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    In the table, click the <code className="action">⋮</code> button in the **Actions** column, to the right of the database concerned, then click <code className="action">View backups</code>.

    <img className="thumbnail" alt="Menu of a row in the Web Cloud DB databases table" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/row-actions-menu.png" loading="lazy" />
  </Tab>
  <Tab label="Step 4">
    A panel titled **Backups**, followed by the name of the database, opens on the right. The backups are listed from the most recent to the oldest, each with its creation date and deletion date.

    Click the <code className="action">⋮</code> button to the right of the backup you want, then click <code className="action">Download</code>. The download starts in a new tab of your browser.

    <img className="thumbnail" alt="Backups panel of a database with the menu of a backup open" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/backup-actions-menu.png" loading="lazy" />
  </Tab>
</Tabs>

### Backing up and exporting a database outside the OVHcloud Console <a name="sauvegarder-et-exporter-une-base-de-données-hors-espace-client"></a>

If the available RAM on your server does not allow the desired export, use the OVHcloud tool in the OVHcloud Console, which uses resources external to your plan. Refer to the section "[Backing up and exporting a database from the OVHcloud Console](#backing-up-and-exporting-a-database-from-the-ovhcloud-console)" of this documentation.

**Click on the export method of your choice to view the content.**

<details>

<summary>Export a MySQL or MariaDB database from OVHcloud phpMyAdmin</summary>

To export your database directly from phpMyAdmin, first log in using the guide "[Connecting to a database](/guides/web-cloud/databases/db-connecting-database-server)".

Once logged in to phpMyAdmin, click on the name of the database you want to export, then on the <code className="action">Export</code> tab at the top.

There are two possible export modes. If you do not have a specific need, we recommend using the **quick** mode in **SQL** format.

<img className="thumbnail" alt="phpMyAdmin Export tab with the quick method and SQL format" src="/images/assets/screens/other/web-tools/phpmyadmin/pma-export-backup-web-cloud-db.png" loading="lazy" />

</details>

<details>

<summary>Export a MySQL or MariaDB database via command line</summary>

```bash
mysqldump --host=server --user=user --port=port --password=password database_name > database_name.sql
```

</details>

<details>

<summary>Export a MySQL or MariaDB database from a PHP script</summary>

```php
1. <?php echo "Your database is being backed up.......";
2. system("mysqldump --host=server --user=user --port=port --password=password database_name > database_name.sql");
3. echo "Backup complete. You can retrieve the database via FTP";
4. ?>
```

:::warning
- To prevent third-party access to this file containing sensitive data, secure access to it using the guide: [Protect a directory or administration interface of your website with .htaccess and .htpasswd files](/guides/web-cloud/web-hosting/htaccess-protect-directory-by-password).
- This action is only possible from an OVHcloud web hosting plan.

:::

</details>

<details>

<summary>Export a PostgreSQL database via command line</summary>

```bash
pg_dump --host=server --port=port --username=user --password database_name > database_name.sql
```

</details>

<details>

<summary>Export a PostgreSQL database from a PHP script</summary>

```php
1. <?php echo "Your database is being backed up.......";
2. system("PGPASSWORD=password pg_dump --host=server --port=port --username=user database_name > database_name.sql");
3. echo "Backup complete. You can retrieve the database via FTP";
4. ?>
```

:::warning
- To prevent third-party access to this file containing sensitive data, secure access to it using the guide: [Protect a directory or administration interface of your website with .htaccess and .htpasswd files](/guides/web-cloud/web-hosting/htaccess-protect-directory-by-password).
- This action is only possible from an OVHcloud web hosting plan.

:::

</details>
