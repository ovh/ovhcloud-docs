## Objective

Following an error on your database, you must be able to restore a backup or import a local database.

**Find out how to restore and import your database on your database server.**

## Requirements

- A [Web Cloud Databases instance](/links/web/databases) (included in a [Web Hosting](/links/web/hosting) Performance, Agency, Agency Plus or Agency Max plan)

[[cpnav:web-cloud-databases]]

## Instructions

:::info
[Web Cloud Databases](/links/web/databases) solutions do not give access to the database management system, but to the databases hosted on it.

- There is no superuser "root" access.
- Generic SQL commands work normally, and software such as HeidiSQL, SQuirreL SQL or Adminer is fully compatible.

:::

### Restoring and importing a database from the OVHcloud Console <a name="restoring-and-importing-a-database-from-the-control-panel"></a>

#### Restoring an existing backup

Click on the tabs below to view each of the **4** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink> page, then select the instance concerned.

    <img className="thumbnail" alt="Web Cloud DB page and list of the account's instances" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    Click on the <code className="action">Databases</code> tab.

    In the **Backups** column, the number corresponds to the number of backups available for each database.

    <img className="thumbnail" alt="Databases tab of a Web Cloud DB instance" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/tab.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    In the table, click the <code className="action">⋮</code> button in the **Actions** column, to the right of the database concerned, then <code className="action">View backups</code>.

    <img className="thumbnail" alt="Menu of a row in the Web Cloud DB databases table" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/row-actions-menu.png" loading="lazy" />
  </Tab>
  <Tab label="Step 4">
    A panel titled **Backups**, followed by the name of the database, opens on the right. Click the <code className="action">⋮</code> button to the right of the chosen backup, then <code className="action">Restore</code>.

    <img className="thumbnail" alt="Backups panel of a database with the menu of a backup open" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/backup-actions-menu.png" loading="lazy" />

    In the **Restore a backup** window that opens, confirm by clicking <code className="action">Restore</code>. The message **Restore started** is displayed.

    <img className="thumbnail" alt="Confirmation window for restoring a backup" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/restore-backup-dialog.png" loading="lazy" />

    :::warning
    Restoration involves overwriting the contents of the database, potentially resulting in data loss. If you are unsure of what you are doing, we recommend creating a backup beforehand.

    :::

  </Tab>
</Tabs>

#### Importing a local backup

Click on the tabs below to view each of the **4** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink> page, then select the instance concerned.

    <img className="thumbnail" alt="Web Cloud DB page and list of the account's instances" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    Click on the <code className="action">Databases</code> tab.

    <img className="thumbnail" alt="Databases tab of a Web Cloud DB instance" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/tab.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    In the table, click the <code className="action">⋮</code> button in the **Actions** column, to the right of the database concerned, then <code className="action">Import</code>.

    <img className="thumbnail" alt="Menu of a row in the Web Cloud DB databases table" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/row-actions-menu.png" loading="lazy" />
  </Tab>
  <Tab label="Step 4">
    The **Import a database** window opens. ***You have two options***, offered by the two buttons at the top of the window:

    **1 - Upload a new file**

    This option is selected by default when the window opens.

    In the **File name** field, enter a name for your imported file. Then click the <code className="action">File to import</code> area to select the file on your computer, or drag it into this area.

    :::warning
    The file must be in ".sql", ".txt" or ".gz" format.

    :::

    <img className="thumbnail" alt="Import a database window with the Upload a new file option selected" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/database-import-new-file-step-2.png" loading="lazy" />

    If you wish, tick the **Empty the database before import** box. The **Receive an email when the import is complete** box is ticked by default: it lets you be informed of the completion of the operation on the primary email address of your OVHcloud account. Finally, click <code className="action">Confirm</code>: the file is uploaded, then the import starts.

    **2 - Use an existing file**

    If you have already imported a file before, click <code className="action">Use an existing file</code>.

    In the **Existing document** drop-down list, then select the file from those already on your OVHcloud account.

    <img className="thumbnail" alt="Import a database window with the Use an existing file option selected" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/database-import-existing-file-step-2.png" loading="lazy" />

    If you wish, tick the **Empty the database before import** box. The **Receive an email when the import is complete** box is ticked by default: it lets you be informed of the completion of the operation on the primary email address of your OVHcloud account. Finally, click <code className="action">Confirm</code> to start the import.
  </Tab>
</Tabs>

### Importing a database outside the OVHcloud Console <a name="importing-a-database-outside-the-control-panel"></a>

In some cases, the RAM available on your database server may not be sufficient to perform the desired import outside the OVHcloud Console. If so, we recommend using the OVHcloud tool in the OVHcloud Console. Refer to the section "[Restoring and importing a database from the OVHcloud Console](#restoring-and-importing-a-database-from-the-control-panel)" of this guide.

**Click on the import method of your choice to view the content.**

<details>

<summary>Importing a MySQL or MariaDB database from phpMyAdmin</summary>

To import your database directly from phpMyAdmin, you must first log in by following the section "[Connect to a MySQL or MariaDB database](/guides/web-cloud/databases/db-connecting-database-server#connect-to-a-mysql-or-mariadb-database)".

Once logged in to phpMyAdmin, select your database by clicking on its name.

Then click on the <code className="action">Import</code> tab.

Select your backup file by clicking <code className="action">Browse</code> (the file cannot exceed 100 MB).

:::info
We recommend splitting your database into several files if it exceeds 100 MB, and performing multiple imports from phpMyAdmin.
You can import files larger than 100 MB from the OVHcloud Console by following the step "[Restoring and importing a database from the OVHcloud Console](#restoring-and-importing-a-database-from-the-control-panel)".

:::

Leave the default options and click <code className="action">Run</code> to start the import.

<img className="thumbnail" alt="Web Cloud Databases" src="/images/assets/screens/other/web-tools/phpmyadmin/pma-upload-backup-web-cloud-db.png" loading="lazy" />

</details>

<details>

<summary>Importing a MySQL or MariaDB database from the command line</summary>

This action is only possible via [SSH](/guides/web-cloud/web-hosting/ssh-on-webhosting) from an OVHcloud shared hosting plan.

```bash
cat database_name.sql | mysql --host=server --user=username --port=port --password=password database_name
```

</details>

<details>

<summary>Importing a MySQL or MariaDB database from a PHP file</summary>

```php
1. <?php
2. echo "Your database is being restored.......<br/>";
3. system("cat database_name.sql | mysql --host=server --user=username --port=port --password=password database_name");
4. echo "Completed. Your database is in place on this hosting plan.";
5. ?>
```

:::warning
- To prevent someone from accessing this file containing sensitive data, secure access to it by following the guide: [How do I password-protect a directory?](/guides/web-cloud/web-hosting/htaccess-protect-directory-by-password)
- This action is only possible from an OVHcloud shared hosting plan.

:::

</details>

<details>

<summary>Importing a PostgreSQL database from the command line</summary>

This action is only possible via [SSH](/guides/web-cloud/web-hosting/ssh-on-webhosting) from an OVHcloud shared hosting plan in stable version or higher.

```bash
psql --host=server --port=port --user=username --password=password database_name < database_name.sql
```

</details>

<details>

<summary>Importing a PostgreSQL database from a PHP file</summary>

```php
1. <?php
2. echo "Your database is being restored.......<br/>";
3. system("PGPASSWORD=password psql --host=server --port=port --user=username --password=password database_name < database_name.sql");
4. echo "Completed. Your database is in place on this hosting plan.";
5. ?>
```

:::warning
- To prevent someone from accessing this file containing sensitive data, secure access to it by following the guide: [How do I password-protect a directory?](/guides/web-cloud/web-hosting/htaccess-protect-directory-by-password)
- This action is only possible from an OVHcloud shared hosting plan.

:::

</details>
