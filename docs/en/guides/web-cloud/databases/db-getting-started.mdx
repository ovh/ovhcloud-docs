## Objective

The Web Cloud Databases solution provides a database instance with dedicated and guaranteed resources, offering performance and flexibility.
By default, your Web Cloud Databases solution is linked to the OVHcloud web hosting network. You can also link it to any other network via a list of authorised IP addresses.

**Find out how to get started with the Web Cloud Databases service.**

## Requirements

- A [Web Cloud Databases instance](/links/web/databases) (included in a [Web Hosting](/links/web/hosting) Performance, Agency, Agency Plus or Agency Max plan).

[[cpnav:web-cloud-databases]]

## Instructions

### Activating your Web Cloud Databases server included with your web hosting plan

If your hosting plan includes the Web Cloud Databases option, click on the tabs below to view each of the **3** steps.

:::warning
Enabling this option requires you to be at least the Administrator contact of the web hosting plan that includes the Web Cloud Databases service. For more information on managing contacts, refer to our guide "[Managing contacts for your services](/guides/account-and-service-management/account-information/managing-contacts)".

:::

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/hosting">Web hosting</ManagerLink> page, then select the web hosting plan concerned.

    <img className="thumbnail" alt="Web hosting page and list of the account's hosting plans" src="/images/assets/screens/console/product-selection/web-cloud/hosting-plans.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    In the <code className="action">Overview</code> tab, find the **Databases** section. The **Web Cloud DB** line shows that your instance is not yet activated. Click <code className="action">Activate</code> under this line.

    <img className="thumbnail" alt="Databases section of the hosting plan with the Activate link on the Web Cloud DB line" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/general-information/wcdb-activate.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    On the **Activate Web Cloud DB** page that appears, choose the capacity of your instance (the 512 MB capacity is included in your web hosting plan, higher capacities are charged), then its engine (PostgreSQL, MariaDB, MySQL or Valkey) and its **Version**. Then click <code className="action">Activate</code> (included capacity) or <code className="action">Order</code> (charged capacity), and confirm the purchase order that opens in a new tab.

    <img className="thumbnail" alt="Activate Web Cloud DB page with the choice of capacity, engine and version" src="/images/assets/screens/console/product-selection/web-cloud/web-hosting/general-information/wcdb-activate-page.png" loading="lazy" />

    Your instance will then be accessible from the <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink> page.
  </Tab>
</Tabs>

### Viewing the general information of the instance

Click on the tabs below to view each of the **2** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink> page, then select the instance concerned.

    <img className="thumbnail" alt="Web Cloud DB page and list of the account's instances" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />

    :::info
    The name of the Web Cloud DB service in the OVHcloud Console contains part of your customer reference and ends with three digits (001 for the first Web Cloud Databases service installed, 002 for the second, etc.).

    :::

  </Tab>
  <Tab label="Step 2">
    Make sure you are on the <code className="action">Overview</code> tab.

    Check that the information displayed in the **General information** and **Resource usage** sections is correct or matches the details below.

    |Information|Details|
    |---|---|
    |State|Shows whether the instance is started, restarting or suspended, among other things. Your instance must be started to perform actions on it.|
    |Engine|Shows the database system used by the server and its version. Make sure your website is compatible with the chosen version.|
    |Region|Shows the region of the data centre where the instance was created.|
    |Host|Shows the OVHcloud server on which your instance was created. This is information inherent to the OVHcloud infrastructure and may be used in communications related to [OVHcloud incidents](https://www.status-ovhcloud.com/).|
    |CPU throttle|Shows how often your instance is limited by the CPU allocated to it. If it is high, consider ordering more RAM.|
    |RAM|Shows the RAM available for your instance, as well as any memory overflows. Your Web Cloud Databases instance has dedicated and guaranteed resources: its RAM. If needed, you can upgrade it with the **Order more RAM** link.|
    |Storage quota|Shows the space taken up by your data out of the space included in your plan. Once this quota is reached, writes fail: you then need to delete data or move to a higher plan.|

    <img className="thumbnail" alt="General information and Resource usage sections of the overview" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/general-information/overview.png" loading="lazy" />
  </Tab>
</Tabs>

### Creating a database

:::info
This step does not apply to the Valkey database system.

:::

Click on the tabs below to view each of the **4** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink> page, then select the instance concerned.

    <img className="thumbnail" alt="Web Cloud DB page and list of the account's instances" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    Click on the <code className="action">Databases</code> tab.

    <img className="thumbnail" alt="Databases tab of a Web Cloud DB instance" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/tab.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    Click <code className="action">Add a database</code>, above the databases table.

    <img className="thumbnail" alt="Add a database button above the databases table" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/add-database.png" loading="lazy" />

    :::info
    PostgreSQL schema creation is currently unavailable on Web Cloud Databases servers.

    :::

  </Tab>
  <Tab label="Step 4">
    The **Add a database** panel opens on the right. Fill in the fields following the criteria shown under each of them:

    - **Database name** (required): this will be the name of your future database.
    - **Access to this database**: choose who will be able to log in to the database and perform queries.
        - **No access for now** (default choice): the database is created without a user. You can grant rights to a user afterwards.
        - **An existing user**: select the **User**, then their **Rights** on the database.
        - **A new user**: fill in the fields below to create the user at the same time as the database.
    - **Username** (only with **A new user**): the user who will be able to log in to your database and perform queries.
    - **Rights** (with **An existing user** or **A new user**): the rights associated with the user on the database. For standard usage, select `Admin`. The rights can be modified afterwards.
    - **Password**/**Confirm password** (only with **A new user**): enter a password, then confirm it.

    Click <code className="action">Add</code>.

    <img className="thumbnail" alt="Add a database panel with a new user" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/databases/add-database-window.png" loading="lazy" />
  </Tab>
</Tabs>

### Authorising an IP address

For your Web Cloud Databases instance to work, you must specify the IPs or IP ranges that are allowed to connect to your databases.

To do this, click on the tabs below to view each of the **4** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink> page, then select the instance concerned.

    <img className="thumbnail" alt="Web Cloud DB page and list of the account's instances" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    On the page that appears, click on the <code className="action">Allowed IPs</code> tab.

    <img className="thumbnail" alt="Allowed IPs tab of a Web Cloud DB instance" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/allowed-ips/tab.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    On the page that appears, click the <code className="action">Add an IP</code> button above the table.

    <img className="thumbnail" alt="Add an IP button above the allowed IPs table" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/allowed-ips/add-ip.png" loading="lazy" />

    :::tip
    If you want to modify an already authorised IP address or IP range, click the <code className="action">⋮</code> button in the **Actions** column, to the right of the line corresponding to the IP address or IP range to be modified, then click <code className="action">Edit</code>. You can change its name and its permissions; the IP address itself cannot be modified.

    <img className="thumbnail" alt="Menu of a line in the allowed IPs table" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/allowed-ips/row-actions-menu.png" loading="lazy" />

    :::

  </Tab>
  <Tab label="Step 4">
    In the **Add an allowed IP** window that opens, several fields need to be completed:

    <img className="thumbnail" alt="Add an allowed IP window and its fields" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/allowed-ips/add-ip-window.png" loading="lazy" />

    - **IP** (required): Enter the IP address (e.g. `203.0.113.44`) or IP range (e.g. `203.0.113.0/24` representing all IP addresses from `203.0.113.0` to `203.0.113.255`) that you want to authorise on your Web Cloud Databases solution.
    - **Name** (required): You can, for example, indicate the role of the IP address or IP range concerned.
    - **Allow service access** (ticked by default): Tick this box to allow the IP address or IP range to access the databases on your Web Cloud Databases solution.
    - **Allow SFTP access**: Tick this box to allow the IP address or IP range to access the logs of your Web Cloud Databases solution.

    :::warning
    It is strongly advised not to tick the **Allow service access** box to authorise the IP range `0.0.0.0/0` to access your databases.

    This would allow all existing IPv4 addresses to access your databases.

    :::

    Once the information is entered, click the <code className="action">Add</code> button.
  </Tab>
</Tabs>

### Authorising connections from an OVHcloud web hosting plan <a name="trustip"></a>

By default, your Web Cloud Databases solution is automatically linked to OVHcloud web hosting plans. If you wish, you can disable access from OVHcloud web hosting plans to your Web Cloud Databases.

To do this, refer to the specific cases in our guide "[Web Cloud Databases - How to authorise an IP address?](/guides/web-cloud/databases/db-authorise-ip-mask)" to enable or disable access from OVHcloud web hosting plans to your Web Cloud Databases.

### Linking your website to the database

Now that your database is created, one or more users have rights on it, and at least one IP address or OVHcloud web hosting plans have been authorised on your Web Cloud Databases instance, all that remains is to link your website to your database. This step can be done in several ways, depending on the website or CMS (WordPress, Joomla!, etc.) used, and the stage you are at if you are installing a website.

To do this, you need the following 5 pieces of information:

|Information|Description|
|---|---|
|Database name|The name you defined when creating the database.|
|Username|The username you defined when creating the database, or any additional user you may have added.|
|User password|The password linked to the user, which you defined during previous steps.|
|Server hostname|The server to enter so that your website can connect to your database.|
|Server port|The connection port to your Web Cloud Databases instance, so that your website can connect to your database.|

To find them, click on the tabs below to view each of the **2** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/databases">Web Cloud DB</ManagerLink> page, then select the instance concerned.

    <img className="thumbnail" alt="Web Cloud DB page and list of the account's instances" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    Retrieve the following connection details:

    - **Server (hostname) and port:** visible in the <code className="action">Overview</code> tab, **SQL** section, **Hostname** and **Port** entries.
    - **User:** visible in the <code className="action">Users & grants</code> tab.
    - **Password:** the password associated with the user. If you have forgotten it, go to the <code className="action">Users & grants</code> tab, click the <code className="action">⋮</code> button of the user concerned, then click <code className="action">Change password</code>.

    <img className="thumbnail" alt="SQL section of the overview with the hostname and port" src="/images/assets/screens/console/product-selection/web-cloud/web-cloud-databases/general-information/sql-connection-info.png" loading="lazy" />

    :::warning
    If you change a database user's password, all applications/websites that access this database must be updated accordingly.

    :::

  </Tab>
</Tabs>

:::warning
The <code className="action">port</code> field may not be available in your website's configuration. You must add this field after the server hostname, separated by a *:*.

For example, for the hostname `aaXXXXX-XXX.eu.clouddb.ovh.net` with SQL port `12345`, you would enter `aaXXXXX-XXX.eu.clouddb.ovh.net:12345` in the "Host" / "Hostname" section.

:::

:::info
OVHcloud does not offer a TLS-encrypted port on Valkey database servers. Communications must use the default, unencrypted port only.

:::
