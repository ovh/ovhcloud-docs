## Objective

Would you like to create a DNS zone for a subdomain?

The **DNS** (**D**omain **N**ame **S**ystem) zone is a domain name's configuration file. It consists of technical information, called *DNS records*. The DNS zone acts as a routing center.

For more information, please refer to our guides:

- [Everything you need to know about DNS servers](/guides/web-cloud/domains/dns-server-general-information)
- [Everything you need to know about DNS zones](/guides/web-cloud/domains/dns-zone-general-information)
- [Everything you need to know about DNS records](/guides/web-cloud/domains/dns-zone-records)

Most often, the DNS records of a subdomain are configured directly from the active DNS zone of the domain name it depends on. 
However, it is also possible to create a DNS zone specific to a subdomain.

For various reasons, you may need to create a DNS zone for a subdomain with OVHcloud.
The subdomain will then have its own zone to configure its DNS records.

:::tip
To recap:

- A domain name usually has the form **domain.tld**. For example: ovhcloud.com.
- A subdomain usually has the form **sub.domain.tld**. For example: help.ovhcloud.com.

By default, a subdomain depends on a domain name to function.
In practice, you will not be able to use the subdomain **sub.domain.tld** if you do not have access to the management of the domain name **domain.tld**.

If you want to create a DNS zone for a domain name, please refer directly to [this guide](/guides/web-cloud/domains/dns-zone-create).

:::

**Find out how to create an OVHcloud DNS zone for a domain name's subdomain via the OVHcloud Console.**

## Requirements

- You can administrate the domain name on which the chosen subdomain will depend.
- The concerned subdomain must not already have an active or inactive DNS zone with OVHcloud or be the subject of an ongoing operation or order with OVHcloud.

## Instructions

### 1 - Create the DNS zone via the OVHcloud Console

Click the tabs below to view each of the **3** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/domains/listing">Domains & DNS</ManagerLink> page, then click the <code className="action">Order a domain or DNS zone</code> button. In the **Standalone DNS zone** tile, click <code className="action">Order</code>.

    <img className="thumbnail" alt="Order page for a domain name or DNS zone and Standalone DNS zone tile" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/order-zone-choice.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    On the **Order a DNS zone** page that appears, enter in the **Domain name** field the subdomain (for example: *sub.domain.tld*) for which you want to create an OVHcloud DNS zone. Wait a few moments while the tool checks the subdomain.

    If a message indicates that the DNS zone cannot be created (for example, "A DNS zone already exists for sub.domain.tld."), check that the subdomain meets the necessary requirements or contact the person who manages it. Once everything is correct, try again.

    <img className="thumbnail" alt="Message stating that a DNS zone already exists for the name entered" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/order-zone-exists.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    Once the check is complete, the **Choose your options** section appears. Tick the **DNS Anycast** option (paid) if needed. The summary, on the right of the page, shows the content and total of your order.

    <img className="thumbnail" alt="Options for ordering a DNS zone for a subdomain and order summary" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/order-zone-subdomain.png" loading="lazy" />

    Click <code className="action">Continue order</code>, then follow the steps displayed until the DNS zone is created.

    :::info
    Minimum records are no longer chosen when ordering. If you want to customise the DNS zone yourself starting from the minimum records only (NS and SOA records), reset it once it has been created: in the <code className="action">DNS Zone</code> tab, open the <code className="action">More actions</code> menu of the **DNS zone** card, click <code className="action">Reset zone</code> and choose <code className="action">Yes — minimal entries only</code>. Read our guide "[Editing an OVHcloud DNS zone](/guides/web-cloud/domains/dns-zone-edit)".

    :::
  </Tab>
</Tabs>

### 2 - Edit the DNS zone (optional)

Now that your subdomain's DNS zone has been created, you can edit it. This step is optional, but it may be necessary if you want to ensure that the services associated with your subdomain remain available (e.g. your website and/or emails).

To edit this DNS zone, please read our guide on [Editing a DNS zone at OVHcloud](/guides/web-cloud/domains/dns-zone-edit).

:::info
If you have just created the DNS zone and the subdomain does not yet appear in your list of services, wait 15 to 20 minutes, then reload the page.

:::

### 3 - Declare the DNS servers in the active DNS zone of the domain name on which the chosen subdomain depends

The activation of a DNS zone for a subdomain differs from that of a domain name, as a subdomain must depend on a domain name to function.

You must first retrieve the names of the **DNS servers** associated with the DNS zone created for your subdomain.

To find them, click the tabs below to view each of the **2** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/domains/listing">Domains & DNS</ManagerLink> page, then choose your subdomain's DNS zone (it appears as **Zone only** in the list). Then click the <code className="action">DNS Zone</code> tab.

    <img className="thumbnail" alt="Domains & DNS page and list of the account's domain names" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/listing.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    In the table that appears, find the **Type** and **Target** columns. To display only the relevant records, click <code className="action">Filters</code>, then select <code className="action">NS</code> in the **Record type** list.

    <img className="thumbnail" alt="DNS zone filtered on NS records" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/filter-ns.png" loading="lazy" />

    Note the 2 values in the **Target** column. The DNS server names must have one of the following 3 forms:

    - `nsXX.ovh.net` and `dnsXX.ovh.net` or, `nsXXX.ovh.net` and `dnsXXX.ovh.net` (where each `X` represents a number between **0** and **9**).
    - `nsXX.ovh.ca` and `dnsXX.ovh.ca` or, `nsXXX.ovh.ca` and `dnsXXX.ovh.ca` (where each `X` represents a number between **0** and **9**).
    - `ns200.anycast.me` and `dns200.anycast.me` (if you have subscribed to the [DNS anycast](/links/web/domains-options) option).
  </Tab>
</Tabs>

Once the two DNS server names are retrieved, two situations are possible.

**Click on one of the two situations to display the content.**

<details>

<summary>The domain name on which your subdomain depends has its active DNS zone with OVHcloud</summary>

Click the tabs below to view each of the **4** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/domains/listing">Domains & DNS</ManagerLink> page, then choose the domain name your subdomain belongs to.

    <img className="thumbnail" alt="Domains & DNS page and list of the account's domain names" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/listing.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    Click the <code className="action">DNS Zone</code> tab, then the <code className="action">Add an entry</code> button above the table.

    <img className="thumbnail" alt="DNS Zone tab and Add an entry form" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/add-entry.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    In the **Type** list, select <code className="action">NS — Delegate to a DNS server</code> (**Pointing fields** section).

    <img className="thumbnail" alt="List of record types with the NS type" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/add-entry-type-list-ns.png" loading="lazy" />
  </Tab>
  <Tab label="Step 4">
    In the **Subdomain** field, enter the subdomain concerned (for example: `sub` for the subdomain `sub.domain.tld`); in the **Target (DNS server)** field, enter one of the 2 DNS servers you noted (for example: `nsXX.ovh.net`). Check the **Record preview**, then click <code className="action">Add</code>.

    <img className="thumbnail" alt="NS record form completed for a subdomain" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/add-ns-record.png" loading="lazy" />

    **Repeat the operation for the second DNS server.**

    If needed, also read our guide "[Editing an OVHcloud DNS zone](/guides/web-cloud/domains/dns-zone-edit)".
  </Tab>
</Tabs>

</details>

<details>

<summary>The domain name on which your subdomain depends has its active DNS zone with another provider</summary>

In this specific case, contact your DNS provider and specify that you want to add two DNS records of type NS for your subdomain.

Here is an example of a request to make to your DNS provider:

<pre className="bgwhite"><code>
Hi,

I would like to add the following NS type DNS records in the active DNS zone of the domain name <b>domain.tld</b> for my subdomain <b>sub.domain.tld</b> :

 - sub IN NS nsXX.ovh.net.
 - sub IN NS dnsXX.ovh.net.

This is to activate a specific DNS zone for my subdomain <b>sub.domain.tld</b>.

Best regards,
</code></pre>

In the example above, replace the values **domain.tld**, **sub.domain.tld**, **nsXX.ovh.net** and **dnsXX.ovh.net** with your own values.

</details>

:::warning
**The following point of attention does not concern the two DNS records of type NS that you have just added.** 

If other DNS records were present in the active DNS zone of the domain name on which your subdomain depends:

1. Do not forget to duplicate them in the DNS zone created for your subdomain.
2. Once duplicated, remove them from the active DNS zone of your domain name.

Indeed, there could be a conflict in DNS resolution.

:::

After modifying the DNS zone of the domain name on which your subdomain depends, the propagation of the changes can take up to **48 hours**.
