## Objective

The SPF (Sender Policy Framework) lets the receiving server check that an email was sent from a trusted server.

<details>

<summary>Why set up the SPF record for your emails?</summary>

- It helps prevent potential identity theft via email addresses using your domain name (spoofing). 
- You can also use it to authenticate the emails you send.
- The SPF record is added as a record in the domain name's DNS zone.

This check relies on the information in the SPF record, a TXT record in the <Tooltip term="dnsZone">DNS zone</Tooltip>, which contains:

- **Servers and/or IP addresses**: these are identified as legitimate sending sources.
- **A qualifier**: tells the receiving server how to treat a message from a source that is not listed.

Make sure the SPF record lists every source that sends emails with your domain name: your own email server, your provider's, or an OVHcloud email solution.

**Example**

You are sending an email from your address `john.smith@domain.tld`.

Only outgoing server **A** is declared in the SPF record of the domain name `domain.tld`.

When the inbound mail server receives the email, it reads the SPF record in the DNS zone of `domain.tld`.

- Outgoing Mail Server **A** is listed in the SPF record, so the email will arrive normally in the recipient's inbox.
- Outgoing Mail Server **B** is not listed in the SPF record, so the email sent from this server will be marked as suspicious in the inbox. Depending on the receiving server's rules, the email may then be tagged `[SPAM]` in its subject, moved to a `Junk` folder, or deleted outright.

<img className="thumbnail" alt="Diagram of an SPF check comparing the sending server with the SPF record" src="/images/assets/schemas/emails/spf-records-diagram.png" loading="lazy" />

:::info
The SPF record is only an indication provided to servers that receive emails, including yours. It is up to these servers to apply, or not, what is specified in the SPF record of domain names for which they receive messages.

:::

</details>

## Instructions

### Checking your current SPF configuration

If your domain name uses OVHcloud DNS servers, you can check whether an SPF record is already configured.

<details>

<summary>How do I check an existing SPF configuration?</summary>

Go to the <ManagerLink to="/beta/#/web-cloud/domains/listing">Domains & DNS</ManagerLink> page, choose the domain name concerned, then click the <code className="action">DNS Zone</code> tab.

This table lists the DNS records of your domain name's zone, one per line.

:::info
If in doubt, check that your domain name is using the OVHcloud DNS servers in the **DNS configuration** section of the <code className="action">Overview</code> tab.

:::

To find the line of the OVHcloud SPF record, filter the table with the <code className="action">Filters</code> button. As the record can appear in two different places and the filter only shows one type at a time, first filter on <code className="action">TXT</code>, then on <code className="action">SPF</code>.

<img className="thumbnail" alt="Filters button and Record type list of the DNS zone" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/filter-type.png" loading="lazy" />

You will get one of the following results.

- **An SPF record that corresponds to OVHcloud email solutions is displayed**: Your domain name currently uses the OVHcloud configuration. If you no longer wish to use it, you must modify it in the next step.

- **An SPF record that does not match the OVHcloud configuration is displayed**: Your domain name already uses a custom SPF. If it is incorrect, modify it or switch to the OVHcloud configuration in the next step.

- **No SPF record is displayed**: first check that it does not exist under the other type (SPF or TXT) by changing the filter. If no SPF record appears in the zone at all, your domain name does not use one; add it in the next step.

:::info
<Region zones={['eu']}>

An SPF record always follows this form: "v=spf1 `sources` `qualifier`". For example, the OVHcloud SPF is: `v=spf1 include:mx.ovh.com ~all`.

</Region>
<Region zones={['ca', 'apac']}>

An SPF record always follows this form: "v=spf1 `sources` `qualifier`". For example, the OVHcloud SPF is: `v=spf1 include:mx.ovh.ca ~all`.

</Region>

:::

</details>

### Configuring a new SPF record <a name="spfrecord"></a>

Above the table, click <code className="action">Add an entry</code>, then, in the **Type** list, select <code className="action">SPF — Servers allowed to send emails</code> (**Mail fields** section). A form opens where you build your SPF record field by field.

<img className="thumbnail" alt="Add an entry form of the DNS zone, SPF record" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/add-spf-record.png" loading="lazy" />

- **Subdomain**: this field is mandatory. Enter `@` to apply the SPF to the whole domain name, or enter a subdomain if you only send emails from it.
- **Authorization mechanisms**: tick the sources that are allowed to send emails for your domain name.
    - **Include OVH email servers (include:mx.ovh.com)**: ticked by default, this box authorises all of the OVHcloud outgoing email servers at once by inserting `include:mx.ovh.com`. Leave it ticked if you use an [OVHcloud email solution](#ovhcloudspfvalue), and check that section for the value to use in your zone.
    - **Allow domain MX servers (mx)**: authorises the servers that receive your emails to also send them.
    - **Allow the domain's IP address (a)**: authorises the server that hosts your domain name (useful when your website and emails share the same IP address, for example on a dedicated server).
- **Additional servers to authorise (include)**: add the SPF domains of other providers that send emails on your behalf (marketing platform, CRM, etc.), so their servers are treated as legitimate.
- **Authorised IPv4 addresses (ip4)** and **Allowed IPv6 addresses (ip6)**: add specific IP addresses or blocks authorised to send emails.
- **SPF policy**: choose how receiving servers should handle an email sent from a source that is **not** listed (see our recommendation below). The value `~all` ("Accept but mark as suspicious") is preselected and marked **Recommended**.
- <Tooltip term="ttl">**TTL**</Tooltip>: leave it on `By default` or set a value.

The **Record preview** box shows the record being built as you fill in the fields. When you are done, click <code className="action">Add</code>.

:::tip
Both the `~all` and `-all` **SPF Policy** values are valid, but for the best protection we strongly recommend `-all`, which asks the servers receiving your emails to **reject** any message sent from a source that is not listed in your SPF record.

Only choose `-all` once you are sure your record lists **every** legitimate sending source: your OVHcloud email solution, but also any third party that sends emails on your behalf (marketing platform, CRM, ticketing tool, etc.). If a legitimate source is missing, its emails will be rejected. If you are not certain the list is exhaustive, use `~all`, which flags those emails as suspicious instead of rejecting them.
:::

:::info
<Region zones={['eu']}>

For an OVHcloud email solution, the minimum SPF record simply consists of leaving the **Include OVH email servers (include:mx.ovh.com)** box ticked, as it is by default — this produces `v=spf1 include:mx.ovh.com ~all` (see [OVHcloud SPF configuration for shared email offers](#ovhcloudspfvalue)).

</Region>
<Region zones={['ca', 'apac']}>

For an OVHcloud email solution, the minimum SPF record is `v=spf1 include:mx.ovh.ca ~all`: untick the **Include OVH email servers (include:mx.ovh.com)** box, ticked by default, which inserts the European value `mx.ovh.com`, then enter `mx.ovh.ca` in the **Additional servers to allow (include)** field (see [OVHcloud SPF configuration for shared email offers](#ovhcloudspfvalue)).

</Region>

:::

If you already have the complete SPF string (provided by your email service) or you need a tag that the form does not expose, enter it directly: select the <Tooltip term="txtRecord">**TXT**</Tooltip> type (<code className="action">TXT — Free text (verification, SPF...)</code>) instead of SPF and paste the full `v=spf1 …` value in the **Value** field, or use the <code className="action">Advanced mode</code> at the top of the form.

:::info
It can take between 4 and 24 hours until the configuration is fully effective.

:::

### Modifying an SPF record <a name="modifyspf"></a>

Go to the <ManagerLink to="/beta/#/web-cloud/domains/listing">Domains & DNS</ManagerLink> page, choose the domain name concerned, then click the <code className="action">DNS Zone</code> tab.

The table shows your domain name's DNS zone: each row is a DNS record. Locate your TXT or SPF record in this table, click the <code className="action">⋮</code> button in the **Actions** column, then <code className="action">Modify</code>. The row expands into an edit form.

<img className="thumbnail" alt="Actions menu of a DNS zone row" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/row-actions.png" loading="lazy" />

See [Configuring a new SPF record](#spfrecord) for details on the SPF fields.

### OVHcloud SPF configuration for shared email offers <a name="ovhcloudspfvalue"></a>

The general OVHcloud SPF configuration applies to the solutions below:

- <Tooltip term="mxPlan">MX Plan</Tooltip> standalone or included in an OVHcloud [Web Hosting plan](/links/web/hosting)
<Region zones={['eu']}>
- [Email Pro](/links/web/email-pro)
</Region>
<Region zones={['eu', 'ca']}>
- [Hosted Exchange](/links/web/emails-hosted-exchange)
</Region>

The configuration is as follows:

<Region zones={['eu']}>

```bash
domain.tld IN TXT "v=spf1 include:mx.ovh.com ~all"
```

</Region>
<Region zones={['ca', 'apac']}>

```bash
domain.tld IN TXT "v=spf1 include:mx.ovh.ca ~all"
```

</Region>

### OVHcloud SPF configuration for Private Exchange

For Private Exchange, enter your server's IP addresses with the `ip4` argument (IPv4, **A** record) and the `ip6` argument (IPv6, **AAAA** record).

```bash
domain.tld IN TXT "v=spf1 ip4:203.0.113.1 ip6:2001:db8::1 ~all"
```

<Region zones={['eu']}>

If you also use a [shared email service](#ovhcloudspfvalue), add `include:mx.ovh.com` to the record:

```bash
domain.tld IN TXT "v=spf1 ip4:203.0.113.1 ip6:2001:db8::1 include:mx.ovh.com ~all"
```

</Region>
<Region zones={['ca', 'apac']}>

If you also use a [shared email service](#ovhcloudspfvalue), add `include:mx.ovh.ca` to the record:

```bash
domain.tld IN TXT "v=spf1 ip4:203.0.113.1 ip6:2001:db8::1 include:mx.ovh.ca ~all"
```

</Region>

<summary>How do I retrieve the IP addresses of a Private Exchange server?</summary>

Go to the <ManagerLink to="/beta/#/web-cloud/email/exchange">Exchange</ManagerLink> page, then click the service whose **Offer type** is **Private Exchange**.

In the <code className="action">Overview</code> tab, **General information** card, the **Server diagnostics** part shows the `A` and `AAAA` indicators. Click <code className="action">View diagnostics</code>, then, in the panel that opens, the <code className="action">A</code> and <code className="action">AAAA</code> tabs: note the value shown under **Target**.

<img className="thumbnail" alt="Server diagnostics panel of a Private Exchange service, A tab and its target" src="/images/assets/screens/console/product-selection/web-cloud/email-and-collaborative-solutions/exchange/server-diagnostics.png" loading="lazy" />

If the `A` and `AAAA` indicators are green, the panel shows "Automatic configuration complete" and does not display the IP addresses. Retrieve them instead from the DNS zone of the domain name attached to your Private Exchange platform. To do this, first note the address of the **Webmail** link in the **General information** card.

<img className="thumbnail" alt="General information card of a Private Exchange service, Webmail link and server diagnostics" src="/images/assets/screens/console/product-selection/web-cloud/email-and-collaborative-solutions/exchange/general-information.png" loading="lazy" />

Then go to the <ManagerLink to="/beta/#/web-cloud/domains/listing">Domains & DNS</ManagerLink> page, choose the domain name attached to your Private Exchange platform, then click the <code className="action">DNS Zone</code> tab. Retrieve the IPv4 (`A` record) and IPv6 (`AAAA` record) addresses corresponding to the webmail URL.
