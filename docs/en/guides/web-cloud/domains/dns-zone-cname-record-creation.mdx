## Objective

A CNAME record is used to associate a subdomain with a domain name or subdomain, without having to specify an IP address. This means that the subdomain will be redirected to the target domain name or subdomain's IP address, without requiring any additional configuration.

For example, if you create a CNAME record for *www.domain.tld* that points to *domain.tld*, then *www.domain.tld* will use the same IP address as *domain.tld*.

CNAME records are useful for avoiding changing IP addresses for your subdomains. They can also be used to configure services such as email servers.

**Find out how to add a CNAME record to your OVHcloud DNS zone.**

> **Do you already have a CNAME record in your DNS zone?** Follow our guide on [Editing an OVHcloud DNS zone](/guides/web-cloud/domains/dns-zone-edit).

## Instructions

### Add a DNS record of type CNAME for a domain name subdomain

Click the tabs below to view each of the **5** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/domains/listing">Domains & DNS</ManagerLink> page, then choose the domain name concerned.

    <img className="thumbnail" alt="Domains & DNS page and list of the account's domain names" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/listing.png" loading="lazy" />
  </Tab>
  <Tab label="Step 2">
    Click the <code className="action">DNS Zone</code> tab, then, above the table, <code className="action">Add an entry</code>.

    <img className="thumbnail" alt="DNS Zone tab of a domain name and Add an entry button" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/zone-overview.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    In the form that opens above the table, select `CNAME — Alias to another domain` in the **Type** list.

    <img className="thumbnail" alt="Type list of the Add an entry form, CNAME type selected" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/add-entry-type-list-cname.png" loading="lazy" />
  </Tab>
  <Tab label="Step 4">
    In the **Subdomain** field, enter the subdomain concerned (for example: `www` for `www.domain.tld`). In the **Target (hostname)** field, enter the domain name or subdomain you want to target (for example: `domain.tld`): the Console adds the final dot itself.

    <img className="thumbnail" alt="Add an entry form of the DNS zone, CNAME record from the www subdomain to domain.tld" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/dns-zone/add-cname-record.png" loading="lazy" />
  </Tab>
  <Tab label="Step 5">
    Check the **Record preview**, then click <code className="action">Add</code>.
  </Tab>
</Tabs>

It takes up to **24** hours for the change to propagate fully over the DNS network.

### Special cases

Click on the links below for more information:

<details>

<summary>CNAME and TXT records for the same subdomain</summary>

Do not configure both a CNAME record and a TXT record for the same subdomain. This can cause random results during DNS resolution, as only one response can be returned per DNS query.

For example, if you have the following records for *www.domain.tld*:

- A CNAME record pointing to *domain.tld*
- A TXT record with a specific value

A DNS query for *www.domain.tld* will return either the target of the CNAME record or the value of the TXT record, at random.

</details>

<details>

<summary>CNAME on a domain name in its own DNS zone</summary>

By convention, **CNAME records cannot be used on a domain name in its own DNS zone**. The domain name must point directly to an IP address with a record of type [A](/guides/web-cloud/domains/dns-zone-a-record-creation) for an IPv4, or [AAAA](/guides/web-cloud/domains/dns-zone-aaaa-record-creation) for an IPv6.

As an example, you will not be able to create a CNAME record for the domain name *domain.tld* in the DNS zone you have created for it.  
However, you can create CNAME records for all subdomains (e.g. *subdomain.domain.tld* or *www.domain.tld*) of the *domain.tld* domain name in the DNS zone created for *domain.tld*.

In the OVHcloud Console, if you enter `@` in the **Subdomain** field of a CNAME record, the <code className="action">Add</code> button remains disabled and the form displays the message "A CNAME record cannot be created at the domain root (@). You can use SVCB pointing instead."

</details>
