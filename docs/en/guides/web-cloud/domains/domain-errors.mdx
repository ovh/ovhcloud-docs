## Objective

Creating, transferring or changing the holder of a domain name can generate errors requiring intervention on your part.

**Find out what to do when an error occurs on a domain name.**

## Requirements

- Being the holder of one or more [domain names](/links/web/domains).
- Being up-to-date in the [payments](/guides/account-and-service-management/managing-billing-payments-and-services/invoice-management#pay-bills) and [renewals](/guides/account-and-service-management/managing-billing-payments-and-services/automatic-renewal#renewal-management) of your domain names.

[[cpnav:web-ongoing-operations]]

## Instructions

### Overview of the ongoing operations management interface

Click on the tabs below to view each of the **2** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/domains/operations">Ongoing operations</ManagerLink> page.
  </Tab>
  <Tab label="Step 2">
    A table lists all the operations relating to the domain names and DNS zones in your OVHcloud account. The tabs above the table let you filter the operations by status (for example <code className="action">To be processed</code> or <code className="action">Failed</code>).

    <img className="thumbnail" alt="Ongoing operations page, status filters and list of operations" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/ongoing-operations-list.png" loading="lazy" />

    - **Resource**: resource concerned by the operation (domain name or DNS zone).
    - **Operation**: operation in progress on the domain name.
    - **Comment**: details about the operation in progress. Instructions.
    - **Creation date**: date the operation was created.
    - **Last update date**: timestamp of the last update of the operation in progress.
    - **Status**: current state of the operation.
    - **Actions**: button giving access to the operation panel, present when an action is possible (relaunch, cancel or accelerate the operation).
  </Tab>
</Tabs>

Not all of the operations listed in this table require your intervention for them to proceed normally.

This guide covers **error** operations through recurring situations.

### Situations

:::info
The list of situations below is not exhaustive. If you encounter an error that is not detailed in this guide:

- Verify that you are up to date with [payments](/guides/account-and-service-management/managing-billing-payments-and-services/invoice-management#pay-bills) and domain name [renewals](/guides/account-and-service-management/managing-billing-payments-and-services/automatic-renewal#renewal-management).
- Check whether an action is possible: if so, a button appears in the **Actions** column, to the right of the operation concerned. It opens the operation panel, which shows the available actions.
- Read the descriptive message and check if it helps you resolve the error.

If, despite these checks, you cannot resolve the error, [open a support ticket](/links/support) from the OVHcloud Console.

:::

<summary>Document requests</summary>

Some domain name extensions require you to justify their use by providing documents. In this case, you must send the documents from the OVHcloud Console.

Click on the tabs below to view each of the **4** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/domains/operations">Ongoing operations</ManagerLink> page.
  </Tab>
  <Tab label="Step 2">
    Find the operation in error in the table. If needed, filter the list on <code className="action">To be processed</code> or <code className="action">Failed</code>.

    For example: a **Contacts update** operation with the **To be processed** status, whose **Comment** column states "In order to complete this task, please provide us with the documents required as soon as possible".

    <img className="thumbnail" alt="Ongoing operations page, status filters and Actions column" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/ongoing-operations.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    Click the button in the **Actions** column, to the right of the operation concerned. The operation panel opens.
  </Tab>
  <Tab label="Step 4">
    The panel shows each document to be provided, with its description and, where applicable, a <code className="action">Download template</code> link. Click the **Upload required document** area to select your document, then click <code className="action">Relaunch</code>.
  </Tab>
</Tabs>

</details>

  </Tab>

    <img className="thumbnail" alt="Ongoing operations page, status filters and Actions column" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/ongoing-operations.png" loading="lazy" />

<summary>Wrong transfer code</summary>

When you transfer your domain name to OVHcloud, you must enter a transfer code (**authInfo** / **AuthCode**) when placing your order. If this code is incorrect, the operation is suspended. You can restart it with the correct code.

Click on the tabs below to view each of the **4** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/domains/operations">Ongoing operations</ManagerLink> page.
  </Tab>
  <Tab label="Step 2">
    Find the operation in error in the table. If needed, filter the list on <code className="action">To be processed</code> or <code className="action">Failed</code>.

    For example: an **Incoming transfer** operation with the **To be processed** status, whose **Comment** column states "The authInfo code is missing". If the code entered when ordering is incorrect, the comment states that the authInfo code is not valid.

    <img className="thumbnail" alt="Ongoing operations page, status filters and Actions column" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/ongoing-operations.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    Click the button in the **Actions** column, to the right of the operation concerned. The operation panel opens.
  </Tab>
  <Tab label="Step 4">
    In the panel, under **Transfer tracking**, enter the transfer code (**authInfo** / **AuthCode**) in the field provided, then click <code className="action">Relaunch</code> to relaunch the operation.
  </Tab>
</Tabs>

</details>

<details>

<summary>Error on a .ie, .de or .it domain name after a DNS update</summary>

When you modify your DNS servers, the registry may check the new DNS servers and the associated DNS zone, and block the domain name if the configuration is not compliant.

:::warning
This type of block is initiated by the registry, not by OVHcloud. Even if the domain name is blocked by the registry, its DNS servers therefore appear with the **Active** status in the OVHcloud Console.

:::

To check if your domain name is blocked, click on the tabs below to view each of the **4** steps.

<Tabs>
  <Tab label="Step 1">
    Go to the <ManagerLink to="/beta/#/web-cloud/domains/operations">Ongoing operations</ManagerLink> page.
  </Tab>
  <Tab label="Step 2">
    Find the operation in error in the table. If needed, filter the list on <code className="action">To be processed</code> or <code className="action">Failed</code>.

    For example: a **DNS update** operation with the **To be processed** status, whose **Comment** column states "error while updating domain name".

    <img className="thumbnail" alt="Ongoing operations page, status filters and Actions column" src="/images/assets/screens/console/product-selection/web-cloud/domain-dns/ongoing-operations.png" loading="lazy" />
  </Tab>
  <Tab label="Step 3">
    To check your domain name, we recommend using the verification tool provided by the registry:

    - For a **.de** domain name: [https://nast.denic.de/](https://nast.denic.de/).
    - For a **.it** domain name: [https://dns-check.nic.it/](https://dns-check.nic.it/).

    :::info
    If your registry does not provide a DNS server verification tool, you can query your new DNS servers via the `nslookup` command at a Windows command prompt, or via the `dig` command at a Linux or macOS terminal.

    If your DNS servers are reachable, the tool will return an IP address.

    In any case, check with the DNS server administrator that the DNS server is correctly configured to host your domain name's DNS zone.

    :::
  </Tab>
  <Tab label="Step 4">
    Once you have identified the cause of the error and corrected it, click the button in the **Actions** column, to the right of the operation concerned. In the operation panel, click <code className="action">Relaunch</code> to relaunch the DNS check operation.

    If the correction concerns the DNS servers themselves, the panel of a DNS update also offers <code className="action">Edit the DNS servers</code>.
  </Tab>
</Tabs>

</details>
