# Object Storage - Enabling HTTPS on a static website using a custom domain

**Learn how to configure your website and the OVHcloud Load Balancer to enable HTTPS.**

OVHcloud Object Storage can host a static website inside an Object Storage bucket.

:::info

A static website contains only static content (HTML pages, images, videos, client-side scripts), whereas a dynamic website relies on server-side processing to process data and help render content.

:::

However, OVHcloud Object Storage static website hosting does not support HTTPS. If you want to use HTTPS, you can use OVHcloud Load Balancer to serve a static website hosted on OVHcloud Object Storage and act as an SSL gateway.

 

## Requirements

- An [OVHcloud Load Balancer](https://us.ovhcloud.com/network/load-balancer/), which will serve the role of an SSL gateway and can offer protection against DDoS attacks
- A registered [domain name](https://us.ovhcloud.com/domains/domain-name-definition/)
- You need to order a TLS certificate associated with your domain name at OVHcloud (optional if you already have a trusted TLS certificate associated with your domain name)
- You have to [enable web hosting on your Object Storage bucket](/storage-and-backup/object-storage/website)

#### OVHcloud Console access

- **Direct link:** [Load Balancer](https://console.us.ovhcloud.com/#/network/load-balancer)
- **Navigation path:** `Bare Metal Cloud` > `Network` > `Load Balancer`

 

## Instructions

### Step 1 - Configuring the Load Balancer

<details>
<summary>Step 1.1 - Add your certificate</summary>

Select your Load Balancer from the list, click the `SSL` tab, then click `Add Certificate`.

:::info

Optionally, you can also [order a free certificate](/network/load-balancer/order-freecertificate).

:::

{/* cp-shot: ![Manager load balancer ssl certificates tab](/images/storage-and-backup/object-storage/website-https/manager-load-balancer-ssl-certificates-tab.png) */}

Choose whether to upload your own certificate or to have a free one issued, fill in the fields, then click `Add Certificate`.

{/* cp-shot: ![Manager load balancer add SSL certificate](/images/storage-and-backup/object-storage/website-https/manager-load-balancer-add-ssl-certificate.png) */}

</details>

<details>
<summary>Step 1.2 - Configure a server farm</summary>

You now need to configure a server farm and add it to your Load Balancer. A server farm is a pool of backend machines that will handle the workload.

Still from your Load Balancer, click the `Server farms` tab, then click `Create farm`.

{/* cp-shot: ![Server cluster tab empty](/images/storage-and-backup/object-storage/website-https/server-cluster-tab-empty.png) */}

Enter the configuration of the new server farm, then click `Create Farm`:

- Name (optional)
- Protocol: HTTP
- Port: 80
- Zone: Choose the region in which you have hosted your website

{/* cp-shot: ![Manager load balancer add server cluster](/images/storage-and-backup/object-storage/website-https/manager-load-balancer-add-server-cluster.png) */}

You now need to add servers to your server farm. Click `Add server` on the farm you created.

{/* cp-shot: ![Manager load balancer server cluster details](/images/storage-and-backup/object-storage/website-https/manager-load-balancer-server-cluster-details.png) */}

Enter the configuration information of your server, then click `Add Server`:

- Name (optional)
- Address: Enter the public IP associated with your static website default URL in the form of `<bucket_name>.s3-website.<region>.io.cloud.ovh.us`

*You can retrieve this IP address by doing a dig command on the URL.*

**Example**: using `dig` command

```
dig <bucket_name>.s3-website.<region>.io.cloud.ovh.us
```

```
; <<>> DiG 9.16.1-Ubuntu <<>> my-site.s3-website.us-east-va.io.cloud.ovh.us
;; global options: +cmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 22041
;; flags: qr rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 1

;; OPT PSEUDOSECTION:
; EDNS: version: 0, flags:; udp: 4096
;; QUESTION SECTION:
;my-site.s3-website.us-east-va.io.cloud.ovh.us. IN A

;; ANSWER SECTION:
my-site.s3-website.us-east-va.io.cloud.ovh.us. 3600 IN A 141.95.161.77

;; Query time: 12 msec
;; SERVER: 10.15.25.129#53(10.15.25.129)
;; WHEN: Mon Jun 05 16:09:56 CEST 2023
;; MSG SIZE  rcvd: 84
```

**Example**: using `host` command

```
host <bucket_name>.s3-website.<region>.io.cloud.ovh.us
```

```
my-site.s3-website.us-east-va.io.cloud.ovh.us has address 141.95.161.77
```

{/* cp-shot: ![Manager load balancer add server](/images/storage-and-backup/object-storage/website-https/manager-load-balancer-add-server.png) */}

</details>

<details>
<summary>Step 1.3 - Configure your frontends</summary>

The next step is to add frontends to your Load Balancer. A frontend will be the internet-facing element of your Load Balancer and is responsible for handling and routing incoming requests.

From your Load Balancer, click the `Frontends` tab, then click `Create frontend`. Fill in the fields, then click `Create Frontend`.

{/* cp-shot: ![Frontends empty - Website https](/images/storage-and-backup/object-storage/website-https/frontends-empty.png) */}

Add two frontends:

- One frontend whose sole purpose is to handle all incoming HTTP requests and redirect them to your domain name in HTTPS

  - name (optional)
  - protocol: HTTP
  - port: 80
  - zone: all zones
  - default route: redirect to URL, with `https://<domain_name>` as the redirect URL

- One frontend that will handle all incoming HTTPS requests and perform the role of the SSL gateway

  - name (optional)
  - protocol: HTTPS
  - port: 443
  - zone: the region where your bucket sits
  - default route: route to farm, with the server farm previously created
  - TLS certificate: the certificate that you created
  - advanced settings > HTTP Header: Host `<website_endpoint>` in the form `<bucket_name>.s3-website.<region>.io.cloud.ovh.us`

{/* cp-shot: ![Manager load balancer add front end](/images/storage-and-backup/object-storage/website-https/manager-load-balancer-add-front-end.png) */}

</details>

<details>
<summary>Step 1.4 - Apply changes</summary>

Once you have created and configured all the resources, do not forget to apply all the changes to the Load Balancer: in the `Overview` tab, click `Apply N change(s)`.

{/* cp-shot: ![Manager load balancer apply configuration](/images/storage-and-backup/object-storage/website-https/manager-load-balancer-apply-config.png) */}

</details>

 

### Step 2: Configure your DNS

Edit the two A records to add the public IP address of your Load Balancer.

:::warning

**NOTE:** Check with the provider of your external domain for instructions to do this.

:::

:::info

You can find the public IP of your Load Balancer in the `Overview` tab of the [OVHcloud Console](https://console.us.ovhcloud.com/#/bare-metal/network/load-balancer).

{/* cp-shot: ![Home tab - Website https](/images/storage-and-backup/object-storage/website-https/home-tab.png) */}

:::

 

### Step 3: Test your website

Check that the website and the redirect work properly. Open a private browser to ensure that you have a clean cache and type your domain name.

**Example**:

![Storage backup object S3 https images test](/images/storage-and-backup/object-storage/website-https/storage-backup-object-s3-https-images-test.png)
