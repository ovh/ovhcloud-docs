## Objective

Creating a snapshot is a fast and simple way to secure a functioning system before making changes that might have undesired or unforeseen consequences, for example testing a new configuration or software. It does not, however, constitute a complete system backup strategy.

**This guide explains the usage of snapshots for your OVHcloud VPS.**

:::info

Before applying backup options, we recommend consulting the [product pages and FAQ](https://us.ovhcloud.com/vps/options/) for pricing comparisons and further details.

:::

## Requirements

- An active [Virtual Private Server](https://us.ovhcloud.com/vps/) in your OVHcloud account

:::warning

**NOTE:** This feature is currently limited for Virtual Private Servers in [Local Zones](https://us.ovhcloud.com/vps/vps-amd/); you can enable, create, or restore from snapshots, but you cannot download the snapshot in Local Zones.

:::

### OVHcloud Console Access

- **Direct link:** [VPS](https://console.us.ovhcloud.com/#/bare-metal/vps)
- **Navigation path:** `Bare Metal Cloud` > `VPS` > Select your VPS

## Instructions

### Step 1: Subscribing to the snapshot option

In the `Overview` tab, scroll down to the **Backup** section.\
If the **Snapshot** row reads "Enabled", go directly to [step 2](#step-2-taking-a-snapshot). If it reads "Disabled", click the `Order a snapshot` link under the **Snapshot** row.

{/* cp-shot: ![Snapshot order - Using snapshots](/images/bare-metal-cloud/vps/using-snapshots/snapshot-order.png) */}

In the panel that opens, note the pricing information, then click `Order`. You will be guided through the order process and receive a confirmation email.

{/* cp-shot: ![Snapshot enable - Using snapshots](/images/bare-metal-cloud/vps/using-snapshots/snapshot-enable.png) */}

To cancel the service option, click the `Close` link under the **Snapshot** row, then click `Confirm` in the **Cancel snapshot option** window.

:::warning

The cancellation takes effect on the renewal date of the option and cannot be undone.

:::

### Step 2: Taking a snapshot

Once the option is enabled, click the `Take a snapshot` link under the **Snapshot** row. In the **Take a snapshot** window, you can write a description that will be attached to your snapshot, then click `Confirm`.

{/* cp-shot: ![Snapshot take - Using snapshots](/images/bare-metal-cloud/vps/using-snapshots/snapshot-take.png) */}

:::warning

Your VPS is not accessible while the snapshot is being taken, and any previous snapshot will be lost.

:::

The time it takes to create the snapshot depends on the storage space in use. Afterward, refresh your page to see the creation date in the **Snapshot** row of the **Backup** section.

### Step 3: Deleting or restoring a snapshot

Since you can only have one snapshot activated at a time, the existing snapshot has to be deleted before creating a new one. Click the `Delete the snapshot` link under the **Snapshot** row, then click `Delete the snapshot` in the window that appears to confirm.

{/* cp-shot: ![Snapshot more options](/images/bare-metal-cloud/vps/using-snapshots/snapshot-more-options.png) */}

If you are sure that you would like to reset your VPS to the status of the snapshot, click `Restore the snapshot` and confirm the restoration task in the pop-up window.

:::warning

Restoring the snapshot erases the current version of your VPS and returns it to the state of the snapshot. This action cannot be reversed.

:::

:::danger

**WARNING:** When you restore a VPS from a snapshot, the snapshot will be deleted. If you wish to keep the same snapshot, you should take a new one before making changes to the restored system.

If the snapshot function is too limited for your project, consider switching to the [Automated Backups](/bare-metal-cloud/vps/using-automated-backups) option.

:::

### Downloading a snapshot

The current snapshot can be retrieved via a download link. Click the `Download Snapshot` link under the **Snapshot** row.

{/* cp-shot: ![Snapshot more options](/images/bare-metal-cloud/vps/using-snapshots/snapshot-more-options.png) */}

:::info

If your VPS is of an older product range, you might receive an error message because the option is not available for a legacy VPS. These older services have the following naming scheme: *vpsXXXX.ovh.us* (in which *X* stands for a number). You can verify this server reference on your VPS page in the [OVHcloud Console](https://console.us.ovhcloud.com/#/bare-metal/vps).

:::

In the **Download Snapshot** panel, click `Generate download link`.

{/* cp-shot: ![Snapshot download link](/images/bare-metal-cloud/vps/using-snapshots/snapshot-download-link.png) */}

After a few seconds, a success message appears. Below it, you can copy the complete download command with one click, then run it in your terminal.

{/* cp-shot: ![Snapshot download command](/images/bare-metal-cloud/vps/using-snapshots/snapshot-download-command.png) */}

The size of the snapshot is also displayed in the **Information** section.

Note that the download link will expire after **24 hours**.

The download command uses `curl`, in the following format:

```bash
curl "https://storage.us-east-va.cloud.ovh.us/v1/AUTH_f5fgh4674dd706f15f6ffgf4z667d3f4g5f05/glance/5ceg3f93-8b49-436b-aefe-4185f9fc3f78?
temp_url_sig=f508cacda60256d5f211ddddf3f81130e935f0e4&temp_url_expires=1678247579" --output vps-000000.vps.ovh.us --fail
```

It should work from any command line terminal.

When using Windows *PowerShell*, however, you will need to adjust the command as follows:

```powershell
curl -Uri "https://storage.us-east-va.cloud.ovh.us/v1/AUTH_f5fgh4674dd706f15f6ffgf4z667d3f4g5f05/glance/5ceg3f93-8b49-436b-aefe-4185f9fc3f78?
temp_url_sig=f508cacda60256d5f211ddddf3f81130e935f0e4&temp_url_expires=1678247579" -OutFile vps-000000.vps.ovh.us
```

![VPS snapshot - Using snapshots - step 9](/images/bare-metal-cloud/vps/using-snapshots/vps-snapshot-09.png)

:::info

We recommend not downloading snapshots directly to the VPS, to avoid using up the storage space.

The downloaded file can be imported into your Public Cloud Project as an image (QCOW2) via [OpenStack](/public-cloud/compute/upload-own-image). An example can be seen in [this guide](/public-cloud/compute/upload-own-image).

:::

### Best practice for using snapshots

#### Configuring the QEMU agent on a VPS

Snapshots are instantaneous images of your running system ("live snapshot"). To ensure the availability of your system when the snapshot is created, the QEMU agent is used to prepare the filesystem for the process.

The required *qemu-guest-agent* is not installed by default on most distributions. Moreover, licensing restrictions may prevent OVHcloud from including it in the available OS images. Therefore, it is best practice to verify and install the agent if it is not activated on your VPS. Connect to your VPS via SSH and follow the instructions below, according to your operating system.

##### **Debian-based distributions (Debian, Ubuntu)**

Use the following command to check whether the system is properly set up for snapshots:

```bash
file /dev/virtio-ports/org.qemu.guest_agent.0
/dev/virtio-ports/org.qemu.guest_agent.0: symbolic link to ../vport2p1
```

If the output is different ("No such file or directory"), install the latest package:

```bash
sudo apt-get update
sudo apt-get install qemu-guest-agent
```

Reboot the VPS:

```bash
sudo reboot
```

Check the service to ensure it is running:

```bash
sudo service qemu-guest-agent status
```

##### **Redhat-based distributions (Centos, Fedora)**

Use the following command to check whether the system is properly set up for snapshots:

```bash
file /dev/virtio-ports/org.qemu.guest_agent.0
/dev/virtio-ports/org.qemu.guest_agent.0: symbolic link to ../vport2p1
```

If the output is different ("No such file or directory"), install and enable the agent:

```bash
sudo yum install qemu-guest-agent
sudo chkconfig qemu-guest-agent on
```

Reboot the VPS:

```bash
sudo reboot
```

Check the agent and verify that it is running:

```bash
sudo service qemu-guest-agent status
```

##### **Kernel issues on cPanel**

Consult our [cPanel auto backup](/bare-metal-cloud/vps/avoid-kernel-panic-cpanel-while-using-automated-backup) guide to find out how to fix issues with cPanel servers getting stuck during an OVHcloud automated backup.

##### **Windows**

You can install the agent via MSI file, available from the Fedora project website: [https://fedorapeople.org/groups/virt/virtio-win/direct-downloads/latest-qemu-ga/](https://fedorapeople.org/groups/virt/virtio-win/direct-downloads/latest-qemu-ga/).

Verify that the service is running by using this *PowerShell* command:

```powershell
PS C:\Users\Administrator> Get-Service QEMU-GA

Status   Name               DisplayName
------   ----               -----------
Running  QEMU-GA            QEMU Guest Agent
```
