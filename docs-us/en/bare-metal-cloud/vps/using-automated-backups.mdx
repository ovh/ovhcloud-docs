## Objective

The Automated backup option for VPS offers a convenient way to have complete system backups available from the OVHcloud Console without having to connect to the server to create and restore them manually. Another advantage is that you can also choose to mount a backup and then access its files remotely.

**This guide explains the Automated backup option for your OVHcloud VPS.**

:::info

Before applying a backup strategy, we recommend consulting the [product pages and FAQ](https://us.ovhcloud.com/vps/options/) for pricing comparisons and further details.

:::

## Requirements

- A [Virtual Private Server](https://us.ovhcloud.com/vps/) in your OVHcloud account
- Administrative access (sudo) via SSH to your VPS (optional)

---

- **Direct link:** [VPS](https://console.us.ovhcloud.com/#/bare-metal/vps)
- **Navigation path:** `Bare Metal Cloud` > `VPS` > Select your VPS

When you order a VPS, a single daily Automated backup is included as a free service option. This standard backup option allows you to:

- Mount and restore the daily backup.
- Set the time of day this backup will be created.

For more flexibility with your backups, you can activate the Premium Automated Backup option.

:::warning

**NOTE:** This feature is currently unavailable for Virtual Private Servers in [Local Zones](https://us.ovhcloud.com/vps/vps-amd/).

:::

## Instructions

### How to subscribe to Premium Automated Backup

The Premium Automated Backup option creates a backup of your VPS every 24 hours at the specified time.\
You will have access to all daily backups of the last 7 days. Once 7 backups are created, each new backup will replace the oldest one.

After selecting your VPS, subscribe to the option in one of two places:

- In the `Overview` tab, scroll down to the **Backup** section and click the `Order automated backup` link under the **Automated backup** row.
- Or click the `Automated backup` tab in the horizontal menu, then click `Enable Automated backup`.

{/* cp-shot: ![Order premium backup](/images/bare-metal-cloud/vps/using-automated-backups/order-premium-backup.png) */}

In the panel that opens, note the pricing information, then click `Order`. You will be guided through the order process and receive a confirmation email.

To disable Premium Automated Backup, in the `Overview` tab, scroll down to the **Backup** section and click `Close`.

:::warning

The cancellation takes effect on the renewal date and cannot be undone.

:::

### How to configure the backup time

You can change the time of day at which the backup will take place.

After selecting your VPS, click on the `Automated backup` tab in the horizontal menu.

Click the `Edit the backup schedule` button above the table.

{/* cp-shot: ![Backup tab edit time](/images/bare-metal-cloud/vps/using-automated-backups/backup-tab-edit-time.png) */}

In the **Configure the automatic backup time** window, edit the time of day in the **Time (UTC)** field (24-hour UTC time standard, HH:MM:SS). Click on `Confirm`.

{/* cp-shot: ![Backup tab edit time confirm](/images/bare-metal-cloud/vps/using-automated-backups/backup-tab-edit-time-confirm.png) */}

:::info

Once confirmed in the OVHcloud Console, the change will come into effect after 24 to 48 hours.

:::

### How to restore a backup from the OVHcloud Console

After selecting your VPS, click on the `Automated backup` tab in the horizontal menu.\
Click the `⋮` button in the **Actions** column of the backup you would like to restore and select `Restore this VPS`.

{/* cp-shot: ![Backup tab more options](/images/bare-metal-cloud/vps/using-automated-backups/backup-tab-more-options.png) */}

If you recently changed your root password, make sure to tick the option "Modify the root password on restoration" in the **Restore my VPS** window to preserve your current root password and click on `Confirm`. You will receive an email as soon as the task is complete. The restoration might take a while, depending on the disk space used.

:::warning

Restoring your VPS deletes all of its current data.

:::

:::danger

**WARNING:** Please note that the automated backups will not include your additional disks.

:::

### How to mount and access a backup

It is not necessary to completely overwrite your existing service with a restoration. The `Mount as a secondary disk` option allows you to access the backup data to retrieve your files.

:::warning

**NOTE:** OVHcloud provides services for which you are responsible for their configuration and management. You are therefore responsible for their proper functioning.\
\
This tutorial is designed to help you as much as possible with common tasks. If you are having difficulty performing these actions, please contact a specialized service provider. OVHcloud cannot provide you with technical support in this regard.

:::

After selecting your VPS, click on the `Automated backup` tab in the horizontal menu.\
Click the `⋮` button in the **Actions** column of the backup you need to access and select `Mount as a secondary disk`, then click `Confirm` in the **Mount the backup** window. The backup is then accessible via an NFS or SMB mount point.

{/* cp-shot: ![Backup tab more options](/images/bare-metal-cloud/vps/using-automated-backups/backup-tab-more-options.png) */}

When you use this option, a read-write copy of the backup is created and mounted. The original backup will remain available unchanged for future restorations.

After the process is completed, you will receive an email. You can now connect to your VPS and access the partition where your backup is located.

<Tabs>

<Tab label="Using Secure Shell">

#### Using Secure Shell

First, connect to your VPS via SSH.

You can use the following command to verify the name of the newly attached device:

```bash
lsblk
```

Here is a sample output of this command:

```console
NAME    MAJ:MIN RM  SIZE RO TYPE MOUNTPOINT
sda       8:0    0   25G  0 disk 
├─sda1    8:1    0 24.9G  0 part /
├─sda14   8:14   0    4M  0 part 
└─sda15   8:15   0  106M  0 part 
sdb       8:16   0   25G  0 disk 
├─sdb1    8:17   0 24.9G  0 part 
├─sdb14   8:30   0    4M  0 part 
└─sdb15   8:31   0  106M  0 part /boot/efi
```

In this example, the partition containing your backup filesystem is named "sdb1". Next, create a directory for this partition and define it as the mountpoint:

```bash
sudo mkdir -p /mnt/restore
sudo mount /dev/sdb1 /mnt/restore
```

You can now switch to this folder and access your backup data.

Remember to unmount the backup once you have finished using it. In the `Automated backup` tab, the mounted backup shows **Mounted** in the **State** column. Click the unlink icon (a broken chain) in the **Actions** column of its row, then confirm in the window that appears.

{/* cp-shot: ![Backup tab unmount](/images/bare-metal-cloud/vps/using-automated-backups/backup-tab-unmount.png) */}

</Tab>

### Best practice for using Automated backups

The Automated Backup functionality is based on VPS snapshots. We recommend that you follow the steps below to prevent any issues before using this option.

#### Configuring the QEMU agent on a VPS

Snapshots are instantaneous images of your running system (“live snapshot”). To ensure the availability of your system when the snapshot is created, the QEMU agent is used to prepare the filesystem for the process.

The required "**qemu-guest-agent**" agent is not installed by default on most distributions. Moreover, licensing restrictions may prevent OVHcloud from including it in the available OS images. Therefore, it is best practice to verify and install the agent in case it is not activated on your VPS. Connect to your VPS via SSH and follow the instructions below, depending on your operating system.

<Tabs>

<Tab label="Debian based">

**Debian-based distributions (Debian, Ubuntu)**

Use the following command to check whether the system is properly set up for snapshots:

```bash
file /dev/virtio-ports/org.qemu.guest_agent.0
```

The expected output is:

```bash
/dev/virtio-ports/org.qemu.guest_agent.0: symbolic link to ../vport2p1
```

If the output is different (for example, "No such file or directory"), install the latest version of the package:

```bash
sudo apt-get update
sudo apt-get install qemu-guest-agent
```

Reboot the VPS:

```bash
sudo reboot
```

Start the service to ensure it is running:

```bash
sudo service qemu-guest-agent start
```

</Tab>

<Tab label="Red Hat based">

**Redhat-based distributions (Centos, Fedora)**

Use the following command to check whether the system is properly set up for snapshots:

```bash
file /dev/virtio-ports/org.qemu.guest_agent.0
```

The expected output is:

```bash
/dev/virtio-ports/org.qemu.guest_agent.0: symbolic link to ../vport2p1
```

If the output is different (for example, "No such file or directory"), install and enable the agent:

```bash
sudo yum install qemu-guest-agent
sudo chkconfig qemu-guest-agent on
```

Reboot the VPS:

```bash
sudo reboot
```

Start the agent and verify that it is running:

```bash
sudo service qemu-guest-agent start
sudo service qemu-guest-agent status
```

</Tab>

<Tab label="Windows">

**Windows**

You can install `virtio-win-guest-tools.exe` via the MSI file, available from the [Fedora project website](https://fedorapeople.org/groups/virt/virtio-win/direct-downloads/archive-qemu-ga/qemu-ga-win-109.1.0-7.el10/).

Verify that the service is running by using this PowerShell command:

```powershell
PS C:\Users\Administrator> Get-Service QEMU-GA
Status   Name               DisplayName
------   ----               -----------
Running  QEMU-GA            QEMU Guest Agent
```

</Tab>

### Troubleshooting automated backups

#### Aborting a snapshot

If your scheduled backups are causing downtime on your VPS, you can cancel the backup using the following API call.

<Api version="v1" section="/vps" method="POST" route={"/vps/\{serviceName\}/abortSnapshot"} regions={["us"]} />

#### Uninstalling the QEMU agent

:::warning

**NOTE:** On Windows VMs, QEMU is not installed by default, so no action is required.

:::

If the QEMU agent is installed on your OS by default and you are experiencing downtime during your automated backups, you can disable QEMU as a troubleshooting step in determining the reason for downtime. Removing these packages will not impact OpenStack or VPS functionality.

To complete this process on Linux, use the following commands.

Identify QEMU packages:

```bash
dpkg -l | grep qemu
```

Remove the QEMU packages:

```bash
sudo apt-get purge --auto-remove 'qemu*'
```
