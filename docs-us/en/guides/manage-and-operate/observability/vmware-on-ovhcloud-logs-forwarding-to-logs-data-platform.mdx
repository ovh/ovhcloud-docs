# VMware on OVHcloud - Logs forwarding to Logs Data Platform

## Requirements

- An [OVHcloud customer account](https://support.us.ovhcloud.com/hc/en-us/articles/115001286870)

- A [VMware on OVHcloud](https://us.ovhcloud.com/hosted-private-cloud/vmware/) environment with an [active Logs Data Platform stream](https://support.us.ovhcloud.com/hc/en-us/articles/28017122298771)

  :::info

  If you are not familiar with all the LDP stream configuration possibilities, simply create a new one with the default options (indexing and websocket enabled, long-term storage disabled) for this guide.

  :::

- Read our [Introduction to the Logs Data Platform](https://support.us.ovhcloud.com/hc/en-us/articles/27980753174035) guide

- You must have the `logForwarder` enabled (see [Step 1](https://support.us.ovhcloud.com/hc/en-us/articles/31687739344147#step-1-enable-log-forwarder-for-vmware-on-ovhcloud))

 

## Instructions

:::info

Please note that **log forwarding** is free to enable. However, to ensure that your Logs Data Platform dedicated cluster is working properly, storage charges for using the catalog of managed services (Graylogs, OpenSearch, Logstash, etc.) may apply at the standard rate.

For pricing information, refer to the solution page: [OVHcloud Logs Data Platform](https://us.ovhcloud.com/logs-data-platform/).

:::

By enabling logs forwarding to a Logs Data Platform stream, you can collect, index, and analyze data from a VMware on OVHcloud service. Regardless of their origin, this platform offers a variety of access methods depending on the protocol, the level of security, and the format desired. The data collected can be easily used, thanks to the multiple APIs and web interfaces available.

For further information on the technical specifications of the Logs Data Platform (ports, protocols, etc.), please refer to our guide [Quick Start for Logs Data Platform](https://support.us.ovhcloud.com/hc/en-us/articles/28017122298771).

 

### Logs and labels

#### Available kinds

A *Kind* is a "type" of log that your product generates.

These are the types of logs you want to transfer to your Logs Data Platform. Here are examples that may be available, depending on the components of your VMware on OVHcloud architecture:

- `esxi`: Filtered by application.
- `nsxtEdge`: Everything is redirected, no filter.
- `vcsa`: Filtered by application.
- `nsxtManager`: Filtered by application.

 

### Step 1 - Enable Log Forwarder for VMware on OVHcloud

<Tabs>

<Tab label="Via the OVHcloud Control Panel">

From the OVHcloud Control Panel, navigate to your PCC via the `Hosted Private Cloud` and `Managed VMware vSphere` menus, then select the `Logs` tab.

Click the `Activate log onboarding` button.

![VMware\_logs\_activation.png](/images/manage-and-operate/observability/vmware-on-ovhcloud-logs-forwarding-to-logs-data-platform/47402651983891.png)

:::warning

**NOTE:** This may take some time to process.

:::

</Tab>

<Tab label="Via the OVHcloud API">

:::info

If you are not familiar with using the OVHcloud APIv6, please refer to our guide on [Getting started with the OVHcloud API](https://support.us.ovhcloud.com/hc/en-us/articles/360018130839).

:::

Check if the `logForwarder` option can be enabled on your PCC:

<Api version="v1" section="/dedicatedCloud" method="GET" route={"/dedicatedCloud/\{serviceName\}/logForwarder/canBeEnabled"} regions={["us"]} />

:::info

If the API output reads "ALREADY\_ENABLED: This option is already enabled," you can skip to [Step 2](https://support.us.ovhcloud.com/hc/en-us/articles/31687739344147#step-2-create-a-logs-data-platform-stream).

:::

Enable the `logForwarder` option on your PCC:

<Api version="v1" section="/dedicatedCloud" method="POST" route={"/dedicatedCloud/\{serviceName\}/logForwarder/enable"} regions={["us"]} />

</Tab>

</Tabs>

 

### Step 2 - Create a Logs Data Platform stream

:::info

VMware on OVHcloud and Logs Data Platform resources must belong to the same OVHcloud account.

Your logs are manipulated for security and observability purposes in the Logs Data Platform private clusters. For more information on LDP pricing, please visit the LDP page available via [this link](https://us.ovhcloud.com/identity-security-operations/logs-data-platform/).

:::

To create a subscription, a stream is required. You can create a temporary stream to subscribe to your subscription with the `streamId` and the API POST call from step 3.

<Tabs>

<Tab label="Via the OVHcloud Control Panel">

You can refer to this guide to find out how to create a stream via the Logs Data Platform interface: [Quick start for Logs Data Platform](https://support.us.ovhcloud.com/hc/en-us/articles/28017122298771).

</Tab>

<Tab label="Via the OVHcloud API">

To create a stream, an LDP `serviceName` is required. This `serviceName` refers to a unique ID of your LDP account (for example `ldp-xx-XXXXX`).

For this reason, you will need to have a temporary LDP account in advance to create a temporary stream.

Here is the API call for creating a stream:

<Api version="v1" section="/dbaas/logs" method="POST" route={"/dbaas/logs/\{serviceName\}/output/graylog/stream"} regions={["us"]} />

> **Parameters**:
>
> - `description`: Description of your LDP stream.
> - `title`: Title of your LDP stream.

Return:

```json
{
  "aliasId": null,
  "createdAt": "2024-08-28T12:25:13.544323+02:00",
  "dashboardId": null,
  "encryptionKeyId": null,
  "indexId": null,
  "inputId": null,
  "operationId": "e34f7a06-386b-4602-8d16-d45249197d40",
  "osdId": null,
  "roleId": null,

  "streamId": null,

  "tokenId": null,

```

Retrieve the `streamId` and save it (copy and paste) in a text editor. You will need it to activate your VMware on OVHcloud subscription with the temporary Logs Data Platform stream in question.

In the next step, we will look at how to attach your managed vSphere subscription to a temporary LDP stream.

### Step 3 - Create a logs subscription for VMware on OVHcloud

:::warning

**NOTE:** To have an active Logs Data Platform subscription with VMware on OVHcloud, you must have an active stream.

To date, if you want to have a stream on the same account and with the same level of security as your VMware on OVHcloud environment, you must transfer this stream to your private infrastructure. You are responsible for the transfer and for the level of security you want..

You can refer to the [Logs Data Platform documentation](https://support.us.ovhcloud.com/hc/en-us/sections/27230973429523-Logs-Data-Platform) for more information on the levels of security and responsibilities available.

:::

<Tabs>

<Tab label="Via the OVHcloud Control Panel">

Once the logs function is activated, click the `Subscribe` button on the right-hand side of the screen.

![VMware\_logs.png](/images/manage-and-operate/observability/vmware-on-ovhcloud-logs-forwarding-to-logs-data-platform/47402651985683.png)

**Select a log type** and the Logs Data Platform service to which to send the logs. Click `Subscribe` to the right of the LDP stream you want to use.

![VMware\_logs\_subscribe.png](/images/manage-and-operate/observability/vmware-on-ovhcloud-logs-forwarding-to-logs-data-platform/47402662052499.png)

</Tab>

<Tab label="Via the OVHcloud API">

Use the following API calls to list subscriptions for your VMware on OVHcloud account.

**API call reference:**

- List all Log kinds available for your VMware on OVHcloud:

  <Api version="v1" section="/dedicatedCloud" method="GET" route={"/dedicatedCloud/\{serviceName\}/log/kind"} regions={["us"]} />

* List the details of a log type (ESXI | NSX-T EDGE | MANAGER | VCSA):

  <Api version="v1" section="/dedicatedCloud" method="GET" route={"/dedicatedCloud/\{serviceName\}/log/kind/\{name\}"} regions={["us"]} />

- List your VMware on OVHcloud subscriptions:

  <Api version="v1" section="/dedicatedCloud" method="GET" route={"/dedicatedCloud/\{serviceName\}/log/subscription"} regions={["us"]} />

* Create an LDP VMware on OVHcloud subscription:

  <Api version="v1" section="/dedicatedCloud" method="POST" route={"/dedicatedCloud/\{serviceName\}/log/subscription"} regions={["us"]} />

- List properties of a subscription:

  <Api version="v1" section="/dedicatedCloud" method="GET" route={"/dedicatedCloud/\{serviceName\}/log/subscription/\{subscriptionId\}"} regions={["us"]} />

To retrieve the **streamId** of your LDP account, read our guide [Quick Start for Logs Data Platform](https://support.us.ovhcloud.com/hc/en-us/articles/28017122298771).

<Api version="v1" section="/dedicatedCloud" method="POST" route={"/dedicatedCloud/\{serviceName\}/log/subscription"} regions={["us"]} />

> **Parameters:**
>
> - `serviceName`: Name of the managed vSphere service (e.g., `pcc-XXX-XXX-XXX-XXX`).
>
> **Request Body:**
>
> - `kind`: VMware Kind that the forwarder uses (e.g., `nxstEdge | vcsa | nsxtManager | esxi`).
> - `StreamId`: Destination stream identifier (e.g., uuid: `ggb8d894-c491-433e-9c87-50a8bf6fe773`).

Example of input parameters for the API call:

```json
{
  "serviceName": "pcc-XXX-XXX-XXX-XXX",
  "kind": "esxi",
  "streamId": "ggb8d894-c491-433e-9c87-50a8bf6fe773",
}
```

With the GET request, you can list the stream IDs in your subscription.

### Step 5 - Disable your Logs Data Platform subscription

:::info

Canceling your Logs Data Platform subscription with VMware on OVHcloud does not mean deleting your streams. The storage used at the time of deactivation is subject to billing.

**Note**: As of this date, you can only delete a stream in its entirety. It is not possible to remove only certain granular inputs.

:::

<Tabs>

<Tab label="Via the OVHcloud Control Panel">

To delete your subscription, simply click the `Unsubscribe` button to the right of your stream.

![VMware\_logs\_unsubscribe.png](/images/manage-and-operate/observability/vmware-on-ovhcloud-logs-forwarding-to-logs-data-platform/47402651991827.png)

</Tab>

<Tab label="Via the OVHcloud API">

<Api version="v1" section="/dedicatedCloud" method="DELETE" route={"/dedicatedCloud/\{serviceName\}/log/subscription/\{subscriptionId\}"} regions={["us"]} />

> **Parameters**:
>
> - `serviceName`: Service name of your managed vSphere (e.g., `pcc-XXX-XXX-XXX-XXX`).
> - `subscriptionId`: subscription ID of your LDP subscription (e.g., `8e729f36-3e5d-4e08-9723-62b2b39c857a`).

Return:

```json
{
 "operationId": "456eb42e-58r6-4cfd-8r5c-ccr97273712r",
 "serviceName": "ldp-XX-XXXX"
}
```

You will get an `operationId`, which is the identifier used to confirm that the deactivation operation has been carried out.

**Glossary**

- **Logs Data Platform:** Logs Management Platform, fully managed and secured by OVHcloud. For more information, see [the LDP Solution Overview page](https://us.ovhcloud.com/identity-security-operations/logs-data-platform/).
- **Data Stream:** Logical partition of logs that you create in a Logs Data Platform account and use when ingesting, viewing, or querying your logs. Multiple sources can be stored in the same data stream, and the unit can be used to define a log pipeline (retention policy, archiving, live streaming, etc.), access rights, and alert policies.
- **Log transfer:** A feature built into an OVHcloud product to integrate logs for its services into the *Data Stream* of a Logs Data Platform account in the same OVHcloud account. This feature must be enabled by you and for your service. Refer to this part of the guide to activate it: [Step 3 - Create a logs subscription for VMware on OVHcloud via the API](https://support.us.ovhcloud.com/hc/en-us/articles/31687739344147#via-the-ovhcloud-api-3)
- **Log redirection subscription:** When enabling log forwarding for your OVHcloud service to a given *Data Stream* Logs Data Platform, a *subscription* must be created and attached to the *Data Stream* for future management.
