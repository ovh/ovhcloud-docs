# Public VCF as-a-Service - Declaring the public IP gateway in VCD

When you order a new Public VCF as-a-Service organization, a vRack and a block of public IP addresses are delivered. To assign those public IPs to workloads, you must declare the block’s gateway inside the target VCD Virtual Datacenter.

This guide shows how to retrieve the correct gateway and add it to your VDC.

 

## Requirements

- A [Public VCF as-a-Service](https://us.ovhcloud.com/public-vcf-aas/) organization with a delivered public IP block
- Technical administrator rights on [VMware vSphere on OVHcloud](https://us.ovhcloud.com/hosted-private-cloud/vmware/)
- You must have completed the steps in our [Public VCF as-a-Service - Linking a public IP block with vRack](https://support.us.ovhcloud.com/hc/en-us/articles/45808153320083) guide

#### OVHcloud Control Panel Access

- **Direct link:** [Public VCF as-a-Service](https://manager.us.ovhcloud.com/#/vmware/public-vcf-aas/)
- **Navigation path:** `Hosted Private Cloud` > `Public VCF as-a-Service` > Select your organization

 

## Instructions

:::warning

**NOTE:** These instructions presume that you have already completed all steps in our [Public VCF as-a-Service - Linking a public IP block with vRack](https://support.us.ovhcloud.com/hc/en-us/articles/45808153320083) guide.

:::

Once you have selected your Public VCF as-a-Service organization, select the `Virtual Datacenters` tab and click the `ID` of your virtual datacenter.

![VCD\_virtualDatacenters.PNG](/images/hosted-private-cloud/cloud-platform/public-vcf-as-a-service-declaring-the-public-ip-gateway-in-vcd/53704505379347.png)

On the next page, select the `vRack` tab and locate the vRack segment named `vRack segment - VLAN0` or `vRack segment - PUBLIC`.

You will see a placeholder subnet `192.168.1.1`, which we will delete later.

Click the *more options* `⋮` button and select `Add a subnet`.

![VCD\_vDC\_vRack-segments.PNG](/images/hosted-private-cloud/cloud-platform/public-vcf-as-a-service-declaring-the-public-ip-gateway-in-vcd/53704505381523.png)

In the pop-up window, enter the **gateway IP of your subnet in CIDR** form for your public IP block, then confirm. The gateway is the **last usable host** of the block.

**Example**: For `203.0.113.0/29`, the last usable host is `203.0.113.6`, so enter `203.0.113.6/29`. You can use any standard IP calculator to verify.

Wait a few seconds and refresh the page. The subnet gateway should now appear on the segment.

:::warning

**NOTE:** After your entry has appeared, delete the placeholder subnet `192.168.1.1` from VLAN 0.

:::

![VCD\_vDC\_vRack-segments\_subnet.PNG](/images/hosted-private-cloud/cloud-platform/public-vcf-as-a-service-declaring-the-public-ip-gateway-in-vcd/53704505382163.png)

 

### Use the gateway when creating workloads

- When creating a vApp or VM in VCD, pick the corresponding **Organization VDC network** and choose a **Direct** network type to see the available public gateways.

![VCD\_vApp\_create.PNG](/images/hosted-private-cloud/cloud-platform/public-vcf-as-a-service-declaring-the-public-ip-gateway-in-vcd/53704505383315.png)

:::info

**Known limitation**:

In the current VCF version, the **Gateway CIDR** field may display the first gateway declared on your `VLAN0` segment, even if you selected another one. This is a visual-only issue and does not affect IP assignment. Use any address from the selected public block on your VM, consistent with the gateway you chose in **Organization VDC network connection**.

:::

 

### Troubleshooting

- If the gateway is rejected, recheck that you entered the **last usable host** with the correct **CIDR mask** for the block.
- Ensure the VDC is attached to the **same vRack** that you linked to the public IP block in the previous guide, [Public VCF as-a-Service - Linking a public IP block with vRack](https://support.us.ovhcloud.com/hc/en-us/articles/45808153320083).
