# Public VCF as-a-Service - FAQ

## FAQ

<details>
<summary>What is Public VCF as-a-Service?</summary>

This is a new product available within the VMware on OVHcloud offer that provides you with a virtual data center powered by VMware technology, on top of a mutualized infrastructure hosted and operated by OVHcloud.

Public VCF as-a-Service will be available in three tiers:

- Public VCF as-a-Service Standard, providing the standard VMware stack virtualization capabilities.
- Public VCF as-a-Service Advanced, including advanced networking & security capabilities on top of the Standard tier.
- Public VCF as-a-Service Premium, adding high-performance vSAN storage to the Advanced tier.

For more information, see our [Public VCF as-a-Service - The fundamentals of Public VCF as-a-Service](https://support.us.ovhcloud.com/hc/en-us/articles/28330367397139) guide.

</details>

<details>
<summary>How will migration be done by OVHcloud?</summary>

If you choose to migrate to Public VCF as-a-Service, OVHcloud will perform the migration for you.

As an exception, we won’t be charging the new current server/host prices during the migration process. We’ll absorb the costs of the license price increase while the migration is ongoing. Whether or not you choose to continue using the current solution, you will still benefit from the new Public VCF as-a-Service prices right away.

However, our goal is to migrate to Public VCF as-a-Service as soon as we’re ready. We’ll notify you 1 to 2 weeks before your migration starts, which will be carried out with zero downtime. If, for technical reasons, a live migration cannot be done, we’ll discuss with you how to proceed best.

</details>

<details>
<summary>How are you migrating my data to Public VCF as-a-Service?</summary>

Your data stays on the Leclerc v3 *filers*. We will expose the storage to Public VCF as-a-Service like we are exposing the storage to vSphere. Live migration between two hosts with the same CPU (Intel) is done via vMotion.

</details>

<details>
<summary>Can I still have access to vSphere ESXi and vCenter API with Public VCF as-a-Service?</summary>

With Public VCF as-a-Service, you cannot access vSphere ESXi and vCenter API. You will have access to Cloud Director API, and you can use tools such as [Terraform](https://registry.terraform.io/providers/vmware/vcd/latest/docs).

</details>

<details>
<summary>Can I still use products like Veeam, Nakivo, and Rubrik to back up my VMs?</summary>

No, with Public VCF as-a-Service, you cannot use tools that request access to vSphere ESXi or vCenter. However, we have set up a managed Veeam solution for setting up your backups.

</details>

<details>
<summary>How are backups configured with Public VCF as-a-Service?</summary>

For backups, we will offer you **Veeam Managed Backup** with an integrated plugin for VM backups. You can follow this guide for more information: [Public VCF as-a-Service - Backup with Veeam Data Platform](https://support.us.ovhcloud.com/hc/en-us/articles/33255029079059).

For backup configuration, we offer three types of jobs by default with Veeam, but you can add different policies if required. You may incur fees when you enable the Veeam Data Platform plugin.

Consumption will be based on VMs and by month, and storage consumption by month.

</details>

<details>
<summary>Can I use rules like affinity and anti-affinity as previously used with vSphere?</summary>

With Public VCF as-a-Service, you can define group affinity for virtual machines and rules like anti-affinity to isolate different virtual machines.

</details>

<details>
<summary>Which certifications apply to the new Public VCF as-a-Service service?</summary>

When the service is launched, OVHcloud will not apply any specific certification to the Public VCF as-a-Service service.

</details>

<details>
<summary>Can I choose the "Thin or Thick disk" type when I create a new virtual machine or disk with Public VCF as-a-Service?</summary>

No, with Public VCF as-a-Service, each disk consumes storage in a Virtual Data Center (vDC) organization. There is no associated "Thin or Thick" setting for a tenant.

</details>

<details>
<summary>Can I use my existing Windows Server licenses in Public VCF as-a-Service?</summary>

It depends on the type of license you own:

- **Software Subscription licenses:** Yes, you can use these in OVHcloud Public VCF as-a-Service.
- **Perpetual software licenses:** No, these cannot be used in OVHcloud Public VCF as-a-Service.

If your organization holds both types of licenses, only the subscription ones are eligible for use with the solution.

</details>
