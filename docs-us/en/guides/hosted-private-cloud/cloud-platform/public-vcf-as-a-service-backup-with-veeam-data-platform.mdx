# Public VCF as-a-Service - Backup with Veeam Data Platform

**Learn how to back up and restore with the Veeam Plug-in for VMware vCloud Director managed on OVHcloud.**

 

## Requirements

- An administrator vCloud Director account with a Public VCF as-a-Service Organization
- A user with the Organization Administrator role to connect to the Veeam Data Platform Self-Service Portal (the new admin user in a virtual data center has the default role)
- You need to have read the following Public VCF as-a-Service guides:\
  [The fundamentals of Public VCF as-a-Service](https://support.us.ovhcloud.com/hc/en-us/articles/28330367397139)\
  [Logging in to your organization](https://support.us.ovhcloud.com/hc/en-us/articles/28512588697875)\
  [How to Use the Public VCF as-a-Service user interface](https://support.us.ovhcloud.com/hc/en-us/articles/28330641929491)
- Be familiar with how Veeam Backup works
- An understanding of the financial impact following the various load factors that apply when setting up this solution with VCD (see the [pricing grid for Veeam vCD on OVHcloud backups](https://us.ovhcloud.com/hosted-private-cloud/vmware/veeam-managed-backup/))

 

## Instructions

Veeam Data Platform supports Public VCF as-a-Service. It uses the Public VCF as-a-Service API to back up the vApps and VMs and restore them directly in the Public VCF as-a-Service hierarchy.

The Veeam Data Platform service is available and ready to use for all three OVHcloud solutions (see the [features catalog](https://support.us.ovhcloud.com/hc/en-us/articles/28330367397139#features-of-vmware-cloud-director-at-ovhcloud)).

:::warning

**NOTE:** For the image processing and guest file system indexing options (compatible with the Veeam application) to work with Windows® virtual machines, the latest VMware tools must be installed. Linux VMs do not support application recognition or guest file system indexing.

If you are using application-aware image processing for MS SQL or Oracle database backups, application-aware and item recovery options will not be supported. A full restore of the virtual machine must be performed; this implies a downtime window for all database users. You cannot manually restart an immutable backup failure. You must run an active full backup or wait for the next scheduled backup to run (see [Veeam documentation for more information](https://helpcenter.veeam.com/docs/backup/vsphere/vcloud_manage_backup.html?ver=120)).

:::

 

### Step 1 - Backup with Veeam Data Platform

The **Veeam Data Platform** service has a Public VCF-as-a-Service plugin to back up VMs and vApps from any Virtual Data Center (vDC) in the organization. It is available at the organization level for any Public VCF as-a-Service user with the organization administrator role.

#### Access the Veeam Data Platform administration console

When using VCD Data Protection integration with Veeam to create backup jobs, you can choose any VM instance from any virtual data center in the organization.

To access the Data Protection Portal with Veeam from Cloud Director, log in to the Public VCF as-a-Service Client Portal with a vCloud Director account with the appropriate rights.

In the left-hand menu, click `More` and select `Data Protection with Veeam`.

<Tabs>

<Tab label="Backup jobs">

Backup jobs require four default settings:

1. Job parameters: Name / Deposit or Quota (Bronze/Silver/Gold: 100TB) / Description / Retention (Days/Restore point)
2. Virtual machines (VMs): Add or exclude virtual machines/vApp/vCloud Organization
3. Guest Processing: Application-aware processing / Guest file system indexing / Guest operating system credentials
4. Email notifications: Enabling email notifications

For virtual machines managed by Public VCF as-a-Service, Veeam Backup & Replication offers a special type of backup job: VMware Cloud Director backup jobs. Public VCF as-a-Service backup jobs process VMware Cloud Director objects, ensure their proper recovery, and support specific Cloud Director features.

</Tab>

<Tab label="Repositories">

By default, you have the following repositories:

- **Bronze Repository**: This repository is based on the [OVHcloud Object Storage Standard](https://us.ovhcloud.com/public-cloud/object-storage/) class. We will be using a bucket closer to your Public VCF as-a-Service environment.
- **Silver Repository**: This repository is based on the [OVHcloud Object Storage Standard](https://us.ovhcloud.com/public-cloud/object-storage/) class. We will be using a Veeam SOBR (Scale-out Backup Repository) with performance tier buckets closer to your Public VCF as-a-Service environment, and a capacity tier from buckets in another OVHcloud region. We also use the Veeam SOBR copy mode to add the backups from the "performance extents" to the "capacity extents" as soon as they're created.
- **Gold Repository**: This repository is based on the [OVHcloud Object Storage High performance](https://us.ovhcloud.com/public-cloud/object-storage/) class and includes the previous options as well as OVHcloud Object Storage "High performance." This repository can be activated from the OVHcloud Control Panel.

All these repositories have a storage quota of 100TB. You can reach out to the [support teams](https://us.ovhcloud.com/support/) to increase this quota.

<Tab label="Data included">

When Veeam Backup & Replication performs backups of vApp and VMs, it also captures vApp metadata.

The metadata for virtual applications (vApp) and VMs include:

- General information on the **vApps** (virtual applications) where the VMs reside, such as: **Name of the vApps**, **descriptions**, and **description of the VMs**.
- Information on the **vApp** networks and the organizational networks to which the vApp is connected.
- The startup options of the **VM** (VM Startup options).
- User information.
- Lease.
- The quota.
- Storage templates.

The vApp/VM metadata is stored with the virtual machine content. Capturing vApp/VM metadata is important for recovery: without it, you will not be able to restore vApps and VMs to Public VCF as-a-Service.

</Tab>

#### How do I create a backup job with the Veeam Data Platform?

You can create your first backup job using the Veeam Data Platform Public VCF as-a-Service plugin.

<details>
<summary>Click here for full instructions.</summary>

In the left-hand menu, click `More` and select `Data Protection with Veeam`.

Select the `Jobs` tab, and then the `Create` button.

![VCD\_dataProtectionVeeam\_jobs.PNG](/images/hosted-private-cloud/cloud-platform/public-vcf-as-a-service-backup-with-veeam-data-platform/53711801720851.png)

In the window that opens, specify the backup job name, description, and retention policy. Once you have defined the elements, click `Next`.

![VCD\_veeamBackup\_createJob-01.PNG](/images/hosted-private-cloud/cloud-platform/public-vcf-as-a-service-backup-with-veeam-data-platform/53711817608339.png)

You then need to choose your virtual machine (VM). To do this, click `+ Add`.

![VCD\_veeamBackup\_createJob-02.PNG](/images/hosted-private-cloud/cloud-platform/public-vcf-as-a-service-backup-with-veeam-data-platform/53711801725203.png)

Expand the Public VCF as-a-Service organization menu and select your VM.

:::info

You can also select a vApp, in which case all VMs within the vApp will be included in the backup job.

:::

Click `OK` and then `Next`.

Your virtual machine will then appear in the list.

Click `Next`.

![VCD\_veeamBackup\_createJob-02b.png](/images/hosted-private-cloud/cloud-platform/public-vcf-as-a-service-backup-with-veeam-data-platform/53870872149139.png)

:::warning

**NOTE:** The next step is vital, as it involves adding the *credentials* required for your VM. If you use the "Guest OS processing" settings, you must add your backup user ID and password according to your OS type.

If you have SSH keys to add for Linux, you can do so.

For Windows, you can choose a standard account or a managed service account.

:::

Make your selections according to your OS type and click `Next`.

![VCD\_veeamBackup\_createJob-03.PNG](/images/hosted-private-cloud/cloud-platform/public-vcf-as-a-service-backup-with-veeam-data-platform/53711817609747.png)

If necessary, you can add monitoring options for your backup tasks. Finally, click `Finish`.

:::warning

**NOTE:** If you add multiple email addresses for monitoring, use a semicolon (`;`) as a separator between each address.

**Example:** `email1@example.com; email2@example.com`

:::

![VCD\_veeamBackup\_createJob-04.PNG](/images/hosted-private-cloud/cloud-platform/public-vcf-as-a-service-backup-with-veeam-data-platform/53711817610899.png)

:::tip

**SUCCESS!** The backup job is listed.

:::

</details>

### Step 2 - Restore with Veeam Data Platform

#### Veeam Backup features

- Application Awareness
- The strategy per VM (Policies)

 

#### Data included in restores

Veeam Backup & Replication enables full recovery of VMs to Public VCF as-a-Service. You can restore separate VMs to vApps, as well as VM data.

 

#### Restore options

:::warning

**NOTE:** Only `Entire VM / vApp Restore` is available at this time.

:::

- Entire VM / vApp Restore
- Disk-Level Restore
- File-Level Restore

 

#### Restoration of a VM

With the OVHcloud Managed Backup service, you can restore standard VMs that are part of vApps, and standalone VMs that have been created in your OVHcloud VMware Cloud Director portal.

When you restore normal or standalone VMs in the vCloud Director hierarchy, the restoration process includes the following steps:

- Veeam uses the captured vApp metadata to define the vApp settings and the original location of the virtual machine in the Public VCF as-a-Service hierarchy.
- Veeam restores the VMs in the backup file to their original location or another location. In addition, Veeam restores all VM settings.
