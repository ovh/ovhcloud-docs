# Setting up Multicloud Snapshot Technology (MST) on a Nutanix on OVHcloud infrastructure

Find out how to deploy and configure **Multicloud Snapshot Technology (MST)** on a Nutanix on OVHcloud infrastructure with OVHcloud object storage.

With MST, you can **replicate snapshots** (UVM/Volume Groups) to **S3**[**™\***](#go-further)**-compatible storage** to optimize TCO, improve data mobility, and simplify disaster recovery (DR.) using a **zero-compute** model.

 

## Overview & advantages

**Main features:**

- Periodic replication of snapshots to S3™ buckets (typical RPO: 1 hour via the Nutanix DR. infrastructure).
- Model **Zero-Compute**: No need to maintain compute standby nodes.
- Store recent snapshots on the main cluster; offload older snapshots to object storage.
- Restore anywhere **Nutanix Cloud Platform (NCP)**: cloud, edge, on-prem.
- Native integration with **Prism Central** and existing DR. workflows.

**Functional limits (Instance Small):**

- Up to **2000 protected entities**.
- **75 Recovery Points** per entity.
- **300 TB** of supported active data.

**Benefits:**

- Reduced TCO (reduced/no standby compute, less expensive object storage).
- Mobility: Retrieve workloads on different NCP environments.
- Manageability via Prism.

 

## Requirements

- A Nutanix cluster in your OVHcloud account
  - If not done already, [replace the OVHgateway](https://support.us.ovhcloud.com/hc/en-us/articles/18875377642387) on your cluster

- Access to the Prism Central interface (only an admin can deploy MST) with:

  - AOS 7.3 minimum (in Prism Central, `Infrastructure` > `Hardware` > `Clusters`)
  - Prism Central 7.5.1 minimum (in Prism Central, `<User Name>` in the top-right corner > `About Nutanix`)

- Verify that you have the following resources available in your environment:

  - **3 static IP addresses** reserved (outside the DHCP range of the subnet MST).
  - **4 IP addresses** from the DHCP range of the MST subnet (consumed by the 4 MST VMs).
  - 3 × **Controller VMs**: 10 vCPU / 24 GiB RAM each.
  - 1 × **Load Balancer VM**: 2 vCPU / 4 GiB RAM.

 

## Instructions

### Prepare the environment

#### Create the Object Storage container (Bucket)

To create the container, you first need to create a project: [Create your first Public Cloud project - OVHcloud](https://help.ovhcloud.com/csm/en-gb-public-cloud-compute-create-project?id=kb_article_view\&sysparm_article=KB0050592).

In the [Public Cloud universe](https://manager.us.ovhcloud.com/#/public-cloud/pci/projects), navigate to the `Object Storage` section and choose the `Users` tab.

Create a user, e.g., *admin-mst*.

![objectStorage\_usersTab.PNG](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/49628884360211.png)

Please note the **Access key** and **Secret key** for that user:

![objectStorage\_newUser-credentials.png](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/49628877117971.png)

Then create a container (bucket). See our [Getting started with Object Storage](https://support.us.ovhcloud.com/hc/en-us/articles/4603838122643) guide for full instructions.

In this example, a container was created in Hillsboro, since the Nutanix cluster is in Vint Hill. This improves data resilience.

![objectStorage\_MST\_HIL.PNG](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/49629917798931.png)

Once you have created the container and the user, you will need to have several pieces of information that are important for continuation:

- The name of your container.
- The URL of the container endpoint: [https://s3.us-west-or.io.cloud.ovh.us/](https://s3.us-west-or.io.cloud.ovh.us/),
- The **access key** for the user you created, and
- The **secret key** for the user you created.

 

#### Activate the Marketplace

Log in to Prism Central, go to the admin center, then click `Enable Marketplace`.

![prism\_marketplace\_enable.png](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/50585708194963.png)

 

#### Enable Network Controller

In `Infrastructure` go to `Prism Central Settings`, click `Network Controller` then `Enable`.

![prism\_networkController\_enabled.PNG](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/49630255016851.png)

 

#### Create a subnet dedicated to MST

Navigate to `Network & Security` > `Subnets` > `Create Subnet`.

We will create an IPAM subnet with a DHCP for using MST.

:::warning

**NOTE:** For the **IP Pool**, make sure that the three required IP addresses for your MST VMs are **outside** of the pool's range.

:::

![prism\_subnets\_create-MST.png](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/50585686677907.png)

 

#### Reconfigure the Gateway

Navigate to `Compute` > `VMs` > `<your gateway VM>`.

Select the `NIC` tab and click `+ Attach to Subnet`.

You will need to reconfigure the gateway with the new network.

Add a NIC to your VM:

![prism\_MST-VM\_createNIC.png](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/49631336170771.png)

Then reconfigure your gateway with the IP defined in the IPAM network creation.

For example, on an Alpine VM:

![09 gateway setup](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/hosted-private-cloud-nutanix-on-ovhcloud-81-multi-snapshot-technologie-images-ms.png)

We would add:

```
auto eth3
iface eth3 inet static
address 10.8.0.254
netmask 255.255.255.0
```

Restarting network services:

![10 gateway setup2](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/hosted-private-cloud-nutanix-on-ovhcloud-81-multi-snapshot-technologie-images-ms.png)

 

### Deploy Multicloud Snapshot Technology

1. Log in to **Prism Central** as an **administrator**.
2. Go to `Admin Center` > `Marketplace`.
3. In **Nutanix Apps**, click `Get` for **Multicloud Snapshot Technology**.

![prism\_marketplace.PNG](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/49630432518163.png)

On the introduction page, click `Deploy`.

![prism\_MSTapp.png](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/49630432523027.png)

Then configure the MST instance:

- **MST Instance Size**: Select `Small` (or other size if available).
- **Cluster Details**: Choose the target Prism Element cluster.
- **Network Configuration**: Select the MST subnet created.
- **Enter the 3 reserved static IPs** (that are outside the DHCP range) in the expected fields.

![prism\_MST-instance-configuration-1.png](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/50585686683539.png)

- **Object Store Provider**: Select `S3 Compatible (Nutanix certified)`.
- **Object Store Endpoint**: Enter your container's endpoint URL, in our example `s3.us-west-or.io.cloud.ovh.us`.
- **Bucket Name**: Enter the name of your container. In our example, *mst-hillsboro*.
- **Access Key**: Enter your container’s `Access Key`.
- **Secret Key**: Enter the `Secret Key` of your container.

![prism\_MST-instance-configuration-2.png](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/50585686689043.png)

Launch the deployment.

![prism\_MST\_deployment.png](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/49631720105107.png)

 

## Disaster Recovery: Use and configuration

Once you have deployed an MST and connected it to your Object Storage bucket, you can configure how your workloads are protected and restored.

 

### Entity protection

From **Prism Central**, go to `Protection Policies` and click `Create Protection Policies`.

![prism\_protectionPolicies\_onboarding.png](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/50585708205587.png)

Define the `Policy name` and enter your cluster in the `Primary location` field.

In the `Recovery Location` box, keep Local AZ and select the container (Bucket) previously configured.

![prism\_protectionPolicy\_location.png](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/50585686693011.png)

On the next screen, click `Configure` to the right of the replication rule.

Specify the following:

- The frequency of snapshots (every hour by default).
- The number of Recovery Points to keep locally.
- The number of Recovery Points to keep on the **OVHcloud S3™ container**.

![prism\_protectionPolicy\_addSchedule.png](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/50585708209811.png)

:::info

**There is an optional third step to create protection groups, if you desire.**

:::

From here, navigate to `VMs` to select the VMs you want to protect.

- **If you are protecting a single VM:** Right-click on the VM's name, choose `Data Protection`, and then `Protect`.
- **If you are protecting multiple VMs:** Choose the *action* `...` menu from the toolbar, choose `Data Protection`, and then `Protect`.

![prism\_VMs\_enable-data-protection.PNG](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/50585708213907.png)

Then select the Protection Policy you created earlier:

![prism\_VMs\_dataProtection\_choosePolicy.PNG](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/50585686704275.png)

 

### Restoration

To restore a VM, navigate to `Data Protection` > `VM Recovery Points` and select a Recovery Point available in the bucket.

![prism\_dataProtection\_recoveryPoints.PNG](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/50585708219795.png)

From here, use the `Actions` menu and choose `Clone`.

![prism\_dataProtection\_recoveryActions.PNG](/images/hosted-private-cloud/nutanix-on-ovhcloud/setting-up-multicloud-snapshot-technology-mst-on-a-nutanix-on-ovhcloud-infrastru/50585686709651.png)

 

### Typical use cases

- **Disaster Recovery (DR)**: Total loss of the source cluster → deployment of VMs on another Nutanix cluster linked to the same OVHcloud bucket.
- **Workloads migration**: Move an application to another site (edge or cloud) by importing snapshots from the bucket.
