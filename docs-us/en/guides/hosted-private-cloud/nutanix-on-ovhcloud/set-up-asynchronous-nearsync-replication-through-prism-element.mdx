# How to Set Up Asynchronous or NearSync Replication through Prism Element

**Learn how to set up cluster replication via Prism Element.**

 

## Introduction

Via **Prism Element**, you can:

- Add links to remote clusters.
- Create protection domains to add replications to remote sites.

:::warning

**NOTE:** The **Starter** Nutanix on OVHcloud pack allows you to use asynchronous replicas **every hour**.\
\
For a shorter replication time, between 1 and 15 minutes, you must configure NearSync replicas. This option is only available with the **Pro** or **Ultimate** OVHcloud packs.

:::

 

## Requirements

- Two Nutanix clusters in your OVHcloud account
- Access to the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/#/hub)
- Access to your clusters via **Prism Central**
- An interconnection between two clusters, e.g. via an IPsec VPN

 

## Instructions

We will use two Nutanix clusters in OVHcloud datacenters, called Datacenter 1 and Datacenter 2, connected via an IPsec VPN, on two different IP addressing schemes which are:

- **192.168.0.0/24** for the cluster in Datacenter 2.
- **192.168.10.0/24** for the cluster in Datacenter 1.

If you need help setting up an IPsec VPN, please refer to our guide on [interconnecting two Nutanix clusters through an IPsec VPN](/guides/hosted-private-cloud/nutanix-on-ovhcloud/interconnect-two-nutanix-clusters-ipsec-vpn).

Connect via **Prism Element** to the cluster in Datacenter 2 from **Prism Central**, as shown in this documentation: [Nutanix Hyperconvergence](/guides/hosted-private-cloud/nutanix-on-ovhcloud/overview-nutanix-hyperconvergence).

### Setting up inter-site replication

Now that the two sites are connected, we will create a protection domain with asynchronous replication containing three virtual machines located on the cluster in Datacenter 2 to the remote site in Datacenter 1.

Return to the cluster’s **Prism Element** interface for Datacenter 2.

Choose `Data Protection` from the main `Home` menu.

![Cluster replication - Set up asynchronous nearsync replication through prism element - step 18](/images/hosted-private-cloud/nutanix-on-ovhcloud/set-up-asynchronous-nearsync-replication-through-prism-element/clusterreplica-18.png)

In the **Data Protection** dashboard, click `+ Protection Domain` in the top right-hand corner, then `Async DR`.

![Cluster replication - Set up asynchronous nearsync replication through prism element - step 27](/images/hosted-private-cloud/nutanix-on-ovhcloud/set-up-asynchronous-nearsync-replication-through-prism-element/clusterreplica-27.png)

Name the protection domain and click `Create`.

![Cluster replication - Set up asynchronous nearsync replication through prism element - step 19](/images/hosted-private-cloud/nutanix-on-ovhcloud/set-up-asynchronous-nearsync-replication-through-prism-element/clusterreplica-19.png)

Select three virtual machines and click `Protect Selected Entities`.

![Cluster replication - Set up asynchronous nearsync replication through prism element - step 22](/images/hosted-private-cloud/nutanix-on-ovhcloud/set-up-asynchronous-nearsync-replication-through-prism-element/clusterreplica-22.png)

Click `Next`.

![Cluster replication - Set up asynchronous nearsync replication through prism element - step 21](/images/hosted-private-cloud/nutanix-on-ovhcloud/set-up-asynchronous-nearsync-replication-through-prism-element/clusterreplica-21.png)

Click `New Schedule` to configure the schedule.

![Cluster replication - Set up asynchronous nearsync replication through prism element - step 20](/images/hosted-private-cloud/nutanix-on-ovhcloud/set-up-asynchronous-nearsync-replication-through-prism-element/clusterreplica-20.png)

Modify this option to **Configure your local schedule**:

- Enter **Repeat every** `1 hour`.

Then enter the retention policies in **Retention policy**:

- Choose locally and remotely **keep the last** `2` **snapshots** to keep two snapshots locally and remotely.

Click `Create Schedule` to commit the schedule.

![Cluster replication - Set up asynchronous nearsync replication through prism element - step 23](/images/hosted-private-cloud/nutanix-on-ovhcloud/set-up-asynchronous-nearsync-replication-through-prism-element/clusterreplica-23.png)

The replication task is created to run hourly. This will be asynchronous replication, which can be used with the OVHcloud **Starter** pack.

Click `Close` to close the window.

:::info

You can change the schedule to reduce the risk of data loss in the event of a disaster, but replication will switch from asynchronous to *NearSync* mode, and you will then need to upgrade your license to the OVHcloud **Pro** or **Ultimate** packs.

:::

### Virtual machine migration

Migrating VMs is an operation to move VMs that are members of a protection domain to the remote site without losing data. Both clusters must be online and communicate correctly with each other.

The migration steps are as follows:

1. Stopping virtual machines on the source cluster (if they are turned on).
2. Replication of missing data to the destination cluster.
3. Deleting virtual machines on the source cluster.
4. Disable scheduling.
5. Enabling virtual machines on the destination cluster.
6. Replication is reversed, the destination becomes the source.

Go to the **Prism Element** interface where the replicated virtual machines are located.

In the **Data Protection** dashboard, click `Migrate`.

![Cluster replication - Set up asynchronous nearsync replication through prism element - step 28](/images/hosted-private-cloud/nutanix-on-ovhcloud/set-up-asynchronous-nearsync-replication-through-prism-element/clusterreplica-28.png)

Select the remote site, type `MIGRATE`, and click `Migrate`.

![Cluster replication - Set up asynchronous nearsync replication through prism element - step 26](/images/hosted-private-cloud/nutanix-on-ovhcloud/set-up-asynchronous-nearsync-replication-through-prism-element/clusterreplica-26.png)

The migration is then launched. It will be completed when the VMs appear at the remote site and are no longer visible at the original site.

Since the migrated virtual machines are turned off, you must start them manually.

![Cluster replication - Set up asynchronous nearsync replication through prism element - step 31](/images/hosted-private-cloud/nutanix-on-ovhcloud/set-up-asynchronous-nearsync-replication-through-prism-element/clusterreplica-31.png)

 

### Virtual machine failover in case of disaster

If the original site is down, you can enable virtual machines that are members of a protection domain at the destination site.

:::warning

**NOTE:&#x20;**&#x41;ctivation of virtual machines at the remote site will be done with the latest replicated data. For asynchronous replication, the maximum data loss risk is one hour.

:::

Connect to the functional site with **Prism Element**.

Go to the **Data Protection** dashboard.

Select the site to activate and click `Activate`.

![Cluster replication - Set up asynchronous nearsync replication through prism element - step 32](/images/hosted-private-cloud/nutanix-on-ovhcloud/set-up-asynchronous-nearsync-replication-through-prism-element/clusterreplica-32.png)

Click `Yes`.

![Cluster replication - Set up asynchronous nearsync replication through prism element - step 30](/images/hosted-private-cloud/nutanix-on-ovhcloud/set-up-asynchronous-nearsync-replication-through-prism-element/clusterreplica-30.png)

The virtual machines will appear in the **Prism Element** console in the state of last replication. Data modified after the last valid replication will be lost.
