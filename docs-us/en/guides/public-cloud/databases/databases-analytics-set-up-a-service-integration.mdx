# Databases & Analytics - Set up a service integration

**Learn how to use Cross Service Integration to expose your Cloud Databases or Analytics service's Logs and Metrics.**

:::warning

**Out of scope:**

- Expose metrics and logs outside of OVHcloud Public Cloud
- MongoDB® is not supported

:::

 

## Requirements

- A [Public Cloud project](https://us.ovhcloud.com/public-cloud/) in your OVHcloud account
- A Cloud Database or Analytics service running ([this guide](https://support.us.ovhcloud.com/hc/en-us/articles/20611621210515) can help you to meet this requirement)
- Access to your [OVHcloud Control Panel](https://us.ovhcloud.com/manager/) or the [OVHcloud API](https://api.us.ovhcloud.com/)

 

## Concept

The Cross Service Integrations for Logs and Metrics allow you, for example[\*](#go-further):

- To send Valkey or MySQL® metrics to PostgreSQL®.
- To send PostgreSQL® or MySQL® metrics to OpenSearch™.
- To show metrics in Dashboard.

For that, you need:

- A source service
- A destination service

![DBaaS\_crossservice01-noborder.png](/images/public-cloud/databases/databases-analytics-set-up-a-service-integration/20619131445139.png)

:::warning

**NOTE:** Although it is possible to define the same cluster as destination service and source service, this is a bad practice for multiple reasons (performance, security, resiliency, etc.).

:::

![DBaaS\_crossservice02-noborder.png](/images/public-cloud/databases/databases-analytics-set-up-a-service-integration/20619085215507.png)

 

### Integration matrix

- All services support logs to OpenSearch® & kafka\_logs to kafka.
- All services support metrics to pg.

Other integrations:

|                                |                       |                    |
| ------------------------------ | --------------------- | ------------------ |
| **source →** **↓ destination** | **dashboard**         | **kafka**          |
| pg                             | dashboard, datasource |                    |
| opensearch                     | datasource            |                    |
| kmm                            |                       | kafka\_mirrormaker |
| kc                             |                       | kafka\_connect     |

 

## Instructions

### Using the OVHcloud Control Panel

#### Store your logs or metrics

Log in to your [OVHcloud Control Panel](https://us.ovhcloud.com/manager/) and open your database instance via the `Public Cloud` and `Databases` menus.

Open the `Integration` tab and click `+ Add an integration`.

![manager\_database\_integrationsTab.png](/images/public-cloud/databases/databases-analytics-set-up-a-service-integration/41904213951507.png)

Define the **Integration type** and th&#x65;**&#x20;Destination service**:

:::warning

**NOTE:** First, create an instance for your *Destination* (Target) service via your Control Panel or API.

:::

![manager\_database\_integration\_postgresqlMetrics.png](/images/public-cloud/databases/databases-analytics-set-up-a-service-integration/41904213955731.png)

Your first integration is ready:

![manager\_database\_integration\_ready.png](/images/public-cloud/databases/databases-analytics-set-up-a-service-integration/41904244827283.png)

:::info

This integration creation may have created two users, respectively: **metrics\_reader** and **metrics\_writer** in your engine instance.

![manager\_database\_users\_metricsUsers.png](/images/public-cloud/databases/databases-analytics-set-up-a-service-integration/41904213960339.png)

Don't delete them.

:::

 

#### Allow metrics visualization into Dashboard

Go to the `Integrations` tab of your **Destination service** and click on `+ Add an integration`.

![manager\_database\_integration\_ready.png](/images/public-cloud/databases/databases-analytics-set-up-a-service-integration/41904244827283.png)

:::info

As you can see, the first integration is referenced.

:::

Define `grafanaDashboard` as the **Integration type** and the **Source service**. Then click `Add`.

![manager\_database\_integration\_grafanaDashboard.png](/images/public-cloud/databases/databases-analytics-set-up-a-service-integration/41904213964947.png)

Your second integration is ready:

![manager\_database\_integrationsTab\_list.png](/images/public-cloud/databases/databases-analytics-set-up-a-service-integration/41904213968915.png)

Connect to your Grafana® instance and browse the dashboards:

![DBaaS\_crossservice10.png](/images/public-cloud/databases/databases-analytics-set-up-a-service-integration/25606371436563.png)

Then open your new dashboard:

![DBaaS\_crossservice11.png](/images/public-cloud/databases/databases-analytics-set-up-a-service-integration/25606371455251.png)

 

### Using API

:::info

If you are not familiar with using the OVHcloud API, please refer to our guide on [First Steps with the OVHcloud API](https://support.us.ovhcloud.com/hc/en-us/articles/360018130839).

:::

#### Get your service and cluster IDs

You first need to identify your `serviceId` and your `clusterId`.

##### **Get the desired service ID**

Execute the following API call:

<Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project"} regions={["us"]} />

From the resulting list, select and copy the service identifier corresponding to the desired service, also known as `serviceName`.

##### **Get the desired cluster ID**

Open the following API call, paste your service ID into the `serviceName` input field, and click `Execute`:

| Engine             | API call                                                                                                                                       |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Dashboard          | <Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/database/grafana"} regions={["us"]} />          |
| Kafka®             | <Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/database/kafka"} regions={["us"]} />            |
| Kafka® Connect     | <Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/database/kafkaConnect"} regions={["us"]} />     |
| Kafka® MirrorMaker | <Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/database/kafkaMirrorMaker"} regions={["us"]} /> |
| MySQL®             | <Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/database/mysql"} regions={["us"]} />            |
| OpenSearch™        | <Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/database/opensearch"} regions={["us"]} />       |
| PostgreSQL®        | <Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/database/postgresql"} regions={["us"]} />       |
| Valkey             | <Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/database/redis"} regions={["us"]} />            |

#### Store your logs or metrics

As a first step, you need to push your metrics or logs somewhere, to store them and retrieve the metrics with Dashboard.

For that, you need to create a new integration:

| Engine             | API call                                                                                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dashboard          | <Api version="v1" section="/cloud/project" method="POST" route={"/cloud/project/\{serviceName\}/database/grafana/\{clusterId\}/integration"} regions={["us"]} />          |
| Kafka®             | <Api version="v1" section="/cloud/project" method="POST" route={"/cloud/project/\{serviceName\}/database/kafka/\{clusterId\}/integration"} regions={["us"]} />            |
| Kafka® Connect     | <Api version="v1" section="/cloud/project" method="POST" route={"/cloud/project/\{serviceName\}/database/kafkaConnect/\{clusterId\}/integration"} regions={["us"]} />     |
| Kafka® MirrorMaker | <Api version="v1" section="/cloud/project" method="POST" route={"/cloud/project/\{serviceName\}/database/kafkaMirrorMaker/\{clusterId\}/integration"} regions={["us"]} /> |
| MySQL®             | <Api version="v1" section="/cloud/project" method="POST" route={"/cloud/project/\{serviceName\}/database/mysql/\{clusterId\}/integration"} regions={["us"]} />            |
| OpenSearch™        | <Api version="v1" section="/cloud/project" method="POST" route={"/cloud/project/\{serviceName\}/database/opensearch/\{clusterId\}/integration"} regions={["us"]} />       |
| PostgreSQL®        | <Api version="v1" section="/cloud/project" method="POST" route={"/cloud/project/\{serviceName\}/database/postgresql/\{clusterId\}/integration"} regions={["us"]} />       |
| Valkey             | <Api version="v1" section="/cloud/project" method="POST" route={"/cloud/project/\{serviceName\}/database/redis/\{clusterId\}/integration"} regions={["us"]} />            |

The `destionationServiceId` and the `sourceServiceId` correspond to the destination cluster ID and the source cluster ID.
