# Databases & Analytics - Maintenance operations

**Learn about how your database or analytics service schedules and performs maintenance operations.**

Cloud Databases and Analytics allow you to focus on building and deploying cloud applications while OVHcloud takes care of the database infrastructure and maintenance.

 

## Why maintenance operations?

Sometimes during a cluster lifecycle, some action may be required to keep it running smoothly. For example, a new patch version of some underlying OS package might get released to provide some fixes.

 

## How are those operations carried out?

- At some point, the system finds out that a maintenance operation becomes necessary. For example, a new version of some package participating in the service installation may become available.
- It then exposes a new maintenance operation for your service, with a description showing what needs to be done, a status (`SCHEDULED`, `APPLYING`, `APPLIED`), and a scheduled date. That date is computed using the "maintenance time" property of your service.
- The operation is triggered when the scheduled date is reached.

 

## What is the expected impact on the service?

The underlying VM often needs to be rebuilt, or the service needs to restart.

For single-node services, that means there is a short time when your service becomes unavailable.

For multi-node services, per-engine resiliency mechanisms ensure the service remains available when a node is operated on. If the application handles such cases gracefully (for example, reconnects and retries properly on failure), then the impact should be minimal or even non-existent.

 

## How can I monitor the planned maintenance?

You can monitor planned maintenance from the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/) by selecting your engine. From the `Dashboard` tab, look at the **Maintenance** panel.

From there, you can `Plan my future maintenance tasks →` or `Manage and schedule my maintenance tasks →`.

![manager\_database\_dashboard.png](/images/public-cloud/databases/databases-analytics-maintenance-operations/41920345903379.png)

 

#### Via the OVHcloud API

You can also use the [OVHcloud API](https://api.us.ovhcloud.com/) to get a list of maintenance operations for a service. Each engine has its own API endpoint similar to the one below for PostgreSQL[®](#go-further), which will be used throughout this guide.

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/postgresql/\{clusterId\}/maintenance"} regions={["us"]} />

To see the details of a maintenance operation, use:

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/postgresql/\{clusterId\}/maintenance/\{maintenanceId\}"} regions={["us"]} />

:::info

If you are not familiar with using the OVHcloud API, please refer to our [First Steps with the OVHcloud API](https://support.us.ovhcloud.com/hc/en-us/articles/360018130839) guide.

:::

 

## How can I control the scheduling?

You can change the **Maintenance time** for your service to a time that suits you. For example, if your application is less busy at night, you can target that timeframe. Be aware that this only affects future maintenance operation scheduling, it won't reschedule already existing operations.

You can also apply a specific operation early by clicking `Apply`.

![manager\_database\_applyMaintenance-2.png](/images/public-cloud/databases/databases-analytics-maintenance-operations/43197184622227.png)

 

#### Via the OVHcloud API

You can preemptively apply some operations using this API endpoint:

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/database/postgresql/\{clusterId\}/maintenance/\{maintenanceId\}/apply"} regions={["us"]} />

This might be a good idea if, for example, you are approaching a busy period and want to avoid disturbances during that time.
