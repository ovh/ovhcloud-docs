# Databases & Analytics - Configure your private network

**Learn how to connect a Public Cloud Instance, hosted in a data center, to a Cloud Database or Analytics service, hosted in another data center, like this:**

![DBaaS\_config\_privatenetwork01.png](/images/public-cloud/databases/databases-analytics-configure-your-private-network/20492770247571.png)

The OVHcloud vRack is a private network solution that enables our customers to route traffic between OVHcloud dedicated servers as well as other OVHcloud services, such as Cloud Databases or Analytics services. The vRack also allows you to add Public Cloud instances to your private network to create an infrastructure of physical and virtual resources. For example, vRack can be configured for [Bare Metal servers](https://support.us.ovhcloud.com/hc/en-us/articles/360001410984) and [Public Cloud](https://support.us.ovhcloud.com/hc/en-us/articles/360002093130).

 

## Requirements

- Access to the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/)
- A [Public Cloud project](https://us.ovhcloud.com/public-cloud/) in your OVHcloud account

 

## Considerations

Here are some considerations to take into account when using a private network:

- Network ports are created in the private network of your choice. Thus, further operations on that network might be restricted - e.g., you won’t be able to delete the network if you didn’t stop the Cloud Databases or Analytics services first.
- When connecting from an outside subnet, the OpenStack IP gateway must be enabled in the subnet used for the service. The customer is responsible for any other custom network setup.
- Subnet sizing should include considerations for service nodes, other co-located services within the same subnet, and an allocation of additional available IP addresses for maintenance purposes. Failure to adequately size subnets could result in operational challenges and the malfunctioning of services.

 

## Instructions

### Step 1 - Creating a virtual network

The first step is to create the virtual network that will be used in your vRack. To proceed, consult this [guide](https://support.us.ovhcloud.com/hc/en-us/articles/360002093130).

 

### Step 2 - Creating a service connected to the private network

Follow this [guide](https://support.us.ovhcloud.com/hc/en-us/articles/20611621210515) to create a new Cloud Database or Analytics service, **while taking note of the information in the boxes below**.

:::info

Choose the plan that best fits your needs. The use of private networking with services is available with all plans.

![manager\_database\_order\_servicePlans.png](/images/public-cloud/databases/databases-analytics-configure-your-private-network/41904158253331.png)

:::

:::info

- Select **Private** from the Network Type list, then choose **your private network**.

- From the Subnetwork list, select the **10.0.0.0/16 - YYY**. *The YYY value is the name of the data center you chose.*

- Then click `Next`.

![manager\_database\_order\_privateNetwork.png](/images/public-cloud/databases/databases-analytics-configure-your-private-network/41904158257043.png)

:::

 

### Step 3 - Configure your instance to accept incoming connections

Follow the *Configure your \[\_\_\_] instance to accept incoming connections* guide of your selected engine type (available [here](https://support.us.ovhcloud.com/hc/en-us/sections/20348597107603-Cloud-Databases)) to configure your service after installation, **while taking note of the information in the boxes below**.

:::info

In the **IPs** panel, authorize the whole private network, as defined in previous steps, and click `+`.

![manager\_database\_configurationTab.png](/images/public-cloud/databases/databases-analytics-configure-your-private-network/41904189164435.png)

:::

The service is now connected to the virtual network, we can use it from any component that is connected to the same vRack.

 

### Step 4 - Adding your service to the vRack

#### Public Cloud instances

Follow this [guide](https://support.us.ovhcloud.com/hc/en-us/articles/360002245164) to create a new Public Cloud Instance, **while taking note of the information in the boxes below**.

:::info

For this step, select **your private network**, then click `Next`.

![DBaaS\_config\_privatenetwork05.png](/images/public-cloud/databases/databases-analytics-configure-your-private-network/24776887566483.png)

:::

:::info

If you want to test the access from an existing instance, read this tutorial to connect it to the vRack: [Configuring vRack for Public Cloud](https://support.us.ovhcloud.com/hc/en-us/articles/360002093130).

:::

 

#### Dedicated servers

You can add your Dedicated server to vRack via the **Network** menu or through your server's **Network Interfaces** tab. See both methods in [this guide](https://support.us.ovhcloud.com/hc/en-us/articles/360001410984#step-2-adding-your-servers-to-the-vrack).

:::
