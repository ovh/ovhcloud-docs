# Valkey - Manage ACLs via API

**Learn how to update your user ACLs with the OVHcloud API.**

 

## Users and roles

As explained on this page: [Valkey Capabilities, Users & roles](/guides/public-cloud/databases/valkey-capabilities-limitations#users-and-roles), the users' ACLs can not be updated via the OVHcloud Control Panel.

You must therefore use the [OVHcloud API](https://api.us.ovhcloud.com/).

 

## Requirements

- A [Public Cloud project](https://us.ovhcloud.com/public-cloud/) in your OVHcloud account.
- An up-and-running Cloud Database for Valkey.

If you have never used the OVHcloud API before, then follow this tutorial: [First Steps with the OVHcloud APIs](/guides/manage-and-operate/api/first-steps).

For this tutorial, we assume that you are logged in to the [OVHcloud API](https://api.us.ovhcloud.com/).

 

## Instructions

### Get your service, Valkey cluster, and user IDs

You first need to identify the service, the Valkey cluster, and the user you want to apply the changes to.

#### Get the desired service ID

Execute the following API call:

<Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project"} regions={["us"]} />

From the resulting list, select and copy the service identifier corresponding to the desired service, also known as **serviceName**.

![Redis ACLs - step 1](/images/public-cloud/databases/valkey-manage-acls-via-api/redis-acls-01.png)

 

#### Get the desired cluster ID

Open the following API call, paste your service ID into the **serviceName** input field and click `Execute`:

<Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/database/redis"} regions={["us"]} />

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/valkey"} regions={["us"]} />

From the resulting list, select and copy the cluster ID, also known as **clusterId**.

![Redis ACLs - step 2](/images/public-cloud/databases/valkey-manage-acls-via-api/redis-acls-02.png)

 

#### Get the desired user ID

Open the following API call and do the following steps:

- paste your service ID into the **serviceName** input field
- paste the cluster ID into the **clusterId** input field
- click `Execute`

<Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/database/redis/\{clusterId\}/user"} regions={["us"]} />

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/valkey/\{clusterId\}/user"} regions={["us"]} />

From the resulting list, find and select the desired **user**.

![Redis ACLs - step 3](/images/public-cloud/databases/valkey-manage-acls-via-api/redis-acls-03.png)

To get more details on a user, open the following API call and do the following steps:

- paste your service ID into the **serviceName** input field
- the user ID into the **userId** input field
- the cluster ID into the **clusterId** input field
- click `Execute`

<Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/database/redis/\{clusterId\}/user/\{userId\}"} regions={["us"]} />

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/valkey/\{clusterId\}/user/\{userId\}"} regions={["us"]} />

Example:

![Redis ACLs - step 4](/images/public-cloud/databases/valkey-manage-acls-via-api/redis-acls-04.png)

The result shows four string arrays, which represent the ACLs defined for the given user.

- Keys: Allow and disallow certain keys and key permissions.
- Categories: Add all the commands in such category to be called by the user, with valid categories being like @admin, @set, @sortedset,...
- Commands: Add or remove the command to the list of commands the user can call.
- Channels: Allow and disallow Pub/Sub channels.

You can follow the [official Redis® documentation](https://redis.io/topics/acl) about users and ACL.

 

### Update an ACL with the API

Open the following API call and paste the corresponding inputs (**serviceName**, **clusterId**, **user**).

<Api version="v1" section="/cloud/project" method="PUT" route={"/cloud/project/\{serviceName\}/database/redis/\{clusterId\}/user/\{userId\}"} regions={["us"]} />

<Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\{serviceName\}/database/valkey/\{clusterId\}/user/\{userId\}"} regions={["us"]} />

Now, according to the strategy you choose, set the different values into the string arrays, such as in the example below:

:::warning

**NOTE:** Running this API call will completely overwrite existing permissions set in the OVHcloud Control Panel.

:::

![Redis ACLs - step 5](/images/public-cloud/databases/valkey-manage-acls-via-api/redis-acls-05.png)

When ready, click `Execute` to update the ACL.

The result should be displayed similarly to the example below.

![Redis ACLs - step 6](/images/public-cloud/databases/valkey-manage-acls-via-api/redis-acls-06.png)
