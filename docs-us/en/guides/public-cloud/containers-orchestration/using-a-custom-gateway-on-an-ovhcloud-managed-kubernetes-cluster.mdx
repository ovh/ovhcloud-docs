# Using a custom gateway on an OVHcloud Managed Kubernetes cluster

In this tutorial, we are going to use a custom gateway deployed in vRack with a Managed Kubernetes cluster.

Why?

By default, in a Kubernetes cluster, the Pods you deploy take the Node's output IP. So we have as many output IPs as Nodes. This can be a problem when you are in a situation where you need to manage a whitelist and you have a cluster with AutoScaling (creating and deleting Nodes on the fly).

One solution is to use a custom gateway, which will allow you to have a single output IP (your gateway).

You will:

- create a private network
- create subnets
- create an OpenStack router (in every region) and link them to the external provider network and the subnets
- create an OVHcloud Managed Kubernetes cluster with the private gateway
- test the Pod's output IP

At the end of this tutorial, you should have the following flow:

![diagram\_kubernetes\_customGateway.png](/images/public-cloud/containers-orchestration/using-a-custom-gateway-on-an-ovhcloud-managed-kubernetes-cluster/46257519012755.png)

:::info

In this tutorial, we guide you on how to create a private network in two regions, but you can use only one region if you want.

:::

 

## Requirements

- A [Public Cloud project](https://support.us.ovhcloud.com/hc/en-us/articles/360002245784) in your OVHcloud account
- The [OpenStack API CLI](https://support.us.ovhcloud.com/hc/en-us/articles/1500009262762) installed
- Being familiar with the [OVHcloud API](https://support.us.ovhcloud.com/hc/en-us/articles/360018130839)
- Being familiar with [Terraform](https://support.us.ovhcloud.com/hc/en-us/articles/15974268257299), if you wish to use it
- The JSON parser tool [jq](https://stedolan.github.io/jq/) installed

 

## Initialization

To set up a functional environment, you have to load the OpenStack and the OVHcloud API credentials. To help you, we also created several useful scripts and templates.

First, create a `utils` folder in your environment/local machine. Then, download the [ovhAPI.sh](https://github.com/ovh/docs/blob/develop/pages/public_cloud/containers_orchestration/managed_kubernetes/vrack-k8s-custom-gateway/utils/ovhAPI.sh) script into it.

And then add execution rights to the `ovhAPI.sh` script:

```bash
chmod +x utils/ovhAPI.sh
```

You have to load the content of the given **utils/openrc** file to manage OpenStack, and variables contained in the **utils/ovhAPI.properties** file to manage the OVHcloud API.

Create the **utils/openrc**, or download it from your OpenStack provider. It must be like:

```bash
export OS_AUTH_URL=https://auth.cloud.ovh.us/v3
export OS_IDENTITY_API_VERSION=3

export OS_REGION_NAME="xxxx"
if [ -z "$OS_REGION_NAME" ]; then unset OS_REGION_NAME; fi
```

Create the **utils/ovhAPI.properties** with your generated keys and secret:

```bash

OVH_ENDPOINT="ovh-us"
```

## Create Private Network

:::info

**Important:** Assuming that your PCI project is added to your [vRack](https://support.us.ovhcloud.com/hc/en-us/articles/360002093130).

:::

We are using the OVHcloud API to create the private network. For this tutorial, we are using the two regions US-EAST-VA-1 and US-WEST-OR-1.

Create a folder `tpl` next to `utils` folder and create inside the **data-pvnw\.json** file with the following content:

```json
{
"name": "demo-pvnw",
"vlanId": 20,
"regions": ["US-EAST-VA-1","US-WEST-OR-1"]
}
```

Create the private network named `demo-pvnw` in `US-EAST-VA-1` and `US-WEST-OR-1` regions and get the VLAN ID.

## Create subnets

For this tutorial, we are splitting a /24 subnet to obtain two /25 subnets.

Ref: https\://www\.davidc.net/sites/default/subnets/subnets.html

| Name     | Region       | CIDR Address     | Gateway       | DHCP Range                  | Broadcast     |
| -------- | ------------ | ---------------- | ------------- | --------------------------- | ------------- |
| Subnet 1 | US-EAST-VA-1 | 192.168.0.0/25   | 192.168.0.1   | 192.168.0.2-192.168.0.126   | 192.168.0.127 |
| Subnet 2 | US-WEST-OR-1 | 192.168.0.128/25 | 192.168.0.129 | 192.168.0.130-192.168.0.254 | 192.168.0.255 |

Create these two data files in the `tpl` folder:

**data-subnetUS-EAST-VA-1.json** file:

```json
{
"start": "192.168.0.2",
"end": "192.168.0.126",
"region": "US-EAST-VA-1",
"dhcp": false,
"network": "192.168.0.0/25",
"noGateway": false
}
```

**data-subnetUS-WEST-OR-1.json** file:

```json
{
"start": "192.168.0.130",
"end": "192.168.0.254",
"region": "US-WEST-OR-1",
"dhcp": false,
"network": "192.168.0.128/25",
"noGateway": false
}
```

:::warning

**NOTE:** To be clear, the parameter `"noGateway": false` means `"Gateway": true`. We want the subnet to explicitly use the first IP address of the CIDR range.

:::

### Link the router to the external provider network

First, get the regional external network ID (extNwUS-EAST-VA-1Id & extNwUS-WEST-OR-1Id), then link the router to it:

```bash
# US-EAST-VA-1
export extNwUS-EAST-VA-1Id="$(openstack --os-region-name=US-EAST-VA-1 network list -f json | jq -r '.[] | select(.Name=="Ext-Net") | .ID')" && echo $extNwUS-EAST-VA-1Id
openstack --os-region-name=US-EAST-VA-1 router set $rtrUS-EAST-VA-1Id --external-gateway $extNwUS-EAST-VA-1Id
# US-WEST-OR-1
export extNwUS-WEST-OR-1Id="$(openstack --os-region-name=US-WEST-OR-1 network list -f json | jq -r '.[] | select(.Name=="Ext-Net") | .ID')" && echo $extNwUS-WEST-OR-1Id
openstack --os-region-name=US-WEST-OR-1 router set $rtrUS-WEST-OR-1Id --external-gateway $extNwUS-WEST-OR-1Id
```

You should have a result like this:


### Link the router to the subnet

Do the same with the regional subnets:

```bash
# US-EAST-VA-1
openstack --os-region-name=US-EAST-VA-1 router add subnet $rtrUS-EAST-VA-1Id $subnUS-EAST-VA-1
# US-WEST-OR-1
openstack --os-region-name=US-WEST-OR-1 router add subnet $rtrUS-WEST-OR-1Id $subnUS-WEST-OR-1
```

 

## Create a Kubernetes cluster with private gateway

Now the network is ready. Create an OVHcloud Managed Kubernetes cluster, specifying the use of the gateway defined on each subnet.

:::warning

**NOTE:** Until the end of this tutorial, we are only using the `US-EAST-VA-1` region, but you can repeat the exact same steps to create a cluster on the `US-WEST-OR-1` region.

:::

:::info

In this guide we defined `1.34` version for the Kubernetes cluster but you can use another supported version.

:::

First, get the private network IDs (pvnwUS-EAST-VA-1Id & pvnwUS-WEST-OR-1Id), then create the OVHcloud Managed Kubernetes Cluster, and finally get the cluster ID (kubeId):

```bash
# Get the US-EAST-VA-1 private network Id
```

### Routers

To delete an OpenStack router, you must first remove the linked ports.

```bash
# Get the routers subnets attached ports Ids
export portIdUS-EAST-VA-1="$(openstack --os-region-name=US-EAST-VA-1 port list | grep -w "192.168.0.1" | awk '{print $2}')" && echo $portIdUS-EAST-VA-1
export portIdUS-WEST-OR-1="$(openstack --os-region-name=US-WEST-OR-1 port list | grep -w "192.168.0.129" | awk '{print $2}')" && echo $portIdUS-WEST-OR-1
# Get the routers Ids
export rtrIdUS-EAST-VA-1="$(openstack --os-region-name=US-EAST-VA-1 router list -f json | jq -r '.[] | select(.Name=="rtr-US-EAST-VA-1") | .ID')" && echo $rtrIdUS-EAST-VA-1
export rtrIdUS-WEST-OR-1="$(openstack --os-region-name=US-WEST-OR-1 router list -f json | jq -r '.[] | select(.Name=="rtr-US-WEST-OR-1") | .ID')" && echo $rtrIdUS-WEST-OR-1
# Remove ports from routers
openstack --os-region-name=US-EAST-VA-1 router remove port $rtrIdUS-EAST-VA-1 $portIdUS-EAST-VA-1
openstack --os-region-name=US-WEST-OR-1 router remove port $rtrIdUS-WEST-OR-1 $portIdUS-WEST-OR-1
# Delete routers
openstack router delete rtr-US-EAST-VA-1
openstack router delete rtr-US-WEST-OR-1
```
