# AI Training - Start a job with a notebook Docker image

**Learn how to start a simple interactive notebook leveraging GPUs over AI Training service.**

 

## Requirements

- Access to the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/)
- An **AI Training project** created inside a **public cloud** project
- A [user for AI Training](https://support.us.ovhcloud.com/hc/en-us/articles/34504142321171)

 

## Instructions

### Step 1 - Begin as a classic job submission

Follow the same steps as a classic job submission described [here](https://support.us.ovhcloud.com/hc/en-us/articles/35104761379219) until you reach [the Docker image step](https://support.us.ovhcloud.com/hc/en-us/articles/35104761379219#docker-image).

 

### Step 2 - Select the notebook corresponding to your needs

A `job` is basically a Docker container that is run within the OVHcloud infrastructure.

Notebooks are `daemon jobs`, meaning they will run indefinitely until the user requests an interruption.

AI Training offers several notebook images with different configurations. You can choose the configuration that best suits your needs.

Currently, the following configurations are available:

- **PyTorch**: An OVHcloud preset image including JupyterLab notebook, Visual Studio Code IDE, and `pytorch` libraries
- **Tensorflow 2**: An OVHcloud preset image containing JupyterLab notebook, Visual Studio Code IDE, and `tensorflow 2` libraries
- **Hugging Face Transformers**: An OVHcloud preset image containing JupyterLab notebook, Visual Studio Code IDEand `hugging face` libraries
- **MXNet**: An OVHcloud preset image containing JupyterLab notebook, Visual Studio Code IDE, and `mxnet` libraries
- **Fast.ai**: An OVHcloud preset image containing JupyterLab notebook, Visual Studio Code IDE, and `fast.ai` libraries
- **auto gluon**: An OVHcloud preset image containing JupyterLab notebook, Visual Studio Code IDE, and `AutoGluon` + `mxnet` libraries

![manager\_aiTraining\_order\_dockerImage.png](/images/public-cloud/ai-machine-learning/ai-training-start-a-job-with-a-notebook-docker-image/42012965913875.png)

 

### Step 3 - Continue as a classic job submission

Continue to follow the same steps as a classic job submission described [here](https://support.us.ovhcloud.com/hc/en-us/articles/35104761379219) until you reach [Step 3 - Consulting your job](https://support.us.ovhcloud.com/hc/en-us/articles/35104761379219#step-3-consulting-your-job).

:::warning

**NOTE:** If you want to be able to save your notebook files on your object storage, we strongly advise that you plug a **read** and **write** volume on your job before submitting. That volume will be synchronized with your object storage at the end of the job.

:::

 

### Step 4 - Access notebook URL

Once your job is `Running`, in the job **Access** panel, you should see the `Container access` link. Click on it, and you will be redirected to your job URL.

![manager\_aiTraining\_dashboard-2.png](/images/public-cloud/ai-machine-learning/ai-training-start-a-job-with-a-notebook-docker-image/42012980943635.png)

 

### Step 5 - Log in as an AI Training user

If you are not authenticated as an AI Training user, you should see a screen asking for your username and password.

:::info

If you have never created a user for AI Training yet, you can follow the instructions [here](https://support.us.ovhcloud.com/hc/en-us/articles/34504142321171).

:::

Fill in the fields and click `Connect`.

![PaaS\_AI\_Training\_startDocker03.png](/images/public-cloud/ai-machine-learning/ai-training-start-a-job-with-a-notebook-docker-image/40110348115859.png)

 

### Step 6 - Use your notebook

In most provided preset images, you can choose which editor you prefer between JupyterLab and VisualStudio code.

![PaaS\_AI\_Training\_startDocker04.png](/images/public-cloud/ai-machine-learning/ai-training-start-a-job-with-a-notebook-docker-image/35374254450067.png)

Select the one that you want to use, and you will be redirected to the corresponding editor.

![PaaS\_AI\_Training\_startDocker05.png](/images/public-cloud/ai-machine-learning/ai-training-start-a-job-with-a-notebook-docker-image/35374238462739.png)

By default, the home directory of your job is located under `/workspace`. It means that you will have **read** and **write** access to that directory as well as your **read** and **write** mounted volumes.

:::warning

**NOTE:** If you are missing a library or a configuration, you can add it directly in the command line of the notebook's **console** as long as you don't need privileged access (root access). Example: `pip install <...>`

For installing specific libraries that require privileged access, you will have to build your own notebook image and use it as a **custom image** at [Step 2](#step-2-select-the-notebook-corresponding-to-your-needs) instead of a **preset image**. More information about creating your own Docker image can be found [here](https://support.us.ovhcloud.com/hc/en-us/articles/36029131111955).

:::

:::info

If you open a **console** tab in your notebook and type `nvidia-smi`, you will see the available GPUs that you can use on your notebook.

![PaaS\_AI\_Training\_startDocker06.png](/images/public-cloud/ai-machine-learning/ai-training-start-a-job-with-a-notebook-docker-image/35374254463251.png)

From the Jupyter Notebook interface, the `!nvidia-smi` command will retrieve the same information.

![PaaS\_AI\_Training\_startDocker06B.png](/images/public-cloud/ai-machine-learning/ai-training-start-a-job-with-a-notebook-docker-image/40519887335059.png)

:::

 

### Step 7 - Stop your notebook

Once you are done working with your notebook, don't forget to stop it.

You can do it by selecting *more options* `...` and then `Stop`.

Then, in the pop-up window, click `Stop`.

![manager\_aiTraining\_serviceList\_moreOptions.png](/images/public-cloud/ai-machine-learning/ai-training-start-a-job-with-a-notebook-docker-image/42012965921555.png)

After some time, your job should go into an `Interrupted` state, meaning that the job has been stopped.

:::info

Before going into the `Interrupted` state, your job may run through the `Finalizing` state. During this phase, all data inside `read & write volumes` are saved inside their linked containers in your object storage.

:::

![manager\_aiTraining\_dashboard\_interrupted.png](/images/public-cloud/ai-machine-learning/ai-training-start-a-job-with-a-notebook-docker-image/42012965924627.png)
