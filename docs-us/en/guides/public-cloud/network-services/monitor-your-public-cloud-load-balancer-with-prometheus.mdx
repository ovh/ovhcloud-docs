# Monitor your Public Cloud Load Balancer with Prometheus

**Learn about the various options available to monitor your Octavia Load Balancer.**

The Public Cloud Load Balancer provides two ways to monitor your Load Balancers: either query an API to retrieve usage statistics or configure a Prometheus listener that your Prometheus infrastructure can scrape to collect metrics.

 

## Requirements

- A [Load Balancer](https://support.us.ovhcloud.com/hc/en-us/articles/18610207964051) created.

#### OVHcloud Control Panel Access

- **Direct link:** [Public Cloud projects](https://manager.us.ovhcloud.com/#/public-cloud/pci/projects)
- **Navigation path:** `Public Cloud` > Select your project

 

## Instructions

### Monitoring using CLI

The Load Balancer service aggregates these statistics and makes them available via the OpenStack API. Those statistics are available at the Load Balancer or listener level.

Load Balancer statistics can be queried using the [OpenStack Client](https://docs.openstack.org/python-openstackclient/latest/). They include metrics for all the listeners configured for the queried Load Balancer.

```
$ openstack loadbalancer stats show <lb id>
+--------------------+-----------+
| Field              | Value     |
+--------------------+-----------+
| active_connections | 0         |
| bytes_in           | 2236722   |
| bytes_out          | 100973832 |
| request_errors     | 0         |
| total_connections  | 3606      |
+--------------------+-----------+
```

Individual listener statistics can also be queried using the [OpenStack Client](https://docs.openstack.org/python-openstackclient/latest/).

```
$ openstack loadbalancer listener stats show <listener id>
+--------------------+-------+
| Field              | Value |
+--------------------+-------+
| active_connections | 0     |
| bytes_in           | 89    |
| bytes_out          | 237   |
| request_errors     | 0     |
| total_connections  | 1     |
+--------------------+-------+
```

 

### Monitoring with Prometheus

To add a Prometheus endpoint on a Public Cloud Load Balancer, create a listener with a `PROMETHEUS` protocol. This will enable the `/metrics` endpoint, which listens on all the interfaces of your Load Balancer by default. **This means that if your Load Balancer is using a Floating IP, by default the&#x20;**`/metrics`**&#x20;endpoint will be opened to the Internet.** To avoid that, we advise setting the `allowed_cidrs` option to protect your metrics, for example with the CIDR of the subnet where the Load Balancer is spawned.

This listener type provides the same features as the "regular" listeners but does not support attaching pools or L7 policies. All metrics will be identified by the Octavia object ID (UUID) of the resources.

:::info

Currently, UDP and SCTP-specific metrics are not reported via Prometheus endpoints.

:::

#### Via the OVHcloud API

You can create the Prometheus listener directly via the OVHcloud API, which lets you set `allowedCidrs` at creation:

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/region/\{regionName\}/loadbalancing/listener"} regions={["us"]} />

In the path parameters, `serviceName` is your Public Cloud project ID and `regionName` is the region of your Load Balancer (for example `US-EAST-VA-1`). In the request body, set `protocol` to `prometheus`, choose a `port`, reference your `loadbalancerId`, and provide `allowedCidrs` with the subnets allowed to reach the metrics endpoint (for example `["192.0.2.0/24"]`).

To change the allowed CIDRs on an existing listener, use the same `allowedCidrs` property on the update endpoint, where `listenerId` is the ID of the existing listener:

<Api version="v1" section="/cloud" method="PUT" route={"/cloud/project/\{serviceName\}/region/\{regionName\}/loadbalancing/listener/\{listenerId\}"} regions={["us"]} />

#### Via Terraform

The resource [openstack\_lb\_listener\_v2](https://registry.terraform.io/providers/terraform-provider-openstack/openstack/latest/docs/resources/lb_listener_v2) from the OpenStack provider enables you to configure a Prometheus listener. The following snippet is extracted from a full example available on [GitHub](https://github.com/yomovh/tf-at-ovhcloud/tree/main/simple_http_lb_with_prom_grafana) that you can adapt to your needs.

```
resource "openstack_lb_listener_v2" "prom_listener" {
 protocol = "PROMETHEUS"
 protocol_port = 9100
 loadbalancer_id = openstack_lb_loadbalancer_v2.tf_lb.id
 #restrict the access of the listener to the private network subnet
 allowed_cidrs = [openstack_networking_subnet_v2.tf_lb_subnet.cidr]
}
```

### Configure Prometheus to collect your metrics

Once the `PROMETHEUS` listener is `ACTIVE`, you can configure Prometheus to collect metrics from the Load Balancer by updating the `prometheus.yml` file.

```
[scrape_configs]
- job_name: 'Octavia LB1'
  static_configs:
  - targets: ['loadbalancer-IP:9100']
```

:::warning

**NOTE:** If your Prometheus server is running within your private network, you can use the virtual IP of the load balancer as the target IP in the `prometheus.yml` file. Otherwise, you must add a public Floating IP to your load balancer and use it as the target IP.

**Example&#x20;**`prometheus.yml`**&#x20;file:**

```
global:
  scrape_interval:     15s # By default, scrape targets every 15 seconds.

  # Attach these labels to any time series or alerts when communicating with
  # external systems (federation, remote storage, Alertmanager).
  external_labels:
    monitor: 'codelab-monitor'

# A scrape configuration containing exactly one endpoint to scrape:
# Here it's Prometheus itself.
scrape_configs:
  # The job name is added as a label `job=<job_name>` to any timeseries scraped from this config.
  - job_name: 'prometheus'
    
    # Override the global default and scrape targets from this job every 5 seconds.
    scrape_interval: 5s 
   
    static_configs:
      - targets: ['localhost:9090']

  - job_name: 'Octavia LB1'
    static_configs:
      - targets: ['10.xxx.xxx.170:9100']
```

:::

For more information on setting up Prometheus, see the [Prometheus project website](https://prometheus.io/).

You can connect [Grafana](https://grafana.com/) to the [Prometheus](https://prometheus.io/) instance to provide additional graphing and dashboard capabilities. A Grafana dashboard for Octavia Load Balancers is available [here](https://grafana.com/grafana/dashboards/15828-octavia-amphora-load-balancer/).
