# Getting started with a dedicated server (Windows and Linux)

**Learn all the information required for your first steps with a dedicated server.**

A dedicated server is a physical server ("bare metal") located in one of our data centers. You are fully responsible for the administration of your dedicated server.

:::warning

**NOTE:** If you intend to use a Windows license and do not already have one, please see our [Purchasing and managing licenses](https://support.us.ovhcloud.com/hc/en-us/articles/360000136970) guide.

:::

 

## Requirements

- Access to the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/)
- A [dedicated server](https://us.ovhcloud.com/bare-metal/) in your OVHcloud account
- Administrative access (root) via SSH or remote desktop (Windows) to your server

:::info

If your server is part of the **Eco** product range (Kimsufi, So You Start, or Rise), use [this guide](https://support.us.ovhcloud.com/hc/en-us/articles/28143494826259) instead.

:::

### Installing or reinstalling your dedicated server

:::tip

Find out more about server operating systems on [our webpage](https://us.ovhcloud.com/bare-metal/os/).

:::

You can easily reinstall your server and choose a different OS image in your [OVHcloud Control Panel](https://us.ovhcloud.com/manager/#/hub).

Navigate to the `Dedicated servers` section via the `Bare Metal Cloud` menu. In the **General information** panel, next to `Operating system (OS)`, click the *more options* `...` button and select `Install my server`.

![dedicated\_generalPanel\_osMoreOptions.png](/images/bare-metal-cloud/dedicated-servers/getting-started-with-a-dedicated-server-windows-and-linux/43776468734739.png)

:::info

Some proprietary operating systems or platforms, such as **Plesk** or **Windows**, require licenses that generate additional fees. You can buy licenses [via OVHcloud](https://us.ovhcloud.com/bare-metal/os/) or from an external reseller. You will then need to apply your license in the operating system itself or by using your [OVHcloud Control Panel](https://us.ovhcloud.com/manager/).

You can manage all your licenses in the `Bare Metal Cloud` section under `Licenses`. In this section, you can also order licenses or add existing ones via the `Actions` button. Learn more about purchasing and managing licenses in [our dedicated guide](https://support.us.ovhcloud.com/hc/en-us/articles/360000136970).

:::

Click `Next` to continue. Then select the operating system from the drop-down menus.

If you need to modify the partitioning scheme of your operating system, check the *Customise the partition configuration* box before clicking on `Next`.

![dedicated\_OSinstall\_step1.png](/images/bare-metal-cloud/dedicated-servers/getting-started-with-a-dedicated-server-windows-and-linux/43776453955859.png)

In this step, you can set up RAID and partitioning options within the limits of the server's hardware and operating system.

![dedicated\_OSinstall\_step3.png](/images/bare-metal-cloud/dedicated-servers/getting-started-with-a-dedicated-server-windows-and-linux/43776453957651.png)

:::warning

**NOTE:** If your server comes with Soft RAID, our system will give priority to installing the operating system using all your disks. With this process, all the disks are automatically mounted during the installation procedure. This also means that you will only have access to storage on one disk, with the other disk(s) being used for data replication, providing redundancy in the event of a disk failure.

:::

If you don't want to use all your disks for the installation, you can update it after checking the *Customise the partition configuration* box. In this case, you will be responsible for mounting the other disks in the operating system. You should refer to the operating system documentation to find out how to do this.

After you have finished your adjustments, click `Next`.

![dedicated\_OSinstall\_step3\_edit.png](/images/bare-metal-cloud/dedicated-servers/getting-started-with-a-dedicated-server-windows-and-linux/43776453959827.png)

On the summary page, you will find additional questions that are specific to the chosen operating system.

If you have selected a compatible operating system, you can provide a public key to be installed automatically. You have two options:

- Manually copy the key string and paste it into the `SSH Public Key` field.
- If you have a [previously stored public key](https://support.us.ovhcloud.com/hc/en-us/articles/38811202776467) in your [OVHcloud Control Panel](https://us.ovhcloud.com/manager/), select the desired key from the `SSH keys` drop-down menu.

To learn more about SSH keys, see the following guides:

- [How to create and use keys for SSH authentication](https://support.us.ovhcloud.com/hc/en-us/articles/115001588250)
- [How to create and use keys for SSH authentication with PuTTY](https://support.us.ovhcloud.com/hc/en-us/articles/41209176606227)

Finally, click `Confirm` to trigger the operating system installation on your dedicated server.

![dedicated\_OSinstall\_step4.png](/images/bare-metal-cloud/dedicated-servers/getting-started-with-a-dedicated-server-windows-and-linux/43776453960467.png)

 

### Logging on to your server

:::warning

**NOTE:** OVHcloud provides services for which you are responsible for their configuration and management. You are therefore responsible for their proper functioning.\
\
This tutorial is designed to help you as much as possible with common tasks. If you are having difficulty performing these actions, please contact a specialized service provider. OVHcloud cannot provide you with technical support in this regard.

:::

:::tip

Click each tab across the top to view all content.

:::

<Tabs>

<Tab label="Linux">

If you have installed an OVHcloud OS template on your server, a user with elevated permissions is created automatically. This user will be named according to the operating system, e.g., "ubuntu" or "rocky".

You will then receive an email containing the information needed to establish a first connection with SSH. SSH is a secure communication protocol, used to establish encrypted connections to a remote host. You can find more detailed information in our guide: [Getting started with SSH](https://support.us.ovhcloud.com/hc/en-us/articles/360000416484).

Most current desktop operating systems will have an **Open SSH** client natively installed. This means that your access credentials allow you to quickly establish a connection to your server in the appropriate command line application (`Terminal`, `Command prompt`, `Powershell`, etc.). Enter the following command:

```bash
ssh username@IPv4
```

**Example:**

```bash
ssh ubuntu@203.0.113.1
```

You can use any third-party application compatible with **Open SSH** as well.

Once connected, you can replace the predefined password for the current user with a better passphrase by using this command:

```bash
passwd
```

On a GNU/Linux distribution, **a password prompt will not display your keyboard inputs**.

Type your current password and press `Enter`. Enter the new passphrase and type it again at the next prompt to confirm it.

```
Changing password for ubuntu.
Current password:
New password: 
Retype new password: 
passwd: password updated successfully
```

:::warning

**Activating the root user account**

It is not necessary to use the "root" user account to get started administrating your server. This account has to be enabled first in the server OS to use it. Moreover, SSH connections with the user "root" are **disabled** by default as a security measure.

Unless stated otherwise, all administrative actions described in our documentation can be accomplished by the default user account, i.e. typing `sudo` followed by the respective command. Learn more about this topic in our [How to configure user accounts and root access on a server](https://support.us.ovhcloud.com/hc/en-us/articles/43778050006419) guide.

:::

Depending on your requirements for security, mobility, and convenience, SSH keys can serve as an additional connection method or replace logins with username and password. Find out how to use them in our guides:

- [How to create and use keys for SSH authentication](https://support.us.ovhcloud.com/hc/en-us/articles/115001588250)
- [How to create and use keys for SSH authentication with PuTTY](https://support.us.ovhcloud.com/hc/en-us/articles/41209176606227)

</Tab>

<Tab label="Windows">

Once the installation is completed, you will receive an email with your Windows login credentials. You can then connect to your server via RDP (**R**emote **D**esktop **P**rotocol). On your local Windows device, open the `Remote Desktop Connection` client application.

![windows\_rdp\_connect.png](/images/bare-metal-cloud/dedicated-servers/getting-started-with-a-dedicated-server-windows-and-linux/43776453961747.png)

Enter the IPv4 address of your server, then your username and passphrase. Usually, a warning message will appear, asking to confirm the connection because of an unknown certificate. Click on `Yes` to log in.

You can also use any third-party application compatible with RDP. This is a requirement if your local device does not have Windows installed.

:::info

If you experience any issues with this procedure, verify that remote (RDP) connections are allowed on your local device by checking your system settings, firewall rules, and possible network restrictions.

:::

As a fallback option, you can use the [IPMI console in your OVHcloud Control Panel](#access-using-ipmi) to connect.

<details>
<summary>Enabling Windows boot logs (optional)</summary>

Windows boot logs can be helpful for server error diagnostics.

To activate them, follow the steps below:

1. Connect to your server via RDP or [IPMI](#access-using-ipmi).

2) Open the Windows start menu and click on `Run`.

   ![windows\_runUtility.png](/images/bare-metal-cloud/dedicated-servers/getting-started-with-a-dedicated-server-windows-and-linux/43776468755731.png)

3. Enter "msconfig" and click on `OK`.

   ![windows\_runUtility\_msconfig.png](/images/bare-metal-cloud/dedicated-servers/getting-started-with-a-dedicated-server-windows-and-linux/43776453962899.png)

4) In the new window, activate the logs option next to `Boot log`. Click on `OK`.

   ![windows\_runUtility\_activateLogs.png](/images/bare-metal-cloud/dedicated-servers/getting-started-with-a-dedicated-server-windows-and-linux/43776468758675.png)

</details>

The next time your server boots, logs will be saved into a `.txt` file. The file path is: `C:\Windows\ntbtlog.txt`.

To access the log file in rescue mode, please follow the instructions in the [rescue mode guide](https://support.us.ovhcloud.com/hc/en-us/articles/115001754490).

</Tab>

</Tabs>

 

### Restarting your dedicated server

A reboot might become necessary to apply updated configurations or to fix an issue.

<Tabs>

<Tab label="Via the OVHcloud Control Panel">

You can carry out a "hard reboot" at any time in your [OVHcloud Control Panel](https://us.ovhcloud.com/manager/). From the `General information` tab, click on the *more options* `...` button next to "Status" in the **Service status** box, then click `Restart` and `Confirm` the action in the pop-up window.

![manager\_dedicated\_serviceStatus\_moreOptions.png](/images/bare-metal-cloud/dedicated-servers/getting-started-with-a-dedicated-server-windows-and-linux/41383289760147.png)

</Tab>

<Tab label="Via CLI">

Whenever feasible, perform a "soft reboot" via the command line:

```
reboot
```

</Tab>

<Tab label="Via the OVHcloud API">

List the ID for your server's boot options:

<Api version="v1" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/boot"} regions={["us"]} />

Find details for a boot ID:

<Api version="v1" section="/dedicated/server" method="GET" route={"/dedicated/server/\{serviceName\}/boot/\{bootId\}"} regions={["us"]} />

Specify the boot ID in the Request Body.

### OVHcloud Monitoring

You can set the monitoring status for a dedicated server from the `General information` tab in your [OVHcloud Control Panel](https://us.ovhcloud.com/manager/#/hub) (section **Service status**) by clicking the `Configure` button.

![dedicatedservers10.png](/images/bare-metal-cloud/dedicated-servers/getting-started-with-a-dedicated-server-windows-and-linux/19689722324115.png)

In the pop-up window, you have three options for monitoring behavior:

- **Disabled**: This option stops alert messages and interventions by OVHcloud. Choose this if you are executing pertinent administrative actions on the server that prevents an ICMP response.
- **Enabled with proactive intervention**: If the server stops responding, an alert email is sent to you, and the server will be checked by a technician.
- **Enabled without proactive intervention**: You will receive an alert message by email in case the server stops responding. To initiate an intervention, you will need to create a support request.

![dedicatedservers11.png](/images/bare-metal-cloud/dedicated-servers/getting-started-with-a-dedicated-server-windows-and-linux/19689730726931.png)

Click on `Confirm` to update your monitoring configuration.

You can find more information about OVHcloud Monitoring in [this guide](https://support.us.ovhcloud.com/hc/en-us/articles/115001821044).

 

### Network configuration

#### Network bridging

Network bridging is the action taken by network equipment to create an aggregate network from either two or more communication networks, or two or more network segments. Bridging is distinct from routing, which allows the networks to communicate independently while remaining separate.

The Network Bridge configuration is most commonly used in the context of virtualization, to allow each Virtual Machine to have its own public IP address.

For more information on network bridging, see our [Configuring a Network Bridge](https://support.us.ovhcloud.com/hc/en-us/articles/19833829144083) guide.

 

#### IP aliasing

IP aliasing is the process of associating two or more IP addresses to the same network interface. This allows your server to establish multiple connections to a network, each serving a different purpose.

For detailed instructions on how to configure IP aliasing, please refer to [this guide](https://support.us.ovhcloud.com/hc/en-us/articles/7154925809683).

 

#### IPv6 configuration

All OVHcloud dedicated servers are delivered with a /64 IPv6 block. To use the addresses in this block, you will need to make some network configuration changes. Please refer to our guide: [IPv6 Configuration](https://support.us.ovhcloud.com/hc/en-us/articles/4412804434195).

 

### Rescue mode

For any kind of issue, the first general troubleshooting step to take is rebooting your server into rescue mode from your [OVHcloud Control Panel](https://us.ovhcloud.com/manager/#/hub). It is important to identify server issues in this mode to exclude software-related problems before contacting our support teams.

Please refer to the [rescue mode guide](https://support.us.ovhcloud.com/hc/en-us/articles/115001754490).

 

### Access using IPMI

OVHcloud deploys all dedicated servers with an IPMI (Intelligent Platform Management Interface) console, which runs in your browser or from a Java applet and enables you to connect directly to your server even if it has no network connection. This makes it a useful tool for troubleshooting issues that may have taken your server offline.

For more information, please refer to our guide: [Using the IPMI with dedicated servers](https://support.us.ovhcloud.com/hc/en-us/articles/360007816120).
