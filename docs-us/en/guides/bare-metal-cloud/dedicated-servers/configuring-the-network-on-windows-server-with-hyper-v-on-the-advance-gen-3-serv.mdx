# Configuring the Network on Windows Server with Hyper-V on the ADVANCE Gen 3 Servers

**Learn how to configure the network in Windows Server with Hyper-V.**

ADVANCE Gen 3 servers can be configured via vRack (through the use of Additional IPs) or via virtual MACs. If you plan on using virtual MAC addresses, please follow [this guide](https://support.us.ovhcloud.com/hc/en-us/articles/19833829144083).

 

## Requirements

- an [OVHcloud dedicated server](https://us.ovhcloud.com/bare-metal/)
- access to the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/)
- a public block of IP addresses in your account, with a minimum of four addresses, attached to the vRack

:::warning

**NOTE:** No virtual MACs should be applied to additional IPs in the OVHcloud Control Panel.

:::

:::warning

**NOTE:** The limit on public bandwidth capacity in every location is set to 5Gbps (egress, per region, per vRack network).

:::

## Instructions

### Step 1: Add the server and Additional IP to a vRack

You can add your server and Additional IP block to a vRack using the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/). Use the following links to see how:

- [Configuring the vRack on Your Dedicated Servers](https://support.us.ovhcloud.com/hc/en-us/articles/360001410984#step-2)
- [Configuring an Additional IP Block on a vRack](https://support.us.ovhcloud.com/hc/en-us/articles/4403594838803#add-the-ip-block-to-the-vrack)

 

### Step 2: Installing the Hyper-V and RRAS roles

Go to the Server Manager and open the `Dashboard`, then click on `Add roles and features`.

![hypervscale7.png](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-windows-server-with-hyper-v-on-the-advance-gen-3-serv/30943622261267.png)

Go through the Wizard until you reach the `Server Roles` section and select `Hyper-V` and `Remote Access`.

![hypervscale8.png](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-windows-server-with-hyper-v-on-the-advance-gen-3-serv/30943580722835.png)

Next, proceed to the `Virtual Switches` subsection of `Hyper-V` and select the adapter of the private interface of the server.

:::info

You can find this adapter by opening up cmd and using the `ipconfig` command. The result you need should have a 169.x... address or will not be tied to the server's public IP.

![DS\_network\_hyperVadvanced01\*\*.jpeg](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-windows-server-with-hyper-v-on-the-advance-gen-3-serv/31040991136147.jpg)

:::

![DS\_network\_hyperVadvanced02\*\*.PNG](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-windows-server-with-hyper-v-on-the-advance-gen-3-serv/31040996492051.png)

Next, proceed to the `Role Services` subsection of `Remote Access` and select `Routing`.

![hypervscale10.png](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-windows-server-with-hyper-v-on-the-advance-gen-3-serv/30943622277651.png)

Finally, proceed to the `Confirmation` section, select `Restart the destination server automatically if required`, and click `Install`.

 

### Step 3: Create the virtual switch in Hyper-V Manager

We will need to create a virtual switch for the VMs.

First, open the Hyper-V Manager and click on `Virtual Switch Manager`.

![hypervscale22.png](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-windows-server-with-hyper-v-on-the-advance-gen-3-serv/33298525046675.png)

On this page, make sure you have `External` selected and click `Create Virtual Switch`.

![hypervscale23.png](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-windows-server-with-hyper-v-on-the-advance-gen-3-serv/33298509815315.png)

Now, give your switch a name, choose your network adapter, then click `Apply` and then `OK`.

![hypervscale24.png](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-windows-server-with-hyper-v-on-the-advance-gen-3-serv/33298525055251.png)

You are now ready to create your VM and configure its network.

 

### Step 4: Configure your VM

Once you create your VM, go to the settings, select `Network Adapter` from the left-hand menu, and click `Advanced Features`.

Set the MAC address to **Static** and enter the MAC address of the virtual switch.

![DS\_confignetwork\_windows\_hyper-v\_scale-hg05.png](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-windows-server-with-hyper-v-on-the-advance-gen-3-serv/30981704639763.png)

Set the Static IP address inside your VM to the Additional IP address.

![DS\_confignetwork\_windows\_hyper-v\_scale-hg06\*.png](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-windows-server-with-hyper-v-on-the-advance-gen-3-serv/30981720850963.png)

Your VM should now have internet access.

![DS\_confignetwork\_windows\_hyper-v\_scale-hg07.png](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-windows-server-with-hyper-v-on-the-advance-gen-3-serv/30981738223891.png)

 

#### Configure a usable IP address

For vRack, the first, penultimate, and last addresses in a given IP block are always reserved for the network address, network gateway, and network *broadcast* respectively. This means that the first usable address is the second address in the block, as shown below:

```
51.81.3.240 # Reserved: network address
51.81.3.241 # First usable IP
51.81.3.242
51.81.3.243
51.81.3.244
51.81.3.245 # Last usable IP
51.81.3.246 # Reserved: network/default gateway
51.81.3.247 # Reserved: network broadcast
```

To configure the first usable IP address, you must edit the network configuration file as shown below. In this example, we use a subnet mask of **255.255.255.248**.

:::info

The subnet mask used in this example is appropriate for our IP block. Your subnet mask may differ depending on the size of your block. When you purchase your IP block, you will receive an email notifying you of the subnet mask to use.

:::

 

#### Windows-19 VM network configuration

In this example, enter one of the usable IP addresses in your block as the **IP address** and the second to last IP in your block as the **Default gateway**.

![DS\_confignetwork\_windows\_hyper-v\_scale-hg04.png](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-windows-server-with-hyper-v-on-the-advance-gen-3-serv/31041436482067.png)

 

#### Configuration example of a client VM on Ubuntu

Create a `vrack.yaml` file under `/etc/netplan/vrack.yaml`.

Content of the file `/etc/netplan/vrack.yaml`:

```
network:
        version: 2
        ethernets:
                eth0:
                        dhcp4: no
                        addresses:
                                - 192.xxx.xxx.16/32
                        nameservers:
                                addresses:
                                        - 213.186.33.99
                                        - 8.8.8.8
                        routes:
                                - to: 0.0.0.0/0
                                  via: 100.64.0.1
                                  on-link: true
```

For the netplan configuration changes to take effect, you must reboot the VM or run this command:

```
sudo netplan apply
```
