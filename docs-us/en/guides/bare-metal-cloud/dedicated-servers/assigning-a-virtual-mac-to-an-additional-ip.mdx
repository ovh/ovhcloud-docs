# Assigning a Virtual MAC to an Additional IP

**Learn how to create a virtual MAC address and assign it to an Additional IP address.**

OVHcloud allows you to associate a virtual MAC address with an IP address, so that you can set up virtual machines with a bridge configuration on your server.

:::warning

**NOTES:**

- This feature might be unavailable or limited on servers of the [Eco product line](https://eco.us.ovhcloud.com/about-us/). Please visit our [comparison page](https://eco.us.ovhcloud.com/compare/) for more information.
- ADVANCE Gen 3 servers (powered by EPYC 4004) support 32 vMACs per server.
- As of May 2025, this feature is available on the Scale and High Grade ranges. These ranges are also limited to 32 vMACs per server.

:::

 

## Requirements

- A [dedicated server](https://us.ovhcloud.com/bare-metal/) that supports [virtual MACs](https://support.us.ovhcloud.com/hc/en-us/articles/19676027960851)
- An [Additional IP address](https://us.ovhcloud.com/network/additional-ip/) or an Additional IP block (RIPE)
- Access to your [OVHcloud Control Panel](https://us.ovhcloud.com/manager/) or [OVHcloud API](https://api.us.ovhcloud.com/)
- Your server must support virtual MACs (to determine this, consult [this guide](https://support.us.ovhcloud.com/hc/en-us/articles/19676027960851))

:::info

If you are not familiar with the OVHcloud API, please refer to our [First Steps with the OVHcloud API](https://support.us.ovhcloud.com/hc/en-us/articles/360018130839) guide.

:::

 

## Instructions

:::warning

**NOTE:** If an IP block has been moved to the vRack, it is no longer assigned to a physical server. This means you cannot assign a virtual MAC address to any IP.

:::

### Assign a MAC address

#### Via the OVHcloud Control Panel

From the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/), select `Bare Metal Cloud` from the top navigation bar. In the left-hand menu, click `Network` and then `IP`.

Use the filter functions beneath **My public addresses and associated services** to limit your results to Additional IPs.

To the right of your Additional IP address (or block), click the *more options* `...` button and choose `Add a virtual MAC`.

![DS\_ntwk\_assignVMAC01\*\*.png](/images/bare-metal-cloud/dedicated-servers/assigning-a-virtual-mac-to-an-additional-ip/36369473428371.png)

In the pop-up window, select a **Type** from the dropdown list, enter the **Name of virtual machine**, and then click `Confirm`.

:::info

**Type:** Refers to the virtual MAC address type ('vmware' will be a MAC address made for the VMware ESXi system, while ‘ovh’ will be for any other type of virtualization system).

**Name of virtual machine:** Refers to the desired name for the virtual MAC address, in order to make it easy to identify this IP/MAC pair in the future.

:::

![DS\_ntwk\_assignVMAC02\*.png](/images/bare-metal-cloud/dedicated-servers/assigning-a-virtual-mac-to-an-additional-ip/36369450722579.png)

:::info

Do not forget to assign the virtual MAC address created in your virtual machine configuration.

:::

 

#### Via the OVHcloud API

Use the following API call:

<Api version="v1" section="/dedicated/server" method="POST" route={"/dedicated/server/\{serviceName\}/virtualMac/\{macAddress\}/virtualAddress/\{ipAddress\}"} regions={["us"]} />

 

### Delete a MAC address

:::warning

**NOTE:** When a MAC address is deleted, it will not be recoverable.

:::

#### Via the OVHcloud Control Panel

To remove a virtual MAC address associated with an additional IP, you must first connect to your [OVHcloud Control Panel](https://us.ovhcloud.com/manager/). Once connected, go to the `Bare Metal Cloud` section and open the `IP` menu. Select the correct server so that the additional IP (or IP block) attached to it appears.

Finally, click on the *more options* `...` button on the right, then click `Delete a Virtual MAC`.

![DS\_ntwk\_assignVMAC03\*.png](/images/bare-metal-cloud/dedicated-servers/assigning-a-virtual-mac-to-an-additional-ip/36369473446931.png)

In the pop-up window, click `Confirm`.

 

#### Via the OVHcloud API

Use the following API call:

<Api version="v1" section="/dedicated/server" method="DELETE" route={"/dedicated/server/\{serviceName\}/virtualMac/\{macAddress\}/virtualAddress/\{ipAddress\}"} regions={["us"]} />

 

### FAQ

*What happens if I move a block with vMACs on a 3rd generation Advance server (powered by an EPYC 4004 Series processor) that already has 32 vMACs?*

The block will not be moved. For example, if you try to move a block of four IPs with different vMACs attached on a server that already has 30 vMACs, the block will not be moved because the total vMACs would be greater than the 32 vMACs allowed.
