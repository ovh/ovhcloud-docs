# Configuring the network on Proxmox VE on the High Grade, Scale, and Advance ranges

**Learn two ways to configure an Additional IP on Proxmox VE: via the public interfaces and via the private interfaces (vRack).**

:::info

The sections related to Advance range servers only apply to third-generation Advance servers powered by EPYC 4004 Series processors.

Older Advance generation servers do not rely on the same network infrastructure.

:::

:::info

This article is about Additional IPv4 configuration on a public interface. You can also configure IPv6 addresses on your virtual machines using [this guide](https://support.us.ovhcloud.com/hc/en-us/articles/43393102564371).

Please note that Additional IP addresses can also be configured in a vRack (private network), which allows interconnection over a wide range of OVHcloud services, offering more flexibility.

Learn how to configure Additional IP addresses in a vRack without guides for [IPv4](https://support.us.ovhcloud.com/hc/en-us/articles/4403594838803) and [IPv6](https://support.us.ovhcloud.com/hc/en-us/articles/31163475160211).

:::

:::warning

**NOTE:** As of May 2025, virtual MACs can be used on High Grade & Scale ranges.

If you want to use virtual MACs to configure the network on Proxmox VE on High Grade and Scale servers, you can refer to [Configuring Additional IPs in bridge mode on your virtual machines](https://support.us.ovhcloud.com/hc/en-us/articles/19833829144083).

:::

 

## Instructions

### Choose your method

Click one of the methods below to jump to instructions for carrying it out.

[**Additional IP in routed mode on public network interfaces**](#method-1-additional-ip-in-routed-mode-on-public-network-interfaces)**:** With this configuration, Additional IP addresses must be attached to a dedicated server. Suppose you have multiple Proxmox virtualization servers and you want to migrate a VM from one server to another. In that case, you must also migrate the Additional IP address to the destination server via the OVHcloud Control Panel or the OVHcloud API. You can automate this step by writing a script that uses the OVHcloud APIs.

[**Additional IP via the vRack**](#method-2-additional-ip-via-the-vrack)**:** This configuration is more flexible as you do not need to associate an Additional IP with a server but with a vRack. This means that if you have multiple Proxmox virtualization servers, and you want to migrate a VM from one server to another, you do not need to perform any action on OVHcloud APIs. The only requirement is for all servers to be connected to the same vRack.

<summary>Determine assignable IP addresses</summary>

In IP blocks purchased from OVHcloud, the first, penultimate, and last addresses of a given IP block are always reserved for the network address, network gateway, and network broadcast, respectively. This means that the first assignable address is the second address in the block, as shown in the example below for the `46.105.135.96/28` block:

```
46.105.135.96   # Reserved: network address
46.105.135.97   # First assignable IP
46.105.135.98
46.105.135.99
46.105.135.100
46.105.135.101
46.105.135.102
46.105.135.103
46.105.135.104
46.105.135.105
46.105.135.106
46.105.135.107
46.105.135.108
46.105.135.109   # Last assignable IP
46.105.135.110   # Reserved: network gateway
46.105.135.111   # Reserved: network broadcast
```

:::info

The subnet mask used in this example is appropriate for our block of Additional IPs. Your subnet mask may differ depending on the size of your block. When you purchase your IP block, you will receive an email with the subnet mask to use.

:::

### Method 1: Additional IP in routed mode on public network interfaces

With this configuration, Additional IP addresses must be attached to a dedicated server. If you have multiple Proxmox virtualization servers and you want to migrate a VM from one server to another, you will also need to migrate the Additional IP address to the destination server, via the OVHcloud Control Panel or the OVHcloud API. You can automate this step by writing a script that uses the OVHcloud APIs.

#### Requirements:

- An [OVHcloud dedicated server](https://us.ovhcloud.com/bare-metal/)
- One or more [Additional IP addresses](https://us.ovhcloud.com/network/additional-ip/)
- Access to the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/)

:::warning

**NOTE:** No virtual MAC address must be applied to Additional IPs in the OVHcloud Control Panel.

:::

#### Explanations

Proxmox is a Debian-based distribution that relies on `ifupdown2` for network configuration. In this guide, the network configuration will be modified via SSH and not via the web interface.

We will:

- connect via SSH on Proxmox
- create a bond interface (only for the High Grade & Scale ranges)
- create a bridge interface connected to the bond
- allow packet forwarding between interfaces
- add routes to the additional IPs

:::tip

Click each step to expand the full instructions.

:::

<details>
<summary>Step 1: Log in to the Proxmox server via SSH</summary>

Log in to the Proxmox server via SSH:

```bash
ssh PUB_IP_DEDICATED_SERVER
```

</details>

<details>
<summary>Step 2: Allow packet forwarding</summary>

Enable the `ip_forward` sysctl parameter. To do this, we recommend modifying the `sysctl.conf` configuration file.

Add the following line to `/etc/sysctl.conf`:

```
# Enable ip_forward
net.ipv4.ip_forward = 1
```

Next, reload the sysctl configuration:

```bash
sysctl -p
```

</details>

<details>
<summary>Step 3: Configure the network interfaces</summary>

<Tabs>

<Tab label="High Grade & Scale ranges">

```bash
vi /etc/network/interfaces
```

```
auto lo
iface lo inet loopback

# Public interfaces
auto bond0
iface bond0 inet manual
        bond-slaves ens33f0 ens35f1
        bond-mode 802.3ad
        bond-lacp-rate fast
        bond-xmit-hash-policy layer3+4

auto vmbr0
iface vmbr0 inet static
        address PUB_IP_DEDICATED_SERVER/32
        gateway 100.64.0.1
        # Define a private network used to communicate with the VMs,
        # it must not overlap with other private networks configured on the server
        address 192.168.0.1/24
        bridge-ports bond0
        bridge-stp off
        bridge-fd 0
        # Add a single Additional IP
        up ip route add ADDITIONAL_IP/32 dev $IFACE
        # Add an IP block
        up ip route add ADDITIONAL_IP_BLOCK/28 dev $IFACE

# Private interfaces
auto bond1
iface bond1 inet manual
        bond-slaves ens35f0 ens33f1
        bond-mode 802.3ad
        bond-lacp-rate fast
        bond-xmit-hash-policy layer3+4

auto vmbr1
iface vmbr1 inet manual
        bridge-ports bond1
        bridge-stp off
        bridge-fd 0
```

</Tab>

<Tab label="Advance Gen 3 range">

```bash
vi /etc/network/interfaces
```

```
auto lo
iface lo inet loopback

# Public interface
auto vmbr0
iface vmbr0 inet static
        address PUB_IP_DEDICATED_SERVER/32
        gateway 100.64.0.1
        # Define a private network used to communicate with the VMs,
        # it must not overlap with other private networks configured on the server
        address 192.168.0.1/24
        bridge-ports enp8s0f0np0
        bridge-stp off
        bridge-fd 0
        # Add a single Additional IP
        up ip route add ADDITIONAL_IP/32 dev $IFACE
        # Add an IP block
        up ip route add ADDITIONAL_IP_BLOCK/28 dev $IFACE

# Private interface
auto vmbr1
iface vmbr1 inet manual
        bridge-ports enp8s0f1np1
        bridge-stp off
        bridge-fd 0
```

</Tab>

</Tabs>

At this point, restart the network services:

```bash
systemctl restart networking.service
```

:::info

When the networking service is restarted, VMs are not added back to the bridge. This is because Proxmox disconnects each VM from the bridges and does not reconnect them. To force the VMs to reconnect to the bridges, you can restart the VMs.

:::

 

##### **Client VM configuration example**

The VM must be attached to the `vmbr0` bridge.

<Tabs>

<Tab label="Debian (ifupdown)">

Contents of the `/etc/network/interfaces` file:

```
auto lo
iface lo inet loopback

auto eth0

iface eth0 inet static
        address 192.168.0.2/24

iface eth0 inet static
        address ADDITIONAL_IP/32
        # The "src" option must be set so that packets reaching the Internet
        # have the public IP as source, instead of the private IP 192.168.0.2
        up ip route replace default via 192.168.0.1 dev $IFACE onlink src ADDITIONAL_IP
```

</Tab>

<Tab label="Ubuntu (netplan)">

Contents of the `/etc/netplan/01-netcfg.yaml` file:

```yaml
network:
  version: 2
  ethernets:
    eth0:
      addresses:
        - 192.168.0.3/24
        - ADDITIONAL_IP/32
      routes:
        - to: default
          via: 192.168.0.1
          # So that packets reaching the Internet have the public IP as source,
          # instead of the private IP 192.168.0.3
          from: ADDITIONAL_IP
```

</Tab>

</Tabs>

</details>

<details>
<summary>Step 4: Testing and validation</summary>

From now on, your virtual machines should be able to access the Internet from the additional IPs. They should also be reachable directly from the Internet using their additional IPs. The available bandwidth corresponds to the bandwidth available on your server's public interfaces and will not affect the private interfaces used for the vRack. This public bandwidth is shared with other virtual machines on the same host, as well as the Proxmox host itself.

To check your public IP, from the VM:

```bash
curl ifconfig.io
ADDITIONAL_IP # must return your additional ip
```

</details>

:::info

You need to restart the VM's network services for the configuration to take effect.

:::

 

### Method 2: Additional IP via the vRack

This configuration is more flexible as you do not need to associate an Additional IP with a server, but with a vRack. This means that if you have multiple Proxmox virtualization servers and you want to migrate a VM from one server to another, you do not need to perform any action on OVHcloud APIs. The only requirement is for all servers to be connected to the same vRack.

:::warning

**NOTE:** This configuration only works with a block of additional IPs. It is not possible to use a single Additional IP (/32) directly in the vRack. To use an Additional IP, it must be [configured on a public interface](#target-configuration-schema-1) and cannot be directly integrated into the vRack.

:::

 

#### Requirements

- A [server compatible with vRack](https://us.ovhcloud.com/bare-metal/)
- A [vRack service](https://us.ovhcloud.com/network/vrack/)
- A block of Additional IPs
- Access to the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/)

<details>
<summary>Step 2 - Option B: Configure the network interfaces (Proxmox interface)</summary>

You can also complete the configuration shown in Step 2 - Option A from the Proxmox web interface.

First, you need to create a Linux Bond (`bond0` or `bond1`).

1. Click `Datacenter`, `<Your Node>`, `System`, and then `Network`.

2) Choose `Create` and select `Linux Bond`.

   ![node\_createBond.png](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-proxmox-ve-on-the-high-grade-scale-and-advance-ranges/43577602466067.png)

3. Select the slave interfaces (e.g., `ens3f1np1`).

4) Choose the bonding mode (e.g., `802.3ad`).

5. Choose the hash policy (e.g., `layer3+4`).

6) Enter the Name `bond0` (or `bond1` if you are creating multiple bonds).

   ![createBond.png](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-proxmox-ve-on-the-high-grade-scale-and-advance-ranges/43577587226131.png)

Next, you need to create a Bridge (`vmbr0`) to link to the bond.

1. Click `Create` and select `Linux Bridge`.

2. Set the Bridge Port to the bond you created (e.g., `bond0`).

3. Set the IP address, gateway, and netmask according to your configuration.

4. Enter the Name for the bridge (e.g., `vmbr0`).

   :::warning

   **NOTE:** While creating the bridge, make sure `VLAN aware` is marked.

   :::

   ![editBridge.png](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-proxmox-ve-on-the-high-grade-scale-and-advance-ranges/43577602471315.png)

Then, edit the `Linux Bond` to add the external interfaces.

![editBond.png](/images/bare-metal-cloud/dedicated-servers/configuring-the-network-on-proxmox-ve-on-the-high-grade-scale-and-advance-ranges/43577602472467.png)

The same steps are used to associate a bond with internal interfaces.

Finally, apply this new configuration.

1. Once the bond(s) and bridge(s) are created, click `Apply Configuration` in the top right corner. This saves the changes and mimics the effect of restarting the network with the `systemctl restart networking` command on the OS side.
2. Proxmox may prompt you to reboot or confirm the changes; follow the prompt carefully to avoid disconnecting.
