# How to reset the administrator password on a Windows server

**Learn how to reset your Administrator account password with the Windows customer rescue system.**

 

## Requirements

- Microsoft Windows installed on your [dedicated server](https://us.ovhcloud.com/bare-metal/)
- At least 16 GB of RAM installed on the server
- Access to the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/)

:::warning

**NOTE:** This guide is not applicable to the legacy Windows rescue system (WinPE rescue mode); see our [rescue mode guide](https://support.us.ovhcloud.com/hc/en-us/articles/115001754490) for more information.

If your Windows Server version is out of support, you might no the able to activate the current rescue system for Windows. In this case, you can use an alternative method for resetting the administrator password using the [OVHcloud customer rescue system based on Debian](#resetting-the-admin-password-using-ovhcloud-rescue-mode).

:::

## Instructions

### Resetting the admin password using the OVHcloud Windows Customer Rescue System

- Step 1: Reboot the server into rescue mode
- Step 2: Clear the current password
- Step 3: Reboot the server

<Tabs>

<Tab label="Step 1">

#### Step 1: Reboot the server into rescue mode

The system has to be started in the **Windows customer rescue system** before the admin password can be changed.

For detailed instructions, please refer to the [Windows rescue mode guide](https://support.us.ovhcloud.com/hc/en-us/articles/43742214886419).

</Tab>

<Tab label="Step 2">

#### Step 2: Clear the current password

Connect to your server in Remote Desktop using the credentials provided by email.

Please note that the username for the rescue mode is `Administrator`.

- If your server uses software RAID on your Windows disk, you have to import your Windows local disk to be able to access it: Follow the instructions in [section A](#a-importing-your-local-windows-disk) below.
- If your server does not use software RAID on your Windows disk, you should be able to directly access the local Windows disk as explained in [section B](#b-reset-the-password) of this guide.

<details>
<summary>A - Importing your local Windows disk</summary>

**Access disk management**

Right-click the `Start` menu and select `Disk Management`.

![DS\_serverMan\_customerRescueMode01.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/30905996564883.png)

You can then see the disks and volumes of the server.

![DS\_serverMan\_customerRescueMode02.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/30905954327187.png)

Your server's Windows disk is probably *Disk 1*. You must import it to be able to access it.

Please note that if you have several disk groups, the number of the Windows disk may vary. You may have to import several disks to get the Windows one.

You also have to import the second disk to properly import your software RAID volume.

 

**Import local disks**

Right-click *Disk 1* and select `Online`.

![DS\_serverMan\_customerRescueMode03.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/30905996570771.png)

Do the same thing for the second disk (*Disk 2*) to properly import your software RAID volume.

Right-click *Disk 2* and select `Online`.

![DS\_serverMan\_customerRescueMode04.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/30905954335891.png)

Disks are now seen as "Dynamic" and "Foreign".

Right-click *Disk 1* again and select `Import Foreign Disks`.

![DS\_serverMan\_customerRescueMode05.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/30905996577299.png)

Click `OK` twice.

![DS\_serverMan\_customerRescueMode06a.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/30905954339987.png)

![DS\_serverMan\_customerRescueMode06b.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/30905954349203.png)

You can see that the local disk is now accessible and that the Windows disk is drive `(E:)` (spreading on two software RAID disks with Mirrored volume type).

![DS\_serverMan\_customerRescueMode07.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/30905954354835.png)

:::info

In this example, the volume status is "Resynching" because the server was hard-rebooted into rescue mode. This is an expected status and it is not caused by the rescue mode itself.

This will not affect data on the volume and resynchronization will continue once the server is rebooted on its installed OS.

:::

:::warning

**NOTE:** You must then use the path of your local Windows directory (here it is `E:\Windows`) when browsing to find the "SAM" configuration file below.

:::

You can now reset the password by following the instructions below.

</details>

<details>
<summary>B - Reset the password</summary>

To reset passwords, the tool NTPWEdit is required.

Once you are connected via Remote Desktop, open the browser and download it from its [official website](http://cdslow.org.ru/en/ntpwedit/).

Navigate to the folder where the downloaded ZIP file is located and extract its content.

Next, open the `ntpwedit64` executable to start the application.

In this interface, you can manipulate the SAM file to clear the admin user's password.

You must browse the local Windows drive to find your system's SAM file.

Click the *more options* button (`...`) to browse the drive containing your server's local Windows folder.

It usually is the `Windows (E:\)` drive.

![DS\_serverMan\_customerRescueMode08.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/30905954357267.png)

Browse to `E:\WINDOWS\SYSTEM32\CONFIG\`.

Select and open the SAM file to display the user accounts by clicking `Open`.

![DS\_serverMan\_customerRescueMode09.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/30905954369683.png)

Select the user account "admin" and click on `Change password`.

![DS\_serverMan\_customerRescueMode10.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/30905954377619.png)

In the pop-up window, choose and verify your new password and click `OK`. Finish by clicking `Save changes` and `Exit`.

:::warning

**NOTE:** The new password will be accepted regardless of complexity.

Keep in mind that this password will allow remote connection to the server once rebooted on its operating system.

:::

After this, the server needs to be rebooted on the normal operating system.

</details>

### Resetting the admin password using OVHcloud rescue mode

- Step 1: Rebooting the server into rescue mode

- Step 5: Setting a new password

#### Step 2: Mounting the system partition

Connect to your server via SSH (see our [SSH introduction guide](https://support.us.ovhcloud.com/hc/en-us/articles/360000416484) if needed). Since it is a Windows server, you will see partitions labeled “Microsoft LDM data”.

```bash
fdisk -l
```

Output:

```text

Units: sectors of 1 * 512 = 512 bytes
Sector size (logical/physical): 512 bytes / 512 bytes

Device          Start        End    Sectors  Size Type
/dev/sda1        2048     718847     716800  350M EFI System
/dev/sda2      718848     720895       2048    1M Microsoft LDM metadata
/dev/sda3      720896     980991     260096  127M Microsoft reserved
/dev/sda4      980992 3907028991 3906048000  1.8T Microsoft LDM data
/dev/sda5  3907028992 3907029134        143 71.5K Microsoft LDM data
```

In the example output, “sda4” must be the (file) system partition, as determined by its size. Usually, there is a mirrored second output which in this case would be “/dev/sdb**X**“. That is because in most cases, the server will have multiple disks with identical partition schemes. For the password reset process, only the first one is important. Next, mount this partition:

```bash
mount /dev/sda4 /mnt
```

Verify the mountpoint:

```bash
lsblk
```

Output:

```text
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINT
sdb      8:16   0  1.8T  0 disk
├─sdb4   8:20   0  1.8T  0 part
├─sdb2   8:18   0    1M  0 part
├─sdb5   8:21   0 71.5K  0 part
├─sdb3   8:19   0  127M  0 part
└─sdb1   8:17   0  350M  0 part
sda      8:0    0  1.8T  0 disk
├─sda4   8:4    0  1.8T  0 part /mnt
├─sda2   8:2    0    1M  0 part
├─sda5   8:5    0 71.5K  0 part
├─sda3   8:3    0  127M  0 part
└─sda1   8:1    0  350M  0 part
```

In the example above, the operation succeeded. If the mounting failed, you might receive an error message like this:

```text
The disk contains an unclean file system (0, 0).
Metadata kept in Windows cache, refused to mount.
Failed to mount '/dev/sda4': Operation not permitted
The NTFS partition is in an unsafe state. Please resume and shutdown
Windows fully (no hibernation or fast restarting), or mount the volume
read-only with the 'ro' mount option.
```

In this case, use the following command and then try to mount again.

```bash
ntfsfix /dev/sda4
```

```bash
mount /dev/sda4 /mnt
```

This step involves manipulating the *SAM* file with a tool to clear the admin user’s password. Change to the appropriate directory and list the Windows users:

```bash

/mnt/Windows/System32/config#
```

```bash
chntpw -l SAM
```

<Tab label="Step 4">

#### Step 4: Rebooting the server

First, change the netboot back to **Boot from the hard disk** in your [OVHcloud Control Panel](https://us.ovhcloud.com/manager/) (repeat the instructions in Step 1 but select `Boot from the hard disk`).

Back in the CLI, unmount the partition and restart the server with these commands:

```bash
cd
```

```bash
umount /mnt
```

```bash
reboot
```

Output:

```text
Broadcast message from root@rescue.ovh.net on pts/0 (Wed 2020-05-27 11:28:53 CEST):

The system is going down for reboot NOW!
```

<Tab label="Step 5">

#### Setting a new password (IPMI/KVM)

In your [OVHcloud Control Panel](https://us.ovhcloud.com/manager/), navigate to the `IPMI/KVM` tab to open a KVM session.

![DS\_serverMan\_changeAdminPW05.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/45601422013587.png)

 

#### For a newer version of Windows

There should be a password expiration message in the login interface.

![DS\_serverMan\_changeAdminPW06.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/45601416886547.png)

The new password for the admin user must now be entered twice. However, the confirmation field is not yet visible, meaning you need to leave the first field blank, type your new password into the second field, then use the tabulator key ("↹") on the virtual keyboard to switch to the third field ("Confirm password"). Type the password again and click on the arrow to save it.

![DS\_serverMan\_changeAdminPW07.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/45601416891923.png)

Click on `OK` and you will be logged in.

![DS\_serverMan\_changeAdminPW08.png](/images/bare-metal-cloud/dedicated-servers/how-to-reset-the-administrator-password-on-a-windows-server/45601416895763.png)
