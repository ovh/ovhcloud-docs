# Configuring SMTP on a Load Balancer service

## Requirements

- An [OVHcloud Load Balancer](https://us.ovhcloud.com/network/load-balancer/) service in your OVHcloud account

- Access to the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/)

- A Postfix-type SMTP service installed and configured on your servers

  :::warning

  **NOTE:** This guide assumes a working knowledge of SMTP protocol and service operation.

  :::

 

## Instructions

As a reminder, each protocol (HTTP and TCP) in the OVHcloud Load Balancer service has its own associated front-ends, server clusters, and servers.

:::warning

**NOTE:** The order in which elements are created is important. In particular, the server clusters must be configured before we can attach servers to them.

:::

### Access your OVHcloud Load Balancer service

<Tabs>

<Tab label="Via OVHcloud Control Panel">

From the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/), navigate to the `Load Balancer` section via the `Network` menu.

:::info

If you are not using the beta version of the OVHcloud Control Panel, you will find the `Load Balancer` section via the `Bare Metal Cloud` or `Hosted Private Cloud` menus.

:::

In the **Home** tab, you will see the following:

![loadBalancer\_homeTab.png](/images/network/load-balancer/configuring-smtp-on-a-load-balancer-service/43383637923987.png)

</Tab>

<Tab label="Via API">

Via the [OVHcloud API](https://api.us.ovhcloud.com/), use the following call:

<Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing"} regions={["us"]} />

For more information on the API’s features, you can refer to [the following guide](https://support.us.ovhcloud.com/hc/en-us/articles/28968875771923).

</Tab>

</Tabs>

 

### Add a server cluster

We will add a server cluster of TCP servers to our service, which is the part that balances traffic on the servers.

<Tabs>

<Tab label="Via OVHcloud Control Panel">

From the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/) select the `Server clusters` tab and click the `Add a server cluster` button.

![IPLB\_serverClusterTab\_empty.png](/images/network/load-balancer/configuring-smtp-on-a-load-balancer-service/46645827088787.png)

On the next screen, fill in the fields:

- **Name** (optional)
- **Protocol:** `SSL TCP (TLS)`
- **Port:** 25
- **Datacenter**

:::info

If no ports are specified, your OVHcloud Load Balancer will automatically use the same port as the corresponding front-end. Also, in the **Advanced settings**, you can add an SMTP probe on your server cluster.

:::

Click `Add` once you have filled in the fields.

![IPLB\_serverCluster\_addSSL-TCP-TLS.PNG](/images/network/load-balancer/configuring-smtp-on-a-load-balancer-service/46645827091475.png)

Your server cluster should appear in the list in the `Server clusters` tab.

</Tab>

<Tab label="Via API">

From the [OVHcloud API](https://api.us.ovhcloud.com/) you can:

- List TCP server clusters:

  <Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm"} regions={["us"]} />

- Find details of a specific TCP server:

  <Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}"} regions={["us"]} />

- Add a new TCP server cluster:

  <Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm"} regions={["us"]} />

- Modify a specific server cluster:

  <Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}"} regions={["us"]} />

- Delete a specific server cluster:

  <Api version="v1" section="/ipLoadbalancing" method="DELETE" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}"} regions={["us"]} />

</Tab>

</Tabs>

 

### Add a server

We will now add a server to our server.

<Tabs>

<Tab label="Via OVHcloud Control Panel">

In the `Server clusters` tab, select the cluster you want to add a server to by clicking the corresponding line. The list of servers already configured in the cluster will appear beneath the list of clusters, along with the `Add a server` button. Click this button to add a new server.

The mandatory fields are *IPv4 address*, *Status*, and *ProxyProtocol version*. If a server port is configured, it will override the port defined in the farm. To keep the configuration as standard as possible and easy to maintain, we recommend only using this parameter in advanced cases.

:::warning

**NOTE:** It is important to configure ProxyProtocol in version v1, so that you can retrieve the real source IP on your SMTP service. Postfix is compatible with this protocol.

:::

Click `Add` once you have filled in the fields.

![IPLB\_serverCluster\_addServer.png](/images/network/load-balancer/configuring-smtp-on-a-load-balancer-service/46645780227347.png)

Your server should appear in the `Server clusters` tab, just below the server cluster created in the previous step.

![IPLB\_serverClusters\_serverList.png](/images/network/load-balancer/configuring-smtp-on-a-load-balancer-service/46645827100179.png)

</Tab>

<Tab label="Via API">

From the [OVHcloud API](https://api.us.ovhcloud.com/) you can:

- List servers in the server cluster:

  <Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}/server"} regions={["us"]} />

- Find details of a specific server:

  <Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}/server/\{serverId\}"} regions={["us"]} />

- Add a new server:

  <Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}/server"} regions={["us"]} />

- Modify a specific server:

  <Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}/server/\{serverId\}"} regions={["us"]} />

- Delete a specific server:

  <Api version="v1" section="/ipLoadbalancing" method="DELETE" route={"/ipLoadbalancing/\{serviceName\}/tcp/farm/\{farmId\}/server"} regions={["us"]} />

</Tab>

</Tabs>

 

### Add a frontend

We will now add a frontend to our service and connect it to our server cluster. The front-end is the component of your OVHcloud Load Balancer that exposes your service on the internet.

<Tabs>

<Tab label="Via OVHcloud Control Panel">

In the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/), from the `Front-ends` tab, click `Add a front-end`.

![IPLB\_frontends.PNG](/images/network/load-balancer/configuring-smtp-on-a-load-balancer-service/46645827102355.png)

On the next screen, fill in the fields:

- **Name** (optional)

- **Protocol:** `SSL TCP (TLS)`

- **Port:** 25

  :::info

  If you want your service to be available across several ports at once, you can specify a list of ports, separated by commas, or a range of ports, in the format "-".

  :::

* **Datacenter**
* **Default server cluster:** the cluster you created at the beginning of this guide.

:::warning

**NOTE:** If you configured a probe on your cluster, you need to open the **Advanced settings** to configure a probe here as well.

:::

If you have routed Additional IPs to your OVHcloud Load Balancer service, you can also attach a front-end to one or more specific Additional IPs.

Click `Add` once you have filled in the fields.

![IPLB\_Frontend\_addSSL-TCP-TLS.png](/images/network/load-balancer/configuring-smtp-on-a-load-balancer-service/46645780234771.png)

Your front-end will appear in the `Front-ends` tab.

</Tab>

<Tab label="Via API">

From the [OVHcloud API](https://api.us.ovhcloud.com/) you can:

- Find details of a specific front-end:

  <Api version="v1" section="/ipLoadbalancing" method="GET" route={"/ipLoadbalancing/\{serviceName\}/tcp/frontend/\{frontendId\}"} regions={["us"]} />

- Add a new front-end:

  <Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/tcp/frontend"} regions={["us"]} />

- Modify a specific front-end:

  <Api version="v1" section="/ipLoadbalancing" method="PUT" route={"/ipLoadbalancing/\{serviceName\}/tcp/frontend/\{frontendId\}"} regions={["us"]} />

- Delete a specific front-end:

  <Api version="v1" section="/ipLoadbalancing" method="DELETE" route={"/ipLoadbalancing/\{serviceName\}/tcp/frontend/\{frontendId\}"} regions={["us"]} />

</Tab>

### Apply the modifications

The modifications made to your OVHcloud Load Balancer must be *explicitly applied* in each of the zones configured for your service. Only at this point will they be visible to your website visitors. This way, you can make complex configuration changes several times, and only apply them once the configuration is ready.

:::info

If you have several regions, you must apply the same configuration for each of them.

:::

<Tabs>

<Tab label="Via OVHcloud Control Panel">

In the [OVHcloud Control Panel](https://us.ovhcloud.com/manager/), click `Apply configuration` in the yellow banner.

On the next screen, select `☑` your **Datacenter** and click `Apply configuration` again.

![IPLB\_applyConfiguration\_page.png](/images/network/load-balancer/configuring-smtp-on-a-load-balancer-service/46645827105811.png)

</Tab>

<Tab label="Via API">

From the [OVHcloud API](https://api.us.ovhcloud.com/), you can apply your configuration with the following API call:

<Api version="v1" section="/ipLoadbalancing" method="POST" route={"/ipLoadbalancing/\{serviceName\}/refresh"} regions={["us"]} />

</Tab>

</Tabs>

 

### Postfix configuration

To make Postfix compatible with HAProxy *ProxyProtocol*, an option is required in the postfix main.cf configuration file:

```
smtp_upstream_proxy_protocol = haproxy
```

You then need to restart your Postfix daemon.

After you have completed all of these steps, you should now have a functional Load Balancer service for your SMTP servers. You can now check the service status by requesting your IP Load Balancer as an SMTP server.
