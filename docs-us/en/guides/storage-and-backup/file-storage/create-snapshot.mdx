# File Storage Service - Managing share snapshots

:::info

**Tip:** Refer to the [OVHcloud API console](https://api.us.ovhcloud.com/console/?section=%2Fauth\&branch=v1) for exact operations, HTTP methods, and request schemas.

:::

 

## Requirements

- A [Public Cloud project](https://us.ovhcloud.com/public-cloud/) with File Storage Service enabled.
- An existing share in the `available` state.
- API credentials with sufficient permissions to manage shares and snapshots.
- Understanding of key API concepts: `serviceName` (project ID), `regionName`, `shareId`, and optional `snapshotId`.

 

## Instructions

### Step 1: Identify your share

List all shares in your target region to find the share ID:

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/region/\{regionName\}/share"} regions={["us"]} />

Confirm that the share is in the `available` state before creating snapshots.

 

### Step 2: List existing snapshots

Retrieve all snapshots for a given share:

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/region/\{regionName\}/share/\{shareId\}/snapshot"} regions={["us"]} />

Use the response to retrieve snapshot IDs and statuses before deleting or automating operations.

 

### Step 3: Create a snapshot

Create a snapshot with a JSON payload specifying a human-readable name (and optional description):

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/region/\{regionName\}/share/\{shareId\}/snapshot"} regions={["us"]} />

- Execute the API call in Step 2 until the snapshot reaches `available` status.
- Snapshot creation time depends on allocated capacity, I/O activity, and platform load.
- Plan snapshots during low I/O periods to ensure consistency.

:::warning

**NOTE:** Snapshots are crash-consistent unless your application explicitly pauses writes before they are taken.

:::

 

### Step 4: Retrieve snapshot details (optional)

Retrieve a single snapshot by ID:

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/region/\{regionName\}/share/\{shareId\}/snapshot/\{snapshotId\}"} regions={["us"]} />

Use this for automated checks after backups or to verify snapshot metadata.

 

### Step 5: Delete a snapshot

Free the storage consumed by a snapshot:

<Api version="v1" section="/cloud" method="DELETE" route={"/cloud/project/\{serviceName\}/region/\{regionName\}/share/\{shareId\}/snapshot/\{snapshotId\}"} regions={["us"]} />

:::warning

**WARNING:** Deletion is irreversible. Ensure the snapshot is no longer required.

:::
