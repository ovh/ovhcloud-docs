# Databases & Analytics - Getting started

**Learn how to order a database or analytics solution in the OVHcloud Console.**

Cloud Databases and Analytics[\*](#go-further) services allow you to focus on building and deploying cloud applications while OVHcloud takes care of the service infrastructure and maintenance.

 

## Requirements

- Access to the [OVHcloud Console](https://console.us.ovhcloud.com/)
- A [Public Cloud project](https://us.ovhcloud.com/public-cloud/) in your OVHcloud account

 

## Instructions

Open the [OVHcloud Console](https://console.us.ovhcloud.com/#/public-cloud/project) and select your Public Cloud project. In the left-hand menu, click your database engine under **Databases** (`PostgreSQL`, `MySQL`, `MongoDB` or `Valkey`).

:::info

The **Analytics** section of the menu gives access to the [Kafka®](/public-cloud/data-analytics/kafka-getting-started), [Kafka® Connect](/public-cloud/data-analytics/kafka-connect-capabilities-limitations), [Kafka® MirrorMaker](/public-cloud/data-analytics/kafka-mirrormaker-capabilities-limitations), [Dashboards](/public-cloud/data-analytics/dashboards-configure-instance-accept-incoming-connections) and [OpenSearch™](/public-cloud/data-analytics/opensearch-getting-started) services.

:::

Click `Create a service`. All the settings are on the **Create a service** page, and the **Summary** panel on the right side of the page updates as you make selections.

{/* cp-shot: ![Manager database onboarding page](/images/public-cloud/databases/getting-started/manager-database-onboarding-page.png) */}

 

### Step 1: Name and engine

Optionally rename your service (a name is generated by default), then select the **Engine** and its **Version**.

{/* cp-shot: ![Manager database order types](/images/public-cloud/databases/getting-started/manager-database-order-types.png) */}

 

### Step 2: Select a region

Choose the geographical region of the data center in which your service will be hosted.

{/* cp-shot: ![Manager database order regions](/images/public-cloud/databases/getting-started/manager-database-order-regions.png) */}

 

### Step 3: Select a service plan

Choose an appropriate service plan. You will be able to upgrade the plan after creation.

Please visit the [capabilities page](/public-cloud/databases/capabilities-limitations) of your selected engine type for detailed information on each plan's properties.

{/* cp-shot: ![Manager database order service plans](/images/public-cloud/databases/getting-started/manager-database-order-service-plans.png) */}

 

### Step 4: Node type and nodes

Select the **Node type**. Depending on the engine, the **Number of nodes** in your cluster can be adjusted.

Please visit the [capabilities page](/public-cloud/databases/capabilities-limitations) of your selected engine type for detailed information on the hardware resources and other properties of the engine installation.

Take note of the pricing information.

{/* cp-shot: ![Manager database order node type](/images/public-cloud/databases/getting-started/manager-database-order-node-type.png) */}

 

### Step 5: Storage

Additional storage can be ordered for the cluster, on top of the storage included in the node type.

{/* cp-shot: ![Manager database order cluster sizing](/images/public-cloud/databases/getting-started/manager-database-order-cluster-sizing.png) */}

 

### Step 6: Network and IP restrictions

By default, the service is accessible over the **Public network**.

{/* cp-shot: ![Manager database order public network](/images/public-cloud/databases/getting-started/manager-database-order-public-network.png) */}

 

#### Connecting a private network (optional)

If you already have a private subnet available, select **Private network (vRack)**, then choose the **Private network** and the **Subnet**. Note that this option might not be available for the selected service type. You can also click `Create a private network`.

Please follow the [Configuring vRack for Public Cloud](/public-cloud/network-services/configure-vrack) guide for detailed instructions.

{/* cp-shot: ![Manager database order private network](/images/public-cloud/databases/getting-started/manager-database-order-private-network.png) */}

 

#### Authorizing IP addresses

Click `Add an IP` (or `Add my current IP`) to add the IP addresses or address ranges (CIDR) allowed to connect to your service.

:::info
For security, the default network configuration blocks all incoming connections. Authorize a suitable IP address to access your database.
:::

 

### Step 7: Summary and confirmation

Review the **Summary** panel on the right side of the page, then click `Create the database` to confirm. To view the equivalent API or Terraform call before ordering, click `API and Terraform equivalent`.

{/* cp-shot: ![Manager database order summary](/images/public-cloud/databases/getting-started/manager-database-order-summary.png) */}

Within a few minutes, your new service will be deployed. The status of the service in the OVHcloud Console shows when it is ready to use.

Continue with the *Configure your instance to accept incoming connections&#x20;*&#x67;uide of your selected engine type available [here](/public-cloud/databases/capabilities-limitations) to configure your service after installation.

Note that the configuration options might be different, depending on the engine type. You will find an example in this repository: [https://github.com/ovh/public-cloud-databases-examples](https://github.com/ovh/public-cloud-databases-examples).
