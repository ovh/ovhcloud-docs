# Databases & Analytics - Restore a backup

**Learn how to restore a backup of a Cloud Database or Analytics service in the OVHcloud Console.**

Cloud Database and Analytics services allow you to focus on building and deploying cloud applications while OVHcloud takes care of the engine infrastructure and maintenance.

We continuously improve our offers. You can follow and submit ideas to add to our [roadmap](https://github.com/orgs/ovh/projects/16/views/5?filterQuery=main-product%3A%22Managed+Databases%22%2C%22Data+Platform%22%2C%22Data+Processing%22%2C%22Data+Integration%22).

 

## Requirements

- Access to the [OVHcloud Console](https://console.us.ovhcloud.com/)
- A [Cloud Database or Analytics service](https://us.ovhcloud.com/public-cloud/databases/) up and running

 

## Instructions

### Step 1: Select the service you want to restore data from

Log in to the [OVHcloud Console](https://console.us.ovhcloud.com/#/public-cloud/project) and select your Public Cloud project. In the left-hand menu, click your engine under **Databases** (or your service type under **Analytics**), then click the name of the service you want to restore the backup from.

 

### Step 2: Go to the backup tab

In the tab list, click on `Backups`.

{/* cp-shot: ![Manager database backups tab](/images/public-cloud/databases/restore-backup/manager-database-backups-tab.png) */}

 

### Step 3: Select the backup to restore from

Select the backup from which you want to restore. To help you choose, observe the dates at which the backups have been performed.

Click on the `⋮` button corresponding to the chosen backup, then click on `Fork` to open the fork panel. You can also click the `Fork` button above the list.

:::warning

**NOTE:** The MongoDB[®](#go-further) service has the option to restore a backup in place, meaning restoring the backup on the same service. This option will rollback **ALL** data to the state it was in when the backup was done. This can cause data loss.

:::

{/* cp-shot: ![Manager database backups tab more options](/images/public-cloud/databases/restore-backup/manager-database-backups-tab-more-options.png) */}

 

### Step 4: Configure the target service

As seen before, when restoring a backup, you create a new, separate service on which the backup data will be imported. You can configure this new service as you wish in the fork panel.

#### Immutable options

For obvious reasons, you cannot change the engine; this option is not offered. The same goes for the engine version, you will be able to update it once the new service is running.

 

#### Name

Enter a name for the new service in the **New cluster name** field.

 

#### Restore point

Choose the restore point from which the service will be duplicated:

- From a backup: the most common option, restore from one of the listed backups.
- Point in time: if your service supports point-in-time recovery (see our [Databases & Analytics - Automated backups](/public-cloud/databases/automated-backups) guide for more details), restore from a specific date and time.
- Latest state: restore from the most recent data.

{/* cp-shot: ![Manager database - Restore backup](/images/public-cloud/databases/restore-backup/manager-database.png) */}

{/* cp-shot: ![Manager database from date](/images/public-cloud/databases/restore-backup/manager-database-from-date.png) */}

{/* cp-shot: ![Manager database newest](/images/public-cloud/databases/restore-backup/manager-database-newest.png) */}

 

#### Plan

When restoring a backup, you can select another service plan.

{/* cp-shot: ![Manager database service plans](/images/public-cloud/databases/restore-backup/manager-database-service-plans.png) */}

 

#### Region

You can choose a different region for your new service.

{/* cp-shot: ![Manager database region](/images/public-cloud/databases/restore-backup/manager-database-region.png) */}

 

#### Nodes

You can choose to upgrade the node to a bigger flavor.

{/* cp-shot: ![Manager database node type](/images/public-cloud/databases/restore-backup/manager-database-node-type.png) */}

:::info

The flavor downgrade will soon be offered. The limitation is that the targeted flavor must have enough storage to restore the backup.

:::

 

#### Sizing

Additional storage can be ordered while forking the service.

{/* cp-shot: ![Manager database cluster size](/images/public-cloud/databases/restore-backup/manager-database-cluster-size.png) */}

:::info

The storage reduction will soon be offered. The limitation is that the targeted total storage must be large enough to restore the backup.

:::

 

#### Options

You can update the network options.

{/* cp-shot: ![Manager database configure](/images/public-cloud/databases/restore-backup/manager-database-configure.png) */}

The estimated price of the new service is displayed at the bottom of the panel. Now, click `Create fork`, and the new service will be created. Please note that, depending on the backup size, it can take some time before the service is available.

 

### Step 5: Wait for service creation

You now just have to wait for your service to be ready. This new service is now completely independent from the one you forked the backup from. You can safely delete the old service without impacting the new one.

:::warning

**NOTE:** The newly created service does not duplicate IP restrictions or users that were created on the old service. You will have to recreate those before using your new service.

:::

{/* cp-shot: ![Manager database dashboard creating status](/images/public-cloud/databases/restore-backup/manager-database-dashboard-creating-status.png) */}
