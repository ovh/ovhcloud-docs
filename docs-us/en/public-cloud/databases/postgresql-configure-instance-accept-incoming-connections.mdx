# PostgreSQL® - Configure an instance to accept incoming connections

**Learn how to configure your PostgreSQL® instance to accept incoming connections.**

Cloud Databases allow you to focus on building and deploying cloud applications while OVHcloud takes care of the database infrastructure and maintenance in operational conditions.

 

## Requirements

- A [Public Cloud project](https://us.ovhcloud.com/public-cloud/) in your OVHcloud account
- Access to the [OVHcloud Console](https://console.us.ovhcloud.com/#/public-cloud/project)
- A PostgreSQL® database running on your OVHcloud Cloud Databases ([this guide](/public-cloud/databases/getting-started) can help you to meet this requirement)

 

## Instructions

### Configure your PostgreSQL[®](#go-further) instance to accept incoming connections

Before making a connection, we must verify that our PostgreSQL® instance is correctly configured.

Log in to the [OVHcloud Console](https://console.us.ovhcloud.com/#/public-cloud/project) and select your Public Cloud project. In the left-hand menu, click `PostgreSQL` under **Databases**, then click the name of your PostgreSQL® service.

{/* cp-shot: ![Manager - PostgreSQL configure instance accept incoming connections - step 3](/images/public-cloud/databases/postgresql-configure-instance-accept-incoming-connections/manager-3.png) */}

 

#### Step 1: Verify your user roles and password

Select the `Users` tab. Verify that you have a user with sufficient rights and a configured password. If you don't remember the user's password, you can either create a new user or regenerate the password of an existing user. Be careful! By doing so you will need to update all the places where you already use this user/password pair.

This first user **avnadmin** comes with the following privileges:

```
  LOGIN
  NOSUPERUSER
  INHERIT
  CREATEDB
  CREATEROLE
  REPLICATION
```

We rely on official PostgreSQL® roles and privileges. You can manage them yourself via CLI or code. So far, **user grants and privileges management are not supported via the OVHcloud Console or the OVHcloud API**.

Please read the [official PostgreSQL® documentation](https://www.postgresql.org/docs/current/database-roles.html) to select the right roles for your use case.

To reset the **avnadmin** password, click the `⋮` button on the row of the user, then click `Reset password`.

{/* cp-shot: ![Manager - PostgreSQL configure instance accept incoming connections - step 2](/images/public-cloud/databases/postgresql-configure-instance-accept-incoming-connections/manager-2.png) */}

To create a new user, click `Add a user`, fill in the form in the **Add a user** panel, then click `Create`.

Once created or updated, the user must have the `Active` status in the OVHcloud Console.

{/* cp-shot: ![Manager - PostgreSQL configure instance accept incoming connections](/images/public-cloud/databases/postgresql-configure-instance-accept-incoming-connections/manager.png) */}

 

#### Step 2: Authorize incoming connections from the PostgreSQL® client

By default, a Cloud Database does not accept any form of connection from the outside world. This way, we can help prevent intrusive connection attempts.

Select the `Configuration` tab. Click `Add`, enter the IP address or CIDR block of your pgAdmin environment and a description to identify its origin, then click `Save`.

You can also click `Add my current IP` to add the public IP address from which you are browsing the OVHcloud Console. This is convenient for a development workstation, provided your address is static.

{/* cp-shot: ![Manager - PostgreSQL configure instance accept incoming connections - step 5](/images/public-cloud/databases/postgresql-configure-instance-accept-incoming-connections/manager-5.png) */}

:::info

If you want to allow connections from the outside, you can enter the IP 0.0.0.0/0. Please use it carefully.

:::

 

#### Collect required information

Select the `Overview` tab to find the connection details of your service: host, port, protocol, connection URI and the CA certificate of the service.

{/* cp-shot: ![Manager - PostgreSQL configure instance accept incoming connections - step 7](/images/public-cloud/databases/postgresql-configure-instance-accept-incoming-connections/manager-7.png) */}

Select the `Databases` tab to get the database name.

{/* cp-shot: ![Manager - PostgreSQL configure instance accept incoming connections - step 4](/images/public-cloud/databases/postgresql-configure-instance-accept-incoming-connections/manager-4.png) */}

Select the `Users` tab to get the username.

{/* cp-shot: ![Manager - PostgreSQL configure instance accept incoming connections - step 6](/images/public-cloud/databases/postgresql-configure-instance-accept-incoming-connections/manager-6.png) */}
