# AI Notebooks - Manage and use data in a notebook via UI

**Learn how to access Object Storage data from your [notebooks](/public-cloud/ai-machine-learning/ai-notebooks-getting-started) via the OVHcloud Console.**

 

## Requirements

- A [Public Cloud project](https://us.ovhcloud.com/public-cloud/) in your OVHcloud account
- Access to the [OVHcloud Console](https://console.us.ovhcloud.com/)
- A Public Cloud user with the `Administrator` or `AI Training Operator` role (see [this guide](/public-cloud/ai-machine-learning/manage-users-roles) for more information)

 

## Instructions

### Upload data to your Object Storage

First, you need to push some data to **Object Storage** before accessing it from the notebook.

In the [OVHcloud Console](https://console.us.ovhcloud.com/#/public-cloud/project), select your Public Cloud project, then click `Object Storage` under **Storage** in the left-hand menu. Your containers are listed in the `Containers` tab.

:::info

You can upload different types of data: datasets, code, notebooks, connection weights, text or CSV files, etc.

:::

{/* cp-shot: ![Object storage containers tab](/images/public-cloud/ai-machine-learning/ai-notebooks-manage-data-ui/object-storage-containers-tab.png) */}

Let's assume that a file named `my-dataset.zip` exists locally on your computer and contains your dataset. You will be able to upload it into an object container in your Object Storage by following these steps.

 

#### Order your Object Storage container

In the `Containers` tab, click `Create an object container`. Select the container type (`Swift API` or `S3-compatible API`), name your container `my-dataset`, then select the deployment mode and the region, and click `Create`. For more information, see [this guide](/public-cloud/ai-machine-learning/compliance).

:::warning

**NOTE:**

- Your container must be located in the same region as your AI Notebook will be.
- For a dataset that you use to train your model, the `Restricted` level of **Confidentiality** is appropriate.

:::

 

#### Add objects to your container

To upload your dataset into your object container click the name of your container to open its `Objects` tab. Click `Add an object`, then click `Browse files`, select your local `my-dataset.zip` file, and click `Upload`.

{/* cp-shot: ![Object storage objects tab](/images/public-cloud/ai-machine-learning/ai-notebooks-manage-data-ui/object-storage-objects-tab.png) */}

Your `my-dataset.zip` file is now displayed in your object container.

{/* cp-shot: ![Manager AI object dataset](/images/public-cloud/ai-machine-learning/ai-notebooks-manage-data-ui/manager-ai-object-dataset.png) */}

:::info

You can also create a new empty `my-weights` container in which you can save your **connection weights** (or your **validated model**) at the end of your training.

:::

We assume that we now have two object containers available:

- `my-dataset`, containing the file `my-dataset.zip`
- `my-weights`, empty

You are now ready to launch a notebook with your data!

 

### Launch a notebook with attached data

To launch an AI notebook, click `AI Notebooks` in the left-hand menu of your Public Cloud project, then click `Create a notebook`.

Use this [tutorial](/public-cloud/ai-machine-learning/ai-notebooks-getting-started) to complete the setup of your AI Notebook until the advanced configuration section of the creation page.

{/* cp-shot: ![Manager AI onboarding](/images/public-cloud/ai-machine-learning/ai-notebooks-manage-data-ui/manager-ai-onboarding.png) */}

 

#### Attach a container or a Git repository

You can attach your different types of data to your notebook in the advanced configuration section of the creation page.

To attach a container, turn on the `Volumes` switch and click `Add a volume`. In the dialog, select the datastore that holds your container, then the container, enter the mount path, and choose the permission. Then click `Add`.

:::warning

**NOTE:** To attach an S3™ compatible bucket to your notebook, you first need to declare it as a datastore in the `S3 volumes` tab of the configuration page of AI Notebooks. To use S3™ compatible solutions from the command line, you can also use the [ovhai](/public-cloud/ai-machine-learning/cli-install-client) CLI.

:::

 

#### Access with Read-Only permissions

You can load the container `my-dataset` in the `/workspace/dataset` directory with the `Read only` permission.

{/* cp-shot: ![Manager AI order volume example - step 1](/images/public-cloud/ai-machine-learning/ai-notebooks-manage-data-ui/manager-ai-order-volume-example-1.png) */}

You will not be able to modify the dataset from this notebook because you loaded it with the `Read only` permission.

The `Read only` permission is to ensure you don't modify your data by mistake. If you want to modify data from your notebooks to store a trained neural network, for example, you can use the read-write permission instead.

 

#### Access with Read-Write permissions

Similarly to the `Read only` mode, you can load data with the read-write permission: for example, load the container `my-weights` in the `/workspace/weights` directory.

Once you have some data that you want to save from the notebook to Object Storage (connection weights in this example), you can simply write it to the `/workspace/weights` folder.

{/* cp-shot: ![Manager AI order volume example - step 2](/images/public-cloud/ai-machine-learning/ai-notebooks-manage-data-ui/manager-ai-order-volume-example-2.png) */}

This folder will be uploaded to your Object Storage when you stop your notebook.

While your notebook is in the stopping state, the upload is still in progress. Once the state changes to stopped, all the data has been uploaded to your Object Storage.

 

#### Attach a public Git repository

If Python code, notebooks, or other files are available on a public GitHub repository, you can attach them to your notebook. To be able to edit and make changes easily, use the read-write permission.

Turn on the `Git Public` switch and click `Add a repository`. Enter the repository URL, then the mount path (for example `/workspace/git-hub-repository`) and the permission, and click `Add`.

{/* cp-shot: ![Manager AI order volume example - step 4](/images/public-cloud/ai-machine-learning/ai-notebooks-manage-data-ui/manager-ai-order-volume-example-4.png) */}

:::warning

**NOTE:** To make your repository URL valid, don't forget to add a `.git` at the end of the GitHub repository URL.

:::

 

#### Use cached volumes

When loading large files from the `Object Storage`, it can take some time to download to your notebooks. In these cases, you can cache the volumes so that it does not need to be downloaded again when you start new notebooks that use the same data.

To do so, tick `Cache the volume close to the instance` in the volume dialog.

{/* cp-shot: ![Manager AI order volume example - step 3](/images/public-cloud/ai-machine-learning/ai-notebooks-manage-data-ui/manager-ai-order-volume-example-3.png) */}

Cached volumes will be deleted at least 72 hours after the last notebook using it has stopped. Note that the cache is shared with all users in your project. The main consequence you need to be careful about is the fact that if someone else modifies the data in your cached volume, you will also see the modifications on your side.

 

#### Launch and access the notebook

Your notebook is now ready to be launched with your data. The attached volumes are listed in the summary of the creation page. Click `Create the notebook`.

Once the notebook is created, read th&#x65;**&#x20;Accessing your AI Notebook** section of our [AI Notebooks - Getting started](/public-cloud/ai-machine-learning/ai-notebooks-getting-started) guide to learn how to find your access URL.

As soon as you access your notebook, you will see the different folders containing your data.

![PaaS AI - step 16](/images/public-cloud/ai-machine-learning/ai-notebooks-manage-data-ui/paas-ai-16.png)
