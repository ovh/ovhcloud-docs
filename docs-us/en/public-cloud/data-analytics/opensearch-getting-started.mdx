# OpenSearch™ - Getting started

**Learn how to configure a Cloud Analytics with OpenSearch™ service in the OVHcloud Console.**

OpenSearch™ is an open-source search and analytics suite used for various use cases related to log and data analysis, real-time monitoring, and application searching. Forked from Elasticsearch and Kibana, OpenSearch™ offers users a highly scalable system with easy access to large amounts of data and integrated metrics.

 

## Requirements

- Access to the [OVHcloud Console](https://console.us.ovhcloud.com/)
- A [Public Cloud project](https://us.ovhcloud.com/public-cloud/) in your OVHcloud account

 

## Instructions

### Subscribe to the service

From the [OVHcloud Console](https://console.us.ovhcloud.com/#/public-cloud/project), select your Public Cloud project. In the left-hand menu, click `OpenSearch` under **Analytics**, then click `Create a service`.

The service creation page is organized in the following sections:

- Database engine: select OpenSearch and the version to install. A name is generated automatically for your service; you can change it later.
- Region: choose the geographical region of the data center in which your service will be hosted.
- Plan: choose an appropriate service plan. If needed, you will be able to upgrade the plan after creation.
- Node type and number of nodes: choose the node template and increase the number of nodes if needed. The initial and maximum number of nodes depends on the plan you chose.
- Storage: you can add additional storage. Please take note of the pricing information.
- Network: decide whether to attach your instance to a public network or a private network (vRack). If you select a private network, you will need to select a network and subnetwork to attach.

Please see the [Capabilities and limitations](/public-cloud/data-analytics/opensearch-capabilities) guide for detailed information on each plan's properties and on the hardware resources and other properties of the engine installation.

Check the summary of your order, including the pricing information. The `API and Terraform equivalent` button displays the equivalent of creating this service with the OVHcloud API or Terraform. Click `Create the database` to create your service.

In a matter of minutes, your new service will be deployed. It is ready to use once its status shows that it is active.

### Configure the OpenSearch™ service

Once the OpenSearch™ service is up and running, you will have to define at least one user and one authorized IP to fully connect to the service.

 

#### Step 1 (mandatory): Set up a new user

Switch to the `Users` tab. An admin user is pre-configured during the service installation. You can add more users by clicking the button to add a user.

Enter a username, then click `Create`.

Once the user is created, the password is generated. Please keep it secure, as it will not be shown again.

You can reset the password of any user, including the admin user, by clicking the `⋮` button in that user's row of the table, then `Reset password`.

{/* cp-shot: ![Manager users tab](/images/public-cloud/data-analytics/opensearch-getting-started/manager-users-tab.png) */}

{/* cp-shot: ![Manager users tab more options](/images/public-cloud/data-analytics/opensearch-getting-started/manager-users-tab-more-options.png) */}

 

#### Step 2 (mandatory): Configure authorized IPs

:::warning

**NOTE:** For security reasons, the default network configuration doesn't allow any incoming connections. You must authorize suitable IP addresses to successfully access your service.

:::

Switch to the `Configuration` tab. At least one IP address must be authorized here before you can connect to your service. It can be your laptop IP, for example.

Click `Add`, enter a single IP address or an IP block (CIDR), then click `Save`. You can also remove IP addresses from the list.

{/* cp-shot: ![Manager configuration tab](/images/public-cloud/data-analytics/opensearch-getting-started/manager-configuration-tab.png) */}

If you don't know how to get your IP, please visit a website such as [www.WhatismyIP.com](https://www.whatismyip.com/). Copy the IP address numbers shown on this website and save them for later.

:::tip

**Success!** Your OpenSearch™ service is now fully accessible!

:::

Optionally, you can configure access control lists (ACLs) for granular permissions.

 

#### Optional: Configure ACLs

OpenSearch™ supports index-level access control lists (ACLs) to control permissions. This approach allows you to limit the operations that are available to specific connections and to restrict access to certain data sets, which improves the security of your data.

ACLs are managed in the `Users` tab. Make sure the switch to enable ACLs is turned on, then define the ACLs of each user when you add or edit it.

{/* cp-shot: ![DBaaS getting started - step 12](/images/public-cloud/data-analytics/opensearch-getting-started/dbaas-gettingstarted-12.png) */}

You can grant the following permissions:

- **Administrator**: full access to APIs and documents
- **Read-only**: allows only searching and retrieving documents
- **Write**: allows updating, adding, and deleting documents
- **Read and write**: full access to documents
- **none**: no access

{/* cp-shot: ![DBaaS getting started - step 13](/images/public-cloud/data-analytics/opensearch-getting-started/dbaas-gettingstarted-13.png) */}

:::warning

**NOTE:** Write permission allows the service user to create new indexes that match the pattern, but it does not allow the deletion of those indexes.

:::

Rules are defined separately for each user as **permission/index model** combinations. The **index model**, also called **pattern**, defines the indexes that the permission applies to. Patterns are glob-style, where **\*** matches any number of characters and **?** matches any character.

{/* cp-shot: ![DBaaS getting started - step 14](/images/public-cloud/data-analytics/opensearch-getting-started/dbaas-gettingstarted-14.png) */}

When multiple rules match, they are applied in the order listed above. If ACLs are enabled and no rules match, access is denied.

 

##### **Control access to top-level APIs**

OpenSearch™ has several “top-level” API endpoints (*\_mget*, *\_msearch*, and so on), where you have to grant access separately. To do this, use patterns similar to the index patterns, for example:

- Administrator/\_\* would grant unlimited access to all top-level APIs
- Administrator/\_msearch grants unlimited access to the \_msearch API only

 

##### **Access control and OpenSearch™ Dashboards**

Enabling ACLs does not restrict access to OpenSearch™ Dashboards itself, but all requests made by OpenSearch™ Dashboards are checked against the current user’s ACLs.

In practice, for OpenSearch™ Dashboards to work properly, you must grant the user admin-level access to the *\_msearch* interface (permission: Administrator, pattern: *\_msearch*).

 

### Advanced configuration

#### Index patterns

An index contains a schema. Each data is based on a basic unit, which is a JSON document, indexed with a unique ID. Indexing is the method used to store data by the search engine for fast retrieval.

You can learn more by browsing the [OpenSearch™ indexing documentation](https://opensearch.org/docs/latest/opensearch/index-data/).

It's not mandatory, but if needed, you can limit the number of indexes kept for a given pattern, which is useful, for example, when an index is created every day to store logs.

Switch to the `Index patterns` tab and click `Add a pattern`. Enter the name of the pattern and the maximum number of indexes to keep, then click `Create`.

{/* cp-shot: ![Manager index patterns tab](/images/public-cloud/data-analytics/opensearch-getting-started/manager-index-patterns-tab.png) */}

{/* cp-shot: ![Manager index patterns tab add pattern](/images/public-cloud/data-analytics/opensearch-getting-started/manager-index-patterns-tab-add-pattern.png) */}

 

#### Automatic backups

OVHcloud performs daily backups for your OpenSearch™ service. To find them, switch to the `Backups` tab. Backups will be created automatically, and retention time depends on the service plan. Please read the [Capabilities and limitations](/public-cloud/data-analytics/opensearch-capabilities) guide for detailed information on each plan's properties.

Via the `⋮` button, you can restore a backup by duplicating it to a new service with `Fork`.

{/* cp-shot: ![Manager backups tab](/images/public-cloud/data-analytics/opensearch-getting-started/manager-backups-tab.png) */}

### Query the OpenSearch™ service

#### DB queries with cURL

Once the service is up and configured, you can try to connect from a remote session to it. You need to have at least:

- the user login and password, with accurate ACLs if enabled;
- the URI of the OpenSearch™ service. It can be found in the connection details of the `Overview` tab.

:::warning

**NOTE:** Verify that the IP address of your system running the cURL command is part of the authorized IPs (IP restrictions) defined for this OpenSearch™ service.

:::

Once ready, try this in a command line, with your user and password:

```bash
export OPENSEARCH_URI=https://user1:2fakeSVV5wvyPykF@opensearch-682faf00-682faf00.database.cloud.ovh.us:20184
```

Then try to connect:

```bash
curl $OPENSEARCH_URI
```

The response should be similar to:

```json
{
"name" : "opensearch-682faf00-1",
"cluster_name" : "ba1b1006-776a-4686-9c3c-9f65d4d73467",
"cluster_uuid" : "UoyMAkrISd6r1rIVYn4q5g",
"version" : {
"distribution" : "opensearch",
"number" : "1.1.0",
"build_type" : "unknown",
"build_hash" : "unknown",
"build_date" : "2021-11-15T16:09:53.881093Z",
"build_snapshot" : false,
"lucene_version" : "8.9.0",
"minimum_wire_compatibility_version" : "6.8.0",
"minimum_index_compatibility_version" : "6.0.0-beta1"
},
"tagline" : "The OpenSearch Project: https://opensearch.org/"
}
```

Now create an index:

```bash
curl -X PUT $OPENSEARCH_URI/my-index
```

In case of a wrongly defined ACL for the user, the response will be similar to:

```bash
<html><body>
<h1>403 Forbidden</h1>
Request forbidden by administrative rules.<br/>
(reason: PUT /my-index/ not allowed)
</body></html>
```

Try to add a document:

```bash
curl -X PUT $OPENSEARCH_URI/my-index/_doc/1' -H 'Content-Type: application/json' -d '{"Description": "To be or not to be, that is the question."}'
```

Retrieve the data:

```bash
curl -X GET $OPENSEARCH_URI/my-index/_doc/1
```

Delete the data:

```bash
curl -X DELETE $OPENSEARCH_URI/my-index/_doc/1
```

Delete the index:

```bash
curl -X DELETE $OPENSEARCH_URI/my-index/
```
