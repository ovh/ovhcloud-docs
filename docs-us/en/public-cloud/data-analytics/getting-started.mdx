# Analytics - Getting started

## Objective

OVHcloud Public Cloud Analytics[\*](#go-further) services let you focus on building and deploying cloud applications while OVHcloud handles the analytics infrastructure and maintenance.

**This guide explains how to order a Public Cloud Analytics service via the OVHcloud Console, API, CLI, or Terraform.**

## Requirements

- A [Public Cloud project](https://us.ovhcloud.com/public-cloud/) in your OVHcloud account
- Access to the [OVHcloud API](https://api.us.ovhcloud.com/) *(API, CLI, and Terraform methods — create your credentials by consulting the [First steps with the OVHcloud API](/manage-and-operate/api/first-steps) guide)*
- [Terraform](https://www.terraform.io/) installed *(Terraform method only — tested with version v1.14.6)*

#### OVHcloud Console access

- **Direct link:** [Public Cloud projects](https://console.us.ovhcloud.com/#/public-cloud/project)
- **Navigation path:** `Public Cloud` > Select your project > **Analytics** group

## Instructions

<Tabs>
  <Tab label="OVHcloud Console">
    In the left-hand menu of your Public Cloud project, the **Analytics** group gives access to `Kafka` (Kafka, Kafka Connect, and Kafka MirrorMaker), `OpenSearch`, and `Managed Dashboards`. Click the product of your choice, then `Create a service`. The **Create a service** page for that product opens.

    {/* cp-shot: ![Manager database onboarding page](/images/public-cloud/databases/getting-started/manager-database-onboarding-page.png) */}

    **Step 1: Select your engine and version**

    Under **Database engine**, select the engine and its **Version**. Optionally rename your service in the **Name** field (auto-generated by default).

    {/* cp-shot: ![Manager database order types](/images/public-cloud/databases/getting-started/manager-database-order-types.png) */}

    **Step 2: Select a region**

    Under **Select a region**, choose the geographical region of the data center in which your analytics service will be hosted.

    {/* cp-shot: ![Manager database order regions](/images/public-cloud/databases/getting-started/manager-database-order-regions.png) */}

    **Step 3: Select a service plan**

    Under **Plan**, choose a service plan. You can upgrade it after creation.

    See the [capabilities page](https://us.ovhcloud.com/public-cloud/cloud-analytics/) of your selected analytics type for plan property details.

    {/* cp-shot: ![Manager database order service plans](/images/public-cloud/databases/getting-started/manager-database-order-service-plans.png) */}

    **Step 4: Select your node type**

    Under **Node type**, select the node model. The number of nodes is set by the plan selected above.

    See the [capabilities page](https://us.ovhcloud.com/public-cloud/cloud-analytics/) of your selected analytics service type for hardware and configuration details.

    Take note of the pricing information.

    {/* cp-shot: ![Manager database order node type](/images/public-cloud/databases/getting-started/manager-database-order-node-type.png) */}

    **Step 5: Sizing**

    Additional storage can be ordered under **Storage** and, depending on the engine, the number of nodes in your cluster can be adjusted under **Nodes**.

    {/* cp-shot: ![Manager database order cluster sizing](/images/public-cloud/databases/getting-started/manager-database-order-cluster-sizing.png) */}

    **Step 6: Configure the network and IP restrictions**

    *Connecting a private network (optional)*

    Under **Network**, if you already have a private subnet available, select **Private network (vRack)**, then choose the **Private network** and the **Subnet**. This option may not be available for the selected service type.

    If no private network exists in the region, the `Create a private network` link redirects you to create one. In that case, you will need to restart the analytics service order.

    For detailed instructions, see the [Configuring vRack for Public Cloud](/public-cloud/network-services/configure-vrack) guide.

    *IP restrictions*

    Under **IP restrictions**, add the IP addresses or address ranges allowed to connect to your service (`Add an IP`, `Add my current IP`).

    :::info
    For security, the default network configuration blocks all incoming connections. Authorize a suitable IP address to access your analytics service.
    :::

    {/* cp-shot: ![Manager database order public network](/images/public-cloud/databases/getting-started/manager-database-order-public-network.png) */}

    {/* cp-shot: ![Manager database order private network](/images/public-cloud/databases/getting-started/manager-database-order-private-network.png) */}

    **Step 7: Summary and confirmation**

    The **Summary** of your order updates as you make selections. Review it, then click `Create the database` to confirm.

    To view the equivalent API or Terraform call before ordering, click `API and Terraform equivalent`.

    Your analytics service deploys within a few minutes. Its status in the OVHcloud Console shows when it is ready to use.

    To configure your service after installation, see the *Configure your instance to accept incoming connections* guide for your analytics service type, [available in our Analytics guides](/public-cloud/data-analytics/landing-page-data-analytics).

    Configuration options vary by analytics type. Examples are available in the [public-cloud-databases-examples](https://github.com/ovh/public-cloud-databases-examples) repository.

    {/* cp-shot: ![Manager database order summary](/images/public-cloud/databases/getting-started/manager-database-order-summary.png) */}

  <Tab label="OVHcloud API">
    **Step 1: Gather the set of required parameters**

    To create an analytics service, specify at minimum:

    - an _engine_, and its _version_ (e.g. `opensearch 3.3`)
    - the _plan_ (e.g. `business`)
    - the _nodes_ of the cluster (e.g. 3 nodes with 4 cores, 15 GiB memory, 100 GiB disk)

    *List the capabilities*

    The _capabilities_ endpoint lists the allowed engine, plan, and flavor values.

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/capabilities"} regions={["us"]} />

    The call returns an object listing the allowed engines (with versions), plans, and flavors.

    *Get the availability*

    The _availability_ endpoint lists the valid parameter combinations. For example, an OpenSearch `Essential` plan allows clusters with a single node, whereas `Business` uses 3 nodes and `Enterprise` 6 nodes. Choose the combination that best fits your needs.

    <Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/database/availability"} regions={["us"]} />

    **Step 2: Create an OpenSearch analytics service**

    :::warning
    Creating a cluster incurs charges.
    :::

    <Api version="v1" section="/cloud/project" method="POST" route={"/cloud/project/\{serviceName\}/database/opensearch"} regions={["us"]} />

    - **description**: a human-readable description for the service.
    - **plan**: the desired plan.
    - **version**: the OpenSearch version.
    - **nodesPattern**: specify the _flavor_, _region_, and number of nodes.
    - **nodeslist**: leave undefined — use **nodesPattern** instead for same-region, same-flavor clusters.
    - **ipRestrictions**: IP address blocks allowed to connect.

    :::info
    For security, the default network configuration blocks all incoming connections. Authorize a suitable IP address to access your analytics service.
    :::

    For private networking, also specify **networkId** (vRack ID) and **subnetId** (vRack subnet ID).

    The call returns the cluster object. Its **status** is `CREATING`. Note the **id** for the next step.

    **Step 3: Wait for your analytics service to be ready**

    The cluster takes a few minutes to become usable. Check its status using:

    <Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/database/opensearch/\{clusterId\}"} regions={["us"]} />

    Its **status** transitions to `READY` when the cluster is available.

    **Step 4: Reset the primary user password**

    List your cluster's users to get the admin user ID:

    <Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/database/opensearch/\{clusterId\}/user"} regions={["us"]} />

    Reset the admin user's password:

    <Api version="v1" section="/cloud/project" method="POST" route={"/cloud/project/\{serviceName\}/database/opensearch/\{clusterId\}/user/\{userId\}/credentials/reset"} regions={["us"]} />

    Note the new password to connect to the cluster.

    :::warning
    This password will not be available later: OVHcloud does not store user passwords.
    :::

    **Step 5: Start using the cluster**

    The cluster connection information is available in the **Connection details** card of the `Overview` tab of your service in the OVHcloud Console. You can now use the cluster.
  </Tab>
  <Tab label="OVHcloud CLI">
    :::info
    All commands require either the `--cloud-project <projectId>` flag or the `OVH_CLOUD_PROJECT_SERVICE` environment variable, set to your Public Cloud project ID.
    :::

    **Step 1: Gather the set of required parameters**

    List available engines, plans, and node flavors:

    ```bash
    ovhcloud cloud reference managed-analytics list-engines --cloud-project <projectId>
    ovhcloud cloud reference managed-analytics list-plans --cloud-project <projectId>
    ovhcloud cloud reference managed-analytics list-node-flavors --cloud-project <projectId>
    ```

    **Step 2: Create an OpenSearch analytics service**

    :::warning
    Creating a cluster incurs charges.
    :::

    ```bash
    ovhcloud cloud managed-analytics create \
      --cloud-project <projectId> \
      --engine opensearch \
      --version 3.3 \
      --plan business \
      --nodes-pattern.flavor db1-7 \
      --nodes-pattern.region US-EAST-VA \
      --nodes-pattern.number 3 \
      --description "My OpenSearch cluster" \
      --ip-restrictions "203.0.113.0/24"
    ```

    :::info
    For security, the default network configuration blocks all incoming connections. Authorize a suitable IP address to access your analytics service.
    :::

    For private networking, add `--network-id <networkId>` and `--subnet-id <subnetId>`.

    **Step 3: Wait for your analytics service to be ready**

    ```bash
    ovhcloud cloud managed-analytics get <clusterId> --cloud-project <projectId>
    ```

    Its **status** transitions to `READY` when the cluster is available.

    **Step 4: Reset the primary user password**

    ```bash
    # List users and retrieve the admin user ID
    ovhcloud cloud managed-analytics user list <clusterId> --cloud-project <projectId>

    # Reset the admin user password
    ovhcloud cloud managed-analytics user credentials-reset <clusterId> <userId> --cloud-project <projectId>
    ```

    :::warning
    This password will not be available later: OVHcloud does not store user passwords.
    :::

    **Step 5: Start using the cluster**

    The cluster connection information is available in the **Connection details** card of the `Overview` tab of your service in the OVHcloud Console. You can now use the cluster.
  </Tab>
  <Tab label="Terraform">
    **Step 1: Gather the OVHcloud required parameters**

    The OVHcloud Terraform provider requires the following credentials:

    - an `application_key`
    - an `application_secret`
    - a `consumer_key`

    To retrieve them, follow the [First steps with the OVHcloud APIs](/manage-and-operate/api/first-steps) guide. Generate credentials with the following rights:

    - **GET** `/cloud/project/*/database/*`
    - **POST** `/cloud/project/*/database/*`
    - **PUT** `/cloud/project/*/database/*`
    - **DELETE** `/cloud/project/*/database/*`

    You can generate them on the [OVHcloud token generation page](https://us.ovhcloud.com/auth/api/createToken).

    The `service_name` is the ID of your Public Cloud project. To copy it, click the `Project` selector at the top of the left-hand menu of your Public Cloud project, then click the copy icon on the row of your project.

    **Step 2: Gather the set of required parameters**

    To create a new OpenSearch cluster, specify at least:

    - the _engine_ (e.g. `opensearch`)
    - the _version_ (e.g. `3.3`)
    - the _region_ (e.g. `US-EAST-VA`)
    - the _plan_ (e.g. `business`)
    - the _flavor_ (e.g. `db1-7`)

    **Step 3: Create Terraform files**

    Create a `main.tf` file:

    ```terraform
    terraform {
      required_providers {
        ovh = {
          source  = "ovh/ovh"
          version = ">= 2.11.0"
        }
      }
    }

    provider "ovh" {
      endpoint           = var.ovh.endpoint
      application_key    = var.ovh.application_key
      application_secret = var.ovh.application_secret
      consumer_key       = var.ovh.consumer_key
    }

    resource "ovh_cloud_project_database" "service" {
      service_name = var.product.project_id
      description  = var.product.name
      engine       = var.product.engine
      version      = var.product.version
      plan         = var.product.plan
      nodes {
        region = var.product.region
      }
      nodes {
        region = var.product.region
      }
      nodes {
        region = var.product.region
      }
      flavor = var.product.flavor
      ip_restrictions {
        ip = var.product.ip
      }
    }

    resource "ovh_cloud_project_database_opensearch_user" "analyticsuser" {
      service_name = ovh_cloud_project_database.service.service_name
      cluster_id   = ovh_cloud_project_database.service.id
      name         = var.access.name
    }
    ```

    Create a `variables.tf` file:

    ```terraform
    variable "ovh" {
      type = map(string)
      default = {
        endpoint           = "ovh-us"
        application_key    = ""
        application_secret = ""
        consumer_key       = ""
      }
    }

    variable "product" {
      type = map(string)
      default = {
        project_id = ""
        name       = ""
        engine     = ""
        region     = "US-EAST-VA"
        plan       = "business"
        flavor     = "db1-7"
        version    = ""
        ip         = "0.0.0.0/32"
      }
    }

    variable "access" {
      type = map(string)
      default = {
        name = "johndoe"
      }
    }
    ```

    Here, we defined the `ovh-us` endpoint because we want to call the OVHcloud US API.

    Create a `secrets.tfvars` file with your actual values:

    ```terraform
    ovh = {
      endpoint           = "ovh-us"
      application_key    = "<application_key>"
      application_secret = "<application_secret>"
      consumer_key       = "<consumer_key>"
    }

    product = {
      project_id = "<service_name>"
      name       = "opensearch-terraform"
      engine     = "opensearch"
      region     = "US-EAST-VA"
      plan       = "business"
      flavor     = "db1-7"
      version    = "3.3"
      ip         = "<ip_range>"
    }

    access = {
      name = "johndoe"
    }
    ```

    :::info
    Replace `<service_name>`, `<application_key>`, `<application_secret>`, `<consumer_key>`, and `<ip_range>` with your actual values.
    :::

    Create an `outputs.tf` file:

    ```terraform
    output "cluster_uri" {
      value = ovh_cloud_project_database.service.endpoints.0.uri
    }

    output "user_name" {
      value = ovh_cloud_project_database_opensearch_user.analyticsuser.name
    }

    output "user_password" {
      value     = ovh_cloud_project_database_opensearch_user.analyticsuser.password
      sensitive = true
    }
    ```

    **Step 4: Run**

    ```bash
    terraform init
    terraform plan -var-file=secrets.tfvars
    terraform apply -var-file=secrets.tfvars -auto-approve
    ```

    Export the credentials and URI:

    ```bash
    export PASSWORD=$(terraform output -raw user_password)
    export USER=$(terraform output -raw user_name)
    export URI=$(terraform output -raw cluster_uri)
    ```

    Your OpenSearch cluster is now ready.

    A Kafka example is available in the [public-cloud-databases-examples/kafka/terraform](https://github.com/ovh/public-cloud-databases-examples/tree/main/databases/kafka/terraform/hello-world) repository.
  </Tab>
