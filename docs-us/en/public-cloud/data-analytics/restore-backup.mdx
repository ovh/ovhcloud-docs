# Analytics - Restore a backup

## Objective

The Analytics service allows you to focus on building and deploying cloud applications while OVHcloud takes care of the Analytics infrastructure and maintenance.

**This guide explains how to restore a backup of an Analytics service solution in the OVHcloud Console.**

We continuously improve our offers. You can follow and submit ideas to add to our [roadmap](https://github.com/orgs/ovh/projects/16/views/5?filterQuery=main-product%3A%22Managed+Databases%22%2C%22Data+Platform%22%2C%22Data+Processing%22%2C%22Data+Integration%22).

## Requirements

- An [Analytics service](https://us.ovhcloud.com/public-cloud/cloud-analytics/) up and running

#### OVHcloud Console access

- **Direct link:** [Public Cloud projects](https://console.us.ovhcloud.com/#/public-cloud/project)
- **Navigation path:** `Public Cloud` > Select your project > **Analytics** group

## Instructions

### Step 1: Select the Analytics service you want to restore data from

In the left-hand menu of your Public Cloud project, click your product under **Analytics**, then click the name of the service you want to restore the backup from.

### Step 2: Go to the backup tab

In the tab list, click `Backups`.

{/* cp-shot: ![Manager database backups tab](/images/public-cloud/databases/restore-backup/manager-database-backups-tab.png) */}

### Step 3: Select the backup to restore from

Select the backup from which you want to restore. To help you choose, observe the dates at which the backups have been performed.

Click the `⋮` button in the row of the chosen backup, then click `Fork` to open the **Fork a cluster** panel. You can also click the `Fork` button above the list.

{/* cp-shot: ![Manager database backups tab more options](/images/public-cloud/databases/restore-backup/manager-database-backups-tab-more-options.png) */}

### Step 4: Configure the target service

When restoring a backup, you create a new separate service on which the backup data will be imported. You can configure this new service as you wish in the **Fork a cluster** panel.

#### Name

Enter a **New cluster name**.

#### Restore point

In **Fork source**, choose the restore point from which the service will be duplicated:

- **From a backup**: the most common option, restore from one of the listed snapshots (**Backup** field).
- **Point in time**: if your service supports point-in-time recovery (see the [Analytics - Automated backups](/public-cloud/data-analytics/automated-backups) guide for more details), restore from a specific date and time.
- **Latest state**: restore from the most recent data.

{/* cp-shot: ![Manager database - Restore backup](/images/public-cloud/databases/restore-backup/manager-database.png) */}

{/* cp-shot: ![Manager database from date](/images/public-cloud/databases/restore-backup/manager-database-from-date.png) */}

{/* cp-shot: ![Manager database newest](/images/public-cloud/databases/restore-backup/manager-database-newest.png) */}

#### New cluster configuration

You cannot change the engine. In the **New cluster configuration** section, you can choose the **Version**, a different **Region**, another service **Plan**, a bigger **Node type**, the **Number of nodes**, and additional **Storage** for your new service. The network of the new service cannot be changed in this panel.

{/* cp-shot: ![Manager database service plans](/images/public-cloud/databases/restore-backup/manager-database-service-plans.png) */}

{/* cp-shot: ![Manager database region](/images/public-cloud/databases/restore-backup/manager-database-region.png) */}

{/* cp-shot: ![Manager database node type](/images/public-cloud/databases/restore-backup/manager-database-node-type.png) */}

{/* cp-shot: ![Manager database cluster size](/images/public-cloud/databases/restore-backup/manager-database-cluster-size.png) */}

:::info
The targeted node type and storage must be large enough to restore the backup.
:::

The estimated price of the new service is displayed at the bottom of the panel. Now click `Create fork` and the new service will be created. Please note that depending on the backup size, it can take some time before the service is available.

{/* cp-shot: ![Manager database configure](/images/public-cloud/databases/restore-backup/manager-database-configure.png) */}

### Step 5: Wait for service creation

Now all you have to do is wait for your service to be ready.
This new service is now completely independent from the one you forked the backup from. You can safely delete the old service without impacting the new one.

:::warning
The IP restrictions of the old service are applied to the new one, but the users created on the old service are not duplicated: recreate them before using your new service. Check the IP restrictions in the `Configuration` tab of the new service.
:::

{/* cp-shot: ![Manager database dashboard creating status](/images/public-cloud/databases/restore-backup/manager-database-dashboard-creating-status.png) */}
