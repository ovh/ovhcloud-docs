# Analytics - Automated backups

## Objective

This page provides the technical descriptions of the automated backup methods and routines for each Analytics engine.

We continuously improve our offers. You can follow and submit ideas to add to our roadmap at [https://github.com/orgs/ovh/projects/16/views/5](https://github.com/orgs/ovh/projects/16/views/5).

## Backup Methods

- Daily remote site backup:

We back up our managed Analytics services every 1 (incremental snapshots), 12, or 24 hours (backups), depending on the product, with the ability to restore from the latest point in time, based on the retention period of the chosen customer plan.

Whether you encounter an issue or simply want to view your data from a previous date, you can restore your data to any point in time within the retention period of the chosen customer plan.

## Off-site backup

### Replication mechanism

Backups are first prepared on-site and then replicated to another region. The on-site backup data persists even after replication to the remote region.

### Default location

Analytics services provide a default configuration for remote backups based on the region where the service is running:

| **Service location**             | **Off-site default backup location** |
| -------------------------------- | ------------------------------------ |
| US-EAST-VA (Vint Hill, Virginia) | US-WEST-OR (Hillsboro, Oregon)       |
| US-WEST-OR (Hillsboro, Oregon)   | US-EAST-VA (Vint Hill, Virginia)     |

### Custom settings

The default backup location and time can be overridden by configuring the `backups` attribute either when creating or updating your Analytics service. As an example, the following settings define `HIL` (Hillsboro, Oregon) as the backup location and `01:00:00` as the daily backup time:

```json
"backups": {
  "regions": ["HIL"],
  "time": "01:00:00"
}
```

As a reminder, here is the API endpoint for an Analytics service creation:

<Api version="v1" section="/cloud/project" regions={["us"]} method="POST" route={"/cloud/project/\{serviceName\}/database/kafka"} />

Replace `kafka` in the route with your service's engine (for example `opensearch` or `grafana`).

Backup settings must respect the following rules:

- The `regions` array accepts one or two elements. If only one element is specified, it must match the region the service is running in. If two elements are specified, one of these elements must match the region the service is running in, while the other element could be set to any other region. It is **recommended** to use two regions for your backups.
