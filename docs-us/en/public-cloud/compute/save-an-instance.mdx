# Taking a snapshot of an instance

**Learn how to create manual and automatic snapshots of a Public Cloud instance.**

You can create a single snapshot of an instance or configure a schedule to automate your instance snapshots. Snapshots can be used to restore your instance to a previous state or to create a new, identical instance.

 

## Requirements

- A [Public Cloud instance](/public-cloud/compute/getting-started) in your OVHcloud account
- Access to the [OVHcloud Console](https://console.us.ovhcloud.com/)
- *Optional:* Access to OpenStack CLI (see [this guide](/public-cloud/cross-functional/compute-prepare-openstack-api-environment) to get started)

## Instructions

:::info

Two types of snapshot are available:

- Local: A local snapshot is stored in the same region as your instance.
- Remote: A remote snapshot automatically creates a copy of the local snapshot in a different region of your choice.

Each snapshot is billed separately — the remote snapshot will be charged based on the storage pricing of the selected remote region.

**Note:** Local Zones are not eligible for remote snapshots.

:::

### Creating a manual snapshot of an instance

<Tabs>

<Tab label="Via the OVHcloud Console">

From the [OVHcloud Console](https://console.us.ovhcloud.com/#/public-cloud/project), go to `Public Cloud` > `Projects` and select your Public Cloud project.

In the left-hand menu of your Public Cloud project, click `Instances` under **Compute**.

Click the `⋮` button to the right of your instance and select `Create a snapshot`.

{/* cp-shot: ![Instances more options](/images/public-cloud/compute/save-an-instance/instances-more-options.png) */}

<details>
<summary>Local snapshot</summary>

Enter a name for the snapshot, review the pricing information, and click `Create`.

{/* cp-shot: ![Instances create backup local](/images/public-cloud/compute/save-an-instance/instances-create-backup-local.png) */}

</details>

<details>
<summary>Remote snapshot</summary>

Enter a name for the snapshot and review the pricing information. Enable `Add a remote snapshot`, enter a name for the remote snapshot, select a region, and click `Create`.

{/* cp-shot: ![Instances create backup remote](/images/public-cloud/compute/save-an-instance/instances-create-backup-remote.png) */}

</details>

The instance is suspended for a few seconds while the snapshot is taken. It is not possible to track the snapshot's progress in real time. However, on the page that opens when you click `Instance Snapshot` under **Compute** in the left-hand menu, the status of the snapshot is displayed during the process.

Once the snapshot is complete, it is available on that page and in the `Snapshots` tab of the instance.

{/* cp-shot: ![Backup progress - Save an instance](/images/public-cloud/compute/save-an-instance/backup-progress.png) */}

</Tab>

<Tab label="Via the OVHcloud API">

Log in to the [OVHcloud API](https://api.us.ovhcloud.com/).

You can list all available regions using the following API call:

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{ServiceName\}/region"} regions={["us"]} />

Then, use the following API call to create your snapshot:

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/instance/\{instanceId\}/snapshot"} regions={["us"]} />

Fill in the variables:

- **instanceId**: The unique instance ID.
- **regionName**: The region name where the source instance is located.
- **serviceName**: The OVHcloud project ID.
- **distantRegionName (optional)**: The  region name where the remote snapshot will be stored.
- **distantSnapshotName (optional)**: The name of the remote snapshot to create in the remote region.
- **snapshotName**: The name of the local snapshot to create.

:::info

Only create a remote snapshot if the parameters related to the remote region (**distantRegionName** and **distantSnapshotName**) are provided.

:::

You can also confirm that your snapshot was created successfully:

<Api version="v1" section="/cloud" method="GET" route={"/cloud/project/\{serviceName\}/snapshot"} regions={["us"]} />

</Tab>

<Tab label="Via the OpenStack CLI">

Run the following command to display the list of instances:

```bash
openstack server list

+--------------------------------------+-----------+--------+--------------------------------------------------+--------------+
| ID | Name | Status | Networks | Image Name |
+--------------------------------------+-----------+--------+--------------------------------------------------+--------------+
| aa7115b3-83df-4375-b2ee-19339041dcfa | Server 1 | ACTIVE | Ext-Net=51.xxx.xxx.xxx, 2001:41d0:xxx:xxxx::xxxx | Ubuntu 16.04 |
+--------------------------------------+-----------+--------+--------------------------------------------------+--------------+
```

You can list all available regions using the following command:

```bash
openstack region list
```

<details>
<summary>Local snapshot</summary>

Then run the following command to create a snapshot of your instance:

```bash
openstack server image create --name snap_server1 aa7115b3-83df-4375-b2ee-19339041dcfa
```

</details>

<details>
<summary>Remote snapshot</summary>

Run the following command after following the local snapshot step:

```bash
openstack workflow execution create ovh. glance.glance_download '{"src_image_id":"<image_id>", "src_region":"<current_region>", "dst_region":"<remote_region>"}'
```

</details>

</Tab>

<Tab label="Via Horizon">

Click on the `Compute` menu on the left, then select `Instances`.\
Then click on the `Create Snapshot` button to the right of the instance line.

![Horizon instances dashboard](/images/public-cloud/compute/save-an-instance/horizon-instances-dashboard.png)

Fill in the snapshot name and press the `Create Snapshot` button.

![Horizon create snapshot](/images/public-cloud/compute/save-an-instance/horizon-create-snapshot.png)

### Creating an automatic snapshot of an instance

:::info

If you want to automate this functionality directly via OpenStack, you can create a Mistral workflow associated with a cron trigger.

:::

<Tabs>

<Tab label="Via the OVHcloud Console">

From the [OVHcloud Console](https://console.us.ovhcloud.com/#/public-cloud/project), select your Public Cloud project.

In the left-hand menu of your Public Cloud project, click `Instances` under **Compute**.

Click the `⋮` button to the right of your instance and select `Create an automatic snapshot`.

{/* cp-shot: ![Instances more options](/images/public-cloud/compute/save-an-instance/instances-more-options.png) */}

A schedule creation page opens, where you can configure the following settings.

 

#### The workflow

The schedule creates an automatic snapshot of the instance and its primary volume. There is no workflow type to choose.

{/* cp-shot: ![Create workflow - Save an instance - step 1](/images/public-cloud/compute/save-an-instance/create-workflow-1.png) */}

 

#### The resource

Select the instance that you wish to back up.

{/* cp-shot: ![Create workflow - Save an instance - step 2](/images/public-cloud/compute/save-an-instance/create-workflow-2.png) */}

 

#### The name

Give the schedule a name and take note of the pricing information.

{/* cp-shot: ![Create workflow - Save an instance - step 3](/images/public-cloud/compute/save-an-instance/create-workflow-3.png) */}

 

#### The schedule

You can set up a custom snapshot schedule (in UNIX cron format, UTC) or choose one of the default frequencies:

- Daily snapshot with retention of the last 7 snapshots, or
- Daily snapshot with retention of the last 14 snapshots.

{/* cp-shot: ![Create workflow 4 rotation - step 7](/images/public-cloud/compute/save-an-instance/create-workflow-4-rotation-7.png) */}

<details>
<summary>Adding a remote snapshot</summary>

Before creating the schedule, enable `Add a remote snapshot`, select a location, and review the pricing information.

{/* cp-shot: ![Create workflow 4 remote](/images/public-cloud/compute/save-an-instance/create-workflow-4-remote.png) */}

</details>

Click `Create` to create the schedule.

Once created, your snapshot schedule will be visible on the page that opens when you click `Workflow` under **Compute** in the left-hand menu.

</Tab>

<Tab label="Via the OVHcloud API">

From the [OVHcloud API](https://api.us.ovhcloud.com/), you can create an automatic snapshot workflow using the following API call:

<Api version="v1" section="/cloud/project" method="POST" route={"/cloud/project/\{serviceName\}/region/\{regionName\}/workflow/backup"} regions={["us"]} />

The snapshots are charged according to the space used, with a granularity of 1GB. Refer to the [Public Cloud pricing page](https://us.ovhcloud.com/public-cloud/prices/) for Instance Backup pricing.

**Parameters:**

|                   |                                                                                                                                                                                    |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Input**         | **Notes**                                                                                                                                                                          |
| serviceName       | API to obtain a list of available services (serviceName):<Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project"} regions={["us"]} />                      |
| regionName        | API to obtain a list of available regions (regionName):<Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/region"} regions={["us"]} /> |
| instanceId        | API to obtain a list of Instance IDs:<Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/instance"} regions={["us"]} />                 |
| cron              | Set to Unix cron format (time zone in UTC)                                                                                                                                         |
| maxExecutionCount | Set the number of executions to process before the end of the task. Zero (0) means that the task will never end.                                                                   |
| name              | The name of the automatic snapshot schedule                                                                                                                                          |
| rotation          | Set the number of snapshots to retain                                                                                                                                                |

You can verify the creation of your workflow with the following API call:

<Api version="v1" section="/cloud/project" method="GET" route={"/cloud/project/\{serviceName\}/region/\{regionName\}/workflow/backup"} regions={["us"]} />

</Tab>

</Tabs>

 

### Managing snapshots and schedules

#### Manual snapshots

:::warning

**NOTE:** Instances and snapshots are charged separately. Deleting an instance will not stop the charges for instance snapshots. They must be deleted separately.

:::

:::warning

**NOTE:** You cannot delete an instance snapshot if an instance that has been spawned from that snapshot is running at the time of the delete action.

:::

From the [OVHcloud Console](https://console.us.ovhcloud.com/#/public-cloud/project), select your Public Cloud project.

In the left-hand menu of your Public Cloud project, click `Instance Snapshot` under **Compute**. Your instance snapshots are managed on this page.

Click the `⋮` button to the right of your snapshot. From here, you can create an instance from the snapshot ([full instructions](/public-cloud/compute/create-restore-a-virtual-server-with-a-backup)) or `Delete` the snapshot.

{/* cp-shot: ![Backup more options](/images/public-cloud/compute/save-an-instance/backup-more-options.png) */}

**Via OVHcloud API**

<Api version="v1" section="/cloud" method="DELETE" route={"/cloud/project/\{serviceName\}/snapshot/\{snapshotId\}"} regions={["us"]} />

 

#### Automatic snapshots

:::warning

**NOTE:** Instances and workflows are charged separately. However, if you delete an instance, all workflows attached to it will be deleted automatically (after approx. 30 minutes).

:::

From the [OVHcloud Console](https://console.us.ovhcloud.com/#/public-cloud/project), go to `Public Cloud` > `Projects` and select your Public Cloud project.

In the left-hand menu of your Public Cloud project, click `Workflow` under **Compute**. Your snapshot schedules are listed on this page.

Click the `⋮` button to the right of your snapshot schedule. From here, you can `Delete` the schedule.

{/* cp-shot: ![Delete workflow - Save an instance](/images/public-cloud/compute/save-an-instance/delete-workflow.png) */}

**Via OVHcloud API**

<Api version="v1" section="/cloud/project" method="DELETE" route={"/cloud/project/\{serviceName\}/region/\{regionName\}/workflow/backup/\{backupWorkflowId\}"} regions={["us"]} />
