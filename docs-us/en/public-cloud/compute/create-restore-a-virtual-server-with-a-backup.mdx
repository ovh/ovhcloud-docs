# Using instance snapshots to create or restore an instance

**Learn how to use snapshots to duplicate and restore your instances.**

The OVHcloud Console enables you to [create snapshots of your instances](/public-cloud/compute/save-an-instance). You can make use of these instance snapshots in two ways:

- Creating a new instance with the snapshot as a template to duplicate the original instance's root disk, for example, if you are configuring a load-balancing infrastructure.
- Restoring instances from a snapshot, for example, if recent changes broke critical configurations on the instance.

 

## Requirements

- A [snapshot of a Public Cloud instance](/public-cloud/compute/save-an-instance)

- Access to the [OVHcloud Console](https://console.us.ovhcloud.com/) or [OVHcloud API](https://api.us.ovhcloud.com/)

  :::tip

  **Creating** (not restoring) an instance from a snapshot can also be done via the [OpenStack CLI](/public-cloud/compute/starting-with-nova) or [Horizon interface](https://horizon.cloud.ovh.us/).

  :::

 

## Instructions

:::danger

**WARNING:** Data is backed up on all instances that do not have local NVMe passthrough disks. Data on local NVMe passthrough disks (e.g., T2-180) is not included, so creating or restoring an instance from a snapshot does not bring this data back. Copy any data you need to Object Storage or Block Storage before creating a snapshot.

:::

:::info

Two types of snapshots are available:

- Local: Stored in the same region as your instance.
- Remote: Automatically replicated in another region of your choice.

Both **creating** and **restoring** an instance from a remote snapshot are fully supported via the OVHcloud API, offering greater flexibility and effortless integration into your automation processes.

**Note:** In the OVHcloud Console, you can create an instance from any snapshot listed on the `Instance Snapshot` page, but you can only restore an existing instance from a snapshot stored in its own region.

:::

### Creating an instance from a snapshot

<Tabs>

<Tab label="Via OVHcloud Console">

From the [OVHcloud Console](https://console.us.ovhcloud.com/#/public-cloud/project), select your Public Cloud project. In the left-hand menu, click `Instance Snapshot` under **Compute**. This page lists your instance snapshots.

Click the `⋮` button in the row of the relevant snapshot, then select `Create an instance`.

{/* cp-shot: ![Instance more options](/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/instance-more-options.png) */}

The **Create an instance** page opens with some elements pre-defined:

- **Region**: Your instance will be created in the same region as your snapshot. The region is determined by the snapshot and cannot be changed.
- **Image**: The snapshot is preselected in the `Snapshots` tab of the image selection.

Choose the new instance’s model, name, SSH key, network and billing settings, then click the `Create my instance` button.

:::warning

**NOTE:**

- Only the models that are compatible with your image are available, depending on your quota.
- Depending on the model chosen, you may only have one option available for the billing period.

:::

For further information on creating an instance, please refer to [this guide](/public-cloud/compute/getting-started).

:::info

To create the instance in a different data center, you will first need to transfer the snapshot to the appropriate region. Please take a look at our guide on [transferring an instance snapshot](/public-cloud/compute/transfer-instance-backup-from-one-datacenter-to-another).

:::

</Tab>

<Tab label="Via OpenStack CLI">

To create an instance from your snapshot, use the snapshot ID as the image with this command:

```bash
openstack server create --key-name SSHKEY --flavor 98c1e679-5f2c-4069-b4da-4a4f7179b758 --image 0a3f5901-2314-438a-a7af-ae984dcbce5c Server1_from_snap
```

</Tab>

<Tab label="Via Horizon">

In the [Horizon interface](https://horizon.cloud.ovh.us/), click on `Compute` in the left-hand menu, then on `Images`. Find the desired image and click the `Launch` button to the right of your image line.

![Horizon images dashboard](/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/horizon-images-dashboard.png)

Name your instance in the dedicated field, then specify the number of instances to create. Then click the `Flavor` tab.

![Horizon instances launch](/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/horizon-instances-launch.png)

Choose the desired instance model, then click the `Networks` tab.

:::warning

**NOTE:** If your instance is a Windows server, you must select a flavor of type win-xx-xx (for example, win-b2-15) and have a public interface on the Ext-Net network. Without these conditions, authentication with the OVHcloud KMS will not be possible, and your server will remain with an [unactivated license](/public-cloud/compute/activate-windows-license-private-mode). This could lead to limitations, including the absence of updates. Please note that it is not possible to resize a Linux instance (such as b2-15) to a Windows instance (such as win-b2-15). To make this transition, you need to recreate a new instance.

:::

![Horizon instances launch - step 2](/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/horizon-instances-launch-2.png)

Choose the network you wish to assign to it, then click the `Launch Instance` button.

![Horizon instances launch - step 3](/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/horizon-instances-launch-3.png)

You can find the status of your new instance by selecting `Compute` in the left-hand menu and then `Instances`.

</Tab>

<Tab label="Via the OVHcloud API">

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/region/\{regionName\}/instance"} regions={["us"]} />

Fill in the variables:

- **serviceName**: The OVHcloud project ID.
- **regionName**: The region name where the instance will be located.

Example of the request body:

```json
{
  "billingPeriod": "hourly",
  "bootFrom": {
    "imageId": "5cb8ea68-****-****-****-820be8346***"
  },
  "flavor": {
    "id": "e81b46f8-****-****-****-cad655e65***"
  },
  "name": "newInstance",
  "network": {
    "public": true
  },
  "sshKey": {
    "name": "MySSHKey"
  }
}
```

</Tab>

</Tabs>

 

### Restoring an instance from a snapshot

:::warning

**NOTE:** You can only restore an instance to the region in which the snapshot resides.

:::

<Tabs>

<Tab label="Via OVHcloud Console">

In the left-hand menu of your Public Cloud project, click `Instances` under **Compute**, then click on the name of the relevant instance.

{/* cp-shot: ![Instances more options](/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/instances-more-options.png) */}

In the `Overview` tab, click `Edit image` next to the instance's image. The **Edit image** panel opens.

Choose the snapshots as the image source, then select the snapshot to restore. Only the snapshots stored in the region of the instance are offered. Click `Edit image` if you are certain that you want to overwrite the current image with the snapshot.

{/* cp-shot: ![Instances edit instance](/images/public-cloud/compute/create-restore-a-virtual-server-with-a-backup/instances-edit-instance.png) */}

The instance will be reinstalled and restarted until the process is completed.

:::warning

**NOTE:** Restoring replaces the instance's root disk with the snapshot. As stated in the warning message, any data written to the root disk after the snapshot was created will be lost. Data on local NVMe passthrough disks is not part of the snapshot and cannot be restored from it.

:::

</Tab>

<Tab label="Via OVHcloud API">

<Api version="v1" section="/cloud" method="POST" route={"/cloud/project/\{serviceName\}/region/\{regionName\}/instance/\{instanceId\}/reinstall"} regions={["us"]} />

Fill in the variables:

- **serviceName**: The OVHcloud project ID.
- **regionName**: The region name where the source instance is located.
- **instanceId**: The unique instance ID.

Example of the request body:

```json
{
  "imageId": "5cb8ea68-****-****-****-820be8346***",
  "imageRegionName": "US-EAST-VA"
}
```

</Tab>

</Tabs>
